reckon build — CI static site generation

active high ROI M effort S5

Add a reckon build command that bundles canonical UI assets into docs/ and generates a portable index.html for GitHub Pages and any static host. Eliminate index.json as wiring by discovering sprints and milestones from HTML meta tags — the same zero-wiring approach already used for plans.

§ 1 — Problem

The reckon server (v8+) serves UI assets via canonical routes: /_ui/<file> and /_shared/<file>. Generated index.html uses these absolute paths. This works perfectly with the live server but breaks for static deployment — GitHub Pages has no reckon process to serve those routes.

Additionally, sprint and milestone definitions currently require authoring index.json by hand. This is the last piece of wiring that plans do not have: plans auto-discover from HTML meta tags; sprints and milestones do not.

§ 2 — reckon build command

reckon build <docs_path> [--project <name>]

What it does (static-site only — no mounts, no symlinks):

  1. Copies reckon/docs/ui/ → docs/_ui/ (all JSX + CSS)
  2. Copies reckon/docs/_shared/ → docs/_shared/ (foundation, dashboard, state.js)
  3. Generates docs/index.html with RELATIVE paths (_shared/, _ui/) — not absolute /_shared/
  4. Calls discover_plans() and writes docs/state/<project>/index.json with discovered inventory + sprints/milestones (for static environments without a live server)
  5. Does NOT create symlinks, does NOT register in mounts.json

Distinction from reckon sync: sync is for developer setup (live server, mounts, symlink, state directory). build is for CI — produces a portable static artifact.

§ 3 — Sprint and milestone discovery from HTML

The zero-wiring principle applied to sprints: define a sprint by dropping an HTML file with meta tags.

<!-- docs/sprints/s5.html -->
<meta name="sprint-id"      content="S5">
<meta name="sprint-theme"   content="CI + zero-wiring">
<meta name="sprint-status"  content="active">
<meta name="sprint-starts"  content="2026-05-26">
<meta name="sprint-ends"    content="2026-06-09">
<!-- docs/milestones/m2.html -->
<meta name="milestone-id"     content="M2">
<meta name="milestone-name"   content="Zero-wiring complete">
<meta name="milestone-status" content="active">

discover_plans() scans docs/sprints/*.html and docs/milestones/*.html in addition to plan pages. Sprint IDs found this way replace auto-synthesized stubs. index.json becomes entirely optional — it holds only active_sprint_id if the user wants to pin it, and that can also come from a sprint page with status="active".

§ 4 — CI YAML template

reckon sync --generate-ci writes .github/workflows/reckon-pages.yml:

name: Deploy plans to GitHub Pages
on:
  push:
    branches: [main]
  workflow_dispatch:
permissions:
  contents: read
  pages: write
  id-token: write
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v4
        with: { python-version: "3.12" }
      - run: pip install reckon
      - run: reckon build docs/
      - uses: actions/upload-pages-artifact@v3
        with: { path: docs/ }
  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/deploy-pages@v4
        id: deployment

§ 5 — reckon as a versioned PyPI package

For CI reproducibility, reckon must be a versioned package on PyPI (or a GitHub release). pip install reckon==1.2.3 in CI ensures deterministic builds. This requires:

  • PyPI registration (currently only on PyPI if published — verify)
  • GitHub Actions release workflow: tag → build → publish to PyPI
  • Version pinning guidance in generated CI YAML
