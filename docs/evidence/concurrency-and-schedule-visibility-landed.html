A derivation map on the project resource

An optional derivations object maps a repository-relative POSIX source path to the generated paths it produces, rejecting absolute, traversal, empty and backslash paths before a versioned write publishes them. An absent key stays absent and an empty map round-trips unchanged, so the feature is invisible to every project that does not use it.

The consumer is deliberately absent, and that absence is a measurement. Expanding a source claim into its generated artifacts belongs in crew.py, which a concurrent node held. This node was the only disjoint lane available at the time — found by searching for one — and it exists because the lead's choice of the project resource over a flight layer put the map in a file nothing else wanted. The plan's thesis, observed on its own execution.

The boundaries were not invented. crew.py had declared them in section comments for months — node, routing, runs, prompts, dispatch, promotion, recovery, reports, summary — so the split was a move, not a redesign, which is why it could be done in one node at speed.

What it bought, measured on the next wave rather than argued. The four remaining nodes on this plan all wanted crew.py and would have run one at a time. They now wanted recovery.py, dispatch.py, promotion.py and roadmap.py, and ran three-wide immediately. One lane became three on the first attempt.

One limit worth recording. The split divided the source and not the tests: tests/test_crew.py is still 3310 lines, so concurrent nodes must each write their own test module or they collide there instead. Every node in the following wave did, which is why the fan-out held.

The stop that made it safe. The worker halted with one failing test rather than edit a test its contract forbade — a contract test that greps crew.py as a file for refusal strings that had moved into dispatch.py. The repair was a fidelity change, not a relaxation: the test now reads the whole package, so the assertion keeps its exact meaning and cannot be satisfied by a string sitting in the wrong module.
