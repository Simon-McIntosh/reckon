§3 — Why the figures were missing, precisely

The coverage gap was never a measurement difficulty. The throughput block's own docstring at _backends.py:137 argues for exactly these figures — “what makes a slow worker distinguishable from a stuck one”, keeping “generation apart from tool wait because wall clock on a node running its own test suite is mostly the suite” — and its only consumer never read it. The field was defined, exported by as_dict(), and dropped by every caller, so its stated reason for existing was unachievable from the day it was written and no test failed, because a computed value reaching no reader breaks nothing.

Two distinct drops, both now closed: dispatch.py:3172 copied five fields out of the observation and not throughput, so no live pointer carried a span; and promotion.py stored the block from an observe_log call made without a receipt, while _harvest_lane_receipt read that same rollout receipt a few functions away. Promotion held both halves and never joined them. The proof that nothing was failing to measure: a direct observe_log of one run's stream computed 6885.08 seconds against that stream's own duration_api_ms of 6885.44.

§5 — The cost figure, and why it is computed

Of 803 committed rows, 107 carry a numeric cost_usd and only 64 — 8.0% — are genuinely metered: $87.65 on claude and $47.91 on claude-opus. The other 43 are fabricated figures on the free local lanes totalling $941.50. So 87% of every dollar this project has recorded was never charged to anyone, and all of it is attributed to hardware that costs nothing per token. Those 43 rows all predate 2026-09-03 while every correctly-flagged row postdates 09-05, with no overlap, so _label_unmetered_cost works and they are pre-guard residue — a backfill for whichever plan owns ledger repair.

The computed figure therefore takes its own name. cost_usd_imputed means this figure was nulled; notional_cost_usd means this figure was derived, with rate_basis recording which dated pair produced it. One word carrying both would have made a nulled row and a derived row indistinguishable in the field that exists to tell them apart.

§6 — Three code lifetimes, one deploy

A pane rendering dashes after this landed is a delivery gap, never a measurement gap, and the reason is worth keeping. The follower reloads installed code in place, so it picked up the new cells within a minute; the watch producer is a separate long-lived process and does not, so records emitted by a producer armed before f5ce93e genuinely lack the spend_* facts. The CLI is current every invocation; an MCP is cold until reconnected. The figures were available throughout: called directly, the accumulator returns elapsed 5961.787 s, generation 5764.321 s and 41,770,910 charged tokens for the pane node's own run — a 96.7% model share.

The evidence is the events file, not the timestamps. The reckon producer was armed at 15:30:38 against an emitting module changed at 17:04:36, so it was 93 minutes cold — but the fact that settles it is that the last four transitions on the stream, including this plan's own attribution dispatch at 15:20:13Z, carried no spend_* keys at all. Every record was unrenderable, which makes it a delivery failure rather than a rendering one. A dispatch does not replace a cold seat: replacement keys on the supervisor having died, deliberately, because refusing a dispatch over a producer that streams perfectly would block work.

The staleness check that exists cannot catch this, and the reason is not the one first recorded here. An earlier reading held that __version__ is the literal dev, making the comparison vacuous — that came from running a system interpreter with no editable install on its path. Under the project interpreter it reads 0.2.1.dev1279, and the released seat had recorded exactly that. The real reason is the one watch_seat_version_current states itself: it “names the install and not the code”, written once at install time, so both sides compare one string whichever revision each process is executing. The distinction is practical rather than pedantic — on the wrong reason a properly-versioned non-editable install would fix it, and on the right one no install can, because the version cannot move when the working tree moves and the working tree is what every session runs. Content or mtime of the emitting modules is the only discriminator.

One consequence for a reader: arming a fresh producer switches the pane from all-dashes to real figures at once, which reads as the feature turning on. It was on; the delivery was not.
