Its first attempt refused to proceed rather than write outside its fence. tests/test_schema.py:489-499 requires docs/_shared/plan.schema.json to equal gen_json_schema(), so adding a field to PlanState changes a generated artifact that the dispatch had not included in the exclusive write paths.

The inventory, computed live

Commit 36eea19. The discovery envelope now carries tag_inventory as an alphabetically ordered list of {tag, count} records, and every plan, research and evidence row carries its full tags list. Counts are derived from non-archived typed resources on every read, each resource contributing once per tag it carries.

The property that makes this a vocabulary rather than a cache is asserted directly: the test authors a brand-new tag during the run and observes it appear with count 1 on the next read, with no code change. The inventory is computed from corpus metadata rather than any literal list, which is what the locked observed-with-counts decision requires — a curated allow-list would have needed governance nobody will perform, and would block a legitimately new topic at the exact moment someone is authoring.

The unfiltered project inventory supplies counts even when discovery rows are filtered, so a narrowed view still shows the whole vocabulary — which is the point: an author needs to see what exists, not what they are currently looking at.
