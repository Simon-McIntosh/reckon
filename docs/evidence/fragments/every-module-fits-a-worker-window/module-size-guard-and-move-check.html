A module-size guard and a pure-move check

The guard. tests/test_every_module_fits_a_worker_window.py measures every *.py under tests/ and reckon/ at the working tree through reckon.crew.routing._tokens_for_bytes — the context-fit check's own estimate, called rather than restated — and fails on a file over 50,000 estimated tokens that is not in a literal ALLOWLIST, and on an allowlisted file that is now at or under 50,000, so each split removes its own entry. A third fixture tree under the bound passes, the positive control that the reader sees a clean tree.

The move check. scripts/check_pure_move.py --base <rev> --module <original> --into <produced>... reads the base module through reckon.velocity.read_sources and the resulting modules (the --into paths plus the original's remainder) from the working tree, adding no git reader of its own. It walks each module body with ast, taking each top-level statement's source including its decorator lines, and requires every non-import top-level statement of the base to appear byte-identically in exactly one resulting module. It prints one JSON receipt — moved (statement, from, to), new (a resulting-module statement not from the base, which may only be an import), and estimated_tokens per resulting module — and exits 1 naming every lost, altered, duplicated or non-import new statement.

tests/test_check_pure_move.py builds a one-commit fixture repository per case. A correct split into two produced modules plus a remainder exits 0 with a receipt naming the three moved statements and their destinations; a moved function with one changed line, a dropped function, and a function copied into two produced modules each exit 1 naming the statement at fault.
