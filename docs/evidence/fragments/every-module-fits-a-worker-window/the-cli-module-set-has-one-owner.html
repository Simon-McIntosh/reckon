The CLI module set has one owner

The seven modules that make up the CLI were named twice, once inside source_code_stamp in reckon/crew/obligation_snapshot.py and again inside follower_code_stamp in reckon/crew/runs.py. A module added to one list and not the other left a running producer or follower on old code with nothing failing. The declaration now lives once, as the module-level tuple CLI_MODULE_FILES in obligation_snapshot.py, and both stamps build their source lists from it.

The one declaration

CLI_MODULE_FILES names the seven modules relative to the package directory, in the order the stamps previously listed them: cli.py, cli_entry.py, project_setup_commands.py, crew_dispatch_commands.py, crew_follow_commands.py, crew_run_commands.py, project_maintenance_commands.py. Each stamp appends its unchanged crew/*.py glob after the declared names. The module adds no import at module level, so the prompt hook that loads it by path still pulls no derivation module.

The stamps are unchanged on unchanged bytes

Both source lists were reconstructed over the same extracted base-tree files, the old hardcoded list and the new declared tuple. The three digests agree to the byte, so a stamp over a given tree is identical before and after the change:

The measure

tests/test_the_cli_module_set_has_one_owner.py walks the click tree from the root group, collects the module of each command's callback, and fails naming any top-level reckon module that carries a command but is absent from CLI_MODULE_FILES. A second case copies the package under the test's temporary directory and proves both stamps move when any one declared module's bytes change and hold when nothing does; the real tree is never written.

Gate: the new file plus the fifteen stamp tests named for this node, run serially with --basetemp under the run directory, reported 134 passed and EXIT=0.

Negative control: removing crew_follow_commands.py from the declared tuple (applied to a scratch copy of the package) makes test_every_command_module_is_declared fail with omits module(s) that carry commands: ['crew_follow_commands.py'] and EXIT=1.
