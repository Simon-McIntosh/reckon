no test resolves the real cache

A session-scoped autouse fixture in tests/conftest.py moves XDG_CACHE_HOME — the one lever every kind in reckon/_store.py reads — to a session temporary directory before any module- or function-scoped fixture runs, and pins UV_CACHE_DIR to uv's own directory as resolved before the redirect so a wheel build still resolves its backend. It sets no per-kind override and leaves RECKON_HOME as found, so a test that steers a root through that variable still steers it.

A wrapper around _store.cache_root, installed when the conftest is imported — a point every xdist worker reaches in its own process — records every ambient resolution that leaves the run's temp tree. the guard's whole-suite failure, and its repair

A second whole-suite run at the same head, with tracebacks on so the guard's own report reaches a log (logs/whole-suite/diagnostic-head-suite.log), names the failure and it is not a leak. The guard test fails at tests/test_no_test_resolves_the_real_cache.py:51 in worker gw2 with “the cache_root wrapper was never installed, so an empty leak record proves nothing” — an empty record because nothing was watching, which is the one thing the guard exists to make impossible. Neither whole-suite arm's log carries a leak report.

The cause is tests/mcp_family_reload.py:27. reload_mcp_family() calls importlib.reload(_store) so the MCP tool modules' store exception classes stay in step with a test that redirected storage, and re-executing reckon/_store.py rebinds cache_root to the module's own function, dropping the wrapper with it. The MCP test modules call it in-process, so whichever worker ran one carried the unwatched window until the guarded test was scheduled beside it.

The repair is in tests/conftest.py: the wrapper is re-armed in pytest_runtest_setup as well as at import, so it is restored at the next test boundary after a reload and present for the guard test, which runs last in its worker. Measured as a pair against the same selection — the reloading modules with the guard test scheduled beside them — the guard test fails in one worker without the repair (logs/whole-suite/reload-family-unfixed.log, 1 failed, 230 passed) and passes with it (logs/whole-suite/reload-family-fixed.log, 231 passed, 1 skipped).

The other 22 ids the after arm added over base are settled the same way: run back to back in one window at both revisions, the 14 tests/test_schema.py::test_cross_project_conformance cases pass at both and the 8 tests/test_spa_rendered_semantics.py cases fail at both, so none is added by this change (logs/whole-suite/settled-ids-base.log, settled-ids-head.log, settled-comparison.log: 22 settled, 0 only-head). the reload gap closed, and the control that names it

Re-arming at a test boundary repairs a store reload one beat too late. The wrapper is absent while the reloading test's own finalizers run, and a module-scoped fixture finalised before the next setup resolves its root in that same window, so a leak there is recorded nowhere. Two changes close it, both in tests/conftest.py. arm_the_guard_against_a_reload() wraps importlib.reload so the wrapper is re-armed the instant any reload returns — the reload that drops it is reload_mcp_family() at tests/mcp_family_reload.py:27, which is outside this node's write path, so the guard is what bends — and pytest_runtest_teardown re-arms as well, which covers a teardown that resolves a root without reloading anything.

The control that names the gap is tests/test_no_test_resolves_the_real_cache.py::test_teardown_control_a_reload_then_a_teardown_resolves_the_real_cache, armed by its own variable: its body reloads the store and its teardown resolves the real cache.
