Garbage collection reaches every crew store

Three stores under the crew home grow with every run and nothing bounded them. garbage_collect now reports all three and removes them only under garbage_collect's apply: a run-keyed report tree under reports/<project>/<run-id>/, a run's advisory lock locks/<run-id>.lock, and a run directory runs/<run-id>/ that holds neither a ledger row nor a live pointer. The three row sets are carried on the report as report_trees, lock_files and unledgered_run_directories, each with a matching *_removed count. The existing plan-review raw-report sweep is folded into the report row set rather than run beside it, so report_trees lists a plan-review tree (family: "plan-review") and a general run tree (family: "run") alike, and the plan_review_raw_reports key is the plan-review projection of that set.

A row is offered only when its run is known — live or already in the ledger — and past retention, and a row whose run a live pointer still names is withheld: the run may be writing into its tree, or may take its lock again. The live set is re-read immediately before each removal, so a pointer that appears mid-sweep still withholds its run's row. A lock is offered only for a run already in the ledger, because a lock with no row is not yet a finished run's, and the queue's own queued-dispatch.lock is never matched. An unledgered run directory is offered whole, because with no row and no pointer nothing durable covers its stream. Every removal prints its path and its size — the bytes a tree holds, the honest zero of an empty lock file.

The declared mutation — _run_has_live_pointer returning False unconditionally, removing the live-pointer re-check — makes the sweep report the live run's report tree and the live run's lock and run directory, and the case fails (EXIT=1, assert report_paths == {str(raw_old)}). The head gate on the node's own change, tests/test_gc_reaches_every_crew_store.py plus the existing gc, raw-report, removal-path and worktree-residue cases, is 77 passed at EXIT=0. This gate measures only this node's own change; verifying the merged result belongs to a separately dispatched test node.
