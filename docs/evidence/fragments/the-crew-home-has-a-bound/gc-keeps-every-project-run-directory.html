gc keeps every project's run directory

The unledgered run-directory sweep offered a directory for removal whenever its run id was absent from the gc repository's own ledger, and the runs directory is shared by every registered project — so a gc from the reckon checkout reported 2,955 "unledgered" directories past retention, 2,776 of them rows in another mounted project's ledger. The known set is now built from every registered project's ledger, read through the same mount authority the dispatch resolver uses, and the sweep fails closed: an unreadable ledger withholds the whole sweep, reporting each would-be row with a reason naming the unreadable project. The two-project case offers only the directory no ledger holds and leaves project B's directory on disk after --apply; with B's ledger unreadable nothing is removed. The declared mutation — build the known set from the gc repository's own ledgers only — fails the two-project case with B's directory offered (EXIT=1); the head gate is 8 passed at EXIT=0.
