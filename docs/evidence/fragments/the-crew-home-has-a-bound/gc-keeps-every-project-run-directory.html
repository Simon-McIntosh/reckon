gc keeps every project's run directory

The unledgered run-directory sweep offered a directory for removal whenever its run id was absent from the gc repository's own ledger, and the runs directory is shared by every registered project — so a gc from the reckon checkout reported 2,955 "unledgered" directories past retention, 2,776 of them rows in another mounted project's ledger. The known set is now the union of the gc repository's own ledgered rows with every registered mount's, read through the same mount authority the dispatch resolver uses; the mounts contribute because a run this checkout never ledgers is still a peer project's, and the repository's own rows are carried because a repository can run workers without being a registered mount. The sweep fails closed: an unreadable ledger withholds the whole sweep, reporting each would-be row with action: "withheld" and a reason naming the unreadable project. The two-project case offers only the directory no ledger holds and leaves project B's directory on disk after --apply; with B's ledger unreadable nothing is removed; a repository that is not a registered mount spares its own ledgered directory. The declared own-ledgers-only mutation fails the two-project case with B's directory offered, and dropping the union fails the unregistered-mount case (EXIT=1 each); the head gates are 9 passed and 27 passed at EXIT=0.
