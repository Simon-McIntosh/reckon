gc sweeps ledger indexes whose checkout is gone

Every worktree resolves a different ledger path, and _run_index_path keys an index by that path, so a dispatched worktree builds a full-size index of the same project's ledger and one whose checkout is later removed is never resolved again. An index now records, in its own metadata table, the resolved ledger path it indexes: _indexed_data writes ledger_path when it builds or refreshes the index, through the same transaction as the rows, so any index a reader touches carries it. recorded_ledger_path reads that path back without creating an index, returning None for a file that is absent, corrupt or written by an older schema.

garbage_collect gains the row set ledger_indexes (with a matching ledger_indexes_removed count). It scans the pick-input cache root for ledger-*.sqlite files only, so the picker's own picker-*.json inputs in the same directory are never matched. An index recording a ledger path that no longer exists is offered outright; one recording no path is offered only once it has aged past LEDGER_INDEX_UNRECORDED_MAX_AGE_DAYS (seven days), so a reader between opening and rebuilding an index is never swept. The pass is global rather than run-scoped, so a sweep confined with --run does not reach it. Every row states its path and its size, removal happens only under --apply, and an index a live process holds a write lock on is left in place.

The declared mutation — dropping the recorded-path existence check so a recorded path is treated as gone — makes the sweep report the live index, and the head case fails (EXIT=1, test_gc_reports_and_removes_orphan_ledger_indexes). The head gate on the node's own change, tests/test_gc_sweeps_ledger_indexes.py plus the ledger, gc and picker-input cases, is 256 passed and 1 failed. The one failure, test_a_loser_of_the_write_race_cannot_overwrite_the_winner, is not this node's: it reproduces failing at the base revision 24b5ef0f with this change absent, so the delta this node adds is zero failures. The node's own four cases pass at EXIT=0. This gate measures only this node's own change; verifying the merged result belongs to a separately dispatched test node.
