What changed

load() in reckon/ledger.py now takes the index route only when the ledger it would index holds something. The new private predicate _ledger_holds_content answers true when the aggregate docs/state/<project>/crew.json exists or the runs directory beside it exists; a project with neither is a project that has run no worker, and load reads it down the uncached path that _load_aggregate already answers with the empty roster at version 0.

Before the change a read of such a project resolved _run_index_path and opened SQLite, creating ~/.cache/reckon/ledger-<sha256>-v4.sqlite for a ledger that is not there. Those files are keyed to a path whose checkout does not exist, so gc classifies each as recorded-checkout-gone and nothing removes it until someone runs a sweeping --apply. Ten such indexes of 28 KB each appeared within an hour of the backlog reclaim for projects that never ran a worker.

The narrowing matters and is the one design decision this node made. A project may hold per-run documents under runs/ and no aggregate file at all; that ledger has content, and its index is kept. Skipping on the aggregate's absence alone broke four derivation tests, which is how the shape was found.

The gate

The node's write scope grants reckon/ledger.py and no test path, so the gate is a scratch-tree measurement rather than a committed test file. Its three cases read:

  • a temporary project with no crew.json and no runs directory reads as the empty roster and writes no ledger-*.sqlite under a temporary cache root;
  • a temporary project holding per-run documents and no aggregate still builds exactly one index and returns the document;
  • a temporary project with a crew.json still builds its index.
