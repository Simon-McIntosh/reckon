The cause, in one sentence

A stored review's commit delta is taken as the two-dot git range <reviewed_head>..<head>, which after a mid-run merge of the integration branch also contains every commit main gained since the reviewed head; the composer writes that whole path list into the review node's goal, and the context census charges each named path a flat 4,000 tokens, so the review is refused as context-window-exceeded for changes its run never made.

The range site the composer reaches

The chain, with anchors at edc04fd259fa (this node's worktree base):

  1. review_head_move — reckon/crew/recovery_review_dispatch.py:1062, at :1091 calls _changed_paths_between(tree, reviewed_head, head). Its result becomes move["paths"].
  2. _changed_paths_between — reckon/crew/recovery_review_dispatch.py:937, runs git diff --name-only <older>..<newer>: the two-dot form, which for a head that merged the integration branch returns main's changes as well.
  3. _review_dispatch_fields — reckon/crew/recovery_review_subject.py:737, at :1011 appends ", ".join(delta["paths"]) to the review node's goal under “covering only the commits it gained since it was reviewed”.
  4. _mentioned_repository_files — reckon/crew/routing.py:3279, scans that goal and done_when for repository paths; _context_file_inputs (:3313) charges each mention _REFERENCE_COST_TOKENS = 4,000 (:75), and _context_fit_verdict (:3583) refuses at :3658.

The delivered-diff reader _review_delivered_paths (recovery_review_dispatch.py:1015, diff at :1039) also diffs two-dot, but on the stored record's own base/head pair — the pair the review actually read. That range is correct and must not gain the integration exclusion.

A second site takes a range off the dispatch base and is reached by the same composer: _changed_figure_paths (recovery_review_dispatch.py:966, diff at :971) diffs base_sha..head, so after a merge a figure review is scoped to main's figures too. It needs the same rule.

One site already expresses the rule the repair needs, for commits rather than paths: unintegrated_claim_work (reckon/crew/node.py:1575) runs git rev-list HEAD ^<integration_ref> ^<base_sha>.

The repair, in the form a plan section takes

Goal. A review's delta between the head a stored review read and the run's head is taken from the run's own commits, so a mid-run merge never puts the integration branch's changes into a review's scope or its context estimate.

Deliverable. One shared helper beside the existing two-dot helper — own_changed_paths(tree, older, tip, *, integration_ref) in reckon/clones.py next to changed_paths (clones.py:629) — returning the paths changed by commits reachable from tip but from neither older nor integration_ref, which is the node.py:1575 rule expressed as paths. Union the per-commit diffs of rev-list --no-merges tip ^integration_ref ^older and add any path a merge commit in that set shows in its combined diff, so a conflict resolution the run wrote is not lost. review_head_move (recovery_review_dispatch.py:1091) and _changed_figure_paths (:971) call it; _review_delivered_paths (:1039) keeps its two-dot diff and clones.changed_paths keeps its signature, because the landing measure's base arm genuinely needs the dispatch-base range.

Should the incremental review path serve this case? It already does, and the correction is what lets it: review_head_move is the incremental path (review_tier LIGHT, delta_base), and with the corrected paths this run classifies changes_runtime_source = False, so carry_review_forward carries the stored review to the merge head without composing one. No second mechanism is needed.

Test. A temporary repository with a dispatch base, a run commit, a stored review record, a merge of the integration branch carrying many unrelated files, and a further run commit: assert review_head_move(record)["paths"] names only the run's own paths, that changes_runtime_source is False for a test-and-evidence delta, and that the composed goal names no integration-branch path. Assert the estimate for the composed node is under the window.

Negative control. Restore the two-dot call in review_head_move and the test fails on the path set and on the runtime classification, not merely on the count.

Write paths. reckon/clones.py, reckon/crew/recovery_review_dispatch.py, tests/test_a_review_reads_only_its_runs_changes.py.
