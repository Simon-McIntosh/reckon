A worker can write only what it was granted

The fence dev-bound the whole filesystem writable and then overlaid the paths somebody had thought to protect, so a path nobody listed was writable. On 19 November a worker's rm -rf with a second argument nobody read took a shared project root. The fence now mounts the filesystem read-only and binds writable only the roots its dispatch handed it, so a write or a removal anywhere else fails in the kernel whether or not anybody enumerated the path.

What changed

  • reckon/_worker_fence.py: fence_argv mounts / read-only, adds --dev so a worker's device nodes still work, mounts the node's /dev/shm back read-only over the fresh devtmpfs, and binds writable only the roots it is handed. Every handed root is now granted, not only those an overlay happened to cover.
  • reckon/_worker_fence.py: declared_grant_refusal judges each declared grant before any mount exists and refuses one that names a filesystem root or a project root, naming the path. A project root is proved by asking git for the checkout's top level, so a directory carrying a bare .git marker is still a grantable directory.
  • reckon/_backends.py: fenced_write_roots raises that refusal per declared write path, and a workspace-write backend no longer re-opens the main checkout.
  • tests/test_a_worker_can_write_only_what_it_was_granted.py: eight cases: the composed argv; an executed write and recursive removal at each of a sibling checkout, the home directory, a shared project root and a removal at a path on the node tmp outside the scratch, every one refused and its target unchanged; the four roots a run may write; the two grant refusals; the incident replay; the launch_plan composition; and the empty-marker regression.

The boundary

Grants a live flight setting must declare

Everything a dispatch composes for itself is granted automatically: the worktree with its git directory and shared object store, the run directory its manifest lands in, the run's own scratch under the node tmp, the reports root and review store paths it may deliver into, its harness home, and the codex login file rewritten in place on a token refresh. A project's own outside-the-repository write surfaces are what collapse under a read-only root, so a live flight setting must declare each of these per project, with a reason, and each must be a directory a run's own work lands in:

  • the project's measurement cache, ~/.cache/<project>-<topic>/: gate and arm logs, census and population output, and every measurement a node writes on its own way to its evidence;
  • the shared package and build cache the project's environment resolves to (~/.cache/uv, and the project's own build cache where it has one);
  • the shared data root the project's workers legitimately write, such as /work/projects/<project> where a run assembles or regenerates operators, weights or fixtures.

None of these may be replaced by a broader ancestor: a repository root, a registered project root, a worktree pool or a filesystem root is refused at composition, naming the path, because a grant there re-opens whole trees a single run may then delete.
