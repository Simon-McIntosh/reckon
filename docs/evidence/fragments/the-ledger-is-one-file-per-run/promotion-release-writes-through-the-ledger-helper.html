The release path writes a run file through the ledger's own helper

_update_run_record now writes the run's file through ledger.write_run_file and keeps no encoder of its own: the direct serialize_run call and the atomic write at mode 0o600 are gone, replaced by one call to the helper the ledger made the single owner of rewriting a run's file. Mode and atomicity are unchanged — the helper's default 0o600 and durable rename are what the removed write used — so the bytes it produces are the base tree's. Both callers reach the helper, not just the release step: the release record in _record_release_on_ledger and the gate re-run in promotion_gate.py call the same _update_run_record, and a fix to either now flows through one encoder. Because a caller holds the run file's path but not the (project, root) pair the helper takes, a new private _ledger_owner_of_run_file recovers that pair from the path and checks it against the ledger's own run_path, so a layout the ledger does not recognise is a refusal rather than a write beside the file; it resolves both the checkout-rooted layout and the config-home layout.
