A failed landing's receipt never lets a cached index decide its row

A landing that fails to stage or commit rolls its own writes back, and the ledger row is one of them. The receipt raised around that landing warns against re-promoting in its "already written" branch, so a real rollback read as a surviving row forbids the one action that recovers it. The read-back chose between "rolled back" and "already written" from ledger.load, which serves the derived index and, when its refresh is refused, falls back to the last published snapshot — a snapshot that can still name a run whose per-run file the rollback has removed and whose row the aggregate never held.

Change

  • _ledger_holds_row in reckon/crew/promotion_scope.py reads the ledger with use_index=False, so the row is decided from the aggregate and the per-run files a reader will open, never from the derived index. A cached index can no longer decide the receipt.
  • The receipt's other branches are unchanged: a path the rollback preserved, or a ledger the read-back cannot open, still keeps the already-written wording.

Measure

tests/test_a_failed_landing_says_whether_its_row_survived.py passes (2 passed), logged under the run directory with the literal command, its revision and an EXIT=0 line.

  • The stale-index case: a promotion appends its per-run file, publishes the index while that file exists, then a peer's .git/index.lock refuses the staging. The rollback removes the file, the aggregate holds no row, and the index is left unwritable so the receipt's read-back is refused and served the last-good snapshot. The receipt reads "was written and has been rolled back … re-promote", the per-run file is absent, and a second promotion lands once the lock is released.
  • The aggregate-row case: a run whose row is seeded in the aggregate itself, with no per-run file, reads "already written; do not re-promote" — the durable row is present.

The declared negative control — restore the index-served read-back against the base tree — is executed and logged under the run directory: the first case fails with the received "already written" wording and a non-zero EXIT.
