A hold check commits the aggregate it rewrote

What changed. A hold transition in record_hold_checks rewrites the whole ledger aggregate, which carries run rows beside the holds, and the transition exists in no per-run file. The write was left in the tree for whichever session next noticed the dirty tracked file. The hold path now commits its own write through the shared state-commit helper the roster write already uses, under a subject naming the transition, restricted with a pathspec-limited commit to the path it wrote. While a merge is in progress (.git/MERGE_HEAD exists) no commit is made, the write is left in place and the skip is stated on stderr; a checkout that cannot answer for the write is skipped the same way, so a hold check against a state directory outside git still records the transition.
