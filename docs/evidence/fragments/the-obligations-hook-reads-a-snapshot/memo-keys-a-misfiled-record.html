The classification memo sees a misfiled review record rewritten in place

A run with no review record of its own is answered from a record a review worker filed under another run id. The classification memo's key (_review_input_identities in reckon/crew/recovery.py) held the review store's project-directory identity and the run's own candidate paths, and a rewrite of that misfiled file in place moves neither of them. The memo written before the rewrite therefore served the earlier verdict. The key now adds the per-file identity of the indexed candidates reachable under another run id whenever the run has none of its own — the same enumeration the misfiled lookup resolves through, so the key and the lookup cannot drift.

Measure. tests/test_memo_keys_a_misfiled_record.py rewrites a misfiled record in place between two classifications and asserts the second reads the rewritten verdict (promotable to scoring) and equals the memo-free arm; an unchanged misfiled record still costs no re-read. With the misfiled identity removed from the key, the in-place rewrite case is served the earlier verdict and fails again (1 failed, 1 passed, EXIT=1).
