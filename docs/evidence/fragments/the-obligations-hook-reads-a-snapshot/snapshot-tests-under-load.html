What the trace shows about the failed assertion (id 1)

The instrumented arm (loops/inst-main/trace-NN.txt) logs every sweep() call with its now, the cadence memory before and after, and the write count. One MainThread sequence (trace-41, one worker's test_a_file_change_and_the_floor_tick_each_republish): 

producer write  now=01:38:34.600161  before[none]  after[checked_at=34.600161 published_at=34.600161 identity=0]  nwritten=1
sweep_at(C+5)   now=01:38:39.600161  before[checked_at=34.600161 …]  after[unchanged]  nwritten=0   -> []          (assert passes)
sweep_at(C+15)  now=01:38:49.600161  before[checked_at=34.600161 …]  after[checked_at=49.600161 identity=1]  nwritten=1   (plan file written; identity 0 -> 1)
sweep_at(C+61)  now=01:39:50.600161  before[checked_at=49.600161 …]  after[checked_at=50.600161 identity=1]  nwritten=1   (floor tick)

The +5 call lands with margin now − checked_at = 5.000 s against STAT_IDENTITY_INTERVAL_SECONDS = 10.0: the cached branch runs, the just-written plan file is deliberately not looked for yet, nwritten=0, and the assert's [] follows — exactly as the test's comment says it should.

obligation_snapshot.sweep() takes one instant per call (instant = _utc_now() if now is None else now) and stamps it into three places: the document (document_for(…, computed_at=instant)), and the memory's checked_at and published_at on the write path. A cached call preserves both memory fields untouched. Therefore, given a single key and a single memory, at now = C + 5:

  • checked is unconditionally true (margin ≤ 5 < 10, because checked_at ≥ published_at = C);
  • with checked true, identity is memory.identity, so the identity trigger cannot fire;
  • the floor needs now − published_at ≥ 60, i.e. published_at ≤ C − 55, which a memory whose published_at is C cannot satisfy.

The assert is arithmetically safe whenever the memory the test consults is the memory the producer's sweep wrote. The observed failure (a republish returned) therefore requires the consulted memory to be absent or stale relative to the writer of first — a different process, a different home resolution, or a second module instance holding its own _SWEEPS. Two candidate mechanisms were tested and falsified; the divergence is not reproducible in 105 loop runs of this file alone.

What remains open

The failing branch needs memory is None (or a stale memory) at the test's direct sweep() call: at sweep_at(C+5), a missing memory makes due true (the first sweep of a producer always writes), which returns the written path and fails the assert exactly as the log shows. A missing/stale memory cannot arise within one process, one module instance and one RECKON_HOME (the home is set per test by monkeypatch.setenv and resolved per call). Every single-file loop I could build — with load, with xdist, with instrumentation — stays within that envelope, which is why 105 runs show zero failures. The original failure ran the whole suite: a worker there also carries the hook/watch tests, and with --dist load the per-worker file mix and import order are scheduling-dependent. The one structural difference I can name between the failing context and my loops is that context, and it is exactly where a second instance or a stale key could be born; it is not reachable from this file alone. The honest statement is: the trigger is a consulted-memory divergence, its required arithmetic is proven, the fixture is cleared, the module split is falsified, and the remaining reproduction demands the full-suite worker context.

Proposed fixing node

Two phases; the first makes the second cheap.

  1. Make the failure self-diagnosing (write paths: tests/test_obligations_snapshot_is_published.py, and optionally a read-only accessor in reckon/crew/obligation_snapshot.py). At both asserts, capture on failure: the key str(snapshot_dir(project)), the _SWEEPS entry for that key (checked_at, published_at, identity length), the resolved RECKON_HOME, the current thread names, and whether sys.modules' entry for reckon.crew.obligation_snapshot differs from the test module's instance. Done-when: the assert failure message alone names which divergence occurred, and the existing passing behaviour is unchanged (30 loops, 0 new failures).
  2. Reproduce in the true context and fix the divergence (write path: whichever file the capture names — the loader in reckon/hooks/coordinator_obligations.py, or the memory keying in reckon/crew/obligation_snapshot.py). Run the snapshot file in a worker that also runs the hook/watch tests (pytest -n 8 over a file set that includes both), ≥ 30 iterations under the same CPU load generator. Done-when: either the instrumented failure fires and names the divergence, or 30 iterations pass in that context; if the by-path loader is named, the fix is to make the loader return the canonical instance rather than replace the sys.modules entry.
