A reload shows the last snapshot, not a remedy

The reload window is one definition, PRODUCER_RELOAD_WINDOW_SECONDS in reckon/crew/obligation_snapshot.py: the follower's probe timeout, the producer's idle poll interval cap, and a scheduling margin, 65 s in total. The follower in cli.py loads the snapshot reader by file path — the way the hook already does — and reads its three figures from there, so one constant governs both the follower waiting a reload out and the hook presenting one, and neither module pays the crew facade's import.

The prompt path presents the last snapshot, headed producer reloading, last snapshot N s old and carrying no remedy line, when any of three signals holds: the snapshot's producer is alive and its code stamp is older than the source; the watch seat recorded a reload intent within the window; or no producer is live but its last publication is within the window, which is the seconds before a replacement publishes. Outside every signal the not-current line keeps its remedy, which is right there because nothing is coming. The duty digest carries the reloading state, so entering and leaving a reload each speak once while repeats inside one stay silent.

What the new test cases check

  • test_a_live_producer_on_older_code_shows_the_last_snapshot: a fresh list is injected, then the producer republishes under an older code stamp and the drive shows the last list headed producer reloading with the run id intact, no remedy, and the snapshot bytes unchanged; a third silent drive closes it;
  • test_a_restarting_producer_shows_the_last_snapshot: the recorded producer is gone and the last publication is seconds old — the brief-restart gap — and the last list is shown with no remedy;
  • test_a_recorded_reload_intent_shows_the_last_snapshot: the watch seat records a reload intent for a snapshot whose producer is gone, and the last list is shown;
  • test_an_absence_past_the_reload_window_names_the_remedy: no live producer and a last publication and intent older than the window earn the no producer line and its remedy, which no longer covers a live reloading producer.

Every case runs on the prompt path as a subprocess against a temporary configuration home. The existing cases keep passing; the one that asserted the not-current line for a live producer on older code — the reading this section reverses — now asserts the reloading header, and the reused-pid case ages its publication so it still reads as an absence.
