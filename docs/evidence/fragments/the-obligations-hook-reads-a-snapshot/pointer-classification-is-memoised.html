Pointer classification is memoised

A pointer's classification now resolves its reads through a memo persisted beside the pointer, live/<run-id>.classification.json, keyed by the stat identity of every file the classification reads. The pointer, the manifest, the stream the observation consumes, the run directory's own exit.json, worker.json and attempt.json, and the review store's candidates for the run are all in the key. So is the worktree's head, read as the git directory's HEAD and the ref it names rather than through a subprocess — a review is selected against the revision the tree carries now, and a memo written before a commit would otherwise report a review of code the run no longer holds. The review store's project directory is keyed on the time its entries last moved, and whether the run has a record at one of its own paths is a key contribution in its own right, because a record that appears where the last classification found none moves the answer from a store listing to a file read.

A key that still matches serves the memo: the manifest text, the stored review and the stream observation. A key that has moved recomputes. Liveness is never served from a memo — a process table is not a file, and the row is still built from a reading taken now.

Stream observation resumes from a byte offset persisted in the same memo. The dialects' event folds take and return their state, as does the timestamp split that refines throughput, so observe_log reads only the records written past the offset and extends the previous fold rather than repeating it. One classification also used to parse the same stream twice — the budget gates and the background-wait signal each read it for a different question; both now share one observation.

Measurement.
