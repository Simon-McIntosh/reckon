A sweep thread ends with the test that started it

The producer starts an obligations sweep on a daemon thread off its own transition path and never joins it, so a sweep one test triggers can still be running while the next test has replaced the modules it reads. join_watch_sweeps in reckon/crew/runs.py (bound WATCH_SWEEP_JOIN_SECONDS = 10.0) joins every registered producer's in-flight sweep, returns the names still running past the bound, and clears _WATCH_STREAM_PRODUCERS. An autouse fixture in tests/conftest.py calls it after every test and then joins any live thread whose name starts reckon-obligations-sweep, because a producer that lives inside the watch claim is popped from the registry when the claim exits; a straggler fails the test by name. tests/test_a_sweep_thread_ends_with_its_test.py: one case starts a watch transition whose sweep holds in flight past the end of the test, the next replaces the ledger decoder with a refusal and asserts no sweep thread exception reaches it, and the third calls the helper directly and asserts stragglers == [], an empty registry and no live sweep thread.

The surviving actor is not a thread. A lifecycle probe over tests/test_obligations_snapshot_is_published.py then tests/test_append_run_writes_one_run_file.py in one xdist worker logs each sweep's start and end with the test active at each: all eight sweeps begin and end inside the test that started them, the last one ending 0.6 s after the fixture's 10 s join begins, and no sweep thread exists in any append window. The four append teardown errors reproduce with threading.excepthook observed and never firing. Capturing the caller of each forged guard names reap_watch_producers_armed_by_this_test reading /proc/<worker-pid>/environ via _named_config_home and json.loads(record.read_text()) via _record_pid — its per-test seat-record walk reading the mirror preserve_seat_records keeps for the session-end reap, through the append tests' own process-global forgeries. The verdict depended on which test ran next, and the sweep was never the cause.

The rule now held. State mirrored for a session-end reader is hidden from the per-test reader: seat_records_mirror_is_hidden_from_the_running_tests moves _seat-records outside the run's root at every test's setup — outside, not renamed inside, because the reap looks for crew/watch directories anywhere under the root — and seat_record_mirror_is_restored_for_the_session_reap puts it back from a finalizer that the session-end reap outlives. Both fixtures sit beside the guards another session added and change none of them; the session-end reap still reads every mirrored record.
