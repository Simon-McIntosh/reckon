A sweep thread ends with the test that started it

The producer starts an obligations sweep on a daemon thread off its own transition path and never joins it, so a sweep one test triggers can still be running while the next test has replaced the modules it reads. join_watch_sweeps in reckon/crew/runs.py (bound WATCH_SWEEP_JOIN_SECONDS = 10.0) joins every registered producer's in-flight sweep, returns the names still running past the bound, and clears _WATCH_STREAM_PRODUCERS. An autouse fixture in tests/conftest.py calls it after every test and then joins any live thread whose name starts reckon-obligations-sweep, because a producer that lives inside the watch claim is popped from the registry when the claim exits; a straggler fails the test by name. tests/test_a_sweep_thread_ends_with_its_test.py: one case starts a watch transition whose sweep holds in flight past the end of the test, the next replaces the ledger decoder with a refusal, scoped to its own body, and asserts no sweep thread exception reaches it, and the third calls the helper directly and asserts stragglers == [], an empty registry and no live sweep thread.

The surviving actor is not a thread.
