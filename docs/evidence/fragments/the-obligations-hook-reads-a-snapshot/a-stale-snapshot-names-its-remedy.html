A stale snapshot beside a live lease names its own follower

A session's snapshot is republished only while that session has a live follower, so a coordinator that stopped its follower keeps reading a list that ages out while the project's producer is healthy and publishing every other session. The not-current line answered that reading with the seat command, which reports the seat is held and refreshes nothing. not_fresh_line in reckon/hooks/coordinator_obligations.py now names, for a stale snapshot beside a live producer lease, reckon crew follow --project <p> --session <s> — this session's own follower arming. A lapsed or absent lease keeps reckon crew watch --ensure --project <p>, as does every other not-fresh state and the reload reading, which never reaches this line for a live producer.

Liveness is read from the lease record the seat writes on claim and every live follower renews on its wait pass, <config home>/crew/watch/<stem>.lock.registration: lease_renewed_at inside the lease interval is a live producer as a reader can see it, with no process probe added. The hook carries its own copy of the 600 s interval, because the watcher's module is not imported on this path; two cases pin that copy to the watcher's own figures (default and RECKON_PRODUCER_LEASE_SECONDS) and one pins the lease path to the writer's, so the two cannot drift.

What the new test cases check

  • test_a_stale_snapshot_beside_a_live_lease_names_the_follower: a released follower registration, a snapshot 900 s old whose recorded producer is the live test process, and a lease renewed this instant — the line names the follower arming and not the seat. The stale age is asserted beside it, so the case cannot pass by falling into the no-producer branch;
  • test_a_stale_snapshot_beside_an_expired_lease_keeps_the_seat_remedy: the lease is a full interval behind and the seat command stays;
  • test_a_stale_snapshot_with_no_lease_keeps_the_seat_remedy: no lease record at all keeps the seat command;
  • test_the_lease_reader_looks_where_the_seat_writes: the hook's lease path equals runs.watch_registration_path;
  • test_the_lease_interval_mirrors_the_producers: the hook's interval and its override behaviour match runs's.

Each drive is a subprocess against a temporary configuration home built per case — mount, registration, snapshot, lease — so no case reads or writes the operator's state.
