A skipped review record reaches the coordinator's checklist

The sweep records a path it could not read under findings in the published snapshot document, but live_payload — the reader the prompt and stop hooks render — dropped that key, and payload_for never turned a finding into a duty, so a coordinator read a checklist that named no skipped record at all.

payload_for in reckon/crew/obligation_snapshot.py now appends one row per finding under the kind unreadable-review-record, and live_payload rebuilds those rows from the stored findings key — dropping any echoed row of that kind first — so the writer and the reader render the same row and both parity checks extend to it. The parity case in tests/test_skipped_record_reaches_the_checklist.py asserts the two readings are equal. In the same file, _parse_instant now reads through reckon._timestamps.parse_utc, keeping the no-zone-is-UTC policy, imported where it is used because the hook loads the module by path.

In reckon/crew/review.py, stored_record hands the records it skipped to its caller — or to the region a collect_read_failures caller opened around the read, which fleet_state opens — in place of the module-level _SKIPPED_RECORDS list and drain_read_failures, so a read made outside a sweep is nobody's finding and cannot reach a later sweep's snapshot.
