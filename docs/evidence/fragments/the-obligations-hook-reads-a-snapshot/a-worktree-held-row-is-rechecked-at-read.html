Landing: a worktree-held row is rechecked at read

The hook now rechecks each worktree-held row where it is offered, against the run's committed record and the tree on disk, so a promotion that released its tree between the sweep and the read no longer offers housekeeping whose own remedy is refused.

What landed

  • reckon/hooks/coordinator_obligations.py — the prompt and stop paths pass the live payload through recheck_worktree_held_rows, which resolves a row's run from the project mount (state/<project>/runs/<run_id>.json, falling back to the aggregate's row) and drops the row when the record shows release.worktree_released or the recorded tree is no longer a directory. A row whose record cannot be read is kept, so an unreadable file never becomes a silent omission. One stat per row.
  • tests/test_a_worktree_held_row_is_rechecked_at_read.py (new) — drives a real crew complete, captures the session snapshot from inside the promotion at the instant the row is still a true reading, keeps that snapshot for the hook, and asserts the released row is not offered. Three companion cases: a retained tree is still offered, a vanished tree is not, and a recorded release decides even when a directory reappears at the released path.
