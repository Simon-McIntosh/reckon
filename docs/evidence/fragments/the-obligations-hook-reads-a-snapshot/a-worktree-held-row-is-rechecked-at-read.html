Landing: a worktree-held row is rechecked at read

The hook now rechecks each worktree-held row where it is offered, against the run's committed record and the tree on disk, so a promotion that released its tree between the sweep and the read no longer offers housekeeping whose own remedy is refused.

What landed

  • reckon/hooks/coordinator_obligations.py — the prompt and stop paths pass the live payload through recheck_worktree_held_rows, which drops a worktree-held row when the run's per-run record under the project's own state directory shows release.worktree_released, or when the tree that record names is no longer a directory. One stat per row.
  • Only the run's per-run file is read. The aggregate ledger beside it gathers every run the project has ever promoted; the one under docs/state/reckon/crew.json measures 81,049,967 bytes and the fastest of three parses took 0.649 s, so resolving a row through it would spend a large fraction of a hook's few seconds on a single row. A run with no per-run file therefore answers no evidence about its tree and the row is kept, which is also why an unreadable record never becomes a silent omission.
  • tests/test_a_worktree_held_row_is_rechecked_at_read.py (new) — drives a real crew complete, captures the session snapshot from inside the promotion at the instant the row is still a true reading, keeps that snapshot for the hook, and asserts the released row is not offered. Four companion cases: a retained tree is still offered, a vanished tree is not, a recorded release decides even when a directory reappears at the released path, and a row whose run has no per-run file is still offered while its tree is on disk.
  • Every case drives the hook with a refusal armed in the hook's own process: pathlib.Path.read_text raises on any path named crew.json, so opening the aggregate fails the case rather than returning an error the reader would swallow. The helper asserts the refusal arms before the drive, so a case cannot pass by having installed nothing.
