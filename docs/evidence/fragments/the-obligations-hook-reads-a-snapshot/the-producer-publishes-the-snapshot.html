The producer publishes each session's obligations snapshot

The watch producer now recomputes every registered session's obligations() payload and writes it to <config-home>/crew/obligations/<project>/<session>.json, by a temporary file renamed over the old one, so the prompt hook that reads it does one stat and one small JSON read instead of deriving. A new module (obligation_snapshot.py) carries the atomic writer, the reader, the freshness rule and the three triggers — a pointer transition the producer already detects, a per-file stat change under the project's state and plan directories, and a sixty-second floor tick. Ages are stored as the instant each is measured from rather than a count of seconds, so a snapshot never shows a frozen age; the reader recomputes them at read time.

The derivation reads live pointers through the same list_live that publishes, so the first case written against the wiring met a RecursionError: every sweep with a registered session re-entered itself. The producer now records that it is inside a sweep and lets the reads it performs report to their caller. Producer identity — pid, process start time and the code stamp of the running source — is read from the lease registration, with the stamp written back when the registration does not already carry the one this process computes, so a producer that took the seat over from a stale one is not reported as stale.

The six cases the new file adds

  • a pointer transition is visible in the session's snapshot by the end of the first sweep after it, with the sweep driven explicitly and the stream offset advanced;
  • the stored snapshot equals obligations() over the same unmodified files — the parity case — with both derivations read at one instant and compared at the snapshot's own computed_at, so the ages are compared too;
  • a writer stopped between its temporary file and the rename leaves the previous snapshot whole, readable, and its temporary behind;
  • each freshness outcome for its case — fresh, no-producer, producer-stale-code, stale-snapshot — including a pid that is alive but carries a different start time, which is the reused-pid case;
  • the file-stat trigger and the floor tick each republish while an inert sweep leaves the snapshot alone;
  • a fresh subprocess importing the module pulls in no derivation module.

The import case loads the file by path, because importing it through reckon/crew.py runs the facade, which eagerly imports every concern module and would report the derivations whatever this module itself reaches. The module's own imports are stdlib only — __future__, hashlib, json, os, re, time, collections.abc, dataclasses, datetime, pathlib, typing — naming no reckon module at all, and the derivation is imported inside sweep() and nowhere else.
