The producer publishes each session's obligations snapshot

The watch producer now recomputes every registered session's obligations() payload and writes it to <config-home>/crew/obligations/<project>/<session>.json, by a temporary file renamed over the old one, so the prompt hook that reads it does one stat and one small JSON read instead of deriving. A new module (obligation_snapshot.py) carries the atomic writer, the reader, the freshness rule and the three triggers — a pointer transition the producer already detects, a per-file stat change under the project's state and plan directories, and a sixty-second floor tick. Ages are stored as the instant each is measured from rather than a count of seconds, so a snapshot never shows a frozen age; the reader recomputes them at read time.

The derivation reads live pointers through the same list_live that publishes, so the first case written against the wiring met a RecursionError: every sweep with a registered session re-entered itself. The producer now records that it is inside a sweep and lets the reads it performs report to their caller. Producer identity — pid, process start time and the code stamp of the running source — is read from the lease registration, with the stamp written back when the registration does not already carry the one this process computes, so a producer that took the seat over from a stale one is not reported as stale. The freshness check also asks whether the recorded process is still running, so a producer that exited and has not been reaped no longer holds a snapshot fresh.

The sweep is bounded to what the fleet is owed. Only registrations list_followers marks live are published for — two of fifty on the real fleet while this measurement ran — and the fleet-wide derivation (classified rows, acknowledgements in force, the resolved configuration, each run's review in flight) is computed once per sweep and then sliced per session. The per-file stat trigger is evaluated at most every ten seconds and no longer walks a state directory's runs/ subtree, whose changes arrive as pointer transitions already.

Warm against the real fleet the slice was still the expensive part: payload_for cost about 7 s for one live session and 14–15 s for two, because each slice re-selected every run's review (subprocesses against the run's tree), re-read the ledger for the held-worktree scan, and re-classified every live pointer for the closure drain — once per session. Each of those derivations is now the fleet's: computed once per sweep and sliced per session. Measured warm, read-only against the real fleet, in sweep-profile.log: payload_for is under 0.01 s and fleet_state, now carrying the whole derivation, takes about 18 s once per sweep — which is why the sweep itself runs on its own thread. A transition is written the moment it is detected and never waits on the derivation, at most one sweep is in flight, and a trigger arriving while one runs is skipped rather than queued.

The eleven cases the new file adds

  • a pointer transition is visible in the session's snapshot by the end of the first sweep after it, with the sweep driven explicitly and the stream offset advanced;
  • the stored snapshot equals obligations() over the same unmodified files — the parity case — with both derivations read at one instant and compared at the snapshot's own computed_at, so the ages are compared too;
  • a writer stopped between its temporary file and the rename leaves the previous snapshot whole, readable, and its temporary behind;
  • each freshness outcome for its case — fresh, no-producer, producer-stale-code, stale-snapshot — including a pid that is alive but carries a different start time, which is the reused-pid case;
  • the file-stat trigger — on its ten-second cadence, so a change just after a sweep is not looked for until the cadence passes — and the floor tick each republish, while an inert sweep leaves the snapshot alone;
  • a fresh subprocess importing the module pulls in no derivation module;
  • only a live registration is published for — a released registration left in place gets no snapshot while the live session does;
  • a slice equals obligations() over the same files, field for field, which is the parity case for the derive-once slice;
  • the stat walk skips a state directory's runs/ subtree and still walks a file beside it;
  • a producer that exited and has not been reaped does not hold a snapshot fresh;
  • a sweep in flight is skipped over: a delay injected into the sweep, and the next transition is still written while it runs — the slow-sweep case.

The import case loads the file by path, because importing it through reckon/crew.py runs the facade, which eagerly imports every concern module and would report the derivations whatever this module itself reaches. The module's own imports are stdlib only — __future__, hashlib, json, os, re, time, collections.abc, dataclasses, datetime, pathlib, typing — naming no reckon module at all, and the derivation is imported inside sweep() and nowhere else.
