Landing: a held tree is named by its record, not its run id

Lands the code half of the entry: the held-worktree fast path no longer selects a per-run file by the node token in its run id. Every per-run file the aggregate does not carry is read once per call and matched by the record's own two namings — the retained path and the node id — which is how the merged reader decides, so a record whose node id differs from its tree's directory name resolves to the same run the whole-ledger reader picks.

What landed

  • reckon/crew/obligations.py — _holding_record takes the per-run records the aggregate does not carry and matches each against the tree by _names_worktree alone; the _run_id_names_node token test is gone, because a run's node id need not equal the tree's directory name, so a file's name cannot tell whether its record names the tree. _held_worktree_records reads each such file once for the call, in the same order the merged reader appends them, and the run the merged ledger's own order puts last holds the tree. A file whose row the aggregate already holds is still never opened.
  • tests/test_held_worktrees_read_run_files.py — a sixth generated mixed state, node-id-differs-from-tree-name: one run dispatched for alpha-holds and a later run dispatched for beta-holds whose retention names the same tree, both file-only. The later run holds the tree in the whole-ledger read.
