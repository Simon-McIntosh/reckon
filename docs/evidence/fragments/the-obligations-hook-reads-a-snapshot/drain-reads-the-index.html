The drain answers the plan remainder from the metadata index

runs._project_executable_remainder walked the resource tree and read and parsed every plan on each call, so a closure drain paid the whole project's parse cost before it could answer. It now reads metadata_index.plan_derivations, one record per live plan file — 145 of the 148 plan files in this repository, the other three being archived. The index revalidates each row with one stat of its plan file and parses only a plan whose stat identity moved, so a fresh process re-reads no plan whose content has not changed.

Each plan row gains the two figures a drain reads — the plan's open-followup count and its implementable-section count — derived once as the row is built and persisted in a plan record beside the served fields, so ROW_FIELDS and the /_index payload are unchanged. The entry schema version moves with the shape, so an index written by the previous shape is rebuilt rather than reused with the figures absent. A plan file that cannot be read yields a record flagged unreadable, and the drain reports the remainder and its uncovered count unknown while any live plan is unreadable; that record is not persisted, so the row is rebuilt on the next call and the inventory is known again once the file can be read.

Gate and negative control

The gate runs the new test, the two other index tests and every test file that calls runs.drain, at the base revision and at the head revision: the base arm (gate-base.log) passes 344 tests and the head arm (gate-head.log) passes 349, the five extra being this node's new file. The head arm adds no failure id. A first head pass recorded test_crew.py::test_second_project_watch_reports_the_live_watcher failing on a five second wait for its own sleeper while measurement arms ran beside it; the quiet re-run passes it, and the id is unrelated to the plan inventory this node touches. The declared negative control replaces the index reader with the read-every-plan rule; its run (negative-control.log) fails the no-plan-changed case along with the two other cost cases, exactly the behaviour it declares.
