The offered promotion command for a read-only run is one crew complete accepts

A read-only run — an investigation that changed no repository file — records its dispatch base as its only commit, because its manifest must name one and the base is what its worktree sits on. The recovery classifier's promotable branch read that citation back and offered crew complete --run <id> --gate <verdict> --commit <base>, which promotion refuses: a citation of the base predates the run, so it would record landed work that is not the run's. The offer the obligations hook relays, and the command promotion accepts, disagreed about what a read-only run's promotion is.

The promotable branch of classify_pointer in reckon/crew/recovery.py now compares the run's resolved commits against the pointer's dispatch base. When the only commit equals the base, the offer is reckon crew complete --run <id> --gate not-run --no-commit '<why the run produced no commit>' --outcome '<what the run produced>' — the commitless declaration promotion accepts, with both placeholders carried as literals. A run with a commit of its own keeps the citation list unchanged. The obligations hook copies the classifier's action verbatim into next_command, so one edit repairs both surfaces.

What the new test cases check

  • test_the_offered_command_for_a_read_only_run_promotes_it: a temporary RECKON_HOME and repository hold a complete read-only run whose only recorded commit is its base, with an attached review keyed by that head. The classifier's next_action is taken, split, and filled at its two placeholders only, then run through the CLI — the run promotes: exit 0, the pointer is gone, the ledger row records commits: [] and the --no-commit reason, and the --outcome text lands as the run's landing comment on the plan (the row defers the narrative to the comment, as promotion does for every run). The offer's shape (--gate not-run, --no-commit, --outcome, no --commit, no base sha) is asserted after the exit status, so a base revision's offer reports its refusal rather than a shape mismatch;
  • test_a_run_with_commits_beyond_its_base_still_gets_its_commit_list: the same drive for a run that committed on top of its base — the offer cites the head with --commit and carries neither --no-commit nor --outcome.
