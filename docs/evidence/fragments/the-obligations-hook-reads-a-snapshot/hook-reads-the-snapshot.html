The prompt hook reads the session's published snapshot

The prompt path now reads what the watch producer published instead of deriving. It resolves its session as before, then loads reckon/crew/obligation_snapshot.py by file path (importlib.util.spec_from_file_location, registered in sys.modules before exec_module) because reaching it through reckon/crew.py would run the crew facade, which eagerly imports every concern module, the three derivation modules included. Session resolution reads the follower registrations directly (read_followers, the same registration directory runs writes, mirroring follower_lock_path for the digest file) so no part of the prompt path imports the crew package. A fresh snapshot goes through the hook's existing formatting, injection and digest unchanged — including the local-lane rewrite of a printed dispatch — and its ages are recomputed at read time from the stored measurement instants.

A snapshot that is not fresh is answered by one line naming the reason and the remedy, reckon crew watch --ensure --project <project>: no producer (nothing published, or the recorded pid is gone or reused), the producer is running older code, or the snapshot is N s old. The hook never writes the snapshot file, and it exits 0 on every path. The stop path is untouched by this node and still derives at the moment of the stop. The measurement target for a turn's opening is under 250 ms; the 20-run figure below is 112.7 ms (second-slowest of 20).

  • each not-fresh reason emits exactly one line naming the reason and the remedy, and the snapshot file is byte-identical afterwards — including the never-published case, where no file exists before or after;
  • a pid that is alive but carries a different start time from the one recorded reads as not fresh, with the same pid and the true start time reading as fresh immediately before it;
  • a fresh snapshot is injected as the derived checklist is, ages normalised, and a repeated drive is silent (the digest);
  • a snapshot naming a duty the live fleet does not have is injected as it stands, and the fleet's own run id does not appear — the list comes from the file, not a derivation.
