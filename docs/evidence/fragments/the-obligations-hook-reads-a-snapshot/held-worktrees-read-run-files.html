The held-worktree obligation reads one ledger file per run

obligations._held_worktrees called ledger.runs(project, root=repository) before it looked at a single tree, so the derivation paid for every recorded run of the project whatever it went on to inspect. Each tree it inspects is now resolved from the per-run ledger file (docs/state/reckon/runs/<run_id>.json) of the run that named it, selected by the node id a run id carries — runs.new_run_id mints r-<stamp>-<node id> — and the record read from that file is matched under the same two rules as before, the retained path and the node id. A tree no per-run file names falls back to the whole ledger, which is where a run recorded before the ledger was split into one file per run lives, and that read happens at most once per session. The derivation builds no index and persists nothing.

Parity and the fallback on the real fleet

The head derivation was compared with the whole-ledger scan it replaced for every session that holds a registered worktree: 25 sessions compared, 0 mismatching run ids (parity-real-fleet.log). All 52 inspected trees across the 24 sessions with work resolve through the fallback today, because every one of them is held by a run recorded before the ledger was split into per-run files (fallback-share.log): no per-run file carries those node ids, so the fallback is the path, and the fast path takes over as post-split runs accumulate retained trees.

Gate and negative control

The gate runs the new tests/test_held_worktrees_read_run_files.py and every test file calling _held_worktrees or obligations(, at the base revision in an extracted tree (gate-base.log: 50 passed, 2 failed) and at the head revision in the worktree (gate-head.log: 51 passed, 1 failed). Each log's header names the module under test as the arm imported it — the extracted tree for the base arm, the worktree for the head arm — and the base arm is the one that fails the never-called case, which is what importing the base module and not the head one predicts. The head arm adds no failure id. The one failure in both arms, test_crew_obligations.py::test_obligations_reads_scoring_without_observing_or_dispatching, reproduces alone on the untouched base tree (gate-base-unrelated-failure.log) and is a metadata-index cache write inside obligations(), outside this node's change. The declared negative control restores the whole-ledger load in _held_worktrees; its run (gate-negative-control.log, EXIT=1) fails the never-called case and the fallback case, which is the behaviour it declares.
