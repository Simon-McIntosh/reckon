A late acknowledgement and an unreadable record do not hold a stop open

Two ways the stop hook refused on a list the fleet no longer owed. First, crew ack records its deferral on the run's live pointer and republishes nothing, so a snapshot computed seconds before the ack went on listing the deferred duty until the next sweep. _stop now re-reads the deferrals in force at the moment it would refuse — obligations._acknowledgements_in_force and _partition_acknowledged applied to the fresh snapshot's list — and refuses only on what is still owed. The acknowledgement's own deadline bounds that reading: an expired deferral is not in force, so the duty returns to the list and the same snapshot blocks again.

Second, a review record the sweep could not read travels in the snapshot as a finding and the reader renders it into the duty list under unreadable-review-record. That kind joined _NON_BLOCKING_KINDS beside review-queued: it reaches the checklist, and it no longer asks a coordinator to act on a file caught mid-write.
