A request on another lane now carries the reason no pass launches it

What changed. The admission pass narrows the queue to the lane it drains, and a request queued on any other lane was dropped by that narrowing with nothing recorded for it: no verdict row, no hold on the request, no launch attempt. A coordinator reading such a request could not tell it apart from one nothing had looked at, which is the state three requests on the metered lane sat in for 25 to 60 minutes. admit_once in reckon/crew/queue_admission.py now records an admission attempt on every queued request its lane filter leaves out — a held-on-other-lane pass hold naming the lane the request is queued on and the lane the drainer serves, in the pass result and on the pointer — so a request on any lane either launches once its waits are met or is refused at once with a readable reason.

The cause, and what the record shows. The three cited requests (r-20261111T162051424939-fixture-tolerance, r-20261111T162227953552-signed-pulse-bounds, r-20261111T192521253689-edge-train-overshoot) are no longer in the crew home: their live pointers were discarded before this node ran, and neither the run store nor the admission verdict log retains them. The cause is therefore established from the code path rather than from their own records. Two facts narrow it. Every other way a pass leaves a request alone writes a hold, a failure or a verdict row — the allowance hold, the gate hold, the claim hold, the retry back-off, the earlier-overlap hold, the plan-review hold, and the launch refusal all record themselves. The lane filter records nothing, and it is the only step that removes a request from the pass's view. A request whose recorded backend is not the lane the drainer runs, in a flight that does not name that drainer's lane as the project's local lane, is therefore queued forever with no attempt recorded.

Honest limit of this finding: under the live flight (local_backend: clive, service crew admit --lane clive) the filter's second clause does include metered requests, so the filter alone does not explain every one of the three under that exact configuration. What this node proves is the hole itself — the one exclusion that strands silently — and it closes it so that the state cannot recur unnoticed on any lane.
