A batch entry's context fit is judged at queue time

A batch entry is measured against the window of the lane it resolves for before any pointer is written, so a request that cannot fit is refused in its own batch row, naming the estimate and the window, instead of sitting in the queue until the first launch attempt refuses it on a pointer nobody is watching. This node found the behaviour already present at its base revision c2438582d1 — node_context_fit_finding in reckon/crew/dispatch_admission.py and its call in _queue_batch before queue_one — together with the test the section names. It therefore verified the behaviour rather than reimplementing it: the arms below are this node's own runs at this revision, and the declared negative control was re-applied and reproduced red.

The measurement is the router's own fit verdict (routing._context_fit_verdict), reached through a four-field stand-in for the resolved dispatch it normally reads, so the queue-time figure and the launch-time figure cannot disagree about which window gates the request — the minimum of the lane's declared usable_input_window and its recorded effective_input_window. A path declared with --regenerate-path is charged the flat reference cost instead of its size, which is what distinguishes a node rewriting a large generated record from one loading it.
