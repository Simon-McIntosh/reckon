A refused request names its refusal in its obligation

Admission re-tests a queued request on every pass, and a request refused on its node contract fails the same check every time: a lane slot never clears it. The classifier reads a refusal only when a session-subject class or a quoted remedy says whose condition the refusal is, so a plain node-contract refusal left the request on the waiting reading — run-queued, "waiting for a lane slot, position 1" — with the refusal sitting unread in the pointer's failure. One project's sections sat unlaunched for the better part of an hour behind that reading.

The row now carries its own kind, queued-contract-refused. _classified_rows attaches the refusal's remedy to the classified row, which is the one place both producers of a session's duty list read: the derivation and the snapshot slice a sweep publishes, which calls the same helper. _queued_contract_refusal reads the failure's stamped text, leaves a lane hold, a full queue, a scope conflict and a capacity refusal on the waiting reading, and takes the failing property names from the refusal's own rendering. A refusal naming only fields reckon crew queue edit can set (single-goal, fully-specified, demonstrable, scoped, bounded) publishes reckon crew queue edit --run <id>, which keeps the request's place. Any plan-owned property (spec-level, negative_control, independently-verifies) leaves nothing an edit can set, so the row publishes reckon crew queue drop --run <id> and its reason says to repair the section and dispatch it again.

Reproduced before the repair: on the base revision with the new test alone, all three cases failed, EXIT=1, the refused pointer reading assert 'run-queued' == 'queued-contract-refused'. After the change: 3 passed, EXIT=0.

Population, one arm at a time at -n 4 over the 55 test files that import reckon.crew.obligations: head 2 failed / 314 passed, base 2 failed / 311 passed, the failure sets identical (test_obligations_reads_scoring_without_observing_or_dispatching and test_the_prompt_path_loads_no_derivation_module), so the change adds no failure. The 3-test difference is this node's own new test.

Negative control, the declared mutation — failure ignored inside _queued_contract_refusal so the pointer's failure is never read: 1 failed, 2 passed, EXIT=1, the refused request collapsing to run-queued. ruff check and ruff format --check report no finding on the staged paths.
