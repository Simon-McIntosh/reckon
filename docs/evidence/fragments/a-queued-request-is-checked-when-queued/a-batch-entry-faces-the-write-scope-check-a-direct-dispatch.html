A batch entry faces the write-scope check a direct dispatch does

A direct dispatch runs _require_write_paths_in_authority while planning, so a write path outside the work repository, the repositories the dispatch authority registers and the durable delivery directories is refused before anything is launched. dispatch.queue_requests judged a batch entry by the node contract and the admission domain only, so the same node was refused singly and queued in a batch — and a request in that state can never launch. The function now resolves the dispatch authority for the entry and runs the same fence before any pointer is written, so the batch row carries the refusal sentence the direct path emits, naming the same path and the same rule.
