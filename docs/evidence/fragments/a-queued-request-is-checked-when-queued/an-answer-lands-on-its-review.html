An answer lands on the review that raised its finding

Reviews stored at successive plan commits record the server-managed plan_version scalar, which is not monotonic: a plan restated from version seven to three to five carries reviews whose version integers run against the commit order. Selecting the covering review by the largest version therefore serves an older review, and an answer written without --review-run lands on it instead of on the review that raised the finding.

The covering set is reduced by the plan commits the reviews read. _newest_by_plan_commit places each record against the current newest with _record_is_newer, which asks _commit_is_ancestor — the velocity module's own ancestry probe, not a second git call — and falls back to the review's timestamp when either commit is unreachable or the two have diverged. read_plan_review returns that record, so crew view plan-review serves it; reckon crew review --answer reduces the raisers of the named finding with newest_covering_review, so the answer lands on the same one. --review-run searches every stored review of the plan for the finding before the absence of a covering review is reported, so a review that no longer covers the plan still answers the finding it raised; the refusal fires only when no listed raiser carries the named run id, and it names the raisers it did find.
