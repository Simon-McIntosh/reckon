An answer lands on the stored review whose finding it names

A plan review records the plan version it read, and that integer is bumped by every metadata write rather than only by an authored edit. Reviews stored at successive plan commits therefore carry equal or non-monotonic versions, so reducing a covering set by the largest version served a review older than the plan's latest one: a reader was shown findings the newest review had already replaced, and an answer naming the newest review's finding could not reach it at all. Both the view and the answer now choose by the order of the plan commits the reviews read.

plan_review gains _record_plan_commit, _commit_is_ancestor, _record_is_newer, _newest_by_plan_commit and _records_oldest_first. Ancestry decides between two recorded commits, and a review whose commit is unreachable, or which has diverged from the other, falls back to its own timestamp so a store with no checkout still answers. An ancestry answer comes from the velocity module's own merge-base reader rather than a second copy of the git call, and it never changes, so it is held in the review read pass beside the record reads already held there; an admission pass asks the same question once per queued request over the same store. The covering predicate orders its records by the same key before it judges units, and both places that reduced a covering set by the version integer now use the one selector.

The answer verb searched for a named review only among the newest covering record and the design review, which is exactly the pair that cannot contain a review the caller named because it is not the newest. --review-run now searches every stored review of the plan for the finding before the absence of a covering review is reported, so a review the caller named still answers its finding once the plan has moved past it and nothing covers the plan; the refusal still fires only when the named review does not raise the finding. An unnamed answer is unchanged: it lands on the newest covering review, which after this change is the one at the newest plan commit.
