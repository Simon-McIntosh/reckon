A batch derives an absolute write path absolutely

_PlanRead.write_paths keeps a leading slash. _PATH_TOKEN now accepts an optional leading /, and the trailing-punctuation strip no longer removes it: only a leading ./ relative prefix is dropped, so the sentence "Write paths: /abs/data/record.json" derives exactly that path instead of abs/data/record.json. A repository-relative path is derived as before. The same method then refuses, at queue time and inside the code that still holds the sentence, a derived path that is neither absolute nor present, nor inside a present directory, under the dispatched repository; the refusal names the path and the sentence it came from, and _entry_node passes it through so the batch row reports that entry refused while the rest of the batch is queued. This is the defect measured on 8 November: a dropped slash turned an absolute record path into a repository-relative one that resolved nowhere, the fence left the real directory read-only and the worker's write failed with EROFS.
