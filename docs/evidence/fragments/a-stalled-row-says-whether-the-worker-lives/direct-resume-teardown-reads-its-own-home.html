The direct-resume cases prove their no-write claim by a path only they create

What changed. The home fixture in tests/test_direct_resume_needs_an_observed_death.py resolved the crew home to a temporary directory and then proved the case wrote nothing to the real one by fingerprinting that home's entries and their mtimes before and after the case. The real crew home is live — the fleet writes into it while the case runs — so that reading moved under the fleet's hand and the case failed intermittently with no code change to explain it. The isolation and the assertion that pins it (assert runs.crew_home().is_relative_to(tmp_path)) are unchanged. The no-write proof is now the absence, read after the case, of the run directories and live pointers named for the run ids this file mints: a real run id carries its launch timestamp, so those names are ones only this test creates and no fleet write can move them. No other assertion changed; the fingerprint helper was removed with the reading it served.
