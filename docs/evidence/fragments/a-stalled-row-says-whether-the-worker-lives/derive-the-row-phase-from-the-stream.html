A working run reads working within one poll

A run's row state was read from the pointer's stored phase, which only a stream fold advances, so a worker that had been thinking and editing for an hour kept the pre-spawn label its launcher wrote and rendered as dispatched until somebody folded its stream by hand. The phase is now derived from the run's own newest stream, and a record of type assistant there reads as working.

What changed

PieceBehaviour
_newest_stream_shows_workAsks the module's shared newest-stream reader — the same one the stall clock uses, so neither can disagree about which file is the run's current one — and reports whether that file holds an assistant record. A resumed turn's resume-*.jsonl and a lane change's lane-change-*.jsonl are reached by that reader rather than by name.
_observed_phaseConsults the stream last, after the terminal-manifest, exit-record and worker-record arms, so a stronger answer always decides first. Only a stored phase that is still pre-spawn is ever asked about, which is the one reading the answer can change.
Row keysphase now carries the derived phase and the launcher's label is kept beside it as stored_phase, so a reader sees why a run left the pre-spawn bucket without anything having run a fold.
Live readoutreckon/mcp_views.py needed no change: the live row is the classifier's own projection, so it carries the derived phase under phase. Case 4 asserts that, so the pane and the tool agree rather than only appearing to.

What this does not reach

The live readout and the watcher's rows both carry the derived phase. The command-line fleet listing renders the pointer's own phase field, so for the same run it still reports the launcher's label — the stored label beside it is what makes the disagreement legible rather than silent. That surface is outside this change and is reported to the coordinator to schedule rather than widened here.

The refusal, made to happen

A suite passing at the change does not show the new reading is what moved the row, so the reducer was returned to reading the stored phase in a scratch copy of the tree — the derivation removed, everything else left as it is. The first case then fails with no transition, which is the same failure the base revision produces and is the one this change removes. The log opens with that mutation as its first line, names the module it imported and its digest, and carries a distinct digest from the change under test, so the two trees cannot be confused for one another.
