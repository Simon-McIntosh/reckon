The closure drain asks liveness through the same gate

What changed. The closure drain is the view a session reads to decide whether it may close, and the retained-work reading inside it turned on whether a run's worker is still working. The drain took that reading itself: it probed the pointer's pid on the reading host and wrote the answer into process_alive — the field classify_pointer reads as the last observer's own account — before classifying the record. The process table answers only on the host that issued the pid while the crew home is shared across login nodes, so a run launched elsewhere whose number this host happened to hold read alive, and one whose end the supervisor had recorded read its exit record as absent, because a live reading outranks it. The drain now classifies through the same host-gated reading the sibling views use, and carries only a reading this host stands behind into the classification.

The narrowing the drain already had is kept rather than dropped: a stored boolean is not evidence that a delivery on disk can be deferred on. It is now expressed as alive if proven else None against the reading local_liveness returns, which is the same rule the retained-work clause states in the other direction — a death is consumed only when it was proven here or recorded by the run itself.

The defect, reproduced before the repair

At the base revision 68a5b96b the two new drain cases fail on the borrowed life the probe writes. Case A builds a pointer whose launcher_host is another machine and whose pid is a process this host really holds, then reads the drain row: the case asserts row["process_alive"] is not True and the log records assert True is not True — the drain handed a closing session the life of an unrelated local process. Case B builds the same foreign pointer with the supervisor's exit record on disk and asserts the row carries it; the log records assert None is not None at row["exit_record"] is not None, because the probe's live answer is exactly what suppresses the fold (ended_exit is taken only where the process is not alive). The recorded end of a run launched elsewhere was unreadable in the view that decides whether a session may close.
