stall window respects a live child

landing record · parent plan a-stalled-row-says-whether-the-worker-lives §6 · delivered 2026-09-28 in the node worktree, uncommitted-to-main at the time of writing

What a stalled row said before

A run whose worker is alive and holding a job — a build, a scheduler reservation, a probe — writes nothing of its own while the child works. The stall decision compared the run's stream silence against a fixed window (fifteen minutes by default) with nothing else in the comparison, so that run read as stalled while it was working. The remedy the row invites is a resume, and a resume spends a turn to arrive where the run already was.

What the reading is now

classify_pointer takes one more read beside the liveness read it already took: whether a live process runs under the run's worker. The stall decision then asks for the window that applies to that reading — the operator's window where the worker has nothing running beneath it, and the run's own budget_seconds where a live child is present. The window is the maximum of the two, so a budget shorter than the operator's window never narrows it.

Three facts decided the shape of the seam:

  • One read, not two. The descendant answer is taken where the worker liveness is taken and is carried on the row as process_descendant_alive, beside process_alive, so the row and the verdicts built from it cannot disagree about which reading they rest on.
  • The pid asked is the worker's, not the pointer's. A supervised launch writes the supervisor's pid on the pointer while the work happens in the worker it spawned, and a supervisor holds its worker as a child — so asking the pointer's pid would answer "a child lives" for every supervised run and make the narrowing vacuous. Where the run's own worker record names a pid, that pid is the one asked.
  • None is not False. A run launched on another host, or one with no live worker to look under, answers "nothing was asked" and keeps the window. An absence is never reported where no check ran.

The stalled baseline is the exact row this change removes: a run quiet past fifteen minutes with a sleeping child under its worker, published to a coordinator as stalled.

Judgment calls a reviewer may want to overturn

  • max rather than the budget alone. A run declaring a three-minute budget would otherwise be judged stalled sooner than one declaring nothing, which is the opposite of what the budget is for.
  • The budget is the horizon, not the fence. The window extends to the run's own declared allowance and no further — past it the run's own fence speaks, not this reading.
  • One level of the child list. A process's children are reparented when it exits, so a running grandchild always has a running parent listed under the worker; a child the kernel has finished is an unreaped table entry rather than a running process.
