A pid this host never issued cannot make a live worker read dead

What changed. list_live asked the local process table about every live pointer's pid and wrote the answer into process_alive — the field classify_pointer reads as the last observer's own account. The crew home is shared across login nodes while a pid answers only on the host that issued it, so a reader elsewhere found nothing holding a peer's worker, the retained-work interruption fired for a worker still running on its own machine, and the row offered a resume of work already in flight.

The fleet read now hands the record on untouched, and liveness is derived where it is read: classify_pointer probes the pid only when the record's launcher_host is this host — which is what marks the reading liveness_proven — and the retained-work arm of _interruption_evidence consumes a liveness answer only when it was proven on this host or an exit record recorded the end.

The defect, reproduced before the repair

At the base revision fc6c5ecb the new file's case F reads a pointer whose launcher_host is another machine, whose pid nothing here holds, whose manifest is the worker's own non-terminal last word, and whose worktree carries one commit past its dispatch base. Through list_live and then _watch_snapshot — the follower's own read path — it produces: process_alive False, liveness_proven False, interruption {'reason': 'dead-pid-with-retained-work', …}, classification interrupted, snapshot state blocked, snapshot recovery resume. The same fixture read without the fleet read in front of it — the stored pointer straight into classify_pointer — is process_alive None, liveness_proven False, no interruption, running (raw-pointer-probe.log in the run directory), which is the whole of the fabrication: the row was produced by the reading host asking about a number this host never issued, and nothing else in it says the worker is gone.

The repair, in two halves

  • The reading is not fabricated. list_live returns the stored record unchanged; every consumer derives liveness where it reads, through classify_pointer or record_process_alive, each under its own host gate.
  • The arm refuses an unproven reading. _interruption_evidence returns nothing when the death was not observed here: the crew home is shared and a pid is not, so a stored answer from another observer is no reading on this host. An end the run itself recorded is untouched — it is read through the exit record or through the phase an observer wrote beside the reading, and neither rests on the reading alone.
  • The mirror direction, closed too. The run directory's worker record carries a pid but no host, so a foreign run whose number happened to be held here was handed proof of life this host cannot support. The record is still read for such a run — whether one exists is what advances the phase — but its answer no longer becomes this host's proven reading.
