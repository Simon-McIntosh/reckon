A plan-level ref a section already declares is reported

reckon/doccheck.py gains one finding beside the wiring check it already carried. plan-ref-could-be-section-ref fires at warn for an implementable plan whose plan-level depends_on names a target that one of the plan's own sections already declares at section level, naming the plan, the dependency and each declaring section. The entry is read from both places a section can declare a wait — the typed section record's data-links, and the section-scoped plan-section-depends-on mapping the roadmap resolves into per-section edges. A plan-level depends_on holds its carrier from the first implementable section onward, because the entry itself names no section; when the plan's own section refs already carry the wait, the plan-level entry re-holds every sibling the section ref deliberately left dispatchable, and the ready set reads the plan stale. The check stays silent when the first implementable section is one of the declaring sections, because a wait the first section begins is a whole-plan prerequisite and the plan-level field is what it is for; it also stays silent on a plan with no implementable section, on a terminal plan, and on a document that does not declare itself a plan.

How §6's clause was read

§6 asks the audit to warn "when a plan-level depends_on could have been a section ref (the consumer's first implementable section does not need the whole target)". The parenthetical is the criterion, and it is load-bearing only where the check compares the declaring section against the plan's first implementable section, which is what this implementation does. The same rule is what the create and edit skills state in the worked example: a plan-level depends_on for a need one section has "reports this plan blocked from its first section onward, which is false and misleads the fleet". No other reader of the document can tell that a bare plan-level ref is section-shaped; a section declaring the same target is the plan saying so, which is why the check keys on it and stays silent when nothing declares it. The reading is stated here rather than left to the diff, because a second reading exists — an #section-anchored ref sitting in the plan-level list — and the two differ in which fixture fires.
