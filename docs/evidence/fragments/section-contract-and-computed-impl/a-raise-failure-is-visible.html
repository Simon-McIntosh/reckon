A raise that fails to resolve is visible where a section with no raise is silent

_dispatch_section_routing in reckon/crew/dispatch.py caught every failure its read could raise — CrewError, PlanVisibilityError, ResourceCollision, OSError, ValueError — and returned None, which is the same value it returns for a node whose section reference names no record at all. A rule whose raised class routes to a lane no layer defines therefore disabled the raise silently, and a dispatch record could not distinguish "this section has not earned a raise" from "the raise could not be read". The read now returns a routing failure record naming the exception class and the section, the dispatch proceeds on role routing exactly as before, and the failure travels on the dispatch payload and on the run pointer, which is the record a later reader reaches without the dispatching process.

Three states, three records

a section whose rule resolves, raise or not attempts, capability, raise, failure: None, summary the resolved lane
a section whose rule raises while being read failure: {section, exception, detail}, summary role routing

The failure key is written on every outcome rather than left off when the rule resolved cleanly, so its absence cannot be read as "checked and found clean" for a section whose rule was never opened.
