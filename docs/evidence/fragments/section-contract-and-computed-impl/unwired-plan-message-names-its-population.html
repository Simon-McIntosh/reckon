The unwired-plan message names its population

The wiring rule reads a document's declared type, so an audit counts plan documents and nothing else in the docs tree. The message a reader receives named no population, so the count could be read as a whole-tree one. The message now states its population, through one constant so every surface states one scope.

The defect: a count with no population

At base 39fff0435, no population string exists anywhere in the shared message or its audit caller:

grep -n "population\|plans-scoped\|docs-wide" reckon/_schema.py reckon/cli.py   # no match

and unwired_plan_message composed the refusal with no statement of what it was counting over:

plan 'sample' is still implementable and declares no plan-depends-on, ... if it genuinely stands alone

The population is read from what the audit actually iterates: unwired_plan_finding returns None unless the document's declared reckon-type is plan, and the roadmap's caller filters plan.get("type") == "plan" the same way. An evidence or research document beside a plan is never a row — a fact the message left the reader to infer.

What changed

  • reckon/_schema.py gains UNWIRED_PLAN_POPULATION, one wording of the population beside UNWIRED_PLAN_CHECKLIST, and unwired_plan_message carries it in the message.
  • The same shared message reaches every caller unchanged in shape: the document audit (reckon/doccheck.py), the roadmap findings (reckon/roadmap.py) and the create/edit refusal (reckon/mcp.py). reckon/cli.py prints findings through the shared formatter, so its output carries the clause too and needs no wording change of its own.
  • tests/test_unwired_plan_message_names_its_population.py: the message names the population, and an audit over a synthetic tree holding two unwired plans beside one evidence and one research document reports exactly the two plan documents, each message naming the population.
