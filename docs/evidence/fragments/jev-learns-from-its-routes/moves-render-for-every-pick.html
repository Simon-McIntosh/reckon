Jev sees coordinator moves when the request names no requirement

_candidate_state in reckon/crew/picker/prompts.py now renders moved_in and moved_off for every candidate, not only inside the block emitted when the request names a requirement: they travel beside outcomes_at_requirement when one is named and stand on their own when none is, so a node dispatched with no declared capability no longer shows Jev zero coordinator moves. Both figures are rendered sparsely, so the state stays within its size budget: moved_in is included only when it holds at least one move, and moved_off only when it is greater than zero. A candidate no coordinator moved a run onto or off carries neither key, so a state with no moves is exactly as large as it was before the move figures existed. Over one moved row (a clive pick a coordinator moved to codex that failed) at a request naming no requirement, the rendered state carries the receiving codex candidate's moved_in with one failed and the chosen clive candidate's moved_off 1, while a third candidate with no moves carries neither key and no outcomes_at_requirement block is present. The moved_in and moved_off glossary entries and the field comments in prompts.py and types.py now state the figures are read at the request's requirement when it names one and over every move when it names none, and that an absent key means no coordinator moved a run onto, or off, that candidate in the window.
