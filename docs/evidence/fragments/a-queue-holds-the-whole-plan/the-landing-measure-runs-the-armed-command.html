The landing measure runs the suite command the run armed

An armed suite command is written the way a shell reads it: PYTHONPATH=. .venv/bin/python -m pytest -q {node_test_files}. The landing measure took that text, split it with shlex and handed the tokens to subprocess as an argv, so the leading assignment became the program it tried to start and every arm stopped before reaching a test. The base checkout also carried no .venv, so the relative interpreter the command names could not start there even with the assignment resolved. Reproduced by restoring the raw shlex argv in measure_run: the head case fails on 'the base arm did not run', which is the refusal the plan recorded against two reckon runs.

reckon/crew/landing_measure.py now resolves the command before any arm starts. armed_argv peels the leading NAME=value tokens into the environment the arms run under and substitutes {node_test_files} with the node's own fenced test files, so the suite pair, the importer population and the isolated re-runs all start the same program with the same environment. _link_environment gives the base tree the .venv link a provisioned worktree carries, resolved through any link the repository itself has. _carry_missing_tests copies the node's test files the base revision lacks in from the head, so the base arm reads the test the node added and counts its failures rather than exiting on a missing file.

A command that is not scoped carries no assignment, so its arms inherit the measurement's environment exactly as before: the assignment handling adds nothing to a command that declares none, and a scoped command that resolves to no test file is refused as unmeasurable rather than silently measuring the whole suite.
