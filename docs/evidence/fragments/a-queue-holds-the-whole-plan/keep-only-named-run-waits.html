A request keeps a stored run wait only when it named it

What changed. An admission pass re-derivation kept every stored _rederive_waits run: ref as the request's own, so a stored wait on a request the waiter never named was permanent. When that request was dropped, the waiter was closed blocked-upstream — a phase no pass lifts and the queue's own drop refuses, so the request could only be thrown away. _rederive_waits now takes the request's own refs from node.after, the authored field it was dispatched with, so a stored run: wait the request did not name is dropped by the next pass, wherever it came from.

The defect, reproduced first. At the dispatch base (d98e22fb19) a queued pointer carrying its plan's declared wait plus run:r-doomed-request, with that request discarded, came out of a pass with waits=['plan-a#s1','run:r-doomed-request'] and phase=blocked-upstream — and stayed there after the declared wait landed. The pass could not remove the wait it had never been asked for. Log: logs/repro-defect-base.log.

The three cases, at the head. tests/test_a_dropped_request_strands_no_waiter.py shows (1) an unnamed wait on a discarded request is removed by the next pass and the waiter moves to queued once its declared wait lands; (2) an unnamed wait on a still-queued request is removed and never waited on; (3) a wait the request did name still turns the waiter blocked-upstream when its run is discarded, as today.

The negative control. Restoring own = {ref for ref in stored if ref.startswith(REQUEST_REF_PREFIX)} fails cases 1 and 2 and passes case 3, exactly as declared. Log: logs/negative-control.log.

Measure. The armed suite covers the new test, the two files whose fixtures it repaired, and the staged-write census. At the head it is 68 passed and 2 failed; both failures are red at the base arm as well, so this node adds none, and the base arm's two defect cases are the delta it clears. Ruff reports no findings. Logs: logs/suite-after.log, logs/suite-baseline.log, logs/ruff.log.

Both arms collect 116 distinct failing ids, the sets are identical, and no failure is added or cleared. Logs: logs/importers-after-s0..s4.log and logs/importers-baseline-s0..s4.log.

The fixtures that had to change. Three fixtures built a stored run: wait their node never named in after — test_a_failed_admitted_launch_keeps_the_waits_it_recorded and test_a_wait_naming_no_project_records_an_issue_and_an_obligation in tests/test_a_queued_launch_keeps_the_run_record.py, and test_accepted_delivery_lands_before_its_downstream_is_admitted in tests/test_queue_landing.py. Production cannot reach that state: every stored run: wait is built from node.after, and the plan editor writes no waits. Each fixture now names the ref it waits on, and each keeps the behaviour it is named for.
