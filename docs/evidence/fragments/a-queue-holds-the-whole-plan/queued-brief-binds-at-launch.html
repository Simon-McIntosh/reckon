A queued request's brief binds at launch, from its steering file

What changed. A dispatch that is held stores its brief as steering.md in the request's own run directory, once, and never overwrites it. queue_dispatch in reckon/crew/runs.py resolves the request's final id — the existing id on an in-place re-queue, the fresh one otherwise — and copies the --brief source there only when the directory holds no steering.md yet. A coordinator edits that file while the request waits; an in-place re-queue of the same node therefore leaves the edit in place rather than restoring the queue-time text.

The launch reads the file, not the pointer. _launch_queued in reckon/crew/queue_admission.py contract-checks steering.md when the request has one, then points the node's brief and brief_path at that file in place of the queue-time values _node_from_pointer carries, before the node reaches dispatch(). Nothing else in the brief path changed: _store_brief still copies the file the node names into the run directory, and _brief_digest still digests node.brief_path downstream, so the run records exactly the bytes the worker read. A request whose authority is a plan section alone has no steering.md and launches from its section as before.

A steering file that no longer reads is refused, not launched. The check is readability and non-empty text. A refusal is raised inside _launch_queued, before dispatch() runs, so _record_queued_failure restores the request to queued with the failure named and a retry time — the same path every other admission refusal already takes. No worker starts.

One place stores a brief. runs.store_brief now owns how a brief's bytes reach a run directory — it materializes a brief the launch re-composes, appends the domain-rules block once, and keeps the source's suffix so the copy reads as the document it was. _store_brief in reckon/crew/dispatch_admission.py delegates to it, so the launch and the queue cannot drift apart on how a brief is written.

Three sources the queue leaves alone. A brief whose source already lies inside the request's own run directory is not copied: it is already the request's stored copy, and a review's own readers resolve that path. A brief the launch re-composes is not copied either — a run review's review-brief.md carries the head the reviewed tree carries now, so a queue-time copy would freeze a head the run may move past before it launches. A brief the queue cannot read is not copied: the launch is where a coordinator's unreadable brief is refused, and a silent queue-time refusal would hide it. Every other brief is stored as steering.md.

The base arm runs the same command from a git archive extraction of the run's base revision, and its log names the absolute path of reckon/crew/queue_admission.py as imported so the tree that answered is readable.

The arms the new module measures

  • Stored once. Queueing a request with a brief writes steering.md in its final run directory carrying that brief's bytes.
  • Not overwritten by a re-queue. The steering file is edited, the same node is dispatched again so it re-queues in place, and the edited text survives; no second request is created.
  • Replaced before launch. The steering file is rewritten while the request waits and the launched run's recorded digest matches the replacement.
  • Discriminating arm. steering.md is left alone and the file the queued pointer's node.brief names is changed; the launched digest matches steering.md and not the pointer's file. On the base code this arm fails, because the queue-time brief is what gets copied.
  • Invalid while queued. The steering file is made unreadable authority text; the request stays queued, the failure is named, a retry time is set, and no launcher is called.
  • Plan section alone. No steering.md is written and the request launches from its section.
  • A re-composed review brief is not frozen. A run review's composed brief is queued as the request's brief; no steering.md is written, the reviewed tree gains a commit while the request waits, and the launch composes the brief again — its digest names the new head and differs from the text the earlier composition left.
  • A source inside the request's own run directory. No second name is written and the source is untouched.
  • An unreadable source. No steering.md is written; the launch refuses the brief, the request returns to queued with the failure named and a retry time, and no launcher is called.

Each skip is held by a failing arm without it. Removing the three skips from _write_steering turns the three arms above red (3 failed, 6 passed) and nothing else, so a later regression that deletes any of them cannot pass unnoticed.

Negative control. The declared mutation restores _launch_queued to pass the queue-time brief from _node_from_pointer unchanged. The replaced-steering and discriminating arms fail under it, which is the defect this node closes, and so does the invalid-steering arm, because the removed rebind is also what reads the file the launch must refuse. A second control deletes the three _write_steering skips and turns exactly the three arms that hold them red, so neither the refinement nor its test can be lost unnoticed.
