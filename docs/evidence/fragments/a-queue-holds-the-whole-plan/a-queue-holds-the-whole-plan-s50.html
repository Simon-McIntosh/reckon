A refused request outlives its dispatcher's session

A refused queued request is charged to the session that dispatched it, and reckon.crew.obligations.obligations(project, session) is built for one session. When no live process carries that session, the refusal sits in a view nobody reads: on 22 November 2026 four queued requests sat refused for between four and nineteen hours — two held on a write claim, two refused because their section was declared done, at r-20261121T201937629427-anchored-flight-key-s18 and r-20261121T201951227166-anchored-module-s18 — behind dispatching sessions 8e41a6d3 and 829e5a4a, both ended. Nothing on the lane ends such a refusal, and no live session was told.

The derivation now reads each queued request that carries a refusal (session_refusal or contract_refusal) and asks the harness's own session records whether a live process still carries its dispatcher. A dispatcher observed ended produces one row of the new orphaned-refusal kind, naming the ended session in its ended_session field and keeping the refusal's own remedy as next_command; the row is listed to a live session of the same project. When the project has no live session at all it is listed to any live session on the lane, which is the reading that stops the request being lost with its dispatcher. The ended session is never told about its own orphan: no process carries it, and reporting there repeats the loss.

Only a session observed ended is orphaned. The harness's reachability answer is three-valued — a process running, a process ended, or no record at all — and a session with no record reads as unknown rather than gone, so its refusals stay exactly where they were. This is deliberate: absence of a record is not evidence of death, and a wrong ended reading would duplicate a live session's own duty. The consequence is that a dispatcher whose harness keeps no record (a headless CLI session) is not orphaned by this reading; it is reported under outside_scope for a coordinator to decide.

Both payload producers use the same helper. The fresh derivation (_obligations_view) and the sweep's published slice (_payload_for_state) build the row through orphaned_refusal_readings and _orphaned_refusals_for_session; the fleet state computes the candidate rows and the project's live-session set once per sweep, so the harness is read once rather than once per published session, and a snapshot and a derivation over the same files list the same orphan. The lane fallback is the only path that asks about the calling session itself, so it is the only one that pays a further harness read.
