An admission pass reads the roadmap once

An admission pass derived the same project roadmap once per launch it made. Each queued launch calls dispatch(), which calls dispatch_waits(), which reaches _readiness_rows() and project_section_readiness() — a scan of every plan resource and a JSON load of the persisted metadata index. The cache _readiness_rows fills was created inside the batch call it ran in, so a pass launching three requests in one project built that roadmap three times, and admission throughput rather than the lane capped how full the lane got: passes that should have taken about 75 seconds took 2 to 15 minutes on 27 October.

admit_once now holds one readiness cache for the whole pass and hands it to every launch's dispatch(), and through that to dispatch_waits(), _validated_batch_waits() and _readiness_rows(). Entries are keyed by the project, its docs directory and _plan_tree_fingerprint() — the newest modification time and count of docs/plans/*.html plus the checkout's HEAD — so a plan edited, or a landing merged, during the pass misses the cache instead of being read as stale readiness. A direct dispatch passes no cache and builds its own.

The gate, tests/test_an_admission_pass_reads_the_roadmap_once.py, counts builds through a patched project_section_readiness and shows four things. A pass launching three queued requests in one project builds the project readiness once, len(builds) == 1. A plan file touched between two launches of one pass builds twice — the edit is read, not answered from the pass's cache. A direct dispatch() outside a pass builds its own. And the three launches read the same refs, projects and unmet lists that an uncached dispatch_waits computes for them, over a fixture whose sections declare a real wait, so the comparison is not [] against [].

The head arm ran 4 passed in 46.04 s with EXIT=0; at the base revision the same command exits 4 because the test file does not exist there. The admission-neighbour files that reach the edited functions — test_queue_dag_waits.py, test_dead_wait_blocks_only_its_request.py, test_a_queued_request_waits_on_its_dependencies.py, test_each_admission_pass_records_its_verdict.py, test_a_manual_admission_pass_reports_its_verdicts.py and test_queue_hold_release.py — ran 63 passed in 94.00 s with EXIT=0 at the changed revision, so they add no failures. The full set of files importing reckon.crew.queue_admission and reckon.crew.dispatch is 349 files, which is the merged-head suite rather than this node's change.
