Landed-work review, repair and re-review run without the orchestrator

What landed

A stored run review now carries an id on every mapping finding, stamped by the store from the shared repair.finding_id over the finding's own file, line and text. A repair answers a finding by that id, and the lifecycle reads the answer back, so the record on disk names the identity an answer targets rather than leaving each reader to re-derive it.

The reflex opens a repair round per reviewed head for up to three rounds and then hands the run to its coordinator: the fourth review opens nothing, dispatches nothing, and records one escalated dispatch naming the rounds spent, the review's score and the open findings with their stable ids. The record is written once per round, so a repeated sweep adds no second escalation. The re-review brief carries the diff from the head last reviewed to the new one and the answers already recorded on the review.

A disposition against a stored review is accepted when the run's head descends from the reviewed head, which is the state a hand-resumed repair leaves behind. The record must have been landed: the descent reader searches the project's committed tree only, resolved from the checkout the project is mounted at, because that is where a promotion commits the run's evidence about its own work, while the run's worktree holds the work and supplies only the ancestry test. A staging round is a live round of a single head that stops describing the work once the head moves past it. A divergent head still refuses, and so does a staging round keyed to another revision.

Every composed prompt now asks the worker to record one rubric.<dimension>: <state> line per review dimension in its manifest before delivery, and prompts.missing_rubric_self_checks reads them, reporting a dimension with no line, or a heading with no state, as absent rather than as a pass.

Measure

The focused review/repair gate is 89 passed on the changed tree. The same targets on the base revision carry one pre-existing failure: a test compared a store-stamped findings record against its unstamped input, and now derives the expected id from the same function the store uses.

The coordinator's importer arms found five failures the landed changes caused, each reproduced and then answered. Three tests compared stored findings against unstamped input and now derive the stamped id from the written finding, so no literal id is written anywhere. The plan prompt snapshot carries the rubric self-check block. The fifth was a behaviour regression rather than a stale expectation: the descent path accepted a staging round keyed to another revision, which the landed-only rule above now refuses, and the landed-and-descended case still passes. The importer set of 452 tests across the files reading the review store and the crew verbs is green at the head.

Negative control: restoring a one-round cap makes the second-round, third-round and escalation arms fail (3 failed, 2 passed), and the limit is restored afterwards.
