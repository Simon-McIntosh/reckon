Landed-work review, repair and re-review run without the orchestrator

What landed

A stored run review now carries an id on every mapping finding, stamped by the store from the shared repair.finding_id over the finding's own file, line and text. A repair answers a finding by that id, and the lifecycle reads the answer back, so the record on disk names the identity an answer targets rather than leaving each reader to re-derive it.

Measure: tests/test_review_repair_runs_without_the_coordinator.py — 2 passed. Importer subset (49 tests across the review store, lifecycle, blocking-severity and repair-answer files) — 49 passed, no new failures.

Blocker: the round cap and escalation live outside the write grant

The plan names the automatic repair's rounds as this node's work and lists the module set as the four review modules. A later refactor (85c4e4813, "split recovery behavior into sibling modules") moved the repair-round cap and dispatch into reckon/crew/recovery_repair_dispatch.py, which is not in this node's write grant. The one-round cap it enforces is proven live by tests/test_one_automatic_repair_round_per_run.py (3 passed), whose test_a_second_round_on_a_new_head_hands_back asserts the exact behaviour the plan asks to change; that test too is outside the grant. A self-widen through reckon crew widen is refused because ~/.config/reckon is mounted read-only (only the run directory is writable), so the pointer lock and live pointer cannot be amended.

Required to finish: a grant covering reckon/crew/recovery_repair_dispatch.py and tests/test_one_automatic_repair_round_per_run.py, plus the dispose head-descent path (in reckon/crew/review_records.py and the dispose verb).
