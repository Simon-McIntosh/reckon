A plan review reads the change, and the gate holds only what changed

What changed. A composed plan review no longer re-reads the whole plan, and one uncovered section no longer refuses the dispatch of every other section. Two mechanisms carry it.

The review is given the change. A stored review records the plan commit that carried the bytes it read: plan_commit_for in reckon/crew/plan_review.py resolves it from the reviewed blob with git log --find-object at the plan path, and write_review_sidecar writes it into the delivery sidecar, which delivered_report_record carries onto the stored record. The next composed review's scope (review_scope) then carries three blocks and nothing else: that commit's diff of the plan file, restricted to the changed lines of the units the review is asked about (_diff_for_units, whose markers are each unit's own data-id or decision block); the full text of each uncovered unit; and the earlier findings with their answers, an unanswered one now shown as (unanswered) rather than dropped. A plan's sections sit one per line, so a hunk's context lines quote the neighbours a reviewer was not asked about — which is why context lines are dropped rather than trusted to be small.

The gate holds only the section dispatched. require_plan_reviewed in reckon/crew/routing.py narrows to plan_review_units(node.section) — the section itself and the document unit that carries decisions, gates and dependencies — when a caller names no units, so an authored edit to a section this dispatch does not read no longer refuses content a review does cover. A dispatch naming no section keeps the whole-plan check, because it reads the plan as a whole. When no stored review covers any unit of the plan, the narrowing is set aside and the refusal names the whole content the plan is owed a review of, so a plan with no review at all still reads as unreviewed rather than as one section's debt.

Measure. The gate command PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_a_plan_review_reads_the_change.py reports 4 passed, EXIT=0. The nine test files importing reckon.crew.routing and reckon.crew.plan_review report 95 passed, EXIT=0 at both the base revision 94e9068e0 and the head, so the change adds no failure to the importer arms. The negative control removes the per-section narrowing (require_plan_reviewed falls back to the plan-wide gate) and the unedited-section arm fails: 1 failed, 3 passed, EXIT=1, the failure being test_unedited_section_dispatches_while_another_is_uncovered, whose refusal reads uncovered units: b for a dispatch of section a.

What the test shows. A review composed after one section is edited carries that section's diff line and full text, no other section's text, and the earlier finding with its answer; the stored record names the commit it read; a dispatch of the unedited section succeeds while the edited one is uncovered; a dispatch of the edited section is refused until a review covers it, and released by the review that does.
