A node waits only on what it names

What changed. crew dispatch gains --waits-only-after. With it a request's waits are exactly the requests its --after refs name: the section's plan-section-depends-on refs, the plan's depends_on and the readiness: ref _validated_batch_waits appends for a gate on the section are none of them. The flag rides the stored node, so _rederive_waits honours it on every later admission pass and cannot add the inherited waits back. It is refused without at least one --after, at the command line and in the node contract the batch path shares, so it can never leave a request waiting on nothing. The request still records its section, for routing, landing and the review gate.

The sibling leak. The pass's re-derivation cache was keyed on (repo_root, plan, section), so the first request of a section re-derived in a pass handed its derived waits to every sibling re-derived after it; a request naming no --after waited on a sibling's run. The key now carries the request's own --after refs and the flag, so two requests of one section derive their own waits.

The measure. tests/test_a_node_waits_only_on_what_it_names.py shows the flagged request queued as its one ref lands with no pass widening it, the same dispatch unflagged waiting on all four refs, a sibling naming no --after never taking another's, the gate ref suppressed, and the flag-without-ref refusal on both the command line and the contract. Five cases pass at the head (five passed) and four fail at the dispatch base with the same test copied in, the "waits on all four" case being the one that already held there. Two negative controls fail exactly the case they name: ignoring the flag fails the flagged-waits and gate cases, and keying the cache without node.after fails the sibling case. The armed suite arm passes 56 tests at the head against 51 at the base revision, both with the armed command recorded verbatim.

The importing population. The test files importing reckon.crew_dispatch_commands or reckon.crew.queue_admission were run in place at -n 4 --timeout 120, one arm at a time, over the same 140-file list at both revisions. Chunk 00 adds one id — test_a_single_section_check_costs_a_tenth_of_the_whole_project_build, a cost-ratio test that passes alone at both revisions and fails only under four-way contention. Chunk 01 adds none: 36 ids fail at the base and the same 36 at the head. Chunk 03 completed at the base (50 failed, 326 passed, 1 skipped) and its head arm was cut off by the run's command budget under storage contention, so no comparison exists for it; chunk 02 did not complete at the base. Those two chunks are outstanding, not passed.
