A section whose record disagrees with its declaration is refused when written

A direct authored edit reopened a section's declaration and left its record at data-status="done". The typed parse refuses such a document, but the refusal arrived only when another project's dispatch happened to read the plan: reckon audit-doc reported no finding that named the section, the server's plan write ended the connection with an uncaught ValidationError, and a promotion would have committed the file.

One derivation, _plan_html.section_status_disagreements, reads the record statuses from the tree and the declarations from the head without the typed parse, so a disagreeing document can be described rather than merely rejected. It is the single source for three surfaces: the audit reports code section-status-disagrees at error naming the section and both values; the server's plan write answers 400 with error: section_status_disagreement, the section list and the same wording, instead of dropping the connection; and a promotion refuses before it writes either store, so the plan and the ledger are left as they were. A document whose two views agree passes all three.

The gate is tests/test_a_disagreeing_section_is_refused_when_written.py: four synthesised cases — the audit names the section and both values and exits non-zero; an agreeing plan carries no error and exits zero; the server refuses the disagreeing file without writing it; a promotion's landing refuses with a non-zero exit, names the section and both values, and leaves no plan write and no ledger row.
