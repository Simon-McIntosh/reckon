A worker widens its own run's scope to a path no live run claims

Change. reckon crew widen accepts --reason and admits the run's own worker while its process is alive: widen_claim in reckon/crew/claims.py now refuses a live worker only when the caller is not that run. A self-widen records the grant on the live pointer's node under write_grants as its path, its stated reason, its timestamp and the source worker, so the widening is visible to a reader who did not watch the command run. A process whose RECKON_RUN_ID is set may name only that run: naming another is refused, which is what stops the live-worker exception becoming a way to widen a peer's boundary. A peer's claim still refuses the added path and names the holder; for a self-widen a queued or upstream-waiting request also binds, because the path will be written when that request launches and no later admission would see the collision. The run review brief now lists every declared path with the source of its grant and states that a self-grant is inside the run's declared scope, which removes the scope-discipline finding the brief's silence about a widened path produced.
