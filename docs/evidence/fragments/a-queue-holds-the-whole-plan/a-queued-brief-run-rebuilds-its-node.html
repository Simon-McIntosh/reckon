A queued brief-carried run rebuilds its node

What changed. _node_from_pointer in reckon/crew/queue_admission.py rebuilds a queued request's TaskNode from the stored pointer at admission. Its empty-string guard dropped a stored empty string whenever the field's dataclass default was truthy, which is the rule that keeps a real default rather than launching a field with nothing. The default of a field that has no default is dataclasses.MISSING, and MISSING is truthy, so the guard also dropped a brief-carried review's stored plan="". The constructor then raised on the missing required argument, and every queued brief-carried run failed once it had to wait for a slot.

The guard now requires that the dataclass default be a non-empty string. A brief-carried node rebuilds with plan="" and its brief kept, a plan-carried pointer rebuilds unchanged, and a stored empty string against a real default still keeps that default.

Measured

The defect was reproduced before it was repaired, in a base tree extracted from the node's base revision with git archive. A brief-carried review node, stored as the dispatcher writes it, reached _node_from_pointer and raised TypeError: TaskNode.__init__() missing 1 required positional argument: 'plan' — the failure the plan records from the live queue. The same fixture rebuilt with the repaired guard returns plan="" and the brief unchanged.
