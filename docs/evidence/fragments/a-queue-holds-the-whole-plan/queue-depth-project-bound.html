Queue depth is the project's bound, and one request is stored once

What changed. The 2–8 per-session queued-dispatch clamp is gone: QUEUED_DISPATCH_CAP_FLOOR, QUEUED_DISPATCH_CAP_CEILING and the fair-share reader that fed them (queued_dispatch_cap in reckon/crew/runs.py, _queued_share_cap in reckon/crew/dispatch.py) are removed. Depth is now a property of the project: queue.max_requests in flight configuration, default 500, read by flight.queue_max_requests (reckon/flight.py) and applied in queue_dispatch under the queue's own lock, so two concurrent dispatches cannot both pass the bound. Every dispatch path passes the resolved figure in, and a caller holding no config resolves the shipped, host and project flight layers through the same resolver. Requests in queued, awaiting-upstream and blocked-upstream all count toward that bound.

One request, one pointer. A request's identity lost its session: _node_identity now returns (plan, section, node id), with the project carried by the pointer directory the scan walks. Queuing the same section twice — from one session or from two — updates the existing pointer and returns its run id, storing nothing new.

The review exemption moved with the bound. A review of a delivered run is neither refused at queue.max_requests nor counted against it, which is the same exemption the per-session cap carried. An explicit session-scoped cap argument survives for callers that impose one; no dispatch path derives one any more.

The bound costs a reader nothing measurable. The crew MCP reads of the live and obligations views each answer inside the 30 s deadline their wrapper enforces, cold and warm, on a fixture of 500 queued pointers.

Measure. tests/test_queue_depth_project_bound.py has a dispatch-path arm: one session queues 200 requests with no refusal (the arm the restored clamp fails at the ninth); a duplicate returns the existing id and the live set is unchanged; another session's copy of one request is the same request; the 501st request is refused with held=500 and the refusal naming queue.max_requests for each held phase; strict flight resolution accepts an override, and a caller without a bound reads the host and project layers; a review is queued at a full bound; a queued review does not shrink the project's remaining room; and the two MCP reads answer inside their deadline. The negative control restores the clamp and fails the 200-request arm at eight held requests.
