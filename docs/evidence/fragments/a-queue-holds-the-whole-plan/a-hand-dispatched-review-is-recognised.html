A review dispatched by hand is recognised by the paths it was granted

What changed. _review_pointer_rubric in reckon/crew/recovery_review_dispatch.py now computes the record paths it expects from the reviewed run's directory — the same review.run_review_record_paths(runs.run_dir(reviewed_run_id), …) call the composer makes in recovery_review_subject.py. It previously computed them from the reviewer's own run directory, so a review's declared paths and the matcher's expected paths never intersected: a live review read as no review at all, and the duties view told a coordinator to dispatch a review that already existed.

One path names both sides. A declaration that spells a head is now authoritative for that head: a pointer whose head-keyed record path names an earlier revision is not the review of the head the run carries now, and its headless spelling no longer stands for the current head either. Only a pointer that names no head at all falls back to the headless match, because it cannot be told apart from one at any revision.

Recognition is not gated on looking like a reviewer. _review_in_flight consults the granted record path before asking whether a pointer carries a review role or a minted review node id, because a hand dispatch chooses both freely. The granted path is what the composer wrote for this run, so it names this run's review whatever the pointer calls itself. The role-and-id reading remains as the second route for records dispatched before the paths moved.

Measure. tests/test_a_hand_dispatched_review_is_recognised.py builds every fixture path by calling the composer, so it fails if either side moves. It shows four arms: a live pointer granted run R's paths at head H, with no dispatch record on R, is returned by _review_in_flight for R at H; the same pointer in queued makes R's duty read review-queued and not review-missing; a pointer granted R's paths at an earlier head is not R's review at H, with the current head's paths accepted as the control; and a figure review is told apart from a content review in both directions. The declared negative control — compute the expected paths from the reviewer's directory again — fails all four arms.

One fixture followed the corrected layout. tests/test_figure_review.py built its in-flight fixture with runs.run_dir("review-run"), the reviewer's own directory, so its figure arm asserted the spelling this change corrects. It now composes the directory from the reviewed run's own record (runs.run_dir(project["record"]["run_id"])) and keeps calling run_review_record_paths, so the fixture and the matcher name one directory rather than restating the layout twice.
