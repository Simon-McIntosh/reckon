A plan edit holds only the request that reads the edited unit

An admission pass now judges the plan-review gate over the units a request actually reads: its own section and the document unit. A stored review that covers the request's section launches it, while a request whose own section is unreviewed is held with reason plan-review-owed and the review invocation recorded as its detail. The narrowed judgment is a units argument to require_plan_reviewed; a direct dispatch passes none and keeps the whole-plan check.

Held requests are re-judged on every admission pass, so storing the covering review releases them with no coordinator call. A hand-held request carries no automatic flag and survives the releasing pass untouched. The obligations view emits one plan-review-owed row per plan rather than one per request, naming the held count and the review invocation.

Each pass re-derives waits with derive_wait_refs and rewrites the stored waits, keeping the request's own run: refs, so a narrowed dependency releases its waiter and a widened one sends it back to awaiting-upstream. A --after ref on an unlanded run survives that pass. A manifest upstream that reads blocked keeps its waiter waiting: only a failed or abandoned manifest, or a discard, closes a wait as blocked-upstream.
