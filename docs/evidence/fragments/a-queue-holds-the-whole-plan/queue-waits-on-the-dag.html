Queue waits follow section and request dependencies

Dispatch accepts repeated --after request IDs. Queue validation checks section, plan and request targets before storing a batch, and rejects cycles across sections and requests. Each admission pass reads the roadmap's per-section verdict once per project. A complete upstream request releases its waiter only after the ledger's promoted revision is an ancestor of HEAD in the registered checkout. Unreadable status and missing revision each produce one upstream obligation.

The new test file covers cross-project release, direct queueing after a completed section, both cycle shapes, missing targets, blocked and failed upstreams, promoted but unmerged work, a no-commit promotion, rejected manifest status, scoped holds and both gate shapes. The declared mutation that drops cross-project refs fails the cross-project arm.
