Queue waits follow section and request dependencies

Dispatch accepts repeated --after request IDs. Queue validation checks section, plan and request targets before storing a batch, and rejects cycles across sections and requests. Each admission pass reads the roadmap's per-section verdict once per project. A complete upstream request releases its waiter only after the ledger's promoted revision is an ancestor of HEAD in the registered checkout. Unreadable status and missing revision each produce one upstream obligation.

The new test file covers cross-project release, direct queueing after a completed section, both cycle shapes, missing targets, blocked and failed upstreams, promoted but unmerged work, a no-commit promotion, rejected manifest status, scoped holds and both gate shapes. Dispatch preflight reads authored section and gate declarations without scanning unrelated scope claims, and the landing fixture records a promoted revision already in its checkout's HEAD. The declared mutation that drops cross-project refs fails the cross-project arm; the focused four-file gate passes 51 tests.

Ordinary dispatch now validates the dependency graph before storing a waiting request. A missing section or a cycle refuses with no pointer left, and an open gate on the request's own section holds it upstream. The focused repair gate passes 57 tests; reversing the repair while retaining its tests fails all three new refusal and gate cases. Batch queueing now delegates to the production dispatch writer. The new shared-writer check fails when that owner commit is reversed, and the six-file focused gate passes 72 tests.
