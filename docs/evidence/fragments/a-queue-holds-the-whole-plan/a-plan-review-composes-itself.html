A plan review composes itself after an authoring burst

What changed. A coordinator had to remember to compose a content review after editing a plan, and one paused at a rate limit could not. A plan therefore sat unreviewed, and its sections could not dispatch past the review gate. The crew watch sweep now composes that review on its own: compose_owed_plan_reviews in reckon/crew/plan_review.py is called from the review pass of sweep in reckon/crew/resumption.py, beside the pass that already dispatches each settled run's review, so every caller of the sweep — the follower's cadence, the resume-ready surface, the MCP sweep action — reaches it once.

The quiet period. A review composed between two edits reads half a document and raises findings against prose the author was about to replace, so a plan is composed for only once PLAN_REVIEW_QUIET_SECONDS (ten minutes) have passed since its file was last written. plan_review_quiet_remaining measures it from the plan file's own modification time — the store an edit writes — and a file whose time cannot be read answers zero rather than being taken as quiet.

The reductions, cheapest first. _owed_review_skip_reason answers why a plan is not the reflex's to review yet: it is finished, so it owes nothing; it was edited too recently; a plan review is already in flight as a live run (_standing_plan_review, the reader the locked dispatch already uses, so the preview and the dispatch cannot disagree); a stored review already covers the plan's current content (read_plan_review with the plan given, which is the coverage predicate the dispatch gate itself runs); or the edit has had the reviews compose_burst_refusal allows, in which case its findings must be answered rather than reviewed again.

The pass is bounded. The sweep runs every couple of minutes, so the pass costs a constant rather than a scan: it records each plan's modification time under the crew home and weighs only the plans written since it last weighed them, it weighs one plan per pass (PLAN_REVIEW_PASS_LIMIT) because weighing one plan against the live store takes about twenty seconds, and it carries a cursor so the next pass starts after the plan this one stopped at. Without that cursor a plan near the top whose skip reason never settles — one with a review in flight, say — would hold the only slot on every pass. A plan is recorded as weighed only when its review was dispatched or queued, or when its reason cannot change without an edit, so a dispatch a lane held is composed again on the next pass instead of waiting for its author to touch the file.

One document's refusal is its own. A document whose location disagrees with its declared type made the catalogue refuse the whole tree, and the sweep caught only CrewError and OSError, so a single bad file would have broken the pass for every plan in the project. The scan is taken in the catalogue's tolerant mode and the files it dropped are read from the scope's own record: the offending document is reported against itself and the other plans are weighed normally. Each plan is weighed inside its own guard for the same reason.

No lane named. The composition goes through recovery.plan_review_subject with the content rubric and no --local, which is what the invocation every surface prints also does: a review naming no lane takes the review lanes review_excluded_backends leaves, which keeps it off metered lanes and holds it when the local lane is saturated.

The notes. A finding the reviewer marked WOULD_CHANGE_THE_PLAN: no needs no decision from the author, so leaving it open costs a coordinator a turn it cannot spend while paused. note_would_not_change_findings answers each such finding on the record that raised it with a fourth action, noted, carrying the reviewer's own REASON when the report stated one. Only an explicit no is answered: a finding whose verdict the report never stated carries None, which is not a no, so it waits for its author like any other. noted is deliberately not one of RESPONSE_ACTIONS — those are the author's judgement, and a decline recorded here would be counted by declined_recurrence as an author ruling on the rubric. Every record is read back between answers, so a review carrying two such findings keeps both: the store rewrites the whole record, and an answer written from a stale copy would drop the one before it.

The measure. tests/test_a_plan_review_composes_itself.py shows the four arms: a plan owing review whose last edit was eleven minutes ago is composed on the next sweep (the composed brief, plan snapshot and sidecar on disk, the launch naming the sweeping session and no lane); one edited two minutes ago is not, and reports the quiet period as its reason; one with a review in flight is not, and names the standing run; and a stored review's would-not-change finding is answered noted with the reviewer's reason while a finding that would change the plan and one carrying no stated verdict both stay open. The negative control removes the quiet-period check, and the two-minute arm fails.
