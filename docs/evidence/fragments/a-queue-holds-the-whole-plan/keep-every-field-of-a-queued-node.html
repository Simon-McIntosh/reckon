A queued node launches with every field it was dispatched with

What changed. A queued request stores its node as data and rebuilds one at admission. _node_from_pointer in reckon/crew/queue_admission.py rebuilt it field by field, and its own comment said a field it did not name was a field the launched worker never saw. It named neither images nor inputs, compares_with, over_fence_reason or admission_findings. TaskNode.as_dict() in reckon/crew/node.py listed its keys by hand in the other direction and omitted admission_findings and peer_scopes, so those two never reached the stored pointer at all. Every queued run lost them; a composed figure review that queued behind a full lane reached its worker with no rendered picture to judge.

Both directions read the dataclass's own field list. as_dict() serialises every field TaskNode declares, copied into JSON-ready data so a reader cannot mutate the node it came from. _node_from_pointer iterates fields(TaskNode) and rebuilds each field from the stored value. No field is named in a second list that can drift from the dataclass, and a field added to TaskNode later is carried without a second edit.

The two deliberate rewrites remain. A manifest path or a write path a previous dispatch defaulted into the queued run's own directory is still dropped, so the launched run derives those defaults afresh from its own id; every path outside that directory is carried unchanged. A field the stored node lacks takes the dataclass default rather than raising, which is what lets a request stored before a field existed launch after it is added.

The measure. The defect was reproduced first in a temporary crew home: a node carrying images, inputs and compares_with was rebuilt through _node_from_pointer from its own as_dict(), and the rebuilt node carried none of them. After the change the same replay loses nothing. tests/test_a_queued_node_keeps_every_field.py shows four cases: the rebuilt node equals the dispatched one in every declared field except the two rewritten paths; run-directory paths are dropped while foreign ones are kept; a field the stored node lacks takes its default; and the operator's real crew home is left untouched. Both declared negative controls were applied and logged: naming the fields by hand again without images fails the first case, and carrying the run-directory manifest path fails the second. The gate passes at the head with no failures against the dispatch base, and the two test files that call _node_from_pointer add no failures against that base.
