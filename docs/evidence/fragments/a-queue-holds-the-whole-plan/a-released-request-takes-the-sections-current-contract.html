A released request takes the section's current contract

What changed. A batch entry that omits a node field takes the section's value, and a queued request stored that value as if it were the dispatcher's own. A request held because its plan had moved was then released onto the text the plan moved to, while its stored done_when still described the text it was queued against — so the worker's prompt and its plan disagreed. _entry_node (reckon/crew/dispatch_batch.py) now records which node fields its section supplied, each with the digest of the value taken, and the batch writer stores that mark on the request beside the node it describes. _release_plan_review_holds (reckon/crew/queue_admission.py) re-derives every marked field from the section at the release base before the request leaves held, records the old and new digest of each under section_rederivation, and publishes the re-derived node on the same pass's in-memory record, so a request released and launched in one pass runs the current contract. crew queue edit (reckon/crew/queue_edit.py) clears the mark on any field it sets, so a coordinator's edit is kept; a field the dispatcher supplied carries no mark from the start.

Measured

Three cases in tests/test_a_released_request_takes_the_sections_current_contract.py run against a synthesised mounted project under RECKON_HOME with plan_review_gate set to enforce, so the plan change takes a hold. In the first, a request whose section supplied its done-when is held when the section's done-when changes, released once a review of the new text is stored, and launches with the new text: the pointer's done_when carries it, and section_rederivation.done_when records the digest of the stored value as old and of the launched value as new. In the second, a done-when the dispatcher supplied survives the same change. In the third, a done-when set by crew queue edit survives it.

The negative control is logged at logs/negative-control.log in the run directory: releasing with the stored fields, as before this change, makes the first case launch the old done-when and the case fails with assert 'pytest -q tests/test_new.py reports 5 passed' in 'Done when : pytest -q tests/test_old.py reports 2 passed.', EXIT=1. The four cases pass at the head. Every test file importing reckon.crew.queue_admission runs at the base revision and at the head in one arm at a time with -n 4; the two arms are compared by delta and the logs sit under logs/ in the run directory.
