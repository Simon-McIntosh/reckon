The self-composing plan review is scoped to its author's burst

What changed. The producer pass in reckon/crew/plan_review.py composed a content review for every quiet plan that owed one. On the live store that meant reviewing documents nobody was editing, dispatching the review under whichever session ran the sweep, and answering the not-changing findings of every stored review it found, one commit per answer. The pass now decides all three by facts the store already records, and leaves every other plan to its coordinator.

The burst window, and the slot spent inside it. A plan is the reflex's to review only while its last edit is between PLAN_REVIEW_QUIET_SECONDS (ten minutes) and PLAN_REVIEW_BURST_SECONDS (a day) old. Both bounds are measured by plan_review_edit_age from the plan file's own modification time, and every plan's age is one stat, so the window is applied to the whole project before anything is weighed and the read slot is spent among the plans inside it. The freshest edit is weighed first. Without that filter a project carrying hundreds of quiet plans spent every pass on a document nobody had touched, and the plan its author had just finished was never reached.

The author's session. The review is dispatched under the session of the run that last named the plan, never under the sweep's. plan_authoring_runs reads both stores a run is kept in — the live pointer's node.plan and the committed ledger row's top-level plan — keeps only runs under a day old, and takes the newest per plan. It reads each store once per pass. A plan no run named in the last day is refused with that reason, and its refusal is printed: a review composed for it would reach no reader.

Coverage, not the existence of a record. A stored review that read one section of a plan still answers read_plan_review, so asking whether any record covers the plan refused a plan whose other sections had never been reviewed, and the plan a coordinator was authoring never composed. The refusal now asks what it means: whether the stored reviews leave any unit uncovered.

Notes only on its own reviews. The pass records the review run ids it dispatched, and answers the not-changing findings of those records and no others. All of one pass's answers are written under one commit through _deferring_record_commits and _commit_record_writes_once. A note written before the walk fails is committed too: a later pass reads a written answer as answered, so an uncommitted one would be lost while the pass reports the failure.

The gate. tests/test_a_plan_review_composes_itself.py reports 20 passed. It covers a quiet plan with an hour-old run composed under that run's session, a two-minute edit refused, a two-day-old edit whose run is an hour old refused, a plan no run has named refused, a review in flight refused, notes on a composed review and not on another's, one commit for two notes, sixty plans of which one is inside the window and the rotation starts elsewhere, and the answers written before a failed note walk.

The negative control. Removing the bound on the plan file's age — if False and edited_age > PLAN_REVIEW_BURST_SECONDS — fails exactly test_a_plan_edited_two_days_ago_is_not_composed_though_it_owes_a_review at 1 failed, 17 passed, EXIT=1 (the file carrying eighteen arms at that point).

The live store. The timed dry_run of compose_owed_plan_reviews returns in 28.8 s on reckon and 7.4 s on nova without raising, inside the 30 s bound, and it lists reckon:a-queue-holds-the-whole-plan as owing a content review, attributed to the run r-20261028T062227367045 that named it on this session. The preview weighs every plan inside the window, so it is bounded by PLAN_REVIEW_PREVIEW_SECONDS rather than by a plan count; the plans it does not reach are named with the reason they were not composed.
