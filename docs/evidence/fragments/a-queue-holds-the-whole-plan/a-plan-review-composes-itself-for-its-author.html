The self-composing plan review is scoped to its author's burst

What changed. The producer pass in reckon/crew/plan_review.py composed a content review for every quiet plan that owed one. On the live store that meant reviewing documents nobody was editing, dispatching the review under whichever session ran the sweep, and answering the not-changing findings of every stored review it found, one commit per answer. The pass now decides all three by facts the store already records, and leaves every other plan to its coordinator.

The burst window. A plan is the reflex's to review only while its last edit is between PLAN_REVIEW_QUIET_SECONDS (ten minutes) and PLAN_REVIEW_BURST_SECONDS (a day) old. Both bounds are measured by plan_review_edit_age from the plan file's own modification time, so the quiet period and the burst window cannot disagree about when the edit was. A file whose time cannot be read refuses rather than passing the burst test.

The author's session. The review is dispatched under the session of the run that last named the plan, never under the sweep's. plan_authoring_runs reads both stores a run is kept in — the live pointer's node.plan and the committed ledger row's top-level plan — keeps only runs under a day old, and takes the newest per plan. It reads each store once per pass, because a ledger load per plan cost more than the reviews the pass starts. A plan no run named in the last day is refused with that reason: a review composed for it would reach no reader.

Notes only on its own reviews. The pass records the review run ids it dispatched, and answers the not-changing findings of those records and no others — a coordinator's own review is its coordinator's to answer. All of one pass's answers are written under one commit through _deferring_record_commits and _commit_record_writes_once. An id is dropped from the record once its review's record is in the store, which is the moment its notes have been answered.

The gate. tests/test_a_plan_review_composes_itself.py reports 18 passed. It covers every arm the section lists: a quiet plan with an hour-old run composed under that run's session, a two-minute edit refused, a two-day-old edit whose run is an hour old refused, a plan no run has named refused, a review in flight refused, notes on a composed review and not on another's, and one commit for two notes — beside the arms the first landing kept: the bounded read, the one-per-pass limit, the retried refusal and the dry run.

The negative control. Removing the bound on the plan file's age — if False and edited_age > PLAN_REVIEW_BURST_SECONDS — fails exactly test_a_plan_edited_two_days_ago_is_not_composed_though_it_owes_a_review at 1 failed, 17 passed, EXIT=1.

The live store. A timed dry_run of compose_owed_plan_reviews returns in 11.6 s on reckon and 3.2 s on nova without raising, inside the 30 s bound. Both previews are empty, and each plan they weighed is named with the reason it was not composed, so the empty result is accounted for rather than blind. The section's positive control could not be demonstrated: the watched plan reckon:a-queue-holds-the-whole-plan was quiet (21.1 minutes since its edit) but a stored review already covers its current content, so it does not owe a review and no plan on either project did. Its refusal, printed by the arm, is a stored review already covers the plan's current content.
