The rebuilt brief names have one owner

What changed. Two readers ask whether a brief is one a launch composes afresh: the queue's steering copy (is_rebuilt_brief) asks before it freezes a copy, and the composition (materialize_run_review_brief) asks before it writes. Each used to carry its own answer — _REBUILT_BRIEF_NAMES in reckon/crew/runs.py, and _RUN_REVIEW_BRIEF_NAME plus a literal set inside the composition. A name added to one was honoured by that reader alone, so the queue skipped its copy while the composition left the path untouched and the request launched from a path that was never written.

One declaration. reckon/crew/runs.py declares RUN_REVIEW_BRIEF_NAME, FIGURE_REVIEW_BRIEF_NAME and REBUILT_BRIEF_NAMES beside STEERING_FILE, because that module cannot import the review module. is_rebuilt_brief reads the set, and materialize_run_review_brief and _review_brief_path in reckon/crew/recovery_review_subject.py read it through runs, so a name is added in one place and both readers answer for it.

The test adds a name at runtime. tests/test_rebuilt_brief_names_have_one_owner.py monkeypatches runs.REBUILT_BRIEF_NAMES with an extra name and requires both readers to answer True for a path carrying it — the composition stub records that it was reached, so an early return cannot pass. A second case requires both readers to answer False for an undeclared name, so the set is what earns the yes rather than the directory the path sits in.
