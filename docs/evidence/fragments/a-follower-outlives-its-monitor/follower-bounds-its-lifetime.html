The follower's lifetime bounds a poll, a reload and its children

The defect

Four findings, all in the arming path the host ends at thirty minutes.

The lifetime bounded the gap between polls, not a poll. Two crew follow --lifetime 29m processes ran 3 h 36 m and 2 h 07 m under degraded storage, both inside the full-tree git status walk the recovery sweep runs over every registered worktree. The deadline was read between polls, so the only thing that could end the arming was the poll returning — which is exactly what a walk over hundreds of worktrees does not do.

A reload re-anchored the deadline at the replacement image's start. The carried instant is absolute, but the watch loop re-anchored it at its own started_at, so each reload charged the grant for that image's setup: a six-second grant ended 7.49 s after the arm, 8.61 s when the first sweep spawned a probe, and 8.61 s is past the eight-second bound §8's own case asserts.

Two hand-off variables lived in os.environ. The reader checkpoint (RECKON_FOLLOWER_CHECKPOINT) was placed in the follower's own environment at the reload, and the arming variable (RECKON_WATCH_ARMING) was inherited from the session that armed it. Every child of the follower inherits that environment — the recovery sweep's condition probes among them — and those children then carried a variable that governs an arming none of them owns. The lifetime deadline had the same defect before it was carried to the replacement alone.

The dispatch preflight reported follower conditions one at a time. A coordinator met them in sequence: no producer, then a follower whose lines end in a file, then session_attached: False with another session named as the delivering one. Each refusal named one condition, so each fix revealed the next; measured at about twenty-five minutes for one worker.

What changed

  1. reckon.cli._follow_watch_lines._sweep_on_cadence runs the sweep on its own thread and waits for it only as long as the arming has left. A poll still walking at the deadline is abandoned and the arming ends; a sweep begun after the deadline is not started at all. Without a deadline the sweep runs synchronously, exactly as before, so an arming without a lifetime is unchanged.
  2. reckon.cli.crew_follow converts the deadline — the absolute UTC epoch, fixed at the first arming and carried to replacements — into the watch loop's own clock once, at arming, and passes it in beside the grant. _follow_watch_lines uses an absolute lifetime_deadline when one is handed in and falls back to granting lifetime from its own start only when one is not.
  3. _FollowerReloader.poll writes the reader checkpoint into the mapping the re-exec passes and never into os.environ; the replacement reads and removes it in one step, as it already did for the deadline. crew_follow drops RECKON_WATCH_ARMING from its own environment as it arms, so no child inherits either variable.
  4. reckon.crew.dispatch._watcher_delivery_admission judges the producer and the session's delivery in one pass, and _unmet_follower_conditions names every unmet condition: no live producer, a follower that is registered but not delivering (with the reason follower_state gives), no registration at all, and — whenever this session's delivery is not in place — the sessions that do deliver right now. _FollowerAdmissionUnmet raises one WatcherRequired carrying the whole list and the one follower command that clears it, so the error key, exit code and watch payload a caller already reads are unchanged. A released registration is still admitted with the re-arm warning. A launch kind that carries no session delivery has no follower of its own to judge, but it is refused without the producer exactly as the ungated check refused it: the seat is what every launch kind reads.

Evidence

tests/test_follower_bounds_its_lifetime.py holds one case per finding, plus one that guards the producer's refusal for a launch kind that carries no session delivery. Its clocks are injected, so each case measures an interval it owns rather than one timed from outside: the poll blocks far past a deadline 0.5 s away, and the bound case requires the follower to end within one second of it with the poll still blocked — a follower that waited for the poll would end when the poll released it.

The reload case enters as a replacement image does — the same command line the first arming had, with the carried instant in the case's environment — and prices the replacement's setup on its own clock at 2.0 s, deliberately larger than the one-second slack the bound allows. An image that spends what is left of the carried instant ends within the slack; one that re-anchors at its own start ends that whole interval past it. Measured: the case passes at head in 0.86 s and fails at base with the arming ending 2.300 s past the instant — by construction rather than by load, so it now guards the fix where the wall-clock version of it did not (that version's base failure measured 1.49 s to 2.61 s and needed a slack wide enough to let it pass).

The child-environment case records each image's child environment through a parked run's declared probe, and its post-reload half waits for a line the replacement wrote: a dump holding only the first image's line would otherwise read as a clean second image, and whether the second sweep landed before the deadline is exactly the race that half no longer depends on. Its grant is 25 s rather than the reload case's six, because it waits for two recovery sweeps and a sweep's tail probes model lanes: the property is which variables a child inherits, not the deadline, so that grant has to outlast the work rather than bound it.

The launch-kind case dispatches through an in-harness backend with a session that is delivering, so the producer is the only condition left; it asserts exit 8 and the producer's refusal in the payload, and fails if the refusal is narrowed back to the cli launch kind.

The declared negative control is executed and logged: with the deadline check removed from the blocking poll in reckon/cli.py, the bound case fails at tests/test_follower_bounds_its_lifetime.py — 1 failed in 3.31 s, EXIT=1 — and cli.py was restored byte-for-byte afterwards. The log's first line is the declared string. A second control covers the restored refusal: removing the producer judgement from the non-cli branch of _watcher_delivery_admission makes the launch-kind case fail — 1 failed in 6.57 s, EXIT=1, the in-harness dispatch admitted with exit_code 0 — and with the refusal restored the same case passes in 2.80 s. Both mutations were verified clean against their commit afterwards, byte for byte.
