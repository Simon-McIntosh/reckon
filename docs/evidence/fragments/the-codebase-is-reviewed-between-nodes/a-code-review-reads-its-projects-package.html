The code review reads the reviewed repository's own import package

reckon/served_code.py resolves the reviewed package at the revision through package_directory: the pyproject.toml [project] name normalised (- → _) when that directory, or src/<name>, holds a tracked __init__.py; otherwise the single top-level package directory (or src/ child), excluding tests, docs and scripts; otherwise a PackageNotFoundError naming the candidates. _package_snapshot passes the resolved prefix to read_sources and roots the snapshot at it, so package_modules, neighbourhood and _reach read any package, not a literal reckon. One normaliser, served_code.dotted_token/as_module, owns the path-to-module mapping; plan_review._module_probes now calls it, so dotted_token is the single owner of the normalisation.

The new gate tests/test_a_code_review_reads_its_projects_package.py builds an acme-tools repository whose package is acme_tools and finds: package_modules lists the four modules and their two packages; neighbourhood of acme_tools/a.py holds acme_tools.b; a --path acme_tools/sub code subject names acme_tools.sub.c and acme_tools.sub.d; a two-candidate repository is refused naming alpha and beta; and this repository's package_modules equals the reckon-prefixed listing. Figures: the gate file and the nine existing served_code/plan_review importers ran 74 passed, EXIT=0. Declared negative control — restore the literal reckon prefix in the package snapshot — fails the three acme cases plus the refusal case (4 failed, 1 passed, EXIT=1).
