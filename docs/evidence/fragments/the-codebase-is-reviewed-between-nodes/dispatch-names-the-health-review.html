The payload carries the newest code review covering the node's write paths, or the command that composes one

An implementation dispatch now carries a health_review block. It is computed beside the lane advisory by _dispatch_health_review in reckon/crew/dispatch_admission.py: the block names the newest stored code review whose neighbourhood — the review record's named_paths together with its modules — covers every one of the node's product write paths (its .py paths), that review's age in days, and the open findings the findings reader already holds against those paths. When no covering review is younger than the seven-day window, the block names the compose command reckon crew review --project <p> --around <plan> --session <s> instead. The block is advisory: it refuses nothing, holds nothing and reroutes nothing; a node that writes no product source carries a null block rather than a command that could not run.

Scope note. The block's logic sits in dispatch_admission.py as briefed, but the dispatch payload is assembled in reckon/crew/dispatch_plan.py (the DispatchPlan dataclass, its as_dict, and the plan_dispatch call site), not in dispatch_admission.py as the brief stated. That file is unclaimed by any concurrent node, so the minimal wiring — one field, one payload key, one call, one import — was made there; nothing else in it changed.

What a review of this node changed. The block counted open findings with a filter of its own, duplicating the one plan_review._open_findings_for already applies; it now calls that function and takes the length of its result, so the block holds no second opinion about which rows are open. The count is read from the tree the findings reader walks — the committed docs/state/<project>/reviews records — so the test that populates it stores a run-kind committed record and exempts one of its three findings by index, which is what makes the bound assertion two rather than three or zero.

Left open. A store made unreadable is only reachable by the block when the block is called directly: the dispatch's review gate reads the same store through a second, unguarded call site (plan_review._stored_code_review_run_ids, reached from store_delivered_reviews), so a store unreadable for the whole process breaks the dispatch before the block sees it. That unguarded reader is another node's file and was not edited; the block's own branch is exercised by handing it an unreadable store, and the call-site guard belongs to a separately dispatched node.
