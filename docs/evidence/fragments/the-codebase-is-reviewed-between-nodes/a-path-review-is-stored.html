A path-only code review is stored by the delivery path

store_delivered_reviews read the code deliveries with around=plan_slug, and the keep filter in delivered_code_reviews retains only sidecars whose around equals that value. A review composed with --path alone carries an empty around, so it was composed and dispatched and then never read into the store. The delivery call now reads delivered_code_reviews(project): every delivered code review for the project is stored once, keyed by its neighbourhood, whether its subject came from --around or --path. The gate adds a path-only case to tests/test_review_composes_a_code_subject.py that composes with --path reckon/a.py, writes the fixed health report into the neighbourhood report directory, runs store_delivered_reviews, and reads the record back under its neighbourhood key; the key is asserted against an expectation computed from the key's documented form (sha256 of the sorted union of named paths and adjacent modules, first twelve hex characters) rather than against code_review_key, so the read side cannot move in step with the write side. The file passes 6 tests at EXIT=0. The declared negative control restores the filter keeping only the plan's around value, drops the path-only record, and reddens the new case (EXIT=1, 1 failed, 5 passed).
