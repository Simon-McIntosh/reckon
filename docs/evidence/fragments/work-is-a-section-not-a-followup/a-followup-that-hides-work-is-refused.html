Landing record — a followup that hides work is refused

Appending an open followup whose invocation hides work is refused on every append route: edit_plan's state ops, the HTTP plan patch path, and the append tool. The HTTP path compares the patched list against the stored one, so a resolution that resends the list is untouched. One refusal built on classify_followup names the reason word and both remedies: add the work as a section of this plan, or create a new plan when this one is complete and point the followup at it; a step that needs authority is recorded as an open decision instead. Resolving, superseding and reading a followup are never refused.
