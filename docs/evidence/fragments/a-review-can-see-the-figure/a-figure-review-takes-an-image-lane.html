Review lane selection admits a lane declaring the modality the review requires

A review that requires an input modality now draws only from the lanes that declare it, and such a lane is admitted despite review_excluded_backends. The exemption lives in _ordered_review_lanes in reckon/crew/recovery_review_dispatch.py, before the candidate list is built, threaded through _review_lane_plan, _review_lane_candidates and _no_lane_reason as a profile; a lane's eligibility is read through reckon.flight.missing_input_modalities. A review requiring no modality keeps the exclusion unchanged. When no configured lane declares the modality, the hold names the modality rather than a lane. select_profile_backend is retired from reckon/ and tests/.

Measure: with a flight whose only image-declaring lane is listed in review_excluded_backends, the review lane candidates for the figure profile are exactly the image-declaring lanes, that lane included; the candidates for a text review still exclude it; with no lane declaring image input the figure review gets no lane and its reason names the image modality. The declared negative control removes the exemption, and the image-lane case then returns no candidate while the text case is unchanged.
