§26 — a dispose refusal names the rubric that holds the record

A run is reviewed under more than one rubric, and each family is stored beside the others. crew dispose --review names the review run whose record the disposition answers, but the selection behind that name is the text family unless --rubric is given, so a figure review named by --review alone resolved to nothing. The refusal then read “carries no record from review run …”, which is true of the selection and false of the store: the record existed, one family over. A reader cannot tell a review run that produced no record from one whose record this selection never looked in, so the finding a figure reviewer raised could not be answered through the verb that raised it.

The family is a property of the stored record, so the store answers it rather than each reader deriving it. review_run_record_rubrics in reckon/crew/review_records.py reads the records the named review run produced for the run — committed tree first, staging store after it, the same order record_for_review_run_anywhere reads — and reports the rubric each carries, with the empty name standing for the text family every rubric-less record belongs to. The refusal is composed by _no_named_review_record_refusal in reckon/crew_run_commands.py: it names the selection that was asked for, then the family that does hold the record. A family the verb can select is handed over as the flag value that selects it (--rubric figure); the text family is named as the selection reached by omitting the flag; a family no disposition selects is named as such rather than offered as a flag the verb would refuse. A review run with no record in any family keeps the existing refusal, which now says what was searched.

The path is exercised through the CLI, not asserted as a string. tests/test_a_dispose_refusal_names_the_rubric_that_holds_the_record.py seeds a temporary crew home with a text review and a figure review over one seeded checkout, the figure record carrying one blocking finding. The first case names the figure review with --review and no --rubric: the command exits non-zero, its output carries --rubric figure and the review run's id, both record files are byte-identical to what they were, and the blocking finding still blocks. The second runs the same call with --rubric figure and shows the disposition landing on the figure record by path, the blocking list emptying, and the text record beside it gaining no disposition key. The third names a review run that produced no record at all and shows the existing refusal with no rubric offered, so the new naming is coupled to a record the store actually holds.
