A figure review is complete by its own rubric

What changed. The completeness rule in reckon/crew/recovery_review_subject.py (_review_missing_measures) judged every stored review record against the six landed-node score dimensions. A figure review records a verdict per item of its own rubric instead, so a figure record that carried all six of its measures was refused at its first promotion as an incomplete review, naming six dimensions it was never asked for. The rule now reads the record's rubric through the same reader crew check --review applies: a figure record is complete when it carries a non-blank verdict for every item of FIGURE_REVIEW_ITEMS, and its refusal names the figure item it lacks. Because the rule lives in the one helper every other reader calls, _review_is_complete and the six production paths that read it give the delivery check's answer rather than a second one

Every other record keeps the completeness rule as it was, so a text record and a claims record are judged exactly as before. A rubric_items value that is not a mapping reports every item missing rather than raising, because the check runs on classification paths that must not take the pass down with them. The delivery check delegates to the shared rule and holds no measure list of its own.

Repair after review

An independent review of this landing found the figure branch in the wrong place: it had been added to the delivery check as a second completeness dispatcher beside _review_missing_measures, so the delivery check and the six production readers of _review_is_complete could answer differently for the same record. The repair moves the branch into that owner and leaves the delivery check delegating to it, so one rule answers for every reader. The delivery module therefore carries no diff from the base revision at all: the whole change is 35 lines in reckon/crew/recovery_review_subject.py.

  • A figure record is complete for the fleet, not just for promotion. The test now asserts _review_is_complete(body) is True on the same body it proves deliverable, so the classification, repair-dispatch, review-dispatch, acceptance and obligations readers give the promotion check's answer.
  • The record proven deliverable is one the review contract accepts. Both fixtures carry added_failure_count and added_failure_ids, and the test asserts review_record_refusals(body) == [] before staging it. The earlier fixtures omitted both, so the case proved delivery for a record crew check --review would have refused.
  • Negative control. Reverting the owner to its delivered form, leaving the delivery check delegating, turns eight cases red: the deliver-and-promote case, the blank-verdict case, and all six missing-measure cases.
  • Arms after the repair. The gate is the test files importing either review module, resolved in each arm's own tree and run one arm at a time at -n 4: base 082607a9e8 gives 349 passed, 2 failed, 1 error; the repaired head 943681379d gives 359 passed, the same two failures and the same error, so the delta is the ten new cases and no new failure. Both arms' two failures are citation-resolution cases unrelated to this change and failing identically at the base revision.
