§24 — a figure finding's dispose command names its rubric

A run is reviewed under more than one rubric and each family is stored beside the others rather than in place of them, so crew dispose selects a figure record only when the command carries --rubric figure. The command an obligation handed a coordinator for a blocking finding was composed from the stored record but named only the review run, never its family, so a figure finding's duty printed the text-review form. Running that command was refused for selecting no record at all, and the finding could not be answered from the surface that raised it.

The rubric is known only where the record is held, so it travels with the record rather than being re-derived by each reader. dispose_commands in reckon/crew/review_dispositions.py takes a rubric beside the review run it already took, renders --rubric figure when one is named, and asks _newest_delivered_review_run_id for that family's round instead of the text review stored next to it. _finding_dispose_commands in reckon/crew/recovery_review_dispatch.py takes the stored record and hands the composer both the family and the round, so the --review flag names the figure review's own run. Its callers dispatch the record they already hold: obligations._review_dispatch_refusal, which composes the duty a coordinator acts on, and _open_review_refusal, which composes the refusal text. That refusal now also carries the record's family and round on its report, so obligations._reflex_open_refusal — which holds only the report — composes the same command rather than falling back to the text form.

A caller holding no record renders the text form exactly as before, which is what keeps a text review's command unchanged: dispose_commands is called with no rubric and no review run from that path, so the two flags are absent and the command is the one every earlier call produced.
