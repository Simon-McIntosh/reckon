§22 — a figure review judges the rendered PNG, never the SVG source

reckon/crew/prompts/figure_review.md asked a finding to be anchored to “the source figure path and line”. A figure review is meant to judge the rendered picture a reader sees, but an SVG's lines are generated XML, so a reviewer could read text elements, dimensions and glyph coordinates out of the markup and report a label the rendered PNG clips or hides. A census of the live figure reviews found every image Read was a PNG, while most reviews also ran 5 to 20 Bash commands over the SVG source; the review of vs3-linkage-repair ran twenty, pulling text elements and glyph coordinates with git show <head>:<figure>.svg through grep and sed.

The prompt now carries a Judge the rendered PNG, never the SVG source paragraph: each figure is judged only from the rendered PNGs named in the review, and the reviewer may not open, read, list, search, render or git show an SVG or any image other than the named PNGs. It anchors a finding to the figure's repository path, or, where the run's own diff shows the script that draws the figure, to a line in that script, and states plainly that a finding is never anchored to a line of SVG markup. The finding-shape bullets follow: file is the figure's repository path or the path of the drawing script, and line is a line in that script or null, replacing the old “source figure path” and “a line in that source” wording. _review_brief_text in reckon/crew/recovery_review_subject.py repeats the rule inside the figure rubric's record contract, so a reviewer that reads only the composed brief receives it too; a text-rubric brief is unchanged.
