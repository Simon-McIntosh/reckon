Promotion refuses a PNG twin of an SVG

A run that commits a PNG beside an SVG of the same stem in the same directory is now a finding of the shared manifest audit: crew check --manifest reports it to the worker while it can still remove the file, and crew complete refuses the promotion with the same text, naming both paths. The two surfaces share one predicate, _png_twin_findings_for_base in reckon/crew/reports.py, so the worker-facing message and the refusal cannot drift apart.

The check reads the run's commits from its base to its head (git diff --diff-filter=A against git ls-tree at HEAD), never the working tree, so a PNG rendered to look at the figure and never staged is not a finding. A PNG already present at the base is not the run's twin either, which is what keeps a regenerated pair held in both formats on purpose acceptable; a PNG with no SVG beside it passes, since the rule allows PNG for raster content.

Measure: tests/test_a_png_twin_of_an_svg_is_refused.py — five cases, each building its own repository under a temporary directory and reading nothing outside it. The twin case asserts the check exits non-zero naming both paths and that crew.complete raises the refusal naming both; the other four assert both commands pass. The negative control removed the twin check from audit_manifest and from the promotion check list: the twin case then passed both commands and the test failed, and the four other cases still passed. The reports-surface suite — the 29 test files importing reckon.crew.reports — shows no added failure against the base revision, and ruff check and ruff format add no finding on the changed files.
