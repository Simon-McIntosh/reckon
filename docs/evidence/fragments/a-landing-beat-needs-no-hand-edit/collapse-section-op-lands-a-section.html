The collapse op lands a section and its declaration together

Retiring a landed section used to take two writes: one to replace its authored prose with the landed card, another to set its declaration to done. Between them a reader could see the card without the declaration, or the reverse. A single op now does both in one versioned write, and collapsing an already-collapsed section refreshes its card in place rather than nesting a second one.

What changed

  • reckon/_store.py gains collapse_section, dispatched from _OP_DISPATCH beside insert_section and append_evidence. It validates the section id, a non-empty summary and a non-empty evidence anchor, then queues the HTML replacement as a write effect and sets the section's declaration to done on the same working state, so the two cannot be observed apart.
  • The card is the shipped landed card: a <section class="section-landed"> whose <header> carries the badge and the original <h2> — and therefore the heading and its id — with a landed-summary paragraph linking the evidence anchor. That header shape is the one the structure audit exempts as card chrome rather than a second shell header.
  • A section already carrying a card is replaced from the card's opening tag to its matching close, so a repeat or refresh keeps exactly one card and one closing tag and the new summary and evidence link replace the old. An authored section runs from its h2 to the next heading, landed card or structured-state region, or </main>; a landed card is itself a boundary, so collapsing a neighbour cannot consume a card's opening markup.
  • A card whose close cannot be found, or whose span would reach across a second heading or a structured-state region, is refused and the file is left unchanged — a partial result is never written.
  • reckon/mcp.py adds collapse_section to _OP_VOCAB, so an agent reading the op grammar can discover it.

The gate

tests/test_edit_plan_collapse_section.py drives the plan-editing tool against a plan synthesised under a temporary directory at _edit_plan_tool (the same call site the MCP server uses), then reads the file back through _plan_html.read_state and audits it with reckon audit-doc.

  • test_collapse_replaces_the_body_and_keeps_the_heading — the authored prose is gone, the heading and its id survive, and the card carries the badge, the summary and the evidence link.
  • test_collapse_sets_the_section_declaration_to_done — the declaration map and the section record both read done.
  • test_collapse_leaves_structured_state_regions_byte_identical — the decisions, followups and comments regions are byte-for-byte unchanged.
  • test_collapse_refuses_a_missing_section_and_leaves_the_file_unchanged — a missing id returns op_error and writes nothing.
  • test_collapsed_result_passes_audit_doc_without_a_duplicate_header — the collapsed file passes audit-doc with no header-duplicate finding.
  • test_collapsing_twice_leaves_one_card_with_the_latest_summary — a second collapse keeps exactly one card carrying the second summary and link, drops the first cleanly, and audits clean.
  • test_collapsing_a_neighbour_keeps_both_cards, parametrised over both orders — collapsing one section then its neighbour leaves both cards intact and audits clean.
  • test_a_card_without_a_closing_tag_is_refused_and_leaves_the_file_unchanged — a card with no closing tag is refused and the file is byte-identical.

Declared negative controls

Control 2 — extent. Declared mutation: restore the scan-to-next-region extent when collapsing. Forcing the card-span path off, so the extent is again scanned to the next structured-state region, the twice-collapsed case fails on assert 2 == 1: two cards remain and the first is left unclosed. This is the defect the fix repairs.

Control 1 — declaration. Declared mutation: leave the section declaration unchanged when collapsing. With the declaration assignment replaced by a no-op the declaration case fails, because the write is refused when the section record and the declaration disagree.
