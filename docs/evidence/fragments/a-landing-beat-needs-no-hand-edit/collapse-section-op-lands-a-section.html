The collapse op lands a section and its declaration together

Retiring a landed section used to take two writes: one to replace its authored prose with the landed card, another to set its declaration to done. Between them a reader could see the card without the declaration, or the reverse. A single op now does both in one versioned write.

What changed

  • reckon/_store.py gains collapse_section, dispatched from _OP_DISPATCH beside insert_section and append_evidence. It validates the section id, a non-empty summary and a non-empty evidence anchor, then queues the HTML replacement as a write effect and sets the section's declaration to done on the same working state, so the two cannot be observed apart.
  • The card is the shipped landed card: a <section class="section-landed"> whose <header> carries the badge and the original <h2> — and therefore the heading and its id — with a landed-summary paragraph linking the evidence anchor. That header shape is the one the structure audit exempts as card chrome rather than a second shell header.
  • The replaced body ends at the next heading, the next structured-state region, or </main>, whichever comes first, so the replacement never reaches across a data-reckon region.
  • A missing section is refused inside the write transform, before any bytes are written, and the file is left unchanged.
  • reckon/mcp.py adds collapse_section to _OP_VOCAB, so an agent reading the op grammar can discover it.

The gate

tests/test_edit_plan_collapse_section.py drives the plan-editing tool against a plan synthesised under a temporary directory at _edit_plan_tool (the same call site the MCP server uses), then reads the file back through _plan_html.read_state and audits it with reckon audit-doc.

  • test_collapse_replaces_the_body_and_keeps_the_heading — the authored prose is gone, the heading and its id survive, and the card carries the badge, the summary and the evidence link.
  • test_collapse_sets_the_section_declaration_to_done — the declaration map and the section record both read done.
  • test_collapse_leaves_structured_state_regions_byte_identical — the decisions, followups and comments regions are byte-for-byte unchanged.
  • test_collapse_refuses_a_missing_section_and_leaves_the_file_unchanged — a missing id returns op_error and writes nothing.
  • test_collapsed_result_passes_audit_doc_without_a_duplicate_header — the collapsed file passes audit-doc with no header-duplicate finding.
