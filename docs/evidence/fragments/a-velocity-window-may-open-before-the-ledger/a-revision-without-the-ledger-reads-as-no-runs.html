A revision without the ledger reads as no runs

Two ledger reads called git show unconditionally, so a window whose base or head predated the ledger's first commit aborted the whole view. Both now go through the one batched reader, which reports an absent object as None; a revision with no ledger reads as a ledger with no runs and a None digest, while a read of a ledger that is present and fails still raises.

What changed

  • _read_ledger reads the ledger's bytes through read_blobs. A revision whose tree has no crew.json returns no records and a None digest rather than raising; a present ledger whose batched read fails still raises, because read_blobs maps only a missing object to None.
  • recover_ledger_clocks stops parsing the ledger at the base itself and takes the runs present there from _read_ledger(repo, base, …), so a base with no ledger has no runs present and every candidate is searched.

The gate

tests/test_velocity_reads_a_revision_without_the_ledger.py builds a temporary git repository whose first commits carry no docs/state/sample/crew.json and whose last commit adds one with a run row, and points both velocity caches into the same directory.
