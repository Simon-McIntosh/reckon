A metadata index survives a restart

Commit 1d48ac7d adds reckon/metadata_index.py. It keeps one metadata index per mounted project on disk, under the configuration home's cache directory at cache/metadata-index/<sha256(project, docs_dir)>.json, and builds it by walking the docs tree, stat'ing each file and re-parsing only the files whose stat identity differs from the recorded one. A persisted entry carries the stat identity alongside the row and is validated against the project and docs root before it is used, so an index written for another tree is declined rather than trusted.

A row carries exactly the declared fields — slug, href, type, title, status, sprint, archived, created, edited and the figure's width/height — and the stat identity is deliberately not one of them. GET /_index/<project> answers with the list of rows and nothing derived: no roadmap, no readiness, no live runs, no stat bookkeeping. The fleet change watch drops a tree's in-process rows when the kernel reports a change to it, so the next read re-stats that tree and rebuilds the rows that moved.
