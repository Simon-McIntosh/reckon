A page paints from the index, and derived state arrives when ready

Commit f83e38014 changes docs/ui/state-loader.js so the served page asks /_index/<project> first — one row per document and figure and nothing derived — and resolves window.STATE_READY on those rows. The discovery payload is fetched on its own task afterwards and its derived fields and ready set are merged into the rows already on screen: each row keeps its object and its place in the list, a row the index did not carry is held as an arrival rather than inserted, and the payload-level blocks (ready set, sprints, counts) are refreshed around them. window.STATE_DERIVED_READY resolves when that merge has happened.

An index request that answers 404, or fails at the network, selects the path that stood in for it before — the discovery payload, then state/<project>/projection.json, then state/<project>/index.json — so a static build still paints. The derived values stay computed in Python; the loader only merges them.

The added failure, and the defect behind it

The change watch that serves /_changes/<project> drops the cached discovery but not the cached metadata index, so after a reported change the next /_index/<project> request can answer a row list that predates it. reckon/serve.py's _send_project_changes calls _invalidate_discovery_signatures and _invalidate_discovery; _invalidate_tree_views — which also calls metadata_index.invalidate_tree — is reached only by the fleet watch that main() arms.

Reproduced at ad6971e0d with the test's own harness: after the change event and await window.revalidateProjectState(), the loader's requests are /_index/sample, /_discover/sample, /_index/sample, and the inventory is ["present"] — the plan written before the event is missing. At the base revision the same test passes because the old loader re-read discovery, which the change watch does invalidate.

The repair is one line in the change watch — route its invalidation through serve._invalidate_tree_views(docs_dir), which is the two calls it already makes plus metadata_index.invalidate_tree, the intent its docstring states ("a change to any one of them must drop all three together"). This node's write scope does not include reckon/serve.py, so the failure is recorded as a follow-on rather than fixed here.
