A page paints from the index, and derived state arrives when ready

Commit f83e38014 changes docs/ui/state-loader.js so the served page asks /_index/<project> first — one row per document and figure and nothing derived — and resolves window.STATE_READY on those rows. The discovery payload is fetched on its own task afterwards and its derived fields and ready set are merged into the rows already on screen: each row keeps its object and its place in the list, a row the index did not carry is held as an arrival rather than inserted, and the payload-level blocks (ready set, sprints, counts) are refreshed around them. window.STATE_DERIVED_READY resolves when that merge has happened.

An index request that answers 404, or fails at the network, selects the path that stood in for it before — the discovery payload, then state/<project>/projection.json, then state/<project>/index.json — so a static build still paints. The derived values stay computed in Python; the loader only merges them.

The stale index the first paint exposed

Painting from the index first made a second defect visible. The watch that serves /_changes/<project> dropped the cached discovery but not the cached metadata index, so a page revalidating after its own change event was handed rows that predated it. Measured at ad6971e0d with tests/test_spa_state_boundary.py::test_open_page_receives_new_plan_without_navigation_or_polling, left unchanged: after the change event and await window.revalidateProjectState() the loader's requests are /_index/sample, /_discover/sample, /_index/sample and the inventory is ["present"] — the plan written before the event is missing. Only the fleet watch that main() arms reached _invalidate_tree_views, which is the call that drops all three views of a tree together.

Commit 83207a0e0 routes the per-connection watch through that same call, so every watch that reports a tree drops the discovery reuse window, the cached discoveries and the in-process index in one rule; the per-stream stamp helper _invalidate_discovery, whose only caller it was, goes with it. The watch-side rule was chosen over revalidating rows by stat identity on every request, which would re-stat the whole tree per request and undo the restart cost the index exists to remove. The boundary case above now passes unchanged.

The case that pins it lives in tests/test_page_paints_from_the_index.py, against a real server: the served index is read, one plan is rewritten, the change event is awaited, and the endpoint is read again — the row carries the new title. Commit 07e4597e2 restores inside that one entry point the guard the per-stream stamp used to provide: the index rows and the reuse window go on every report, while a cached discovery computed after the reporting watcher's own observation survives, so two open pages cost one rebuild per change. The stamp is taken as the change is observed, before the settle wait, at both watch call sites.

Two cases cover it. test_two_change_streams_recompute_discovery_once opens two real streams, rewrites one plan and counts rebuilds: one. It is honest about its limit — it passes at the pre-guard revision too, because the second stream's pop lands before the first stream's rebuild in that interleaving — so test_a_report_keeps_a_discovery_newer_than_the_report pins the guard itself, deterministically: a change is reported, the next read rebuilds, a second report of the same change leaves that rebuild in place while the index rows are rebuilt again. Against the pre-guard revision the file reports 1 failed, 1 passed, EXIT=1.

Two defects the review found in the loader are fixed in the same commit. window.STATE_DERIVED_READY was created only on the index path, so a consumer awaiting it after the fallback — the path a live server takes until it restarts — got undefined; every path now settles it, after the merge on the index path and with the assembled state on the fallback. And mergeDerived pushed a row the index had not carried into the inventory while also recording it as pending; it is now held as an arrival only, so a row that arrives with the derived payload does not insert itself into the list the reader is looking at. Both cases fail against the pre-fix loader (2 failed, EXIT=1).
