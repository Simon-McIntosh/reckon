The cached index absorbs each change

The index keeps its cached build across every change a source can attribute, and drops it only when a change names nothing. The gate passes: 8 passed, EXIT=0. The one case in a neighbouring suite that this landing first regressed is repaired in the detector, and the gate carries the case that reproduces it.

The change is carried as a value, not as a count. metadata_index.TreeChange holds a set of docs-relative files and a set of docs-relative directories, and mark_tree_paths folds one into a mark map keyed by the docs root. The cached read takes the mark, re-observes each marked directory's stat identity, re-parses each marked file, and reuses every other row from the persisted shape without a stat. A mark the cached build cannot absorb — its persisted shape is unusable — falls through to the rebuild that was the old answer, so a mark never costs correctness. Every other derived view is invalidated and every subscriber is notified exactly as before, because the marking happens inside _invalidate_tree_views, which still drops the discovery reuse window and the cached discoveries on every reported change.

Five sources name their paths. The kernel watch's consume() and drain() now return the (path, is_directory) events they read rather than a bare count, and observed_change turns them into marks: a directory event marks its parent directory, a covered file name marks the file, and anything else marks nothing. The detector's fast pass marks every directory whose identity moved and, when the git identity moves and HEAD moved with it, marks the covered paths the commits between the two heads touch by name; staging alone moves the index file and marks nothing, because a staged file has no new commit date to give a row. The slow pass marks the covered files whose stat moved, and a state-directory rewrite marks nothing because state files are not covered. _send_project_changes marks the names from its own burst, and a fleet-pipe wake that carries no names marks nothing. An inotify queue overflow, an unresolvable HEAD and a commit range git refuses to diff are all unattributable, and an unattributable change drops the build.

The gate is tests/test_the_cached_index_absorbs_each_change.py: 7 passed, EXIT=0. Case 1 writes a JSON file in a deep state directory and confirms neither build_index nor _dir_identity is called, on a tree whose documents sit under a typed root. Case 2 edits one HTML document under a kernel burst and asserts the exact set of stat-ed directories is the one holding the change, with its inner directory included and the figures directory absent. Case 3 moves a directory and shows the fast pass marks that directory, then picks up an HTML added inside it. Case 4 stages, commits a JSON-only change and commits an HTML change, showing that staging and the JSON commit leave the build alone and the HTML commit refreshes the row with the commit's own date. Case 5 overflows the event queue and shows the build is dropped, not kept. Case 6 edits a document in place for the slow pass and shows the row refreshed within the build, while a state rewrite marks nothing. Case 7 holds an open change stream across a JSON write and shows the build object is the identical one afterwards. Case 8 writes a second document into a marked directory after that directory's mark and before the read that absorbs it, so the read's own shape already contains it, then runs the fast pass and requires the pass to report the directory and mark it rather than compare it against a stamp the write had swallowed.

Nine controls are armed one per environment variable, each applied, run, logged and unset, and each fails the case it belongs to with EXIT=1 against the head arm's 8 passed and EXIT=0: dropping the build on every kernel burst fails cases 1 and 2; ignoring HTML names fails cases 2 and 4; dropping on every moved directory fails case 3 and the folded-write case; skipping covered entries in the re-scan fails four cases; dropping on every git identity change fails cases 3 and 4; keeping the build on an unattributed change fails case 5; dropping whenever the slow signature moves fails case 6; dropping on every stream wake fails case 7; adopting the reloaded stamps wholesale fails case 8. Nothing was mutated in the source tree to apply them, so no reversal was needed, and git status --porcelain is empty after the run.

That failure was this landing's own regression, and it is repaired. The absorbing read re-scans a marked directory and then writes the shape it measured, so a document landing between that scan and that write is inside the shape the detector reloads on the next pass; adopting the reloaded stamps wholesale compared the directory against a stamp that already contained the second write, the pass reported nothing, and the notification carrying the change to an open stream was never sent. merge_dir_stamps now compares each directory the detector already holds against its current identity first: where it has moved, the detector's own stamp is kept and the pass goes on to report the directory; the reloaded stamp is adopted only where the directory has not moved since the detector last looked, and a directory the reloaded shape no longer records is dropped with it. The case that carried the defect passes 4 times out of 4 standalone runs, EXIT=0 each, and the gate gained the case that reproduces it, with the reload's own control.
