A served log keeps the home its server first served under

The served log's path was resolved again for every access line (Handler.log_message → _write_access_line → _server_log_path → the configuration home the environment names) and again before every request (_bound_server_log). A change stream's handler runs on a thread that outlives the request that opened it, so its closing access line was written after a test's teardown had restored RECKON_HOME and landed in the operator's own ~/.config/reckon/logs/server.log rather than the test's home; a request that found the log bound crossed could rotate the operator's log the same way. A server object is what every handler reaches as self.server, so a bare ThreadingHTTPServer a test builds around serve.Handler leaked through the same path as the served entry point.

Change. reckon/serve.py resolves the served log path once per server object, at that server's first request, and keeps it on the object (_served_log_path, attribute _reckon_served_log_path). Every access line and every bound check made for that server's requests passes the kept path, so a home that moves after the first request — a teardown restoring the environment while a handler thread is still open — cannot retarget a later line or a rotation. The live deployment is unchanged: its environment never moves, and its log path is the one it resolved before. The startup bound check in serve.main still resolves freshly, before any server exists.

Measure. tests/test_a_served_log_keeps_the_home_it_started_under.py builds a bare ThreadingHTTPServer around serve.Handler under one temporary home, serves one binding request, then points RECKON_HOME at a second temporary home. Case 1: a change stream opened before the move closes after it, and the first home's log carries the closing GET /_changes/sample line while the second home holds no log. Case 2: the log bound is lowered and the first home's log pushed past it after the binding request and before the move, and one request after the move rotates that log, leaving a non-empty predecessor beside it and creating nothing in the second home. Head arm: 2 passed, EXIT=0 (logs/gate-files-n4.log, run at 91087a8 with -n 4 together with the cross-node suite — 16 passed). Control: the access line's path resolved per line again, and separately the bound check's path resolved per call again — each fails its own case, 2 failed, EXIT=1, and the tree was restored by hash comparison (logs/negative-control.log). tests/test_every_module_fits_a_worker_window.py passes with reckon/serve.py at 47,032 estimated tokens against the 50,000 bound.
