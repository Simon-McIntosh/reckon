A changed directory re-scans only itself

The shared covered-set reuse stopped being all or nothing. A directory's recorded stat identity moves exactly when an entry is added to or removed from it, so _reuse_covered now keeps the persisted files of every directory whose identity is unchanged and rescans only the directories whose identity moved. The rescan runs the one docs-tree walk with roots set to those directories and skip_subtrees set to every recorded directory, so a directory the tree already had keeps its own identity check rather than being read twice, while a subdirectory the walk does descend into is one the tree did not have before and is read in full. A recorded directory whose stat identity cannot be taken — it is gone — drops its files and its descendants. An absent or empty persisted index returns None and the build walks, as before.

Every reader of the covered set goes through it. index_rows now consults it on the process-cache miss as well as on the revalidate path, so the cache-miss read that serves /_index takes the incremental file set instead of handing build_index nothing; the discovery signature keeps reaching it through _covered_files_for_project and _covered_files; and the resource identity listing in reckon/resources.py reads reused[0] unchanged. build_index gained one keyword, rescanned, so a build whose file set came from rescanning persists the observed directory identities even when no row changed — without it a non-covered file added to a deep directory would leave the stale identity stored and the next cold read would scan the same directory again.

The gate is the new tests/test_a_changed_directory_rescans_only_itself.py: 5 passed, EXIT=0. It builds a nested temporary tree, persists its index, clears the process cache to stand in for a restart and reads through index_rows(..., revalidate=False), the served path. Case 1 adds a non-covered file to one deep directory: the rows are unchanged and a spy on os.scandir shows exactly that directory read. Case 2 adds an HTML file to a changed directory, removes one and adds a new subdirectory holding an HTML file: each row moves as it should and the covered set equals a full walk's. Case 3 removes a recorded directory and its files are gone. Case 4 clears the cache again and scans nothing, because the identity of the rescanning build was persisted. Case 5 does the same through _covered_files_for_project, which reads exactly the moved directory and returns a full walk's set.

Five mutations are armed one per environment variable, and each fails the case it belongs to, every arm ending EXIT=1 against the head arm's EXIT=0. Handing build_index no covered set on a cache miss fails case 1 (and cases 4 and 5, which assert exact scan sets); skipping new subdirectories fails case 2; keeping a removed directory's files fails case 3; recording the rescanning directory's identity as it stood before the change fails case 4; leaving the discovery reader on the all-or-nothing fallback fails case 5. The three the node declares are logged arm by arm in one file, the other two in one log each.
