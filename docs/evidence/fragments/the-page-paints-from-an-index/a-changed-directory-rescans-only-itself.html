A changed directory re-scans only itself

The shared covered-set reuse stopped being all or nothing. A directory's recorded stat identity moves exactly when an entry is added to or removed from it, so _reuse_covered now keeps the persisted files of every directory whose identity is unchanged and rescans only the directories whose identity moved. The rescan runs the one docs-tree walk with roots set to those directories and skip_subtrees set to every recorded directory, so a directory the tree already had keeps its own identity check rather than being read twice, while a subdirectory the walk does descend into is one the tree did not have before and is read in full. A recorded directory whose stat identity cannot be taken — it is gone — drops its files and its descendants. An absent or empty persisted index returns None and the build walks, as before.

Every reader of the covered set goes through it: the discovery signature reaches it through _covered_files_for_project and _covered_files, the resource identity listing in reckon/resources.py reads reused[0] unchanged, and index_rows now consults it on the process-cache miss as well as on the revalidate path, so the cache-miss read that serves /_index takes the incremental file set instead of handing build_index nothing.

The scan is recorded where it happens, by the reuse itself, and not left to the build that may follow. The readers that want only the file set never reach a build, so a scan they made and did not record was a scan the next reader in the same read repeated: measured on the cold read, the one directory whose identity had moved was listed three times. _reuse_covered now writes the shape it observed — the file set and every visited directory's identity — on the read that scanned, which drops a vanished directory's files in the same write. The build no longer carries a keyword saying whether its file set came from a rescan, because nothing needs it: with the observation recorded at the scan, the reader that rescanned leaves the whole shape current for the next read, including when no row changed.

The gate is the new tests/test_a_changed_directory_rescans_only_itself.py: 5 passed, EXIT=0. It builds a nested temporary tree, persists its index, clears the process cache to stand in for a restart and reads through index_rows(..., revalidate=False), the served path. Case 1 adds a non-covered file to one deep directory: the rows are unchanged and a spy on os.scandir shows exactly that directory read. Case 2 adds an HTML file to a changed directory, removes one and adds a new subdirectory holding an HTML file: each row moves as it should and the covered set equals a full walk's. Case 3 removes a recorded directory and its files are gone. Case 4 clears the cache again and scans nothing, because the rescanning read recorded the shape. Case 5 does the same through _covered_files_for_project, which reads exactly the moved directory and returns a full walk's set.

Five mutations are armed one per environment variable, and each fails the case it belongs to, every arm ending EXIT=1 against the head arm's EXIT=0. Handing build_index no covered set on a cache miss fails case 1 (and cases 4 and 5, which assert exact scan sets); skipping new subdirectories fails case 2; keeping a removed directory's files fails case 3; recording nothing after a scan — so the moved directory keeps the identity it had before the change and the next read re-scans it — fails case 4; leaving the discovery reader on the all-or-nothing fallback fails case 5. The three the node declares are logged arm by arm in one file, the other two in one log each. That fourth arm moved with the code it guards: it used to force the build's flag false, which nothing reads now, so it replaces the shape write with a no-op instead.

One expectation elsewhere asserted the full walk this landing replaces, and it was rewritten rather than reported. test_a_cold_read_walks_the_docs_tree_once.py::test_one_cold_roadmap_lists_each_docs_directory_once moved a directory's shape and then required every docs directory to be listed; it now requires the moved directory listed exactly once and the directories whose identity did not move to be absent from the listing. Its own control restores the full walk in that file's driver and the rewritten case fails it — 1 failed, 2 passed, EXIT=1, with the moved directory listed three times — against 3 passed, EXIT=0 at this head. The rest of that file is unchanged.
