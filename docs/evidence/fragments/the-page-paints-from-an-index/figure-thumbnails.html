A thumbnail is a thumbnail

Commit 56952fa9b adds the thumbnail route to reckon/serve.py. /_thumb/<project>/<figure path> answers with a PNG downscaled to at most 200 pixels on its long edge. The render happens once per source revision: the PNG is written under the configuration home's cache/thumbs directory at a path keyed by the source file's stat identity (ino, size, mtime_ns), so a second request — another thread, another process, after a restart — reads that file rather than decoding the figure again. The same stat identity is the response's ETag, and the If-None-Match check runs before the cache is touched, so a browser that already holds a thumbnail is answered 304 without a render. An .svg source is passed through unchanged, because it scales without cost. A source Pillow cannot open — an unreadable file, or an image whose bytes contradict its extension — is served whole with its own content type rather than answered with a 500: a list row is worth more drawn at full size than broken.

docs/ui/shell-plans.jsx draws the figure list from that route: artifactImageSrc prefixes a project-absolute figure href with /_thumb and leaves anything else — an inline data: capture, a fabricated state — as it was, and the row's img keeps loading="lazy" and decoding="async", so the downscales are fetched as rows approach the viewport. The figure reader in docs/ui/plan.jsx is deliberately untouched: opening a figure still draws the full-resolution file. Pillow is now a declared dependency in pyproject.toml and uv.lock rather than a package reached through matplotlib's own dependency.

Nine cases, all passing: the downscale and its byte ratio, a tall figure bounded by its long edge, the ETag 304 with the render counter proving no regeneration, the disk cache answering a second request with one render, a rewritten source keyed to a new cache entry and a new ETag, the SVG pass-through, the unthumbnailable source served as itself (200, not a 500), a missing figure answering 404, and the served shell's figure row deriving /_thumb/sample/figures/demo/wide.png from a figure href while leaving an inline data: capture alone.

Not done here, by scope. Thumbnails are rendered on first request rather than at index build, so the first view of a figure pays its decode; the cache is never swept, so a figure re-edited many times leaves its earlier revisions' PNGs behind under the configuration home. The served process was not restarted, and no browser on this node could draw the figure list, so the row's rendered src is evidenced by the served compiled module and its probe rather than by pixels.
