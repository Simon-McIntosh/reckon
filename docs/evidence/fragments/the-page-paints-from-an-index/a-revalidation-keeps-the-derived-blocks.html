A revalidation keeps the derived blocks

A page load resolves in two round trips: /_index/<project> answers the rows, and /_discover/<project> answers the derived blocks built from them. A revalidation re-requests the index alone. Before this node, the index path assembled a fresh state object and installed it, so every derived block the first load had filled — the schedule, the sprint fields, the ready set — vanished from window.STATE for as long as the discovery round trip took, and each derived flow that reads them repainted as empty in between. The loader now carries each derived block across that window, and a discovery that cannot build a schedule keeps the one already on screen rather than replacing it with a blank.

The key list is derived, not restated. docs/ui/state-loader.js hoists the block builder to module scope and freezes window.DERIVED_STATE_KEYS as the keys derivedBlocks itself returns, plus milestones, which travels beside them. A block added to the builder is therefore carried across a revalidation without a second edit, and a key the merge never fills cannot enter the list by being written down by hand.

A discovery that answers with a null schedule and a schedule_error is the case the second round trip made possible: the rows moved, no schedule could be built from them, and the alternative to keeping the served schedule is showing none. The merge keeps it, sets stale and stale_error on it, and docs/ui/crew.jsx draws the bars plus one line above them naming the failure and the instant the bars were last served. A schedule drawn without that line would read as current.

The merge lands after the checks fetch has already returned, so a reader waiting on reckon:checks alone sees the flow paint once and never again. The loader now dispatches reckon:derived when the merge lands, and docs/ui/shell.jsx answers it with a render, as it answers reckon:checks. The dispatch is guarded on window.dispatchEvent being callable, because the loader's node harness supplies a window without one.

The form this took, and why. The first draft delayed /_discover and held /_checks unanswered on a page served straight from the tree, and observed no fetch at all: the served page's own /_index/reckon never resolved in this harness, so the shell sat on its loading state and never reached the crew view. The delivered case answers the index and the discovery from fixtures instead, which leaves the shell, the crew view and the loader exactly as served, and samples the drawn flow across the revalidation rather than holding a route unanswered.
