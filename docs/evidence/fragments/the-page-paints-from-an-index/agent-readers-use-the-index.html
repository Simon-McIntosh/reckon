Agent readers answer from the same index

The MCP read views derived a project's whole document state in their own process, with no change watch and a zero-second reuse window, to answer a question that is list-level: which documents exist, and what a sprint holds. The cost landed on the agent while the served page painted from the persisted index.

Commit ac9beac9 adds reckon.mcp_views.index_discovery, which reads the rows of reckon.metadata_index — the same module and the same persisted file the served process uses — and reads the project's own state document for its sprints, milestones, blockers and timeline (state/<project>/index.json, or the composed distributed state). The sprint list is hydrated against the rows through the shared _derive_lifecycle, so a sprint summary names its composition without deriving the rest of the project. In reckon/mcp.py the project summary view and the sprint summary view take that payload; view="detail", view="raw" and a body search keep the derived path, because they ask for per-document state or document bodies. A count the index cannot derive — open followups, open questions, open decisions, mean impl — is omitted from the summary rather than reported as zero, and discovery_view states the followup clause only when its payload carries the count.
