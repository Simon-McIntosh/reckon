A cold read sweeps the directories once

The cache-miss path in index_rows, from _reuse_covered through the build, now runs in one reader at a time per tree and stamp source: _join_cold_path registers a _ColdPath per cache key, a reader that finds one in flight waits on it and then rereads through the cache, and a failed path releases its waiters to read for themselves. _reuse_covered returns the identities it read and build_index and _record_covered_shape consume them, so each recorded directory is statted once and only a directory a re-scan reached for the first time is read again. mark_tree_paths records a mark while a path is in flight for the tree, and _cold_build consumes every mark recorded while it ran before returning, taking them before it publishes the build: a reader entering at that moment waits on the path or reads the patched build, and can no longer consume the marks the path is about to absorb and leave the path answering from rows written before a change it recorded. A mark with no cached build and no path in flight is still dropped. invalidate_tree moves the tree's generation, and _store_cold_build refuses a build that started before the drop. Gate 8 passed at head over tests/test_a_cold_read_sweeps_the_directories_once.py, EXIT=0, and the consolidated gate over the metadata-index and change-stream population, this file and the worker-window measure 204 passed, EXIT=0, both at the commit that took the marks before publishing the build. Each of the eight mutations was armed on its own, one run per variable over the whole file: every arm 1 failed, 7 passed, EXIT=1, failing exactly the case it exists for and no other — NO_WAIT the concurrent-reader case, BUILD_REREADS the single-read case, WAITERS_INHERIT the failed-path case, SHAPE_REREADS the gained-file case, MARK_DROPPED the mid-path mark case, WAITERS_SKIP_CACHE the post-path mark case, STORE_ANYWAY the drop case, and EARLY_STORE the case that enters a reader as the path publishes. That last case also fails against the code that published the build before taking the marks, which is the defect it was written for.

The spy on _dir_identity counts one read per recorded directory for a single cold read (six directories in the fixture), one per directory across six concurrent readers instead of six times the count, and one extra read for the single directory the re-scan reached for the first time after a directory gained a subdirectory. Removing the wait turns the concurrent count into six times the directory count; having the build reread the identities doubles it; having the shape record reread them adds the directory count back.
