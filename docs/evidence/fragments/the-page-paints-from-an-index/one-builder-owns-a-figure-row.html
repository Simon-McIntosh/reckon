One builder owns a figure row

Two builders derived one figure's row. _figure_row in reckon/metadata_index.py reached into figures._DIMS_BY_SUFFIX, figures._capture_metadata and figures._titleize to derive a slug, kind, title, dimensions and href, while figures.figure_rows derived the same fields for the Figures inventory, and the copies had already diverged: the inventory row carried for_plan, caption and download where the index row did not. Commit 4f15b18ba makes reckon.figures.figure_row the one public builder of a single figure's row from its path. figure_rows calls it for each file and renders its dims string from the builder's numeric width and height, carrying neither number itself, so the inventory row keeps the shape it served before. The index builds each figure row by calling the same builder and adding only what the index alone carries — its width and height come straight from the builder, and its created, edited, revision and the empty status, sprint and archived are added on top — projected onto ROW_FIELDS. _figure_row is gone, and reckon/metadata_index.py defines no such name and reads no private name of reckon/figures.py.

The revision-drop seam moved with it. The negative-control fixture in tests/test_a_figure_revision_is_fetched_once.py patched metadata_index._figure_row; it now patches metadata_index._figure_revision, the step that adds the revision to an index row. The file's cases are otherwise unchanged.
