A restart reuses an unchanged file's row by its stat identity

A cache-miss build read and hashed every covered file before it could decide whether the persisted row still applied, and the digest memo lives only in the serving process, so the first read after any restart paid a full read of the tree. build_index now takes the file's stat observation first — through covered_stat, which reuses this pass's first observation — and compares it with the persisted entry's recorded signature through _same_stat_identity. The identity is _stat_signature, the stat fields any write moves without the device number, which a shared filesystem reports differently on each host, so the form stays comparable across hosts. A match serves the row, its discovery state and its plan record unchanged and reads nothing; a mismatch falls through to the digest path exactly as before, which decides from the bytes.

The covered-set reuse returned a third element saying whether any directory had been scanned. Every caller discarded it — index_rows bound it and never read it, and _covered_files and reckon/resources.py read only the first element — so _reuse_covered now returns the covered set and its directories, as before the re-scan section, and the paragraph describing the flag is gone with it. The recording of the observed shape, which is what makes the next reader skip the scan, is unchanged and still happens where the scan happens. reckon/resources.py needed no change.

The gate is the new tests/test_a_restart_reuses_rows_by_stat_identity.py: 4 passed, EXIT=0. It builds a temporary project of six files over a temporary configuration home, persists its index, clears the process memo to stand in for a restart, and builds again. Case 1 reuses every row with a spy on _content_digest counting zero calls and a spy on the parse, and asserts the reused count equals the covered-file count. Case 2 edits one file to the same length but different bytes; it is digest-checked and parsed again. Case 3 rewrites one file with its own bytes, so the identity moves and the bytes do not: one digest for that file, no parse, no rebuild. Case 4 simulates a reader on another host by adding 24 to the device number the stat identity is built from; every row is still reused by signature with no digest.

Four mutations are armed one per environment variable in one driver, each applied and reversed, and each fails the case it belongs to, every arm ending EXIT=1 against the head arm's EXIT=0. Refusing every signature match — restoring the digest-first order — fails case 1 (2 failed, 2 passed). Dropping the modification time from the comparison fails case 2, where a same-size in-place edit now matches and is served stale (2 failed, 2 passed). Skipping the digest fallback, by returning a digest that differs on every call, fails case 3 alone (1 failed, 3 passed). Comparing the full signature including the device fails case 4, where every file is digested (2 failed, 2 passed).
