A run from a previous fleet node gives up its claim

A promoted run's pointer written on the node the fleet has since left records a pid that answers only on that machine. Its liveness reads unknown, and unknown is kept, so the pointer held its claim for ever.

pending_landing.release_pointers_of_a_previous_fleet_node, called from retire_promoted_pointers, retires the pointer of a promoted run whose launcher host is not the node the fleet record names and whose newest stream carries no assistant turn inside the silence window the stall clock already applies. A run proved dead on the host that issued its pid is released by the same pass. A stream carrying a turn inside the window keeps its pointer in either case, because unknown with a turn in progress is never a licence to release.

Retiring a pointer releases a claim, never work: the worktree, commits and run records are untouched, and the paths that reclaim workspaces still see them.

Measure: the new test builds three promoted runs in a temporary crew home; after one pass the previous-node quiet run and the fleet-node dead run have no pointer and the previous-node working run keeps its own (2 passed). At the base revision both cases fail on the first run keeping its pointer (2 failed).
