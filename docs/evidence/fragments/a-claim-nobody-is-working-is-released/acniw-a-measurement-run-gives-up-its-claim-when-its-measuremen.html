A measurement run gives up its claim once its record is stored

What changed. A measurement-only run is journaled rather than landed: its promotion writes the run's record, its head is never merged, and a promotion that could not retire the pointer leaves a pending-landing journal beside it. Every later pass read that journal as proof another pass owned the job, so the pending-record pass merged the run's replayed head onto the primary branch and cleared the journal while the live pointer kept the run's paths claimed. release_merged_promotions now recognises a measurement run before it consults the journal and releases it on its record alone, and the record pass finishes no landing for one, so a refused release keeps the pointer and the record claiming together.

The journal is left exactly as written. It is the evidence that the run's measurement was recorded, so the pass that releases the run does not consume it — the test compares its bytes before and after.

A fence notice is the launch's line, not the log's first record. A gate launched on a job node whose temp directory is absent opens with the fence saying so, then writing the measure's header after it. The gate-log reader now skips that notice the same way it skips the scheduler's, so the header stays the log's first record and the measurement's revision and summary are read.

Measured

Two measurement-only runs with a reaped worker in one temporary crew home: one with its record and journal stored, one with neither. After a single finish_pending_landings() pass the recorded run has no pointer and no worktree, its journal is byte-identical, and its replay head is not an ancestor of the branch; the recordless run keeps its pointer and worktree, and does again on a second pass.
