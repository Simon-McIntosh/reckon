A node declares the MCP set it needs

A flight declares MCP sets under mcp_sets, each a list of servers. A node carries mcp_set — given at dispatch with --mcp-set, in a batch entry as mcp_set, or read back off the node on a resume or a lane change — and the launch resolves that name against the flight before anything is seeded. A name the flight does not declare is refused by name, listing the declared sets. A node naming no set gets the flight's flat worker_mcp_servers declaration, or no server at all when the flight names none. The resolved set and its servers ride the composed plan and are recorded on the run as worker_mcp: {set, servers}.

The same resolved list reaches all three launch backends through the one allowlist they already read: claude writes it into the run's worker-mcp.json and the seeded enabledMcpjsonServers, codex disables every other configured server on its argv, and omp keeps only the set's servers in the run's agent store and names the rest in disabledServers.
