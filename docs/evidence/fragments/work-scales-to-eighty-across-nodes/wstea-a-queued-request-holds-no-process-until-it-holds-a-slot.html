Gate: 20 queued requests against a router of width 4

tests/test_a_launch_waits_for_a_slot.py queues 20 requests in a temporary crew home, publishes the router's remaining worker slots as the width less the workers already live, and runs six admission passes. Each pass starts a real long-lived stand-in process per launched request, so a live process is a worker and never the test's own interpreter. At every pass it reads:

  • live workers at most the router's width plus two (4 + 2);
  • every queued request carries no pid and no process start time;
  • the set of pid fields on launched pointers equals the set of live stand-in process pids — so no request that is still queued owns a process.

The final phase reaps one stand-in process, publishes the freed slot, and reads the head of the queue admitted into it. Gate log gate.log: 1 passed in 160.29s, EXIT=0.

The one-hour full-lane fleet measure is not run here

This node ran as a 75-minute worker on a compute allocation, not on the fleet node, so it could not hold a one-hour window at a full lane.
