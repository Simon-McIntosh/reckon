Dispatch hands each run a private directory under the node-local scratch root and sets it as the worker's TMPDIR; promotion and discard remove that directory, printing the path they removed, and a sibling run's directory survives.

§6 — A worker's scratch lives and dies with its run

Commit c6e49d9 adds worker_scratch_root(), worker_scratch_dir(), ensure_worker_scratch() and remove_worker_scratch() to reckon/crew/dispatch.py. The root defaults to <tempfile.gettempdir()>/reckon-crew-scratch — the host's node-local /tmp — and is overridable through RECKON_WORKER_SCRATCH_ROOT. The run's directory is <root>/<run-id>. _worker_runtime_environment now sets TMPDIR to that directory and creates it, and every launch path — the supervisor's worker spawn, a resume, and the in-harness directive — composes its worker environment through that one function, so they cannot disagree about TMPDIR.

Removal is wired once, in _release_run_workspace in reckon/crew/promotion.py, which promotion (_release_after_promotion) and discard (_remove_discarded_worktree) both funnel through. It removes only <root>/<run-id> and prints removed worker scratch directory <path>; a run id that would climb out of the root is withheld rather than joined, so a directory a different run owns is never in reach. Gate logs and evidence continue to go to the run directory under the config home on GPFS.
