The dispatch exit bound reads its machine

The case that proves a dispatch returns without waiting for its supervisor asserted the return against a fixed DISPATCH_EXIT_BOUND = 8.0 seconds. On a loaded host that constant measures the machine, not the return: at load near 50 the same case measured about 10.9 s and failed on both the base and the head. The bound is now derived from a reference round trip measured on the dispatch's own host at the moment of the dispatch, so a loaded host widens the bound instead of failing it, while the mutation that makes a dispatch join its supervisor still fails the case.

What changed

  • tests/test_dispatch_returns_without_worker.py measures a reference immediately before the dispatch: the slowest of three fresh-interpreter import reckon.crew.dispatch runs, and the dispatch driver's self-reported startup_seconds as a second sample of the same quantity. The slower reading sets the bound.
  • The bound is SUPERVISOR_SURVIVAL_SECONDS + 8.0 × reference, reading the survival window from reckon.crew.dispatch rather than duplicating it. At normal load the reference measures 0.6–0.9 s, giving a bound of about 7.2–8.8 s against a dispatch that returns in about 4.6–5.2 s.
  • The gate report carries reference_seconds, dispatch_exit_bound, driver_startup_seconds and dispatch_seconds, so each run's margin is readable rather than inferred from a constant.

Declared negative control

With the mutation that joins the supervisor applied, the test fails, which is the failure the bound must still catch.

In a scratch copy, _spawn_detached_supervisor waits for the supervisor to exit before reporting its pid (while process_alive(pid): time.sleep(0.05)). Beside eight spinners the case reports 1 failed in 62.85 s, EXIT=1, at the driver wait with the boundary scan still held open: a dispatch that joins its supervisor cannot return while the case holds the scan, so the return bound never receives a returning dispatch to bound; the derived bound only ever judges a dispatch that returned.

Log negative-control-join-supervisor.log names the revision, the scratch tree, the command, the imported module and the working directory; the mutant tree is the run's gate report package_root.
