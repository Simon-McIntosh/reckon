A session mismatch never skips the host silently

A dispatch issued with --session naming something other than the calling Claude session was refused by the host hand-off, and refused silently: _request_host_follower returned False on the name comparison, so no host was ever asked for the run's follower. The caller's pane showed nothing while the run read as unattached everywhere else. The mismatch case now prints one line naming both sessions, and hands the run to the calling session's own waiting host.

Measure

tests/test_a_session_mismatch_never_skips_the_host_silently.py exercises four cases on a temporary crew home with a stub reader on the caller's session-host FIFO:

  • a mismatched session with a waiting host writes the run's request to the caller's FIFO, prints one line naming both sessions, and returns host_handoff with requested_session, calling_session and handed_to_host true;
  • a mismatched session with no waiting host returns handed_to_host false and the line says no waiting host received the run;
  • a matching session leaves the ordinary ask path alone and _request_host_follower still writes its request;
  • an empty session name is not a mismatch.
