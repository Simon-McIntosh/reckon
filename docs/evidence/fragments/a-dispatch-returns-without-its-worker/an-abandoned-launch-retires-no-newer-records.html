An abandoned launch retires no newer record

A fresh dispatch that stalls on storage can have its reservation released and a newer attempt reserved for the run. Preparing the attempt records is what retires the run's canonical records: it overwrites attempt.json and unlinks worker.json and exit.json. That preparation ran before the reservation re-read, so an abandoning launch retired records the newer attempt owned, and the liveness refusal inside the preparation did not fire because the newer attempt's worker was not yet live. The re-read now runs first, so a superseded dispatch writes only its own attempt's exit receipt, leaves the pointer, run directory and worktree standing, and starts no supervisor.

Measure

PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_an_abandoned_launch_retires_no_newer_records.py — 2 passed, 0 failed at the head. The first case lets the newer attempt write its attempt, worker and exit records while the older launch is stalled, with no worker live, then asserts those three files are byte-identical afterwards, that the dispatch refused naming the abandonment, that only attempt-1-exit.json was written and that no supervisor started. The second case is the unchanged path: a fresh dispatch whose attempt is still the newest prepares its records and starts its supervisor.

The negative control at the base revision ran red on the first case: the abandoned dispatch overwrote the newer attempt's attempt.json, with the differing byte reading attempt 1 where the newer attempt wrote attempt 2. Both logs are under the run directory.
