A launch finds its backend on the declared path

A host process restarted without reading the shell's startup files handed its launches a PATH that held neither the directory a clive command lives in nor the one a codex command lives in, so every review it composed was refused as unresolvable. A backend's location is a fact about the host, so the flight layer now declares a search path per backend: the launching PATH is searched first, the declared directories after it, and a command found only there launches with that directory on the worker's own PATH. A command on neither path still refuses, naming both.

What changed

  • reckon/schema/flight.yaml: a search_path slot on BackendConfig — multivalued, home-relative or absolute entries, no directory named by the schema. Without the slot the flight layer's extra="ignore" would drop a declared path silently.
  • reckon/_flight_schema.py and docs/_shared/flight.schema.json: regenerated by scripts/regen_flight_schema.py, not hand-edited. The generated diff is the one new field on BackendConfig and on LaneConfig, which inherits it.
  • reckon/crew/dispatch_launch.py: declared_backend_search_path() reads the resolved flight config for one backend; launch_search_path() appends those directories after every inherited entry, so an inherited PATH that already carries the command still wins. _persisted_worker_environment() takes the backend name and writes the widened PATH into the composed worker environment. preflight_launch_command(), resolve_launch_executable() and the watcher's routable-backend check pass the backend name through and name both searched paths in the refusal.
  • tests/test_a_launch_finds_its_backend_on_the_declared_path.py (new): a temporary flight layer declaring a temporary directory that holds a stub backend binary.

What the test shows

  • A stub backend is resolved to its absolute path when the launching PATH holds neither the directory nor the command.
  • The composed worker environment carries the declared directory after the launcher's own entries — and a launch naming no backend does not carry another backend's directory, so the declaration is what put it there.
  • A command on neither path refuses, and the message names the launching PATH and the declared search path separately.
  • A flight layer carrying search_path validates and keeps the key, rather than dropping it as an unknown slot.
