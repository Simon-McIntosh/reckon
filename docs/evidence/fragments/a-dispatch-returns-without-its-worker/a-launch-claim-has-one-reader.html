A launch claim has one reader

A run's claim.json was parsed by two callers: the launch read the registration instant for its worker receipt, and the admission pass read the whole record, each validating the run id against the same file. The two copies were free to drift about which shapes they refuse. The claim now has one path-taking reader in the module that writes it, and both callers reach it.

Measure

PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_a_launch_claim_has_one_reader.py — 8 passed, 0 failed. The cases drive both callers over a well-formed claim, a claim naming another run, an unreadable file and an absent file, and assert the two agree on each: a claim is read or it is not, and when read both name the same registration instant. A fifth case pins the path-taking contract, showing the record comes from the directory named and never from a re-resolved run directory.

The existing coverage passes unchanged: tests/test_claim_grace_follows_live_launches.py and tests/test_a_launch_span_is_dated_and_bounded.py — 9 passed.

Negative control. Restoring the local parse in _claim_registration_for_worker with a different validation rule — the file read with no run-id match — ran red: 2 failed, 6 passed, and the failure includes test_both_callers_agree_on_every_claim_shape[another-run]. The log is logs/negative-control.log under the run directory.

Where the change lives

  • reckon/crew/dispatch_claims.py — read_claim(run_directory, run_id), beside the claim's publisher, does the read and the validation; read_launch_claim(run_id) delegates with run_dir(run_id).
  • reckon/crew/dispatch_launch.py — _claim_registration_for_worker is a projection of the shared reader and no longer opens the file; a grep of the module for claim.json finds nothing.
  • reckon/crew/recovery_liveness.py — the docstring names dispatch_claims as the owner of the read.
  • tests/test_a_launch_claim_has_one_reader.py — the agreement cases above.
