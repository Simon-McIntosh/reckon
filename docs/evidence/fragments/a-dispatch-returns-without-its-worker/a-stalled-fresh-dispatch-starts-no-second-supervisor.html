A stalled fresh dispatch starts no second supervisor

A fresh dispatch takes its reservation, then can stall on storage before it reaches its supervisor start. Past UNREACHED_LAUNCH_BOUND_SECONDS that reservation stops holding the run, so another launch takes the next attempt. The relaunch path already re-reads its reservation before spawning; the fresh-dispatch path did not, and could start a second supervisor into a worktree the newer attempt now owns.

What changed

  • reckon/crew/dispatch.py: the fresh-dispatch path calls _refuse_superseded_launch(directory, reservation, run_id) twice — once immediately before the shared supervisor.json is written and once immediately before _start_supervisor — the same unlocked re-read the relaunch path uses, no new lock and no second fence. The pre-spec call matters because that file is the run's shared one: a stale launch that wrote it could hand the newer attempt's supervisor its own spec even after abandoning.
  • reckon/crew/dispatch.py: the refusal is raised as _SupersededLaunchError, caught by its own clause ahead of the generic except Exception unwind. That clause writes only the attempt's exit receipt and re-raises, so the superseded launch never runs the rollback that would unlink the pointer, remove the run directory or remove the worktree — all of which belong to the newer attempt of the same run id.
  • reckon/crew/dispatch_launch.py: the docstring of the release rule now names _refuse_superseded_launch, the fence that exists, rather than a _launch_still_newest that does not.
  • tests/test_a_stalled_fresh_dispatch_starts_no_second_supervisor.py (new): two cases against a temporary crew home and git repository.

The gate

The new file's two cases pass. The four ids that appeared only in the head arm of the wide cohort were each run three times at the base revision and three times at the head, as one all_debug job (1312323), one log per run under the run directory. Base: 11 passed, 1 failed; head: 11 passed, 1 failed. The single failure at each revision is the same id, test_a_promoted_run_replays_its_allowance_from_the_committed_row, once in three at each revision, so none of the four fails more often at the head. The first ages the dispatch's own reservation past UNREACHED_LAUNCH_BOUND_SECONDS, reserves attempt 2 for the run and publishes that attempt's pointer from the last step before the fence. It asserts the dispatch refuses naming attempt 2, records no supervisor start, writes attempt-1-exit.json, and leaves the newer attempt's reservation, pointer, run directory, worktree and supervisor.json byte-for-byte in place. Removing only the pre-spec fence call makes that last assertion fail (pre-spec-fence-removed.log), so the earlier fence is demonstrably load-bearing rather than redundant. The second asserts an un-superseded fresh dispatch still starts its supervisor and writes no exit receipt.
