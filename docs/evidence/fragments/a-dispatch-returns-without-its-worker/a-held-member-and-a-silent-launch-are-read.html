A held member and a silent launch are read

A roster member's session is a single-writer resource, and two readings of stored labels hid that. The member guard released a member whose run had recorded a terminal phase without asking the process table, so a run that reached its end while its worker still held the session was launched onto and the launch died against the backend's writer store before its first event. The guard is now judged from process liveness alone: a worker running on this host, or one whose liveness cannot be established here, blocks, and only a worker proven gone releases. A dispatch that would have continued a session its prior worker may still hold starts a fresh conversation instead and records the substitution rather than dropping it silently. Beside it, a launch that dies before its first turn leaves a zero-length stream and its reason in stderr.log, and nothing read that file: observe classified the run as an orphan whose detail named only the path, and, because launch-failed is not a terminal phase, a later observation overwrote a stored launch-failed phase with the same orphan reading. observe now reads stderr when the stream is empty, classifies the run as the launch failure it was with the reason on the record, and leaves a stored launch-failed phase alone.

What changed

  • reckon/crew/node.py, member_in_flight_verdict: the terminal-phase release is removed. Every pointer is judged by _member_worker_liveness; alive blocks, gone releases, and an answer that cannot be established here — no recorded pid, or a pointer recorded on another host — blocks and is reported as unknown. A stored phase is not consulted, because the run reaching an end and the process releasing the session are different facts.
  • reckon/crew/dispatch.py, _prior_session_still_held (new): a prior same-task run that is still a live pointer is judged by the member guard's own verdict, so the predicate that refuses a dispatch onto a busy member is the one that withholds its session. A committed record is a run that has ended and its session stays continueable.
  • reckon/crew/dispatch.py, _task_session_resolution: the new withholding is the first disqualifier, ahead of the harness-owner and stream-size checks. The dispatch resolves no session, launches on a fresh conversation, and writes the substitution into session_withheld and session_id_absent (point dispatch-same-task-session-withheld) with the prior run named and the reason given.
  • reckon/crew/dispatch.py, _empty_stream_launch_failure (new) and the observe fold: when the run's stream is zero-length or absent and a dead process left a non-empty stderr tail, the run is classified launch-failed, the last stderr line is carried into detail, and a launch-failures entry is appended in the reaper's own shape with the bounded stderr tail and the stream path. An empty or absent stderr leaves the reading as the orphan it was, so no cause is invented.
  • reckon/crew/dispatch.py, _stored_phase_survives (new): terminal phases and launch-failed are final for their pointer, so a later observation cannot overwrite a recorded launch failure. observe consults it for both its own reading and the manifest fold; _terminal_phase_survives keeps its name and role because the stored-phase writer test patches it by name.
  • tests/test_a_held_member_is_read.py (new): a same-task live pointer whose run recorded complete while its worker runs is withheld through a real dispatch and the fresh launch carries no resumed session; the same dispatch against a worker proven gone continues the session; the observe arm reads a zero-length stream through its stderr for both the function and the CLI (reckon crew observe) and a stored launch-failed pointer is not reclassified orphaned; an empty stderr still observes as an orphan; and the member guard and the session withholding are asserted to answer from one predicate.
  • tests/test_member_guard_counts_live_processes.py and tests/test_dispatch_guard_consults_liveness.py: the terminal-phase release cases are replaced by the liveness judgements they assert — a terminal phase over a live worker blocks, over a proven-gone worker releases, with no pid is unknown — and the dispatch-arm case for a terminal-phase holder with a live worker is expressed as the refusal it now is, rather than by counting a string in the source.
