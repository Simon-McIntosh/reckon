A terminal wait probe wakes its worker

A worker that ends its turn on a declared external wait leaves its supervisor alive beside it, and every resume door read that live supervisor as an attempt in flight. The sweep evaluated the probe, saw it turn terminal, and refused to resume the run — so a job that ended wake nothing, and one run sat thirty minutes past the end of its job until an operator stopped it. The narrowing is that an idle supervisor holds nothing: a run parked on a wait it declared no longer carries a reservation, and is no longer refused by the launcher's live-process guard or by the observed-end guard. A worker that is still running is not parked, and its reservation holds exactly as before.

What changed

  • reckon/crew/recovery_liveness.py: parked_on_declared_wait is the single reading all three gates share. A run is parked when it declares a valid external wait, the liveness read of its worker record is not alive, and the run's newest reservation does not outrun that record. The pointer's own pid names the supervisor for a supervised launch, and an idle supervisor is exactly what a parked run has beside it, so that field is dropped before the worker reading is taken. A manifest keeps its wait block after the worker was resumed, so a worker that is still running is not parked; an invalid declaration is no park either.
  • parked_on_declared_wait also holds a reservation that is newer than the worker record: a reservation keyed on a later attempt than the record's, or written after the record landed. Between a resume being admitted and its worker writing the record, the record still describes the attempt that parked, so a reading from the record alone would free the reservation the resume had just taken. The attempt number is the primary key and the reservation's stamp against the record's write time is the fallback.
  • reckon/crew/dispatch_launch.py: reservation_in_flight returns not-held for a reservation whose supervisor is alive but whose run is parked. _run_is_parked_on_a_declared_wait reads the run's own pointer and manifest, and any failure to read them leaves the hold standing.
  • reckon/crew/resumption.py: _parked_on_a_wait lifts _launcher_refusal's live-process refusal and _observed_end_refusal's “nothing observed the end” refusal for a parked run — the second being the reason the probe's conversion to terminal previously changed nothing.
  • tests/test_a_terminal_wait_probe_wakes_its_worker.py (new) covers four behaviours: a parked worker's idle supervisor holds no reservation and a resume is admitted; a running worker's reservation is still held; a reservation keyed on a later attempt than the worker record — a resume that has not written its worker record — is still held and a second resume is refused; and a probe that turns terminal wakes its worker inside five minutes on the run's own clock while the station's tick is held.
  • The wake case drives production code rather than a stand-in: station.run_station with its own SweepBeat and ReflexBeat threads, the tick genuinely blocked inside its per-project refresh stage on an event the case never sets, and the station's clock injected so the hold is half an hour of the run's own time while the case runs for seconds. The wake is the resume the sweep offers, recorded in place of the launch it would compose; any sweep that raises fails the case.
