A stranded launch reaches its coordinator as a duty

What changed. RECOVERY_CLASSIFICATION_DUTY_KINDS in reckon/crew/obligations.py gains a launch-failed entry, so the recovery word the classifier already derives for a launch cut off before it spawned a worker becomes a duty row. A pointer holding a pre-spawn phase with no pid, worker record, stream and launch log, past STRANDED_LAUNCH_BOUND_SECONDS, now appears in the obligations view with the classifier's own next command rather than as silence while it holds whatever dispatch claim it took. The bound is unchanged, so a launch that is merely young still reads as starting.
