A discard releases its run's dispatch claim

What changed. promotion.discard gives up the node dispatch claim of the run it removes, through the claim's own _NodeDispatchClaim.release(), and reports the unlinked paths as dispatch_claim_released. Selection is by the run the claim records, never by the node the discarded pointer names, so a claim another run has since taken over that node is left standing. A deliberate discard is not a stale claim, so the claim is unlinked rather than displaced to a .reclaimed- artifact, which is what the reclaim path leaves for a stale one. A dispatch cut off between taking the claim and spawning its worker would otherwise hold that node against every later dispatch for as long as its holder process lives.

The behaviour and its gate are already present in this tree at the base revision. The behaviour needed no change: this node confirmed the deliverable both directly and under mutation, rather than reimplementing a working guard. It added the one assertion the deliverable states but the test did not cover — that a discard leaves no .reclaimed- artifact — and gave that assertion its own control.
