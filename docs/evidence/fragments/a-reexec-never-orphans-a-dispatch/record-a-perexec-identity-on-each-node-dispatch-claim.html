Node dispatch claims identify the holder's execution

Each import of reckon.crew.dispatch_claims publishes a new execution identity in the crew home's claims directory. New node claims record it beside the holder's pid and process start time. A claim with a matching pid and start time becomes reclaimable when that published identity changes; an unchanged identity or a legacy claim with no identity remains held.

The new temporary-home gate passed all three cases (EXIT=0). Applied separately, comparing only pid and start time, ignoring the recorded identity, and treating a missing identity as a mismatch each failed its corresponding case; the combined control log records three failed test ids and EXIT=1. The wider importer run passed 112 tests and failed one queue-capacity assertion. That same assertion failed with the prechange claim source loaded, so it is not a new failure from this change.
