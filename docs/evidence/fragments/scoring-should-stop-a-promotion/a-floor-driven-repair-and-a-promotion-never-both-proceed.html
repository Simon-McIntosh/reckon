A floor-driven repair and a promotion never both proceed

The defect

A live repair worker already blocks promotion while its own round is open. The window that remained is the other order: a round launched after a promotion has begun. A promotion rewrites the run's record and removes its pointer as its last step, so for the whole of a promotion any reader watching only the pointer or the ledger block sees a run that looks untouched. The reflex's repair pass read exactly those, opened a floor-driven round for a review scoring one dimension below its declared floor, and the round then committed in a worktree the settled run no longer had a landing path for.

The change

promotion.promotion_in_flight reads the claim promotion takes before its first write and releases after its landing — the cross-host lease, not the pointer. A stale lease reads as unheld, so a holder that stopped renewing never refuses work forever. The reflex's repair door asks it before dispatching and, when it is held, reports the run in repair_held naming the holder instead of opening a round. resumption.hold_against_promotion asks it too, so a reopen refuses under a promotion on another host as it already refused under a local flock.

The obligation is not dropped. A promotion that lands a run whose ledger block carries a dimension below its declared floor names it in the receipt as owed_floor_repair, listing each dimension with its score and floor. The floors come from the project's resolved flight config and the scores from the block the promotion already read, and the stored record is consulted only where a dimension is below a floor, so a dimension answered as folded or exempted before promotion is no longer owed and names nothing.

Evidence

Two cases are driven on a seeded run whose review scores one dimension below its floor. While a promotion of the run holds its claim, the reflex's pass opens no repair round, reports the run as held with its worktree untouched, and the promotion that follows names the owed dimension with its score and floor. After it, a second pass opens nothing and the repository gains no work. A run whose floor was answered as folded before promotion lands with no obligation named.

The base revision is the negative control: it reads no claim, so its pass holds no round and reports no holder, and the first case reddens there. The gate ran on a compute partition, one arm at a time; log paths are recorded in the run manifest.
