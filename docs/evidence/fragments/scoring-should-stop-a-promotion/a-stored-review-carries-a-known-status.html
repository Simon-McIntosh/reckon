A stored review carries a status its readers know

The defect and the repair

A run-review record reached the store reading "status": "complete", a word copied from an older record's shape rather than from the parser's vocabulary. Every reader acts on "parsed" alone, so promotion refused the run as though no review existed while the record sat on disk. store_review validated the subject, the material and the revisions, but never the status.

The repair adds the public RECOGNISED_REVIEW_STATUSES set to reckon/crew/review.py — the values parse_review writes: parsed, unparsed, incomplete — and refuses any record whose status is absent or outside it, naming the status found and the accepted set. The readers (promotion_checks.py, recovery_review_subject.py) are unchanged.

The measure

New file tests/test_a_stored_review_carries_a_known_status.py: a complete-status record and a record with no status are each refused with the status found and the accepted set named and no file written; a parsed record stores as before. Head arm 4 passed / 0 failed; the declared negative control removes the status check and both refusal cases fail, 2 failed / 2 passed, EXIT=1.
