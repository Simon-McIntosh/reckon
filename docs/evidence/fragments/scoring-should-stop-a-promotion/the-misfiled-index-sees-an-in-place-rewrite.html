The misfiled-review index sees a record rewritten in place

Both defects the review of misfiled-lookup-is-indexed left are repaired in reckon/crew/review_records.py, after a reproduction taken at the base revision and with the mutation restored as the negative control.

The defect, reproduced

A record rewritten in place keeps its name, its inode and the store's directory entries, so the directory's stat identity does not move while the record's content does. At e5b03805a the index answered from the facts it read when it was built: a lookup naming the rewritten head selected nothing (rewritten_head_found: false), and one naming the new reviewed run found an empty group (rewritten_run_found: false). A run holding its own file at one head returned nothing at a head a second record of the same run carried (own_file.found: false).

Validity follows the files

  • A miss revalidates the run's own entries. _revalidated_entries stats the files the index holds entries for and re-reads the ones whose identity moved, which costs a handful of stats and no staleness window.
  • A miss no entry explains re-reads the store once per process. _refresh_store_entries runs the existing update pass, guarded by a flag on the cached index, so the shape a record rewritten onto another run leaves is found without paying a whole-store pass per lookup.
  • The store is not walked per lookup. One per-file stat pass over the operator's real store, 5 896 records on GPFS, measured 1.5 to 3.1 s, against the three-second budget the section sets for a two-hundred-run session. A per-lookup pass would have cost 300 to 600 s.

The run's own file no longer hides a misfiled record

stored_record asks the index whether any entry for the run carries the head asked about (_indexed_at_head, which revalidates only that run's entries) and calls the store search only when one does. The previous section's guard is therefore intact: tests/test_misfiled_lookup_is_indexed.py::test_a_record_at_its_expected_path_never_reaches_the_scan passes unchanged, and a head mismatch the index knows nothing about is still answered from the run's own files.

The gate

Four cases in tests/test_the_misfiled_index_sees_an_in_place_rewrite.py: an in-place rewrite at a new head, one naming another run, a misfiled record beside the run's own file, and the session budget. Both arms are git archive extractions on node-local disk with the main checkout's .env linked; the population is the 40 test files that import reckon/crew/review_records.py or reckon/crew/review.py, including from-package comma-list imports.

  • Base arm: the four new cases fail and nothing else adds a failure.
  • Head arm: the whole population passes.
  • Negative control: with validity keyed on the store directory's stat identity again at both refresh points, the two in-place cases and the session case fail, and the own-file case still passes, which is right — that repair is a different change.
  • ruff check and ruff format --check are clean on both changed paths.

Every log is under the run directory, names its revision, tree and literal command, and ends in EXIT=.
