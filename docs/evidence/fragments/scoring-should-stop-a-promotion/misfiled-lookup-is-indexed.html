The misfiled lookup answers from an index

The review store’s misfiled fallback read every record file in the store to answer one lookup. The coordinator obligations hook reached it once for each live run whose lookup missed — including runs whose review sat at its expected revision-keyed path — and paid a whole-store pass each time, about 1,600 file reads against the live store. A record at one of the run’s own paths now settles the lookup, and the store-wide search that remains answers from an index built at most once per process and per store directory.

Why the fallback ran for a run whose review was filed

stored_record collects the run’s expected files — the bare path and every <run>.at-*.json — and, when a head is named, returns a record only if one of them carries that head in its content. A run whose stored review describes an earlier revision than the pointer now resolves therefore matched nothing, the loop fell out, and the lookup dropped into the whole-store content scan even though the run’s own file sat exactly where a reader keyed on the run looks for it. A run whose worktree head had moved past the reviewed head, or a review run with no record at all, missed on both the head-named and the unnamed lookup and scanned twice.

A spy over _record_filed_elsewhere during one obligations(’reckon’, ’s21-1c’) recorded 31 fallback calls (log fallback-trace.log, script diag.py). The run r-20261001T110746880717-a-shared-grant-charges-only-its-holder had a record at both its bare path and ….at-b48d66a0c696596713af7c47b36d981936376bcb.json, while the pointer resolved head 182a115a3562…; the stored head did not match, so the lookup scanned the store and returned nothing. Reproduced directly on the real store at both revisions with a head that matches nothing (script repro_mismatch.py, logs repro-mismatch-{base,head}.log; the run now also carries ….at-182a115a….json, written by a live review while this node ran):

What changed

  • reckon/crew/review.py: stored_record returns (None, None) after a head-named miss when a file of the run’s own exists, so the store-wide search runs only for a run with none of its own files. _record_filed_elsewhere answers from _store_index, which maps the run id each record names — with the head it reviewed — to its path, is built at most once per store directory and process, and is rebuilt when the directory’s stat identity moves. The file the index selects is re-read, so a record rewritten in place is returned with its current content, and the misfiled flag is unchanged.
  • tests/test_misfiled_lookup_is_indexed.py (new): a synthesised store of 3,000 records under tmp_path. Twenty-five misses read each record file at most once; a record at its revision-keyed path never reaches the scan; a misfiled record is still found and flagged; a record added after the index was built is seen on the next call.

The measurement

obligations(’reckon’, ’s21-1c’) timed on the real store, a fresh process per reading, one call per process. The stub figure from the brief is 19.4 s and the limit is 22.4 s. The paired rows were taken alternately (base, head, base, head …) so ambient load lands on both arms; the host was at load average ≈ 20 on 28 CPUs, shared with peer workers.

Every paired head reading is inside the limit; the head’s cost is the stubbed figure plus one index build, measured at 0.571 s for 1,601 records (log index-build-cost.log). The unpaired rounds show the ambient variance on this host: one head reading of 27.322 s sat beside a base reading of 20.295 s in the same window, which is why the paired series is the one to read. The two arms ran with RECKON_RUN_ID unset, the context a coordinator session runs the UserPromptSubmit hook in; inside a fenced worker shell the git shim refuses git worktree list --porcelain, which the hook never issues and this measurement does.

Negative control

With the index cache disabled in reckon/crew/review.py so every miss rebuilds it, the read-once case fails: 75,000 record reads against 3,000 files over twenty-five misses, one failing id, EXIT=1 (log negative-control-index-disabled.log).
