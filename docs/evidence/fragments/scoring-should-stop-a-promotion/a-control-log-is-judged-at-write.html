A control log is judged where its writer can still repair it

The defect

The write-time manifest audit read status and never read negative_control_log. A node whose write paths include a test file declares the mutation that check must fail against, and its manifest discharges the declaration by naming the log that mutation produced; nothing judged that field until promotion, hours after the worker's process had ended. Measured at base 1c20ca680 (log repro-empty-control-at-base.log, module resolved to the base tree): a manifest with status: complete, a commit, a tests: line and an empty negative_control_log audits to findings: [].

The shapes that reached promotion in that window were not one defect. The manifest field is under-determined — a bare path, a path followed by prose, a mapping of declared/log/result sub-keys, and a heading line above the path were all observed — and a log that resolved but recorded no exit status, or exited zero, stated nothing about whether the mutation ever failed.

The change

In reckon/crew/reports.py, _control_log_findings judges the field inside audit_manifest, for a node that writes a test path and declares a negative control, once the manifest claims completion and records no waiver reason. The field must be the bare path to a readable file whose last non-blank line is a bare EXIT=<code> line with a non-zero code. Each refusal names the field and what it found; the value's own text is quoted, so a reader can tell an empty line from a path carrying prose.

A relative path resolves beside the manifest that carries it (the manifest path argument, else the node's own recorded manifest path), because resolving against the calling process's working directory would judge one manifest two ways.

The log's wording is deliberately not compared against the declaration. Pasting the declaration into a log satisfies that comparison while proving nothing, so the match stays a judgement a reader makes at promotion rather than a test that manufactures agreement. The facts this check does require — a path that resolves, an exit status the run itself wrote — are properties of a run rather than of a string.

Four exemptions, each mirroring the promotion gate's own: a node that declared no control, a declaration of none: <reason>, a node whose write paths include no test file, and a run that has not claimed completion. A manifest recording negative_control_waiver: <reason> is left for a reader to judge; an empty waiver records nothing and the log is still judged.

The gate

Four files — the new file plus tests/test_manifest_check_command.py, tests/test_worker_prompt_contract.py and tests/test_a_review_manifest_passes_its_own_check.py — run in one pytest process per arm, each with a private basetemp. The base arm is an export of 1c20ca680 with the head test files copied in, so its failures are the cases asserting behaviour the base lacks and nothing else.
