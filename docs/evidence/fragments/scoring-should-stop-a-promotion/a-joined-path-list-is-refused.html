A path list joined by an unsplit separator is refused, not read as one path

A manifest's list fields are split on commas and newlines only. A worker that wrote several entries on one bare line joined by ; had that value read as a single entry: the first path satisfied the write-scope audit and every path after the separator was never scope-checked at all, so the guard looked applied while covering one path. The measured shape — a report path under the reports root, then scripts and logs under the run directory — parsed to ['docs/evidence/reports/x.html; scripts/foo.py; logs/bar.log'], and the audit answered ok: true against a scope declaring only the reports root, with the out-of-scope scripts/foo.py and logs/bar.log never reported.

What changed. reckon/crew/reports.py now refuses a value whose entries a semicolon joins before a path-like token, at the parse, naming the field and the separator. The refusal is scoped to the path-bearing list fields the write-scope audit reads — changed_paths and the orientation_write_paths declaration — drawn into one named set beside the keys it is drawn from, so the check asks the field list, not the field list and its exceptions. Every other list field keeps the reading it had: a prose field such as follow_ons, artifacts or blockers routinely names a path after a semicolon as ordinary punctuation, and refusing it would refuse a delivered manifest for its wording rather than for a joined path list. Commas and a JSON array stay accepted forms and still split into separate entries; an entry that keeps a semicolon after its own split is refused the same way.

The measure. A manifest whose changed_paths is docs/evidence/reports/x.html; scripts/foo.py; logs/bar.log with scope docs/evidence/reports is refused, the refusal naming changed_paths and ';'; at base the same manifest parsed to one entry and answered ok: true. The same join in orientation_write_paths is refused naming that field. The same three paths comma-separated and as a JSON array parse into three entries, and scripts/foo.py and logs/bar.log are reported outside the write scope. A follow_ons prose naming two paths either side of a semicolon parses as written, while the same text in changed_paths is refused — the scoping shown beside the refusal. The declared negative control — restore the comma-only list reading; the semicolon-joined case then answers ok — removes the refusal call and four tests fail (4 failed, 3 passed, EXIT=1).

The combined gate ran 254 tests, EXIT=0. ruff check and ruff format --check add no findings — the one SIM102 finding in reports.py is present at base. One pre-existing failure, test_one_function_resolves_a_citation (a merge.py source assertion), reproduces identically at base and is recorded as a follow-on, not a regression here.
