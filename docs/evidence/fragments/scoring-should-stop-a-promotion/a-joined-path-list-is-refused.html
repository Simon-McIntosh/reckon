A list joined by an unsplit separator is refused, not read as one entry

A manifest's list fields are split on commas and newlines only. A worker that wrote several entries on one bare line joined by ; had that value read as a single entry, and the guard that consumes those entries one at a time then read only the first. The measured shape — a report path under the reports root, then scripts and logs under the run directory — parsed to ['docs/evidence/reports/x.html; scripts/foo.py; logs/bar.log'], and the write-scope audit answered ok: true against a scope declaring only the reports root, with the out-of-scope scripts/foo.py and logs/bar.log never reported. The same join in test_logs leaves the cited-log audit opening the first log and never reading the rest, and in commits leaves the first identifier cited and the second hidden.

What changed. reckon/crew/reports.py now refuses a list value whose entries a semicolon joins before an entry-shaped token, at the parse, naming the field and the separator. The refusal is bounded to the fields whose entries a guard consumes one at a time — each as its own path or its own token — drawn into one named set beside the keys it is drawn from: changed_paths, orientation_write_paths, test_logs and commits. That is the whole membership rule, and the prose list fields (artifacts, evidence_inputs, follow_ons, blockers) are outside it: a semicolon before a path there is ordinary punctuation rather than a join, and refusing it would refuse a delivered manifest for its wording. Commas and a JSON array stay accepted forms and still split into separate entries; an entry that keeps a semicolon after its own split is refused the same way.

The measure. A manifest whose changed_paths is docs/evidence/reports/x.html; scripts/foo.py with scope docs/evidence/reports is refused, the refusal naming changed_paths and ';'; at base the same manifest parsed to one entry and answered ok: true. The same join in orientation_write_paths is refused naming that field; so is a joined test_logs and a joined commits. The same three paths comma-separated and as a JSON array parse into three entries, and scripts/foo.py and logs/bar.log are reported outside the write scope. A follow_ons prose naming two paths either side of a semicolon parses as written, while the same text in changed_paths is refused — the scoping shown beside the refusal. The declared negative control — restore the comma-only list reading; the semicolon-joined case then answers ok — removes the refusal call and six tests fail (6 failed, 3 passed, EXIT=1).

Evidence. New test tests/test_a_joined_path_list_is_refused.py (9 passed). The reports.py importer suite ran 247 tests at both arms with no added failure (baseline_suite and after_suite, EXIT=0 each). The combined gate ran 256 tests, EXIT=0. ruff check and ruff format --check add no findings — the one SIM102 finding in reports.py is present at base. One pre-existing failure, test_one_function_resolves_a_citation (a merge.py source assertion), reproduces identically at base and is recorded as a follow-on, not a regression here.
