A promoted row names its reviewed revision

The defect

A stored review is evidence about one revision, and two gaps kept that fact out of reach. Nothing on the live path asked the reviewer to say which revision it read: the composed review brief's done-when (reckon/crew/recovery.py, _review_dispatch_fields) named the five dimensions, the added-failure count and the added-failure ids, and no revision; the role prompt (reckon/crew/prompts/review.md) contained no revision ask either. And the compact block a promotion stores onto the ledger row (reckon/crew/review.py, ledger_block) returned only status, scores, absent and total, so even a record that named the pair could not reach the row.

Reproduced at the base revision fa66c530 against the worktree's own tree (gates/base-reproduction.log, EXIT=0 — the script exits non-zero had either defect already been absent):

factat base
the emitted brief's done_when names reviewed_base_sha / reviewed_head_sha False / False
the review prompt names reviewed_base_sha / reviewed_head_sha False / False
ledger_block of a record carrying the pair {'status', 'scores', 'absent', 'total'} — the pair dropped

The change

The brief's done-when now requires the reviewer to record "the revision it read as reviewed_base_sha and reviewed_head_sha", named beside the count it already asked for. reckon/crew/prompts/review.md gains a short section stating the same ask: the record must carry the canonical pair, base for the commit the diff was taken from and head for the commit it landed at, recorded from what was read rather than reconstructed from a filename or a timestamp.

ledger_block now resolves the pair through the store's existing carried_revision_pair and writes reviewed_base_sha and reviewed_head_sha onto the block when the record carries them, so any of the five recorded spellings reaches the row under the canonical names. A record naming none keeps the bare block: the absence is a fact about the record, and a defaulted pair would claim a revision nobody read. The existing exact-shape assertions on the bare block (a legacy record's row) therefore hold unchanged.
