An arm's ids reduce against the directory its own record names

The defect

pytest prints a summary line's node id relative to the root directory it resolved, and that directory can sit above the arm's own working directory. A base arm run as env -C /tmp/rcq2-base whose root resolved to /tmp printed rcq2-base/tests/… where the head arm printed tests/…. Compared verbatim the two spellings name different tests, so a run that added nothing reports added failures and the nonzero count caps its total below the promotion floor — the direction the count exists to prevent.

Reproduced from a live run's own logs (r-20260929T144906489940-repair-of-direct-resume-needs-an-observed-death):

armlog line
base FAILED rcq2-base/tests/test_session_lives_on_its_run.py::test_promoted_session_resumes_same_task_without_roster_write[False]
head FAILED tests/test_session_lives_on_its_run.py::test_promoted_session_resumes_same_task_without_roster_write[False]

That run's manifest names the tree the base arm ran inside, in two places: measurement_cwd: /tmp/rcq2-base, and the env -C target its own gate command pins the arm to.

The change

canonical_node_id in reckon/crew/review.py takes the arm's recorded working directory and, before it splits the path, drops the longest leading run of components that matches the tail of that directory. rcq2-base/tests/x.py::t against a directory of /tmp/rcq2-base reduces to tests/x.py::t; a spelling that shares no suffix with the record is left alone.

The directory is read per arm from the arm's own record by _arm_directory: the env -C / --chdir= target of the suite's recorded command, else the manifest's measurement_cwd line. Nothing is stripped from a log whose own record names no directory, and no directory from one arm is applied to the other — a reduction that cannot be explained by an arm's own record would silently under-count, which is the failure this count exists to catch.

A path whose leading components are part of the repository-relative path — a package's own pkg/tests/ — shares no suffix with the scratch record, so it is not reduced and stays a different test from the repository's tests/.

The gate

Every test file that imports reckon.crew.review (32 files at base, plus this change's own file at head), run in a scratch tree exported from the base revision and in the worktree at head, each arm under env -C with PYTHONPATH pointing at its own tree, and each log's header printing the revision and the reckon/crew/review.py it resolved:

armrevisionresultfailed ids
base 467c0aab 5 failed, 468 passed in 242.46s 5
head 41a8a4f0 5 failed, 471 passed in 251.42s 5

The two arms' failed ids are identical, all five in tests/test_ledger.py, so the head arm adds no failure id: derived through the production added_failures_from_gate_logs with each arm reduced against its own recorded directory, the added set is 0 []. Both arm logs are recorded as JSON with completed: true, and the record's own env -C line reads back as the directory it names.

The equivalence itself is asserted without a scratch tree on disk, by driving the production read path (annotate_review_of_run) with a synthesised manifest and the two arm logs it names. The base log's spelling is derived from the directory its record names rather than written down, in both shapes a real record uses (env -C and measurement_cwd): the scratch-prefix case adds nothing and the total is not capped, while the pkg/tests/ case, where the head alone reports tests/test_gate.py::test_alpha, still reports one added failure.

The negative control

The declared control reverts the reduction and requires the scratch-prefix case to go red. Its log's first line, verbatim:

revert canonical_node_id in reckon/crew/review.py to its base body; the scratch-prefix case in tests/test_scratch_arm_ids_reduce.py reports two added failures

Run by swapping the function's body for the base revision's own body text while leaving the head signature in place, so the caller still binds the arm's directory and the run measures the reduction rather than a missing parameter. The two scratch-prefix case parametrisations fail with assert 2 == 0 — the two failures read as added — and the pkg/tests/ case passes: 2 failed, 1 passed, exit 1. The tree was restored byte-identically (sha256 equal before and after).

What the gate arms do not show

Both gate arms were run with their own tree as the working directory and with relative test paths, so neither log carried a scratch prefix and the reduction is the identity on both — the same derivation with no recorded directory at all also reports 0 []. The prefix case itself is carried by the unit tests and the negative control above, not by those two logs.

The five tests/test_ledger.py failures are present at both arms, outside this change's scope, and are unchanged by it.
