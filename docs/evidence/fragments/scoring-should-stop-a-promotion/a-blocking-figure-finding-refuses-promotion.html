A blocking figure finding refuses promotion

The defect

The review guards in reckon/crew/promotion_checks.py key on a stored record's status and the revision it read (_require_review_waiver). No promotion check read a finding's severity, so a figure review carrying a blocking finding satisfied every guard: the review was stored, its head matched, and the run promoted with the figure defect it named unrepaired. The text-review reader cannot stand in, because it excludes figure records by rubric — the two subjects coexist at one head and only the text one was read.

The change

_require_no_undisposed_blocking_figure_finding reads the run's newest figure review through review.read_review(..., rubric=FIGURE_REVIEW_RUBRIC) — the store's own rubric-keyed selection, so it is the same record every other figure-review reader sees. Its blocking findings arrive from repair.blocking_findings, the single owner that classifies a finding's severity and filters out the ones a disposition has answered. An open blocking finding refuses the promotion with the figure path, its line and the finding's own claim, so the drawing to open is named rather than left to a search of the record.

The guard is called from _landing_preconditions, the ordered sweep the landing path already runs, so it is reported beside every other precondition failure in one refusal. A run that carries no figure review is untouched, and a run whose text review alone carries a blocking finding promotes exactly as before — this guard reads the figure rubric alone.

Commit: 02a433003.

A figure review that cannot be read

The store answers None both for a figure review it could not parse and for a run carrying no figure review — deliberately, because a review worker composes its record by hand and a reader can meet one mid-write. The guard took that single answer for the first absence, so a figure review that could not be read promoted unread — and the record that could not be read is the one that might carry the blocking finding.

The guard now asks whether a figure record exists for the run before it acts on the reader's silence, and refuses naming the record and the error the store met. The candidates are the files the run's figure review could sit in, enumerated by the store's own path rules in the staging store and in the project's committed reviews tree, together with the files the store met and could not read on the way — the committed tree answers first and a read that names no revision returns on it alone, so a committed record that does not parse is reported from the store's own account rather than from the enumeration. A file counts only when its name marks it as a figure record, so a text review met mid-write still promotes, and a run carrying no figure review behaves exactly as before.

What this node does not do

No base arm was run: this gate measures only this node's own change, and the coordinator runs the importer population of reckon/crew/promotion_checks.py at merge. Verifying the merged result belongs to a separately dispatched test node.

One gap is recorded rather than closed, because its repair is outside this node's write scope. crew dispose cannot reach a figure finding: the record it selects (recovery.select_review_for_head through obligations.stored_review_for_run) excludes figure records by rubric, so a disposition naming a figure finding's index is refused with “carries 0 findings” against the text record. The test therefore records the disposition through the same store writer and key (FINDING_DISPOSITIONS_KEY, built by review_dispositions._build_disposition_entry) that the dispose path writes, which is the record state the guard reads; giving crew dispose a figure-review selection is named in this node's follow-ons.
