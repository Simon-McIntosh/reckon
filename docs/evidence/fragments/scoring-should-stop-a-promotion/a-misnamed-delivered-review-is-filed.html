A misnamed delivered review is filed

The defect

A run review delivers its record into the reviewed run's review-records/ directory, and delivered_run_review_paths in reckon/crew/review.py resolved exactly the paths the reviewer's own write-path declaration named. A reviewer writes its record by hand, so it can name the file by its own run id rather than the declared path — measured 2026-10-24 on run r-20261024T201437083115-a-stream-past-its-window-lets-a-resume-launch, whose review run wrote both records under its own id while its manifest said the declared paths had been written. Filing read the declared names, found no file there, and filed nothing, so the reviewed run read as unreviewed: crew check --review and crew dispose both answered no stored review although a well-formed record naming the run and its head was in the run's own directory.

Reproduced at base 89065e610 in an extraction carrying this node's test file: the record delivered under the review run's id is left unfiled, and the dry-run receipt does not name it.

The change

delivered_run_review_paths keeps the declared names first and in their declared order, then adds any record in the reviewed run's review-records/ directory that carries review_run_id equal to this review run's id and reviewed_run_id equal to the run being reviewed. Requiring the pair is the whole of the guarantee: a sibling review of the same run and head names itself in review_run_id, so it is never selected and cannot overwrite the record already stored for that head or the dispositions written on it. A malformed record that does match stays refused, because the filing still hands it to store_review, which owns the decision about what a review is.

The dry-run receipt in reckon/crew/promotion.py (_delivered_review_records) asks the same resolution, so the names it reports are the names a filing would open, and a promotion's filing — which runs ahead of every guard — moves the misnamed record into the store on either the supervisor path or crew complete.
