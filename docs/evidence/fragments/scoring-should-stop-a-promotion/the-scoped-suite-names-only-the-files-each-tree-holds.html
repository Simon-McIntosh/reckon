The scoped suite names only the files each tree holds

The defect

The armed suite declaration is scoped with a placeholder that stood for the node's fence write paths. A write path is not a file that exists: a node that replaces a test deletes one file and creates another, so the same fence names a different file list in the base tree and in the head tree. Resolving it once, over the write paths alone, produced a head command naming a deleted file. Reproduced in a scratch repository holding the head tree — one kept test, the deleted test, the added one — the old command ran nothing:

ERROR: file or directory not found: tests/test_deleted.py

no tests ran in 0.00s
EXIT=4

Because the suite delta is computed from failure ids alone, a pair in which neither arm ran a test carried an empty failure list and was credited as a clean observation.

The change

_scoped_suite_command in reckon/crew/promotion_records.py takes the revision the command will run against and keeps only the scoped files that revision's tree holds, read from the tree's own object store rather than from a working directory, which is the head's content whichever arm is being resolved. An unanswered probe falls back to the declared scope as written, and the arm-level checks below still refuse a pair that measured nothing.

The comparison accepts the per-tree resolution of the same template for each arm, and still accepts the whole-scope spelling a run dispatched before the rule recorded. An after arm left naming no file, or either arm exiting 4 or 5 with no failure, is refused as unmeasured; a base arm whose own tree holds none of the scope's tests is recorded explicitly as an empty baseline rather than refused, because a scope whose tests the change creates has nothing to measure against.

Evidence

The node inherited this behaviour at its base revision and verified it rather than reimplementing it: the five cases in tests/test_a_scoped_suite_names_only_present_files.py pass at the base (5 passed, EXIT=0) and after the node's change (5 passed, EXIT=0). The same test file fails against the pre-rule module (5 failed, EXIT=1), so the cases are sensitive to the behaviour they describe.

The declared negative control removed the presence check from _scoped_suite_command, resolving over the write paths alone again. Three cases reddened (3 failed, EXIT=1): the per-tree resolution case, the accepted pair, and the collected-nothing refusal, which then reported a missing file rather than a run that collected nothing.

The node's own change removes a helper the review of the landing work had flagged as duplicated: _write_suite_manifest was defined twice, the second shadowing the first byte for byte.
