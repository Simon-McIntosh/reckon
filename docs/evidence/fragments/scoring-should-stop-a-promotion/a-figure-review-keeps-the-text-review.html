A figure review keeps the text review

The defect

A run review's supersession compared only the reviewed run and the dispatch time (reckon/crew/review_lifecycle.py, _later_run_exists). Once the review reflex files a figure review for the same run, that figure review is a later record of the same run, so it superseded the run's text review: the text review read superseded and the obligations view, which reads its findings only while it is hot, dropped them. A run's text review and its figure review are separate subjects, as a plan's design and content reviews are.

The two records coexist at one head rather than replacing each other: the store keys a figure record at <run>.figure.at-<sha>.json beside the text record's <run>.at-<sha>.json, so both are present and both are read by the derivation. Only the supersede rule treated them as one subject.

The change

The subject a run review is ordered by is now its reviewed run together with its rubric family (_run_subject), and _later_run_exists compares that pair. The family is the store's own figure-rubric constant, read through a small _is_figure_review predicate, so a record under the figure rubric is a figure review and a record under no rubric or another rubric reads as a text review — the field the store writes and the field the derivation reads cannot drift. Ordering within one family is unchanged: a later text review still supersedes an earlier text review, and a later figure review an earlier figure review. The module docstring's superseded paragraph is updated to match.

Only the derivation changed; the store, the readers and the views are untouched. A run carrying only text reviews reads exactly as before.
