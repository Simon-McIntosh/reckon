A landing record in a section body is read, under the section that holds it

The defect

read_state in reckon/_plan_html.py selected section[data-reckon="comments"] .r-comment, so a landing record an agent wrote into a section's own body was invisible to every agent read while reading correctly to a human in a browser: parse_plan()['comments'] omitted 19 of the scoring plan's 111 comment elements, including both §2d landing records (c-run-r-20260921T195859674086-a-promotion-never-creates-a-ledger, c-run-r-20260921T204619583360-the-refusal-asks-git-whether-the-ledger-existed). Reproduced at base 84fd7ff4f in logs/base_read_counts.log: 111 elements, 92 read, both named records absent. Corpus-wide, 45 records across five plans were unread (a-review-can-see-the-figure 4/6 read, a-worker-cannot-write-your-home 70/88, burn-is-visible-before-it-bites 42/47, scoring-should-stop-a-promotion 92/111, the-monitor-under-measurement 9/10).

The change

A comment element belongs to the section its own data-section holds, wherever the element sits; markup quoted inside a pre or code sample is text, not a record. read_state reads every comment element in document order, comments-section records first, body-resident records after, and keys each by its own anchor. The writer is the other half: rendering from a state that now carries body records would copy them into the comments section on the very next write, so write_state renders only the records the comments section holds, matched against the source by the record's own fields and counted, and judges the unparsed-section refusal against that same filtered collection. A document holding one record in both places keeps both. Judged against the source text rather than the state, so a writer that never carried the body records still cannot duplicate them.

Verified in logs/head_edited_write.log and logs/head_strip_compare.log: an edited write (one appended comment) through the store on the five body-record plans and three controls leaves everything outside the comments sections and the version/modified metas byte-identical, every body record's source block byte-identical and present exactly once, no duplicate ids, and exactly one element added.
