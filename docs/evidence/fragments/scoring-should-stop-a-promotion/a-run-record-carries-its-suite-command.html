A run record carries the suite command it will be gated on

The defect

A project arms its promotion consequence gate with a suite command, and the declaration may carry the scoped placeholder {node_test_files}, which promotion substitutes with the node's own fenced test files. Dispatch stored the declaration verbatim (gates.suite_command) and the composed prompt carried no suite command at all, so an armed worker was told neither the command nor the files it would measure, and met the requirement for the first time when a promotion refused the pair it had recorded against a different suite.

The change

_resolved_suite_gate in reckon/crew/dispatch.py hands the declaration and the node's write scope to promotion_records._scoped_suite_command — promotion's own substitution, not a second one written for dispatch — with the run's worktree as the tree the scope paths are named within. The result is resolved once, after the worktree exists and before the prompt is composed, so the command the worker is told and the command promotion will re-run are the same string by construction.

The record carries the declaration beside it: suite_command stays the template as written, suite_command_resolved is the command the run's promotion will actually execute, and suite_gate is armed or unarmed. A scoped declaration over a scope holding no test file resolves to nothing and records unarmed with no resolved command, rather than an empty string that reads as a command no one could run.

The composed prompt states the resolved command under its own fence, with the instruction to run it unedited for both arms, so the pair a worker records matches the one promotion compares. Where the declaration resolves to nothing the prompt names the gate unarmed for that node instead, and a project declaring no command at all composes exactly the prompt it did before.

Commit: a4d530ed9.

The gate

A throwaway project's flight file carries the scoped template, and its gate layer is read back through reckon.flight.resolve, so the case exercises the declaration a project actually writes rather than a dict assembled in the test. Both cases dispatch through crew.dispatch into a temporary repository with a substituted launcher. Base and head arms are git archive extractions on node-local disk, each with the main checkout's .env linked.
