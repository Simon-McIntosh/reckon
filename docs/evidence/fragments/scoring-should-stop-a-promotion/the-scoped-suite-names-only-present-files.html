The scoped suite names only the files each tree holds

What changed. _scoped_suite_command in reckon/crew/promotion_records.py now takes the revision whose tree the command will run against, and resolves {node_test_files} over the write paths that tree holds rather than over the write paths alone: presence is read from the revision's own tree through the object store (_paths_present_in_tree, git cat-file --batch-check), so a test the node deletes leaves the head arm and one it creates leaves the base arm. The arm comparison now compares each arm's recorded command with that per-tree resolution of the same template, and still accepts the whole-scope spelling, so a run record dispatched before the rule still promotes. An after arm left naming no test file, or an arm that exited having collected none (exit 4 or 5 with no failure), is refused as unmeasured; an empty base is recorded as baseline_measured_nothing rather than refused, because a change that creates the tests measuring it has nothing to measure against at the base.

Dispatch's suite fence (_suite_gate_prompt_body in reckon/crew/dispatch.py, rendered by compose_prompt in reckon/crew/prompts.py) states the template, the per-tree rule and the string the node's whole scope produces, so a worker resolves the template over each arm's tree instead of running a file list its own change invalidates. The run record still carries suite_command (the template verbatim) and suite_command_resolved.
