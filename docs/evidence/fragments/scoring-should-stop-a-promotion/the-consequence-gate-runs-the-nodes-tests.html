The armed suite command is scoped to the node's own fenced test files

gates.suite_command took only a literal command, so arming the promotion-consequence gate meant naming the whole suite. An armed node runs the pair twice, at its base and at its head, and the whole suite measured 720–762 s, which is most of a node's budget for tests its change cannot reach. The declaration may now carry {node_test_files}, which promotion resolves against the node's own fenced write paths, so one project-level declaration measures each node on exactly the tests its scope holds.

What changed. reckon/crew/promotion_records.py resolves the declared command before comparing it with either arm: the placeholder is replaced by the test_*.py entries among the run record's node.write_paths, sorted, and named relative to the run's tree because the base and head arms run in different trees. Non-test scope entries — the modules a node edits, its landing fragment, its figure directory — are not tests and are dropped. A declaration without the placeholder is taken as written, so an existing literal arming is unchanged. A scoped declaration over a node whose scope holds no test file resolves to nothing, and promotion then records no suite observation, which is the state an unarmed project is in. The resolved command is what the suite delta records, so a reader sees which files were measured. docs/state/reckon/flight.yaml now arms reckon with PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q {node_test_files}.

The measure. A promotion whose pair ran the resolved command promotes with suite_delta.status: clean and records that command on both arms; a pair over the whole suite is refused naming both arms' command_matches_suite_command; a pair over another node's test file is refused the same way; a record with no suite_command promotes with suite_delta: null, recording no suite observation. The declared negative control — the declaration removed — reddens both file-linked cases: test_the_project_arms_the_gate_with_a_scoped_command and test_the_declared_command_measures_the_nodes_fenced_test_files fail (2 failed, 9 passed, EXIT=1), so the checks are bound to the declaration rather than to a constant copied into the test.
