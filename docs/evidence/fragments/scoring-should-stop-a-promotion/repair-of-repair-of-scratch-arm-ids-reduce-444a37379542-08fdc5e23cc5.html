The review ties its added-failure count to the revision each arm log names

The defect

Two defects were raised against the arm-id reduction's landing. Its gate log's first line named the base revision cbbbb56f while the change itself sits at 08fdc5e23, so the recorded 5 passed could not be tied to the committed change without re-running the gate. And the change carried no evidence file, although its diff is 150 changed lines — well past the small-node clause that exempts only diffs of fifty or fewer — so its evidence anchor existed only as a manifest line.

The underlying gap is in the review path: annotate_review_of_run derived the added-failure count from the two arm logs but did not carry forward the revision each arm log's own first line names, so nothing in the annotated review let a reader tie that count to a commit.

The change

The source run's gate log was re-run against an export of 08fdc5e23, so its header now names that revision and the change it measures agree: 5 passed, exit 0. A fragment now records that landing.

In reckon/crew/review.py, recorded_log_revision reads the revision a gate log's first line names, and annotate_review_of_run records it under base_log_revision and head_log_revision beside the added-failure count it already derives. A base log naming one commit and a head log naming another now read as the mismatch they are rather than as evidence about either.

The gate

The node's own file, run at the change's commit through the production annotate_review_of_run path with a synthesised manifest and repository:

tests/test_scratch_arm_ids_reduce.py 6 passed, exit 0

The new case drives each arm log with a header naming its own revision and asserts the annotated review carries both.

The negative control

The declared control reverts each change in turn and requires its named check to go red. Its log's first line, verbatim:

revert each answering commit in turn and confirm the check the finding names fails without it

Removing the two lines that record the arm-log revisions reddens test_the_annotated_review_carries_the_revision_each_arm_log_names with a KeyError (1 failed, 5 passed, exit 1). reckon/crew/review.py was left untouched in the worktree; the mutation ran on a scratch copy.

What this record does not show

The carried revisions are read from each log's first line only; a gate log whose first line names no revision records None, which is a state a reader must still treat as unknown rather than as agreement.
