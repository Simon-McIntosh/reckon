The arm-id reduction keeps a genuine repository path whole

The defect

The recorded-directory reduction introduced for scratch-arm-ids-reduce matched a leading id component against the scratch tree's basename alone. A base arm run as env -C /tmp/pkg in a repository that holds a pkg package printed pkg/tests/test_gate.py::test_alpha, and the basename pkg reduced it onto the repository's tests/test_gate.py::test_alpha — two different tests merged into one, hiding a failure the head arm really added.

_arm_directory returned the manifest's single measurement_cwd for an arm whose suite record named no command, so that field — which belongs to whichever arm was measured in the scratch tree — was attributed to the other arm and its ids reduced against a tree it never ran in.

The change

In reckon/crew/review.py, _strip_recorded_directory now leaves a leading component whole when _names_repository_path finds it at the repository root (_REPOSITORY_ROOT, with _REPO_DIRECTORY_NAME derived from it), so a genuine pkg/tests/… id is no longer reduced away.

_arm_directory returns None for an arm whose suite record names no command, so the manifest's measurement_cwd is withheld rather than attributed to whichever arm is read first.
