A --land promotion hands an unmerged head to the pending landing

What changed

A crew complete --land committed its ledger row and plan comment, then the pointer-removal guard raised run ... changed while promotion ran because a resume had started the same run again. The merge never ran, the row read landed, and the reviewed head stayed off the primary branch. The pending-landing pass already finishes a promoted-but-unmerged head, but it read a run's pointer only when its record carried merge_conflict, so this state was skipped.

reckon/crew/promotion.py now keeps the pointer it could not remove, marks it pending_landing_repair, and reports the promotion as recorded with its landing pending, so the caller stops before the merge rather than deleting the newer attempt's pointer. reckon/crew/pending_landing.py reads a live pointer even when the record carries no conflict: a marked pointer is finished by the pass, and an unmarked one is left alone as belonging to a newer attempt. No second recovery and no refusal family were added; the run finishes through the mechanism the interrupted-landing repair already provides.

Evidence

A patched resume moves the pointer's attempt and phase after the ledger commit; the promotion raises naming the change, and the pointer survives marked pending_landing_repair. The next finish_pending_landings pass lands the reviewed head on the remote branch, removes the pointer and clears the record. An undisturbed promotion removes its pointer and lands as before, and an unmarked live pointer is still left alone.
