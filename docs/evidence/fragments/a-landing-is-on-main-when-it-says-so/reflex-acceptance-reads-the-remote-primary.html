The reflex acceptance reads the remote primary branch

What changed

The accepting branch of the reflex promoted a reviewed run once its recorded gate still passed at the merged head, but it answered "is the run merged?" with git merge-base --is-ancestor ... HEAD against the checkout's own tree. A checkout whose main was fast-forwarded while the push failed satisfies that test while the remote has never seen the work, so acceptance could promote a run no other reader can find.

reckon/crew/recovery_review_acceptance.py now asks merge.head_on_remote_branch — the function the plain-complete path already uses, which reads ls-remote over the port-22 to 443 retry, fetches a remote head it does not hold, and answers through the same _is_ancestor the landing lands by. The local probe survives as _commits_missing_from_local_head and is reached when the checkout configures no remote, which is the one case where there is no remote branch to be off.

An unreachable remote and a reachable remote carrying no primary ref are distinct answers and each declines the promotion, recording remote_cause and a reason naming the remote, the branch and the commits. Neither is read as "not missing", because either would promote work the remote may not hold.

Measure

Gate: tests/test_reflex_acceptance_reads_the_remote_primary.py over a temporary repository and a bare origin. At the head it reports 8 passed, EXIT=0. Each declined arm carries a control, because a guard that never fires passes the same assertions as one that refuses everything: a run whose commits are only on local main is not promoted, while the same run with the deliverable pushed promotes; an unreachable remote declines with remote_cause: unreachable and a control that answers the remote read as promotable promotes it; a remote with refs/heads/main deleted declines with remote_cause: missing-branch and the same control promotes it; and a checkout configuring no remote judges its own branch and promotes, which is the behaviour a remote-less repository has always had.

Negative control: the declared mutation reverts the question to the local checkout. Over a tree extracted from base revision bf85149157 with this node's test copied in, the local-main case fails because the run is promoted, and report["accepted"] reads ['r-20261109T120000000000-reflex-acceptance'] against the expected empty list — the defect §7 records, reproduced. With it the unreachable-remote and missing-branch arms fail too, since neither cause is represented in the base code. That run reports 3 failed, 5 passed, EXIT=1.

Regression: tests/test_review_acceptance_promotes.py, which exercises this module's accepting branch through a remote-less fixture, reports 6 passed at the base revision and 6 passed at the head, so the change adds no failure and the no-remote fallback preserves the path. Ruff check and ruff format --check are clean on both staged paths.
