A resume refuses while its run is promoted

What changed

A promotion holds a lock named for the run for the whole of the promotion and takes the run's pointer lock inside it. The live-worker check that runs before that lock can only refuse a promotion starting while a turn is alive; it says nothing about a resume that starts after it has passed. Such a resume took only the pointer lock, so it rewrote the pointer underneath a promotion that had already decided what to do with that run.

_pointer_lock in reckon/crew/runs.py now takes an optional non-blocking mode, which raises PointerLockHeldError when the lock is held instead of queueing for it. mark_resume_launching in reckon/crew/resumption.py takes the run's promotion lock first in that mode and the pointer lock inside it, which is the order promotion itself uses: a promotion in progress is a refusal that names the promotion and tells the operator to retry once it finishes, and the two cannot hold what the other waits for. The refusal happens before the pointer is read, so the pointer is left exactly as the promotion has it, and no worker is started.

Measure

Gate: tests/test_a_resume_waits_out_a_promotion.py over a temporary crew home and a run whose pointer and worktree are under it. At the head revision it reports 3 passed, EXIT=0. The three cases are: a resume attempted while the promotion lock is held refuses naming the promotion, with the pointer byte-for-byte unchanged and the launch seam never called; a resume with no promotion in progress proceeds and leaves no in-flight marker; and a promotion-shaped critical section and a resume started together finish inside a five-second bound in all 25 rounds, in whichever order they arrive.

Negative control: at the base revision f6a07c1c23, over a tree extracted from that revision with the node's test copied in, the refusal case fails with DID NOT RAISE CrewError — the resume proceeds while the promotion lock is held, which is the defect §8 records, reproduced. That log is negative-control-base-arm.log in the run directory; the same tree reports 1 failed, 2 passed, EXIT=1.

Importer arm: the six existing test files that name _pointer_lock, mark_resume_launching or a promotion lock report 11 failed, 205 passed at the head and the same 11 failed, 205 passed at the base revision, with identical failing ids, so this change adds no failure. Ruff check and format are clean on the three staged paths.
