Landing measure arms use the declared compute partition

A project declaring landing.measure_partition submits each suite, importer-population and isolated-repeat arm through sbatch --wait as a separate job. Its srun step names the partition and time bound and carries no --overlap. Bounds over one hour select landing.measure_long_partition, defaulting to rigel. Projects without a partition declaration retain in-place execution, recorded as execution: in-place; scheduled measurements record execution: slurm.

Each job archives its named revision from the shared Git object store into its own node-local temporary tree, creates local Git metadata pinned to that revision, links the common environment and carries any newly added test files needed by the base arm. The job writes its revision, hostname, tree, command and terminal receipt to the run directory on shared storage, and removes its temporary tree on exit. A missing receipt or one disagreeing with the scheduler result makes the arm unreadable. Timed-out submissions cancel only their reported job ID.

The service-owned flight validator accepts the partition names and a positive finite landing.measure_timeout_seconds, and rejects malformed settings. The generated provider-neutral schemas are unchanged.
