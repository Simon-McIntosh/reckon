A gate meets the base of its own suite

What changed. A run that measured more than one suite could record only the default pair (baseline_suite/after_suite), so _red_base_uncovered_ids compared every gate with that one base. A gate on a second suite was therefore measured against the wrong suite's inherited failures: every id the second suite inherits read as a failure the head added, and the zero-added path was unreachable for that gate however red the head's own suite was.

A manifest may now record further pairs under suite_pairs, a mapping from a pair name to its base and head arms, each shaped like baseline_suite's arm. _suite_pair_for_gate selects the pair whose head arm cites the gate's own log, comparing the two citations by resolved path so a relative spelling on one side and an absolute one on the other still match one file. The default pair stays the fallback: a gate that names no log, or whose log matches no recorded head, is measured as before, and a manifest recording no suite_pairs field is unchanged. The refusal beside a nonzero exit now quotes the selected pair's own arm names (suite_pairs.UNIT.base, suite_pairs.UNIT.head) rather than the default pair's, so a reader is sent to the field the base sits in.

Matching a recorded pair's head arm to the gate's log is not a second rule: it goes through _arm_describes_the_cited_log, the function the receipt comparison already owns, which matches by resolved path or by digest. An arm that names its log by digest alone therefore selects its own pair instead of falling back to the default one, and a digest leg is skipped only when the cited log cannot be read, so an unread log is never compared with the digest of empty text. The receipt comparison, too, is made against the selected pair's head arm — not the default after_suite, which describes another suite's run — and its refusal names that arm.

The guard. A new test, tests/test_a_gate_meets_the_base_of_its_own_suite.py, drives the admission and the receipt comparison through a temporary run record. Case one records a red default pair and a second pair whose base and head both carry the same three ids; a gate on the second pair's head log is measured zero added and the passing verdict is admitted. Case two keeps the same gate and drops one id from the second pair's base, and the comparison reports exactly that id, refusing the verdict. Case three records no suite_pairs and shows the default pair still measured as before. Case four records the second pair's head arm by log_digest alone, and it is still the pair the gate is measured against. Case five gives that head a failure_count of zero beside a log naming three failures, and the receipt refusal names suite_pairs.UNIT.head.
