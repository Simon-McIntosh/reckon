A reclaimed run has one head for its review and its promotion

A run whose worktree has been reclaimed has its head read from the manifest's commits: field, and that field is a citation list, not an ordered history. The review path's _record_carried_head took the last listed entry while the promotion path resolved the newest by ancestry, so on a manifest written newest-first a review and a promotion of the same run named different heads, and the review scored the oldest commit the run had landed.

The ancestry resolution now lives once, in _record_carried_head (reckon/crew/recovery_review_dispatch.py), which resolves each cited entry through the run's tree and takes the newest by ancestry with a bounded git rev-list --topo-order --max-count=1. Promotion's _run_head (reckon/crew/promotion_records.py) reads a reclaimed run's head through that same function, so the two readers cannot disagree about the ordering; its duplicate resolver is removed.
