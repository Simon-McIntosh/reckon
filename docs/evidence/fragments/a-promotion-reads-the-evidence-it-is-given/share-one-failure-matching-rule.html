Failure comparisons share one identity rule

The control-admission, ledger, landing-measure, review-log and retirement readers now use review.failure_ids_covered. Retry overlap uses review.failure_ids_match, which returns a FailureIdMatch with matched_base, matched_head, unmatched_base and unmatched_head. Both functions share the same directional matching implementation. Coverage accepts a bare baseline name for a qualified head id; overlap accepts a bare name on either side. Qualified paths and parameter brackets retain their identity.

Attribution is stored under the measured head id even when supplied as a bare name, so completeness checks can account for every added id. Retirement keeps canonicalisation against every recorded arm directory. The scratch-tree reduction already worked at dispatch and is retained under the shared rule.
