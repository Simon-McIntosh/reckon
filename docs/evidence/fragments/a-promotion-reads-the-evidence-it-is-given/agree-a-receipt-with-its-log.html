A gate receipt's failure figures agree with its log

What changed. A promotion asserts a passing gate from two records: the manifest's after_suite arm, which states an exit status, a failure count and failure ids, and the gate log the row cites. Nothing compared the figures with the log. The gate-log guard read the log's tail for a status and stopped there, so a log holding two runs accepted a receipt copied from the first run's figures beside the second run's status.

In reckon/crew/promotion_evidence.py, _require_gate_log_agrees now takes the run record and reads the arm that describes the cited log — by path or by digest; an arm naming another log is not compared. Its count is compared with the failed plus errored figure of the log's last pytest summary, and its ids with the ids of the log's last run in both directions through review.failure_ids_match, with the receipt as the base so a bare receipt id covers a qualified log id. Each field is compared only when the arm records it, so an arm stating one figure is not refused for the absence of another.

Two further shapes are refused, both for a passing gate. A cited log with no terminal EXIT=<n> line is refused, read through reports._terminal_exit_status, which already owns that question; the command-not-found refusal is asked first, because a log whose only content is that diagnostic is better named by it. A gate whose command runs pytest and whose last run reaches no pytest summary is refused, because such a run stopped before reporting a result; a command that does not run pytest is not held to one.

In reckon/crew/review.py, gate_log_failure_ids gains a last_run reading, cut by the new last_run_text at the log's second-to-last exit record, so the ids come from the same run the status does. The section adds no refusal family: every mismatch is reported through the gate-log refusal that already exists.
