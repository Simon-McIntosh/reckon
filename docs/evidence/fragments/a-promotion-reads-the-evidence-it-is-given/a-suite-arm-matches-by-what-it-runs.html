A suite arm matches by what it runs, not how it is spelled

What changed. _arm_missing_fields in reckon/crew/promotion_records.py compared an arm's recorded command with the armed one after normalising whitespace only. A worker records the shell string it ran, so three spellings of the same run were refused as missing evidence: the test files named in another order than the armed template sorts them into, the interpreter written as the environment's absolute path where the template is relative, and a leading cd <tree> && into the tree the arm ran in. Each refusal cost a resume round and a failed promotion for an arm that had run the suite.

The comparison now reads the command. A new _arm_command_matches splits the recorded string with shlex and canonicalises it in three ways: a leading cd into the arm's own tree is dropped (a cd anywhere else still refuses), the interpreter word is resolved to one path against that tree so .venv/bin/python and its absolute path meet, and the test-file arguments are compared as a set rather than in order. Every other word, including each flag, is still compared in place, so a different test file, a different flag or a different interpreter still refuses. Both the scoped and the unscoped branch of _arm_missing_fields use it.

Measured

The new tests/test_a_suite_arm_matches_by_what_it_runs.py shows five cases against _arm_missing_fields over a scratch git tree holding two collectible tests and an interpreter: the same files in another order match, the absolute interpreter matches, a leading cd into the arm's own tree matches, a missing test file refuses, and an extra pytest flag refuses. All five pass at the head (7c38e14f2201332e888ce5f70e3a50ca7565ecf5).

The suite pair promotion reads, each arm resolved over its own tree: the base arm at 22716863ce names only the census test and reports 51 passed, exit 0; the after arm at the head names the new test and the census test and reports 56 passed, exit 0. The test files importing reckon.crew.promotion_records report the same six failures at both revisions (6 failed, 140 passed at the base, 6 failed, 145 passed at the head), all pre-existing in tests/test_crew_promotion.py and tests/test_promotion_records_the_pick.py, so the change adds no failure.

Negative control. Restoring the whitespace-only comparison makes the first three cases refuse and the last two pass: 3 failed, 2 passed, exit 1, with the failures being test_the_same_files_in_another_order_match, test_the_absolute_interpreter_of_the_runs_environment_matches and test_a_leading_cd_into_the_arms_own_tree_matches.

Ruff by delta. ruff check and ruff format --check report no finding on either staged path.
