A printed warning is not a failing test

The landing check read a failure from a gate log by the word a line opens with. A test's captured logging output reaches the same short-summary region as ERROR package.module:file.py:3553 message, so two arms carrying identical failing ids compared unequal whenever one of them merely printed something. Measured on run r-20261111T033929508961's own archive arms: 15 failing ids at base and 14 at head, and the check reported 2 added failures, both of them printed records.

A failure line now counts only where its id is one pytest names: a node id carrying the :: separator, the .py path a collection error reports, or the bare test name the shared matching rule lets stand for a qualified id. The captured-record shape — logger, filename and line number separated by single colons, then a message — is what excludes an id.
