A red base matches a bare test name to the qualified id it names

What changed. The red-base admission compared failure ids verbatim. A manifest records baseline_suite.failure_ids with the bare test name a worker copied from a summary line (test_charge), while the head arm's gate log writes the node id (tests/x.py::test_charge). One test therefore read as two, the head's ids were not covered, and a run that added no failure at all was refused as having added one. The matching rule now lives beside canonical_node_id, as review.failure_ids_covered(base_ids, head_ids), which returns the head ids the base does not cover: a bare base name covers a head id whose final :: segment, with a trailing parameter bracket removed, equals it; a bracketed bare name such as test_charge[1] covers only that parametrisation; and a qualified id covers only itself, so tests/other.py::test_charge never covers tests/x.py::test_charge. canonical_node_id is unchanged. promotion_evidence._red_base_uncovered_ids is the one function that reads the arms and calls the predicate, returning the uncovered head ids or None when no comparison could be made; _zero_added_against_a_red_base keeps its boolean and admits only a comparison that was made and left nothing uncovered. The refusal beside a passing verdict names the uncovered ids, at most twenty plus a count of the rest, and keeps the arm-completion clause when no comparison could be made.
