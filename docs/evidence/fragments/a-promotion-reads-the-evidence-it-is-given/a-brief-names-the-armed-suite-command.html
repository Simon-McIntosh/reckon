A brief and a resume advice name the revisions each suite arm must record

What changed. The implement brief and every resume or repair advice now state the two revisions the suite arms must record, with the armed command resolved separately over each. _suite_gate_prompt_body (reckon/crew/dispatch.py) takes a base_revision and states it beside the resolution it already printed — the worktree's head is the base revision at dispatch, so that resolution is the baseline arm's command — together with the after-arm rule: record the after arm at the run's head, with the command resolved over that head. The revision itself is read by _suite_gate_prompt_body_for from the worktree payload the dispatch has just cut, not supplied by the caller, so the one place that knows which revision the tree was cut from is the one place the brief reads it. A new _revision_suite_block in reckon/crew/resumption.py resolves the declaration at both revisions from the run record's base_sha and the worktree's current HEAD, read through the repository's shared commit resolver _resolve_commit rather than a second git rev-parse composed beside it, and _resume appends it to the advice before the prompt is built, so both the stdin and the argv prompt channels carry it. The repair advice reaches the same writer, so it carries the block without a second change.

The guard. tests/test_a_brief_names_the_armed_suite_command.py shows two cases. The first composes the real dispatch brief through _compose_dispatch_prompt from the worktree payload, using the same _suite_gate_prompt_body_for the call site uses, and asserts it names the base revision, the command resolved there, and the after-arm rule; the same payload carrying no base_sha must yield a brief naming no revision. The second drives resumption._resume over a run whose head adds tests/test_y.py absent at its base revision, captures the advice a worker would read, and asserts both revisions are named with two different resolved commands.
