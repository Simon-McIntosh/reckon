A ctest receipt is counted in its own format

What changed. _receipt_mismatches compared a suite arm's failure_count with every cited log through pytest_summary_failure_count, whatever the log's format. A ctest log prints no result-count line; its test programs print counts of their own, and the reader matched the last such line, so a suite whose programs reported 0 failed apiece was measured at zero however many tests ctest listed as failed. The count is now read in the log's own format by a new _log_failure_count, through the same dispatch gate_log_failure_ids uses (_gate_log_format): a pytest log keeps its summary figure, a ctest log's count is the number of entries in its The following tests FAILED: block — the set its ids comparison already reads — and a log in neither format states no count, so the figure is left uncompared rather than read as zero.

The defect, reproduced on the log that raised it. Run r-20261110T144158998914-sizing-solver-fixes' cited candidate/validation.receipt.log reads as format ctest; the pytest count reader returns 0, the ids reader returns 22, and an arm recording failure_count: 22 was refused with its failure_count records 22 and the log's last run names 0 failed or errored test(s) — the refusal the section quotes. After the change the same log and the same arm raise no mismatch, with the ids figure unchanged at 22.

Measured

The new test, tests/test_a_ctest_receipt_counts_its_own_failures.py, shows four cases over temporary logs: a ctest log whose programs print 0 failed and whose FAILED block lists 22 entries agrees with a receipt of 22; the same log disagrees with a receipt of 21, naming both figures; a pytest log is read from its summary line as before (3 agrees, 2 is refused as 3); and a log in neither format raises no count mismatch.
