A landing judges its worktree against the commit it wrote

What changed. crew complete --land released a run's worktree by comparing the worker head with HEAD in the checkout the run recorded. A run's repo can name a checkout the merge did not move — a linked worktree detached at the commit the worker started from is the shape one coordinator landing recorded — and the release then read the head as unreachable, withheld the tree and exited 1 with the head already pushed. Two further reads in the same landing had the same fault: the ledger write for the release staged the run's ledger file inside the recorded checkout, where it does not exist, and the post-push check read the primary branch there. _land_a_promoted_run now passes the checkout it merged in and the commit merge.land returned into promotion_release._release_after_promotion, so reachability, the worktree audit, the ledger write and the branch read all use the revision the landing wrote. A release on the merge path therefore reports the post-merge reading, and a tree whose head is on the branch is released rather than withheld.

Changed paths

  • reckon/crew/promotion_release.py — the release, the promotion wrapper and the worktree audit take the landed checkout and commit; the audit reads the checkout the release judges against.
  • reckon/crew_run_commands.py — the landing passes the checkout it merged in and landed["commit"], and stages the release's ledger write and reads the branch there rather than in the recorded checkout.
  • tests/test_a_landed_head_releases_its_worktree.py — the three cases and the two negative controls.
