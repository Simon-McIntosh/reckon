Server serves one code version

The request guard reads the same 30-second, executed-definition report published by /_server. Six requests inside that window compare package source once, and editing a module the server never executed leaves the next request at HTTP 204. When executed code changes, the refusal names only the report's changed files and derives both distinct fingerprints from those files. It returns HTTP 503 stale-code with Retry-After: 5, stops serving new requests, waits up to three seconds for active handlers, then calls the injected exec function with the process's interpreter and original arguments.

In the temporary-package reproduction, the server executed an old recovery function before the copy gained a new import name and a changed definition. Discovery receives the named refusal before it can lazy-load the replacement roadmap. With the guard removed, that same request returns HTTP 500 with cannot import name 'stale_code_probe'.
