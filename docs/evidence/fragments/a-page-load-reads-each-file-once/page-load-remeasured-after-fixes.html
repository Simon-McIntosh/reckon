One malformed plan page causes both failures

Scanning all 14 mounts with the server's own parser found exactly one refused page of 1,753. imas-codex/docs/plans/migration-project-state.html carries section records as <section id="s1" data-reckon="section"> with no data-id, so _plan_html._read_section_records reads an empty identity and refuses it: ValueError: sections[''].id: record must be adjacent to its h2 at reckon/_plan_html.py:378.

The asymmetry between the two routes is the finding. /_discover/imas-codex catches the refusal and answers a structured 500. /_projects/index.json does not: the raise happens inside a ThreadPoolExecutor worker under project_entry, so the handler thread dies and the client receives no response at all. One bad page in one project therefore costs the whole fleet index.

This is not section 7's fix. The page was written 2026-09-24 17:57, after both the section 7 merge (2026-09-23 19:59) and the prior measure (2026-09-23 16:22), and the rollup's call chain is unchanged by section 7. The new failures attribute to that page's last write in imas-codex, ec7ec63ae, not to any commit here.

Corrections and limits

  • /_discover/nova's 3.082 s is a contention artifact: four immediate re-samples give 0.16 to 0.18 s. The preceding failed rollup drops the connection while its workers keep walking, so the next request pays for abandoned work. The miss is recorded rather than excused.
  • No py-spy dump could be taken. py-spy dump is refused on this host with Permission Denied even with the worker sandbox disabled, although ptrace_scope is 0; the prior run's success was on a different host. The server's own traceback substitutes, being the exact raise site rather than a sample of it.
  • The cold pass is not a true first touch, for the same reason the prior run's was not: restarting a shared service to force one is a blast-radius action. The warm pass, which section 5 gates on, is unaffected.
  • The harness needed one added except clause, because unmodified it aborts the entire run on the first request's closed connection and records nothing. The crash log is kept beside the completed run.
