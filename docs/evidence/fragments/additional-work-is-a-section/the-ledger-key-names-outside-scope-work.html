The ledger key names work outside a worker's scope

The committed run row names the paths a worker reported beyond its own scope under outside_scope_paths, renamed from follow_on_paths. build_record writes the new key and promotion passes its extracted paths under it, so a promotion produces outside_scope_paths and no follow_on_paths on the row. The manifest field the paths are read from keeps its own name here.

A row promoted before the change still reads. run_record owns the mapping from the retired spelling onto the current one and exposes it as outside_scope_paths (read, with fallback) and normalize_outside_scope_paths (the row with the retired key dropped). ledger applies it in _read_run, _load_aggregate and _index_payload; run_store applies it at every stored-payload decode. One key therefore answers whichever revision wrote the row, and the retired spelling is never carried into a later write.
