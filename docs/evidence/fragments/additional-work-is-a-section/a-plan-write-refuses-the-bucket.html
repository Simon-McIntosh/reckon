A plan write that names the deferred-work term in prose is refused

What changed. The plan store now refuses an authored plan body that names the deferred-work term in prose. The refusal is one more reason the existing forged-body predicate reports (_forged_plan_structure in reckon/_store.py), not a second check: insert_section, an append_evidence body, a created plan's section body — which reaches the same predicate through _queue_authored_section and _insert_authored_section — and a set of sections.<id>.body through reckon/_store_section_ops.py's _refuse_forged_structure all raise it in the channel they already used, so no caller sees a new error code: an operation error on the state routes and a text-edit error on text mode. The reason the predicate returns is the rule itself with the quoted fragment, as in the term "follow-on" in prose; additional work is a plan section or an instruction in the dispatching prompt.

Three details carry the design. The prose is read by the audit's own reader, reckon/doccheck.py's _prose_text, which already leaves the <pre> and <code> subtrees out, so a section citing the term as a symbol stays writable and the store and the audit cannot disagree about what counts as prose. Text mode (_replace_plan_text) supplies the fragment it replaces beside the fragment it writes, and only the term the edit adds is refused, counted per occurrence, so a plan whose older prose already carries the term stays editable. A sections.<id>.body set has no prior body to compare against, so a legacy body carrying the term is refused there, and that refusal names text mode as the route out.

reckon audit-doc reports the term in prose as one new warning kind, deferred-work-term-in-prose, on a plan that already carries it, so the corpus is converted without a write-time refusal breaking on history.
