Promotion records a brief run's owner

A brief run carries no committed plan section, so the ordinary landing path had nothing to join a product change to the plan that owns it. Promotion now lands a brief run with plan null and the digest of the stored brief it read, skips the impl-move guard that has no plan to read, and refuses an implement-role brief run that names neither the plan it changed nor a reason it changed none.

The gap: a product change with no owner

A brief replaces --plan and --section, so its node carries an empty plan. The impl-move guard read that empty plan and exempted the run with node-names-no-plan, but nothing in the landing path required the run to say which plan its product change belonged to. An implement-role brief run could therefore land code without any row field naming the plan it touched.

The reproduction is the declared negative control below: with the implement-role check dropped, an implement brief run that names neither discharge promotes, and the refusal case fails.

What changed

  • reckon/crew/promotion.py gains _require_brief_owner, called before any store is written. It reads the node's brief, and for an implement-role run with neither --plan-link nor --unplanned-reason it refuses, naming both flags. A non-implementing role and a plan run are untouched.
  • _require_impl_moved gains an explicit brief exemption (brief-names-no-plan) ahead of the role check, so a reader of the row sees the run's carrier as the reason rather than an absent plan that could read as a defect.
  • reckon/ledger.py: build_record gains brief, plan_link and unplanned_reason. A brief run stores plan null and the brief's sha256/path; either discharge lands on the row or is null, so an unrecorded value is told from one never asked for.
  • reckon/cli.py: crew complete gains --plan-link SLUG and --unplanned-reason TEXT, forwarded through complete and _complete_locked.

The gate

tests/test_promotion_records_a_brief_runs_owner.py writes a pointer over a synthesised temporary repository (RECKON_HOME moved into a temp tree, no real ledger or live pointer directory touched) and promotes through crew.complete, and, for the CLI cases, through reckon crew complete via the click runner.

  • test_an_investigate_brief_run_promotes_with_no_extra_flag — the row's plan is null, its brief.sha256 is the pointer's digest, and the impl move is exempt with reason brief-names-no-plan.
  • test_an_implement_brief_run_without_an_owner_is_refused — the refusal names both --plan-link and --unplanned-reason, and the pointer survives.
  • test_a_plan_link_lands_on_the_row and test_an_unplanned_reason_lands_on_the_row — each discharge lands on the row and the other stays null.
  • test_the_cli_refuses_an_implement_brief_run_without_an_owner, test_the_cli_plan_link_reaches_the_row and test_the_cli_unplanned_reason_reaches_the_row — the command line reads the refusal and forwards each option to the row. Deleting the forwarding in reckon/cli.py fails both option cases.
