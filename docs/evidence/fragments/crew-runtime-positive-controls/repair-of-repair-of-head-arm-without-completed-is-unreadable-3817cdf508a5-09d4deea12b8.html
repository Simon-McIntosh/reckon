The baseline arm reads its failure ids the way the head arm reads them — evidence

The control gate reads a red log against a suite arm. The head reader _head_suite_failure_ids validated the arm's failure_ids before using it: a non-list, or a list carrying a non-string, is unreadable and decides nothing. The baseline reader _baseline_suite_failure_ids did not — it iterated observation.get("failure_ids") or () directly. A value recorded as a JSON string therefore iterated as its characters, and a baseline that could not name its failing tests admitted a control the same manifest in list form refused; a non-iterable value raised TypeError out of the gate.

The baseline reader now asks the shape the way the head reader does: a list of non-empty strings, and None otherwise. An unreadable baseline decides nothing in every shape — the caller falls through to the head arm when one is readable and refuses when neither is, so a malformed id set is never folded into the empty arm that admits every control.
