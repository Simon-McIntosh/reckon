A worker spawn retries when a protected bind source vanished — evidence

The fence composes a read-only bind for every protected path present at composition, from the declared set, and a writer that replaces a file by rename leaves the name missing for an instant — the harness replaces ~/.claude.json that way. A spawn landing in that instant died inside bubblewrap before the worker started: bwrap refuses --ro-bind whose source is absent at mount time, and the run was recorded as a launch failure for a source that was back a moment later, so the node was marked failed for a race the retry now absorbs.

The mechanism, and what is deliberately not retried

  • Recognition is keyed to this launch's own binds. _read_only_bind_sources(argv) lists the --ro-bind sources the argv would mount, and _refusal_names_a_bind_source matches one of the two phrases bwrap answers with when a source is gone (Can't bind mount, Can't find source path) and a source this launch mounted. A refusal over anything else, and any spawn failure at all, is returned at once for its caller to record as the launch failure it is.
  • The retry is inside one attempt. A worker that starts on a later try is the attempt that launched: nothing is appended to launch_failures and the run's phase is untouched. Each dead try is reaped by process.wait() so it cannot later be mistaken for the worker's own exit. Tries are bounded by _backends.PROTECTED_BIND_WAIT_ATTEMPTS with _backends.PROTECTED_BIND_WAIT_INTERVAL_SECONDS between tries; a refusal that outlives the bound ends as the launch failure it is.
  • Both spawn seams share the retry — _spawn_detached_worker and _supervisor_spawn_worker each build a per-try attempt() closure.
  • A poll consumes the status it observes. The retry's startup check polls the fresh child, so a worker that died inside that window is no longer waitable; registering its pid handed the reaper a child it could not wait (ChildProcessError ECHILD), and the reap discarded the pid without recording the failure while the _LAUNCHED_WORKER_RUNS entry leaked. The detached seam now records the exit the check collected exactly as a reap would, instead of registering the pid. This was found by the node's own second case failing, not by inspection: the first full run recorded launch_failures empty and the phase still working for a worker that had died.
  • The launch seam accepts a stand-in. The supervisor seam is exercised both by real spawns and by tests that replace Popen with an object carrying only a pid; the startup check treats a launch that cannot be polled as started rather than failing on it, since the refusal is proved by the child's own exit.

The pool control driver mutates what the fence reads

The fence composes from declared_protected_paths (the intent), not from the narrowed protected_paths (on disk now) — a protected path absent for an instant must still be sealed, which is the same race this node retries. tests/test_fence_protects_the_worktree_pool.py's _negative_control_report therefore patches declared_protected_paths through _without_pool, so stripping Code/.reckon-worktrees removes the pool's read-only overlay from the composed argv and case 1's write into the sibling lands, which is the control's red result. The new test file's last case pins both directions: the composed launch really does overlay the pool, and under the mutation it no longer does.

The measure

The gate is the caller-derived set the brief names: every file under tests/ matching _spawn_detached_worker (the new file) or _supervisor_spawn_worker (tests/test_stored_phase_advances.py, tests/test_worker_env_export.py), unioned with the changed fence file — four files at head, three at base, where the new file does not yet exist. Both arms ran under pytest-xdist -n 8 --timeout=300 with their own basetemp outside any repository, each log naming its revision on its first line and ending EXIT=<code>.

  • Base arm (a31484ff0, a git archive extraction of the base under the run's scratch): 11 passed in 23.24s, EXIT=0 (gate-base-bind.log, gate-base-bind.json).
  • Head arm (9bf13264b, this worktree): 17 passed in 38.93s, EXIT=0 (gate-head-bind-2.log, gate-head-bind-2.json). The failure sets are identical — the head arm adds no failing id, none lost.
  • The first head arm added three ids, and they were this node's own defect. tests/test_worker_env_export.py replaces Popen in dispatch's namespace with a stand-in carrying only a pid, and the retry's startup check called poll() on it (AttributeError: 'Spawned' object has no attribute 'poll', gate-head-bind.log). The seam now treats an unobservable launch as started, which is the second commit of this node.
  • This node's own six cases (tests/test_spawn_retries_a_vanished_bind.py): both refusal phrases retried with the run's phase still working and launch_failures empty; an unrelated failure not retried and recorded as the launch failure (the positive control for the retry cases); the bound honoured at exactly PROTECTED_BIND_WAIT_ATTEMPTS tries ending as one launch failure; the supervisor seam retrying; the pool control driver's mutated fence lacking the pool bind. They also passed serially (6 passed in 24.18s, node-tests-serial.log) before the xdist arms.
