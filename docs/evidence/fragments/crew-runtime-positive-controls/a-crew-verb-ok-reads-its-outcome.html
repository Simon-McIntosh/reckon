The published rule

_crew_result_ok in reckon/cli.py reads the result before _emit_crew_result publishes it. An explicit ok wins, including false. A refusal, hold, finding, red exit status, timeout, failed validation or unmeasured attempt is false and exits nonzero. A deliberate skip is different: the result retains its skipped or stopped reason, publishes ok: true, and exits 0, so a cross-project verb can complete even when one project needs no action or must be left untouched. A worker's pending exit status inside an observation is data about the worker; the successful read stays true. The emit helper uses exit 1 for a false result and preserves preflight's established exit 3 for a hold.
