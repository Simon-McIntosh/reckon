A review record's revisions resolve before its review run completes

What changed

reckon/crew/review.py gains unresolved_reviewed_revision, which resolves a record's carried base/head against the reviewed run's own live pointer — its worktree, or its repository once the worktree is reclaimed — and store_review now refuses before writing when a carried value names no commit there. reckon/crew/reports.py adds the same check to the manifest audit, so crew check-manifest on the review run reports it while the reviewer still holds its turn. Both refusals name the stored sha and the head the reviewed worktree actually carries. A record about a run with no readable pointer or tree is not judged, so no correct record is refused on a guess. Each carried value is resolved through reckon.crew.recovery._resolve_commit, the function that already answered whether a revision names a commit in a tree; the --verify, --end-of-options and timeout hardening lives there, so one resolver serves both callers.
