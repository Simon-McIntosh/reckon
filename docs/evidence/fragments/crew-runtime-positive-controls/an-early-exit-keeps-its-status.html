A worker reaped inside the launch retry's startup window keeps its exit

Landed at fac9f9557 (the carry) and c34c0ab97 (the carry stands beside another child) on reckon/crew/dispatch.py and tests/test_an_early_exit_keeps_its_status.py.

The vanished-bind retry polls the worker it has just spawned for SANDBOX_STARTUP_WINDOW_SECONDS, and a poll of a child that has already exited collects its status and leaves the pid unwaitable. The spawn helper now converts a collected Popen return code back to the wait status the exit record is composed from — _wait_status_from_returncode — and carries it on the pid it returns as an _WorkerPid, an int that every other reader keeps seeing as the pid. The supervisor writes that carried status as the attempt's exit instead of waiting on a reaped pid, and the carried exit is final: the worker has been reaped, so nothing else parented to the supervisor is a still-running worker whose exit could end the attempt, and the leftover-child wait is the launcher path, entered only when no exit was carried. A worker that outlived the window carries nothing and is supervised exactly as before.
