granted-path-is-a-claim — a plan's landing files are compared against live claims like any other path

Defect. crew dispatch --dry-run reported live_conflicts: [] for a node granted the plan HTML, its cumulative evidence record and its figures topic while a live pointer claimed all three. Two concurrent runs were therefore handed the same file — the record every node on a plan appends its landing to — with nothing naming the other holder, and a whole-file write by either silently takes the other's landed section. The report skipped them because _live_conflict_rows built its candidates with _candidate_scope_entries and skipped every claim whose path was one of the plan's landing files, so the paths dispatch grants were the only paths the live-claim report never compared.

Reproduction at 9e5081bb32085947e24a8b17921c94c7935e32df (temporary config home, one plan, a live pointer holding the three granted paths, then a second dispatch dry-run): live_conflicts == []; the new case test_a_granted_landing_collision_is_reported fails at base while the caller-named and promoted-holder cases pass (base arm 1 failed, 230 passed).

Fix, one commit. The reporting check now resolves the node's whole scope (_resolved_node_scope_entries) and holds the landing paths the node actually claims (_granted_landing_paths): a live claim on a landing path the node itself holds is reported like any other collision, and one on a landing path it does not hold is still skipped, so the fragment default's ordinary work is untouched. The refusal path is unchanged — a granted collision is admitted and reported, which is what lets two nodes' appends meet in a merge. Directory-claim refusal is unchanged for the same reason: pairs involving a held landing path are reported and never judged as a directory claim (_live_conflict_outside_granted_landing), while every other pair keeps the judgement it had.

Evidence — three cases in tests/test_granted_path_is_a_claim.py, each driving the real dry-run CLI in a temporary config home:

  • Granted collision reported. A live pointer holds the plan HTML, the cumulative evidence record and the figures topic; the second dispatch is granted the same three and reads one row per shared path, naming the holder's run and node and the shared path on both sides. Head arm: 231 passed (exit 0).
  • Caller-named collision unchanged. A live claim on an ordinary exclusive path reads exactly the row it read at base.
  • Promoted holder not reported. The holder's claim is asserted through scope_claims while live, then its pointer is removed as promotion removes it; the second dispatch reads live_conflicts == [], because a released claim is not a conflict.
