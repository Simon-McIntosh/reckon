granted-path-is-a-claim — a plan's landing files are compared against live claims like any other path

Defect. crew dispatch --dry-run reported live_conflicts: [] for a node granted the plan HTML, its cumulative evidence record and its figures topic while a live pointer claimed all three. Two concurrent runs were therefore handed the same file — the record every node on a plan appends its landing to — with nothing naming the other holder, and a whole-file write by either silently takes the other's landed section. The report skipped them because _live_conflict_rows built its candidates with _candidate_scope_entries and skipped every claim whose path was one of the plan's landing files, so the paths dispatch grants were the only paths the live-claim report never compared.

Reproduction at 9e5081bb32085947e24a8b17921c94c7935e32df (temporary config home, one plan, a live pointer holding the three granted paths, then a second dispatch dry-run): live_conflicts == []; the case test_a_granted_landing_collision_is_reported fails at base while the caller-named, promoted-holder and figures-parent cases pass (base arm 1 failed, 231 passed).

Fix, two commits. The reporting check resolves the node's whole scope (_resolved_node_scope_entries) and holds the landing paths the node actually claims (_granted_landing_paths): a live claim on a landing path the node itself holds is reported like any other collision, and one on a landing path it does not hold is still skipped. Reports only — whether a collision refuses the dispatch is untouched. The second commit makes that structural: the directory-claim judgement reads _live_conflict_rows(..., include_granted_landing=False), exactly the rows the exclusive-claim walk produced before the change, and the granted report is a second, additive read of the same claims snapshot, so nothing the report adds can drop a refusal or judge a collision the walk never saw. The refusal path (_raise_repository_scope_conflict) and the directory-claim judgement for the walk's own rows are unchanged; a granted collision is admitted and reported, which is what lets two nodes' appends meet in a merge.

Evidence — four cases in tests/test_granted_path_is_a_claim.py, each driving the real dry-run CLI in a temporary config home:

  • Granted collision reported. A live pointer holds the plan HTML, the cumulative evidence record and the figures topic; the second dispatch is granted the same three and reads one row per shared path, naming the holder's run and node and the shared path on both sides.
  • Caller-named collision unchanged. A live claim on an ordinary exclusive path reads exactly the row it read at base.
  • Promoted holder not reported. The holder's claim is asserted through scope_claims while live, then its pointer is removed as promotion removes it; the second dispatch reads live_conflicts == [], because a released claim is not a conflict.
  • Figures parent refused as at base. A live pointer holds docs/figures, the parent of the granted figures topic; the dispatch is refused with the directory-claim finding, exactly as at base. A sixteen-shape probe matrix (four declared scopes across four holder paths, live-claim-refusal-matrix-*.txt) shows identical refusal outcomes at base and at the repaired head; only the reported rows differ.
