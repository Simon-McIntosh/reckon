The prompt teaches the rule the control gate applies — evidence

Two live prompt sites in reckon/crew/prompts.py told the worker its red log's first line had to repeat the declared mutation verbatim. The gate that discharges the declaration no longer does: _require_declared_negative_control in reckon/crew/promotion.py reads the run's terminal exit status and the failing test ids the log names, and matches no wording. A worker could satisfy the prompt exactly and still deliver a log the gate refuses.

The removed sentence was reproduced from the composed contract before the change — a prompt composed at base 0c32542d carries the word verbatim twice, once in the declaration block and once on the manifest line (logs/reproduction-base.txt); at head it carries none (logs/reproduction-head.txt).

Both sites now state the rule the gate applies, including the arm that decides when the head arm cannot be read:

  • NEGATIVE_CONTROL_DECLARED_RULE: admission is judged on the facts that log records — a non-zero EXIT= line and at least one failing test id the head arm does not fail, falling back to the baseline's failing ids only when the manifest records no readable head arm, an arm being readable only when it declares its run complete — never on the log's wording. The declared string is what you apply and what a reader compares the log against, not a string any gate matches.
  • The manifest template's negative_control_log line: the same facts clause, in the same words, after the bare-path requirement and before the bare EXIT= last-line requirement, both of which are left exactly as they were.

The declared mutation is still interpolated once, unchanged, and the block names it as what the worker applies and a reader compares the log against. The diff holds the two sites plus the comments and the docstring that described the removed match. The four test modules that pinned the verbatim sentence now assert the facts rule, tests/test_the_prompt_teaches_the_rule_the_gate_applies.py pins both sites against the removed wording and for the fallback, and tests/test_prompt_carries_the_declaration.py — which pinned the same wording and was named by the review — has its two wording cases brought onto the same rule; its other cases are untouched.
