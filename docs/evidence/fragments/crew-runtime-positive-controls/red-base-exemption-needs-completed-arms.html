A red-base exemption needs both suite arms completed — evidence

The exemption at reckon/crew/promotion.py::_zero_added_against_a_red_base is the one path that admits gate: passed beside a nonzero exit status: the repository judges a gate by its delta against its base, so a red baseline plus a head that adds no failure id is a measured zero added, and the passing verdict is that delta. The old reading asked only for a red baseline exit and containment of the head ids. An arm that never finished its run records a short failure list, and a head whose log repeats those ids satisfies the containment without any delta having been measured — a baseline that stopped mid-suite could license a passed verdict.

Both arms must now declare completed: true as a literal, read from the manifest the way the strict arm validator asks it, and the refusal beside a nonzero exit names the arm that was not completed (via _arm_without_completion). The head arm's failing ids stay read from the cited gate log's own FAILED/ERROR lines (_head_arm_log_failure_ids, returning None when the log cannot be read), never from the manifest's after_suite list: the manifest is the run's own record, so a failure left out of it would read as zero added while the log beside it names the id. The baseline ids remain the manifest's baseline_suite list — the set the head is compared against.
