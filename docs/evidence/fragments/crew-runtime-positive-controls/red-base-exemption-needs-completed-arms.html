A red-base exemption needs both suite arms completed — evidence

The exemption at reckon/crew/promotion.py::_zero_added_against_a_red_base is the one path that admits gate: passed beside a nonzero exit status: the repository judges a gate by its delta against its base, so a red baseline plus a head arm that adds no failure id is a measured zero added, and the passing verdict is that delta. The old reading asked only for a red baseline exit and a head failure set contained in the baseline's set. An arm that never finished its run records a short failure list, and a head that repeats those ids satisfies the containment without any delta having been measured — a crash mid-suite could license a passed verdict.

Both arms are now read from the manifest, and both must carry completed: true as a literal, matching the sibling readers and the strict arm validator. An arm whose completion is missing or false refuses the exemption, and the refusal beside a nonzero exit names the arm that was not completed (via _arm_without_completion), so a reader knows which observation to finish and record.
