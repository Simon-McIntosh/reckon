Every removal path reads the wide claim

What changed

reckon/crew/routing.py: _remove_worktree, the rollback that undoes a worktree created for a dispatch that then failed, read liveness through the phase-gated _live_worktree_claims. A run parked between turns carries a terminal-looking phase and a dead worker process, so a live pointer's tree read as unclaimed and the rollback force-removed it. It now reads _live_pointer_worktrees, the wide claim every gc path already reads, and the phase-gated import leaves the module with it.

_live_pointer_worktrees, defined in the same module, was already the claim the sweep and residue-release paths read; this change makes its docstring's guarantee true of the remaining path.

How the removal paths were enumerated

The test carries no list. It parses every reckon/**/*.py source, and a function is a removal path when its body invokes a command whose literal argument list carries the adjacent pair "worktree", "remove" — covering both shapes in the package, the _git(...) helper and a subprocess argv list. Four paths were found: _remove_worktree, garbage_collect and _save_and_release_worktree in reckon/crew/routing.py, all reading the wide claim after this change, and _release_run_workspace in reckon/crew/promotion.py, which reads its removal target from the released run's own record — the sanctioned release door, excluded from the reclaim population by the same derivation, and reported below.

_live_worktree_claims is kept for its non-removal callers: the worktree audit in reckon/crew/promotion.py, whose read is report-only, and the promotion boundary check, which asks whether a run is in flight rather than whether a tree is reclaimable.

Evidence

  • Head arm, same population: 299 passed (EXIT=0); the new test file alone re-run against its committed bytes: 3 passed.
  • Negative control, the declared one: a scratch copy of head in which _remove_worktree reads _live_worktree_claims again — 2 failed, 1 passed (EXIT=1), both failing ids absent from the green head arm. The parked tree the failing case built no longer exists under that run's retained basetemp, while the same tree and its marker are present in the head run's basetemp.

Follow-on

_release_run_workspace in reckon/crew/promotion.py is the one removal path outside this node's write scope. It removes a worktree it does not own and decides through the phase-gated claim (excluding the run being released), so the same parked-run case applies to it; its read should become _live_pointer_worktrees() minus its own run.
