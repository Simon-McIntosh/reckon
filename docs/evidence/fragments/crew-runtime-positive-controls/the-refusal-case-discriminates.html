The refusal case discriminates — evidence

A promotion that omits --commit carries its citations as manifest text, and the citation check in reckon/crew/promotion.py is the only guard that resolves them. If that check stops running, an unresolvable citation falls through to the worktree-head guard, whose refusal — cites no commit, but its worktree is at … rather than its base … — leaves exactly the same four facts behind: a non-zero exit, no traceback, no ledger row, and a surviving pointer.

That is what the case at tests/test_cited_identifier_resolves.py asserted, and it is why the case held whichever refusal fired. It is the shape the earlier review described: an assertion that holds under the mutation it exists to catch measures nothing.

The reproduction, before the change

The citation check was short-circuited in memory only — reckon.crew.promotion._unresolved_citations replaced with a function returning [], loaded through pytest -p citation_shortcircuit. reckon/crew/promotion.py on disk was never edited; the plugin asserts the substitution took effect and the log records it. The named case alone, at the base revision:

  • 1 passed, EXIT=0 (logs/base-shortcircuit-named-case.log, arm arms/base-shortcircuit-named-case.json).
  • The full file in the same patched process is 3 failed, 7 passed, EXIT=1 (logs/base-shortcircuit-reproduction.log): the three sibling refusal cases fail, which shows the mutation is live, and the named case is among the seven passed.

So the case could not catch the citation check going silent, and nothing else in the file fails on the mutation for the reason the case exists to test.

The change

The case now asserts the refusal's own words beside the outcome it already asserted, as the sibling refusal cases do: assert _FABRICATED in result.output and assert "does not resolve" in result.output. The existing assertions — non-zero exit, no traceback, no row, the pointer survives — are kept. Nine lines added, none deleted; the marker the change introduces (assert _FABRICATED in result.output) reads 2 at head against 1 at base; no source file changed.

The measure

  • Base arm (8b89df3321f9f3a47eac9a0cedb170c836c6e9bb, this worktree): 20 passed in 84.85s, EXIT=0 (logs/base-gate.log, arms/base.json).
  • Head arm (abfab2c93ced3a8f923a15765eaca382a4da1020, this worktree): 20 passed in 92.33s, EXIT=0 (logs/head-gate.log, arms/head.json). The head arm adds no failure id.
  • Negative control (the declared mutation, head revision): 4 failed, 6 passed in 67.61s, EXIT=1, the second line recording that the patch applied, and test_the_refusal_leaves_no_row_behind_it is among the four failed (logs/negative-control.log, arms/negative-control.json). The same short-circuit that left the case green at base now reddens it, which is the discrimination the item asked for.
  • Ruff, over the changed path only: ruff check and ruff format --check report All checks passed and 1 file already formatted at head, identical to the base revision's reading.

Each pytest process ran with a basetemp private to it under /tmp/r-20260930T233349956479-the-refusal-case-discriminates/, and every log's first line names its revision, its tree and the literal command; each ends with a bare EXIT= line.

Scope

The presentation branch — a promotion that presents at least one commit — still resolves only the presented list, so an unresolvable value declared beside a presented one is dropped rather than refused. That behaviour is pinned by a test file outside this node's granted paths and is unchanged here.
