A stale terminal manifest does not license promotion — evidence

A resumed attempt reuses its run directory, so a complete or blocked manifest beside the pointer may be the verdict a superseded turn left. Recovery already reads that pair correctly: a worker launched after the manifest's last write cannot have written it, so _worker_launched_after_manifest and the superseded_manifest arm of deferred_outcome defer the run's outcome instead of calling it delivered. _require_worker_stopped_before_promotion stayed silent on the same file, so crew complete accepted the previous attempt's record as the delivery and removed the live pointer — the one harm that guard exists to prevent, since promotion deletes the pointer and the still-running worker is then orphaned with no follower row and no claim on a coordinator.

The gate now asks recovery's own question rather than a second version of it. A terminal manifest whose file predates the live attempt's launch is read as unfinished, and the refusal names the superseded status instead of presenting it as this attempt's verdict:

  • reckon/crew/promotion.py:3412–3430: superseded is computed with recovery._worker_launched_after_manifest(record, Path(str(record["manifest_path"]))), and live admits a terminal status only when the manifest is not superseded. The reading is fail-open on unreadable evidence, exactly as the helper's own contract states, so a run with no worker record behaves as it did before.
  • reckon/crew/promotion.py:3440–3452: the refusal distinguishes the two cases — a stale status reads “its manifest's 'complete' status was written before this attempt was launched, so it reads a superseded attempt rather than the work running now” — and still offers --waive-live-run REASON, which rides the promoted row as before.
  • reckon/crew/promotion.py:3732–3768: _unreviewed_refusal states the classification and the absent review as two statements (is classified {classification}; {revision}). It previously wrote classified running because no complete independent review is stored, which reads as a claim that producing a review moves the classification a run already holds.
