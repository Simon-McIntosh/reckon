A stale terminal manifest does not license promotion — evidence

Promotion deletes the live pointer, so a run promoted while its own process is still running carries on with no pointer, no follower row and no claim on any coordinator — an orphaned worker whose worktree cannot be reclaimed. Recovery already reads the pair correctly: a worker launched after its manifest's last write cannot have written it, and deferred_outcome defers such a run rather than calling it delivered. _require_worker_stopped_before_promotion did not, and the review of the first landing found the hole the first measurement had missed.

Two shapes reach the guard and they are not the same defect:

  • A first dispatch leaves its manifest fresh by the run's own baseline, so the attempt's terminal status has to be judged against its launch time — that is what the first landing fixed.
  • A real resume sets its baseline to the inherited manifest's own mtime (reckon/crew/resumption.py:778), so runs._manifest_freshness reports (True, False), _fresh_manifest returns None, and the guard returned without refusing. An independent probe of the committed first landing measured exactly that: baseline 1790753590166677713 equal to the manifest's mtime_ns, record_process_alive = True, _worker_launched_after_manifest = True, and GUARD VERDICT = ADMITTED.

The guard now reads an attempt that has delivered no manifest of its own as unfinished, for the same reason it reads a non-terminal status that way:

  • reckon/crew/promotion.py:3419–3458: live is record_process_alive(...) is True and (manifest is None or status not in TERMINAL_MANIFEST_STATUSES or superseded), where superseded reuses recovery._worker_launched_after_manifest rather than composing a second reading. The refusal distinguishes the three verdicts — no manifest written by this attempt is on file, a terminal status written before the attempt's launch, or a non-terminal status — and the live-run waiver admits any of them.
  • reckon/crew/promotion.py:3770: _unreviewed_refusal states the classification and the absent review as two statements. It previously wrote classified running because no complete independent review is stored, which reads as a claim that producing a review moves a classification the review does not move.

The 21 ids the coordinator must place before this can land

The guard is implemented as directed and this node's own cases pass, but the stricter admission is not a change whose fallout is confined to the guard: 21 tests assert the old admission by promoting a live-worker run that has delivered nothing. Repairing them is outside this node's write scope, so the node records blocked and names every id rather than editing them:

Two ways out, and the choice is the plan's rather than this node's. Widen the scope to those three files and update the fixtures to the shape a real run has — a recorded worker that has exited, a manifest written for the attempt, or an explicit --waive-live-run REASON — after which the guard lands unchanged. Or narrow the predicate to the resumed shape the defect actually describes, refusing when a manifest is on file but is not this attempt's while leaving a run with no manifest to the gates that already judge delivery; that keeps all 21 green but leaves the plain live-in-progress case unguarded, which is the case the direction explicitly asked to cover.
