A sweep spares every worktree a live pointer names, and acts on one run on request

What changed

reckon/crew/routing.py: the removal paths read a new _live_pointer_worktrees() — every worktree named by any live pointer, with no phase filter — in place of the phase-gated _live_worktree_claims() used before classification, before the apply loop's re-read and in the residue release's guard. A tree is a run's until promotion or discard removes the pointer that names it; an integration state, a terminal-looking phase or a dead worker process no longer licenses a sweep to reclaim it. garbage_collect also gains run_id, which resolves one run's worktree from its live pointer or its ledger row and refuses a path that is not a registered worktree, then confines classification, removal, pointer reaping and run-directory retention to that run. _pointer_claims_worktree and its phase-gated wrapper are unchanged for their other callers, whose reads ask whether a run is in flight rather than whether its tree is still its own.

reckon/cli.py: crew gc --run RUN_ID passes the confinement through, and refuses --run together with --scratch, which act on different targets.

reckon/crew/obligations.py: a worktree-held row's remedy is now reckon crew gc --repo <repo> --project <project> --run <run id> --apply — the run that holds the tree, never a repository-wide sweep, so answering one duty cannot reclaim a peer's work. A retained row that names no run id is skipped rather than widened.

The read-time existence check was already present at the base revision (_held_worktree_records filters path.is_dir()); it was verified rather than reimplemented, and the new test's third case asserts it against a tree removed after registration while git still lists the path.
