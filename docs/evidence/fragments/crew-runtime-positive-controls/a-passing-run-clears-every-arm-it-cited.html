Execution evidence

A passing run clears every arm it cites

A release reads the fields that declare an arm — the two log fields, the suite records' own log and basetemp, and an artifact path rather than the description beside it — removes every declared path under the node-local temp root after copying its logs into the run directory, and leaves a blocked or failed run's arms in place as the evidence a repair reads.

What the release does

The manifest is parsed with the shared manifest reader, and only the structured fields that carry a declared path are read: test_logs, negative_control_log, the log_path of baseline_suite and after_suite, the --basetemp inside those suites' own commands, and the artifact paths. An artifacts field is read differently by shape because its two shapes put the declaration in different places: given as a mapping, each key is the declared path and each value is a free-text description of what the run did with it, so only the keys are read; given as a list, each item is itself a path. That distinction is the same prose rule applied one level down — a description saying where a file came from, or naming the tree a peer session left behind, is not a declaration and never becomes a removal candidate. Prose fields are not read at all, so a landing line, a checkpoint or a follow-on naming another session's directory is never a candidate either, and a path merely mentioned on a shared node cannot cost a peer its tree.

A declared directory is removed when it resolves under the node-local temp root (the parent of the run's own scratch root), is not the run's own scratch subtree, does not contain or sit inside the repository, the worktree or the run directory, and is not declared by another run holding a live pointer — that other run's own record is read through the same field set. Only a run whose gate verdict passed is cleared: a blocked or failed run reports the withheld verdict on arms_withheld and keeps every arm. Declared logs inside a removal target are copied to <run>/cleared-arms/<arm-name>/<relative path> before the tree goes, so a gate log survives the arm it measured, and a log that cannot be copied holds its directory in place. The receipt carries arms_removed_paths (path and byte count per removal), arms_kept (path and reason) and arms_logs_copied, and all of it persists to the ledger through the existing release mapping.

Measure and controls

The focused file tests/test_a_passing_run_clears_its_arms.py synthesises a config home, a repository with a worktree, and a node-local temp root. Declared arms: a declared arm and a declared control tree are removed with their byte counts recorded (11 and 14), a basetemp declared by a second live run is kept naming that run, a declared tree outside the temp root is kept naming the temp-root bound, and both declared logs are readable under the run directory. Prose: a temp-root directory named only in checkpoint and follow_ons survives untouched and is not even listed as kept, while the run's declared arm is still removed. Artifact description: an artifacts mapping declares one arm in its key and describes it in its value, naming a different existing temp-root tree; the declared path in the key is removed and the described tree survives with its file intact. Failed gate: the same declaration promoted with gate=failed leaves both arms in place, records no removal and no copied log, and reports the withheld verdict.
