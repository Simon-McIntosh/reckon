A run whose worktree is gone can be promoted — evidence

A completed run's worktree is released, and its commits survive in the repository, which shares the object store. Promotion resolved every citation through the worktree path, so the first git call whose working directory no longer existed raised FileNotFoundError: the reproducing base run failed both new cases with FileNotFoundError: [Errno 2] No such file or directory: PosixPath('…/r-reclaimed-promotes-tree') from subprocess, and the run could not be promoted at all. The recorded workaround was to re-create the worktree at the run's head before promoting.

What changed

  • reckon/crew/promotion.py gains _run_commit_directory, which returns the run's worktree while it is a directory and its repository otherwise. _require_gate_evidence reads through it, so a reclaimed run's citations, the presented-versus-declared comparison and the unresolvable-citation refusal all resolve through the repository instead of going unmeasured.
  • _commit_canonical_id returns None for a root that is not a readable directory, so no promotion step invokes git in a directory that has been removed.
  • The reading that asks whether the run's own HEAD moved stays on the worktree: the repository's head belongs to a tree the run never worked in, and consulting it would refuse a truthful promotion on another tree's movement. With no worktree there is nothing to ask, so that guard stays silent as before.

The measure

The gate is the files that reach the change: tests/test_a_short_commit_list_is_reported.py and tests/test_control_gate_repairs.py name _require_gate_evidence and _commit_canonical_id directly, tests/test_crew_promotion_scope.py calls crew.complete over a detached worktree, and tests/test_a_vanished_worktree_reads_as_no_referent.py promotes runs whose worktree directory has been removed. Each arm ran with -n 8 --timeout=300, its own basetemp outside any repository, and its own log naming its revision, tree, command, module.__file__ and working directory.

  • Base arm (4efd4fdea, git archive extraction at $TMPDIR/base-tree): 43 passed in 55.42s, EXIT=0 (gate-base.log).
  • The defect at base, the new test file run against that extraction, with the same test file copied in: 2 failed in 6.90s, EXIT=1, both failures the FileNotFoundError above (gate-base-reproduction.log).
  • Head arm (17c205ecb, this worktree): 45 passed in 38.18s, EXIT=0 (gate-head.log) — the base’s 43 plus this node’s two, no added failure id.
  • Negative control (the declared mutation: the unreadable-root guard removed and the gate-evidence tree resolution reverted to the raw worktree path, so _commit_canonical_id runs git in the deleted worktree again): 2 failed in 6.54s, EXIT=1, the same two ids failing with FileNotFoundError against r-reclaimed-promotes-tree and r-reclaimed-cites-tree (negative-control.log). The worktree was restored from a copy immediately afterwards and git status is clean.
  • Lint and format: ruff check reports 3 findings in promotion.py at both base and head (all pre-existing, none on a changed line, none in the new test file), and ruff format --check --diff produces the same hunk content at base and head — no finding the base did not have.

What the new cases pin

  • test_a_reclaimed_run_promotes_and_registers_its_commit — the done-when: commit on a detached worktree, merge the commit, delete the worktree directory, and crew complete stores the row, registers the commit and removes the pointer.
  • test_a_reclaimed_run_cites_through_its_repository — a fabricated commit presented by a reclaimed run is still refused by value, which is the positive evidence that the citations are read through the repository rather than skipped as unmeasured.
