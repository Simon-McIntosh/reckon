Two dispatches of one node cannot race into one worktree

Two dispatches of one node for one session resolve to one worktree path, and both may read the live-pointer claims before either publishes its own, so a check-then-act guard sees nothing and both reach git worktree add on that path — each creation then losing directories the other is writing. Each dispatch now takes an exclusive claim file under the crew store, keyed by project, worktree identity and node id, immediately before the worktree is cut. The kernel's exclusive create decides the owner; the loser reads the holder's record — waiting briefly for its write to land — and refuses before touching the worktree, naming the run already in flight with its pid, registration time and claim path. The claim is released when the dispatch finishes, and after any refusal has unwound, so a failed launch leaves the node dispatchable again. The record also carries the holder's kernel process start time, so a claim left by a holder that is gone — or whose pid now belongs to a different process — is moved aside atomically by the next dispatch, which names the reclaimed holder on its result; a holder that is still alive still refuses. One dispatcher killed mid-flight therefore cannot block its node for everyone.

Five cases in tests/test_concurrent_dispatch_of_one_node.py run in a temporary repository and RECKON_HOME. The first holds both threads at a barrier on the live-claims read so neither sees the other's publication, holds the winner inside worktree creation, and lets the other run its whole admission against the held claim; it asserts exactly one worktree creation ran, exactly one dispatch launched, the refusal names the winner's run, and the claim is gone when the dispatch finishes. The second fails a launch after the claim is taken and asserts the retry launches. The remaining three cover reclamation: a claim left by a dead pid is reclaimed and the dispatch launches, naming the reclaimed holder; a claim whose pid now names a different process is reclaimed the same way; and a claim held by a live process still refuses, naming it, without touching the worktree.
