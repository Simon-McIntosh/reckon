A timed-out replay is not ok — evidence

A reckon crew verify-gate replay that outlives its bound measures nothing, and the report it returned did not say so in the field a caller reads first. rerun_gate_at_integrated_revision in reckon/crew/promotion.py built a report carrying ran: true, timed_out: true and exit_status: null, and the CLI publishes that payload as {"ok": True, **result}, so with no ok key in the result the JSON read "ok": true beside a null status. Its replay log stopped after the three header lines, which reads the same way as a gate that ran and printed nothing.

The reproduction, at the base revision

A replay against a scratch checkout with the stored gate replaced by sleep 300 under a 1 s bound, driven directly at 9443e674ade1ae410b7e31da46c1c00058658af2: the report carried no ok key at all, exit_status null, integrated_verdict not-run, and the log on disk held exactly its three header lines and no EXIT= record. The CLI merge then yields ok: true on a replay that was stopped by its bound.

One recorded detail does not reproduce at this revision, and it is reported rather than assumed. The section records the measured payload as having finding: null too. At the base revision of this node a timed-out replay already produced a finding naming the bound — the negative-control log below shows it — so the null finding was not reproduced here. The two facts this node repairs are the ok field and the silent log, and both reproduce.

The change

reckon/crew/promotion.py changes 78 added and 12 deleted lines, most of them the docstring and comment text stating the rule. rerun_gate_at_integrated_revision now measures the re-run's wall time around the subprocess call and sets ok from what came back: true only when an exit status was produced. A replay stopped by the bound returns ok: false, carries timed_out and replay_elapsed_seconds, and its finding — already produced because a base-green gate the merged tree does not re-confirm is a divergence — names the bound, which input set it, and the seconds it ran before it was stopped. Its log gains a # cut short: line carrying the same sentence, so the file states that it was stopped rather than ending on header lines. record_gate_rerun_at_integrated_revision passes ok through on its payload, which is what the CLI's {"ok": True, **result} merge was already written to honour; reckon/cli.py is outside this node's write scope and is unchanged.

A replay that completes is untouched: it keeps its own exit status and verdict, whatever that status is, and reports ok: true because a status was measured. A replay that never ran — a refused tree, a stored command that describes rather than executes — also produced no exit status, so it reports ok: false under the same rule; no test in the population asserted the old value there.
