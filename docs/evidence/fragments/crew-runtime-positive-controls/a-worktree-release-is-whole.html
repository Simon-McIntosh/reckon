A worktree release is whole or not at all

One helper, _release_worktree_whole, owns removal for every site. It first requires its path to be a disposable tree — a registered linked worktree inside a root this node manages, neither the checkout nor an ancestor of it — and refuses anything else with a reason, so a run record naming the repository can no longer have the repository renamed into trash. Then it renames the tree onto a same-filesystem trash directory, deletes that tree's own administrative directory to deregister it alone, and deletes the copy with no deadline. A global git worktree prune is deliberately not run, because it would also drop the registration of a peer tree whose directory vanished outside git — another session's record, which crew gc reports and leaves in place. A refusal means the path is not a disposable tree at all — not registered, or the repository root, an ancestor of it, or the main checkout — and it is reported as a withheld row rather than as a removal that happened. Where a tree sits is the caller's judgement rather than the helper's: crew gc narrows what it offers to the roots it manages, so a tree a caller legitimately owns is never withheld for its location.

Two negative controls redden as declared: dropping the repository-root and main-checkout guards has the pointer naming the repository rename the checkout into its own trash directory, and having garbage_collect ignore the returned released flag reports a withheld tree as removed while it stays on disk.
