check-manifest resolves every cited commit in the run's repository

What changed

reckon/crew/reports.py: audit_manifest now calls _commit_citation_findings, which asks the run's own git stores (the repository recorded on the pointer, then its worktree) about every commit-id shaped token carried by a commits entry, and reports each entry whose token no store can resolve — naming the value. An entry holding several space-separated revisions is read token by token, so the fleet's honest multi-revision entries are not refused for the shape of the line. A field whose first entry opens with a declared absence word (none — …) is a statement about the run, not a citation, and is left alone. A store that cannot answer (a pointer into a tree that is not a repository) leaves the check unarmed rather than reporting every citation as unresolvable. check-manifest passes the pointer's worktree and repository through unchanged, so the refusal reaches the worker while it still holds a turn.

The honest-population shapes the reader must accept were measured first on 401 delivered manifests: 497 entries carried one or more space-separated or comma-separated ids, 4 carried an id beside its subject, and 235 fields opened with an absence declaration; the parsed-first-entry absence rule agreed with the raw field on every one, so no raw-field reader was needed.
