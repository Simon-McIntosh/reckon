A commit that fails to resolve refuses the promotion rather than being dropped

What changed

_resolve_commit in reckon/crew/recovery_review_subject.py gains an opt-in strict mode. A git that ran out of its ten-second bound or could not be started raises a CrewError naming the revision and the tree, because there the instrument failed rather than the citation naming nothing; only a query that ran and reported the revision as naming no commit still answers the empty string. Every existing caller reduces the answer to a truth value or an optional id and does not opt in, so its behaviour is unchanged — in particular reports._commit_resolves_in and promotion_evidence._commit_canonical_id, which read the same function through their own wrappers.

_descendant_commit in reckon/crew/promotion_scope.py now resolves every citation strictly before it takes part in the comparison, and refuses the promotion naming the citation and the run's tree when one names no commit. That closes the defect the incident on 2026-10-23 exposed: an unresolved citation was dropped, the remaining citations agreed on an earlier tip, and the promotion recorded that tip as the revision the run reached. The two branches that returned a citation that had not resolved — the single-entry shortcut that returned the text as written, and the last-entry fallback for a list in which none resolved — are gone. A presentation whose citations have no single descendant is still refused as before.
