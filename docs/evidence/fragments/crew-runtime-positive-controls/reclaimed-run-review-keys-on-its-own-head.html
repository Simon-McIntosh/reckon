A reclaimed run's review keys on its own head

The review reflex keyed on the shared checkout's HEAD whenever a run's worktree had been reclaimed: the manifest cited its commits by nine-character id, the pointer carried no head, _record_carried_head accepted only full object ids, and _reviewed_run_head then fell through to the run's repository — the main checkout. Each review's own promotion commit moved that HEAD, so the next sweep found the stored review stale and dispatched another, five reviews in half an hour. The readings that close that loop: _record_carried_head resolves an abbreviated commits: entry of seven or more hex characters to its full commit id through the run's repository, which shares the object store its worktree wrote into, by running git rev-parse --verify on the entry with ^{commit} appended, and still skips an entry git cannot resolve unambiguously; _review_head_and_tree returns an empty head, not the repository HEAD, for a run whose worktree path no longer exists and whose record names no resolvable head, and the reflex composes no review for that run and records the missing head as the reason; and the head-move carry-forward reads the same resolution, so no branch borrows the checkout.

The scope decision, the updated pin, and the second fallback it surfaced

The first round reported blocked: the case test_a_reclaimed_worktree_with_no_recorded_head_does_not_accept_the_newest (from 08a8a7d2f, 2026-09-30) pinned both halves of the superseded reading at the evidence-selection surface — recovery._stored_review must return None with only an earlier-head record stored, and must return the record stored at the repository head — while this section's done-when forbids exactly that fallback, and the case sat outside this node's write scope. The coordinator upheld the reading and brought tests/test_rereview_keeps_its_lane.py into scope with a decision: keep the case's first assertion; make newest-record acceptance stop for an empty head in reckon/crew/recovery.py if that is what it appears to need; replace the second assertion with one asserting that an empty head accepts no record and composes no review. The empty-head rule now sits in select_review_for_head, the one selection the classifier, the promotion gate, the obligation producer and the disposition CLI all read, so no reader can hold a different answer; the case still calls _stored_review with an earlier-head record stored and then with a record at the checkout's head, and then composes: neither is accepted, nothing is composed, and the refusal names the missing head.

That compose assertion then surfaced a second reader of the fallback. review_head_move, the carry-forward decision, resolved the run's head through _reviewed_run_head over _review_tree's fallback tree — for a reclaimed run, the shared checkout — so a stored review selected as newest could be carried forward to the checkout's HEAD, the resolution this section forbids, reached in a branch that runs before the refusal. In the case it presented nondeterministically: the store's newest pick is by modification time, and two records written in quick succession can tie. The head now comes from _run_head_for_review, whose reclaimed branch reads the run's own record, so every reader resolves one head; a record naming no resolvable head moves nowhere and the dispatch refuses instead of carrying or composing.

The repair: the headless reading, shared by both readers

The claim above — that the empty-head rule sits in the one selection "the classifier, the promotion gate, the obligation producer and the disposition CLI all read" — did not hold for the obligation producer. _sub_floor_items_by_session asks _reviewed_tree for a tree, and a live run whose pointer names no readable worktree or repository gets none; the reader then passed the resulting empty head to select_review_for_head, which refuses an empty head, so no record was read at all and a stored review carrying a sub-floor dimension produced no disposition duty. The classifier kept the newest-record reading for the same shape through its own branch in _stored_review; the duty reader did not, so the one selection was not one.

The reading now lives in newest_review_for_headless_run: a reclaimed worktree is still refused, and every other headless record — one naming no worktree, or one whose tree resolves no head — reads the store's newest record for the run. The classifier takes it in its own branch and the duty reader takes it whenever no readable tree gives it a head, so a low dimension is no longer left undisposed over a head the pointer can no longer resolve.
