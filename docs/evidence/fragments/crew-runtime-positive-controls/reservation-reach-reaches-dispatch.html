A dispatch carries the reservation's reach — evidence

One unkeyed record holds the host's placement allocation, and its roster cap is summed over the placed live runs on the host. Three things disagreed with that fact. The dispatch route called ensure_reservation for its side effect and discarded the report, so a session that armed the reservation through a dispatch was never told the cap or which projects' placed runs it counts. The already-held read-back stated the job id and “started nothing” but named neither the cap nor the reach. And the reach statement counted every backend's placed live runs while the guard that refuses past the cap counted only the calling backend's, so with two placing backends the projects the statement named exceeded the population the refusal was taken over.

The change

In reckon/crew/placement.py a single seat selection, roster_occupants, now applies the phase filter and the memory-holding test once, and both the reach statement and the dispatch guard call it. The already-held result carries a detail stating the cap and the reach — the same sentence the arming hold states — and every hold result carries its roster_reach beside the record.

In reckon/crew/dispatch.py the backend-placement resolution keeps the ensure's result and writes the hold's job id, reason, detail and reach onto the run's payload under placement_reservation, on both the fresh-dispatch and the resume routes; the resume route carries the key into the pointer it persists. The concurrency ceiling hands the roster guard, and the reservation's cores bound, one host-wide population collected across every backend — the population the hold's reach counts with — while the lane bound stays the calling backend's own occupancy, because the lane is the backend's queue and the allocation is the host's. The refusal's “Occupying runs” list names the seats rather than the population handed in, so a reader is not shown every live run on the machine.

The direction chosen is to broaden the guard rather than narrow the reach: one host allocation admits every backend's placed workers as steps under --overlap, so a reach that counted one backend would under-count what is resident, and the dangerous direction is oversubscription. The reach statement's landed host-wide wording is unchanged.

The measure

Both arms ran with pytest -n 8 --timeout=300, each with its own basetemp under a run-named directory in /tmp, over the seven test files that reach the changed symbols (ensure_reservation, _held_result, _roster_reach, RESERVATION_ROSTER_LIMIT). Each log's first line names its revision and its last line is a bare EXIT=.

  • Base arm (bd621f63ce227fb31b8627fe9f4ac69d2115f90e, a git archive extraction under /tmp/r-20261003T105036595106-base, this node's test file copied in): 2 failed, 32 passed, EXIT=1 (gate-base.log in the run directory). Both failures are this node's two cases: the arming case dies on KeyError: 'placement_reservation' — the route discarded the report — and the two-backend case fails because the guard counted one backend's thirteen against a cap of twenty five and admitted the twenty sixth. The other five files pass at base.
  • Head arm (aae9a9e5f3711f8ae7a668ed969e8744a4473892, this worktree): 34 passed, EXIT=0 (gate-head.log). It adds no failure id, and the base arm's two ids are gone.
  • Negative control (the declared mutation — the dispatch route discards the ensure_reservation result again — applied to the head revision's working tree and reverted; the tree is clean at the committed revision): the arming case in tests/test_reservation_reach_reaches_dispatch.py fails on the missing payload key while the guard case passes — 1 failed, 1 passed, EXIT=1 (negative-control.log). The case discriminates the exact defect it exists to catch.
  • Ruff, in place at each revision over that revision's own paths: ruff check reports 7 findings at each — the same seven in dispatch.py, none added — and ruff format --check reports the same one file (dispatch.py) unformatted at each revision, with placement.py and the new test file formatted at head. No finding is added; a missing final newline in the new test file was caught and fixed before the commit.

Scope

The merged head's own gate belongs to the separate test node, as does any suite wide check; this fragment measures this node's two arms and its control alone. The lane bound and the login-memory bound keep their existing populations; only the reservation's roster and cores bounds moved to the host-wide set, which is the set the allocation actually admits.
