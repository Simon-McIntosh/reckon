Two intervals, not one: the request a crew makes and the launch it waits for

The defect. A delivered run cannot land until it is reviewed, and the request that starts the review is made by the crew. The stage receipts already dated each handoff, but nothing read them as the two intervals the measure turns on: the delivery to the request, and the request to the launch. Read as one figure, a late request and a slow launch are indistinguishable, and a run whose request was never made at all appears only as a review that is missing.

What landed. reckon/crew/recovery_review_dispatch.py reads the first instant of each of the four stages from the run's own receipts (review_stage_instants) and reports them as review_request_census: one row per delivered run with request_lag_seconds and launch_lag_seconds kept apart, the median and 90th percentile of each, and an obligations list holding every delivered run with no request after REVIEW_REQUEST_DEADLINE_SECONDS (600 s), each carrying the reason its own record gives — the reflex's recorded dispatch, the refusal its dispatch rule would return, or the session no armed follower serves. reckon/crew/resumption.py runs that reading on the pass that makes the requests and carries the obligations on the sweep's report, so a sweep that could not request a review says which run and why.

The harness. tests/test_a_delivered_run_is_reviewed_within_minutes.py builds the fixture repository and a temporary crew home, delivers a scoring run by the watcher's own writer, and holds a stand-in station tick in its refresh stage while the follower's sweep requests the review. It asserts the sweep's own report names the run as dispatched, the review's pointer exists, and the receipt's request instant is no later than 120 s after the delivery's — then reads the same instants back through the census. The second case withholds the request's precondition — its session has no armed follower — and reads no obligation at 599 s and one at 601 s whose reason names that session. A third case reads a recorded refusal as the reason rather than as no dispatch at all.

Gate. The node's three tests pass at the head (3 passed), and the armed suite arm — the node's test file beside the two importer files — is recorded in the manifest's after_suite field with its own command and revision.

Negative control. With the sweep's review pass made to wait for the tick — the pass gated on a marker the held tick never writes — the in-window case fails (FAILED tests/test_a_delivered_run_is_reviewed_within_minutes.py::test_a_delivered_run_is_requested_inside_the_window_while_a_tick_is_held, 1 failed, 2 passed, EXIT=1), so the case measures the request's independence rather than restating it. The log is named on the manifest's negative_control_log line.
