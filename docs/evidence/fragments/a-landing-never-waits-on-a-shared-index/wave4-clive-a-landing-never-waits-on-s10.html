A lander clears an index lock whose holder is proven gone

What changed. A git process killed while holding the checkout's .git/index.lock leaves the file behind, and every later crew merge then waits out its retries on a lock no live process will ever release. Measured that day: an empty lock dated 11:54:40 sat in the shared checkout for more than sixteen minutes with no git process on the host holding it, and no landing reached main until the file went.

reckon.crew.merge._run_waiting_out_a_held_index_lock now judges the lock when its retries run out, and clears it only when all three hold: the lock file is at least ten minutes old (INDEX_LOCK_STALE_SECONDS = 600), its size and mtime did not move across the whole retry window (a live writer grows or touches the file as it writes the index), and no process on this host holds it open, read from /proc/<pid>/fd. The checkout is written from other hosts too, so host-local absence cannot prove a holder is gone; age and stillness carry that judgement, because no git index operation holds an empty lock still for ten minutes. A cleared lock is retried once, and the landing's report carries an index_lock_cleared entry naming the lock, the removal and the age it had reached. A lock any process holds, one younger than the bound, or one that moved refuses as before, now with the lock's age in the message.

Measured

Every case builds a real repository with a bare origin and a reviewed head on a side commit, runs the landing, and reads the checkout, the lock and the report back. An eleven-minute-old lock no process holds is removed, the merge lands, and the record names the removal and an age of at least 600 s. The same lock held open by a live child process refuses and the file survives. A lock whose mtime moves by one second during the retries refuses and survives, and it is still eleven minutes old, so only the stillness condition refuses it. Locks at five minutes and at thirty seconds refuse and survive. A three-minute lock is removed when the caller sets a two-minute bound, which shows the bound is the landing's own parameter and the ten-minute figure is its default.

The base run of the first case's own scenario is what makes the case a defect rather than a description: at the base the same eleven-minute-old unheld lock refuses after eight attempts and nothing is written. The negative control removes the staleness judgement, and the live-holder case then fails because the lock the child holds is cleared rather than refused — the condition that distinguishes a dead holder from a live one is what the case measures.
