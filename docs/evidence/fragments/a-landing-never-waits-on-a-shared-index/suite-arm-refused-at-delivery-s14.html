A suite arm that is not an observation is refused while the worker still holds a pen

What changed. A worker that wrote baseline_suite and after_suite as prose passed crew check --manifest and was then refused at landing as red-suite: the manifest records no after_suite observation of the delivered head — hours later, when the only party left who could restructure the record was a coordinator. The manifest audit now refuses the same bytes at delivery, naming the field: after_suite must be an inline JSON object.

Where the declaration comes from. Nothing in a manifest says whether a suite pair was owed: a prose arm states no gate at all, and the arms of an armed run are indistinguishable from prose a run that owed nothing wrote to after_suite — and that second shape is still accepted, because it is a declaration rather than evidence. So the audit reads the declaration from the run's own live pointer, which dispatch writes after it resolves the flight's declared command over this node's scope; a manifest's own directory names its run, so the pointer is reachable from the file the audit already reads. _run_was_armed_a_suite answers armed when suite_command_resolved is present: a nil one is a declaration this node's scope emptied, which owes no pair, and a manifest whose pointer cannot be read or found is judged as it was before — the check never invents a declaration.

One reader. reports.suite_observation answers which values are observations at all, and both the check and the landing guard's _after_suite_arm ask it. The landing guard's own refusal text is unchanged: the two readers previously kept separate tests and reached opposite verdicts on the same bytes, which is what let the pair travel from the check to the lander.
