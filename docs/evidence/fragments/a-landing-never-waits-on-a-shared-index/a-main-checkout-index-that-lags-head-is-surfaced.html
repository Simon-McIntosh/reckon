A main checkout whose index stages a path HEAD still holds is surfaced

The obligations view now reads each project's registered main checkout for paths that git diff --cached --name-only --diff-filter=D HEAD lists, that the working tree still holds, and that the checkout does not ignore. Any such path is a notice naming the paths, HEAD, and the path-limited restoration git reset -q --; the reason it carries states that a plain git commit in that checkout would record the paths as deleted. The first read of each distinct lag — HEAD plus the path set — appends one line naming the instant, HEAD and the paths under the crew home (index-lag.log, with the seen keys in index-lag-seen.json), so a later occurrence can be matched to its writer. Reading the view never changes the index: every git call runs with GIT_OPTIONAL_LOCKS=0, so the read cannot even refresh the stat cache it reports on. An intended deletion and a path untracked and then ignored are both silent, because the file is gone in the first and the checkout ignores it in the second.

The row belongs to the project rather than to any run, so every session working that project reads the same notice, and it is a notice rather than a duty: the kind is declared in obligations.NON_BLOCKING_DUTY_KINDS and in the prompt hook's own copy of that vocabulary (reckon/hooks/coordinator_obligations.py, which cannot import the derivation on the snapshot's read path), so it is listed without holding a coordinator stop open. The two copies are held together by tests/test_queued_work_shows_where_held_work_shows.py::test_a_queued_run_never_holds_a_coordinator_stop_open.

The notice travels to the published snapshot as well as the derivation. The stop hook's prompt path reads a session's published payload and loads no derivation module, so a notice that stopped at the derivation would never reach it: the payload appends the derivation's own detector, and a case publishes a snapshot and reads it back through the hook's own vocabulary. Dropping that append leaves the snapshot case as the only failing one, which is how the case is known to be load-bearing rather than incidental. Reading is cached per main checkout against the index's stat identity and the head the checkout records in .git/HEAD and its ref, and a cached notice is dropped as soon as a path it names stops existing. Without it the station's steady-state case failed: a second tick with nothing moved ran one git subprocess the first tick had not. The head in the key is read from files rather than by running git, which is what keeps the key free; the notice's own head still comes from git rev-parse HEAD, and the test asserts it against the checkout's own answer rather than against the detector's.
