Summary

A promotion's checks now read the paths the run declared rather than every path in the checkout. The figure-twin check reads the commits a run cites; the commitless-work guard and the worktree audit read only the roots the run declared, as literal pathspecs.

Measure

  • Fixture: a promotion over 2,000 ledger rows and a checkout of 5,000 tracked files.
  • Ledger loader: called once (ledger.load_open).
  • Figure-twin check: the twin is refused, and the git calls it issues are commit-scoped; the base-to-head diff --name-only and ls-tree -r --name-only HEAD are gone.
  • Full promotion: no git status, ls-files, ls-tree or working-tree diff runs without a pathspec, counted by wrapping subprocess.run.
  • Commitless-work guard: a path the run declared and left uncommitted is still refused; a stray edit outside the declared roots is charged to whoever declared them.
  • Negative control: restoring the base-to-head check makes the run-commit test fail, naming those two calls.

Where the reads were

  • promotion_evidence._uncommitted_paths ran git status --porcelain over the tree for a --no-commit promotion; it now takes the declared roots as literal pathspecs.
  • routing._tree_state, reached from the worktree audit's snapshot and from _inspect_workspace, ran git status with no pathspec; both call sites now pass the run's declared roots. A run that declares no root keeps the unrestricted read, so an empty declaration is never reported as a clean tree.
