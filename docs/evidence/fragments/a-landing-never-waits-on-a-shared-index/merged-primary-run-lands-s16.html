A discharged refusal, and the clause it superseded

A merge repair tells a worker to merge the current shared branch into its worktree, and crew merge --head then runs the promotion's dry run against that head. The dry run filled the run's citations from base..HEAD in the run's own tree. Every commit the merge had brought in from the shared branch was inside that range, and the citation guard in reckon/crew/promotion_evidence.py refused a citation that was not a commit the run made beyond its base. A peer forks its branch before the run's base and lands it on the shared branch afterwards, so the shared branch reaches commits that do not descend from the run's base; the run's merge pulls them in, and the dry run refused with cites <sha>, which is not a commit this run made beyond its base. The dry run went past the guard only when the coordinator retyped the run's own commits with --commit, so the repair advice led straight to a refusal.

Reproduced at base revision 622ef4617d73 over a temporary primary checkout, a peer worktree, the run's worktree and a temporary crew home: the peer's branch forks before the run's base and lands on the shared branch, the run commits its own work and merges the shared branch in, and the dry run with no commit supplied reports would_promote: false with exactly that refusal, naming the peer's commit c1a0573194.

The change

The citations are no longer the plain base..HEAD range. reckon/crew/merge.py gains commits_between, which lists a range oldest first, follows one traversal, and leaves out the reachable commits of one revision named as excluding. The inference in reckon/crew/promotion.py asks it for the run's own line (--first-parent) less the history the shared branch reaches, so a run cites its own commit and its own merge of the shared branch and neither the commits that merge imported nor the shared branch's own commits.

The shared revision is read through recovery_classification._primary_branch_revision, the reader the classification sweep already uses, so a sweep over many live runs asks git once per checkout instead of once per row. A record naming no readable checkout answers empty and the inference falls back to the plain range, because an unreadable shared branch is not evidence that its commits belong to the run.

The range is memoised against the tree's own head, the base, the manifest's citations and the shared revision, under a key name that says what it now holds. A landing that moves the shared branch changes the key, so the citations are re-read rather than answered from a read taken before that landing.

The merge with the primary branch conflicted on this function, because the primary branch had landed its own answer to the same defect: cite the run's first-parent line, and accept any citation reachable from the run's head as a valid import rather than refusing it. Both changes keep their intent. The traversal is the primary branch's, and the reachability exclusion is kept beside it because it is the one that holds for a run whose branch was rebased onto the shared branch: there the shared branch's own commits sit on the run's first-parent line, and they are still not the run's work.

One clause of this section no longer holds, and the change did not cause it. The primary branch's guard now treats a commit reachable from the run's head as a valid citation, so a run citing a commit from another branch is not refused for it; the refusal that remains is for a commit outside the run's history at all. What the row credits is therefore decided by the inference, and the second case pins that: another branch's commit, merged into the run's worktree, is not cited as the run's own and the dry run does not refuse it either.

Measure

The cases are tests/test_a_run_that_merged_primary_lands.py. Both fail at the base revision and pass at the head. The first makes the recorded defect happen — a peer's branch forked before the run's base and landed on the shared branch, then merged into the run's worktree — and asserts both that the dry run promotes with no commit supplied and that the citations are exactly the run's own commit and its merge. The second merges an unrelated branch as well and asserts that branch's commit is not credited to the run.

Both arms run as PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q over the files this node's write scope resolves to on each arm's own tree, so the base arm's command drops the test file this node adds and names only tests/test_staged_write_inventory.py and tests/test_every_shared_home_lock_holds_across_nodes.py. At the base revision 622ef4617d73 that arm reports 58 passed, exit 0. At the repaired head 0cb2e73380 the arm adds this node's file and reports 60 passed, exit 0. Both logs open with the revision, the tree, the imported module path, the working directory and the literal command, and end with EXIT=.

The seventeen existing test files that import reckon.crew.merge, import reckon.crew.promotion_evidence or call complete_dry_run were run before the merge as well. They report four failures and nothing else, and each of those files was then run at the base revision 622ef4617d73, where the same four fail the same way: one in tests/test_complete_reports_every_refusal.py, three across tests/test_every_review_round_is_committed.py and tests/test_promotion_keeps_every_round.py, all of them the gate-log refusal for a cited log carrying no terminal EXIT= line.

The primary branch's own cases for this behaviour, tests/test_a_merged_primary_run_keeps_its_own_commits.py, report the same four failures at the primary revision 8bb015c640 as at the repaired head: 4 failed, 3 passed, exit 1, twenty-four refusals reading names no executable because the fixture records the gate command python -m pytest and this host has no python on PATH, only python3. The cause is the environment, not either revision.

The negative control applies the declared mutation — inferring the citations from base to head again — and both cases go red, 2 failed, exit 1, the first naming the shared branch's commit it now cites and the second naming the foreign branch's commit it now credits to the run. The cases measure the inference, not the harness around it.
