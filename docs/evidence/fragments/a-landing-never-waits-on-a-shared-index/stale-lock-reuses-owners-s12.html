One holder scan, one lock age, and every clearing named

What changed. The stale-lock check that §10 added brought its own copy of two facts the package already owned. It walked /proc/<pid>/fd itself, with matching rules that differed from reckon.crew.gc._processes_holding, and it asked one lock's age through a function the landing module and the promotion module both reached. The check now calls the one holder scan — extended to answer None when /proc cannot be read, so an unreadable process table is never read as proof that nobody holds a lock — and the one lock-age function, reckon.crew.merge._index_lock_age_seconds. git grep at head finds exactly one definition of each, asserted by the new test rather than by inspection.

Why the scan could not simply be imported. reckon.crew.gc imports reckon.crew.routing, which re-exports gc's names at the bottom of its own file, so a module-level import of the scan from the landing module would have gc read half-built. The name is resolved on first use and remembered under the landing module's own name; that also keeps the seam a caller patches when it wants to ask the stale-lock judgement a different question.

The record. The wait that clears a lock is shared by six callers, and only the landing passed a callback that names the removal, so a lock in a checkout other sessions commit to could vanish under a promotion, a rollback, or a state write with nothing written down. Every caller now passes one: the landing report keeps stale_index_lock_removed, staging, the landing commit, the plan-text projection and the rollback append a stale_index_lock_removed entry to the run's landing record, and a state write — which has no run record, only its commit — states the same line on stderr. The wording comes from one composer beside the wait, stale_index_lock_removal_line, so a reader looking for the age of a cleared lock has one shape to find wherever it happened.

Two callers whose files this node may not write. reckon.crew.promotion's review-record rollback and two cases in tests/test_rollback_asks_head.py call the rollback without a recorder. Making the callback required broke both, which the importer arm caught: TypeError: _restore_landing_writes() missing 1 required keyword-only argument: 'on_stale_removed'. The callback now defaults to the shared stderr note, so the clearing is still named and no caller has to know the recorder to keep working.
