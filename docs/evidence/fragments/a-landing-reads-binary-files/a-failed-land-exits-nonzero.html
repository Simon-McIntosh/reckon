A land step that fails exits non-zero

Landing

At base, a non-MergeError raised inside the crew complete --land merge step escaped the land call: the command printed no JSON report at all and the exception reached the caller. Reproduced at base e3c761311 with merge.land_merge patched to raise UnicodeDecodeError: exit code 1, an escaping UnicodeDecodeError, and an empty output stream — no steps.land entry, so the ledger read as landed while the change reached no reader.

One module-level function, _merge_land_refusal, now owns the mapping from a merge failure to a land refusal and its exit status: crew merge's handler and the promoted-land handler both call it and build no message of their own. A MergeError keeps its message verbatim, as at base; any other exception is refused as <Type>: <message>. The promoted-land refusal carries the reckon crew merge command that resumes the landing and exits 1.

Gate: the new test drives both commands through crew complete --land and crew merge against a temporary repository and asserts the failed land step, the named exception and the resume command. The negative control narrows the declared mutation back to MergeError and the first case escapes the land step, which is the red log the manifest names.
