The landing marker check reads a blob as bytes

Landing

The landing check reads each changed path by blob identity first. A path whose merged blob equals the head's survived without a content read, so a head adding a binary file lands instead of raising UnicodeDecodeError; content is read only when the blobs differ, and decoded only for a text path, so a differing binary path is refused as an altered binary file. One function, _read_path, owns the reading, and change_markers and surviving_change_refusals both call it. The landing's survived block now carries a judgements map, naming a binary path blob_identity rather than reporting an empty marker count.

The refusal names the path and says what was compared: a path whose merged blob differs from the head's and does not decode as text is refused with "the merge's content is not the head's and is not text, so the change could not be compared line by line". A text path whose merged copy is present but no longer carries the line the change introduced is refused by the marker comparison itself.
