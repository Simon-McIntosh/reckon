The synthesized record's plan-verdict was the reading of the whole ledger: fail as soon as any row carried a failed gate, pass only when every row passed, qualified otherwise. Measured on the-obligations-hook-reads-a-snapshot's synthesized record — 54 rows, 20 passed, 32 not-run and 2 failed, both failures classified pre-existing-failure and both merged — that reading reports fail for a plan whose every section landed, and because a review records its gate as not-run by design, no reviewed plan could ever read pass.

The repair reads the population a section attempt count uses. _overall_verdict in reckon/evidence.py now keeps ledger rows of the implement and test roles only, addresses each by reckon.crew.routing.section_record_id — the same role filter and section identity the section attempt count derives — lets each section's latest run decide (ordered by completion, then run id, as the record's own run tables are), and reports the worst reading across sections: pass; qualified for a not-run gate or a failure classified pre-existing-failure; fail for a failure with any other cause, a missing classification included. A failure a later pass repaired no longer holds its section, and a section whose latest run produced no gate evidence qualifies rather than fails.
