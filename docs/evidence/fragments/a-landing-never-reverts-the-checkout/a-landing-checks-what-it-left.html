A landing checks what it left at its paths and records every rollback

What changed

reckon/crew/promotion_scope.py _commit_landing_writes now brackets its commit with two checks and records every attempt. Before it stages, it reads git diff --cached --name-only and reports every staged path that undoes an earlier landing — the newest commit on HEAD that wrote the path carries a promote( or release( subject and the staged content is exactly that commit's parent's content, or the path is staged as deleted and the parent did not have it. Reversals are reported on landing_check.reversals, on the promotion's receipt, on stderr and in landing.json; they are never repaired, because restoring one would write to an index other sessions share. After the commit returns, each written path's blobs in HEAD, the index and the working tree are read once; a disagreement is reported on landing_check as ok: false with the path and its three blob ids, and rolls nothing back. The release outcome in reckon/crew/promotion_release.py _record_release_on_ledger now lands through the same _commit_landing_writes instead of repeating the stage/commit/ rollback sequence inline, so the file runs no git add or git commit of its own.

Every refusal and success appends one entry to landing.json in the run's directory (run_dir(run_id)), appended rather than overwritten. A refusal names its step (stage, commit or review-record — the last written at its raise site in reckon/crew/promotion.py), git's message, the HEAD the rollback read and the rollback's per-path report; a success names its commit, the HEAD before it and its landing_check. The append is best-effort.
