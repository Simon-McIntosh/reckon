A replacement producer appends no row for a run that has not moved

The first sweep of _publish_watch_transitions in reckon/crew/runs.py now appends no row for a live run whose state equals the state the stream last published for it, so a producer reload republishes only runs that moved (as a transition from the predecessor's state) or that the stream never named (as a baseline). The new test tests/test_a_reload_republishes_no_unmoved_run.py drives a first sweep over a stream naming one run complete and another working, keeps the first complete and moves the second, and finds no row for the first, a transition from working for the second and a baseline for a third unseen run: 155 passed at head against 154 at base (zero added failures), and the unchanged-run case is red under the base first sweep (1 failed, EXIT=1, test_a_reload_republishes_only_the_run_that_moved).
