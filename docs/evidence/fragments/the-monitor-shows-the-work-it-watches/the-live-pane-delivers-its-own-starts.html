The live pane delivers its own session's run starts

The row policy that delivers a pane's own session's run start was inert on the live follower. Two facts were missing on the way through. follower_row_path in reckon/crew_follow_commands.py built its PaneRowPath without own_session, so the policy could never tell which runs were the pane's own and held every start as observer context. And the transition written by _watch_transition in reckon/crew/recovery_watch.py carried neither the lane nor the time budget, so a start row could not name them even once delivered. The follower's own row path now carries its session, and the transition carries the run's resolved lane and its declared time budget.

Reproduced on the base revision before the repair: a real dispatched → working transition built by the producer's own builder, fed through follower_row_path(session=S), delivered 0 rows and the event carried neither lane nor time_budget. After the repair the same path delivers 1 row reading dispatched → working and naming run id, node, lane, model and time budget.
