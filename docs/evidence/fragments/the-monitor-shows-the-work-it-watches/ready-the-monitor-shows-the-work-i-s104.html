A held duty is settled against the run's current pointer

A session's duties are computed once per station tick and served until the next one, so any launch, resume or promotion that happens inside that window is invisible to the answer a coordinator reads. The only read-time settlement was obligation_snapshot.without_departed_run_duties, which dropped a row when its run's live pointer file was gone and nothing else. A delivered run that resumed, or a resumed run whose previous attempt left a halt behind, changes the pointer while the held row stands — so the stop hook went on refusing turns for work the pointer had already answered.

That settlement now reads two further facts from the run's current pointer, all of them pointer fields rather than derived state, so it still imports no derivation module and makes no ledger read. A review-ready or promotable-stale row is dropped once the pointer no longer reads complete, because a promotion is taken only on a delivered run. A blocked or review-missing row is dropped once the run has been resumed after the manifest that row was built from, which the pointer states as a working phase and a resume instant later than the manifest's own write.

The review duties are settled exactly as they already were: a review-missing or review-queued row is dropped when the run has released its pointer, or when that pointer records a review dispatched for the head the row names. The two readings above compose with that rule rather than replacing it, so a review-missing row is answered either by the dispatch main reads or by a resume after the manifest.

The hook's own account of the settlement, in recheck_worktree_held_rows (reckon/hooks/coordinator_obligations.py), names the two new readings beside the ones it already carried. Every other duty kind is left as it was: a row whose evidence is a ledger record, a worktree hold or nothing at all still keeps through any pointer state.

Evidence: tests/test_a_held_duty_is_settled_against_the_pointer.py passes seven cases. Each writes its rows into one stored snapshot and reads that same snapshot back after the fleet has moved, and each records the settled answer from before the move as its positive control. A review-missing row survives the sweep and is dropped once the run's pointer records a review dispatched for the row's head; it is kept when no review has been dispatched, when the attempt was held for a lane, or when the dispatch stands for an earlier head. A promotable-stale row and a blocked row built from a manifest are both dropped once the run's pointer reads working after a resume stamped later than that manifest's write, and a review-missing row is dropped by the same resume; a manifest written after the resume keeps the halt, so the comparison is against the manifest's own write rather than the resume alone. A promotable-stale row whose run still reads complete, and a promotion row whose pointer carries no phase at all, are both kept. The declared negative control — removing the promotion and resume readings from the settlement — fails exactly the promotion and resume cases (2 failed, 5 passed).
