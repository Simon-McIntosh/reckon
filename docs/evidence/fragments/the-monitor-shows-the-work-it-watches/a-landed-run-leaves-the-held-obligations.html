One pointer check settles a held answer before a coordinator reads it

A station computes each session's duties once per tick and keeps that answer until the next tick, so the list the obligations view and the prompt hook serve can be minutes old. A run that lands inside that window releases its live pointer, and the landing-refused duty derived from that pointer was settled at the moment the pointer went; the held answer kept naming it anyway, which reads as a failed landing in exactly the window a coordinator checks.

Deliverable. reckon/crew/obligation_snapshot.py gains live_pointer_path and without_departed_run_duties. The helper drops every duty whose run_id names a run with no pointer file under the crew home the module already resolves — one stat per run-keyed duty. A duty that names no run is kept, because its evidence is not a pointer. The summary is recomputed so the header counts the rows actually shown. Both readers call it: reckon/mcp_views.py in the obligations view's station branch, and reckon/hooks/coordinator_obligations.py in recheck_worktree_held_rows, through which every rendering of a held answer passes on both the prompt and the stop path. The derivation path (obligations.obligations) is untouched, and the hook still reaches no derivation module: the helper imports nothing new.
