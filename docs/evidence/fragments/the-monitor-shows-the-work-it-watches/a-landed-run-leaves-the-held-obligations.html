One pointer check settles a held answer before a coordinator reads it

A station computes each session's duties once per tick and keeps that answer until the next tick, so the list the obligations view and the prompt hook serve can be minutes old. A run that lands inside that window releases its live pointer, and the landing-refused duty derived from that pointer was settled at the moment the pointer went; the held answer kept naming it anyway, which reads as a failed landing in exactly the window a coordinator checks.

Deliverable. reckon/crew/obligation_snapshot.py gains live_pointer_path, LIVE_POINTER_DUTY_KINDS and without_departed_run_duties. The helper drops a duty whose kind is in that set and whose run_id names a run with no pointer file under the crew home the module already resolves — one stat per such duty. A duty of any other kind is kept, whatever its pointer state, because its evidence is a ledger record, a queue request or nothing at all. The summary is recomputed so the header counts the rows actually shown.

Design decision: the set is the pointer-evidenced kinds, not every run-keyed duty. Dropping every run-keyed duty whose run held no pointer emptied duties that were never pointer-evidenced: a worktree-held row is raised from the project's retained ledger records and a queued or stalled row from the queue and the admission verdicts, so a missing pointer says nothing about any of them, and a landed run whose worktree remains is a real duty. The set is therefore declared once, beside the helper, from the kinds reckon/crew/obligations.py derives from a live pointer: the classification kinds raised from _classified_rows (which classifies one live pointer each) including the review reassignment in _run_duty_row and the landing-refused read from a pointer's own admission_landing, plus review-dimension-sub-floor, run-held and plan-review-owed, each raised by a loop over _live_pointers. The module cannot import that derivation — the hook loads it by path precisely so no derivation module arrives with it — so the kinds are literals there, with the deriving sites cited above them.

Both readers call it: reckon/mcp_views.py in the obligations view's station branch, and reckon/hooks/coordinator_obligations.py in recheck_worktree_held_rows, through which every rendering of a held answer passes on both the prompt and the stop path. The derivation path (obligations.obligations) is untouched, and the hook still reaches no derivation module: the helper imports nothing new.

Gate. tests/test_a_landed_run_leaves_the_held_obligations.py: 5 passed. (a) A held station answer carrying a landing-refused duty for a run with no live pointer yields no such duty through both serve_crew_view("obligations") and the hook's injected checklist, and the checklist header reads 1 outstanding because one run-less duty remains; (b) the same answer with the pointer written keeps the duty, through both surfaces, and the header reads 2 outstanding; (c) a duty naming no run is kept; (d) a process that loads the snapshot module by path — as the hook does — and calls the helper holds reckon.crew.obligation_snapshot and none of reckon._backends, reckon._plan_html, reckon.ledger, and never reckon.crew; (e) a worktree-held duty for a run with no live pointer is kept while a landing-refused duty for the same run is dropped, so the narrowing is measured and not assumed.

Why the rule is narrowed. The general form — drop every run-keyed duty whose run holds no live pointer — was measured first, on an 11-file subset: 10 failed at the head against 2 at the base, eight of them added (test_the_obligations_view_answers_from_the_station, test_the_injected_list_is_the_snapshot_not_the_live_fleet, test_an_unreadable_record_prompts_without_holding_the_stop, test_a_fresh_snapshot_decides_the_stop, test_each_held_worktree_keeps_its_own_run_scoped_line, test_a_held_tree_is_still_offered, test_a_row_without_a_per_run_file_is_kept, test_a_skipped_record_is_named_in_the_prompt_checklist). Every one stages a duty that is real without a pointer: a retained-tree row, a review row, a skipped record. The narrowing drops only what a pointer alone evidences and leaves those rows standing, which is what the hook's own contract already says about a row whose record cannot be read — dropping it would turn a damaged ledger into a silent omission.
