A request that can never start reads as stuck on every surface that shows it

The drain view derived its own notion of a stuck request while the live view and the stop hook each reported the same request as an ordinary wait, so a wait that can never resolve looked like patience on two surfaces and like a stall on one. The verdict is now one function, runs.stuck_verdict, which judges a pointer from its own stamps and from the admission pass history: a wait whose ref names no project or run it can land in is wait-unresolvable; a request left admissible with lane room across three admission passes without launching is admissible-unlaunched; the drain view's existing one-hour case remains waiting. A request merely behind earlier ones on a launching lane is not stuck at all, so held-behind-earlier-request and unplaced leave the stuck set. The pass history is read once per view and handed to every row, so no two rows in one view judge from different readings of the log, and a pass that never mentions the request stops the count rather than counting toward it.

The drain view builds its stuck rows from that function, recovery_classification.classify_pointer carries its reason on the live row, and obligation_snapshot.apply_stuck_verdict writes the same reason onto the duty the stop hook formats, under a kind of its own so the checklist prints the line rather than counting it among waits nobody can shorten.

tests/test_every_surface_reads_one_stuck_verdict.py builds the drain view's existing stuck case, both new cases and one request that is merely waiting, then reads each from the drain view and the live view and through the hook's own formatter: the three name the same requests stuck for the same reason and the waiting request is stuck on none. Two further cases pin the boundaries — a request is not stuck after two admission passes and is stuck after three, and a request behind earlier ones is never stuck. Three cases pass. Two negative controls were applied and both fire: having the obligation row derive its own text fails the agreement case, and marking a request stuck on its first unlaunched pass fails the two-pass case.
