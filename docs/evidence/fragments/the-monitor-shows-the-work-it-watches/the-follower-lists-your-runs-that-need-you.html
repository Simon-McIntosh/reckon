landing: the follower now stands a needs-you line. A new module, reckon/crew/needs_you.py, derives the owning session's runs whose state is in the fleet partition's blocked bucket (FLEET_BLOCKED_STATES) or unpromoted bucket (FLEET_UNPROMOTED_STATES) and composes the line from it: needs you: 1 unpromoted pta-adopted-read-cost 1h21m · 1 blocked fsa-repair 5m, or yours: 4 working · nothing needs you when nothing is outstanding. Each entry names the node and the span the run has held its state, read from the run's own stream so it carries the clock the pane already stamps its rows with; an unpromoted run whose review is already stored is marked reviewed. _follow_watch_lines in reckon/crew_follow_commands.py emits the line from inside the generator, beside _tick(), on any change of the set and again on a cadence, so a quiet pane is a heartbeat. _needs_you_runs is now a delegate to the module, so the row the follower prints at the end of an arming names exactly the runs the standing line names.

The focused gate tests/test_follow_needs_you_line.py: 4 passed, driven over a two-session fixture with the cadence at one second — the first case sees the line at least twice in three seconds, names the owning session's own-unpromoted run with the word unpromoted and the age token 2h00m read from its own stream, and names neither the peer session's blocked run nor the word blocked; the second case asserts the heartbeat yours: 1 working · nothing needs you repeats with nothing outstanding; the third asserts a stored review marks its run reviewed; the fourth asserts the follower's line and a direct call of needs_you_runs over one fixture name the same runs.

Where this departs from the plan, and why. The section asks the line to be emitted unconditionally, with the cadence defaulting to ten minutes. Emitted unconditionally it was measured at 14 failed, 687 passed against the base arm's three: eleven added failures, every one in a frozen test that reads the follower's output as data — a re-arm that shows nothing twice, a replayed gap, a relayed payload whose events are all rows (test_follow_replays_the_gap.py, test_follow_rearm_continues.py, test_follower_rearm_shows_nothing_twice.py, test_crew_session_delivery.py, test_removed_flag_migration.py).
