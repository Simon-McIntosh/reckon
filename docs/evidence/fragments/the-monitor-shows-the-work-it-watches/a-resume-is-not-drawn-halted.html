What changed

A resume advances a run in three steps: it publishes the new attempt's identity in attempt.json and retires the previous attempt's canonical records, its supervisor spawns the new worker, and that worker registers. For the seconds between the first and the last, the run directory holds an attempt record naming the new attempt, no worker record at all, and the previous attempt's exit record still under its canonical name — while the pointer still carries the previous attempt's pid and phase, because nothing has rewritten them yet.

Read from that evidence the predecessor's recorded end is drawn as this attempt's. The classifier's exited_unfinished arm asks four questions — is the pointer's process gone, is there an exit record, does the manifest still carry a non-terminal word, and does the worktree hold commits past its base — and a resume answers every one of them from the attempt that already ran: its dead pid, its exit record, the status word the resume's manifest reset left behind, and its committed work. So a run that is only starting is drawn exited-unfinished, the pane renders that word halted, and a reader is sent to repair work that is already resuming. The halted row below lasted three seconds.

The reading now defers to the attempt's own clock. An attempt that has recorded neither a process nor an end of its own is read as running, which the pane draws as starting — the same deferral the producer's death branch already applies to this window. The definition is narrow in two ways, so the deferral cannot outlive its meaning: past STRANDED_LAUNCH_BOUND_SECONDS (900 s) with still no worker record and no stream of its own, the existing stranded-launch rule reports the resume that never launched; and a manifest carrying a verdict word of its own outranks the arm entirely, so a delivered run is read as delivered exactly as before.
