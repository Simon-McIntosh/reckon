A failed catalogue read is not an absent catalogue

The code identity folds the model catalogue, with the package and its dispatch scripts, into one content tree naming what a reloading process will run. The catalogue reader returned None both when HEAD carried no catalogue and when its git read failed — a timeout under load included. One failed read therefore yielded the catalogue-less tree, a valid-looking identity every follower and producer reloads onto, launching with no model named until the next good read moved the identity back and forced a second reload. A read that did not answer now leaves the identity unknown, and the reloader keeps the image it is running.

The gap: one failed read changed the code identity

_committed_catalogue_blob in reckon/checkout_trust.py asked git rev-parse --verify HEAD:docs/state/reckon/model-catalogue.yaml and returned None on any non-zero exit or on OSError/SubprocessError. _committed_reload_tree read that None as “a checkout with no catalogue” and returned the package-and-scripts tree. So a read that never answered was indistinguishable from git answering that the path is absent, and the identity computation produced a different tree either way. committed_reckon_tree folded its own failed read the same way.

The reproduction is the first case of the gate: a temporary repository whose HEAD carries the catalogue, with the catalogue read made to raise subprocess.TimeoutExpired. At the base code the identity comes back as the catalogue-less tree; at the delivered code it comes back as IDENTITY_UNKNOWN. The declared negative control below re-applies that folding and the first case fails again.

What changed

  • reckon/checkout_trust.py gains IDENTITY_UNKNOWN (the value "unknown", which collides with neither a 40-digit tree id nor a 64-digit content digest) and IdentityReadError, raised where a read could not be completed.
  • The catalogue is now read with git ls-tree HEAD -- <path>, which answers whether or not the path exists — exit zero naming the blob when present, exit zero naming nothing when absent, and non-zero only when it could not answer. So empty output is git's own statement of absence, and a non-zero exit or an unfinished read is raised rather than read as absence. committed_reckon_tree similarly raises on a read that did not complete, and only returns None when git ran and answered that there is no such tree.
  • _committed_reload_tree propagates an IdentityReadError rather than returning a partial tree, and source_code_identity catches it to report IDENTITY_UNKNOWN. A checkout that genuinely lacks the catalogue still yields the package-and-scripts tree, and a package outside Git is still hashed directly.
  • reckon/crew_follow_commands.py: _FollowerReloader.poll treats an unknown reading as no new identity — it returns before comparing, keeping its current image and its recorded stamp rather than materialising a tree from a partial read. The producer's reloader is the same class, so it gets the same treatment.

The gate

tests/test_a_failed_catalogue_read_is_not_an_absent_catalogue.py builds a temporary checkout carrying the package, its dispatch script and the catalogue. The first case makes the catalogue read raise TimeoutExpired and requires the identity to be IDENTITY_UNKNOWN, distinct from the catalogue-less tree. The second case removes the catalogue from HEAD and requires the package-and-scripts tree. The third requires a fully successful read to fold the catalogue in, confirmed by materialising the identity and finding the catalogue file inside the image. The fourth arms a reloader on a good stamp, then feeds it IDENTITY_UNKNOWN and requires it to keep its recorded stamp, to run its check without re-executing, and never to materialise a tree.
