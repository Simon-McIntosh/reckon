A follower that exits leaves a record of why

A follower used to end silently. Two followers named in the plan's evidence stopped renewing while their runs were still working, and nothing on disk said whether they had settled, been signalled or crashed. _FollowerRegistration.release in reckon/crew/follower_registration.py now writes an exit record beside the registration file when this follower held the claim, carrying the reason, the moment it ended, its pid and its host. The record is named for the follower's own pid (follower_exit_path), because the registration is one per project-and-session pair and a shared name would let two followers overwrite each other's end.

The reason is taken from the exception that unwinds the follower's loop, so it needs no opt-in at the exit site. The settle path leaves through sys.exit(SETTLED_EXIT_CODE) and reads settled; any other SystemExit reads its exit code; a crash reads the exception's type. A SIGTERM handler installed for the life of the registration raises its own exception type carrying the signal rather than a SystemExit, so a signal is never recorded as a deliberate exit code, and the signal's name wins wherever both could apply. The station-attached branch releases through the same registration from its own finally, so both delivery paths leave one record.

The new tests/test_a_follower_exit_leaves_a_record.py runs real follower images under a temporary crew home and asserts the record each one leaves. The head arm is 4 passed. The base arm, with the node's test carried into the base tree, is 4 failed: without the release write there is no record at all. Three negative controls each turn exactly the case they name red while the rest stay green: dropping the exit-record write fails all four cases including the settle case; dropping the station branch's delegation fails only the station case (1 failed, 3 passed); installing no SIGTERM handler fails only the signal case (1 failed, 3 passed). The 27 test files importing reckon.crew.follower_registration or reckon.crew_follow_commands are 148 passed at head, and the extracted base tree shows 142 passed and 2 failed, both reexec probes in a non-git tree, so the change adds no failure.
