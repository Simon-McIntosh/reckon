A row the follower replays on attach now begins with [replay]

On a pipe the follower marks every row it derives from what was already on disk when it attached, and leaves a transition written since the attach in the live format. reckon/crew_follow_commands.py carries REPLAY_PREFIX = "[replay] ", and the renderer applies it to a row flagged replay only when the output is not a terminal, so a terminal pane keeps its colour and its own scrollback distinction while a Monitor reading through grep can drop the replayed rows with one filter. crew follow --help states the prefix on the --project option.

The mark is set where the row is made, not where it is returned. The fleet replay hands each baseline and each pre-boundary transition to the ticker's row path, which may hold a row for its settle window and release it on a later flush, so marking the returned rows would leave a held row unmarked. Baseline rows and the transitions read up to the attach boundary are marked before path.feed, the gap rows a re-arm fills in are marked the same way, and the station subscriber's first poll — the other path that delivers what was already on disk — marks its backlog the same way. The renderer strips the flag before the row reaches note_delivered, the JSON form or the history burst.
