A follower stays while its session owes a review

live_work_populations in reckon/crew/station_subscriber.py is the one statement of the has-live-work rule: the station writes the reading a pane settles by from it on every tick, and a pane with no fresh reading asks the same function through population_has_live_work. It read every run in a terminal phase as drained, so a session whose last run had delivered settled its follower while the review that run owed was still uncomposed — and the reflex that composes that review lives inside that follower.

The rule now also counts a delivered run that still owes its review. The judgement is the obligations' own and nothing is re-derived here: the run's review duty is built by the obligations' own call, obligations._review_duty_item, and the pane is held exactly when that duty reads review-missing. Every exemption the duty carries is therefore carried here too — an evidence-only delivery reads review-ready because its review tier is none, a review already queued for the head reads its queued kind, and a delivered review the lane refused reads its own — so none of those holds a pane. Both settle paths read this one function, so a station reading and a fallback listing cannot disagree about which run holds a pane. One pass takes one snapshot of the live directory, one admission ordering and one grace per project, so the duty is asked of one read rather than one read per pointer.

The new tests/test_a_follower_stays_while_a_review_is_owed.py drives _check_settle through _follow_watch_lines on an injected clock, with a temporary crew home and a stubbed station, so each case measures the pane's own judgement rather than the predicate alone. Seven cases, 7 passed: a station reading written by record_live_work from live_work_populations holds the pane over a delivered run owing a review; the same follower with no station reading holds it through the fallback listing; each arm settles once the review is stored; a delivery naming no commit still holds the pane, because the obligations still call its review missing; a delivery whose tier is none settles; and a session with nothing live or owed settles.

Two negative controls, both reproduced. Restoring the terminal-only rule (dropping the delivered_run_owes_review call) turns the station-reading and fallback cases red — they settle over the review they owe — and leaves the tier-none case green. Counting every delivered run without the duty's own reading turns the tier-none case red, so the exemption is load-bearing.
