A run owing its coordinator keeps the pane

What changed. live_work_populations in reckon/crew/station_subscriber.py no longer settles a terminal run by the review it alone owes. terminal_run_duty_items derives a terminal run's own duties through the obligations module's own helpers and kind tables, and run_owes_its_coordinator holds the session live while any of those duties carries that run's own run_id. A promotion owed by a delivered review, a promotable run, a refused landing, an owed repair, a run that ended needs-help and a delivered run whose review tier is none therefore keep their coordinator's pane; a project-wide notice with an empty run_id keeps nothing. The one exemption is a review keyed on a head that will not resolve: no dispatch could satisfy it, so the obligations list it but the pane does not hold for it. A duty carrying no head at all is a promotion, which is actionable whatever the tree reads.

Measure. tests/test_a_run_owing_its_coordinator_keeps_the_pane.py — 9 passed, EXIT=0. The declared negative control, restoring the review-only gate, fails the keep-live cases that rule did not cover.
