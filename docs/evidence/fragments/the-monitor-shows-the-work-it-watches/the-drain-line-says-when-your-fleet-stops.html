The drain line says whether a session's fleet is drained

The row a follower leaves as its session's work drains said only when the work stopped. That is the moment a coordinator looks up from the pane, and the row gave it nothing to act on: a session whose last run had just been delivered unpromoted looked exactly like one that had nothing left to do. The row now keeps its existing text as a prefix — the session, the since word and the HH:MM stamp — and gains a tail saying either that the session's fleet is drained or how many of its runs still need the coordinator.

The count comes from the derivation the standing needs-you line already reads, composed in reckon/crew/needs_you.py as drain_tail from the same fleet partition and the same two state buckets. A second count composed at the call site would let the closing row and the line it closed disagree about what the session owed, which is the disagreement the shared derivation exists to prevent. The follower gains only the call, so its module stays inside the worker-window bound the token test holds.

tests/test_follow_drain_line.py reaches both drains through a run the pane saw working, because the settle is hinged on that sighting: a follower armed into an already quiet session keeps following, so a drain is only observable from live work. The case asserts the prefix is intact to the HH:MM stamp of the sighting, asserts the tail names exactly one run that needs the coordinator, and holds the row against a direct call of the derivation over the same fixture. It then makes the run live again and promotes it, and asserts a second row says the fleet is drained.

The gate ran the follower suite of 64 test files in both arms from scratch checkouts, pytest -n 8, with the session-host, follower-owner, follower-image and follower-source variables unset. Base ff7ec47c1: 4 failed, 570 passed. Head 67856d08b: 4 failed, 571 passed, the same four ids in both arms, so the node adds no failure and the extra pass is the new file. Withholding the tail from the settle row turns the first case red (exit 1) with the drained pane names no run that needs the coordinator and no failing id the head arm does not carry.
