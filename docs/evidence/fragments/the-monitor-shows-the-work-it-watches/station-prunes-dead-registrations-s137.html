The station prunes a released follower registration after a day

A released follower registration keeps its file, and nothing called follower_registration.sweep_released_followers, so each project's registry grew by one file per session that had ever followed it; the reset report listed 187 ended sessions as unreached. Station.tick now runs the sweep for every mounted project from its maintenance stage, never from a read path, with a one-day threshold and at most once an hour. The hourly bound is recorded as a station value, because the registry grows from sessions that have ended and no single session's fleet change announces that. The sweep's own non-blocking lock stays the only liveness check: a held lock keeps a registration whatever its file's age. Each removal prints one station-pruned-follower: line naming the project, session and path.

tests/test_the_station_prunes_dead_registrations.py builds one project with three registrations: a live one whose lock a second process holds and whose file is back-dated two days, a released one back-dated two days, and a released one an hour old. One tick removes only the two-day-old released registration and prints exactly one line naming it; the live registration survives on its lock alone. A second case adds a second two-day-old registration after the first tick, shows it surviving a tick thirty minutes later and removed by a tick two hours later, which is the hourly bound measured rather than asserted. A third case shows a released registration younger than a day surviving a pass that prunes.
