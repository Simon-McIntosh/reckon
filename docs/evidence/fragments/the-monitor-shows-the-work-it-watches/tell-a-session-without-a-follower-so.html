A departed session's snapshot is rewritten instead of left frozen

The station derives obligations only for sessions a follower delivers for, and _drop_absent removed a departed session's stored row without touching the per-session snapshot the producer had last written. A coordinator therefore kept reading a duty saying “the review reflex owns this dispatch” on exactly the session where no reflex would run again. station_obligations.refresh now collects the sessions its drop removes, and rewrites each one's obligation_snapshot.snapshot_path through the snapshot module's own writer on that tick. The rewritten document carries a follower block stating that no follower is delivering, and its duties are derived with the registration no longer live, so a review-missing row names the review dispatch command (reckon crew dispatch … --role review) rather than deferring to the reflex. The removed store row is what makes the rewrite one-off: a session already dropped has no row left to drop, so later ticks leave the file untouched. Commits 256a510e1a, ba6c2f5d49.
