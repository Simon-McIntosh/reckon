What changed

The follower's settle judgement ended on its first reading of an empty population, so an admission handover — the queued request's pointer deleted, the admitted run's worktree built, its pointer written only after that — read as the work being finished and the pane left before the admitted run started. The hold is now a bound on that handover: the pane settles only once its population has held no unfinished run for FOLLOWER_SETTLE_GRACE_SECONDS (120 s), replacing the one-second hold. A request still queued is unfinished work in its own right, so a session waiting its turn never settles the pane.

The real-follower case, and the seam it needed

An earlier head arm showed one failure this change did cause: test_the_real_follower_settles_when_the_host_advertises_it spawns a real follower child through crew follow, and that child took the production grace of 120 s while the case waits SETTLE_BOUND = 20.0 s. Shortening the grace for that child was the repair rather than raising the bound, because the two minutes is the deliverable and a bound that outran it would gut the assertion.

The grace therefore resolves per arming: an explicit settle_interval argument, then RECKON_FOLLOWER_SETTLE_GRACE, then the constant. The case names a short grace in the child environment it already builds, so its bound measures the follower rather than the grace. Production and every ordinary child take the constant unchanged, and a value the variable cannot parse falls back to it rather than stopping the follower — a follower that refused to run would take the pane with it.
