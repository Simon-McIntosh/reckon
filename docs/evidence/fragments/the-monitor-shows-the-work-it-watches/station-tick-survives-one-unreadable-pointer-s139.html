One pointer that cannot be classified costs its own row, not the tick

On 14 November the station died on a single pointer. A blocked CLI run whose backend command was srun reached _stream_session through classify_pointer → _blocked_session_resolution → resolve_session, where dialect_for raised BackendError because srun has no launch translation. Nothing between the resolver and run_station isolated that one row, so the pass ended for every other live pointer and took the process with it. The reproduction in the assigned tree printed the escape verbatim from classify_tick: reckon._worker_fence.BackendError: no launch translation for command 'srun'; reckon can translate: claude, clive, codex, omp.

Two repairs, measured as separate facts. reckon/crew/station_store.py classifies each pointer under its own guard in classify_tick: a row whose classification raises is recorded with state and classification unreadable and a detail naming the exception's type and message, a line naming the run is written to the station's stderr, and the pass continues. Nothing is stored for that row, so the next tick classifies it again rather than serving the error from the store. reckon/crew/resumption.py adds BackendError to the exceptions _stream_session already treats as an unreadable stream, so an untranslatable command answers an empty session and the resolver falls through to the ledger.

Gate. tests/test_one_unreadable_pointer_never_stops_the_tick.py on a temporary crew home, over three live pointers: two ordinary working runs and one blocked CLI pointer whose backend command is srun. The guard case injects the incident's own BackendError at _stream_session — the seam the incident's call path named, because the sibling repair removes the natural trigger — and reads two rows classified working and the srun row unreadable naming BackendError, with no exception escaping; the log case reads the same verdicts plus the station-tick-unreadable: r-srun: BackendError line. The resolver case calls the unpatched _stream_session on the real srun pointer and reads "" with no exception, and the unpatched-tick case reads all three rows with srun at blocked. 4 passed. At the base revision 53c4c5238e the same four cases all fail with the exception escaping (4 failed, EXIT=1), log logs/base-revision-new-test.log.
