A session's follower pane settles when no work is live

A follower started by a settle-aware session host prints one idle line, no live work in <session> since HH:MM, and leaves once the project carries no live work. The host stays alive, keeps the settled pair retired, and starts one fresh child on the pair's next request. The judgement is _population_has_live_work's, sampled on the follower's own tick.

Both mixed host/child pairs hold. A host that sets no advertisement never starts a child that settles, so an old host cannot read a settle as a crash; a host that does understands a retirement only from the child's settle exit status, so any other exit is still restarted on the backoff. A request that arrives while a child runs re-arms the pair on the settle, which covers the dispatch window where the follower is armed before its run's pointer exists.

Eleven cases pass in tests/test_a_pane_settles_when_no_work_is_live.py: the section's cases over a temporary host state directory — including an observed peer's live run keeping the pane open against an unobserved peer's, which does not — plus a case for each mixed pair. The existing session-host and follower tests show no added failure against the base revision. The declared negative control — restart a settled child immediately as the current backoff does — turns the settle case red at EXIT=1, logged under the run directory.
