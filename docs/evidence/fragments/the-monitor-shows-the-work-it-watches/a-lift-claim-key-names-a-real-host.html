A pane's lift-claim key names a real host and its node

§51 keyed a pane's lift claim on RECKON_FOLLOWER_OWNER when that variable was present. Two defects followed. A follower's own reloader writes that variable into its replacement image unconditionally (from follower_owner(), which always returns a pair), so an unhosted follower took a host key it had no host for after its first reload. And the key — host-<pid>-<start> — named no node, so a sweep could not tell a host that died here from one alive on another node sharing the home. lift_claim_key in reckon/crew_follow_commands.py now decides hosting from RECKON_SESSION_HOST_SETTLE, which only SessionHost._spawn stamps and a reload carries through unchanged; a hosted key names the node as host-<node>-<pid>-<start>, and an unhosted follower keeps the per-session key before and after any number of reloads.

Measured by tests/test_a_lift_claim_key_names_a_real_host.py (3 cases) plus §51's tests/test_a_pane_draws_a_lift_once_per_host.py: 7 passed. A reloaded follower carrying RECKON_FOLLOWER_OWNER but no settle variable keys on its session; a hosted key reads host-<node>-2226630-…; §51's two-session case still draws one grant row and one end row. The negative control decides hosting by the owner variable's presence again, and the unhosted case fails with EXIT=1.
