A project's watch producer survives when linger is unavailable

A producer armed on a host without linger runs as a plain background process under the arming supervisor. Its seat is a renewable lease, and when nothing renewed that lease the producer ended with status 0 — the value the supervisor reads as a deliberate stop — so it stayed gone until someone armed it by hand.

What changed

PathChange
reckon/crew/runs.py A producer that still holds its lease but can no longer renew it, or whose own registration nobody renewed for a full interval while runs are live (watch_lease_lapsed, read through the one predicate watch_lease_remaining), now leaves from renew_watch_host_lease with WATCH_SEAT_LOST_EXIT and writes reckon crew watch stopped: seat lost for <project> to the project's watch log. The same lapse behind no live run is the ordinary drain: exit 0, so a quiet project is not restarted once per interval.
reckon/crew/recovery_watch.py Every lapse the producer sees between polls now asks the same verdict, including the one taken on entry to its wait, which used to end the ticker with exit 0. The wait's lease arithmetic delegates to the one predicate in runs rather than re-deriving it.
reckon/crew/dispatch_watch.py The arming supervisor restarts a producer that exits with that status, and declares the seat free first (watch_seat_held_elsewhere): a seat another live producer took at renewal time is not contested, where a foreign host's record is taken at its word and this host's must name a process still running. Exit 0 still means a deliberate stop and is never restarted.
tests/test_a_producer_survives_without_linger.py New: six cases, every one started through the same supervised launch — a lapsed lease with work still live is restarted; a lapse seen inside the wait is restarted; a misplaced-seat release stays stopped; a claim refused by a live holder stays stopped; a seat taken at renewal stays stopped; a lapse with no live run left starts nothing more.
tests/test_a_crashed_producer_is_restarted.py The lapsed-lease case, which pinned the old not-restarted behaviour, becomes a restart case; the crash-limit fixture's steady-run bound is raised above the interpreter's start-up, which the supervisor counts from the spawn.

Why the exit status carries the reason

The supervisor can only see a child's exit status, and three different stops have to be told apart: a deliberate stop (0), a crash (a status it counts against the restart limit), and a seat this producer lost rather than gave up. Only the producer knows which happened, so the reason travels as its exit status; the supervisor then asks whether anyone else holds the seat before starting it again.

Evidence

The gate is the two node test files, run on all_debug one arm at a time, with the base arm at a5764282bdeeeda4d3f26910564f212bcfcacc12's own tree. The negative control re-treats the lost seat as a deliberate stop, after which the first case ends with no producer running.
