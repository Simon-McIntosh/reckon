A refused queued launch keeps its row, and the refusal is what the pane names

Where the row came from. The admission pass launches a queued request by releasing its live pointer and writing the attempt, then writes the request back as queued when the launch refuses. A follower reads the pointer leaving and returning as a departure. The word it generates is _departure_word in reckon/crew/recovery_watch.py, whose last line at the base blob 8e200ea58c is return "withdrawn" (reckon/crew/recovery_watch.py:2009): a ledger that resolves and records no row leaves the request the bare withdrawal, and fleet_transitions publishes it as queued → withdrawn. The refusal itself was already composed by the classifier — detail = f"the queued launch was refused: {text}" at reckon/crew/recovery_classification.py:334 — and put on the snapshot as detail with the remedy in next_action. The pane never printed it, because a queued row is not a carried word: stream_carries carries the transition-only rows, so the one actionable fact on the row was invisible.

The observed incident is in the stream itself: 2026-10-21T23:44:36Z r-20261021T232042616739-a-limit-reset-is-one-record queued → withdrawn, then 23:45:05Z None → dispatched and 23:45:10Z dispatched → queued with the router's slot detail. The request kept its place throughout. The literal dropped row that incident drew no longer reproduces at the base revision: the withdrawal is suppressed before it reaches the landing judgement, by a rule that landed three days later. What remained at base is the deliverable here — the refusal was never named on the pane, so a coordinator saw a request reappear with no account of why its launch had failed.

What changed, all in reckon/crew/ticker.py. queued_refusal reads the classifier's clause off a queued row and appends the remedy from next_action; RowPolicy._feed decides it before any hold or round-trip rule, so the row is the request's own and the word the pane holds for it does not move. Each refusal the request has not shown before prints once and is remembered per run; the same refusal again prints nothing, because the remedy has already been given. The refusal row also cancels a departure hold the launch attempt left standing, so the attempt's released pointer adds no second row. stream_carries carries the marked row, Ticker._refusal_line renders it, and the request that really is discarded is explicitly kept as news so it still draws dropped.
