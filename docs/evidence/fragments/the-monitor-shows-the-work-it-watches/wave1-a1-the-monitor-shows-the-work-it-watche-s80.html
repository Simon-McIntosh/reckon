Where the row came from. The admission pass launches a queued request by releasing its live pointer and writing the attempt, then writes the request back as queued when the launch refuses. A follower reads the pointer leaving and returning as a departure. The word it generates is _departure_word in reckon/crew/recovery_watch.py, whose last line at the base blob 8e200ea58c is return "withdrawn" (reckon/crew/recovery_watch.py:2009): a ledger that resolves and records no row leaves the request the bare withdrawal, and fleet_transitions publishes it as queued → withdrawn. The refusal itself was already composed by the classifier — detail = f"the queued launch was refused: {text}" at reckon/crew/recovery_classification.py:334 — and put on the snapshot as detail with the remedy in next_action. The pane never printed it, because a queued row is not a carried word: stream_carries carries the transition-only rows, so the one actionable fact on the row was invisible.

What changed. In reckon/crew/ticker.py, queued_refusal reads the classifier's clause off a queued row and appends the remedy from next_action; RowPolicy._feed decides it before any hold or round-trip rule, so the row is the request's own and the word the pane holds for it does not move. Each refusal the request has not shown before prints once, held against the run id; the same refusal again prints nothing, because the remedy has already been given. The refusal row also cancels a departure hold the launch attempt left standing, so the attempt's released pointer adds no second row. stream_carries carries the marked row, Ticker._refusal_line renders it through the shared clause-row helper that _submission_line and _lift_line also use, and the request that really is discarded is explicitly kept as news so it still draws dropped. In reckon/crew/queue_admission.py the re-queue's write is the named _requeued_request, which is the line stating that a refused attempt goes back to the queue under the id the request was dispatched with: that is what makes the run id the request's identity for this reader, and a test pins it there rather than leaving it to a docstring.
