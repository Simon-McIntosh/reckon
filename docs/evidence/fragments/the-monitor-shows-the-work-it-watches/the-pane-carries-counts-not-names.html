What changed

The follower pane stops printing three lines that named runs instead of counting them, measured in one pane as 34 stale-heartbeat sentences between 03:43 and 05:52 while the station they named was running:

  • the settle row's needs you: <names> tail. The row is still emitted, because the follower's host retires the child on the event rather than on its text, and its line is now empty (_follower_settle_event in reckon/crew_follow_commands.py);
  • the lifetime end row's N runs need you: <run> (<node>) tail. The row keeps its re-arm instruction, and the event no longer carries a needs_you payload field;
  • the station subscriber's stale-heartbeat line (STATION_STALE_EVENT, stale_heartbeat_line, StationSubscriber.stale_line in reckon/crew/station_subscriber.py). The liveness verdict stays with the obligations hook, which is where a coordinator acts on it.

The composition helpers that served only those tails are removed with them: needs_you_line, drain_tail, needs_you_signature, _entry and DEFAULT_REMIND_SECONDS in reckon/crew/needs_you.py; the follower's _needs_you_runs and its re-export in reckon/cli.py; and the --remind option, whose only promise was re-emitting a line the pane no longer prints.

The derivation is untouched. needs_you_rows and needs_you_runs still name every run the owning session owes, with its age, its kind and the stored-review mark, and the obligations view still carries each run's next_command — so the pane loses the names and the reader keeps them in exactly one place.

skills/reckon-build/SKILL.md now says where a coordinator reads the two: counts on the rows, names and commands from reckon crew view obligations.
