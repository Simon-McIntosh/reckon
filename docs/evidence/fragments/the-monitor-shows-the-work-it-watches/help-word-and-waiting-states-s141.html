The pane says help where it needs you, and waiting where the run lifts itself

What changed. The needs you bucket held two situations: runs that cannot move until the coordinator acts, and runs that move on their own once other work finishes. "you" did not say who, so the bucket read as work for a reader nothing was waiting on. The bucket is now help, counted under h, and blocked-upstream, held, interrupted and ready moved to waiting, counted under q. SUPERSEDED_PANE_WORDS reads a stored needs you — and the older halted — as help, so a pane restored from history draws the new word and a record whose only change is the word draws no row. CARRIED_PANE_WORDS carries help. No word set in ticker.py names needs you except the superseded mapping.

The fleet partition moved with it. recovery_watch.WAITING_STATES gained the same four states, so a row's word and a counter's letter name the same population: a held run now draws → waiting and counts under q instead of drawing → help beside a q figure that already counted it. skills/reckon-build/SKILL.md names help and h and states which four states waiting holds.

Gate. tests/test_a_run_that_needs_help_reads_help.py, driven through the producer's own partition and transition builder so every figure asserted is a figure a pane receives: a blocked run draws → help and counts 1h; a blocked-upstream run and a held run each draw → waiting and count 1q, not 1h; a stored needs you word restores as help, and so does halted; and every state in FLEET_BLOCKED_STATES draws → help, with no word the pane emits or counts still naming the old one. Against the base tree with only the test added: 4 failed, EXIT=1 — the first three on the old word and letter the pane drew, the fourth on KeyError: 'help'.

Negative control. SUPERSEDED_PANE_WORDS left empty fails exactly the restore case, test_a_stored_needs_you_word_restores_as_help (assert '' == 'help'), with the other three passing: 1 failed, 3 passed, EXIT=1. A second control reverts the commit that renamed the test literals and fails all six modules that pinned the word — 9 failed, 23 passed, EXIT=1 — so each of those six assertions is load-bearing rather than passing by itself.

What the move costs. A run a review interrupted now reads waiting, and waiting is not a carried word, so the pane prints neither the halt nor the resume that follows it: START_KINDS pairs a stop state with working by reading the help bucket, so interrupted → working is no longer a launch. In tests/test_a_shown_delivery_is_not_drawn_again_after_its_review_starts.py one sequence drew seven rows before this change and four after, and the case that guards a resumed attempt's launch and delivery now halts on blocked, so it still measures a carried halt. Recorded rather than repaired: the plan settles the four states in waiting, and whether a review-interrupted run should still announce its resume.
