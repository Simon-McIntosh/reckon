A discarded run leaves the needs-you set, the obligations list and the pane

The test drives the chain a coordinator actually runs: it spawns a process carrying the run id, records a run whose manifest reads blocked and whose recorded supervisor has already exited, asserts the run present in the needs-you set, the obligations list, the blocked count and the halt row, then calls the real crew terminate and the real crew discard. Before the discard, this is the one direct instrument: the run is blocked — present in every list, with 1n in the halt row.

Gate. tests/test_a_discarded_run_is_never_listed_as_blocked.py. The fixture is a blocked run whose recorded pid names a supervisor that has exited while a leftover process still carries the run id: a proven-alive process would defer the blocked verdict to running, which is why the shape matters. The stop is asserted to end the leftover (target_pids carries it) and to draw no transition at all — fleet_transitions over the before and after-stop snapshots folds to []. The discard then removes the pointer and records its marker, and the run is absent from the needs-you set, from obligations() and from recovery.recover() with a blocked count of 0; its departure reads discarded from a previous word in NEEDS_ACTION, and the pane draws → dropped with 0n , never → needs you.

Arms. Both arms are git checkouts under the run's scratch directory, with the four follower variables unset, run in place on the fleet node with pytest -n 8. The base tree is revision 49431529bc carrying this node's test file, so the same reading runs against the modules at the base revision: base 1 passed, EXIT=0; head 1 passed, EXIT=0. The behaviour predates the test, and the test adds no failure, which is what a node that adds a missing test to a working guard reports. Logs under the run directory: arms/base.log, arms/head.log.

Negative control. The control classifies the stopped run before reading its discard record: _departure_word is stripped of its discard-record arm, so the reader words the departure from the block the stop left. The test goes red — 1 failed, EXIT=1 — on assert state == "discarded", the departure reading withdrawn against discarded expected. Every pre-discard classification in the same run still reads blocked, which is the control's statement: only the discard record moves the run off the block it stopped in. Log: arms/negative_control.log.

Lint. ruff check and ruff format --check on the test path add no findings.
