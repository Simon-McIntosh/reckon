A standing lift survives the follower's own reload

The row policy's set of lift groups drawn as in force now travels with the follower across its own in-place reload and its re-arm. RowPolicy and PaneRowPath in reckon/crew/ticker.py take the groups in and expose them; reckon/crew/follow_checkpoint.py carries them in the reader checkpoint (write/read, key omitted when empty so the recorded document is unchanged) and rebuilds them from stored history (seed_lift_groups, with the group recorded on each lift row); reckon/crew_follow_commands.py restores them in both arms — the in-place reload from the carried checkpoint through _follow_resume_plan and path.reseed, the re-arm from follow_checkpoint.seed_lift_groups. tests/test_a_standing_lift_survives_a_follower_reload.py passes 9/9: the in-place reload and the re-arm are each driven through the follower's own arming (cli._follow_watch_lines), with the producer's baseline row appended while it waits, so the hold is measured on a row that really reached the pane — the companion case that carries no memory proves the harness live by drawing it; a reload holding the drawn groups draws no row for the producer's re-arm baseline, a reload with none still draws it, the re-arm rebuilds the groups from stored history, a first attach still draws the standing lift once, and a grant and an end after the reload each draw one row.
