A session host never waits in a read it cannot leave

A FIFO can have more than one reader, and select reporting it readable does not reserve those bytes for the reader that asked. When another reader sharing the request FIFO took them first, the host's blocking os.read waited for input that had already gone: the host stopped handling requests and never reached the stop path, so neither a dispatch request nor a signal freed it. SessionHost.supervise now sets the request descriptor non-blocking and treats BlockingIOError as an empty pass, falling through to the owner check and the tick, so a pass whose bytes went elsewhere still finishes and still supervises.

Two further properties keep one host in charge of its own artefacts. A host takes an advisory lock named for its owner pair (beside its census record, held open for the life of the process): a second host started for the same pair returns ALREADY_RUNNING_EXIT_CODE, states on stderr that another host already serves the pair, writes no census, and leaves the first host's FIFO untouched, where before it would have read the same FIFO beside the first and removed it at its own stop. And the FIFO removed at stop is now decided by device and inode recorded when the host took the descriptor, not by path: a path that now names a later session's FIFO is left alone.

Gate on tests/test_a_session_host_never_blocks_in_its_read.py, one arm, 4 passed, EXIT=0. Case (a) races two real readers on one FIFO: the other reader takes the request bytes after select reports the FIFO readable, the host's read finds nothing, and the pass reaches exactly one tick inside two 0.1 s poll intervals; the stolen bytes are asserted equal to the request, so the reader is shown to have taken them rather than the host having silently handled them. Case (b) puts the host in that same state, then makes the stop request a signal handler makes — the flag plus a wake-pipe write — and the supervise returns within two poll intervals of the write. Case (c) holds the pair's lock with one host and starts a second through the entry point: it returns the already-running status, names the reason on stderr, writes no census, and the FIFO survives with its identity. Case (d) replaces the host's FIFO at its own path and stops it, and the replacement survives; a second host whose own FIFO is intact is stopped in the same case and its FIFO is removed, so the removal instrument is shown to work rather than merely to be quiet.

Declared negative control: restore the blocking read and drop the inode check. 3 failed, 1 passed, EXIT=1.
