A refused review dispatch names the dispose command, not a window that will pass

A run whose every sweep the reflex refused was still handed "the review reflex owns this dispatch … no manual dispatch is needed", because the duty read only that a follower was armed. The refusal the dispatch wrote on the run's own pointer was never read, so the coordinator waited on a promise its own record contradicted.

The writer. _open_review_refusal (reckon/crew/recovery_review_dispatch.py) now records the head the run carries and the finding indices the refusal named, through _record_review_dispatch's new reviewed_head and findings arguments. Before this, the entry carried head: None, so no reader could tell a refusal made against the current revision from one made against a revision the run had left.

The reader. _refusal_speaks_for_revision (reckon/crew/obligations.py) now counts a record only when it names a head the run still carries. The age anchor it used to fall back to is gone, and _review_head_covers — which treats an unnamed side as matching — is deliberately not the rule: a record that names no head covers no revision, which is what every entry written before this change looks like. When a refusal does speak for the current head, the duty takes the kind review-dispatch-refused (REVIEW_DISPATCH_REFUSED_DUTY_KIND), a kind of its own — review-refused already names a live review whose stored record the store refused — carries the refusal's recorded reason, and prints the reckon crew dispose command that lifts the finding. The command is composed from the stored record's finding when that record can still be read, and otherwise from the indices the refusal recorded, so a refusal that outlives its store still names an answer.

Evidence. tests/test_a_refused_reflex_review_names_its_remedy.py drives the obligations derivation on a synthesised repository, a temporary crew home and an armed follower, five cases: a refusal recorded for the current head raises the refused-dispatch duty with a reckon crew dispose action and no review_owner; the same refusal recorded for an earlier head leaves the reflex's own text; a run with nothing recorded reads as the reflex owning the dispatch; a real dispatch_review_for_run refusal over an undisposed blocking finding records the run's current head and findings: [0] and the derivation then reads the duty from it; and a stored refusal with no head covers no revision.

Negative control. Declared string: the negative control ignores the recorded dispatch, and the first case fails. Applied by making _review_dispatch_refusal read no recorded dispatch at all; the first case then fails as review-missing rather than review-dispatch-refused (EXIT=1, one failed, in the run's negative-control.log). The mutation is reverted; the committed tree does not carry it.
