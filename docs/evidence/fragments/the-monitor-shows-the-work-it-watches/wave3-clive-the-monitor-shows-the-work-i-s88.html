A worker that ends its first turn without acting is named as a premature end

A print-mode worker gets no turn after the one it is in. A run that opened its first turn, wrote one message and called no tool therefore stopped without attempting anything and without reporting a fault, and its session survived to continue it. The fleet read that run as halted, so the pane said a failure had happened and a coordinator went looking for one.

The classifier now reads that stream shape as a premature end. Its row carries the premature-end clause with the text the worker ended on quoted verbatim, and the remedy reckon crew resume --run <id> --advice continue. The same classifier produces the obligations item, so the duty a coordinator sees carries the same command. The reading is one recovery word of the classification module, which both surfaces consume; no second implementation was added.

The three cases are the premature end with its quoted text and resume remedy, a one-turn stream whose message is an API error, and a one-turn stream whose message called a tool. The mutation removes the distinction, keeps the shared classifier and both surfaces, and leaves the first case reading as halted.

The three logs sit under the run directory and each opens with its revision and the literal command it ran. The arms are git clones of the two revisions under the run's scratch directory, the four follower variables unset, run in place on the arm's own tree with pytest -n 8. The declared mutation also fails the API-error case, because removing the distinction removes it for every one-turn stream; that case is pinned by the same classifier arm and is reported here rather than treated as a separate control.

Worktree creation was refused by the read-only mount holding the shared object store, so each arm is a git clone --shared --no-checkout of the worktree at that revision. The clones carry their own writable repository, which the staged-write inventory test needs to read its trees.
