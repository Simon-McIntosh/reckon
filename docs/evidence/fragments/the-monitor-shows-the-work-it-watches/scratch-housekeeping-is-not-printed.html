Scratch housekeeping never prints to a pane

The bare print() calls in remove_worker_scratch and garbage_collect_scratch are gone, so a promotion or discard running inside a follower or producer no longer puts a housekeeping line on a session pane. Every removal stays named on the result: the release result carries scratch_removed_paths with each removed path and its byte count, the over-budget notice stays as scratch_warning, and the crew gc --scratch report names each directory and its disposition in its emitted JSON, dry or applied. tests/test_scratch_housekeeping_is_not_printed.py passes 3/3 (a promotion with stdout captured prints nothing about scratch and names the path and size on the in-process result; crew gc --scratch --apply names the path in its JSON and prints nothing outside it; a dry run names the would-remove directory the same way). The importer-population gate is 200 passed / 2 failed at head against the same 2 failures at base 4870a37ab, EXIT=1 both arms, with no failure at head absent at base. Ruff adds no finding and no format delta over base on the staged paths. Both declared controls fire: restoring the print in remove_worker_scratch reddens the promotion case, and restoring the print in garbage_collect_scratch reddens the crew gc --apply case (EXIT=1 each).
