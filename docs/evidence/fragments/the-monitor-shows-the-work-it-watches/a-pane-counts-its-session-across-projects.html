A session-scoped row counts that session's workers in every watched project

A follower scoped to one session relays one project's stream, while the session may work in several projects at once, each with its own watcher and events file under the watch directory. _scoped_watch_event in reckon/crew/recovery_watch.py took a row's counters from that row's own project's session_counts entry, so consecutive rows from different projects reported different populations under one unlabelled column and the figure jumped (7w, 8w, 7w, 3w… within 17 minutes on 2026-10-18). The row's own project's figures are still its session's entry; the session's entry from the newest transition carrying session_counts in each other project's events file is now added. Each other file is read from its tail in chunks (_newest_session_counts), so a row's cost does not grow with an events file's history. A project whose newest such transition carries no entry for the session adds nothing, and a follower with no session is one project's pane and keeps that project's counts. The scoped event carries the session-wide figures the pane renders (working/blocked/unpromoted/waiting) beside the row's own project's figures under project_*, so a consumer of either reading loses nothing.
