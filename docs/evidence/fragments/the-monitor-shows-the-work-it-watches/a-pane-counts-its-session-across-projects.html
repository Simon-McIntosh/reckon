A session-scoped row counts that session's workers in every live-watched project

A follower scoped to one session relays one project's stream, while the session may work in several projects at once, each with its own watcher and events file under the watch directory. _scoped_watch_event in reckon/crew/recovery_watch.py took a row's counters from that row's own project's session_counts entry, so consecutive rows from different projects reported different populations under one unlabelled column and the figure jumped (7w, 8w, 7w, 3w… within 17 minutes on 2026-10-18). The row's own project's figures are still its session's entry; the session's entry from the newest transition carrying session_counts is now added from each other project's events file — but only while that project's producer is live, so a stopped watcher's last transition stops contributing. Commits 8398fec58, a21ac3bd2.

Reading and liveness. Each other events file is walked from its tail by the owner of that read, runs._iter_stream_lines_backwards, rather than by a second implementation carried in this module, so a row's cost does not grow with an events file's history. The liveness judgement is the obligation snapshot's own: obligation_snapshot.freshness_reading (with its seat reading) is reused, and only its no-producer verdict excludes a project's figure — a producer on another host, one running code other than this checkout, and a producer that is alive but has not spoken all still count, and no new time bound is added. This process's own code identity is read once and kept (_running_code_stamp), because that read shells out to Git over the whole checkout. The scoped event carries the session-wide figures the pane renders (working/blocked/unpromoted/waiting) beside the row's own project's figures under project_*, so a consumer of either reading loses nothing; a sessionless follower is one project's pane and keeps that project's counts.
