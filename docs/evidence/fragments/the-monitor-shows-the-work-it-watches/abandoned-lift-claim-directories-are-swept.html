Lift-claim directories of hosts that ended on this node are swept

A session host files its lift claims under one directory keyed on the host, host-<node>-<pid>-<start> beneath crew_home/watch/lifts, so every host lifetime left a directory standing: the per-lift prune empties only the running pane's own directory, and a host's directory is never that pane's. A follower's prune pass now also sweeps the claim directories of hosts that have ended on this node — _prune_abandoned_lift_claim_dirs in reckon/crew_follow_commands.py, called from _prune_lift_claims so a lift end triggers it. Liveness is the host pid together with its kernel start tick, as owner_alive in reckon/crew/session_host.py decides it, so a reused pid does not keep a dead local host's directory. A directory naming another node is never removed; a node-less key from the layout before the node entered the key is removed only once nothing has touched it for seven days; a per-session directory carries no host- keyings and is left alone. The stale per-session description of the claim in reckon/crew/ticker.py now states the host keying.

Measured by tests/test_abandoned_lift_claim_directories_are_swept.py: one prune pass over five directories removes two — a dead local host's directory and a node-less directory untouched for eight days — and keeps three — a live local host's directory, another node's host's directory whose pid is absent here, and a node-less directory touched now (4 passed). The negative control drops the node check and removes the other node's directory, failing with EXIT=1, logged in the run directory.
