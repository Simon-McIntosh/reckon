The session pane shows a run starting

A run's beginning reaches the pane from more than one pair. START_KINDS in reckon/crew/ticker.py now also holds ("queued", "working") — an admission pass launching a request the pane listed as queued — and (None, "working"), a follower attaching after a run began and delivering that run's first row already in the pane's working word with no left side. RowPolicy._is_own_start reads the same set and excludes a baseline first, so inventory taken at attach is never a first row; _is_own_launch keeps its own baseline exclusion. Both new pairs still gate on the pane's own session, so a peer's start prints nothing.

Reproduced first: at the base revision the new test's two positive cases read no row (2 failed, 1 passed), and its peer case passed, so the instrument saw a known-absent row rather than failing to start. At the head revision both print exactly one row, and a repeated row of either pair adds none. The follower's own settled-rows cases encode the rule this replaces — they expected a first streamed row already in working to be held back — so those two now expect the start row: the owning pane draws four rows with it counted once, the observer pane five, and every other assertion in both is kept. Two negative-control arms, one per new pair, each restore that exclusion and return their failures with EXIT=1: 1 failed, 5 passed for the queued pair and 3 failed, 3 passed for the no-left-side pair, whose three are the node test's case and both follower cases.
