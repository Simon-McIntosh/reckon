The session pane shows a run starting

A run the session owns draws one row when it begins working, from either pair that announces it: ("queued", "working"), an admission pass launching a request the pane already listed as queued, and (None, "working"), a follower attaching after the run began and delivering its first row already in the working word with no left side. Both pairs are in START_KINDS in reckon/crew/ticker.py; RowPolicy._is_own_start reads that set and excludes inventory first, and both gate on the pane's own session, so a peer session's start draws nothing. The pane's row path is the follower's own path: _follow_selects carries no state filter, so these rows reach the policy and are decided there.

The deliverable was already present at this node's base revision 18385bba31f0292b7514a36666ccdfea1a906624, landed as 3233841951, so it was verified here and not reimplemented. This node changes no product source: it adds coverage for two behaviours beside the deliverable that the section's test left unasserted — a re-arm baseline must not draw as a start, and a follower attaching after an admitted request's start must not draw a second row.

The gate is one arm at a time. The base arm runs the same test files against an extraction of the base revision; the head arm is the worktree head with this node's change applied. Every log names its revision, the module path printed as imported and the literal command, and ends with a bare EXIT= line.

The baseline pair is suppressed by two predicates, _is_own_start and _is_own_launch, so removing either alone leaves the inventory case green — each is measured and recorded that way — and the case mutates red only with both removed. The case therefore asserts the behaviour the section owes rather than one line; the pair reads as defence in depth, and the review that first noted the line as untested is answered by the behaviour rather than by a white-box assertion on a private predicate.
