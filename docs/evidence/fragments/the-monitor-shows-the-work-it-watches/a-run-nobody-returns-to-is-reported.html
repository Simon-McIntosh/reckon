A run nobody will come back to is reported

A live pointer is forgotten when both hold: its classification is terminal and unpromoted — the classifier's promotable, scoring, blocked or failed, or the fleet verdict's complete or abandoned — and its owning session has had no live follower registration and no dispatch for a threshold defaulting to six hours. The derivation lives in reckon/crew/forgotten_runs.py and joins classify_pointer with _follower_liveness and _unattended_seconds, the two readings that until now drove only the watcher's sweep. It deliberately does not reuse overdue_unreconciled_runs: that list feeds the dispatch fence and refuses, while this one only reports. The threshold is a parameter of the derivation, and a pointer naming no session is judged by its own terminal age, because absence is not ownership.

The list is served as a crew read view rather than a new verb — crew(view="forgotten") and reckon crew view forgotten --project P call the one function both surfaces share — and each row names the run, its node, its session, its classification, its unattended and terminal ages and the recovery the classifier already offers it.

Three pointers are built in a temporary RECKON_HOME: a complete run whose session holds a live follower registration, a complete run whose session has had neither follower nor dispatch for seven hours, and a running run under that same second session. pytest tests/test_forgotten_runs_are_reported.py — 4 cases — lists exactly the second, with its age and its recover action, and the derivation called at an eight-hour threshold lists nothing. The no-dispatch guard reads every reckon/crew/dispatch*.py module and finds neither the new module nor its function, and its positive control finds the name in reckon/crew/forgotten_runs.py by the same instrument, so the absence is a reading rather than a failed search.

The declared mutation — the follower-liveness condition removed from the derivation — lists the followed run too: AssertionError: … it named ['run-attended-complete', 'run-forgotten-complete'], EXIT=1, 1 failed id the head arm does not fail. Log: logs/negative-control.log in this run's directory.

The gate ran in place on the fleet node with pytest -n 8 over the four suites this node's done-when names plus its own: 112 passed, 1 failed — tests/test_every_module_fits_a_worker_window.py::test_every_module_fits_a_worker_window, which reports reckon/ledger.py: 51666 estimated tokens exceeds the 50000 bound. That module is untouched by this node and belongs to a concurrent node's scope; the same case fails in the base arm, so this node adds no failure. Two files outside the granted write scope were required to keep the view parity case green — reckon/_mcp_tools.py (the crew tool's hand-written view Literal) and skills/reckon-build/SKILL.md (which documents exactly the views that Literal admits) — and they are landed as their own commit for the coordinator to keep or drop.
