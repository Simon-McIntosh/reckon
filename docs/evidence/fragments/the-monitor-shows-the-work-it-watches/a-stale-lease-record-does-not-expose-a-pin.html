Chosen mechanism: the pin stamps its .in-use mark as it takes the lease, and the prune keeps a tree whose record is stale but whose mark was stamped inside the publish grace. The alternative — rewriting the node record before the flock — was rejected because it reorders _record_lease_node ahead of pin_matches_materialized_tree, so a vanished tree would raise a write error instead of the "vanished before its lease" refusal the reload retry reads. Stamping the mark keeps the existing error path and reuses the grace already defined for the publish-to-lease gap.
