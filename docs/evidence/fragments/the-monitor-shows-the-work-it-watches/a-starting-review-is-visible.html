A review run that has started counts as its subject's review in flight

A composed review is dispatched before it files anything. In that window the store holds no record for it, so review_present read false, the subject's row printed the composed dispatch anyway, and the command came back already starting — the review run existed and no surface named it.

classify_pointer now asks the reflex's own recogniser (_review_in_flight) whether a review already stands for the run at its current head, and reads that review run's own pointer for its phase. When the phase is starting, queued or working, the row carries review_run_id and review_run_phase, review_present is true, and next_action is the read of that run (reckon crew observe --run <id>) instead of a dispatch. A review whose phase is terminal is not in flight: the store answers for a filed record, and a review that died without one leaves the run owed a review again. The two names join LIVE_CLASSIFICATION_FIELDS in reckon/crew/query.py, so the live view and the pre-flight read one vocabulary. The live view already listed starting pointers; the new test pins that.

A view classifying several rows has already read the live pointers, so project_live_rows and the runs view hand that snapshot to classify_pointer, which passes it to the recogniser. Without it the sweep ran once per row and a view over N rows read the directory N more times after its own read; a case counting the reads sees six against one when the snapshot argument is dropped.

tests/test_a_starting_review_is_visible.py (7 passed) covers the subject naming its starting review with no dispatch printed, the live view listing the starting review with the subject pointing at it, a subject with no review run still printing the dispatch, the four phases at the edge of in-flight (queued and working count, complete and failed do not), and one pointer read for a five-row view. Negative controls: _review_run_in_flight returning ("", "") reddens the first two cases, and dropping the snapshot argument reddens the read count, both at EXIT=1.
