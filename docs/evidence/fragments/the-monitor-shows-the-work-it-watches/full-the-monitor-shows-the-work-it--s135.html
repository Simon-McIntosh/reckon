A replayed row is dated by its transition, not by the attach

A follower that replays what was already on disk printed every row with the moment it attached, so a transition from the previous day read as [replay] 12:30 and looked like news. A replayed row now carries the stamp the event log holds for its run's last transition, in both shapes the pane draws: a transition read out of the log's trailing span, and a row for a run already terminal at the attach. The pointer records no time for its phase change, so where the log holds no transition for the run the row shows --:--:-- rather than the attach hour. A live row, drawn without the prefix, keeps the clock it had. The word a row announces is still the live fleet's, because the pointer is current while the stream is history; the time answers a different question and the log's word does not overrule the fleet's.

tests/test_a_replayed_row_shows_its_transition_time.py drives the wired crew follow command against a temporary crew home, with the attach frozen at 12:30:00 and the zone forced to UTC. Three cases: a replayed transition stamped 09:00:00 the previous day reads [replay] 09:00:00, and a replay of a review run already terminal at the attach reads [replay] 08:00:00, the stamp of its own last transition, with neither row carrying 12:30; a transition written after the attach prints without the prefix and carries its own observed time; a run whose log holds no transition reads --:--:--. The review case is the one that pins the rule: its log word is complete while the live row draws the review's delivered word, so a clock taken only where the two vocabularies agree would fall back to the attach time there, which is exactly the reading the prefix exists to correct.
