A slow station tick reads as slow in the pane, as it already did in the hook

Reported three times on 15 November: a pane printed producer reckon lost: snapshot age 167–364s exceeds 120s; re-arm with: reckon crew watch --ensure while the obligations hook, reading the same station in the same minute, said the station was alive but slow three minutes into a per-project-refresh tick. The producer never died and the remedy answered started: True and changed nothing, so the row and its remedy were both wrong for a slow tick.

The divergence is in the two reads, not in the station. Both surfaces call read_station_answer, but the answer's source decides what it can carry. Read from the store, the answer is built from the station table's own rows, which hold the beat beside the running tick's stage and start. Read from the export — the branch taken whenever the store cannot answer the session's document — the answer carries _station_heartbeat and nothing about the tick, so its beat is stale by construction and the tick that explains it is invisible. Measured on this node: obligations/reckon/station-snapshot.json has station keys heartbeat, host and job only, with a beat of 2026-11-15T15:03:00Z against a station.sqlite3 whose markers read tick_stage=store-tick, tick_started_at=2026-11-15T17:54:18Z and a beat of 17:54:19Z at a read taken 17:54:19Z. The pane's loss path then compared that stale export beat, and its own producer snapshot aged 200 s, against FRESHNESS_WINDOW_SECONDS and drew a loss.

Deliverable. reckon/crew/obligation_snapshot.py gains read_station_tick, which reads the store's station rows alone — beat, tick stage, tick age and the instant the running tick started — and station_state, the one function both surfaces now use to turn those two ages into stopped, slow or live. read_station_answer keeps its place as the pane's first read, and its answer gains tick_started_at so a reader can report one row per tick rather than one per sample. ProducerSnapshotNotices.poll reads read_station_tick on the export branch and only there, and treats a fresh beat as a station alive now: a tick past the window draws one producer-slow row naming its stage and duration with no remedy, the tick ending draws one producer-restored row, and a stale beat with no tick running still draws the loss with the re-arm remedy. The verdict comes from one function, so a pane that can read the store and a pane that cannot draw the same row in the same tick.
