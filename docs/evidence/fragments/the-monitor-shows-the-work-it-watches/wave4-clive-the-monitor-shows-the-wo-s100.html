Every parked request counts once, and a stuck one reads apart from the queue

The pane's waiting figure counted queued requests and declared waits, so a request parked in awaiting-upstream or blocked-upstream fell into no cell at all. A session whose whole fleet sat behind an upstream section therefore read as an empty fleet, which is the one reading a coordinator must not be given: nothing was running, nothing was streaming, and no row said so.

_fleet_counts now counts every parked phase exactly once in the waiting figure, whatever its phase word, and the one stuck verdict is carried beside the buckets rather than inside them. A stuck request keeps the pane's queue cell, because its phase is still what the request is doing; the new figure recounts rows the buckets already hold rather than moving one out of them. _fleet_counts keeps its sum over the fleet, and the per-session partition carries the same figure so a follower scoped to one session reads it. The ticker draws an s cell, painted in the block's alarm hue when it is above zero and dimmed to a zero when it is not, and the added cell keeps the block's fixed shape.

tests/test_the_pane_counts_parked_work.py reads a session with one request in each parked phase through the producer's own partition and transition builder: it asserts four waiting and nothing stuck; then marks one request stuck and asserts one in the alarm colour with the queue still four; then clears it and asserts a dimmed zero in the same screen column, with the row inside the width bound. The two negative controls both fire: removing awaiting-upstream from the waiting bucket fails the first case, and dropping the branch that carries the verdict onto the event fails the second. The suite arms are recorded in the delivered manifest.
