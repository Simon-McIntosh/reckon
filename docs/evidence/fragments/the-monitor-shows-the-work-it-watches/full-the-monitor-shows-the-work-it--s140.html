A held duty outlives its run, and a failed step's row keeps the stop blocked

A station computes each session's duties once per tick and keeps that answer until the next tick, so the list a pane and the stop hook read can be minutes old. Most of a held answer's life is already settled at read time: a run-keyed duty whose live pointer has gone is dropped before a coordinator sees it. What was not settled was the pair of rows an automatic step leaves behind -- promotion-failed from a refused promotion, and sweep-failed from a station sweep that failed. Each publishes a remedy for the run it names, so each is owed only while that run can still be acted on. The stop hook read them as outstanding for a run that had already released its live pointer, already landed, and already had its outcome written to its ledger record, so a coordinator ending a turn there was sent to a remedy that could only fail.

Three facts are recorded here as measured, not assumed: all three already hold at the base revision. The pane's obligations reader drops a duty whose run has no live pointer. A run whose live pointer reads a working phase is drawn working from that pointer whatever the answer's age, and its session is not drawn halted. And a duty for a run whose pointer goes between two reads of the same held answer is dropped on the second. Those are the settlement's own behaviour, delivered by the earlier section that added the read-time drop, so this section fixes them in a case rather than reimplementing a working guard.

Deliverable. reckon/hooks/coordinator_obligations.py gains _FAILED_STEP_DUTY_KINDS, _failed_step_row_is_stale and a second branch in recheck_worktree_held_rows. A failed step's row is dropped only where both facts read now hold: the run has released its live pointer, so nothing is being attempted for it, and the run's own ledger record is present, so an outcome exists the failure belongs to. A run that never reached the ledger is kept, because there the row and nothing else records the failure. It reads only the per-run file the worktree settlement already reads, so the hook's budget is unchanged.
