A queued launch refusal states its own remedy

An admission attempt refused by a condition of the session is the one stop a queued request cannot wait out: the lane will refuse it again on every pass. The refusal is stamped on the queued pointer's failure field, and the obligations item for a queued request is composed by _queued_failure_remedy in reckon/crew/recovery_classification.py. That reader kept only refusals whose text named the session, so a PlanReviewMissingError — whose message names the plan and quotes the reckon crew review invocation that clears it, never the session — was dropped, and the coordinator read waiting for a lane slot while the lane refused the launch on every slot that opened.

Change. _queued_failure_remedy now surfaces a queued pointer's stamped launch failure whatever text it carries, and publishes the remedy the failure itself states. A refusal that names the session is a condition of that session and keeps the follower the session arms, as before. A refusal that names no session but quotes the command which clears it — the reckon crew review a plan-review gate names, read by the new _remedy_command_stated_by from the backtick-quoted command in the message — publishes that command, preferring a review invocation over a bare verb quoted beside it and taking the longest match so the full invocation with its arguments is the one published. A lane hold is still left to the waiting reading, and a refusal that names no session and quotes no command likewise keeps the waiting reading rather than raising a duty with no command behind it. The classifier's next_action and the obligations item's next_command both read this through the reader they already call; no second reader was added.

Gate. tests/test_a_queued_refusal_names_its_remedy.py writes three queued pointers into a temporary crew home (a PlanReviewMissingError that names no session, a refusal that names the session, a lane hold) and finds: the review refusal reads queued with its session_refusal set and its next action equal to plan_review.review_invocation(PROJECT, PLAN), and appears in the session's obligations under queued-awaiting-session with that command; the session-naming refusal keeps runs._watch_attach_line(PROJECT, session=SESSION); the lane hold keeps wait for a local lane slot and is listed under run-queued.
