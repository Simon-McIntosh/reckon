A producer stuck on old code is no longer reported as reloading

What changed. reload_in_progress in reckon/crew/obligation_snapshot.py answered true for every snapshot in the producer-stale-code state, whatever its age, so a producer left on older code that never reloaded was reported as producer reloading forever and its reader was never given the remedy the not-fresh line carries. The code-stamp arm now counts as a reload only while the snapshot is inside the shared producer reload window (PRODUCER_RELOAD_WINDOW_SECONDS, 65 s), the same bound the seat's recorded reload intent and the silent-producer arm already carried. Past the window the caller falls through to not_fresh_line, which prints the producer is running older code than the checkout and the reckon crew watch --ensure remedy.

The bound changed one existing expectation. tests/test_a_quiet_foreign_producer_reads_live.py::test_snapshot_from_predecessor_uses_seated_producers_stamp[False] asserted producer reloading for a stale-code snapshot 20 hours old; it now asserts the stale-code not-fresh line and the absence of the reload wording. Every other case in that file is unchanged.

Measured

The new test file carries three cases: the inside-window stale-code snapshot reads as a reload, the past-window one does not, and the hook prints the not-fresh line rather than producer reloading for a twenty-hour-old stale-code snapshot.
