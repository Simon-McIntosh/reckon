A launch names the interpreter of the process that composed it

A worker's shims on the composed launch PATH start an interpreter that can import the package. A launch composed by a process running out of a reload image, or any tree without a .venv of its own, has none to fall back on: its shims then pick a bare python3.12 off PATH that cannot import the package's dependencies, and the launch fails at once with ModuleNotFoundError. An earlier fix exported the composing interpreter when the reloader re-executed, but that export reached a process only on its next reload, so a launch that depended on how its composer was last reloaded stayed exposed until the next change to reckon/ or skills/.

The dispatcher now names its own interpreter — RECKON_SHIM_PYTHON = its sys.executable — in the environment it persists for a launch, beside the PATH that launch_search_path builds, unless the caller already set one. Every shim the worker runs then resolves an interpreter that can import the package however the composing process was started or reloaded. The change is in reckon/crew/dispatch_launch.py (_persisted_worker_environment).

Two focused tests pass. Composing a launch environment finds RECKON_SHIM_PYTHON equal to sys.executable, and a value the caller already set is kept. A shim run from a tree with no .venv, under the composed environment and a PATH whose python3.12 is a stub that exits non-zero with a marker, resolves the composing interpreter and reaches its main (TOOL=srun, exit 0), never the stub. The declared negative control removes the setting and both tests fail: the shim reached the stub (STUB-PYTHON3.12-RAN) and the composed environment named no interpreter, EXIT=1, logged under the run directory.

The eight test files that exercise the launch environment — the workers' shim path, the composed prompt's host line, the persisted environment and the nested-launch route — ran 44 passed at base and 46 at the changed revision, the two additions being the tests above, with no failing id on either arm. ruff check and ruff format --check added no findings on the changed Python files (one pre-existing PYI034 and four pre-existing format hunks in dispatch_launch.py are unchanged from base).
