A review the router holds now waits as a queued run

The condition that separated the unqueued 06:44Z dispatch from the queued 07:25Z one is which code path raised the lane hold, not the lane's state. Both saw the same lane: the recorded reason on both sides is the router granting the session 0 extra workers while the gate document read paused: False. At 06:44Z the reflex composed the review through dispatch(), which raised LanePaused/LaneHeld carrying the allowance gate and no queued record; recovery_review_dispatch's except LanePaused branch reads getattr(exc, "queued", None) and reports error: lane-paused when it is absent, so the reflex had no queueing of its own and the review existed only as a hold. At 07:25Z reckon crew dispatch --role review reached the local-lane branch in dispatch.py, which writes the queued pointer through _queued_request_record before raising, and answered queued: true, position: 1. The gate state is a separate, narrower condition: a paused or unreadable gate withholds without queueing on both paths, which is the behaviour the second case holds.

The reflex now queues a router-held review itself when the hold is a router holding on the local lane rather than a shut gate: _router_hold excludes the gate states paused and unreadable and accepts a hold carrying held or an allowance, and _queue_router_held_review stores the request with runs.queue_dispatch using the same _queued_request_record builder the CLI path uses, so the queued position rule is one rule rather than two. A paused gate reaches the same except branch and still queues nothing.

Evidence: tests/test_an_automatic_review_held_by_a_full_lane_is_queued.py holds the three cases the section lists, each on temp paths for the crew home, the mounts, both gate documents and the worktree root. Case 1 raises the recorded production shape (a real LaneHeld from _dispatch_lane_allowance with no queued attribute) and finds exactly one queued pointer whose run id the report names; case 2 finds error: lane-paused with no queued key and no pointer at all; case 3 runs the CLI against the same config and gets queued: true, position: 1. Negative control, with the fallback removed and the branch restored to the state that raised without queueing, case 1 fails with report={"dispatched": false, "error": "lane-paused", ...} and no queued key — the 06:44Z record shape, reproduced.
