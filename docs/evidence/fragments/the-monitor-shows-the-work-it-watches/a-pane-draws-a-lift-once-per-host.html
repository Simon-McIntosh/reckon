A pane draws a lift once however many sessions its host follows

The lift claim's arbiter was keyed on the session, so a session host following two crew sessions — a coordinator dispatching under two session names — drew each lift transition once per session. lift_claim_key in reckon/crew_follow_commands.py now keys the claim on the host that spawned the follower, read from RECKON_FOLLOWER_OWNER, whose presence (not the value of follower_owner(), which falls back to the parent pid) selects the host key; a follower without a host keeps the per-session key. Each of the module's claim readers resolves through lift_claim_dir, so one key covers them all.

Measured by tests/test_a_pane_draws_a_lift_once_per_host.py: a host with one follower per session and one lift granted then ended draws one grant row and one end row (4 passed). The negative control, keying the claim on the session again, drew two grants and failed with EXIT=1, logged in the run directory.
