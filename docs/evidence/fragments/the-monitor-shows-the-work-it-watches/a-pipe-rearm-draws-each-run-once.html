A pipe re-arm draws each run once

The resume branch of reckon/crew_follow_commands.py compared a session's live rows against the file delivered record. On a node running a station the live rows never reach that file: the follower hands each row to the subscriber's checkpoint and returns before write_delivered. The record therefore stops advancing the day the station takes delivery, and every live run of the session looks undrawn at every arming — the repeated waiting rows the lead reported from the nova pane. The rows the branch drew were not recorded either, so even the file-record path redrew them on the next arming.

The re-arm now reads and records the one delivered-state store the live rows use: the station subscriber's checkpoint while one is attached, the file record otherwise. A word the re-arm draws is written back to that same store — through the subscriber's path, reseeded so the row policy carries it too, and through write_delivered for the file record. No second store of delivered state is added.

Measure: tests/test_a_pipe_rearm_draws_each_run_once.py drives the wired crew follow command against a temporary crew home and re-arms twice in each of three cases — a station-attached pipe, a run that moves between armings, and a node with no station, whose file record is seeded at the earlier word. All 3 pass at the head revision; all 3 fail at the base revision, each with the second re-arm drawing the row again ( r-rearm-one waiting r-rearm-one). The declared negative control — the re-arm reads the file delivered record while a station subscriber is attached — fails the first case with the same row (EXIT=1, 1 failed).

The 66 test files importing reckon.crew_follow_commands ran on the all_debug partition, one arm at a time, -n 4: base arm 506 passed and 9 failed, head arm 509 passed and 9 failed, with the two failure-id sets identical — 3 additional passes and no failure added against the base. The 9 shared failures are the same tests on a base the change does not touch.

  • The active store is proved by the fixture, not assumed: the file record and the subscriber's checkpoint are both seeded at working while the live run stands at waiting, and each case asserts the derived word first, so a fixture that failed to produce the word under test reddens rather than passing vacuously.
  • The instrument sees movement: a second case moves the run to queued after the first re-arm and requires it drawn exactly once at the new word, so a re-arm that drew nothing at all cannot pass.
  • The no-subscriber case covers the half of the defect the station masks: at the base revision the file-record path also redrew the row, because the resume branch recorded nothing it drew.
