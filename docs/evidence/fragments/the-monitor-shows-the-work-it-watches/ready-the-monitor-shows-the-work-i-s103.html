An automatic repair round is named while it runs, and hands back the review duty when it delivers

Where the gap was. A review that files a blocking finding resumes the reviewed run's own worker with the findings as advice (reckon/crew/recovery_repair_dispatch.py), and records the round on that run's pointer under repair_dispatch with round_id = <reviewed run>@<head>. The resumed worker reopens work the run had already delivered, so the pointer carries an alive pid and its classifying row reads running: reckon/crew/obligations.py derived no duty at all for it. The coordinator's list therefore showed nothing for a run mid-repair, which is the same silence it had for a delivery whose promotion it still owed — the two states the plan's report could not tell apart.

What changed. _repair_round_in_flight reads the pointer's own round record and accepts it only under an opening status, so a round the reflex held, declined, refused or exhausted names nothing in flight. _repair_round_item builds the row while that record is open, the round names a head, and the run's classified row reads a live process: the kind is repair-round, and the row carries round_id, the worker pid, the finding text and the review_run_id. The last two are read from the stored review for the head the round is keyed to, through recovery.select_review_for_head reached via the view's own memoised _selected_review; the finding is the first blocking finding that states a claim, so a record with none names none rather than inventing one. The row carries no command, because the reflex owns the round and re-fires when it ends. It is listed ahead of the classifier's other readings and joins NON_BLOCKING_DUTY_KINDS in the derivation and the stop hook's mirror _NON_BLOCKING_KINDS, so it prints and never holds the turn open. Once the round delivers, the run's head moves past the reviewed revision and the ordinary review duty for the new head stands again unchanged.

Gate. The new tests/test_a_repair_round_shows_on_the_obligations.py builds a real checkout, stores a review carrying a blocking finding, and writes the round's record on a pointer whose pid is this process alive on this host, so the liveness read is a real one rather than a stubbed answer. Four cases: the single repair-round row names the review run, the finding text, the pid and the round id and carries no command; the stop hook lists the kind and _blocking_items returns empty for the payload; the same live worker with the round record removed derives no round row, which is the record being the evidence rather than liveness alone; and after the round delivers a new head and its worker exits, the row reads review-missing against the new head. 4 passed.
