The pane carries a standing line for the session's working runs

reckon/crew/ticker.py gains InFlightLine, which composes one standing line from the rows the live view serves: the head in flight followed by each of the session's working runs as node, phase, age, stream age, in run-id order. It emits on a fixed cadence, at once when the set of working runs changes, and never repeats identical text, so a line that would say nothing new is not reprinted. A peer session's run is never named, a run the fleet classifies as stopped (a stalled run whose pointer phase is still working) is not in flight, and a session with nothing working emits nothing — its cadence resets, so the next run to start prints immediately. The line is cut to the pane width with a counted remainder, so it never wraps. Identity hue and grid come from the pane's own Ticker, so a run keeps the colour its transition rows carry.

tests/test_the_pane_shows_its_work_in_flight.py drives it with a stubbed clock and a live view in the view's own row shape, six cases passing: two working runs on one line with phase, age and stream age; a refresh after the cadence carrying the new figures; a changed set drawn at once; a peer session's run absent; a stopped run absent; and no line when nothing works. The negative control disables the standing line and 5 of the 6 cases fail (EXIT=1). The ticker-importer test population at head reports 487 passed and at the base revision 481 passed, so the change adds no failing id. Ruff check and ruff format --check are clean on both staged Python paths.

The printing caller is not in this node's write scope: the follower's wait pass in reckon/crew_follow_commands.py is where InFlightLine.emit would be given the live view rows and write a non-None line to the pane, and that wiring is recorded as outside scope for the coordinator to place — the ticker's own render of the live view is what this node delivers.
