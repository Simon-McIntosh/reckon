What changed

The needs-you derivation now holds out a run whose deferral is still in force, so a run the coordinator has put off is not named on the reminder cadence until its deferral's instant passes. The deferral is read through obligations._acknowledgements_in_force — the reader the obligations view already defers by — rather than a second copy of its expiry rule, so the pane line and that view hold the same run out at the same instant. reckon/crew/obligations.py is unchanged.

The filter sits in needs_you_rows in reckon/crew/needs_you.py, the single row derivation the standing pane line, the closing drain row and needs_you_runs all compose from, so no reader can name a run another withholds. Because the deferral expires on its own, the run re-enters the set exactly once, as a change, and the line names it then. needs_you_runs now also accepts the instant it composes for, matching needs_you_rows, so the boundary either side of a deferral's instant is asserted rather than slept through.
