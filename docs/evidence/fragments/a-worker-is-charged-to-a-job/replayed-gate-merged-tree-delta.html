What was measured. Merge commit 355a8864 has first parent 19d9f51f (main at the time of this run, and this node's base) and second parent 3a9eec99. Against its first parent the merge changes three paths: reckon/crew/promotion.py (+223/−5), a new tests/test_verify_gate_replay_is_diagnosable.py (297 lines), and one figure SVG. The empty difference is measured, not blind. Three checks stand behind it. A synthetic control on the comparison itself: one FAILED line injected into a copy of the merged log is reported by the differ as added, so the instrument that returned the empty set can see a new failure. A provenance assert before every run: each arm printed reckon.crew.promotion.__file__ and required it to lie inside its own tree (/tmp/promotion-arms/base/reckon/crew/promotion.py and /tmp/promotion-arms/merged/reckon/crew/promotion.py), probe exit 0 in both arms — and the assert was load-bearing, since a first probe run from the worktree resolved the worktree's module rather than the tree's. And the failures reproduce serially: the six files carrying them, run serially (no xdist) in each arm, give the same 11 failed, 43 passed in both, so the identity is not an artefact of parallel test order.

It changed no source file: the repository is read-only for this role and the scratch trees are exports under a node-local /tmp, so no worktree is touched and git status --porcelain is empty. The trees are archive exports with no .git, so a test that resolved the enclosing repository through git would read that absence in both arms; the measurement is a comparison between the arms and both share the shape. The population differs by exactly one file between arms (the merge's new test file, absent at base and therefore not runnable there); the common 34 files are the comparison basis.
