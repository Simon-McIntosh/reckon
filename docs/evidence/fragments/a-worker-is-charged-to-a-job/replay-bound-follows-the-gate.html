A gate re-run's bound follows the replayed gate's recorded duration

What changed. reckon crew verify-gate no longer runs every replay under a fixed 300 s bound. When the caller names none, the bound is derived from the duration the run's own gate log records — with headroom, held between the 300 s default and an 1800 s ceiling — and a run whose log records no duration keeps the fixed default. An explicit --timeout-seconds is still taken as given. The recorded report and the committed row name which input applied (explicit, derived or default), the bound's value in seconds, and the recorded duration it derived from.

The defect, reproduced before the repair

Measured 2026-09-29 on a promoted run whose own gate log recorded 213 passed in 378.29s: every verify-gate reported the integrated revision as not-run, because the replay stopped at the 300 s constant. A gate that legitimately outran the constant could never be verified as recorded; the command had to be narrowed to a single file to get any verdict at all.

The reproduction is the base arm: the new cases run against revision 33c5e761 in a scratch copy with only the test file added. A stubbed replay whose virtual duration is 330 s — above the 300 s constant, below the bound the recorded duration derives — reports not-run there:

'integrated_verdict': 'not-run', 'reason': 'the gate did not finish within the 300s re-run bound' — the exact failure the derived bound removes.

The repair

  • Three inputs, named in the result. An explicit --timeout-seconds wins outright. Otherwise the recorded duration from the run's own gate log, read from the path the committed row cites (the copy promotion preserves under the run directory) with a fallback to the preserved name beside it, derives 2 × duration clamped into [300, 1800] seconds. A log that is absent or carries no runner duration leaves the 300 s default — an unmeasured duration is not a zero.
  • The derivation only loosens. The lower clamp is the historical constant, so the change can unblock a gate the fixed bound refused and can never tighten a bound a fast gate was already passing under; the ceiling stops a mis-recorded duration from mounting a bound that holds a fleet slot for an hour.
  • The bound reaches the process, and the record. The stub observes the timeout the replay was actually run with, and the report carries replay_bound_source, replay_bound_seconds and recorded_gate_seconds; the committed row carries the same fields, so a reader of the durable record knows which bound applied without opening the report.

The stubbed duration makes the discrimination without real waiting. A run whose gate recorded 378.29 s is replayed under a derived bound of 756.58 s, so a stubbed replay of 330 s finishes and reports passed; the same stub under the default is not-run; and --timeout-seconds 120 against the same recorded duration reports explicit at 120 s and not-run, so the explicit value — not the derivation — decided it.

The negative control

In a scratch copy of the committed tree, the declared mutation — replace the derived replay bound with the fixed 300 s — was applied inside the bound resolver, so everything else stands. The derived-bound case turns red (1 failed, 2 passed, assert 'not-run' == 'passed'), exit 1: the case fails on the constant and not on anything else. The red log's first line repeats the mutation verbatim, the mutated helper's text is printed under it, and the log ends in EXIT=1; it is named in the node's manifest under negative_control_log.

What is not here

No real multi-minute gate is run: the replayed command's duration is stubbed, and the stub is what the verdict discriminates on. The bound is derived from the run's gate log text as the record of the duration, so a runner that prints no in <n>s summary keeps the default. No figure: this change's measure is a set of verdicts and field values, which reads as a table. Logs live under the run directory on this workstation, so a later reader opens them by path. No real fleet run is replayed and no real config home is touched: each case builds a promoted row and a preserved gate log in a temporary config home and asserts the real one gained nothing under this run's own id.
