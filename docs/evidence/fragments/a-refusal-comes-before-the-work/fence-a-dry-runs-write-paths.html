A dry run applies the real call’s write-path fence

At the dispatch base the preview and the launch disagreed about one call. A crew dispatch --dry-run naming a write path under a temporary home’s ~/.cache answered "ok": true and listed the path on the node, while the same dispatch without --dry-run refused it with “write path … resolves outside the authorised work repository”. The condition the reproduction named is repo is None: the dry-run branch handed plan_dispatch the caller’s --repo unchanged, and the authority block that calls _require_write_paths_in_authority sits inside if verdict.ok and repo is not None. With no --repo, the fence never ran. Giving the preview a --repo made it refuse correctly, and the launch resolves the project’s registered mount in dispatch() before it reaches plan_dispatch, which is why the two diverged only on the omitted flag.

The repair resolves the mount in the dry-run branch on the launch’s own rule (resolve_project_repository(project, repo)) before calling plan_dispatch, so the fence runs and the preview reaches the launch’s verdict. A project with no registered mount now refuses the preview with the same sentence the launch gives, rather than previewing a dispatch the launch cannot honour.
