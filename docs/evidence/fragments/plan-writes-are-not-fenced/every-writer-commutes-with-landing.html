Landing record — every writer that can race the landing write commutes or is refused

The landing write had one measured survivor: a comment append whose base revision moved under it is merged by section and id rather than refused. This node adds the two-writer race for each of the five writers that can reach one plan — the landing record, a followup append, a section append, a state set and a comment append — each meeting an in-flight landing write on the same plan in a temporary repository. Both writers rendezvous inside the render step, after each has passed its own version check and before either replaces the file, which is the meeting the original lost update was measured at. For each writer the test requires that its change is present afterwards, or that its loss is refused with both versions named; a writer that reports success while its change is gone fails the case. Every writer's case passes at this revision, so no store repair was needed. The same file keeps the positive control: a sequential write still succeeds and still advances the version.
