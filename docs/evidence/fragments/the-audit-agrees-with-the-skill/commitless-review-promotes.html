§3 — A review's commitless manifest promotes without a hand edit

One node's evidence: the review promotion already worked at the dispatch base; the failing case was the same prose standing in for a commit over an in-repository path.

Outcome

What reproduced at the dispatch base, and what did not

At the dispatch base (40d23d9b) the review side of the done-when already held. The report-only handling added at reckon/crew/promotion.py's _declares_absent_commits and its use by _unresolved_citations reads a commits: none (…) line as a declaration rather than a citation, so a review run whose manifest carries it promotes through crew complete with commits: [] and no refusal — no --no-commit and no hand edit. The defect from the three recorded reviews does not reproduce at the base; it was fixed by that earlier handling, and nothing on the review path needed reimplementing.

What still failed is the mirror of it. The same declaration also answered the commit-for-changed-manifest guard, which asks whether a manifest's named in-repository path has the commit that contains it. A run naming an in-repository path while declaring it has no commit is exactly the contradiction that guard exists for, and the prose let it through. A review run is exempt from the review gate, so nothing else refused it, and the run promoted with the ledger recording a change and no commit pointing at it. Measured on the base source: a review run whose manifest read changed_paths: candidate.txt with the commitless prose promoted.

Change

_manifest_cites_a_commit now answers whether a manifest's commits line cites a real commit, reading a declared absence as neither a citation nor an omission. The guard uses it in place of a bare truthiness test, so the declaration still promotes a run whose paths lie outside the repository and is refused for a run that names a path inside it. The refusal is manifest field 'commits' is missing, raised for every role, review included.
