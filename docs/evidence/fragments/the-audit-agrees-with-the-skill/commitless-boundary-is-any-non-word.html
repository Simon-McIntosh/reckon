commitless-boundary-is-any-non-word — the absence word ends at any non-word character

A commitless role's commits: declaration was recognised by an enumerated separator set — whitespace, end of value, comma, semicolon, colon, em dash, hyphen, opening or closing parenthesis. A sentence punctuation mark outside that list kept the declaration unread: commits: none. review only and commits: none/review only were parsed as citations and refused with does not resolve to an object, so the coordinator still had to blank the line by hand. The set was incomplete by construction: any new punctuation a node reached for re-opened the hand edit.

The rule now reads the word boundary instead of a separator list. After leading whitespace, the field opens with an absence word when the next character is the end of the value or a character that is not a letter, digit or underscore — _ABSENCE_BOUNDARY = r"(?!\w)" in reckon/crew/promotion.py. A letter, digit or underscore after the letters means a longer word that merely begins with them (nonesuch), so that stays a citation attempt. The reading is still given only to a role that commits nothing; a role that commits keeps the entry-by-entry citation check.
