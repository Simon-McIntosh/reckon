commitless-changed-paths-reads-the-declaration — the changed_paths absence read by the commits rule

A commitless run declares its unchanged repository in two fields: commits says none … and changed_paths says none under the repository; the sole deliverable is the report. The commits declaration was already honoured by reading the raw field, but the changed_paths declaration was recognised only through the manifest list's prose shape — none followed by whitespace or the end of the parsed item. A declaration word followed by sentence punctuation therefore survived as a path: 

'none under the repository; the sole deliverable is the report' -> prose_none=True
'none (the node changed no file under the repository)'         -> prose_none=True
'none. review only'                                            -> prose_none=False
'none, no repository change'  (parsed: ['no repository change']) -> prose_none=False
'none) review only'                                            -> prose_none=False
'candidate.txt'                                                -> prose_none=False

For a review the false reading resolved the leftover text as an in-repository path, so _require_commit_for_changed_manifest refused the promotion with “the manifest field 'commits' is missing” and the coordinator blanked the field by hand. The fix reads changed_paths through the same helper commits already uses — _commitless_field_declares_absence, now parameterised by field key — so both fields are governed by one rule with no second copy. The role gate is unchanged: only a commitless role (review, investigate) gets the raw-field reading, and a committing role keeps the list reading, so candidate.txt and none. … on an implement run still demand their commit.
