commitless-changed-paths-reads-the-declaration — the worktree, not the declaration, decides

A deterministic commitless run — a review or an investigate node — has no repository work to commit, so it writes commits: none and a changed_paths value that names an artefact outside the repository or declares no path at all. crew complete read those fields as a commit citation and refused the run, and the coordinator blanked the line by hand each time.

Three attempts read the declaration to decide, and each was walked around, because no shape rule can tell a filename from a declaration in a free-text field:

  • The first recognised none only when the parsed list item ended at a space or the end of the value, so a declaration followed by sentence punctuation (none under the repository;) survived as a path and the manifest was refused.
  • The second read changed_paths through the boundary commits uses, which accepts any non-word character after the absence word. A review that really changed a file called none.txt was then read as declaring an absence, while the path reader resolved the same field to ('none.txt',) — the two readings disagreed about one field.
  • The third added a file-existence check for a bare value, but the path-entry reader returned the parsed entries whenever they were non-empty, so changed_paths: none, no repository change arrived as a survivor entry and the token none was never tested. A repository that really committed a file named none promoted with no commit where the dispatch base had refused.

The rule now decides from evidence. For a role that carries no repository work, promotion with no commits requires the run's own worktree to show no repository change against the base sha recorded at dispatch: no commit beyond the base, no tracked modification, and no untracked file apart from the .venv symlink that provisioning plants in every worktree. A worktree that holds work needs the commit that contains it, and a run whose worktree holds work is refused with the paths git reported. The declaration then keeps only its remaining role: it says whether the run claims no change, and a manifest that names a path under the run's own repository still needs the commit that contains it.

A refusal is not a dead end. The coordinator may pass --no-commit '<why>', the same override the gate-evidence guard takes, and the run then promotes with the paths git found recorded on the ledger as no_commit_uncommitted_paths beside the reason. The ledger row therefore says which uncommitted repository work was declined a commit, not merely that one was. No manifest text reaches this path — the reason is read from the command line — so a worker cannot declare its own changes away.

Negative control. The declared mutation — skip the worktree evidence check — reddens the committed-none case first: with the check skipped, a review whose worktree really committed a file named none promotes under each of none, none, no repository change, none. review only, and an empty changed_paths, together with the untracked-file case — 5 failed and 12 passed over the targeted cases. The red log is negative-control-worktree-evidence.log under the run directory, whose first line repeats the declared mutation verbatim; the mutated source was restored in a finally block.

Gate. The 25 tests/test_*promot*.py files plus tests/test_cited_identifier_resolves.py (26 files) ran with -rf -n 6 at the head 3005ac1a: 240 passed, 0 failed (gate-head.log). A base arm was not run this attempt; the head is green, so the change adds zero failures by id.

Landing note. The behaviour is carried by reckon/crew/promotion.py: _worktree_git_paths runs the git reads, _worktree_repository_changes measures the worktree against the recorded base sha (commits beyond base ∪ tracked modifications ∪ untracked, minus _PROVISIONED_WORKTREE_ENTRIES), and _require_commit_for_changed_manifest refuses a commitless run whose worktree holds work, returning the paths instead when a no_commit_reason is given. complete passes the reason through and _complete_locked records no_commit_uncommitted_paths. For changed_paths, _changed_paths_declare_no_paths now reads only the claim; the path-absence boundary, the path-entry reader, the tree-existence helper, and the first-path file test are gone.
