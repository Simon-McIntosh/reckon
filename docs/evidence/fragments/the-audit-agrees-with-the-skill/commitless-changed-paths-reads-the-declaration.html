commitless-changed-paths-reads-the-declaration — the changed_paths absence, read at a path boundary

A commitless run declares its unchanged repository in two fields: commits says none … and changed_paths says none under the repository; the sole deliverable is the report. The commits declaration was already honoured by reading the raw field, but the changed_paths declaration was recognised only through the manifest list's prose shape — none followed by whitespace or the end of the parsed item. A declaration word followed by sentence punctuation therefore survived as a path, and a review was refused with “the manifest field 'commits' is missing” until the coordinator blanked the field by hand.

The first fix read changed_paths through the same helper commits uses. Review found that fix unsafe. The commits field's boundary accepts any non-word character after the absence word, which is right for a commit value — a revision can never read as a path — but wrong for this field. changed_paths: none.txt opens with the letters none and then a full stop, so it was read as a declaration while _changed_paths_inside_repository resolved the same field to ('none.txt',). A review that genuinely changed a file called none.txt (or nil.rs, -x.csv) then promoted with no commit and no scope in the ledger, where the dispatch base had refused the same manifest. The two fields cannot share one boundary, because only one of them can hold a path.

Negative control. The declared mutation — read changed_paths with the commits absence boundary, dropping the path-shape and the file-name checks — reddens the new cases in the order they run: the none.txt case first, then nil.rs, each refused at the dispatch base but promoting under the mutation. The red log is negative-control-changed-paths.log under the run directory, whose first line repeats the declared mutation verbatim.

Landing note. The behaviour is carried by reckon/crew/promotion.py: _opens_with_a_path_absence_word holds the tighter boundary, _first_changed_path_is_a_file holds the existence check, and _changed_paths_declare_no_paths composes the two with the prose and committing-role readings. _commits_field_declares_absence keeps the permissive boundary, and both docstrings state which rule each field follows and why they differ.
