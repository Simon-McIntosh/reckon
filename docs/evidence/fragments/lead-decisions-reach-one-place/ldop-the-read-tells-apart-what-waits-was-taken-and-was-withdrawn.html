The read names four states and drops what was withdrawn

read_decisions returned ready, pending and taken-and-reversible rows, and everything else landed in decisions. A plan-authored decision holding no queued request, run or deferred section is now plan-block: its own list, its own state, and its owning session, recording time and held work reported absent by name (absent) rather than as an empty value, so a plan edit date and a plan coordinator are never stood in for facts the decision does not carry.

A record that names the decision which settled it (withdrawn_by) stands in no list at all. Nothing else would ever release the work waiting behind it, so release_withdrawn_holds returns those requests to the phase they were held from, and the admission pass runs it beside the plan-review release. A pointer that has moved off held since the pass read it is left where it now stands.

Measure: three tests over a temporary crew home with two mounted projects. The four lists hold one record each and no record twice (total_count == 4, count == 1); the withdrawn report appears in none of them; and an admission pass over a queued request held behind it reports released_withdrawn == ["r-held"] with the pointer's queue_hold is None. Removing the sweep, the plan-block branch, or the withdrawal exclusion from the source fails the corresponding test; the base-revision run of the same test is recorded in s5.html.
