Batch B — six top-level readers on one parser

Six timestamp readers outside reckon/crew/ no longer parse timestamps themselves: each now calls reckon._timestamps.parse_utc and keeps only the policy around the call that its own callers depend on. Re-parsing locally would have been the smaller edit and is the defect this migration exists to remove, so a reader whose policy differs holds that policy in a line or two rather than reaching for a parser of its own.

The base outputs were recorded before any edit, at 142cdf05, by exercising each reader through the door it already exposed over one shared input list — aware ISO, Z-suffixed, naive, date-only, epoch number, empty string, None, a non-string object, and garbage text. Those readings are the expectations of tests/test_timestamp_callers_batch_b.py, which asserts every migrated reader still produces the output it had; a raised exception is recorded by its type and message. The five modules this node touched are byte-identical between 142cdf05 and the worktree base a15e11cb, the parent of the migration commit, so the two base revisions give the same readings.

Four of the six readers preserve every recorded cell. One does not. sprint_liveness._observed_seconds read a naive string as local time through .timestamp(), so its reading depended on the host timezone the node ran under; parse_utc reads a naive value as UTC. Four cells move — the naive and date-only strings, an epoch number the C parser rejected with TypeError, and a non-string object — and each is named in the test beside its base reading and the reason the unified rule replaces it. In production the value is always Z-suffixed, written by the runs and fleet-supervisor producers, so the change is invisible to every live caller; the difference is the timezone-independence the migration buys.

The sixth reader is a hook that runs outside the package. reckon/hooks/worker_stop.py is registered as its own file path and launched by its shebang, so its process carries no sys.path entry for the checkout. A module-scope import of the shared parser broke that launch with ModuleNotFoundError, which surfaced as the hook writing empty stdout and its own test failing to parse it. The import now sits inside the one function that needs it, with a sys.path bootstrap from the file's own location that runs only when the module is not imported as a package, so an ordinary import is untouched and the bare-script launch still resolves the shared parser.
