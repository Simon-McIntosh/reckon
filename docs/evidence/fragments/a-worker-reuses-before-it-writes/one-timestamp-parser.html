One timestamp parser -- evidence

A new primitive module reckon/_timestamps.py with one function parse_utc(value), its behaviour fixed by tests/test_timestamps_parse_utc.py before any caller migrates, and every caller of fromisoformat under reckon/ grouped into migration batches disjoint from each other and from every live run's path claims. No caller is migrated in this node.

The behaviour the tests fix

  • A Z suffix and an explicit numeric offset both return an aware UTC datetime, asserted with a positive and a negative offset that normalise to the same instant.
  • A naive value is read as UTC.
  • A numeric epoch in seconds and one in milliseconds are both read, told apart by magnitude split at 1e11, the threshold stated in the module docstring.
  • Malformed input returns None rather than raising.

Evidence arms: the base arm at a928b6be fails with ModuleNotFoundError: No module named 'reckon._timestamps' exit 2 (base-arm.log); the head arm at the committed head is 15 passed exit 0 (head-arm.log); the declared negative control (read a naive value as local time) fires the naive case red and is reverted.
