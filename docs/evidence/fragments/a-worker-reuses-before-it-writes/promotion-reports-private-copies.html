§4 — a copy is visible at promotion

reckon/clones.py ports the review census's six-line normalised clone detector — whitespace, comments, docstrings and layout dropped, string and number literals collapsed to token kinds, identifiers and operators kept — and matches each window a run's added or modified function owns against every function in reckon/ and tests/ at the promoted revision. Nothing in reckon/ imports from docs/: the detector was ported rather than imported.

Promotion reads the base and promoted revisions from git (reckon.clones.promotion_clone_matches), feeds the result to ledger.build_record under the declared field clone_matches, and lands the row. Each match records the run's function and the existing function it copies, both with file:line. The report warns and never refuses. A run the detector ran over carries the list of matches, empty when none; a run with no revision pair to compare — a shadow, a commitless report, or an unreadable archive — carries the marker {"status": "unmeasured", "reason": …}, so a measured run that copied nothing and a run never measured do not read alike. The key is present on every row, as the ledger's RECORD_FIELDS contract requires.

tests/test_promotion_reports_clones.py promotes three synthesised runs. One adds a private copy of reckon/_timestamps.py:parse_utc; the row's clone_matches names that function's file and its ast-derived line. A second adds an unrelated function; the row's clone_matches is []. A third promotes a commitless report with no revision pair; its clone_matches is the unmeasured marker, not [].
