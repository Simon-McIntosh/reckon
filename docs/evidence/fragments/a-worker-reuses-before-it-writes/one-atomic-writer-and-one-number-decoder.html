One atomic writer and one numeric decoder — evidence

reckon/_store.py gains write_json_atomically beside its envelope writer, and a new module reckon/_observations.py provides optional_number. Their behaviour is fixed by tests/test_one_atomic_writer_and_number_decoder.py before any caller migrates. The manifest lists the fourteen atomic-JSON writers and the four numeric-decoder bodies found at main HEAD, each with the durability and locking its migration must keep. No caller is migrated in this node.

The behaviour the tests fix

  • No stray temporary. A write whose serialisation raises leaves the destination byte-for-byte as it was and no sibling temporary behind: the scratch directory holds the target and nothing else.
  • No interleaving. Two threads each write a 4,000-element payload forty times; every read observes one whole payload, never a blend, and the file is readable throughout.
  • The flush is under the caller's control. fsync is called once by default and never when the caller passes fsync=False.
  • The decoder refuses the flag. optional_number returns None for True, False, a string, None, a list and a dict, and a float for an int and a float. The bool case is the point: True is an int subclass and would otherwise decode to 1.0, leaving a flag and a measurement indistinguishable.

Reuse, not a copy. The envelope writer's temporary-write-and-rename step is factored into _write_through_sibling_temporary; write_json_atomically calls that same helper rather than repeating the atomic move. The envelope writer's own body shrinks to building the envelope and handing a renderer to the helper, so the two cannot drift apart.

Evidence arms. Base arm at a928b6be: the primitives are absent, so collection fails — ModuleNotFoundError: No module named 'reckon._observations', exit 2 (base-arm.log). The fourteen writers, and what each migration must keep

Found by AST over the code-depth census's list (docs/research/data/crew-pattern-review/code-depth/findings.md, copies at census commit 056c08e0), re-grounded per def at main HEAD a928b6be. The census pins its line numbers at the older commit; the symbol names below are what git grep resolves today. Three copies flush with fsync, seven clean up their temporary on failure, and one takes a lock — each row is a durability or concurrency guarantee the migration must carry forward, and none may be silently dropped.

  • reckon/_store.py:_write_json_envelope — the envelope writer itself: unique sibling temporary through _write_through_sibling_temporary, removal on failure, fsync on by default, and the in-process _json_envelope_lock(path). This is the writer write_json_atomically now shares a rename step with.
  • reckon/capabilities.py:rebuild_capabilities — fixed sibling <name>.tmp written with write_text, no cleanup, no fsync, no lock.
  • reckon/crew/dispatch.py:_supervisor_write — unique NamedTemporaryFile, unlink in finally, fsync before rename, no lock.
  • reckon/crew/fleet_supervisor.py:_write_json — mkstemp sibling with a unique name, unlink on failure, no fsync, no lock.
  • reckon/crew/paid_lanes.py:write_document_atomically — unique NamedTemporaryFile, removes the pending path on failure, no fsync, no lock.
  • reckon/crew/placement.py:publish_reservation — pid-named sibling <name>.<pid>.tmp, no cleanup on failure, no fsync, no lock.
  • reckon/crew/plan_review.py:store_plan_review — fixed sibling .<name>.tmp, no cleanup, no fsync, no lock.
  • reckon/crew/resumption.py:_write_lane_probe_cache — pid-named sibling, no cleanup, no fsync, no lock.
  • reckon/crew/review.py:store_review — delegates to reckon/crew/review.py:_write_record, a fixed sibling .<name>.tmp with no cleanup, no fsync, no lock.
  • reckon/crew/runs.py:_write_json — unique NamedTemporaryFile, unlink in finally, fsync before rename, no lock.
  • reckon/resources.py:migrate_typed_layout — a mkdtemp staging directory with rmtree in finally; no fsync, no lock. It moves non-JSON files too, so it is not replaced wholesale.
  • reckon/serve.py:_store_git_creation_cache — unique NamedTemporaryFile, unlink() in finally, no fsync, no lock.
  • reckon/serve.py:_store_git_last_modified_cache — same shape as the creation-cache writer: unlink() in finally, no fsync, no lock.
  • reckon/serve.py:Handler._handle_post — fixed sibling <out_file>.json.tmp, no cleanup, no fsync, no lock.

Two of the fourteen — migrate_typed_layout and Handler._handle_post — mix the JSON write into a larger operation (a layout move, an HTTP response write). Each is a caller the primitive can be introduced into without changing the surrounding operation.

The four decoder bodies

Four differently named functions carry exactly the same body at HEAD: reject bool and anything that is not an int or float, otherwise return float(value). reckon/_observations.py:optional_number is their one home; each caller keeps only the name its local vocabulary expects.

  • reckon/_backends.py:_number — also feeds _seconds, which rounds the result; the rounding stays at the caller.
  • reckon/crew/carryover_census.py:_measured — feeds _median over the non-None values.
  • reckon/crew/hold.py:_as_number — the hold age read from a lane document.
  • reckon/crew/window_reading.py:_numeric — a window reading's own numeric field.

No caller is migrated here. Each migration is a one-line import swap that keeps the caller's name, so it can proceed independently of the others.

What this node did and did not do

Landed: reckon/_store.py (the shared helper and write_json_atomically), reckon/_observations.py, and tests/test_one_atomic_writer_and_number_decoder.py. Not landed here: any caller migration, and the mutation of the fourteen writers and four decoders onto the new primitives. That is the handoff the inventory above supports, and it is what the follow-on nodes carry. This node's gate measures only its own change; verifying the merged result belongs to a separately dispatched test node.
