One atomic writer and one numeric decoder — evidence

reckon/_store.py gains write_json_atomically beside its envelope writer, and a new module reckon/_observations.py provides optional_number. Their behaviour is fixed by tests/test_one_atomic_writer_and_number_decoder.py before any caller migrates. The manifest lists the sixteen atomic-JSON writers re-derived mechanically at the base revision, and the four numeric-decoder bodies found at main HEAD, each with the durability and locking its migration must keep. No caller is migrated in this node.

The behaviour the tests fix

  • No stray temporary. A write whose serialisation raises leaves the destination byte-for-byte as it was and no sibling temporary behind: the scratch directory holds the target and nothing else.
  • No interleaving. Two threads each write a 4,000-element payload forty times; every read-back is asserted to equal one of the two complete payloads, so the other writer's whole payload landing between this write and this read is accepted while only a genuine blend fails. The check compares against both payloads rather than the writer's own, which is what the earlier form got wrong: it reddened one run in twelve when a complete payload from the other thread was simply the newer one.
  • The flush is under the caller's control. fsync is called once by default and never when the caller passes fsync=False.
  • The decoder refuses the flag. optional_number returns None for True, False, a string, None, a list and a dict, and a float for an int and a float. The bool case is the point: True is an int subclass and would otherwise decode to 1.0, leaving a flag and a measurement indistinguishable.

Reuse, not a copy. The envelope writer's temporary-write-and-rename step is factored into _write_through_sibling_temporary; write_json_atomically calls that same helper rather than repeating the atomic move. The envelope writer's own body shrinks to building the envelope and handing a renderer to the helper, so the two cannot drift apart.

The sixteen writers, and what each migration must keep

The starting list is the code-depth census's clone group (docs/research/data/crew-pattern-review/code-depth/findings.md, copies at census commit 056c08e0), which counts repeated six-line windows and so counts clones, not the writer population. Re-derived mechanically at the base revision a928b6be with git grep for a rename-into-place call joined to a JSON serialization — git grep -n -E 'os\.(replace|rename)\(' a928b6be -- reckon returns 13 sites and git grep -n -E 'json\.dump\b' a928b6be -- reckon returns 6, and joining both per enclosing definition (which the mention of os.replace alone misses, because most copies move a temporary with Path.replace) yields the population below. That join found two writers the census's window comparison did not group: reckon/_backends.py:_write_private_json and reckon/cli.py:_write_json_atomically, both real atomic JSON writers whose bodies differ enough from the group to fall outside a six-line window. The census pins its line numbers at the older commit; the symbol names below are what git grep resolves at the base. Three copies flush with fsync, ten remove their temporary on failure, and one takes a lock — each row is a durability or concurrency guarantee the migration must carry forward, and none may be silently dropped.

  • reckon/_backends.py:_write_private_json — a pid-named sibling opened O_CREAT|O_EXCL at 0o600, written with json.dumps bytes, moved with os.replace, unlinked on any failure, no fsync, no lock. Its migration must keep the parts the primitive does not carry: bytes rather than text, O_EXCL so a stale sibling is an error rather than silently overwritten, and the explicit final chmod that narrows the destination to the caller's ceiling (the primitive leaves the temporary's 0o600 in place, which is the same or narrower, so this last step is a no-op for the operator's own file).
  • reckon/_store.py:_write_json_envelope — the envelope writer itself: unique sibling temporary through _write_through_sibling_temporary, removal on failure, fsync on by default, and the in-process _json_envelope_lock(path). This is the writer write_json_atomically now shares a rename step with.
  • reckon/cli.py:_write_json_atomically — a unique .{name}.reckon-{pid}-{ns} sibling written as bytes with a preserved mode, moved with os.replace, unlinked on an OSError; no fsync, no lock. Its migration must keep the optimistic-concurrency guard the primitive does not carry: the original bytes are re-read before the replace and a changed file is refused rather than overwritten.
  • reckon/capabilities.py:rebuild_capabilities — fixed sibling <name>.tmp written with write_text, no cleanup, no fsync, no lock.
  • reckon/crew/dispatch.py:_supervisor_write — unique NamedTemporaryFile, unlink in finally, fsync before rename, no lock.
  • reckon/crew/fleet_supervisor.py:_write_json — mkstemp sibling with a unique name, unlink on failure, no fsync, no lock.
  • reckon/crew/paid_lanes.py:write_document_atomically — unique NamedTemporaryFile, removes the pending path on failure, no fsync, no lock.
  • reckon/crew/placement.py:publish_reservation — pid-named sibling <name>.<pid>.tmp, no cleanup on failure, no fsync, no lock.
  • reckon/crew/plan_review.py:store_plan_review — fixed sibling .<name>.tmp, no cleanup, no fsync, no lock.
  • reckon/crew/resumption.py:_write_lane_probe_cache — pid-named sibling, no cleanup, no fsync, no lock.
  • reckon/crew/review.py:store_review — delegates to reckon/crew/review.py:_write_record, a fixed sibling .<name>.tmp with no cleanup, no fsync, no lock.
  • reckon/crew/runs.py:_write_json — unique NamedTemporaryFile, unlink in finally, fsync before rename, no lock.
  • reckon/resources.py:migrate_typed_layout — a mkdtemp staging directory with rmtree in finally; no fsync, no lock. It moves non-JSON files too, so it is not replaced wholesale.
  • reckon/serve.py:_store_git_creation_cache — unique NamedTemporaryFile, unlink() in finally, no fsync, no lock.
  • reckon/serve.py:_store_git_last_modified_cache — same shape as the creation-cache writer: unlink() in finally, no fsync, no lock.
  • reckon/serve.py:Handler._handle_post — fixed sibling <out_file>.json.tmp, no cleanup, no fsync, no lock.

Two of the sixteen — migrate_typed_layout and Handler._handle_post — mix the JSON write into a larger operation (a layout move, an HTTP response write). Each is a caller the primitive can be introduced into without changing the surrounding operation.

The four decoder bodies

Four differently named functions carry exactly the same body at HEAD: reject bool and anything that is not an int or float, otherwise return float(value). reckon/_observations.py:optional_number is their one home; each caller keeps only the name its local vocabulary expects.

  • reckon/_backends.py:_number — also feeds _seconds, which rounds the result; the rounding stays at the caller.
  • reckon/crew/carryover_census.py:_measured — feeds _median over the non-None values.
  • reckon/crew/hold.py:_as_number — the hold age read from a lane document.
  • reckon/crew/window_reading.py:_numeric — a window reading's own numeric field.

No caller is migrated here. Each migration is a one-line import swap that keeps the caller's name, so it can proceed independently of the others.

What this node did and did not do

Landed: reckon/_store.py (the shared helper and write_json_atomically), reckon/_observations.py, and tests/test_one_atomic_writer_and_number_decoder.py. Not landed here: any caller migration, and the mutation of the sixteen writers and four decoders onto the new primitives. That is the handoff the inventory above supports, and it is what the follow-on nodes carry. This node's gate measures only its own change; verifying the merged result belongs to a separately dispatched test node.
