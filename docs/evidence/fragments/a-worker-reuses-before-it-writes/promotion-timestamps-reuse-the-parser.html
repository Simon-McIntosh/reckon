promotion-timestamps-reuse-the-parser — three promotion readers onto the shared parser

Three timestamp readers in reckon/crew/promotion.py no longer parse fromisoformat themselves. _elapsed_seconds reads reckon._timestamps.parse_utc and keeps its own elapsed policy (two workers' producer bound to one reference pair and a clamp at zero seconds). _assume_utc_if_naive reads parse_iso and keeps its display policy (a stamp that names no zone is rewritten with a trailing Z, anything else is returned as written). The stream-event loop inside _terminal_stream_data is now a named helper, _zone_aware_stream_timestamp, which reads parse_iso and keeps only stamps that name a zone, so the span is decided in one place rather than inline. After the change grep -c fromisoformat over the module is zero; the new test also asserts it by walking the module's AST.

One recorded difference, deliberate and stated in the test. _assume_utc_if_naive called value.replace at base, so a numeric value raised AttributeError: 'int' object has no attribute 'replace'. Routed through parse_iso, whose non-string miss returns None, the reader now returns the value unchanged — the same policy it already applied to a string it could not parse. No caller reaches it: the one caller guards the stamp before the call.
