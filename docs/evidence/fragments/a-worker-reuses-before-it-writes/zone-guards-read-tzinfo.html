Zone guards read the parsed tzinfo — evidence

Three defects are repaired by test against the pre-migration base outputs. Two callers decided whether a stamp named a zone from the text's shape, so every offset spelling the shared parser accepts but the regex did not match — +00, -05, +000000 — read as naming no zone. The shared writer removed its sibling temporary on a failed os.chmod but not on a failed os.fdopen, leaving the file the open had created on disk. And the hook installer escaped a non-ASCII script path that the pre-wave writer had written literally.

The defects and their repairs

The offset spellings read as zoneless. row_moment and _parse_cached_fetch_stamp each tested the text with re.compile(r"(?:Z|[+-]\d{2}:?\d{2}(?::\d{2})?)$"). The pattern needs four or six digits in the offset, so the spellings datetime.fromisoformat accepts but it did not — +00, -05, +000000 — matched nothing. Under TZ=Europe/Paris with the summer stamp 2026-07-01T00:00:00-05, the base 92274925 returned 1782874800 from row_moment — a 7200 s shift from the instant the offset names — and None from the cache reader. The zone is now read from the parsed result’s tzinfo through reckon/_timestamps.py:parse_iso, the zone-preserving view of the shared parser; both return the aware instant the pre-migration base cea6da07 returned (datetime.fromisoformat(text).timestamp()). The cache reader keeps its strict spelling rule, refusing a lowercase z that parse_iso normalises to a zero offset, because the recorded migration contract holds lowercase_z → None.

The leaked temporary on a failed fdopen. _open_sibling_temporary creates a unique sibling with os.open, chmods it, then os.fdopens it. When the fdopen raised, the base closed nothing and removed nothing: the file os.open created stayed on disk, and the caller’s finally could not reach it because _open_sibling_temporary never returned. Reproduced before the repair by patching reckon._store.os.fdopen to raise, leaving .dest.json.<pid>.<hex>.tmp beside an untouched destination. Every failure after the temporary exists now closes the descriptor and unlinks the candidate before re-raising.

The escaped non-ASCII settings path. The second writer wave routed hooks.install._write_settings through write_json_atomically, whose json.dump defaulted to ensure_ascii=True, so a hook-script path with non-ASCII characters landed as \uXXXX escapes rather than literal bytes. write_json_atomically gains an ensure_ascii keyword defaulting on; the installer passes False, restoring the literal bytes the pre-wave writer produced and matching _render, which already printed with ensure_ascii=False.

Scope note

The zone decision needs a view of the shared parser that keeps a zoneless string naive, so the caller can tell a stamp that states its zone from one that does not. parse_utc normalises a zoneless value to UTC and discards that distinction; parse_iso, already present beside it in reckon/_timestamps.py, keeps it and is what both callers now read. The lowercase-z strictness the fixed cache reader keeps is a caller policy, not a zone test: the shared parser deliberately reads z as a zero offset, so the reader refuses the spelling itself.
