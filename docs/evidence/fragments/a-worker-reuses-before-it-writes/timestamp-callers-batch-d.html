Eleven deferred timestamp readers share one parser

The deferred readers left after the first migration wave each parsed a timestamp with their own fromisoformat call. All eleven now read through reckon._timestamps.parse_utc, and every one reproduces the output it produced at base cea6da07 for all sixteen recorded inputs. One reader is a retained exception, named with its reason.

The recorded table

One shared sixteen-input list was run through the base code at cea6da07, and every cell below is that run's output. A raised exception is recorded by its type. The clock is frozen for the callers that age a stamp against now, so their cells are values rather than the moment of reading. The gate asserts the migrated callers reproduce this table cell by cell.

Three shapes are separated by the table that a single parser would otherwise blur. A stamp padded with whitespace or suffixed with a lowercase z is refused by most readers and must stay refused, because parse_utc strips whitespace and accepts a lowercase zone marker. A bare calendar date carries no hour, and readers disagree about whether it is a stamp at all: the cli follower places such a row at the moment of reading, while flight and serve read it as midnight. A stamp naming an offset of its own is normalised to UTC by parse_utc, so a reader whose value renders in the written zone cannot use the shared result unchanged.

The retained exception

One reader keeps its own parser, and the gate names it:

  • ledger._parse_timestamp — returns the moment in the zone the stamp was written in, which the ledger compares and renders; the shared parser normalises every zone to UTC, which would change what a stamp carrying an offset of its own resolves to. Its cells for the offset-with-seconds and near-midnight stamps show the difference: base returns 2026-09-29T01:02:03+00:00:30 and 2024-03-05T00:30:00+02:00, where the shared parser resolves the same instants in +00:00.

An ast walk over the six touched modules collects every function that still calls fromisoformat and asserts the set is exactly that one name, so a later reimplementation inside one of these modules fails the gate.
