Batch A — thirteen crew readers on one parser

Thirteen timestamp readers in reckon/crew/ no longer parse timestamps themselves: each now calls reckon._timestamps.parse_utc and keeps only the policy around the call that its own callers depend on. A second parser would have been the smaller local edit and the defect the migration exists to remove, so a reader whose policy differs holds that policy in a line or two rather than re-parsing.

The base outputs were recorded before any edit, at 142cdf05 (the caller files are byte-identical at a15e11cb, the revision the base-arm log records), by exercising each reader through the door it already exposed over one shared input list — aware ISO, Z-suffixed, naive, space-separated zoned, space-separated naive, date-only, epoch number, empty string, None, a non-string object, and garbage text. Those readings are the expectations of tests/test_timestamp_callers_batch_a.py, which asserts every migrated reader still produces the output it had. A datetime is recorded as the instant it names and whether it is zone-aware: the wall offset a value carries cannot survive a parse_utc migration without a second parser, and the eleven normalising readers compare equal as instants either way.

Two readers keep a policy, and a third carried a defect the migration exposed. query._normalize_stamp still reports a zoneless value as unknown rather than adopting parse_utc's naive → UTC reading — a stamp with no zone is not evidence of when a run happened. rollout._parse_timestamp still returns a naive stamp unchanged. Both decide whether a stamp names a zone from its trailing offset designator, so the separator between date and time is irrelevant: 2026-09-29 01:02:03+00:00, which ISO 8601 permits, is normalised exactly as the T-separated form is. lane_evidence._moment raised on any naive stamp at base, because it referenced datetime.UTC on the class rather than the module:

AttributeError: type object 'datetime.datetime' has no attribute 'UTC'
reckon/crew/lane_evidence.py:209

The migration repairs that by routing the stamp through parse_utc; the recorded output for its naive, space-separated naive and date-only cells is the corrected UTC instant, marked as a delta above the row. No private helper was left without a caller, so none was removed.
