One recorded difference, deliberate and stated in the test. follow_checkpoint.write's compact record carried no trailing newline; the shared writer terminates every document with one. The document is byte-identical and the added byte is the only change to any recorded output. Every other caller reproduced its recorded bytes, permission bits and fsync behaviour under the umask the test sets and restores.

  • Retained exception — the pane's history. follow_checkpoint._replace_atomically writes a log of JSON lines rewritten as a whole file, which one commit of the document-oriented writer cannot express (it emits exactly one JSON value plus a newline). append_history appends one line per row and rewrites through that helper only once the log has outgrown its cap, so a rewrite here would put a whole-file write and three fsyncs on the path of every line the reader waits for.
  • Retained exception — rendered HTML. project_state's typed resources are HTML, which the JSON writer cannot express; the HTML branch of _write_resource_unlocked and the transactional restore path keep their temporary-and-durable-replace.
  • One non-ASCII caveat, not a defect at the recorded input. hooks.install._write_settings serialised with ensure_ascii=False; the shared writer does not parameterise ensure_ascii and so emits ASCII escapes. The recorded ASCII payload reproduces byte-for-byte; a non-ASCII hook script path would now be escaped rather than literal. Recorded as a follow-on rather than widened in this node's scope.
