The run-time profile's completion-stamp read routes through the shared parser

The post-migration census counted reckon/crew/run_time_profile.py:_completed_after among the functions still calling datetime.fromisoformat directly with no comment stating why. It is not retained: it now reads its stamp through reckon/_timestamps.py:parse_utc, the repository's one timestamp parser, so a stamp read here and the same stamp read in the ledger cannot resolve to different moments. The rule the function already carried is kept — a stamp the parser cannot read is not evidence the row falls outside the window, so the row is left in rather than dropped, and only a string is accepted, the shape the ledger writes.

tests/test_run_time_profile_parses_through_the_shared_home.py pins _completed_after against a behaviour table recorded at the base revision. Every row resolves identically at base and at head:
