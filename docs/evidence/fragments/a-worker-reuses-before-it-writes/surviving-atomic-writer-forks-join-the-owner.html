The surviving atomic-writer forks join the owner

The forks

The atomic-publish core survived at three levels beside _store.write_json_atomically: project_state._durable_replace with a byte-identical _fsync_directory (five call sites), follow_checkpoint._replace_atomically, and three .html.tmp write-then-replace paths inside _store itself. Each kept its own temporary-and-rename beside the primitive that already did the job.

What changed

  1. The private _store._write_through_sibling_temporary is promoted to the public write_atomically, keeping its signature and gaining one keyword, binary, which opens the sibling temporary in binary mode and hands the render callback a binary handle. write_json_atomically stays the JSON adapter over it.
  2. The three _store HTML writers (the evidence-append path and the two plan writers) render their document through write_atomically.
  3. project_state's five call sites become calls to write_atomically: the typed-resource HTML branch and the staged-install branch render text, and the three recovery sites render bytes with binary=True. The duplicated _fsync_directory and the retired _durable_replace/_fsync_file are deleted in favour of the owner's.
  4. follow_checkpoint.append_history renders its line log through write_atomically; _replace_atomically is deleted.

No new function is added to project_state or follow_checkpoint.
