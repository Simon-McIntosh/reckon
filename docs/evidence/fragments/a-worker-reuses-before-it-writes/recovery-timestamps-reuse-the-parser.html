recovery-timestamps-reuse-the-parser — six readers join the shared parser

The six timestamp readers in reckon/crew/recovery.py — _budget_timing, _worker_launched_after_manifest, _attempt_started_seconds, _manifest_wait, _run_chain_manifest_freshness and _seconds_since_dispatch — now resolve their stamps through reckon._timestamps.parse_utc. No datetime.fromisoformat call remains in the module.

The change is a substitution, not a behaviour change. Every reader kept the str coercion and the naive-as-UTC rule it already had, so the only thing replaced is the parser call itself. The base revision's functions were driven over one shared six-input list (a Z stamp, an offset stamp, a naive stamp, an empty string, a malformed string and a non-string value) and the table captured; 36 of 36 cells agree between base and head, so no reader moves on any recorded input and there is no retained exception to name.

tests/test_recovery_timestamps_reuse_the_parser.py holds that table per reader and asserts it at head (39 tests: 36 cells plus a no-fromisoformat AST check, a table-coverage check and an import check). It turns red under the declared mutation — making _seconds_since_dispatch return None for an offset stamp fails exactly the offset row of its table.
