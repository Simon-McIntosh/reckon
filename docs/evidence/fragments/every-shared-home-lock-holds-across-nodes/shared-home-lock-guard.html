A guard refuses any bare flock that is neither judged nor pending

tests/test_every_shared_home_lock_holds_across_nodes.py walks every Python module under reckon/, collects each flock call that asks for a lock rather than releasing one (a bare flock, or one whose operation is not LOCK_UN), and keys it by file and qualified enclosing function. The qualified name comes from reckon/interface_counts.py's definitions walker, so a method keys as Class.method and a nested function as outer.inner exactly as the interface census names them; there is no second name resolver. The module set is the union of read_trees' revision listing and the working tree, read in the working tree's own bytes, so an uncommitted lock is caught by the same assertion as a committed one.

Each site must appear in exactly one of two tables. The judged table carries 21 keys covering 24 lock-taking calls, each with the mechanism that makes it safe on one host: the lock file and what it guards exist only on this host, the producer host lease decides the foreign-host case, the renewed follower lease decides it, or the call is the same-node half of the cross-node lock. The pending table carries the 21 shared-home sites that have not moved yet, including reckon/compliance.py::_locked, reckon/crew/runs.py::_pointer_lock and reckon/crew/picker/outcomes.py::record_picker_hold. No site was migrated here: the census at the delivered head reads 42 keys and 45 calls, of which 24 calls are judged and 21 are pending.

The guard has three failures, each naming reckon.node_exclusive_lock.exclusive_lock as the remedy where a site is unjudged: a site in neither table, a table entry with no lock-taking call left, and an entry in both tables. One further test asserts the walk itself sees something known present, so an empty census reads as an instrument failure rather than as a clean tree.

Three negative controls are logged in the run directory, each a genuine failing run of the real test rather than an assertion about the guard: negative-control-1-scratch-module.log points the guard at a scratch tree holding one module with a bare flock and it fails naming ['reckon/fresh.py::write_shared']; negative-control-2-deleted-judged-entry.log removes the judged entry for reckon/crew/watch_unit.py::watch_state from a copy of the test and it fails naming that site; negative-control-3-stale-entry.log adds a pending entry for reckon/crew/runs.py::no_flock_here and it fails naming that stale entry. Each log ends in a bare EXIT=1.

The guard is declared in docs/state/reckon/flight.yaml under gates.census_tests beside the staged-write inventory. Composed through promotion_records._scoped_suite_command for a node writing product source, the scoped gate command reads PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_staged_write_inventory.py tests/test_every_shared_home_lock_holds_across_nodes.py, and a node writing only docs composes an empty command — so the guard runs in every product-source node's gate, not only in a full-suite run.

The baseline arm resolved over the base tree carries the inventory test alone (51 passed, EXIT=0); the after arm at this head carries both (55 passed in 32.26s, EXIT=0). The new file passes ruff check and ruff format --check.
