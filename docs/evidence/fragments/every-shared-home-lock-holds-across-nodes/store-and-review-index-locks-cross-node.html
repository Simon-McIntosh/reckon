The store, compliance, review-index and peer-index locks exclude across nodes

Four shared-home locks moved from fcntl.flock onto reckon.node_exclusive_lock.exclusive_lock, whose POSIX record lock the file server holds across nodes: reckon/_store.py::_serialized_path_lock, reckon/compliance.py::_locked, reckon/crew/review_records.py::_index_lock and reckon/crew/dispatch_peer.py::_update_peer_index. The store and compliance helpers keep only the lock-path derivation (_lock_path is the new name in compliance); the review index lock still yields False when the lock cannot be taken and None for a reader whose non-blocking take finds a holder. The guard's pending table drops the four rows.

At the delivered head both pass; at base 65431adf17, where the sites take only flock, both fail because the record lock is invisible to them.
