Lane, budget and picker locks exclude across nodes

Five shared-home lock sites took reckon.node_exclusive_lock.exclusive_lock, whose POSIX record lock the file server holds, in place of a bare flock, which the local kernel grants and a second node therefore never sees: budget_reset._locked, model_catalogue._refresh_lock, paid_lanes.refresh_reserved_window, paid_lanes.publish_document and picker.outcomes.record_picker_hold. Each keeps the answer its callers already received: no call site changed.

The banked-reset flag drops its module-level threading.RLock, because exclusive_lock holds a process-local lock per path before it opens the file, so two threads of one process are excluded exactly as before and a nested call from one thread would deadlock no matter which lock came first — the module makes no nested call. The catalogue refresh keeps its non-blocking take: a refresh that cannot take the lock yields False and check_model_catalogue returns _read_snapshot(), so a producer that loses the race reads the snapshot on disk instead of fetching. The picker's holds log no longer locks the file it appends to; it takes its lock on picker-holds.jsonl.lock, because closing any descriptor for a record-locked file drops the record lock, so the log being appended to cannot itself be the lock.

Each of the four lock files is opened under reckon/ only through exclusive_lock. The audit log lock-path-audit.log in the run directory shows the four constructions — budget-resets.json.lock at budget_reset.py:94 and the with_name(... + ".lock") forms in the other three — beside every open() in those modules: the picker's path.open("a") appends to the log, and paid_lanes' three opens read the lane document and a stream. No other module in reckon/ names a lock path for any of the four, and nothing globs their directories, so no second opener exists to drop a migrated lock mid-body.

The guard's pending table drops exactly these five rows (reckon/crew/budget_reset.py::_locked, reckon/crew/model_catalogue.py::_refresh_lock, reckon/crew/paid_lanes.py::publish_document, reckon/crew/paid_lanes.py::refresh_reserved_window, reckon/crew/picker/outcomes.py::record_picker_hold); the migrated calls no longer take a bare flock, so the second assertion would name any row left behind.

tests/test_lane_and_picker_locks_hold_across_nodes.py holds each lock from a second process with fcntl.lockf only — never flock — which is the half GPFS holds across nodes. A hold recorded in a thread while the picker's lock is held does not reach the log (_log_lines(log_path) == [], asserted against a log that the released hold then fills with exactly one line) and lands as one whole JSON line once the holder releases. A catalogue refresh while the record lock is held calls its fetch zero times and returns the snapshot already on disk; the same call on the free lock fetches once and returns the new models, which is the control that the fetch this test watches for can be seen to happen.

The negative control is the same test file run against 65431adf17b56c3a1fb04f32971d7729e4108dcc, where neither site waits on a record lock. Both cases fail there, on the assertion each exists to make: AssertionError: the hold did not wait for the record-lock holder and AssertionError: the refresh fetched while a record-lock holder held (assert ['https://lis...valid/models'] == []). The run is negative-control-base.log in the run directory, ending 2 failed and EXIT=1.
