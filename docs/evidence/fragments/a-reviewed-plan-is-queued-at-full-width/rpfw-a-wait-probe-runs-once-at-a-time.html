A wait probe is evaluated by one reader at a time

A waiting run's probe was run by whoever polled the wait, so a probe reading a large store ran once per poller. On 22 November 2026 nine copies of one probe held a 1.16 GB store open and every promotion on the node failed on its database lock. At the pinned base c37ee57, ten readers of one wait started the probe ten times — logged in the run directory's negative-control-reproduction.log, reading probe runs started by ten readers: 10.

Every reader now goes through reckon/crew/recovery_wait.py's run_wait_probe, which holds one result per (run, probe) under the crew home behind the cross-node record lock. A reader inside WAIT_PROBE_INTERVAL_SECONDS (30) is handed the last result; a reader arriving while a run is in flight waits for it instead of starting another; a run past WAIT_PROBE_RUN_BOUND_SECONDS (60) is killed with its process group and recorded as one duty of kind run-wait-probe-stopped naming the run and the vector. The classifier's reader and the sweep's reader both use the gate, and the obligations view surfaces the recorded duty.

Measured

  • The declared negative control, executed and logged. At the pinned base with this node's test file copied into a scratch tree built from that revision, the first case fails and closes EXIT=1 (negative-control.log). The same ten-reader scenario run through the base reader starts the probe ten times; run through the head it starts it once (negative-control-reproduction.log and -head.log).
  • The interval arm. Ten threads reading one wait inside a barrier start the probe once and all ten are handed its line, and a probe still running when the interval comes round is not started again.
  • The bound arm, at the real sixty seconds. A probe sleeping ninety seconds is stopped after the sixty-second bound, its pid is gone from the process table, and one recorded duty names the run and the vector. The classifier's reader reports the stopped probe, answered=False, from the same recorded result without running it again.
  • The gate and its arms. The scoped gate at dd0d3bf3 ran 63 passed in 102.73s (0:01:42) with EXIT=0. The baseline arm at c37ee57 reported 58 passed in 41.20s and the after arm at dd0d3bf3 reported 63 passed in 99.44s (0:01:39), both EXIT=0: the five added passes are this node's cases and the after arm adds no failure id.
