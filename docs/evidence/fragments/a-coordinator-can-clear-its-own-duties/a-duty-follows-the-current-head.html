An obligation follows the run's current head

What changed. A resume carries a stopped run forward from the revision it delivered, so every duty that reads against that revision — its missing review, its stale review, the promotion behind either — speaks for work the run has moved past. The run's pointer now records that revision under resume_superseded_head, with the instant the resume happened, and four sites key on it:

  • reckon/crew/resumption.py — _record_resume_supersedes_head stamps the head the resume leaves behind from the run's own tree, called from _resume after the new attempt is recorded, so every resume the system performs records it: the hand-typed crew resume, the --reopen form and the sweep's automatic lift all pass through the one launcher. It records nothing when the tree yields no head, because a slot keyed on an empty head would withdraw duties of every kind rather than the superseded one.
  • reckon/crew/recovery_review_dispatch.py — supersedes_head is the reader, and withdraw_superseded_review now takes its trigger from the newest resume the run records rather than from the sweep's own auto_resume slot alone. A queued attempt that never spawned a worker is now discarded as well as recorded: the withdrawal text is written onto the review's own departure marker through _discard_stranded_review, so the lane has nothing left to launch for the head the resume replaced — previously the withdrawal was recorded on the reviewed run while the queued review's pointer still stood and was launched by the first admission to reach it. A review whose worker already launched is untouched: it finishes and its verdict carries forward.
  • reckon/crew/recovery_review_dispatch.py — _resume_superseded_refusal is the reflex's own arm: it refuses to compose a review for a head the run's own resume replaced, recorded on the run as withdrawn. This is the race the plan's §1 reports, where the reflex queued a review for a head the coordinator was about to replace.
  • reckon/crew/obligations.py — _review_duty_item returns nothing for a run that still carries the head its resume superseded, so review-missing, promotable-stale and every other kind this reader derives are withheld until the run delivers a head of its own. The duty returns at the new head because the comparison is against the recorded revision, not against the resume instant.

Measure. tests/test_a_duty_follows_the_current_head.py, four cases over a real git history: a complete run owing a review is resumed and its obligations list nothing for the head the resume replaced; the same run, delivered on to a new head, owes review-missing naming that new head; a review queued before the resume is withdrawn, recorded as superseded by that resume, and its pointer discarded; and a run nobody resumed keeps its review-missing duty at its delivered head, which is the control.

Repair: the slice that read a duty the derivation withholds

What the review found. The withdrawal lives in the derivation's review-duty reader, which now returns nothing for a run carrying the head its resume replaced. The snapshot module holds no derivation but reaches that reader, and payload_for in reckon/crew/obligation_snapshot.py appended its result without checking it, so one resumed run put None in the duty list and _partition_acknowledged raised on it — an AttributeError: 'NoneType' object has no attribute 'get'. The sweep reports a failure per session, so the cost was the whole session's snapshot, and it surfaced only as a producer that stopped publishing rather than as an error a reader would see.

The fix, and the two cases asked for. The slice skips an absent duty the way the derivation's own caller does. tests/test_obligations_snapshot_is_published.py publishes the snapshot for a session holding a resumed run and asserts the sweep succeeded, that nothing on stderr named a sweep failure, that no duty names the superseded head, and that the slice still equals the derivation. tests/test_a_duty_follows_the_current_head.py drives the reflex's own refusal: a run whose resume replaced the head it still carries is refused a composed review, the refusal is reported without being recorded on a dry run, and the real call records it as withdrawn with its reason.

Arms. The guard-removed mutation — append the duty without checking it — reads 1 failed, 5 passed, EXIT=1, failing exactly the new snapshot case and reproducing the reviewer's own traceback, so the case detects the defect it was written for rather than passing beside it. The base arm at dec005048c, with this head's two test files overlaid, reads 5 failed, 65 passed, EXIT=1 — precisely the five cases this change introduces, the three from the landing and the two added here, each failing on the absent seam (module 'reckon.crew.resumption' has no attribute '_record_resume_supersedes_head'). The head reads 70 passed, EXIT=0, so it adds no failure id against the base.
