A queued run keeps one id from dispatch to launch

What changed. The admission launch now continues the request it was admitted from rather than becoming a different run. _launch_queued in reckon/crew/queue_admission.py passes run_id=str(pointer["run_id"]) into the shared dispatch() call, and dispatch already forwarded a caller-named id through plan_dispatch, which resolves it as run_id or new_run_id(node.id). So the id a dispatch prints is the id the launched run answers to, and it is the id crew observe, crew discard and the ledger read.

The id was already stable across admission retries before this change: _restore_queued and _requeue_admitted_failures both write the request back under snapshot["run_id"]. Only the launch re-minted, which is why the printed id went dead the moment the lane freed. Nothing had to change in reckon/crew/runs.py or reckon/crew/reserve.py.

The watch stream needed no change either, and the guard for it is kept as a regression: fleet_transitions in reckon/crew/recovery_watch.py folds a departing request without a row when a live run names it in admitted_from, a field the admission launch already set. With the id now shared there is no departure to fold at all.
