A queued run keeps one id from dispatch to launch

What changed. The admission launch now continues the request it was admitted from rather than becoming a different run. _launch_queued in reckon/crew/queue_admission.py passes run_id=str(pointer["run_id"]) into the shared dispatch() call, and dispatch already forwarded a caller-named id through plan_dispatch, which resolves it as run_id or new_run_id(node.id). So the id a dispatch prints is the id the launched run answers to, and it is the id crew observe, crew discard and the ledger read.

The id was already stable across admission retries before this change: _restore_queued and _requeue_admitted_failures both write the request back under snapshot["run_id"]. Only the launch re-minted, which is why the printed id went dead the moment the lane freed. Nothing had to change in reckon/crew/runs.py or reckon/crew/reserve.py.

The watch stream needed no change either, and the guard for it is kept as a regression: fleet_transitions in reckon/crew/recovery_watch.py folds a departing request without a row when a live run names it in admitted_from, a field the admission launch already set. With the id now shared there is no departure to fold at all.

The four sibling assertions the change retires

Under the launch id change, four pre-existing assertions in tests/test_a_queued_run_is_admitted.py fail because each one asserts that the queued id's pointer or run directory is vacated by the launch — which is the id-swap this node retires. With one id there is one pointer and one run directory, so:

  • test_one_slot_launches_the_highest_ranked_queued_run_only and test_a_launched_run_leaves_queued_for_starting_then_working assert not runs.pointer_path("r-first"|"r-phased").exists(); the pointer now exists as the launched run's, and the phase assertion beside it already covers the intent.
  • test_a_queued_launch_takes_its_manifest_from_its_launched_run asserts str(queued_dir) not in prompt and test_a_queued_launch_derives_write_paths_under_its_launched_run asserts no write path is under the queued directory; both compare the queued directory against the launched directory, which are now one path.

Those four assertions are updated in the same change, each replaced with the identity the launch now guarantees: the two pointer cases assert that the launch reports the queued id itself, and the two directory cases assert that the launched run directory is the directory the request was queued in, so the derived manifest and write path are the run's own. No case is dropped and none is disabled, and the file still reports twenty-two tests. The head arm is green because of that update: the four ids above do not appear in after_gate.log, and the base arm's two do not either.

Ruff check --no-cache and format --check are clean on all three changed paths: reckon/crew/queue_admission.py, tests/test_a_queued_run_is_admitted.py and tests/test_a_queued_run_keeps_one_id.py.
