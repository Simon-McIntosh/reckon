The hooks install command prints before it writes

What changed. reckon/cli.py gains a hooks group with an install command. It wraps install_hook_settings from reckon/hooks/install.py without reimplementing the merge: without --write it prints the fragment and opens no file, and with --write it merges into the named settings file (the scope's own file when none is named). A target that already carries the whole fragment is refused, exiting non-zero, rather than reported as a silent no-op. The command catches the installer's HookInstallError and exits non-zero with its message, so a file the installer cannot parse surfaces the refusal rather than a traceback.

Pin. tests/test_hooks_install_cli.py drives the command through the click test runner: the dry run prints the fragment and leaves the target byte-identical; --write merges into a temporary settings file; a second --write refuses the duplicate install and leaves the file as the first install left it; and an unparsable target exits non-zero with the installer's message. Every case points the settings path at a file under the pytest temporary directory and compares the real user-scope settings file before and after, so a command that reached for the default path fails here rather than installing onto the machine running the suite.
