§10 — A moved checkout serves every call on current code

The routing is the fix. _refuse_when_stale in reckon/mcp.py served a call on the current code only once the call had failed: _SERVE_ON_CURRENT_CODE recorded that, and was read as the gate on every later call. A call that still worked on the running image was therefore answered by the image, and after a landing that answer was behaviour the tree no longer has, with nothing in it to say so. Once the child is warm — its readiness probe has answered — and the tree is moved and trusted, every call is now routed to it, writes included and from a tool's first call: a successful write answered by the running image is the same defect as a successful read answered by it. A write the child does not answer is never re-run on the image, because it may have landed there; the caller gets write_may_have_landed naming the read that settles it, which is the honest answer for a write whose fate is unknown. A read the child does not answer falls back to the image, and if the image then fails, the failure stands and carries both stamps with current_code_note.

A raised failure while the child is cold. The guard's except re-raised, so a caller saw a crash where a returned failure had carried both stamps and a remedy. A call that raises while the tree is moved and trusted is now answered with stale_server_code, code_stamp_at_start, code_stamp_now, the reconnect remedy, and original_error naming the exception that was raised.

A schema failure beside a successful answer. An edit_plan write can succeed and report why its review predicate could not answer in review_owed_error; when the running image's classes cannot validate config the tree has moved past, that failure is this guard's own case. _embedded_schema_failure reads it only where it can be the guard's: the field must be one of _EMBEDDED_FAILURE_FIELDS — the fields that carry a sub-computation's exception rather than the call's outcome, which today is review_owed_error alone — and the value must lead with one of _SCHEMA_ERROR_NAMES. A match on any *_error field whose text merely contained pydantic's message was wide enough to read an unrelated failure as this guard's case and replace the call's own result on it, so the read is a leading exception type in a named field and nothing else. An error of any other kind in one of those fields, or a schema error the call reports in a field of its own, is the caller's answer and stands.

Gate. Seven cases in tests/test_a_moved_checkout_serves_every_call.py run the guard in process against a temporary tree with a controllable child: a successful read served by the warm child and carrying its stamp, with the image's tool never called; an unmoved checkout serving in process and starting no child; a raised failure while the child is cold, answered with both stamps and the remedy; the first write of a tool served by the warm child and carrying its stamp, with the image never called; an embedded schema failure not passed off as the image's successful answer, and carrying both stamps; an embedded error that is not a schema failure left standing; and a schema error the call reports in a field of its own left standing. That file and the five neighbouring stale-code test files run as one gate, judged by failure delta against the assembly base.

The gate's delta, stated plainly. The gate reports one failure at this head, against five at the base, so no failure is added: the guard's own seven cases pass, and the slow-child case the write routing moved passes with them. test_a_slow_child_never_forces_a_reconnect.py::test_an_unanswered_write_says_it_may_have_landed is the case the routing changed: it wrote to a child that answers its probe and then never answers the call, and it asserted the running image's version_conflict — an answer the image no longer gives, because it never ran the write either. It now asserts what such a write gets, that it may have landed with the read that settles it and both code stamps, while keeping its refusal to see a reconnect on a slow child and asserting the image stayed untouched. The remaining failure is the pre-existing one named above, which fails on the base tree too and is not this node's.
