§11 — The scopes read narrows to the path it is asked about

The view answered about every file, so the one question it exists for could not be asked. crew(view="scopes") passed its path argument through the tool signature and then ignored it: the view composed the project's whole live-claim registry whatever the caller named. A coordinator asking who holds one file got the project, and on a project with enough live claims got an over-budget refusal whose narrow_with named only candidates.

A named path selects the claims that contain it or lie inside it. Narrowing is judged by path components, the rule the dispatch scope check applies to two declared scopes (_scopes_overlap), so a claim on a directory answers for a file beneath it and a claim on a file answers for the directory holding it. Each kept claim travels with its owners and the verdict dispatch would apply — binding and disposition_reason — and nothing is trimmed from that answer, because an exact answer for one path is what the call is for. The path is resolved repository-relative with _repository_relative_scope, so an absolute spelling inside the checkout and a relative one answer the same claims; a path that resolves outside the checkout is refused as invalid_path rather than read as an empty claim set.

The default read is one page that fits its own row. With no path and no candidates the view answers a page of held paths with their owners, a summary carrying the totals behind the page (claims, paths, runs, binding and non-binding counts), a pagination cursor to the next page, and a narrow_with naming path before candidates. The page is measured with the budget module's own serialised_characters against VIEW_BUDGETS[("crew", "scopes")] and shortened until it fits, because a kept path carries an unbounded number of owners. Every page that returns a cursor moves past at least one path: a path whose owners alone fill the row is answered in its owners' summary form and named in over_budget_paths with its omitted count, rather than dropped, so a caller following the cursor always advances and the walk terminates. The transport ceiling's narrow_with for this view now names path first as well.

The served read, on this node, naming one held file. The measure is a fixture holding more claims than the row allows. tests/test_the_scopes_read_narrows_to_its_path.py writes 60 holders of two files each, one holder of a directory, and one holder of a path outside the checkout, so the claim set is larger than the 24,000-character row and the paths it holds exercise both directions of containment. It asserts the path read against the claim map the test computes from the fixture — a wrongly kept claim and a wrongly dropped one both fail — and asserts the default read against the row, including that the path it offers is answerable by the call it invites. One path is held by enough runs that its owners alone fill the row, so the paging case walks the cursor to the end and asserts every cursor strictly advances, the walk terminates, and the union of the pages covers every path — naming the dense path in its summary form rather than dropping it. On the base revision the same file fails all eight cases, the default read measuring 53,565 characters against the 24,000 row; after the change all eight pass.

The control is the mutation each case must catch. Two mutations were applied and reverted. With the scopes branch made to ignore its path argument again, five of the eight cases fail — every one that asks about a path, including the refusal of an outside path — and the default-read cases still pass. With the paging branch made to return the unchanged cursor on an empty page, the two paging cases fail and the exact narrowing cases still pass. Each guard is therefore seen firing on the behaviour it names rather than only passing beside it. The gate logs, the base arm, the after arm and both red runs are recorded beside this node's manifest.

The row holds with little to spare. The served default read lands at 22,879 characters against 24,000, because the page shortens itself until it fits rather than to a fixed page size; a project whose owners carry longer disposition prose therefore returns fewer paths per page rather than a larger answer, which is the contract working, but it means the page size is not a fixed number a reader should predict.
