A row is compact and names its section

Every crew list view that lists runs — live, runs, obligations and directory — now builds its rows and routes them through one projection, project_run_rows in reckon/crew/query.py. That one function owns the field vocabulary the views share, fills each row's section from the run's own pointer, refuses a requested field the view does not carry while naming the fields it does have, and leaves a field whose value is empty off the row.

Two clauses of the section's done-when are not met, and both need a file outside this node's write scope:

  • A section reference whose target section is done while its plan is in progress must read satisfied, with the section's declaration as its state. The per-section verdict already exists (_section_satisfied in reckon/roadmap.py), but the dependency row a plan summary reads carries the plan's status and no declaration, so _section_blocking can report a satisfied section as blocking. Closing this needs reckon/roadmap.py.
  • The serialised power_convertor roadmap does not shrink, because the roadmap's own rows are compacted in reckon/roadmap.py, which this node may not write. Measured both sides: 142,482 characters.

References the rows and the projection travel in remain strings of the one grammar, [project:]plan[#section][@run|@f-id]: the rows carry plan and section as plain strings, never as expanded objects, and the projection adds none.
