A row is compact and names its section

Every crew list view that lists runs — live, runs, obligations and directory — now builds its rows and routes them through one projection, project_run_rows in reckon/crew/query.py. That one function owns the field vocabulary the views share, fills each row's section from the run's own pointer, refuses a requested field the view does not carry while naming the fields it does have, and leaves a field whose value is empty off the row.

The same rule covers a dependency row: it reports the dependency's own state, never the containing plan's. Three producers of section-scoped rows said otherwise — the roadmap's section edges, the resolver behind read_plan's deps list, and the section_blocking projection, which re-derived its verdict from the plan's status. All three now read the target section's own declaration, falling back to the plan's status only where the plan declares none.

The declared mutation — returning section to the run row's omitted set — turns the measure red: EXIT=1 with six failing ids, including three of the four views of the names_the_section case.

The roadmap shrinks for one reason, and the reason is the rule above rather than a compaction pass: the section-scoped rows it carries now report the section's own declaration instead of the containing plan's status, and the declaration is the shorter string. A per-key comparison of the two serialised payloads puts the whole difference there — depends_on[].status and section_depends_on[].status fall from 559 to 410 characters in pending_work and from 495 to 374 in ready_now, while the readiness blockers' own status fields rise from 169 to 195. Nothing else moves beyond live-run counts. The roadmap's own row shape is unchanged.

References the rows and the projection travel in remain strings of the one grammar, [project:]plan[#section][@run|@f-id]: the rows carry plan and section as plain strings, never as expanded objects, and the projection adds none.

One divergence from the done-when's literal wording, recorded rather than smoothed over: the fixture dispatches for P#s4 and the four views read §4, the canonical spelling of the same identity, because the one projection normalises every row's section through normalize_section. Before the change the views disagreed — runs read §4 and directory read s4 for the same run — so a single spelling is the point of the clause.
