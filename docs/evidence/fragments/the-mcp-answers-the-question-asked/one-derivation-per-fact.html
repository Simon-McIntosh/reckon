One derivation per fact, held by a parity check

section_blocking in reckon/mcp_views.py published a section-scoped wait's target readiness by testing the dependency row's status against the completed set. That status is the target plan's status, or the target section's own declaration — neither is the readiness of the section the row names, and the roadmap resolves the same edge through _section_satisfied in reckon/roadmap.py. The two readings disagree on an undeclared section of a terminal plan: the status reads shipped while the roadmap holds the edge, so read_plan dropped a wait the roadmap kept. The projection now resolves the target plan itself and asks the roadmap's _section_satisfied over it, so the rule has one home.

The run-classification fact was already single-sourced: the roadmap, the crew live view and read_plan all reach classify_pointer through reckon.mcp_views.partition_live_runs. That guard asserts the sharing rather than changing it — with the classifier replaced by a sentinel that answers interrupted, every surface publishes that classification for the one run and asks the classifier exactly once per read.

The read path's rows are built in reckon/mcp.py (_resolve_plan_ref), which is outside this node's write scope and does not yet carry the roadmap's satisfied verdict. The projection therefore resolves the target itself rather than trusting the row's status: _section_target_plan reads the target plan through the row's own scope, and _section_target_satisfied asks the roadmap's _section_satisfied over that plan's declared section identities. A ref to a section the target never declares holds, whatever the plan's status says; a target that cannot be read holds too, because an unobserved target is no evidence that it landed.

The reviewer's finding was correct and is answered by c3b642292: the earlier change added a branch for a row-carried verdict that no production row reaches, leaving the status reading in place. The guard now runs the production path — rows built by _section_dependency_rows from two authored plans, one terminal with an undeclared section and one open with a declared-done section — so a regression to the status reading fails a test rather than an argument.

One existing test encoded the reading this change removes. test_satisfied_section_wait_leaves_no_section_row asserted that a wait on a section a shipped plan never declares reports no row, while the roadmap holds that edge (_section_scoped_edges requires the section to be declared). It is now test_undeclared_section_of_a_shipped_plan_holds_without_blocking_the_plan and expects the s3 row, keeping its original point that a section edge never reaches the plan-level blocking list. A second test, test_a_declared_done_section_leaves_no_section_row, covers the satisfied direction.

The verdict depends on which tree the caller reads, so the projection threads the read's own checkout down to the target resolution. With the threading dropped, read_plan resolves the target through the mounted project while the waiting plan comes from the worktree, and the two copies disagree — test_a_section_wait_reads_its_target_through_the_calling_checkout holds a target the mounted copy declares done and the checkout copy declares implementable, and it fails when resource_view stops passing checkout.
