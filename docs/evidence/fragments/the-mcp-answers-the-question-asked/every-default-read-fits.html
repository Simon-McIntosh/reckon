§2 — A default read fits by construction

The contract is a table the code reads. VIEW_BUDGETS in reckon/mcp_budget.py maps every (tool, view) of every reckon MCP read tool to the most characters a call using only that view's required arguments may return. view_budget(tool, arguments) resolves the row for a call — falling back to the tool's default view when the call names none — and an over-ceiling receipt now carries view_budget_characters, so a refusal names the row it broke rather than only the transport ceiling. bound_response's ceiling is unchanged and stays the guard; a default call that reaches it is a defect in that view.

The views that serialised whole records were paged instead of refused. All three changes route existing collections through the existing paginate(); no parameter, view or refusal was added. roadmap view=detail answered dict(raw) — every per-plan row, every dependency object, the whole report — and now answers the summary facts plus compact pending rows and one page of findings. read_plan view=raw keeps every fact of the plan state and pages its section records, the part that grows without bound. crew view=findings returned every row twice — once inside its path groups and once flattened beside them — and now pages the groups and rebuilds rows from that page, so the two cannot disagree about which rows the page carries. Recurrence is still counted from the records, not from a page.

The measure is a pinned fixture, and the control is the size failure itself. tests/test_every_default_read_fits.py mounts a synthetic project of 60 plans and 400 sections and calls every view of every reckon MCP read tool with only that view's required arguments, asserting each answer is within its row and that no view returns response_over_budget. On the base revision the same fixture answered roadmap view=detail with response_over_budget — the answer it built there was 177,661 characters against the 80,000 ceiling, measured with the ceiling lifted so that the size is visible rather than only the refusal — and after the change it answers in 14,704 characters against its 30,000 row. The gate log records an arm for each.

One gap is recorded rather than closed. The two raw views are explicit lossless opt-ins rather than defaults, so the test names them as a declared exception instead of holding them to a compact row: audit raw answers in 23,507 characters on the fixture and fits, while roadmap raw still reaches the 80,000 ceiling on a 60-plan project and returns response_over_budget. Paging it would change what the lossless view means, and §2 does not list it, so it is left as it is and raised under follow_ons.
