A gate log's failure count is read across the whole gate

A multi-label ctest gate runs ctest once per label into one log. The agreement check between a suite arm and the log it cites cut that log to its last run, so an arm recording the 32 failures an earlier label inherited was compared with a clean final label and refused. The receipt was honest and the reader was reading one label.

Reproduced before repair. At base revision b30f1e1350adcc64d38de45901cccf13801e5b2c, a log whose first ctest label lists 32 failures (exiting 8) and whose second label runs clean (exiting 0), against an arm recording failure_count: 32 and failure_ids naming those 32 tests, raised CrewError: ... does not agree with the after_suite arm that describes it, naming the count and the ids the log's last run does not report. Three of the five cases failed there; the log is negative-control.log in the run directory.

What changed. _text_the_receipt_describes selects the part of a log one receipt's figures span. A pytest log holds one run per attempt at the same suite, so it keeps its last-run reading and a receipt copied from an earlier attempt still refuses. A ctest log is the gate's whole text, because its labels are one gate rather than successive attempts. _ctest_failure_ids also resumes scanning past the end of a FAILED block instead of stopping at it, so a failure in any label joins the gate's failure set.
