An undeclared project shares its source files; the classes git cannot merge stay exclusive

A project that carries no shared-write-paths.json, or one whose declaration names no shared_roots key, now admits two concurrent file claims on the same source file. The policy is computed once in reckon/crew/runs.py, which every claim check already calls (dispatch, admission, queue edit, widen and promotion), so the answer cannot drift between them.

The classes a textual merge cannot reconcile stay exclusive in every project, declared or not: a plan document, a cumulative evidence record, generated state, a figure topic directory, the dependency manifest and lock, a generated receipt, and any binary file. They are listed once in DEFAULT_EXCLUSIVE_PATHS (plus the binary-content probe) and read both by the undeclared default and by a declared project's exclusivity check. A declaration that cannot be read still shares nothing, and the refusal it causes names the declaration. A declaration naming shared_roots, even an empty list, governs as before. Directory claims remain exclusive.
