A repair-gate refusal names its log and both commands

A pending landing whose repair gate refuses on a command mismatch used to report only repair gate command does not match its captured log. The operator was left to guess which of two cited logs the gate had read, and which two commands disagreed. The refusal now names all three: the resolved path of the log it read, the command the manifest's tests: line says, and the command that log records — or that it records none.

The message is built by _repair_gate_command_refusal from the same log path the fill resolved, so a refusal about an after_suite log names that log rather than the test_logs entry it was chosen over. The declared command is read through the same freshness reader the gate used, so the refusal quotes the command that was actually compared.

CaseWhat the refusal names
Manifest command differs from the log's headerLog path, manifest command, log command.
Log carries no command headerLog path, manifest command, the log records no command line.
An after_suite log wins over test_logsThe after_suite path, never the superseded test_logs entry, plus both commands.
Matching gateNo refusal: the repaired head is admitted.
