Critical work takes a freed slot ahead of waiting reviews

What changed. The admission order ranked a delivered run's review above every priority override, so no override could reach a freed slot while a review waited. A request whose override reaches its project's critical level now takes a freed slot ahead of a waiting delivered review. The critical level is the flight setting queue.critical_priority (default 100), read per project through the same resolved config the pass uses. It is declared in reckon/schema/flight.yaml, shipped at 100 in reckon/schema/flight-defaults.yaml, and read by flight.queue_critical_priority.

The level is a move over the shared order, not a class within it: queue_order._critical_ahead_of_reviews places a critical request ahead of the first waiting review, after every request past the starvation age, and returns the queue unchanged when no review waits. Both admission_order_details and fair_queue_order_details apply the same move, so the admission and promotion queues keep one order, and starvation ageing and a review's precedence over the run it reviews are unchanged. Every request below the critical level keeps the order it had, with delivered reviews first.

Measured

With one queued review of a delivered run and one implement request, the order's head is the implement request at override 100 and the review at override 99, with no override, and at override 50 under a project layer setting the level to 50. At the base revision the same first case offers the review the slot ahead of the override-100 request. The production paths are covered too: fair_share_admission_order returns the critical request, then the review, then a lower override, and promotion_requests._pending_requests honours a project level of 50 for an override of 50.

The five shared-order tests that first failed — the starvation bound, both starvation boundaries, ageing ahead of a younger priority, and a queued review ahead of the run it reviews — pass unchanged in the importing-test arm at the head, and the base and head arms fail exactly the same twelve environment-dependent tests, so this change adds no failure.
