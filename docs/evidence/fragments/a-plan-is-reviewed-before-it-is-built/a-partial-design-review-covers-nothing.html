What changed

_delivered_status marks a delivered review incomplete when its parse leaves out any item of the rubric it was delivered under — design included. The rubric test that narrowed the mark to the content rubric is removed, so a design report delivered with an item missing no longer stores ready. review_coverage already skips a record carrying the mark, so such a review covers nothing.

require_plan_reviewed reads the newest design review as before and now refuses an implementation dispatch when that record is marked incomplete, through _review_is_incomplete, naming the design-review command. A review stored without the mark — every design review written before the mark existed, including the ones missing only interface_budget — keeps its coverage.

The answer verb falls back to newest_design_review for a finding that review raised when no covering record exists, so the findings of an incomplete design review stay answerable rather than reading as a review nobody made.

The three deliveries that composed a partial design report and expected it to count — in test_a_section_reviewed_as_authored_stays_reviewed.py, test_review_plan_command.py and test_the_surfaces_pass_the_plan.py — now compose a complete one, a RUBRIC line for every item of PLAN_DESIGN_REVIEW_ITEMS, so each goes on testing what it tested.
