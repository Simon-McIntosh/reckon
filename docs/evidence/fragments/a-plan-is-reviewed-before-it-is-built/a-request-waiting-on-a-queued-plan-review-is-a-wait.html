A request waiting on a queued plan review is a wait

A queued request the admission pass refused with plan-review-missing was listed under queued-awaiting-session with the compose command as its remedy. When a review of that plan is already live or queued for the same session, running that command only queues a duplicate review, and the request is waiting on work in flight that no action at this session shortens. Both producers now resolve the review's plan from the composed node id (plan-review-of-<slug>, the one place a plan review records the plan it reads, since its node.plan is empty) and read the request through _queued_item under run-queued: the row carries review_run_id, states in its reason that composing the review again would duplicate it, and gives a wait: command naming that run. A recorded stall verdict is set aside while the review is in flight, because the pass having turned the request over is not what the session waits on. With no such review — or one another session composed, whose recovery reading is that session's own — the request keeps the queued-awaiting-session duty and its compose command. The derivation and the published snapshot slice share _plan_review_this_request_awaits and the one _queued_item builder, so the two surfaces cannot disagree about the request.
