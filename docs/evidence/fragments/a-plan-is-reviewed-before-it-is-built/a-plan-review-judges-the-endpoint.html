a-plan-review-judges-the-endpoint

The composed plan-review briefs now judge a section's endpoint and never its implementation. In the content rubric, reasoning drops the two checks that judged a stated method — whether a section's mechanism produced its done-when, and whether the mechanism ran on a named production caller — and asks instead whether the endpoint is reachable and checkable and whether the section prescribes implementation, which is a finding. anchors_resolve no longer requires claims to be cited: a reference is judged on resolution alone. In the design rubric, the reuse map is produced for the node brief and no finding asks the plan to name a module, function or file to extend. skills/reckon-build/SKILL.md and skills/reckon-review/SKILL.md state that the reuse map stays out of the plan.

The mechanism is identified, and it is a defect in that test rather than in this node's change. The test means to substitute a launcher (monkeypatch.setattr(crew, "_spawn", …), tests/test_crew.py:1992) but the stub is unreachable: dispatch() takes launcher=None and its launch step then calls _start_supervisor, which spawns a real detached python -m reckon.crew.supervisor_main process with parent pid 1. That supervisor is handed the composed brief as the worker's stdin and records phase: starting → working in the live pointer; promotion snapshots the pointer before landing and refuses when a compared field moves, so the supervisor's write lands inside the dispatch → complete window. The rubric's size moves the window because the brief is the worker's stdin. A three-second delay before the promotion check makes the collision certain and shows the single field that moves: {"phase": ["starting", "working"]}.
