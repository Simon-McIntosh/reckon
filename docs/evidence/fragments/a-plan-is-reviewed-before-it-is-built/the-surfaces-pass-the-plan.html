The answer verb and the plan-review view read through the plan

The delivered-review store step and the section-aware read_plan_review landed in the sibling node, but only the build gate read through them. Two surfaces still read the old way. crew review-plan --answer in reckon/cli.py called read_plan_review(project, plan_slug) without the plan's content, so a plan whose only review was an unstored delivery — one no build had judged — reported no stored review; and the MCP plan-review view in reckon/mcp.py called it the same way, so a plan covered section by section read as unreviewed there while the gate admitted it. Both callers now resolve the plan file through _store._resolve_html_file, the same resolver the plan editor and promotion already use, and pass it to read_plan_review; the answer verb additionally calls plan_review.store_delivered_reviews for the plan before it reads, so answering a finding stores any delivery first and never depends on a dispatch having stored it. A plan path that does not resolve passes an empty document, so an absent plan yields no coverage rather than a read error.

Passing the plan narrows both surfaces from the newest stored review to the newest covering review, and a plan edited past its last review has none. That narrowing is the point — a review of content the plan no longer carries is not a review of the plan — but a bare no stored review would have hidden the review that does exist and misled its author. So when stored reviews exist and none covers the current content, both surfaces name the newest stored review by plan version, say it no longer covers the plan, and point at crew review-plan to compose a review of the content now present. The message is composed once, in reckon.mcp._stale_plan_review, and the answer verb reads it through that one function; a plan with no stored review at all still reports plainly that none exists, which is a different fact.

Shape checks

At the head, grep -rn 'read_plan_review(' reckon/ reports the definition in reckon/crew/plan_review.py and four call sites. Three read a review for a plan and each passes the plan's content — reckon/cli.py:2621, reckon/mcp.py:4351 and the gate's reckon/crew/routing.py:2676. The fourth, reckon/mcp.py:443 inside _stale_plan_review, omits it deliberately: it asks for the newest stored review of the slug regardless of coverage, which is exactly the review the note reports as no longer covering the plan, so no call that reads a review for a plan omits the plan's content. grep -rn 'def store_delivered_reviews' reckon/ returns one line in reckon/crew/plan_review.py; grep -rn 'def _store_delivered_plan_review' reckon/ returns nothing.
