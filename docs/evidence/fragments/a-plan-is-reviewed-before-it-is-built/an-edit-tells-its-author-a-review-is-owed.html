An edit tells its author a review is owed

Creation and every structured edit of a plan go through one tool, _edit_plan_tool in reckon/mcp.py. After a successful write to a plan — not to a doc — the response now carries review_owed: the outstanding units the coverage predicate reports uncovered, each with the measured change where one exists, beside review_invocation, the one-line command that composes a review of them. The tool composes no review itself; the author decides when an authoring session is finished, so a burst of edits earns one review and no review is attributed to a session that did not ask for it.

One predicate, two readers

_review_coverage in reckon/crew/plan_review.py is renamed review_coverage with its return unchanged, and every caller is renamed with it — the dispatch gate in reckon/crew/routing.py, read_plan_review, and the four plan-review test files. The edit tool reads it across the package boundary, so the gate's refusal and the edit's review_owed cannot disagree about which units are owed. Renaming the one function rather than adding a second reader raises public_definitions by exactly one.
