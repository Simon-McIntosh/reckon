What changed

The join that writes a launched plan review's run id into its composed dispatch.json moved from the admission pass's post-launch block into _launch_queued, the one function every launch of a queued request passes through. Three callers reach it: the admission pass's own launch, a dispatch yielding its lane slot to an older request of its session (dispatch._launch_yielded_queued_request), and a queued request moved onto another backend (queue_admission._await_moved_launch via move_queued_run). The first joined; the other two did not, so a review launched by either kept run_id: null in its sidecar, promotion found no run, and the delivered report was never stored.

The join reads only a launched record: a dispatch that returns none still reaches the refusal its caller reports, and a sidecar write that fails no longer reads as a refused launch that the caller then re-queues.
