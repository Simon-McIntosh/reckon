A report is admitted on what its own parser read

The separate admission guard is gone. delivered_report_record now reads the sidecar's subject once, dispatches a code subject to _code_review_record and every other subject to parse_review_report, and refuses the report as not a review when the parse of its own grammar holds no rubric item and no finding. The refusal names the grammar the report was read under — plan or health. _report_line_reader and report_carries_review_lines are deleted with it.

A code report whose only emitted lines are RUBRIC evidence: pass and a TREATMENT line is now refused rather than stored with six absent items: evidence is not a health-rubric item, so the health grammar reads no item and no finding in it. A plan report whose only RUBRIC line names an item outside its own rubric is refused the same way. A bulleted plan report is still admitted, its finding still stored and still answerable through crew review --answer.

Head arm: the declared gate ran 85 cases, 82 passed and 3 failed. The three failures are two test files outside this node's write scope whose fixtures deliver a report carrying only RUBRIC wiring: pass under the design rubric, so the new rule refuses them. Negative control: the base revision with the new test file copied in failed 2 cases (test_a_code_report_outside_the_health_rubric_is_refused and test_a_plan_report_naming_an_item_outside_its_rubric_is_refused) with EXIT=1 — the ids the head arm does not fail.
