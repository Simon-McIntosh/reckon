What changed

crew review --answer now builds its covering set from every stored content review of the plan that raises the finding, plus the plan's design review, instead of from the one record the coverage read returned and the design review. With no --review-run the answer lands on the newest of those, plan_review.newest_covering_review, which orders them by the plan commit each read and falls back to the record's own timestamp. A record the store wrote always carries a timestamp, so the only set that cannot be ordered is one holding a hand-written record; that set is refused naming every covering run rather than answered on a guess.

--review-run matches any covering review of the plan, so a caller naming an older round reaches it, and the crew tool gained review_run: the parameter on _crew, its pass-through to _crew_write_action, and the answer entry of the action argument map, which is the seam that decides whether an argument reaches the verb.

The coverage read already reduced a covering set by the plan commits its reviews read — the deliverable's two max(plan_version) sites had been replaced by _newest_by_plan_commit in an earlier change — so this node verified that behaviour through the first and fifth cases rather than reimplementing it, and the two mutations that revert each reader to its version comparison show the cases bite (logs/negative-controls.log, controls 3 and 4).
