What changed

_standing_plan_review counted any live plan-review pointer for the plan, so the next round could not be composed until the previous run was promoted — and promotion takes ten to fifteen minutes and can fail partway, leaving the gate shut until it is re-run by hand.

A new reader, _delivered_plan_review, asks the plan-review store whether a record naming the run is stored and readable. The in-flight check now skips such a run and returns the first pointer still composing or working. What remains for a delivered review is its promotion, which is owed and listed as it is today; it no longer blocks the next compose. A review whose record is missing, unreadable, or belongs to another run is still working and keeps the gate.

The gate is one reader for the locked dispatch, the preview and the obligations view, so all three move together: a preview no longer reports a delivered review as in flight, and a queued request waiting on one reads as owing its own compose again rather than as a wait on a review that has already delivered.
