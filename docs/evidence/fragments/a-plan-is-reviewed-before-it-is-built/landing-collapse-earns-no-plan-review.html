A landing collapse leaves the plan fingerprint equal

A landing beat both replaces a section's authored body with its landed card and sets the section's declaration to done. Both are machinery writes, but plan_fingerprint (reckon/crew/plan_review.py) digested the card as authored content, so the next build dispatch was refused for lack of a review of content nobody had changed.

The digest now drops a landed card's interior while keeping the heading it carries, drops the per-section lifecycle declaration (the section is digested by its identity and structural record instead), and normalises the element boundary the collapse moves. The one definition of a landed section is exported from reckon/_store.py as landed_section_ids, built on the existing _is_structural_boundary and _landed_card_span helpers, and plan_fingerprint calls it. A section declared done without a collapse keeps its authored prose, so an edit to a live section still moves the digest — the edit a review exists to catch.

A stored review under the previous definition still counts as current: plan_fingerprint gains a legacy=True form that keeps card interiors and declarations, the dispatch gate computes both digests, and read_plan_review accepts a set of fingerprints. The sweep therefore composes no review solely because the definition moved; the equality is exercised by the store case and no stored record is orphaned by the change against the same revision.

tests/test_plan_review_store.py holds the collapse through the production path the MCP plan-editing tool calls: the fingerprint is unchanged across the collapse, an authored edit to another live section moves it, and a record stored under the legacy digest is still returned. The gate (tests/test_plan_review_store.py, tests/test_plan_review_gate.py, tests/test_plan_review_dispatch.py, tests/test_edit_plan_collapse_section.py) runs 45 passed, EXIT=0. Under the fold-back mutant — collapsed sections digesting their landed card again — the collapse-equality case reddens, EXIT=1. Change at 3080646c9.

Store census: 17 stored plan reviews; every plan document resolves, and none of the 17 equals the current document's digest under either the new or the legacy definition, because each was stored at an earlier plan revision than the file on disk. No record is left unreviewable by the definition change itself.
