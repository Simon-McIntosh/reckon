A review dry run composes nothing

A plan review composes four artifacts under the plan's report root: a run directory, brief.md, the plan.html snapshot, and the plan-review.json sidecar that names the report the reviewing worker will write. The composer now takes write and returns those paths and the composed brief text either way. The preview path passes write=False, so it returns the fields the dispatch would carry — the brief, the write path, the sidecar path — and brief_text carrying the prompt itself, while creating no directory and taking no lock; the delivered-report store has nothing to consume and nothing accumulates for it. A real dispatch still creates the directory, writes all four files and takes the plan lock.

The dispatch resolver reads the brief from disk to digest it, and that read is what the preview cannot skip without changing what it validates. The preview therefore stages the composed text into a scratch directory for that one read and removes it with the call, so the resolution — repository, sandbox, gate and population checks — is reached on the preview exactly as on the launch while the report root stays untouched. Accepting a resolution with no repository would have reached a weaker verdict; the resolver's own signature does not yet accept a precomputed digest, which is the follow-on that would let the staging go.

The measure is a listing of the plan's report root before and after a dry run against a committed plan, in tests/test_review_plan_command.py: two consecutive previews leave the listing empty and the returned brief path nonexistent, and a real dispatch against a stubbed launcher writes exactly one run directory holding the brief, the snapshot equal to the plan's committed bytes, and the sidecar. Against the base revision the same listing test fails on a written brief.md — the defect it exists to catch.

The declared negative control — restoring the early write in the composer at head — reddens that test (EXIT=1, 1 failed, one failing id the head arm does not fail). Restored, the worktree is identical to the commit.
