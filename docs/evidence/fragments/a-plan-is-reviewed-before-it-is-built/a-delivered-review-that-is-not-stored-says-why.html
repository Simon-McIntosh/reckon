A delivered review that is not stored says why

A review run leaves a report and a sidecar beside it on the plan's durable report path; the build gate stores the delivery the first time it judges a build of that plan, so the coordinator never runs a store step. The store step existed once, as the module-private routing._store_delivered_plan_review, and swallowed an OSError or ValueError with a bare continue, so a delivery that did not store surfaced only as its consequences. The step now lives beside the report store it wraps, in reckon/crew/plan_review.py, as the public store_delivered_reviews; when it refuses a delivery it reads that delivery's existing sidecar payload back and rewrites it through the one sidecar writer, write_review_sidecar, with the reason under store_error, and returns each refusal so the gate names it in its missing-review detail. The report store goes private as _store_delivered_report, because once the loop moved into the review module its only production caller is that loop. read_plan_review keeps its name and gains the plan's content as an optional argument: given it, it returns the newest stored review among those the coverage predicate counts as covering, the record whose findings the gate checks, and the gate takes its record from that call rather than picking its own newest-by-version over the contributing records, so the gate reads one rule with one owner.

Why the three named deliveries stayed unstored

Each named delivery stores cleanly when its sidecar is handed to the store into a scratch root, so the fault is not in the reports. Read back from the live store, all three read stored=False, and the cause differs by delivery.

  • imas-codex dd-defect-upstreaming r-20261005T053339024695 — the earlier of two deliveries whose sidecars carry the same reviewed_blob_sha 0211bb1a… and plan_version 0 (the later re-review r-20261006T005048785174 carries the identical blob with a different whole-document fingerprint 06fee862…). The store keys a record by project, slug, version and blob8, so the identical version and blob resolve both deliveries to the one plain file plan-dd-defect-upstreaming.v0.json. The live file carries the later run's review_run_id, so the earlier delivery's identity was overwritten by the later store of identical content and it reads unstored for good. Evidence: delivered_reports("imas-codex", "dd-defect-upstreaming") returns the later as stored=True and the earlier as stored=False, and the stored record's review_run_id is the later run.
  • imas-ambix jt60sa-geometry-and-signal-figures r-20261006T055800475236 at version 13 — a valid delivery (blob d65a0489…, snapshot present) that read unstored at measurement. The only store step lives inside the build gate and fires only when a build of the plan is judged, and the answer verb reads with read_plan_review(project, slug) by whole-document match without storing, so answering a finding before any build found no stored review. The delivery became stored only when a later gate pass stored it; the live record at plan-jt60sa-geometry-and-signal-figures.v13.json now carries this run id with its responses.
  • imas-ambix serving-record-warehouse r-20261005T141020240778 — one of nine delivered reviews for the plan (blob ee673eb7…, version 225) that all read unstored, and the live review store holds no record for the plan at all. Every one stores cleanly into a scratch root, so they stayed unstored because no store step ran for them: the gate's store step is the only one, and no build dispatch of the plan judged it after the reviews landed.

The shared shape of all three is that the one store step was silent and confined to the gate: a delivery the plan never had built, or one whose identity an identical-content sibling overwrote, left no stored review and no written reason. This node closes the silence — a refused store now records its reason and the gate names it — and makes the record the gate checks readable by the coverage rule; storing a delivery before the answer verb answers is the sibling node whose write paths include the answer verb.
