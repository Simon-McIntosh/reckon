What changed

A stored review already records the units a round traced against the code (traced_units). That set is now also the review's own scope: plan_review._observation_ids marks a finding whose every blocked unit lies outside it, observation_findings lists those ids, and unanswered_findings_by_unit — the one reader the dispatch gate uses — leaves them out. A finding that blocks the document unit is never an observation, because the document unit is the plan as a whole and every review reads it. A review that traced nothing read the whole plan, so nothing it raises is an observation: every first review, and every record stored before a round could be scoped, gates on every finding exactly as before.

The distinction is the review's scope, not the dispatch's. The gate already narrowed findings to the units a dispatch builds; this node adds the other half, so a re-review composed for one edited section no longer holds a node building a section an earlier review already covers. Observations are recorded and answerable — unanswered_findings still lists them — so they are carried rather than lost.
