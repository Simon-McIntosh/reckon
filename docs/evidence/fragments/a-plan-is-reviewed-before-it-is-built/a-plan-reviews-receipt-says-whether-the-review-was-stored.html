A plan review's receipt says whether the review was stored

The receipt's store field is the promoted run's own ledger index append — _index_append in reckon/ledger.py — so a plan review whose record never reached the plan-review store still read store: written. The receipt now carries plan_review_store, present only when the promoting run's node id carries the plan-review prefix. Its value is read back off the delivery the store recorded, through the same join promotion already uses: _delivered_plan_review_for_run resolves the report directory whose dispatch.json names the promoting run, and the sidecar's stored and store_error keys are the outcome and the reason. written means a stored record carries the delivery's id; failed carries the store's own reason. A promoting plan review whose composed report names no run — the silent miss — is reported from the composed directory the run's write paths name, with the run id that directory fails to name, because that is exactly the delivery promotion could not join and therefore never stored. The computation lives in reckon/crew/promotion_checks.py beside _plan_review_record_for_promoting_run, whose store call produces the outcome, and reckon/crew/promotion.py attaches the field to the receipt it assembles. store is unchanged.
