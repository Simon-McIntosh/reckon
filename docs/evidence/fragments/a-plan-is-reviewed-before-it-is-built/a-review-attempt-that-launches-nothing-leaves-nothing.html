A review attempt that launches nothing leaves nothing

A plan-review attempt composes its run directory under the plan's report root — the brief.md, the plan.html snapshot and the plan-review.json sidecar — before the lane admits it. The composer in reckon/crew/recovery.py now records whether this call created the directory, and the plan-subject path in dispatch_review_for_run holds those composed fields, calls the dispatch once under the plan's dispatch lock, and — when the returned report did not dispatch — discards the composed directory once through _discard_composed_plan_review. Every refusal and hold the dispatch can return reads as not dispatched, so one check at the composing caller covers them all rather than a removal copied into each branch. Only a directory this call created is removed: a run directory that already existed when the fields were composed leaves the report untouched. A removal that fails is not swallowed — it is named on the report under discard_error with the path and the error, so a caller can see what was left. The refusal payload is otherwise unchanged: a paused lane still returns error: lane-paused with the gate it read.

The measure is tests/test_a_review_attempt_that_launches_nothing_leaves_nothing.py, six cases passing. A plan-review dispatch refused by a paused lane leaves the plan's report root holding no new run directory and still returns lane-paused with the gate reason; a run directory that existed before the call, holding a delivered report.md, survives the refusal untouched; an admitted dispatch keeps its composed directory with the brief, snapshot and sidecar; a removal that fails reports discard_error naming the path and the error rather than swallowing it; the composer names the run directory it created; and the source shows the removal as one call at the composing caller with a single shutil.rmtree and no ignore_errors.

The declared negative control — skipping the shared removal exit, the one call the plan-subject path makes when the dispatch launched nothing — reddens three cases: EXIT=1, 3 failed, 3 passed, the failing ids being test_a_paused_lane_leaves_no_run_directory_and_still_reports_lane_paused, test_a_failed_removal_is_reported_not_swallowed and test_the_removal_is_one_exit_at_the_composing_caller_not_one_per_branch, all of which the head arm passes. The run directory the composer created is left behind and the listing assertion fires. The log is kept under the run directory at logs/negative-control-lane-paused.log.
