A worker never outlives its supervisor

signal_worker gains reach_run: it ends every process a run owns, found by descent from the run's recorded supervisor and worker pids and by RECKON_RUN_ID in each process's environment, and returns the pids ended. Every run-ending caller inherits the reach, because the identity-checked signal takes the run id from the run directory it is handed and reaches the whole run from there; a caller holding only a pid to stop, with no run of its own, keeps the single-pid behaviour. The reach is taken only while the pid it starts from still names the process a record registered — the handed pid against the start tick its record carries, the worker record's pid against the tick in worker.json — so a pid the kernel has recycled contributes neither itself nor its children, and the launch floor the environment scan uses is the recorded tick rather than whatever process holds the number now. An unreadable environment and a bare worktree holder are never signalled. A stop takes that identity check only while the recorded pid still names a process: a start tick beside a pid the table no longer holds is evidence about a process that is gone, where there is no identity left to be wrong about, so the stop falls to the run's environment mark and reaps the worker its exited supervisor left reparented to init instead of refusing — or raising out of a group lookup for a pid with no process. crew stop reports the pids ended, the survivors and the worktree holders; the supervisor's exit record names the pids its signals reached; a run whose supervisor and recorded worker pid are gone but whose environment mark lives reads alive, so it is no longer classified complete or scoring.
