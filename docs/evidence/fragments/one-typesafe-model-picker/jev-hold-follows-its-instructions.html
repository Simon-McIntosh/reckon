The routing instructions name the serving lanes and the key form Jev is answered by

Section §26 replayed the two recorded review holds with the serving-lane facts in the state and Jev still held, at 0.87 and 0.89. Two causes sat in reckon/crew/picker/templates/questions.jinja. The instructions described each option key as its lane and its model joined with a colon, but option_key returns <lane>:<model>:<backend> — the backend is the part that keeps two configured backends sharing a lane and a model distinct. The instructions also never named serving_lanes or hold_waits_for, so a hold read as wait for any lane to free even when one lane alone could run the node.

Both recorded holds were replayed from their run records (r-20261007T075608324298-review-of-subscription-lanes-record-no-spend, r-20261008T023220940800-review-of-member-friction-asserts-its-own-writes) over a review config that withdraws every metered lane from review routing. In both reconstructed states local_lane.admission reads admitting (headroom 7), not full, paused or unavailable, and serving_lanes is ["local"] with hold_waits_for naming the local lane, the only lane that can serve this node. Verdict: the recorded holds were not the instructed answer. The instructions reserve a hold for the local lane only when admission is full, paused or unavailable; it was admitting, so the instructed answer was to route, and the hold was driven by the missing facts rather than by the admission rule.

The instructions now name serving_lanes and serving_lane_count, state that a lane absent from serving_lanes cannot run the node however much pressure it shows, and state that when exactly one lane can serve the node a hold waits for that lane alone. The option key is described as its lane, model and backend joined with colons. Both the instructions and the hold criterion carry the single-serving-lane rule.

Four real Jev calls (typesafe/jev-1.13, Decisions endpoint) replayed both held states with the rest of the state held fixed, before and after the instruction change. All four route the node to the one serving lane; no hold is selected. Before: hold probability 0.05 (subscription) and 0.03 (member-friction). After: 0.15 and 0.13. The recorded 0.83 and 0.84 do not reproduce under these reconstructed conditions, and the instruction change leaves the pick a route while naming the lane a hold would wait on.
