The member-friction guard asserts its own writes, not peer activity

The teardown of tests/test_member_friction.py compared the whole real crew store before and after each test (assert _real_stores() == before), so a peer session dispatching or committing during a suite run made it error in both arms of a merge check. The guard now watches the real crew home — the destination an escaped write reaches — and asserts only that this fixture's ids never reach it, so peer activity around it is ignored while a genuine leak is still caught.

An independent review found the first cut of the guard watching a temporary directory that neither the code under test nor the fixture wrote, so it could not fire on the escaped write it exists to catch (fc0907bc0cd); the guard's default target is now the real crew home, with a RECKON_GUARD_HOME override redirecting it to a temporary stand-in for the tests that plant entries. The review also found the previous manifest recorded a clean after_suite the head log contradicted (f366309052d); the record is corrected here to the head log's own result.

The defect reproduced

Recorded at the base revision in ~/.cache/reckon-suite-logs/merge-subscription-lanes-base.log: ERROR tests/test_member_friction.py::test_unnamed_dispatch_is_admitted_while_a_review_worker_is_alive at assert _real_stores() == before, the pointer list differing because entries appeared in the live directory while the 16-minute suite ran, in a run reporting 2731 passed, 3 skipped, 4 warnings, 1 error. The whole-store comparison names no fixture identity, so it cannot tell a leak from a peer's arrival.

What changed

  • _guard_store() returns the real crew home (Path.home()/".config"/"reckon") by default — the destination an escaped write reaches when a dispatcher bypasses the isolated RECKON_HOME — so the guard watches the write it exists to catch. RECKON_GUARD_HOME redirects it to a temporary stand-in for the tests that plant entries, so those never touch the operator's real home.
  • _fixture_writes_under(store) returns a live pointer only on an exact filename match for the fixture's run ids (r-first.json, r-second.json), and the project roster only when it names fixture-member. An exact-name match keeps the guard peer-safe where a substring match would fire on any roster describing a sample or a per-second rate.
  • A guard_stand_in fixture installs the redirect and removes planted entries after the guard has looked; test_isolation_guard_watches_the_escape_destination asserts the default target is the real home and not a temporary directory.
