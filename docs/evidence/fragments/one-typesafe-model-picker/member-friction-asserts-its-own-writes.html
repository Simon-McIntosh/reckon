The member-friction guard asserts its own writes, not peer activity

The teardown of tests/test_member_friction.py compared the whole real crew store before and after each test (assert _real_stores() == before), so a peer session dispatching or committing during a suite run made it error in both arms of a merge check. The guard now watches a temporary crew home that stands in for the machine's real one and asserts only that this fixture's ids never reach it, so peer activity around it is ignored while a genuine leak is still caught.

The defect reproduced

Recorded at the base revision in ~/.cache/reckon-suite-logs/merge-subscription-lanes-base.log: ERROR tests/test_member_friction.py::test_unnamed_dispatch_is_admitted_while_a_review_worker_is_alive at assert _real_stores() == before, the pointer list differing because entries appeared in the live directory while the 16-minute suite ran, in a run reporting 2731 passed, 3 skipped, 4 warnings, 1 error. The whole-store comparison names no fixture identity, so it cannot tell a leak from a peer's arrival.

What changed

  • A real_store fixture makes a temporary crew home the guard target and installs it as RECKON_HOME; the operator's real home is neither read nor written.
  • _fixture_writes_under(store) returns every live pointer or roster row under that home naming the fixture's project (sample), member (fixture-member) or run ids (r-first, r-second). _assert_isolation refuses when any is present.
  • A peer_dispatch fixture plants an unrelated pointer for the duration of a test and removes it after the guard has looked, standing in for a concurrent dispatch.
