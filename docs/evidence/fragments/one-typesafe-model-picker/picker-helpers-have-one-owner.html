Each duplicated picker helper and the profile cache have one owner

Design review found picker helpers copied across modules and a hand-rolled run-time-profile cache beside the shared one. Both are now single-owner: the helpers live once in reckon/crew/run_time_profile.py and are imported everywhere else, and the profile cache is served by reckon.capabilities. No rendered picker figure changed.

What landed

  • One owner per helper. run_time_profile._size_class owns the budget/token size classification; lane_context._bucket, a byte-for-byte duplicate, is gone, and lane_context._size_of now delegates to _size_class by handing it a one-field row. _number and _percentile are defined once in run_time_profile and imported by picker/outcomes.py and picker/lane_context.py; the local copies and their import math are deleted. _number preserves the input's own type — an int stays an int and a float stays a float — while rejecting bool, non-numeric and non-finite values. Merging the three copies without this also merged their return types, and the picker state then rendered an integer wall-second figure as 300.0 where the base rendered 300; the type-preserving form restores the base's bytes.
  • The profile cache routes through capabilities.cached_pick_input. The hand-rolled reader, writer, schema marker and key (_read_persisted_profile, _write_persisted_profile, _profile_key, _stat_stamp, _profile_cache_path, _PROFILE_FILE_SCHEMA) are deleted. lane_context now calls a new shared entry point, capabilities.cached_pick_input_rekeyed, which owns the schema marker, the atomic write and the corrupt-entry handling, and which re-keys after the build so a profile built while the ledger was still settling is not cached. The on-disk name is preserved (run-time-profile/<project>.json). The file name is checked against the ledger's safe-identifier pattern before it is formed, so a project string never forms a cache path unchecked; an unsafe id is read without caching rather than raising on a pick, which is what the base's guarded reader and writer did (they raised deep and caught ValueError at the cache boundary).
  • The lane document is read once. local_lane_load() now returns the parsed document it read, and lane_context.local_lane() reuses that value instead of reading it a second time.

Checks that could have failed

tests/test_picker_helpers_have_one_owner.py holds four tests:

  • A positive control asserting each behaviour has exactly one definition in run_time_profile.py — without it, a scan that finds nothing would read the same whether the helpers were merged or simply renamed away.
  • A one-owner scan asserting no module under reckon/crew/picker/ defines an owned helper name (_bucket, _number, _percentile).
  • A before/after render check: the bytes state.jinja rendered at the base revision for one frozen fixture (integer wall-second figures included) are committed as GOLDEN_STATE, and the head must reproduce them exactly. The bytes were produced by running the base tree's own code over the same fixture through render_base_state.py, never transcribed by hand. This replaced an earlier test that rendered the new code twice — a check that rendered the code twice moves with the code it is meant to hold still. It was confirmed to fail against a float-returning _number (p90_s":500.0 against the base's 500) before the type-preserving owner landed; log before-fix-render.log.
  • An unsafe-name guard asserting a project id that is not a safe cache file name never forms a cache path: the profile is read without being cached, and no file is written under the cache root.

One declared deviation from the spec

The spec listed _ledger_stamp among the symbols to delete. It is retained (beside _PROFILE_CACHE and _profile_cache_root) because three test files named by this node's own gate, and outside this node's write scope, pin them: tests/test_picker_foreign_wait_is_bounded.py and tests/test_one_cache_cascade_serves_every_kind.py. The shared cache takes a caller-computed freshness key, so a stamp accessor is legitimately the caller's responsibility; what was deleted is the hand-rolled reader, writer, schema and key, so the cache mechanism itself has one owner.
