Each duplicated picker helper and the profile cache have one owner

Design review found picker helpers copied across modules and a hand-rolled run-time-profile cache beside the shared one. Both are now single-owner: the helpers live once in reckon/crew/run_time_profile.py and are imported everywhere else, and the profile cache is served by reckon.capabilities. No rendered picker figure changed.

What landed

  • One owner per helper. run_time_profile._size_class owns the budget/token size classification; lane_context._bucket, a byte-for-byte duplicate, is gone, and lane_context._size_of now delegates to _size_class by handing it a one-field row. _number and _percentile are defined once in run_time_profile and imported by picker/outcomes.py and picker/lane_context.py; the local copies and their import math are deleted. _number keeps the strictest of the three prior semantics (rejects bool, non-finite floats), which is a superset of each caller's old behaviour on numeric input.
  • The profile cache routes through capabilities.cached_pick_input. The hand-rolled reader, writer, schema marker and key (_read_persisted_profile, _write_persisted_profile, _profile_key, _stat_stamp, _profile_cache_path, _PROFILE_FILE_SCHEMA) are deleted. lane_context now calls a new shared entry point, capabilities.cached_pick_input_rekeyed, which owns the schema marker, the atomic write and the corrupt-entry handling, and which re-keys after the build so a profile built while the ledger was still settling is not cached. The on-disk name is preserved (run-time-profile/<project>.json).
  • The lane document is read once. local_lane_load() now returns the parsed document it read, and lane_context.local_lane() reuses that value instead of reading it a second time.

Checks that could have failed

tests/test_picker_helpers_have_one_owner.py holds three tests:

  • A positive control asserting each behaviour has exactly one definition in run_time_profile.py — without it, a scan that finds nothing would read the same whether the helpers were merged or simply renamed away.
  • A one-owner scan asserting no module under reckon/crew/picker/ defines an owned helper name (_bucket, _number, _percentile).
  • A byte-identical render: one fixture state is rendered twice through state.jinja, the second render after the in-process memo is cleared so the profile can only come from the persisted copy. The ledger loader runs exactly once, the two renders are byte-identical, and the payload carries size_bucket == "30m_to_60m", p50_s == 200.0, p90_s == 300.0, runs == 2.

One declared deviation from the spec

The spec listed _ledger_stamp among the symbols to delete. It is retained (beside _PROFILE_CACHE and _profile_cache_root) because three test files named by this node's own gate, and outside this node's write scope, pin them: tests/test_picker_foreign_wait_is_bounded.py and tests/test_one_cache_cascade_serves_every_kind.py. The shared cache takes a caller-computed freshness key, so a stamp accessor is legitimately the caller's responsibility; what was deleted is the hand-rolled reader, writer, schema and key, so the cache mechanism itself has one owner.
