Headroom agrees with the context-window gate

Change. _context_block in reckon/crew/picker/snapshot.py now renders the estimate the context-fit verdict measured for that candidate's backend (context["estimated_tokens"], that backend's standing instruction chain plus the repository files the brief loads) and derives headroom_pct as 100 × (window_tokens − estimated_tokens) / window_tokens against the gating window the verdict compared it with. The request-level, harness-independent figure still governs the request estimate; only the per-candidate block moves to the gate's number. A backend declaring neither usable_input_window nor effective_input_window gets no gate verdict (context is None), so its block keeps the request figure as estimated_tokens and a null headroom_pct, as on main. This supersedes §15's rule that every block carries the request's one figure.

Measured. The new tests/test_headroom_agrees_with_the_gate.py offers two windowed backends whose standing chains differ (claude 60000, codex 51000, window 200000) and a third declaring no window, with the request figure at 55000. Each windowed block reports estimated_tokens equal to the estimate measured for that backend's chain — 60000 and 51000 — and headroom_pct of 70.0 and 74.5, the two differing from each other and from the request. The windowless block reports 55000 with headroom_pct null.

Negative control. Against the unmodified snapshot.py the new test fails at assert 55000 == 60000: the larger-chain backend's block reports the request figure's 55000 rather than the gate's 60000. 1 failed, EXIT=1 (negative-control-on-main.log).
