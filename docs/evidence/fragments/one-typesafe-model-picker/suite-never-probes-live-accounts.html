No test spawns a real provider account probe

A lane whose receipt-derived position is stale makes the lanes view re-query the backend's account probe. For a codex-backed lane that probe is reckon._backends.run_probe, which spawns <command> app-server. Whether it answers depends on the machine's codex login (CODEX_HOME, fallback $HOME/.codex): a logged-in home answers in about four seconds and the lane adopts the probe's own observation stamp, an unanswerable home costs the probe's twenty-second wait. A test's outcome and runtime therefore depended on ambient account state.

Change

  • Guard. A new autouse fixture no_live_account_probe in tests/conftest.py, beside no_live_jev, replaces reckon._backends.run_probe with a stub returning None — the exchange's documented no-answer result — so probe_budget returns its existing unknown block and every caller's no-answer path stays exercised. The guard is disabled for a negative-control run by RECKON_TEST_DISABLE_ACCOUNT_PROBE_GUARD=1.
  • Opt-in. A test whose own subject is the probe exchange passes probe_budget its own runner=/fetch=, or patches reckon._backends.run_probe itself, which replaces the guard for that test. No existing test file newly needed to opt in: every caller of probe_budget in the suite already passes runner= or fetch= and so never reached run_probe. The seam-patch opt-in is demonstrated by test_a_test_may_opt_in_by_patching_the_launch_seam.
  • Test. New file tests/test_suite_never_probes_live_accounts.py points CODEX_HOME at a home that would answer, spies subprocess.Popen and subprocess.run, composes a lanes view over a stale codex-backed lane with no probe_reader, and asserts no subprocess is attempted and the lane carries the run's record stamp (budget.run_observed_stamp(run)).

Negative control

With the guard disabled (RECKON_TEST_DISABLE_ACCOUNT_PROBE_GUARD=1), the no-subprocess test fails: AssertionError: a live account probe was spawned: [('Popen', ['codex', 'app-server'])], 1 failed, 1 passed in 21.18s, EXIT=1 (negative-control.log). The 21 s is the real probe wait. With the guard, the same file is 2 passed in 0.96s, EXIT=0.
