A named-backend dispatch resolves deterministically

A shadow names the candidate backend it compares and a lane change names the backend it moves to, so the picker has nothing to select for either. Under routing.picker=route plan_dispatch still resolved the picker for them and refused with picker route has no selection; with a selection present it would have silently rerouted the run off the shadow's named candidate. Both paths now resolve with route=deterministic and record route deterministic on the run.

What changed

  • shadow passes route=deterministic to both its dry-run plan_dispatch and its dispatch, so the candidate it names is the backend that runs.
  • change_lane passes route=deterministic to its plan_dispatch and records the resolved route on the run it moves (a resolution that declares no route leaves the run's recorded route unchanged).

Measure

Two cases drive each path under route mode. At the base revision both fail with picker route has no selection; at the committed head both pass. The named gate (the two files plus every test that calls shadow(/change_lane() reports 94 passed, EXIT=0 at head, so zero failure ids are added.
