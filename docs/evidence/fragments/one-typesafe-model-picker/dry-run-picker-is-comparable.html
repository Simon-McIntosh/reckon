A dry-run report is comparable when the picker answers

A dry run resolves the node and prints the DispatchPlan without launching anything. When the picker answered, that report carried the selection's per-call latency_ms and jev_latency_ms, so two previews of one node differed in a field the picker happened to measure — a comparison between two dry runs read as two different dispatches for a reason unrelated to what was being compared. Under routing.picker=shadow the preview carried the picker's answer even though the route never used it, so the report moved with the picker while the dispatch did not.

What changed

plan_dispatch now records the picker answer on the resolved plan only when the route used it (route == "picker"), and strips the per-call latency fields from what it records. A shadow or deterministic preview therefore carries no picker_selection at all, and a routed preview keeps the decision it routed by — action, backend, model, probabilities, reason — minus the timing behind it. The live dispatch record is unchanged: it takes the selection from its own local, not from the plan's.

Measure

test_a_report_changes_no_other_dry_run_field masks _at stamps and compares a reported against a quiet dry run; it fails at the base revision on picker_selection.latency_ms and passes at the committed head. The new test_a_dry_run_report_is_comparable_across_picker_modes pins both modes with the picker stubbed to report a different latency on each ask: shadow carries no selection, route carries the decision with no latency field, and the two previews compare equal once clock stamps are masked. The 22-file gate reports 1 failed, 441 passed at the base revision — the target test alone — and 444 passed, 0 failed at the committed head; the two extra tests are the new parametrised case. No failure id is added.
