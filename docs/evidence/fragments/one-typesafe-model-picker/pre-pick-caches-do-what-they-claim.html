The pre-pick caches and guards do what they claim

Three places where §13's code and tests claimed more than they did were closed. Each is stated below with the reproduction that failed on the base revision 1f00bba45 and the check that now passes.

Each defect, its base reproduction and its head check
ItemBase reproduction (1f00bba45)Head behaviour
1. The identity cache is keyed by the repository Resolving a worktree path then its mount ran two git probes: the mount after the worktree re-probed git: [(… 'rev-parse', '--path-format=absolute', '--git-common-dir')]. The cache keyed by the path string, so the two spellings of one repository were two entries. The memo is keyed by the resolved path string probed, with each result aliased under the resolved repository-root path it returned, so a worktree path followed by its mount costs one probe where it was two. It is not keyed by the git common directory: a mount probed before its worktree, or two linked worktrees, still probe separately.
2. The sweep guard exercises the grace The sweep test only asserted that SCRATCH_GRACE_SECONDS appeared in the source, so it stayed green when the sweep stopped applying the grace. garbage_collect_orphan_scratch runs on directories one second inside and one second outside the grace the survey docstring states; the inside directory is kept and the outside one removed, and the test fails if the sweep stops applying the figure.
3. The driver counts git probes The driver passed at base: it timed a fixture whose local git probe is milliseconds, so it never showed the fix. The driver counts git invocations. It discriminates base on the first dispatch's probe count — the worktree and its mount cost one probe at head, two at base — and asserts the second dispatch runs none; the second dispatch is zero at base too, because the base memo already holds the worktree spelling it names.
