Subscription lanes record no per-token spend

The ledger recorded the harness's total_cost_usd as spend for the claude lanes, which run on the operator's Claude subscription, and for the codex lanes on the codex codex-sub group. Nothing is billed per token for either. Reports showed claude-opus at $35.77 for six runs when nothing was charged per token, so a subscription lane could rank as the dearest on any surface that ranks or sums cost_usd.

The model catalogue declares the claude lanes' budget group (claude-sub); a budget group whose name ends in -sub is subscription-billed. The flight schema admits no separate billing key, so the group name carries the declaration. The ledger treats such a lane's harness cost like an unmetered one: cost_usd and cost_usd_cumulative are nulled, cost_usd_imputed is set, the figure is preserved under harness_reported_cost_usd, and the lane is labelled billing: subscription. An unmetered local lane (clive) keeps its original shape. The cost surfaces (capabilities routing rows and the picker's metered_spend) reinterpret already-committed rows from the catalogue at read time and report subscription lanes as billing: subscription, not dollars; no committed ledger row is rewritten.

The lookup reads resolved flight config through the budget-group owner, not the catalogue file alone, so a host or project override of a lane's budget_group wins over the catalogue. A catalogue that does not parse raises flight.FlightConfigError; the ledger falls back to no declaration rather than propagating it, so one bad catalogue edit cannot stop every promotion — the lane is left metered and keeps its recorded cost.

Tests are in tests/test_subscription_lanes_record_no_spend.py. The node gate (tests/test_ledger*.py, tests/test_capabilit*.py, tests/test_picker_outcomes.py, tests/test_flight_catalogue_layer.py, tests/test_budget_group*.py and the new file) ran 328 passed at the committed head (319 at the base revision, whose count lacks the new file).
