Pick paths carry the authority

Item 1 — every pick path passes the dispatch authority — landed. The production dispatch already handed its resolved authority into the pick, but the dry-run preview and the deferred shadow pick reached the picker with no authority: they fell through a fallback that swallowed a resolution failure, so a dispatcher-granted landing fragment was charged on those two paths with nothing saying why. Both paths now resolve the authority through one helper, resolve_picker_authority(project, repo) (fragment), which returns (authority, None) on success and (None, "TypeName: msg") on failure, catching CrewError, PlanVisibilityError, OSError, KeyError and TypeError. dispatch_picker_selection gained an authority_error parameter and threads it into the recorded selection — the resolved pick carries it as a key, a fallback carries it as authority_error — so a reader who sees the granted fragment charged can see why it was not exempted. The dry-run site in crew_dispatch_commands.py and the shadow site _record_shadow_picker_selection each call the helper and pass authority= and authority_error=.

Item 2 — one backend-settings rule for both figures — blocked and named. The request estimate supplies no backend settings (estimated_context_tokens(node, repo, authority=…), harness-independent), so it is one figure. Each candidate's context block renders its own context["estimated_tokens"], which _context_fit_verdict computes from that backend's resolution.backend_settings; two backends whose standing chains differ (a cli-dialect model versus a codex one) therefore get different candidate figures while the request wears one. The rule that unifies them lives in reckon/crew/picker/snapshot.py: _context_block (line 216) must render the once-per-pick harness-independent figure (node_tokens) as every candidate's estimated_tokens rather than the per-backend context["estimated_tokens"], and headroom_pct follows from it. That file is not in this node's write scope and is held exclusively by the live node hold-names-the-serving-lane (run r-20261008T161834154362, session s25-picker, write path reckon/crew/picker/snapshot.py). Per the brief's conditional, this item is blocked and the change is named here rather than implemented.

Four tests in tests/test_pick_paths_carry_authority.py drive both paths through the CLI (a real CliRunner dispatch against a temporary RECKON_HOME, a temporary mounts.json and a seeded git repository) and assert the resolved authority reaches the pick on each: test_the_dry_run_pick_passes_the_dispatch_authority and test_the_shadow_pick_passes_the_dispatch_authority spy on dispatch_picker_selection and require a non-null authority whose plan.project is the dispatched project, with authority_error null; test_a_failed_authority_resolution_is_reported_not_swallowed passes a failure through and requires it to ride on the selection; test_the_resolver_reports_its_failure_instead_of_raising proves the helper returns a (None, reason) pair rather than propagating.
