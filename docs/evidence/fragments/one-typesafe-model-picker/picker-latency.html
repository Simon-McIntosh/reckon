picker-latency — one project read and one budget snapshot per pick

What changed. A pick judges every configured backend. Each candidate's competence verdict called capabilities.project_cache_status, which reloaded the whole project ledger, so a nine-candidate pick paid nine whole-ledger reads, and each candidate's plan lookup scanned the docs tree. The verdicts now accept preloaded inputs: routing.shared_verdict_inputs loads the capability cache and the ledger freshness key once per pick, and snapshot.candidates threads that bundle into every candidate's _competence_verdict. A pick also enters resources.resource_scan_scope(), so the docs tree is scanned once rather than once per candidate.

Nine-candidate measurement (fixture with nine eligible backends, tests/test_picker_latency.py): the ledger loader is called once per pick; at the base revision it is called nine times, one per candidate. The budget view is taken once per pick. The unshared arm of the same fixture reads the ledger nine times and produces the same reason list as the one-read arm, so the sharing does not change any verdict. The declared negative control — restoring a per-candidate the ledger read in the competence check — makes the call-count test read 10 == 1 and fail, in negative-control.log.

Replay summary. The median Jev latency is now taken only over the rows that made a Jev call, with jev_calls naming how many those are; a pick that made no call is no longer counted as a zero-millisecond call. Refused-model picks are derived from each picked backend's serving observation collected at replay time, instead of from a hardcoded model name, so the figure can be non-zero. A fixture whose picked model's observation reads refused shows a count of one.

Done-when item (4) is not met in this node, deferred by the coordinator. The live replay arm could not run here: the serving probe writes a lane-probe lock under ~/.config, which the worker fence mounts read-only, so crew pick --replay stops before the first row with Error: [Errno 30] Read-only file system and exit 1 (replay-after.log). Both the after arm and the base-revision arm need that probe, so neither the per-pick median nor the maximum for the same twenty nodes is recorded here. The coordinator has deferred item (4) to a separate unfenced measurement node (picker-replay-measure), which will record the per-pick medians and the maximum through the combined code after this node merges. The correctness measures above are unaffected and pass.
