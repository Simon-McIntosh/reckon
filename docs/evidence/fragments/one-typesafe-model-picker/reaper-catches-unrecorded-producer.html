The per-test reaper reaches a producer that never wrote its seat record

The per-test reaper in tests/conftest.py found producers only through their seat records. A producer a test armed but which had not yet written its record when the test ended was never signalled; it survived to fail the session-end leaked_watch_producers scan at teardown, which is the load-dependent failure recorded on this node.

reapable_watch_pids(root) — the seam the per-test reaper signals — now unions the records under root with the live crew watch producers whose own /proc/<pid>/environ names a RECKON_HOME under root (the new unrecorded_watch_producers_naming). A process whose environment cannot be read, or that names any other home, is still left alone. The named half is a whole-host scan, so the per-test fixture runs it only for a test marked arms_watch_producer (per_test_reap_pids(root, armed=…)); the session-end reap passes include_named_half=False and keeps the scan and its failure unchanged as the backstop.

The new test tests/test_reaper_catches_unrecorded_producer.py arms a stand-in producer whose argv and environment match _live_watch_producers, lies under the test's tree, and writes no seat record. It shows the precondition (live, no record), the repair (reapable_watch_pids names it; the child's own exit is -SIGTERM), and the scoping (the named half is absent for an unarmed test, present for an armed one).

Negative controls: revert the reaper to record-listed pids and the unrecorded-stand-in test fails; revert the scoping and the scoping test fails.
