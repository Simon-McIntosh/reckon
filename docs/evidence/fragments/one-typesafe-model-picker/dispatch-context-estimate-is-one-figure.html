The production pick passes the dispatch authority so Jev sees one context estimate

The picker already threaded a dispatch authority through both the request-level estimate and each candidate's context-fit verdict, but no production caller supplied one. A node with a dispatcher-granted landing fragment was therefore charged for its own granted path in the figure Jev weighs, and the review that found this called the fix inert on every production path. This node makes the production call hand the authority over.

What changed

  • dispatch_picker_selection takes an authority argument and resolves the same one itself when a caller does not hold it — which is how the deferred shadow-pick and the dry-run pick reach it, neither of which holds the dispatcher's resolved authority.
  • The request-level estimate is measured with that authority and the same harness-independent rule the candidate scan uses for its once-per-pick figure, removing the second divergence the review named (the request passed the local backend's settings while the scan measured without one).
  • The authority travels into picker.pick(), so each candidate's context-fit verdict exempts the granted fragment exactly as the request figure does.
  • The main dispatch() call site passes the authority it already resolved, so the pick's figure and the dispatch's plan authority are the same object.

The reproduction

Before the change, driving dispatch_picker_selection for an implement node granted its own landing fragment reported a request estimate that charged the fragment, while the candidate blocks it rendered carried the exempt figure: two figures for one node. After the change, a real dispatch_picker_selection call renders the same number everywhere — the request figure and both candidate blocks all read 51535 tokens for a node whose granted fragment is otherwise charged. The granted fragment is what moves the figure: measured without the authority it is charged, and the estimate reads larger.

The check and its control

tests/test_dispatch_context_estimate_is_one_figure.py drives the real production call with a stub picker client and asserts both that the request figure equals every offered candidate's context.estimated_tokens and that the figure is the exemption-bearing one — equality alone holds even when both sides are charged, so the exemption is pinned separately. The declared negative control stops passing the authority from dispatch_picker_selection; the production one-figure test then fails, with the request estimate reading 53821 against the exempt 51535. The run's output is kept at negative-control.log in the node's run directory, ending in a non-zero EXIT= line.

Gate

Head at the node's tree: 196 passed (EXIT=0) across the context-estimate, picker and dispatch-speed suites. The same gate at the pre-change revision carried a single pre-existing timing failure in tests/test_picker_dispatch_pace.py (an elapsed-time assertion off by 1.6 s), so head carries no added failure. The gate files are gate-head.log and gate-base.log in the node's run directory.
