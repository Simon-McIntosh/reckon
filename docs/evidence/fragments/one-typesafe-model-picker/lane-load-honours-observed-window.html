Local lane load honours the router's observed window

Base inspected: 2a581fb443537002de44c581f544abc78fac9d3e. local_lane_load in reckon/crew/run_time_profile.py read worker_slots straight from the lane document's admission block, so a slot figure the router had published while its averaging window was still empty read as a real capacity. The router states that window as observed_seconds, and its own dispatch allowance refuses a slot figure resting on no history: a zero, negative or absent window falls back to headroom. The load reading did not apply that rule, so the two surfaces could disagree about the same lane.

What changed

pathchangewhy
reckon/crew/run_time_profile.py local_lane_load calls the dispatcher's _lane_worker_allowance and carries the published worker_slots only when that reader chose one of the router's own slot sources; otherwise the field is None. The window test is reused, not restated. A slot figure averaged over no observed history is read as absent, matching the dispatch allowance, so the load surface and the dispatch surface cannot disagree about which slot figures rest on real history.
tests/test_run_time_profile.py Adds test_worker_slots_rest_on_an_observed_window (zero, negative and absent observed_seconds each yield None) and test_a_positive_window_carries_the_published_slots; the present-document positive control now states a positive observed_seconds so its worker_slots figure is carried legitimately. Each new guard is exercised by a case whose opposite was the recorded defect: the three window states that must withhold the figure, and the one that must carry it.
