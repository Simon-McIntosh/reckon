estimate-stage-times-the-estimate — estimate_ms times the context estimate, and a cached view is not shared

The picker's timing line recorded estimate_ms as the duration of a trivial math.ceil(len(rendered) / 4) division, so it read 0 on every production pick while the context estimate that actually costs time — estimated_context_tokens — ran inside candidates() counted only within snapshot_ms, and again, untimed, in dispatch_picker_selection before pick() began. A test that injects a 50 ms estimator measures the stage against the computation it exists to time.

A second defect sat in the cached budget view's zero-delta path. _reage_budget_report returned value["report"] by reference when the clock had not advanced, so a caller that mutated the view it was given rewrote the cached composition and the next read of the same value served the mutation. Reproduced on the base revision with a direct call: the first read is the cached report object and a mutation on it reads back on the second call.

Fix. candidates() now measures the context estimate once per pick and reports the figure and its own duration through an estimate_out outlet: a figure already on the request (the dispatch path measures it before the pick's own bound) is reused rather than measured a second time. pick() records that duration as estimate_ms, taking a caller's pre-pick duration when the figure was handed in; the rendered-length division still produces the token figure but carries no stage of its own. dispatch_picker_selection times its pre-pick measurement and hands the figure and its duration into the pick. _reage_budget_report copies the report on the zero-delta path, normalised the same way the advancing path normalises, so a reused view equals the figures the same files produce and never aliases the cache. The comment that claimed most plans declare no total — a claim contradicted by the census below — no longer asserts an unmeasured share; the rule it explains is kept.

Measured share. A census of the mounted projects' docs/plans/*.html (excluding _-prefixed pages) finds 284 of 404 plans (70.3%) declare a positive plan-effort-hours total, so the old claim that most plans declare none was false. The figure is recorded here rather than written into the comment, where a moving absolute would rot; the comment keeps the rule and drops the share.
