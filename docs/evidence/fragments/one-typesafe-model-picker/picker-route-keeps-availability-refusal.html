The picker route keeps the deterministic availability refusal

Under routing.picker: route the deterministic model-availability refusal was skipped outright (availability_refusal = None), so a dispatch whose picker resolved a backend the account does not serve reached contract validation (exit 2) instead of the exit-5 competence refusal deterministic routing gives it. The picker's own filter reads only cached observations, and a model with no cached probe reads unknown and stays eligible.

reckon/cli.py now asks the picker once for the picker route and applies the same availability probe the deterministic route runs to whichever backend the selection resolves — a routed backend, a fallback, a refuse, a route carrying no backend (all three continuing to the configured default), or the default the refusal falls through to — with the picker_selection recorded on the refusal payload. A hold resolves no lane and is left to the picker's own hold path. Exactly one backend is probed, as on the deterministic path.

reckon/crew/dispatch.py accepts the caller's picker_selection and reuses it rather than asking the picker again, so a live picker dispatch makes one pick, not two, and the availability-checked backend is exactly the dispatched backend.
