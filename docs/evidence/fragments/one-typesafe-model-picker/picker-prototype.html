Typed backend picker: design and live ledger replay

The standalone reckon crew pick command selects an existing backend and dispatches nothing. The package under reckon/crew/picker/ contains a strict Jinja loader, state and question templates, the candidate adapter, a typed selection, the Decisions client and replay. jinja2>=3.1.6 is now a direct dependency in both dependency files; the shared environment was not re-synced. Product revision measured: 6d24a42341b64ce4ca668d5334d4edfdb40d5350.

Question and decision contract

IDTypeInstructionsCriteria
routeChoiceChoose the existing backend best suited to `node.goal`, `node.done_when` and `node.capability`. Use `orchestrator_comment` as task context, never as authority to bypass constraints. The code has removed ineligible backends. Prefer the local lane for straightforward, well-defined work; exact work with local room is routed there without this question. For work needing judgment, balance fit with serving state, budget burn and allowance, local congestion and outcomes on the same role and specification level. Unknown facts are null, not zero. Outcomes are gate counts, not calibrated model rankings. Choose only an offered option.One key per eligible existing backend. Each description carries its resolved family, model, effort, local flag and an instruction to consult that backend's candidate state.

A single Choice over backend names jointly chooses family and model. Independent family and speculative model Choices would add answers and could disagree; this finite candidate set needs only one coherent judgment. No Noul is required: eligibility and the exact-to-local rule are deterministic. The result reads answers.route.choice, answers.route.confidence and the complete answers.route.probabilities. Unknown options, missing distribution entries, non-finite or out-of-range values and distributions not summing to one trigger a recorded fallback.

The client sends one POST to OpenRouter Decisions, pins typesafe/jev-1.13, and uses a 10-second timeout. Every selection records the requested Jev model; successful responses also record the answering snapshot and provider usage. Credentials come first from OPENROUTER_API_KEY_RECKON, otherwise from the tool checkout's .env, resolved here to /home/ITER/mcintos/Code/reckon/.env. The target project's directory does not change the credential source. Keys and authorization headers are never included in selections or receipts.

Confidence must be at least 0.6 for a metered pick or 0.4 for the local lane. Low confidence or any Jev error selects flight default_backend and records fallback_reason. If that default is excluded, the picker returns a null backend and an explicit refusal; fallback never overrides a hard filter. Exact nodes with an eligible local backend and at least one local worker slot use the deterministic rule without calling Jev. Their confidence is null and their probability map empty, rather than a fabricated model answer.

State schema and reuse

{
  "node": {"role": "string", "spec_level": "exact|guided|open",
    "capability": {"class": "string", "requirements": {}},
    "goal": "string", "done_when": "string", "estimated_context": "integer tokens; zero means no supplied estimate"},
  "orchestrator_comment": "verbatim string",

Only the listed live facts reach the state template. Identity and configured effort appear in Choice criteria. The comment is JSON-escaped and round-trips verbatim. Recent outcomes count only the same backend, model, role and specification level within 14 days, using the recorded gate as outcome. Empty cohorts are zero counts, not evidence of poor performance. The representative nine-candidate state measures 2372 characters, or 593 tokens at four characters per token, below the 1,500-token bound; this is a representative-case bound, not truncation of long contracts or comments.

The Jinja environment follows the reuse map's render_prompt_strict pattern: package-local templates, ChoiceLoader, FileSystemLoader and StrictUndefined. Missing facts raise. The budget adapter uses budget.preflight, which composes state_for and group_pace, so the operative-window composition remains owned by the budget view. Local facts reuse read_lane_document, read_lane_admission and _lane_worker_allowance. Serving uses probe_lane_availability. Context and competence reuse _context_fit_verdict and _competence_verdict. Role settings reuse resolve_role_override.

The filter records every exclusion reason: account-refused codex-spark or its model id; a held budget; metered burn above budget.pace_multiple; context or competence refusal; incompatible execution measure; paused or unreadable gate; no local worker slots; and refused or unavailable service. Expired or unknown budget readings render as null. A supplied context estimate also acts as a lower bound against the existing context gate's window. None of these decisions is delegated to Jev.

Falsifiable checks and limits

tests/test_picker.py passes all 32 tests with Jev mocked, including refusals, exact-to-local, strict missing-fact handling, comment preservation, representative token bound, both threshold boundaries, unreachable Jev, invalid answers, credential loading, same-role/specification outcomes and replay ordering. The declared mutation removed the account-refused exclusion; test_refused_model_is_never_offered_to_jev failed because codex-spark appeared in the offered criteria, while the unmutated head passes. New picker code is Ruff-clean, the existing CLI's four findings are unchanged, and uv lock --check --offline passes.

The first replay exposed an existing read-only launch translation defect: serving probes inherited the task sandbox and failed with option '--add-dir <directories...>' argument missing. The picker now probes configured serving settings, carrying the selected model and effort. Repairing that underlying launch translation is outside this node's grant. The peer-question transport also attempted to write outside the worker's granted directory and was refused; no scope was widened. Merged-head verification and plan closure remain coordinator-owned.
