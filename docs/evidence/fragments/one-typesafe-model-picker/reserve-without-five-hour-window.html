Recommendation the code now implements

On an account with no five-hour window, the reserve reads the provider-reported primary window as the operative window; it does not treat the missing five-hour sibling as an unreadable account. The pacing merge carries the provider's own window length into the reading (reckon/crew/window_reading.py: WindowFigure.window_minutes, taken from the provider's windowDurationMins with named-period fallbacks) and derives the group allowance from the operative window (reckon/budget.py: _operative_window; a primary-only reading's allowance is the elapsed fraction of its reported period leaned by budget.pace_multiple). The merge's own record (docs/evidence/fragments/one-typesafe-model-picker/codex-window-pacing.html) captures the provider response it was measured against: one primary window of windowDurationMins: 10080 (10,080 minutes), no secondary, and a paced row reading 1.00% used. A short fallback period and a long primary therefore pace by the same rule, and a later change of the reported length needs no code change.
