The suite never calls the live Jev service

Since routing.picker became route by default, any test that dispatched with no lane named called Jev over OpenRouter. The suite therefore depended on an external service, spent money on every run, and read Jev's judgement back as a test outcome: a whole-suite run failed test_a_layer_removing_a_default_leaves_it_writable_and_records_it with a real BudgetHold: wave held on budget ... picker selected hold.

An autouse no_live_jev fixture now removes OPENROUTER_API_KEY_RECKON from the environment, adds a RECKON_PICKER_CREDENTIAL override to the client, and points credential resolution at a path holding none. With no usable credential the client raises LiveJevDisabledError before it builds a request, so the picker records its usual fallback (jev-error: LiveJevDisabledError) and dispatch continues along deterministic routing. tests/test_suite_never_calls_live_jev.py asserts the urlopen spy is never reached, the fallback reason names the disabled live call, the routed exit code equals the deterministic one for the same dispatch, and the real credential is unreadable under test.

Gate: 154 passed at head against a 152-passed base (the two new tests), zero new failures. The declared negative control — removing the autouse fixture — turns the urlopen spy test red.
