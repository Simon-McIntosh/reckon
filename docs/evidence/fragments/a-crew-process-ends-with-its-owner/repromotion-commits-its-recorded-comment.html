A re-promotion commits the plan comment its own earlier attempt recorded

Promotion writes the plan landing comment, appends the ledger row, then commits both as one landing. When that commit fails — a held index.lock is the measured case — the rollback drops the newly created ledger run file but cannot restore the tracked plan file, because the same lock blocks git restore: the comment stays on disk uncommitted. The re-promotion read it back as already recorded and, in promotion.py:_plan_comment_store_path, returned no plan path for the already-recorded branch, so the landing commit carried only the ledger row and the plan file stayed dirty until committed by hand.

The fix carries the plan file whenever it differs from HEAD, not merely when this call recorded the comment: _path_differs_from_head compares the working tree to HEAD with git diff --quiet, and _plan_comment_store_path includes the file when the comment is newly recorded or the already-recorded file differs. A genuinely clean idempotent re-promotion still returns no path, so it stages and commits nothing.
