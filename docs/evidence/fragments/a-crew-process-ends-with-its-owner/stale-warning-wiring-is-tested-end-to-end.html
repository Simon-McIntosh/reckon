The stale-producer deferral is tested through the reload's own wiring

What changed

The review of the landed stale-producer deferral found two coverage gaps in tests/test_stale_producer_warning_waits_for_its_reload.py. The deferral flag the loop reads, _follow_watch_lines(reloaded_in_place=...), was always injected directly by the existing cases, so nothing exercised the place the flag is actually computed: crew_follow reads _FOLLOWER_CHECKPOINT_ENV in os.environ before it pops the checkpoint value, and _FollowerReloader.poll is what puts that variable into the environment the replacement image receives on a non-seat reload. No case covered a fresh arming either, which must report the mismatch at once rather than defer it. Only the test file changes; no product source is touched.

  • tests/test_stale_producer_warning_waits_for_its_reload.py: a helper _reload_environment constructs a real _FollowerReloader for a non-seat follower, stubs its import proof and os.execve, and returns the mapping the reloader composed for the replacement. A helper _follow_events drives the real crew follow click command with --json, so the deferral is decided inside crew_follow and not by an injected flag. test_a_reload_handed_through_crew_follow_defers_the_mismatch runs the reloader's hand-off, adopts only the checkpoint variable into this process's environment exactly as a replacement image would, and asserts the reloading note appears while the stale advice does not. test_a_fresh_arming_through_crew_follow_reports_the_mismatch_at_once removes the checkpoint variable and asserts the opposite: the stale advice appears at once and no reloading note does.
