A producer recreates a registration unlinked under it

What changed

  • reckon.crew.recovery._recreate_unlinked_registration is new. On each wake-up the producer compares the seat record path against the inode it holds; when the path names no file, it recreates it, locks the fresh inode and writes its record, naming its own pid. The seat handle registry is repointed at the new descriptor. A path a replacement producer has meanwhile taken is left alone and the loop returns, so a superseded producer ends rather than overwrite a seat that is no longer its own.
  • reckon.crew.recovery.watch_ticker, the producer loop, calls it before the lease check on every wake-up.
  • reckon.crew.recovery._watch_registration writes the arm-time parent_pid fields through the held seat handle rather than reopening the path. The reopen raised FileNotFoundError and ended the producer before it polled once when the file was unlinked in the window after the claim.

Which file unwatch reads. crew unwatch opens the seat record at crew.watch_lock_path(project), not the lease registration the producer's lease lives in (watch_registration_path). The lease registration is written read-modify-write by two writers and records lease_renewed_at; unwatch never opens it, so unlinking it cannot blind unwatch. The seat record, whose inode carries the lock and whose record carries the pid, is the file this node recreates.
