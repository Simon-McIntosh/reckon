A pointer's stored phase advances past starting

The launcher wrote only starting and nothing advanced it afterwards, so the stored phase a reader sees — the follower's re-arm replay, the MCP views, a peer's tooling — stayed at the pre-spawn label for the whole life of the run; at review time 26 of 41 live pointers read starting. The per-run supervisor is the only process that touches the pointer while the run is alive, so it now writes the advance: working once the worker is spawned, and the delivered manifest's terminal status once the worker has exited, or launch-failed when the worker reached no model. A pointer that is gone (a discard took it), or that names a later attempt, is left untouched. Commit 0fe6861.
