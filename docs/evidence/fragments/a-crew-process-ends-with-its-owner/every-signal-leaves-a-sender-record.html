Every signalling path records its sender in the target run

What changed

  • reckon.crew.routing gains the one shared writer, _write_sender_record(run_dir, target_pid, reason, sig, target_pgid), and run_directory_of(record), which resolves a run's directory from its id or its stream path. The record is one JSON line appended to senders.jsonl in that run's directory, carrying {sender_pid, sender_argv0, target_pid, target_pgid, reason, signal, time}. It is written before the signal, so a signal that also ends the sender still leaves the attribution behind; a write that cannot land (a run directory a rollback already removed) never withholds the signal.
  • routing.signal_worker is now the only function in the crew that calls os.kill or os.killpg. It takes an optional run_dir/reason and writes the record before delivering; routing._signal_process_group forwards both, so the shared writer is reached from every run-signalling path.
  • The run-signalling paths now name their reason through the writer: recovery._stop_delivered_reviews and recovery._apply_budget_watchdog, dispatch's rollback, change_lane and terminate, and promotion._end_live_writer_for_settle and the release step. fleet_supervisor's session-start copy and standing_suite._kill_process_group now signal through signal_worker too; they signal processes that are not runs, so they name no run directory and write no record.
