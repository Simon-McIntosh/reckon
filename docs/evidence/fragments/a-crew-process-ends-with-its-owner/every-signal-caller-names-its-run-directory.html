every signalling caller names its run directory

The six run-bearing callers of _signal_process_group — dispatch.py dispatch-rollback, lane-change and run-stop, promotion.py promotion-settle and promotion-release, and recovery.py budget-watchdog — now pass run_dir and reason matching the attribution record they pre-write, so a guard refusal writes its refused outcome into the run's own senders.jsonl. The unwatch record, which lands in the shared watch directory rather than a run directory, now names the watcher's project. tests/test_every_signal_caller_names_its_run_directory.py drives one caller from each module against a live process whose recorded start time does not match and asserts the run's sender file ends with a refused outcome — 3 passed, EXIT=0. The declared mutation (drop run_dir from the promotion caller) fails the promotion case with no outcome line, EXIT=1. Base and head arms of tests/test_every_signal_leaves_a_sender_record.py, tests/test_unwatch_leaves_a_sender_record.py, tests/test_worker_signal_reach.py and tests/test_promotion_release.py each report 17 passed with zero added failures.
