gc applies past a registered worktree whose directory vanished

What changed

  • reckon.crew.routing.garbage_collect now inspects each registry candidate with _inspect_workspace(..., raise_on_unavailable=False). A registered worktree whose directory is gone is returned as its own unavailable classification carrying the state's detail, is never counted reclaimable, and is neither removed nor pruned; the pass continues and reclaims every reclaimable tree beside it.
  • _inspect_workspace keeps raising by default, so promotion's two callers are unchanged; only gc opts out.
  • The blanket git worktree prune after removal is gone: each git worktree remove already deregisters its own tree, while a prune would drop the registration of a tree whose directory vanished outside git — the record this pass reports and leaves in place.
