A promotion reads only the fleet fields it records

The promotion result stamps a bounded fleet reading on the row: live_runs, unreconciled_runs, actionable_runs, actionable_classifications and occupied_lanes. Only one of those came from the closure drain, and _fleet_state_reading ran the whole drain — including its plan inventory over every plan file — to read the single unreconciled_runs count. That control-plus-plan read was measured at 22 % of an 81.9 s promotion. The reading now derives its unreconciled count in _unreconciled_live_runs from the live pointers alone, by the same closure predicate (closure_disposition_valid) over the same pointers, taking liveness through the same host-gated local_liveness the drain uses so the answer cannot differ. The live-pointer projection still owns the actionable classification, unchanged.

A new test builds synthetic fleets in a temporary RECKON_HOME and asserts the bounded reading equals what runs.drain writes on the same pointers (unreconciled_runs and live_runs), including a fleet carrying a handed-off disposition so the count is not trivially the live count; a second test patches promotion.drain and asserts it is never invoked. Four cases pass, EXIT=0.

The declared mutation — unreconciled_runs calling the full drain again (int(drain(project)["unreconciled_runs"])) — fails the no-drain assertion: EXIT=1, test_the_bounded_reading_does_not_run_the_closure_drain failed, one id the head arm does not fail. This gate measures only this node's own change; verifying the merged result belongs to a separately dispatched test node.
