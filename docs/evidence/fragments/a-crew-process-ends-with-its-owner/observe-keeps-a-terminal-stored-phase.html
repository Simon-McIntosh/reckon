A late observe keeps a terminal stored phase

What changed

The supervisor is the single writer of a terminal stored phase: once the worker exits it writes the delivered manifest's phase onto the live phase. A later observe() folds the run's stream back into the pointer, and a stream that was rewritten, truncated, or read before its terminal event reports a live phase for a run that has already ended. Folding that over the stored terminal phase showed a finished run as still running.

  • reckon/crew/dispatch.py gains _terminal_phase_survives, consulted at every phase-write site in observe(): the cli stream fold, the in-harness manifest fold, and the orphaned branch that writes orphaned from the raw stream phase and process liveness. When the stored phase is terminal (complete, failed, stopped, interrupted) and the observation is not, the stored phase is kept. The deliberate resume override that reopens a live resumed attempt is untouched.
  • tests/test_terminal_stored_phase_has_one_writer.py writes the terminal phase through _publish_stored_phase(..., ended=True) as the supervisor does, then observes a live stream and asserts the phase is unchanged; a second case shows a non-terminal stored phase still advances; a third reproduces the orphaned branch's shape — a pointer at complete, a spent recorded pid and one live event — and asserts the finished phase stands.

Evidence

Reproduced at base c8087d0bc: a pointer whose stored phase is complete and whose stream carries one live event yields observed["phase"] == "working", overwriting the stored complete. A second shape — the same pointer with a spent recorded pid — yielded observed["phase"] == "orphaned", the defect the review found. After the guard every shape yields complete.
