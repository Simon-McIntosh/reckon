A discarded run is promoted once its commits reach main

A run whose live pointer is removed at discard can have its commit carried into main by a follow-on node's merge. Completion already reconciles such a run from its surviving run directory, but the rebuilt record carried no write scope, so citing the run's own commit was refused for changing paths outside an empty declaration. The rebuild now recovers the run's declared scope from the durable manifest's changed_paths, the one scope statement that survives the discard.

The gate builds a scratch repository, discards a run whose commit is then merged into main by a follow-on node, and shows crew complete on the pointerless run writing exactly one ledger row that cites the discarded run's own commit, while the follow-on's row is unchanged. The declared negative control refuses completion of a run that has no live pointer; the discarded-run case then fails (1 failed, EXIT=1).
