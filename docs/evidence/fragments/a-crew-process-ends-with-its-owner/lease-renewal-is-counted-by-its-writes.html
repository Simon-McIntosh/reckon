A lease renewal is counted by its writes

What changed

tests/test_producer_holds_a_lease.py — the renewal case counted a renewal whenever renew_producer_lease returned non-None. That call also returns the existing registration on a throttled pass, so a no-op counted as a renewal and the renewals >= 5 assertion could be satisfied without five writes landing. The case now reads lease_renewed_at back from the registration after each call and counts a renewal only when the instant advanced. The assertion now measures writes rather than return values. reckon/crew/runs.py is unchanged: the defect was in what the test read, not in the renewal itself.

The scratch arms ran the interpreter with -P, so the module under test is the scratch tree's reckon/crew/runs.py and not the worktree's; each arm's log header names the imported module path.

Negative control, declared and swept: count throttled returns as renewals; a run with throttled renewals satisfies the old assertion. A scratch copy of renew_producer_lease was made to write only on a scheduled subset of calls and return the existing record (a throttled no-op) on the rest. The ratios tried were period/keep 2/1, 3/1, 3/2, 4/3 and 5/4 — every partial throttle — plus 1/1 (no throttle) as the positive control. No ratio separates the two counts while keeping the producer alive. Because the producer exits once lease_renewed_at falls one lease interval (3.0 s) behind, and the test calls once per half interval (1.5 s), any skipped write leaves a 3.0 s gap: every partial throttle lapses the lease, and both the base and head arms fail at their thread.is_alive assertion — base at line 110, head at line 119 — before either count is reached. Under 1/1 both arms pass. So the tightened count cannot be isolated by throttling alone in this case: the lease's own liveness requirement already forces at least one write per half interval, which is the very floor renewals >= 5 asserts, and the head warning is that a failure to write is caught by the liveness assertion rather than by the count. The test is left unchanged; the ratios tried are recorded in negative-control.log.
