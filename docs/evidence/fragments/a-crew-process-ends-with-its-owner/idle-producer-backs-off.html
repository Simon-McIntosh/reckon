An idle producer backs its poll interval off to a cap

What changed

  • reckon.crew.recovery.watch_ticker, the producer loop, now carries a live poll_interval_current alongside the armed poll_interval. On each wake it records that value into the lease registration as poll_interval_seconds through the existing update_watch_registration (which merges the field rather than replacing the record, so the follower's lease_renewed_at survives).
  • A wake that sees a live run pointer sets the interval back to the armed base in the same pass. A wake that sees no live run pointer doubles it for the next wake, capped at IDLE_POLL_INTERVAL_CAP_SECONDS (30 s). The recording precedes the sleep, so the registered value is the interval in effect for that pass.
  • No sleep was widened: both wait sites still go through _wait, which bounds every sleep by the lease's remaining time, so a backed-off producer still ends within a second of its lease lapsing.

Evidence

tests/test_idle_producer_backs_off.py runs in a temporary RECKON_HOME with RECKON_PRODUCER_LEASE_SECONDS=3 and no live run pointer, and reads poll_interval_seconds from the registration.

  • Back-off and recovery. With a fake sleeper the producer's recorded interval follows 1, 2, 4, 8, 16, 30 from the armed base to the cap, and returns to 1.0 on the first wake that sees a fabricated live run pointer.
  • Lease bound. With base=0.2 s and a real sleeper the producer's recorded interval grows past its base and it still ends at the lease lapse (asserted within one second), showing the increased interval never outlasts the remaining lease.
