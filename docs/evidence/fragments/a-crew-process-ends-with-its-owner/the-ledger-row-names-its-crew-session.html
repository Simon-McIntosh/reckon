A promoted ledger row names its crew session

Promotion now copies the live pointer's session onto the committed ledger row as session, so a reader asking which coordinator session dispatched a run finds it at the top level instead of only under node_definition.coordinator.session_id. The row's session_id is left as the worker's own harness session. The key is present on every promoted row — null when the pointer named no session — because every key in RECORD_FIELDS is present on every row; an absent key made four tests that assert set(RECORD_FIELDS) <= set(row) report session missing. The key is declared in reckon/ledger.py's RECORD_FIELDS, so a promoted row carrying it no longer trips the schema-completeness check; the undeclared-key union reproduces ['session'] before the declaration and [] after.
