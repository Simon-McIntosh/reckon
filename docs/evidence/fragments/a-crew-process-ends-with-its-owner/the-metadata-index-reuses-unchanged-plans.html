The metadata index re-parses only the files whose bytes changed

The promotion profile attributed 35 % of an 81.9 s promotion to _plan_html.read_state reached through metadata_index._plan_record over every plan and doc HTML. The persisted index already reused a row when a file's stat identity was unchanged; it now keys reuse on a sha256 of the file's bytes, so a rewrite that restores the same bytes reuses the parsed row and only a byte change re-parses.

What changed

  • reckon/metadata_index.py: the reuse gate is the entry's stored digest compared against _content_digest(path), a sha256 of the file's bytes, replacing the stat-identity comparison. The persisted entry drops its stat field; the index schema version steps to 3 so an index of the previous shape is discarded once rather than reused without a digest.
  • A file that cannot be read still yields a row with its parse left unknown (digest stored None), so an unreadable plan keeps its inventory-unknown row as before.
  • The digest is cheaper than what it replaces: over this repository's docs tree, read+sha256 of 624 HTML files measured 0.55 s against 11.2 s for read+read_state.

The gate

tests/test_the_metadata_index_reuses_unchanged_plans.py builds the index twice over a synthetic docs tree of 12 plans and 4 evidence notes, changes one file, and asserts only the changed file is re-parsed and the warm rows equal a cold build. A second case moves a plan's mtime with its bytes unchanged and asserts the row is reused.

The measure this node owns

With the digest key, a rebuild over an unchanged tree re-parses zero rows, a rebuild after one plan changes re-parses exactly that plan, and a build whose only change is a moved mtime re-parses none. The warm rows equal a cold build over the same tree. The full wall-time profile at the merged head belongs to a separately dispatched node; this node measures only its own change.

Declared negative control

Declared mutation: drop the digest key so every file is re-parsed; the one-changed-file case re-reads unchanged files and fails.
