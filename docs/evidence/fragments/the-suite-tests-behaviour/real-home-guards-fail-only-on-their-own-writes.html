Real-home guards fail only on their own test's writes

A shared needle-filtered search, tests/real_home_traces.py, replaces the whole-snapshot comparisons six guards used to prove a test wrote nothing into the real config home. Each guard now searches for an identifier its own test mints — a session, node id, project or mounted path — so a peer session dispatching or arming a follower no longer fails it. The write-side assertion is unchanged.

  • Migrated onto the helper: test_watch_arming_isolation, test_member_registration_commits, test_impl_is_computed, test_rollup_isolates_a_project, test_append_decision_keeps_its_question, test_lanes_view_is_live, test_no_member_dispatch_runs_alone, test_follow_lifetime (its _own_traces) and the four dispatch modules carrying fixture_pointers. No module keeps a private copy of the trace search.
  • Gate: tests/test_real_home_traces.py — a foreign entry added between the readings is not reported, while an entry carrying a needle by name or by content is.
  • Two negative controls fail with the runner's FAILED line and a non-zero EXIT: the helper reverted to whole-root reporting fails the foreign-entry case; the no-member guard pointed at the test's own temporary home fails naming the pointer r-first.json the test wrote.
  • Census of every module resolving the real config home, with needles and reading lines: census.log under the run directory.
  • Every migrated module was re-run against the migration and passes: test_watch_arming_isolation 8, test_member_registration_commits 10, test_impl_is_computed 8, test_rollup_isolates_a_project 2, test_append_decision_keeps_its_question 9, test_lanes_view_is_live 15, test_no_member_dispatch_runs_alone 2, test_follow_lifetime 3, and the four dispatch modules 8, 5, 22 and 5. test_refused_dispatch_leaves_no_pointer carries one failure, test_a_refusal_over_an_existing_worktree_leaves_no_new_trace, which reproduces identically at the base revision and is therefore not added by the migration.
  • The two guards reading the real crew home search only its bounded subtrees — the live pointer directory and the watcher stream — because the run archive beside them carries per-run transcript trees that a recursive walk does not finish over. A leaked run directory does not outlive the live pointer that claims it, so the pointer subtree covers the trace that matters. Searching the archive whole made both guards hang rather than assert; a guard that never returns protects nothing.
