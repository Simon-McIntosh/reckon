The nine real-home snapshot guards now fail only on their own trace

The census re-check classified nine modules as snapshot-unfiltered: each proved a test wrote nothing into a shared tree by snapshotting it before and after the case. Six carried a copied _home_fingerprint that listed the real config home's top level by name and mtime; test_coordinator_obligations_hook stamped that home plus two settings files; and test_ledger and test_run_store compared the existence of the real crew/run_store.db. A peer session dispatching, arming a follower or promoting during a case moved those trees and failed the guard for a write the test never made.

  • The copied _home_fingerprint is gone from the six modules that carried it — test_a_foreign_pid_never_reads_dead, test_resume_offer_needs_a_dead_process, test_resume_sweep_needs_an_observed_death, test_stall_window_respects_a_child, test_stalled_row_names_liveness and test_unreadable_names_its_word. Each now defines one _real_home_traces(real_home) that calls traces_naming(real_home, ("crew/live", "crew/watch"), NEEDLE_RUN_IDS), where NEEDLE_RUN_IDS uses the module's own run ids.
  • All nine search through tests/real_home_traces.py with a needle the module mints. The hook module searches its minted fixture ids (hook-fixture, coordinator-hook-fixture, run-hook-fixture, and the per-case run and node ids) across .config/reckon/crew/live, .config/reckon/crew/watch and the two .claude settings files. test_ledger and test_run_store each search the single real crew/run_store.db file.
  • The two store checks assert on an identifier, not existence. _real_store_traces(*run_ids) returns a hit only when the real store's bytes carry one of the run ids the test wrote; the run id is what the test mints, so a peer promotion rewriting the real store names the peer and is no hit. The four was_present = real_store.exists() comparisons in test_run_store and the five in test_ledger are replaced. Every store guard was then checked against the ids its own case writes: test_store_is_created_on_first_use_with_separate_tables writes r-storefs-first-use and searches storefs; test_append_writes_one_durable_and_one_detail_row_and_leaves_others_alone writes r-storefs-four and searches storefs; test_import_brings_every_ledger_run_into_the_store_and_reports_imported writes r-storefs-import-a/b/c and searches storefs; test_a_rate_limit_refusal_stamp_outlives_its_run_directory stamps lane storefs-lane and searches storefs; and the five in test_ledger search r-store-echo, r-store-fail, r-store-ok, r-from-empty- and r-teardown-, each of which its case writes.
  • One guard was blind, and the audit found it rather than the guard. The import case seeded r-import-a/b/c while its guard searched for storefs — an id that case never wrote — so the guard could not have seen those rows leak and would have stayed green through one. Its ids now carry the needle its guard searches.
  • The search reads bytes, once per file. The helper decoded each file to str with errors="replace"; on the real 355 MB store the undecodable runs widen into replacement characters and the search costs several times the file's own size. Measured on that store: text 2.47 s and 3.06 GB peak against bytes 0.45 s and 353 MB — store_search_cost.log. Needles are encoded once and each file is read once per call, not once per needle.
  • Generic needles rejected. The real store already carries r-one, r-four and codex-spark, so those would have been vacuous. test_run_store now mints r-storefs-first-use, r-storefs-four, r-storefs-import-a/b/c and storefs-lane; test_ledger already minted r-store-* and r-teardown-* and r-from-empty-*, none of which the real store carries.
  • Bounded search. The shared crew home holds 1,202,726 files (find under ~/.config/reckon/crew, 179.7 s), so no guard walks it; the search is confined to live/ (33 entries) and watch/ (82), where a leaked pointer or registration lands, plus the single store file.
  • Negative control — negative_control.log.
