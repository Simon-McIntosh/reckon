A process table is read once per beat

The liveness read's environment walk (_processes_owning_run in reckon/crew/process_signal.py) opened /proc/<pid>/environ for every process on the node, and it runs once per beat for every run whose recorded pid has gone, so the same environments were re-read several times a second. A process's environment changes only when it execs, and an exec keeps the pid and the kernel start tick while replacing the program. So a reading is now kept in one index keyed by the pid, its start tick and its executable identity, and a walk reuses it until one of those three changes.

Two things follow. Every run answered in a beat reads each process's environment at most once — the first walk reads it, and the rest of the beat is answered from the index. And a walk in a later beat reuses every process that has not execd, so the cost falls to the processes the machine actually started or re-exec'd. A pid that has left the table is dropped, so no reading outlives the process it describes. The owner of the /proc entry is read before the environment, so another user's process — unreadable in any case, and 58% of the opens the capture saw — is skipped without an open at all.

The stop path's signal-time checks are unchanged. A candidate is still narrowed by the run's own crew home, still floored by the start tick the run's record carries so a recycled pid cannot be claimed, and _start_tick is read fresh at the moment of the query rather than from the index — a memoised reading never by itself selects a process to signal.

Paired suite, and the control the index rests on

Sixteen existing test files covering process_signal.py and recovery_liveness.py ran at the base and again at the head that lands: 155 passed and 1 skipped at the base, 163 passed and 1 skipped at the head, the eight-test difference being the new file and no test added to the failing set. The new file holds eight cases: a second beat opens no environment for a process that has not execd; several runs in one beat open one environment per process; a pid the kernel recycles is read afresh; another user's process is skipped without an open; a reparented worker is found by the liveness read and by the stop path.

The declared negative control removes the executable identity from the reused key, so a process whose environment was read between its fork and its exec is answered from that pre-exec reading after it execs carrying the run mark. The case that asserts such a process is found on the next beat fails against that mutation (EXIT=1), which is the coverage the identity key buys.

The work is committed locally and left unpromoted for the coordinator.
