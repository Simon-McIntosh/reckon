A moved checkout is proved importable once

A published reload image is now proved once, under an exclusive lock in the image's own directory. The first asker records the verdict beside the image, keyed by the interpreter, published by rename; every later asker reads that verdict instead of spending a probe of its own. A pass and an import failure are both recorded. A timeout is recorded by nothing, because it says nothing about the code, so the next asker under the lock proves the image alone. A source checkout has no immutable tree and keeps its per-process probe. The retry a timeout earns is now drawn back by a random fraction on each timeout, so the followers of one slow node do not re-probe in step; the shortening is downward only, so the gap and its cap stay a true ceiling on the wait.

Negative control

The declared scenario is a materialised tree carrying a module that fails to import, or any state where the shared verdict does not hold: sixteen concurrent askers must all refuse the reload from one probe and the failure verdict it records, and none may re-execute into the tree. The mutation applied was _published_image returning False for every image, which removes the shared verdict outright. Against it, three checks fail: the sixteen-asker single-probe check, the sixteen-asker shared-failure check, and the recorded-failure-not-reprobed check.

Tests

Seven checks cover the bullet list directly: concurrent askers on one image start one probe and all receive its verdict; concurrent askers all receive a recorded failure; a timed-out probe records nothing and the next asker probes; a recorded failure is returned without probing again; a new image id is probed afresh; a verdict proved under another interpreter is not reused; a source checkout keeps its per-process probe. Two more cover the retry jitter.
