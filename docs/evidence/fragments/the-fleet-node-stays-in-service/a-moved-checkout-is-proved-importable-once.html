A moved checkout is proved importable once

A published reload image is now proved once, under an exclusive lock in the image's own directory. The first asker records the verdict beside the image, keyed by the interpreter, published by rename; every later asker reads that verdict instead of spending a probe of its own. A pass and an import failure are both recorded. A timeout is recorded by nothing, because it says nothing about the code, so the next asker under the lock proves the image alone. The wait for that lock is bounded by the probe's own timeout: a waiter reaches the deadline, reads the verdict once more, and with none refuses with a timeout naming the wait, so a follower takes its jittered retry rather than proving the image on its delivery path and one timed-out proof is not paid by every waiter in turn. Whether a tree is a published image is one recogniser, shared by the import proof, the running-code identity, the materialised-tree pin and the follower's reload path. A source checkout has no immutable tree and keeps its per-process probe. The retry a timeout earns is now drawn back by a random fraction on each timeout, so the followers of one slow node do not re-probe in step; the shortening is downward only, so the gap and its cap stay a true ceiling on the wait.

Negative control

The declared scenario is a materialised tree carrying a module that fails to import: sixteen concurrent askers must all refuse the reload from one probe and the failure verdict it records, and none may re-execute into the tree. It was measured end to end in place on the fleet allocation: the image's own package carries a module that raises ModuleNotFoundError on import, and the sixteen askers return sixteen refusals from one probe, no re-execution, a single shared failure verdict, in 4.35 s. The unit-level control removes the mechanism rather than stressing it: published_reload_image returning False before its name test, so no verdict is ever shared. Against that mutation five of the twelve checks go red — the held-lock timeout, the recorded failure not re-probed, the verdict read while waiting, the concurrent shared failure, and the concurrent single probe.

Tests

Twelve checks cover the bullet list directly: concurrent askers on one image start one probe and all receive its verdict; concurrent askers all receive a recorded failure; a timed-out probe records nothing and the next asker probes; a recorded failure is returned without probing again; a new image id is probed afresh; a verdict proved under another interpreter is not reused; a source checkout keeps its per-process probe; a tree carrying no completion marker is not shared; a held lock makes the waiting asker time out within the bound without probing; a verdict recorded while the asker waits is read; and two cover the retry jitter. The existing reload and follower suite is unchanged in behaviour against its base revision: 87 passing at the base, 99 at the change, which is those 87 plus the twelve.
