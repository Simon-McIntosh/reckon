A stopped fleet worker cancels its Slurm step through the srun client

Finding. The supervisor's recorded worker PID is the srun client on the fleet node. Its argv starts with srun --overlap --jobid=… --ntasks=1 bwrap …; bwrap is the task inside the step. The supervisor sends SIGTERM to that PID after a terminal manifest or a run stop, and can send SIGKILL after the grace. In both drain cases, Slurm marked the step cancelled in the same second as the first delivered SIGTERM to the client; SIGKILL followed about 12 seconds later. Each step ended CANCELLED by 39486, 63 seconds after Slurm's cancellation timestamp, rather than COMPLETED.

Code path

  1. reckon/crew/dispatch_launch.py:1102–1119 prefixes the backend launch with the reservation's scheduler; reckon/crew/placement.py:233–240 supplies --overlap --jobid=…. The recorded argv in both drain runs has srun first and bwrap fifth.
  2. reckon/crew/dispatch_launch.py:2256–2285 starts that argv with Popen and retains its PID. Because argv begins with srun, this PID belongs to the local srun client. The worker records identify it as PID 1677365 for job 1281970's step and PID 2258183 for job 1277272's step.
  3. reckon/crew/dispatch_launch.py:2860–2884,2936–2963 calls signal_worker(pid, SIGTERM) and later signal_worker(pid, SIGKILL). reckon/crew/process_signal.py:293–324,341–393,450–463 expands reach_run to the run's processes and delivers to each PID; it records an outcome before treating a signal as delivered. The directly matched sender receipts target the two srun PIDs, not a bwrap PID. In each receipt the target PID differs from its process-group ID, so _signal_one uses os.kill(pid, sig) for the client, not os.killpg. reckon/crew/dispatch_sessions.py:1889–1927 also reaches the supervisor and its run descendants when crew stop is invoked.

Completed-step control

1281970.73 is COMPLETED with exit 0:0 in the saved table, 03:58:18–04:09:31 CEST. The unique attempt matching both its start and exit is attempt 2 of r-20261008T015730285964-plan-review-of-a-follower-row-is-worth-a-wake: worker.json gives 01:58:15 UTC and exit.json gives 02:09:34 UTC with exit code zero and no exit signal. Its senders.jsonl contains a delivered promotion-settle SIGTERM at 02:09:31.892 UTC to the supervisor, and no SIGKILL sender record. This control shows a step can complete as its task exits even when the surrounding run records a late SIGTERM.

Implication for the next change. The reaper must be the task inside the step, with the stop signal delivered to that task while the srun client remains alive. The run record should preserve the task's eventual exit instead of asking Slurm to cancel it. This is the mechanism inferred from the current code and the two observed cancellations; the later probe must verify the new behavior.
