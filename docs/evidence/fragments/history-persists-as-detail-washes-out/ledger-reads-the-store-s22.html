Every ledger reader answers from the run store once a project holds no run documents

What this is. The per-run directory docs/state/<project>/runs/*.json is the ledger's last file-shaped copy of history, and the locked decision committed-export-scope takes it out of git so the crew-home run store is the only store. A reader that still walked that directory would answer an empty ledger — reporting a project with no history rather than one whose history moved. This landing makes the store answer every reckon/ledger.py read path and the operational projection in reckon/crew/open_run_index.py, and the rule that decides which source answers is one function: run_directory_holds_records.

The precedence rule. The documents answer while the project holds any and the store is not read at all; the store answers once it holds none. Store rows are joined by run_id against what the aggregate and the documents already named, so a surviving document's row stays as the fuller record: a stored row carries the durable half only — _split_durable drops the promotion record — and is never allowed to shadow a file.

How the population is measured. One fixture — three promoted runs, each still owing its retained worktree — is written as run documents and into the store over an isolated config home (RECKON_HOME set, RECKON_STATE_ROOT and RECKON_MOUNTS_PATH cleared). The first answer is taken with the documents present. The directory is then removed, the test asserts the removal reached the absent-runs-directory case and that the chosen run's own run_path no longer exists, the operational cache is dropped, and the same reader must return the same answer. Each answer is checked against the whole population, so an empty read cannot agree with an empty directory and be counted as a pass.

The negative control, and what it proves. With the store disabled, the absent-runs-directory case fails for test_a_reader_answers_the_store_when_the_documents_are_gone[load], and so do [runs], [records], [run_ids], [open_rows], [open_row] and [open_has_row]; every reader of test_the_store_answers_with_no_aggregate; and test_a_store_deleted_and_rebuilt_returns_an_equal_answer_set. The two that pass are load_version and open_version, which is the control working as designed rather than a gap: a version is the aggregate's, the store moves none, and those readers answer a version rather than a run population. So the twelve failing names are exactly the readers this landing moves, and the failure is the absent-runs-directory case the measure names.

What this node did not decide. Two limits belong to the plan rather than here: load_aggregate keeps its writer semantics by design (see the table), and the merged result's suite is a separate verification node's measure — this gate measures this node's own change over its own write paths. detail-horizon and the store's location are untouched.
