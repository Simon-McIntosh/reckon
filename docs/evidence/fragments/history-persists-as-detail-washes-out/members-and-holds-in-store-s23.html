Roster members and holds persist in the run store

Roster registration, idle-member reaping and budget hold transitions now replace project-scoped rows in the run store without changing committed paths. Disposable-member retirement uses the same roster writer. A one-time import preserves the aggregate's members, holds and version; subsequent reads use the store, including when the roster is deliberately emptied or the aggregate is removed. Compare-and-replace transactions refuse stale versions and roll back both rows and version when a replacement fails.
