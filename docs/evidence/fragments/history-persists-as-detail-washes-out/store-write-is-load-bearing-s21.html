The store write is load-bearing

What changed. _index_append in reckon/ledger.py no longer returns a failure payload. It raises a LedgerError that names the run store's path and the repair verb, so a store that will not take a run refuses the promotion instead of reporting a landed run that no store holds. append_run now writes the store row before the rebuildable projections, and when that write raises it unlinks the per-run file it had already written, so neither store keeps a row. Docstrings that described the store as a rebuildable cache beside an authoritative committed file are corrected in the same commit.

The refusal, shown by injection. The new test injects a raising run_store.append and asserts four things: the raised message carries the store path, scripts/import_runs_into_store.py and --project proj; the per-run file is gone; the store answers no row for that node; and run_store.compare reports 0/0/0. The healthy arm appends for real, then asserts both stores hold the row and the same comparison is 0/0/0 — so 0/0/0 in the refused arm cannot pass by the comparison itself being broken.

It fails at base. Against a git archive of 9530fe3d48ea with the new test copied in, the injected-raise case fails with Failed: DID NOT RAISE LedgerError: at base the append returned {"status": "failed"} and kept the run file. The healthy case passes on both revisions, so the red arm is the inversion, not the harness.

The negative control. Restoring the swallowed form in _index_append — the exact mutation this node declared — turns the injected-raise case red again (FAILED tests/test_a_failed_store_write_leaves_no_row.py::test_a_refused_store_write_leaves_no_row_in_either_store, 1 failed, 1 passed), which is the check proving the assertion measures the raise and not the setup.

Arms. Baseline, resolved over the base tree 9530fe3d48ea (tests/test_crew_promotion.py included): PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_staged_write_inventory.py tests/test_every_shared_home_lock_holds_across_nodes.py tests/test_crew_promotion.py — 106 passed, 2 failed, exit 1; the two failures are the store-write pair named above. After, at the head that carries them (tests/test_a_failed_store_write_leaves_no_row.py added) — 110 passed, exit 0. Logs are in the run directory.

The promotion itself, at the same contract. tests/test_crew_promotion.py drives a full crew complete against an injected raising run_store.append. It now asserts what this section requires: the command exits 1, the refusal names the store path and scripts/import_runs_into_store.py --project proj, the per-run file is gone, and run_store.compare is 0/0/0. Its sibling, the healthy store-write case, keeps its assertions.

A scaffolding defect found on the way. Both store-write tests cited a gate log holding only probe check passed. The gate evidence check refuses a log with no terminal EXIT=<n> line, so neither test ever reached the store write it asserts about; both were red at 9530fe3d48ea, before this section's change. The logs now carry EXIT=0.
