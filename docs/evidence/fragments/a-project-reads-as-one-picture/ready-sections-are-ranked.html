Ready sections are ranked by the signal that places them

immediate_roadmap held plan rows and nothing else. Once the section edges reached the graph, the walk could cross a plan's sections, but the ready list a reader starts from still named plans: a reader could see that a plan was ready and not which of its sections to open, and the only ordering signal was the plan's own reach. The ranking key was a nested closure inside _build_roadmap, so no section-scoped term could be expressed in it without touching the payload function itself.

The key is extended rather than rewritten, and the extension is the same key for both populations: after_hold, critical-path membership, sprint position, ROI, reach, the stuck signal, remaining effort, identity. A term a row cannot carry is neutral for it, so the plan rows keep the order they had wherever the new terms are neutral — which is everywhere a plan carries no stuck section — and ROI and effort stay late tie-breakers. Reach for a section counts the sections that wait on it, which the section edges now supply; reach for a plan is unchanged.

The stuck signal is section_is_stuck(attempts, blocked_run_seconds): true when the section has been attempted twice, from section_attempts_by_plan, or when a run on it reports itself blocked for more than a day. It leads among rows otherwise equal, because a row a reader has already been through twice is the one to look at first. Where a section is both on the critical path and stuck, the row reports critical path: one field, one vocabulary, and the first signal in key order is the one named.

One row per ready section, ranked by the shared key beside the plan rows and interleaved with them by it, each carrying ref <plan>#<section> with its plan named beside it in plan, its own remaining effort, the sections it releases, and the placing signal in the existing reason field. No second field is added: a section row's reason and a plan row's reason are read by the same consumer, so they are the same vocabulary. A section held by a dependency is not in the list; a section-scoped wait holds its section, not its plan, so the plan row and its remaining ready sections both stay.

The ranking arithmetic moves whole into reckon/roadmap_ranking.py: the priority key and both wrappers, the path ranking including the critical-path selection, the section edge lifting and the section-effort read it needs. Nothing there reads a project — every function takes the values the caller resolved — and reckon/roadmap.py loses those bodies rather than keeping a copy. The module bound is what forced the move.

Gate: the eleven roadmap-surfaces files, 105 tests, green at EXIT=0 on the repair head; the same command run against the reviewed head's source with this node's test file in place fails four tests at EXIT=1, so the head adds no failure against its base. Ruff check and ruff format are clean on the changed paths, with the five findings the files carried before the change — RUF005, PERF401 twice, TRY301 twice — the only ones remaining and none added. The seven tests in this node's file fail at the pre-feature revision, where immediate_roadmap has no section rows at all.

The run-classification read lives in reckon/live_run_classification.py, moved whole: the recorded watcher event per run, and the resolution that prefers that event and falls back across recovery_classification, classification and to_state. The live-run partition in reckon/mcp_views.py and the roadmap's stuck rule both import it, so a run cannot read as blocked in one surface and as running in the other. The module reads no project state of its own, which is what lets the two import it without an import cycle between them, and a classifier that refuses a pointer yields an empty record — no reading, rather than a hold or a death.

A section row's reason names the term of the shared key on which it leads the section row below it, so ROI, sprint position, reach, the stuck signal and critical-path membership are all nameable and none is reported for a row that did not lead on it. The previous read reported reach whenever a row was neither on the path nor stuck, which claimed reach for a row placed by ROI or a scheduled sprint. The last section row of a read has nothing below it, and is measured instead against the least favourable section row its own key admits, so it can report only the terms a section carries outright — critical-path membership and the stuck signal — and says ready when neither applies.

Both halves of the stuck rule are now measured, not just the attempts half. A fixture dispatches two runs that both report themselves blocked, one thirty hours old and one an hour old: the older one lifts its section and the fresher one does not, so the rule is shown to read the age rather than the classification alone. The recorded-event seam is the one production uses, so the test exercises the shared resolution rather than a stub of it.

A plan's ready sections come from the row the roadmap already builds: implementable_sections less the sections blocked_sections names. The first version derived the hold set a second time and included a section-scoped gate hold nothing else in the roadmap implements, so the ranking and the row could disagree about what was ready. The row's two fields are the single source, and a hold the row does not report cannot hold a section here.

The stuck signal reads a run's classification through the same resolution as the live-run partition, from one module rather than one implementation each: the latest watcher event leads, the pointer classifier is the fallback, and the three keys are read in one order. A run the roadmap counts as live therefore cannot read as stuck for a different reason, and a stream that cannot be read falls back to the classifier rather than to silence.

A plan's ready sections for the ranking come from the row's own implementable_sections, less the sections its own blocked_sections names, and a plan's implementable sections are enumerated once per read rather than once per field. The row's separate ready_sections field is not that set and cannot be: it enumerates the sections a plan declares — including ones only a gate anchor names and ones no classification still admits — and it is reported only when a section-scoped hold exists, both of which its callers depend on. Reading it here would rank anchor-only sections as dispatchable work and would drop the ranked rows of every plan that holds no section by name.

Plan rows and section rows are ranked by the one shared key and interleaved by it, not appended as a second block: a section whose key beats a plan row's now precedes that plan. The fixture's loner is a plan row off the path with nothing behind it, and hub#s1 precedes it — which an appended block cannot do.

The reach fixture now puts the largest reach where the path is not. slow#s1 and slow-waiter#s1 cost 40 hours each and hold the critical path; hub#s1 releases two sections at one hour and hub#s2 none, in the same plan at the same hours. hub#s1 leads every off-path row, with reach as its reason, so membership cannot be what places it.

Negative control: with the section rows held out of the ranked list — computed and then dropped, so nothing else in the read changes — all seven tests in this node's file fail at EXIT=1. The rows are what the list carries.

The fixtures write each plan's ROI and effort explicitly, so no ranking test is decided by a term it is not about: four of them use ROI-high plans at effort M, and the ROI test sets a low-ROI plan on the path and a high-ROI plan off it, with equal hours, reach and attempts on both sides, so their plans' ROI is the only term that can separate their sections. The attempts test uses a fixture whose two sections are equal in reach, hours, ROI and sprint, so only attempts can move them, and the section with two attempts is the one that leads.
