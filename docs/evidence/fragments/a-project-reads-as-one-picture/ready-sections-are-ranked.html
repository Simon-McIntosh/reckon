Ready sections are ranked by the signal that places them

immediate_roadmap held plan rows and nothing else. Once the section edges reached the graph, the walk could cross a plan's sections, but the ready list a reader starts from still named plans: a reader could see that wide was ready and not which of its sections to open, and the only ordering signal was the plan's own reach. The ranking key was a nested closure inside _build_roadmap, so no section-scoped term could be expressed in it without touching the payload function itself.

The key is extended rather than rewritten, and the extension is the same key for both populations: after_hold, critical-path membership, sprint position, ROI, reach, the stuck signal, remaining effort, identity. A term a row cannot carry is neutral for it, so the plan rows keep the order they had wherever the new terms are neutral — which is everywhere a plan carries no stuck section — and ROI and effort stay late tie-breakers. Reach for a section counts the sections that wait on it, which the section edges now supply; reach for a plan is unchanged.

The stuck signal is section_is_stuck(attempts, blocked_run_seconds): true when the section has been attempted twice, from section_attempts_by_plan, or when a run on it has reported itself blocked for more than a day, from the live pointers that classify_pointer reads the same way the recovery surfaces do. It leads among rows otherwise equal, because a row a reader has already been through twice is the one to look at first. Where a section is both on the critical path and stuck, the row reports critical path: one field, one vocabulary, and the first signal in key order is the one named.

One row per ready section, appended after the plan rows and ranked by that key, each carrying ref <plan>#<section> with its plan named beside it in plan, its own remaining effort, the sections it releases, and the placing signal in the existing reason field. No second field is added: a section row's reason and a plan row's reason are read by the same consumer, so they are the same vocabulary. A section held by a dependency is not in the list; a section-scoped wait holds its section, not its plan, so the plan row and its remaining ready sections both stay.

The ranking arithmetic moves whole into reckon/roadmap_ranking.py: the priority key and both wrappers, the path ranking including the critical-path selection, the section edge lifting and the section-effort read it needs. Nothing there reads a project — every function takes the values the caller resolved — and reckon/roadmap.py loses those bodies rather than keeping a copy. The module bound is what forced the move.

Gate: 102 tests across the eleven roadmap-surfaces files, green at EXIT=0 on the committed tree; ruff check and ruff format clean on the three changed paths, with the two findings the file carried before the change — RUF005 and PERF401 — the only ones remaining and neither added. The four new tests fail on the base commit, where immediate_roadmap has no section rows.

Negative control: with the append into immediate_roadmap held out — the section rows computed and then dropped, so nothing else in the read changes — all four new tests fail, EXIT=1, on test_the_section_with_the_largest_reach_leads_the_ranked_rows, test_every_section_row_says_which_signal_placed_it, test_a_section_placed_by_reach_says_reach_and_outranks_a_side_section and test_two_attempts_outrank_an_equal_section_with_none. The rows are what the append adds.

The ranking fixture writes every plan ROI-high and effort-M, so ROI and effort decide nothing in it: what separates two rows is the signal the test is about. wide#s1 releases four sections at 30 hours, wide#s3 releases two, wide#s2 releases none, and all three are otherwise equal. The ranked section rows come out wide#s1, wide#s3, wide#s2: the largest reach first, then the side section with two waiters ahead of the one with none. The stuck test uses a second fixture whose two sections are equal in reach, hours, ROI and sprint, so only attempts can move them, and the section with two attempts is the one that leads.
