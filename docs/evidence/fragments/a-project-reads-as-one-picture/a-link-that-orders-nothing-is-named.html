Delivered with tests/test_a_link_that_orders_nothing_is_named.py, seven cases, at be1c86dd5.

Both findings are emitted through the existing _finding helper and nothing else in the report changes. _redundant_link_findings reads the graph the roadmap already builds — the edges that still order work, section nodes included — unioned with the declared plan-level edges, and searches a path with the candidate edge removed, so an edge only ever reaches its own target through other edges; a ref declared twice is a duplicate rather than a redundant path and is not reported as one. Only an edge whose target is still open is a redundancy candidate: a settled target is what settled-link reports. Each extra carries ref, field, target, set and remaining, so a review can apply the named op without re-deriving the list.
