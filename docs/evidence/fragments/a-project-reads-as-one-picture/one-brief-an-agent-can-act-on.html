One brief an agent can act on

The roadmap payload is correct and large. Reading it meant reading it all: a coordinator choosing work had to hold the ranked rows, the critical path, the wiring findings and the run classifications in mind at once, and the figures that decided the choice were scattered across fields with no line naming them. What was missing was not another analysis of the project but the composition of it — the few lines a coordinator needs before picking a node.

The composition is one public function, project_brief(project, since=None), in reckon/project_brief.py, reading the payload reckon/roadmap.py produces and adding nothing to it. It is exposed as --brief with an optional --since on the existing roadmap verb, which prints one project's brief or one per project in a portfolio report.

The brief is six lines plus an optional seventh. The overview names both completion percentages and the share of open plans carrying the leading return figure when that share reaches 0.8, and the counts of ready, blocked and deferred plans. The sprint line names the active sprint's goal and what is left of it. The critical-path line gives the path as sections with its elapsed and worker hours, and what holds its head: the runs sitting on the head section and the holds they carry. The ready line ranks the ten ready sections the payload placed, each with the signal that placed it, and adds the three releasing the most work. The blockers line groups true blockers by kind. The at-risk line names the oldest run blocked for more than a day, the sections with repeated attempts, and the interrupted runs. The wiring line counts the findings with the top three shown. With since, a seventh line reports what started afterwards.

What holds the head is read from the head's own section row rather than from a poll of the fleet, so the brief names the run that has stopped instead of the fact that a path exists. A run the payload places nowhere on a section still travels on its sprint's in-flight list, which is read as a fallback rather than as a section placement. The head is the first node of the path, which is the deepest prerequisite the chain forces.

The brief composes fields rather than recomputing them, so a brief and the roadmap cannot disagree — a parity test compares every figure it prints back against the payload field it came from, including the ranked section rows and the wiring findings. Two entries it cannot honestly fill are stated as such rather than invented: the payload reaches no end date for an active sprint, so the sprint line prints that none was declared, and a payload carrying no sprint row at all says so instead of printing an empty goal. Over the character budget the function raises rather than truncating, because a brief that dropped what the payload holds would report less than the project has.

The path is read as sections, not as plans, and the head follows from that. With the plan-level path read instead, a brief over the same payload names plan-a where the fixture wired plan-a#s2. The declared negative control makes exactly that substitution and is recorded below.

The fixture is a synthetic three-plan chain whose wiring is plan-section-depends-on alone — plan-a#s2 releasing plan-b#s3 releasing plan-c#s1 — plus an independent fourth plan, written into a tree under the test's own temporary directory with the live-pointer read patched, so no test reads a mounted project's state or the running fleet. The head, the top-ranked ready section, the oldest blocked run and the undeclared wait are fixed by the fixture rather than read back off the brief. One blocked run sits on the head section and names a section its dependencies do not declare, which is what makes it a wiring finding; a second arm puts two blocked runs in and requires the older to be the one named, so a brief that took the first in payload order would be caught.

The rewire arm writes a sibling tree that drops the middle plan: plan-c#s1 waits on plan-a#s2 directly. The payload's path becomes two nodes where the wired tree had three, and the brief's critical-path line moves with it — so the line is the chain the payload carries, not a restatement of the plans involved.

Two ways the command line could hide a mistake are closed. A change window passed without --brief was silently ignored — the option was read only inside the branch that prints the brief — and is now a usage error naming the option that reads it, raised before the report is read, so a mistyped invocation costs no scan. And the budget refusal, which is a raise inside the composition, reached the reader as an unhandled traceback; the command now prints the reason on the error channel instead. The ready sections named by reach also took the wiring-findings count as their bound, so two limits answering different questions moved together; the reach list has its own named bound.

The reach list is a ranking, not a truncation, and the fixture is built so the two differ. A fifth plan holds two sections with the second waiting on the first, which puts a third ready section in the ranked list; the sections releasing the most work are then not in section order, so an ordering by name alone is wrong and is caught. The list is compared against the fixture's own written-out expectation — the head releasing one section, the releasing plan's first releasing one, the independent plan releasing none — rather than against a repeat of the fixture's own sort, which would agree with any ordering.

The module carries the brief, its line builders and its reads of the payload's own fields, and holds no project identity: the project name reaches it as an argument and every path it reads comes from the payload. A module-size test bounds every source file in the package, and this one is inside that bound.
