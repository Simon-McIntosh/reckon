The critical path runs through the sections that wait

plan-section-depends-on edges were resolved and then dropped. _section_scoped_edges in reckon/roadmap.py already parsed each ref through parse_plan_ref, judged satisfaction through _section_satisfied against declared_section_identities, refused malformed entries and emitted dangling-hard-dependency, and its rows reached the dependency rows a reader sees. What no source did was give those resolved waits a place in the graph the roadmap closes over, so the longest-path walk stopped at the plan level and every plan's unlocks was empty however many section edges the plans declared between them.

One lift closes that, and tests/roadmap_fixtures.py's plan-row builder is untouched. A resolved, unsatisfied cross-plan wait becomes an edge between two section nodes named <plan>#<section> — the ref grammar the declaration already uses, and a spelling no plan slug can collide with — so the existing walk sees it without a second resolver being written. The path is priced by each section's own effort_hours rather than by the plan's: the work sits in the section. critical_path and each open_paths entry name the sections beside the plans. A plan whose work is sectioned no longer competes as one node beside its own sections, because pricing the plan and its sections together would count that work twice and hide the sections the path runs through.

A section-scoped wait is recorded at plan granularity in dependents alone. The plan keeps no graph edge of its own, so it stays in the ready set and out of the cycle walk: a plan-level veto is the very behaviour the section-scoped declaration exists to replace, and tests/test_section_edge_stays_off_plan_blocking.py pins it.

The surface changes by addition, not by replacement. critical_path and every open_paths entry always carry a sections list, empty when the path crosses no section, so a reader can rely on the key's presence instead of probing for it. The two assertions that pinned the old key set — the exact-dict assertion at tests/test_roadmap.py:138 and CRITICAL_PATH_KEYS at tests/test_roadmap_reports_section_edges.py:189 — gain sections in the same change; no case was removed from either.

Gate: tests/test_the_critical_path_runs_through_sections.py — five tests over a synthetic three-plan fixture whose only cross-plan wiring is the chain plan-b#s3 waits on plan-a#s2 and plan-c#s1 waits on plan-b#s3, with no whole-plan dependency anywhere. It reports the critical path as ["plan-a#s2", "plan-b#s3", "plan-c#s1"] in that order, the plans as ["plan-a", "plan-b", "plan-c"], both worker_hours and length_hours as 10.0 — the summed effort_hours of the three sections, 3.0 + 5.0 + 2.0 — plan-c among plan-b's unlocks and plan-b among plan-a's, and plan-c still structurally ready with s1 as its only blocked section.
