A declaration write on a finished plan reads closed, not a roadmap error

The readiness helper _plan_readiness_fields in reckon/mcp_deadlines.py looked the plan up in the roadmap report's pending_work, and reckon/roadmap.py skips that list for any plan whose status is terminal. So a declaration write on a shipped or done plan returned readiness: null with readiness_error reading that the roadmap carries no row for the plan — an error naming a roadmap defect where the roadmap is behaving correctly, read by exactly the coordinator who has just closed the plan.

The helper now reads the plan's persisted status before consulting the roadmap and, when that status is terminal, answers readiness: closed with an empty closure_blockers and no readiness_error; the roadmap lookup is reserved for live plans. The terminal set is not restated: the branch tests membership in TERMINAL_STATUSES from reckon/lifecycle.py, the module that already owns which statuses are terminal, so a status added there reaches this branch without a second list to keep in step. The status itself is read from the plan's own HTML, which is the sole store, through _resolve_html_file; a status that cannot be read leaves the branch unentered and the roadmap answers as before, so the change can only add the closed verdict for a plan whose status it actually holds.

reckon/mcp_edit_plan.py is untouched — it still attaches readiness only on a state-mode write that moves a section declaration, and both the helper and its test are the only files this section touches.
