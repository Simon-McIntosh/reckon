A gate over finished work stops holding the plan

split_unpassed_gates in reckon/roadmap.py now reads a gate against the plan's declarations: a gate holds a section only while the plan still declares that section implementable, so a gate whose named sections are all done, descoped or deferred holds nothing. The gate over a resolved section is no longer a wait, and the plan it was pinning reads unblocked — closable where the declared-remainder reader gives it that value, ready where other live work remains. Every reader of gate blocking reaches this one function, so the roadmap ladder, the discovery inventory serve.py derives in _derive_lifecycle, and the MCP plan view move together.

The three plan shapes the census measured are covered: an open gate over a done section, an open gate over a deferred section, and a concluded gate whose verdict is failed over a deferred section. A gate over an implementable section still holds the plan, and a gate naming no sections still holds it, so the split's existing contract is unchanged for live work.

One boundary is worth naming, because it is where the split keeps its previous reading. A plan that persisted no section classification tells this function nothing about which sections a gate still holds, so such a plan keeps the reading it had before declarations were consulted at all: every unpassed gate holds it. That is the same distinction is_closable makes, and it is what keeps an undeclared legacy plan — and the legacy execution gate covered by test_legacy_gate_still_blocks_execution — reading as it did.
