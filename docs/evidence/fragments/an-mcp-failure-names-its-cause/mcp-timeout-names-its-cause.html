A reckon MCP timeout names its cause

_run_under_deadline reads the worker thread's CPU time at the deadline, through /proc/self/task/<tid>/stat, subtracts the baseline it took before the body ran, and reports a cause of computing when that thread CPU time reaches half the wall time it held (with a small floor for clock granularity), otherwise waiting. The result carries both waited_seconds (wall) and cpu_seconds, and the error value stays storage-slow so no existing caller's branch changes. The message names the cause, and a computing body's hint gives the CLI command that answers without a deadline — reckon roadmap, reckon audit or reckon crew list by tool — instead of sending the reader to retry a storage read that was never the problem.
