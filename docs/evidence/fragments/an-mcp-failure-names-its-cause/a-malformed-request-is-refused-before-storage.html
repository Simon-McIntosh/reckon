§17 — A malformed request is refused before it touches storage

A request whose only defect is an argument — a crew view outside the served set, a crew field no row carries, a read_plan or roadmap view outside the declared shapes, an edit op verb outside the edit vocabulary — was answered only after storage had been consulted. Against a stub whose every open raises, the base revision reached the stub: _crew read the live pointers through reckon.crew.list_live and classified an empty pointer before it read the requested field names, and the store read the plan before it dispatched _apply_one_op.

Change. reckon/mcp.py gained _crew_argument_refusal, called at the head of _crew for a read request (no action). It refuses a view outside CREW_TOOL_VIEWS, a live field outside the vocabulary the live view itself declares — the field checks delegate to the views' own validators, query._refuse_unknown_live_fields and query._refuse_unknown_fields, so the accepted set and the wording of its refusal have one owner — and a runs scope or source outside RUN_SCOPES/RUN_SOURCES, each naming the accepted values. _read_plan_tool refuses a view outside mcp_views.VIEW_NAMES, and _roadmap_tool a view outside ROADMAP_TOOL_VIEWS; both judge the name as their own read does, stripped and lowercased, so a spelling the read serves is not refused ahead of it. reckon/mcp_edit_plan.py gained _refuse_unknown_op_verbs, called before the run-scoped checkout resolution, which refuses an op whose verb is outside the grammar reckon.mcp._OP_VOCAB publishes — the one declaration, minus create, which is a parameter rather than an op key — naming the op's position and the accepted verbs.
