A retried reckon read waits for the copy already running

A read body's future is kept in _INFLIGHT_READS, keyed by tool and arguments, for as long as it runs. The registered read adapter awaits that shared future under asyncio.shield, so a call whose deadline expires abandons the wait, not the body, and an identical retry awaits the same future instead of submitting a second copy — one body answers both calls. The registry is emptied by a done-callback when the body finishes, so the next identical read after that starts fresh; a read whose arguments differ keys its own body, and a write is never registered, so it always runs its own body under its own deadline.
