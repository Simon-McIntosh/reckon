The census names every connection failure's cause and counts storage-slow results

A new module reckon/mcp_census.py holds one public function, census, that takes an explicit window and returns, per server, the connections seen, the failures grouped by cause, and the storage-slow tool results per tool. It reuses the existing owners of every fact: _in_linked_worktree for whether a path is a linked worktree, _repository_named_by_worktree for the repository a reaped .reckon-worktrees path names, transcript_index and the store's STORAGE_SLOW sentinel. The transcript tool-block walk promotion_receipts held inline is extracted into transcript_tool_blocks, which both readers call. reckon doctor gains an "MCP connections" block that prints the census for the seven days ending now.

The one-cause-per-signature fixture lands every signature in its cause, reports an unmatched failure as unclassified with its first line, counts a clean connection as a success and a failure whose .reckon-worktrees directory was removed as a worker worktree of its repository, and reads two storage-slow results for read_plan and one for roadmap. The real-tree run is logged at the run directory as census-real-tree.log.
