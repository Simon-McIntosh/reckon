The fleet batch step's request loop read its request FIFO with a blocking readline() and swept for exited children only before each request. Requests arrive rarely and the loop's whole life is that read, so a child that exited while the FIFO sat idle stayed defunct until the next request happened to arrive — an exited supervisor could hold a process-table slot for days.

The loop now waits on the FIFO with a bounded select (REQUEST_WAIT_SECONDS = 0.5) instead of a blocking read, sweeping for exited children on each interval and reading whatever whole lines the wakeup delivered. The sweep still runs only between requests and never during the synchronous session-start wait _run_session_copy performs on its own child, so it cannot race that wait's collection — the existing session-start cases still pass. A new test, test_an_exited_child_is_collected_with_no_request_arriving, starts a short-lived child under the serving loop and, with no request sent afterwards, requires its pid to leave /proc within the bound (COLLECT_SECONDS = 5.0).
