A descope with its reason lands on a plan that carries no section records

What changed. A plan can declare its work as a plan-section-declarations map beside bare <h2> headings with no ids, so there is no typed section record for a descope reason to live on. _carry_descope_reason wrote the reason to a record and did nothing when there was none, and _require_descope_reasons then refused every reasoned descope — naming a dotted form that failed for the same reason. The reason for a section with no record is now stored in a plan-descope-reasons head meta map (reckon/_plan_html.py), and the whole-map form of section_declarations normalises each entry through _descoped_declaration_value so a reasoned value is accepted while the stored map stays a map of strings (reckon/_store.py). The guard and the read consult the record first and the map second. Because the write path schema-validates the state dict and drops keys the typed contract does not carry, the map is also queued as a document write effect and applied to the plan's head, the same way the section-scoped dependency meta is.

Measured

The new test is four cases on a temporary copy of a plan with no section records and bare headings: the dotted reasoned form stores the declaration descoped and the reason; the whole-map form with one reasoned value and plain strings beside it does the same; an unreasoned descope is refused and the refusal names the reasoned dotted form; and a plan that does carry records keeps the reason on the record, with no duplicate in the map.
