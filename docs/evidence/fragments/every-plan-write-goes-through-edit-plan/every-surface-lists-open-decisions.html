Every read surface lists the open decisions holding work

A plan waiting on the lead carries no followup, so its open decision is the only record that it waits and on whom. Both surfaces that a reader consults now list that record from one derivation. _decision_rows in reckon/roadmap.py gained a waiting_context option which carries the owning project, the plan's last-modified date and the recorded recommended/recommended_by onto each decision row. The option is opt-in, because a caller that consumes rows for readiness compares them whole: a row that gained a field would read as a different decision rather than the same one with more to say. build_roadmap therefore emits both lists — the readiness rows it always did, unchanged, and a new top-level waiting_decisions list carrying the context — from the one _decision_rows call, so no surface re-derives a wait.

waiting_decision_rows(report) is the single reader of that list. The roadmap's default summary view, mcp_views._roadmap_project_summary, attaches it as open_decisions with its open_decision_count, so the view a coordinator reads by default no longer drops the decisions the raw report already derived.

The served /crew route carries the same rows for every mounted project under open_decisions. It reaches them through unsettled_decisions(..., waiting_context=True) — the roadmap's own derivation — applied to the plan state the poll already parses and memoises (serve._crew_plan_state, one whole-document read per plan per file identity, shared with the crew row's own sprint/effort read under the existing crew-plan-details memo entry). Reading the whole document rather than its head is what makes the decisions visible; it costs no extra parse of a referenced plan, and the route's one-second budget over forty live pointers is unchanged because the added work is memoised per file identity.

tests/test_every_surface_lists_open_decisions.py builds one temporary mounted project, with every environment-resolved directory pointed at temporary paths, whose one plan carries an open decision scoped to a section, a gated decision held by a pending decision-lockable transition gate, and a locked decision. Four cases: the summary view lists exactly the open and gated decisions with their sections, recommendation, recommender and the plan's last-modified date, and excludes the locked one; the /crew payload lists the same rows; the two lists are equal; and locking the open decision removes it from both. The fixture's date is written into the plan rather than taken from today, so the case cannot pass on the day it is written and expire.

Both arms ran the same eighteen test files — the new one, every file importing reckon.mcp_views's roadmap views, and the crew-route, crew-page and roadmap files — each from its own tree, so the arm that names a revision is the arm that imported it. The base arm (9a9492e0a) reported 10 failed, 197 passed in 329.79s, EXIT=1: four failures are the new cases, which is the measurement this change is judged against. The head arm (496fdf6a7) reported 6 failed, 201 passed in 521.24s, EXIT=1, and its six failures are exactly the base arm's six browser-layout cases (test_spa_composition, test_spa_project_visibility ×4, test_spa_topbar_snapshot), which are pre-existing and untouched here. The delta is four fixed and none added. The negative control removed the list from the summary view and ran the parity case alone: it failed at the summary read with KeyError: 'open_decisions', 1 failed in 12.67s, EXIT=1. ruff check and ruff format --check report no finding on any staged path — the same counts as at base for the three modules they share. Logs live under the run directory as logs/base-gate.log, logs/head-gate.log and logs/negative-control.log.
