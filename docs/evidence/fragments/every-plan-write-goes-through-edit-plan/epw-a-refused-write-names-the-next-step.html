§7 — A refused or late edit_plan write names the caller's next step

Four refusals now answer with the step the caller needs, each verified through edit_plan on a temporary project in tests/test_a_refused_write_names_the_next_step.py (eight cases, all passing at the node head).

  • Version conflict. _attach_changed_targets in reckon/mcp_edit_plan.py adds a changed_targets list — each op the refused write addressed, with the value the document holds now — beside the current_version the conflict already carried (reckon/mcp_deadlines.py::_conflict_response, unchanged: the current-version half already held at the base, so it got no code). Case: test_conflict_carries_current_version_and_targets, which reads the expected version back off disk rather than asserting the value it passed itself.
  • Batch. reckon/_store.py::collect_refused_ops applies ops one at a time on a rolling copy, so a state-mode batch reports every op the store would refuse, each with its index and reason. Case: test_batch_reports_every_refused_op (three bad ops, three entries).
  • Late write. An optional request_id records a receipt (reckon/_store.py::record_write_receipt, keyed by an opaque scope key under the state root). A retry of the same id with the same request returns the landed version with ok and replayed: true; the same id with different ops is refused as reused_request_id. Cases: test_request_id_returns_the_landed_version_on_retry, test_reused_request_id_with_different_ops_is_refused.
  • Enumerated field. reckon/_store_section_ops.py::_enumerated_field_legal_values names the legal values of a section's effort_hours (a positive multiple of 0.25), capability (class and requirement level lists) and links, and a capability refusal carries a valid example. Cases: test_effort_refusal_names_the_quarter_hour, test_capability_refusal_names_legal_values_and_an_example. The effort case asserted only that the refusal contains 0.25, which the raw validation detail contains too, so it passed with the legal-values sentence removed; the enumerated-field control exposed that, and the case now asserts the sentence the change supplies.
  • Resource write. A write to a distributed project resource — a sprint, a milestone — answered through a separate branch that never attached the addressed targets and never recorded a request-id receipt, so a resource conflict named no changed_targets and a late-landed resource retry was not idempotent while the plan path did both. That branch now returns through _attach_changed_targets on ProjectStateConflict and records its receipt on success. Cases: test_sprint_conflict_names_its_changed_targets (the target's current value is the one the store holds, not one the test supplied), test_sprint_request_id_returns_the_landed_version_on_retry.

_value_at_path resolves a list element by id through the store's own reckon/_store.py::_find_by_id rather than its own lookup, so one owner answers that address form.

Measure. Head gate: 93 passed, 1 failed — the single failure is test_every_module_fits_a_worker_window, which also fails at the base arm (reckon/crew/review.py, reckon/ledger.py exceed the bound), so zero failures are added. The one out-of-scope failure is recorded under follow_ons.

Negative controls. Four, one log each, every mutation applied to a copy of the node revision, never committed, and reverted before the next: the reused request id (the digest comparison short-circuited, so a reused id is answered with the earlier version), the batch (collect_refused_ops returns only its first refusal), the enumerated field (an enumerated-field refusal carries the raw validation detail without its legal-values sentence), and the conflict payload (_attach_changed_targets attaches no targets and the refusal drops its current version). Each names the case it must turn red; each did.
