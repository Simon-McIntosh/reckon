§7 — A refused or late edit_plan write names the caller's next step

Four refusals now answer with the step the caller needs, each verified through edit_plan on a temporary project in tests/test_a_refused_write_names_the_next_step.py (six cases, all passing at the node head).

  • Version conflict. _attach_changed_targets in reckon/mcp_edit_plan.py adds a changed_targets list — each op the refused write addressed, with the value the document holds now — beside the current_version the conflict already carried (reckon/mcp_deadlines.py::_conflict_response, unchanged: the current-version half already held at the base, so it got no code). Case: test_conflict_carries_current_version_and_targets.
  • Batch. reckon/_store.py::collect_refused_ops applies ops one at a time on a rolling copy, so a state-mode batch reports every op the store would refuse, each with its index and reason. Case: test_batch_reports_every_refused_op (three bad ops, three entries).
  • Late write. An optional request_id records a receipt (reckon/_store.py::record_write_receipt, keyed by an opaque scope key under the state root). A retry of the same id with the same request returns the landed version with ok and replayed: true; the same id with different ops is refused as reused_request_id. Cases: test_request_id_returns_the_landed_version_on_retry, test_reused_request_id_with_different_ops_is_refused.
  • Enumerated field. reckon/_store_section_ops.py::_enumerated_field_legal_values names the legal values of a section's effort_hours (a positive multiple of 0.25), capability (class and requirement level lists) and links, and a capability refusal carries a valid example. Cases: test_effort_refusal_names_the_quarter_hour, test_capability_refusal_names_legal_values_and_an_example.
