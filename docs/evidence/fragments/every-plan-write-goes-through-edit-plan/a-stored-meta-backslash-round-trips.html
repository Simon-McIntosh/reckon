A stored meta value carrying a backslash is written back verbatim

_set_meta passed the new meta tag to re.sub as a replacement string, which re reads as a template. A stored value carrying a backslash is therefore parsed as a replacement escape: \u00a7 (how the JSON store spells a section sign) raises re.PatternError: bad escape \u, and \\ silently collapses to one backslash. The first write on a plan inserts the tag and succeeds; the second write replaces it and raises, so the plan could not be written, promoted against or closed until its meta was hand-edited. Reproduction before the repair: _set_meta(head, "plan-descope-reasons", '{"s1":"r\u00a7"}') against a document already carrying that tag returned PatternError: bad escape \u at position 66.

The replacement is now a callable (lambda _match: tag), so the tag is inserted as one verbatim string and no byte of it is reinterpreted. It is the only re.sub in reckon/_plan_html.py whose replacement carried stored or authored text: the others pass a literal lambda replacement, an empty string, or a constant.

tests/test_plan_html_meta_roundtrip.py holds two tests. One writes a plan whose plan-descope-reasons holds the section sign § is not ASCII twice in succession and asserts the second write succeeds, that the stored file carries the escaped \u00a7, that the reason reads back unchanged and that the second write is byte-identical to the first. The other writes C:\Users\u00a7\d, \u00a7 and \d{2}\s over an existing tag and reads each back byte for byte. Negative control: with _set_meta reverted to the template replacement, both tests fail with re.PatternError. Ruff adds no finding on either staged path.
