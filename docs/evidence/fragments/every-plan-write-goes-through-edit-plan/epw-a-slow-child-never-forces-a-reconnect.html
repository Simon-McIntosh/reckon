§11 — A slow current-code child never forces a reconnect

The guard kept two defects that a loaded node turned into reconnects. An unanswered child made _answer_on_current_code return no answer at all, and the caller then got stale_server_code — a version_conflict or a storage-slow deadline, whose remedy is to re-read and retry, came back as "reconnect", with a detail saying the current code had failed too though it had never run. And every call opened a fresh interpreter that paid the whole import against a _CURRENT_CODE_TIMEOUT_S bound of 120 s, so on a loaded node a session waited and often failed on each call. Both are gone.

One persistent child per code stamp. reckon/served_code.py gains CurrentCodeServer and ServedChild: the tree's current code runs behind the stdio front in one child, started when the guard first sees a stamp it does not hold, and stopped and replaced when the stamp moves again. The child imports the tree, answers a readiness probe with every tool's parameter names and runs no tool, and then takes one request-tagged JSON line per call. A reader thread is the only reader of its stdout, so a caller bounds its own wait while the pipe stays drained; a reply that arrives after its caller gave up is discarded by id rather than misread. Closing the server's end of the pipe ends the child, which is what its for line in sys.stdin loop does at EOF.

Cold never waits; warm runs once. Warming is by the probe and not by a caller's call. While the probe has not answered the child is cold, no call is routed to it, and the running image serves every call — so a cold call never blocks on the child and no tool call is spent warming it. Once warm, a call of a tool that has fallen back runs in the child instead of the image, so it runs once. A routed read the child does not answer falls back to the image. A routed write is never re-run on the image: it returns write_may_have_landed, whose detail names the read to make before retrying. A failed call the current code did not answer keeps its own error code and detail, marked with code_stamp_at_start, code_stamp_now and a current_code_note.

The one refusal left. stale_server_code is returned only for a tool whose probed parameter names disagree with the registered ones, and it names that tool with its reconnect remedy: there the client holds the schema it connected with, so a reconnect is the real remedy.

The seven cases in tests/test_a_slow_child_never_forces_a_reconnect.py drive the guard against a temporary tree with a spawn hook that launches a fake child the test can slow, silence or stop: an unanswered child leaves a version_conflict a version_conflict with both stamps and no reconnect field; twenty calls start one child and a further stamp move stops it and starts exactly one more; a cold call is served by the image without waiting and the child's call log is empty; a routed call runs once, in the child, with the image's call count unchanged; a routed write the child does not answer returns the may-have-landed timeout with the image's write count unchanged; a changed signature still refuses; closing the pipe ends the child.

Each case has a negative control, kept one log per control under the run's logs/: restoring the refusal on an unanswered child fails the first case, starting a child per call fails the second, making a cold call wait fails the third, running a routed call on the image as well fails the fourth, re-running a timed-out write on the image fails the fifth, ignoring the probe's parameter names fails the sixth, and leaving the child running after the pipe closes fails the seventh. Every control's log ends in a non-zero EXIT= line.

The gate. At the node head the four targets run 1 failed, 51 passed and at the base revision the three that exist there run 1 failed, 44 passed, both exiting 1. The one failure is the same test in both arms, test_every_module_fits_a_worker_window, and it names reckon/crew/review.py and reckon/ledger.py — two modules this node neither touches nor changes. It is present at the base revision before any of this work, so the node's own delta is zero added failures.

tests/test_mcp_server_serves_current_code.py is updated to the new contract where the section changes it: the two cases whose child reaches no tool and whose child answers nothing at all now assert that the call keeps its own error code, with both stamps and no reconnect, where they previously asserted the refusal. Its driver waits for the persistent child to answer its probe before the answered child can take over a call.
