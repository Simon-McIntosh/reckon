A plan closes in one write, without a placeholder followup

edit_plan gains one op, {op:'close', status, outcome, by[, superseded_by]}. It sets the plan's status to any value in TERMINAL_STATUSES and resolves every open followup with the close's outcome, so the close itself supplies the chain-closing continuation and no placeholder followup is appended. A set of a plan's status to a terminal value is refused, naming close; the terminal path has one spelling. Sprint, milestone, blocker and inventory statuses are untouched, because close closes a plan and nothing else.

The close runs every guard the terminal transition fires and reports them together rather than one at a time: the section-ticked guard (shipped/done only), the terminal-evidence record, the pending transition gate, the appended hiding followup and the continuation. The list is not the close's own — it is validate_landing_patch, which the merge-patch writer calls too, given a mode that collects every failing guard instead of raising at the first, so one transition is judged by one list and a guard added there reaches both writers. A plan that is refused names every outstanding condition in one answer. The section-ticked guard is skipped for a superseded or archived close, which is not a landing.

Census of the op-path terminal-status writes at the base. Every plan status written through the op path (a set of status at a terminal value, applied through edit_plan or the store's apply_ops) moved to close, or was replaced by a benign edit where its subject was unrelated to the landing. Direct status literals written into fixtures, and sprint and inventory statuses, are not hits. Files touched: tests/test_terminal_status_needs_every_section_ticked.py (LAND, now a close op), tests/test_closure_gates.py (three calls), tests/test_continuation.py (three calls; one rewritten because the op-path continuation guard is now reached only through close), tests/test_edit_plan.py (the schema-boundary and version-conflict cases), and tests/test_every_section_has_a_declaration.py (one call). No source op-path hit existed in reckon/.

Gate. tests/test_a_plan_closes_in_one_op.py drives three cases: a finished plan closes in one version step with every followup resolved and no placeholder appended; a plan with an implementable section, no evidence record and a pending transition gate is refused naming all three; a set of status to each value of TERMINAL_STATUSES (imported from reckon/lifecycle.py) is refused naming close. The declared negative control — report only the first failing guard — makes the three-guard case fail for the two guards it omits.

Scope. The guard list lives in validate_landing_patch, which both writers call, and close is the only op that sets a plan's terminal status. The HTTP merge-patch writer behind POST /plan is not on that op path and still sets a terminal plan status directly, judged by the same guard list but without the close's outcome resolution — closing it is outside this section's scope.
