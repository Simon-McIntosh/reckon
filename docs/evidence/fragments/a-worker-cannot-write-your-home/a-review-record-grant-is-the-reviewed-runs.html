A review's record grant is the reviewed run's

A review node's declared record path is now admitted by _review_record_directory_grant in reckon/crew/dispatch_admission.py only when it lands in the review-records/ directory of the run the node id names; the parts-count shape rule is gone and containment is read through review.run_review_record_location against that run's own directory. The reviewed run is resolved from the node id as recovery_review_delivery._resolved_reviewed_run_id resolves it. 5 cases in tests/test_a_run_review_with_run_directory_records_dispatches.py pass, 12 with the sibling record suite; the declared mutation restores the pre-change "any run" grant and the run-B case goes red at EXIT=1.

Two cases are added. A review node naming run A that declares a record path under run B's existing review-records/ directory is refused as scoped, and the refusal names the node id (test_review_cannot_declare_another_runs_record_directory). The same node declaring run A's own record path is admitted and the composed fence grants run A's record directory and no directory holding another run's record (test_review_admits_its_own_runs_record_directory_and_fence_grants_it_alone). The existing composed-review and reflex-launch cases still pass, and the composed review reads its node id from the production composer, so a re-review composed through the production path is admitted.

Confirmed before the change: a re-review's minted id resolves. Against a live pointer whose node id is semantic rather than a run id, _reviewed_run_id_for_node("review-of-the-semantic-node-aaaaaaaaaaaa") returns the reviewed run's run id through the fleet lookup, and the grant then returns that run's review-records/ directory; an id that names no run grants nothing (None). A production re-review is therefore admitted, not refused, so no widening was needed.
