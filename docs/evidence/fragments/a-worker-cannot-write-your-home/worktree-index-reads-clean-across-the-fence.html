A worktree index written inside the fence reads clean outside it

A worktree routing._create_worktree creates now carries core.checkStat=minimal in its own worktree configuration, reached through extensions.worktreeConfig=true written once to the shared .git/config. The main checkout keeps the default comparison. Minimal drops uid, gid, inode and device and keeps whole-second mtime, ctime and size.

The defect reproduced at the base revision: git config --get extensions.worktreeConfig and git config --get core.checkStat both returned nothing on a freshly created worktree, so every entry's fence-era gid 65534 was compared against the files' group 89486 on the next unfenced call.
