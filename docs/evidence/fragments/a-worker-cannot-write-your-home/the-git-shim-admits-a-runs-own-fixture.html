The git shim admits a run's own scratch repository

The shim refused the throwaway repositories test fixtures create under the run's scratch directory, so every test-running worker set env -u RECKON_RUN_ID and the bypass landed in recorded gate commands. reckon/worker_git_shim.py now admits a mutating verb whose repository lies entirely inside worker_scratch_dir(run_id) — the directory promotion and discard remove with the run. The admission rests on git's own report: the absolute git dir and the common dir must both resolve inside, and a work-tree top level, when there is one, must be inside too. A verb that creates a repository (init, clone) resolves to none yet and is admitted on the invocation directory and any path it names. tests/test_git_shim_checks_the_resolved_repo.py gains a scratch fixture and three cases, each in its own process group under a 60 s bound with two shim directories on PATH: an init-and-commit under the scratch directory succeeds; a commit into a foreign checkout is refused with its head unmoved; a linked worktree under scratch whose common dir lies in a foreign checkout is refused with that checkout's refs and dirty file unchanged.
