A shim ignores the job's Python path

The four shims — reckon/worker_shims/git and reckon/host_shims/salloc, sbatch, srun — start reckon's interpreter with only reckon's import root on its path: they set PYTHONPATH="$repo_root", add -s to drop the user site, and unset PYTHONPATH, PYTHONHOME and PYTHONSTARTUP so a job that ran module load cannot shadow reckon's dependencies. The caller's interpreter-path variables are parked under RECKON_SHIM_CALLER_* and restored by caller_environment, a single definition that lives with the shim lookup helper in reckon/shim_lookup.py and is imported from there by reckon/worker_git_shim.py and reckon/nested_launch.py, so the git or scheduler command a shim runs still receives the caller's environment unchanged, PYTHONPATH included. The bootstrap puts nothing of the caller's on the shim interpreter's path, so a sitecustomize the job's PYTHONPATH carries is never imported: a startup hook that raises on import cannot stop a shim before git or the scheduler is reached.

Measured by tests/test_a_shim_ignores_the_job_python_path.py: with PYTHONPATH and PYTHONHOME naming a temporary directory whose typing_extensions.py raises on import, a git command through the worker shim succeeds, each host shim reaches its main, and the program each shim runs sees the caller's PYTHONPATH and PYTHONHOME unchanged. A further case names a directory whose sitecustomize.py raises: git still succeeds and each host shim still reaches its main. 5 passed. The declared negative control — restoring the appended caller PYTHONPATH and the bootstrap's sitecustomize import in the shims — makes the same test fail with the import error on 4 of its 5 cases, the sitecustomize case among them.
