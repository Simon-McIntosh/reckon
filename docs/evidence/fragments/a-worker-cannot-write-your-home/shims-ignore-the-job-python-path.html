A shim ignores the job's Python path

The four shims — reckon/worker_shims/git and reckon/host_shims/salloc, sbatch, srun — start reckon's interpreter with only reckon's import root on its path: they set PYTHONPATH="$repo_root", add -s to drop the user site, and unset PYTHONPATH, PYTHONHOME and PYTHONSTARTUP so a job that ran module load cannot shadow reckon's dependencies. The caller's interpreter-path variables are parked under RECKON_SHIM_CALLER_* and restored by caller_environment in reckon/worker_git_shim.py and reckon/nested_launch.py, so the git or scheduler command a shim runs still receives the caller's environment unchanged, PYTHONPATH included.

Measured by tests/test_a_shim_ignores_the_job_python_path.py: with PYTHONPATH and PYTHONHOME naming a temporary directory whose typing_extensions.py raises on import, a git command through the worker shim succeeds, each host shim reaches its main, and the program each shim runs sees the caller's PYTHONPATH and PYTHONHOME unchanged. 4 passed. The declared negative control — restoring the appended caller PYTHONPATH in the shims — makes the same test fail with the import error on 3 of its 4 cases.
