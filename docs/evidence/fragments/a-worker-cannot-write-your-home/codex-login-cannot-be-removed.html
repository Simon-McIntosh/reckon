A fenced codex run cannot remove or blank the operator's login

The writable single-file bind of ~/.codex/auth.json that lets a fenced refresh land is also what could blank the operator's only login, so the file's guarantees are now asserted rather than assumed. A fenced run cannot remove the login at either path — an unlink at the run home's mount point is refused Errno 16 and at the operator's own ~/.codex Errno 30 — and cannot replace it, by rename over it or by unlink and recreate (both Errno 16). Both refusal cases pass at the base revision unchanged: they are documented as holding already, not as newly repaired. A truncation to zero bytes is possible through the bind, and is detected after the run by comparing the size recorded before launch with the size read back — two stat calls that never open, read, copy or print the credential — and reported as a truncated record on the run directory's codex-login.json and a line on the run's stderr.log, carried into the run's stream observation; a rewrite after a mid-refresh zero heals the record rather than pinning a loss that did not happen.

Gate: 25 modules that reach the change, pytest -n 8 --timeout=300, each arm its own basetemp under the run's scratch root and its own log under the run directory. Head (27d347f91f5788c60d3cab7705df2615addb6c74, git archive extraction): 210 passed, EXIT=0. Base (9e5081bb32085947e24a8b17921c94c7935e32df): 3 failed, 207 passed, EXIT=1 — the three failures are exactly the new truncation cases (no observe_codex_login at base), so the truncation half reproduces red at base and the head arm adds no failure id. Negative control (declared string, first line of logs/negative-control.log): with the post-run size check removed the zero-byte truncation case fails, EXIT=1. A cwd-dependent picker hold in test_the_protected_set_is_declared.py appears only when the gate runs from inside a git worktree and reproduces with the base code under the same cwd, so it is attributed to the environment, not to this change; from the extraction-based arm it does not appear. No other run's records are read or written by the change or by this gate.
