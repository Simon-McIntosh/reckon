A slow launch's vanished-bind refusal is retried

The retry that recovers a launch refused over a read-only bind source a rename left missing for an instant keyed on the child exiting inside a half-second startup window. On a placed launch the child is the local scheduler client, which outlives the step's own start, so the sandbox's refusal reaches the launch's own stderr seconds after the launch and the client is still running when it does. A refusal that landed four seconds in was therefore recorded as a launch failure although the same launch a moment later would have begun normally.

The startup watch now reads the refusal from the launch's own stderr inside a window sized for a placed step, and ends early on the first of two facts: the launch's stream beginning, or the child exiting — whose stderr decides the answer. A try counts as dead only once its child has exited, because the retry collects a dead try by waiting on it: reading the refusal on its own would declare a worker that is still running a failed launch and then block in it.

The window is thirty seconds, and it is a floor rather than a margin: what it has to cover is the step start before the child's own refusal, and a step start on a loaded host is exactly the interval a window narrowed to the four seconds one recorded launch took would return before. The window is counted from before each try's own spawn, so it bounds the try rather than the child. That is what lets the floor stand: an earlier attempt at this node had cut it to fifteen seconds to keep a healthy child whose own life is thirty seconds from being collected at the window's last poll and written into the launch's failure record — the upper bound was real, and it is answered by where the window starts rather than by lowering it. The stream path is threaded through both spawn sites.
