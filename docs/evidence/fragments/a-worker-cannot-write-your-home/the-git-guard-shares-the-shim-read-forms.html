The Bash-tool git guard reads its read forms from the shim

reckon/hooks/worker_git_guard.py classified git verbs with a private READ_ONLY_VERBS set whose membership omitted worktree, so a worker that typed git worktree list --porcelain against another checkout was refused at the PreToolUse layer even though the execution-time git shim forwards it. The two classifiers had drifted on this verb once before.

The guard no longer keeps a read-verb list. It imports mutating_verb from reckon.worker_git_shim — the single table both layers read — and classifies each parsed invocation through it, passing the tokens after the verb so an explicit read form of a multi-purpose verb (worktree list, branch --list) is read-only here exactly as the shim reads it. The guard keeps only a mutating-name deny-list, used to scan a command the shell parser cannot split.

tests/test_worker_git_guard.py gains a case per verb in the shim's own read tables that asserts the guard allows the shim-classified read form at another checkout with RECKON_RUN_ID set, a per-modifier case for worktree list --porcelain, -z, -v and --expired, and a denial case for the mutating forms of a readable verb.
