The protected set is declared — evidence

The set a worker's fence seals read-only was a compiled list in reckon/_backends.py. It is now a flight key, protected_paths, declared in reckon/schema/flight.yaml beside unprotected_paths and regenerated into reckon/_flight_schema.py and docs/_shared/flight.schema.json. _default_protected_paths is the shipped default — today's built-in list, the worktree root ~/Code/.reckon-worktrees included — and protected_paths composes that default with the extra paths a host or project layer names, minus the defaults a layer names under unprotected_paths. The default is never replaced, so a layer that drops one from protected_paths leaves it protected; the only way to remove a default is to name it under unprotected_paths. dispatch threads the resolved config into fence composition and writes fence_unprotected_paths on the run's pointer, only when the fence composed and a default was actually removed.
