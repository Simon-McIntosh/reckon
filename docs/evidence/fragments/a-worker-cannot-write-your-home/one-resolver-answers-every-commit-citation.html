One resolver answers every commit citation

The commit-citation predicate now has one definition, in reckon/crew/promotion_evidence.py; the copy in reckon/crew/reports.py is deleted. Nothing behaviourally changed, because the deleted copy already answered through recovery._resolve_commit and the remaining one answers through _commit_canonical_id, which is _resolve_commit(root, revision) or None. Measured: git grep -n 'def _commit_resolves_in' reckon/ prints exactly one line, reckon/crew/promotion_evidence.py:383.

reports reaches that definition without closing an import cycle. promotion_evidence imports reports at module scope, so reports imports the resolver inside _commit_citation_findings, the function that calls it — the same deferred form the neighbouring recovery readers in that file already use. A module-level __getattr__ serves the same function object to a reader that names reports._commit_resolves_in as an attribute, which an existing test does; the assertion is object identity, not equality of behaviour, so a wrapper would not satisfy it.

The new test drives the audit's citation check on one fixture repository holding a single commit. The commit's own id is accepted (no finding). An all-zero 40-hex hash is refused (_commit_resolves_in returns False, and the check returns one finding naming that token). A 40-hex hash derived from the real id by changing its 31st character is refused the same way. The same four tests assert that reports._commit_resolves_in is promotion_evidence._commit_resolves_in, so a reintroduced second definition fails here rather than drifting quietly.

Gate: tests/test_one_resolver_answers_every_commit_citation.py passes 4 of 4; together with tests/test_one_function_resolves_a_citation.py the pair reports 6 passed at EXIT=0. The 108 test files importing reckon/crew/reports.py, reckon/crew/promotion_evidence.py or reckon/crew/promotion.py report 1094 passed at EXIT=0, so the added-failure count against base is zero by construction: a fully green head arm has nothing to add to any baseline. ruff check and ruff format --check report zero findings and zero formatting changes on the two changed Python files.
