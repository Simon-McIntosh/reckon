The git shim reads worktree list as a read form

worktree is a multi-purpose verb, and the shim admitted only the bare list action: any output modifier on the listing made the invocation mutating, so git worktree list --porcelain — a read that changes no ref and writes no file — was refused against a repository that is not the run's own. reckon/worker_git_shim.py now admits --porcelain, -z, -v/--verbose and --expired as read modifiers on worktree list, alone or together. Each is a flag that consumes no value and names no file, so none can be pointed at a write target; the verb's mutating actions (add, remove, prune, lock, unlock, repair) are unchanged and stay refused.

tests/test_git_shim_checks_the_resolved_repo.py gains four cases, each in its own process group under a 60 s bound with two shim directories on PATH: worktree list --porcelain with -C at a foreign checkout succeeds and its output equals the real git's porcelain listing of that checkout; the listed modifier alone and together is admitted (the shim never returns its refusal status — git 2.39.3 itself rejects -z alone and does not know --expired); worktree prune at the same checkout is refused and the metadata directory it would have removed is still present; and reckon.crew.routing._registered_worktrees, which runs the listing through PATH, returns the checkout's worktrees rather than raising.
