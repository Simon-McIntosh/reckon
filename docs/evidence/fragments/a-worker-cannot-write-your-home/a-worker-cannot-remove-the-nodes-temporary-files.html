A worker cannot remove the node's temporary files — evidence

The fence dev-binds / writable and overlays the declared protected paths read-only. It sealed the crew scratch root (§9) and the reports and review stores (§10), but nothing sealed the rest of the node's /tmp, so every fenced worker held the whole of it writable under one uid. reckon/_worker_fence.py now resolves the node's /tmp through node_tmp_seal_root() and emits its overlay after the protected binds and before the writable grants, so the grants land after it and are the last word on their own paths.

The seal does not suppress a protected path's own bind. Folding the node tmp into the protected set would have let protected_read_only_binds dedupe away every protected path beneath it, because a resolved target already inside another protected path is judged a redundant overlay. It is kept out of that set and emitted as its own overlay instead: a protected path under /tmp keeps its explicit --ro-bind even though the seal already covers it, and the redundant read-only sub-path bind costs bwrap nothing. That bind is not decoration: the vanished-bind retry reads _read_only_bind_sources from the composed argv to decide whether a refusal names a path this launch actually mounts, so a suppressed bind makes a real retry look unkeyed. The two spellings were told apart by three assertions in tests/test_spawn_retries_a_vanished_bind.py, which go red when the bind is deduped and pass when it is kept.

The paths a launch must still write there are enumerated once, in node_tmp_runtime_paths(), placed beside worker_scratch_seal_root. Each entry carries the reason it is there: the fleet's runtime directory (runtime_directory() in reckon/crew/fleet_supervisor.py, /tmp/<uid>-fleet), which holds srun's fleet sockets, and /tmp/.codex, codex's sandbox synthetic-mount registry. The run's own scratch directory is re-bound writable by the ordinary grant loop, so it is not in the list — a state the test asserts as an ordering property rather than trusting the enumeration.

Proved by executing the composed argv. tests/test_a_worker_cannot_remove_the_nodes_temporary_files.py builds a synthetic node /tmp holding the owner scratch, the runtime paths, and an outside file, composes the fence through fence_argv, and runs it around a shell that creates and removes a file in its own scratch, does the same in each enumerated runtime path, and then removes the outside file. The results file records the scratch and runtime writes as done, the outside rm exits non-zero with Read-only file system naming the outside path, and the outside file survives. The argv shape is asserted separately, because a shape assertion cannot tell a fence that holds from one spelled correctly and doing nothing, and an executed refusal cannot tell which overlay produced it.

Negative control. node_tmp_seal_root is the seam that decides the seal; the fixture patches it to return None, so no read-only overlay of the node tmp is composed. The executed case then goes red — EXIT=1, one failed — and the outside file is removed. The first patch of the control was made in the wrong place (the test body re-set the root through monkeypatch, undoing it), which left the executed case green under the mutation; the seam exists because of that, and the control was confirmed red only against it.

Gate state at delivery. The importer population — every test file importing reckon/_worker_fence.py or reckon/crew/dispatch_launch.py, 25 files and 422 tests — ran in two arms, four workers each, at the declared base ff9b7f230 and at head 11c746141. Each arm reports 1 failed, 421 passed, and the single failure is the same test in both: tests/test_dispatch_returns_without_worker.py::test_a_discarded_run_is_not_recreated. The delta against base is zero. Both arms are logged under the run directory with the revision, the tree, the host and the literal command on the first line, ending in a bare EXIT= line.

Each declared lane's worker reaches its first turn inside the fence. The launch is composed through the production path (launch_plan with fence=True) and the real CLI is run with a one-turn prompt. All three exit zero and reach a turn: claude in 15.2s, codex in 6.4s, and the local lane clive in 30.2s. The composed argv shows the --ro-bind /tmp seal followed by the scratch, /tmp/<uid>-fleet and /tmp/.codex grants, so the seal does not cost a launch the paths it writes. A lane's first turn is read from the harness's own record of it — the final message when the dialect writes one, otherwise the end-of-turn result record on stdout — and a lane that wrote neither is reported as having reached none rather than assumed to have.
