A worker cannot remove the node's temporary files — evidence

The fence dev-binds / writable and overlays the declared protected paths read-only. It sealed the crew scratch root (§9) and the reports and review stores (§10), but nothing sealed the rest of the node's /tmp, so every fenced worker held the whole of it writable under one uid. reckon/_worker_fence.py now resolves the node's /tmp through node_tmp_seal_root() and adds it to the protected set before the writable grants are emitted, so the grants land after the overlay and are the last word on their own paths.

The paths a launch must still write there are enumerated once, in node_tmp_runtime_paths(), placed beside worker_scratch_seal_root. Each entry carries the reason it is there: the fleet's runtime directory (runtime_directory() in reckon/crew/fleet_supervisor.py, /tmp/<uid>-fleet), which holds srun's fleet sockets, and /tmp/.codex, codex's sandbox synthetic-mount registry. The run's own scratch directory is re-bound writable by the ordinary grant loop, so it is not in the list — a state the test asserts as an ordering property rather than trusting the enumeration.

Proved by executing the composed argv. tests/test_a_worker_cannot_remove_the_nodes_temporary_files.py builds a synthetic node /tmp holding the owner scratch, the runtime paths, and an outside file, composes the fence through fence_argv, and runs it around a shell that creates and removes a file in its own scratch, does the same in each enumerated runtime path, and then removes the outside file. The results file records the scratch and runtime writes as done, the outside rm exits non-zero with Read-only file system naming the outside path, and the outside file survives. The argv shape is asserted separately, because a shape assertion cannot tell a fence that holds from one spelled correctly and doing nothing, and an executed refusal cannot tell which overlay produced it.

Negative control. node_tmp_seal_root is the seam that decides the seal; the fixture patches it to return None, so no read-only overlay of the node tmp is composed. The executed case then goes red — EXIT=1, one failed — and the outside file is removed. The first patch of the control was made in the wrong place (the test body re-set the root through monkeypatch, undoing it), which left the executed case green under the mutation; the seam exists because of that, and the control was confirmed red only against it.
