A message reaches a live worker at its next tool call

Delivery no longer depends on the model remembering to look. A PostToolUse hook, reckon/hooks/worker_inbox.py, reads <run dir>/inbox/*.md, claims each message by moving it into inbox/claimed/, emits the bodies as hookSpecificOutput.additionalContext and appends a line per delivery to inbox/receipts.jsonl naming the message, the delivery time and the tool call it followed. The transport stays the run directory, as §6 requires: the change is that the harness reads it, not the model.

The claim is the rename, and that is what makes it exactly-once

Three parallel tool calls run three hook processes, and each lists the inbox before any of them has claimed anything. A hook that merely read a message would deliver it three times. The rename into claimed/ is the claim: the kernel serialises it, the process that moves the file delivers, and the others find the source gone and skip it.

Declared negative control — the claiming rename replaced by a plain read — makes the concurrency case deliver three times: 1 failed, EXIT=1, naming test_three_concurrent_hook_invocations_deliver_one_message_exactly_once with assert 3 == 1 (three hook processes each emitted the same only message 0). Log: negative-control.log in this run's directory.

Registration lives in the fence's seeding, not the operator's settings

seed_harness_home merges the entry into the run home's settings.json for Claude-dialect runs, after the declared-file loop, whether or not the home already carried a settings file. It is merged rather than skipped — the one place the seeder rewrites a run's own settings — because the hook is what gives the run a channel, and a home seeded before the hook existed would otherwise read as reachable while holding no hook. Every other key and hook group is kept and an entry already present is not duplicated.

The writer refuses what it cannot deliver to

reckon crew tell --run <id> "<message>" writes one message atomically to <run dir>/inbox/ and reports queued_for_next_tool_call, never a delivery: the receipt is the only proof. It refuses, in this order, an ended run (naming crew resume --advice), a record naming no manifest path, a record whose fenced flag is not true — explicitly false, or absent — any non-Claude dialect, and a Claude run home whose settings.json carries no PostToolUse entry. The first refusals are record reads: a run that was never fenced has no delivery channel however its home looks. The settings file, read through install.settings_carry_worker_inbox, is the last test and the one that catches a fenced run whose home was seeded before the hook existed — a live run's home is never re-seeded.

The peer-send guard now names crew tell while the addressed worker is live and crew resume once it has stopped; crew check --manifest reports a run whose receipts record a delivery its manifest does not quote, and one that received nothing without saying messages_received: none.

A coordinator can see a message it has queued

The runs view answers a named run with its inbox, split into what is still waiting and what already carries a receipt, both read from the run's own directory — the store the hook claims from, so the view cannot report a message as queued after a tool call has taken it. A case drives the real sequence: queue with crew tell, see the message listed unclaimed, run the hook once, and see the listing empty with the message named in the receipts.

Reconciling the seeding contract

Every seeded Claude home now carries one more PostToolUse entry, so the three test files that asserted the seeded hooks equal the operator's own were updated — without loosening what each one checks. Each keeps the comparison over the operator's groups exact and names the one addition beside it, because a looser comparison would stop seeing a change in any other group, which is the property those cases exist to protect. The byte-for-byte equality with the operator's file is replaced by that group equality plus the operator's file still being compared unchanged, since the seed now writes a document that is not identical to it. Every one of those edits is a consequence of this section's requirement rather than a defect in it, and none belongs to a concurrent node.

Two integration points remain outside it, and both are named so a reader does not mistake "the check exists" for "the check is enforced": promotion-time enforcement of the manifest's messages field would live in reckon/crew/reports.py — the check implemented here runs in crew check --manifest, where the writer can still fix it — and the worker prompt's manifest contract (reckon/crew/prompts.py) does not yet name the messages_received field.

The help census gains the writer's row. The inbox writer composes a message through the shared staged writer rather than keeping a private temporary beside it — the hook itself only reads and claims, so the shared writer's import is paid once per message by the coordinator's command, never on the per-tool-call path — and the staged-write census therefore needs no entry for it.
