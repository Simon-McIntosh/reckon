A codex run's reachability is decided by the argv its launch recorded, not by the live pointer

crew tell decided a codex run's reachability from the live pointer's argv field. No real run has one: the pointer is rewritten on every state change and carries no argv at all, so the predicate answered neither the inbox hook override nor its trust override for every codex run, and a coordinator could not reach a codex worker through the verb even when the launch had composed both overrides.

The refusal, reproduced on the run it blocked

Codex live check r-20261111T132025827799-codex-inbox-live-check. The pointer holds no argv key; the run directory's worker.json holds a 283-word argv whose indices 264 and 266 are hooks.PostToolUse and hooks.state. Reading the pointer's argv answers 'neither the inbox hook override nor its trust override', so the verb refused. Reading the run directory's argv answers None, the acceptance the verb needed. The message the coordinator had to write by hand was inbox/claimed/20261111T132804524207Z-manual.md, a name the verb's own message_name() never produces; the hook claimed it at 13:28:06Z and its codeword OSPREY-LANTERN-3 was quoted in that run's report. Delivery worked, and only the verb's argv source was wrong.

Where the launch records its argv

_run_recorded_argv takes the attempt the pointer names from the records the run directory holds, discovered by _attempt_worker_records, the helper the resume path already reads: the canonical worker.json is the attempt running now and its argv answers, while an attempt-<n>-worker.json receipt describes an attempt since retired. While a resume has retired the canonical record and not yet written the replacement, the pointer's attempt is the newest receipt that exists. A run directory holding no readable record answers None, so such a run is refused rather than reported queued.

The hook override is recognised across checkouts

The override names an interpreter and a script path from the checkout that composed it. An equality test against this checkout's own composition refused every run launched anywhere else, including the run that produced the measurement above, so the hook is now identified by worker_inbox.py, the part that reads the inbox.
