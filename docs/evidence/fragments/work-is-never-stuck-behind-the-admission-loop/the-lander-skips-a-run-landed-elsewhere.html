The lander skips a run completed elsewhere

The landing pass reads the selected run’s current pointer and durable ledger row before checkout, measurement, and promotion. If the pointer has gone or the ledger already holds the run, its landing result records landed-elsewhere and the pass moves to the next candidate. The check leaves the pointer untouched. The crew’s own post-promotion measurement is exempt because its promotion has already written the ledger row; an ordinary successful completion still reports landed.

Two temporary-home cases exercise the guard. Removing the pointer after selection produces a landing-stage skip without an error; adding a ledger row while retaining the pointer produces a skip with zero calls to landing_measure.measure_run. With both current-state checks disabled, the first case records CrewError: no live run in the landing error and the second starts measurement: both fail (EXIT=1). With the checks enabled, the exact head gate reports 2 passed (EXIT=0).
