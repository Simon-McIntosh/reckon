A launch re-reads the run it starts

What changed. A pass ranks the queued pointers it read at its start and then works through them, so a request can move while the pass is busy with the others. _launch_reread_refusal (reckon/crew/queue_admission.py) re-reads the request's live pointer and the run's attempt-*-exit.json records under runs._pointer_lock immediately before the launch, and refuses a request whose pointer is gone or whose attempt already exited with a recorded result, writing a refused-before-launch verdict that names the reason. A launch-failure attempt reached no model, so the queue's own retry still follows it.

What this node changed. The guard itself landed at 4a8f690d9d. Its two refusal cases did not measure the window they name. The attempt-resulted case wrote the exit record and the delivered manifest before the pass began and handed its after-read hook a no-op, so a guard that read attempts once at pass start passed the case. Both refusal cases fired their change from inside the pass's opening read of the live set, which a pass-start read would still have seen. Each case now writes its change when the pass reaches its launch decision for the request — the last point at which the request can still have moved — and the attempt case asserts the delivered manifest is byte-identical afterwards.
