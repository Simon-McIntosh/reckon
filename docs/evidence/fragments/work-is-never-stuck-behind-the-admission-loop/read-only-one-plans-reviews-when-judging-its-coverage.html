A plan's review coverage reads only that plan's reviews

What changed. list_plan_reviews (reckon/crew/plan_review.py) takes an optional plan slug. With one, it reads only the committed plan/<slug>/*.json directory and the staging plan-<slug>.v*.json glob, whose .v immediately follows the slug so a plan whose slug prefixes another's reads only its own. The pass cache key carries the slug, so a pass that asks about two plans does not answer the second from the first's listing.

Every caller in the module that filtered one plan out of a project-wide listing now passes the slug: review_coverage, newest_design_review, review_scope, compose_burst_refusal and review_day_summary. The callers that genuinely read across plans (declined_recurrence, the review reflex's whole-project pass, _stored_review_run_ids) are unchanged.
