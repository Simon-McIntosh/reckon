A repair round's scope reaches the run's claim

A repair round composes its write scope from a review's blocking findings, and a finding may name a path the reviewed run was never dispatched to write. The round's advice told the worker to edit that path, but nothing recorded it on the run's claim, so promotion refused the landing as changed paths outside its declared write scope and a coordinator had to pass the exception by hand. While the round edited the path, peers saw no claim on it at all.

claims.widen_claim now takes a grant_source, so a caller other than the run's own worker records what it granted and why; a grant is written for the added paths whenever a source is named, stamped with that source instead of the fixed worker. The repair round grants each finding path outside the run's declaration through that same check, with source repair-round and the finding's id as the reason, immediately before it resumes the worker. dispatch_claims.declared_write_grants reads the grant back by path, so the widened path is in the scope promotion measures with no --accept-path. A path a peer's binding claim already holds is refused by the existing conflict check: it is not granted, it is left out of the advice's scope line, and the advice names the peer that holds it. Only a scope conflict names a peer, so only that is reported as one: any other refusal — the claim amendment refusing because the run's own worker is still running, or a pointer recording no claim to widen — carries its own error text into the advice and names no peer, since it is about this run rather than about contention for the path.

Measured through resumption.sweep with the resume entry point and the dispatch stubbed, against a reviewed run declaring reckon/crew/declared.py and a blocking finding in reckon/crew/ticker.py. After the sweep the run's write_paths are [declared.py, ticker.py] and declared_write_grants reports ticker.py with source repair-round and the finding's own id as its reason. Promotion's own scope product now measures a commit changing the granted path with no acceptances recorded; before the grant the same measurement refuses it. With a peer pointer holding ticker.py as a binding claim, the path is absent from both the declaration and the grant list, and the peer's run id appears in the advice while the path is absent from its scope line. A claim amendment refused for the run's own live worker is reproduced against the pre-fix revision, where the advice read reckon/crew/ticker.py is held by peer run r-unpromoted — the reviewed run named as its own peer, the real reason discarded; at the fix the same probe renders Scope grant refused: reckon/crew/ticker.py: cannot amend the write claim of run 'r-unpromoted': its worker is still running… and names no peer.
