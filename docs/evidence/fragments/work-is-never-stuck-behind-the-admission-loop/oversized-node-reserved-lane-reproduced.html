Why an oversized node did not reach the reserved lane, reproduced

The two recorded refusals reproduce, and the replay that reproduces them exits EXIT=0. The claim was not true of the script as committed: run on this node it exited 1, because the 02:34:43Z attempt's pick was cut off by the dispatcher's stage bound before it answered. The pick never disagreed with the record — it did not finish. The fix is a replay-side stage budget, and the evidence below separates what the refusal rests on from what it does not.

A dispatcher bounds its pick with PICKER_DISPATCH_TIMEOUT_SECONDS = 5.0 (reckon/crew/dispatch_picker.py:46, waited on at dispatch_picker.py:590), and a bound that fires replaces the picker's own answer with the dispatcher's timeout fallback (dispatch_picker.py:655–661). The bound is a limit on how long the dispatcher waits, not an input the picker weighs. Measured here, the 02:29:07Z attempt's path takes 6431 ms and the 02:34:43Z attempt's 7764 ms on a cold process — both past 5.0 s, so the earlier claim that both reproduced could only have held on a process whose read caches were already warm. The replay now lifts the bound to REPLAY_STAGE_BUDGET_SECONDS (120 s), records both figures in its log, and prints each attempt's elapsed time beside its answer, so the lift is visible rather than hidden. No routing or competence verdict is stubbed on either path: the candidate scan runs reckon.crew.picker.snapshot.candidates unchanged.

The path that withheld codex, and the absent local lane

The withholding term is the lane-window term of the reserved-lane policy, reckon/crew/picker/snapshot.py:1259, reached from the candidate loop at snapshot.py:1748. The node declares reasoning: deep and the codex policy's floor is reasoning: [deep], so the tier term (snapshot.py:1300) withheld nothing; the reason on the row is the window term, which withholds when the lane's window percentage is absent or at or past the 60% ceiling (snapshot.py:1315, snapshot.py:1320). claude was withheld on the same term. That the refusal carries it establishes no lift governed either group at either moment (a lift releases the term at snapshot.py:1310).

The local lane was absent from the later attempt because that dispatch named a lane. The fourth attempt's command carried --backend codex, which reaches lane_model_selection (reckon/crew/dispatch_picker.py:1061, called from reckon/crew_dispatch_commands.py:1604) and asks the picker with the configuration narrowed by _config_within_lane(config, "codex") (dispatch_picker.py:979). Only that lane's backends remain candidates, so clive, claude and native could not appear as rows whatever the window reading was: the local lane was never offered.

What would have to change for the node to reach codex

The oversize waiver (snapshot.py:1896–1899) is the one place that may override the reserved-lane policy, and on this configuration it can never fire. It requires every unreserved candidate to be excluded on context fit alone; the unreserved population includes the native backend, whose reason is in-harness-backend (snapshot.py:1668) and never a context fit, so the all(...) cannot hold. The attempt's own set carries an independent second blocker: clive's third reason is competence, not context-fit, which fails the same test on its own. Either fact is sufficient.

The dispatch reroute could not have moved it either. _reroute_oversized_request (reckon/crew/dispatch.py:633) chooses through widest_fitting_candidate (snapshot.py:612), which admits only candidates carrying no reasons (snapshot.py:639–644); codex carries reserved-lane, so it is never selectable there. The candidate scan itself needs no widening: _reserved_lane_exclusion withholds on a policy rule rather than a measurement, and the waiver is already the one place allowed to override it. So the change is in the waiver: judge the unreserved population as the lanes a dispatch could actually launch the node on — an in-harness backend cannot be launched, so it is not evidence that an ordinary lane could run the work — and read a competence refusal for the same window shortfall as a context exclusion, since one shortfall is reported as two codes depending on which verdict measured it.
