A service runs the code main carries

What changed

reckon/crew/fleet_supervisor.py: a service's pid record now carries a third field, the code identity of the checkout that started the copy. It is written by run_declared_service — the wrapper that becomes the service — so the record describes the process rather than what a supervisor believed at spawn time; the spawn path writes it too, for the window before the wrapper runs. recorded_service_stamp reads it, and a two-field record written before this change reads as unrecorded.

DeclaredServices.reload no longer adopts every running copy. It compares the copy's stamp with the checkout's own identity, and where they differ it asks the same trust probe the followers and the MCP take. A trusted checkout with a differing stamp stops the copy and starts it again, logging both stamps. An untrusted checkout leaves the copy running and logs the refusal with its reason, once per pair of stamps. A copy with no readable stamp is restarted once, so its code is known from then on. An identity read that does not answer is never read as a move.

The stop confirms the old copy has gone before the replacement starts: SIGTERM, then SIGKILL once the grace has run out, then a bounded wait for the pid and its lock to clear. That ordering is what lets a lease-holding service such as the station take its lease again instead of being refused as still held, and a replacement that fails to start is scheduled for retry rather than dropped from the supervisor's view.

The supervisor's own move check now records the refusal when the checkout has moved and cannot be trusted, naming the probe's reason; previously that case was silent.
