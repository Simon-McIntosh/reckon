A refused launch records one verdict

A pass that refused a request before launch wrote two rows in one pass record, refused-before-launch and then stalled, because the pass's held set knew only the hold verdicts. The next pass read the refusal as a request still waiting — _last_verdict_of returns the first matching row — and appended another stall, so a request nothing was wrong with accumulated one stall verdict per pass for as long as it sat. Both defects reproduce at the base revision: one pass records ['refused-before-launch', 'stalled'], and the stall rows in the verdict log grow 1 then 2 across two passes.

A refusal settles the request for the sessions that follow

refused-before-launch joins a TERMINAL_VERDICTS set in admission/shared.py. The pass's own held set unions that set, so a request it refused gets no stall row beside the refusal in the same pass, and admission/verdicts.py's _record_stalls skips a request whose last verdict is terminal, so a later pass reads the refusal as answered rather than as a wait it repeats. The behaviour lives in the admission package because the facade split left reckon/crew/queue_admission.py holding re-exports only.

Evidence

One case joins tests/test_a_launch_rereads_the_run_it_starts.py: a refused request's pass record holds exactly one row, and two passes record no stall row at all for it. It asserts that its own change landed in the window, so it cannot pass by never applying it. The guard that tells a pass reading attempts at its launch decision from one that read them at pass start is the case the file already owns — test_a_request_whose_attempt_already_resulted_is_not_launched, which writes attempt-1-exit.json inside the same after-read hook — so this change verifies that guard at the base revision rather than adding a second case asserting the same behaviour. Gate at head: 55 passed, EXIT=0; at base: 54 passed, EXIT=0. ruff check and ruff format --check report nothing on the staged paths.

Every test file naming queue_admission — 104 files — was run at both arms on the all_debug partition, one arm at a time, -n 4, each to a log ending in its own EXIT=. head 191e27d87b: 133 failed, 596 passed, EXIT=1; base 433d71f076: 135 failed, 594 passed, EXIT=1. Comparing failure ids, head adds none. The two the base arm carries that head does not are the new refusal case, which this change repairs, and test_a_queued_launch_never_classifies_the_fleet.py::test_the_launch_inputs_equal_the_base_except_for_backlog. The 133 that remain are pre-existing at both arms. Every arm log opens with its own # revision line, then the tree, the working directory, the module under test and the command, so a reader can resolve the run from the first line rather than from the summary.

Negative controls, each applied to the committed change and logged. Moving the attempt read to pass start makes the launch-decision case launch and fail: 1 failed, EXIT=1. Leaving the stall handling unchanged so a refusal does not settle the request makes the refusal case report stall rows recorded 1 then 2: 1 failed, EXIT=1, which is also the failure the base arm carries for that case.
