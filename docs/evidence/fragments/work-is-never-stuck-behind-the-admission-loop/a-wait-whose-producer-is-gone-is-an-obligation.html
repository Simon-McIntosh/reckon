A wait whose producer is gone is an obligation

What changed. A run parked on a declared wait is held until its probe reports a terminal value, and nothing noticed when the work the probe watched had died. The classifier now reads a waiting run as producer-gone when three facts hold together: no process of the run is alive and that is a reading proven on the launching host; the probe's observed value has not changed for WAIT_PRODUCER_GONE_SECONDS (fifteen minutes); and no scheduler job the wait names is still listed by squeue -h -j <id>.

  • reckon/crew/recovery_classification.py — the producer-gone arm sits in the waiting branch after the existing probe-did-not-answer branch, so every verdict that branch gives today is kept. Liveness is read only from the hoisted local_liveness reading the classifier already takes: a stored answer carried for a run launched elsewhere is proven=False and keeps the run waiting, and a probe with no recorded pid keeps it waiting too. A probe that cannot answer and left no exit record — a worker killed outright — is producer-gone as well, with the stillness clock taken from its last answered observation, or from when the wait began when it never answered. _scheduler_job_alive is the one small scheduler read, and it never contributes to a gone reading when it cannot be answered.
  • reckon/crew/resumption.py — _record_wait_probe_history is the one per-sweep actor. Every observation the sweep makes, answered or not, is appended with its time to the pointer's wait_probe_history and pruned by age: an entry goes only once it is older than the bound plus one sweep interval and a newer entry is already past the bound, so the history always reaches back across the window the classifier measures. A dry run records nothing, because a preview that wrote would be a preview that acted.
  • reckon/crew/obligations.py — _producer_gone_item projects the reading into the run-producer-gone duty, naming the probe, the value it is stuck on, the terminal states expected and how long that value has stood still, and offering the resume or the discard. The duty blocks a turn: no reflex will lift it, so the session is the only thing that can decide.

Measure. tests/test_a_wait_whose_producer_is_gone_is_an_obligation.py passes its nine cases: the producer-gone arm with its duty; a file wait over a live worker; a value still moving; a run launched on another host; a scheduler job still queued; a worker killed outright with no exit record; an ended worker with an exit record keeping its existing stalled reading; a probe reaching its terminal; and the sweep recording and age-pruning the history the reading is taken from. Five negative controls each fail the arm they target: removing the process-liveness clause fails the file-wait arm, removing the stillness clause fails the moving-value arm, removing the host proof fails the other-host arm, removing the scheduler-job clause fails the scheduler arm, and removing the no-exit-record route fails that arm's killed-worker case.

What remains. Nothing in this node. A waiting run with no live process no longer reads as working: its row names the producer as gone, and its session owes a resume or a discard.
