The lander reads every review tier the run owes

What changed. The landing pass asked the review store for the run's review with no rubric (select_review_for_head), and every text-review reader excludes figure records by design. A run that changed figure images was therefore judged on its code review alone: its figure review could be missing, queued, or never dispatched, and the pass saw a run with nothing outstanding. land_once in reckon/crew/queue_landing.py now reads every tier the run owes at its head, through the rule the review reflex dispatches by (recovery_review_dispatch._changed_figure_paths): the code review always, and the figure review when the run's commits add or change an image under a figures directory. A tier that is missing is recorded awaiting-review naming that tier and that tier's own reflex state, which is what a missing code review already did. A tier that is stored but not complete is refused: the code tier by the acceptance rule it always used, the figure tier by the store's own delivery contract for its rubric.

The refusal stamp now covers every owed tier. A refusal holds only while the review records it read are unchanged, so a stamp keyed on the code review alone left a run refused for a missing figure review held after that review was stored: nothing moved in the record the stamp read. _owed_review_stamp digests each owed tier's record, an absent tier included, so storing the missing review changes the stamp and the next pass judges the head again. The awaiting-review record compares the tier it named as well, so a run that gains a figure review rewrites its record rather than keeping one naming a wait that has ended.

The three cases the gate shows. A delivered run whose commits change runtime source and an SVG, with its code review stored and its figure review not, is not landed; its live pointer reads status: awaiting-review with review_tier: figure. The same run, seeded refused with the code stamp and the review stamp it was judged under while the figure review was missing, is left exactly as recorded on the next pass — and lands as soon as the figure review is stored and complete, which is the refusal hold lifting on the review record changing rather than on the code moving. A run whose commits change no figure image lands on its code review alone, unchanged.

Not done here. The reflex's own reading of an unreadable changed-path list is mirrored rather than tightened: git reporting no paths reads as no figure review owed, because a lander waiting on a review the reflex would never dispatch would hold the run forever. Undisposed blocking findings in a figure review still refuse the landing at promotion, as before.
