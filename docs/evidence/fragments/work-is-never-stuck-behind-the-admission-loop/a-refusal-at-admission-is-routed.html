A refusal at admission is routed to a lane that fits

An admission pass that refuses a queued request with CompetenceLimit no longer parks it. The pass asks the picker for its ranked candidates, takes the first whose competence verdict passes (a candidate carrying no exclusion), and moves the request there with move_queued_run, which recomposes the launch on the destination backend and carries the request's recorded waivers. A destination the service launches is launched in the same pass; a destination on another lane leaves the request queued on that lane with one obligation naming the lane.

Only when no lane's window holds the request does it stay where it is, under the existing until-changed hold, with exactly one obligation naming the shortfall in tokens. The stored reason is the refusal itself rather than the lane's last allowance, so a coordinator reading the pointer sees what refused it.

crew queue edit now raises the same two refusals the next launch would, while the coordinator who made the edit is present: ScopeConflict naming the live run whose claim covers the edited scope, and CompetenceLimit naming the shortfall against the widest window any lane declares. An accepted edit re-records the request's review contract through queue_admission.record_review_contract, so it keeps the narrowed hold rather than falling to the dispatch gate's wider one.
