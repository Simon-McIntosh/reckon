The bounded readiness read builds no coordinators

A dispatch judges one section's readiness, and admission asks that question once per queued request through the bounded per-plan read. The answer is a readiness and a set of section verdicts; no coordinator is derived from it. But roadmap.section_readiness_rows called build_roadmap outside any scope, so the build resolved each plan’s coordinator: _critical_path_links → critical_path_coordinators → resolve_plan_coordinators, which reads every run’s ledger document through a deep copy. Measured on 6 November, the release stage of an admission pass still sat in resolve_waits → _ref_state → _readiness_rows → plan_review.section_readiness_rows → roadmap.section_readiness_rows → build_roadmap → critical_path_coordinators; six stack samples of pid 4157884 showed it there.

roadmap.section_readiness_rows now enters roadmap_build_scope(resolve_coordinators=False) itself. The scope is what build_roadmap’s critical-link resolver already reads, so entering it here covers every caller of the bounded read — admission and dispatch alike, and any caller added later — without each one having to remember the scope. Coordinator resolution is optional for this build because neither a readiness nor a section verdict reads who coordinates a plan; the only row that carries a coordinator is an idle link in the critical path, and section_verdicts_by_plan does not read that field.

Measure: tests/test_the_bounded_readiness_read_builds_no_coordinators.py, three arms over a synthetic project of 20 plans and 10 live runs. The first counts resolve_plan_coordinators through a patch while one plan_review.section_readiness_rows call answers: zero calls. The second derives the same rows the base revision derived — one unscoped build_roadmap over the read’s own inventory — and asserts equality for every plan and every section verdict. The third reads the MCP roadmap outside any node scope and asserts the critical-path links still name session-owner, with the resolver reached.

At the base revision the first arm fails with assert [1] == []: one coordinator resolution inside the bounded read. Negative control (the scope entry removed, the call left as the base revision had it): 1 failed, 2 passed, EXIT=1, the first arm counting the call again. At head: 3 passed, EXIT=0.
