the-queue-reports-its-own-stalls

An admission pass now records a stall verdict, in the record a coordinator already reads, for a request that has stayed admissible on a lane with room for longer than ten minutes while nothing holds it. The verdict names the request, the stage it is owed — release, launch or land — and that stage's duration on the most recent pass, read from the verdict log. It is written once per request and stands until a later verdict for the same request replaces it, so a request that has since launched no longer reads as stalled.

Every row a pass writes carries the age of the oldest request the lane could launch and did not, measured through the lane's own gate and allowance. The drain view reports each stuck request's age and stage from the recorded verdict in place of resolving its waits a second time: an overdue request is stuck when a pass examined it, recorded why it did not launch, and it is still there an hour later. A request the lane has no room for, and one a live run's claim holds, record no stall — its wait is accounted for by the hold the pass already names. No monitor-stream row is written; the stall is the one added verdict kind and no new row kind is added.

The request's own session sees the stall once through the needs-you rows, under the blocked kind, carrying the stage the stall named, and the row clears when a later verdict for the request replaces the stall.
