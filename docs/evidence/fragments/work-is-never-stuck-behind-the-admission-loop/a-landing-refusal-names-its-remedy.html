A landing refusal names its remedy

An automatic landing refused for a missing gate-check field now carries the action that supplies it. The lander derives the remedy from the run's own manifest, records it beside the guard on the live run, and the landing-refused obligation reads automatic landing refused: <guard>; remedy: <action>. For a missing exit_status the remedy names the gate log the manifest cites and the terminal EXIT=<n> record that log must end in; when the manifest itself is one promotion will not read, it names the manifest rewrite instead.

Why the guard alone was not enough

The guard states the rule — "a passing gate requires the check that produced it; missing exit_status" — and the obligation repeated it beside the run's generic crew complete command. A coordinator who reads that looks at the promotion command it ran. The reported defect was in the evidence behind it: the worker's gate-repair.log ended # exit status 0 (the gate printed EXIT=0) rather than a bare EXIT=0 line, so the promotion's fill found no exit status to read.

The remedy is derived where the refusal happens

queue_landing._landing_remedy reads the guard, and when it is the gate-check refusal it names each absent field. It first asks whether the promotion reads any manifest evidence at all, because promotion_checks._fresh_manifest ignores a manifest no newer than the attempt's manifest_baseline_mtime_ns: for an absent or stale manifest the remedy names the write the coordinator actually owes — the manifest for this attempt, carrying its status, gate command and test_logs — rather than a line in a log the promotion never opens. Only when the manifest is one promotion will read does the exit_status advice name a log, and that log is the one the promotion's own selection picks — promotion_records._default_gate_evidence_from_manifest's first test_logs entry resolved beside the manifest — with its last line read by promotion_evidence._recorded_exit_status. A log that does not end in the record yields the log path and the record expected; an unreadable log or one already well formed falls back to naming the missing field and the flag that supplies it. The remedy is stored as admission_landing.remedy and appended to the row's reason in obligations._review_duty_item. A guard the lander cannot repair carries no remedy, so it reads exactly as recorded rather than with invented advice.

The reader is not widened

A log ending # exit status 0 (the gate printed EXIT=0) is still refused. The third case asserts against the promotion's own pieces: _recorded_exit_status returns None for that text, ledger.gate_check_missing_fields names exit_status, and promotion_checks._require_gate_check_precondition raises the "missing exit_status" refusal. The guard the first case matches is taken from that same production precondition rather than from a literal the test hands the lander, so the assertion cannot pass by the test agreeing with itself.
