A delivered run always reaches a landing verdict

Two exits dropped a delivered implementation run with nothing written down. land_once continued past a run whose head carried no review, so a coordinator could not tell a run waiting on its review from one the pass never reached. And the crew complete --land step the pass runs re-read the worker's commits: entry as one revision, so an entry carrying its subject after the revision, or several revisions on one line, was refused as an unresolvable commit by the step the pass had just decided to take.

The pass now writes awaiting-review into the run's admission_landing with the review reflex's own state beside it — review_state: dispatched, or refused with the reason the reflex recorded — once per head and state, so a pass every 30 s does not rewrite the pointer for a situation that has not moved. The land step presents the revisions the shared reader queue_landing._delivered_revision places, and promotion_evidence reads the manifest's commit entries through that same reader, retiring its own whole-entry reading.

Measured through crew complete --land with the land step's own argv, on a repository whose manifest carries each entry shape.
