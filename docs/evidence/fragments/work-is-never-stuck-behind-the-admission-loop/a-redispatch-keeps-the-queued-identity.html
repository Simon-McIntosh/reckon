A re-dispatch keeps the queued request's identity

A coordinator re-dispatching a node whose request was still waiting steered the wrong way: queue_dispatch in reckon/crew/runs.py wrote the new dispatch's whole record over the waiting pointer and kept only run_id, queued_at and created_at. Everything a launch or an observation had already written onto that request — its argv, its base_sha, the observed session_id, and its node.manifest_path — was replaced by the new request's empty values, which repointed the manifest into a second run directory. crew resume then had no session to continue and the landing pass had no argv to check.

queue_dispatch now merges: the new record's fields win at the top level and inside node, so goal, done-when, role, spec level, brief fields and every other steer apply, and every field only the waiting pointer carries is kept. One node field is the exception — node.manifest_path — because the new record names a path for its own run directory while the waiting request's worker was already told where to write. It is named once, as _REQUEUE_PRESERVED_NODE_FIELDS beside queue_dispatch, rather than as an enumeration of the steerable fields, which would drop whichever field it forgot. A re-dispatch onto a run that is not queued is unchanged.

Four cases in tests/test_a_redispatch_keeps_the_queued_identity.py. A queued request carrying argv, base_sha, an observed session_id and a node.manifest_path is re-dispatched with a changed done-when and keeps all four while carrying the new measure. A re-dispatch with a changed brief carries the new node.brief, node.brief_sha256, and the empty node.brief_path a queued request holds before its run's stored copy exists. A plain re-dispatch keeps the run id, coordinator session, queued and created times. A re-dispatch onto a working run answers with that run, reports queued: false with no position, and leaves its pointer byte-identical. Gate: 4 passed, EXIT=0. Negative control (restore the whole-record overwrite): 1 failed, 3 passed, EXIT=1, the first case reading KeyError: 'argv' and the other three passing. The 29 test files that reach queue_dispatch or _answer_existing_node_run ran over both arms: 181 passed, 2 failed at base 695f6616 and 182 passed, 1 failed at head, the one head failure also present in the base arm (test_a_new_dispatch_over_a_queued_claim_at_the_session_cap_is_refused, a pre-existing defect in the session-cap refusal path), so no failure id was added.
