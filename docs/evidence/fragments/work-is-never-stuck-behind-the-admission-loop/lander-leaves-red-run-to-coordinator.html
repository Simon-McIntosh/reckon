The lander leaves a run whose own evidence is red to its coordinator

What changed. The admission lander promoted a delivered run whose own manifest recorded an after_suite exit status of 1 with a failure its baseline did not name, and whose review carried added_failure_count: 1 and five open findings. It recorded gate passed and merged the red test onto the primary branch with no coordinator action, because the lander judged a run on its own measurement and the review's acceptance rule exempted its non-blocking findings itself.

reckon/crew/queue_landing.py now reads the run's own evidence before it measures anything, and records the existing refused status with a red-suite guard when that evidence is red or unreadable. Three arms state it. _manifest_suite_guard reads the manifest's baseline_suite/after_suite pair: _after_suite_arm reports an arm that is absent, that does not declare completed: true, or that records no exit_status as unreadable rather than clean; _after_suite_exit_guard refuses a nonzero exit; _after_suite_added_guard refuses a failure id the baseline does not name. _review_added_failure_guard refuses a review recording added_failure_count above zero, and _undisposed_finding_guard refuses a finding with no disposition. A manifest recording neither suite arm states nothing, so a run whose node armed no suite pair is judged on the pass's own measurement exactly as before.

A refusal is judged again when the record it read changes, so the suite arms now enter the refusal's review stamp through _suite_evidence_stamp: a coordinator who records the missing observation releases the refusal on the next pass rather than leaving it standing over evidence that has moved. Repair: the landing no longer speaks over a disposition

Making a disposition mandatory before a landing exposed the consequence on the other side of it. The pass recorded an exemption over every non-blocking finding the review carried, and that writer replaces the entry it finds, so the folded:<node> a coordinator had recorded came back as exempted:non-blocking, noted at landing on the next pass and the node the finding was folded into was lost. The pass now records an exemption only for a finding still open: a run reaching the landing has already been answered, so it writes nothing, and the record a coordinator wrote is the record the run lands with.

Reverting that repair reproduces the overwrite exactly — folded:the-follow-up-node reads back as exempted:non-blocking, noted at landing — in negative-control-fold.log. The same reading consolidated three duplicated checks: the suite arms are read once per pass and shared by the refusal and its stamp, and the three status fields go through one integer predicate instead of each restating the boolean exclusion.

The two directories this fragment cites live beside the run, not in the tree: gate-repair.log is the importer gate at the repair commit and negative-control-fold.log is the reverted run above.

Consolidated. The first repair wrote its own exemption writer beside the shared one, differing only in a filter, which is two rules that agree until one of them is edited. The rule now lives once, in recovery_review_acceptance._excusable_finding_indexes, which skips a finding that already carries a disposition, and record_landed_exemptions reads those dispositions from the record it rewrites rather than from the mapping its caller holds — a caller that parsed a review in memory carries none, and reading them there would report every finding unanswered and overwrite what the store holds. The landing and the promotion path both call that one function, so a coordinator's fold survives either route.
