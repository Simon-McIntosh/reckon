Every arming replays the fleet, each row under its run's recorded state time

What a re-arm draws

The section's opening case was a follower re-armed with ten live runs showing nothing for sixteen minutes. The contract it replaced — merged at 4cccc311 — had the first arming draw the fleet and a re-arm print only what moved, which is silent whenever nothing moved. The lead's 2026-09-29 ruling replaces it: every arming, a re-arm included, replays one row per live run, each stamped with the recorded time that run entered its current state and ordered by that time, so a re-arm is never blank and never a burst of rows sharing the attach second.

The rows carry the run's own clock, read from the producer's stream: the follower reads each run's last recorded transition (_recorded_fleet_times over runs.read_stream_events) and overlays that observed_at onto the live-pointer baseline before the rows are fed through the row path. The overlay is taken only where the stream's last recorded state for the run agrees with the live classification; where the two disagree the row keeps the live state and the fleet's own clock, never a state the live fleet denies. A re-arm whose pane is a terminal restores its stored history first, under its frame, and the replayed rows are drawn regardless of the pane's remembered states, so the very states being re-announced do not suppress their own rows.

The replay is bounded so a re-arm is neither blank nor a burst of rows sharing the attach second. The stream's size is read once, before the replay reads anything, and that boundary fixes both halves: the replay covers the span between the run's recorded place and the boundary, and the read loop that follows opens at exactly the boundary, so a line appended in between falls to one side and arrives once. A first arming has no recorded place in this stream, so it derives the fleet as it stands and leaves the read loop at the cursor's own offset, delivering every line it never replayed.

Negative control

The declared mutation stamps every replayed row with the arming time instead of the recorded state time — the pre-ruling behaviour in a new shape. Its log's first line is the declared string, verbatim:

stamp every replayed row with the arming time instead of the recorded state time

The mutation fails the two cases that observe the overlay (2 failed, 25 passed) — a quiet re-arm's still runs lose their recorded time, and the first arming's rows do — so those cases observe the recorded-time overlay rather than passing on the attach second. The six replay cases whose runs moved in the gap are unaffected by this mutation, because their rows come from the replayed lines that already carry the recorded stamps.
