§4 — the rearm test comment matches the code

The section comment above the pane-history tests in tests/test_follow_rearm_continues.py now describes the history burst as it is written, not as an unframed replay. The burst is: emitted only when the follower's stdout is a terminal, and, when it is, a single string opening under one dim frame line with every history row rendered dim beneath it and no closing separator.

The two facts the comment now states, and where the code holds them

  • Terminal-only. _follow_replay_visible (reckon/cli.py) answers sys.stdout.isatty(), and the burst is composed only when session is not None and _follow_replay_visible() at the re-arm event. A pipe — the host's line-batching Monitor is one — has no scrollback to restore and would read the restored rows as fresh transitions.
  • One dim frame line. _follow_history_burst (reckon/cli.py) returns "\n".join([frame, *(dim(row["text"]) for row in rows)]) with frame = dim(_HISTORY_FRAME.format(count=len(rows))) and _HISTORY_FRAME = "── history · {count} rows ──". One frame at the head, dim rows beneath, and no trailing separator line.

What changed

Comment lines only, in tests/test_follow_rearm_continues.py: the paragraph that called the replay framed by nothing and explained a header above and a separator below as noise is replaced by a description that names its subject in every sentence — the gate _follow_replay_visible, then the two branches keyed on stdout.isatty() that _follow_history_burst serves. The HISTORY_HEADER and HISTORY_SEPARATOR module constants beside it are unchanged.
