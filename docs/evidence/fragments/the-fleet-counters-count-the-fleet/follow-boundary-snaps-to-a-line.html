The follow boundary snaps to a line so a half-written record is delivered once, whole

What the boundary is

The follower derives its replay span from a boundary captured from the stream file's size before the replay reads anything. The producer appends one JSON record per line, so a line boundary is a record boundary — but a size read while the producer is mid-write lands inside a record that has no newline yet. Taken there, the replay stops on the last whole line before it and the follow loop opens in the middle of the broken record, so the first half is dropped by the parser and the completion reads as a second unparseable fragment: the record reaches the pane never.

The guard now snaps the captured offset back to the byte after the last newline at or before it (_follow_boundary in reckon/cli.py, replacing the raw stream_path.stat().st_size). The boundary always lands on a newline, so the replay reads only whole records and the follow loop opens at the start of any record still being written — which it then reads whole once the newline lands, delivered exactly once.
