A schedule failure leaves discovery served

The discovery handler attaches the schedule per read from the live crew rows. That derivation can fail while the stored inventory is already in hand, so a failure attaching it no longer fails the read: the payload carries the inventory with schedule null and the failure named in schedule_error, and the read logs the failure once. A failure reading the stored result itself is unchanged and still answers 500 with distributed_project_state_invalid. The degradation sits in one helper, _attach_schedule_for_read, which owns the try around _attach_schedule; the handler keeps the stored-result read and the attach in one error path so the mutation below restores the old behaviour by swapping the helper for the raw attach.
