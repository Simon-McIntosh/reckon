The home view loads a fleet summary

The fleet home now waits for /_projects/index.json before showing counts. Each visible project's plan statuses, progress, activity and active sprint come from that summary. The home no longer substitutes an indexed-document total or paints zeros while the summary is pending. Its recent-activity panel reports project edits and progress from the summary, which needs no inventory rows.

The command palette starts the fleet's full /_discover requests on its first open, once per mounted project. The current project's loader also stays off discovery while the home route is open; leaving home resumes its normal derived-state load. A reckon-fleet event for the rollup key rereads the summary, and an older response cannot replace a newer one. Crew schedule bars resolve their plan slug against the current inventory before using its title, sprint, status or link.

The browser case withholds the summary, sees a loading state and no status counts, then receives a three-plan summary and renders 50% progress. It sees no discovery request before the palette opens and exactly one request per mounted project afterward. It also publishes a second rollup before the first response finishes; the newer count of three remains visible after a stale count of 99 arrives. A served-page browser case checks the actual state loader: the base requests /_discover/reckon before the palette, while the head does not. Both browser cases ran and passed at the head.
