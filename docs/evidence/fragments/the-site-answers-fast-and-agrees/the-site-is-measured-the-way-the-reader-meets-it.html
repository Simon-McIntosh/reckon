§11 — The site is measured the way the reader meets it

A headless Chromium probe loads the served site through an SSH tunnel to 98dci4-srv-1006:8765, as the WSL client reaches it, cold and again warm, and records the time until each surface is populated, the bytes the browser transfers and every console error. The probe ran on the fleet allocation, node 98dci4-clu-2002, job 1281970; the served host's load average was 4.8 and the probe host's was 34.8 during the head pass. The miss the home view owns is §6's. The fleet summary the home view renders transfers 1.17 MB cold and 897 KB warm, against the 500 KB the gate allows; the plan list, graph, velocity and crew surfaces are all far inside their budgets, so this is the one surface out of budget and it is the home view's load, which §6 delivered.

The plan-agreement check could not be completed with the instrument this node had. Ten plans are drawn at random per project from the rows the plan list actually renders, each plan's served HTML is parsed by the site's own reader and its figure is compared with the bar the row shows. Twenty-three of the thirty reads came back 409 Conflict from the server while the browser held a page open, across eight spaced retries each, so only imas-ambix's ten and a handful of others were read; every one of the seven that was read agreed exactly (35, 40, 0, 17, 50, 17, 96 against the same figures the row shows). The same URLs answer 200 from a shell when the browser is idle, so this is a defect in the probe's fetch path under load rather than a disagreement in the site. The criterion is reported unmet, not failed: it is unverified, and a later pass with a quieter fetch path can settle it.

The negative control fails the gate, so the probe tells a fast site from a slow or empty one. The same probe ran against a temporary reckon serve on port 18766, started from the plan's base revision b98f7a160 (the commit before the plan's first section merged as 46e5138f2), extracted from the object store into the run's scratch directory. There the plan list never shows a non-zero bar at all (None for nova and reckon), the graph does not populate within 30 s for those two, the home view's warm load is 850 KB, and power_convertor's figure first screen transfers 2.66 MB warm with a 6.1 s cold draw — four of the six gate lines fail.
