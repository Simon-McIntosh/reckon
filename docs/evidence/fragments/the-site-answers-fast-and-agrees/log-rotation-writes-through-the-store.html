§9 — The rotated log's predecessor is published by the one shared writer

The served log's rotation copied the over-bound live file to a private staging path beside the predecessor (<predecessor>.tmp) and moved it into place with os.replace. That is a second, ownerless staged-file writer sitting beside reckon._store.write_atomically, which the project keeps as the single place a file is published through a sibling temporary: every writer that needs the guarantee renders through its callback rather than keeping a private temporary-and-rename of its own. The staged-write inventory census (tests/test_staged_write_inventory.py) reads exactly that shape and reported the violation directly, naming ('reckon/serve.py', '_bound_server_log') as a staged write the census did not expect.

_bound_server_log now renders the copy into its destination through write_atomically(predecessor, stage_live, binary=True): the render callback streams the live file (shutil.copyfileobj) into the temporary the shared writer created, and write_atomically owns the temporary, the flush, the rename and the failure cleanup. There is no local staging path and no os.replace in the function any more, so the census sees one writer for a staged replacement and the module agrees with the rule the rest of the codebase follows.

The behaviour the plan's §9 record depends on is unchanged: the copy and the empty still run under _ACCESS_LOG_LOCK, the lock every access line takes, so a line written while the log is rotating is written wholly before the copy or wholly after the empty and is never dropped between them. The copy is still taken before the empty, so a crash between the two leaves the predecessor whole and the live file still carrying the content.

The interleaving case in tests/test_request_duration_and_log_bound.py deterministically drives that window by pausing the rotator inside its copy. The pause seam moved with the copy primitive: the test now patches serve.shutil.copyfileobj (the primitive the shared writer's render callback uses) instead of the retired serve.shutil.copyfile. The property it asserts — a sentinel line written mid-rotation is present in the live file afterwards — is unchanged.

Measure: the named check pytest -q tests/test_staged_write_inventory.py tests/test_request_duration_and_log_bound.py reports 54 passed at the head revision. At the base revision the inventory case fails on the extra item ('reckon/serve.py', '_bound_server_log'), reproducing the defect; the same command passes at head. ruff check reports the same 19-finding set on the two changed files at base and at head — the change adds no finding — and ruff format --check is clean on both. The negative control restores the hand-rolled copyfile+os.replace in _bound_server_log and the inventory case fails again on the same extra item.
