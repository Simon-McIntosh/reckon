Text responses are gzipped once per revision

_send_file gzips a text response — SVG, JavaScript, CSS, HTML or JSON — above the existing threshold when the request accepts gzip, and caches the compressed bytes per ETag under the configuration home, so a file is compressed once per revision. A client that does not accept gzip still receives the file as it is, the ETag is unchanged, and a matching If-None-Match still answers 304.
