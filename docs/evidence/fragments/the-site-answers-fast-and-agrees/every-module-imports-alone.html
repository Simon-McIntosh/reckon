§10 — Every reckon module imports on its own

Outcome. The import cycle between reckon.project_state and reckon.crew.fleet_supervisor is broken. reckon.project_state reached the crew package through reckon.sprint_liveness while it was still initialising, and reckon.crew.fleet_supervisor imported _sha256_path from it at module scope, so importing reckon.mcp_edit_plan first raised a circular ImportError. fleet_supervisor now re-exports the shared digest through a module __getattr__ and imports it lazily at its one call site, so no module-level edge runs back into project_state and the helper stays a single implementation.

Measure. The new test imports each module under reckon/ first in its own fresh interpreter, with the repository root first on sys.path and an isolated home. At the head revision 176 passed (EXIT=0); at the base revision 4 failed, 172 passed (EXIT=1), failing on reckon.mcp_edit_plan, reckon.project_state, reckon.project_state_parity and reckon.sprint_liveness. The negative control restores the module-level import in fleet_supervisor.py and fails the same four (EXIT=1). Logs sit under the node's run directory.
