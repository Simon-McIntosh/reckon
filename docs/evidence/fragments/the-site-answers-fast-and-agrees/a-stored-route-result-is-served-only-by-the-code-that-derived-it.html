Stored route results carry their requesting server's revision

The served process reads the revision from its startup source snapshot when it asks for a refresh. It passes that revision to the refresh child, which stores it beside the result. A read under another revision follows the existing miss path and starts a refresh for the key. A record from before this field existed is also a miss when the served process has a revision.

The child stores the command-line revision exactly, including an absent value. The store's fallback to the running server snapshot applies only when an in-process caller omits the argument. The child test clears the server snapshot while invoking the child's entry point, so it cannot recover a revision that its parent failed to pass.
