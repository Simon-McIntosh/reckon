§12 — A figure's thumbnail is a small raster image

Outcome. The thumbnail route rasterises an SVG figure to a PNG instead of passing the vector through. _render_thumbnail in reckon/serve.py now dispatches on the source's suffix: a raster is decoded by Pillow as before, and an SVG is drawn straight to the thumbnail's pixel size by resvg_py.svg_to_bytes and then bounded by Pillow's thumbnail, so neither edge can exceed THUMB_MAX_EDGE. The output goes through the existing per-revision cache keyed by the source's stat identity, so a second request is a cache read and a rewritten figure keys a new entry. A figure that fails to rasterise — an SVG included — falls through the route's existing handler and is served as itself under its own media type, rather than answered with a 500. The SVG passthrough branch is retired.

The rasteriser. resvg-py 0.5.0, added with uv add --no-sync resvg-py and recorded in pyproject.toml and uv.lock. It was chosen because the wheel is self-contained: the manylinux x86_64 build carries its own resvg_py.abi3.so and needs no system library, so the server and its tests get a rasteriser wherever they run. rsvg-convert was the measured reference (11 to 32 KB PNGs in 18 to 141 ms each against six sampled figures) but it exists on the login node only, and cairosvg would need a system libcairo present at import time.

Environment. The wheel is named in the project's lockfile so every checkout and CI install it with uv sync. It could not be installed into the operator's shared environment from this run: /home/ITER/mcintos/Code/reckon is mounted read-only inside the worker fence, so UV_PROJECT_ENVIRONMENT=/home/ITER/mcintos/Code/reckon/.venv uv sync --no-install-project --inexact reports WARN Failed to acquire environment lock and installs nothing. The gate was run against the same interpreter with the locked wheel unpacked on PYTHONPATH. Until the shared environment is synced, import resvg_py fails and the route falls back to the SVG — the pre-change behaviour.
