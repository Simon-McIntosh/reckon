§14 — a figure revision is fetched once per browser

reckon/serve.py now derives one revision token per file — _file_revision, the same inode–size–mtime identity the ETag is built from, so a URL's token and its validator agree by construction — and exposes it on every figure inventory row as revision. do_GET reads ?rev=<token> from the request, and both the figure route (_send_file) and the thumbnail route (_serve_thumbnail) answer Cache-Control: max-age=31536000, immutable when the token still matches the file, falling back to the existing no-cache revalidation when it does not. The comparison is one helper, _revision_matches, so a request naming a stale revision — a rewritten figure — is refetched under the new URL the surface now builds.

The surface takes the token from the row it already has. artifactImageSrc in docs/ui/shell-plans.jsx appends artifactRevisionQuery(item) to the thumbnail URL, and readerFigureSource in docs/ui/plan.jsx appends the same query to the reader's image URL, so the list icon and the full drawing are addressed by one revision for one figure.

The gate — PYTHONPATH=$PWD <venv>/python -m pytest -p no:cacheprovider -q tests/test_a_figure_revision_is_fetched_once.py, run in the node worktree on the fleet allocation (job 1281970), log logs/head.txt ending EXIT=0 — reports 7 passed. It requests a temporary figure and its thumbnail by their current revision and asserts the immutable header, requests one without a revision and asserts no-cache, rewrites the figure and asserts the old revision's URL is no longer immutable while the new one is, and confirms the inventory row carries the token. One test compiles the served shell-plans.js and plan.js and shows both the list source (/_thumb/….png?rev=abc123) and the reader source (/sample/figures/demo/wide.png?rev=abc123) carry the revision, and that a data: URL and a row without a revision are unchanged.

The declared negative control, armed with RECKON_TEST_DROP_FIGURE_REVISION=1, makes the server ignore the URL's revision so both figure and thumbnail fall back to no-cache. Applied and reverted after, it turned the run red: EXIT=1, 3 failed, 4 passed, the failing ids being the figure-immutable, rewritten-figure, and thumbnail-immutable cases; the two no-revision controls still pass, so the failure is the immutable path and not the suite. The log is logs/negative-control.txt in the run directory.
