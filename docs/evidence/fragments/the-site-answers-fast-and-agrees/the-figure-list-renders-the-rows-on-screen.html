The figure list mounts only the rows on screen

A figure index of a thousand-plus rows put every row, each with a thumbnail <img>, into the page at once: a headless load recorded seven long tasks totalling 1.05 s, the longest 383 ms, while the first screen holds about 60 rows. The artifact feed now mounts only the rows within and near the viewport, with spacer elements standing in for the rest so the feed keeps the scroll height of the full list and the last row stays reachable.

Each mounted row’s height is cached as it renders, and rows that have not been measured yet are charged the running average of the measured ones. The offset model therefore converges after the first measurement pass instead of drifting as the reader scrolls, which is what makes a single jump to the end land on the last row.

The window is applied to the lists that carry a thumbnail per row — the figure and animation kinds — which are the ones whose row counts run into the thousands and whose images cost the most to mount. A document list (plans, research, evidence) still renders in full. That boundary is required by an existing check outside this node’s write scope: test_rendered_status_chips_reduce_the_plan_feed reads the rendered row count as a proxy for the filtered plan count, so windowing the plan feed makes its baseline > statusCount premise false. Windowed for every kind, the head arm added that one failure against base; scoped to the image kinds, the head arm adds none.
