§9 — The server records each request's duration, in a bounded log

Every latency in this plan had been reconstructed by hand because the access log carried no duration, and the served log had grown to hundreds of megabytes unrotated. Each answered request now logs one line carrying its duration in milliseconds, and answers with the same figure in a Server-Timing header. The handler times the request in handle_one_request, sets Server-Timing: app;dur=<ms> in end_headers, and emits the access line through the existing log_message, which the base log_request cannot do because it runs inside send_response, before the duration is known. The base access line is suppressed in favour of this one.

The served log is bounded and keeps one predecessor. The unit opens the log with StandardOutput=append:, so systemd holds one descriptor in append mode for the process's life and a rename would leave it writing the renamed inode. _bound_server_log therefore copies an over-bound log to one predecessor (server.log.1, via a staging file and os.replace) and then empties the live file in place; append mode re-seeks to the current end on every write, so the next logged line lands at offset 0 of the same short file. The bound is checked once per request and once at start-up, under one lock shared by the handler threads.

Measure: the focused gate pytest -q tests/test_request_duration_and_log_bound.py reports 2 passed at the head revision — one request carries its duration on the logged line and in the header, and after the log is driven past its bound one predecessor holds the prior content and the live file is bounded. The test files that import reckon/serve.py or reckon/service.py report 72 passed at the head; the same set (minus the new file, which exists only at head) reports 70 passed at the base — no added failures. ruff check reports 17 findings on serve.py at both base and head and zero on service.py, and ruff format --check is clean on all three changed files. The negative control removes the log size bound (rotation returns False) and the bounded-size case then fails, EXIT=1, on the missing predecessor.
