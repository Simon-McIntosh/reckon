§9 — The server records each request's duration, in a bounded log

Every latency in this plan had been reconstructed by hand because the access log carried no duration, and the served log had grown to hundreds of megabytes unrotated. Each answered request now logs one line carrying its duration in milliseconds, and answers with the same figure in a Server-Timing header. The handler times the request in handle_one_request, sets Server-Timing: app;dur=<ms> in end_headers, and emits the access line through log_message, which the base log_request cannot do because it runs inside send_response, before the duration is known. The base access line is suppressed in favour of this one.

The served log is bounded and keeps one predecessor. The unit opens the log with StandardOutput=append:, so systemd holds one descriptor in append mode for the process's life and a rename would leave it writing the renamed inode. _bound_server_log therefore copies an over-bound log to one predecessor (server.log.1, via a staging file and os.replace) and then empties the live file in place; append mode re-seeks to the current end on every write, so the next logged line lands at offset 0 of the same short file. The bound is checked once per request and once at start-up.

The empty and every logged line share one lock. A copy-then-empty rotation drops any line written between those two steps, because the line then sits in the predecessor only if the copy passed its offset and in the emptied file not at all — so a rotation lock held only against other rotations would still lose access lines under concurrent traffic. Access lines go through _write_access_line, which appends them through the served process's own O_APPEND handle (opened once by _AccessLogSink, so it survives an empty of the same inode) under the same lock the rotator holds; a line is therefore written wholly before the copy or wholly after the empty. Where that handle cannot be opened the line falls back to the inherited stdout, which the unit has on the same file. Residual: the few lines the process writes outside _write_access_line — the start-up banner, a compliance-refresh spawn failure, and a traceback the socket server prints on stderr — are not covered by the lock, but the per-request access line is.

Measure: the focused gate pytest -q tests/test_request_duration_and_log_bound.py reports 3 passed at the head revision — one request carries its duration on the logged line and in the header, after the log is driven past its bound one predecessor holds the prior content and the live file is bounded, and a line written while the log is being rotated survives the rotation. The test files that import reckon/serve.py or reckon/service.py report 73 passed at the head; the same set (minus the new file, which exists only at head) reports 70 passed at the base — no added failures. ruff check reports 17 findings on serve.py at both base and head and zero on service.py, and ruff format --check is clean on all three changed files. Two negative controls each fail on the case they disarm: removing the log size bound fails the bounded-size case on the missing predecessor, and removing the exclusion between a write and the rotation fails the rotation-survives case on the dropped line; both EXIT=1.
