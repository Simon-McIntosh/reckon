Velocity answers for every scope

capture_project took selected[0] without checking that the window selected any commit, so one repository quiet in the window raised IndexError and failed the all-project view. The same line took first[-1] when the window opened at a repository's first commit, which Python reads as the last commit rather than as no base, so that commit's changes were measured from the wrong revision and counted as zero. The base is now resolved explicitly for both cases.

What changed

  • capture_project resolves the window base from the selection instead of indexing it blind. A window that selected no commit takes the head as its base — an empty range, so every metric reads zero. A window whose first commit is the repository's first takes None as its base, which names the empty tree, so that commit's additions count from nothing.
  • _rev_range is the one place that renders a range: the empty tree object stands in for a None base, used by the commit capture, the record-file addition scan and both ledger-recovery logs.
  • The patch of a parentless root commit is taken against the empty tree, since parents[0] does not exist for it; every line it carries reads as an addition.
  • The ancestry assertion, the seen-set of already-reachable commits and the ledger read at the base all treat a None base as the empty tree: the whole first-parent line is expected, nothing is pre-existing, and no earlier revision carries a ledger.
  • reckon/velocity.py only; no report field changes shape.

A quiet repository is measured at zero for every metric, a repository whose first commit is inside the window counts that commit's lines from the empty tree, and an ordinary repository counts only its windowed commit while the six lines added before the window opens stay outside it.
