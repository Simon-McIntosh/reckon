§16 — serve.py fits a worker window again

Outcome. Two concerns have left reckon/serve.py by pure move. The per-path git dates — the creation and last-modified caches with their paths, payloads, loaders and stores, _run_git, the git directory, HEAD and outside-repository readers with their memos, and _git_first_committed and _git_last_committed — now live in reckon/git_dates.py. The change streams — _ProjectChangeWatch, _FleetChangeWatch, and the tree-signal and cross-node timing helpers they use — now live in reckon/change_streams.py. Each definition moved as it stood; scripts/check_pure_move.py reports no problem for either move: no statement was lost, duplicated, or introduced except imports, and the two creation and last-modified mirrors moved as they were rather than being merged.

Budget. reckon/serve.py measured 54,746 estimated tokens at the base revision and 44,178 now, under the 45,000 this section allows and under the 50,000 bound tests/test_every_module_fits_a_worker_window.py holds every module to. The code it gave up sits in reckon/change_streams.py (5,725) and reckon/git_dates.py (5,605); the difference is the two re-export blocks this module keeps and each new module's own header. The token test no longer names reckon/serve.py; its only remaining failures are reckon/crew/review.py (51,584) and reckon/ledger.py (51,666), both measuring identically at the base revision, so this move adds no failure of its own.

Import surface. serve.py still imports every moved name another file imports from it, and the moved definitions reach this module's LOGGER, _STATE_ROOT, _invalidate_tree_views and _walk_discovery_signature through function-level back-references that resolve here at call time. That is what keeps a test which rebinds one of those on serve reaching the moved code: the patch works because the reader of the name the patch targets stayed in serve.py.

Repointed census. Every test that patched or rebound a moved name, or a constant a moved reader consults, now names the module that holds it: the git date caches, memos and loaders/stores to reckon.git_dates (test_git_head_is_resolved_once, test_a_tree_outside_git_asks_once, test_cache_paths_carry_their_format, test_staleness_counts_from_the_last_commit, test_writer_callers_first_wave, whose three cache cases drive the stores through the module the store resolves its path, payload and writer from), and the project change watch to reckon.change_streams, which is where the fleet watch arms each tree (test_cross_node_writes_refresh_the_index, test_server_listens_before_it_watches). Patches that still addressed serve were left alone where the reader stayed — serve.subprocess.run, serve._run_git's callers in this module, and serve._git_first_committed — because those resolve against this module at call time and still bind.

Negative control. The change-watch patch in tests/test_cross_node_writes_refresh_the_index.py was pointed back at serve and test_an_unread_tree_pays_no_slow_sweep then failed (EXIT=1, "an unread tree was swept"), because the tree the fleet watch arms resolves the class from reckon.change_streams: the patch has to name the module that holds the name. The file was restored afterwards and the worktree left with no diff against its commit.

Named limits. The pure-move check was run against the revision that introduced the function-level back-references this move carries, so the moved statements are compared with those lines already in them; against the orientation base revision those lines read as additions to the moved functions. Only the BOUND the token test enforces is quoted as a limit here — the 45,000 in the section text is a budget target for this section, not a test constant.
