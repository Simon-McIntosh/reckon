The paired replay record is written from the store and the run directories

What landed

An evidence record at paired-replay-report.html carries the per-arm table of paired differences with 90% intervals over sections, every one of the 54 runs by id with its section and base revision, the seed and the section choice of the draw, the query and the literal command that produced it, §8's two positive controls, the same-arm negative control, and each arm's verdict under §8's rule. It reports one section excluded with its reason and no run excluded on arm membership.

The record is generated, not transcribed: the producer committed beside it at paired_replay_report.py reads the run store through runs/run_details for each replay's gate, base revision, commits and attempts, and each run's own directory for its streams (and, for codex, the harness's own session rollout) for tokens, tool calls and edit outcomes. It ran on the all_debug partition; its log in the run directory names the revision and the literal command on its header lines and ends in EXIT=0.

Where the figures are

No number is restated here: a figure typed into prose is a second copy that drifts from the one the script measured. The record's own tables carry them, generated from the store and the run directories in one pass — each arm's verdict under §8's rule with its mean paired difference and 90% interval over sections, the same-arm spread the replicate clive run shows against clive, and §8's metrics per arm.

Every treatment interval overlaps the same-arm interval, so all three arms are reported as not separated and, under §8's rule as §14 applies it, none is adopted. The gate pass rate is unchanged against the baseline for all three, and no flight default moves.
