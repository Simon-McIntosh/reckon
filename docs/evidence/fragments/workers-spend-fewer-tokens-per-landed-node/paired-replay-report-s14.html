The paired replay record is written from the store and the run directories

What landed

An evidence record at paired-replay-report.html carries the per-arm table of paired differences with 90% intervals over sections, every one of the 54 runs by id with its section and base revision, the seed and the section choice of the draw, the query and the literal command that produced it, §8's two positive controls, the same-arm negative control, and each arm's verdict under §8's rule. It reports one section excluded with its reason and no run excluded on arm membership.

The record is generated, not transcribed: a script kept beside the record in the run directory reads the run store through runs/run_details for each replay's gate, base revision, commits and attempts, and each run's own directory for its streams (and, for codex, the harness's own session rollout) for tokens, tool calls and edit outcomes. It ran on the all_debug partition; its log in the run directory names the revision, the tree and the literal command on its header lines and ends in EXIT=0.

What it measures

Over the nine dispatchable sections of seed 20261116's draw, the mean paired difference in cumulative input tokens, with its paired bootstrap 90% interval over sections, is −1.35M (−7.0%) for clive-anchored, −2.26M (−11.6%) for omp-local and −3.15M (−37.5%) for codex-anchored.

The same-arm spread is not small: the replicate clive run paired against clive on the same sections reads +4.01M (+20.7%), interval 0.06M to 7.97M. Every treatment interval overlaps that interval, so all three arms are reported as not separated, and under §8's rule as §14 applies it none is adopted. The gate pass rate is unchanged against the baseline for all three, and no flight default moves.
