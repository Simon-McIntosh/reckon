A fenced omp run reads the models.yml the fence seeds

Landing

The omp launch environment now carries PI_CODING_AGENT_DIR=<run home>/agent beside HOME=<run home>. oh-my-pi resolves its home as <HOME>/.omp and its agent store, which holds models.yml, one directory below that at <HOME>/.omp/agent; the fence mirrors the operator's files relative to the run home it owns, so the seeded copy landed at <run home>/agent/models.yml. Relocating HOME alone therefore left the harness reading an empty store.

The variable is declared once, in _HARNESS_AGENT_STORE in reckon/_worker_fence.py beside _HARNESS_HOME, and applied by launch_plan through harness_agent_store(). Only omp has an entry, so the claude (CLAUDE_CONFIG_DIR) and codex (CODEX_HOME) environments are unchanged.
