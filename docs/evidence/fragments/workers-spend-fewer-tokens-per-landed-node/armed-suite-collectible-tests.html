An armed suite command names only the files pytest collects

A node's fenced write scope names fixtures, helpers and conftest modules under tests/ beside the checks it wrote, because all of them are part of the check. The armed suite command handed every one of them to pytest, so a fixture made pytest exit on a usage error and the arm read as one that collected nothing, while a command narrowed by hand was refused as not matching the command the run was armed with. Neither shape could promote a node that writes a fixture. One predicate now decides which paths pytest can collect, and every consumer that turns write or changed paths into pytest arguments reads it.

is_collectible_test_path sits beside is_test_path in reckon/crew/node.py and matches pytest's default python_files (test_*.py and *_test.py) on the basename, case-sensitively, because this repository declares no python_files of its own. _node_test_files in reckon/crew/promotion_records.py resolves the armed command with it, so the recorded command and the command each arm is compared against are the same list; _landing_test_files in reckon/crew/queue_landing.py applies it to the fallback over a delivery's changed paths, which would otherwise re-admit the fixture the resolver had just narrowed out; and _suite_gate_prompt_body in reckon/crew/dispatch.py states the same rule to the worker, which resolves its own command from that sentence.

is_test_path is unchanged, so a node writing a fixture is still writing part of a check and still owes a negative-control declaration, and the census tests the project declares still run for a product-scope node with no test file of its own.
