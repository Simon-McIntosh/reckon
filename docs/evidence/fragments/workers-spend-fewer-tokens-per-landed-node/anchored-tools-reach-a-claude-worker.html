A seeding Claude launch now names the anchored tools in the worker's prompt

The launch step that seeds the anchored server (launch_plan) now appends an instruction to the worker's prompt naming read_anchored and edit_anchored and giving the ToolSearch query that loads them. It is added where the seeding is decided, so an unfenced, resumed, operator-settings or no-flight-config launch — none of which registers the server — carries no instruction.

Two causes were measured, on headless clive sessions against a scratch worktree with the server registered in a run-shaped config home. First, the session-start record snapshots MCP state about two seconds after launch: a server that answers initialize in one second reads connected with its tool in the 23-tool list, while the anchored server (4.0–5.6 s, almost all of it the mcp SDK import) reads pending with 22 tools and none of its own. Second, this build defers MCP tools behind the harness search: the same unfixed session's ToolSearch returned both anchored tools, so they were reachable and the prompt never said so. Neither MCP_TIMEOUT (60 s) nor MCP_CONNECT_TIMEOUT_MS (15 s) moves the snapshot; both were measured against the same 3 s server, which stayed pending.

The added cases assert the seeded launch's prompt carries both tool names and the search query for both claude and clive, that each ineligible launch's prompt is untouched, and that a prompt already carrying the instruction keeps exactly one copy. Negative control: with the launch-step instruction removed, test_a_seeding_launch_instructs_the_anchored_tools fails for both dialects (2 failed, EXIT=1). Ruff check reports the same three pre-existing findings on both arms; ruff format is clean on the staged paths.

The startup half of the deliverable is not shipped: reaching connected at session start requires the server's own start under about two seconds, which means importing the MCP SDK lazily in reckon/anchored_edit.py — outside this node's write scope. The search route the instruction names is what makes the tools reachable in the meantime, and the closing live run is the coordinator's.
