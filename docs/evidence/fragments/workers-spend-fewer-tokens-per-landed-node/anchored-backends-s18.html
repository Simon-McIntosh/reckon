No launch resolves the retired edit-tool flag any more

Launch composition in reckon/_backends.py no longer reads the per-backend flag that used to request the line-anchored MCP server. A codex launch therefore declares no such server on its -c argv, a Claude-shaped launch no longer passes --disallowedTools Edit MultiEdit, and LaunchPlan carries no anchored treatment fields, so nothing records a decision the launch no longer makes. The composition also stops calling the prompt composer for the tool's instruction: the dispatch layer still composes and strips that block from the backend declaration, and with no launch seeding the server it has nothing to add. The codex observation keeps counting the harness's own file_change items and drops its per-tool breakdown for a server no launch declares.

In reckon/capabilities.py the reader that treated a completed MCP edit call as the worker's first write target is gone with it, since every write a worker makes now arrives as the harness reports it and no MCP write tool is offered.

Measure. Substituted suite, both arms on all_debug, one arm at a time: PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_picker_local_backend.py tests/test_queue_edit_keeps_the_named_backend.py tests/test_worker_mcp_allowlist.py tests/test_staged_write_inventory.py tests/test_every_shared_home_lock_holds_across_nodes.py read 103 passed at base 1666d19f77 and 103 passed at head 78fa4487cc, zero added failures. The scoped gate over the same files at head read the same 103 passed, EXIT=0.

The key is gone from the changed paths. grep -rn 'anchored_edit\|anchored-edit' over the five changed paths returns no line at head (grep-exit=1), while the same pattern at base matches 46 times: 38 in _backends.py, 4 in capabilities.py, and one or two in each of the three test files. The absence is therefore an observed zero rather than a pattern that never means anything.

Falsified. The mutation restores reckon/_backends.py at the base revision and runs a launch whose backend still declares the retired key. Both parametrised cases fail (claude and codex, 2 failed, EXIT=1): the codex argv carries an mcp_servers.anchored override and the Claude argv carries --disallowedTools. The same check passes twice against this node's head, so it is sensitive to the removal and not to the fixture.

Outside this node. reckon/crew/dispatch_launch.py still reads the launch-plan treatment fields this change removes, so that module's launch-record write breaks until the node that owns its record field lands. That removal is a separate part of the same plan section, and the merged result is verified by a separately dispatched test node.
