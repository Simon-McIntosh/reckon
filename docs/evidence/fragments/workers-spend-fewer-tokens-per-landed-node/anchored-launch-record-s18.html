The launch record carries no anchored edit field

reckon/crew/dispatch_launch.py no longer writes an anchored_edit or anchored_edit_reason field at any of its three record sites: the supervisor spec, the worker record, and the live pointer's phase rewrite. A grep for anchored_edit and anchored-edit over the changed path finds nothing.

What read the field. One test file did: tests/test_anchored_edit_claude_arm.py. Its receipt helper asserted anchored_edit and anchored_edit_reason on the supervisor spec (lines 145–146), on the worker record (150–151) and on the pointer (440–441), so removing the fields broke it: 13 failed, 28 passed in 4.29s against 41 passed at base. The repair turned those into absence assertions on the same three records. The sibling node anchored-fence-prompt-s18 then removed the anchored edit prompt and the fence seeding, and deleted that test file on main, so the merged tree carries neither the file nor its assertions: the guard's subject left with the tool, and the field's absence is asserted by no test. That is why the fragment names the reader instead of claiming none existed.
