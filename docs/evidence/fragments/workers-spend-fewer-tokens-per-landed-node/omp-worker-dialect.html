A recorded stream, not a guessed one: the oh-my-pi dialect

What changed. reckon/_backends.py registers a third worker dialect beside codex and claude. It composes the headless invocation the contract note measured — omp -p --mode=json, the brief on argv and no text on stdin, an --config overlay that disables the task runner, the browser, desktop control, web_search, fetch and project MCP, and a --tools allowlist carrying only read, bash, edit, write, grep, glob and todo. Its observe() folds the harness's own event vocabulary, and reckon/_worker_fence.py gains the entry that relocates the run home through HOME.

Why each of those is load-bearing, and would pass silently if written the obvious way. Three findings from the contract note are traps rather than conveniences:

  • The harness reports an all-zero usage record on the first assistant message of every turn and the real totals on the last, so a reader that takes the first reports a run that spent nothing. The parser keeps a recorded total and refuses to let a zero placeholder replace it, whichever order the turn's records arrive in.
  • The harness writes plain prose onto the same stream as its JSON records — the fixture carries a real MCP connection warning — so a reader that raises on a non-JSON line dies on a healthy run.
  • The harness reads piped stdin as the prompt and blocks until EOF, so a launch that feeds the brief on stdin stalls in the harness's own read phase and presents as a worker that started and produced nothing. The dialect declares stdin_prompt = False and puts the brief last on argv.

The run home. oh-my-pi resolves its root as path.join(os.homedir(), ".omp") and hangs its log directory from that root, so redirecting the agent-store variable alone leaves every run appending a log file into the operator's ~/.omp/logs. The entry names HOME because that is the only variable that moves the whole tree; the test asserts both the declared triple and that a real launch plan carries HOME pointing into the run's own home.

Refusing a stream in another dialect's vocabulary. A fold written for omp finds none of its own events in a codex stream, and the obvious result is not an error but a terminal-shaped observation reporting a healthy run that spent no tokens and called no tools — the same silent under-count this dialect exists to remove, arriving through the front door. The parser therefore refuses a stream carrying a known foreign event and none of its own, naming the dialect it recognised.

Measured

The parser's expected figures are the recorded run's: 32,722 input and 18 output tokens, one tool call, session 01a1c6d3-39cd-7000-b58d-4ed2ecd74b85, and a final message that is the file it read. The fixture is the contract note's four verbatim records with the surrounding event kinds it names; only the last record's truncated millisecond tail is completed.

The armed command cannot be run, and that is a defect in the scoped-suite rule rather than in this node. The node's scope holds a test fixture under tests/fixtures/omp-stream.jsonl. is_test_path classifies every path under a tests directory as a test file, so _node_test_files hands the fixture to pytest, which exits 4 on any argument it cannot collect. Promotion then reads that exit as collected_no_test and refuses the arm; a command naming only the two collectible files is refused instead as command_matches_suite_command. Every arm is therefore refused, whichever way it is run, for a node that ships a data fixture under tests/. The two-sided log is kept so the refusal is a measurement rather than an assertion, and the repair — restrict _node_test_files to collectible paths, or exempt a declared fixture — belongs to a reckon node, not to this one.

Left open

reckon/shadow_reads.py::stream_tool_calls recognises only the codex and claude message shapes, so an omp stream reads there as zero tool calls and every second of tool wait is charged to the model. The dialect's own observation counts tool_execution_start, which is where the landed measurement comes from; the shadow read is a separate surface and is not touched here. The host flight entry omp-local must also declare harness_home_files: [{"path": "agent/models.yml"}], or a fenced run home has no model catalogue — that entry is the coordinator's.
