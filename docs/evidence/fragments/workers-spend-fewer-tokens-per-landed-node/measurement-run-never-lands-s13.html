A measurement run builds and gates and then lands not

Landing

crew dispatch --measure-only REASON dispatches a node as a measurement run. It builds and gates exactly as an implementation run does, and then nothing else takes it: the review reflex composes no review, the landing pass skips it before reading its evidence, crew complete writes a row whose outcome is measured beside the gate verdict, the token counts and the commits it reached, and the worktree is released even though its head is deliberately unmerged. The marker is written on the run's own pointer, which is the record the reflex and the lander both read, so one write decides all three; the dispatch answer carries the same field so a caller does not pay a second read to see the run it asked for.

A section declared done is dispatchable only with the flag, and the refusal names it: section §13 of plan … is declared done, so its work is already on the branch; it is dispatchable only as a measurement run … pass --measure-only REASON. The declaration is read from the plan through the ledger's own section normal form, so s13, §13 and section 13 are one identity. The refusal is raised before any claim, run directory or worktree exists, so a refused dispatch leaves nothing behind and the next call is the same call with the flag on it.

The requirement is on roles whose work lands. review, verify and investigate dispatch a landed section without the flag, because they read work rather than add it, and a done section is exactly what they are given. This was not the first shape of the check: refusing every role made the review reflex's own dispatch of a landed section impossible, which the comparison control found, and refusing a review is the one refusal a landed section cannot afford.

The ordinary release withholds a worktree whose HEAD is not an ancestor of the integration branch, because that head is the only copy of work nobody has merged. A measurement run's head is never merged, so the same policy would hold every replay's tree back and a measurement population — every arm building the same landed sections — would fill the disk it is measured on. The tree is therefore removed before the ordinary release runs, so the release reports it already absent and its audit describes the trees the release left behind rather than contradicting the removal. The commit stays in the repository's object store and the row names it, and a tree any other live pointer names is left alone.

Measure

tests/test_a_measurement_run_never_lands.py: 9 passed, EXIT=0 as the after arm's own file. The nine cases are the marker the dispatch writes; the reflex refusing and composing nothing; the landing pass skipping the run and recording no judgement against it; crew complete writing outcome: measured with gate: passed, the run's commit and its 1200/40 tokens, the run's commit still not an ancestor of main and its file absent from it, and the worktree gone; the refusal of a landed section without the flag naming it; an open section dispatching without the flag; the dry run reaching the same refusal; and two comparison controls.

Every case synthesises its own repository, plan, ledger and workspace under a temporary config home. The launcher stands in for the worker: the case writes the manifest, the run's commit and the token counts a harness fold would have put on the run, so the complete case measures the promotion rather than a stand-in for it. Nothing reads or writes outside the temporary tree.

Negative controls

Two declared mutations were applied over the head revision: recovery_review_dispatch._is_measurement_run returning False for every record, and _land_deliveries ignoring _measurement_run_skip. The reflex case then fails because its refusal no longer names the measurement — the reason it reports is the run's liveness — and both lander cases fail on the skip entry that is no longer there. Log: 3 failed, 1 passed, 5 deselected, EXIT=1 (negative_control.log). Both modules were restored to their committed contents before the arms ran.

The two comparison controls do not mutate product code: they dispatch the same delivery twice, once marked and once unmarked, and assert that the landing pass reaches the unmarked one — an admission_landing judgement — while the marked one leaves the pass with the measurement status and no judgement against it; and that the reflex composes a review for the unmarked run with its measurement refusal lifted by monkeypatch. Both would pass on a fixture that is simply unlandable, which is why they assert the positive half too.
