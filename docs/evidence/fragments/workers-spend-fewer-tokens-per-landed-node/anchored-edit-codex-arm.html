A codex worker can be offered the anchored tool, and the stream says what it used

The per-backend anchored_edit key now reaches the codex dialect. When it is true the composed argv carries three -c overrides under mcp_servers.anchored: command is the launching interpreter, args is -m reckon.anchored_edit followed by one --root per root the worker may write, and default_tools_approval_mode is "approve". The approval mode is not a convenience: a headless codex refuses every MCP tool call under any other setting, so without it the arm reads as a worker that declined the tool.

The overrides are arguments to one process. They need no harness home, no settings seed and no resume exclusion, and they write no file: the fenced codex home's config.toml is still the operator's own file copied verbatim, which the arm's test asserts byte for byte. That is also why the recorded launch fact for codex is simply the key — the key and the launch cannot disagree, and a resumed codex run keeps the server because the flags travel with it. Codex cannot be told to stop using its own apply_patch, so the arm offers the tool; the prompt is the second half of the treatment, and it names read_anchored and edit_anchored only for a codex launch whose key is true.

The run record's codex fold learned to count what the worker called. Calls to the anchored server are counted apart from the harness's own file_change items, once per call — codex emits a started and a completed record for the same call, and counting both would double every one. Both totals are carried onto the run pointer, which is the record a later comparison reads, so the share of edits an arm routed through the tool survives the run that produced it.

The numbers reach further than the count. An edit_anchored call that completed is read as a write by the input-to-first-write measure, the same way a harness file_change item is, so an anchored arm is timed on the edit that actually landed. A call the tool refused is not a write: the tool answers a stale anchor with a refused result rather than an error, so the call completes with the file untouched.

Commands are literal; each log's last line is its own exit status.

The fixture carries no file_change item, so a zero there would prove nothing on its own. A synthetic stream holding one anchored call, one file_change item and one call to another server is folded beside it: the anchored counter moves by one, the file-change counter by one, and the foreign server is counted as neither. The start/completed pair is exercised separately, where one call must stay one.

Codex's stream names the server, so the capture is taken from the call itself rather than inferred from the tool name. The prompt line is composed in reckon/crew/prompts.py and applied where dispatch finalises the worker's prompt; the plan's intended seam, the composing call in reckon/crew/dispatch_claims.py, is outside this node's write scope and the equivalent hook in dispatch.py keeps the instruction keyed on the same resolved backend.
