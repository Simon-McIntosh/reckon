Arm membership

A Claude-dialect run belongs to an anchored arm only when its session-start record lists reckon-anchored-edit as connected. The clive-anchored run's first launch recorded anchored_edit: true and its resumed launch recorded false (reason disabled), yet the resumed session's own start record still lists the server connected with both tools, because the run home kept the server the first launch seeded. The session-start record is the fact read, which is why this run counts in the anchored arm. A codex run belongs to the anchored arm when a launch record carries anchored_edit: true: the codex-anchored run's first launch did, its later launches did not, and its stream carries 6 read_anchored and 0 edit_anchored calls, the reads all in the first launch.

The query that produced this record

The record is generated, not transcribed: scripts/interim_arm_report.py reads the wave file, each run's stream files (stream.jsonl and resume-*.jsonl under the run's own directory), each run's attempt-*-worker.json launch records, the plan sections' effort hours, and git -C reckon log main --grep "land(<run_id>)" for landing. Its run-store cross-check reads SELECT detail FROM run_details WHERE run_id = ?: the store's budget.tokens.input_tokens_cumulative is written at a launch boundary and covers one launch rather than the whole run, so the per-run totals are summed from the streams, while the store's figure is used to check the reading against the harness's own count. Definitions: cumulative input is the whole prompt of every request, cached segments included (Claude Code assistant records deduplicated by message id, which reproduces each launch's result usage exactly; omp's per-turn message_end usage; codex's turn.completed usage); edit calls are Edit, MultiEdit, edit_anchored, omp's edit tool and codex file_change items, with a refusal read from the tool result's error flag or, for codex, from the model's message text; peak context is the widest single prompt, which codex's stream does not carry. Landing is a land(<run_id>) commit on main; every one of the five runs has one.
