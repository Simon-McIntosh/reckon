A dispose hint prints only the rubric the dispose verb accepts

An obligation's dispose hint is composed from the stored review record, and the record names its own family. A code review's record states the health rubric, so the hint composed for its blocking finding printed --rubric health; a reader pasting it met unknown review rubric 'health'; the one rubric a disposition may name is 'figure', and omitting --rubric answers the run's text review. The dispose verb selects a figure record by --rubric figure and answers the run's text review when no rubric is named, so the hint named a family the verb refuses and sent its reader to edit the store by hand or to abandon the disposition.

What changed. One normaliser, _cli_review_rubric in reckon/crew/obligations.py, renders the flag only for the family the verb accepts. A figure review keeps --rubric figure, because the verb needs it to select that record beside the text one; every other stored family — the health rubric a code review carries, and the older run, code and node spellings — renders by omitting the flag, which is exactly the selection the verb applies to the run's text review. Both composition sites already route through this normaliser: the sub-floor dimension duty and the blocking-finding duty, the latter through _finding_disposition_commands, so the two spaces cannot print one command two ways.

What does not change. A figure review's finding still prints --rubric figure with its --review identity. A text-review disposition remains the unrubriced default, so the command a coordinator runs selects the same record it selected before. Nothing about the disposition writer, the store or the promote path moves.
