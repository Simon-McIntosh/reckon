A hand merge can be recorded with the gate that passed

A run whose recorded suite arm aborted before pytest printed a summary carries no failure count to compare, so its arms cannot licence a promotion. When the lead has already merged that run's reviewed head by hand, the gate that actually passed is the coordinator's merged-head run, kept in its own log. crew merge has always taken that gate as --gate-command, --gate-log-path and --gate-exit-status; crew record-merge took none of them, so the only evidence the recording could cite was the aborted arm.

What changed. crew record-merge accepts the gate options crew merge accepts, plus --waive-suite-delta. A cited gate must be complete and must have exited zero; the row carries its command, exit status and log path, and the run's recorded arms are not read in that gate's place. A recording that cites no gate falls back to the arms the run recorded, so an armed run whose arm aborted is refused exactly as any other promotion refuses an uncounted arm, with the test rows, the measured receipt and the formatter unchanged. A gate declared with crew declare-gate carries no log or exit status, so it is never read as a citation.

Test coverage. tests/test_a_hand_merge_records_the_gate_that_passed.py covers the three cases the node names: an armed run whose base and after arms both aborted at exit 134 is recorded when given a passing gate, and its row carries that gate's command, exit status and log path; a gate whose exit status is 1 is refused with nothing written and the pointer left live; and a run given no gate is refused on its uncounted arm, naming --waive-suite-delta as the remedy. The verb's help lists all four options.

Negative control. The node's test file was run against a tree built from the base revision d7f54a14d1dcf7ae8054acd61fbf1a2e20d0425e: 2 failed, 1 passed in 1.61s, EXIT=1. The passing case is the refusal of a nonzero gate, which the base reaches only because --gate-exit-status is an unknown option. One measurement here contradicts the plan's own account of the defect. The plan says the base refused such a recording "on the aborted arm"; measured, the base accepted it and exited 0, recording the merge with a suite delta of status not-run. The reason is in reckon/crew/promotion_records.py: a record naming recorded_merge returned not-run before its arms were read at all, so an aborted arm could not refuse it. The first case still fails at the base, as the plan requires, but on the absent option rather than on the arm-abort refusal. The arm-abort refusal is what this node makes reachable for a gate-less recording, and it is asserted directly by the third case.

The plan's gate logs are arms/base-gate.log and arms/head-gate.log in the node's run directory; each carries its revision, its literal command and a closing EXIT= line.

What does not change. A hand-merged run armed with no suite command still records as not-run, as tests/test_a_hand_merged_run_is_in_the_rollup.py asserts. The suite-delta waiver reaches the arm evidence unchanged, and the record that a cited gate is written onto is the same row the ledger builds for every promotion.
