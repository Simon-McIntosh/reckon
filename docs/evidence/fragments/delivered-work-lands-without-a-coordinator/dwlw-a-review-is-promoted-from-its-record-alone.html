A review whose manifest cannot be read is promoted from its record

A review run's whole deliverable is the record it files for the run it read. Both readers on the promotion path asked the manifest first: the unattended sweep held a review in the waiting state while its manifest did not read complete, and the promotion command refused one whose manifest held a byte that does not parse. Either way a finished review sat unlanded behind a file that says nothing about it.

The reproduction is a review run with a complete, parsed record, an exited worker, and a one-byte manifest. On the base revision the promotion command refuses it with cannot be promoted: cannot read manifest: the body is present but no 'key: value' field could be read, and the sweep leaves the run waiting.

What changed

  • A manifest that is present and cannot be parsed no longer withholds a review whose record delivers: the sweep treats such a run as ready, and the promotion command judges its record instead of refusing the file.
  • The ledger row carries manifest_unreadable — the manifest path and the reader's own refusal — so the promotion states what it could not read rather than leaving it to be discovered.
  • The tolerance is reached only where a reader actually refused the file. An unreadable manifest with no delivered record, an unreadable manifest on an implement run, and an absent manifest all behave as before, and each of those three is pinned by a case.

Evidence

Six cases pass at the head: the promotion route and the sweep route both promote a complete record behind a one-byte manifest and record the unreadable manifest on the row; a review with no record stays refused with record cannot be read and keeps its pointer; an implement run stays refused naming the manifest; and the sweep leaves a record-less review as it found it.

Negative control: on the pinned base revision the first case fails with the cannot-read-manifest refusal, and the sweep route fails because the run is never promoted. Both figures are in the run's gate logs.
