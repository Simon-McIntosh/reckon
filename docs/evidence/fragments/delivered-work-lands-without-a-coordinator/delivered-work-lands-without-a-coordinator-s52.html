A merged run is recorded from its run directory when its pointer is gone

A coordinator can merge a run's reviewed head by hand: the merge measures the change, stores the review and releases the worktree. The run's live pointer may then be removed before any promotion or discard records it, and the run directory is all that survives — its dispatch prompt, supervisor record and durable manifest.

crew record-merge already knew how to record a hand merge without measuring the suite again, but it read the live pointer first and refused a pointerless run with no live run. The landed work was left with no ledger row, no released waiters, and a run directory nobody could promote from.

Reproduction: a run whose worktree has been released, whose pointer has been removed, and whose head the primary branch carries through a merge. On the base revision the command refuses it with Error: no live run 'r-…-a-merged-run' (looked in …/crew/live/…), and the ledger holds no row for it.

What changed

  • The command reads the run through the pointer-or-rebuild reader the promotion path already used: a surviving pointer is read as before, and an absent one is rebuilt from the run directory.
  • The rebuild recovers the plan section the run delivered from the surviving dispatch prompt's PLAN line, so the landing writes the section's comment and releases the waiters queued behind it. A brief-only dispatch carries no plan pointer and yields no section rather than a guessed one.
  • The verified hand merge is passed into the promotion as the run's recorded merge, so no suite pair is measured over a change the primary branch already carries. A run whose pointer is live is still mutated as before, and a live pointer is never created for a pointerless run.
  • A run the ledger already holds is refused naming the project ledger; the row the ledger holds already names what the landing recorded.

Evidence

Three cases pass at the head. A pointerless run with a released worktree is recorded with a row naming the merge, no suite delta, and the section's waiters released — the release names the plan section recovered from the fixture's prompt, not a section passed in by the caller. A merge that does not carry the recorded head is refused naming both commits and writes no row. A run the ledger already holds is refused and keeps one row.

Negative control: on the base revision the first case fails with no live run, and the other two fail behind the same refusal. Base and head gate logs sit under the run directory; each opens with its revision, tree, resolved working directory, the module under test as imported, and the literal command, and closes with a bare EXIT= line.

Results as recorded: at the base revision, the three cases in the gate fail (exit 1); at the head revision, three pass in 3.38 s (exit 0). The importer arm — the hand-merge, discarded-run, plan-review, withdrawn-run, reclaimed-head and blank-worktree suites — adds no failure: 22 passed (exit 0) at both the base and the head revision.
