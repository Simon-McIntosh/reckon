A plan holding a request on its review is never recorded as settled

At the pinned base d7f54a14d1dcf7ae8054acd61fbf1a2e20d0425e, the owed-plan-review reflex skips any plan whose edit stamp it already recorded (no plan was edited inside the authoring burst). An admission pass holds a request on plan-review-owed when a plan unit the request reads carries no stored review, and nothing composes that review unless the reflex weighs the plan again. So a plan weighed once while a unit was uncovered kept its request held across every later pass, even though nothing had ever answered it. The node's first case reproduces this exactly at the base revision: the pass reports composed: [] and skipped: [{'reason': 'no plan was edited inside the authoring burst'}].

What changed. The pass now reads the live pointers once and identifies the plans holding a request on its review — phase held, an automatic hold whose reason is plan-review-owed. Such a plan is taken out of the already-weighed set before the pass judges anything, and it is never accepted into the settled set after composing: a held plan is written back as unsettled, so the next pass weighs it again rather than answering its unchanged stamp. Each pass therefore does one of two things for it: it composes the owed review when a unit is uncovered and under its review cap, or it records why it did not.

The recorded reason. When the pass cannot compose, it writes an obligation under the reflex state's __obligations__ map, keyed by plan, naming the plan, its version and the reason — a unit at its review cap with the refusal text, or the ids of the unanswered findings against the plan's contributing reviews — and the session that owns the held request. The map is rewritten whole on every pass, so a reason drops out the moment the plan stops holding a request. The obligations view reads it beside the plan-review-owed row, so the owning session is told why the review is still owed rather than only that it is.

What does not change. A plan holding no such request keeps today's fast skip: the fourth case runs the pass over a plan already weighed at its unchanged edit, and asserts the pass reads nothing, composes nothing and leaves the plan recorded as weighed. A second pass over the same held plan composes no second review for a version a stored review already covers.
