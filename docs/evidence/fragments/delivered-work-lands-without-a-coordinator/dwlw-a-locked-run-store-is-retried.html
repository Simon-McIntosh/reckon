A locked run store left a promotion permanently failed

A promotion records its row in the run store, and the store retries a held write lock with a bounded backoff. A lock outlasting that bound is a refusal rather than a landed run: the ledger raises it naming the store, the request records promotion-failed, and the deliverable is otherwise unchanged. Nothing promoted it again. The run stayed a coordinator obligation although the only thing that had gone wrong was a busy store.

The reproduction is a promotion whose store write raises the store's own lock error on the refusal's cause chain. On the base revision the service's next pass launches nothing, the request is still promotion-failed, and its obligation asks a coordinator to promote the run again.

What changed

  • A refusal whose cause chain carries the run store's lock now records that the service owes the retry, beside the ledger's own account of the refusal.
  • The service's next pass re-queues such a request with the kind and options it carried, so the promotion runs again and lands once the lock is free.
  • The obligation names the locked store and says the service retries the promotion, so no coordinator action is owed.
  • The debt is read from the lock itself. A gate refusal, and any other failure, is not marked and is never retried; the existing rule for a refusal judged by superseded code is unchanged.

Evidence

Three cases pass at the head: a locked-store refusal is re-queued on the next pass and reaches promoted when the lock clears; while it waits its obligation names the locked store and the service's retry; and a gate refusal is not retried.

Negative control: on the pinned base revision the first case fails with the service left the request at promotion-failed after its pass, and the obligation case fails because its reason carries the ledger refusal instead of the service's retry. The run records 2 failed, 1 passed in 0.51s and closes with EXIT=1; both figures are in the run's negative-control.log, which records the base revision, its tree and its literal command.
