§30 — A run that adds a test file can still have its control mutation measured

The control mutation is a node's own tests run over the tree its repair is absent from. Where the measurement goes to a partition, that tree is built from a revision inside the submitted job, so a test file the node adds — absent from the run's base revision — has to be carried in from a revision that holds it. The partitioned builder carried from the revision it was asked to build, and the control measure asked it for the base revision (its own arm's revision), so an added test file produced fatal: pathspec 'tests/test_iron_field_source.py' did not match any files, then tar: This does not look like a tar archive, and EXIT=2 — read as "the control mutation did not run".

Reproduced before the change against a temporary repository whose head adds tests/test_added.py and whose base does not hold it: the submitted script's log held exactly those three lines and control_mutation_observation returned {'unreadable': 'the control mutation did not run'}.

The control now carries the node's test files from the head the delivered tree is at — the revision that holds them — while still building the tree at the run's base revision. The carry step is named: a path the revision does not hold stops the arm with cannot build the measurement tree: <path> is not present at revision <rev> rather than two runner fragments, and that sentence is the arm's unreadable reason, so the refusal names the path and the revision it asked.

The delivered head is read through the repository's shared commit resolver rather than by a second rev-parse of its own, so a bound or a revision validation fixed in that resolver reaches this reader too. The case that holds it replaces the resolver and asserts the delivered head came from it, which a private rev-parse call cannot satisfy.

Measure: the focused gate at 8f68df5e4e runs the new test file together with the neighbouring partition and control tests — tests/test_a_gate_creates_its_log.py, tests/test_negative_control_log_is_a_path.py, tests/test_a_landing_measures_a_mismatched_arm.py, tests/test_a_measured_arm_reads_its_receipt_past_scheduler_lines.py — and reports 43 passed in 8.23s. The four cases in that file are: the added test file carried from the head reads red over the base as declared (tests/test_added.py::test_mutated, a FAILED id and EXIT=1); a run editing only an existing test is measured from the base revision's own copy; a path neither revision holds is refused naming the path and the revision; and the delivered head is answered by the shared commit resolver while the arm's own log header records the revision it ran at. The baseline arm at b5444d24baca reports 58 passed in 36.68s and the after arm at 8fa3985e4e reports 62 passed in 38.45s, each arm resolving its declared suite over its own tree.

Negative control: on the base revision the first case fails with {'unreadable': 'the control mutation did not run'}, red with a FAILED id and EXIT=1. Reverting the delegation so the delivered head is read by a private rev-parse makes the resolver case fail on its own assertion, with EXIT=1 and FAILED naming that case. Each arm's log sits under the run directory and carries its revision, its literal command and a closing EXIT= line.
