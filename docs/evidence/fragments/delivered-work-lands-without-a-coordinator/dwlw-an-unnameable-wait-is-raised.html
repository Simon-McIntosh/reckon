A run that ends on a wait nothing can probe reaches its coordinator

What changed. A worker can write a wait block and end while its status still reads a working word, with the probe written as prose naming scheduler jobs rather than as the shell-free argument vector the reader accepts. The waiting reader acts only on a manifest whose status is waiting, and the reader that runs a probe refuses that shape, so nothing swept, resumed or promoted the run. Read as still working it reached no duty at all: classification: running, recovery verb observe, and no next action, so the coordinator found the run only by opening its manifest.

The classifier now reads that state as unreadable — the declaration is what is wrong, and the remedy is a repair only its coordinator can make. The row carries the manifest status word and the declared probe text together, because a repair edits exactly those two lines; the existing unreadable duty already reaches the repair verb, so the run appears as one obligation of its session whose reason is that account. A manifest refused for a status word outside the vocabulary names a declared wait beside that word too, since the refusal is the last place both are still in hand.

What did not change. A run whose status is waiting and whose probe can be run is still lifted by the sweep when the probe reports a terminal state, and a manifest carrying complete still keeps its terminal word: the new reading fires only for a dead worker whose declared wait cannot be probed.

Measured

The gate is tests/test_an_unnameable_wait_is_raised.py, four cases: the prose-probe run; a liftable file-condition wait that the sweep still resumes; a complete run that keeps its word; and an out-of-vocabulary status word whose refusal now names the declared wait. Against the pinned base the first case fails, because the base reads the run as running with no next action — the run that reaches nobody.

The remedy the row names

The row's account reads, for the reported manifest: the worker ended with manifest status 'in-progress' and a wait nothing can probe: wait_probe is a single value the reader cannot parse as a JSON array … (declared 'sbatch jobs 1335599 and 1335600 finish and their logs land'); the run was left waiting on the manifest at … and no sweep or resume lifts it. The next action tells the coordinator to replace the status with the verdict the worker reached and to re-declare the wait as an argument vector if it is still awaited.
