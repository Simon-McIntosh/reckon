Dispatch asks the session host before it refuses

A dispatch from a Claude Code session that is not attached now writes one JSON request line to the session host's node-local FIFO and waits, for at most WATCHER_LOAD_BOUND_SECONDS, for the host to attach the session. The payload's delivery field reads host when the host took it and monitor otherwise; a host-delivered session carries no arming line. Without a host — no FIFO, or a FIFO with no reader — the refusal text is unchanged.

  • The host FIFO resolves to <runtime>/reckon-session-host/<CLAUDE_PID>-<start>.fifo, where <runtime> is $XDG_RUNTIME_DIR, else /run/user/<uid>, else $TMPDIR, and <start> is field 22 of /proc/<pid>/stat. The request uses _write_fleet_request with a deadline already in the past, so a FIFO with no reader falls back at once rather than waiting.
  • Gate: tests/test_dispatch_session_host.py, two cases:
    • test_dispatch_asks_the_session_host_and_is_admitted_by_it — a stub reader holding the FIFO confirms the JSON line names project and session, and the dispatch is admitted with delivery == "host" and an empty arming_line.
    • test_dispatch_without_a_host_reader_falls_back_to_the_monitor_refusal — the same dispatch with a FIFO that holds no reader is refused with text identical to a no-FIFO control, and the refusal carries delivery == "monitor".
  • Gate log gate-head.log: 2 passed, EXIT=0. Negative control gate-negative.log: skipping the host request makes test_dispatch_asks_the_session_host_and_is_admitted_by_it raise _FollowerAdmissionUnmet, EXIT=1.
