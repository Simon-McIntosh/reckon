The crew MCP tool carries the coordinator's write verbs

The crew MCP tool accepts eight more actions — complete, land, dispose, ack, answer, widen, stop and discard. reckon/mcp_crew_actions.py maps each action's tool parameters onto the same command function its crew CLI verb runs through, calls that function in-process and returns the one JSON document the verb emits, so the tool and the CLI cannot drift about what one call returns. The tool description names every action's parameters. A refused complete or land is re-read through the promotion's own dry run, so its answer carries every failing guard in guards alongside the invocation that would pass rather than one refusal at a time. The obligations view now renders each duty's printed command in the tool's action form as next_action_form, so a coordinator can call the action directly instead of composing a shell command from the printed tokens, while next_action keeps its existing meaning as a command string.

Measure: tests/test_crew_tool_carries_the_write_verbs.py — 12 passed. For each of the eight actions the MCP tool and the CLI run on one temporary configuration home and their answers are compared, with a CLI refusal normalised from its bare Error: line to the tool's ok/error/detail shape. The negative control remaps ack's until argument onto the verb's reason parameter and the run goes red on exactly that one action: EXIT=1, 1 failed (test_each_action_matches_its_cli_verb[ack]), 11 passed. The focused gate — the parity test plus the MCP, obligations, acknowledgement and worker-window suites — is 88 passed, 1 failed at the node head, EXIT=1, the one failure being test_every_module_fits_a_worker_window for reckon/crew/review.py and reckon/ledger.py, which is red identically at the base arm (74 passed, 1 failed, 1 error) and lies outside this node's fence. Ruff format and check findings on every changed path do not exceed the base.

Repair round, from an independent review of the first head. The action form had dropped every option it did not recognise and had appended a repeated option once per occurrence, so the commitless promotion a coordinator is offered arrived without its --no-commit waiver, and a command naming two commits arrived as two parameters called commits. A command is now rendered whole or not at all: every option the eight verbs accept is mapped, a repeated option renders as one list-valued parameter (commits=["1111111", "2222222"]), and an option the form cannot carry leaves the reader the printed command rather than a call that would answer differently. Four cases were added — the commitless promotion rendered from the classifier's own composition, two commits on one command, an unmapped option, a missing value, and a parity case driving two --commit flags through both surfaces. The action names are stated once, in reckon/mcp_crew_actions.py, and read from there by the tool's dispatch and by the obligations view; the MCP module no longer imports the obligations view for a test's benefit, and the test that read that import now reads the module the view is served from. The re-run gate at the repair head is 92 passed, 1 failed, EXIT=1 — the base-red worker-window failure and nothing else, against a base arm of 1 failed and 1 collection error — and the re-run negative control fails ack alone, 15 passed, EXIT=1.
