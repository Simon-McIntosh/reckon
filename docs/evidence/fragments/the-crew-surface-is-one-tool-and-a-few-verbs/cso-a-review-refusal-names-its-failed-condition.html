A review refusal names its failed condition

A review run's outcome is taken from the record it stored, and a promotion of a review whose record has not delivered was refused with one generic sentence whatever the cause. The commonest cause — a record that parses, scores every dimension, and carries no total — read as a corrupt file and sent a coordinator to inspect a good record. The refusal now names the one delivery condition that failed, with the record path it concerns and the remedy that condition calls for.

The gap: one message for five causes

_delivered_review_record in reckon/crew/recovery_review_delivery.py decides delivery from five conditions and returns None for all of them. _resolve_promotion_outcome in reckon/crew/promotion_checks.py saw only that None and refused with “a review run whose stored review cannot be read”. Measured 2026-10-19 in power_convertor: two review runs whose records parsed and whose finding text was readable were refused, because each scored all six dimensions and carried no total.

What changed

  • reckon/crew/recovery_review_delivery.py gains _review_delivery_verdict, the single evaluation of the five conditions. _delivered_review_record and the new review_delivery_refusal are its two projections, so the delivery rule keeps one owner and no reader restates the conditions. _read_review_record separates reading a record from judging it complete, so a refusal can tell a record that cannot be read from one that reads and is incomplete.
  • reckon/crew/recovery_review_subject.py: _review_is_complete becomes the negation of the new _review_missing_measures, which returns the measures a review lacks. The completeness rule keeps one owner, and a refusal names the missing measure rather than restating the rule.
  • reckon/crew/promotion_checks.py: _resolve_promotion_outcome reads review_delivery_refusal and raises a refusal naming the condition, the record path and the remedy.

Refusals read, for a record that parses: “run ‘r-…’ is a review run refused for delivery: record is not a complete review; stored a record at …/x.at-<head>.json that is not a complete review: it lacks total; pass --outcome with the verdict the review reached, or re-store the review with total”. The same sentence for a corrupt file says the record “cannot be read”; for a record that parses it never does.

The gate

tests/test_a_review_refusal_names_its_failed_condition.py builds one review run for each of the five conditions on a temporary project. The incomplete case is the shape the cited runs had: six scored dimensions and no total. Each is refused by crew complete --gate not-run with no --outcome, and the refusal names that condition. A delivered record still promotes with its outcome taken from the stored review.
