The ledger and velocity read verbs retire behind crew view

Change. crew ledger and crew velocity are gone. reckon/crew_run_commands.py loses both command definitions and binds the two module-level names the CLI shim re-exports to tombstone_command("ledger") and tombstone_command("velocity"), so each retired name answers with the JSON document that names its successor and exits 10. reckon/crew/tombstones.py gains the two rows — ledger → crew view ledger and velocity → crew view velocity — and a positional field, because crew view names its case as a positional operand (reckon crew view ledger …) rather than a flag, so argv alone cannot carry it: argv stays the token path into the live command tree, which is what the successor-resolution check walks. The row also names the flag the retired verb selected its case with (operand_flag="--view"), so a caller's --view records renders as the successor's operand and the flag is consumed rather than forwarded: forwarded verbatim it printed reckon crew view ledger --view records, which exits 2 with No such option '--view', and an arrow a caller cannot follow is not a successor. One case name did not carry the retired verb's own case across unchanged: crew ledger defaulted to --view summary, the ledger rollup, while crew view summary is the fleet summary — a different document — so the row also carries operand_aliases=(("summary", "ledger"),) and renders that case as crew view ledger. The retired rollup therefore reaches one successor however the caller spelled it, and successor_name() reports the view a case-mapped call actually reaches, so the document does not name one view and print an invocation that reads another. Each side is composed by a different builder, so only the fields both documents share are compared, and that field set is written down in SHARED_FIELDS rather than derived: a successor that later drops one of them fails the file. The sets are, in order, (path, project, version) for the ledger rollup, (project, runs) for records, (artefacts, path, paths, project, records, rows) for findings, and the full velocity payload key set. The ledger entry is narrow because the retired --view summary rollup and the ledger view are not one document: both name a runs field and one counts them where the other lists them, so what they genuinely share is the ledger they read. Two further cases assert each retired name exits 10 and its document names the view in SUCCESSORS — literals written in the test, not read from the registry, so a row repointed at another view fails rather than agreeing with itself — and that no string under reckon/ still names either as a reckon crew command. The scan is shown to be meaningful by a fourth case asserting both names really are registered tombstones. A fifth case follows the arrow literally for four calls onto the retired ledger — bare, --view summary, --view records and --view findings — asserting the invocation the tombstone prints is the one the successor accepts and then running that invocation, so a case answered with a usage error fails rather than being read past; each call also holds the printed invocation against the successor the payload reports, so one caller is not told two different things.
