Test. tests/test_read_verbs_retire_behind_crew_view.py holds both ends of the arrow. A module-scoped synthesised checkout (a committed ledger, a committed review, dated commits in a velocity window) feeds four cases, one per retired read: the document the retired verb composed — through the module function it called (ledger.summary, ledger.read_records, findings.findings_by_path, velocity.view) — is compared against the same document driven through crew view. Each side is composed by a different builder, so only the fields both documents share are compared, and that field set is written down in SHARED_FIELDS rather than derived: a successor that later drops one of them fails the file. The sets are, in order, (path, project, version) for the ledger rollup, (project, runs) for records, (artefacts, path, paths, project, records, rows) for findings, and the full velocity payload key set. The ledger entry is narrow because the retired --view summary rollup and the ledger view are not one document: both name a runs field and one counts them where the other lists them, so what they genuinely share is the ledger they read. Two further cases assert each retired name exits 10 and its document names the view in SUCCESSORS — literals written in the test, not read from the registry, so a row repointed at another view fails rather than agreeing with itself — and that no string under reckon/ still names either as a reckon crew command. The scan is shown to be meaningful by a fourth case asserting both names really are registered tombstones.
