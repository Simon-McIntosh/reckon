Execution evidence · fragment

A reopened run reads as working, not blocked

crew resume --reopen --write-path P widened a completed run's claim and then healed its delivery by writing a status the reopen chose — blocked. The resumed worker ran its whole attempt under a word no attempt had reached: the run classified as blocked and the obligations read raised a blocked duty for a run that was working, which coordinators acknowledged by hand.

The defect, reproduced

Run r-20261021T023811534757-cold-test-discharge-replay delivered status: complete; its status-repair.json recorded previous_status: complete, status: blocked, reason: reopening the completed run at 04:39:51Z; its worker was alive and its manifest read blocked. Reproduced before repair against the base source with the head's tests: 4 failed, 57 passed, EXIT=1 — the reopened manifest asserts as blocked; and the run classifies blocked, so the obligations read carries a blocked duty for the live run.

What changed

  • reckon/crew_run_commands.py: the --reopen branch no longer calls repair_manifest_status(run_id, "blocked", ...). It widens the claim, then clears the delivered verdict through resumption._reset_delivered_manifest_status — the existing owner of “clear a delivered verdict before a new attempt” — so the manifest is non-terminal before the worker spawns and the delivered text is kept beside it under an attempt-named copy. No second owner is added.
  • The reopen's durable record is reopened.json in the run directory, written by the new _record_reopening: the fact, the reason, the paths granted and the delivered copy path. The record is not a status word, so a reader separates the reopen from the run's own course.
  • The run classifies from its non-terminal manifest as running, so the obligations read raises no blocked item while it works.

The gate

tests/test_a_reopened_run_reads_as_working.py reopens a completed run through the CLI, with the launch stubbed the way the fold test stubs it, and asserts the manifest is in-progress and not a terminal word, that the delivered text survives as an attempt-named copy, that classify_pointer reads running, and that the obligations read for the run's session carries no item for it. A live worker still refuses the reopen before anything is granted or cleared.
