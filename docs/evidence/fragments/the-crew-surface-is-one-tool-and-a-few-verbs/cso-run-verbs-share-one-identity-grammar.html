Execution evidence · fragment

Every run verb takes one identity grammar

The single-run crew verbs each spelled their identity differently: some took only --run, some required --project, dispose required a project the run already named, crew review answered with two run ids where only one had a live pointer to complete, and crew review --answer silently picked one of two covering reviews. Every one now accepts --project beside --run, refuses a project that disagrees with the run's own, answers with one run id to complete, and refuses an ambiguous answer naming both reviews.

The gap: one identity, spelled five ways

A census of the crew command tree at base found eighteen single-run verbs. Nine took no --project at all; among the rest, dispose and verify-gate and supersede-review required a project the run's own pointer already recorded, while directory, view, path, gc, resume and observe took it optionally. A caller looping over runs could not pass one project flag to all of them, and a mistaken project was answered about a different run rather than refused. crew review returned both run_id (the run being reviewed) and review_run_id (the review run it launched), only the second of which carries a live pointer to complete. crew review --answer fell back from the newest record to the newest design review and, when both raised the finding, landed on one of them silently.

What changed

  • reckon/crew_dispatch_commands.py gains _accept_a_matching_project, the one resolver: it reads the run's project from its live pointer, or from the promoted record when the pointer is gone, refuses a --project that disagrees naming both, and returns the run's project so a verb keyed by run can fall back to it. It also gains _one_run_to_complete, which presents a composed review answer as one run_id to complete with the reviewed run named reviewed_run_id for provenance; the stored records keep their own review_run_id field.
  • Every single-run verb in reckon/crew_run_commands.py and reckon/crew_dispatch_commands.py now declares --project and calls _accept_a_matching_project before its own logic. dispose no longer requires it. crew path accepts --project beside --run for the run-keyed kinds instead of refusing any project, and resolves one from the run for --kind reviews.
  • crew review --answer gathers every covering review that raises the finding. Without --review-run a finding carried by two is refused naming both; with --review-run the answer lands on the named review, and an unknown review is refused naming the ones that do. The covering reviews come from two readers — the newest stored review and the newest design review — which return one file as two mappings, so they are keyed by the review run the record names, or by the fields naming its content when it names none; a key of object identity would count one review twice and refuse a finding only it raises.

The gate

tests/test_run_verbs_share_one_identity_grammar.py enumerates the crew command tree rather than a fixed list, so a verb added later is covered, and names follow as its one exclusion (a repeatable delivery filter that already takes --project). It asserts every swept verb declares --project, then invokes every one with a matching project and a disagreeing one, asserting the first is not refused for the disagreement and the second is refused naming it. It drives the repeated-finding answer both ways on a temporary project: two covering reviews raise dup-1, the answer without --review-run is refused naming both r-design-0 and r-content-1, and with --review-run r-design-0 it lands on that review.

The negative control drops --project from one verb's options; the sweep then fails naming that verb, because test_every_single_run_verb_declares_a_project_option reads the tree the verb still sits in.
