Change. reckon/crew/promotion.py gains complete_dry_run and complete(..., dry_run=True). The dry run runs the same guard sweep a promotion runs — _require_independently already collects every independent refusal into one _PromotionRefusalError — and returns a JSON answer carrying would_promote, the full refusal list, and the one invocation that would pass for the run's state. It writes nothing: no ledger row, no plan comment, and no live-pointer mutation. In reckon/crew/promotion_records.py the suite-delta evaluator takes dry_run and its three pointer writes route through one _record_refusal helper that is a no-op under the dry run, so the sweep cannot leave a partial record behind on its way to refusing. The emitted invocation is synthesised from the refusals themselves: the run id, the gate verdict, the gate flags when a refusal says the receipt is the check that produced it, and any remedy flag a refusal names in its own text — each with a concrete reason quoted so the line runs as it stands. Emitted placeholders would be the same defect the fill repair addresses, so the emitted line is executed rather than inspected: shlex.split of the answer, invoked through the real CLI, promotes the run and removes its pointer. reckon/crew_run_commands.py adds _refuse_a_flag_as_a_reason as the callback of all eight reason-taking crew complete options (--no-commit, --no-impl-change, and the six --waive-* flags). In --no-commit --gate passed, click binds --gate as the reason and leaves the gate unstated, and the run is then refused for the wrong missing thing. A value beginning with two dashes is now refused as a missing reason, naming the swallowed flag and the form that works; the callback fires before the parser reaches what follows, which is why the refusal can name it. Nothing is written on any path. Three writes sit ahead of the dry-run branch, because a promotion takes them before it judges a guard: a run naming no project is withdrawn — its pointer unlinked and its workspace released — a run carrying a delivered review has it filed into the store, and a run whose deferred pick has not answered has the picker's timeout stamped onto its pointer after the pick's own bound elapses. Each is now branched before it writes and reported instead. A withdrawn run reports would_withdraw and offers no invocation, because its promotion writes no ledger row to point at; a delivered review names the record a filing would read, resolved through the filing's own directory resolution so the two cannot disagree; a pick still out answers to would_wait_for_pick, which the dry run against that run no longer pays. The wait and the report share one predicate, so neither can call a pick outstanding while the other does not. Because the review checks read their store before a filing would land, the report says so rather than leaving an operator to infer it from a refusal naming no review.

Measure. The plan asks how often the existing manifest gate-receipt fill applies, and why not, over the manifests of the runs promoted in the last seven days. fill-rate-measurement.py under this run's directory loads the six mounted project ledgers, keeps every row whose gate is passed and which completed or dispatched inside the window, and asks of each cited manifest whether the fill yields a usable receipt: a command a shell can re-run, a cited log that reads, and an exit status read from that log. Both arms call the module's own _default_gate_evidence_from_manifest, the second with the log-header recovery disabled, so the same instrument is measured in both. Over 845 such runs the fill produced a usable receipt 285 times (0.3373). The named causes: the command is not runnable 500 times, the cited log is unreadable 46, the log carries no exit status 12, and no log path was filled at all 2. The dominant cause is the tests: line itself — a description of the suite rather than the command a shell was handed. Repair, in three parts. The fill reads the cited gate log's own header for the command when the manifest's tests: line is absent or carries prose: the log is what the gate actually wrote, and it is already in hand because the fill resolves log_path first. The reader it uses is now the one the manifest evidence check already applies to a cited test log (reports._test_log_command). The fill previously carried its own copy, and the two disagreed about what a header line looks like — the copy matched only a line beginning # command: over ten raw lines, while the owner strips each line and accepts command or cmd followed by : or = across the first five non-blank ones. A log the owner read was a log the fill could not, and a run holding its command in plain sight was refused for a command that was not runnable. With the copy deleted, the rate rises to 444 of 845 (0.5254): command is not runnable falls from 500 to 341, with every other reason unchanged. The second half of the repair is at the source: the dispatch contract in reckon/crew/prompts.py now states the contracted form of tests: and test_logs: — a literal command rather than a description of one, and a log whose first line names the revision and command and whose last line is a bare EXIT=<code> — so the next wave writes a receipt the fill can use instead of one it must recover.
