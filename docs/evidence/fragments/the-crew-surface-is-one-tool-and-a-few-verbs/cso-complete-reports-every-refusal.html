Change. reckon/crew/promotion.py gains complete_dry_run and complete(..., dry_run=True). The dry run runs the same guard sweep a promotion runs — _require_independently already collects every independent refusal into one _PromotionRefusalError — and returns a JSON answer carrying would_promote, the full refusal list, and the one invocation that would pass for the run's state. It writes nothing: no ledger row, no plan comment, and no live-pointer mutation. The pointer survives the call, which the test asserts directly. In reckon/crew/promotion_records.py the suite-delta evaluator takes dry_run and its three pointer writes route through one _record_refusal helper that is a no-op under the dry run, so the sweep cannot leave a partial record behind on its way to refusing. The emitted invocation is synthesised from the refusals themselves: the run id, the gate verdict, the gate flags when a refusal says the receipt is the check that produced it, and any remedy flag a refusal names in its own text — each with a concrete reason quoted so the line runs as it stands. Emitting a placeholder reason would be the same defect the fill repair fixes, so the line is executed by the test rather than merely inspected: shlex.split of the answer, invoked through the real CLI, promotes the run and removes its pointer. reckon/crew_run_commands.py adds _refuse_a_flag_as_a_reason as the callback of all eight reason-taking crew complete options (--no-commit, --no-impl-change, and the six --waive-* flags). In --no-commit --gate passed, click binds --gate as the reason and leaves the gate unstated, and the run is then refused for the wrong missing thing. A value beginning with two dashes is now refused as a missing reason, naming the swallowed flag and the form that works; the callback fires before the parser reaches what follows, which is why the refusal can name it.
