A one-plan read reads its project's declaring record, not the project

What changed. reckon/project_state.py gains read_project_manifest(docs_dir, project): the project's declaring record alone — the project resource in a distributed store, and the legacy index in a legacy one, where the north stars sit beside the project rows rather than on the row. The mode branch now exists once, and read_project_derivations reads through it. In reckon/_store.py, _declared_north_stars takes the declared north-star ids from that record instead of from compose_project_state, so the north-star diagnostic a plan read feeds no longer composes the project. The diagnostic text is unchanged in both storage layouts.
