A persisted parse carries the version of the code that made it, and every read seeds from it

What changed. reckon/metadata_index.py gains one persisted-memo helper, persisted_memo, beside _persisted_cache_path. It keeps one value per identity in that cache file, beside the source digest of every module that produced it, and treats an entry whose digests differ as absent — so a value is only ever reused by the code that made it. The metadata index's own store, and the parse each unchanged file records through it, now go through that helper with _plan_html's and metadata_index's source digests: a parser change invalidates every stored parse instead of serving a value older code made. reckon/_store.py gains _seed_parsed_state, which seeds the shared parse from metadata_index.discovery_state through _plan_html.reuse_parsed_state before the state read behind read_plan and edit_plan parses anything, as the served discovery payload already did. It seeds from an existing store and never builds one (discovery_state(..., build=False)), so a single-document read does not pay for a whole-tree build, and a store that cannot answer leaves the read parsing as before.

Measured

Gate: tests/test_a_persisted_answer_carries_its_code_version.py over a synthetic 40-plan store mounted in a temporary configuration home, with _plan_html.read_state counted through a patch. Each probe below clears file_memo and the in-process caches first, so it runs as a fresh process would. Each arm is a log whose first line names its revision and its tree and whose last line reads EXIT=<code>.

caseheadbase revision
one-plan read in a fresh process 0 parses of unchanged plans 1 parse per read
one edited plan 1 parse, and the untouched plan read in the same process parses 0 parsed by every read
changed _plan_html source digest 40 parses on the rebuilding pass, 0 on the next no such helper: the case errors
corrupt stored entry the parsed value, no error same (already correct)

The instrument's positive control is inside each case: the pass that builds the store asserts its own parse count before the zero is asserted, and the corrupt-store case asserts that a fall-back parse happened, so an absence is never read off a counter that never fired.

Negative controls

  • Removing the seed from _store._read_state turns test_a_second_process_parses_no_unchanged_plan and test_one_edited_plan_is_parsed_once red (2 failed, exit 1) — the seeded read parses the whole file again.
  • Leaving the code digest out of the helper's key turns only test_a_changed_parser_source_digest_invalidates_every_stored_parse red (1 failed, exit 1): the stored parse is reused across a parser change, so the rebuilding pass parses 0 rather than 40.

What is not measured here. The per-call cost of seeding one plan read is a store load plus a stat per recorded entry, not the whole-tree parse it stood in for; the read's wall-clock at the merged head is measured by the plan's measurement section, not here.
