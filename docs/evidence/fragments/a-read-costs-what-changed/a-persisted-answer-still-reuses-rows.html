A persisted answer still reuses rows by stat identity

What changed. reckon/metadata_index.py now records each persisted memo's producer source identity beside its source digest, and reuses the recorded digest when that identity has not moved. Before this, revalidating a stored value hashed the source file of every module that produced it, so a reader that revalidated after a restart read and hashed _plan_html.py and metadata_index.py even when every stored row still applied. build_index reused every covered row by stat identity and still touched files, which is what the two stat-identity tests measure and what they caught once the stored value carried its code version.

The guard itself is unchanged in strength. A write to a module's source moves at least one field of the identity recorded with the entry — the fields are _stat_signature's, device dropped so a shared filesystem does not invalidate the store on every host — so a source change still makes every stored value absent and each plan is parsed once. An entry written before identities were recorded carries none, falls back to digesting, and is simply not reused until it is rewritten.
