a-review-duty-reads-the-ledger-once-per-pass — the station's review duty reads the ledger once per pass

What changed. ledger.run_ids is served from the stat-validated run index ledger.load already keeps, through load(project, root, headers_only=True), instead of parsing the aggregate on every call. The station evaluates every delivered run's review duty on every tick, and each duty asks ledger.run_ids whether the run is closed — through station_subscriber.live_work_populations, delivered_run_owes_review, obligations._review_duty_item, _reflex_open_refusal and recovery_review_dispatch._open_review_refusal. With the aggregate read per call, one tick paid a full ledger parse per delivered run. The index is keyed on the aggregate's and the runs directory's stat identity, so a ledger written behind the index is rescanned, and a run file whose own record the index could not decode still counts by its name. The refusal the duty reports is unchanged.

Measure. tests/test_a_review_duty_reads_the_ledger_once_per_pass.py builds a synthesised crew home of three delivered runs whose only stored review describes an earlier head, so each reads scoring with a review-missing duty the reflex owns. After one warm-up ledger.read_records call, one station_subscriber.live_work_populations pass enters _open_review_refusal for all 3 runs and calls _load_aggregate 0 times (the gate asserts at most 1 per project). A direct ledger.run_ids(project) after the pass opens no further aggregate read, and the same pass run with the aggregate-reading run_ids returns the identical duty text for every run. Head gate: 1 passed, EXIT=0.

Declared negative control, executed and logged. Reverting run_ids to _load_aggregate(project, root) makes the pass read the aggregate 3 times, once per delivered run, and the gate fails on assert 3 <= 1 — 1 failed, EXIT=1. Log: logs/negative-control.log.
