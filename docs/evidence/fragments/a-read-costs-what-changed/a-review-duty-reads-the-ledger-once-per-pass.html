a-review-duty-reads-the-ledger-once-per-pass — the station's review duty reads the ledger once per pass

What changed. ledger.run_ids is served from the stat-validated run index the ledger already publishes, through a new _indexed_run_ids that reads the index's ids only, instead of parsing the aggregate on every call. The index is trusted while the aggregate's stat identity matches the one it recorded and every run file carries the stamp it stored; otherwise the read is refreshed through load and answered from the refreshed index. It is deliberately not load unconditionally: load rebuilds the index and decodes rows a membership caller did not ask for, and the run store's cross-check requires membership to stay cheap. Both halves are taken from the owners that already held them rather than restated: _open_current_index is the read-only connection and aggregate-stamp check _last_good_index_data already performed, and _index_membership is the union _index_payload's header read already built, extended to count a run file whose stored record the index could not decode. A membership read and a header read therefore cannot disagree about such a file. The station evaluates every delivered run's review duty on every tick, and each duty asks ledger.run_ids whether the run is closed — through station_subscriber.live_work_populations, delivered_run_owes_review, obligations._review_duty_item, _reflex_open_refusal and recovery_review_dispatch._open_review_refusal. With the aggregate read per call, one tick paid a full ledger parse per delivered run. The index is keyed on the aggregate's and the runs directory's stat identity, so a ledger written behind the index is rescanned, and a run file whose own record the index could not decode still counts by its name. The refusal the duty reports is unchanged.

Measure. tests/test_a_review_duty_reads_the_ledger_once_per_pass.py builds a synthesised crew home of three delivered runs whose only stored review describes an earlier head, so each reads scoring with a review-missing duty the reflex owns. After one warm-up ledger.read_records call, one station_subscriber.live_work_populations pass enters _open_review_refusal for all 3 runs and calls _load_aggregate 0 times (the gate asserts at most 1 per project). A direct ledger.run_ids(project) after the pass opens no further aggregate read, and the same pass run with the aggregate-reading run_ids returns the identical duty text for every run. Two further cases exercise the currency check itself: a run file written after the warm read is counted by run_ids, and a run file rewritten in place is refreshed rather than answered from the index row it replaced, each without a single _load_aggregate call. Head gate: 3 passed, EXIT=0.

Declared negative control, executed and logged. Reverting run_ids to _load_aggregate(project, root) makes the pass read the aggregate 3 times, once per delivered run, and the gate fails on assert 3 <= 1 — 1 failed, EXIT=1. Log: logs/negative-control.log. Two further controls, each run at the final code and logged: returning the index's ids without the file-stat currency check leaves the added and rewritten files unseen, and making the refresh branch fall back to _load_aggregate leaves the index row stale; each turns both new cases red (2 failed, 1 passed, EXIT=1). Logs: logs/negative-control-currency.log, logs/negative-control-refresh.log.
