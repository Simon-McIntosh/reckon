arcwc-a-version-read-resolves-no-dependencies — a version, raw or section read parses its own document

What changed. reckon/mcp.py's _read_plan now takes a with_deps flag, and the progressive resource read sets it false for every view but summary and detail. Those two views serve dependency rows and keep resolving them; version, raw, section, history and schema serve none, so they no longer resolve the plan's depends_on and plan-section-depends-on refs. Resolving a ref reached _section_dependency_rows → _indexed_plan_states → metadata_index.discovery_state(build=True), which built the whole project to answer one meta field.

Measure. A cold view="version" read of docs/plans/the-monitor-shows-the-work-it-watches.html (888 KB) in a scratch copy of this repository's docs tree, on all_debug: 16.079 s at base revision 48a03513a8 and 0.741 s at head e491453a67, a factor of 21.7. Both arms ran the same literal command in fresh processes with a fresh RECKON_HOME, so the persisted index was cold in each. The logs are timed-arms.log in the run directory, carrying each arm's revision, literal command and closing EXIT=0.

Gate. tests/test_a_version_read_pays_only_its_version.py builds a temporary store whose target plan declares three section refs and whose index is cold, then counts metadata_index.build_index calls and plan parses: a version, a raw and a section read each build the index zero times and parse exactly one document (the target). A detail read of the same plan still returns its two section rows' waits (alpha#s1 for s1; beta and gamma for s2), each found and active. Negative control. At the base revision the three cases build the index once and parse all twelve documents, and fail with assert 1 == 0; the detail case passes there too, so the change is shown to remove only the index build.
