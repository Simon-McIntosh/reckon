A section ref resolves its target without building the project index

What changed. A dependency-serving plan read answered every section ref through _indexed_plan_states, which called metadata_index.discovery_state. On a warm store that is a digest check per covered document; on a cold one it builds the project's index and parses every covered document, so the first read after a restart paid for the whole project however few plans the refs named.

reckon/mcp.py now resolves each ref one at a time from the persisted index. _indexed_plan_states returns a _PersistedPlanStates mapping that answers a slug when it is asked for: it reads the store's entries once per read, validates that one document's entry against its own file through metadata_index.current_discovery, and returns the entry's parsed state. A target the store does not cover — no store at all, or one written before the document existed — is parsed from its own document through _parsed_plan_state, so one ref costs at most one parse rather than a project index. Each slug is resolved at most once per read, and the state_cache shares the mapping across every ref a read resolves.

The list-level inventory a plan read assembles for its holds still comes from the index. A summary read is the read whose subject is that inventory, so it assembles it as before. A detail read on a cold store serves the plan and its refs alone and therefore carries no list-derived blocker state until the store is warm; its dependency rows are the rows a full build returns, which is what the deliverable requires.

Measured

tests/test_a_section_ref_resolves_without_a_project_build.py builds a temporary project of twenty plans and points RECKON_HOME at an empty directory, so the persisted index starts absent. A patch on reckon._plan_html.read_state counts the distinct documents parsed — the document parser every plan read passes through, and distinct documents rather than calls because a document reached twice is memoised. A plan absent from the persisted index resolves by exactly one parse: the store covers the twenty plans, a twenty-first is written after it, and the ref into it parses that document and nothing else, returning its status and its section declarations. A plan the store does cover, asked for the same way, parses nothing. The three arms' dependency rows are compared rather than asserted separately, so a saving that changed an answer fails the same test.

Before routing the refs back through the full discovery pass, the test first proves the switch still does what it claims: with it thrown, the same cold read parses all twenty documents. A negative control that silently stopped reproducing would let the bound pass for the wrong reason.

The document parser counts distinct documents; the cold arm's read_state is reached by the plan's own read and by the three refs, and no document is parsed twice because read_state_and_text_file memoises on the file's stat identity.
