The time-zone deadline test tolerates a one-second straddle

Cause. The two-zone case ran the stated seconds-left command once under TZ=UTC and once under TZ=Europe/Paris, then required the two printed figures to be equal (assert utc == paris). Each run of the command reads the clock at its own instant (date +%s), so two runs that straddle a second boundary print figures one apart and the equality failed on the boundary rather than on the zone. The command under test is unchanged.

Reproduction, before repair. Traced to the base revision d0370a61a3244494cd434e27d19bf8a526d8f83c. Running the id alone thirty times at that revision produced one failure (29 passed, 1 failed) — the same class the plan records as 1 of 5 and assert '-128166' == '-128167' at line 100. Because the failure is a clock race, a probe was run to characterise it. Calling the same stated command back to back under the two zones 200 times gave a difference distribution of {0: 195, 1: 5}: the two readings differ by exactly one second, and never by the 3,600 seconds a zone offset would produce. The one-second drift is therefore the straddle, and carries no information about the zone.

Change. The comparison parses both readings as figures and fails only when the largest per-figure drift exceeds one second:

utc = _figures(_run(command, "UTC"))
paris = _figures(_run(command, "Europe/Paris"))
assert len(utc) == len(paris), (...)
assert utc, "the command prints no figure to compare"
drift = max(abs(a - b) for a, b in zip(utc, paris, strict=True))
assert drift <= 1, (...)

The length check and the non-empty check are kept so a command that prints nothing in one zone cannot pass by comparing two empty readings.
