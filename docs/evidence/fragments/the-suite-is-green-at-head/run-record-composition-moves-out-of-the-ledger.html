The run-record composition fits a worker window

Cause. tests/test_every_module_fits_a_worker_window.py refused reckon/ledger.py at main, measured at 51,666 estimated tokens by reckon.crew.routing._tokens_for_bytes against the test's 50,000 bound. The completion-record family had accreted beside it — the throughput, pace and lane measurements a run reports, the budget-group resolution that decides whether a lane's harness cost is spend, and build_record, which assembles the row promotion commits.

Change. That family now lives in reckon/run_record.py, named for what it does. Its constants and helpers stay in the ledger, and the dependency runs one way: run_record imports them at the end of its module, and ledger re-exports every moved name at its own end. A module-scope import in either direction would close an import cycle and make either module depend on which one an interpreter reaches first, so both imports sit after the definitions they need. The re-export is eager, not a lazy attribute hook, so a nested reader such as ledger.effort_report still resolves measurement_exclusion_reason through the module namespace and a patch on ledger.measurement_exclusion_reason still reaches it, exactly as before the move. Callers that already import the moved names from reckon.ledger — reckon/capabilities.py, reckon/calibration.py and reckon/crew/promotion.py — keep resolving the same function objects, and the two tests that patch a moved name (tests/test_calibration.py, tests/test_capabilities.py) were not modified, because the name they patch is read from the ledger's namespace at call time.

Measures. Both figures are reckon.crew.routing._tokens_for_bytes over the head tree: reckon/ledger.py 42,735 estimated tokens (149,570 bytes) — down from 51,666, and under the 45,000 the plan names; reckon/run_record.py 9,665 estimated tokens (33,825 bytes) — under 40,000. At head the width test no longer names reckon/ledger.py; it names only reckon/crew/review.py (52,989), which is a sibling node's target and outside this node's scope. ruff check and ruff format --check report no finding on either file.

Two-arm comparison. Both arms are trees materialised with git archive at their revision under the run's scratch directory and run in place on the fleet node with pytest -n 8; each log names its revision, tree and literal command, and ends in EXIT=. The selection is the tests/ files that reference a moved name.

Negative control. reckon/ledger.py restored to its base content in a scratch copy of the head tree. The width test then names reckon/ledger.py again — 51666 estimated tokens exceeds the 50000 bound — and exits non-zero.
