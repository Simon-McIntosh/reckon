A resumed run's fresh refusal is the hold the sweep waits on

Cause. sweep in reckon/crew/resumption.py treated a pointer as a resume candidate only when classify_pointer called it blocked. A resume replaces the pointer's stream with the new attempt's, and the classifier deliberately defers a freshly resumed attempt to that attempt's own clock before it will read it as halted — its word for a run in that window is running, with the detail the run's current attempt has recorded no process and no end of its own yet. So an attempt that was refused again was dropped by the candidate gate before hold_state was ever asked, and the sweep reported nothing: not hold-in-force, not a duplicate stamp, no entry at all. The one-resume-per-hold guarantee therefore held only until the next attempt started.

Reproduction. The listed id at the base revision dea3758c1, run from a git archive extraction on node-local disk, fails at tests/test_crew_recover.py:297: assert [] == ['hold-in-force'] — the second sweep's skipped list is empty. Instrumented at the gate, the resumed pointer classifies as running with the deferral detail quoted above, which is the mechanism.

Fix. The gate now keeps a run whose attempt's end is observed (_observed_end_refusal answers None) even when the classifier has not caught up with it. The refusal it judges is read from the attempt's own stream, so a refused attempt's own end is exactly the evidence the hold rests on. A live process, a non-CLI launch and a worker whose end nothing observed still stay out of the sweep's candidates, which is what the gate was doing for those cases — the live-process case is pinned by tests/test_dry_run_predicts_the_launcher.py and passes.

Test change. One assertion in the same file was repaired, for a reason the reproduction shows: test_a_stopped_run_with_no_session_anywhere_still_reads_discardable pinned "the advice offers no resume" with "resume" not in next_action, and next_action embeds the worktree path. Under this node's own worktree — a path containing refused-resume — the substring was found in the path and the test failed with no code defect behind it; it fails that way at the base arm too. The advice's own verbs are now pinned either side of the unchanged full-sentence assertion, so the property is unchanged and no longer reads the filesystem path.
