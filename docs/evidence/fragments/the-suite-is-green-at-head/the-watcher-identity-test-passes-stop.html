The watcher identity test passes the stop argument.

Cause. test_crew_watch_sheds_identity_before_its_first_sweep drives crew_watch.callback directly with keyword arguments, exercising the in-place reload route that sheds inherited session identity before the first sweep. When crew_watch, the click command in reckon/crew_follow_commands.py, gained stop as its second parameter the call no longer supplied it, so the test raised before reaching the code it guards. It failed in both arms of a population at merge on 2026-10-21 and no plan tracked it.

Reproduction, confirmed first. At the worktree head d837dec4393851e2acee5dceb8f12e4d0e83dbf1 the file's own run is 1 failed, 4 passed, EXIT=1, the single red id reading TypeError: crew_watch() missing 1 required positional argument: 'stop' at the call site. The other four cases pass at that revision.

Fix. The call now passes stop at the value the command's own --stop option declares, read from the click command's parameter list rather than written as a literal — stop=_option_default(follow_module.crew_watch, "stop"), where _option_default walks command.params for the named option and returns its default. A parameter the command gains with no default therefore still fails this call in the same way, instead of being handed a value the test chose. No product code changes: reckon/crew_follow_commands.py is untouched.

Measure. Logs are under the run directory. Head arm (change present), the whole file, head d837dec43: 5 passed, EXIT=0 — the named id and the four other cases its file carries. Base arm (change absent), the same file at the same revision: 1 failed, 4 passed, EXIT=1. Negative control — the declared mutation, the stop argument removed from the call, applied to the committed test file and restored immediately after: 1 failed, EXIT=1, the red id's TypeError naming the same missing stop argument as the base arm. ruff check and ruff format --check add no finding on the changed file: both report clean at base and head, so the delta is zero.
