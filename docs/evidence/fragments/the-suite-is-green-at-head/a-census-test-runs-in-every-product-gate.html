A census test runs in every product node's gate

A scoped suite command is drawn from a node's own fenced test paths, so no node's scope reaches a check over the whole tree. A node that adds a staged writer ran only the tests its own paths covered, and the staged-write inventory turned red at the next node that happened to run it. The project now declares its census tests in its own flight file, and a node whose write paths include product source measures them beside its own tests at both arms.

Measure

  • Head arm: 5 passed, EXIT=0.
  • Base arm, the test copied into the dispatch base tree: case (a) fails, since the base resolution returns no command for a product-only scope.
  • The census case runs the project's own census over a scratch repository built from the census's expected inventory: 50 passed at its base, and 1 failed at its head naming the owner test after an unlisted staged writer is added.
  • Negative control, dropping the census list from the resolution: cases (a) and (d) fail, the latter with no delta computed at all.
  • Importers of reckon.crew.promotion_records (5 failed, 125 passed at each arm) and of reckon._flight_schema alongside the dispatch importers (8 failed, 440 passed at each arm) add no failure at head against base; the failure-id sets are identical, one arm at a time with -n 6.

The recurrence the census describes closes here: a node that adds a staged writer without listing it now turns the inventory red at its own head, and its suite delta refuses the landing, rather than the tree turning red at the next unrelated node.
