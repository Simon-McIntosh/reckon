Terminal-record settle test drives freshness through its patched observation

The fold test drove the settle's freshness by calling os.utime on the stream and reading its filesystem mtime back. That makes the test an instrument of the storage: GPFS mtime is coarse and does not read back promptly after a utime, so the observation could leave the settle's window and the run would return before the terminal record landed. The test now supplies freshness from the patched _newest_stream_mtime itself — never a stat — so the settle's initial already-quiet check and its change detection are driven by the test's own clock.

What changed

  • tests/test_promotion_reads_the_terminal_record.py: in test_a_terminal_record_landing_after_exit_is_folded_into_the_row the patched observation returns time.time() for its first two reads (fresh, so the already-quiet check cannot return before the tail begins; the second read appends the terminal lines) and a fixed stale value thereafter, so the settle observes the stream quit and returns. os.utime and the real_newest stat are removed from this test.
  • The append of the terminal record is unchanged; only the freshness signal moved from the filesystem to the patched observation.
  • reads["count"] >= 3 is unchanged.
  • The three sibling tests that legitimately need a fresh filesystem mtime (the mtime fallback, the already-quiet fast path) keep their os.utime.
