The delivery-path test waits for the reader to attach before the fleet moves

The window is the fixture moving the pointers before the reader attaches, and it is in the test rather than in the follower. A follower's first attach derives its baseline from the live records and captures the stream offset it will read from, both in reckon/crew/runs.py:2484-2505 at the committed blob: watch_stream_cursor reads _list_live_records and builds each baseline row with previous=None, which is why its from_state is null. The lines the fixture appends when it moves the fleet land after that captured offset, so a reader armed behind the move never reads them; what it delivers for the moved run is the baseline row itself, inventory with no left half. The assertion asks for news and gets inventory, and the dispatched half is the state that goes missing.

Reproduced two ways. Natural, unmodified tree: 25 alone runs and 10 -n 8 runs of tests/test_removed_flag_migration.py at 87d07ec6 were all green (logs/alone-25.log PASS=25 FAIL=0, logs/xdist-10.log PASS=10 FAIL=0), so the window is real but the race almost never lands. Forced ordering, same tree: holding the reader's attach until the fixture had finished moving made the test fail at the set assertion, not at the _wait_for ceiling: AssertionError: assert {'completed_unpromoted'} == {'completed_u... 'dispatched'}, with the receipt [{'project': 'proj', 'event': 'baseline', 'run_id': 'r-one', ...}] — one baseline row carrying no from_state. The failing run is 24.49 s, inside the 30 s bound, which is the same fact from the other side: the ceiling never fired because the baseline row did arrive, so no transition after the baseline is lost.

The repair is in the test, and no product module changes. _wait_for_the_first_attach waits, bounded by WATCHER_LOAD_BOUND_SECONDS, for the reader to report that it has derived its baseline; the reader reports it from a wrapper around runs.watch_stream_cursor that sets the event after the real call returns, so the baseline and the offset are both captured before the test touches anything. The fixture then moves the fleet inside the watch claim and the move is read as a transition. The assertion message now carries the rows it received, because the receipt is what distinguishes the two windows.
