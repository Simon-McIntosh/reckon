A promoted run with a live pointer is held, not re-announced

Promotion writes the run's ledger row before it removes the live pointer, so for at least one poll a promoted run is observed with its pointer still present. The fleet fold in reckon/crew/recovery.py dropped a run whose transition word was promoted from the memory it carries between observations. A run absent from that memory is an arrival on the next observation, and the fold words an arrival dispatched — so the still-live promoted run alternated promoted and dispatched every tick and the follower never terminated. Reproduced standalone: 21 events in 5 s, the loop re-announcing the same landing.

The run is now held in the fleet while its pointer remains: the fold drops a run only when it is absent from the observation, so the next observation finds the promoted run in both its memory and the fleet and emits nothing. It leaves on its own pointer's disappearance, where the ledger row names a single promoted departure.

Cause group, and which side moved. The behaviour moved, not the assertion: the fold's arrival detector was reading a moved fleet member as a new one. A second defect in the same window was closed with it — _promote_record_holds read the promotion row from whatever root a repo-less pointer resolved to, not from the run's own repository, so a row left under the default root answered a promotion the run did not record. The row is now read from the run's recorded repository, and a pointer that records none keeps the word its pointer earns. This is the reading tests/test_crew_ticker.py's fleet stream has always described, and it is what makes that file's promoted-live run read its completion until the pointer goes.
