The graph-target family moves out of reckon/roadmap.py

Cause. tests/test_every_module_fits_a_worker_window.py holds every module at or under 50,000 estimated tokens. Two landings on 2026-10-22 took reckon/roadmap.py over that bound and neither node's gate ran the width test, so the file measured 51,232 estimated tokens against the bound at 77213b275. The reproduction is the base arm's one failure, quoted from logs/gate-base.log: reckon/roadmap.py: 51232 estimated tokens exceeds the 50000 bound and is not allowlisted.

What moved. The graph-target family now lives in reckon/graph_target.py, named for what the family does: resolve_ship_target, resolve_graph_target, _claims_graph_handle, _qualified_plan and _dependency_endpoints. No helper the family shares with code that stays was copied, and no ALLOWLIST entry was added to the width test: the bound is met by the split itself.

Callers. reckon/mcp.py imports resolve_graph_target from the new owner. _dependency_endpoints and _qualified_plan stay importable from reckon.roadmap because code there reads them — _build_roadmap calls the first and _judgment_member calls the second twice — and the two resolvers are re-exported so a caller or test that already names reckon.roadmap keeps resolving them. The re-export is a binding of the same object, not a copy: reckon.mcp.resolve_graph_target is reckon.roadmap.resolve_graph_target is reckon.graph_target.resolve_graph_target, which is what tests/test_mcp_import_surface.py asserts.

Why the imports are deferred. The dependency runs both ways — the graph resolver reads readiness and closure verdicts that stay in the roadmap (build_roadmap, _plan_decision_sections, unsettled_decisions, closure_blockers, _whole_plan_dependency, _judgment_member, _status, _progress, _decision_rows and GraphTargetError) — so the moved functions read those names from reckon.roadmap at call time while reckon.roadmap imports the new module at its top. No cycle forms at import time, and a patch on reckon.roadmap.build_roadmap still reaches the graph resolver: the wheel test below exercises that path and its graph arm passes. No behaviour changes.

The guard therefore fails on the condition it exists to catch, rather than the split having found a file already under the bound.

Ruff. On the three changed paths, ruff check reports 12 findings at head against 12 at base — two in reckon/roadmap.py, ten in reckon/mcp.py, none in the new module — so the change adds none. ruff format --check passes on all three. The two re-exports carry a narrow line-level # noqa: PLC0414 because ruff's default isort wants each redundant alias on its own statement.

Notes for the coordinator. The gate in this node's done-when excludes the rest of the suite, so the wider population belongs to the separately dispatched test node at merge.
