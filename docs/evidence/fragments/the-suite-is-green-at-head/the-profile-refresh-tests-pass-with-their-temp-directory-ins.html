The profile-refresh tests pass wherever their temp directory sits

The ledger resolved its run index by walking up from the ledger file to the nearest checkout. A ledger resolved from the configured home is legitimately outside any checkout, but when that home sits beneath one the walk found the enclosing checkout and re-homed the ledger to <checkout>/docs/state/<project>/crew.json — a file nobody wrote. The index under that key was empty, so the first read returned 0 rows where the fixture had written 50, and 16 of the file's cases failed. The suite reproduces this exactly: run against the base revision with --basetemp inside a scratch repository, tests/test_a_promotion_profile_refresh_costs_its_row.py reports 16 failed and 7 passed, with assert 0 == 51 at the fold assertions.

A checkout now claims the ledger only when its own state path for the project resolves to that same file. The index and the reads served from it are then keyed on the ledger the caller named, wherever the temp directory happens to sit. The worktree-sharing case the walk exists for is unchanged: there the checkout's state path and the ledger are one file, so the shared index is still found.

PathChange
reckon/ledger.py_ledger_repository skips a candidate checkout whose ledger_path(project, checkout) is not the resolved ledger path, so an enclosing checkout cannot adopt a config-home ledger.
