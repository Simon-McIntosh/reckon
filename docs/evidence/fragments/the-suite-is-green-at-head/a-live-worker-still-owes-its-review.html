A delivered run owes the review its tier requires

The review gate in reckon/crew/promotion.py derived review_required from the live pointer's classification alone: scoring, or promotable with a stale review head. A run that has delivered a terminal manifest while its recorded process is still alive classifies as running -- the classifier defers that outcome rather than calling it delivered -- so it matched neither arm. The gate had therefore disarmed itself for exactly those runs: they promoted unreviewed with no waiver, and a waiver offered for one was refused as a waiver of nothing. _require_review_waiver now reads the obligation from the delivery the promotion proceeds on, the terminal manifest released for this attempt (_release_terminal_manifest), so a delivered run owes its tier's review whether or not its process has stopped and --waive-unreviewed-promotion is admitted as the waiver of that obligation. The delivered arm covers any terminal status, not complete alone: the release path already permits promoting a run whose manifest reads complete, blocked or failed, and a delivery of any of those statuses is one this gate must not wave past unreviewed.

The refusal was corrected in the same change. A run refused under the deferred classification carries, for its own lifecycle, the action of watching it, and the refusal text named neither the classification it was reached under nor a command that produces a review -- it said the run is classified scoring whatever the classifier actually said. _unreviewed_refusal now states the classification the refusal was reached under, and a delivery-driven refusal names the review dispatch (reckon crew dispatch ... --role review ...) rather than an observation that produces no review.
