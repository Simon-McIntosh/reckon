A delivered run owes the review its tier requires

The review gate in reckon/crew/promotion.py derived review_required from the live pointer's classification alone: scoring, or promotable with a stale review head. A run that has delivered a terminal manifest while its recorded process is still alive classifies as running -- the classifier defers that outcome rather than calling it delivered -- so it matched neither arm. The gate had therefore disarmed itself for exactly those runs: they promoted unreviewed with no waiver, and a waiver offered for one was refused as a waiver of nothing. _require_review_waiver now reads the obligation from the delivery the promotion proceeds on, the terminal manifest released for this attempt (_release_terminal_manifest), so a delivered run owes its tier's review whether or not its process has stopped and --waive-unreviewed-promotion is admitted as the waiver of that obligation.
