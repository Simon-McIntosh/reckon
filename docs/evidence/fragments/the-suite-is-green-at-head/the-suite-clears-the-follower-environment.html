The suite clears the follower environment it inherits

A crew-host session exports four variables into every process it starts, the test suite included: RECKON_SESSION_HOST_SETTLE, RECKON_FOLLOWER_OWNER, RECKON_FOLLOWER_IMAGE_COMMIT and RECKON_FOLLOWER_SOURCE_ROOT. Follower and session code reads them to decide whether this process runs under a live host, which process owns a follower, and which commit and source tree the running image carries. A test that drives a follower therefore inherits a state it never set and reads the host that ran the suite as its own session.

The defect reproduces

Run from a crew-host session, the three files that exercise dispatch, session delivery and reload fail in bulk. At the base revision da1a110ab13de2c3f5b38a38fb807c35cbad06ae, with the four variables set exactly as a crew host sets them, that run reported 32 failed, 17 passed (EXIT=1) over the same three files.

The fix and its guard

An autouse fixture without_the_follower_session in tests/conftest.py deletes the four variables for every test. A test whose subject is that state still sets the variable it means through monkeypatch, which runs after the fixture and keeps its value.

tests/test_the_suite_clears_the_follower_environment.py pins the behaviour: it runs the three affected files as a subprocess with the four set exactly as a crew host sets them and requires them green, and it asserts the running suite process carries none of the four.

The guard fires

Removing the fixture and re-running the new test file turns it red (EXIT=1): the subprocess over the three files reports 32 failed, 17 passed again, and the failing id test_the_affected_files_pass_with_a_crew_host_session_set is one the armed head does not fail. With the fixture it reports 49 passed (EXIT=0).

The measure

Two gate arms at head bf1e00cb over the 29 test files carrying a failing id in the inherited-environment population, plus the new test file, run -n 8 from a checkout under the run's scratch tree: one arm with the four variables set with values a crew host supplies (5 failed, 408 passed), one with them cleared (3 failed, 410 passed). Both arms fail the same three tests at head (test_preflight_hold_and_clear_result_have_matching_exit_codes, test_crew_watch_sheds_identity_before_its_first_sweep, test_a_clean_moved_checkout_answers_on_the_current_code), which fail with the variables cleared and are not this node's.

reckon.crew.review.added_failures_from_gate_logs then base=cleared, head=set derives two ids, both follower tests failing in the set arm only. Run five times alone in each environment they fail in both, in no consistent direction — the pane test fails its second run under either environment, and the freshness test fails four of five with the variables cleared against none of five with them set — which is the signature of a timing dependence on machine warm-up rather than a dependence on the four variables. Both were already in the inherited-environment failing population at the base revision the population was taken from.
