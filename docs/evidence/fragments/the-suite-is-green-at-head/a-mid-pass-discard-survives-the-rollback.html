a-mid-pass-discard-survives-the-rollback — a discard recorded during an admission pass survives the launch rollback

Defect, reproduced first. A discard records its departure in the run's own directory (_write_discard_record, reckon/crew/promotion.py). The admission pass releases a queued request into the shared dispatch path (_launch_queued, reckon/crew/queue_admission.py), and a refused launch's rollback removes the whole run directory (_release_launch_claim, reckon/crew/dispatch_claims.py). A discard issued in that window therefore went with the directory: the restore read no record, wrote the request back queued, and the first-failure report appended a row for a run the operator had already discarded.

A trace probe at the base revision recorded the mechanism end to end: discard(r-probe) -> record=…/crew/runs/r-probe/discard.json exists=True, then rmtree(…/crew/runs/r-probe) marker_before=True, then after pass: run_dir_exists=False run_dir_record=False spool_record=False recorded=False. Both listed ids failed at base (2 failed, 3 passed, EXIT=1), each on assert promotion.discard_recorded(run_id).

Fix, one commit. preserve_discard_record copies the run directory's discard marker into the shared discards spool, and the admission pass calls it immediately before handing the directory to the launch. The departure is then durable whether or not the rollback removes the directory, so the restore reads it, leaves the pointer absent, and the report stays silent. Nothing is copied when no marker is present, so a request nobody discarded has no spool record and its restore is unchanged; an existing spool record — the older account of the same departure, written when the run had no directory — is left alone.

Measured, both arms from git archive extractions on node-local disk. Gate tests/test_a_discarded_request_stays_discarded.py: base c11e89e83 2 failed, 3 passed, EXIT=1; head 300473b4e 5 passed, EXIT=0. Each repaired id fails at the base and passes at the head.

Importer population — every test that reaches a changed function (discard_recorded, _write_discard_record, _launch_queued, admit_once, _discarded_since), 27 files under -n 4: base 2 failed, 181 passed — the two listed ids and nothing else — head 1 failed, 182 passed, and that one id, test_the_later_request_launches_once_the_earlier_is_promoted, is flaky in the base arm too: re-run alone it fails at base (1 failed, 10 passed) and passes at head (11 passed). It is not an added failure.

The repair is reverted in a scratch tree (both files restored byte-for-byte to the base revision): the gate then reports 2 failed, 3 passed, EXIT=1 on test_a_request_discarded_during_the_pass_is_not_written_back and test_a_discarded_request_is_reported_nowhere. Scope. reckon/crew/promotion.py gains preserve_discard_record and reckon/crew/queue_admission.py calls it before the launch; no test is changed, skipped or weakened, and the ordinary discard path (marker in the run directory, spool only when there is no directory) is unchanged. ruff check and ruff format --check report nothing added on the two changed files; the two ruff check findings in promotion.py are pre-existing at the base revision (lines 1666).
