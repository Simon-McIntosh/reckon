the-host-handoff-test-runs-the-same-on-a-compute-node — the reloaded-follower case no longer reads the ambient harness

What it depended on: the harness that launched the suite. test_a_reloaded_follower_adopts_launched_workers_before_it_hands_off is the one case in this file that drives crew follow in the test process (crew_follow.callback(...)) rather than through a subprocess. The subprocess cases scrub the ambient crew and harness variables in _follower_env; the in-process case set only RECKON_HOME, XDG_RUNTIME_DIR, CLAUDE_PID and CLAUDE_CODE_SESSION_ID and left every other variable inherited. An ambient CODEX_SESSION_ID then makes _coordinator_runtime() resolve the harness as codex, so _session_host_owner() returns None, _session_host_fifo() has no path, and _hand_off_from_follower() is false. The follower streams instead of handing over, and the case sits in the watch loop until the pytest timeout.

It is the session, not the node. The trial job this node repairs was submitted by a Codex worker (backend: codex on all three attempts), and a Codex session exports CODEX_SESSION_ID to the shell it runs a job from. Location tracked the symptom only because that worker's job landed on a compute node. Setting the single variable CODEX_SESSION_ID reproduces the hang in place on the fleet node.

The change. A new _isolated_harness_env helper deletes the ambient RECKON_, CLAUDE_ and CODEX_ variables and sets the four the case needs, exactly as _follower_env already does for the subprocess cases. The case also arms lifetime="8s", so a follower that streams instead of handing over ends within the case's own bound and fails naming the missing handoff line rather than hanging. Only the test file changed; no product code.
