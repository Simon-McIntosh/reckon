Follower and producer tests see their follower and producer run

Reproduction. All 11 census ids fail at the node's base revision in a git archive extraction on node-local disk: 11 failed in 192.61s, EXIT=1 (logs/base-arm.log). They split into two causes, and only one of them is a test that had drifted.

Intended changes. Ten ids fail because the production contract they read changed on purpose, and the test still asserted the superseded one.

Commit 06467f9da ("fix(crew): the monitor stream carries only actionable lines") made reckon.crew.ticker.stream_carries the single gate between the watch stream and the pane, and it carries only a row naming something the coordinator can act on — a delivery, a halt, a limit reset, a lift, a declared wait. A launch or a working transition is no longer printed. Eight of the ten expose _follow_watch_lines and drive it with a working row, or read the pane without a live producer, so they measured a row the stream is now right to withhold, and a stream read the follower now refuses to perform at all. Each repair keeps the property the test exists to pin — a sweep on cadence however busy the stream is, a raising sweep that does not end the follower, a pane byte-identical with the sweep running, an observed session's rows marked foreign and an owning session's not, a real configuration home left untouched — and re-points the fixture at a carried row, or supplies the live producer the follower requires, or computes the expected pane through crew_follow_commands.follower_row_path, the object the follower feeds, rather than a mirror of it.

Commit 9a7c6b83d ("feat(crew): project every list view's run rows through one function") leaves a field whose value is empty off the row. The simultaneous-end id read an empty-field row from a healthy run as row["lane_cause"] is None, which is now a KeyError; the repair reads the absence with .get() and adds assert row["recovery"], so the test still proves the absence is the row's shape rather than a projection that dropped every field.

Blocked id — unintended change. tests/test_producer_loop_survives_a_config_change.py::test_the_producer_defers_a_broken_config_and_recovers is not a stale test. reckon/crew/runs.py:_publish_watch_stream sets producer.tick_deferred = True when the flight config will not load (commit a89d8419e, "fix(crew): defer the producer tick when the resolved config will not load"), and every later tick then returns early on if producer.tick_deferred: return False. The deferral's stated contract is that the next tick retries once the config resolves; the code never retries at all, so a producer that meets one broken flight.yaml publishes nothing for the rest of its life. Reproduced independently of the test: with a broken config written, runs created, and the config then unlink'd, the stream still carried only its baseline row and the producer stayed alive (logs/probe_defer.py). The defect is production code outside this node's write paths, so neither that code nor that test was changed; the repair belongs in its own section.

Negative control. Ten repaired ids, one arm, production mutated in a git archive extraction carrying the repairs: stream_carries returns False, tests/test_follow_observes_other_sessions.py's four ids and the sweep's line-traffic and rate-guard ids lose their rows; _sweep_on_cadence returns at its first line, so no sweep runs at attach or on cadence; recovery is popped from every projected run row; and the follower's reload probe no longer compiles the tree before reloading. 10 failed in 65.34s, EXIT=1 (logs/negative-control.log) — every repaired id fails again, and each fails on the field, message or call it pins. Restoring an old expectation is not used anywhere in the arm.

At the head. The five-file gate at 4cdd078a5 runs 1 failed, 29 passed in 108.24s, EXIT=1 (logs/head-gate.log): the single failure is the blocked id above, and the 10 repaired ids pass. The node changed no production module, so no unlisted test file imports a module it changed; the arm that could show such a failure is the head gate itself. ruff check and ruff format --check pass on the four staged test paths.

Load-sensitive join. The two follower helpers joined their reader thread on a two- to three-second bound. It failed twice on a loaded node — test_a_follower_with_an_owning_and_two_observed_sessions_delivers_all_three (logs/post-ruff-follow-observes.log, passing alone next run in 5.06s, logs/retry-owning-and-observed.log) and then the census id test_pane_output_is_unchanged_by_the_sweep — each time on a stopped follower must return rather than on the property under test. Commit 4cdd078a5 widens that bound to fifteen seconds in both helpers and leaves the bounded join and the aliveness assertion in place, so a follower that never stops still fails.
