A killed-worker resume loses the fenced attempt's exit

Reproduction. tests/test_a_killed_worker_resumes_to_completion.py::test_a_killed_worker_is_classified_resumed_and_completed fails alone at head with assert None == 0 at line 328, which asserts second["exit_code"] == 0 on the resumed attempt's supervisor exit record. The record carries None.

Cause (product defect, outside this node's write scope). reckon/crew/dispatch.py:9426-9431 _supervisor_spawn_worker calls _spawn_worker_retrying_a_vanished_bind and returns process.pid without transferring the process.returncode that helper's startup poll may already have collected. In _died_over_a_vanished_bind_source (dispatch.py:8579-8586) the poll watches a just-spawned child for up to SANDBOX_STARTUP_WINDOW_SECONDS (0.5 s) through Popen.poll(); a poll that observes the child's exit reaps it. The resumed attempt is composed by the resume launcher and carries the bwrap fence, so its read-only bind sources are non-empty and the poll runs; the stub worker writes its manifest and exit 0 well inside the window, so the poll consumes the status before the supervisor's waitpid, which then gets ECHILD, returns None, and writes exit_code/ signal/signal_name all null. The sibling lane _spawn_detached_worker already guards this exact case (dispatch.py:8667-8678) by reading getattr(process, "returncode", None) and recording the collected exit; the supervised lane needs the same transfer.

Attribution. The change was introduced by 04538bea5 (fix(crew): retry a worker spawn refused over a vanished bind source), ledger run r-20261003T014214828711-spawn-retries-a-vanished-bind, crew session s22-coord.

Evidence. Attempt 1’s plan argv is ["/bin/sh", <stub>] (unfenced), so no bind sources exist and the poll is skipped; its exit record carries signal_name: SIGTERM and a live pid_start_time. Attempt 2’s argv is the bwrap fence, and its exit record carries worker_pid with pid_start_time: null and all-null exit/signal fields, while resume-1.jsonl proves the inner worker ran and exited 0. The asymmetry isolates the fenced spawn path.

Outcome. No test or product source changed by this node; the failure is a product defect filed under follow_ons. The id stays red at head, by design, until the supervised spawn path transfers the collected status.
