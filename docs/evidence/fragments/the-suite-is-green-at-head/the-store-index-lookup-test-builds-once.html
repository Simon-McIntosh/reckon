The store-index lookup test builds once on every run

Cause. _store_indexes starts a process from the index another process persisted for the same store directory (reckon/crew/review_records.py), and that document lives under XDG_RUNTIME_DIR keyed by the store's resolved path. The fixture pinned RECKON_HOME but left the runtime directory ambient, and pytest reuses a numbered basetemp path across sessions, so a second run at the same --basetemp found the first run's document, served the lookup from it and never called _build_store_indexes — assert 0 == 1 at line 248. Reproduced deterministically at one fixed path: run 1 6 passed, run 2 1 failed (repro-1.log, repro-2.log in the run directory). The document the failing run read names that exact store: …/bt-repro/test_the_review_run_lookup_ser0/config/crew/reviews/reads-committed-first with one entry for r-review-run (evidence/persisted-store-index-repro.json). Distinct basetemps never reach the defect.

Change. The root fixture in tests/test_reviews_read_the_committed_store_first.py sets XDG_RUNTIME_DIR to tmp_path / "run", so every case in the file starts with an empty persisted cache and the index is built once per run. Production's cross-process reuse is untouched; the same idiom already isolates the sibling tests/test_the_review_store_index_re_reads_only_what_changed.py.

Measure. On the repaired tree, 50 consecutive runs at one fixed --basetemp ($TMPDIR/bt-gate): failures=0 of 50, EXIT=0, each run logged with its revision and command and ending in EXIT= (gate/gate.log, gate/gate-run-01.log … gate/gate-run-50.log). The importer arm over the 15 test files touching reckon.crew.review_records: 113 passed, EXIT=0 head (importers-after.log) and 113 passed, EXIT=0 at the base revision (importers-base.log) — no added failure. Ruff check and ruff format --check are clean on the staged path.
