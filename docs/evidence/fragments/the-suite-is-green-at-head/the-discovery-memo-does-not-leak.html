No served case leaves a live discovery memo behind

A test that starts the served process assigns reckon.serve._SIGNATURE_TTL_S (the discovery walk-reuse window) and never restores it, so a later test sharing its process reads a memoised walk it did not arm.

Reproduction

The leaking file is tests/test_served_code_drift.py, not the two files named in this node's brief. Its two serve.main cases (test_main_releases_the_served_process_state_when_serving_stops and ..._when_it_cannot_bind) run serve.main, which assigns _SIGNATURE_TTL_S = 60.0 at reckon/serve.py:3739 before binding or before it raises, and neither restores it. Running that file and tests/test_server_listens_before_it_watches.py in one process, in that order, errors the entry-point cases at setup with an earlier test in this process left the discovery memo live (_SIGNATURE_TTL_S=60.0). Neither named candidate leaks: each already restores via an autouse monkeypatch fixture, and each leaves 0.0 at session end.

What changed

  • tests/conftest.py gains an autouse restore_discovery_memo_ttl fixture that snapshots serve._SIGNATURE_TTL_S at each test's entry and restores it on teardown, so no test leaves the window changed for the next. It is armed off by RECKON_TEST_SKIP_DISCOVERY_MEMO_RESTORE=1 for the negative-control run.
  • tests/test_discovery_memo_does_not_leak.py runs tests/test_served_code_drift.py and tests/test_server_listens_before_it_watches.py in one child pytest process, in that order, without xdist, and asserts the entry-point cases pass.
