Test modules import shared fixtures by name instead of promoting a plugin

tests/test_fence_is_on_again.py, tests/test_worker_env_export.py and tests/test_backend_environment.py each declared pytest_plugins = ("tests.test_crew",), which registers tests.test_crew as a session-wide plugin. Its autouse fixture then ran for every test in the session and its module-level cells were shared beyond the module that owns them. Each module now imports the home and repo fixtures by name, so the fixtures resolve for these modules while test_crew's autouse fixture and cells stay scoped to test_crew.py.

Evidence. A grep over tests/ finds no pytest_plugins naming tests.test_crew. The reduced -n 8 gate over test_crew, test_budget, the three modules and test_shared_helper_edges is 290 passed, EXIT=0; base and head arms of the four files are 217 passed each, zero added failures. Declared negative control: restoring pytest_plugins in one module and adding an eager mkdir to the autouse fixture makes test_shared_helper_edges.py::test_chmod_failure_leaves_no_temporary_beside_the_destination fail (1 failed, EXIT=1).
