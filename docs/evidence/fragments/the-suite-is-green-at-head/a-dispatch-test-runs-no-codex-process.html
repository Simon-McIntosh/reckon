A dispatch test runs no codex process

Since the inbox hook's trust was made a launch precondition, composing a codex worker's argv asks the app server to list the workspace's hooks and refuses when no trusted listing comes back. The suite's probe guard answered every probe with no answer, so every codex-backend dispatch test refused with BackendError: codex inbox hook trust could not be established by hooks/list; all 12 dispatching tests in tests/test_a_source_file_is_shared_by_default.py failed that way, making any armed gate over claim tests unmeasurable on any node.

The guard now answers that one listing itself, echoing the hook command the probe is already loading and carrying a key and hash of its own making, so the trust overrides still reach the argv while nothing is spawned. A live launch is untouched: the product still takes the key and hash from the harness's own hooks/list answer, as the inbox-hook section requires.
