the-basetemp-lock-is-exact — the basetemp lock refuses only a live holder of the same process

Defect. The session lock that guards an explicit --basetemp (tests/conftest.py) had three faults. (1) _process_is_alive treated any live pid as the holder, so a lock left by a killed session was never taken over once an unrelated process reused that pid — the basetemp was refused until someone removed the lock by hand. (2) acquire_basetemp_lock created the lock with O_CREAT | O_EXCL and wrote the holder afterwards; a second session that read the still-empty file in that window got no pid, unlinked the lock and took it, so both sessions ran. (3) The evidence fragment recorded the earlier arm's head revision as 531027092, not its actual head 2225ab398.

Fix. tests/conftest.py now records the holder's process start time — field 22 of /proc/<pid>/stat — beside its pid, and _holder_is_live treats a pid that is alive but whose recorded start time no longer matches that pid's current start time as stale, so a reused pid is taken over. _link_lock writes the holder's record to a temporary sibling and os.links it into place, so the lock path never exists without its holder's pid and start time. A lock read as empty or unparseable is refused while it is younger than five seconds (_LOCK_PARTIAL_GRACE_SECONDS) rather than unlinked, because it is a session mid-acquisition, not a stale lock.

Two new cases in tests/test_a_shared_basetemp_is_refused.py, each driving a real child pytest session connected to the repository's conftest:

  • A reused pid is taken over. A lock naming a live pid (this process's own) with a different recorded start time is stale: a session acquires the same basetemp and passes.
  • A partial lock write is refused. A lock file created but not yet written — the state a first session's acquisition passes through — is refused rather than unlinked and taken over.

Creating the lock with O_EXCL then writing it (the pre-fix acquisition, which also unlinks an unreadable lock) reddens the partial-write case: the second session takes the lock and runs.
