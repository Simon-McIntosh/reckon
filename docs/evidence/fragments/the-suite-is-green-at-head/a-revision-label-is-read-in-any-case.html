A revision label is read in any case.

Cause. The manifest audit holds each suite arm's gate log against the revision that arm records, reading the revision from the log's first line with the pattern _GATE_LOG_REVISION in reckon/crew/reports.py. That pattern was compiled without re.IGNORECASE, so a first line labelled REV=<sha> or Revision: <sha> named no revision and the audit refused a log whose revision was in fact the one the manifest recorded. On 2026-10-17 the whole-suite worker r-20261017T141450191818 met this refusal and rewrote its own gate logs' first lines after the run, lowercasing REV= to rev= with a script so the audit would pass: the revision value was unchanged, but a log edited after the fact is no longer the capture it claims to be.

Fix. _GATE_LOG_REVISION is now compiled with re.IGNORECASE. Nothing else about the match changed: the label is still required, so a first line carrying only a bare hexadecimal run — a tree path with digits, a timestamp — still names no revision. The label is read as written, so no writer is driven to edit its own capture.

New case. tests/test_a_revision_label_is_read_in_any_case.py holds both halves through the audit's public entry point, audit_manifest. Four first-line labels — REV=<sha>, Revision: <sha>, rev=<sha> and # arm=head REVISION=<sha> — are each followed by the forty-hex sha the manifest records for the arm, and each must produce no finding naming the head log. The negative half feeds a first line naming only a tree path carrying the same forty hex digits and requires the audit to report that the log names no revision.

Measure. Logs are under the run directory. Head arm (change present, revision 91a8aea54): 5 passed, EXIT=0 — all four labelled cases and the tree-path case. Negative control — the declared mutation, the pattern compiled without re.IGNORECASE, run against the base tree extracted at 91a8aea54 with only this node's test file copied in: 3 failed, 2 passed, EXIT=1. The three red ids are the REV=, Revision: and # arm=head REVISION= cases; the lower-case rev= case passes at base (it already did) and the tree-path case passes at base and head alike, since the label is required in both. ruff check and ruff format --check add no finding on the changed files: the base tree carries one pre-existing SIM102 in reports.py (line 702) and the changed tree carries the same one, so the delta is zero.
