A stream past its window lets a resume launch

Cause. The route the section left unknown is the resume's own attempt claim. _resume reserves attempt-N.claim before it composes anything, and the claim's at stamp dates the current attempt. _observed_end_refusal then asks how long the run has been silent, and _run_stream_quiet_seconds caps the newest stream's silence at that attempt clock. So the claim the door itself had just taken made a three-hour-old stream read as one second old. _newest_stream_in_motion answered true, and the door refused the resume that had reserved the attempt a moment earlier, reporting a live process that no stream showed. The commit that introduced it is 718b6fba4, which dates an attempt from its claim so a just-resumed run is not drawn halted. That reading is right for the pane; it is wrong for the dry-run and launcher doors, which ask about the worker that wrote the stream.

Reproduction. The listed id at the base revision 3c79a6d38, run from a git archive extraction on node-local disk, fails at reckon/crew/dispatch_sessions.py:1311 with reckon.crew.CrewError: run 'r-stream-quiet' still has a live process; observe or stop it before resuming. Instrumented at that guard on the same fixture, the attempt clock reads one second from the claim, the newest stream's own silence reads 10800 s against a 900 s window, and the capped reading min(10800, 1) is what the refusal is made on.

Fix. The end reading now measures the stream's own silence. _newest_stream_in_motion gains from_stream_alone, and _stream_reading_refusal and _newest_stream_ended pass it; both live in reckon/crew/resumption.py and both callers of the door read the same helper, so the dry-run prediction and the launcher still refuse identically. The attempt-capped clock keeps deciding the stall and pane readings, so the window 718b6fba4 exists to fill is untouched. The test file needed no change: it already pins the contract, and nothing in the reproduction showed it asserting something no commit intended.
