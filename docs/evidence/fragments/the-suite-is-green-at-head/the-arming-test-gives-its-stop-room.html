The stubborn-producer arming test gives its stop room to run

Cause. The case set ARM_BOUND=2, so _stop_watch_producer_within in reckon/crew/dispatch_watch.py handed the stop child only the remainder of that budget. The child starts a fresh interpreter and imports reckon.crew.recovery before it can signal. Timed on the fleet node at load average 54 to 71, that start alone took 1.75, 2.17, 2.32, 2.46, 2.46, 2.78, 3.35, 3.38, 4.01 s over ten runs — against a remainder of about 1.9 s, so subprocess.run killed the child before it reached unwatch. Arming then exited 3 naming its own bound, correctly, while the marker the test asserts had never been written. Product behaviour is sound: the bound did what it promises, and the test asserted a delivery that bound never guaranteed.

Change. Test only, tests/test_arm_lock_is_never_held_by_a_follower.py. The arming bound is now STOP_CHILD_ARM_BOUND_SECONDS = 40, sized so the stop child can start, signal and finish even when a load spike has consumed most of arming's own start; the communicate timeout is derived from it (ARM_OUTPUT_SECONDS = STOP_CHILD_ARM_BOUND_SECONDS * 2) rather than being a separate literal; and term-seen is read through a bounded wait whose failure message is still "the stop request must reach the producer". Only two bounds can end the attempt, and the assertion accepts exactly those, each read from the code that enforces it: within {STOP_CHILD_ARM_BOUND_SECONDS:g}s; arming stopped from reckon/crew/dispatch_watch.py when arming's own bound expires, and beyond {UNWATCH_SEAT_WAIT_SECONDS:g}s from reckon/crew/recovery_watch.py when the stop child reaches unwatch and the seat stays held. Both claims stand: arming ends with exit 3 naming the bound that ended the attempt, and the stop request reaches the producer.

Reproduction at the base. 7db6cd8de4, the case alone 10 times with the 19-file importer population of reckon.crew.dispatch_watch beside it at -n 6: 10 of 10 failed, every one at line 205, the stop request must reach the producer. A poller over /proc recorded the marker's first appearance against every ARM process's exit: in all ten the marker appeared after the last ARM process had gone, by 0.8 to 2.9 s, so it came from the fixture teardown's terminate and never from a stop child. No base run reached the signal.

Measure. At the head, the same 10-of-20 protocol under the same population: 20 of 20 passed. In all 20 the poller saw the marker written before arming exited, by 2.2 to 2.8 s — the stop was delivered while arming was still waiting, which is the claim the base runs could not show. An earlier head bound of 12 s failed one loaded run in twenty, with arming's own start having eaten the margin and the stop child killed before it signalled; the bound now carries margin past that spike, and widening the wait for the marker instead was rejected because the fixture teardown's own terminate would then have stood in for the child's signal. Suite arms over the node's own test file: base 7db6cd8de4 1 failed and 4 passed, EXIT=1; head 5 passed, EXIT=0. Ruff check and ruff format --check add no findings on the staged path.

Negative control. Two, both applied on extractions of the head. Restore the two-second bound and the immediate term-seen assertion: 20 of 20 loaded runs failed at the term-seen assertion. Make the seat refusal report 30s in place of the bound that ended the attempt: the assertion fails, reporting that it accepts only within 40s; arming stopped or beyond 2s, so a message naming an unrelated duration no longer passes. The head arm fails neither.
