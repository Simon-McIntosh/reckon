A directory claim that overlaps a peer asks first

The defect

The exclusive write-scope walk refuses any overlap, and a directory claim is the coarsest scope a brief can declare. A node that declares tests collides with every peer holding a single file under it, and the refusal a coordinator reads is the same shape as a genuine file-versus-file collision: no alternative is named, so the only visible remedy is to stop and redispatch. The imas-ambix coordinator lost about thirty minutes to its own tests claim blocking a peer.

The refinement here separates the two cases. A directory claim that overlaps a live claim is a decision the caller should make explicitly; an exact file claim that collides with another file is not narrowed by anything dispatch can suggest.

What changed

  1. reckon.crew.dispatch._directory_claim_overlaps decides whether a candidate write path claims a directory rather than an exact file: the path exists as a directory on disk, or it strictly contains the live claim by path component. A candidate that is an exact leaf inside a peer's directory claim is neither, so it keeps the plain refusal.
  2. dispatch._directory_claim_alternatives lists the files the brief declares under the claimed directory, or the overlapping claim's own path when the brief names no files inside it.
  3. dispatch._raise_repository_scope_conflict raises DirectoryClaimConflict (a ScopeConflict) for a directory claim, its message naming the claim, the owning run and node, the exact alternative, and --accept-directory-claim. With the flag the claim is admitted and the acceptance is recorded as directory_claim_acceptances on the run.
  4. crew dispatch gains --accept-directory-claim, threaded into both the launching path and the --dry-run resolution. The dry run with the flag proceeds and records the acceptance; without it the resolution is not ok and the warning names the alternative.
  5. The claim walk keeps its original signature when the flag is absent, so the callers and spies that wrap it are unaffected.

Evidence

tests/test_directory_claim_asks_first.py (6 passed under the root .venv python) drives the crew dispatch entry through --dry-run against a synthesized repository with a live claimant whose launcher pid is this process:

  • a live run claiming tests/test_x.py and a dry run claiming the directory tests exit 2 with a warning naming the claim, the owning run and node, and --accept-directory-claim;
  • the warning lists tests/test_mine.py — the file the brief names — as the exact alternative;
  • the same dry run with --accept-directory-claim exits 0 and records the acceptance naming tests/test_x.py;
  • a declared file path overlapping nothing, and a directory overlapping no live claim, both dispatch with no directory warning;
  • the classifier itself: a directory over a leaf is a directory claim; a sibling file and a leaf under a peer's directory claim are not.

Negative control (negative-control.log): neutering the overlap check so a directory claim over a live file claim dispatches without the flag makes the no-flag case fail on its warning assertion.
