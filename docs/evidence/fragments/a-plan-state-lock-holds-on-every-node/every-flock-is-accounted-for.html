Census of every fcntl.flock call under reckon/ that takes a lock, read at commit 7d8ca3f4658ee37aebaeb0d9c7749394c1f4f85e. The commit carries 43 lock-taking calls; a further 31 calls only release a lock and are not rows.

How the rows were found

An AST walk of every *.py under reckon/ collected every Call whose callee is fcntl.flock (or a bare flock). Each was classified by its flag argument: LOCK_EX or LOCK_SH, with or without LOCK_NB, takes a lock; a call passing only LOCK_UN releases one. reckon/crew/runs.py:493 passes a computed flags that is LOCK_EX or LOCK_EX|LOCK_NB and is counted. The set was cross-checked against a text search for flock, and the two agree. Two files (reckon/crew/quota_weight.py, reckon/file_memo.py) need a 3.12+ parser; neither contains flock.

The three verdicts

  • node-local by design — the lock file, or the object it guards, exists only on one host, so a holder on another node cannot reach it.
  • already judged cross-node — another mechanism decides the cross-node case, and the flock is the same-node half of it.
  • needs the §2 lock — the guarded file lives on shared storage, a writer or reader on another node can reach it, and nothing else decides the cross-node case.

The check, and its negative controls

A checker walks the AST of every *.py under reckon/ at the named commit, keeps the lock-taking calls, and compares the set of file:line keys with the data-site values in this fragment. It fails on any site missing from the fragment, any row naming no site on disk, and any site listed twice. Run against this fragment it passes (43 rows, 43 sites, no duplicate).

  • One row removed: the check reports the missing site and fails.
  • One row removed and another duplicated in its place: the check reports both the missing site and the duplicate and fails.

Both controls and the passing run are logged under the run directory.
