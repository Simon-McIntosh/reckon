A run's attempts are folded by the harness that wrote each of them

A run that changes lane keeps the streams its earlier harnesses wrote while its live pointer names the lane it carries now. Every reader folded those streams through the pointer's dialect: the omp dialect refuses a stream in another dialect's vocabulary outright, so crew observe and crew complete died on such a run with BackendError: the 'omp' dialect refused a stream in the codex vocabulary, and a dialect that does not refuse would instead fold the stream to a complete-looking run that spent nothing.

The stream fold now names each attempt's writer from the event vocabulary its own opening records carry, in reckon/_backends.py, at the single entrypoint (_observe_run_stream) every reader of a run's stream goes through: crew observe, promotion's terminal measure, the recovery sweep, and the live view's spend. A stream whose vocabulary matches the pointer's dialect keeps the pointer's backend unchanged, so a run that never changed harness reads exactly as it did. The identification is a bounded opening read, so pointing it at a live stream stays cheap, and it is memoised against the stream's stat identity so a stream being written is re-read rather than remembered by its previous contents.

The spend is summed across both attempts by the existing reckon/crew/metering.py fold, which already treats each attempt as a distinct thread: this node's change makes both attempts readable, and the arithmetic then covers both.
