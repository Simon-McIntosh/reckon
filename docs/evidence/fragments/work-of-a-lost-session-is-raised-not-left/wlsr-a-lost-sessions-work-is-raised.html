A lost session's implement work is raised as one decision

The admit pass now records exactly one open decision per lost session's implement work, listing every record it owns with its project, plan, section, phase, age and the work it holds back. The decision is written once and updated in place; a pass that finds the same list writes nothing. Until the lead answers it, the session's implement requests launch nothing and its landing groups are skipped with one reason, not refused per pass.

Answers

  • adopt moves each named record's ownership to a live session, so the adopter's live view lists the run and the lost session's does not.
  • retire removes a request with a discard record and records a run's disposition without promoting it.

A pointer the classifier already reads as promoted needs no answer: the pass retires it with the reason already-promoted recorded, and it is absent from the decision.

A request the wait rule retires as stranded is retired whoever owns it and is absent from the decision: the decision covers only records still live after that retirement.
