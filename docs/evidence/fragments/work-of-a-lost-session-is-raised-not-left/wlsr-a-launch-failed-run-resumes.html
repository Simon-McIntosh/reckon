A person's resume of a launch-failed run relaunches it; the sweep still refuses

What changed. reckon crew resume --run now relaunches a run in phase launch-failed on the run's own recorded backend. The refusal that protected the lift loop was written for the unqualified case: a launch that produced no stream record has no session for a lift to continue, so repeating the exec every tick was the loop the phase exists to stop. That reasoning holds for the sweep and not for a person, and resumption._resume already received the distinction as coordinator=True from the crew resume entry point — the same function the sweep calls without it (the lane-change form calls change_lane instead, which is how the 20 November dispatch relaunched a launch-failed run without ever reaching this guard). The refusal now applies only where coordinator is false. The hand-typed path clears the phase and the launch_failures list before the launch, so the run no longer reads as the attempt that failed and its attempt allowance is restored; the failure history survives in the retired per-attempt records. The live view's next action for the phase now names the plain command (reckon crew resume --run <id>) rather than a form that carries a backend override.
