Crew merge reads labelled suite arms

Commit e1d03bc8b1 teaches the merge's suite guard to read arms recorded per label. A run armed on more than one population writes baseline_suite_UNIT beside after_suite_UNIT and baseline_suite_VALIDATION beside after_suite_VALIDATION, and writes no unlabelled pair at all. The manifest parser typed only baseline_suite and after_suite, so the labelled arms arrived as raw text that the delta evaluation could not read, and a promoted, passing run was refused for the two top-level fields it had in fact supplied under other names.

Two changes hold it up. reckon/crew/reports.py types every suite-arm key the manifest actually records, so a labelled arm keeps the type it had in an unlabelled one. reckon/crew/promotion_records.py takes a labelled manifest down its own path: each label's baseline is compared with that same label's after arm, never with another population's, which is why one population's failures cannot be laundered against a different population's clean run. A label missing either side is refused naming the missing field; a label whose after arm names a failure its baseline does not is refused naming the label and the id. An unlabelled manifest takes exactly the path it took before.

Measured

  • The declared measure. tests/test_crew_merge_reads_labelled_suites.py runs 4 passed. It covers the three cases the section names: two labelled pairs each adding nothing merge, and the change lands on the repository's main with the origin ref moved to match; a second label whose after arm adds tests/test_unit.py::test_new_behaviour is refused with after_suite_validation names failures its baseline_suite_validation does not, carrying the id in added_failure_ids; and a label carrying only its baseline is refused with missing_fields == ["after_suite_unit"]. A fourth case asserts the clean delta reports both labels with an empty added set. Log: gate-head.log in the run directory.

The same test file, run at the base revision ff3bb24bcf in a scratch tree with the landing's own measurement unavailable, fails test_two_clean_labelled_pairs_merge with the refusal armed promotion requires complete baseline and after suite evidence; missing baseline_suite, after_suite and exits EXIT=1. That is the defect reproducing at the unmodified tree, not a passing test being re-described. Log: negative-control-base.log.
  • Ruff. ruff check passes and ruff format --check reports the three staged files already formatted, so the change adds no finding and no formatting drift.

Not done here, by scope. The labelled path judges each pair's completeness and its added failure ids. It deliberately does not re-check that a labelled arm's revision and command agree with the unlabelled pair or with the run's head the way the unlabelled path does, because a labelled manifest has no unlabelled arm to compare against and the deliverable asks for the missing-side and added-failure judgements alone. A manifest mixing an unlabelled pair with labelled ones takes the unlabelled path, where the labelled arms are typed and carried but not judged.
