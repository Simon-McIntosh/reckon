A lost session's reviews retire

A review request queued, or parked against an upstream, by a session nothing has heard for the flight threshold can never be read. It used to sit in the queue indefinitely, and the reflex composed a fresh review for every finished run the same session owned, each one created only to be refused. The admit pass now retires those requests before any ordering or lane question, through the discard path every stranded review already uses, and the reflex composes none.

The departure record names the session, the instant it was last heard and the rule that decided it: lost_session, last_heard_at and rule, written onto the same marker a discard leaves, so a reader asking why a pointer went finds the answer in the one place it already asks. The pass's verdict record lists every retirement under retired_lost_session and every refusal under retirement_refused.

Lostness is one derivation per session per pass. LostSessionReads in reckon/crew/lost_sessions.py dates a session from its follower lease, a process, or its oldest live record, and the pass reads each session once. A record's creation stamp is written as an ISO string by dispatch and as an epoch by older writers and fixtures; both are read from the value itself, because stringifying an epoch first produced a date-less string, which left such a session looking heard for ever.

What the review round changed

A pass asked about one run decides only that run. The retirement sweep and the re-read that follows it ranged over every live pointer, so a named admission could retire, and then launch, requests its caller was promised would be untouched. Both now follow the pass: the named request alone when one is named, the fleet otherwise.

A discard that refuses leaves the request queued. The pass counted it retired anyway and then launched the very review the retirement exists to suppress, on the same pass. A refusal is now named in the obligation, stamped on the pointer, kept out of that pass's ordering, and reported as retirement_refused rather than as a retirement.

The retirement carries its own facts to _discard_stranded_review instead of keeping a second discard writer that repeated the same marker lookup and the same three refusal sentences; the pointer stamp goes through the existing retirement helper. At the reviewed revision holds.py carried its own _stamp_discard_reason and _record_lost_session_retirement; both are gone and the file's discard calls are _discard_stranded_review.

The reflex dated a session from the run that owed the review alone, while the admit pass dates it from every live record. A young run under a session with an older record past the threshold then read live, and its review was composed only to be refused. Every live record dates the session now.

The control

Reverting the repair commit's source in the working tree, with its tests kept, reads 3 failed and 8 passed, exit 1, and each failure is the defect the finding named:

  • test_a_named_admission_retires_only_the_request_it_was_handed — the retired list carries r-lost-review-unnamed as well as the request that was passed, so the named pass retired a stranger's request.
  • test_a_refused_discard_is_not_reported_as_a_retirement — the retired list carries r-lost-review-refused, a request whose discard refused and which therefore never left the queue.
  • test_a_sessions_lostness_is_read_from_its_oldest_record — the reflex composes a review for r-delivered under a session whose older live record is 73 hours old.

The declared pairing holds at the head: the live session's identical queued review is neither retired nor held back, the pass launches it, and the reflex composes its review; the lost session's is retired with its facts and composes nothing.
