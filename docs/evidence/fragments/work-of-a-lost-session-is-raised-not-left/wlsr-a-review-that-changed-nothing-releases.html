§13 — A review that changed no file releases cleanly

Two halves had to agree before a commitless review could release: the declaration reader, and the release step that judges the field. The reader already existed and already recognised the observed shapes. What was missing was the release path using it: landed_workspace_refusal iterated the parsed commits entries and resolved each as a revision. The list reader leaves a prose declaration where a citation list would be, so none (read-only review run) was asked of git as a revision and refused with manifest commit '…' does not resolve. A bare none survived only because the list reader empties a field that holds nothing but an absence word.

Reproduction at the base revision, in a synthesised repository whose worktree sits clean on the primary branch:

none                                          -> ""
none (read-only review run)                    -> "manifest commit '…' does not resolve"
none — a read-only run has no commit to cite   -> "manifest commit '…' does not resolve"

The release step now judges the field through _presented_commits_without_a_declaration, the same reader promotion uses, which returns no commits when a commitless role's field declares an absence. All three observed spellings then release.

The guards that must survive do: a review worktree holding an uncommitted file is still refused, naming the file, and an implement run whose manifest names a commit that does not resolve is still refused.

Measure. tests/test_a_review_that_changed_nothing_releases.py: 5 passed, EXIT=0 at head. Negative control at the base revision: the first case fails with the release refusal — 3 failed, 2 passed, EXIT=1. Adjacent release and promotion gates: 33 passed.
