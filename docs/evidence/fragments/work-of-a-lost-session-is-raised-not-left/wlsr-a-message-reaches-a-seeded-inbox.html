A message reaches a seeded inbox

crew tell decided whether a live run could be reached by a list of dialect names: codex on its argv overrides, claude on its run home's settings, and every other name refused. A harness that speaks another harness's interface — the local lane's clive wrapper is one — is seeded the same run home and inbox hook, but its record is not the name claude, so a message to it was refused although the hook that would deliver it was on disk.

The decision now follows the route the harness interface declares, read from inbox_trigger_for — the same statement compose_worker_behaviour composes each launch from — and tests that route's artifact. A settings-group route is admitted when the run home's settings file carries the inbox hook; an argv-override route is admitted when the recorded argv carries both the hook and its trust record; a harness declaring neither route reads its inbox only on a later resume, so a live run on it is refused. Every refusal names the inbox path, so the directory a message would have been lost in is in the operator's hands rather than only the name that was rejected.

What the sweep found beside it

Two existing inbox test helpers seeded a run home without the settings file the launch passes, so they exercised a home whose hook was never written, and six cases in tests/test_worker_inbox.py plus two in tests/test_crew_tell_codex.py were red at the base revision for that reason: they are the eight failures the base arm above records, and they pass at the head.
