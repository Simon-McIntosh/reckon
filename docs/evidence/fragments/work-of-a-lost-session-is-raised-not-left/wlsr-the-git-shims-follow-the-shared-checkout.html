The git shim directory follows the image rule the scheduler shims use

What changed. The scheduler shim directory already named the checkout a published reload image was published from, so a worker placed on another node can read the shims the fence binds. The git shim directory did not: worker_shim_directory() in reckon/worker_git_shim.py was Path(__file__).resolve().parent / "worker_shims" with no exception, so a process running from an image named the image's copy on the launching node's local disk. That directory is on the worker's search path and the shim script it names is executed there, so a worker on another node got a directory it cannot read and a script it cannot run.

The rule itself moved into reckon.nested_launch.shims_beside(module_file, directory), which both families now ask: shim_directory() passes this module and host_shims, and worker_shim_directory() passes its own module and worker_shims. The rule is stated once, so the two directories cannot come to different answers about where a launched worker reads its shims, and the image test now holds the git directory to the same four cases as the scheduler one: the carried root, the interpreter's checkout, no checkout found (keep its own), and a checkout keeping its own whatever root is carried.
