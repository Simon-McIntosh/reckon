A queued review is not a missing review

A review dispatched into the lane's queue is a live run pointer carrying the queue phase and naming the run it was composed for. It has written no review record and no review is working, so the obligations view found no evidence of a review at the run's head and read review-missing — naming a dispatch the coordinator had already made. It reads review-queued while the queued run exists, beside its place in the admission order, and raises no stop refusal over a wait the lane owns.

One reader carries it, in reckon/crew/obligations.py. _queued_review_fields now reads two sources for the one REVIEW_QUEUED_DUTY_KIND: the refusal reader it already had, split out unchanged as _refused_review_fields, and _queued_review_run_fields, which scans the live pointers for a queued run that is a review and whose reviewed run and head match the duty's. The pair is read through recovery._review_subject and recovery._review_head_covers, the same helpers the review subject itself uses, so a review composed for an earlier revision does not speak for the head the run carries now. The place travels from queue_admission.queued_placements, the admission pass's own ordering, so this view cannot disagree with the lane about which request goes first. The earliest queued review is named when more than one waits.

One companion change was needed and is part of the same reader: _current_review_in_flight treated a queued review pointer as a review working on the revision, so the duty was suppressed entirely rather than listed. A review the lane accepted but has not launched is not in flight — no review is working — so it no longer suppresses the duty; the duty is listed as queued. Once the review launches, the live review suppresses it exactly as before.

Arms

Three arms, in tests/test_a_queued_review_is_not_missing.py, each on a synthetic repository and a temporary, fully environment-resolved crew home. The first builds a delivered run whose classification is scoring and asserts the duty reads review-missing with no queued review, then records a queued review pointer labelled for the run's head and asserts the duty reads review-queued with position 1 and rank 1. The second asserts the same queued reading and then removes the queued pointer, asserting the duty returns to review-missing. The third is the negative-pair control: a queued review of another run leaves this run's duty review-missing, so the second source is keyed on the reviewed run rather than on any queued review existing.
