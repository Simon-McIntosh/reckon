A producer off the fleet node gives up its seat

A producer whose host is not the node the fleet record names cannot probe the worker pids of runs launched on that node, so every liveness reading it publishes for those runs is unknown while it still holds the seat that would let a producer on the fleet node start. The seat owner now takes that decision itself: watch_unit.producer_start_decision reads the fleet record through its existing owner, compares the producer host to the recorded node, and when the project has a live run launched there returns release-and-exit with the unit-disable command composed (never run) so Restart=always cannot bring the same misplaced producer back. The same host, an absent fleet record, and a project with no run launched on the fleet node all hold.

Measure. The start-up decision against a temporary fleet record and seat: foreign host with a run on the fleet node → release-and-exit with ["systemctl","--user","disable","--now",unit]; the same host → hold; an absent fleet record → hold; a foreign host whose project has no run on the fleet node → hold. Gate: 6 passed, exit 0 (gate-head.log). Negative control — make the decision ignore the fleet record — holds the seat instead: the two foreign-host arms fail, 4 passed, exit 1 (negative-control.log). The base revision holds the seat, having no release decision at all: 6 failed, exit 1 (gate-base.log).

Scope. reckon/crew/watch_unit.py and tests/test_a_producer_off_the_fleet_node_gives_up_its_seat.py. No test reads or writes the real fleet record or seat. The producer loop's call to this decision at start-up and on each lease renewal is out of this node's exclusive write scope (reckon/crew/recovery_watch.py and reckon/crew/runs.py are held by a concurrent node) and is recorded as a follow-on.
