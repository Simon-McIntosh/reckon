The pane shows every state change

A pane carried a run's delivery and its halt and almost nothing else, because stream_carries admitted only those two words plus waits and recoveries. The row policy built a launch and then dropped it on the way out, so a coordinator reading the Monitor stream could not tell a run starting from a run that had never existed, could not see a review begin, and never saw a run land.

Three changes carry it. CARRIED_PANE_WORDS in reckon/crew/ticker.py grows from {delivered, halted} to {delivered, halted, in review, landed, dropped}, and a launch is carried by a marker the row policy sets. RowPolicy._launch_row builds the launch row under the session, once-per-attempt and reviewed-run checks; _release_launch routes each of the three release paths — the arrival hold resolving, the direct start, and the expired or stale hold — through it, so no path appends an opener behind the checks. _note_launch advances the run's shown word so the following working row is not counted as a second launch. A review run's event now also carries the id and node of the run it reads: recovery_watch._watch_transition adds reviewed_run_id and reviewed_node from _reviewed_run_facts, which resolves the review-of- node id and reads the reviewed run's live pointer for its node.

The in-review word is drawn by the row policy, not by a producer state. No producer ever writes a state called in-review; the policy rewrites a review run's first working row into the reviewed run's row with to_state in-review, run_id the reviewed run and node its node, keeping the hold memory keyed by the review run so the once-only judgement stays the review's own. That is what puts the row under the run it reads rather than under a node id no coordinator recognises.

A landing and a drop reach the pane through a second, narrower change. _observer_exception suppressed a settled row for a run already told, which silently swallowed every landing; it now returns for the two landing words ahead of that logic. The once-only property is kept by the same-word suppression, which is why a complete → recorded pair fed twice prints one row.

The gate, and the negative control

The new test file states one sequence per pane behaviour and drives them through a real PaneRowPath with timed arrivals, so a hold's window is measured rather than waited out: eight tests, all passing at the working tree. The negative control restores the base reading in a scratch copy — CARRIED_PANE_WORDS back to its two words, the launch arm of stream_carries deleted, the landing exception in _observer_exception removed — and runs the same file: eight failures, EXIT=1, every assertion arm failing. Both logs name the revision, the tree, the command, the module file actually imported and the cwd.
