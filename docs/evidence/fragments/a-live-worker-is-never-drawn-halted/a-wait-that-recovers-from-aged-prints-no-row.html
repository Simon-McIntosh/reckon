A wait that recovers from aged prints no row

wait-aged and waiting draw one pane word, waiting. The aging row is news because the wait has become overdue; the return to a pending wait is not, because nothing the coordinator must act on has changed — the same declaration is still being waited on. Both rows carry the wait declaration, so a same-word rule reading one event alone kept both and the pane drew waiting → waiting carrying only a growing elapsed.

Two changes in reckon/crew/ticker.py. RowPolicy keeps _shown_wait beside _shown: the wait facts of the row the pane last actually showed for a run, written where rows are released rather than where they are noted. same_word_row_is_news takes that memory as remembered and reads it through the new wait_facts helper, which returns the overdue flag, the probe's verdict, the same-word row's last observation, its declared horizon and its resume brief — or None for a row declaring no wait. A same-word wait row is news where it newly sets wait_overdue (the shown row had it false or absent) or where the declaration differs from the shown one; a row that only clears the overdue flag with the declaration otherwise unchanged is withheld. No second same-word rule sits beside it: RowPolicy.feed and Ticker.render still call the one predicate, each handing its own per-run memory, which is why a row the policy releases is never drawn blank. The aging row's own wording is unchanged.
