A missing pointer launch names the pointer

A launch that ended before a worker existed is read from its run directory, and the supervisor's exit record distinguishes the causes under launch_failure.kind. Two of them want opposite recoveries. A command that could not be executed needs the command and the PATH it was looked for on; a live pointer that went missing between the dispatch writing it and the supervisor's first read needs the path it was expected at, and a resume. The classification's launch-failed arm offered the command-and-PATH remedy for both, so the one case where PATH is irrelevant was handed the remedy that cannot clear it.

The change is confined to reckon/crew/recovery_classification.py. A new helper _missing_pointer_recorded reads the exit record's launch_failure block and answers the pointer_path only when kind is pointer-missing; anything else — a spawn kind, no block at all, no exit record — answers None and leaves the branch untouched. The launch-failed arm now composes its next action from that helper: the missing-pointer arm states that the launch found no live pointer at the recorded path and names reckon crew resume --run <run_id>, while every other launch failure keeps the previous command-and-PATH wording verbatim. The detail text, the classification word and the phase are unchanged, so no reader's existing reading of a launch failure shifts.
