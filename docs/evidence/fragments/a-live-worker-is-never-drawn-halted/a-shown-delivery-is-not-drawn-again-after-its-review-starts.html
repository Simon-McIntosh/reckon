A producer re-sweeps a delivered run whose state has not changed, so the delivery it writes again is a row the pane printed before. The row survives the same-word rule because a delivered run awaiting its review carries the action classification scoring, and same_word_row_is_news names every actionable row news so a repeated word never hides a duty. RowPolicy now holds an attempt-keyed memory in reckon/crew/ticker.py: _launches counts the launches the pane released for a run, and _review_started records the ordinal at which it drew that run's in-review row. _note_launch writes both — the review's own launch marks the reviewed run's open attempt, and a launch under the run's own id moves the ordinal — and _redraws_a_shown_delivery withholds a delivered row for a run whose marked ordinal is still the open one. A resumed attempt is therefore a new ordinal, so its own delivery prints.

The rule is the reviewed run's alone. A review run's own delivery, the reviewed run's landing, and the halt and resume a review's findings cause all still print, which the resume arm drives end to end: launch, delivery, in review, the review's delivery, halt, the resume's launch, the resumed attempt's delivery.
