A live worker's unreadable manifest is not unwritten

A run in motion may hold a manifest body the strict reader refuses — a list field joined with a separator parse_manifest does not accept, or a status word outside the vocabulary. That refusal is real and stays: it is named on the row's detail. What changed is what it is taken to mean. Classification reads the body for a status the reader accepts, and only that counts as a written verdict. Orientation keys alone, a non-vocabulary status word or an unsubstituted status template are all the same absence read from a later moment, and the motion predicate _orientation_write_of_a_run_in_motion already owns what to do with an absent verdict on a run in motion: a proven-live worker, or — for a run whose pid this host cannot look up — an assistant record in the newest stream inside the stall window the stall clock already applies.

The change is one test in reckon/crew/recovery_liveness.py: a new helper _manifest_carries_no_verdict_yet reads a body as carrying no verdict when it is an orientation write, or when it is non-empty and its status is not one the reader recognises. The guard inside _orientation_write_of_a_run_in_motion now asks not _manifest_carries_no_verdict_yet(...) in place of its old orientation-only test, and the motion rule beside it is untouched — the same predicate, the same three-way live/unknown/gone decision. This is the size the node declared: an extension of the predicate, not a second rule. In reckon/crew/recovery_classification.py the live-unwritten arm's detail now names the parse error itself rather than only the path, so a coordinator still sees the body that needs rewriting.
