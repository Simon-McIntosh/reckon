Landing record — a seat release reaches the panes

A producer off the fleet node gives up its seat and announces it, but the announcement was printed to the producer's own log (watch_unit.watch_log_path) and never reached the transition stream the panes read. Measured 2026-10-24 04:25Z: the reckon, nova and power_convertor seats moved to the fleet node and no pane drew it. A seat changing hands is a state change a coordinator oversees, so the release has to be a row on the stream, drawn under a word of its own.

watch_unit.release_seat_when_misplaced now writes one row to the project's watch stream through announce_seat_moved, built by seat_moved_row on the same recovery_watch._watch_transition surface a lift and a limit-reset row use, so every existing field a follower renders is filled. The row carries to_state: seat-moved; both hosts ride it as structured fields (seat_from_host, seat_to_host) beside the clause in detail, so a reader knows where the work moved without parsing either. The write sits inside the existing once-per-project announcement guard, so the lease renewal that re-asks the question cannot draw the same move twice.

ticker.PANE_STATES gains "seat moved": frozenset({"seat-moved"}), the constant SEAT_MOVED_STATE, a hue for both themes, and CARRIED_PANE_WORDS gains "seat moved". No run's state changes when a seat moves, so the word describes the seat and is selected by the release row's own to_state — the same shape in review already has. The row names no session, so a session-scoped follower admits it (its owner compares only against a non-empty owner), which is what makes the release reach every pane rather than one session's.

tests/test_a_seat_release_reaches_the_panes.py holds five checks against a temporary config home, fleet record, seat and stream: a foreign-host release-and-exit writes exactly one row whose to_state is seat-moved and whose two host fields and clause name both hosts; the row policy prints that row once with the pane word seat moved and the rendered line names the fleet node; a second asking (the lease renewal) writes no second row; a producer on the fleet node holds and writes nothing; and the account's real stream is unchanged afterwards. The row is fed through ticker.PaneRowPath and crew_follow_commands._follow_selects, the follower's own selector and policy, rather than a second opinion of them.
