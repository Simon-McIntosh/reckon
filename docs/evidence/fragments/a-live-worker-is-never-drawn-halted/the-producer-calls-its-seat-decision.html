The producer calls its seat decision

The start-up decision existed in the seat owner and nothing called it, so a producer on a host that is not the fleet record's node still took the seat: every liveness reading it published for a run launched on the fleet node read unknown, and it held the seat that would let a producer there start. The producer now asks the question at start-up, before it claims any seat, and again on every lease renewal — a reload can leave a producer holding a seat on a host it can no longer serve, so the start-up answer alone would miss that one.

A release runs in this order and ends the process: the unit-disable command the decision composed, through an injectable runner; the seat this process holds is erased through its own handle and unlocked, and its host lease given back, so a producer on the fleet node reads a free seat rather than a foreign one whose stream was just written to; the announcement is printed once, naming both hosts; then the process exits. The descriptor is unlocked rather than closed, because the claim that opened it closes it on the way out. In reckon/crew/fleet_supervisor.py the short-hostname spelling gained an optional name and _hosts_match now shortens both of its names through it, so the two sides of that comparison cannot drift. The real-record assertion in the seat-owner test is guarded by exists() as its before-reading already was.
