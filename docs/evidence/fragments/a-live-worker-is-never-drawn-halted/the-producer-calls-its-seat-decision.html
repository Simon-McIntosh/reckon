The producer calls its seat decision

The start-up decision existed in the seat owner and nothing called it, so a producer on a host that is not the fleet record's node still took the seat: every liveness reading it published for a run launched on the fleet node read unknown, and it held the seat that would let a producer there start. The producer now asks the question at start-up, before it claims any seat, and again on every lease renewal — a reload can leave a producer holding a seat on a host it can no longer serve, so the start-up answer alone would miss that one.

A release runs in this order and ends the process: the unit-disable command the decision composed, through an injectable runner; the seat this process holds is erased through its own handle, and the teardown the claim already performs — one function in the seat's own module, dropping the registries and unlocking the held descriptor — is called rather than repeated; then the announcement is printed once naming both hosts, and the process exits. The descriptor is left open because the claim that opened it closes it on the way out. Answering the renewal question reads the live pointers through the reader that only reads: the listing that publishes the watcher stream and can start an obligations sweep would make a producer that does nothing else scan and publish the fleet every five seconds. Both that read and the host comparison it follows sit after the cheap host check, so a producer already known to be on the fleet node's host never reaches them. In reckon/crew/fleet_supervisor.py the short-hostname spelling gained an optional name and _hosts_match shortens both of its names through it. The real-record assertion in the seat-owner test is guarded by exists() as its before-reading already was.
