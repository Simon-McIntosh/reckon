Landing record — a full queue is a wait, not a session refusal

A queued request's launch is retried on every pass, and two refusals are waiting readings that name the session or quote their own retry commands. QueueFull says the session already holds its share of queued dispatches — “session <id> already holds 2 queued runs, at its cap of 2; a queued run launches when a slot frees”. ScopeConflict says a live run claims a write path the request needs, and its text quotes reckon crew observe and reckon crew dispatch as the route. Read by its text, the first matched the session and published the follower attach line, and the second matched the quoted dispatch, so each raised a duty no follower and no retry of the same dispatch can clear. The request was already waiting on a lane slot or on a peer's run end.

Both exception names are now declared in _WAIT_REFUSALS beside the lane-hold reading, and recovery_classification._queued_failure_remedy returns no remedy for a failure stamped with either class. It is read from the class the admission pass stamps at the head of the stored failure (QueueFull: …), never from the text, which is the same route the preceding section gave the stamped reader. The request keeps its run-queued duty in the obligations view, since the view lists a queued row under the session-refusal kind only when a remedy is published for it.

The retry back-off is deliberately untouched. queue_admission._is_lane_hold is what the admission pass asks before skipping a failed request's back-off. Had it been widened to cover these refusals, _retry_backoff_hold would return None for a QueueFull pointer and the request would be re-launched on every pass while the session is at its cap. The two classes are therefore named in the classifier, not added to the lane-hold test, and a check pins that _is_lane_hold still answers no and that the back-off still holds the pointer until its recorded retry instant. The follower condition (_FollowerAdmissionUnmet/WatcherRequired) still reads as the session's own duty.

tests/test_a_full_queue_is_a_wait_not_a_refusal.py holds six checks: a QueueFull pointer and a ScopeConflict pointer each read no session_refusal and wait for a local lane slot; each lists as run-queued in the obligations view; a pointer refusing on an unregistered follower still reads queued-awaiting-session with the attach line; and a full queue still answers _is_lane_hold false and is still held by _retry_backoff_hold. The refusals are built from the real exception classes and stamped as the pass composes them, so the checks read what a pass records rather than a hand-written stand-in.
