Persisted-item record and persist root

Persisting copies a figure, and any named data files, into the project's own root outside the crew home; every copy is checked against its source's byte count and content hash before one record per copy is appended to the project's persisted-items resource.

What landed

  • reckon/crew/persist.py — persist_item: resolve the mounted project and reports.persist_root, copy each source, verify size and sha256, then append records. A verified copy that does not match its source is refused and leaves no record; a repeat persist of unchanged bytes returns the record already held and writes nothing.
  • reckon/project_state.py — new persisted_items resource type at docs/state/<project>/persisted-items.html, validated and written through the same lock, version check and atomic write as every other distributed resource.
  • reckon/flight.py — the reports block carries persist_root (and staging_root for the retention pass that reads it next). Absolute paths only, no shipped default, so a project that declares none is refused by name.
  • tests/test_a_persisted_item_has_a_record.py — seven cases over a synthetic crew home and a temporary persist root.

Negative control

With the content-hash comparison skipped (copied_hash set to source_hash), the altered-copy case accepts a corrupt copy and fails: expected PersistError, none raised. The size check is still in place in that mutation, and the case alters bytes without changing the length, so only the hash can catch it.

Repair round

  • The persist module no longer carries its own file digest: it reads the chunked reader the project-state module owns, so the content hash has one definition. Checked by object identity, not by wording.
  • The reports block declares only the persist root. The staging root belongs to the retention pass that reads it, and this node writes no such pass.
  • The untouched check now watches the operator docs state as well as the crew home, the data records are compared with the fixture path rather than with a script- produced field, and a case drives the refusal for a persist root inside the crew home.

Each fix has a red control: disabling the crew-home guard fails its case, and a data record naming its own copy rather than the figure source fails the two-data-file case.
