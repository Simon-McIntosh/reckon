A plan's report is written once, at closure

The store composes a plan's landed record in its write tail, on the one transition where a plan reaches a landed terminal status. The record names the plan and the sprint it ran in, links both from its first block, and embeds each node's figures beneath that node's row.

What landed

  • reckon/_store.py — _write_state_locked calls evidence.compose_closed_plan_report after a plan moves from a non-terminal status to shipped or done. A composition failure warns; it never refuses the write, so closure gains no new refusal.
  • reckon/evidence.py — ReportIdentity and _identity_block render the plan and sprint links; _served_href is the record's one address rule, applied to the plan resource and to the sprint document alike; compose_closed_plan_report composes with require_runs=False, so a plan with no committed runs can still close.
  • tests/test_a_closed_plan_has_one_report_naming_its_plan_and_sprint.py — five cases: closing in a sprint with two figures, a landing on an open plan with no record present and with a record present, both links deriving from the one address rule, and closing with no sprint.

Repair round

  • The sprint link no longer rebuilds the served-address rule. The plan-state module's own plan_sprint_href is gone; the sprint document resolves through the resource path convention and the record derives both links from _served_href, so the address convention has one definition.
  • The open-plan case now covers the state a plan that never landed a record is in: an append with no record present asserts that none is created, because the earlier case could only show that an existing record was not rewritten.

Negative control

At the base revision the first case fails with the sprint absent from the record. With the store's status guard removed so that every landing composes, the new no-record case fails because a report appears where none existed.
