What changed

The persist operation that copies a report item outside the crew home and records it now has three callers over one Python function. reckon crew persist takes a figure and repeated --data paths; POST /crew/<project>/reports is a sub-path of the existing crew route; and the existing records view carries a persisted field rather than a new view, because the MCP crew tool is read-only and its argument model carries no action field.

The listing reads the one classifier

GET /crew/<project>/reports?plan=<slug> answers each of the plan's report items with its retention class and, for working material, the date it expires. Both come from reckon.crew.report_retention.classify_item, the function the retention sweep calls, so a listing cannot show an item as kept while the sweep would remove it.

Evidence

One synthetic figure and its data file are persisted through the CLI and through the HTTP sub-route, each against its own temporary store, and the two records compare equal apart from the store's own root and the moment of the write. A control routes the HTTP endpoint through a second implementation that drops the data records and the same comparison fails, so the agreement case is known to see its subject.
