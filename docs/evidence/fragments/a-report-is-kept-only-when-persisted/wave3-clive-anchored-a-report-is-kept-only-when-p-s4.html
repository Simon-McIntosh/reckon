An unpersisted report expires at its plan's close or after 30 days

The retention sweep's report-tree pass is now an item rule. A new reckon/crew/report_retention.py owns one classify_item judgement, which the sweep calls: an item is persisted when a §2 record keeps a copy inside it, cited when its path or a path inside it appears in one of the project's plan, research or evidence documents, and working otherwise. A working item expires at its plan's close when it is attributed to a plan — by its own folder name, or by a ledger run naming that plan whose report directory lies inside it — and otherwise at 30 days after its newest write.

Gate: tests/test_an_unpersisted_report_expires.py beside tests/test_staged_write_inventory.py, 63 passed at the head revision; the base arm over the same tree resolved to tests/test_staged_write_inventory.py alone, 51 passed.

  • 31-day unreferenced item removed; 29-day item kept.
  • The real reports store is unchanged by a sweep in the synthetic home, measured on this project's own path before and after.
  • 29-day item named for a closed plan removed; for an open plan kept; 31-day item of an open plan removed at the ceiling.
  • 29-day item attributed through a ledger run's report path removed on that plan's close; a 29-day unattributable item kept whatever any plan's status.
  • Kept at 90 days: a persisted item, a directly cited item, an item cited only through a file inside it, one cited from a research document, one cited from an evidence fragment, and one named by a live pointer.
  • No reckon-written folder removed whole; a 31-day code-review child removed; plan-review contents untouched.
  • An expired symlinked item loses both target and link; a symlink outside the staging root is kept and reported.
  • The dry run's candidate list equals what --apply removes.

Negative control: with the citation branch of classify_item disabled, test_every_keeper_survives_ninety_days fails (1 failed, 11 passed), showing the citation check is what keeps the cited item rather than incidental age. The real-store case is falsifiable the same way: taking its before-snapshot after the removable item exists fails it (1 failed), so the comparison detects a removal rather than always passing.
