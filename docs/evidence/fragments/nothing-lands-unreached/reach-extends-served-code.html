The served-code module index answers production reachability

What changed. reckon/served_code.py gains a reachability reader beside its existing module index, rather than a second import graph. reached(repo, revision) resolves the production entry points — the console scripts in pyproject.toml and the Click verbs they mount, the MCP server, the serve.py handlers, and every module launched by python -m from reckon's own source — and returns the modules and module-level definitions reachable through imports and attribute references, plus the roots it started from. neighbourhood(repo, revision, paths) returns the production modules one import away from the named paths in either direction. The reader reads one revision's reckon/ tree with ast and never imports the package, reusing velocity.read_sources, interface_counts.definitions and the module's own memo pattern. Two tests are added: tests/test_reach_graph.py drives a throwaway repository through a console script and a python -m launch, and tests/test_every_module_is_reached.py is a ratchet whose ALLOWLIST is exactly the seven modules unreached at this section's base, each naming its owning plan.

Measured. At the head revision 1578a16e7, tests/test_reach_graph.py and tests/test_every_module_is_reached.py are 5 passed, EXIT=0. The reader reports 159 of 167 modules reached and project_state_parity and the six crew census/hold/origin modules unreached — exactly the allowlist.
