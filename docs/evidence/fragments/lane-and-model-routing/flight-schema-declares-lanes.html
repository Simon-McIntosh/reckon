flight-schema-declares-lanes — the flight schema declares lanes with models inside them and expands them into today's backends

The LinkML source (reckon/schema/flight.yaml) gains a top-level lanes: key, with LaneConfig and LaneModelConfig classes; the generated module (reckon/_flight_schema.py) and JSON Schema (docs/_shared/flight.schema.json) are regenerated from it. A lane carries today's backend-block keys plus default_model and models.<key>; each model carries model, effort, alias, optional dated rates, an optional budget_group defaulting to the lane's, and an optional time_budget overriding the lane's. Resolution (reckon/flight.py, expand_lanes) expands each lane into today's backends: entries: one named after the lane (carrying its default model) and one named <lane>-<key> for every model whose derived name is already a declared legacy backend. Every expanded entry carries lane and model_key; a derived entry also carries derived_from so reckon flight can count the legacy names still live. The override layer merges before expansion, so --set lanes.claude.models.opus.effort=xhigh reaches the expanded entry.
