The provenance leaf rule has one owner: _record_provenance walks through _leaf_paths

Change. reckon/flight.py::_record_provenance held its own inline leaf traversal beside _leaf_paths, a second copy of the rule that stayed correct only while the two agreed on which paths are leaves — an agreement asserted by a comment rather than held by the code. _record_provenance now stamps every leaf by iterating _leaf_paths(data) and holds no traversal of its own; the recursive helper and its prefix argument are gone. _leaf_paths is the module's one definition of a leaf. The walk was already value-identical to the inline one (a non-empty mapping recurses; a scalar, an empty mapping and a list are leaves), so resolved provenance is unchanged; only the owner of the rule moved.

Test. tests/test_provenance_has_one_leaf_rule.py resolves a host layer whose lane declares environment: {}. Under the shipped rule the empty mapping is a leaf: origin() names its raw layer path lanes.claude.environment, and the lane expansion records its source backends.claude.environment → lanes.claude.environment. The test then replaces _leaf_paths alone with a walk that treats an empty mapping as a non-leaf, and asserts both surfaces drop it while a scalar leaf is still found. Both surfaces moving together is what one owner means: a resolver whose _record_provenance kept its own walk would leave origin() naming the empty-mapping key while only provenance_sources moved.
