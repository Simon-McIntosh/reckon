A picker route launches the model it chose, not only its lane

A picker answer names a lane's own backend with the chosen model beside it, so a pick of codex and astra must launch gpt-6-astra rather than the lane's declared default gpt-6-sol. Before this change the route applied the picked backend and dropped the picked model, so the lane default was launched under the picked name — the recorded run said codex while the argv carried the wrong model id.

The picked model is applied exactly as --model narrows a named pair: the route resolves the model to the expanded backend entry of the picked lane that serves it, matching the model key, the model id and the alias. A model the picked lane does not declare is refused by name — the lane and the model both appear in the refusal — rather than launching the lane's declared default under the picked name. The narrowing lives beside the route in reckon/crew/dispatch_plan.py, so it needs no import of the --model path and the picked lane stays authoritative.

With the picked model applied, the launch argv carries gpt-6-astra and the run record's identity — derived from the agent block's model id through the catalogue resolver — reads back the pair (lane=codex, model_key=astra), so the row names the model that actually ran.
