The router decides on preferences; only a hard constraint excludes a lane

A reserved-lane policy, a competence verdict and a pacing ceiling below the account's own limit no longer remove a candidate. They travel beside it as evidence the router weighs: a reservation block carrying the intent, the tier floor, the attempt threshold, the window ceiling and its use, and any lift in force with its reason, plus a preferences list. Only a constraint that makes a lane unable to run the node still excludes it: context fit, an execution refusal, serving state, a paused gate, a budget verdict the account would refuse, and the lead's review exclusion.

The deterministic fallback, which has no router to ask, is the one place the preferences decide as rules: it keeps an unlifted reservation and places low-think work on the local lane while it has room.
