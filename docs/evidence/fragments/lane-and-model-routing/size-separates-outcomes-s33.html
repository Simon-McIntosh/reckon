Which dispatch-time size separates outcomes within a requirement

A read-only measurement of five candidate size signals and one control over the committed run records of every mounted project. It writes docs/research/what-sizes-a-node.html: one table per signal, the control included, with one row per cell and bucket carrying project, role, spec level, requirement, bucket, rows, passed, median attempts and median review total. A cell is one project, role, spec level and recorded requirement, and rows are matched as _candidates_scan matches them, through the picker's own _recorded_requirement and _picked_backend_away. The bar was fixed before any outcome was read: each compared bucket holds at least 5 rows and the pass rates differ by at least 20 percentage points; the control is judged on that alone; a signal separates a cell only when its own pair also clears the bar and its difference exceeds the control's difference there. Where the control clears the bar, that cell ranks nothing and names no signal.
