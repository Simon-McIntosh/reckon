A lane model key re-pointed to a new model id starts from its key's record

The flight schema gains an integer slot prior_outcome_threshold on RoutingConfig (minimum 1, regenerated into _flight_schema.py and flight.schema.json from flight.yaml). Candidate carries prior_outcomes: dict | None. _candidates_scan takes an optional key_counts out-parameter — the same idiom _fit uses for context_out — and, in the row loop it already makes, tallies each run a second time under the (lane, model_key) pair ledger.normalize_identity reports for that run, broken down by the model id the run was recorded under. A new _prior_block helper turns one key's entry into the gate vocabulary plus model_ids, excluding the candidate's own id and any run recorded with no id. In candidates, a candidate whose own model id holds fewer than prior_outcome_threshold outcomes (default 5, read from the routing config so a host or project layer retunes it) carries that block; at or above the threshold it carries none, so a candidate with enough history of its own renders exactly as before. Selection is untouched: the block is state Jev is shown, not a route.

Matching is by the pair the run record itself carries, never by today's lane default. A run recorded under model key astra counts toward astra even when the model id it was recorded under is now the default for a different key, so re-pointing a catalogue default cannot move a key's history to the key it now names.

Six new tests in tests/test_a_new_model_id_starts_from_its_keys_record.py. A key re-pointed from gpt-6-sol to gpt-6.1-sol leaves the new id with one passed and one failed of its own, and a prior block of 17 passed, 2 failed, 1 not-run naming ["gpt-6-sol"]. Five own outcomes means no prior block. Another lane gains nothing from this key's runs. A run recorded under a key that is not the id's current default counts under the recorded key. The rendered candidate state carries the block in the gate vocabulary and the glossary defines it. A declared threshold of 1 moves the point at which a prior stops being shown.
