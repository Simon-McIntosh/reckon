A named lane lets Jev choose its model

A dispatch that names a lane declaring more than one model, and names no model, now lets the picker choose the model inside that lane. Before this change --backend codex always launched the lane's declared default, so a lane offering sol, astra and luna could only ever run the one model its flight happened to declare first.

One owner carries the ask, in reckon/crew/dispatch_picker.py. It narrows the configuration to the named lane's backends through a sibling of _config_without_lane, built on _lane_backend_names, re-asks disabled, and puts that narrowed configuration through dispatch_picker_selection, so the picker is offered the lane's own models alone. The answer's model is applied through flight.select_lane_model, the same call plan_dispatch uses for a picker route's model. The lane never changes: a hold, a refusal, a fallback, a timeout or a model of another lane launches the lane default exactly as before, and the ask runs only where the resolved flight sets routing.picker: route, so a --model request, --local, a one-model lane and a paired or shadow arm all remain unasked.

The CLI's named-lane path (reckon/crew_dispatch_commands.py) and the review reflex (reckon/crew/recovery_review_dispatch.py) both call the owner, so a composed review of a run recorded on codex reaches the same ask as a coordinator's own --backend codex. The run still records route_mode: explicit; its picker_selection records the in-lane ask and its model_key records the model launched.
