The live-home guard skips a peer's in-flight store temporary

The listing arm of _writes_into_the_live_home in tests/test_a_pick_sees_each_lanes_burn.py now skips an entry named in the store's temporary form — a leading dot and a .tmp suffix — so a peer's dispatch caught mid-write in the live-pointer directory is not reported as a stray pointer. _store_temporary(name) is the predicate; the listing comprehension filters through it before deciding whether an entry names a run. The needle arm and the listing arm's refusal of a real stray pointer are unchanged.

Every live pointer is published through a sibling temporary named ....tmp in that same directory — reckon/_store.py's _open_sibling_temporary creates it and write_json_atomically renames it over the destination — so a peer's dispatch can leave one in the live-pointer directory between the guard's two listings. Caught mid-write it holds a partial record and names no run, which is exactly the shape the listing arm reports; a case that wrote nothing then fails on a peer's ordinary traffic.

The defect was reproduced before the repair. Two cases were added first and run against the unpatched guard (logs/repro-before-fix.log): 2 failed, 13 passed, EXIT=1. The in-flight case failed as AssertionError: a store temporary was read as this case's write with assert ['a file naming no run of its own appeared in the live-pointer directory: .burnfixture-leak.json.4242.0f3a1c9d.tmp'] == [], and the stray-beside-temporary case failed because the temporary was reported first, assert 'burnfixture-stray.json' in '…: .burnfixture-leak.json.4242.0f3a1c9d.tmp'.

Two cases stand up a temporary home and drive the guard's own helper against it, as the file's existing control does, and neither writes the operator's crew home. test_the_home_guard_ignores_a_store_temporary_in_the_live_directory creates a store temporary holding a partial record between the two listings and requires the guard to pass. test_the_home_guard_reports_a_stray_pointer_beside_a_temporary places the same temporary beside a pointer naming no run and requires the guard to still report the stray, so the skip is of the store's temporary form and not of every new entry.

The gate ran pytest -rA in the foreground over the file: 15 passed, EXIT=0 (logs/gate-pytest-rA.log). The negative control declared for this node — remove the temporary filter, run under pytest with the default short summary — produced 2 failed, 13 passed, EXIT=1, the two failures being the new cases (logs/negative-control-filter-removed.log); the worktree was restored to the fixed form afterwards and the gate re-run green.

Ruff judged the staged path against its base blob (logs/ruff-vs-base.log): ruff check is All checks passed! at both base and head, and ruff format --check reports 1 file already formatted at both. The change adds no finding and no format difference.
