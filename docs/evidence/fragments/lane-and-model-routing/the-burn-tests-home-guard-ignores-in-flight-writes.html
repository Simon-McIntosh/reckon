The live-home guard skips a peer's in-flight store temporary

The listing arm of _writes_into_the_live_home in tests/test_a_pick_sees_each_lanes_burn.py now skips an entry the store names as its own temporary — a leading dot and a .tmp suffix — so a peer's dispatch caught mid-write in the live-pointer directory is not reported as a stray pointer. The form has one owner: reckon/_store.py gains _sibling_temporary_path(path), which builds the sibling temporary path and is now the only place the name is constructed, and is_store_temporary(name) beside it, which answers whether a name has that form. _open_sibling_temporary renders its candidate through the builder; no behaviour of the write itself changes. The predicate replaces the copied expression in all three test files that carried it — this node's file, tests/test_runs_pointer_writer_reuses_the_store.py and tests/test_supervisor_write_reuses_the_store.py — so a writer whose form changed can no longer drift away from three independently written copies. The needle arm and the listing arm's refusal of a real stray pointer are unchanged.

Every live pointer is published through a sibling temporary named ....tmp in that same directory — reckon/_store.py's _open_sibling_temporary creates it and write_json_atomically renames it over the destination — so a peer's dispatch can leave one in the live-pointer directory between the guard's two listings. Caught mid-write it holds a partial record and names no run, which is exactly the shape the listing arm reports; a case that wrote nothing then fails on a peer's ordinary traffic.

The defect was reproduced before the repair. Two cases were added first and run against the unpatched guard (logs/repro-before-fix.log): 2 failed, 13 passed, EXIT=1. The in-flight case failed as AssertionError: a store temporary was read as this case's write with assert ['a file naming no run of its own appeared in the live-pointer directory: .burnfixture-leak.json.4242.0f3a1c9d.tmp'] == [], and the stray-beside-temporary case failed because the temporary was reported first, assert 'burnfixture-stray.json' in '…: .burnfixture-leak.json.4242.0f3a1c9d.tmp'.

Two cases stand up a temporary home and drive the guard's own helper against it, as the file's existing control does, and neither writes the operator's crew home. test_the_home_guard_ignores_a_store_temporary_in_the_live_directory creates a store temporary holding a partial record between the two listings and requires the guard to pass. test_the_home_guard_reports_a_stray_pointer_beside_a_temporary places the same temporary beside a pointer naming no run and requires the guard to still report the stray, so the skip is of the store's temporary form and not of every new entry. test_the_store_temporary_predicate_matches_the_name_the_store_writes asserts the predicate against a name _sibling_temporary_path actually produces and rejects an ordinary pointer name, so the writer and the predicate are checked against each other rather than against a literal that could go stale, and the predicate's two arms are exercised rather than only its skipping arm.

The listing arm now exempts a leak written under the store's temporary form, and that is an accepted cost: a case that left a file named .something.tmp in the live-pointer directory is not reported by the listing arm. The needle arm still closes the material gap, because it reports a pointer filed under an identifier this case minted whatever its name, and a real stray pointer — the shape a peer cannot produce — is still reported.
