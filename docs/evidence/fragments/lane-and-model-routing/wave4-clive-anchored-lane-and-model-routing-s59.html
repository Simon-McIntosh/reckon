A dispatch waits for the router's answer, and a default route is never silent

A dispatch asked the picker inside a five-second bound, and on expiry it placed the request on the configured default lane and returned a selection that read as an ordinary fallback: a route the router never weighed, indistinguishable from one it gave. Three things changed. The bound is 120 s by default and a flight's routing.picker_timeout_seconds sets it (reckon/crew/dispatch_picker.py, picker_dispatch_timeout). The section's capability and declared effort are resolved by the dispatcher before the ask (dispatcher_declared_difficulty) and travel on PickRequest as capability and estimated_hours, so the pick's own difficulty step resolves nothing inside the bound (reckon/crew/picker/__init__.py, _declared_difficulty returns on the "request" source). A pick still running at the bound now sets awaiting_pick on the selection, and plan_dispatch stores the request as a queued pointer with reason: awaiting-pick and raises the lane hold that reports where it waits, rather than routing it. A stored request whose pick never answered is picked again at launch through the existing launch_route_* decision, which reads its awaiting_pick marker as a re-pick.

A review of that work scored reuse at 5 against a floor of 10, and the repair removes the duplications rather than documenting them. The dispatcher's difficulty resolution is now delegated to the picker's one owner of the plan lookup, so a node's own estimate keeps its precedence in _declared_difficulty's order (node, then section, then plan) instead of being overwritten by the section's figure. The request a held pick stores is built by reckon/crew/dispatching/requests._queued_request_record, the shape's one owner, so it carries the same keys as every other held request: due, urgency, dispatch_options, queued_at and hold, with the picker selection passed through rather than copied. The pick's within-bound telemetry reads picker_dispatch_timeout, the resolver dispatch itself applies, so a host that sets the flight bound moves the flag with it.

A pick that fails rather than expires still falls back, and the fallback names the step it gave up in. Both boundaries record that step before they let the pick's failure go: the dispatcher records the stage whose build raised, and the pick keeps the last step it entered past the step's own clear. The step the fallback reports used to be the fixed word pick, which no assertion could contradict. A run placed on a default route is also listed by the obligations view as the non-blocking notice route-defaulted, carrying the step and the failure's own text, so a lane the router never chose is visible to a coordinator rather than only in a dispatch's own output.
