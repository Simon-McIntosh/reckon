a-pick-sees-each-review-dimension — a pick's at-requirement block reads each review dimension's median and the fully scored review count

Change. A candidate's at-requirement block in reckon/crew/picker/snapshot.py reported one review-total median and never said how many rows it covered, so a total that hid a weak dimension read the same as one that did not. _candidates_scan now collects a fully scored matched row's scores into one list per name in REVIEW_DIMENSIONS in its existing single pass and counts those rows, beside the reviews, walls and attempts lists it already kept. A row is fully scored when its review.scores holds a real number (never a bool) for every dimension, so a review the parser recorded with a dimension absent, or one scored before reuse existed, feeds the dimension lists and the count not at all while its recorded total still counts toward review_total_median. _requirement_block adds reviewed, the count of fully scored matched rows, and review_dimensions_median, each dimension's median over exactly those rows rounded to one decimal and keyed in REVIEW_DIMENSIONS order, null when reviewed is 0. The dimension names are imported from reckon/crew/review.py as the source of truth rather than copied. The outcomes_at_requirement glossary entry in reckon/crew/picker/prompts.py defines both fields and says review_total_median may rest on a different number of rows. Nothing else changed: the question template's instructions, the outcomes and moved_in blocks, the hold logic and dispatch are untouched, and no pick is routed or overridden.
