a-pick-names-the-step-it-expired-in — a deadline inside pick() names the step pick() is itself inside

A dispatch bounds the picker call, PICKER_DISPATCH_TIMEOUT_SECONDS (5 s) in reckon/crew/dispatch_picker.py, and the deadline can expire at any step the pick runs. Before this change the dispatcher knew only its own input stages, so a pick that outlasted the bound inside the picker call read the bare fallback_reason: "timeout" — blaming the picker whether the slow work was the state render, the estimate, or the Jev call. pick() now marks the step it is inside in a sink the dispatcher hands it (running["step"]) and clears the mark when the step returns; the dispatcher names that step in pick()'s own vocabulary. The name is derived from the step's own timing key by _step_label: the _ms suffix is dropped and underscores become hyphens, so state_render_ms reads timeout in pick:state-render and jev_ms reads timeout in pick:jev.

One vocabulary, not two. PICK_STAGES in the dispatcher is now only the dispatcher's own stages — the ledger records, the verdict inputs, the budget snapshot and the context estimate — and no longer carries a "jev" entry mirroring a step name that belongs to pick(). The jev timing key is gone from the dispatcher's stage_ms; a step inside the picker call is named by the pick, from the sink, rather than by a list kept beside it that can drift. A pick that marks no step, or that spent the budget in a dispatcher stage instead, keeps the previous reading: the dispatcher's own stage name, and the bare timeout when neither applies.

The pick's collaborators resolve where they are read. pick()'s snapshotter and caller defaults are now None and resolve to snapshot.candidates and client.ask at call time, so a check can replace the candidate scan or the Jev client at the module it is read from instead of replacing pick() wholesale. That is what lets the new checks exercise the real pick — and therefore the real step marking — while making one step slow.

The hold recorder drops an argument it never used. record_picker_hold in reckon/crew/picker/outcomes.py writes its hold under the crew home, so its docs parameter was dead weight; the recorder no longer declares it and both call sites in reckon/crew/dispatch.py stop passing it. Because three test files outside this node's write scope still call the recorder with docs=, the recorder accepts and ignores it through a **_legacy catch-all, so those callers keep working and still record their hold. This is the one place the implementation departs from the node's spec, which assumed the parameter could be dropped outright; it is recorded in the manifest as a deviation. The shared crew-home log helper in reckon/crew/picker/__init__.py now states its never-fail contract for both its callers — the pick's own timing line and the state render's per-read counter.
