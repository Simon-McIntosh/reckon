The repair round: one shape, one parser

A review of the first round returned four findings, and they were one defect seen from four sides: the change had left two spellings of the account answer alive and two parsers for the same rule, so a reader could not tell which was canonical. The repairs are:

  1. The reset stamp is validated through reckon/_timestamps.parse_iso, the module that owns the Z-suffix and strip handling, rather than a local datetime.fromisoformat call. A repository-wide invariant names that module as the only caller of fromisoformat; it passes at this head.
  2. The compatibility read for the nested windows spelling is deleted, and the tests that asserted it — three named by the review, and a fourth that went red the moment the read went — are migrated to the top-level windows. One answer shape now crosses the boundary.
  3. The windows are keyed by their length in minutes, which is the key every other quota map in the module carries. The first round keyed them by name, which the lane view then read as a number and failed on — found by the migration, not by inspection.
  4. Lint and format are re-run on the changed paths at this head, judged against the base blobs: format clean, and the check's three findings are all present in the base, so the commit adds none.

The measurement is a bounded arm over the twelve test files that reach the changed modules plus the structural invariant: base 132 passed, head 140 passed, both exit 0, with no identifier failing in one arm alone. The literal importer population is 171 files and does not fit the node's window — a run over all of them was bounded without reaching its cut — so that run is logged and the bounded arm is what is claimed. The negative control was re-applied to the repaired head and still fails exactly the one case it was declared to fail.
