A reset is one durable event, whether or not a flag was there to clear

At the base revision budget_reset.mark_used returned changed: false and wrote nothing whenever no banked flag was available, so a reset the lead announced left no record at all — the eleven idle sessions had nothing to read. It now appends a used event to the group's record either way, carrying id (reset-<group>-<UTC stamp>), detected_at (now, or the instant --from names), clock, by, reason and session (absent for a global event). Only a global event clears an available flag, because that is the account's own reset arriving; a session-scoped one is a rehearsal that reaches one session and leaves the flag standing. A global event for a group and clock that already carries a global event within ten minutes returns that event and writes nothing, so several sessions relaying the same news produce one record. Consumed events, which observe already wrote when the window readings show a banked reset spent early, gain an id in the same form, and the new budget_reset.recent_resets(session=None, now=None, horizon=...) reads both kinds across every group that apply to a session within the horizon. crew budget --reset --used passes --reason, --from, --clock and --session through and refuses a used reset with no reason, and crew budget --list shows the last 24 hours' events beside the lifts through the same reader.
