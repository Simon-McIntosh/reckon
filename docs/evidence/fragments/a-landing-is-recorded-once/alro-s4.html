§4 — A plan does not close over a section with no landing line

The terminal guard list in validate_landing_patch now carries _require_every_landed_section_answered, so the close op and the merge-patch writer refuse together. A section declared done that states a done-when must hold a landing comment on the section or a committed run record naming it; the refusal names every section it refuses on. A done section that states no done-when is outside the rule. The check is keyed to the transition into a terminal status, so a plan that has already landed stays editable.

The rule applies to a section marked done after it landed. The store records no per-section tick time, so the rule reads the section's own last recorded activity — the newest comment on it, or the completion time of a run whose ledger record names it, whichever is later — and compares that with one fixed instant, 2026-11-15T10:05:58Z, held as LANDING_ACCOUNT_ENFORCED_FROM. A section recorded before it, or recorded nowhere at all, was already done when the rule landed and owes nothing; a plan edited afterwards cannot move a section across that line, and no side of the comparison reads the clock, so a fixture's expectation cannot expire with the calendar.
