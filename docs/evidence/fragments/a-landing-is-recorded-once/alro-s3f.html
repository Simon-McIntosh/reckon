§3 — Every plan-keyed ledger read resolves a run's plan the same way

ledger._row_plan gave the plan-selected run read one owner for a row's plan, but three other readers in reckon/ledger.py still read the row's top-level plan field directly, so a brief-carried run fell into the empty-plan bucket everywhere else. All three reproduced over a temporary store: a promoted brief-carried run naming a plan, read through review_scores(runs, plan=NAMED), returned []; effort_report reported one row, for "", with all three runs in it; and summary()["plans"] read [''] with the named plans absent.

Decision. Each reader takes the plan from the one resolver: the scored read selects and reports on _row_plan(record), the effort rollup buckets by it, and the plans index is sorted({_row_plan(record) for record in records}). No second resolver was added and each read stays where it was — the scored and effort reads still filter decoded rows, and the plan-selected run read keeps its filter inside the index query.

The stored-row half. The version bump that forces re-extraction of stored rows had no test: every case read a cold index over a fresh store. The new case builds an index under the earlier extraction — the row's own field alone, under that extraction's own projection version, so the index entry carries no plan while the row's node definition names one — and then reads through the current code, which returns the row for its plan. With the index version returned to its earlier value the same case fails, because the warm planless entry is reused and the row is missing from its plan's read.

Measure, over a temporary store built through write_run_file: tests/test_a_brief_carried_run_keeps_its_plan.py reports 8 passed at the head, adding one case per reader (scored read, effort rollup, plans index — each counting the brief-carried run under the plan it names and keeping the run naming no plan in the "" bucket) and the stored-row case. The negative control runs the same file with _RUN_INDEX_VERSION returned to 6: 1 failed, 7 passed, the failure being test_a_row_indexed_under_the_earlier_extraction_is_read_for_its_plan with assert 'r-20260102T000001000-alro-stored' in set().
