A named figure is held to what the run delivers

What changed. The manifest check (reckon/crew/reports.py, audit_manifest, read by crew check --manifest) now reads a figures: line. A named figure is held to three facts, because the name alone establishes none of them: the path lies inside docs/figures/; it lies under the figure directory of the plan the node builds; and the run's own commits carry it. A figure a worker rendered to look at but never committed is refused, naming the path.

The commit fact is read from the committed head against the base the manifest records at orientation. A stale or unresolvable base leaves that half of the check unarmed rather than reporting every named figure as orientation-unreadable, which is the same ground the PNG-twin check stands on. A node with nothing to show names none, and an absent or empty line is accepted: there is no quota.

The prompt states the rule. The plan landing contract in reckon/crew/prompts.py already placed a figure under docs/figures/<plan>/<node-id>/; it now also names the figures: manifest line and the directory the check holds it to, so a worker reads the placement and the record of it together.

Measured
