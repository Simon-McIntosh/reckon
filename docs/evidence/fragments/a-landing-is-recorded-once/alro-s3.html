One sourced overview per closing plan

synthesize_landed_record now renders the plan's landed record as a sourced overview instead of a per-section dump of comments and run tables. read_section_landings is the single reading of what a section landed — its landing comment, its implementing runs and the figures those runs named on their manifests — so the close guard and the sprint page can answer the same question from one derivation rather than two populations.

The record holds, in order: the ledger-sourced summary; one paragraph per section naming what it set out to do, quoting its landing line and giving the latest attempt's measured result; one table with one row per landed node stating its attempt count; each figure a run named, with a project-absolute src and its caption; and totals for runs, attempts and worker time against declared effort. A section that did not land gets one sentence giving its declaration. Every sentence in those blocks carries a source element naming the record it rests on — a run id, a comment id, a plan section, a figure path or the ledger.

The blocks this renderer owns carry data-evidence-origin="overview", so a re-synthesis replaces its own reading instead of carrying the copy already on disk forward, and the appended anchors beneath it are still carried exactly as before.

Reading: reckon/evidence.py. Gate: tests/test_a_closing_plan_gets_one_sourced_overview.py.
