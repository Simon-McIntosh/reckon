A run's gate declares the command and partition its arms ran with, and a hand-merged run is recorded

Promotion compared every run's suite arms against the project's single armed command, so a GPU node on a project armed with a CPU-pinned command recorded arms that could never match, and its work could not land without re-running a command that dies on the armed partition. A run now declares its gate's command and partition on its live pointer through reckon crew declare-gate; _declared_command_text reads that declaration before the project's arming, and landing_measure.armed_observations takes the declared partition (and its long-partition bound) for the measurement a landing would run. A pair that still cannot be matched is waived with a written reason, which the row records beside the arms actually held; an added failure is still refused under that waiver. A pair differing only in its command is refused from the record without submitting a scheduler job.

reckon crew record-merge records a run whose reviewed head already reached the primary branch: it resolves the merge and the run's reviewed head, requires ancestry both ways, writes the row naming the merge, retires the pending landing record before and after the promotion, and _evaluate_suite_delta returns not-run naming that merge rather than measuring a change the branch already carries. On all_debug the node's two test files plus tests/test_staged_write_inventory.py and tests/test_every_shared_home_lock_holds_across_nodes.py read 55 passed at base cb00d30e70 (the two new files do not exist there) and 62 passed at head 905128fb92, zero added failures, both arms EXIT=0 on -n 4.
