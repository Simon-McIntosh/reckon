A released composed review leaves the run owing one

_release_stranded_launches removed a stranded launch's claim, pointer and run directory — including a composed review's last mention on the run it reviewed. That run's dispatch record still named the released review as dispatched on the lane at that head, which is the released attempt's lane and not a lane that refused the revision. _failed_review_backend reads exactly that record to withhold a lane, so the next reflex pass found no candidate lane at all: the review for r-delivered-awaiting-review has no eligible lane (backend 'clive' already dropped it), reported with awaiting_lane and nothing launched. Two reviews were lost this way on 15 November and a coordinator dispatched each again by hand.

The release now writes its outcome onto the reviewed run's record through the reflex's own dispatch record builder, with the status the reflex already uses when it releases a stranded standing review itself (released-stranded-launch). The run reads as owing its review again and the next pass composes one for the same run and head. The write is skipped when the reviewed run has since been promoted or discarded, and when its record now names a different review; a requeued stranded request takes the same early exit it already did, so the write happens only on the plain release.
