The verdict row names the implementation role as a run pointer does

What changed. reckon/crew/admission/ordering.py now spells the implementation role implement (IMPLEMENTATION_ROLE), so the roles map a pass writes to admission-verdicts.jsonl carries the same two role values a run pointer carries — implement and review — and a reader can join a pass's per-role figures to the runs they count. The role string is a key only: _role_of classifies a request and role_cadence counts it, and no ordering decision reads the spelling, so the seat order is untouched.

The defect, reproduced before the repair. On the base tree the same twelve requests — nine implementations ahead of three reviews, one project — produce a cadence keyed

cadence keys: ['implementation', 'review']
pointer roles: ['implement', 'review']
unjoinable: ['implementation'] ['implement']

Neither side contains the other's key, so the implementation side of every verdict row was unjoinable. After the change the same probe prints cadence keys: ['implement', 'review'] against the same pointer roles.

The test that could have passed on nothing. The verdict-row case in tests/test_reviews_and_implementations_share_the_seats.py queued each pointer by copying the shared fixture's pointer and then overriding every field from the ordering case — including backend: "local", a backend no config in the test defines. Every request was therefore refused, the pass launched nothing, and the row it asserted on was the shape a stalled cadence writes: review 0 launched / 3 waiting, implement 0 launched / 9 waiting. The assertions only summed launched + waiting, so that the launched count was zero never failed. The case now takes the fixture's own backend and dispatch options and changes only the identity and the queue position, and it asserts three things against the row it reads back:

  • the role values read back from the queued run pointers are exactly {review, implement}, and the row's role keys equal that set — the join the defect broke;
  • the launched counts across roles sum to the pass's seats (SEATS = 3), so a cadence that launches nothing fails;
  • each role's launched + waiting still accounts for its whole backlog.
