Dispatch reads the fleet record through its owner

reckon/crew/dispatch_launch.py no longer resolves the fleet record's path itself. _fleet_record_path is deleted, together with its re-export from reckon/crew/dispatch.py, and _read_fleet_record asks the owner — fleet_supervisor.state_directory() joined with fleet_supervisor.RECORD_NAME — keeping only the RECKON_FLEET_RECORD override that tests and operators set. The two resolvers disagreed whenever FLEET_NAME was set: the owner put a named fleet's record under …/fleet/fleets/<name>, while the dispatcher's copy looked under the catch-all directory and found nothing, so a launch read an absent record as an absent fleet.

Measure: tests/test_dispatch_reads_the_fleet_record_through_its_owner.py passes 3 of 3. With FLEET_NAME=alpha and RECKON_FLEET_RECORD unset it asserts the record written at state_directory()/record.json is read, and that state_directory() is the named fleet's own …/fleet/fleets/alpha. The negative control — the XDG_STATE_HOME default restored in _read_fleet_record — fails exactly that case at EXIT=1. The importer gate ran 131 test files at head (1 failed, 1271 passed, 1 skipped) and 130 at base (1 failed, 1268 passed, 1 skipped): the one failure is the same id in both arms, tests/test_a_crashed_producer_is_restarted.py::test_repeated_crashes_reach_a_reported_limit, a 20-second wall-clock bound that fails in the base tree as well when the node is loaded, so no failure is added by this change.

  • A named fleet's record is read where the owner resolves it.
  • An explicit RECKON_FLEET_RECORD still wins over the owner's path.
  • A named fleet with no record reads as no record.
