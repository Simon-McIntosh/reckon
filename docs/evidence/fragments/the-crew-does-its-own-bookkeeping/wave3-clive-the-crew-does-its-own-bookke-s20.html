A review brief follows the reviewed run's head

Defect reproduced at base 47d4d53612. A review brief reached a run's directory only when a review dispatch named it, so nothing wrote one at the run's delivery. The three cases of the new test, run against a checkout of that revision, all failed with the brief absent — including the case that defers the run's obligations first, whose assertion read AssertionError: assert False ... review-brief.md.is_file(). A resumed run therefore kept whichever brief an earlier dispatch had written, and a run whose obligations a coordinator deferred advanced no dispatch at all and never got a brief, which is the report the section opened on.

The repair puts the writer at the delivery itself. recovery_review_subject.write_delivered_run_review_brief composes the brief from the head the run's tree carries now, through the same _review_brief_text a dispatch uses, and the launch supervisor calls it when it advances a live pointer to its delivered phase — the one place a run's delivery is recorded. A launch failure is not a delivery and writes nothing; a run whose head resolves to nothing gets no brief rather than one naming an unknown revision; and the brief is left untouched when it already names that head, so a delivery that moves nothing costs no write. The deferral is never consulted: an acknowledgement puts work off, it does not change what the section's deliverable is.

Measure. At the repaired head the same three cases pass (3 passed), driven through the supervisor's own pointer advance rather than by calling the composer, so a writer that ran anywhere but at delivery fails them. The negative control replaces the writer with one that composes the brief only when none exists on disk: the first delivery still writes it, and the delivery after a resume then leaves the old head, failing test_a_resumed_run_s_brief_names_its_new_head with the two revisions named (1 failed, 2 passed, EXIT=1).
