A disposition names the review it writes

The defect reproduced at base revision e3f3aaf7cc in a temporary crew home and repository: a run whose worktree head stands at a revision later than both of its reviews, with review r-20261010T100000000000-review-of-the-earlier-head promoted into the project's committed tree and r-20261010T110000000000-review-of-the-current-head delivered into the staging store and unpromoted, crew dispose --finding 0 --kind exempted --reason because exited 0 and wrote its disposition onto the earlier record. The selection path that returned it is stored_review_descending_from in reckon/crew/review_records.py, which searches only the committed tree, so the newer staging round is invisible to it; the receipt's path was the only sign, which is exactly what the report described.

crew dispose now accepts --review <review run id> and resolves that review run's own record through the new record_for_review_run_anywhere in reckon/crew/review_records.py — committed tree first, staging store after — writing onto that record alone. Without --review, a call whose selected record is not the run's newest delivered review, read through the new newest_delivered_review, is refused: the refusal names the newer review run and states both remedies (--review <id>, or crew complete --run <id> to promote it). Every successful receipt now carries review_run_id and reviewed_head beside path.

Measure: tests/test_a_disposition_names_the_review_it_writes.py — 4 passed at this head, and the same file with the newest-review check removed gives 1 failed, 3 passed, the failing id being test_a_call_naming_no_review_is_refused_when_an_older_round_was_selected, whose receipt shows the call writing r-20261010T100000000000-review-of-the-earlier-head. The other three cases show the named call writing onto the newer record only while the earlier record stays byte-identical, every receipt's review_run_id and reviewed_head, and an unknown --review refused. The 14 test modules importing reckon.crew_run_commands plus the new file give 378 passed at head and 374 passed at the base archive, for zero added failures. ruff check and ruff format --check are clean on all three staged paths.
