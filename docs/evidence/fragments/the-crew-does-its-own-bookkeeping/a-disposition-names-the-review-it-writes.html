A disposition names the review it writes

The defect reproduced at base revision e3f3aaf7cc in a temporary crew home and repository: a run whose worktree head stands at a revision later than both of its reviews, with review r-20261010T100000000000-review-of-the-earlier-head promoted into the project's committed tree and r-20261010T110000000000-review-of-the-current-head delivered into the staging store and unpromoted, crew dispose --finding 0 --kind exempted --reason because exited 0 and wrote its disposition onto the earlier record. The selection path that returned it is stored_review_descending_from in reckon/crew/review_records.py, which searches only the committed tree, so the newer staging round is invisible to it; the receipt's path was the only sign, which is exactly what the report described.

crew dispose now accepts --review <review run id> and resolves that review run's own record through the new record_for_review_run_anywhere in reckon/crew/review_records.py — committed tree first, staging store after — writing onto that record alone. Without --review, a call whose selected record is not the run's newest delivered review, read through the new newest_delivered_review, is refused: the refusal names the newer review run and states both remedies (--review <id>, or crew complete --run <id> to promote it). Every successful receipt now carries review_run_id and reviewed_head beside path.

Review found three follow-on defects in that repair, all now fixed. Ordering: newest_delivered_review ordered rounds by the record file's modification time, and because a disposition rewrites the record it answers, writing onto an older round moved that round past the newer one — so the next unnamed call read the answered round as current. It now orders by the record's dispatch stamp, then by the dispatch instant the review run id itself encodes, with file mtime only as a tie-break. Reachability: the crew tool's dispose action had no review parameter, so the remedy the refusal names could not be reached through the tool surface; reckon/mcp_crew_actions.py now maps it. Printed remedies: dispose_commands in reckon/crew/review_dispositions.py rendered fold and exempt commands without --review, so a command a duty printed would itself be refused; it now names the review run the duty answers.

Measure: tests/test_a_disposition_names_the_review_it_writes.py — 7 passed at this head. The first four cover the repair itself: with the newest-review check removed the file gives 1 failed, 3 passed, the failing id being test_a_call_naming_no_review_is_refused_when_an_older_round_was_selected, whose receipt shows the call writing r-20261010T100000000000-review-of-the-earlier-head; the named call writes onto the newer record only while the earlier record stays byte-identical; every receipt names review_run_id and reviewed_head; an unknown --review is refused. The three added cases cover the review findings, and each was shown to bite by a targeted mutation: with the ordering reverted to file mtime, test_a_rewritten_older_round_does_not_read_as_the_newest fails (the rewritten earlier round reads back as newest); with the tool's parameter map entry removed, test_the_crew_tool_carries_the_review_argument fails (the unnamed call is refused and the named remedy is unreachable); with the review flag dropped from the rendered command, test_a_rendered_disposition_command_names_its_review fails. The 28 test modules importing the four changed modules give 475 passed at head and 468 passed at the base archive, the seven-case difference being the new file itself, for zero added failures in either direction. ruff check and ruff format --check are clean on all five staged paths.
