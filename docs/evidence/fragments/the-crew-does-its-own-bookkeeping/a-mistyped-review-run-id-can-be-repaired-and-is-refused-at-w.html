A mistyped review run id can be repaired, and is refused at write time

The defect reproduced at base revision bc6d7fd9f1 in a temporary crew home: a record delivered into the reviewed run's review-records directory carrying review_run_id r-20261110T233217626304-review-of-ripple-relations, a prefix of the review run that wrote it. review_record_refusals returned [], so the record filed as valid; crew repair --review --run <review run> --set review_run_id=<full id> exited 1 with record is outside the reviewed run's review-records directory, because the location check resolved the staged directory from the run id it was handed rather than from the record's own subject; and crew check --review --run <review run> exited 1 with run … has no stored review, because the store answers for the reviewed run and nothing read the declared path.

Three changes. crew check --review --run <review run> now locates the record the review run actually declared — the head-keyed path crew complete itself reads — and, when the pointer names a review-role run, adds a refusal naming the expected id whenever the record's review_run_id is not that run's own; the --record form is unchanged and still accepts a record whose id cannot be checked without a writing run. repair_run_review accepts --set review_run_id=<id> only when the stored value is a prefix of the requested id, and its location check accepts the review-records directory of either the run it was handed or the record's own reviewed_run_id, so the review run may be named. The anchor is checked against the record's reviewed run, its stored review run and the requested id, so an unrelated run id is still refused.

Measure: tests/test_a_mistyped_review_run_id_can_be_repaired.py — 5 passed at this head. The four done-when cases are the check's refusal naming the full id, the repair writing the full id after which review_delivery_refusal no longer reports record names a different review run, the repair refusing an id that does not extend the stored one with the record byte-identical, and the location check accepting the record when --run names the review run. The fifth holds the guard the looser location check could have dropped: a record outside every review-records directory is still refused. The negative control removes the prefix rule and the repair case fails (1 failed, 4 passed), while every case the head arm runs passes. The two suite arms give 56 passed at head and 2 setup errors at base, both attributed to the archive extraction having no git object store for the staged-write census's git ls-tree HEAD; tests/test_review_record_contract.py, the nearest importer of both changed modules, gives 62 passed. ruff check and ruff format --check are clean on the three staged paths.
