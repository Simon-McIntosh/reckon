A repaired status moves the run's phase with it

crew repair --status rewrote the manifest's verdict and left the live pointer's phase as it was. The live view reads the phase and the classifier reads the manifest, so after a repair the two named different runs: at base 4cae3c76ca a blocked run repaired to complete reads effective_phase: blocked to crew view live while the reflex's own pass classifies it scoring and composes the review dispatch the view also offers. That pair is the incident's shape — a view that calls a run halted beside an offer to dispatch a review of it.

The repair now writes the pointer's phase onto the verdict it writes into the manifest (reckon/crew/runs.py, repair_manifest_status), taking the one lock every pointer writer takes, so one record describes the run. The repair's own status-repair.json states the phase it replaced beside the phase it wrote (previous_phase, pointer_phase), and a repair on a run whose pointer is gone still rewrites the manifest, recording both as null.

The measure. tests/test_a_repaired_status_moves_the_run_phase.py drives a temporary crew home from a blocked run, reads it through crew view live and through recovery.recover (the reflex's own pass), repairs it to complete, and reads both again. After the repair the live row reads effective_phase: complete with manifest_status: complete, both readers name classification: scoring and recovery: review, and the row no longer offers the blocked run's action (resolve the blocker). It still offers the review dispatch, which is the same act the reflex's pass takes from the same classification — one act named by both readers, rather than a halted reading beside a dispatch.

The negative control. The declared mutation removes the pointer phase write from the repair, which is the code as it stood. The run then fails at assert live["effective_phase"] != "blocked" (assert 'blocked' != 'blocked') while the manifest already reads complete — the two readers disagreeing, which is the defect. Its log is negative-control.log under the run directory.
