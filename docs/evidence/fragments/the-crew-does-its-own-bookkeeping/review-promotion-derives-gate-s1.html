A review's promotion derives the gate it carries

At base 39c52edbf709fb345de519ffbdd6d477aa2a88ef, a review run promoted with --gate passed and no gate flags had its own stored record cited as the gate log, and the record is JSON with no terminal EXIT=<n> line: the first two cases of tests/test_a_review_runs_promotion_derives_its_own_gate.py refused with carries no terminal EXIT=<n> line. The base arm reported 3 failed, 62 passed, the third failure being the fifth case, whose fixture log carried no pytest summary beside a pytest command and so measured the guard rather than the behaviour it names.

The check is now performed instead of cited: test -s over the delivered record is evaluated and its outcome written to review-gate.log in the review run's own directory, ending in the terminal EXIT=<n> line promotion reads its status from (_derived_review_gate_log in reckon/crew/promotion_evidence.py, called from _review_record_check in reckon/crew/promotion_records.py). The log is rewritten only when its content would change, and is captured only where the promotion will cite it, so a caller's own --gate-command/--gate-log-path or a log the manifest names is never shadowed. The total a record does not state is still derived from its six scores on the way into the committed tree.

The test that decides whether a cited log owes a pytest summary reads the command's words for the program's own name rather than matching the name inside a longer word, because a file test over a path stored under a directory named for the runner executes no pytest. The predicate was not widened: a command whose word is pytest is still held to its summary. The fifth case's fixture log now carries 1 passed in 0.01s before its EXIT=0, so the case measures that a caller's own check is kept rather than that its fixture is the shape the guard accepts.
