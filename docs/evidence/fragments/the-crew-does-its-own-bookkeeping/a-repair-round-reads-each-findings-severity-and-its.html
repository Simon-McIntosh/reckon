A repair round reads what each finding says it is

A review finding states its severity either in a severity field or by opening its claim with the severity and a colon. Only the field was read, so three findings whose text began "non-blocking:" carried no declared severity, were classified blocking, and resumed the reviewed worker as a round with advice reading "found 3 blocking finding(s)" — for work the reviewer had said did not block, and after the coordinator had already exempted all three and merged the reviewed head.

declared_severity in reckon/crew/review.py now reads the claim prefix when the finding carries no severity key, so the repair reflex and the landing gate's _finding_blocks classify such a finding alike. The explicit field still wins wherever both are present, and a value outside the vocabulary is still no declaration rather than an invitation to re-read the prose.

A finding that states neither a field nor a prefix stays blocking, because the reviewer's silence is not a non-blocking judgement. The round's advice now counts it apart: the "found N blocking finding(s)" figure excludes it and a following line names it unclassified. A record stamped before the severity audit began flags no such finding and reads exactly as before.

The reflex also starts no round for a reviewed head the integration branch has already moved past. The run's repository is the project's shared checkout, so its checked-out branch is the branch a coordinator lands on; a reviewed head that branch carries means the work the findings describe is integrated, whether promotion or a hand merge put it there. The branch's own tip is excluded, because a head sitting exactly where the branch sits is the tree the run holds rather than work the branch took in beyond it, and an unreadable answer — no repository, a detached checkout, an unresolvable revision — never starts nor stops a round on its own.

The new test drives four states through recovery.dispatch_repair_for_run on a temporary crew home and repository: three prefixed non-blocking findings start no round and each reads non-blocking to the landing gate; one undisposed blocking finding starts the round; a blocking finding on a head the branch moved past starts none; and a record stamped after the audit with one blocking and one unstated finding starts the round with advice reading "found 1 blocking finding(s)" that names the other unclassified. Removing declared_severity's prefix reading makes the first case start a round and fail.
