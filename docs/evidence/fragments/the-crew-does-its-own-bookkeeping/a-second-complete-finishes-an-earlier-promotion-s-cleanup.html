A second complete finishes an interrupted promotion's cleanup

What changed. A promotion writes the plan comment, appends the ledger row, then retires the live pointer and releases the worktree. A landing that stops after the row leaves the run recorded by the ledger and still live through its pointer, which no recovery verb clears because the row already exists. The next crew complete refused twice over, both refusals raised inside _report_written_ledger_row's span and reported as one message: “the ledger row for run ... is already written; do not re-promote. Landing or cleanup failed: landing comment ... already contains a different narrative; refusing to report the corrected outcome as recorded”.

The reproduction, captured before the repair. The repair. The committed ledger row is the record of the promotion, so a call that finds one is finishing that promotion's cleanup instead of promoting again. _record_landing_comment now reports a differing narrative beside the receipt rather than raising it, names both narratives (kept_narrative, requested_narrative) in one note, and leaves the comment the first promotion wrote untouched. Before the row exists the first narrative still pins the outcome, so a differing one stays a refusal; that branch is decided by _ledger_row_is_written, which answers written only when it can show the row, so an unreadable ledger is never read as a promotion the run already landed. The promotion path itself is unchanged and is not in this node's write scope.
