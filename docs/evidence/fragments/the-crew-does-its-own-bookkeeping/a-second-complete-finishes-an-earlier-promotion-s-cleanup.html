The repair. The committed ledger row is the record of the promotion, so a call that finds one is finishing that promotion's cleanup instead of promoting again. _record_landing_comment now reports a differing narrative beside the receipt rather than raising it, names both narratives (kept_narrative, requested_narrative) in one note, and leaves the comment the first promotion wrote untouched. Before the row exists the first narrative still pins the outcome, so a differing one stays a refusal; that branch is decided by _ledger_row_is_written, which answers written only when it can show the row, so an unreadable ledger is never read as a promotion the run already landed. The promotion path itself is unchanged and is not in this node's write scope.

Repair round: reuse. The first landing carried three copies of things the tree already had. The receipt reduced a stored comment to plain text with a local regex rather than the plan reader's tag stripper; whether a run's row is written was asked by a second ledger read beside the receipt's own; and the new test built its own config home, repository and pointer beside the reconciliation tests' fixture for the same promote-and-retry path. The narrative now goes through _strip_tags, one reader answers the row's state as True, False or None and each caller applies its own reading of an unreadable ledger, and the test imports the sibling fixture and keeps only the assertions this case adds. Behaviour is unchanged: both arms of the repair gate collect 54 tests and pass.

Review round: which source proves the row. The two halves of the ledger are not mirrors, and a repair that treated them as one made the ordinary case unprovable. A promotion appends the run's own document under runs/, and the aggregate carries only the rows that have none, so document without aggregate row is the normal shape of a promoted run; reading it as a disagreement refused the very call this node exists to let through, and the gate caught it as four red cases. The document alone now proves the row. A row the aggregate carries with no document beside it is the one shape the two sources disagree about, and both that and a failed read are answered by the caller's choice: the receipt answers present, so it never withholds a cleanup it performed, and the decision to promote answers absent, so an unproven row never stands in for a promotion. Both callers now share one helper parameterised on that answer.

The receipt names an entity once. The stored and requested bodies were unescaped for comparison and then stripped by the plan reader's tag stripper, which unescapes again, so a narrative that writes &lt; was reported as <. Both bodies now go to the stripper as they were written, which decodes exactly once; a case asserts that a literal entity survives as written.
