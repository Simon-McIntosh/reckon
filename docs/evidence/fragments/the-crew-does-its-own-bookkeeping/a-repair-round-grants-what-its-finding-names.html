A repair round grants the test its finding asks for

The defect. A blocking finding whose file is a production module and whose text says the change has no committed regression test named one reachable path. _grant_round_scope read only finding["file"], so the round granted reckon/crew/merge.py and the reviewed run's fence, and no tests/ path at all. The worker could not commit the regression test the finding demanded: it blocked on a scope extension and the test it wrote lived in run scratch, where it dies with the run. The recorded manifest of r-20261103T075956692165-a-merge-refuses-a-run-whose-promotion-would-be-refused states the write fence excludes every tests/ path, and the defect was then reproduced directly at base: a probe calling _grant_round_scope with that finding over a temporary home and repository returned advised: ["reckon/crew/merge.py"], has_test_path: false, and the predicate absent (asked: false). The same probe at this head returns advised: ["reckon/crew/merge.py", "tests/test_a_merge_refuses_a_run.py"], has_test_path: true.

What changed. _asks_for_a_test(finding) in reckon/crew/recovery_repair_dispatch.py reads a finding's text and answers true for the three phrasings a review uses — “no committed … test”, “test … missing”, “test … uncommitted” — stopping at a clause boundary so an unrelated sentence that mentions a test is not read as the ask. The adjective-before-noun form admits only the words that qualify a test (missing regression test, uncommitted unit test), because a looser gap also read “the uncommitted rename breaks the test suite” as an ask. _grant_round_scope now extends the round's scope with, for each asking finding, every tests/ path its text names and, when it names none, tests/test_<node>.py for the reviewed run's node id read from the pointer (pointer["node"]["id"], hyphens as underscores). That path's reason is the asking finding's own id, set explicitly, because _grant_reason matches on a finding's file and would name the production module the test is about. The added path goes into both the grant and the advised scope, so the resume advice's write-scope line names it.

Measure. tests/test_a_repair_round_grants_a_missing_test.py, run from the worktree root over a temporary crew home and a temporary git repository — 5 passed at the committed head f61cb085e0. The cases are: a missing-test finding naming reckon/crew/merge.py grants both that module and tests/test_a_reviewed_node.py, the test path recording the asking finding's id as its reason and appearing in the advice's write-scope line, with a second finding citing that same test path but asking for nothing so the assertion fails if the reason falls back to _grant_reason; with two blocking findings the second asker's id is recorded, not the first finding's; a finding that names tests/test_merge_requires_promotable_run.py grants that module and not the node-named file; a finding naming the same module about something else grants the module and no test path; and _asks_for_a_test answers true for each of the three phrasings and false for naming, style, and the two quoted sentences “the uncommitted rename breaks the test suite” and “the missing cache key makes the test suite slower”.

Negative controls, each red. Removing the test grant (skipping every finding in the extension loop) gives 3 failed, 2 passed, with test_a_missing_test_finding_grants_the_node_test_and_its_file among the failures. A predicate that always answers true gives 3 failed, 2 passed, including test_a_finding_about_anything_else_grants_no_test_path. Taking the reason from _grant_reason gives 2 failed, 3 passed, failing both the single-grant case (which reads the citing finding's id) and test_the_test_path_reason_is_the_second_finding_that_asked. Restoring the loose adjective-before-noun pattern gives 1 failed, 4 passed on the predicate case, on the quoted sentences.
