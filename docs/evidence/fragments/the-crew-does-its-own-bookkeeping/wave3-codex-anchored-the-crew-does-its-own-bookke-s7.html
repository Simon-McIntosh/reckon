Reopen a halted run with its existing scope

Reopening accepts a halted or completed run without requiring another write path. An explicit grant still widens the scope. Reopening starts no worker; the caller's subsequent resume carries the advice and records the resumed attempt. A live process or an in-flight resume is refused before preparing the delivery.

The base reproduction returned --reopen needs --write-path and --reopen requires a completed run. Four regression cases cover stopped and completed runs resuming with unchanged scope, a stopped run receiving another path, and a live-worker refusal. The resume cases reuse the recorded-run fixture and launcher seam, retaining attempt > prior_attempt.
