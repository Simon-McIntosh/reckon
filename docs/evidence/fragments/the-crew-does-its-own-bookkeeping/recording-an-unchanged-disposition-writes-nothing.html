Recording an unchanged disposition writes nothing

Reproduced at base. At base revision b20201397b, in a temporary crew home and a temporary git repository carrying one committed review record, record_finding_disposition and record_dimension_disposition each re-stamped recorded_at on the entry already stored and committed the record again: the second identical call moved the record's bytes and grew the checkout's commit count by one. The fold sweep showed the same shape through _fold_findings_into_round, whose finding loop skips an already-folded finding but whose dimension loop re-recorded every dimension on each sweep — one commit per sweep on a record whose content was unchanged, which is the commit run the report described.

What changed. _disposition_already_stored in reckon/crew/review_dispositions.py compares the entry a caller is about to store against the one the record already holds, field by field and deliberately excluding recorded_at, which every build stamps afresh. All three writers — the dimension writer, the code-review finding writer and the shared run-review finding writer — return the record's own path without writing, carrying to the delivered copies or committing when the stored entry already answers the same way. The writer's refusals are unchanged, and a changed node, reason or kind still writes and commits.

Measure. tests/test_an_identical_disposition_writes_nothing.py, four cases, run on all_debug with pytest -n 4. At the head every case passes; the declared negative control restores the unconditional write at all three sites, and the run then reports 3 failed, 1 passed in negative-control.log, the failing ids being the finding, the dimension and the fold-sweep cases. The unmutated run: 55 passed over the new file plus tests/test_staged_write_inventory.py.
