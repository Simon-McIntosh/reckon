Readers accept the shapes their writers produce

Reproduced at the base revision. A measure test written against the base checkout (922001b305, extracted from git under the run's scratch directory) failed 6 of its 8 cases: a record carrying string findings read as bare strings rather than the declared object shape, a record carrying object findings read as objects, and a manifest whose tests: field held a JSON array raised out of the parser instead of being named by the manifest check. The two cases that already passed are the positive controls: test_logs: written as a YAML list already parsed as a list, and a mapping under tests already parsed as a mapping.

What changed. reckon/crew/review.py gained normalised_findings and with_normalised_findings: a finding written as a bare string is read as {"text": <claim>}, a finding written as a mapping is kept as the finding it already is, and an entry stating no claim is dropped on the same rule the claim reader applies. Both store_review and read_review normalise, so an older record carrying strings and a newer one carrying objects produce the same list. reckon/crew/reports.py keeps the tolerant parse for a list body under a text field — the joined text it has always produced, so an older manifest keeps reading — and collects the shape refusal for the manifest check, which now names the field instead of failing to read the record at all. An inline JSON array under such a field is collected the same way.

Head arm. The same 220 test files that import either changed module, plus the measure test, run at the head revision ccba432736 gave 1 failed, 2191 passed and the base arm at 922001b305 gave 7 failed, 2185 passed. The six failures the head arm clears are the measure cases; the one that remains, test_obligations_reads_scoring_without_observing_or_dispatching, fails identically at base: it asserts that reading a run's scoring changes nothing under the config home, and the shared git-object answer cache writes there, so the assertion fails with the same two extra files either side of the change. The delta is zero added and six fixed. Both arms were extracted from git with git archive under the run's scratch directory and run in place on the fleet node with pytest -n 8 and the follower variables unset.

Negative control. With the string-to-object lift removed from normalised_findings, the same measure test failed 3 of 8: the record with string findings no longer read as the declared object shape, the two records no longer read as the same normalised list, and a record lost the shape of its findings while keeping its other fields. The object-finding cases still passed, which is what makes them a control rather than a second red arm. negative_control.log ends EXIT=1.

Where the test lives. The measure test is measure_readers_normalise_shapes.py under the run directory, copied into each arm as tests/test_readers_normalise_shapes.py. The node's write grant does not include tests/, so a permanent test could not be added to the repository tree; that is recorded under outside_scope in the manifest for the coordinator to answer.
