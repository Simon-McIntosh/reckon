The velocity view is served over the crew surface

The velocity census gains a windowed report entry point, and the crew surface gains a velocity view that serves it. The command-line surface that will call it consumes velocity.report unchanged; the measurement layers underneath it are reused rather than re-implemented.

One report function, one surface

velocity.report(projects, *, start, end, branches=None, run_store_db=RUN_STORE, transcript_root=None, baseline=None) takes a mapping of project name to checkout path with a window start and end. It assembles the snapshot with capture_project per checkout, calls recover_ledger_clocks once over the assembled snapshot, then measure and compact_summary. No measurement logic is copied: capture_project gained a repo_path keyword and recover_ledger_clocks a repos keyword so a caller may name arbitrary checkouts rather than the census's fixed code root — both are additive with defaults that preserve the census entry point's behaviour.

The returned mapping is the compact summary, never the commit census, with by_project_day_lane appended so every quantity is available by project, by lane, by day and in three-dimensional cells. review_share was added to the promotion split in both the per-run aggregation and the per-cell aggregation, so the review-or-investigate share reads from the same ratio helper that every other share uses.

The crew surface serves it

crew(view="velocity") reads the existing since as the window start and a new until that defaults to the current time. A missing or unparseable since is refused by name — error: crew_error with a detail naming since — and a supplied until that is unparseable is refused the same way. The view takes one project, resolved through the server's existing _docs_dir_for_project, or "*" for every mounted project, resolved through mounted_project_docs(); each mount's repository root is the docs directory's parent. The response is the compact summary, never the commit census.

The view is deliberately hermetic: report defaults transcript_root to None, so the read does not walk a coordinator transcript tree the caller did not name, and the fallback run store is opened only when a promotion in the window has no committed ledger record. Over the test fleet the store is never opened.

Tests, arms and the negative control

tests/test_crew_velocity_view.py synthesises two git repositories under tmp_path with a committed run ledger at their heads, mounting both through an isolated mounts.json, and calls the view through the MCP function. Nothing outside tmp_path is read. Four assertions: the implementation-class/review-or-investigate promotion split and its review share on hand-computable fixtures; one project-by-lane-by-day cell with its counts; the refusal on a missing and an unparseable since; and a commit dated after until excluded from the measured head.

Scope

Three paths changed in this node: reckon/velocity.py, reckon/mcp.py and tests/test_crew_velocity_view.py. The reckon crew velocity command in reckon/cli.py is held by a peer node and is not touched here; the report function is shaped so that surface calls it unchanged.
