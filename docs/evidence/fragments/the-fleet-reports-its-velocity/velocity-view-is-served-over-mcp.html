The velocity view is served over the crew surface

The velocity census gains a windowed report entry point, and the crew surface gains a velocity view that serves it. The command-line surface that will call it consumes velocity.report unchanged; the measurement layers underneath it are reused rather than re-implemented.

One report function, one surface

velocity.report(projects, *, start, end, branches=None, run_store_db=RUN_STORE, transcript_root=None, baseline=None) takes a mapping of project name to checkout path with a window start and end. It assembles the snapshot with capture_project per checkout, calls recover_ledger_clocks once over the assembled snapshot, then measure and compact_summary. No measurement logic is copied: capture_project gained a repo_path keyword and recover_ledger_clocks a repos keyword so a caller may name arbitrary checkouts rather than the census's fixed code root — both are additive with defaults that preserve the census entry point's behaviour.

The returned mapping is the compact summary, never the commit census, with by_project_day_lane appended so every quantity is available by project, by lane, by day and in three-dimensional cells. review_share was added to the promotion split in both the per-run aggregation and the per-cell aggregation, so the review-or-investigate share reads from the same ratio helper that every other share uses.

The crew surface serves it

crew(view="velocity") reads the existing since as the window start and a new until that defaults to the current time. A missing or unparseable since is refused by name — error: crew_error with a detail naming since — and a supplied until that is unparseable is refused the same way. The view takes one project, resolved through the server's existing _docs_dir_for_project, or "*" for every mounted project, resolved through mounted_project_docs(); each mount's repository root is the docs directory's parent. The response is drawn from the compact summary, never the commit census.

The view is deliberately hermetic: report defaults transcript_root to None, so the read does not walk a coordinator transcript tree the caller did not name, and the fallback run store is opened only when a promotion in the window has no committed ledger record. Over the test fleet the store is never opened.

The response is shaped to fit the crew tool's response ceiling. Its default is the per-project, per-lane and per-day tables, the window and the count of the project-lane-day cells; every other block of the compact summary — the cells included — is served only when the caller names it in fields, and an unrecognised field is refused with the accepted set named. The cells are paged by limit and cursor through the same paginate helper the other crew views use. Measured over the mounted reckon checkout at each window's derived head, serialised with mcp_budget.serialised_characters against a ceiling of 80,000:

Both parameters that hint names, limit and fields, are accepted by this branch. Its suggested fields value is a runs-view placeholder rather than a velocity field, so a caller who passes it verbatim is refused by name with the accepted set beside it. The measurement is velocity-size-measurement.log.

Tests, arms and the negative control

tests/test_crew_velocity_view.py synthesises two git repositories under tmp_path with a committed run ledger at their heads, mounting both through an isolated mounts.json, and calls the view through the MCP function. Nothing outside tmp_path is read. Seven tests: the implementation-class/review-or-investigate promotion split and its review share on hand-computable fixtures; one project-by-lane-by-day cell with its counts, walked across the pages; the refusal on a missing and an unparseable since; a commit dated after until excluded from the measured head; the default response's shape and its size, serialised by mcp_budget.serialised_characters and compared with mcp_budget.DEFAULT_RESPONSE_CEILING rather than a copied figure; the cells returned on request and paged by limit and cursor; and an unrecognised field refused by name with the accepted set.

Scope

Three paths carry this node's work: reckon/velocity.py, reckon/mcp.py and tests/test_crew_velocity_view.py. Bringing the response inside the ceiling changed reckon/mcp.py and the test file and left reckon/velocity.py as it was: report still returns every block, and the surface decides what to withhold and page. The reckon crew velocity command in reckon/cli.py is held by a peer node and is not touched here; the report function is shaped so that surface calls it unchanged.
