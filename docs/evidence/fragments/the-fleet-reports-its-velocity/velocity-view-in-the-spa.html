The velocity view is in the plan SPA

The browser gets a Velocity work tab. It reads a server route that calls the composition behind the crew read and the command line, so all three surfaces answer one payload; the tab renders that payload and derives none of it.

The route serves the composition; it does not re-derive it

GET /crew/velocity?project=NAME&since=ISO&until=ISO&fields=...&limit=N&cursor=C joins the crew paths in reckon/serve.py. It validates the project name, resolves a named project's checkout through the server's own mount table (mounts[project].parent, so a mount recorded as the docs directory yields the repository root the view wants), and maps the query onto reckon.velocity.view with the same keyword surface the crew read passes — since, until, checkout_path, fields, limit, fields and cursor. The payload is written straight out as JSON, so the route owns no arithmetic at all and a change to the measurement layers reaches the browser with no server edit.

The default window. A caller that names no window gets one: the route opens the last VELOCITY_DEFAULT_WINDOW_DAYS (14) and passes both ends to the view, so the response's window block names the window it was measured over and the tab can label it. A caller that names part of a window — an until with no since, or an unparseable since — is refused with 400 carrying velocity.view's own refusal detail verbatim, because a partial window is a caller error the view already names and inventing a start would silently measure something the caller did not ask for. The two statements in the node's measure are therefore not in tension: the window absent gets the default, the window incomplete is refused by name. The test file pins both.

The checkout is the one the mounts name. A missing project is a 404, not a silent "*" read of every mounted project: the tab is scoped to the project the payload it is showing came from, and a browser asking for a project the server does not mount should be told so rather than shown another project's numbers.

The tab renders, it does not derive

docs/ui/velocity.jsx defines VelocityView, registered in the SPA's script list before shell.js so the shell can call it, and reachable as the velocity key in WORK_TABS and the #velocity hash route. It renders:

  • a per-project table with the promotions split into implementation class and review-or-investigate, the review share, lines added and removed by class, the two-day-allowed 7-day deletion share, the dispatch-to-completion median and p75, and attempts per landed node;
  • the same rows by lane and by day;
  • weekly plans opened and closed;
  • a window picker that re-requests the route with since and until, with a control that clears them back to the server's default;
  • a loading state that names the window being fetched, so a slow read says what it is reading over rather than showing an empty table.

Every figure on the surface is read from a field the payload carries. The component holds no arithmetic beyond formatting a ratio as a percentage and an epoch as a duration or a clock: there is no count it computes, no share it divides, no median it takes. That is deliberate and it is the repo's binding rule — a derivation written in JSX is invisible to every non-browser reader, and an agent and a human reading the same project would disagree with nothing failing.

Tests, arms and the negative control

tests/test_serve_velocity_route.py builds one synthesised git repository under tmp_path with a committed run ledger at its head — an implementation-class and a review-or-investigate promotion, source, test and plan commits, and two promotion commits — mounts it through an isolated mounts.json pinned into the server's own mount table. It binds serve.Handler to 127.0.0.1:0, serves it on a thread, and reads it with HTTPConnection. Nothing outside tmp_path is read or written except the two SPA source files the load-list and tab assertions must inspect (docs/index.html, docs/ui/shell-route.jsx).

Gate selection. The head arm runs the files that reach the changed code: the new route test, the three velocity surfaces' tests, the crew route tests, the SPA module-list and bundle gates, the artifact-route and crew-stylesheet gates and the composition gate — not the suite. The whole suite is one integration verification at the merged head, where it measures the merge rather than this worktree.

Negative control. The declared mutation replaces the route's conditional default with an unconditional one — since, until = named("since"), named("until") followed by an unguarded since, until = _velocity_default_window() — so the route returns the default window regardless of what the caller named. The parity case then fails, which is the assertion the node exists to make. The mutation was reverted and the file's md5 confirmed identical to its pre-control value; the mutation string is the first line of negative-control.log.

Scope, and one extension taken

Six paths carry the work: reckon/serve.py (the route), docs/ui/velocity.jsx (the tab), docs/ui/shell-route.jsx (the hash route and the work tab), docs/index.html (the load list, which is the single source the three other SPA entry points are held to), docs/ui/crew.css (the tab's styles) and tests/test_serve_velocity_route.py.

Extension taken: docs/ui/shell.jsx. The shell's canvas body dispatches each view with its own literal, so a tab that is not named there renders nothing however well it is registered. The added line is one dispatch (canvasView === "velocity" rendering window.VelocityView) beside the crew dispatch it imitates. It is outside the node's declared fence and is taken deliberately rather than reworking the dispatch into a table, which would have been a refactor across every peer's tab.
