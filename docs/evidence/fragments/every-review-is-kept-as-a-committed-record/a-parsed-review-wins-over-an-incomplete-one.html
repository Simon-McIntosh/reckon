Landing: a parsed, complete review wins over an incomplete one at the same head

What landed

  • reckon/crew/review_records.py — _select_stored_record now returns the first record at the named head that the completeness rule reads complete, and falls back to the first head-matching record when none is. The new _record_reads_complete applies the same read-time total derivation read_review applies before consulting the recovery reader's _review_is_complete, so a record whose six scores were stored without a total is judged as the gate will read it. The completeness rule therefore keeps one owner; the import is local because that module reads this store. An incomplete record alone at its head is still selected, and the gate still refuses on it, so the change replaces "first file in sorted order" rather than the refusal.
  • tests/test_a_parsed_review_wins_over_an_incomplete_one.py (new) — three cases over a temporary repository whose committed run directory holds the records, read through the committed caller's sorted glob. The incomplete record's name sorts first, so first-match selection sees it first. The first case writes both records and asserts the promotion gate's own raising caller returns no waiver; the second writes a complete record that scores every dimension but carries no total beside the incomplete one, so the selection has to derive the total before judging completeness, and asserts it wins with the derived total read back; the third writes the incomplete record alone and asserts the same caller raises with no complete independent review is stored.
