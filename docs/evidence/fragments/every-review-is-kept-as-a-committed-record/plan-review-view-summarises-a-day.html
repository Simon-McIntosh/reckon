The plan-review view summarises a day

What changed

plan_review.review_day_summary(project, since, until, plan=None) (new, in reckon/crew/plan_review.py) folds the committed records over an inclusive since and exclusive until — list_plan_reviews is the one reader, never a directory walk. A review is placed by its dispatch instant: the committed dispatched_at stamp, or the instant its review_run_id encodes when the record carries none. For each plan with a review in the window it reports the reviews run split by rubric, and for each re-review — a review with any earlier review of the same plan, under any rubric, at any time — the previous review it is compared with, the sections new since it, the largest share any existing section changed, and whether the per-section rule fires: a new section, or any section changed by at least the project's plan_change_threshold (read through flight.plan_review_change_threshold). Each review's authored bytes come from the repository object store with one git cat-file --batch per project (the batching reckon.velocity.read_blobs uses), falling back to the snapshot _snapshot_evidence already reads; a record with neither is listed unmeasured with no firing verdict rather than counted as a zero change. The change behind each re-review is measured with the module's own _prose_texts and _edit_share, so the summary and the coverage gate cannot drift.

crew(view="plan-review") carries the fold under day_summary when since is passed, with plan optional and narrowing the summary to one plan; plan stays required without since, so the existing missing_plan refusal is unchanged for every current caller. No view, tool argument or CLI option was added. The summary reports; it never refuses, stores or rewrites a record.

Real-data measure, 2026-10-06 (read-only, run id window up to r-20261006T055800475236, threshold 0.30): the fold over the four mounted projects' committed trees reports 87 re-reviews, 4 with a new section, 14 firings, 0 unmeasured. The throwaway evidence script (section_change.py over the host report directories) reports 96 re-reviews and 15 firings for the same window; the fold sees fewer because it reads the committed records rather than the script's host report directories, and a runner-up review whose predecessor is not committed as a record is not a re-review here. Of the 86 runs the two readers share, the firing verdict differs on four: it fires in the script and not in the fold for r-20261006T012931206272-plan-review-of-jt60sa-machine-map and r-20261006T014907201002-plan-review-of-artifacts-carry-no-worktree-paths, and in the fold and not in the script for r-20261006T033057910745-plan-review-of-a-plan-is-reviewed-before-it-is-built and r-20261006T050249615320-plan-review-of-jt60sa-discovery-completion. The two readers split a section at different boundaries and tokenise differently; the fold's split and tokens are the ones the coverage gate uses.
