Delivered reports are imported

What changed

scripts/import_host_reviews.py now imports, beside the host staging records it already committed, every delivered plan-review report that no committed record carries. It enumerates plans from the report root (reports_dir()/<project>/plan-review/<slug>/) and reads each plan's report directories through plan_review.delivered_reports, so it never walks for a report.md by hand. A report is carried when a record's review_run_id equals the report directory's name, or when the record's (plan_slug, plan_fingerprint, rubric) equals the sidecar's; a carried report is skipped, so a second write pass imports zero. Each unrecorded report is committed through review.store_committed_review, keyed by the report directory's run id, landing at docs/state/<project>/reviews/plan/<slug>/<run-id>.json. The dry run lists each such report by path and prints a per-project count line: delivered reports without a record: N, refused: M.

reckon/crew/plan_review.py: the record a sidecar and its report describe is factored out of _store_delivered_report into delivered_report_record, so the staging store and the commit importer build one record through one parser; a report_carries_review_lines predicate recognises a review as a report whose text carries a RUBRIC or FINDING line. A directory whose report carries neither is a composed-but-never- delivered artefact, not a review, so it is neither imported nor counted.

Refusals are visible. A report that is a review but whose record cannot be built — an unknown rubric, a missing plan_version — is listed as refused <path> <reason>, counted separately in the per-project line, and its reason is written onto its own sidecar under store_error through plan_review._record_store_error, the same way the staging store records a refusal. A report whose import or store is refused keeps the reason beside it; a report the store commits has any stale store_error cleared, so the file never contradicts the record beside it.

Gate

tests/test_import_host_reviews.py, tests/test_plan_review_store.py and tests/test_plan_review_rounds_keep_their_own_file.py ran in the foreground: 24 passed, EXIT=0. Three new cases drive the change: an unrecorded delivered report is imported once and a composed-but-undelivered directory is not; a report carried by run id or by content is not re-imported; and a report that cannot be parsed is listed and counted as refused with its reason recorded on its sidecar. A second write pass prints delivered imported: 0.

Negative control

Two mutations were applied and their logs kept. First, skipping report directories when gathering records — the candidate loop iterating an empty slug list — turns test_delivered_report_with_no_record_is_imported_once and test_delivered_report_that_cannot_be_built_is_refused_and_recorded red (2 failed, 22 passed, EXIT=1): no report is gathered, so none is imported and none is refused. Second, swallowing the build error instead of refusing — the except clause dropping the refusal — turns test_delivered_report_that_cannot_be_built_is_refused_and_recorded red (1 failed, 23 passed, EXIT=1): the unbuildable report is neither listed nor counted, which is the follow-on this node closes.
