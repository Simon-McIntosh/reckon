A subjectless review record is refused at delivery

The delivery-time check already refuses a record that names neither a reviewed run nor a plan. crew check --manifest, which every reviewer passes before its turn ends, reads each run-directory record through review.review_record_refusals, and that function extends store_review_refusals, which has carried the subject predicate names_a_review_subject since a0182b4ae7 (2026-10-18, the day of the reported run). The wiring that reaches delivered run-directory records arrived with 1bfed6d8ce. So §22's product gap was closed by work that landed beside it, and the missing piece was the test: nothing pinned the refusal, so nothing would have noticed it going away.

Added tests/test_a_subjectless_review_record_is_refused_at_delivery.py. It points a temporary crew home and run pointer at a review run whose declared paths are the reviewed run's review-records/ directory, writes a record scored on all six dimensions and carrying no reviewed_run_id and no plan, runs crew check --manifest, and requires a non-zero exit whose findings name that record path and say it has no subject. A record carrying its reviewed_run_id passes the same check unchanged, with no findings. No product source changed.
