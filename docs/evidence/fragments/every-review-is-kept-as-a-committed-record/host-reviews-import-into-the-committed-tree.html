The host review store is imported into the committed tree

What changed

scripts/import_host_reviews.py takes scripts/import_runs_into_store.py's contract — --project/--root, project resolved through the ordinary loader, exit 0 — and adds --write, dry run by default. It sorts a project's host staging store into recognised records and non-records. A file is a record when it carries review material — a findings, scores or rubric field or a reviewed sha — and names a subject: a plan, or a run, that its body gives, or, when the body names neither, the run its filename gives under the store's own <reviewed-run-id>[.at-<head>].json grammar. A review run id is not required. The id that keys its committed file is taken from review_run_id or the legacy reviewer_run_id, and a record naming neither is filed under a stable derived id (legacy- plus the first twelve hex of the sha256 of its bytes) and marked review_run_id_source: derived in the committed body; a reviewed run recovered from the filename is written into the body so the committed file is filed under the run it reviewed. It lists each entry with path, size and modification time, and under --write commits each record through review.store_committed_review so its times are the run's own, importing a duplicate that resolves one committed path once, and moves every non-record to <config>/crew/reviews-quarantine/<project>/ outside the store without deleting it. A record's staging file stays in place; only non-records move. A second pass imports zero.

Real host dry run (counts = recognised records, of which derived ids shown separately; bytes of records / non-records): reckon 1647, 77 derived, 16.8 MB / 94 B; nova 431, 102 derived, 4.5 MB / 2.55 GB; imas-ambix 362, 2 derived, 4.0 MB / 0; imas-codex 202, 0 derived, 2.0 MB / 0; imas-efit 67, 2 derived, 0.76 MB / 0; imas-ink 27, 0 derived, 190 KB / 0. Reckon's remaining three non-records are .keep, .probe-write.txt and the .ruff_cache directory; the 2.55 GB is nova's scratch tree. Legacy records naming a review run as reviewer_run_id keep that real id rather than a derived one, so the derived count is the subset naming no review run at all.
