Raw review reports are pruned once their record is committed

crew gc gains one pass over the plan-review report directories. A report.md older than review.raw_report_retention_days (declared as a non-negative integer in flight.REVIEW_OWNED_KEYS, read through flight.raw_report_retention_days, default 30) is listed as prune and removed only under --apply, and only when the review's committed record exists under docs/state/<project>/reviews/plan/<slug>/<run>.json; otherwise it is listed as withheld with the reason missing-committed-record. Every candidate is printed with its path, age in days and action; a dry run prints the same set --apply would act on. The sidecar and the plan.html snapshot survive every case.

The pass takes the same run_id as the rest of garbage_collect, so crew gc --run <id> --apply confines it to the one report directory named by that id: another run's past-retention report is neither listed nor removed.
