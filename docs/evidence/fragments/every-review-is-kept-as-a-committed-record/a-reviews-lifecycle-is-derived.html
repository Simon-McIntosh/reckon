A review's lifecycle is derived, never stored

What changed

reckon/crew/review_lifecycle.py (new): lifecycle(record, *, plan_state=None, run_promoted=None, later_records=()) returns the first of landed, superseded, open, answered that holds for a stored plan or run review, deriving it from the record and its subject's state and writing nothing. A plan review is landed when its plan's status is shipped/done/archived, or when every section named in its section_digests is now declared done; a run review is landed when its run's ledger row records it promoted. Superseding is a later review of the same subject — same plan under the same rubric (design and content separate, as plan_review.is_design_review does), or the same reviewed run — ordered by plan version then dispatch time, or by dispatch time for a run. A run review is open while a finding whose severity is not follow-on has no answer in the record's responses or response_events; a plan review is open on plan_review.unanswered_findings, exactly as the dispatch gate reads it. HOT_STATES = {"open", "answered"} is the pair a default view reads. review_lifecycles(project) is the thin loader: plan reviews through plan_review.list_plan_reviews, run reviews through the run-review store readers, plan states through the plan parser, promotions through the ledger's run-id reader; it returns each record's path with its state.
