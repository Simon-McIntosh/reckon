audit-doc resolves a review reference against the committed tree

What changed

reckon/doccheck.py gains review_reference_findings, which reads review:<project>/<id> citations from a document's comment bodies, followup bodies and — for an evidence record — its whole visible text. Each citation resolves against the project's committed reviews tree, located through reckon.crew.review.committed_review_root from the audited document's own checkout root (checkout_root_for, with an explicit root overriding it). A citation whose id names a committed record is silent; one that names no record is an error, review-reference-missing, naming the reference. No citation is ever looked up against the host staging store.

Gate: tests/test_audit_doc_resolves_review_references.py plus every existing tests/test_doccheck*.py and tests/test_audit_doc*.py file — 104 passed, EXIT=0. Negative control (every reference treated as resolved without looking it up): 4 failed, EXIT=1, the failure ids being the four cases the head arm passes.
