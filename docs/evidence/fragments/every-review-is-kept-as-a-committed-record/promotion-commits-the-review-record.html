A promotion commits the review record it delivered

What changed

reckon/crew/promotion.py: _complete_locked reads a review run's delivered record before it assembles the ledger row, so the row's review block carries the record's own id, and writes that record into the committed reviews tree just before the landing commit. The record's path joins the set _commit_landing_writes stages, so the review record and the run's ledger row land in one commit and the record adds none of its own. A record the committed store refuses rolls the row this attempt appended back out, so neither is committed and the retry re-promotes cleanly.

reckon/crew/review.py: store_committed_review now requires the review run id that names a committed record and refuses a record carrying none, rather than filing it under the run it reviews; it routes a plan review under plan/<slug>/ and a run review under run/<reviewed-run-id>/, and takes the dispatch and completion stamps from the review run's own record, falling back to the reviewed run's only when a run review carries no times of its own. The run_record_times docstring states that a live pointer supplies both stamps, its dispatch and its completion stamp.

Gate: tests/test_review_record_committed_at_promotion.py promotes a run review and a plan review in a synthesised project and holds each record to the row's commit, checks the row's review.id, checks the no-id refusal, and checks that a record that cannot be stored commits neither; it passes alongside tests/test_review_records_have_a_committed_root.py, tests/test_state_write_commits_a_set_of_paths.py, tests/test_ledger.py and tests/test_a_review_promotes_what_it_passed.py.
