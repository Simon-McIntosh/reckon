A review written to both of its paths is committed once

A promotion now files a staged review round once, and never rewrites a round the committed tree already holds.

What changed. _delivered_review_payloads_for_commit skips a staged record whose bytes equal the delivered record's, so a reviewer that wrote its one record to both of the paths its dispatch grants has it filed once. It separately skips a round the committed tree already holds — matched by the round's review id, or by the reviewed head it carries — in that order, so a later promotion does not rewrite a committed round and drop a disposition recorded on it. A staged round the subject has not committed yet is still committed under its derived legacy id. The committed tree those skips read is the caller's root — the same root promotion.py writes the landing into — rather than the run's own repository, which a landing given an explicit root may differ from.

The measure. Four cases in tests/test_a_review_written_twice_is_committed_once.py, each with the crew home and the committed tree under temporary directories: one record at both granted paths lands once under the review run's id; a second staged round at another head lands under its legacy id; a disposition written to a committed round survives a later promotion; and the same disposition survives when the landing's root is a checkout other than the run's own repository. The file is 4 passed, exit 0. The importing population runs at both revisions in its own pytest process — base b329ee744 55 passed, exit 0; head 59 passed, exit 0 — so the +4 is exactly the new file and the added failure id set is empty. ruff check and format are unchanged against base on the three changed files.

The negative controls. Removing both skips from the declared mutation reddens all three original cases: the byte-identity skip files the one round twice (legacy-17c189f35223.json beside the run's own file), and the already-committed skip makes the later promotion drop the disposition (KeyError: 'finding_dispositions'). Pointing the reader back at the run's repository — the mutation written on disk for the one run and the file restored from its exact original bytes afterwards — reddens the differing-root case the same way: 1 failed, exit 1.

What this node did not do. A worker does not close its own node: this fragment sets no terminal status and resolves no followup. The test file comparing the surfaces at the merged head belongs to a separately dispatched node.
