Landing: a discarded review's record loses the head to a promoted one

What landed

  • reckon/crew/review_records.py — _select_stored_record, the by-head selection behind stored_record, select_review_for_head and the disposition writer, now asks promotion.discard_recorded — the rule's one owner, imported at call time — for each head-matching candidate's review run, and drops a discarded record while another record stands at that head. A lone record at the head is still returned, so a head carrying one record is never made unreadable by its disposal. Within the remaining pool the existing rule still prefers a complete record over an incomplete one, and a parsed record now wins over one that measured nothing — the case a figure review leaves behind when it blocked without reading its images. The same filter applies in _filed_match, the store's content-keyed lookup for a record filed under another run id, so a discarded review cannot shadow a promoted one through that path either.
  • tests/test_a_discarded_review_never_shadows_a_promoted_one.py (new) — four cases over a temporary crew home and a committed reviews tree holding the records. Each paired case pins the discarded record ahead of the promoted one, by filename or by modification time, so a selection that ignored the discard marker would keep the discarded record. The first case resolves through stored_record(..., rubric="figure") to the parsed promoted record and then records a disposition through crew dispose --review <promoted> --rubric figure, asserting the receipt names the promoted file and the discarded file is untouched; the second pairs two parsed records and asserts the promoted one wins; the third holds a lone unparsed record and asserts it still resolves; the fourth files both records under their own review run ids in the staging store and asserts the misfiled lookup returns the promoted one, flagged as misfiled.

The defect reproduced before the repair

With the base revision's _select_stored_record in place, the new test failed exactly as the plan records: the selection at the head returned the discarded unparsed record, so the operator's crew dispose --review could not reach the promoted review.
