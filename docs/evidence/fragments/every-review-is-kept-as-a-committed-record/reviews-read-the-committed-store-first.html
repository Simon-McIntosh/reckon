The review readers read the committed store first

What changed

stored_record in reckon/crew/review.py reads the project's committed reviews tree first — resolving it through committed_review_root and enumerating run/<reviewed-run-id>/*.json — and falls back to the host staging store only for a run the committed tree does not hold. A record present in both trees is answered from the committed copy. The selection rule (newest, or the record whose head carries a named revision) is factored into _select_stored_record, shared by both trees. plan_review._candidate_paths searches the committed plan/<slug>/ tree beside the staging root, with read_plan_review applying a named version against the record's own plan_version; list_plan_reviews lists committed plan reviews beside staging ones, counting a review present in both trees once as the committed copy. promotion._staging_review_record_by_run now calls the review store's record_for_review_run, which is answered by the store's index (built once per directory and cached by stat identity, keyed by the review run id) rather than by walking the project directory.
