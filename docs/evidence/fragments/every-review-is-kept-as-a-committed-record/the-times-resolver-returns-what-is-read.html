Landing: the times resolver returns only what its callers read

What landed

  • reckon/crew/review.py — the private _run_record_times_found is gone. run_record_times now resolves the committed per-run record, or the live pointer when no committed record exists, and returns only the (dispatched_at, completed_at) pair. Its public signature, return shape and behaviour are unchanged; its docstring states the current rule, that a record whose times resolve from no source is committed as unknown (both entries empty strings).
  • tests/test_run_record_times_returns_the_pair.py (new) — holds the pair from the committed run record, from the live pointer before promotion, and empty strings when neither source carries a stamp; the pair is asserted whole, so a resolver returning a third value fails.

Measure

  • Gate, the two named files run in the foreground under --basetemp in this run's directory: 13 passed, EXIT=0. Log: gate/head.log.
  • Negative control, the declared mutation (make the resolver return the found flag as a third value again): 4 failed, EXIT=1 — every case in the new file fails and the head arm does not. Log: gate/negative_control.log.
  • Completeness search across reckon/, tests/ and scripts/: no _run_record_times_found and no unread found flag. Log: gate/search.log.
