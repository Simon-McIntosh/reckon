A ctest id names its test, not its index

Landing

canonical_node_id in reckon/crew/review.py left a ctest summary id's leading index in place, so a manifest's baseline_suite.failure_ids copied verbatim from a run summary (157 - XPOINT_BASELINE/ITER/imas/corsica) did not compare equal to the name the gate-log reader takes from a log's failure block, and _zero_added_against_a_red_base refused a genuine zero-added delta against a red base. It now drops a leading ctest index before reducing the path; the index is a position in one run's list, not the test's identity, and a pytest node id never opens that way. New tests in tests/test_a_ctest_id_names_its_test.py; gate logs and the negative control are under the run directory.
