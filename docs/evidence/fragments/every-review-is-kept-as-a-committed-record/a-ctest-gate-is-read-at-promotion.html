promotion reads a ctest gate log the way the review does

One format-aware reader, gate_log_failure_ids in reckon/crew/review.py, names a gate log's failing ids in whichever format the log is written: a pytest log's FAILED/ERROR node ids, or the entries of a ctest log's The following tests FAILED: block keyed by test name, or None for a log in neither format. The review's added_failures_from_gate_logs and the two promotion-side readers go through it, so the review and promotion cannot disagree about one log. _head_arm_log_failure_ids in reckon/crew/promotion_evidence.py now calls it; a head log in neither format returns None, so _zero_added_against_a_red_base refuses rather than measuring an empty set that is a subset of every red base. _control_failure_ids in reckon/crew/promotion_checks.py keeps its set return, reading a ctest control's failure block and returning the empty set for a log in neither format, which the negative-control check then refuses as never shown to fail.

The declared mutation — pointing both promotion readers back at review._pytest_failure_ids — makes the red-base case with one unrelated baseline id return true, and its log records EXIT=1 with test_a_ctest_head_log_widens_a_red_base among three failing ids.
