A review without its run id still promotes

What changed

reckon/crew/promotion.py: _delivered_review_payloads_for_commit now files the round the promoting run delivered under the promoting run's own id when that round's body carries no review_run_id. It stamps the delivered payload with run_id before the committed store reads it, so the round lands rather than being refused. A round the staging index returns that is neither this run's own delivered round (matched by its path) nor carries a review run id cannot be filed under any committed path, so it is skipped with a warning naming the file rather than refusing the whole landing; every other round still commits. store_committed_review's own direct refusal is unchanged, so a bare record is still refused at the store boundary.

Gate: tests/test_a_review_without_its_run_id_still_promotes.py (new) plus tests/test_every_review_round_is_committed.py, tests/test_review_record_committed_at_promotion.py and tests/test_review_records_have_a_committed_root.py — the new file passes (2 cases); one pre-existing case fails, see the blocker below.
