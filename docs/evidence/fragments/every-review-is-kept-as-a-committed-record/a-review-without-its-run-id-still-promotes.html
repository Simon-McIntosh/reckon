A review without its run id still promotes

What changed

reckon/crew/promotion.py: _delivered_review_payloads_for_commit now files the round the promoting run delivered under the promoting run's own id when that round's body carries no review_run_id. It stamps the delivered payload with run_id before the committed store reads it, so the round lands rather than being refused. A round the staging index returns that is neither this run's own delivered round (matched by its path) nor carries a review run id cannot be filed under any committed path, so it is skipped with a warning naming the file rather than refusing the whole landing; every other round still commits. store_committed_review's own direct refusal is unchanged, so a bare record is still refused at the store boundary.

Gate: tests/test_a_review_without_its_run_id_still_promotes.py (new) plus tests/test_every_review_round_is_committed.py, tests/test_review_record_committed_at_promotion.py and tests/test_review_records_have_a_committed_root.py — 21 cases pass, EXIT=0. Negative control: reverting the stamping makes the new file's two cases fail with EXIT=1.

The rollback case, repointed

tests/test_review_record_committed_at_promotion.py's test_a_promotion_that_cannot_write_its_record_commits_nothing staged a delivered record with no review_run_id and asserted the promotion refused it — the inverse of this node's goal, so a scope extension was granted to repoint it. A missing id is no longer a write failure, so the case now makes the write fail by raising from store_committed_review (monkeypatched) and still asserts the property it protects: no committed record, no ledger row, and the live pointer kept.
