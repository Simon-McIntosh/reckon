The picker sizes a heavy gate at the resolved fence

The picker classified a node only by the time budget the node declared, so a brief naming a queued cluster job and no budget of its own was sized at the small implement default — 8 m, the up_to_30m bucket — and reported to the router as small-node work. A node whose goal, done-when or brief names the compute its gate runs on is now sized at the resolved fence, and a node naming no such compute keeps the budget it declares.

What changed

  • reckon/crew/picker/lane_context.py: a new node_budget(node, config=...) returns the budget the picker sizes a node by. A node naming no gate compute keeps its declared budget unchanged. A node whose goal, done-when or brief names a scheduler, a GPU model or host, a partition or a cluster job takes the larger of that declared budget and the resolved fence (resolved_time_ceiling). return_times and build size the node through it, so the size key and bucket they report are the floored ones.
  • tests/test_a_heavy_gate_gets_a_full_budget.py (new): a brief naming a betelgeuse H200 job and no time budget receives the resolved fence; the same brief at the 8 m implement default reports size_bucket: over_60m rather than up_to_30m; a node naming no compute keeps 8m and up_to_30m; a declared budget already above the fence is not lowered; and a heavy brief with no fence configured keeps what it declares.
