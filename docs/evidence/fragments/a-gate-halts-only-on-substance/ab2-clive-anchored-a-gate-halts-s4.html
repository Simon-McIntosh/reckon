A resume can change the run's budget — verification

The deliverable is present in the tree at the base revision: crew_resume in reckon/crew_run_commands.py declares --time-budget and --over-fence (lines 2281 and 2287), _refuse_a_budget_above_the_resume_fence applies the resolved fences.time_budget ceiling and names --over-fence in the refusal, _record_resumed_time_budget writes the new allowance onto the run's node and appends a budget_changes entry carrying the figure it replaced, the instant and any stated reason, and the pointer is re-read before launch so the resumed attempt's fence is composed from the new figure. The session module that composes that fence is reckon/crew/dispatch_sessions.py, which reads the node budget it is handed; the resume door was handing it the stored one and now hands it the recorded one. This node found the behaviour already correct and re-implemented nothing.

With the launch instant pinned to 2031-01-01T01:00:00Z, a run stored at 25m resumed with --time-budget 45m composes deadline 2031-01-01T01:45:00Z and stores 45m; a 90m resume above the 60m fence is accepted with --over-fence and keeps its reason; the same 90m without the option is refused naming --over-fence, launches no worker and leaves the stored 25m untouched. Three cases pass (EXIT=0).

The declared mutation sets the recording helper aside, so the option is ignored: the resumed prompt then carries deadline 2031-01-01T01:25:00Z, the stored budget's, and two cases fail while the refusal case still passes (EXIT=1).
