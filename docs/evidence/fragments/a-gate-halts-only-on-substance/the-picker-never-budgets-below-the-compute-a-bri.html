The picker never budgets below the compute a brief names

The budget floor for a node whose gate names heavy compute is already carried at this revision by node_budget in reckon/crew/picker/lane_context.py, with tests/test_a_heavy_gate_gets_a_full_budget.py asserting it. This node verified that behaviour rather than reimplementing it: the gate and the importer cohort are green, and the declared mutation reddens exactly the two fence cases.

The behaviour, as it stands at this revision

  • node_budget(node, *, config=None) returns the node's declared budget unchanged when its goal, done-when and brief name no gate compute.
  • When the node's own text names a scheduler verb, a GPU model or host, a partition or a cluster job, it returns the larger of the declared budget and resolved_time_ceiling(config). A brief naming an H200 job and no budget therefore receives the resolved fence rather than the small implement default.
  • return_times and the build path size the node through it, so the reported size_key / size_bucket are the floored ones.

Reproducing the defect the floor prevents

At this revision the defect does not reproduce in the unmodified tree, so the instruction's reproduction step was taken as the declared mutation: with node_budget returning the declared budget before the fence is read, the stubbed node whose brief names a betelgeuse H200 job and declares no budget returns '' and is reported size_bucket: up_to_30m. That is the small-node size the plan names. The unmodified tree returns the fence and over_60m for the same node.

This is the same floor an earlier node on this section landed; the reproduction confirms it is load-bearing rather than incidental.
