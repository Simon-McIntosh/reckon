A blank reason is not a reason

What this node found. The plan's §3 behaviour was already at the base revision: crew dispatch --over-fence REASON admits an over-fence budget only when the recorded reason is non-blank, the refusal otherwise names the option, and an in-fence budget touches none of it. So this node verified the behaviour rather than rebuilding it, and closed the one arm the check relies on that no test exercised.

The bounded check reads over_fence_reason.strip(), so a reason made only of whitespace must leave the refusal standing — that is what makes "a recorded reason" mean a stated one rather than any non-empty string. No arm covered it. The arm added here asserts the pair at the check itself: whitespace alone is refused, and a reason padded with surrounding whitespace still admits.

The first version of that arm was vacuous, and the record shows it. Written through the dispatch command, the blank case asserted only that the command refused — and it stayed green under a mutation that ignores the recorded reason entirely, because the command refuses every over-fence budget in that state for a different reason. The assertion survived the very regression it sat beside. Re-asserted at the check, each of two mutations now takes it red: reading the raw reason fails the blank arm, and ignoring the reason fails the padded one and both reason-bearing arms.
