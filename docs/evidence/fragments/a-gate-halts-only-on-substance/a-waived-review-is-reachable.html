A waived failure count is reachable from the brief and from the row

What changed. A review may file added_failure_count as the literal "waived" against a run whose suite delta stands waived, but nothing reached that form on the path a waived run takes, so the capability was unreachable in both directions.

The brief. _review_brief_text in reckon/crew/recovery_review_subject.py asked only for a count derived from the reviewed run's baseline_suite and after_suite gate logs. A reviewer whose arms carry no pytest summary has nothing to difference, so it wrote a null count and the delivery contract refused it — exactly where the waiver applies. The brief now carries a block naming the waived form, the added_failure_waiver field it must state, and the run's own recorded reason, and the dispatch done_when admits the waived form beside the measured one. Both are conditioned on a waiver the run's record actually holds: the reason is read through recorded_suite_delta_waiver, the same reader the delivery check judges with, so the instruction and the acceptance cannot disagree. A run with no waiver gets a brief that names neither the heading nor the field.

The committed row. Once a run's live pointer is gone, the committed-row fallback in reckon/crew/review.py recognised a waiver only under suite_delta.status == "waived". A matched pair that crew complete --waive-suite-delta was given a reason for records status clean with the reason in waiver_reason, because there the status names what the evidence found rather than how it was accepted — so a waived count filed against a landed run was refused once its pointer was dropped. The reader now takes both spellings, from the pointer and from the row, and a record carrying neither is still no waiver: neither an absent status nor an empty waiver_reason authorises the form.

Measured

tests/test_a_waived_review_is_reachable.py asserts three things on a temporary crew home. (a) The brief composed after crew complete --waive-suite-delta names Suite delta waived, added_failure_waiver and "waived", and carries the run's written reason; the brief of a matched unwaived run, composed at the same head, carries the record contract and none of the three. (b) A promoted run whose row reads status clean with a non-empty waiver_reason accepts the waived record once its pointer is deleted — crew check --review exits 0 and store_review files it. (c) The same record against a promoted run whose row carries status clean and waiver_reason: null is refused by the check and by the store with no suite-delta waiver.

Negative control, the declared mutation — the base revision with the same test file: the waived brief does not name the waived form (assert 'Suite delta waived' in '...' fails), and the waived record against the clean-with-reason row is refused with added_failure_count is waived but the reviewed run records no suite-delta waiver. 2 failed, 1 passed, EXIT=1; at head the same three cases pass, EXIT=0. Ruff check and format --check add no finding on the three staged paths.
