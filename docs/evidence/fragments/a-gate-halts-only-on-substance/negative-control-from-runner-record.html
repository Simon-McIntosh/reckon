A negative control is admitted on the runner's own record

What changed. The control-evidence reader admitted a declared mutation's log only when a terminal EXIT=<n> line was present and non-zero. A log written without the fleet's capture convention — pytest's FAILED <id> list beside its N failed summary, and no appended status — therefore recorded the run's failure in the runner's own words and was still refused. The reader now takes the failure from either record: the shell's status decides when a capture line is present (and EXIT=0 is never overridden by text), and otherwise the runner's failure output decides. Nothing else about the admission moved. The identity requirement is unchanged — the control must name at least one failing test id the head arm does not fail — so a bare EXIT=1 with no runner output is still refused, a log naming no failing id is still refused, and a log whose only failing id also fails at head is still refused.

Where the decision lives. _control_run_shows_a_failure in reckon/crew/promotion_evidence.py is the single point that answers did this run fail, from the recorded status when there is one and from _runner_reports_a_failed_run when there is not. _require_declared_negative_control in reckon/crew/promotion_checks.py calls it and keeps the rest of the refusal chain — ids, then the arm comparison — exactly as it was.

The dispatch prompt states the contract. NEGATIVE_CONTROL_DECLARED_RULE and the manifest block in reckon/crew/prompts.py now say that a terminal EXIT= line is one way the log shows the run failed and is not required, because a worker that is not told so writes a red log it believes is incomplete.

Measured

The new check is tests/test_a_negative_control_is_read_from_the_runner.py and holds four arms: a runner-written red log with no exit line is admitted; an exit line with no runner output is refused for naming no failing id; a log whose only failing id also fails at head is refused; and a composed implement prompt for a node declaring a negative control names the contract. Two pre-existing tests that encoded the retired refusal — tests/test_control_gate_checks_facts.py and tests/test_control_is_compared_with_the_head_arm.py — were updated to assert the admission and each gained a companion case proving a log with neither record is still refused.
