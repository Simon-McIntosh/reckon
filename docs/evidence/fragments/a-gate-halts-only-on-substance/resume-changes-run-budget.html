A resume can change the run's budget

A run stopped on budget kept the allowance it was dispatched under, because crew resume composed the resumed attempt's time fence from the budget stored on the run. The only way to give the work more clock was to discard the run and dispatch it again, losing the session that already held the context and colliding with its own leftover worktree. crew resume now takes --time-budget: the new allowance is recorded on the run's node, each change kept in a budget_changes entry naming the figure it replaced, the instant and — where one was stated — the reason, and the resumed attempt composes its fence from the recorded figure. --over-fence REASON is the recorded way through the fence: an allowance above the resolved fences.time_budget is refused naming that option, and accepted with its reason when one is given. The resumed fence is not composed in this module — reckon/crew/dispatch_sessions.py's _restate_time_fence already reads the node budget it is handed, and the resume door was handing it the stored one.

Three cases pass against a stubbed run in a temporary crew home, with the launch instant pinned so the fence is readable as arithmetic: a run stored at 25m resumed with --time-budget 45m launches a prompt whose fence reads deadline 2031-01-01T01:45:00Z — 45 m from the pinned launch — and the run's stored budget is 45m; a 90m resume above the 60m fence with --over-fence is accepted and its reason is kept on the run; the same 90m without the option is refused naming --over-fence, launches no worker and leaves the stored 25m untouched.

The declared mutation sets the recording helper aside, which is the reader that ignores the option: the resumed prompt then carries deadline 2031-01-01T01:25:00Z, the stored budget's, and two cases fail, while the refusal case still passes (EXIT=1). The importer arm over the test files importing reckon.crew_run_commands, run one arm at a time with -n 4, is 377 passed at this revision and 374 at the base revision — three more tests, no added failure, EXIT=0 either arm. This gate measures only this node's own change; verifying the merged result belongs to a separately dispatched test node.
