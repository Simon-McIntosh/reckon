A brief may raise the time fence, and must say why

What changed. crew dispatch gains --over-fence REASON. A node whose wall-clock budget exceeds the fence the flight layer resolves is now admitted when that option states why, and the reason is stored on the node as over_fence_reason, which rides TaskNode.as_dict() onto the run record and its ledger row. Without the option the refusal stands, and it now names the option a caller must pass. A budget inside the fence is untouched: the reason is never consulted, and an over-fence budget with a blank reason is refused exactly as before.

Why the fence became a bounded default rather than a hard stop. A gate measured at three hours against a fence written before it was measured had no way through. The alternatives were splitting work that cannot be split or writing a budget that lies, and a lying budget is the worse of the two because nothing downstream can tell it from an honest one. A recorded reason makes the overrun auditable on the node and the row instead of invisible.

Measured

The new check runs in tests/test_a_budget_may_exceed_its_fence_with_a_reason.py and carries four arms: an over-fence node with a recorded reason passes the bounded check and the reason is readable on the node; the same node with no reason is refused with a finding whose detail names --over-fence; a budget inside the fence passes untouched; and a dispatch preview carries the reason from the command line onto the node it resolves. The negative control drops the reason test from the bounded check, and the two reason-bearing arms go red against that mutation.

Every arm is a log whose first line names its revision, tree and command and whose last line reads EXIT=<code>.

One thing this node could not close. _node_from_pointer in reckon/crew/queue_admission.py rebuilds a queued request's node field by field, and it does not name over_fence_reason. A request that queues and is later admitted would therefore lose its recorded reason and be refused at launch. The file lies outside this node's write scope and is claimed by concurrent nodes, so the repair is reported to the coordinator rather than made here.
