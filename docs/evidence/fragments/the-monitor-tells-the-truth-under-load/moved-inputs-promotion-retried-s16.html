A promotion refused because its inputs moved is judged again

What changed. Acceptance reads a run's pointer, review and gate, then re-reads them under its lease before writing. A run whose state moved between the two readings was refused with the run or its acceptance inputs changed while it was judged, and that refusal is right for the state it names — which no longer exists. Three runs on 15 November reached promotion-refused on those words, and the durable promotion queue returns a terminal receipt to every later request for the same run, so nothing read the run again and each one needed a coordinator to land it by hand.

The identity is now a view as well as a digest. reckon.crew.recovery_review_acceptance._acceptance_input_view returns the judged inputs themselves, and _inputs_digest hashes them for the refusal memo, so a judgement that finds them moved can name the fields that moved rather than only that something did. _judge_again_on_moved_inputs records the attempt in acceptance-inputs-moved.json in the run directory, returns retry: True while the attempt budget (INPUTS_MOVED_ATTEMPTS = 3) has room, and after that returns the refusal with what moved named in it: … changed while it was judged 3 times, so the run is not settling; the last changes were: pointer.attempt 3 -> 4. A judgement that gets past the identity check clears the budget, so a movement months apart starts a fresh count.

The sweep takes the run up. dispatch_awaiting_reviews reads the durable receipt for every promotion it handed over; an acceptance refusal whose result asked to be judged again is re-queued with request_promotion — the same queue the station drains behind crew complete — instead of being reported as a refusal. The retried judgement reads the inputs the run now has, so it promotes when they pass and refuses on them when they do not.

While a repair attempt is live, the sweep attempts no promotion. _live_repair_attempt reads the round recorded on the run, takes its dispatched repair run, and answers live while that run's pointer stands the attempt has written no exit record. The accepting branch then records the hold in the sweep's repair_held and hands nothing over. Before this change the sweep promoted the reviewed head under a live repair attempt: the base-revision log for the live-repair test records accepted: True, promoted: True for a run whose repair was mid-round.

The negative control is decisive because the retried judgement is the only path that turns that refusal into a landing: with the helper stood down, the test's second sweep reports the refusal the base revision reports, which is precisely the state the change removes.

Scope of the record. Only the acceptance refusal for moved inputs is re-judged. Refusals for a merged gate that failed, a plan reserving manual landing, an unreadable remote and a coordinator's hold are unchanged: each describes the run's own state and is still terminal until something outside the judgement changes. The attempt budget lives in the run directory and is not part of the plan's state, so no plan record is touched by this node.
