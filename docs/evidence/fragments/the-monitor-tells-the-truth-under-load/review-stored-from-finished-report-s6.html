§6 — A review record is stored only from a finished report, in either shape

The report the store refused to read and the record it read instead were both finished to the grammar. A report holding the brief's own template lines — RUBRIC wiring: RUBRIC-PLACEHOLDER-1 and FINDING wiring FINDING-PLACEHOLDER — parsed as a complete review: a placeholder is non-empty text in the verdict cell, so all seven items read as answered, and the FINDING line carried an anchor with no claim and was dropped. Stored, that is a record with no verdict and no finding, which is how three real findings never reached the gate. The reproduction at the base revision is the condition itself, built in the new test file: the store returns no refusal and writes plan-review-finished-report-target.v1.json with status: ready and rubric_items holding RUBRIC-PLACEHOLDER-1..7.

The store now tells the two states apart by the run that writes the report, because only that run can say whether the placeholders are a writer mid-turn or a writer who has gone. review.report_placeholders is the one reader of the template tokens and parse_plan_review_report returns them beside the verdicts; delivered_report_record raises UnfinishedReviewReportError naming them, and plan_review._store_deliveries decides what that means from _review_run_is_live: the crew run the report directory's dispatch.json names is read through the run pointer and process_liveness.record_process_alive, the same reading every other liveness decision on the host is taken from. A live reviewer holds the report and clears any stale store_error, so a later pass reads the finished file and stores its findings; a reviewer that has ended leaves a delivery defect recorded on the sidecar, which the promotion's plan-review outcome raises as the store's own reason, opening a repair round instead of holding the review open.

The second shape is the figure record. One figure review judges every figure its brief attached, so a record states its verdicts per figure under figures; the completeness rule reads a single item map, so it answered such a record as carrying no verdict at all and refused it as "not a complete review", which is what two sessions met. review.figure_rubric_verdicts folds the per-figure verdicts to that item map — an item is present only when every figure answered it — and with_figure_verdicts carries the unanswered figure-and-item pairs beside it, applied by the store's read_review and by the delivery verdict so no two readers disagree. The refusal names the figure: it lacks contrast, left unanswered for docs/figures/.../second.svg: contrast.
