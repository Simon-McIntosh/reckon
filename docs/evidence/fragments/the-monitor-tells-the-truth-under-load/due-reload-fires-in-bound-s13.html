The hold is dated from when the code moved, and a deferred image is proved again

The defect. StationReloader holds a due reload while the derivations in flight land, and dates that hold at the poll that first sees the code move. The reloader is polled only after a tick, so a tick longer than RELOAD_HOLD_SECONDS left no poll between the move and the bound's expiry: the deadline moved by the tick's own length and the reload fired on the tick after the one that had already outlasted the bound. Reproduced at the base revision af516b3ac9 with the station's clock and polls driven by a 30 s tick against a 20 s bound: the reload that should fire at the tick's end held instead (station-reload: holding a due reload … for at most 20s), and the case failed DID NOT RAISE OSError.

The second defect. A deferred image was suppressed until committed code moved again, so a refusal that says nothing about the image — the throwaway import proof timing out, or a peer process holding that image's own proof lock (ImportProofPending) — held the station on stale code for exactly as long as the branch stood still. Reproduced at base: with the proof refusing on one poll and answering on the next, the same identity was never proved again and the reload never fired. That is the shape of the 15 November report of a station 100 minutes past several landings.

What landed. reckon/crew/station.py now records _clear_since, the instant of the last poll that found no reload owed, and _quiet dates the hold from there rather than from its own poll. That instant is never later than the moment the code moved, so the station now fires at the first poll at or after the bound's expiry whatever the tick length, and the bound stays the upper bound it reads as. The exec path is untouched: the reloader is still polled at a tick's end and still re-executes on the station's loop, after the dispatches in flight have been waited for, so no re-exec lands in the middle of a tick.

A deferred image is retried. _reload_owed treats a deferred identity as owed again once _deferred_proof_at passes, and _arm_deferred_proof sets it, so the next poll repeats the proof. A deferral that repeats then waits RELOAD_DEFERRED_RETRY_SECONDS (60 s), doubling up to the hold bound, so an image that will not import is not re-proved on every tick — a recorded verdict is, so the image's own answer costs a file read.

Gate. tests/test_a_due_reload_fires_within_its_bound.py, four cases, each driving the reloader's monotonic clock and its polls directly. A reload due through a slow tick fires within one tick of its bound; a deferred image is proved again at the next poll; a repeatedly deferred image waits its spacing (2 probes over three polls, a third after the spacing); a reload due with nothing in flight fires at the first poll. The first three fail at base — 3 failed, 1 passed, EXIT=1 (logs/base-red.log, the base tree with this file copied in unmodified) — and the fourth passes there, which is the honest reading: the no-derivation path was already correct, so the case is a guard on the dating rather than a repair.
