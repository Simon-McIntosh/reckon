§10 — A dry run reports what the real call will refuse

Three dry-run gaps, each reproduced at the base revision before it was repaired, and each held by a test that fails against the code it replaces. crew complete --dry-run reported would_promote: true for a run the landing would not promote, and answered the question a coordinator did not ask. A delivered implementation with no stored review of its head reported would_file_reviews: [], which answers which delivered review records a filing would move into the store — not whether a review is owed — so an owed review looked like none. And the dry run took the run's pointer lock and its cross-host claim, so it could queue behind a promotion of the same run and answer as a write that timed out.

The report now carries the suite evaluation the promotion itself reached — the delta, its would_measure state, and the arm fields the pair is missing — rather than a second reading of the record that could drift from the landing's own. The one unmeasured state a landing acts on is a measurement it takes itself, by running the armed command over the base and head trees, so that state is reported as the measurement it is and not as a refusal: a merge reads would_promote before it moves anything, so a run the landing would promote must never read as refused. The dry run still measures nothing and starts nothing; the dry-run answer is stated by the evaluation itself, in the landing's own words.

The review gate's own predicate is extracted and read by a helper that states the review owed as a fact — the run, the tier that decided it is owed and the head it must read — and the dry run takes neither the pointer lock nor the cross-host claim, because a dry run writes nothing and a lock it waits on is itself a write.
