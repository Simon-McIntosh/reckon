A resumed repair is never killed as a terminal run

A repair round is started by resuming a run that has already delivered, so its pointer carries the complete the earlier attempt's delivery wrote. Every other writer of that phase puts back what it read before the resume — a promotion drain restores the phase its request recorded, a fold reads the superseded attempt's stream — so the live repair's pointer reads complete again at some point during its work.

The terminal-run guard in reckon/crew/dispatch_launch.py read that word as the attempt's own delivery and armed its clock. Thirty seconds later it ended the worker with forced_exit.reason = "terminal-run" while the worker was mid-edit. The phase word is a summary; the attempt's own exit receipt is the fact, and it belongs to exactly one attempt.

  • _terminal_attempt_phase returns a delivered phase (complete, failed) only when the attempt it names also holds the exit receipt its own ending wrote — attempt-<n>-exit.json, or the canonical exit.json naming that attempt, which every launch clears. A word another writer restored no longer satisfies it.
  • _reopen_a_live_attempt_phase answers the stale word where it is read: while the worker is live in that supervisor's own charge and the attempt holds no exit receipt, the pointer's phase is restored to working, so the run reads as the resume left it rather than as a finished attempt with a live process. It takes the pointer lock without waiting and only when the pointer has been written since the last look. stopped and interrupted are untouched: they are deliberate facts, not words a delivery leaves behind.
  • The remedy an obligation offers for a run mid-repair is §5's, and this node did not touch reckon/crew/obligations.py.

The defect's reproduction, from the field, is what the base arm of the new test reports: “a resumed repair was signalled on the delivered word its earlier attempt left; the live attempt had no exit receipt”, beside “the live repair reads as 'launch-failed', not working” — the second because the signalled worker's empty stream is then read as a launch failure. Eight resumed attempts in the shared crew home carry the same shape: an exit record reading ended_during: "working" with forced_exit.phase: "complete" and forced_exit.reason: "terminal-run".
