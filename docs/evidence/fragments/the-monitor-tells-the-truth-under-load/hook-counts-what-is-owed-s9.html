The hook's figures count the obligations it lists

What changed. format_checklist in reckon/hooks/coordinator_obligations.py took its header count from the payload's summary.count and its closing figure from summary.unreconciled_runs, and printed the instruction to work the list unconditionally. Both figures now come from the rows the render prints: the header counts the obligations it lists, and the trailer appears only when the list holds a row a coordinator can act on, counting those obligations rather than the closure's run figure.

The reproduction, at the base revision. A session that dispatched nothing, and a session whose only row is a request awaiting upstream, on a synthesised configuration home:

summary: {'count': 0, 'oldest_age_seconds': 0, 'unreconciled_runs': 3}
items: []
--- rendered
reckon obligations for session probe-session (project probe-derive): 0 outstanding
unreconciled runs: 3; work the list to empty before ending the turn.

summary: {'count': 1, 'oldest_age_seconds': 0, 'unreconciled_runs': 1}
items: [('run-queued', 'run-upstream-request')]
--- rendered
reckon obligations for session probe-session (project probe-derive): 1 outstanding, oldest 0s
- [1 waiting, no action shortens them] run-queued 1 (oldest 0s)
unreconciled runs: 1; work the list to empty before ending the turn.

That is the reported reading: the closure's run figure printed beside a list that does not hold those runs. A worker in flight is work already moving, and a request awaiting upstream starts by itself when its last ref lands, so neither is a duty and a trailer asking the list be worked to empty names work nobody can do. After the change the first render says nothing at all and the second lists its wait without the trailer.

The second reading. A registered session with no pointer and no producer was answered at every prompt with are not current: no producer; run `reckon crew watch --ensure …. The prompt path now reads the session's own pointers before warning: session_holds_live_work walks the pointer directory, an unreadable pointer counts as work so the silence is only ever taken on evidence, and a pointer that never reached a worker or ended owing nothing is not work at all — an unpromoted delivery manifest, or a review dispatch not withdrawn, keeps an ended run speaking. A session with one live run still names the remedy, and a session due a limit reset is still told it, so the silence is the fleet's answer rather than a hook that stopped speaking. The no-follower reading is untouched; the reading this change silences, for a registered session holding no pointer, is the no-producer line, and five expectation cases pinning its old wording are red at head (see Not done here).

Two statements of one rule, compared. The phase sets and the ended-pointer rule are stated in the hook itself, because the modules that own them cost 2.0–3.0 s and 521–525 modules to import, reckon.ledger and reckon._plan_html among them — the derivation cost this hook exists to keep off a turn's opening. So tests/test_the_hook_counts_only_what_is_owed.py compares the hook with its owners: the phase sets against reckon.crew.node._TERMINAL_RUN_PHASES and dispatch_launch.LAUNCH_FAILED_PHASE, and _pointer_owes_its_session against station_subscriber._record_has_pending_work over eight pointer shapes. A rename or a new terminal phase in either owner fails there instead of becoming a hook that reads an ended pointer as live work.

What the figures mean now. The header counts rows; the trailer counts the same rows and prints only while at least one of them is actionable.
