A run-scoped gc touches only that run

crew gc --run X --apply swept every directory under each workspace trash root, because _sweep_worktree_trash was called with no notion of the run the pass was scoped to. The trash root is shared by every run releasing a tree beneath the same workspace, so a destructive command named for one run removed other runs' leftovers.

The sweep now takes the labels the named run owns and the directories this same pass moved a tree into. A release writes its copy as <label>-<stamp> — the releasing run's id when it had one, the tree's own directory name otherwise — so a run-scoped pass takes its id, its recorded tree's name and any copy it made itself, and leaves the rest. An unscoped pass passes no labels and still sweeps the whole root. Every removal is printed by name either way.

Reproduced at the base revision before the change: a scoped pass printed removed worktree trash …/_trash/r-20261115T010000000001-other-20261115T020000000001Z for another run's copy. After the change the same pass prints only its own two entries and both of the other run's directories are still on disk. The new test fails at the base revision (1 failed, 1 passed, the unscoped case already correct and now covered) and passes at the head (2 passed). Restoring the unscoped sweep as a negative control fails the same case again.
