A section can no longer land only when none of its runs still can

One node of a section writing failed turned every request waiting on that section into blocked-upstream, which reads “a section this request waits on can no longer land” and offers to recover or drop the request. The section still owned a second run, in flight on a scheduler job, and the failed run was resumed within a minute. The section's death is now a judgement about every run that names it, and a request that stays waiting names the run it is waiting for. The new checks fail at the base revision; the already-correct third case stayed green through both arms.

What changed

  • reckon/crew/admission/release.py: _dead_sections now builds two sets over the live pointers instead of one. A section lands in the ended set when one of its runs reads failed or blocked-upstream, or has a discard recorded; it lands in the standing set when a run it owns may still land, which is any other phase plus an ended run carrying a resume mark. The answer is ended minus standing, so one failed node no longer closes a section that still owns a queued, held, working or resuming run. _section_key is the one place a pointer's (plan, section) is spelled, so the two sets cannot disagree about identity; a pointer whose phase is complete neither keeps the section open nor closes it. _resume_in_flight reads the mark mark_resume_launching writes on the pointer before the resumed attempt records its own, through resumption.launch_in_flight, so the window in which a resumed run still reads failed no longer closes its section. _live_runs_on reads the same judgement for one waiting request, and resolve_waits records those run ids on the request as upstream_live.
  • reckon/crew/admission/release.py, _advance_waiting_requests: the pass persists upstream_live beside upstream_obligations whenever either changes, so a name recorded for a live sibling is cleared when the section does die.
  • reckon/crew/admission/shared.py: DEAD_RUN_PHASES is documented as one run's vote rather than the section's verdict, and LANDED_RUN_PHASES names complete — the phase of a run whose work already landed whose pointer may outlive it. Both are exported from the module that owns the phase vocabulary.
  • reckon/crew/recovery_classification.py: the awaiting-upstream row appends the runs recorded in upstream_live to its detail, so the row says which run is still live on the section instead of naming only the section. The blocked-upstream wording and its recover or drop remedy are untouched: they remain the honest reading for a section no run of which can land, which is the case this change keeps.
  • tests/test_a_section_with_a_live_run_can_still_land.py (new): three cases over a synthesised crew home, checkout and plan, storing one pointer per run and driving the admission pass directly. Each asserts the real crew home is untouched.
