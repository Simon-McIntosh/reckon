A queued request is checked for review once

Admission re-ran the whole dispatch gate on every pass, over the request's section and the document unit, so an edit anywhere in a plan's contract held every queued request of that plan until a fresh review was answered — even though each request carries the done-when it was dispatched with. The request is now judged against the plan text it was queued against: its own section's digest and the digest of the document text it reads as its contract (summary, decisions, gates), both recorded on the pointer when the request enters the queue.

The predicate is _plan_review_owed in reckon/crew/queue_admission.py. It holds a request only when one of its two recorded digests has moved and plan_review.review_coverage leaves that unit uncovered; a document-unit change is further narrowed by routing._document_change_is_contract, so a change confined to remainder prose holds nothing. A request whose stored reviews cover no unit it reads — no review at all, or only reviews marked incomplete — has no reviewed text to compare against, so it is held exactly when the dispatch gate holds it, and a test drives both paths over such a plan and asserts equal verdicts. plan_review_units is now defined once, in reckon/crew/routing.py, and imported, so the rule for which units a request reads is one definition.

One limit is worth stating plainly. The contract is recorded only by queue_admission.queue_requests today. A request without a current contract record — any pointer written by runs.queue_dispatch, which is where production queue writes go, or one whose section was changed with crew queue edit — falls back to the dispatch gate's own verdict, the wider hold admission asked before this node. The fallback is the behaviour, not a re-stamp: nothing rewrites a contract onto a pointer the queue writer did not record, so the narrowed check is reached only for a request that entered through the batch entry. Production wiring is pending: stamping the contract inside runs.queue_dispatch puts every production request on the narrowed check, and that hook lands separately.
