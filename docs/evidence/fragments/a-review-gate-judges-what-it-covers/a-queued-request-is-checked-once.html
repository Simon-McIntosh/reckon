A queued request is checked for review once

Admission re-ran the whole dispatch gate on every pass, over the request's section and the document unit, so an edit anywhere in a plan's contract held every queued request of that plan until a fresh review was answered — even though each request carries the done-when it was dispatched with. The request is now judged against the plan text it was queued against: its own section's digest and the digest of the document text it reads as its contract (summary, decisions, gates), both recorded on the pointer when the request enters the queue.

The predicate is _plan_review_owed in reckon/crew/queue_admission.py. It holds a request only when one of its two recorded digests has moved and plan_review.review_coverage leaves that unit uncovered; a document-unit change is further narrowed by routing._document_change_is_contract, so a change confined to remainder prose holds nothing. The digests are recorded by queue_admission.review_contract, called by the batch entry before it returns and by the admission pass for a pointer queued by any other writer. A request whose section was changed with crew queue edit is re-stamped rather than compared across two sections. A pointer carrying no recorded contract — every request queued by a writer that does not stamp it — is judged by the dispatch gate itself, the wider hold admission asked before, rather than being held on a comparison it has no side of. plan_review_units is now defined once, in reckon/crew/routing.py, and imported by admission, so the rule for which units a request reads is one definition.
