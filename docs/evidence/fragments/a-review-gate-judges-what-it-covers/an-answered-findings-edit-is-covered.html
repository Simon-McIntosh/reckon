An answered finding's edit is covered

A review that raises a finding and is answered acted has already said what the plan must change, so the edit that follows is the review's own subject. plan_review.review_coverage now lets that review cover the section the finding anchors while the edit stays under review.plan_change_threshold (0.30), even when the review-need judge answers that a review is required — the answer the gate gave to a 1 % correction a finding had asked for. An edit of the same size to a section no finding named is still owed, an edit past the threshold still is, and the document unit is unchanged, still covered only by an exact digest match.

The rule is one branch in the existing per-review loop: the units whose findings carry an acted response, read through _acted_finding_units and finding_unit, are remembered when the measured share falls under the threshold, and the pending-unit verdict honours that memory ahead of a judge that asks for a review. record_response records the edit's commit on an acted answer, named by the caller or resolved as the newest commit touching the plan through _plan_head_commit, so the covering record carries the evidence for its verdict. Two normalisation helpers became one: the earlier digest definition, which dropped only the per-section lifecycle status, is now a field set (_PREVIOUS_SECTION_FIELDS) on the present _without_section_bookkeeping, and the _fingerprint_forms docstring states only the two forms that function returns.
