A finding blocks only the section it is about

The dispatch gate narrowed its coverage judgment to the units a request reads, but its unanswered-findings check still collected every unanswered finding of the plan. A plan with many sections therefore held every section behind its slowest finding: on 2 November a §19 dispatch of another plan waited about forty minutes behind a re-review of §4 and §21, whose findings said nothing about §19. The gate now refuses a node only for the findings that block the units it builds.

plan_review gains finding_units and unanswered_findings_by_unit, both built on one resolver. An anchor naming #<unit> blocks that unit outright. A line anchor is resolved through the reviewed snapshot only when its path is the plan file itself — a line number in a source file is that file's line, so reckon/crew/routing.py:3122 no longer resolves to whichever plan section happened to contain line 3122. A finding anchored anywhere else blocks each section its own text names (§N or sN), and one that names none belongs to the document unit, which blocks every section. A carried answer now records every unit under sections, with the first kept under section for readers that take one, and carried_findings_for_section reads the list.

Node gate on tests/test_a_finding_blocks_its_own_section.py: 6 passed, EXIT=0. The six cases are the plan's five: a dispatch of §19 passes while §4 and §21 carry unanswered findings; a dispatch of §4 is refused naming reasoning-1 and not done_when-1; a finding anchored in a source file and naming no section refuses every section; the design review's source-anchored findings each refuse exactly the sections their text names, with duplicate_owner-3 refusing §5 and not §7 and a copy stripped of its section name refusing every section; and a source line number that falls inside a plan section does not resolve to it.

The fixture's design findings are anchored and worded after a stored design review in the tree (a-project-reads-as-one-picture), because the record the plan names — plan-a-read-costs-what-changed.v7.json — is not present in the tree at this revision under any path, staging or committed, nor in its git history. The behaviour the case measures is the resolver's, and it is measured against real source-file anchors and section-naming text; the substitution is recorded under outside_scope in the node's manifest.
