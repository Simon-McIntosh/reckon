A review run promotes on the record it stored

The hand promotion path required an executable gate command of every role. A review run has none: its deliverable is the record it stores for the run it reads, and its manifest's tests line is a summary of what it did. A review whose record was already on disk was therefore refused with “describes the check rather than running it”, and a coordinator blanked the line by hand each time.

A review-role run now reads the stored record — its status, its findings, its report path — through the same delivery reader the review loop's own self-promotion uses, so the hand path and the automatic path cannot disagree. A delivered record of a recognised status stands as the gate check. A review run with no delivered record keeps the rules it had, because the code-review path stores its record during promotion and has none on disk beforehand. Every other role keeps the executable-gate rule unchanged.
