A printed review command composes from the dispatch write paths

The dispatch payload's health_review block always composed its remedy around the plan: reckon crew review --project <p> --around <plan> --session <s>. The composer that command reaches resolves a plan to the write paths its implementable sections declare and refuses one that declares none. So a dispatch against a plan with no section write paths printed a remedy that refused the moment it was run — the refusal moved one step later rather than removed, which is the failure this section exists to close.

The block now asks the plan for its declared write paths (through plan_review.code_review_paths_from_plan) and, when the plan has none, composes the remedy from the write paths of the dispatch that printed it — one --path per product source path, quoted through shlex.quote. A plan that does declare write paths keeps the plan as the subject, so a review still covers the whole of what the plan is about to build. A plan that cannot be read, or a block reported against an unreadable review store, gets the same fallback: the command must run.
