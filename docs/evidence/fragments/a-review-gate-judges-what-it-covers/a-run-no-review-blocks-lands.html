What changed

The landing pass accepted a stored review only when it carried no finding of any severity, so a review that raised two non-blocking observations held the run for a coordinator who had nothing to add. The acceptance predicate now withholds a landing on a blocking finding and accepts a review whose findings all declare a non-blocking severity. A finding that declares no severity still withholds the landing, because the repair reflex already reads an unstated severity as blocking and two readers of one record must not disagree.

The score sets no bar

The rule reads a record twice: it must be complete, and it must carry no finding that withholds a review. It never compares the total, or any dimension, against a threshold. A reviewer who scored the work low said so in the scores, which every later reader can open; a second bar in the landing pass would hold the run for a coordinator reading the same numbers. The acceptance floor and every reader of it are gone with the rule that consulted them.

Exemptions follow the landing

When the pass lands a run it records each non-blocking finding against the stored review's own head-keyed record, exempted with the reason non-blocking, noted at landing. That write now happens only after the landing succeeds, in the landing pass and in the acceptance sweep alike: written first, a refused promotion left a run's findings marked exempted with a reason that says a landing happened, on a run that never landed. A landing that succeeds and then cannot write them is reported and stands, because the run did land.

A conflicting head is named before it is measured

The pass reads the merge of the run's head onto the primary branch with git merge-tree --write-tree, which touches neither the checkout nor the branch. A head that conflicts is refused before the expensive measurement runs, and the obligation names the conflicting paths. The landing step's own merge applies the same refusal, so nothing is written to the branch on either path.
