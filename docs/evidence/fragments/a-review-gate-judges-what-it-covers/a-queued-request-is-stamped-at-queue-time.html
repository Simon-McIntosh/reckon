A queued request is stamped at queue time

The admission-side check landed first and compared a request's recorded contract against the plan, but no production writer recorded that contract: queue_admission.record_review_contract was called only by the batch entry queue_admission.queue_requests, which no production path calls. Every pointer written by runs.queue_dispatch therefore carried no contract and fell back to re-running the whole dispatch gate on every admission pass, which is the behaviour the section narrows.

queue_dispatch in reckon/crew/runs.py now calls record_review_contract(record) once the queued pointer is written, in both the first-write and the re-queue branches. The stamp is taken after that write and outside the per-run pointer lock, because record_review_contract takes the same lock itself; the digest of the section's prose and of the document text the request reads (the summary, decisions and gates) is recorded from the plan as the dispatch left it. A pointer that cannot be stamped keeps no contract and is judged by the dispatch gate, which is what it was judged by before, so the write fails closed.
