A torn transcript line does not break a board read

dispatch_accounting._jsonl_events opens the transcript with errors="replace". A last line torn in the middle of a multi-byte character now decodes to an undecodable JSON line, which the existing parse guard skips, instead of raising UnicodeDecodeError out of the loop and discarding every whole line before it. The board's context-use read (directory._last_assistant_request falling through to that reader, and directory._context_use above it) inherits the fix at the owner.

Reproduced at the base revision before repair: a transcript of whole records followed by b'{"type":"assistant","content":"h\xc3' makes list(_jsonl_events(path)) raise UnicodeDecodeError: 'utf-8' codec can't decode byte 0xc3 in position 0: unexpected end of data. The board's tail read survives it because it parses raw bytes, which is why the fall-through forward scan is the path that fails.

tests/test_a_torn_transcript_line_does_not_break_a_board_read.py writes the torn transcript in a temporary directory and asserts both shapes: _jsonl_events yields the user record and both whole assistant records and raises nothing, and with directory._TRANSCRIPT_TAIL_SIZES shrunk to (32,) so the tail read falls through, the context-use read returns the last whole request at 250,040 charged tokens. Gate at head: 2 passed, EXIT=0. Importer measure over the six test files importing reckon.crew.dispatch_accounting or reckon.crew.directory, both arms from git archive extractions on node-local disk with the checkout's .env linked: 38 passed at base, 38 passed at head, EXIT=0 both, no added failure.
