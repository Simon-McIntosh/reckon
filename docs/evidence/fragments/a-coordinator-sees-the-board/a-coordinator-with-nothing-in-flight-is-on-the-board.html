What landed

A session whose runs have all ended and whose follower has settled was named nowhere: the run pointers were all gone, so nothing on the board said the session existed. The session host's census in reckon/crew/session_host.py kept only children with a pid, and a settled child has none. It now keeps a settled child with its project, its session, a null pid, and settled_at, the time its follower left. live_census(environ=None) reads every host record whose owner process still lives and skips a host that has stopped, and record() drops a settled child again when it is re-armed, so a session that dispatches resumes carrying one child rather than two.

The board in reckon/crew/directory.py lists each session the census names that the run grouping cannot see, with live_node_count: 0, no runs, state: "idle", its project, the time its follower settled, and last_dispatch read from the ledger rows the plan-coordinator resolver uses. A session already listed from a run is left to that row, so one session never appears twice, and a host whose owner has exited names no session at all.
