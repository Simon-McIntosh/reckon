The ready set says which rows nobody is working on, and who to ask

What changed. ready_set_view already projected the roadmap's ready rows, and a row with a run on it read exactly like a row nobody had picked up. Each row now carries live_run (the run id on the row, or null), coordinator and plan_owner from the crew's plan-coordinator derivation, and critical_path. The view also gains closable: the plans whose every declared section is resolved, each with the closure blockers close would still have to clear.

ready_idle=True filters the same view to rows with no live run. It is a filter argument, not a view: nothing new is served and no refusal family is added. The filtered answer pages with limit/cursor through the same paginate every other view answers with. An unpaged call keeps the whole set, so a surface already reading this projection is not silently cut to one page.

One derivation per fact: the coordinator columns are read from resolve_plan_coordinators, or taken as an argument when the caller already holds them, never re-derived from the ledger here.
