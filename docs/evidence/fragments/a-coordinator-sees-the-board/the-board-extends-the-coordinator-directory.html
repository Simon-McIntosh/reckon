Discovery lock

Merged with main, the board deadlocked. Plan discovery holds the server's discovery lock while it builds the roadmap; the roadmap's critical path asks the plan-coordinator resolver who owns each plan; that resolver reads the directory view to decide which sessions are still dispatching; and a directory read that always derived ready-idle owners ran plan discovery again, waiting on the non-reentrant lock its own caller held.

directory() now takes ready_idle, off by default, and the crew view asks for it. The resolver's read derives no plan facts, and the payload names which join ran (not_requested, project or workstation_scope) so a read that did not ask is not mistaken for one that found nothing.

Case: test_discovery_returns_while_the_roadmap_reads_coordinators drives discover_plans in a thread bounded at 30 s against a real plan tree whose critical path reaches the resolver. It fails at the node's pre-fix head merged with main (logs/deadlock-control.log, the assertion that discovery returned) and returns in 3.6 s with the change.

Repair round

Review returned four findings and all four are folded into commit dd6625581b.

  • One read of the lane document. The lane-share block read the file twice — once through read_lane_document_file for the report it quotes and again through its own json.loads for the admission block — so a lane rewriting the file between the two reads produced a report and a session row from different vintages. lane_document.read_lane_document_with_admission now reads and parses once and returns both, and the view's own parse helper is deleted. The per-session row lookup is lane_document.session_admission_row, beside the block it reads.
  • The idle join reads every page. The join pages the ready-set view and unions the pages, carrying its page size on every request, so an owner whose ready-idle sections sort past a page is not listed as idle over nothing. Case: the join is held to a page of seven and a plan of 40 ready-idle sections is seeded, so six pages are read and all 40 sections are named on the owner. With the loop replaced by a single page the case fails (logs/paging-control.log, EXIT=1).
  • The mounted set comes from its owner. The workstation-scope join reads the project registry through the wrapper the rest of the package uses, so a registry written in either shape is read and an unreadable one fails closed instead of reading as no projects.
  • Workstation scope joins. The join runs once per mounted project when the read names none, so the default directory lists a run-less owner. Case: directory() with no project lists idle-coordinator, and still does not list the gated one.
  • The queued claim is asserted. A queued run holds no worker and no worktree, so its claim reads as disregarded; the test now asserts binding is False and that its reason says so.
