The coordinator read is bounded by its window

The ledger's per-run document run_rows_from_documents takes a lower bound on each document's own modification time and skips a file at the directory walk when it is older. The plan-coordinator resolver passes its horizon less one day of margin. The bound is the document's mtime, never the instant its run id names: a run id is stamped when the request is queued while the document is written when the run is promoted, so a long-queued run has an old id and a recent document.
