A plan's coordinator is derived from its most recent dispatched run

What changed. A listing built from the live run pointers can only name a plan whose work is in flight, which is exactly not the plan a coordinator needs to ask about: an idle plan with a committed history has no pointer at all. Two ownership facts already existed and nothing joined them — every ledger run row carries session, the crew session that dispatched it, and every plan carries <meta name="plan-owner">. reckon/crew/plan_coordinator.py adds resolve_plan_coordinators(project, *, root=None, now=None, window="168h", pointers=None), which reads the committed ledger rows and the live pointers, matches each run to its plan, and returns per plan the dispatching session of the most recent match inside the window, its tier, whether that session is live, and the plan's own owner beside it.

Three things about the join are decisions rather than mechanics, so they are stated rather than left in the code:

  • Match order. A run is matched to its plan by the row's plan field, then by its plan_link (a brief-dispatched landing names the plan, and its section suffix — iter-power-supply-model#s2 — is stripped), then by the plan its node id names. A plan review's node id plan-review-of-<slug> names its slug; a run review's review-of-<run id> names the run it reviews, whose own plan the review then carries by the same rules. The reviewed run's dispatcher is not the review's coordinator: the review's own session answered.
  • A row with no session is no match at all, rather than a weaker one. A run nobody's session dispatched can name no coordinator, and falling through to an older row would answer a question the ledger does not support.
  • The window is the caller's. DEFAULT_COORDINATOR_WINDOW is "168h" — a dispatch usually outlives its run by days, so the window is measured in days, and parse_duration has no day unit. A dispatch older than the window is history: the plan reverts to the next dispatch still inside it, or to unowned.

The universe of plans is the project's own <docs>/plans/*.html, unioned with any plan a row names, which is what gives "a plan with no rows resolves to unowned" a referent. The plans directory is also where each plan's owner is read, so the resolver enumerates and reads owners in the one pass.
