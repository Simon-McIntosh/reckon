Typed discovery skips evidence fragments

A node's landing record lives as its own fragment under docs/evidence/fragments/<plan>/<node>.html. A typed-resource discovery walk now passes over that subtree instead of refusing the path, so a fragment no longer breaks every plan read while still composing into its own record.

The defect: a fragment is a mis-shaped typed resource

A typed resource is canonical at <root>/<slug>.html or <root>/archive/<slug>.html. A discovery walk that meets any other shape under a typed root raises ResourceCollision. The fragment path docs/evidence/fragments/<plan>/<node>.html is two levels deeper than the evidence root allows, so every walk that did not pass a tolerant flag refused it — and the first fragment landed in the tree took read_plan, the served SPA and audit-doc down for the whole project until it was withdrawn.

The walk inside reckon/resources.py is where the fix belongs: the fragment subtree is a known non-resource, so every rglob site that discovers typed resources and _path_context adopt one shared predicate, _is_evidence_fragment, keyed on the leading evidence/fragments parts of the relative path.

What changed

  • EVIDENCE_FRAGMENTS_SUBTREE and _is_evidence_fragment in reckon/resources.py name the skip in one place.
  • _path_context returns a non-typed context for a fragment, so _path_type never calls ResourceCollision for it.
  • identify_resource returns None for a fragment, so it is not minted as a resource.
  • Each discovery rglob loop (_scan_resources, _migration_candidates) and the migrate_typed_layout rewrite loop skips the subtree before identifying a resource.
  • reckon.evidence.compose_landed_record is untouched: it reads the fragment directory directly, so the skip cannot hide an anchor from the record a reader sees.

The skip is exactly the fragment subtree. A document outside it that is still mis-shaped — docs/evidence/extra/x.html — keeps raising ResourceCollision, so the change narrows the refusal rather than removing it.

Declared negative control

Declared mutation: remove the evidence/fragments skip from reckon/resources.py; the unrelated-plan read_plan case must then fail. The read path the tool exposes already swallows the collision through a tolerant walk, so the read itself is not the half that moves. The case the tool is named for therefore also asserts the non-tolerant walk the read resolves through — iter_resources(docs, project) — and that assertion is what turns red when the skip is removed.

Each log header prints its revision, reckon.__file__ and the resolved cwd, so the tree that served each arm is checkable.

The gate: tests/test_discovery_skips_evidence_fragments.py

A synthesised docs tree under tmp_path holds two plans, one cumulative record and one fragment owned by only one of the plans. Four cases:

  • both plans read through reckon.mcp._read_plan_tool, including the plan the fragment does not belong to, and the non-tolerant walk discovers both;
  • the fragment is walked past rather than discovered — neither the strict walk nor the tolerant map yields it;
  • the composed record still carries the fragment's anchor, so the skip did not hide it from its reader;
  • a mis-shaped document outside the fragment subtree is still refused with ResourceCollision.

The figure the walk with the skip, the refused mis-shaped path, and the composer that still reads the fragment draws the three routes.

The worker does not resolve the driving followup or change terminal plan state.
