The audit flags an element id a composed record repeats

A cumulative evidence record is audited in its composed form — the record's own bytes followed by its fragments. Two fragments that reuse one element id, or a fragment that reuses an id the record already carries, produce a document with two equal anchor targets: a link to the id resolves to the first occurrence and every later one is unreachable. reckon/doccheck.py now reports each repeated id once, naming the record file and each fragment that carries it.

What changed

  • reckon/doccheck.py reads a record's composed text and, for each element id that occurs more than once, emits one error finding with code duplicate-element-id. The finding names the id, its total count, and per occurrence whether it comes from the record file or a named fragment.
  • Attribution reads each source's own bytes rather than slicing the composed text, so a fragment composed as its body alone — with its head dropped — is still attributed to the fragment that carries the id.
  • The same check flags a single document with a duplicated id, outside any composition, with the whole document as the sole source.

The gate

  • tests/test_audit_flags_duplicate_composed_ids.py: a record and a fragment that share the section id s3 yield one finding naming s3 and the fragment's file; a fragment whose id is its own node name yields none; a standalone document with a duplicated id is flagged. 3 passing at head.
  • Base and head arms over the 19 tests/ files whose AST imports reckon.doccheck, -n 4 with a separate --basetemp: head 207 passed, exit 0; base (the two new cases run against the unmodified module) 2 failed, 205 passed. Head adds no failing test id.
  • Negative control: making the check skip ids that occur exactly twice fails the record-plus-fragment s3 assertion (log first line repeats the declared mutation; exit 1).

Measured on the live record

A run of the audit over the 118 records under docs/evidence/archive/ reports 29 duplicate-element-id findings across 10 records. The record for this plan carries four: the-defect, what-changed, and negative-control each appear in three fragments, the-test in two. The check sees a known collision before any absence is reported.
