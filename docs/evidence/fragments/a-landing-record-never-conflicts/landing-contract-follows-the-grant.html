The landing contract follows the fragment grant

The plan landing contract tells a worker to write its evidence anchor to the node's own fragment and its figures to the node's own figure directory. It was composed on worktree writability alone, so a verifier role whose sandbox can write the worktree — but whose fence withholds the fragment — was told to write a path its fence withholds. The contract now reads both facts, and a node whose fence withholds the fragment reads the run-record carrier a brief already reads.

The defect: the contract named a path the grant withheld

Section 2 gives each node its own fragment and figure directory as its default scope, and a following fix withholds those two paths from a role that may not land work in the tree. The grant gate then read role_may_write_repository_paths(node.role) as well as sandbox writability. The prompt's contract gate read only sandbox writability, so the two disagreed about the same node.

The disagreement was measured on the fragment role-scope run r-20260929T053221615781, whose independent review recorded it: the landing contract is still composed on worktree writability alone at reckon/crew/dispatch.py:4577, so the writable-sandbox verifier whose fragment this change withholds is still told by PLAN_LANDING_CONTRACT to write docs/evidence/fragments/<plan>/<node-id>.html. The reproduction is the declared negative control below: under the base decision, a test-role node with a worktree-full sandbox and no fragment in its write paths still reads the plan landing contract, and the verifier assertion fails.

What changed

  • reckon/crew/dispatch.py gains _writes_its_landing_fragment(node, *, authority), which derives the node's fragment with the same _landing_fragment_paths the grant uses and resolves each declared write path with the same _resolve_declared_path, so the contract and the grant cannot disagree. It names no role and repeats no path format.
  • The two landing facts are resolved behind one call site, _compose_dispatch_prompt, so the prompt a test composes is exactly the prompt dispatch composes and a change to either fact is visible rather than masked.
  • reckon/crew/prompts.py: compose_prompt gains writes_landing_fragment. When the fragment is not in scope the plan carrier is replaced by BRIEF_LANDING_CONTRACT — the run-record wording already defined — so the landing line stays on the run's own record. A caller that supplies no fact keeps the plan carrier for a writable node, the shape every direct composer has used.
  • The default grant is unchanged; only the prompt stops naming a path the grant withholds.

The gate

tests/test_landing_contract_follows_the_grant.py composes through the dispatch path: it dry-runs a node and composes with _compose_dispatch_prompt, the same call site dispatch uses.

  • test_an_implement_node_reads_the_plan_contract_and_its_fragment — an implement node's write scope carries its fragment and figure; the composed prompt states PLAN_LANDING_CONTRACT and names the granted fragment path.
  • test_a_writable_verifier_reads_the_run_record_carrier_not_the_plan_contract — a test role with a worktree-full sandbox carries neither path; the composed prompt names neither the plan contract nor the fragment, and states the run-record landing sentence.
  • test_the_fragment_fact_reads_write_paths_not_the_role — the same verifier role reads the plan carrier when its scope carries the fragment and the run-record carrier when it does not, so the decision follows the scope rather than a role list kept in a second place.
  • test_a_direct_composer_without_the_fact_keeps_the_plan_carrier — a direct composer that supplies no scope is unchanged.
