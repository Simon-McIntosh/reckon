Execution evidence · fragment

The landing fragment reaches only landing roles

A node's default write scope grants its own evidence fragment and figure directory. That grant was keyed on sandbox writability alone, so a verifier role whose sandbox can write the worktree was handed a repository write path it could never land. The grant now reads the same role predicate the promotion refusal reads.

The defect: a verifier offered a path it cannot land

The default scope added by section 2 grants docs/evidence/fragments/<plan>/<node-id>.html and docs/figures/<plan>/<node-id>/. The grant sat behind one gate — sandbox writability of the worktree — so any role whose sandbox is worktree-full received it. The test role is worktree-full in the flight defaults, so a verifier was offered a repository write path.

Promotion reads a second rule: a test role may not commit any repository path, so a run that wrote the fragment it was handed is refused at promotion. The two rules disagreed. Measured at base 29af302f, a test-role dispatch with a worktree-full sandbox carried both paths in its write scope:

assert 'docs/evidence/fragments/plan-a/role-scope-node.html' not in [... 'docs/evidence/fragments/plan-a/role-scope-node.html', 'docs/figures/plan-a/role-scope-node']

A review or read-only investigate role already lost the paths through the sandbox gate, but only as a side effect of its sandbox; the role rule itself was not consulted.

What changed

  • reckon/crew/dispatch.py gates the default fragment grant on role_may_write_repository_paths(node.role) as well as _can_write_worktree(...). role_may_write_repository_paths is the single spelling of "this role may write repository paths" — the same predicate promotion refuses on — so the grant and its refusal read one authority and cannot drift.
  • A role that lands no work in the tree acquires no landing path: the fragment and figure directories are never appended to its write_paths, and its evidence goes in its run directory as before.
  • tests/test_role_write_scope.py: the two cases that pinned the retired plan-wide landing paths now assert the node's own fragment and figure paths, and that no shared plan or archive path is granted. A new case pins a writable-sandbox verifier to no landing paths.

The figure the landing grant before and after: one gate, then two draws the decision the change makes.

The gate

  • test_an_implement_role_receives_the_landing_paths_in_its_write_scope — an implement role receives its own docs/evidence/fragments/plan-a/role-scope-node.html and docs/figures/plan-a/role-scope-node, its declared deliverable, and neither docs/plans/plan-a.html nor docs/evidence/archive/plan-a-landed.html.
  • test_an_implement_role_on_the_local_lane_still_receives_the_landing_paths — the same on the local-lane dialect, so the grant tracks writability rather than the backend command.
  • test_a_read_only_role_does_not_receive_the_landing_paths (review, investigate) and its local-lane twin — neither the shared paths nor the fragment and figure paths appear.
  • test_a_verifier_whose_sandbox_can_write_gains_no_landing_paths — the new case: a test role with a worktree-full sandbox still receives no landing path.
