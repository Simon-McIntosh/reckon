Six study commits merge without conflict once the record is a fragment

Two arms, one base

The measure builds two arms from the base 457bbec7 the six study commits share. Each arm re-applies the six commits' own file changes onto that base, then folds the six together with git merge-tree and counts the conflicted paths under docs/plans and docs/evidence. The before arm takes the commits as they are; the after arm moves each commit's evidence anchor into its own fragment under docs/evidence/fragments/orchestrator-crew-pattern-studies/<node>.html and drops the plan edit (which becomes a landing: line recorded through the versioned write, not a git change).

Controls

  • No-fragment control: composing the record's own bytes with the fragment directory absent finds 0 anchors, so the anchor check is shown to see something rather than to always pass.
  • Scratch isolation: each arm's head commit resolves under the scratch object store and does not resolve against the repository's own store, so the measure wrote nothing to the shared object directory. (A bare object count cannot carry this check: peers commit to that store concurrently.)

The arms are built in a scratch object store outside the checkout (GIT_OBJECT_DIRECTORY under a private temp directory, with the repository's own objects as alternates). A git clone and a sibling worktree are both refused by a crew worker's git guard, which permits a mutating verb only against the run's own worktree; redirecting the object store keeps the resolved repository this run's own while every byte the measure writes lands outside it.
