The suite holds light promotions — landed evidence

The declaration, the record and the hold all landed in an earlier node; the hold was disclosed there as having no caller. This node gives it one: promotion consults the project's own suite wherever it has already resolved a run's review tier, so the lighter tiers wait while the whole-tree check is broken — and never the full review, which reads the run for itself.

The hold reaches the promotion path

reckon/crew/promotion.py calls standing_suite.hold_reason inside complete, immediately after the review-waiver gate resolves. It passes three things the caller already holds — the run's landing_project, the review_tier just resolved from what the run changed, and the project's checkout root — so the tier is neither re-derived nor copied, and the check sits where the tier is settled rather than in a second decision path that could drift from it. A refusal names the recorded reason and both ways out, so an operator is not left to guess which command answers the node.

The refusal reads, in shape:

standing suite holds this promotion: the project's latest suite run at <rev>
(observed <time>) failed to collect; a tier 'none' promotion waits until a passing
run is recorded or the lead waives it; record a passing run with
`reckon crew suite run --project NAME` or record a lead waiver with
`reckon crew suite waive --project NAME --reason TEXT`

A run whose record names no project owns no declared suite and is not held; a project with no recorded runs returns None from hold_reason and is unaffected, so the many existing promotion tests move no failure id.

Two commands for the coordinator

  • reckon crew suite run --project NAME resolves the project's registered checkout, reads its declared review.suite command and budget from the project flight layer, runs it under that budget through standing_suite.run, records the result with standing_suite.record, and prints the recorded counts as JSON. A project with no mount needs an explicit --checkout-path, so a run cannot be filed under the wrong root and be invisible to the promotion it answers.
  • reckon crew suite waive --project NAME --reason TEXT records a waiver through standing_suite.record_waiver, carrying who excused the hold and why.

Both are subcommands of a new crew suite group.

One scope note

This node's edit is confined to a single call inserted immediately after the review-waiver gate resolves and one helper defined beside it, so the two should merge cleanly, but the coordinator must reconcile promotion.py across the two before promoting either.
