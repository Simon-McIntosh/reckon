a-tier-none-run-owes-no-review — a tier-none run owes no review duty

The review sweep reads a run's tier through promotion's resolver and skips the review of a run that changes no runtime source, recording the skip on the run's pointer. The coordinator's obligations view read the tier not at all, so it held such a run at review-missing with the review dispatch as its next action — a duty nothing could ever satisfy, which the coordinator could clear only by running a review the tier rule had exempted or by acknowledging the duty by hand.

_review_duty_item (reckon/crew/obligations.py) now reads the tier through reckon.crew.recovery._sweep_review_tier, the very resolver the sweep uses, so the two surfaces cannot disagree about which run owes a review and the tier's inputs — changed paths, changed lines, spec level, capability risk — are never re-derived in the duty. A tier-none run reads the kind a reviewed run with a passing review would get, carrying its tier on the duty, and stays in the list rather than falling out of it. A run whose tier requires a review keeps today's reading. The duty's command is composed from the run's own citations rather than taken from the row: _live_item copies the row's next action, and for a scoring row that is the review dispatch the tier rule has just declined to run, so the duty read promotable while naming work nothing would ever do. That composition lives once, as recovery_classification._promotion_command, which the classifier's own promotable branch and the duty both call: a copy in the duty had already drifted from it, offering the manifest's citations without canonicalising them against the run's tree and reading a run whose only citation is its dispatch base as an ordinary citation — printing the form promotion's refusal reproduces.

Measure. In tests/test_a_tier_none_run_owes_no_review.py a temporary crew home holds a documentation run and a runtime-source run, both live and both classified scoring (whose unqualified reading is review-missing). The documentation run's obligation is present with kind review-ready and review_tier: none; the runtime-source run still reads review-missing in the same pass, so the quietening is keyed on the tier and not on something the read did to every run. Gate: 10 passed with the obligation fixtures at the repair round's head, EXIT=0. Two negative controls, each reverting one half of the duty: with the tier read removed the test fails assert 'review-missing' == 'review-ready' (EXIT=1), and with the composed command removed it fails on the docs run's next_command naming the review dispatch instead of the promotion (EXIT=1). A third case pins the base citation: a tier-none run whose only citation is its dispatch base is offered the --no-commit form, so the read the copy had dropped is asserted rather than assumed. The arm of the reuse round is the 90 test files importing the classifier or the obligation module — 662 passed with no failure at the head, against 662 passed and no failure at the same 90 files at base. Ruff check and format over the changed files report exactly the findings the base revision reports for them (UP017 on an untouched line of the classifier and one unformatted expression in the obligation module), so the round adds none.

Fixtures — nine recordings moved, all repaired. The tier read moved nine fixtures from review-missing to the promotable kind. Each pinned a run whose cited commit touches no runtime source, so the tier rule owes it no review and the duty now says so. Every affected fixture now seeds a runtime source under reckon/ in a commit that has a parent, and the run cites that commit, so the run is tiered and the assertions are unchanged. One mechanism accounted for all nine, and it is easy to miss: the tier is read from the cited commit's diff against its own first parent, so a repository's first commit — which has no parent — yields an empty path list and reads as a run that changed nothing at all. After the repair the obligation-fixture arm is 9 passed at base and 10 passed at the new head (the gate included), both EXIT=0, and the 39-file importer arm is 219 passed with no failure, against no failure at base — and again 219 passed at the repair round's head, where the duty's command is composed.
