a-tier-none-run-owes-no-review — a tier-none run owes no review duty

The review sweep reads a run's tier through promotion's resolver and skips the review of a run that changes no runtime source, recording the skip on the run's pointer. The coordinator's obligations view read the tier not at all, so it held such a run at review-missing with the review dispatch as its next action — a duty nothing could ever satisfy, which the coordinator could clear only by running a review the tier rule had exempted or by acknowledging the duty by hand.

_review_duty_item (reckon/crew/obligations.py) now reads the tier through reckon.crew.recovery._sweep_review_tier, the very resolver the sweep uses, so the two surfaces cannot disagree about which run owes a review and the tier's inputs — changed paths, changed lines, spec level, capability risk — are never re-derived in the duty. A tier-none run reads the kind a reviewed run with a passing review would get, carrying its tier on the duty, and stays in the list rather than falling out of it. A run whose tier requires a review keeps today's reading.

Measure. In tests/test_a_tier_none_run_owes_no_review.py a temporary crew home holds a documentation run and a runtime-source run, both live and both classified scoring (whose unqualified reading is review-missing). The documentation run's obligation is present with kind review-ready and review_tier: none; the runtime-source run still reads review-missing in the same pass, so the quietening is keyed on the tier and not on something the read did to every run. Gate: 1 passed, EXIT=0. Negative control — the tier read removed from the duty — fails that test with assert 'review-missing' == 'review-ready', EXIT=1. Ruff check adds no finding; ruff format adds none beyond the same pre-existing unformatted lines the base revision already reports.

Blocker — one failure remains, outside this node's write scope. The tier read moved nine fixtures from review-missing to the promotable kind. Each pins a run whose cited commit touches no runtime source, so the tier rule owes it no review and the duty now says so. Eight are repaired in the files this node was granted: every one of those fixtures now seeds a runtime source under reckon/ in a commit that has a parent, and cites that commit as the run's head, so the run is tiered and still owes the review the assertion names. After the repair the obligation-fixture arm is 9 passed at base and 10 passed at the new head (the gate included), both EXIT=0, and the 39-file importer arm is 218 passed and 1 failed, against 0 failed at base. The one failure left, test_stop_hook_reads_the_snapshot.py::test_a_lane_refused_review_reads_queued_and_returns_after_the_bound, is the same shape in a file outside the granted scope: its repository fixture seeds only seed.txt in a root commit, which its run cites, so the duty returns the promotable kind before the refused-review branch is reached.
