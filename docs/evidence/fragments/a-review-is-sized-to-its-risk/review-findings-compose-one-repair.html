review-findings-compose-one-repair — one repair node per finding-bearing review round

A review that carries findings had no path from its stored record to work. The reflex composes only reviews, and code-review findings were parsed without an identity, so nothing could key "one repair per round" or "no finding left unanswered". Three findings answered in one turn cost one dispatch; a design that emitted one repair node per finding would cost three lanes and three merges against the same files.

reckon/crew/repair.py turns a stored review record into that single node. Each finding is given a stable id minted from the record's own frozen order (f01, f02, …). The node's brief lists every finding under its id, and its write scope is the union of the reviewed run's own fence and the paths the findings name — so a finding outside the reviewed run's fence is granted that path rather than refused the file its brief asks it to edit. The composed done_when obliges the repair to answer every finding by id: acted <id>:<commit> for one it fixes, declined <id>: <reason> for one it does not. The response vocabulary is shared with plan review (stable id, acted-or-declined with a reason) rather than reinvented.

Round identity is the pair the review stands for — the run it reviewed and the head it read. Composition is a pure function of that pair and the record, so composing twice returns the same node_id: a redispatch of a failed attempt is another attempt of one round, not a second round. A run reviewed again at a later head composes a different id, so a later round is not mistaken for a retry. The module imports the existing review parser and store and edits neither.

Gate. tests/test_review_findings_compose_a_repair.py drives a real stored review — written through the shared store into a temporary root — carrying three findings, one naming a path outside the reviewed run's fence, and asserts: one repair node composed; its brief naming all three findings by id; its write scope containing the out-of-fence path; and a second composition of the same round returning the same node. Negative control. The declared mutation — composing one repair node per finding instead of per round — reddens the three-finding case: the composer returns a list of per-finding nodes, so the single-node and round-identity assertions fail. The mutation was applied, the case observed to fail, and reverted before the final commit. The red log negative-control.log under the run directory carries the declared mutation verbatim on its first line, exits 1, and names test_a_findings_review_composes_one_repair_node FAILED.

Scope. Wiring the composer into the review reflex is a later node: reckon/crew/recovery.py and reckon/crew/review.py are held by concurrent nodes and were not touched. A review that carries no finding composes nothing — the clean review is not work, which is the state a separate node's acceptance path consumes.
