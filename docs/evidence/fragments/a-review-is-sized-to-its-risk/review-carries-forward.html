The reflex reviews a settled head and re-reviews only what changed.

A stored review is evidence about a revision, so the moment a reviewed run gained commits the reflex found nothing covering its new head, read the run back as scoring, and composed a second full review of the whole run — even when the new commits changed no runtime source. Section 5 sizes that re-review to the move.

What changed

  • Carry-forward. carry_review_forward measures the paths between the stored review's head and the run's current head. A move over paths that change no runtime source re-stores the stored record at the new head, marked with the revision it came from, so the one selection shared by the classifier (_stored_review), the promotion gate and the obligation producer finds a review at the head the run carries. The run raises no review-missing obligation.
  • Light re-review. A move that does change runtime source dispatches a light review scoped to the moved commits alone. The verdict is the shared classifier's — review_tiers.changes_runtime_source — never a second predicate.
  • Resume withdrawal and settle. A queued review dispatch the run's own resume has moved past is recorded withdrawn; a run resumed within five minutes is left to settle before the reflex reviews it.

Measure

tests/test_review_carries_forward.py — five cases, all green at cc17465e: a resumed run's queued review for the superseded head is withdrawn; a queued review that still covers the current head is not; a data-file relocation carries the stored review forward and raises no review-missing obligation; a runtime-source commit's move is classified by the shared review_tiers.changes_runtime_source (forcing it false flips the verdict); and that move dispatches a light review whose scope is the moved path alone.

Negative control

Removing the carried-forward record write (the store_review(carried) call) turns the data-file relocation test red — EXIT=1, failing id test_a_data_file_relocation_carries_the_review_forward — because the run then reads review-missing. Log: negative-control.log in the run directory.
