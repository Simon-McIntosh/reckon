suite-arms-use-the-armed-command — an armed run's suite pair must measure the command it was armed with

An armed promotion derives its added-failure delta from the baseline_suite and after_suite arms its manifest carries, comparing them against the run's recorded suite_command. Nothing tied an arm's own command to that armed command: a run armed with the project's whole suite could hand in a pair run over a focused test selection, and the delta would be calculated as if it measured the armed suite. Two selections of tests produce two different failure sets, so the recorded delta then described a suite the run was never armed with.

reckon/crew/promotion.py now refuses such a pair. _evaluate_suite_delta compares each arm's command against the record's suite_command after whitespace normalisation — runs of whitespace collapse to single spaces (_normalized_command) — and appends baseline_suite.command_matches_suite_command or after_suite.command_matches_suite_command to the missing-evidence list for each arm that differs. The mismatch rides the same refusal path as any other missing suite evidence, so the run is refused with suite-delta-refused and the pointer carries the refusal. An arm whose command matches is accepted as before, and the unchanged-run exemption and the reasoned waiver path are untouched: an unchanged run needs no pair at all, and a waived run keeps its waiver.

Measure. tests/test_suite_arms_use_the_armed_command.py passes 3/3: a focused pair handed in against a whole-suite arming is refused naming both baseline_suite.command_matches_suite_command and after_suite.command_matches_suite_command; a pair whose arms differ from the arming only in spacing is accepted with a clean delta; and one arm matching while the other does not is refused naming only the mismatched arm. The named gate ran tests/test_suite_arms_use_the_armed_command.py, tests/test_gate_evidence.py and tests/test_an_unchanged_run_needs_no_suite_pair.py together — 32 passed, exit 0 — with no call reaching SLURM.

Negative control. Against a scratch copy of the tree with the command comparison removed, the two refusal cases fail (2 failed, 1 passed, EXIT=1), each because the mismatched pair promoted instead of being refused; the module under test resolved to the scratch promotion.py, confirmed on the log's header. The red log is logs/negative_control.log under the run directory, whose comment line records the declared mutation: drop the command comparison; the focused-pair case must promote and so fail its refusal assertion.
