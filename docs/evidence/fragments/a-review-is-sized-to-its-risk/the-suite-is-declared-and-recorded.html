The suite is declared and recorded — landed evidence

A per-node gate runs only the tests its brief names. A project whose default command stopped at collection — or whose suite quietly outgrew its budget — could therefore keep promoting without anyone running the whole tree. This change gives the project a place to declare its own suite and the ceiling it is held to, a runner that records what each run observed at a named revision, and a hold that says when the lighter promotions must wait.

The declaration

The project layer of flight config now accepts a review.suite block holding a command (an argument vector, run from the checkout root) and a budget (an integer followed by s, m or h). Reckon's own project layer declares it:

review:
  suite:
    command: [.venv/bin/python, -m, pytest, -n, "8", -p, no:cacheprovider, -q, tests/]
    budget: 20m

review_suite(config) in reckon/flight.py returns None when nothing is declared — so a project that has not adopted this is unaffected — and refuses a malformed block by name, naming review.suite.command or review.suite.budget rather than failing somewhere downstream. SuiteDeclaration.budget_seconds() converts the declared budget, so 20m reads as 1200.

The record

reckon/crew/standing_suite.py provides three functions:

  • run executes the declared command from the checkout root under its budget. The runner is started in its own session, so when the budget is reached the whole process group is killed — not just the runner, which would leave forked children behind. The combined output is captured to a caller-named path and the returned record carries the revision, the command, the exit status, the collected/passed/failed/errored counts, the duration and budget, the failure ids, and the flags a hold reads.
  • record writes one JSON file per run under the project's state tree (docs/state/reckon/suite-runs/ for this repository), named by the observation time so a listing sorts by when each run was taken.
  • hold_reason(project_root, tier) returns a sentence naming the revision, the observation time and whichever failure occurred — or None to proceed.

Counts are read by the parsers this repository already uses: the FAILED and ERROR ids with reckon.crew.review's reader, the result-count tokens with reckon.crew.promotion's. Both are imported, not copied, and neither file was edited. The collection line is read in both its plain ("collected 12 items") and pytest-xdist ("[12 items]") forms.

Promotion is deliberately not wired here. This node builds the declaration, the record and the hold; connecting the hold to the promotion path is separate work.

When the lighter tiers wait

A hold exists only while the latest recorded run failed to collect or overran its budget and no later waiver has lifted it. A tier full is never held: a full review reads the run for itself, so it is not made to wait on the project's suite. A latest record that is a waiver, a latest run that collected and ran a test (even if a test failed), a project with no records, and an undeclared suite all return None. record_waiver writes the waiver, carrying who excused it and why.

The distinction that matters: a suite with one failing test is a failing suite, and a writer knows what to do with it. A suite that failed to collect is a suite that no longer runs at all, and it is the failure this hold exists for.

The eight tests added by this node build throwaway projects under tmp_path and run each with sys.executable, so nothing is written outside the test's own temporary tree. They cover: the reader returning None when undeclared; the reader refusing a malformed block by name; the declared budget converting to seconds; a collection failure being recorded and holding none and light but not full; a later passing run lifting the hold; a waiver lifting the hold; a run past its budget being stopped with its process group gone; and the record landing under the project's state tree.

The full project suite was not run by this node; the wave close runs it once at the merged head, and that declaration is this node's own subject.

Two deviations, stated plainly

The schema source, not only its generated artifacts. The assigned write paths named the generated pair (reckon/_flight_schema.py, docs/_shared/flight.schema.json). Those files carry a generator banner and the repository holds byte-identity parity tests between them and their LinkML source at reckon/schema/flight.yaml, so hand-editing them would have been reverted by the next regeneration and would have failed parity. The LinkML source was therefore edited and the generated pair regenerated from it. reckon/schema/flight.yaml is outside the assigned paths and is the one file touched beyond the fence.

The atomic writer. The record is written through the JSON writer this repository already uses for a run record, imported at call time. The writer named in the brief as living in reckon/_store.py is not present at this revision — that helper arrives with separate work — so the equivalent existing writer was used rather than a third one introduced.
