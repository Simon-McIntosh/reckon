the-reflex-resumes-an-unpromoted-run — the repair of an unpromoted run is a resume

The reflex composed a repair node for every finding-bearing review round, but an unpromoted reviewed run still holds its own worktree and its commit claim, so a repair over the reviewed run's own paths was refused at dispatch — measured live as a repair withdrawn about fourteen seconds after it was dispatched and re-fired on every sweep, while the reviewed run's findings stayed unaddressed.

dispatch_repair_for_run in reckon/crew/recovery.py now recognises the unpromoted case: when the reviewed run still has its live pointer, is not promoted, and its worker process has exited, the composed repair — its blocking findings by id, the round's done-when and the declared negative control — is delivered as advice to a resume of the reviewed run itself, through the same entry point a hand-typed crew resume uses (reckon.crew.resumption._resume). No new repair node is dispatched. The round is recorded on the reviewed pointer with status resumed and its round id, and a second sweep for the same round resumes nothing. A run whose worker is live or resumed, whose live pointer has gone, or which is promoted keeps the dispatch path and is settled by its existing guards.

Measure. tests/test_the_reflex_resumes_an_unpromoted_run.py passes 3/3 (EXIT=0) at commit afa5c04f, with the resume entry point and the dispatch both stubbed so no worker is launched and no call reaches a scheduler. The three cases: an unpromoted exited run with one blocking finding is resumed once with advice naming the finding's id and the dispatch is never called; the same round swept twice resumes once; and a promoted run is not resumed and still refuses at dispatch.

Negative control. Disabling the resume branch (if not _repair_launch_refusal(...) → if False) so the unpromoted case routes back to dispatch_module.dispatch reddens the two resumed-not-dispatched cases (2 failed, 1 passed, EXIT=1); negative-control.log under the run directory. Only the named test file ran.

Wider population. Two sibling suites encode the superseded behaviour and fail against this change — tests/test_reflex_dispatches_one_repair.py and tests/test_repair_skips_out_of_repo_findings.py (base arm 23 passed EXIT=0; head arm 10 failed / 13 passed EXIT=1). They are outside this node's write scope and are reported as follow-ons; each asserts a dispatched repair node for an unpromoted reviewed run, which this change replaces with a resume.
