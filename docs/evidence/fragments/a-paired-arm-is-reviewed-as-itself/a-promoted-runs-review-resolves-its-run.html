A promoted run's review resolves its run

Change. A review node id minted from a run's node id resolved against the live fleet alone, so once the run was promoted there was no pointer left carrying that node id and the resolver handed the grant a bare node id. A bare node id names no run directory, so the record directory was refused — the scoped refusal that blocked re-attaching r-20261019T214532819779-cs1-ripple-window's review. Two edits close it. _resolved_reviewed_run_id (reckon/crew/recovery_review_delivery.py) falls back, when no live pointer carries the source node id, to _durable_reviewed_run_id — the durable rows carrying that source node id, chosen by the head suffix the node id mints through round_node_head_suffix and compared against the head _run_head_for_review gives each row. Exactly one match resolves; no match and more than one both return the bare source whether or not refuse_ambiguous is set, and a read that raises is answered the same way and never propagates. The reader, runs_for_node (reckon/run_store.py), selects rows by the indexed node column, scoped to the caller's project whenever it has one and across projects only when it has none, over a read-only connection that creates and migrates nothing. Live pointers are still read first, so every resolution that worked before works unchanged.
