A paired arm's review names its run

Change. A paired dispatch launches two arms under one node id, so a review node id minted from that node id is ambiguous: the codex shadow's printed review command resolved to its clive primary and dispatch refused it as not-dispatchable on the scoped property. Three edits close it. _review_dispatch_fields (reckon/crew/recovery_review_subject.py) mints the review node_id from the reviewed arm's own run id when the record is one arm of a pair, read through _paired_partner_run_id (reckon/crew/promotion_checks.py) — the test promotion already resolves a partner with, not a second pairing test — while source_node stays the node id every other reader composes from. _resolved_reviewed_run_id (reckon/crew/recovery_review_delivery.py) gains a keyword-only refuse_ambiguous flag defaulting false; with it set, more than one live pointer sharing the source node id returns the bare source rather than the first match. _reviewed_run_id_for_node (reckon/crew/dispatch_admission.py) is the only caller that sets the flag, so only the dispatch grant changes; every other reader keeps the first match. An unpaired run is unchanged.
