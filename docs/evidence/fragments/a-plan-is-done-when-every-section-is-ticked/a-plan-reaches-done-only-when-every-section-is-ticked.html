A plan reaches done only when every section is ticked

A write that moves a plan into shipped or done is refused while any section declaration is still implementable or deferred, and the refusal names the open sections in declaration order. The guard _store._require_every_section_ticked reads the shared _plan_html.open_sections predicate and sits with the existing terminal-status guards: validate_landing_patch for the patch writer, the terminal check in apply_ops for the ops writer, and the terminal block in _write_state_locked. It keys on the transition into a terminal status, so a plan already at one is not re-judged and history under an earlier rule stays editable.

The guard is transition-keyed rather than a state-level invariant precisely so these 17 are not locked by a newer rule: they stay editable but cannot be re-landed while a section is open.

The patch path keys on the transition too

The three guard sites must agree on when the rule applies. The ops path (apply_ops) and the common write path (_write_state_locked) already read the status that preceded the write, so an already-terminal plan is not re-judged. The patch path (validate_landing_patch) originally keyed on the requested status alone, so a plan already at shipped or done that held an open section was re-judged on a later patch — including a patch that merely re-asserted the same status. The patch writer merges the patch into the state before its validators run (serve.py calls _patch_into first), so the status the state carries is the requested one and the transition is invisible there. The fix reads the status that preceded the write from the stored plan — the same technique _followups_before_the_patch already uses for the followup rule — and skips the section guard when that status is already terminal, matching the other two sites. The existing terminal-evidence and transition-verdict checks beside it are unchanged.

The failures are an order-dependent flake of the kind this suite has shown before; a base-arm run of the same set was started for comparison — it did not complete inside the node's bound on a contended host and was stopped.
