A plan reaches done only when every section is ticked

A write that moves a plan into shipped or done is refused while any section declaration is still implementable or deferred, and the refusal names the open sections in declaration order. The guard _store._require_every_section_ticked reads the shared _plan_html.open_sections predicate and sits with the existing terminal-status guards: validate_landing_patch for the patch writer, the terminal check in apply_ops for the ops writer, and the terminal block in _write_state_locked. It keys on the transition into a terminal status, so a plan already at one is not re-judged and history under an earlier rule stays editable.

Census — plans already terminal with an open section

Run over every mounted project's plans (census_open_sections.py), before the guard: 15 projects, 374 plans, 213 already at a terminal status, 17 of those with a non-empty open_sections. The guard is transition-keyed rather than a state-level invariant precisely so these 17 are not locked by a newer rule: they stay editable but cannot be re-landed while a section is open.
