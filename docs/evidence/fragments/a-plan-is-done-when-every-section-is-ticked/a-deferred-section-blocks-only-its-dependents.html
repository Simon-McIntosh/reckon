A deferred section blocks only its dependents

Roadmap readiness judges a dependency on a whole plan by that plan's sections. _whole_plan_dependency in reckon/roadmap.py is the one entry point. The declared depends_on edge, a gate reference, a soft after edge and the graph closure all call it. It treats a dependency as satisfied in two cases: the target plan is complete, or at least one of its sections is done and none is still implementable. A dependency on one section is satisfied only by a done declaration. Deferred and implementable sections never satisfy it.

Held for the orchestrator's judgment

The lead locked uncertain-dependency = judgment-required. Under it, two cases have no fixed rule. Both are held by default, and both are reported so the orchestrator can weigh them rather than have a rule decide:

  • deferred-only: every open section of the target is deferred, and none is done.
  • undeclared-heading: the target has an authored section heading that its declaration map does not name.

Every edge path carries a judgment_required block, {required, count, members}, beside schedule_override. Each member names the dependent project and the target project on its own side, so a judgment that crosses projects says which plan is which. skills/reckon-build/SKILL.md names the block, so a coordinator reads it before scheduling.
