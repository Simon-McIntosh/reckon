Every section has a declaration

Census of every mounted project's live (non-terminal) plans for a heading/declaration coverage gap, counted 2026-10-08: 109 gapped of 214 live plans. A gap a plan already carries is not refused: the write guard compares the gaps after a write with the gaps the plan carried before it and refuses only when the write adds one (decision coverage-gap-scope = refuse-new-gaps). The 109 are reported by reckon audit-doc as section-without-todo or todo-without-section, and stay writable; a plan that would acquire a gap it did not have is refused at that write, naming only the new id.

A gap a plan already carries cannot be used to land it. At the transition into shipped or done an authored heading with no declaration is counted as open beside the sections declared implementable or deferred, and the refusal names it; the headings are read from the plan's HTML, so a heading nothing declares has an answer owed. The check applies wherever a landing can be written: the state write, the landing patch, and the op batch that applies before either. A plan already stored at a terminal status is not re-judged, so history stays editable.

POST /plan/<project>/<slug> patches state and renders the file itself, reaching neither store write path, so it runs the same coverage comparison on the text it read and the HTML it is about to write. A patch that would drop a declaration or introduce a heading without one is refused with 400 section_coverage, naming the new ids, and the file is left unchanged.
