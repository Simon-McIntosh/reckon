An exited attempt's harness caches leave with that attempt

_supervisor_exit_record now removes the harness scratch an attempt built for its own process before it composes the record: the client's plugin catalog and download cache under codex-home/cache/ and codex-home/plugins/, and the per-run tool cache under cache/. The paths it removed and the size each held go onto the record under removed_harness_caches, so the attempt's own receipt says what left with it. The removal is bound to the writing of an attempt's exit record rather than to the presence of one, so a later attempt of the same run filling the same paths is never touched by a read of an earlier attempt's record. The client's session tree a resume reads, codex-home/sessions/ (named by RUN_HOME_SESSIONS), is deliberately not listed and survives. A removal that fails leaves the path in place rather than raising, because a surviving cache must not cost the run its exit record.

A fixture run holding codex-home/cache/, codex-home/plugins/, cache/ and codex-home/sessions/, put through _supervisor_exit_record, keeps the session tree and loses all three caches, and its record lists each removed path with the bytes it held. A fixture that has not exited keeps everything. A run whose first attempt has exited and whose second is running keeps the second attempt's caches through a later read of the first attempt's exit record.
