A run's scratch leaves with the run, on every host that holds a copy

A directory named for a run is that run's scratch on whichever host it sits, and node-local scratch is not shared between hosts, so the rule is now kept by run rather than by host. remove_worker_scratch names the host that removed each copy (scratch_host) and reports scratch_absent when the host it runs on holds nothing, so a receipt can no longer be read as describing a copy elsewhere. reckon.crew.gc.settle_run_scratch is a pass of its own, not the garbage_collect_scratch survey: it reads each run-named directory under the scratch root, and removes it at once — no age wait — when its run has no live pointer, no process holds it, and the run directory in the shared crew home records that the run ended (exit.json, an attempt-N-exit.json, or the discard marker). A copy whose run has neither a pointer nor a run directory waits for SCRATCH_GRACE_SECONDS, after the same holder check. It runs from three callers: ensure_worker_scratch, which the launch, resume and lane-change paths all reach before a new worker's scratch is made; the step wrapper _STEP_TASK_WRAPPER, for a node that only runs steps and never launches; and §7's hourly retention_sweep, which now calls it and appends its removals to the same rotating log. The pass removes nothing when the state home and the scratch root are not both known to it — a caller that sets RECKON_HOME alone leaves the host-wide default root in place, where the copies belong to runs whose live pointers that private home cannot see, and the holder scan does not reach a worker sitting in its worktree between turns. It therefore withholds with state and scratch roots differ, the same guard the orphan sweep applies. The release receipt is also written beside the run's own record (release.json) before the ledger write, because the ledger write is not durable on its own — see the route named below.

The routes, and the records they were read from. Every ledger row under every mounted project's docs/state/<project>/runs/ was joined against the scratch directories on this host and against ~/.config/reckon/crew/live/. Of the 105 run-named directories here, 42 belong to live pointers and were left alone; the remaining 63 split into four shapes, and each shape names a different route:

  • 33 rows record scratch_removed: true, naming the run's own path in scratch_removed_paths, and the directory is still here. The receipt is true about the host that ran it and silent about this one: both hosts spell the path identically (/tmp/reckon-crew-scratch/<run> reports), so the release removed the same-named path on the promoting host while the worker's copy on this host was never in its reach. Examples: r-20261020T202608740663-shc-gap-docs-regen, r-20261020T202606397921-scg-name-domain-writer. This is the route §8 exists for, and it is closed by settle_run_scratch running on this host.
  • 16 rows record scratch_removed: false. The release ran on a host holding no copy, so it had nothing to remove and withheld the reason — e.g. r-20261020T212940955037-review-of-ssog-anchor-rerun-wall-recomb-jev-b032b1c48f66. Here too the surviving copy is on the worker's own node.
  • 14 review and plan-review rows carry no release block at all (release: null). Two effects put them there. Where the release's own ledger commit could not stage, _commit_landing_writes (reckon/crew/promotion_scope.py) restores every path it wrote to HEAD before refusing, so the receipt is erased with the commit: the run directory of r-20261022T165107694120-review-of-the-claude-account-is-read-from-their-own-record carries eleven stage_retry entries and a final stage refusal in its landing.json, and its committed row has release: null. Where the receipt's commit short-circuited, the row keeps the schema default and no release(...) commit exists for the run — r-20261023T093727181057-review-of-a-plans-coordinator-is-derived-from-the-ledger-4fed6ea3963c has one landing.json entry (its landing commit, 10:10:50Z) and no release entry, while a peer promoted minutes earlier carries one. The route is therefore the release receipt depending on a landing commit that is not durable, not a promotion path that skips the release: every promotion path calls _release_after_promotion before _record_release_on_ledger (reckon/crew/promotion.py:1752 and :1125). This node makes the receipt durable beside the run record, and settle_run_scratch removes those copies whether or not a receipt ever landed.
  • The survivors that fit none of the three records above: two, and both are rows absent from every mounted ledger. r-20261021T073526532476-jt60sa-2023-shot-census and r-20261023T181108111637-review-of-a-disposition-after-promotion-reaches-the-reflex-afd3f6e5bd8b have a scratch copy here and no row under any project in mounts.json, so the release recorded nowhere these records could be read. Their copies are the "no run directory or no row" case the settling pass takes under the grace, after the holder check. (The plan counts four; reading the same records at 01:5xZ today finds these two still surviving, the other two having since been reclaimed, so the class is named by its route rather than by a fixed count.)

In a temporary crew home and a temporary scratch root, remove_worker_scratch removes this host's copy and its timestamp-stem sibling, records scratch_removed: true and names the host; the same call with no copy present records scratch_absent: true and removes nothing. On a second host, ensure_worker_scratch and, separately, retention_sweep each remove a finished run's fresh copy — its ctime is well inside SCRATCH_GRACE_SECONDS, so no age wait applies. A copy under a live pointer, and a copy a process holds open, are both left. A run-named copy whose run has neither a pointer nor a run directory is left at its own ctime and removed once past the grace. A private home that leaves the scratch root to this process's environment removes nothing, and names state and scratch roots differ; a caller that names both trees is settled as usual. The step wrapper, run under bash with the wrapper's own environment, removes a finished run's copy. A review run's release removes its scratch and names the host, and its receipt survives a landing commit that is refused.
