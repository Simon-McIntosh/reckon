Reload images live under the node's runtime root

checkout_trust._committed_tree_cache resolves the image cache through reckon.crew.station_store.runtime_root_source — the station's own resolver, not a second one — and returns <runtime root>/reload-trees. When no node-local root is available it raises, naming the three candidates, rather than falling back to the crew home, and the answer it does take goes through the station's own filesystem-type proof (_refuse_nonlocal_root), so a root on a shared mount — including the TMPDIR fallback when that sits on GPFS — is refused in the station's words rather than written to. No second check is written beside the station's. With every image node-local, the cross-node lease record is gone: _record_lease_node and _lease_nodes are deleted, pin_materialized_tree and refresh_materialized_tree_pin no longer write it, and _prune_must_keep loses its host branch. What remains is the same-node rule: an image whose .in-use mark exists is left to the pruner's flock, which is visible on this node and refuses while a reader holds one, and a tree with no mark yet — the publish-to-lease gap — is spared for the publish grace.

The gate ran in the foreground on the fleet allocation: 35 passed at head across the six reload tests named in the brief, the revised pruning file, the housekeeping file and the new cache file. The armed pair reads 6 failed, 5 passed at the base revision (EXIT=1) and 11 passed at head (EXIT=0), and a further case steers the resolver at a root the station's proof calls shared and asserts the cache is refused.

Negative control. The declared mutation makes the resolver return the crew-home path. The path test then fails — 6 failed, EXIT=1 — while the head arm fails none.

The fixtures follow the cache. tests/test_a_reload_waits_for_a_clean_tree.py gives its producer a temporary XDG_RUNTIME_DIR created by the isolated_home fixture and asserts the image under that root, so no run of the suite writes into the node's real /run/user/<uid>/reload-trees. The pruning fixture that held a tree as another node did is deleted with the record it exercised, and the two fixtures that wrote a lease record or stubbed the node name drop both, which leaves _lock_node_name and COMMITTED_TREE_LEASE_MARKER referenced nowhere and deleted from the product.
