A retention pass finishes inside its slot

retention_sweep now stops after it has examined its limit rather than after it has offered that many directories for removal, so a head of permanently withheld rows cannot consume a pass's whole budget without advancing. It resumes from a cursor persisted under the crew home (RECKON_RETENTION_CURSOR may name it), so that withheld head is walked once per cycle instead of re-judged every hour, and it resolves each project's grace window once rather than once per judged directory as _run_directory_grace_seconds did. Progress lines and one timing line per phase go to stderr as the pass runs, so a pass killed under its timeout still leaves a record; stdout keeps the single JSON report main() and crew retention-sweep emit.

tests/test_a_retention_pass_is_bounded.py (5 cases, synthetic crew home of 2,000 run directories) passes at the head: 5 passed. The base arm, the test files importing reckon.crew.gc that exercise the changed function, run at 976bf02dcc in a scratch extraction: 33 passed. Both negative controls produce a red log: counting only offered rows again fails the limit case, and resetting the cursor at the start of every pass fails the withheld-head case.

The first 500 examined directories offered nothing for removal: 486 were withheld with a missing derived figure and 14 were skipped as unledgered or live. That is the defect this node bounds — without a cursor, every hourly pass spends its budget on the same withheld head. A direct probe of the same store measures the judge phase's fixed cost: listing and is_dir() over 20,975 entries takes 169.86 s, and 500 subsequent stat() calls take 3.87 s, so the listing is paid once per pass and the per-directory judgment is cheap.

A dry run with --limit 100000 was timed on the same quiet window. It completed the ledger phase in 25.696 s and reached the judge phase, where per-prune tree_size_bytes walks on GPFS dominate: at 936.25 s it was still judging, having examined 8,310 directories (7,976 judged, 4,602 offered), and the run ended EXIT=143 rather than completing the store. That is the full-store pass, which the plan does not require to finish in one run — the acceptance is that a pass of 500 finishes under five minutes, and the bounded cursor retires the full store across successive hourly passes rather than in one unbounded run.
