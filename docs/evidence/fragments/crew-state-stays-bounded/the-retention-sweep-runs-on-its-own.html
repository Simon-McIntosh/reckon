An hourly timer runs the run-directory retention across every mount

reckon.crew.gc.retention_sweep is the pass, and python -m reckon.crew.gc --apply is the entry point the installed unit runs; reckon crew retention-sweep is the operator surface, with --apply, --limit, --project and --install-timer. The pass starts no git process and inspects no worktree — it is the run-directory retention alone — because garbage_collect's worktree checks are where the unscheduled pass spent its ten minutes. Both garbage_collect and the sweep classify a directory through the one predicate _run_directory_retention_report, so the hourly pass and the on-demand gc cannot drift on what a run directory is. Each pass removes at most RETENTION_SWEEP_LIMIT (500) directories, so a pass over the backlog stays short on shared storage and the next hour takes the rest.

Every mounted project's ledger is read once, through ledger.runs — the index-backed reader the rest of reckon uses — and each run directory is judged against the ledger of the project that dispatched it. That is what retires a run another project dispatched, which one project's ledger could never judge. A directory no mounted project's ledger records is left to gc's existing unledgered-directory pass; a project with no readable mount is reported under unreachable_projects rather than judged, since without a checkout there is no committed-review store to test a review-owed run against. A pass appends its removals to crew/logs/retention-sweep.log through _WatchLogStream, which rotates the file to one .1 sibling at a fixed size, and writes nothing at all when it removed nothing.

The units are installed by reckon.service.install_timer_units — the one generic write-and-enable step in reckon/service.py, modelled on install_timer in reckon/crew/paid_lanes.py; that module is held by another run and is not changed here. reckon.crew.gc.install_retention_timer renders the hourly service and timer and delegates the write, reload and enable to it, so an unchanged re-run writes nothing and calls nothing.

What the gate measures

One temporary crew home holds finished runs for two projects, each ledgered in its own project under its own mount: one pass removes both, and its log carries both paths. A second pass with nothing left removes nothing and leaves the log byte-identical. A pass over 1,200 removable fixtures removes 500 and leaves 700 on disk for the next. A pass whose fixture checkout carries a registered git worktree removes both runs while a git shim first on PATH records no invocation — a measured absence, since the same pass completed its removals. A spy on the ledger's index-backed reader records both mounted projects read through it: the pass reaches that reader once per mounted project, so a pass that parsed an aggregate instead would leave the record empty and the case red. Installing under a temporary systemd user directory writes reckon-crew-retention.service with ExecStart, reckon-crew-retention.timer with OnUnitActiveSec=1h and Unit=reckon-crew-retention.service, and issues daemon-reload then enable --now reckon-crew-retention.timer; a second install reports changed: false, issues no command and leaves both files' mtimes untouched. The gate reporting those six cases is 140 passed in 157.86s (0:02:37) at revision 341d6a5be — the six new cases, the paid-lanes timer cases, and every existing module that imports the systemd surface — with ruff check and ruff format --check reporting nothing added on the staged paths.

The unit sections live in reckon/service.py rather than in the sweep's own module. One thing a periodic pass does not inherit is its ordering: the shared template takes an after argument, the publish service passes network.target because it reads providers over the network, and the sweep passes nothing because it only touches the local crew home. A case renders both and requires the directive on the publish unit and its absence from the sweep's, so dropping the line shows up as a failing test rather than as a timer that starts before the network is up. A repo-wide case inventories every module whose source carries a systemd section and fails when one appears elsewhere, so that a policy repair cannot land on one copy of a unit and miss another; the retention service and timer therefore render through service.render_periodic_service_unit and service.render_periodic_timer_unit, and only one module writes the sections.

Declared negative control: only the first project's ledger is read

The declared mutation narrows the sweep's project list to its first entry, so only the first project's ledger is read. The two-project case — test_a_pass_retires_the_finished_run_of_every_mounted_project — then fails, because the second project's finished run is left in place, which is exactly the failure mode the section exists to remove. The head arm fails no test. The mutation was applied and the case file run against it: 3 failed, 3 passed, exit 1, the head arm having passed all six. The three failures are the two-project case, the git-shim case (which also needs both projects retired) and the ledger-read spy (which asserts both projects are read), and the three that pass are the cases a single project exercises. The mutated source was restored from a byte-identical backup, and the worktree is clean at that revision afterwards.
