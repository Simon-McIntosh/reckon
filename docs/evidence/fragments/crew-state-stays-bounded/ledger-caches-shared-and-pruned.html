One persistent cache per repository and projection

The cache key combines the repository's common git directory, the ledger's tree-relative path and the projection version. Identical worktree ledgers read the main checkout's index; a differing aggregate or per-run document reads through without publishing another full index. Git pointer discovery reuses reckon.git_head, and unchanged content digests reuse reckon.file_memo. Process-region keys retain the caller's root spelling; only the persistent source is normalized, preserving the existing derivation contract.

The existing gc.retention_sweep calls _orphan_ledger_indexes and _expired_picker_views. It prunes missing-source indexes and picker budget views older than seven days, prints each removal, and records it in the existing rotating retention log. The configured and fence-fallback cache roots are covered while private homes remain isolated. Local open descriptors and SQLite write locks protect active files; an index backed only by per-run documents remains valid when no aggregate exists. Scheduled diagnostics preserve the existing on-demand garbage-collection JSON response.
