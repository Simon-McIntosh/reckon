A finished run's directory is retired on need, not on age

The retention pass no longer judges a run directory by its mtime alone. A directory is kept while anything can still need it — a live pointer or a queued entry, no terminal ledger row (an unpromoted run may still be resumed and re-promoted), a review owed or in flight, or stream-derived figures absent from the ledger row — and once none of those holds it is held for a configured grace window and then removed. The window is the flight key gc.directory_grace, written as an integer and a unit (s, m, h) and defaulting to 24h; it is declared in reckon/schema/flight.yaml and regenerated into reckon/_flight_schema.py and docs/_shared/flight.schema.json by scripts/regen_flight_schema.py, never hand-edited. The raw-report, lock and unledgered-directory sweeps keep their own thirty-day age and are untouched.

The window is read through reckon.crew.node.parse_duration rather than a second units table, and the committed-review test calls promotion_checks._committed_review_rounds and asks whether it returned any reviewed head, so the sweep and promotion agree on what a landed review is. The config is resolved with checkout_path set to the checkout being swept, the same way the run-file bound is resolved in the same pass, so a project layer's override is read from that checkout.

Each removal prints the directory's path and its measured size before it happens, on the same pass that removes it, so the reclaimed set is readable in the command's own output rather than inferred from a report afterwards.

Seven planted states, one removal

One temporary crew home holds seven run directories, one per state a finished run can be in: a live run and a queued run (each sixty days old), an unpromoted run with no ledger row, a promoted run owing a review, a promoted run whose stream-derived figures were never recorded, a promoted and reviewed run inside the grace window, and one reviewed run past it. A dry run of garbage_collect lists exactly one for removal — the reviewed run past its window — and the real run removes that one and leaves the other six on disk; the withheld rows name review-owed and missing-derived-figure as their reasons. Measured: 5 passed, the file carrying two further cases: a configured gc.directory_grace of 3h resolves so that a run promoted and reviewed four hours ago is retired while one reviewed two hours ago is kept, and a window in no duration form — reachable only through a config the schema never validated — falls back to the shipped day, with a run reviewed twenty-five hours ago retired and one reviewed two hours ago kept. A value in no duration form written into a real layer is refused by the flight schema itself, which is where the typo is caught.

The unpromoted fixture is deliberately younger than thirty days but far older than the grace window, so it is the unledgered-directory sweep (a different pass, thirty days, outside this node's write scope) that would hold it on age alone and the retention predicate that holds it here. That is what makes the declared mutation decisive.

Declared negative control: the predicate reduced to age alone

Applying the declared mutation — the live-pointer, queued-entry, in-flight-review and review-owed tests removed so the directory is judged by age alone — fails all three cases (3 failed, 2 passed, EXIT=1): the dry run offers runs that something can still need, and the withheld-reason assertions lose their rows. The two passing cases are the grace-window cases, which measure the window rather than the predicate and are untouched by the mutation. Each failure names the full prune set, so the fixtures the predicate exists to hold are visible rather than implied: ['figures-missing-run', 'live-run', 'queued-run', 'review-owed-run', 'reviewed-old-run', 'unpromoted-run'] — the older unpromoted run the plan names is listed once the guard that held it is dropped. Restoring the predicate from a byte-identical backup brings the file back to 5 passed.
