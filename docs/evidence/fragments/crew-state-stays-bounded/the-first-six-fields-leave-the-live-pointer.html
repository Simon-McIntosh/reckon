Six dispatch fields live beside the run

Dispatch stores picker_selection, admit_request, argv, competence, peer_scopes and unreconciled_override in dispatch-detail.json. The live pointer carries that file's path. One accessor reads the stored path and falls back to inline values on old pointers; observation, resumption, admission, promotion and the server use it. A promoted ledger row retains its picker selection and unreconciled override.

Before the change, the test dispatch raised KeyError: 'dispatch_detail', and an AST check found four direct reads in source. The six existing test cases that read moved fields directly initially failed with KeyError; they now assert the same field values through the accessor. The final AST walk of reckon/ and tests/ found no direct live-pointer read of those fields.

A CLI test dispatch wrote a 12,193 byte pointer, below the 12 KiB (12,288 byte) bound, with none of the six fields inline. The base arm passed 14 tests and the final head arm passed 19, adding no failures. An in-harness diagnostic pointer measured 14,165 bytes because its remaining directive is large; later work in this section moves that field.

With the inline-pointer fallback removed from the accessor, the old-shape test failed on picker_selection with EXIT=1. The mutation was restored after the red run, and the final head arm has EXIT=0.
