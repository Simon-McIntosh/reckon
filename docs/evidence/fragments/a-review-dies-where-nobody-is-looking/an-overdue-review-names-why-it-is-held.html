An overdue review names the refusal that holds it

The defect

When a delivered run's review had not been dispatched past the armed follower's sweep window, _reflex_review_command printed inspect the follower's review pass. The follower was usually healthy. dispatch_review_for_run declined first, in _open_review_refusal: the run's newest stored review still carried a blocking finding with no disposition, so a fresh round would repeat it. That refusal already names the blocking finding and both crew dispose commands that lift it, and the duty never asked for it.

Reproduced on the base tree with the new test module copied in. The first case FAILED because the duty carried no refusal and still printed the follower text:

assert 'inspect the... review pass' not in 'review over... review pass'
E   "inspect the follower's review pass" is contained here:
E     's review; inspect the follower's review pass
1 failed, 1 passed

What changed

  1. reckon/crew/recovery_review_dispatch.py: review_dispatch_refusal(record) is the read-only form of the predicate dispatch_review_for_run applies before it composes anything — the same _open_review_refusal, called with dry_run=True so a reporting reader cannot write a refusal onto a live pointer.
  2. reckon/crew/obligations.py: _reflex_open_refusal answers None inside the reflex's window and, once past it, asks review_dispatch_refusal. A held review sets the duty's reason to the refusal's own text and its next_command to the first undisposed finding's crew dispose pair, built by the same _finding_dispose_commands the refusal renders. Nothing refuses → the duty reads exactly as before, including the reflex-owner fields.
  3. New tests/test_an_overdue_review_names_why_it_is_held.py: two cases on a synthesised repository, a temporary crew home and an armed follower whose review window has passed. Case one asserts the dispose pair, the absence of the follower text, and that the duty's reason equals what dispatch_review_for_run returns for the same record, so the two cannot name different reasons. Case two has nothing refusing and asserts today's text.
