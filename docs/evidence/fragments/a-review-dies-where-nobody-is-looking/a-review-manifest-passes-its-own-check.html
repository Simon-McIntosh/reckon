A review's own manifest passes the check it runs

Read at base b04701d0e, changed at d62c8f6ed with the cases at 01c66e55f. Two nova reviews stored a parsed record at the only path their dispatch granted, marked their manifest complete, and were refused by the check a worker runs on itself before it ends its turn. Both refusals were reproduced at base with the currency probe (review-dies-currency/review_currency_probe.py), and both are gone at head.

What refused them. A review's whole deliverable is the record it stores beside the run it read, and that store lies outside the repository. The declaration mapping resolved only declarations lying under the worktree or the repository, so the store path was dropped and every changed path was judged stray against nothing; and the commit finding asked a commit of a role that has none. The rule now. A declaration that resolves to no repository root is compared as the absolute path it already is — equality or containment — so the declaration the dispatch granted still decides what it grants, and a relative changed path is still judged by the repository mapping alone. The head-keyed record the store writes beside a granted record (<stem>.at-<7..64 hex><suffix>) is the same deliverable under the revision it read, and the declaration of the record admits it. The commit finding is asked of no review, whose deliverable no commit records. A list annotated in place is read as the list, so prose beside an empty changed_paths is no longer reported as a changed path.
