Local-lane session inheritance is zero across the task key

The question

A dispatch that resumes a session sends the earlier conversation on its opening request, so a node inherits whatever an earlier node gathered — the cost §8 recorded as 284 of 318 local resumed runs carrying more history than their own prompt, with a median of about 82,000 inherited tokens. Dispatch session reuse was then keyed to the run's own task, and the codex half of this census measured the metered lane afterwards: docs/research/data/codex-resume-burn-after.json reports zero cross-task resumes over 75 codex dispatches, but over a window in which no session was reused at all. This node measures the local lane the same way, over a window in which reuse was exercised.

Method

docs/research/scripts/scan_local_session_carryover.py walks the run directories, keeps every run whose recorded backend is the local lane (clive or its clive-glm alias — the two names the ledger's unmetered discriminator carries) and whose own stream opens the claude grammar, and reads two things: the run's launch records (the run store's row, plus the run directory's attempt.json and worker.json where they exist) and a prefix of its stream that stops at the first assistant record carrying usage. No run's whole stream is parsed; 6,748 streams cost 137 MB of prefix reads and the pass took 28.6 seconds, both recorded in the file.

The classes, the window rule and the summary fields are the ones the codex census uses, so the two files compare field for field. A run is fresh when it opened its session, and resumed when an earlier run by dispatch order opened the same session id, which is the only durable record of what the first turn actually sent: a launch argv that declares a resume while the stream opens a new session inherited nothing. A resume is same-task when the session's owner shares this run's (project, plan, node) identity and cross-task when it does not. Inherited tokens are the first turn's charged input less the fresh-run median of the same population (64,636 tokens on this lane, against 41,002 on codex). The boundary is the committer time of adbb6067, 2026-09-23T10:40:20Z, matched against the run id's own timestamp.

On the local lane 27 of the 273 resumed runs read zero inherited tokens because the resumed session's own turn was refused by the endpoint, and the first-turn instrument under-reports a refusal by construction — the plan's motivating death is one of them, below. The reproduced figure over the resumed runs that were charged is a median of 74,725 inherited tokens and a maximum of 492,702.

The zero is read over a window in which reuse was exercised. Every local dispatch after the boundary opened a new session in its own stream, so the stream population alone would read as a window in which nothing was reused at all. The launch records say otherwise: 148 of the 1,439 after dispatches carry an attempt whose argv declares --resume, and every one of the 148 targets the declaring run's own session — a crew resume continuing the attempt it succeeds, which is the same task by construction. Zero target another task and zero target a session outside the population. The launch recorder begins 2026-09-24T08:08:24Z, a day after the boundary, so the declarations cover 1,270 of the 1,439 after dispatches; the other 169 are the first day after the boundary, where no declaration is recorded rather than none made.

Controls

Positive control. The instrument is shown to read a cross-task resume it already knew: r-20260911T082453435340-n-swcr-cut-the-candidate-now-the-guard-reads-it-right is classified cross_task with 492,702 inherited tokens (first turn 557,338), its prior session owner r-20260911T054747432149-n-swcr-cut-the-candidate-and-open-the-fork-review-request is a different node of the same project, and the run is named as resumed with that same prior run by the earlier census docs/research/data/session-carryover.json — a different instrument, taken on 2026-09-23, which reported 494,181 inherited for it. That the two figures agree to 0.3% while the bases differ is the check that both are reading the same quantity.

Negative control. Classifying every dispatch as fresh in a scratch copy of the scanner reddens the gate: positive_control becomes null and test_positive_control_is_a_before_window_cross_task_resume fails, 1 failed, EXIT=1 (negative-control.log in this node's run directory). The same scratch copy unmutated runs the gate green first, so the red is the mutation and not the scratch tree (negative-control/clean-gate.log beside it). The scanner's first-record histogram is its own positive control: 3,695 claude streams and 3,017 codex streams are both present, so the pass discriminates rather than returning nothing.

The motivating death, re-read. r-20260923T031542572571-cca-exact-bank-callback-capacity-from-the-mesh is in this census as a cross-task resume whose prior owner is r-20260922T213154046276-cpu-fold-duplicate-probe-exit-tests, with a first turn of zero charged tokens because the endpoint refused it — the same run and the same owner §8 records, reached here from the stream rather than from the run record.

What this does not claim

  • The resumed attempt's own first turn is not measured, only its declaration. A crew resume writes its stream to a later file, and this census reads the dispatch stream. So the 148 after-window resumes are attributed by their launch record's argv — same-task or cross-task — but the context their resumed turn carried in is not read here. On the before window the same path exists and is visible in the stream population because reuse then happened at dispatch.
  • 26 claude-dialect runs are unplaced. They have no run-store row, no launch record and no local model name in their opening record, so no record places them on a lane and they are excluded from both windows rather than guessed at. A further 14 runs recorded local have a stream that opens in another grammar, so their dispatch stream is another attempt's and they are excluded too.
  • A session opener whose own run directory is gone reads as fresh. The session join can only see run directories that still exist; the drift this causes is bounded by the 26 unplaced runs above, and a resumed run misread this way carries its inherited tokens in a row still classified fresh.
  • This measures the local lane's dispatch path. The merged result is a separately dispatched test node's job, and anything failing outside this node's declared paths is carried under follow_ons rather than repaired here.
