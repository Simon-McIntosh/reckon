The delivered-review stop reads the later write, and its template guard fires

The defect

Two findings from the review of the delivered-review stop, both confirmed against the base revision b04701d0e before either was repaired.

  1. The delivered_at assertion could not fail. It compared the reader's return value with max() of the two mtimes the reader had just returned, so it was true by construction; and the fixture dated the record and the manifest writes to one instant, so a regression that dated the delivery from the earlier write would have left the file green. Reproduced: at the base revision with the declared mutation applied (max replaced by min in review_delivered), the original test file reported 7 passed, exit 0.
  2. The template-status clause could not fire. In _complete_manifest_write_time the guard read status != "complete" or manifest_status_is_template(status). The second operand is only reached when the status is complete, and a status carrying the dispatch template never equals that word, so the clause could never decide the branch. The behaviour was correct by accident; what was wrong was that a guard named the template while nothing could reach it.

What changed

  1. reckon/crew/recovery.py, one line: the clause is consulted before the equality test, so the status that names the template is refused by the check written for it rather than as a side effect of the equality. The clause is now reached, and the template is refused by name.
  2. tests/test_a_delivered_review_ends_its_turn.py: the record and the manifest are written WRITE_GAP (60 s) apart, the fixture hands the two dates to the test through a writes mapping, and the assertion names the later manifest write instead of recomputing a maximum from the fields under test.
  3. A new case drives the stream offset into the gap between the two dates (GRACE - WRITE_GAP / 2): the stream is past the grace counted from the record and inside it counted from the manifest, so a delivery dated from the earlier write changes the stop decision.
  4. A new case feeds an unsubstituted template status and asserts both that the run is left alive and that the template check was consulted from _complete_manifest_write_time. The call site is part of the assertion because the first version of this case recorded only the status, and it passed at the base revision: the tick's own classifier consults the same helper with the same status (classify_pointer), which the reproduction output shows.
