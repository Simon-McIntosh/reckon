Why the write path is unreachable once the subject lands

A figure review's whole deliverable is a record stored beside the run it read: runs/<reviewed run>/review-records/<reviewed run>.figure.json, plus its .at-<sha> sibling. The review's node id carries the reviewed run's name and a head suffix, and dispatch turns that id back into a run directory in order to grant the directory. The resolution goes: the node id's source (bank-drive-continuation) is looked up in the durable run store, the row's head is compared against the b818dab4d60f suffix, and the matched row's tree is what the grant is built from.

Promotion removes that row's tree. The live pointer is gone and the committed ledger row carries neither worktree nor repo, so the head lookup returns nothing, the matched run id falls back to the bare source bank-drive-continuation, and that names no run directory under the crew home. Nothing is granted, both declared record paths fall outside every writable root in the resolved read-only tier, and the launch is refused as a node contract failure. That refusal is the same on every pass, so the hold keyed to it never releases. The subject landed before the review launched; there is no future in which the directory reappears.

What the pass does now

A queued request is retired instead of held when four things hold together: its node role is review; its recorded failure is the node-contract refusal and names one of its own declared paths under a runs/<id>/review-records/ directory; the reviewed run has no live pointer; and the durable ledger records that run as promoted. A review of a run still in the fleet is admitted exactly as before, and a run that left the fleet without landing is left alone — it may still be resumed, and retiring its review would discard work that still has somewhere to go.

Neither half of that recognition is spelled out again here. The reviewed run's directory comes from the review module's declared-record rule, and each declared path is located by the same rule the dispatch fence grants a record through, so a change to what counts as a review's record path reaches the retirement as well as the fence. A copy of the directory shape in this pass would have been a second spelling that could drift from the one the grant is decided by.

The retirement discards the request through the same store every discard uses, writes the reason into the marker, records a retired-landed-review verdict row in the pass log, and raises one obligation naming the landed run with the dispose commands for any finding the review would have carried.
