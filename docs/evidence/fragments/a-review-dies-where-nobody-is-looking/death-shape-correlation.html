The review deaths that carry an exit record are all signalled

The measure

§1 of the plan asks the death record to distinguish a signal the worker did not choose from a clean exit, and the death rate had no read of it: the census classified attempts by stream shape, which says a death happened and nothing about what ended the process. docs/research/scripts/scan_local_lane_deaths.py now reads the supervisor's exit record — attempt-N-exit.json in the run directory, the same read its positive control already made — and emits, per cell, how many attempts carry one, how that splits across the cell's classifications, and what signal each names. A signal is read from the record's own field, or from an exit code at or above 128 by the shell's 128+N convention, and the block names which answered.

The block states its coverage beside the share it computes, because a death whose attempt carries no record is unread and a share quoted over all deaths would count those as clean exits.

The controls

The 100% is a reading and not a rule. A uniform column is a claim about the instrument until the instrument is shown able to produce the other answer, so the block builder was driven over synthetic rows — its own function, not a copy:

dead, record names SIGTERM           with_record=1 deaths_with_record=1 deaths_signalled=1 names={'SIGTERM': 1} src={'named_in_record': 1}
dead, record carries code 143        with_record=1 deaths_with_record=1 deaths_signalled=1 names={'SIGTERM': 1} src={'exit_code_128_plus': 1}
dead, record carries clean code 0    with_record=1 deaths_with_record=1 deaths_signalled=0 names={} src={}
dead, no record                      with_record=0 deaths_with_record=0 deaths_signalled=0 names={} src={}
completed, record carries code 0     with_record=1 deaths_with_record=0 deaths_signalled=0 names={} src={}

A recorded death with a clean exit code is counted in deaths_with_exit_record and left out of deaths_signalled, so the two are equal in the corpus because no such record exists there and not because the reader cannot express one.

The reader reports clean exits where they exist. Of the 959 recorded attempts, 827 completed and hold 818 records with exit code 0 and 8 with exit code 1, reported as clean exits by the same block that reports the signals. One recorded completion does carry a signal — the shape of a run killed after its result was written.

The classifier's own control is unchanged. r-20260928T044354744785-review-of-reflex-keys-on-reviewed-run-and-head is still read as dead on its first attempt (7394 records, no result record, last record user) and completed on its resumed attempt (11689 records, last record result/success), and its exit record still names SIGTERM.

What this does not establish

The record names the signal and not the sender: an external kill and the harness's own stop of a run are indistinguishable in this block. A deliberate stop is recorded on the run's live pointer, which is deleted on promotion and so is absent for the historical corpus. The breakdown is therefore a divided account of how these runs ended and not of why.

The coverage gap remains the larger fact: for 262 of the 392 review deaths no record was written, so the distinction §1 asks for is available for a third of that population and unavailable for the rest.
