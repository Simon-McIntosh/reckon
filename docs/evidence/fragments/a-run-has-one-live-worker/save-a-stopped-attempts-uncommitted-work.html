A stop keeps the attempt's uncommitted work

crew stop ended a run's whole process tree and recorded nothing about the tree. A repair round cut short mid-turn left its uncommitted edit in the worktree with no account of whose it was, and the next attempt committed it as its own work — measured in r-20261107T052438443051-line-arm-screen-rows, where attempt 2's change to scripts/iter/converter_filter_study.py was committed by attempt 3 as c9c427d97. The stop now reads the worktree before it signals anything, keeps what the attempt had not committed in the run directory, and says which of three things happened.

The read precedes the signal, because a worker that keeps working up to the signal, or that clears its own tree while dying, is only preserved by a read taken before it. terminate in reckon/crew/dispatch_sessions.py calls _preserve_stopped_worktree first and records the outcome under stopped_attempt_work on the run's own record, whose detail it also carries: saved with the path of stopped-attempt-<n>.diff, where <n> is the attempt that held the work and a number already taken by an earlier stop of the same attempt is skipped rather than overwritten; clean with no file written and the record saying the tree held no uncommitted changes; unreadable naming the worktree and the reason, with the stop still proceeding. A run whose record names no worktree reports that it had none. The file keeps git diff HEAD byte for byte, so it applies as a patch, and follows it with the names of untracked files as comment lines, because their content is not in the diff and a reader needs to know the tree held more than the patch carries.

The read the stop takes has its own budget. Sharing the module's reader also shared its hardcoded ten-second timeout, which is right for a lane handoff and wrong for a stop: on shared storage that stalls for longer than ten seconds — which this fleet's filesystem has done repeatedly — the stop would report the tree unreadable and keep nothing, in exactly the moment the uncommitted diff is worth waiting for. _worktree_git_read now takes a timeout defaulting to the handoff's ten seconds, so its three existing callers are unchanged, and _preserve_stopped_worktree passes _STOP_WORKTREE_GIT_TIMEOUT_SECONDS (60) for both reads.
