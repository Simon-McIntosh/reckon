A worker launched on another host refuses a relaunch until it is shown to have ended

A pid means nothing on a machine that did not issue it, so live_worker_reading answers LIVENESS_UNKNOWN at once for a record whose launcher_host names another host. _launch_refused_by in reckon/crew/dispatch_launch.py refused only a placed-unknown reading and fell through to return False for every other unknown. So a pointer left by a worker launched outside the fleet allocation — the shape §14 recovered from run r-20260914T064500219481 — read as "no worker" and a second launch was admitted beside a live one.

The shared predicate now takes the placed-unknown branch for an unknown reading on a record _record_is_known_foreign marks foreign, so _prepare_attempt_records, _supervisor_spawn_worker and the dispatch guard answer alike. Off-host only an exit receipt frees the launch: the canonical exit.json beside a canonical worker.json, or the newest retired attempt's attempt-N-exit.json, both read through the new _exit_receipt_shows_ended so the two shapes cannot be freed on different terms. _retired_attempt_ended applies the launching-host rule _worker_record_liveness already applies: a retired worker receipt for a foreign run is never probed against this host's process table, because a dead local number is not the remote worker's end. A record that never launched is let through, as before, and age never frees a launch. live_worker_reading still answers unknown off-host, because that answer is honest and other callers read it.

_live_worker_naming and _live_worker_refusal gained a foreign arm fed by the record rather than the reading, since a foreign reading carries neither a host nor a pid. A refusal now names the recording host and the pid that record holds, and says how to proceed: launch from that host, or stop the run there. Every refusal for a run launched on this host reads exactly as before, which the local live-worker case asserts.
