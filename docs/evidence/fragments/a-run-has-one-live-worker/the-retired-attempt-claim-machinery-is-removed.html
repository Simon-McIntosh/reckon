The retired attempt-claim machinery is removed

The resume door reserves the attempt it launches through reserve_launch_attempt, so the older attempt-claim files had no production writer left. Deleted from reckon/crew/resumption.py: claim_next_attempt, release_attempt_claim, _claim_may_be_reclaimed, attempt_claim_path and the helpers only they reached (_create_attempt_claim, _attempt_claim_age_seconds, _move_attempt_claim_aside, _ATTEMPT_CLAIM_SUFFIX, _ATTEMPT_CLAIM_ATTEMPTS). Deleted from reckon/crew/recovery_liveness.py: _newest_attempt_claim_number, _attempt_claim_seconds, _attempt_started_from_claim and the two readers only they used (_attempt_claim_path, _attempt_claim_numbers).

_current_attempt_number now reads only the attempt record a launch publishes, and _attempt_started_seconds candidates only the pointer's attempt_started_at and the attempt record's. No production behaviour changes, because every deleted reader already answered None for every production run: no production path wrote an attempt-N.claim after the reservation landed. scripts/census/monitor_census.py still globs the claim files by name, by design — it reads historical run directories, and it calls none of the deleted functions.

The named grep over reckon scripts skills returns nothing. Over tests it returns only the two ast.parse fixture sources in tests/test_staged_write_inventory.py (lines 168, 169, 198 and 199), which model a call shape and call nothing. The test files in this node's write scope, run one arm at a time, report 1 failed, 64 passed at the dispatch base (664f5ccc23) and 1 failed, 55 passed at the head: the same single failure (test_every_staged_write_reaches_the_owner, whose census expects a set of staged writers that other landed work has since extended by four entries, identical in both arms), and nine fewer passing ids at the head — exactly the nine deleted cases.

The 69 test files that import reckon.crew.resumption or reckon.crew.recovery_liveness were then run one arm at a time with -n 6. The base arm (664f5ccc23, in a scratch checkout under the run's temporary directory) reports 14 failed, 708 passed, 1 skipped, EXIT=1; the head arm reports 13 failed, 707 passed, 1 skipped, EXIT=1. Comparing failure ids, the head adds none: its thirteen are a subset of the base's fourteen, and the one base-only id is tests/test_crew_recover.py::test_the_follow_loop_sweeps_on_a_cadence_not_every_iteration, a cadence test that passed at the head. The raw totals differ by two fewer collected at the head although nine cases were deleted, so seven tests elsewhere in the population collected only in one arm; the id-level comparison above is what the measure rests on, and no failure id moves from pass to fail.

Deleted cases and the mechanism each pinned. In tests/test_a_resume_never_launches_beside_another_node.py: test_an_abandoned_claim_is_reclaimed_after_the_launch_window (a claim older than the launch window is reclaimed by age) and test_a_fresh_claim_is_not_reclaimed (a claim inside the window still refuses). In tests/test_a_resumed_attempt_is_read_through_its_own_records.py: test_arm_i_a_claim_after_a_status_repair_is_not_the_repaired_word, test_arm_ii_a_claiming_attempt_with_a_worker_is_not_the_repaired_word, test_arm_iii_a_launch_failed_attempt_with_a_next_claim_starts, test_arm_iv_an_exit_unfinished_attempt_with_a_next_claim_starts, test_arm_v_the_attempts_own_word_is_provisional_while_it_writes (all five resolve the current attempt from the claim, which is what made the resumed attempt visible), test_a_claim_alone_dates_the_attempt (the claim is the attempt's only clock) and test_every_claim_in_the_directory_dates_the_attempt (two claims with no attempt record between them both date the run). The two surviving cases date an attempt from its own exit record and from its own quiet word, so they stay.

The duplicated _create_attempt_claim fixture in tests/test_staged_write_inventory.py was reviewed rather than merged: the two census cases drive different analyser branches — one delegates the move to a helper, the other inlines os.rename — and their names already say which (..._delegated_move_aside_... and ..._inline_move_aside_...), so merging them would drop a branch from the census.

The declared negative control is none: this deletes code no production path reaches, and the measure is the empty production grep and the importer-population delta rather than a failure that a mutation would produce.
