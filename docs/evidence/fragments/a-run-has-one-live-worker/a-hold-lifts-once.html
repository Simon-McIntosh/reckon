A hold lifts once per condition

The wait sweep lifted the same hold twice. It decided by reading a single slot on the live pointer that a resume's own launch had already rewritten away, so the second sweep saw no record of the first. The sweep's append-only recovery log already named every lift; it is now what the sweep reads before lifting, and the pointer slot is only a cache of it.

The gap: the authority was a slot a rewrite could drop

sweep in reckon/crew/resumption.py lifted a hold unless the live pointer's auto_resume slot read back the hold's signature, and _stamp_resumption_trigger wrote that slot by rewriting the whole pointer. The resume's launch then rewrote the pointer from a snapshot taken before the stamp, so the slot read absent for a lift that had happened. On the reported run the sweep lifted, stamped, the launch dropped the stamp, and 70 s later the next sweep lifted the same unchanged hold again (recovery log lines 7668 and 7669).

The reproduction is the declared negative control below: with the log read removed so only the pointer slot is consulted, the pointer's rewrite between the two sweeps leaves the cache absent and the second sweep resumes the run again.

What changed

  • reckon/crew/resumption.py gains _lifted_holds, which reads the project's recovery log and returns the set of (run id, signature) pairs it already records under a sweep's resumed list. A dry-run line lists what a sweep would resume, so reports whose dry_run is set are skipped — a preview lifts nothing and must not retire a hold the sweep never took.
  • sweep reads that set once per pass and refuses a lift whose (run id, signature) is already in it, in addition to the existing pointer-slot check. The pointer's auto_resume slot is now a cache: when it agrees the run is skipped without consulting the log, and when a rewrite has dropped it the log still answers. No new record is added and nothing is retired — the log the sweep already appended to is the one it now reads.
  • The module docstring's first bound now states the log as the authority and the slot as its cache.

The gate

tests/test_a_hold_lifts_once.py builds a refused run whose pid was checked dead on this host, takes a snapshot of its pointer before the sweep's stamp, sweeps, then rewrites the pointer from that pre-stamp snapshot so the auto_resume slot is gone while the lift happened, and sweeps again. The second sweep resumes nothing. The recovery log is asserted to carry exactly the one lift.

  • test_a_pointer_rewrite_cannot_lift_the_same_hold_twice — first sweep resumes once; after the pointer rewrite the second sweep returns resumed: [] with reason already-resumed-for-this-hold, the launcher is still called once, and the log holds exactly the one lift.
  • test_a_dry_run_preview_does_not_retire_the_hold — a preview reports would_resume and launches nothing; the following real sweep still lifts the run once. Deleting the dry-run skip makes the preview retire the hold and this case fails.
