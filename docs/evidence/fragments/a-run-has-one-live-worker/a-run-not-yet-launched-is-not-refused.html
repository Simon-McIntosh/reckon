A placed run that never launched is not refused as if a worker held it

A direct dispatch on the fleet writes its srun placement onto the pointer before its first launch. The scheduler cannot be asked about that placement, so record_process_liveness answers placed with liveness unknown, and _launch_refused_by in reckon/crew/dispatch_launch.py refused every such reading. A run that had never launched was refused on its own first launch, and the refusal removed it.

The guard now takes the run record beside the reading. A placed reading of unknown liveness refuses only when the record holds a recorded worker that nothing has shown to be gone: a pointer pid, the run's own worker.json, or an attempt receipt (attempt-*-worker.json / attempt-*-exit.json). A record with none of them has never launched and proceeds. A record whose worker record names a pid this host probes dead also proceeds, because that record names the worker itself rather than the scheduler client the pointer's pid names. Every other placed-unknown reading still refuses, including a pointer pid with no worker record to answer for it. Both callers, _prepare_attempt_records and _supervisor_spawn_worker, pass their record; live_worker_reading and record_process_liveness are unchanged.

The reproduction ran first: a temporary crew home holding a placed pointer with no pid, no worker record and no attempt receipt was passed to _prepare_attempt_records with the previous predicate restored, and it refused with cannot read whether its worker is live (placed on job 1291586, liveness unknown); with the guard in place the same record writes its attempt record. The gate is tests/test_a_run_not_yet_launched_is_not_refused.py: at the head revision it reports 5 passed, EXIT=0; at the base revision with the test copied in it reports 3 failed, 2 passed, EXIT=1, failing the never-launched case, the dead-worker-record case and the supervisor-seam case, which is the defect reproduced. The negative control restores the refusing predicate and reports 3 failed, 2 passed, EXIT=1 on the same three ids.

The four §11 cases run through _prepare_attempt_records with the scheduler query stubbed to answer nothing: a never-launched placed pointer proceeds and writes attempt.json; a placed pointer whose worker record names a dead pid proceeds; a placed pointer whose worker record names a live pid is refused naming that pid; a placed pointer with a recorded pid and no worker record is refused with the placed-unknown text. The never-launched case also passes through _supervisor_spawn_worker, which spawns the stand-in and records its pid. Every case asserts the operator's own crew home listing is unchanged.

A repair round answered two review findings. The guard now reads the run directory through recovery_wait._run_directory and "shown gone" through recovery_liveness._worker_record_liveness instead of keeping private copies of either read, so one module owns each and the launching-host rule comes with the owner. The placed refusal case in tests/test_a_queued_run_launches_once.py had asserted the superseded predicate through a dead worker record; it now keeps its purpose — a placed refusal of unknown liveness that names the job and never the client's pid — on a record this rule still refuses, a placed pointer with the live client's pid and no worker record.
