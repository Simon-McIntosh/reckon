A refused resume names the attempt that is live

A run delivers, a review raises a blocking finding, and the review reflex resumes it as a second attempt. A coordinator who then types crew resume meets the bare sentence run '<id>' still has a live process; observe or stop it before resuming. It names no attempt, so it reads as a stale process, and the coordinator stops the worker that was about to deliver. The defect is reproduced against the dispatch base 5bc89fc029 in a temporary crew home holding a live attempt-2 worker record whose advice opens with the repair-round token:

REFUSAL: run 'r-repro-live-attempt' still has a live process; observe or stop it before resuming

The same script against the delivered head gives the same opening and then names the process it found:

REFUSAL: run 'r-repro-live-attempt' still has a live process; observe or stop it before resuming. That process is attempt 2 (pid 1375, launched 2026-11-07T06:25:56Z), a resume; the review reflex opened it as a repair round, which delivers by itself: advice sent after it does will reach it; its newest stream record is 0s old.

What changed

  • reckon/crew/resumption.py gains live_process_refusal(record, *, reading), the one composer. It reads the run's own records: the immutable attempt-<n>-worker.json receipts (with the canonical worker.json as a fallback), attempt.json for the attempt's kind, the pointer's repair_rounds for a round the reflex opened, and the stream files for the age of the newest record. A detail the records do not hold is left out, never guessed.
  • All three doors call it: _launcher_refusal and _stream_reading_refusal in resumption.py, and resume_plan in reckon/crew/dispatch_sessions.py. At the two pid-alive sites the old sentence stays as the opening, so the tests that match it keep passing. The in-motion site opens with liveness unknown — no pid could be read here and no exit was recorded — and never says live process.
  • A process found only by the session walk is attributed to no attempt, so it keeps the bare sentence: nothing in the records ties that pid to a receipt, and naming the nearest one would be a guess.
  • tests/test_a_refused_resume_names_the_live_attempt.py is new: five cases through resume_plan, the sweep's mirror and the stream-reading gate.

The gate

  • test_a_repair_round_attempt_is_named — a live attempt 2 that a review round opened is named with its pid, launch time and kind, and the message says the round delivers by itself. Both launch doors give it.
  • test_a_coordinator_resume_is_named_without_the_repair_wording — the same shape with no opened round is named, and is not called a repair round.
  • test_a_live_process_found_by_its_session_invents_no_attempt — a live process no receipt records keeps the bare sentence with no attempt and no pid.
  • test_both_launch_doors_give_the_same_message — parity: the launcher and the sweep's prediction are byte-identical.
  • test_an_unknown_liveness_stream_names_the_moving_attempt — a run launched elsewhere, with no pid here and no exit record, is refused naming attempt 2 and the age of its newest record, saying its liveness could not be read on this host.

Delta on the neighbouring modules

The three tests the section names as the doors' own — test_resume_refuses_a_live_worker.py, test_resume_sweep_needs_an_observed_death.py and test_a_resume_never_launches_beside_another_node.py — were run in both arms: 18 passed at base 5bc89fc029 (EXIT=0), and 1 failed with 17 passed at the head before the assertion was repaired (EXIT=1). That failure was test_a_stream_in_motion_refuses_the_resume, which asserted "still has a live process" for the in-motion door, while the door says liveness unknown and never live process, which is what the section requires of it because no process was read alive there. The assertion now requires liveness unknown and forbids the live-process claim, and with that one-line change both files pass: 12 passed at 248e2dcdea (EXIT=0) against 1 failed and 9 passed at the repair's base 2c1996aa (EXIT=1). A wider run over the 61 test files importing the two changed modules was started and stopped at 38% by the harness background limit, so it is not cited here.

The repair also removed a duplicate the review named. The opened repair round is no longer looked up on the record the refusal was handed; it is read through _opened_repair_rounds in reckon/crew/recovery_repair_dispatch.py, the owner that reads the live pointer afresh, so a round opened after a sweep read its pointer is still named. And an attempt is dated only by a stream that belongs to it: the run's newest stream is no longer a fallback, so a second attempt is never given the first attempt's age. Two cases guard the pair, and reverting the repair reddens both (EXIT=1).
