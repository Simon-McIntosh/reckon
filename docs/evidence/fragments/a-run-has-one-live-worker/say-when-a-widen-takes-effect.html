A widen says when the paths it added take effect

A running worker's mounts are fixed when its sandbox starts, so a widened write claim reaches that worker only on its next attempt. The widen result listed the added paths and said nothing about this, and a coordinator read its ok as a fence that had already moved. The result now carries a takes_effect sentence, composed in widen_takes_effect (reckon/crew/claims.py) from one liveness reading.

process_liveness.record_process_liveness returns a LivenessReading carrying the arm that answered: recorded pid, session walk, placed run, proven dead, or unknown. record_process_alive keeps its bool | None shape by returning that reading's alive, so the arm and the boolean are one decision rather than two. The sentence names a pid only in the recorded-pid arm, names the session and no pid when the session walk found the worker, names the scheduler job for a placed run and never presents the scheduler client's pid as the worker's, says the next resume or launch mounts the paths on a proven death, and says only that the worker's liveness could not be read on this host when the reading is unknown. Every arm ends by naming the field the launch fence is built from, node.write_paths.

The defect was reproduced first at the dispatch base in a temporary crew home: a self-widen beside a live stand-in worker and a coordinator's widen of a stopped run each returned ok with the added paths listed and no word on when they apply (negative-control-reproduction.log).

The gate is tests/test_a_widen_says_when_it_takes_effect.py. At the head revision it reports 11 passed, EXIT=0. At the dispatch base with the test copied in it reports 10 failed, 1 passed, EXIT=1; the case that passes is the fence-field guard, which asserts behaviour the claim writer already had. With the declared mutation applied — the liveness read dropped, the session-walk arm's recorded pid named as the worker's, and the boolean decided apart from the reading — it reports 4 failed, 7 passed, EXIT=1, failing the live-worker case, the session-walk case, the unknown case, and the unknown arm of the boolean case.
