A worker spawn refuses a run that already has a live worker

The supervisor's spawn seam, _supervisor_spawn_worker in reckon/crew/dispatch_launch.py, now reads the run's own records through record_process_alive before it starts a worker and before it writes this attempt's worker record. The read answers for the pid an earlier attempt recorded, and when every recorded pid is dead it walks for a live process of this user whose command line carries the run's session id — the reach a worker reparented away from its supervisor still answers on. A live worker refuses the launch and the refusal names its pid (still has a live worker (pid N)); a run with nothing live spawns as before.

The gate is tests/test_a_queued_run_launches_once.py. At the head revision it reports 5 passed, EXIT=0. At the base revision with the test copied in it reports 2 failed, 1 passed, 2 skipped, EXIT=1, both failures reading DID NOT RAISE CrewError: the second launch proceeded beside the live worker, which is the defect reproduced. The negative control (the liveness refusal removed) reports 2 failed, 3 passed, EXIT=1, failing the same two case ids the head arm passes.
