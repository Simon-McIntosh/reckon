Refuse resume beside a live worker identified by session id

A supervisor that exits ahead of its worker leaves the worker reparented to init and unrecorded, so every pid a run's pointer names answers dead while the worker goes on driving the run's session. The liveness owner that both resume doors call now takes one more reading. When the pid probe is not True and the record is a spawned (launch: cli) run naming a session_id, it walks /proc for a live process owned by this user whose command line carries that session id as one whole argument, excluding the caller and its ancestors. A hit reads alive, so resume_plan and the sweep's mirror _launcher_refusal both fire their existing live-process refusal, with the same message on both doors. The match is on whole arguments, so a session id embedded in another argument is not a worker; the walk's reach is this host and this user, the same reach the pid probe beside it has. A run whose pid the probe proves alive never reaches the walk.

Five cases pass at the head. A run whose recorded pid is dead and which records a session id is refused by resume_plan and by _launcher_refusal with one identical message while a real child process carries that session as an argument element; both admit once that child exits; a live process carrying a different session refuses neither; and a child carrying the id inside --resume=<id> refuses neither. Each case runs against a temporary crew home and asserts the real crew home carries none of its run paths afterwards.

The declared mutation — the whole-argv session search removed — leaves the two refusal cases building a launch plan instead, and they fail (EXIT=1, 2 failed ids the head arm does not fail). Before the repair the same two cases failed against the unmodified tree, and the three admit-cases passed, so the reproduction names the defect rather than the fixture.
