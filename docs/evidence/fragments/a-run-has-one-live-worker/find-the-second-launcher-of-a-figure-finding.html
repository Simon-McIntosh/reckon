Which of the three explanations holds

It is the second: the guard ran, and read attempt 1's liveness as not-live. The reading is not dead, it is unknown, and unknown is exactly what the refusal predicate lets through.

  1. _refuse_a_live_worker_before_the_worktree reads the pointer and calls live_worker_reading(record) (reckon/crew/dispatch.py:515).
  2. live_worker_reading answers LivenessReading(LIVENESS_UNKNOWN, None) immediately when _launched_on_this_host(record) is false (reckon/crew/recovery_liveness.py:1362). That gate is record["launcher_host"] == socket.gethostname() (reckon/crew/recovery_liveness.py:1219–1227), and the pointer's launcher_host is stamped from the creating host's gethostname() (reckon/crew/runs.py:396–433).
  3. _launch_refused_by refuses an alive reading (reckon/crew/dispatch_launch.py:2147) or a placed reading with unknown liveness (reckon/crew/dispatch_launch.py:2149); anything else falls to return False (reckon/crew/dispatch_launch.py:2158). An UNKNOWN arm therefore never refuses.

This is consistent with, and caused by, the same fact the argv[0] clue establishes: attempt 1 was created inside the allocation and attempt 2's launcher ran outside it, so the two ran on different machines (release.json scratch_host is 98dci4-clu-2023.iter.org for this run's own fleet node). A pid is meaningful only on the host that issued it, so the launcher could not have proved attempt 1 alive even had it tried; the guard's host gate turned that inability into a pass.

Explanation 1 (a door reaching _create_worktree without the check) is excluded: _create_worktree has exactly one call site, and the guard's call at dispatch.py:2545 precedes it at :2867 unconditionally in the same function; every door in the table above enters through dispatch.

How a crew process's code stamp maps to a commit

The stamp is a git tree, not a commit. _committed_reload_tree (reckon/checkout_trust.py:343) composes it from git ls-tree HEAD reckon skills plus the blob at docs/state/reckon/model-catalogue.yaml, folding the catalogue's path with git mktree. So git cat-file -p 01863fb71f lists three entries (docs, reckon, skills) and matches no single commit — it matches every commit whose three entries compose to that tree. A commit that touches anything outside the three leaves the stamp unchanged.
