Every launch door reserves exactly the attempt it launches

The reservation key now reads three on-disk facts — the newest attempt receipt plus one, else the attempt the in-flight marker names, else the attempt the run's live pointer records — so no door's own inputs enter it. A paired shadow arm's first launch keeps the attempt it was dispatched with instead of being reset to one, and a compatibility launch keys on the pointer rather than restarting at attempt one. Every launch that spawns a supervisor reserves, and a reservation is freed by the reserved attempt's own exit receipt under the strict run-id reading, so a hold left naming a long-lived admitting process no longer outlives its run.

  • Key: launch_reservation_key reads receipts, else the attempt.json marker, else the pointer, taking the greatest present reading; the in-flight marker is never a receipt, so two doors racing on a first attempt still compute one number.
  • Doors: the dispatch door writes its marker before it keys and rewrites it with the reserved attempt whenever the reservation reassigns it; a solo shadow launch creates its run directory first so the marker lands; supervised_launch reserves unconditionally and the record-derived attempt floor is gone.
  • Freeing: held_launch_reservation skips any reservation whose attempt has an attempt-N-exit.json naming the run, for every caller; a failed supervisor rewrite is returned rather than suppressed and reported in the launch result as reservation_supervisor_recorded: false.
