The dry-run discriminator sits beside the option

The --dry-run help on reckon crew dispatch carried the promise (“Validate and resolve only: no worktree, no process, no record”) and nothing that would stop the next check being added to the surface from repeating the defect. It now carries the discriminator in one sentence beside that promise: ask of any check added here: what would make this field wrong while it still printed the same value? The sentence says what a green preview is — a true statement standing in for the one the caller is asking — so the affirmative answer is named as the hazard rather than left to a plan the reader would have to know to find.

tests/test_dry_run_discriminator_documented.py reads the rendered reckon crew dispatch --help through click’s runner and extracts the --dry-run option’s own wrapped block, so a question parked elsewhere in the same help does not satisfy it. It requires the question, the green-preview clause it disarms, and the original skip promise, so the documentation is added to rather than replaced.
