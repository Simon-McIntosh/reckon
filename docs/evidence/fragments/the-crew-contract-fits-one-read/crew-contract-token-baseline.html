The 26 September pre-dispatch skill-load baseline

Baseline: a coordinator spends a median of 20,484 input tokens loading the reckon-build skill and its references before its first reckon crew dispatch call. The figure is the median of the per-session totals of five sessions, each total being the sum of every skill load that session recorded before it dispatched. Recorded from the transcripts under ~/.claude/projects read read-only, from the frozen usage figures those transcripts carry. The section 3 rewrite is judged against this number; the "at most half" target it implies is therefore about 10,000 tokens.

What is counted, and what is not

A load is the skill reaching a coordinator from its installed location: a Skill invocation of reckon-build, an injected SKILL.md body, or a whole-file Read of a path under ~/.claude/skills/reckon-build.

Two things that look like loads are excluded, and both had to be excluded to get a number that means anything:

  • A repository's own copy of the skill. Sessions on 25 September that read <worktree>/skills/reckon-build/SKILL.md are authoring the skill, not loading it. Counting them put partial 219- and 1,726-token file reads into a distribution of 20,000-token skill loads.
  • A partial read. A Read carrying an offset or a limit reads a fragment of a file; it does not load the skill. Forty-line reads of a 75 KB skill are code reads.

Token accounting

Each assistant request records a usage block whose total input is input_tokens + cache_creation_input_tokens + cache_read_input_tokens. A load's cost is the rise in that total across the load, and the lower bracket is the load's own request, not the request before it. That is what keeps a tool result which landed earlier in the same turn out of the figure: where a turn issues the load alongside another tool call, the other tool's result is already inside the load's own request total. A turn issuing more than one tool is still reported in the log as an upper bound. Nothing is estimated from characters.

A load is reported unmeasured rather than as a zero when no request precedes it (the skill was injected at session start), when no request follows it, or when the context shrank across it — a compaction landed between the two requests and bundled the re-injection with its summary.

Selection

Sessions are selected when they record a skill load on the baseline date, widening symmetrically to neighbouring days until at least five have a complete per-session total. The baseline date, 2026-09-26, is a Saturday: it holds four qualifying sessions and only two complete ones. Dates used: 2026-09-26 and 2026-09-25. The five complete totals are the headline; five further selected sessions had at least one load the instrument could not isolate and are listed in the log with the reason.

Separate figures

The clean full SKILL.md load is 25,904 tokens, at 2.32 tokens per word against the current 11,181-word file. That is a first delivery of the whole body into a context that did not already hold it, measured in 1d1d2f0d. The other whole-body loads land at 25,650, 20,484 and 17,427, and one at 1,935 — that last is a re-invocation in a session that had already loaded the body, so it is cheap and is not a comparable full-load figure.

Per-reference loads: worker-verification.md 5,889 tokens; orchestrator-harness/claude-code.md 5,410 tokens. A single reference read therefore costs a coordinator roughly a quarter of a full skill load — which is why the headline is a per-session sum rather than the cost of one load.

Word counts

Measured by the done-when's own rule (whitespace-split words): SKILL.md 11,181 words; the ten reference files together 23,726 words; the two together 34,907 words, against the 12,000-word ceiling the rewrite must meet — a deficit of 22,907 words.

These word counts date from the measurement time, not from the baseline date. The load figures come from frozen transcripts and cannot move; the files do. SKILL.md was last written 2026-09-29 05:09 UTC, minutes before this measurement, so the word counts describe the file as it stands now and should be re-read rather than quoted forward. The 11,050-word figure this fragment previously carried was taken at revision a34a62bb and no longer describes the file.

Controls

The log prints two checks, both passing:

  • A session known to invoke the skill (1d1d2f0d) is detected, and 1225959a — a session that merely quotes a transcript containing the skill body inside a tool result — is rejected.
  • A bracketing control reproduces the attribution defect that this measurement corrects: 6f6c5410's reference read follows an 821-token Bash control result in the same turn. Bracketed on the load's own request the load costs 5,410 tokens; a looser bracket on the preceding request would have charged 6,231 and silently added the Bash result to the skill-load figure. The control asserts the loose bracket is not in use.
