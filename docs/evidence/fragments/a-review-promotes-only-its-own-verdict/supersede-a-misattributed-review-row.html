§ — a misattributed review row is corrected by an appended correction every reader honours

A committed ledger row records what a promotion believed when it landed, so a row whose review fields describe another round is not rewritten in place: the record of the belief is itself evidence. reckon crew supersede-review --project <p> --run <id> --reason <text> appends exactly one review_correction beside the recorded fields — the time, the reason, the head the row was dispatched to read and the head it recorded, and the field it supersedes — and lands it as one commit through _commit_landing_writes, keeping the aggregate row and its per-run file byte-identical. The dispatched head is read as the census reads it: a declared .at-<head> write path through _review_record_subject first, then the twelve-hexadecimal head suffix the node id mints, recovered through round_node_head_suffix, a new inverse of round_node_id added beside round_node_source.

Three row shapes are refused with nothing written: a row whose recorded head is the same revision as its dispatched head (same_revision matches an abbreviated head against a full one, so the twelve-character-prefix case is refused as correctly attributed), a row naming no dispatched head from either source, and a row already carrying a correction.

Every reader of a row's review reads through one accessor, reckon.ledger.review_block, which returns nothing for a corrected row. The known readers moved onto it are ledger.review_scores, capabilities._arm_figures, crew/picker/snapshot._candidates_scan and crew/picker/outcomes.summarize; a sweep for other readers of a committed ledger row's review key found none outside these (the remaining review reads in the tree are of a review record or a review payload, not of a ledger row). A corrected run therefore drops out of review totals and per-dimension medians and is not counted as reviewed.

Both logs run with /usr/bin ahead of the worker's git shim on PATH, and their headers say so. The shim hangs on the throwaway repositories these tests create: with it first on the path test_ledger.py blocked in a git rev-parse --git-path subprocess and never finished — 16 of its 97 cases in 560 s — and the same single test passed in 11 s once the real git resolved ahead of it.
