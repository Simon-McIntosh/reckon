Queued work shows where held work shows

A request waiting for a lane slot is no longer reported inconsistently. The follower's waiting counter already counted it, while the obligations view listed nothing for it and the live rows carried no place in the lane's queue, so a request waiting its turn read as missing on two of the three. The order the admission pass admits by is now exposed once, by queue_admission.queued_placements(), and every surface that reports a queued request's place reads it from there. A live row carries position, its place among the lane's queued requests, which is the figure a queued dispatch already reports, and rank, its place among its own session's queued requests. Both come from the one ordering, so no surface derives an order of its own and two surfaces cannot disagree about which request goes first.

The obligations view lists a queued request as waiting for as long as its pointer exists, under run-queued, carrying the place it holds and naming that place in the row's next command. The kind is listed among the non-blocking kinds, because the lane's own admission pass ends the wait and the coordinator has nothing to shorten. It is deliberately not review-queued, whose reading stays bounded by the 30-minute bound that kind already carried, and not queued-awaiting-session, which names a condition only the session can clear.

The gate is the declared mutation. With one queued pointer the follower's waiting count reads 1, the obligations view lists one run-queued row at position 1 rank 1, and the live view returns one queued row at position 1 rank 1. Removing that same pointer empties every one of those readings. Run against the base revision's own modules, the first case fails at the obligations reading — the follower still counts the run and the obligations payload lists nothing — ending EXIT=1. Head gate: pytest tests/test_queued_work_shows_where_held_work_shows.py tests/test_a_session_side_refusal_reaches_the_session.py, 6 passed and 1 expected-to-fail, EXIT=0.

The run list is the one surface this node could not carry. It composes its rows in reckon/crew_run_commands.py, which a concurrent run holds, so its place is asserted in a case marked expected-to-fail that names that claim and the two keys its row dict needs.

Two expectations elsewhere in the suite asserted the old reading by name: that a lane-held queued request is absent from the obligations payload. The plan replaces that reading with a listed waiting row, so both now expect the row they read — the lane-held request listed under the waiting kind beside the session-side refusal, in the case that holds one of each for the same session. What each case checks is otherwise unchanged.
