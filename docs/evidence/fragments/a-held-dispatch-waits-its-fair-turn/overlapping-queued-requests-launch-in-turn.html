§18 — Overlapping queued requests launch in turn

Two queued requests naming one write path refused each other's launch on every admission pass. claim_disposition read a pointer with no worker process as "not yet spawned" and kept the claim held, so an earlier queued request blocked a later one exactly as a running worker would. A queued request holds no worker and no worktree, so claim_disposition now returns a non-binding disposition for a pointer in the queued phase, keyed on the phase rather than on the missing pid. A starting run — pid-less between its pointer write and its worker spawn — keeps binding, because the rule reads the phase and not the absence of a pid. Its two readers stay in step for free: the dispatch scope check (_repository_scope_claims) and the crew scopes view (_live_scope_claims) both call claim_disposition, so a queued claim refuses nothing and the registry reports the same verdict the enforcer applies.

On top of that the admission pass keeps rank order among overlapping requests. Before admit_once releases a request it looks, through _earlier_overlapping_request, for an earlier-ranked queued request whose write paths overlap. If one exists it leaves the request queued with no failure recorded, exactly as a lane-gate hold does, and the pass does the check itself rather than inferring the overlap from a queued record returned by dispatch. The head of the queue has no earlier-ranked request and is never held this way. The hold is bounded by the queue's existing STARVATION_AGE_SECONDS, so a request is never held without end behind an earlier one whose own session is never granted a slot: once it has waited past the age the pre-check releases it and it may launch ahead under the ordinary claim rules. When both requests sit in one slot-less session, the existing session-allowance hold takes both before the pre-check runs. Once a request launches, its claim binds as any running worker's does; a later overlapping request whose launch is refused on it goes back to the queue with the conflict recorded, keeping its run id and place.

Measure: the focused gate python -m pytest -q tests/test_overlapping_queued_requests_launch_in_turn.py tests/test_a_node_is_queued_once.py reports 18 passed with EXIT=0 at the head revision, covering the seven section cases (earlier launches and the later stays queued; the later waits behind an earlier whose session has no slot; the later launches once the earlier is promoted and its back-off has expired; the starvation age releases the later; a new dispatch over only a queued claim queues then launches, and is refused queue-full at the session cap; a working or starting claim still refuses with scope-conflict; the crew scopes view reports a queued claim non-binding and a starting one binding). The superseded case test_a_different_node_over_a_queued_path_launches in tests/test_a_node_is_queued_once.py now expects the dispatch to launch with the queued request left live, and a companion case keeps the working-run refusal.

Three negative controls, each logged under the run directory with its own EXIT=1 line and the failure id it names. Counting queued pointers as claims again in claim_disposition fails both the earlier-launches case and the crew scopes case (2 failed). Removing the admission pre-check fails the later-waits case (1 failed). Removing the starvation bound so the pre-check holds regardless of age fails the release case (1 failed).
