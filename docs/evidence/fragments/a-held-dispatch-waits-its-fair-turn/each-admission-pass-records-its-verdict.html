landing: admit_until_stopped in reckon/crew/queue_admission.py now appends one JSON line per admission pass whose lane had a queued pointer to <crew home>/admission-verdicts.jsonl, beside pick-timings.jsonl. The line carries the pass time, the lane, the code stamp the service runs, and per queued pointer the run id, the session, the allowance read with the published source it came from and the verdict — launched, held-for-allowance, held-by-gate, held-on-retry-backoff (with the pointer's own retry_at), held-behind-earlier-request or refused with the refusal's failure text. A pass whose fleet gate is waiting returns as soon as it has read the gate, so it now reads its lane's queued pointers only to name them and records each as held-by-gate with the gate's state — nothing is released, launched or rewritten on that path. A pass that examined no queued pointer writes nothing. The log is bounded past ADMISSION_VERDICT_LOG_MAX_BYTES (1 MiB) by fleet_supervisor.trim_service_log, the same trim the service logs use: it edits the file in place and keeps the inode, so the appender's own descriptor stays valid and a line written while the trim runs is not lost. That bound is what stops a service running for days from growing the log without limit. The per-pass verdicts are built where admit_once decides each request, and _session_allowance became _session_allowance_read, returning the allowance with the figure's source so _dispatch_lane_allowance's own label reaches the record.
