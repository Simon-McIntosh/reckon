§10 — A review is not refused for the run it reviews

A review carries the unreconciled-runs waiver because the run it reviews is an unreconciled run: past the grace the fence refuses the very dispatch that reconciles it. The waiver reached dispatch as unreconciled_override, but a request the lane holds is recorded with only its dispatch_options, and the admission pass rebuilds the waiver from there. Two composed-review callers — the reflex (reckon/crew/recovery_review_dispatch.py) and the composed plan-review dispatches (reckon/crew/plan_review.py) — passed the override without the option, so a queued review relaunched with no waiver and failed UnreconciledRuns on every admission pass.

The fix records allow_unreconciled_runs in the dispatch options each caller passes, so the queued request carries the waiver into its relaunch. A stranded review whose launch never spawned a worker now also keeps its strand reason: the discard marker is read from the run directory or the shared discards spool, whichever the discard wrote.

Measure: the focused gate python -m pytest -q tests/test_a_review_is_not_refused_for_its_run.py reports 4 passed at the head revision; the wider focused set of reflex, stranded-review, plan-review and queue-admission test files reports 71 passed. The negative control (the reflex's dispatch_options waiver dropped) turns the queued review's admission into the fence refusal (project has 1 unreconciled run(s) older than the 1s grace), failing the head-green test.
