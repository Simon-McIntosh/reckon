§17 — A repair has one path: it resumes the reviewed run, or it is refused

The section was written on the premise that a repair the local lane holds is recorded as a queued request and relaunched by the admission pass, so the request must carry every launch input that pass rebuilds — its unreconciled waiver and its reviewed-head base — in dispatch_options. Reading the reflex showed the premise did not hold. dispatch_repair_for_run reached its composed dispatch() call only when _repair_launch_refusal was truthy at the resume/dispatch split, and the same predicate re-evaluated immediately before the launch then returned refused: an unpromoted reviewed run always took the in-place resume, and any other was refused before composing a node. The composed dispatch() call was unreachable, so no repair was ever launched or queued and there was no queued request for a waiver to ride.

The re-planned section removes the dead block and gives a repair one path. _repair_launch_refusal now reports a gone pointer as a refusal on the real path: runs.read_pointer raises CrewError for a missing, invalid or non-object pointer, and a single helper turns that raise into None for the reads that only degrade on absence, so the gone-pointer case is a returned refusal rather than an exception escaping the reflex. The composed-dispatch block, its TaskNode and importlib/dispatch_module launch, are removed; the imports and helpers only that block used are removed; the second refusal read's refused return is kept, and its record is written only while the run still has a live pointer, because the write re-reads the pointer under its lock.

Measure: the focused gate python -m pytest -q tests/test_a_repair_has_one_path.py tests/test_reflex_dispatches_one_repair.py reports 21 passed at the head revision. The population of test files that import reckon/crew/recovery_repair_dispatch.py, built from the head's tests/ with grep, reports 123 passed; the same set (minus the new file, which exists only at head) reports 121 passed at the base — no added failures. The negative control restores the unguarded read (fresh = read_pointer(run_id)) at the single refusal-read site, and both the new file's and the reflex file's gone-pointer cases then fail with CrewError: no live run '…', so the real-path refusal is what the pass rests on.
