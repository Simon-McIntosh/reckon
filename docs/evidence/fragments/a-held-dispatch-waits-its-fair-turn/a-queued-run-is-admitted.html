A queued run is admitted

Added reckon crew admit (reckon/crew/queue_admission.py): one admission pass reads the fleet gate and the queued pointers, ranks them by queue_order.admission_order, and launches each in turn through the shared dispatch path while the lane grants its session room. A held or paused gate launches nothing; a launch the shared path refuses leaves the request queued with the failure and its time recorded; a run the reaper marks launch-failed is re-queued by the next pass. Declared as a fleet service the verb repeats on a cadence, and --once drives a single pass.

Measure: tests/test_a_queued_run_is_admitted.py 7 passed (one slot launches the highest-ranked queued run only; two racing passes launch each run once; a paused gate launches nothing; a failed spawn leaves the pointer queued carrying the failure; a launch-failed run is re-queued; a temporary services configuration declaring the verb is accepted by the supervisor's reader; a launched run's phase sequence is observed as queued, then starting, then working as the follower folds the worker's own stream back). Negative controls: launching without restoring the queued pointer fails the failed-spawn case (negative-control-admit.log EXIT=1); stopping the launched run at starting without the follower fold fails the phase-sequence case (negative-control-phase.log EXIT=1).
