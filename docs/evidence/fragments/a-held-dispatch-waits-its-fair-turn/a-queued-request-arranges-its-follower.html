A queued request arranges its session's follower

A held dispatch previously stored its queued pointer and returned before ensuring the producer or asking the calling session host for a follower. The new FIFO-backed regression reproduced both effects: the host received no request, and the first admission pass launched no run.

The held and launching paths now use one helper to ensure the producer and ask the calling session host. A queued request leaves its session attached before dispatch returns, so the first admission pass can launch it. The held path can also start a producer just before a test cleans up its watcher. That test now waits for the raw producer registration before calling unwatch, with a bounded failure if it never appears.

Measure: the focused gate reports 2 passed at the repaired head, and removing the queue branch's helper call makes both cases fail (2 failed, EXIT=1). The delayed-registration case and its three neighbouring tests passed in three consecutive eight-worker runs (4 passed each); before the teardown change, that case and the queued-review case both failed with an empty locked registration. Across 80 direct importer files, the complete base arm reports 6 failed, 569 passed, 1 skipped. The final repaired-head arm, including the new regressions, reports 4 failed, 574 passed, 1 skipped, with zero added failure ids. An earlier repaired-head arm had two different head-only timing failures outside the changed paths; both arms and their failure ids remain in the run record. Ruff adds no findings, and all three changed Python files pass format checking.
