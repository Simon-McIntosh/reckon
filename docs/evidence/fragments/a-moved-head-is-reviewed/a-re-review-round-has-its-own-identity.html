A review round composes a node id and worktree path carrying the head it reviews

The run-review node id is composed by the shared round_node_id rule that repair_node_id already applied to repair rounds — <prefix><source>-<head[:12]> — so a re-review of a resumed run cannot reuse the first round's id and collide with its worktree, and both head-stripping readers (_task_identity, _resolved_reviewed_run_id) resolve every round's id back to the run it reviewed. tests/test_a_resumed_head_is_reviewed.py passes its four watch-path cases; the 41 test files importing recovery_review_dispatch or recovery_watch show no added failure against base.
