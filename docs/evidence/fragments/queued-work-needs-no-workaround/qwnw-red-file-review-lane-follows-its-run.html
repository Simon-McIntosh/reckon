A review follows the lane its run recorded: the four red cases and their one cause

Verdict: the product was wrong, in one place. classify_pointer gave a pre-spawn phase label priority over the run's own manifest, so every delivered run whose pointer still read starting was classified running. The review reflex refuses a run that is not scoring, so all four failing cases stopped at the refusal — the run is not awaiting review (running) — before reaching the lane selection, the exclusion refusal or the sweep's session ownership they measure. The classification module's own derived phase already stated the rule the product broke: a delivered manifest is evidence the launch got past starting, and a delivered report never falls back to the launcher's label.

No assertion was deleted or weakened. The fix is one predicate in reckon/crew/recovery_classification.py: pre_spawn_waiting no longer holds when the manifest carries a terminal status. A pointer with no manifest, and a strand past its bound, read exactly as they did; a launch that has spawned nothing is still the running row it was.
