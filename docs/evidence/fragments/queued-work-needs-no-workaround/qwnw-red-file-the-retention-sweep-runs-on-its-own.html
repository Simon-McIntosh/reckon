The retention sweep is pinned to the reader it calls

The case that pins the pass to the shared ledger reader spied one layer beneath it, on ledger._indexed_data. That layer is no longer reached: once the run store holds a row, the reader answers a project's history from the store, and this fixture writes the store through ledger.append_run. The spy now sits on ledger.runs, the reader the pass calls once per mounted project, and the assertion that both projects are read is kept in meaning. A pass that parsed an aggregate, or carried its own notion of where a run's project is recorded, calls that reader for neither project and still fails.
