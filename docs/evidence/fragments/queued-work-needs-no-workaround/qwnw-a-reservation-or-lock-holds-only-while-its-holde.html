§9 — a reservation holds only while its holder is working on it

reckon/crew/host_heartbeat.py publishes one beat per host under the shared crew home, and dispatch_launch.reservation_in_flight now reads a reservation through the test that can speak about the holder. A reservation taken on this host is judged as before, by probing its pid and matching the recorded start time, so a dead pid is released on read. A reservation naming another host carries a pid this host cannot read at all — the number may belong to an unrelated local process — so it is judged by that host's beat: a beat inside the 90-second window keeps the reservation, and a lapsed or absent one releases it. Reserving an attempt records launcher_host and refreshes that host's beat.

A door that holds a reservation it does not use now lets go of it. The repair advice hold calls withdraw_unlaunched_repair_reservations, which drops the reservations this process took for the round, writes their attempt exit receipts, and returns them before returning the hold — so an advice hold leaves no reservation on disk.

A coordinator's resume supersedes a round rather than being refused by it. crew resume passes coordinator=True, and supersede_a_held_repair_round releases the held round's unlaunched reservation and records status: superseded — only when the pointer already records an advice-hold, so any other reservation is still a launch under way and still refuses.

A resume mark now holds only while its attempt has answered nothing. resumption.launch_mark_holds spends the mark when the attempt's stream ends in a result record or the attempt has left an exit receipt, and a mark naming no attempt stands for the attempt the pointer names; recovery_review_dispatch._settled_delivery_refusal asks that question instead of asking whether a mark is present.

A working holder keeps its own beat current. A beat written once would lapse on a timer while its host is still busy, and the reservation it guards would then be released out from under a live holder. Publishing a beat therefore starts a renewal thread that this process owns and that every renewal refreshes the beat file's write time; the thread ends with the process, which is exactly the event a beat is meant to mark. A lapsed beat is read as a host that has gone only when the process it names cannot be seen in the reader's own process table: a stalled renewal is a slow host, not a dead one.

A door releases its reservation by one path. release_unspawned_reservations and its twin release_a_withdrawn_reservation share one body and one guard: each applies the attempt's exit-receipt test, so a reservation whose attempt already ended is not re-released, and the repair advice hold calls that shared path rather than repeating it. host_heartbeat.heartbeat_host is host_lease.local_host, so host identity has one definition and a pid is only ever compared on the host that issued it. The host's beat is published to a temporary beside the keyed file and renamed over it, and that staged write is declared in the staged-write census beside the writers that publish a replacement.

Gate. tests/test_a_reservation_holds_only_while_its_holder_works.py builds a temporary crew home and run directory for eleven cases: a live door still refuses the next launch; a dead pid is released; a lapsed host beat releases while a fresh beat keeps the reservation; a lapsed beat whose holder is still running keeps it while one whose holder has gone releases it; a mark whose attempt delivered holds no review while an undelivered one still holds; the advice hold withdraws its reservation and the next launch is admitted at attempt 3; a coordinator's advice releases a held round and records it superseded; and a published beat stays fresh while its publishing process lives. All eleven pass against the worktree at db127ee63f.

Negative control. A probe that runs unchanged on both arms writes a fresh beat for a foreign host and asks reservation_in_flight whether a reservation naming that host still holds. On the base tree it answers False and reports the reservation was released though its holder was working, exit 3 (negative-control-base.txt), because the base judges the holder by probing a pid issued on another machine, where that number names an unrelated process or none at all. On the head tree the same probe answers True and reports the reservation followed its foreign holder, exit 0 (negative-control-head.txt).
