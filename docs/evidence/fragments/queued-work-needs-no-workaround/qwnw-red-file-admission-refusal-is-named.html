A red admission-refusal test file reads green, with two causes named

tests/test_admission_refusal_is_named.py carried five failing tests on the primary branch. Both causes are named below, one product and one test, and neither was cleared by weakening an assertion: the five assertions and the three cases that already passed are unchanged.

The two causes

  1. Product wrong — the pre-spawn reading outranked the pointer's own worker record. classify_pointer read any pointer whose phase sits in _PRE_SPAWN_PHASES (starting, launching, launcher, dispatching) as a request the launcher had claimed and not yet started, whatever the pointer recorded. The commit that gave the parked phases their launched guard states the rule it did not apply here: a pid or a launch clock means the request launched and its liveness, not its label, decides the reading. A run refused at admission carries exactly that shape — a pre-spawn label, a recorded pid, a stream holding the refusal, a dead process — so it read running for as long as its pointer lived and the refusal the classifier can name was never reached. Repaired in reckon/crew/recovery_classification.py: pre_spawn_waiting now requires not launched, beside its existing stranded-launch term.
  2. Test wrong — the fixture recorded no worker. The file's _pointer helper wrote a stream, a dead process and a pre-spawn phase but no pid, so its pointer described a request that had not started rather than a run whose worker had ended. A pointer a launch writes records the process it started, so the fixture now carries pid: 424242. The assertions are untouched: the rule the file asserts — a refused admission is named, a genuine vanish still abandons, an in-harness run and a mark-less refusal are not refused, and every neighbouring classification is unchanged — is the rule the product now keeps.
