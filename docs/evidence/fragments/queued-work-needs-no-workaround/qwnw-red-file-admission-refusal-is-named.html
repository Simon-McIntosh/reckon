A red admission-refusal test file reads green: the fixture, not the product

tests/test_admission_refusal_is_named.py carried five failing tests on the primary branch. One cause explains all five, and it sits in the file rather than in the classifier, which already keeps the rule the file asserts. No assertion was deleted, weakened or added: five failing cases failed identically before and after, and the three cases that passed still do.

The cause: test wrong — the pointer recorded no worker

The file's _pointer helper wrote a stream, a dead process and a pre-spawn phase (starting), and recorded no pid. classify_pointer reads a pre-spawn phase in a pointer that records no worker as a request the launcher has claimed and not yet started — pre_spawn_waiting, whose comment and the commit that added its launched guard both state the rule: a pid or a launch clock means the request launched and its liveness decides the reading. So the fixture's pointer was the other row entirely, held at running, and every liveness reading the file asserts on — a refusal named, a vanish abandoned, an in-harness run and a mark-less refusal left alone — was unreachable.

The repair is the fixture: _pointer now carries "pid": 424242, the record a launch writes. The product is unchanged — it was verified, not reimplemented.
