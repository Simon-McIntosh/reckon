One refused promotion reports every failing independent precondition

What was wrong. tests/test_one_refusal_on_main.py asks the promotion to report two independent preconditions in one refusal — an unmoved plan impl, and a passing gate whose check names its command but no log — with the leading refusal's wording unchanged and the two in the order the promotion checks them. On the primary branch at 23b901694b4bfec73d95be3a082d4c336d9a4101 the first of the three cases fails, and the refusal it reads

a gate check is a command and the evidence it ran against: pass --gate-command and --gate-log-path (or --gate-log-digest) together, or neither, because a command beside a log the promotion found elsewhere records a run that never happened

names neither precondition the case asserts, because the half-stated check is refused inside _default_gate_evidence_from_manifest before the promotion's precondition sweep runs at all.

Cause and verdict: the product. One cause, and the product is wrong, not the test. The refusal's own stated reason is that the missing half would be derived from the manifest or the stored record — the hazard is a completed check, pairing the caller's half with evidence found elsewhere. A run whose manifest and record supply nothing for the other half completes nothing, and its check is simply missing a field, which ledger.gate_check_missing_fields already names inside the promotion's one-refusal sweep. Raising up front also contradicts the contract that file asserts: a refusal assembled from every independent precondition, in the order they run. So the refusal now stands at each place the missing half would be filled, and a check the fill completes nothing for falls through to the gate precondition beside every other precondition. No assertion was deleted, weakened or rewritten, and no test file changed.

The guard still fires. A half-stated check the manifest can complete is refused wherever it would be completed: a command with no log is refused when the manifest's own test_logs entry would be cited, a log with no command when the manifest's tests line or the cited log's header names the command, and both directions on a review run whose stored record supplies the whole check. test_a_review_runs_promotion_derives_its_own_gate.py::test_case6 (both arms) passes, and the review-run refusal precedes the derived-log capture, so a refused promotion leaves no file behind it.
