A stop gate whose stub the fenced worker could not exec

Cause, and which side was wrong. Test wrong. At the base the failing id was tests/test_stop_before_spawn_spawns_nothing.py::test_a_group_stop_after_the_spawn_is_recorded_as_that_stops_exit, red with the assertion that arm records, the stub worker never ran, so the group stop would find nothing to end. The cause was read from the fence's composition rather than from a string in that log: the stub was installed under tmp_path, which is beneath the node /tmp whenever pytest's temporary root lives there. Since reckon/_worker_fence.py (worker_tmp_mount_source, commit f420eb11bf, 14 November) mounts a run's own scratch over the node tmp, every other path there reads as absent to the worker rather than merely read-only, so a stub beside the case's own tree cannot be executed inside the node's own fence.

What changed. The stub is now installed in a base created outside the node tmp (/dev/shm or $HOME, whichever is writable and outside the node tmp), reached unchanged through the fence's whole-filesystem bind, and the fixture removes that base. No assertion changed: the marker and the exit record are still read from the run's scratch directory, which is the one temporary root the worker sees.
