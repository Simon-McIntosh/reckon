A census of the live crew home, and the row that survives its run

This node's declared write paths are the section's evidence fragment and its figures directory. The section's done-when asks for tests in a temporary repository and crew home, and for a fix in product source. Both lie outside those paths, so this record carries the measurement the section asks for and states the code work it cannot perform, rather than reporting the section met.

The census the section asks for

Every obligation row stored in the live crew home was read, and each row's run was classified by two independent facts: whether it still holds a live pointer, and whether it still has a ledger row, which a promoted or landed run writes. A run with neither cannot be promoted, landed or resumed again, so a duty naming it can only offer a command that fails.

The census ran as an all_debug job at 2026-11-14T20:55:53Z (census.log, exit 0), reading 130 stored documents and 151 rows carrying a run id. 77 rows name a run with no live pointer: 62 of those runs have a ledger row and 15 have neither. The figure the section asks for — zero rows whose run has no live pointer or has landed — reads 77 at the base revision, not zero.

Two of the section's four row kinds are not the defect the raw count suggests. All 21 worktree-held rows name a tree that is still on disk and unoccupied, each resolved through _held_worktree_records, so they are live duties to collect a tree rather than duties whose run has gone. The seven promotion-failed rows whose run holds no pointer are already settled on read: _settled_state in reckon/crew/promotion_requests.py answers discarded, promoted, landed or gone and rewrites the request before any row is built.

The row that survives its run, reproduced

The sweep-failed row clears by none of the routes the deliverable names. The station keeps its per-session failure list as durable state, through record_sweep_report in reckon/crew/station_obligations.py, and only that session's next completed sweep replaces it. The view adds every stored entry back as a row in _with_sweep_failures without asking whether the run it names still exists.

The reproduction is repro_sweep_failed.py, run against the base revision. It stores one failure for a run, builds the payload the station would publish, and reads the rows back:

rows after one pass: [('sweep-failed', 'r-gone-promoted-and-landed')]
REPRODUCED: a run with no live pointer and no ledger row still raises a row
run r-gone-promoted-and-landed has pointer: False

So a run promoted, landed, discarded or resumed still raises sweep-failed after a pass, which is the case the section names. No such row exists in the live crew home at this instant. The route that raises one has no settlement path, so the row returns as soon as a sweep fails once for a session that then stops sweeping.

The acknowledgement route, measured

The section also asks that crew ack accept any run that still raises a row, whatever its pointer or ledger state. It does not. A run with neither a pointer nor a ledger row is refused unless the caller passes --project, and a row's own next command does not carry it, so the command the coordinator is shown cannot clear the row. Measured directly (probe_ack_gone_run.py, exit 0):

REFUSED: CrewError - no live run 'r-gone-with-no-pointer-or-ledger', no ledger record for it, and no --project to file its deferral under (looked in: no mounted project)

An acknowledgement does clear a row when it is accepted: the view partitions acknowledged rows out of the duty list, and the live home carries 21 such rows at this instant (13 worktree-held, 3 blocked, 2 promotable-stale, 2 run-queued, 1 review-in-flight). So the acknowledgement path is sound where it admits a run; the gap is in what it admits.

What the section still needs, and where it lives

Three changes are needed, none of them in this node's write paths: reckon/crew/station_obligations.py, to drop a stored sweep failure whose run has no live pointer and no ledger row and to prune the stored entry as it is read; reckon/crew/runs.py, to accept an acknowledgement for a run whose pointer and ledger row are both gone, which today needs --project and otherwise refuses; and a test module under tests/ that raises each of the four row kinds and settles the section each way.
