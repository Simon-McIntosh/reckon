An edit recorded as an answer keeps its section covered

An acted answer to a plan-review finding cites the commit of the edit it answers for. Plan-review coverage now reads each unit that finding blocks at that commit and covers the unit while the plan still holds that text: the answered edit is covered whatever its size, a later edit moves the unit and owes a review again, and a declined answer — which asks for no edit — covers nothing.

Measure

tests/test_answering_edits_stay_covered.py, driven through queue_admission.admit_once over a synthesised repository and crew home: at head, 3 passed. At the base revision, 2 failed and 1 passed — the two requests queued on the answered sections stayed held, each naming its own section as uncovered (uncovered units: s2; s2 changed).

Cases

  • Both sections edited and answered acted: both requests launch, held is empty, and no plan-review-owed obligation is composed.
  • A later done-when edit with no finding answered: that section is held with uncovered units: s2, and the request on the second section launches.
  • A finding answered declined with the section edited: the section is held, owing a review.
