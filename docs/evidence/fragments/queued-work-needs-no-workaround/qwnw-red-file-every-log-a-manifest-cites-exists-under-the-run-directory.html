What changed. The manifest check judges a suite arm's revision as a git object id: prose and an abbreviation of an object id are refused, because a spelling cannot be compared with the base the arm must match. The log-location test's fixture cited the seven-character abc1234 in both arms and wrote the same abbreviation into each log's head, so both accepting cases were refused for the revision rather than judged on where their logs live. The product rule is the one the check states in reckon/crew/manifest_faults.py; the fixture is what encoded the older one.

The fixture now cites one 40-character object id from a module constant and writes the same id into each log's head, so an arm and its log name one revision and the assertions turn on log location alone. No assertion was deleted or weakened: the four refusals per log field (scratch, missing, directory, symlink), the acceptance of every field under the run directory in both absolute and relative spelling, and the relative escape are unchanged.
