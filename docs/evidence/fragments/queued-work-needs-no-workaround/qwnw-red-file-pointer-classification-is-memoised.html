The mutation that did not move the file

Green on its own does not show that a guard fires, so the guard the file names was made to fail twice, in a scratch extraction of the same revision. First _read_classification_memo was made to return {}, so no classification could serve what the last one wrote. Then _classification_memo_path was made to return None, so the memo was neither read nor written at all. Both mutations left the file green: 10 passed, EXIT=0, on each.

The reason is in the product, not in the assertions. A second classification of an unchanged stream does not reach _backends.parse_events even with the classification memo gone, because reckon/_backends.py keeps a process-wide _STREAM_SUMMARIES entry keyed by the stream's stat identity and serves the whole read from it. So the eight cases here that count parses are satisfied by that cache inside one process, and the file does not discriminate the persisted memo it is named for. That is worth stating plainly rather than reading as coverage: a regression that stopped the memo being written would leave this file green. A case that opens a second process, or one that clears the backend summary between the two classifications, is what would make the memo load-bearing here; it is not this node's change, and it is not needed for the deliverable, which is the file passing in full.
