A landing reads a suite by its delta and a repeat by its own request

What changed. Three landing readers decide on evidence the run itself carries, and two of them were reading a narrower fact than the one they needed.

An after-suite arm measured before a later commit was refused whenever the head had moved, so a documentation or evidence commit after the measurement invalidated an arm that still described the suite the head runs. reckon/crew/promotion_records.py now asks what the commits between the arm and the head touch: a Python file, anything under the tests tree, or the pytest configuration files count as reaching the suite, and a head that moved through none of them keeps its arm. The question is deliberately conservative, because deciding it properly needs an import graph this check does not carry, and an arm wrongly kept is a regression that lands, so a diff that cannot be read keeps the refusal.

A dry run measured what a real landing would measure, submitting a scheduler job and waiting on it. The suite-delta reader now reports would-measure with the arms it is missing instead of running them, and the declared negative control takes the same path: a run that kept no log admitting its control is reported as one the landing would measure rather than as one that failed.

A coordinator repeating a promotion request that was still queued received the duplicate receipt and nothing else, so the repeat reported the same state as the first call and left the promotion waiting on a drain that might never come. reckon/crew_run_commands.py now carries that request out in the call that found it, and the emitted outcome records "driven": true. A repeat that finds its request terminal keeps the receipt path, so nothing is promoted twice.

Measured

Every arm is a log whose head names its revision, tree and command and whose last line reads EXIT=<code>.
armrevisionresult
gate (this change) 3d55349501 17 passed, EXIT=0
negative control (the pair at the plan's base) a346fba4aa 6 failed, 1 passed, EXIT=1

The gate runs the new file beside the two refusal files it must not disturb: tests/test_a_landing_judges_the_head_by_its_suite.py, tests/test_a_landing_measures_a_mismatched_arm.py and tests/test_a_trailing_after_suite_arm_is_refused_by_name.py, 17 cases in all. The negative control extracts the base revision to a scratch tree, copies the same file in, and runs it against the base code: six of its seven cases fail there, including both halves of the paired base-and-head failure — the arm is refused at the base whichever direction the delta points, and the log is kept.

Cases and what is covered

  • A head whose only failure is the id the base also fails measures zero added, against a red base.
  • The same base with an id the head alone fails is refused, naming that id.
  • A documentation commit after the arm leaves the arm standing; the same shape with a code commit still refuses it.
  • A dry run names the arms it would measure and measures none; a control the run kept no log for is named the same way.
  • A repeated crew complete carries the request its first call queued.
