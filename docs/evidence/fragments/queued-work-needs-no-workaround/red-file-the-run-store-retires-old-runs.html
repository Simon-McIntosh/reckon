The run store retires old runs out of its hot tables

The measured check is tests/test_the_run_store_retires_old_runs.py. At the base revision one test failed; at the head revision the file passes in full. The two runs below are the negative control: the base run's failing id, and the head run of the same command.

The defect

RunStore._refresh rebuilds the store's rows from the committed ledger, and it decided whether to rebuild by comparing the ids its own tables hold with ledger.run_ids(). Every reader answers through the store once it holds a row, so run_ids() returns the store's own ids: both sides of the comparison were the same set. The rebuild could therefore never fire, and a ledger that changed after a retirement left the archived run holding the durable fields it was retired with — tool_steps stayed 7 where the file said 19 — and left a run the ledger no longer carries in the archive.

ledger.run_ids(..., use_index=False) answers membership from the committed documents alone, and the refresh compares that against its own ids. run_ids() keeps its store-first answer for every other caller and takes the document read as a parameter, so document membership has one owner rather than a second reader beside it.

A project whose ledger documents are absent or empty is skipped before the comparison: the committed set would read as empty and the rebuild would delete rows that a mount simply not present here still holds, which the method's own docstring forbids.
