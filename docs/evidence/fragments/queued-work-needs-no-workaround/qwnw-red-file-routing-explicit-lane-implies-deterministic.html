Routing test file: one stale output surface, fixed

Cause, with its verdict

Verdict: test wrong — one assertion basis, not one rule. The dispatch CLI deliberately keeps its final JSON document on stdout and writes the reckon: created run <id> notice on stderr (reckon/crew/dispatching/preparation.py: "Stdout remains the command's final JSON document, so notices use stderr"). Since click 8.2, CliRunner's Result.output is a mix of both streams and is no longer a proxy for stdout.

The real-dispatch case read result.output.splitlines()[0], so under the installed click 8.4.2 it received the stderr notice and failed decoding it as JSON. Every other dispatch test in this repository already parses result.stdout (tests/test_dispatch_names_...): this file was the outlier.

Fix: json.loads(result.stdout.splitlines()[0]) at all five parse sites — precisely stdout rather than output. No assertion deleted, none weakened; the same backend, route and picker-selection facts are asserted. The file was also run through ruff format, which is what left the changed path clean.
