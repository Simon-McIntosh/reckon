The merge into primary main keeps both arms

Promotion met a conflict in reckon/crew/recovery_classification.py against primary main at 9c9fa0ab0d: both sides narrowed the same pre_spawn_waiting expression, from opposite evidence. This node required that the pointer carry no manifest verdict; main required that it carry no spawn evidence — no pid, worker record, stream or launch log. Neither reading is a superset of the other, so dropping either would restore a bug the other had fixed: without the manifest arm a run whose worker finished still reads as one that never started, and without the spawn arm a run that reached a worker still reads from a label the launcher could not advance.

The resolution keeps both, in one conjunction over the same phase test:

pre_spawn_waiting = (
    phase in _PRE_SPAWN_PHASES
    and not manifest_status
    and not _spawn_evidence(record)
    and not _stranded_launch(record, now_seconds=moment)
)

Both comments are carried too, because each names a separate receipt that outranks the launcher's label. No other path conflicted; the merge commit a39a5e4037 has both parents and no conflict marker.

The same arm at the merge head runs cleaner than either earlier head: 63 failed, 1717 passed, 13 errors in 1048.21s, EXIT=1 on all_debug job 1320659. The union comparison against the base arms leaves six ids that no base run reported, and all six are red on primary main itself: running their five files at 9c9fa0ab0d and at the merge head returns the same seven ids in the same order (7 failed, 17 passed at both, job 1320831), so they are inherited from primary's newer commits rather than introduced by this merge.
