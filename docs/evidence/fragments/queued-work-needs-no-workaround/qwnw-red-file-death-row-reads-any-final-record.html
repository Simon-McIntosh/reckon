qwnw-red-file-death-row-reads-any-final-record

tests/test_death_row_reads_any_final_record.py was red on the primary branch at 7c481b65f22d8bb7d27b8f9ce15d52a57f7a7061: one failure, four passes. The cause is in the product, not in the test.

Cause

The death reading asks a run's newest stream for the type of its last complete record. _tail_record_type (reckon/crew/recovery_wait.py) found the last newline's offset through _last_newline_offset — one read of the 64 KiB tail window — and then read that same window again for the record type. The module states the contract the test measures in its own comment: "One window answers the common case … such a chunk holds that record entire and the read stops there." An accounting case that counts the bytes the handle returns saw the duplication directly:

FAILED tests/test_death_row_reads_any_final_record.py::test_the_common_small_record_path_reads_one_window_not_the_stream - AssertionError: (131072, 3000142)
assert 131072 <= 65536
 +  where 131072 = sum([65536, 65536])
 +  and   65536 = recovery._STREAM_TAIL_BYTES

The four parametrized sizes — 1 KiB, 64.5 KiB, 65.5 KiB and 512 KiB — already passed at base, so the floor read that extends backwards past a record taller than the window was working; the accounting case was the only failure. The offset is now taken from the chunk that answers the record type, so a window holding the record ends the read after one. No assertion was deleted or weakened; the window itself is unchanged at 64 KiB, and the sizes' own boundary assertion still reports a window the case list no longer straddles.
