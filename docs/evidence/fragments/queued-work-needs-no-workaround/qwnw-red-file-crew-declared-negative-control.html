Cause, and its verdict: test wrong. tests/test_crew_declared_negative_control.py held one case to the retired wording rule. test_promotion_refuses_a_log_that_does_not_name_the_declared_mutation delivered a red log reading FAILED tests/test_other.py - AssertionError against a declaration of a mutation, and expected promotion to refuse, because the log's text does not repeat the declaration. The gate stopped comparing text with a declaration in 8901431b8a: it now reads two facts about the run the log captured — that the run failed (a terminal EXIT=<n> line, or the runner's own FAILED ids beside its summary) and that it names a failing test id the comparison arm does not fail. That commit updated the two control tests that carried the retired refusal and added a companion case, but left this file alone, so the case was red on the primary branch.

What changed. The case now states the fact its refusal rests on. The delivered log names tests/test_other.py::test_elsewhere and the manifest records a head arm (... after_suite) whose failure_ids already holds that id, so the control adds no failure and promotion refuses it. The declaration the refusal carries was shortened to removing the declared mutation, and the assertion that the declaration reaches the reader is kept, beside a new assertion naming the refusal's own reason (adds no failure to the head arm's). No assertion is deleted or weakened. The manifest fixture grew an optional after_suite record; it is written by json.dumps, so the arm has the shape the gate parses.

Why an arm is needed. _baseline_suite_failure_ids reads a manifest that recorded no arm at all as an arm that failed nothing, so an armless fixture admits every failing id its log names. The refusal is a comparison, and a comparison needs the other side to be recorded: the fixture now records that side; the product was not changed.
