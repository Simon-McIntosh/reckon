Landing a section's last node records the section done

What changed. A plan's impl moves only when a section's declaration moves, so a landing that did not write a declaration could never move impl — and the promotion's own guard then refused with impl did not move for the movement the landing was about to make. Two reviewed runs hit that on 2026-11-23 and both needed --no-impl-change with a reason that said exactly this.

reckon/crew/promotion_scope.py decides, once per landing, whether the run landing is the last open node of its section: an open node is another executable run of the same plan section still holding a live pointer, and this run's own pointer must be present, so a re-promotion cannot re-declare a section a coordinator has since reopened. When it is the last, the section is recorded done after the landing's own plan comment has committed, through the same edit surface a coordinator uses, and committed as its own commit naming the run, so the plan's derived impl advances with the run that closed the section. reckon/crew/promotion_checks.py stops refusing an implement or test run whose own section still reads implementable, because a section's impl cannot move until its last node lands; a plan run naming no section, or a section already declared done, is still held to the movement the guard exists to require.

Recording the declaration after the commit is what lets both guarantees hold at once. Section 48 requires that a refused landing record no declaration, and section 41 requires that a state write accepted after staging survives a refused landing. A declaration carried inside the landing's staged plan write makes the landing's bytes identical to the declaration write a coordinator makes for the same section, so the refused landing's rollback cannot tell them apart: it either takes the coordinator's accepted write with it or leaves a refused landing having recorded a declaration. After the commit there is no staged plan write to roll back, so a refused landing writes no declaration, and a coordinator who wrote the declaration while the landing was in flight keeps it. A run that leaves siblings open records nothing, so impl does not move and no override is recorded.

An earlier attempt at bba1d13a7a wrote the closure inside the landing's own staged plan write instead, and the declaration-set axes of the concurrency measure failed there: 2 failed, 5 passed, 34 deselected in 10.43s. That is the state this ordering replaces.

A closure that cannot be written or committed after the landing has committed is reported in the promotion's receipt (plan_closure) rather than raised: the code has already landed by then, and the missing declaration is a plan repair the coordinator can see.
