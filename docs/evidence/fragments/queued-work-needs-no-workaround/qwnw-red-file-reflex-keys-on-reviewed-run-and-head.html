The reflex test's fixture, not the reflex, was wrong

The file tests/test_reflex_keys_on_reviewed_run_and_head.py failed five of five at base revision ee93819a0d. Every case drove recovery.dispatch_awaiting_reviews, and the sweep returned an empty report, so the failure looked like a product regression. It was not.

Two causes, both in the fixture

CauseVerdictRule the code now keeps
The seeded pointer carried "phase": "starting" with no worker. That is a pre-spawn launch, so the classifier reports running — the launcher has claimed this run and has not started its worker yet and never reaches the completed-manifest arm that makes the run scoring. No run awaiting review, so no review composed. test wrong A run that has launched carries a launched phase; the pre-spawn phases name a claim whose worker has not started.
The seeded repository had no remote-tracking integration ref. clones.own_changed_paths answers None for a history it cannot compare, so review_head_move found nothing to decide and the data-only move re-reviewed instead of carry_review_forward carrying the stored record to the new head. That decision is documented at commit beb6dfff11: “A history git cannot compare — no remote, or a ref that does not resolve — reads as an unshown delta, so no review is carried forward over it.” test wrong Carry-forward needs a measurable move; the fixture must give the repository the origin/main ref it resolves.
