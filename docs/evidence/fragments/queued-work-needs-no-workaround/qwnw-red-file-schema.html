A conformance scan that read evidence fragments as documents

What changed. tests/test_schema.py's cross-project conformance scan walked the whole docs tree of every mounted project, including evidence/fragments/. A node writes its landing record as a fragment there (evidence/fragments/<plan>/<node>.html) and the product composes it into that plan's cumulative record at read time: the fragment is a body include, not a typed resource, so every discovery walk passes over the subtree (resources.EVIDENCE_FRAGMENTS_SUBTREE), and evidence.compose_landed_record appends only the fragment's body, never its document wrapper. The scan held a different line, and a section wrapper or a table row that no reader ever treats as a document failed the document's contract.

The scan now reads the product's own EVIDENCE_FRAGMENTS_SUBTREE constant rather than a second spelling of the layout, and a case asserts the exclusion is in effect: the subtree must be present in the mount set, and no file it names may also be one the scan reads. On this mount set the scan passes over 4,557 fragment files and still reads 2,803 documents and audits 536 archived evidence records.

Causes and verdicts

All four failures the recorded suite carried for this file are one cause: the scan read fragments as documents. Verdict: the test was wrong; no product rule broke and no product file changed. Each cause below names the rule the scan now asserts.
