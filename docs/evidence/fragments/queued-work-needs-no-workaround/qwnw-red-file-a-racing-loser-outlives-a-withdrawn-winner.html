A racing loser outlives a withdrawn winner

What changed. Nothing in the product. The file's three failing tests published the winner's claim on src/claimed.py and expected the loser to refuse it, and that expectation is the part the code no longer keeps. Since the overlap policy narrowed to the paths git cannot reconcile, a mergeable source path is shared by default: _raise_repository_scope_conflict reaches _claim_paths_share and continues before any refusal, so a claim on src/claimed.py cannot refuse anything, and the bounded wait for an unlaunched racing winner is unreachable through it. The fixture now claims pyproject.toml — an entry in DEFAULT_EXCLUSIVE_PATHS that a textual merge cannot reconcile — and every assertion in the first four cases is kept unchanged: the loser proceeds when the winner withdraws, refuses naming a winner that launches, refuses at its derived bound having actually waited, and never waits on a launched peer. The fifth case is untouched.

The probe that decided the verdict

A silent non-refusal is equally consistent with "the wait is broken" and with "the claim never refuses", so the sharing predicate was asked directly before either was repaired. It was run against the head tree; the log is logs/claim-path-probe.log in the run directory.
