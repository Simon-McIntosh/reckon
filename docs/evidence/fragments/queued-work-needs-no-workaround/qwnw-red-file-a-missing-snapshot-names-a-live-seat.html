A missing snapshot names a live foreign seat

What changed. The prompt hook's absent-producer reading is already the one the seat judgement produces: a session with no snapshot beside a live foreign seat names that seat's host and offers this session's follower arming, while a stalled seat or no seat at all keeps the "no producer" sentence and watch --ensure. Six of the file's eight cases asserted that behaviour and passed at the base revision.

The two cases that failed at the base revision are the two that assert the "no producer" sentence, and they failed for the reason the hook's own silence rule gives: since the hook stopped warning a session whose live pointers show no unsettled work, a registered session holding no runs publishes nothing, so stdout was empty and both cases died on the JSON decode rather than on the sentence they name. Both now record the session's live pointer first — runs.pointer_path under the same temporary home — which is the precondition the reading is owed to. No assertion was deleted or weakened: the no-seat case still names the host-less absent producer and offers watch --ensure; the stalled-seat case still names no host and offers no follower arming.

That the silence rule is the cause, and that it is already guarded, is shown by the hook's own suite: tests/test_the_hook_counts_only_what_is_owed.py drives an idle session and asserts an empty stdout, then writes a working pointer and asserts the "no producer" line appears. It passes at this head (19 passed).
