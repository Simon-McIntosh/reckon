What changed. tests/test_spa_viewport_containment.py holds two cases over the SPA snapshot walk. At the base revision the first passes and the second fails: test_stale_readiness_selector_is_reported_loudly.

Cause and verdict. The case re-declared the plans readiness selector as .r-list .r-row on the premise that a component rename had retired those classes, then required the walk to raise BrowserProbeError naming a stale selector. That premise stopped being true: docs/ui/shell-plans.jsx renders <div className="r-list"> with <div className="r-row"> rows, and the artifact index renders beside it, so both the live selector (.r-artifact-index .r-artifact-row, set from a same-day commit) and the "retired" one match. Nothing was stale, so nothing raised, and the case asserted nothing at all. Verdict: the test was wrong. The product rule is intact and was shown to fire (below); only the selector the case names has moved.

The repair. STALE_PLANS_READY_SELECTOR = f"{PLANS_READY_SELECTOR}-retired" derives the absent class from the live constant instead of hand-writing a selector that looked retired when it was written. Every assertion in the case is kept: the raised type and its stale readiness selector match, the selector in the message, matched nothing in the rendered surface, and the absence of timed out waiting for. Only the literal the message is compared against moved, from the retired spelling to the derived one, so the case cannot silently rot the next time a class is renamed.
