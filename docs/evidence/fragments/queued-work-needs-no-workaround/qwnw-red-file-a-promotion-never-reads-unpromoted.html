A promotion's landing is read against the project's checkout

What changed. A departure's word comes from the ledger row the promotion wrote, and that row carries no checkout. In reckon/crew/recovery_watch.py, _ledger_landing_word asked the landing question with a record naming no repository, so the ancestry check could not read one and the word fell back to complete: a row whose commits sat on the project's primary branch read as work that never landed.

_ledger_landing_word now resolves the project's repository through project_mount_repository, and sets it on the record before asking whether the head landed. That call already holds the row it read, so it passes the row to _delivered_head, which now accepts one and skips the second read; _promoted_awaiting_merge forwards it.

No assertion changed. A head reachable from the project's primary branch reads promoted; the same head one commit off it still reads complete. A row whose checkout cannot be read still reads complete too, which is the fail-closed direction: the word changes only when the ancestry was actually read.
