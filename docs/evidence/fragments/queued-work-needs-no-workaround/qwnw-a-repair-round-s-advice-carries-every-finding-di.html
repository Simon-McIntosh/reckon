A repair round's advice carries every finding disposed into it

A repair round composes its advice from the review's open blocking findings and its sub-floor dimensions, and a finding the coordinator disposed as folded:<node> is by definition not open, so nothing that was folded into a node reaches the advice composed for that node. The defect reproduces on the base revision: an advice composed over one blocking finding and two non-blocking findings folded into the same node names one of the three. A candidate change was written and measured in a scratch tree, and it carries all three — but the change lives in reckon/crew/repair.py and a test module, and this node's write grant is the fragment and a figure directory only.

Why the fold is dropped

compose_repair_node builds its finding list as blocking_findings(review) + sub_floor_repair_findings(review, floors) (reckon/crew/repair.py:772 at the base revision), and blocking_findings keeps a finding only when its disposition reads open (repair.py:226). A fold is a closing disposition (reckon/crew/findings.py:60), so a folded finding is removed from the list the brief, the done-when ids and the composed node are all built from. The fold recorded a decision — this finding is that node's work — and the node the fold names is then composed without it.

The composer returns nothing at all when no blocking finding remains (repair.py:776), which is the deliberate shape of a decline-only round: a review whose findings are all non-blocking composes no repair. So a fold cannot be carried by simply widening that gate without also turning every decline-only round into a dispatch. The candidate change therefore widens the advice, not the gate.

The candidate change, and what it measured

Three edits to reckon/crew/repair.py:

  • folded_findings(review, *, node_ids) reads the record's dispositions through finding_disposition and parse_finding_disposition and returns the findings folded into the reviewed run's node or into the repair node composed for the round. A fold naming another node, an exemption and an open finding are not carried.
  • compose_repair_brief takes a folded sequence and lists those findings under a sentence saying they were folded into this node and are answered the same way. The existing per-finding answer contract is unchanged.
  • compose_repair_node composes the brief with the folded list, builds the done-when ids over blocking plus folded, and exposes folded_findings on the returned node. The if not findings: return None gate is left untouched, so a decline-only round still composes nothing.

Over the same script the patched tree exits 0 and the advice carries all three ids and texts (head-arm-advice-carries-every-finding.log). The eight focused repair modules — test_repair_answers_only_blocking_findings.py, test_repair_brief_states_its_suite_pair.py, test_review_findings_compose_a_repair.py, test_an_unmarked_finding_is_reported_not_repaired.py, test_a_disposed_finding_ends_its_repair_round.py, test_a_folded_finding_widens_its_repair.py, test_review_repair_runs_without_the_coordinator.py and test_a_claimless_finding_is_not_a_finding.py — run 50 passed, 0 failed at the patched head (head-arm-focused-repair-tests.log).

What the change needs from a coordinator

  • The write grant. The change needs reckon/crew/repair.py and a new test module under tests/. Neither lies in this node's grant, which is the reason this node reports blocked rather than landing the work its measure already demonstrates.
  • Which node id a fold names. The candidate matches the reviewed run's node id and the composed repair node id. If a coordinator folds onto the round rather than the run — a spelling like repair-of-<node>-<head> — the reader must be widened to it, or the fold will name a node no round claims.
  • Whether a folded finding belongs in the returned node's findings list. The candidate keeps it out of that list and names it separately, so the write scope stays as repair_write_scope defines it (only a blocking finding widens the grant). A version that merged the lists would widen every repair's scope by a non-blocking finding's path.
