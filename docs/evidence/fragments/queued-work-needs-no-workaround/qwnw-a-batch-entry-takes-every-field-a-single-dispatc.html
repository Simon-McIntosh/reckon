What landed

One crew dispatch --batch call now carries the per-node options a single dispatch carries. An entry takes an over_fence_reason, a comment, local and a priority, and each is stored by the same writer a single dispatch uses: the reason on the node, the comment inside dispatch_options, the lane on the pointer's local and backend, and the priority as the three override keys the reprioritise verb writes. An option given beside --batch is the default for every entry that does not set it.

crew dispatch --batch <file> --dry-run is no longer refused. Every entry is judged exactly as a launch would judge it — node contract, write scope, admission domain, waits and window fit — one row is printed per entry, and no pointer and no run directory is written. A compound duration such as 1h30m is read wherever a duration is, summed from its runs, so 1h30m and 90m are the same ninety minutes.

Where the change sits: reckon/crew/dispatch_batch.py reads the four fields per entry and takes the command-level defaults; reckon/crew/dispatching/requests.py takes local, comment, priority and dry_run and stores them on the request; reckon/crew/node.py reads a compound duration; reckon/crew_dispatch_commands.py passes the options through and documents them on --batch.

The done-when, measured

  • Each of the four fields lands where a single dispatch stores it. test_an_entry_carries_the_four_fields_a_single_dispatch_carries queues one entry carrying all four and reads the stored pointer: the reason on node.over_fence_reason, the comment at dispatch_options.comment, local true with local_backend as the backend, and priority_override 5 with its set-at stamp and its reason.
  • A command-level option reaches every entry. test_a_command_level_option_reaches_every_entry queues three entries — one setting nothing, one setting its own comment, one setting its own reason — beside a command-level reason and comment, and asserts the default on each entry that omits it and the entry's own value on the entry that sets one.
  • A dry-run batch prints a row per entry and writes nothing. test_a_dry_run_batch_prints_a_row_per_entry_and_writes_nothing snapshots the crew home, runs a three-entry preview (one of them refused), and asserts rows at indices 0, 1 and 2 with statuses would-queue, refused, would-queue, queued 0, would_queue 2, an unchanged home snapshot and no live pointer. test_the_dry_run_flag_accepts_a_batch proves the flag reaches the batch through the CLI and that the same run writes nothing.
  • A priority-5 entry is admitted before an unranked sibling. test_a_prioritised_entry_is_admitted_before_its_unranked_sibling queues both in one session and asserts queue_order.admission_order puts the ranked one first, while the unranked pointer carries no override key at all.
  • 1h30m stores as 90 minutes. test_a_compound_duration_is_the_minutes_it_says reads 1h30m, 90m, 1h30m15s and 25m and refuses 1h30; test_a_compound_duration_queues queues an entry with time_budget: 1h30m and reads ninety minutes back out of the stored request.

The arms, as run

Both arms run on all_debug as one sbatch --wait job, the base arm from a git archive extraction of 1ba716cf0aeb500f4cf9bc0192d6927e11f9d6b2 and the after arm in this worktree, each resolved over its own tree with the main checkout's interpreter (PYTHONPATH=<tree> <root>/.venv/bin/python -m pytest -p no:cacheprovider -q).

  • Base arm: 90 passed in 8.82s, BASELINE_EXIT=0 (gate-baseline.log).
  • After arm: 98 passed in 7.21s, AFTER_EXIT=0 (gate-after.log).

The targets are the node's two test files plus the batch, dispatch-surface, duration and time-fence modules that cover the changed code. Six cases in tests/test_a_queued_request_is_stamped_at_queue_time.py fail identically on both the base extraction and the after arm, so the delta between the two runs is zero — that failure is not this node's.

The negative control, executed

One entry carrying all four fields is handed to dispatch_batch.queue_batch under a chosen PYTHONPATH. Against the base revision the entry is refused with entry 1 carries unknown field(s): comment, local, priority, exit 0 from the driver (negative-control.log). Against this tree the same entry passes the field check and is answered on its plan document instead, which is how the field set is proved to be the difference. The refusal fires before any plan is read, so the control needs no repository to reproduce.

Scope

Four production modules and two test files. One existing test file whose premise the node retires — the batch path refusing --dry-run — now asserts the preview instead and is named for it (tests/test_a_batch_dry_run_previews.py). No plan edit, no version or modified meta touched: the node's closure is the coordinator's.
