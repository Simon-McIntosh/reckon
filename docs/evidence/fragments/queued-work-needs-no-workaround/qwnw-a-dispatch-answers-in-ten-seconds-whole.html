A batch derives its project once, and discovery stops waiting on git history

What changed. reckon/serve.py gains discovery_without_git_dates(). Under that scope _discover_plans_* no longer calls _git_first_committed or _git_last_committed — two queries bounded at ten seconds each — and stamps documents from the working tree, which the shared stamp rule already falls back to. A discovery built this way lives under its own cache key, so a reader needing commit times never receives the approximation. reckon/crew/dispatching/fences.py enters that scope for every dispatch preview beside plan_read_scopes(); queue_batch enters it too. reckon/crew/dispatch_batch.py keys the batch's one-derivation cache on the project and derives from the project's registered mount. Queue ordering names the mount while a section's wait check names the checkout's own, so a dispatch from a worktree keyed those readers apart and derived the whole project twice.

Negative control — the new test fails at the base revision. tests/test_a_batch_derives_the_project_once.py queues three entries for one project from a worktree whose docs tree is not the registered mount, and counts derivations. Base d45930c3b8 with the test file placed on it: 1 failed, assert 2 == 1, naming the worktree and the checkout as the two trees derived. Head 325fe07e72: 1 passed.

Gate, both arms on all_debug over tests/test_staged_write_inventory.py and tests/test_every_shared_home_lock_holds_across_nodes.py: 55 passed at base, 55 passed at head — no failure added. The first base attempt used a plain git archive extraction with no .git, and two velocity tests errored on git ls-tree; the arm was rerun in a tree with its own git extraction plus git init, which is the 55-passed figure above.

What this table does not show, and why it matters. The instrumented discovery share is 0 on both arms: a dry run resolves a preview without deriving the project at all, so the base-versus-head wall times above cannot be attributed to this change. They also move with a load average that rose from 32 to 130 across the measurements. The change is proven at the mechanism, not by this table: the derivation count is 1 at head against 2 at base, and the suppressed path takes no git query.

Still open. The ten-dry-run table needs a quiet node to mean anything, and the discovery share needs a dispatch path that actually derives the project — queueing does, and a queued request is what the original measure named. A rerun should instrument queue_batch rather than a preview.
