A review row reads a completed manifest past a stale pre-spawn phase

What changed. tests/test_a_review_row_knows_the_producer_is_down.py passes in full. The file was green when it landed in 314c066daf, and three later commits in the same classification path (213b8fd3fa, fab923980b, 4d90e8cbd4) broke it: a live pointer in a pre-spawn phase (starting, launching, launcher, dispatching) now keeps its phase reading and skips the liveness arms, so a run whose worker had already written its manifest read as the launcher has claimed this run and has not started its worker yet for as long as the pointer lived. Its manifest status was never read, so obligations published no review-missing duty, and a review composition refused for want of a producer returned before the queue-writing arm that stores it.

The rule is repaired in reckon/crew/recovery_classification.py. The pre-spawn reading now holds only while the pointer carries no manifest. A manifest is the worker's own record and only a spawn writes one, so its presence is the evidence the launch happened and its status decides the reading, as it does in every other phase. A pointer with no manifest keeps its phase reading, so a claimed-but-unstarted request is still drawn in its own phase — the rule the three later commits introduced is kept, not reverted.
