A mismatched resume asks the run's own host

What changed. One case in tests/test_a_resume_rearms_its_follower.py and the docstring of _rearm_session_follower in reckon/crew/dispatch_watch.py. No product behaviour changed: the re-arm already sends a mismatched resume's request to the run's own live host, and to the calling session's waiting host, unmarked, only when the case's session has no live host.

The rule the case pinned, and how it went red. The case asserted that a resume issued from another session writes no request at all and answers naming the session that owns the follower. That was the rule when the re-arm first checked ownership. Two later repairs superseded it: a mismatched request now hands the run over, the resume path included, and the hand-off goes to the case's own host first. The case was not updated with them, so the primary branch has carried it red since.
