A composed budget is not evidence that a worker spawned

The file failed in two cases on the primary branch, both at the same assertion: _release() returned [] where the review the admission pass was meant to release was expected. The cause is a product rule, so the verdict is product wrong and one product rule is repaired.

Every dispatch composes its live pointer with reckon._backends.unknown_budget("no events yet") before anything launches, and recovery_liveness._spawn_evidence counted any budget mapping as proof a worker had spawned. A launch that stopped before it spawned therefore read as spawned for as long as its pointer lived, so _release_stranded_launches never released a real dispatch: the review kept its claim and its run directory, and the reviewed run kept a dispatch record reading dispatched.

The reproduction, quoted from the base arm at the base revision, is the release returning nothing for a pointer whose only remaining record is the composition placeholder:

The ten failures the arms share are outside this node's change: the in-harness liveness case fails identically at the base revision, and the process-table, stopped-run and server-version cases are environment-tier readings of the same partition. They are recorded under outside_scope.

The repair is recovery_liveness._budget_reports_a_reading: a budget block counts as spawn evidence only when it carries a reading — a headroom label other than unknown, a numeric utilisation, a token count, a cost, a rate-limit window, a threshold verdict or a refusal. A placeholder that measures nothing is the launcher's own act, and a fold that read a stream is separately evidence through the stream reader.
