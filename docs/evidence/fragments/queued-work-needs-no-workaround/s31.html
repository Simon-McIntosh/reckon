A stored sweep failure is owed by the session the run's live pointer names

The station kept failed runs per project as durable state, keyed by the session whose sweep recorded them, and republished each as a sweep-failed row in that same session's obligations. The key outlives the run's owner, and a sweep may record a failure with no session at all, so a run handed from one session to another raised its row where the row's own command (reckon crew observe --run) could not act on it: the wrong session could clear it only until the next sweep raised it again.

The refresh now groups the stored failures under the session each run's live pointer names (station_obligations._sweep_failures_by_owner), selects sessions from that grouping rather than from the record's keys, and leaves a failure whose pointer names no session in the stored record while raising it nowhere.
