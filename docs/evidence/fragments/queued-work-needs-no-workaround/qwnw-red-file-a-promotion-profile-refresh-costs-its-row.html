A promotion's profile refresh folds instead of decoding its history

What changed. The file was red in nine cases, from three causes, and each cause was a product rule, repaired rather than restated:

  • The index maintenance writer published a row the index schema no longer accepts. _index_record_written_document inserted five values into the six-column records table the full index build fills, and its OperationalError was caught and dropped. Reproduced at 6699d0257d: sqlite3.OperationalError: table records has 6 columns but 5 values were supplied, with metadata.generation still 1 against a ledger generation of 2. So every append left the index at the generation before it, the profile fold found no current index, and a promotion's refresh rebuilt from the ledger and decoded every retained payload: 51 decodes where the test allows 0. The writer now inserts the same six columns the rebuild does (reckon/ledger.py).
  • A run store created by one append held that run alone. Every reader answers from the store once it holds a row, so the first append for a project whose committed aggregate carried history answered that history as one row: measured at 6699d0257d, 5 committed rows plus one append read back as 1 row while the ledger held 6. A promotion therefore hid the runs already committed. append_run now imports the committed ledger before the project's first stored row exists, once per project (_complete_store_from_ledger), and an ordinary append still writes one row.
  • The fold read only the file index. A store-backed read no longer builds that index, so a project with no index had no fold inputs and wrote no samples at all. The refresh now falls back to the store's picker projection, selected in SQL, so a retained full payload is still never decoded (reckon/crew/picker/lane_context.py).

Two tests encoded a rule the code no longer keeps, and both were updated to the rule it now asserts, without weakening an assertion. A refused file index used to send the refresh to a raw document scan (len(raw) == 1) or to a single index retry (len(attempts) >= 2); since reads answer from the store, a refused index reaches neither. raw == [] with fallback.call_count == 0, and attempts == [], now assert the absence the old assertions could only infer, beside the figure the old cases kept.
