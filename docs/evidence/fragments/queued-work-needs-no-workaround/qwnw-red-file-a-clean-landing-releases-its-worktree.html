One assertion in tests/test_a_clean_landing_releases_its_worktree.py failed at the assigned base revision bc7b7bec5c55: a landing whose worktree was already removed refused with cites <sha>, which is not a commit this run made beyond its base. One product rule is the cause, and the product was wrong. The repair is 21 added and 7 deleted lines in reckon/crew/promotion_evidence.py; no test was edited.

Cause and verdict

Verdict: product wrong. _require_commits_beyond_base asks whether a cited commit is reachable from HEAD as read in the record's tree. A landing removes the run's worktree, and _record_tree then reads the record through the repository that shares its object store — whose HEAD follows the integration branch, not the run's line. The run's own reviewed commit therefore reads as an unmerged branch, so the landing that had just removed its tree could not promote, and the release's worktree_absent branch — which answers the same state as released — was never reached.

The guard's own docstring already says a record that names no readable directory is not measured against whatever repository the promotion happens to run in; the head read did exactly that. The reachability arm arrived in 0a27d4b750 (attribute merged runs to their own history, 2026-11-15), and that commit is the one that broke the file: the same file reports 3 passed at 956c261790, the commit that landed it, and fails at 0a27d4b750. The repair reads the head only from a worktree the record names and that still exists; with no worktree to read, a citation is the run's work when it descends from the base the run was dispatched against, which is the rule this guard applied before that commit.
