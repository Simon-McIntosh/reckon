A finished upstream releases its waiters

What changed. A request waiting on a whole plan was judged by that plan's own status alone, so a plan whose sections are all done but whose status is still active held every dependent until someone closed it by hand. reckon/crew/admission/readiness.py now decides that wait through the roadmap's own reader, roadmap._plan_dependency_satisfied, whose rule is that a plan-level dependency is met once every section of the upstream plan is done or descoped. One predicate answers for the roadmap, the batch and admission, so the plan-level wait can never disagree with the roadmap about which sections count as done. An unreadable plan holds the wait rather than releasing it.

An input an upstream has yet to write is no longer a queue-time refusal. reckon/crew/dispatching/requests.py resolves the batch's waits before it judges each node, and drops the inputs finding from a request that carries a wait. That absence is not a refusal at queue time: the launch re-derives every input finding against the tree the work will actually run in, so a request whose upstream has not written the file stays parked, and one whose upstream has is launched.

A review run is not an unlanded run of the section it reviews. _section_run_unlanded in the same admission package treated every live pointer as a holder, so a reviewer still working on a landed section kept candidates parked for as long as the review ran. Candidates are now filtered with recovery_review_delivery._is_review_run, the predicate that already owns the difference between a run that has something to land and one that has nothing.

Every promoted row now carries its plan slug. reckon/crew/promotion.py took the plan from the pointer's node alone, and a plan review names its plan as its subject rather than on its node, so the row it wrote recorded no plan at all. _run_plan_slug falls back from the node's plan to the pointer's, and then to the plan slug of a plan-review node id. The fallback reads that id through recovery_review_dispatch._plan_review_pointer_slug, the reader that owns the node-id grammar, so a design review's rubric is not folded into the slug.

A metered request already launched when its upstream landed. That behaviour was measured on this node and found correct, so the missing test was added rather than the working guard rewritten: the request queued awaiting-upstream on the metered lane, and the release launched it under that lane with the lane recorded on its pointer.
