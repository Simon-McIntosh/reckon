What changed. Three changes, all in the one test file; no product module was touched. Causes, each with its verdict: the test was wrong

1. seen["state"] was never set — test_assessment_renders_beside_the_declared_capability, test_rendered_state_is_build_states_mapping_encoded_once. _stub_picker fed its candidate scan to the pick through pick(..., snapshotter=...). The dispatcher now passes its own reported scan — recording_snapshotter in reckon/crew/dispatch_picker.py, which keeps the scan on the result for a fallback — so the keyword the stub set was shadowed, the real scan of the synthetic repository offered no eligible candidate, and the pick never reached the client. KeyError: 'state' was therefore about the stub, not about the assessment. The scan is now replaced at snapshot.candidates, the module attribute the dispatcher's own scan reads, the same boundary other cases in this suite use (tests/test_a_dispatch_waits_for_the_router.py). No assertion changed.

2. The payload's first line was not the payload — test_record_carries_capability_on_the_explicit_route, test_record_carries_capability_on_the_picker_route. _payload parsed result.output, which is the mixed terminal stream. Dispatch prints an advisory to stderr: “node explicit-node names no --time-budget, so the default fence 25m from backends.beta.time_budget is under a quarter of the 2h this node estimates…”, which made the first mixed line prose and raised JSONDecodeError. The command's own channel is unchanged and correct: on stdout it answers with exactly one line, a JSON document (measured below). The helper now reads result.stdout, so it reads the channel the command answers on rather than the one a reader's stderr would see first. No assertion changed.

3. The fixture read the host's temp filesystem. Dispatch refuses before routing when the filesystem that will hold a run's scratch is under its floor, so the case's outcome depended on the node's free space — this one was below it for part of the run and the same invocation answered exit 75 with tmp-headroom-refusal: 2199502848 bytes free, floor 5368709120 bytes instead of routing. CONFIG now pins worktree.scratch_min_free_bytes and worktree.scratch_min_free_pct to zero, which is the config key the guard reads, so the case no longer depends on state outside the repository the fixture synthesises. This is the repository's own rule for a test that would otherwise report on the machine.
