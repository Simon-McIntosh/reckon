One of two racing reviews survives, on a path the sharing policy keeps exclusive

What was recorded. The file tests/test_one_of_two_racing_reviews_survives.py failed four of its eight cases on the primary branch: every case that drives a real dispatch and expects reckon.crew.ScopeConflict failed with DID NOT RAISE ScopeConflict. The four cases assert the racing-claims rule the module exists for — a claim registered first keeps the paths, a claim registered second withdraws naming the first, a launched claim refuses a newcomer whatever the order, and a running owner is never outranked — so a failure here looks like a lost product rule.

Cause, and the verdict. One cause, and it is the test that was wrong, not the product. Each case declares one path for both dispatches: src/claimed.py, a mergeable source file, on a fixture project that ships no sharing declaration. Since 2026-11-11 a project with no sharing declaration shares its source files (_shared_write_paths returns default_share=True), so _claim_paths_share exempts the pair before the arbitration runs, and no refusal can be produced on that path at all. The exemption is the documented rule and is asserted by its own file (tests/test_a_source_file_is_shared_by_default.py: two dispatches on one source file are both admitted). The racing order the cases assert is observable only where the paths are genuinely contended — a path the policy keeps exclusive — so the fixture now declares docs/evidence/archive/race-landed.html, an exclusive artifact class. No assertion was deleted or weakened: the four refusals are still asserted, still name the peer run id and the contended path, and still assert the refused dispatch leaves no live pointer behind.

The probe that decided the verdict, run against the fixture's own project in the delivering tree: _claim_paths_share(shared, p, p) reads True for src/claimed.py (no exclusive class) and False for docs/evidence/archive/race-landed.html (class docs/evidence/archive/). Instrumenting the arbitration showed the peer claim reaching the check as binding=True, unread=False, launched=True and being passed over by _claim_paths_share alone — the ordering helper was never reached, which is the difference between a lost rule and a fixture that cannot exercise it.
