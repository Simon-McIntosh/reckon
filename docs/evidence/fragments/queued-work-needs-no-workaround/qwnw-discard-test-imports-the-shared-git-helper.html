The discard-read tests call the shared git helper

What changed. tests/test_crew_discard_reads_discarded.py carried its own git wrapper — _git(repo, *arguments), a subprocess.run of git -C <repo> with the inherited environment. It now imports git from tests/helpers/git.py as _git and defines nothing of its own. The local name is kept so the six call sites in the fixture read unchanged.

The shared helper runs the same git command with cwd=repository and with the crew run identity (RUN_ID_ENV) stripped from the child's environment. That is the difference that matters: the git shim refuses a mutating verb whose run's live pointer it cannot read, so a test that names a temporary RECKON_HOME but inherits the worker's run id is refused its own git init the moment the suite runs inside a worker. The local wrapper did not strip the run id; the shared helper does, and it is the one place that strip lives for the suite.

No assertion was deleted or weakened: the file's diff is one added import line and ten deleted lines — the import of subprocess and the local _git body.
