A delivered run is read from its verdict, not from the phase label it was launched under

What changed. classify_pointer in reckon/crew/recovery_classification.py read a pointer whose phase is one of the pre-spawn labels (starting, launching, launcher, dispatching) as a run its launcher has claimed and not started, and that reading was taken ahead of every arm that reads the run's manifest. The manifest is written by the worker, so a pointer carrying one describes a launch that happened; a supervised launch writes the pre-spawn label and never rewrites it, so a delivered run kept that label for as long as its pointer lived.

Read as never started, such a run answered the run is not awaiting review (running) — never scoring — so the review reflex composed nothing, queued nothing and reported nothing; and never promotable, so the run never reached a promotion. The branch that produced the reading was added on 14 November for a real fault: a starting pointer raised UnboundLocalError and took the project's whole live view down. The repair classified that pointer from its label alone, and so let the label outrank a verdict already on disk.

The label now applies only while no verdict is on disk. A pointer with no manifest, no readable status, or a template body still reads as the run its launcher has claimed, which is the case the arm exists for; a delivered, blocked, failed or waiting run falls through to the arm that reads its word.
