A lane family has one owner

What changed. The rule that maps a configured backend to its lane family had one owner in reckon/crew/dispatch_picker.py, but the read underneath it — resolve the backend's command to a dialect, and treat a command that names none as no dialect — was still stated three times: in lane_family, in reservation_family, and in the picker snapshot's local-wrapper check. A 15 November change gave that check a dialect_for call of its own, so the node's test file went red on the primary branch: test_the_owner_is_the_only_lane_family_derivation_among_the_consolidated_modules refuses a dialect_for( in either former duplicator.

Verdict — product wrong. The rule the test states is the one this section is about: the derivation has one owner. The snapshot's later call was not a lane-family derivation, but it was a second statement of the dialect read, which is the thing the owner replaced. Rather than narrow the assertion, the consolidation it asks for is completed: backend_dialect(backend) in dispatch_picker now states once what it means for a backend's command to name no dialect, and lane_family, reservation_family and the snapshot's local-wrapper check all read it from there. The snapshot's unused reckon._backends import goes with the call it served. No assertion was deleted or weakened; this node does not touch the test file.
