What landed

A brief named by a relative path is resolved once at dispatch, in plan_dispatch, against the request's own repository. The stored path is absolute, so the admit service — which launches from whatever directory it was started in — reads the same file the coordinator named. A request whose brief file is absent is still refused at dispatch, before anything is stored; that refusal already existed and is now pinned by the test.

A queued request whose launch keeps failing no longer cycles for ever. Past queue.launch_failure_limit failures in a row (a new flight setting, shipped default 3, declared in reckon/schema/flight.yaml and regenerated into both committed artifacts) the request is left launch-failed with the last failure recorded as its failure, instead of being written back as a fresh queued pointer. Below the limit it re-queues exactly as it did.

The node's test, tests/test_a_relative_brief_launches_from_any_directory.py, fails three of its five cases at the base revision 3ab436fe38858d361bdd38ee97ab437d867b2043: the relative brief is not resolved, the launch from an unrelated directory is refused (result["failed"] == ["r-briefed"]), and a request past its launch limit is still re-queued.
