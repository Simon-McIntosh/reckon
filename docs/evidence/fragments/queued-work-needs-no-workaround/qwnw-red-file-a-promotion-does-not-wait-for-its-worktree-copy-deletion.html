A promotion's copy-deletion check carries out the promotion it measures

What changed. tests/test_a_promotion_does_not_wait_for_its_worktree_copy_deletion.py drove its two cases through crew complete --gate not-run and then asserted on a promotion that never ran. crew complete now records a durable promotion request for the fleet's admission service and returns; promotion happens in the caller's process only when --wait asks for it. Without the flag the command exits 0 having queued a request, the worktree is never released and no trash entry appears, so both cases ended red for a reason with nothing to do with the deletion they measure.

Verdict: the test was wrong. The product already keeps the rule the file asserts. The release path wraps its worktree release in deferring_worktree_copy_deletion() (reckon/crew/promotion.py), so the registered path is vacated by one rename and the moved-aside copy is left to the sweep; and --wait is the documented way to carry a promotion out in one call. The repair adds --wait to the fixture's invocation; no assertion, no fixture and no product line changed.
