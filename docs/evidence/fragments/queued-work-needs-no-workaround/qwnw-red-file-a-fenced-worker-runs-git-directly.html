Cause 1, verdict: the test was wrong

The case held that a fenced launch outside an allocation carries only the inherited entries, so it asserted _entries(searched) == ["/usr/bin"]. dispatch_launch.launch_search_path prepends the scheduler-shim directory on every fenced launch, inside an allocation or out of one (if fenced or placement.in_allocation, commit c48178ede7), so that a task a fenced worker submits re-enters the fence. test_fenced_launch_resolves_scheduler_shims_outside_allocation in tests/test_shared_environments_are_read_only.py asserts that rule. The case now requires the inherited git shim to be absent and names the whole resolved path, which is [str(shim_directory()), "/usr/bin"]. The assertion is as strong as it was: the same exact list, with the scheduler entry it must now carry named.
