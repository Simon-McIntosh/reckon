Cause 1 — a refusal filed a completion receipt

The live-pointer guard sat inside the member body that path calls, so a landing refused for a missing live pointer still left crew/reports/completion-<ns>.json behind: the refusal wrote a receipt for work it never began, and the test asserts the crew home is unchanged afterwards. That is the rule the reply path already states for a run directory — a refusal must not create one. The guard now runs over every named run before that path is taken, so the crew group's own failure document answers the pending record and nothing is written. The in-body check stays for the queued replay, where the pointer can go between the two reads.
