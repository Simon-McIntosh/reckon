Ledger plan selection goes through the plan owner

ledger.read_records answered a plan-filtered store read from the store's own plan column, a value written when the row landed. The row's plan is owned by ledger.row_plan, so a row whose owner moved read as belonging to the plan it was written under. reckon/run_store.py now exposes PLAN_OWNER_FIELDS and plan_owner_rows(project), a narrow projection of the three owner inputs, and ledger.stored_plan_ids(project, plan) selects the stored ids whose owner answers to that plan. read_records intersects that set with any id filter and leaves the store's plan column to the file index, which cannot outlive its row.
