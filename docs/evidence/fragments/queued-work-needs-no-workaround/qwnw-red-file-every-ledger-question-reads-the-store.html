Ledger plan selection goes through the plan owner

ledger.read_records answered a plan-filtered store read from the store's own plan column, a value written when the row landed, so the column was a snapshot of the owner's answer rather than the answer. The row's plan is owned by ledger.row_plan: the row's own field, then the implementation move it reported, then the node definition it ran. reckon/run_store.py now states that precedence as _plan_owner_sql over both halves of a row, so the store selects a plan's rows by the owner whether the caller names a plan or names the runs it checks, and ledger.stored_plan_ids selects an unnamed read's ids from the three fields plan_owner_rows projects.
