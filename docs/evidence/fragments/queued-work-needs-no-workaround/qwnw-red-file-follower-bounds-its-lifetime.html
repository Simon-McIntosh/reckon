Cause

The dispatch command documents stdout as the channel carrying its result document and writes the notice naming the run it created to stderr (reckon/crew/dispatching/preparation.py), so a refusal's stdout must stay one JSON document. Since click 8.2, CliRunner.output mixes stdout and stderr in write order, so both cases decoded the stderr notice as a prefix of the document and json.loads raised JSONDecodeError: Expecting value: line 1 column 1 (char 0). Both cases now read result.stdout, the channel the command documents; no assertion or field check is removed.
