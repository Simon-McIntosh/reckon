A lane-killed run passes its own test file in full

What changed. tests/test_lane_killed_run_is_blocked.py was red on the primary branch: 3 failed, 7 passed at the merged head. All three failures share one cause, and the product was wrong. recovery_classification.classify_pointer read a pre-spawn phase label as a statement about the present: a pointer whose phase is one of starting, launching, launcher or dispatching was classified running by the pre_spawn_waiting arm before any liveness arm could read its process. A killed run keeps the phase it held when it died, and starting is exactly that phase, so a run the lane killed before its first turn read running for as long as its pointer lived, whatever its recorded liveness said. The retry arm's own comment already states the rule the label broke: phase is not consulted, because a finished or killed run can still carry a starting phase in its pointer.

The repair. One conjunct on pre_spawn_waiting in reckon/crew/recovery_classification.py: a pointer already recorded dead (alive is False) is not waiting to start, so it falls through to the liveness arms that read a lane kill, an exhausted refusal, an unreadable manifest and a vanished worker. Nothing else moved. A genuinely pre-spawn pointer records process_alive: null — record_process_alive answers None for a record naming no pid — so the launcher-claimed window still reads running as before.
