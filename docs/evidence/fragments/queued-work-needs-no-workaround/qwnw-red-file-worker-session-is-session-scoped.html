The session-scope cases measure session selection, not the host's fence

tests/test_worker_session_is_session_scoped.py reported four failing ids on the primary branch because its dispatch helper read the host's user-namespace capability and was refused with D22 before the session selection it asserts. The cause is the test, not the product: the helper's launcher is a stub, so no worker runs and the fence has nothing to seal. The helper now names a fence waiver and its reason, and every assertion is kept. Those four ids were reproduced at cc8a94d by making the capability read fail as a fence-less host fails: they fail there and pass at head under the same probe.
