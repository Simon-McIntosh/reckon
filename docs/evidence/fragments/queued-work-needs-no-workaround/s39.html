A gate log of several per-file runs counts every failure

A gate that runs one pytest process per file appends every run into one log. The receipt reader took the log's last run only, so a gate whose earlier files failed and whose last file passed counted zero failures.

# reproduced before the repair: three marked runs, first two failing, last passing
ids: {'tests/test_b.py::test_two', 'tests/test_a.py::test_one'}
receipt describes: '# file: tests/test_c.py'
log_failure_count: 0

The repair marks each run with a per-file header, sums the per-file summaries and unions the failure ids across every marked file. A marked file that reached no summary leaves the gate unmeasured rather than clean, and an unmarked log is still read at its last attempt.
