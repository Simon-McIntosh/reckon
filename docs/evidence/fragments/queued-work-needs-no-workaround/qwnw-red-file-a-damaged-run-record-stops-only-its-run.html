The cause and its verdict. Test wrong. The test was written when crew complete carried out a promotion in the call. The product's rule has since become the one tests/test_no_caller_waits_on_a_promotion.py states: a plain crew complete only requests promotion and answers with the request receipt.

The third case watched for a refusal that therefore never ran: the second crew complete queued a promotion for the damaged run, printed {"ok": true, "phase": "promotion-requested", ...} and exited 0 — the assertion that caught it was assert refused.exit_code != 0 at assert 0 != 0. Because the request path returns before any promotion runs, --wait is what makes the call carry the promotion out and hand back its outcome, which is where the damaged record is read.
