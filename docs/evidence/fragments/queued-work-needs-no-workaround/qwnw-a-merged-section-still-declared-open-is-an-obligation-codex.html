Merged work names the declaration it still owes

The obligations view and its published snapshot share one derivation over the mounted checkout, completed run records and the live plan declaration. An implementation revision reachable from that checkout while its section remains implementable yields one section-declaration-owed duty for the dispatching session. The duty names the merged runs, the section and every queued request waiting on it, with versioned actions to record completion or a partial delivery.

Temporary-repository caseObserved result
Merged upstream; declaration implementableOne duty for its dispatching session, naming both waiting requests; other sessions receive none
Declaration changed to doneDuty disappears; both requests leave awaiting-upstream on the next admission pass
Declaration changed to deferredNo declaration duty remains
Partial delivery recorded for the merged runNo duty for that run; waiters remain held; another merged run in the section owes a new duty
No run, or a promoted revision outside the primary branchNo merged-section duty
Offered completion and partial-delivery actionsBoth execute through the validated plan writer and clear their duties
Published snapshot after the merged run's pointer is removedThe duty matches the direct obligations view and survives departure filtering

Partial delivery uses the existing section-comment store, with the comment identity c-partial-<run-id> and a non-empty explanation. Its scope is one run in one section. Reachability raises a duty; it never advances the section declaration or releases requests by itself.
