A fragment claim never blocks a sibling

The live-claim check narrowed a plan fragment directory to the owning node's own record, then asked the repository's sharing policy about the overlap that narrowing had produced. docs/evidence/fragments/ is not one of the exclusive artifact classes, so a project that shares by default admitted a peer naming a fragment file a live run already held. The narrowing was right; the exemption contradicted it.

Verdict: product wrong. The test asserts the rule the code should keep — a fragment directory claim compares as the owning node's concrete files, so a sibling fragment file is admitted and the same fragment file is refused. No assertion was changed, deleted or weakened; the test file is untouched.

One helper now answers the overlap question for both the dispatch enforcer and the conflict report: a comparison naming a fragment record on either side never reaches the sharing policy, because one fragment file is one node's cumulative document while its siblings under the plan directory are separate files that merge. Every other overlap keeps the policy the declaration states.
