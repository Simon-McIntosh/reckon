A classification read creates no run directory

What changed. Classifying a pointer that names a foreign launching host read the node's job answer and then wrote that answer into the run's own directory as launcher-host-observation.json. The shared writer creates a missing parent directory, so a pointer whose run had never had a home gained one; where the directory existed but held nothing, the observation filled it, which then defeated the memo writer. The memo's own guard refuses an absent or empty directory, but it checks the directory it is about to write into, so an observation written first made the directory a home and the memo followed it.

Two causes, both product wrong. First, the observation wrote without asking whether the directory was the run's home. Second, runs._write_json had no way to refuse to materialise its parent, so the same write created the home it was meant to describe.

Three changes. _run_home_holds_records in reckon/crew/recovery_liveness.py is now the one statement of the rule — an absent directory and an empty one are both outside a run's home — and both writers that a classification may reach call it. The launcher observation is written only when the home already holds something, and its writer now passes create_parents=False, so a directory a discard removed between the check and the write stays removed. recovery_memo._write_classification_memo lost its private copy of the guard and calls the shared predicate.

The run's own home is the store a discard leaves its marker in, so a read that created one made a pointer that merely vanished read as a deliberate discard, and resurrected a run whose home had been removed.
