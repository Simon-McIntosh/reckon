One fleet-state derivation decodes each live pointer once

What was wrong. A fleet-state derivation lists the project's live directory once and publishes that listing for its own rows and every duty kind it reaches. Two readers below it ask for one run by id and did not answer from that listing: the review-dispatch fields read the reviewed run's waiver through review.recorded_suite_delta_waiver, and the delivery reading looked a run's promotion up through promotion_requests.read_promotion's pointer fallback. Both reach runs.read_pointer, which decoded the run's document again — so one sweep over 300 pointers decoded every document three times.

What changed. runs.published_pointers publishes a pass's listing beside the stat identity each record was read under, and runs.read_pointer answers from it while the file still holds that identity. A pointer written during the pass is decoded afresh, so a caller that changes what it read writes over the record it was shown; a run the population does not hold falls back to the direct read. The station-pid rule the direct read applied is now one helper both routes take, and each caller still receives a dict of its own. obligations.live_pointer_snapshot opens the region around its yield, so obligations(), the station's work-population pass and obligation_snapshot._derive_fleet_state all publish.
