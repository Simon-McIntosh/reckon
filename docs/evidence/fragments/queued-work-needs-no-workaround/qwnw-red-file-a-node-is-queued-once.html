What changed. tests/test_a_node_is_queued_once.py was red at 8fdf39585f with four failing cases and two causes.

The first is a product regression. runs.queue_dispatch stamps a queued request with the review contract it was dispatched for, and the stamp rebuilt the request's node before writing it. A stored node missing a field TaskNode requires raised TypeError: TaskNode.__init__() missing 1 required positional argument: 'goal' out of queue_dispatch, after the pointer had already been written and against the stamp's own contract that a request it cannot stamp keeps no contract and falls back to the dispatch gate. record_review_contract now returns without a contract when the stored node cannot be rebuilt, and the guard is shown firing below.

The second is the test's own instrument, in two shapes. It read Click's Result.output, which since Click 8.2 interleaves stderr with stdout in write order, so a queued launch the case triggers printed its own reckon: created run ... line ahead of the dispatch's JSON answer and the parse failed on that line. The file now reads result.stdout, the channel the documented document is written to, and parses the same document. Separately, one case declared result.json, a file a merge reconciles, and expected a working run's claim to refuse a second node over it. The rule the code keeps is that only a path a merge cannot reconcile is fenced; worktrees isolate the edits to one mergeable file and the merge reconciles them. That case now declares result.png, which a textual merge cannot reconcile, so a working run's claim is still shown to refuse a second node while the queued case is still shown not to bind. No assertion was deleted or softened.
