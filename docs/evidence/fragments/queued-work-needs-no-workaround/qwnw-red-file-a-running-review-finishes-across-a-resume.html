A running review finishes across a resume

What changed. One line of history in the fixture. Every case in tests/test_a_running_review_finishes_across_a_resume.py asks what a resumed run's head move means for the review stored against it, and the product answers that by reading the run's own commits — the ones reachable from its new head but from neither the reviewed head nor the integration branch's remote-tracking ref (reckon/clones.py:own_changed_paths). A tree with no such ref is read as uncomparable history rather than as an empty delta, by design, so the fixture's bare local repository made every head move uncomparable: carry_review_forward answered None, and the composed review fields carried no delta, so the light re-review recorded no tier.

The fixture now seeds refs/remotes/origin/main at its first commit, which is the clone shape a real run's worktree has. No assertion is deleted or weakened; the shipped rule under test — a resume withdraws only a review that never launched — is unchanged.
