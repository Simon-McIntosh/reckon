A held tree named only by a run-less row stays held

What changed. The file was red in five cases at 0e0f25b0f941 for two causes, both judged here.

Cause 1 — test wrong. The fixture registered its retained trees clean, at the primary branch's own head. On 15 November c778aaa1f6 changed the derivation to hold a retained tree only while it carries work no landing has taken, so a clean tree is not a duty and every fixture tree was dropped before the naming rule was applied: the derivation answered {} where the reference expected twenty-one trees. The fixture now writes one uncommitted file into every tree it registers, which is the rule the code keeps; the reference is unchanged.

Cause 2 — product wrong. The derivation read its rows from the merged ledger reader, which now answers from the run store whose identity is a run id. A row the aggregate carries without a run id is therefore never a run that reader returns, even though the ledger still holds it and the document reader the same derivation falls back to does (merged_reader_carries_run_less_row False, document_reader_carries_run_less_row True). The tree such a row names was not held. The aggregate is read by the derivation anyway and the ordinals its ordering map still holds after the rows are filed are exactly the rows the read did not deliver; a pending row without a run id is now filed from the aggregate's own position, so the tree it names stays held. A pending row that does carry a run id is a disagreement between the aggregate and the store and is left to the store's own refresh, so a retired row cannot return as a duty.

The test's per-case reset now drops the derivation's own index beside the shared memo. Without it the derivation answered from the answer a previous case had computed and the bounded case counted zero resolutions — a measure of nothing rather than a small count. With it the case counts the resolutions it claims to.

No assertion was deleted or weakened: the fixture gained a working-tree change, three reference calls read the reader that keeps the aggregate's rows, one assertion compares against that reader, and one reset line was added.
