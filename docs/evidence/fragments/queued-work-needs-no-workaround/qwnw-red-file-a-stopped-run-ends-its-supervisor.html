A stopped run's supervisor case stops the run the way it measures it

What broke. The file's cases stop a live detached supervisor with a stub worker that ignores SIGTERM, then wait for the supervisor's pid to go. They measure the supervisor's bounded drain: one poll to notice the recorded stop, the configured stop grace for the worker to end on its own, a poll to escalate to worker-ignored-the-stop-grace-signal, and a poll to reap.

The stop was made with dispatch.terminate, the call crew stop makes, and that call acquired a second escalator after these cases were written. terminate now waits its own settle window (_STOP_SETTLE_SECONDS, 2 s) for the graceful SIGTERM to be honoured, then SIGKILLs the run's whole tree itself with reason run-stop-escalation. The supervisor's own reaction cannot fit inside that: it notices the stop on its next manifest poll, and that poll is _WORKER_MANIFEST_POLL_SECONDS = 3 s, lengthened from 0.25 s for storage load. With the case's 1 s grace the supervisor's SIGKILL would land at 3-4 s, well after the stop's at 2 s.

Verdict: the test, not the product. The product keeps the rule these cases were written against: the supervisor still drains a stopped worker it is left to drain, and still attributes that kill in the run's own senders.jsonl and exit record. What changed is who ends the run when crew stop is the caller, and the stop's own whole-tree escalation wins by design. Measured on the base tree with the stop the red case made (below), the supervisor's reason never appears and the exit record is filed by the stop, so the supervisor's kill was not observed at all.

What changed. _stop sends the group SIGTERM crew stop sends first, addressed to the supervisor's own session, so the supervisor and the worker both receive it and the supervisor's grace escalation is the only escalator that runs. The whole-tree fallback is unchanged and stays covered by tests/test_a_worker_never_outlives_its_supervisor.py, which drives terminate against a live run. Every assertion in the file is unchanged; the module docstring and _stop's own docstring name why the fallback is not sent from here.

The base defect, reproduced

A probe replayed the fixture at base with terminate as the stop. terminate returned after 2.09 s; the run's senders record in order reads run-stop seven times, then run-stop-escalation four times, and the exit record left behind reads recorded_by: crew-stop with SIGKILL sent to 2 that ignored the 2s grace. The supervisor's kill reason appears nowhere, which is exactly what the red assertion reported. Receipts: repro-terminate-senders.jsonl, repro-terminate-exit.json; the base job's own failure is negative-control-base.log.
