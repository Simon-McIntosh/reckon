§48 — Landing a section's last node moves the plan's impl

A plan's impl moves when a section's declaration moves, and a coordinator declares a section done after its last node lands. When the run landing is the section's last open node, the landing records that declaration once its own plan write has committed, as its own commit, so impl moves as the work that closed the section lands and the promotion passes with no --no-impl-change. A node that leaves siblings open lands with the section still implementable and records no override.

See the node record docs/evidence/fragments/queued-work-needs-no-workaround/qwnw-a-last-node-landing-moves-impl.html for the mechanism and the measured arms: the lone node reads back with its section done and impl moving 0.5 to 1.0; a node with an open sibling leaves impl at 0.5; a refused landing leaves the declaration unchanged; and at the unchanged base revision the lone-node landing is refused with impl did not move.
