A refusal at the scratch floor names its owners

When free space on the node's temp root falls below the dispatch floor, the refusal now carries a per-owner breakdown of the bytes under the scratch root beside the free bytes and the floor. Three owners are named: a landing-base-* tree with no process holding it (with its holders listed when a live process does hold it), each run's own scratch directory with its run id and owning session, and everything else by its top-level path.

The three doors that meet the floor — crew dispatch, crew resume and crew review — each answer with that JSON document and exit 75. A resume previously met no floor check at all; it now reads the same check, through the dispatch plan module so a caller that answers it for one door answers it for both.

The measure is tests/test_the_scratch_floor_is_announced_with_its_owners.py: three refusals driven through the real commands against a temporary scratch root holding an unheld lander tree, two run scratch directories in two sessions and an unrelated directory, each with a distinct byte size and every figure and session asserted from the returned JSON. Negative control: with the owner breakdown removed from the refusal, the assertions on reclaimable_by_owner fail.
