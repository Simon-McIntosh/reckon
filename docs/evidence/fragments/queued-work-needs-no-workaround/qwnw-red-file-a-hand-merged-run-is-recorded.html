A hand-merged run is recorded as the landing it was refused at

What changed. reckon crew record-merge already verified the merge it is given: the commit resolves, it carries the run's reviewed head, and it is on the local primary branch. It then handed the merge to promotion as the run's commit citation, and the promotion citation guard (reckon/crew/promotion_evidence.py::_require_commits_beyond_base) measured that citation in the run's own worktree. A commit made on the primary branch is by construction not on the run's history, so the guard refused the one commit that was actually the landing, and every hand-merged run failed after its merge had already been pushed.

The guard now accepts a citation that is the pointer's recorded_merge field. That field has exactly one writer — crew record-merge — and it writes it only after the three verifications above, so the field names a landing rather than a candidate. The acceptance is per citation: a foreign commit cited beside the recorded merge is still refused, and the base-citation and unmerged-branch refusals are untouched.
