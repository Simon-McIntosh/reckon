A decline-only round names what it declined

What changed. The review reflex composes a repair round from a review's blocking findings and declines one whose blocking findings cite no path the worker can reach. A review that also scored a dimension under its declared floor reaches the composition through that dimension finding, which cites no file of its own. When the composition then yielded an empty write scope, the round was recorded declined with the composed write scope filtered to empty, so the round is decline-only. That sentence states a mechanism and never the decision: it does not say that no blocking finding cites a repairable path, it does not name the dimension that scored below its floor, and it does not name the repository paths the follow-on findings cited. A coordinator reading the round record concluded the review raised nothing repairable, and the sub-floor dimension had no stated next step.

The cited-path read in dispatch_repair_for_run (reckon/crew/recovery_repair_dispatch.py) is now taken once and both decline branches decide from it. A round whose blocking population cites nothing the worker holds carries the decline-only reason the earlier guard records — the blocking-only decision, each sub-floor dimension as name score/floor, and each follow-on repository path. A blocking path that passed the guard while the composition still granted nothing keeps its own wording, because that round did cite a repairable path and test_an_empty_composed_scope_records_a_decline still measures it.

One cause, product wrong. The test asserts a recorded rule the code had stopped keeping when the composition path changed; no assertion was deleted, weakened or re-pinned. Nothing else in the file failed, and the two other cases in it already passed at base and still pass at head: the decision is unchanged, so a blocking source finding composes exactly as before.
