A named lane request queues and takes the reserve

What changed. reckon/crew/dispatch_admission.py, reckon/crew/admission/attempts.py, reckon/crew/admission/launching.py and reckon/crew/dispatching/preparation.py. One admission pass submits its candidates to a pool of width eight, so each launch's concurrency-ceiling read saw the pointer population as it stood before its siblings published a seat. A pass holding one freed seat therefore launched every queued request it considered. LaunchBatch.submit now hands each attempt the number of launches the pass has started and not yet settled, and the bound reads that figure as seats taken — in the roster refusal and in the reservation occupancy the cores and memory bounds are judged on.

The cause, and its verdict

Product wrong. The test asserts a rule the code was meant to keep and did not: a seat admits one launch.
