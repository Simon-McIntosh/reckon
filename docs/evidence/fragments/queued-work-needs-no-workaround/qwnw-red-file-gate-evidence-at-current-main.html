The gate-evidence suite reads the outcome its completion recorded

What changed. tests/test_gate_evidence.py read a promotion's gate check, its suite delta and the fields a suite-delta refusal names off the completion command's standard output. That command no longer answers with the whole outcome: it returns a bounded reply — the row the caller acts on, beside record_path, the path of the run's recorded outcome — and the full statement is the file. Fourteen of the file's twenty-five tests therefore failed at the base revision with KeyError: 'record', 'missing_fields' or 'added_failure_ids', while the command itself behaved correctly: each promotion it refused still recorded {"error": "suite-delta-refused", "missing_fields": ["after_suite"], ...} in that file.

Verdict: the test was wrong. No product rule broke. The cause is ba811581d3 (feat(crew): confirm delivered runs together with bounded replies), which shrank the reply and kept each run's full outcome in completion-<ns>.json under the run directory. The repair adds one helper, _recorded_outcome, which reads record_path from the reply and returns the recorded outcome, falling back to the reply itself when it names no record (a refusal raised before the outcome is filed). Every assertion keeps its subject: the gate check a promotion stored, the suite delta's status, added failure ids, waiver reason, attribution and the missing fields a refusal names are read from the record rather than the shortened reply. No assertion is deleted, weakened or relaxed.
