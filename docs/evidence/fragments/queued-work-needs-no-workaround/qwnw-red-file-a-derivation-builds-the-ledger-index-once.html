The fixture created its tree with git worktree add --detach at the primary branch's own head, leaving a clean status and no commit main does not reach. reckon.crew.obligations._tree_holds_unmerged_work exists to refuse exactly that row: a tree that survived its run but holds nothing a landing would take "only costs someone a look, while a row claiming otherwise costs a reader their trust in every row beside it". Cause 2 — product wrong: one derivation decoded the index twice

With the fixture corrected, test_one_derivation_builds_the_index_once still failed, measuring one derivation built the index 2 times. A probe recording each ledger._index_payload call showed the two decodes differed only by their bound: one activity_since=1794480600 from the utilisation reader, one unbounded from the held-worktree pass. The read pass keys its decoded payload on that bound (ledger._payload_slot), so the two readers cannot share a decode by key alone.

The bound is not free to drop. It is the change that keeps a long-lived monitor from paying a whole-history decode once per five-minute bucket (measured at 10,770 rows, 5.9 s and a 1.61 GB peak). So the repair shares the other way: the derivation marks the history it read (obligations.derivation_history), the utilisation reader takes those rows and applies the same bound to them (obligations.derivation_run_rows), and a reader outside a derivation keeps its bounded read. The held-worktree pass now runs before the classification the utilisation reader is reached from; the two reads share no input, so neither answer depends on the order.

The file's second case carried a count control asserting that the explicit-root route still built the index twice. That build no longer exists — the repair removes the second decode for every route — so the control now measures what distinguishes a count of one from a count that cannot see a build: a derivation whose memo the process has dropped builds again, so two such derivations read two builds. The equality assertion it also carries, that both routes answer with the same held rows, is unchanged.
