A session-host case that asked a session it was not

What was red. At the base revision 94359be6ce0d3f31fd31f0ac4d4b7437f2835832, one case of tests/test_dispatch_session_host.py failed and 7 passed:

Verdict: the test was wrong in three places; no product module was changed. The file was written on 7 October; three rules it encoded were changed or extended afterwards, and each is guarded where it lives.

The three causes

  1. A request is written only for the calling process's own session pair (reckon/crew/dispatch_watch.py, _request_host_follower: “the FIFO belongs to the calling process's host, so a pair named for any other session would be followed by a host that does not own it”). The case dispatched under the name session-hosted while the fixture makes this process claude-session-host-test, so nothing was written to the FIFO and the dispatch fell through to the unchanged Monitor refusal. Measured directly, with the FIFO open and its host reading:
session session-hosted request written: False elapsed 0.0
session claude-session-host-test request written: True elapsed 0.0
line: b'{"project": "sample", "session": "claude-session-host-test", "owner_checked": true}\n'
  1. The answer dispatch accepts is the host's own live child in its census, not a bare follower registration (_ask_session_host_for_follower waits on _session_host_child_pid). The stub host took a follower registration and published no census, so even a delivered request left the answer unheld. Measured with a live registration and then with the census record naming that same pid:
census child with registration only: None
census child after record = the follower's pid is the host's: True
  1. The request line carries the owner mark (_request_line writes owner_checked), and the case asserted a two-key line. That mark is printed in the probe above.

What was updated, and to what rule. The case now dispatches as the session the environment declares (a module constant, CLAUDE_SESSION, that the fixture also sets), the stub host publishes the follower it starts in the host census under the registration it holds, and the delivered line is asserted whole, owner mark included. No assertion was deleted or weakened: the two-key line assertion was replaced by a three-key one, which is stricter; the delivery, attachment and empty arming line assertions are unchanged.
