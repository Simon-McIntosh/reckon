What changed. Two causes in tests/test_reflex_acceptance_reads_the_remote_primary.py, both in the test and neither in the product. No product file changed.

Cause one: the arm asserted a refusal the product stopped producing. The file's first arm recorded a run with "role": "implement" whose commits the remote did not carry, and expected the sweep to refuse with unmerged_commits. Acceptance now lands an implementation itself — automatic_land = bool(missing and implementation) in accept_clean_review — so that refusal survives only for a role acceptance does not land. The base arm reproduces the defect as KeyError: 'unmerged_commits' on test_a_run_only_on_local_main_is_not_promoted, with 11 of the file's 12 tests passing beside it.

Cause two: the fixture named the project checkout as the run's worktree. A promotion writes its own ledger row onto the primary branch, so a run whose worktree is that checkout finds it moved when the landing is judged: with the measure transport stubbed, the arm reached the land step and was refused with the run's worktree … is at <promotion row>, which is neither the reviewed head <head> being merged nor an ancestor of it. The same arm reached sbatch --wait --parsable --partition=all_debug without providing a scheduler, which the repository's session guard records as a teardown error.

What the file now asserts. A run only on local main is landed by acceptance: the sweep measures it at its merge candidate and, with the recorded gate still passing there, promotes it, merges the reviewed head and pushes, so the remote carries the work. The arm gives the run its own detached worktree at the reviewed head, replaces only the scheduler transport (partition measurements run the product's own wrap script in this allocation, and the archive script, gate command and EXIT= receipt stay the product's), and asserts the promotion, the pointer's retirement, the ledger row's review-acceptance promoter and git merge-base --is-ancestor <head> refs/heads/main on the bare origin. The shared run writer gained an optional worktree, so the two files that import it are unchanged. No assertion was deleted: the four that read the old refusal were re-expressed against the rule that displaced it.
