A tier-none duty keeps its review tier

What changed. The obligations view narrows a delivery row to a fixed field set so a reply stays bounded, and that set dropped review_tier. A run the tier rule exempts therefore read review-ready with no tier beside it, so a reader could not tell it from a run whose review has passed, even though the full row carried the tier and the row's own kind is decided by it. reckon/crew/obligations.py now carries the field on the bounded row.

Two expectations in tests/test_a_tier_none_run_owes_no_review.py encoded rules the code stopped keeping after they were written, and each is updated to the rule it now asserts. A settlement is offered only from a passing measurement of the current head, so a run that records no gate is offered its observation rather than a promotion the acceptance gate would refuse with the run records no passing gate to re-run at the merged head; what the duty must never name is the review dispatch the tier rule exempted. And the commitless promotion form belongs only to a run that declares no repository change, so the base-citation case now declares none and the expected form carries the wait flag the composer inserts. No assertion was deleted, and the tier-none duty still reads review-ready with review_tier: none while the runtime-source run in the same pass still reads review-missing.
