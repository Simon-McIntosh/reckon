A malformed request is refused before storage

What changed. The live view's contract is one declaration, reckon.crew.query.LIVE_FIELD_VOCABULARY, which the view serves from and the MCP pre-flight refuses from. The classification had gained four keys since that declaration was written: delivery, orientation_check, stuck and stuck_reason. The view therefore served them while the pre-flight turned a request for one of them back as an unknown field — a refusal the caller cannot act on, because the view would have answered the request that was just refused.

The rule kept. No test assertion was changed or weakened. The file was red and the product rule it states was the stale side, so LIVE_CLASSIFICATION_FIELDS now carries the four names and the declared vocabulary is once again the set a classification produces, field for field.
