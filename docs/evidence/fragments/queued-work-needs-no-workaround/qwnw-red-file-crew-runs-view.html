A drain reports an unreadable plan inventory as unknown

What was wrong. A drain counted a plan it could not read as a plan declaring no sections. The closure remainder is derived from _plan_html.read_state_file, whose shared text read turns an OSError into "", so a plan refused by the filesystem parsed as an empty document and the inventory answered a number it had never read. The product already stated the rule one reader over: the metadata index's _plan_record takes a readability read of the file's bytes first for exactly this reason, and reports unreadable rather than a figure. The drain's own plan inventory had no such guard.

What changed. _plan_html.read_readable_state_file takes a readability read of the file's bytes, memoised against the file's stat identity, and parses those bytes when the shared parse holds a masked empty document; an unreadable file raises instead of answering with an empty plan. _drain_plan_states uses it, so one unreadable plan leaves the whole inventory None/None rather than shortening it, and _plan_record now shares the same read instead of carrying a second copy of the guard. No assertion was deleted or weakened: the test that failed encodes the rule the index already kept, so the cause verdict is product wrong.
