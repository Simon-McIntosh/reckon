A scoring pointer carries the phase a spawned run carries

tests/test_scoring_dispatches_its_review.py was red on the primary branch: three of its four cases failed, and the fourth passed without reaching the behaviour it names. Each case builds its source run through one helper, _scoring_pointer, and that helper wrote a pointer whose phase was starting — a pre-spawn label — while its manifest reported status: complete.

Verdict: the test's fixture, not the product. The classifier reports a pointer in a pre-spawn phase (starting, launching, launcher, dispatching) that carries neither a pid nor a launch clock as a run its launcher has not started, which reads running. That rule is deliberate: a pre-spawn pointer once raised UnboundLocalError out of classify_pointer and took the whole live view down for the project. The review dispatch composes only for a row classified scoring, so all three cases answered the run is not awaiting review (running) before the reflex under test was ever asked whether the run is qualified — the two KeyErrors are the same cause. No product rule broke: a run in that shape does not exist in production, because the launcher writes the pid when it spawns. The fixture now names working, the phase a spawned run carries once its worker has delivered, and each assertion therefore exercises the composition, the lane hold and the admission refusal it was written for. No assertion was deleted, and the quiet half — which had been passing on the refusal it did not mean to test — now reaches the stored-review arm it asserts.
