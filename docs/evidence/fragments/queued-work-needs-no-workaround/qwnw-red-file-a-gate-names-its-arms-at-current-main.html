A gate's arms are read from the record its reply links

What changed. The test file's four red cases read a completion's outcome off the command's own JSON reply: json.loads(result.output)["record"]["suite_delta"] for the arms a declared gate lands, and payload["missing_fields"] or payload["added_failure_ids"] for the two refusals. That was the reply's shape when the file was last repaired. It is not any more. A completion reply is now a bounded receipt — ok, run_id, ledger_path, record_path, pointer_removed — and the outcome, the suite delta and the fields a refusal names, is the record that record_path holds. The reply answered KeyError: 'record' and KeyError: 'missing_fields' on a landing that had in fact succeeded, so the file was red about the reply's shape and not about the gate declaration it is written to measure.

The change is one helper, _receipt(result), which loads the record the reply links, and the four cases read through it. No assertion was deleted or weakened: every case still asserts the same status, the same declared command, the same missing fields, the same added failure ids and the same detail sentences — it reads them from the document the receipt names instead of from the receipt.

Verdict. Test wrong. The product rule the file encoded was retired deliberately in ba811581d3, "confirm delivered runs together with bounded replies": recording full outcomes and returning compact receipts. The record still carries every field the cases assert, and reading the linked record is what any other caller of this reply shape does — tests/test_a_clean_landing_releases_its_worktree.py and tests/test_a_conflicting_landing_is_repaired.py already read json.loads(Path(json.loads(result.output)["record_path"]).read_text()). Nothing in reckon/ was edited.
