A vanished review pointer does not stop the station

What was wrong. The station views its live pointers over a snapshot and reads each listed review's own pointer from disk, so a review promoted or discarded during a slow tick is listed but unreadable; the reader must see a falsy value rather than an exception. That half of the file already held: _current_review_in_flight passed at the base revision, and the case that asserts it passed there untouched. The two failures were in the station-loop cases, and neither was about the vanished pointer.

The cause, and which side was wrong. Both failures were the test's own station double, not the product. run_station's shutdown drains the station's duties — a bounded moment for a derivation in flight to land — and the tick loop polls the reloader with those duties. The double carried a clock, a reflex and a tick and nothing else, so the teardown raised AttributeError: 'types.SimpleNamespace' object has no attribute 'duties'. In the case whose tick raises, that teardown error was raised over the error the case asserts on, so the recorded traceback named the double rather than the failing read. The real Station always constructs duties and the real StationReloader.poll takes them, so the product rule is intact: verdict test wrong, and the double now carries a duty drain that lands immediately and a reloader that answers "no reload owed". No assertion was deleted or weakened; the three assertions of the file are unchanged.
