Admission tests date their live fixtures when they run

Three of the five admission tests built their queued-pointer fixtures from a fixed calendar date. A queue entry belongs to a coordinator that is live at the moment admission reads it, so the five tests passed on the day the date was written and failed every day afterwards: once the fixed timestamp sits more than 72 hours behind the moment under test, the lost-session retirement drops the pointer as retired-lost-session before the assertion that expects it held or launched can see it. Both fixtures now stamp their live timestamps with datetime.now(UTC).isoformat() at import time. The one seed that is genuinely historical — the earlier completed run in test_a_new_plan_review_is_a_first_attempt.py — keeps its fixed date, because a past attempt is what it models.

The remaining two failures were a different kind of staleness in the same five files. test_a_queued_launch_never_classifies_the_fleet.py replays reckon/crew/dispatching/preparation.py at a pinned reference revision and compares the launch inputs the current code produces against it. Two changes land after that pin: the seats_in_flight keyword on the launch call, and the dispatch_width recorded default. The comparison now drops the keyword the pinned reference never knew and states the width on the request, so both arms are compared on the inputs they share rather than on the ones that postdate the pin. test_composed_review_waits_for_a_roster_slot.py asserted that the queued pointer carries the composed directory in node.brief; the pointer instead carries brief_path, the path of the run-directory copy the launch will read, and node.brief is null. The assertion now checks that the stored copy's parent is the request's own run directory and that the composed directory survives the hold.
