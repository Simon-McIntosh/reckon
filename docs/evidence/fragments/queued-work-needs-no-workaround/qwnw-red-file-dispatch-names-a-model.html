The dispatch model-pair test reads the document from stdout

What was red. At base 94359be6ce0d3f31fd31f0ac4d4b7437f2835832, tests/test_dispatch_names_a_model.py failed one of its twelve cases — test_live_pointer_records_lane_and_model_key raised json.decoder.JSONDecodeError: Expecting value: line 1 column 1 (char 0). That case is the only one in the file that dispatches without --dry-run, so it is the only one whose dispatch creates a run.

Cause. The file's payload() helper decoded result.output, which click 8.2 and later fold stdout and stderr into. A live dispatch prints a progress notice before it answers — reckon/crew/dispatching/preparation.py writes reckon: created run <id> to stderr — so the decoder was handed 'reckon: created run r-…-model-test' instead of the document, and the pointer assertions never ran.

Verdict: the test was wrong, the product is right. Two facts fix the direction. The rule is held by tests/test_dispatch_stdout_is_one_document.py, whose _one_document() reads result.stdout and asserts a notice printed from beneath the command is absent from it. And the notice is written to stderr deliberately, beside the operator's terminal. Repairing the product instead would break that rule.

What changed. Five lines added, two deleted, all in tests/test_dispatch_names_a_model.py: payload() now decodes result.stdout.splitlines()[0], and its failure message carries both streams. No assertion was deleted or weakened — the assertions on the live pointer's backend, lane and model_key now execute and pass, which is the first run in which they did.
