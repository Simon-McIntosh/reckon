Held-tree read-once: the fixture trees were never held

Verdict: the test was wrong; the product rule is right. Since c778aaa1f6 the held-tree derivation holds a retained tree only while a landing would otherwise lose something: an uncommitted change, or a commit its primary branch does not reach. The fixture registered its trees detached at the seed commit and committed nothing in them, so every tree was clean and reachable. The filter removed all of them before a naming rule ran, the derivation answered an empty map, and four cases compared that empty answer against the whole-ledger expectation.

The rule is stated in reckon/crew/obligations.py, in _tree_holds_unmerged_work applied by _HeldWorktreeState.refresh_trees, and is owned by the guard in tests/test_a_duty_clears_when_its_run_ends.py, so it is not repaired here. The repair gives each fixture tree one commit its primary branch does not reach, which is the state a dispatched run leaves behind. No assertion was deleted or weakened, and the read-once behaviour the file exists to measure is what the four cases still measure.
