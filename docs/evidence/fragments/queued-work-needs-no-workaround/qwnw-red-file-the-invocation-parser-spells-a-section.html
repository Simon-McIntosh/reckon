The invocation parser spells a section through the shared core

What changed. tests/test_the_invocation_parser_spells_a_section.py failed at the base revision in one test, the census that walks every regular expression under reckon/ and requires each section-spelling frame to compose SECTION_NUMBER_PATTERN. Every functional assertion in the file already passed: the invocation expression composes the core, dotted and hyphenated spellings resolve to s5-1, and an alphabetic suffix is rejected. The census failed because three readers that landed after the census (0609e28519, 3fa3b7b8e9, 0daa5071f8) spelled the number grammar again in their own pattern rather than composing the exported core.

Causes and verdicts. Each is a product rule that broke, and each repair is a substitution with no change to the accepted language:

  • reckon/crew/plan_review.py::_SECTION_REFERENCE — product wrong. It accepted §5.1 and s5-1 with a literal copy of the number grammar; it now interpolates the core, and its compiled pattern is byte-identical to the base one.
  • reckon/crew/plan_review.py::_SECTION_TOKEN — product wrong. ^[sS][0-9]+(?:[.-][0-9]+)*$ became ^[sS]\d+(?:[.-]\d+)*$; the anchored languages are the same, and the token is handed to section_record_id exactly as before.
  • reckon/doccheck.py::_DEFERRED_WORK_TERM — product wrong. The prose alternative that reads "carries to §N" matched the number with its own \d+; it now composes the core, so the one grammar decides what a section number is. The only behaviour that moves is the length of a quoted refusal: §5.1 is quoted whole instead of as §5. Every group in that pattern stays non-capturing, so re.findall still yields text.

The test's own change. The census's expected set is the whole population of core-composed frames, so it now names the three sites the repair brings into the fold — ten entries, from seven. No assertion was deleted or weakened: the census still requires the core in every frame it finds, still compares the site set exactly, and its filter is unchanged. The test was renamed from …_reports_seven_… to test_widened_census_reports_every_core_composed_expression, because a site count frozen into a name is a figure that goes stale on the next reader; the set below it carries the figure.
