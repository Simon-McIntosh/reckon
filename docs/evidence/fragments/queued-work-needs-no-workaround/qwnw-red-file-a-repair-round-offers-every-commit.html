The cause, and which side was wrong

The citations themselves were already read from history: reckon.crew.promotion._promotion_commits returns both commits, and _default_gate_evidence_from_manifest hands them on — five of the file's six tests passed at the base revision for exactly that reason. What the sixth call reaches is _promotion_command, and there is a second gate in front of its citations: completion_offer(record) returns False unless the manifest carries a completed, passing after_suite arm whose revision is the tree's current head, and the command then degrades to reckon crew observe. That gate is deliberate — it arrived with 121ec82a42 and is held by tests/test_an_obligation_offers_only_measured_remedies.py::test_only_a_completed_passing_current_head_is_offered, which asserts a passing gate is offered for a manifest with a current-head arm and is not offered for one without, for each of an absent arm, a non-zero exit, an incomplete run, a stale revision and a bool exit status.

Verdict: the test was wrong. Its fixture recorded a completed repair round with no head arm at all, which is not what a repair delivery looks like and which the product now, on purpose, refuses to promote. The fixture was given the passing current-head arm a repair round delivers, and every assertion was left as it stood: the manifest's commits field is still empty at the point of assertion, and the offered citations are still asserted to equal both commits. No assertion was deleted or weakened.

The assertion still bites

With the fixture in its delivered form, _promotion_command was mutated to compose its citations from the manifest field alone — the pre-repair behaviour — and the file was re-run: 1 failed, 5 passed, the same single test, again reading an empty list against two commits. The mutation was restored. So the repaired fixture still detects the defect it names rather than merely passing.
