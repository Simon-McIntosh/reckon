A full queue is a wait, not a refusal — the file red on the primary branch

What was red, and how it reproduced. At the primary branch revision 42fe90d0b0a46060bafde2490dda7d4002cda4782 failed, 6 passed as an all_debug job (job 1329382) with the measured command's SLURM_JOB_ID unset. Both failing ids were the r-scope-conflict arm of the two parametrised tests: test_a_wait_refusal_keeps_the_queued_reading[r-scope-conflict-_scope_conflict] and test_a_wait_refusal_lists_as_a_queued_run[r-scope-conflict-_scope_conflict]. The first failed on row.get("session_refusal") is None, the second on 'scope-held' == 'run-queued'.

Two causes, each with its verdict. The file was written on 24 October, when every scope-claim refusal read as an anonymous queued row. On 14 November the product rule changed deliberately (213b8fd3fa, a queued row names the hold it waits on): a refusal naming a live run's write claim is published under its own duty kind, scope-held, carrying the holder run and the path it fences and publishing no command, because a command there sends a coordinator to act on a peer's claim, and the stop hook then refuses the rest of that turn. That rule is pinned by tests/test_a_queued_row_names_its_own_hold.py. So cause one is test wrong: the two arms encoded a rule the code no longer keeps, and they are updated to the rule it now asserts — the queue cap keeps the plain waiting text, and a claim reads as a wait on its holder.

Cause two is product wrong, and it is why the r-directory-claim arms were the only passing claim arms. The class walk recognises a claim kind by walking the ScopeConflict family, and its docstring states that the reading names the holder and the path every such claim names; but the holder was read from one phrase only, conflicts with live claim …, so the directory claim's … overlapping the live claim … matched nothing and the row fell back to the anonymous waiting reading. The pattern in reckon/crew/recovery_classification.py reads both phrasings now, so the coarser kind publishes its holder like the exact one. The test arms assert that: each claim arm names r-20261023T220036362628-a-peer-holds-the-path and the path it fences, carries next_command == "", and is followed by SCOPE_HELD_DUTY_KIND, which the test also holds to NON_BLOCKING_DUTY_KINDS. No assertion was deleted or weakened; the arms that asserted the anonymous reading now assert the named one, which is the stricter reading of the same refusal. The follower-condition case keeps its own arm, still read as the session's own duty.
