Queue depth: the red file's two causes, and the runs that show them, repaired

tests/test_queue_depth_project_bound.py reported 5 failed, 6 passed at the base revision and at head before the repair, from two causes. Both were product defects: each broke a rule the code states in its own docstring, and neither assertion in the red file was deleted, weakened or edited.

The two causes and their verdicts

CauseFailing idsVerdictRule the code states, and broke
The launch rebuild of a queued node raised TypeError: TaskNode.__init__() missing 1 required positional argument: 'goal' when the stored node carried no required field. queue_dispatch stamps the review contract when a request enters the queue, and record_review_contract reads the node back out of the pointer, so the refusal escaped the whole dispatch instead of the rebuild alone. test_a_duplicate_request_returns_the_existing_id_and_stores_nothing, test_another_sessions_copy_of_one_request_is_the_same_request, test_a_review_of_a_delivered_run_is_never_refused_by_the_bound, test_a_queued_review_does_not_shrink_the_projects_room product wrong _node_from_pointer: “A field the stored node lacks takes the dataclass default” — a required field has none, so the rebuild was not total. A required field now takes its type's empty value; an empty goal is still refused by the node's own well-formedness check where it matters.
The crew live read answered crew_error: '<resolved flight>: local_backend: must be set before `reckon crew dispatch --local` can route work' on a host with no declared local route, for every row of a five-hundred-request queue. test_the_mcp_crew_reads_answer_inside_their_deadline_on_five_hundred product wrong _lane_config_for: “a configuration that cannot be resolved leaves the row with no reading rather than failing a view whose other rows are readable” — the except clause caught OSError, ValueError and ClickException, and it did not catch FlightConfigError, which is a plain Exception. The flight schema says an absent local_backend means the host has no local worker route, so selecting one is a dispatch concern and not a read failure. FlightConfigError is now caught beside the others.
