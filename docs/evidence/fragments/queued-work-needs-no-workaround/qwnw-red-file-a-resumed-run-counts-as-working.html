A delivered run awaiting its review counts as unpromoted

What changed. _fleet_counts in reckon/crew/recovery_watch.py read the delivered figure from promotion evidence alone. A run classified scoring — its manifest reports completion and its independent review is missing or in flight, so _delivery_reading returns no status at all — was therefore reported as nothing waiting, although its fleet state is completed_unpromoted, the state the state-based count had always treated as unpromoted. The delivered-awaiting-review population is now counted with the delivered one, so the figure keeps the meaning its docstring states: delivered work waiting on a gate, the review included. No assertion in the node's test file was deleted or weakened.

The cause. The test file landed on 29 September (9bf9d9eb9e) and the evidence-only count was introduced by 130499dbb3 on 17 November, so the file predates the change that broke it, and the state the failing run carries never disagreed with the test. The defect is the product's: the commit that split delivered work from requested promotions lost the population whose gate is still the review. Verdict: product wrong.
