E  At index 0 diff: {... 'run_id': 'r-review-first', 'age_seconds': 20} != {... 'run_id': 'r-review-first', 'age_seconds': 0}

Verdict: the test was wrong. The product keeps the duty and keeps its raise instant; what moves is the age the read derives from it. obligation_snapshot.live_payload recomputes every row's age_seconds from the stored age_since against the read instant — the docstring of payload_identity states the rule directly: "Ages are measured from the read instant, so a fleet that has not changed still derives a payload whose age_seconds differ from the stored one", which is why that function strips ages before digesting. The duty row read at moment therefore carries age 0 and the same row read at moment + 20s carries age 20, and the retained duty is exactly what the test was written to prove. A single cause, and only the test encoded a rule the code does not keep.

What changed. tests/test_a_sweep_failure_is_an_obligation.py compares the retained rows with age_seconds removed (through a local _without_ages) and then asserts the retained row's age is the 20 seconds that separate the two reads. Every field the original comparison covered is still compared, the row is still required to be retained with the same detail and next command, and no assertion was deleted; the aging field is compared for what it is rather than for byte equality. No product code changed.
