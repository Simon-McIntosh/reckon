A review run's promotion derives its own gate

What it measures. A review run changes no code, so its promotion rests on the record it stored rather than on a suite result, and its manifest's tests: field carries whatever shape the node's report took — on a review node, a JSON list rather than a command. Six cases hold that derivation: a promotion with no gate flags over a JSON-list tests:; a record with six dimension scores and no total, promoted to the total those scores sum to; a manifest that appears seconds after the promotion starts; a manifest that never appears, refused naming its path; a caller's own gate check kept rather than replaced; and a half-filled gate check refused naming both missing halves.

Result. The file passes in full at the dispatched head, so this node changed no product source and no test. Its deliverable is the passing head run set beside the recorded defect reproduced at the revision that reported it.

Each arm is a log whose first lines name the revision, tree and command and whose last line reads EXIT=<code>.
