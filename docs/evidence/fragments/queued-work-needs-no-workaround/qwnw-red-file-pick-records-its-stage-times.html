A pick record's bound moves with the module that owns it

What changed. tests/test_pick_records_its_stage_times.py was red on the primary branch: one of its four cases, test_a_pick_past_the_bound_records_when_it_completes, read assert True is False at its within_bound assertion. The file moved PICKER_DISPATCH_TIMEOUT_SECONDS on reckon.crew.dispatch to a 50 ms bound, then required a 250 ms pick to record within_bound: false.

Cause, and which side was wrong: the test. When the case was written, the picker read the flag's bound by importing reckon.crew.dispatch and taking its module global, so patching that module moved the figure. The dispatcher now resolves the bound per host through picker_dispatch_timeout(config) in reckon.crew.dispatch_picker, which owns the figure; reckon.crew.dispatch only re-exports it through the facade. The patch therefore moved a name nothing reads. Measured directly, with the picker's own resolver:

default bound: 120.0
after patching dispatch only: 120.0
after patching dispatch_picker: 0.05

The product keeps its rule unchanged and still true: the pick's flag and the wait a dispatch applies to that pick both call picker_dispatch_timeout(config) with the same config (reckon/crew/dispatch_picker.py:686 for the wait, reckon/crew/picker/__init__.py:134 for the flag), so the two cannot drift. Only the test's lever was repointed, at the module that owns the figure, matching the sibling tests that move the same bound. No assertion was deleted or weakened, and the module docstring's stale five-second figure — the shipped bound is 120 s — was corrected.
