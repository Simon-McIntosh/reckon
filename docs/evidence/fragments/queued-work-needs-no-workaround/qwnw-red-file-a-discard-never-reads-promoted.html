A recorded promotion reads promoted only once its head is landed

Cause and verdict: test wrong. The case wrote a ledger row naming no checkout ({"run_id": …, "commits": ["HEAD"]}), so no primary branch could be asked whether the delivered head had reached it. The departure word reads such a row as delivered (complete) rather than promoted, failing closed by design — the rule tests/test_crew_discard_reads_discarded.py already pins, that a row whose head no branch carries is a landing still owed. The case predates that rule and asserted the older one, that the case's row alone settles the run as promoted. The repair promotes the fixture into a real checkout whose primary branch carries the head. The assertion is unchanged, and so is the bar for reading a departure promoted rather than withdrawn or discarded.
