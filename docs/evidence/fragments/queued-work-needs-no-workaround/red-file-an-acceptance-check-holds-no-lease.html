The acceptance-lease suite passes in full at head

What changed. Two defects in tests/test_an_acceptance_check_holds_no_lease.py, both in the test and neither in the product.

Cause one: the fixture wrote a role the product no longer refuses. Every fixture in the file recorded its run with "role": "implement" and then asserted a refusal carrying "unmerged_commits". Acceptance now lands an implementation itself: accept_clean_review computes automatic_land = bool(missing and implementation) and measures the work at a merge candidate instead of refusing it, so the unmerged_commits refusal survives only in the arm kept for a role acceptance does not land (if missing and not implementation). The assertion was reading a key the product stopped producing, and three tests raised KeyError: 'unmerged_commits' against a run the product was promoting.

Cause two: the file never stubbed the measure transport. That merge-candidate measure runs as a job on the project's measure partition, so review_landing.replay_candidate submitted sbatch --wait --parsable --partition=all_debug. The file reached a scheduler verb it never provided, and the repository's _refuse_real_scheduler guard in tests/conftest.py failed eight tests at teardown naming the verb it caught. That guard is why a real submission is a failure here rather than a submitted job.

What the file now asserts. The delivered implementation's own commit breaks the gate it recorded green: node.txt no longer contains satisfied, and gate.sh reports FAILED node.txt::satisfied with a non-zero exit, which is the shape the arm reader needs before it may call a gate failed rather than unreadable. The scheduler transport is replaced by one function that runs the partition's own wrap script in this allocation and writes the receipt that script produces; the archive script, the gate command and the EXIT= receipt remain the product's own.

No assertion was deleted. The refusal is read as gate_report["integrated_verdict"] == "failed". The memo tests still count one _commits_missing_from call per unchanged input and two once a revised head or a changed stored review moves. The coordinator test still completes on the real cross-host lease while the sweep is held inside the commit check, and the two lease tests still observe the lease and the ledger row. Two tests were re-expressed against the rule that displaced the old one: a run the primary branch already carries is re-gated in place and promoted without a measure, and a run refused at its merge candidate is judged again rather than promoted when the branch the remote carries moves at an unchanged head, because the remote answer is one of the inputs a refusal memo is keyed on.

_sweep() calls acceptance.dispatch_awaiting_reviews(project=PROJECT, session="") rather than handing each promotion to a worker: a promotion handed to a worker reports only what finished inside its wait, and these tests ask about one run's own outcome.
