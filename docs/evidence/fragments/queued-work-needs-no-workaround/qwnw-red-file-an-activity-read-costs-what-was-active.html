An activity read costs what was active

What changed. reckon/run_store.py gains stored_run_exists(project): whether the store holds any row for a project, answered by one indexed row over the same schemas, main then the archive, that the read it decides walks. reckon/ledger.py asks that question at both places that asked for the whole membership to learn whether it was non-empty: read_records and _complete_store_from_ledger.

Causes, and which side was wrong.

  • test wrong. The fixture replaced ledger._aggregate_headers with a stub answering only {"runs": []}. Both real paths of that function end at {**data, "runs": []}, so its answer always carries the members and holds collections that load merges unconditionally; every case raised KeyError: 'members' at ledger.py:2584 before it reached a cost assertion. The stub now returns the three collections its stand-in returns. No assertion was changed, deleted or weakened.
  • product wrong. With the stub repaired the read answered the right rows and paid for history beside them: over the fixture's 20,000 rows a window of 50 recent runs cost 20,101 row reads, because the membership probe walked the project's whole history to answer a boolean. It now costs 102.
