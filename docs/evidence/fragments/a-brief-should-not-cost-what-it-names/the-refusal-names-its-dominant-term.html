A context refusal names how its dominant term arrived

What changed. The context-fit refusal already answers with the estimate, the window it exceeded and the largest contributing files with their token figures. It now also names the single largest contributing input and whether it arrived as a declared write path or as a mention, in _context_refusal_detail and _context_contributors in reckon/crew/routing.py. The origin is the group each charged input was read from: a path the node must write is charged because it must edit it, and no brief change can remove it, while a path the brief names in prose can be cut or replaced by a reference. The two shapes send a coordinator to different levers, and only one of them is under the coordinator's control.

The refusal gains one clause and keeps everything it said before. In the fixture whose dominant term is a write path the sentence reads, in full:

context-window-exceeded: estimated 306715 usable input tokens against a 230144 token
window (shortfall 76571 tokens); largest contributing files: …/large_module.py (285715
tokens), …/small_module.py (1000 tokens); dominant term: …/large_module.py (285715
tokens), which arrived as a declared write path

With the same two files but the large one named in prose and the small one declared as the write path, the same clause reads which arrived as a mention. When no repository file is charged at all the refusal keeps its existing sentence — no repository file dominates the estimate — and adds no dominant-term clause, so it never invents a term from nothing.

  • The dominant term is the largest input, not the write path. In the write-path fixture large_module.py (285 715 tokens) is a declared write path and dominates; in the mention fixture the same file is named only in prose and dominates its own 1 000-token write path, so the clause reports mention. An implementation that answered "write path" for any refusal would pass the first case and fail the second.
  • The token figure is the payload's own. Each case reads the figure back from context.inputs.repository_files and asserts the clause carries it, so the sentence and the census the reader can already inspect agree.
  • The evidence a reader already relies on is unchanged. Both fixture cases assert the sentence's existing prefix verbatim — estimate, window, shortfall — and the full largest contributing files list beside the new clause.
  • A small brief still gets an answer. A fixture whose every charged file is 100 tokens against a 20 150-token window still names a dominant term rather than leaving the coordinator with no line to act on.
  • Nothing dominates when nothing is charged. A node with no write paths and no named inputs keeps the existing no repository file dominates sentence and carries no dominant-term clause.
  • What is not measured here. The remedy a coordinator takes once the origin is named — charging a mention at a reference cost (§3) and the anchor opt-out (§4) — is not touched by this change. Nor is the CompetenceLimit message, which renders the estimate, window and shortfall from the verdict and does not carry the detail clause; the clause reaches the reader on the competence-refusal payload's competence.detail.
