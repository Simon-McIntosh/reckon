A brief cut after a context refusal leaves a trace

What changed. A dispatch refused on context fit stops before a worktree exists, so a coordinator who shortens the brief and dispatches the same node again left no record that the cut happened: the accepted run looked exactly like one whose brief had always fitted. A context refusal now writes what it measured under the crew home — the estimate, the window, the shortfall and the repository inputs it charged — in the new module reckon/crew/dispatch_refusals.py. The next dispatch of that same (project, plan, section, node id) that fits records the reduction on the live pointer's node block, which promotion rebuilds the committed row from, so the record reaches the reader auditing landed work as well as the one watching the dispatch.

The record is the flag plus the two token figures the plan's decision chose, never a stored brief diff:

"brief_reduction": {
  "retried_after_refusal": true,
  "refused_estimated_tokens": 220000,
  "accepted_estimated_tokens": 20003,
  "refused_window_tokens": 30000,
  "removed_paths": ["/…/repo/package/payload.py"],
  "removed_text_bytes": 33,
  "refused_at": "2026-11-05T14:58:18Z"
}

It answers nothing unless the accepted attempt measures below the refused one and something in the brief actually differs, so a brief dispatched unchanged to a lane whose own agent layout measures differently records no reduction, and a first-attempt run carries no marker at all.

Consumption is unconditional and the match is bounded. Any dispatch of the node that fits ends the trace, whether or not the brief changed: a brief re-sent unchanged into a roomier lane is not a retry, and a trace left behind would mark a later dispatch against an older refusal's figures while a node never dispatched again would leave its trace in the crew home for good. A trace older than a day is not matched at all — a refusal is evidence about the cut a coordinator is making in that sitting, and an older one describes a brief nobody is holding any more.

removed_paths carries the resolved path the census charged, which is what identifies one file across two attempts that may spell it differently; the entry is shortened to the fixture root here and is absolute in a live run. Only repository inputs are recorded: routing's contributor reader also returns the standing instruction chain, which is charged against the estimate but is not something a brief can cut.

The trace is read through the owners the repository already has. Its instant goes through the shared UTC parser, which reads a stamp with no zone as UTC rather than as unknown; its paths are the contributor reader's records; and its payload carries a version, so a trace written by an earlier shape is treated as absent instead of read back as a dict repr inside the trace's lifetime.

  • The refusal is recorded, not the intention. The refused dispatch is asserted to leave its trace file under the crew home, and the same assertion reads the generated repository back with git status --porcelain unchanged and no path matching *refusal* anywhere in it, so a record written into the repository would fail.
  • The accepted run carries the figures the refuser measured. The marker's refused_estimated_tokens and refused_window_tokens are the refusal's own, read from the raised CompetenceLimit verdict rather than from the trace, and the accepted figure is asserted below the refused one.
  • The record survives promotion. The dispatched run is promoted with crew.complete and the reduction is read back off the committed ledger row's node_definition, so a pointer-only record would fail the case.
  • The marker means something. A node accepted on its first attempt is asserted to carry no brief_reduction key and to leave no trace directory behind, so the marker's presence is evidence of a retry rather than of the feature existing.
  • A fit without a change leaves nothing behind. A node refused at one window and accepted unchanged at a wider one is asserted to carry no marker and to leave no trace file, so a brief that was never cut is never reported as cut.
  • An expired trace marks nothing. A trace whose recorded instant is two years old is asserted not to mark the next dispatch, and to be cleared by it, so a refusal cannot be matched to a brief from another sitting.
  • The input shape has one reader. The charged paths are taken from routing's contributor reader, which already walks the repository-file groups, rather than walking them again in the refusal store.
  • An instruction file is never a path that left the brief. With a standing instruction file in the refuser's census and absent from the accepted attempt's, the reduction names only the repository path, so an input the brief never named cannot be reported as one it cut.
  • An older shape marks nothing. A trace whose paths are mappings and which carries no version is asserted not to mark the next dispatch, so a shape change cannot resurface as a reduction.
  • The negative control. Declared as skip recording the refusal; the accepted run carries no reduction marker and the test fails: with record_context_refusal made a no-op the two acceptance cases fail on the missing marker and the first-attempt case still passes, which is what makes the red attributable to the record rather than to the dispatch.
  • What is not measured here. The estimate is measured through routing's own verdict function with the standing instruction chain pinned, so the two attempts differ only in the brief the test wrote. A census cache keyed without the node's declared write paths can serve one brief's estimate for another brief that differs only there; that is recorded as outside this node's scope, and the fixture shortens the brief text as well as its declared path, which is the shape a coordinator cutting a brief takes.
