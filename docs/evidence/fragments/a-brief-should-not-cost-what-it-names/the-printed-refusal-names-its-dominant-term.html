The context refusal dispatch prints names its dominant term

What changed. CompetenceLimit (reckon/crew/node.py) rendered the context-window refusal as the estimate, the window and the shortfall only. It now appends a dominant-term clause naming the single largest contributing input with its token figure and how it arrived — a declared write path, a mention, or a standing instruction. The ranking is routing's own _context_contributors, imported where the clause is built, so the sentence an operator reads at dispatch and the payload a reviewer inspects name the same input; reckon/crew/routing.py is unchanged. When no repository input is charged the clause states that no repository file dominates the estimate and the standing instruction context alone exceeds the window, because that absence is itself the answer that tells a coordinator the brief is not the problem. A verdict built without the fit it came from (a hand-built or horizon verdict) carries no ranking and gets no clause, so the existing message is preserved exactly where the fit is unknown. The estimate, window and shortfall figures and the D08 remedy are unchanged; the clause is added beside them.
