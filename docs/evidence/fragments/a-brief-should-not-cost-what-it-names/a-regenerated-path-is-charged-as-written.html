A declared regenerated path is claimed as written and charged a flat reference cost

What changed. A dispatch can now declare a path with --regenerate-path (added beside --write-path on crew dispatch and crew pick), carried on TaskNode.regenerate_paths. TaskNode.__post_init__ folds every regenerated path into write_paths, so a regenerated path is a write path for every scope purpose without touching a single scope consumer: the live-claim walk, the scope-conflict refusal, the peer-scope disclosure and promotion's scope reads all treat it as written because it literally is one. The context census in reckon/crew/routing.py (_context_file_inputs) charges each regenerated path one named constant, _REGENERATED_PATH_REFERENCE_TOKENS (4 000 tokens), independent of the file's size, and records it with provenance regenerated plus reference_tokens, so the census shows what was charged and why; an ordinary write path is still charged at full. The regenerated set is part of the census cache key, so two nodes whose scopes differ only there cannot share one cached figure. The live pointer (built from node.as_dict()) and the node definition rebuilt for a shadow or replay carry regenerate_paths, so a node that declares a path regenerated and then reads it is visible to review.
