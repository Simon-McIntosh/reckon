A named anchor is recorded on the node and costs the estimate nothing

What changed. A dispatch can now name a path as an anchor with --anchor-path (repeatable, beside --write-path and --regenerate-path on both crew dispatch and crew pick), carried on TaskNode.anchor_paths. An anchored path enters the context census at zero rather than at a reference cost: the record keeps provenance anchor, its real bytes, and counted: false, so a reader sees a file the worker was briefed about and not given, rather than a file that happens to look small. The anchor comparison is made on the resolved path, so an anchor written in one spelling withholds a mention or a declared input written in another. A path that is both anchored and declared a write path is refused at dispatch with the path named (a regenerated path counts, since TaskNode.__post_init__ folds it into the write scope), because a node cannot both edit a file and be briefed without reading it. The field is carried onto the queued request record and across the admission rebuild, which now also carries regenerate_paths — the same field-by-field rebuild had been dropping it.

Repair — the anchor selects its own cached census

The defect. The census cache is keyed on the fields that select a figure. The regenerated set was already in the key because it changes what a write path is charged; the anchored set changes a charge the same way and was not. A census cached for the unanchored brief was therefore served for the anchored one while the file stamps stood, so the anchor silently bought nothing — and the same figure gates the context-fit refusal. Reproduced on a git-archive extraction of 1c1b41bb with one 1 000 000-byte file: cold caches give 54 392 tokens unanchored and 50 392 anchored, while one shared cache gives 54 392 for both.

Repair — the estimate gate charges what dispatch charges

The defect. The node's estimate cases called the module-private _context_file_inputs rather than context_census, the function dispatch and the fit verdict actually charge with. A gate written that way cannot see the census cache at all, which is how the cache-key defect above passed it green. A second rebuild of the same shape was also present: _recorded_task_node in reckon/crew/dispatch_sessions.py rebuilds a live run's node field by field and named neither anchor_paths nor regenerate_paths, so a node rebuilt from its own record carried no anchor and would be charged the reference cost again, and a regenerated path would not read as written.
