§4 — A finding that does not block is deferred at landing, not held

The landing guard refused any finding without a disposition, whatever its severity: _undisposed_finding_guard enumerated every finding and refused the run for the first one still open. A review that raised two non-blocking observations therefore held a delivered run for a coordinator who had nothing to add. The pass did then write an exemption, but only after the landing — and an exemption is a judgement the pass made rather than the reviewer's, which is why the earlier rework removed it rather than relying on it.

The guard now refuses only a finding that withholds the landing: one declaring the blocking severity, and one declaring none at all, since an unreadable severity is a judgement the reviewer left unstated. The severity is declared_severity's decision, the same reader the repair reflex uses, so the guard, the repair reflex and the new deferral writer cannot disagree about one finding.

The split is read once, by findings.undisposed_finding_indexes: the guard refuses one half and the deferral records the other, so the set a run lands over is the set it defers, numbered by the index a disposition answers.

Every other open finding is recorded once the landing has succeeded, as a deferred disposition naming the run the rule deferred over and the code path that deferred it. The writer is review_dispositions.record_landed_deferrals; the dispose verb refuses the kind by name, so a deferred entry always means the rule acted rather than that somebody typed it. A deferral closes nothing: the findings reader reports it beside open: true, and the row stays open work until a fold or an exemption answers it.
