A review's own promotion waits for its record

A review run's promotion was requested as soon as the review sweep saw the run, which is while the reviewer is still working and before the record it owes exists. The request moved the pointer out of its working phase, and the promotion service then refused it for a record that had not been written yet. Nothing re-requested it, so the review stayed unpromoted until a coordinator noticed.

Reproduction before repair

The base revision's own modules, run against a live reviewer whose record is not yet stored and whose review-self request exists:

{"launched": ["r-20261113T100000000001-review-of-first"], "phase": "promotion-refused", "error": "the review run's worker is still alive", "pointer_phase": "working"}

The request was launched at the first opportunity and refused while the reviewer was alive, exactly the defect the section records.

What changed

  • review_self_state() answers one question for both callers: ready when the record is stored, waiting while the reviewer is still producing it, refused once the reviewer has ended without it. A refusal and a wait are now different facts rather than both being reported as a failure.
  • The review sweep requests nothing while the reviewer is running, so no promotion-requested pointer is written for a record that cannot be read yet.
  • The promotion service parks a review-self request whose reviewer is live: the request moves to promotion-waiting outside the pending set, so it holds neither a promotion slot nor the head of the queue, and the run's pointer keeps its working phase. The requests behind it are drained in the same pass.
  • A reviewer that has ended without a record still leaves a refusal, and that refusal names the missing record.

The cases the tests fix

  1. A stub reviewer writes its record only when it is told to. The sweep reads no review-self request while the reviewer is alive, and the review is promoted once the record is stored and the reviewer has ended.
  2. A request that exists while its reviewer is live is parked: it reads promotion-waiting, the pointer keeps its working phase, and a ready review queued behind it is promoted by the same service pass.
  3. A reviewer that ends without a record leaves the request refused, with the missing record named, and the run's pointer intact.
