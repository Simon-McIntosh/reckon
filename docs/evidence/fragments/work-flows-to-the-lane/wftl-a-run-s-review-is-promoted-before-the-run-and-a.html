A run waiting on a review that is promoted from this queue is not refused

The queue already promoted a run's review ahead of the run when both were waiting, and already requeued a run refused only for that still-queued review. One state escaped both: a review whose record the reviewer is still writing is parked in the promotion-waiting phase, which sits outside the pending set, so the run's requeue test saw no queued review and refused the run. The refusal was then permanent, and a coordinator had to re-request work that was one stored record from promoting.

The test below reproduces exactly that: the review's request is parked while its record is written, the run is drained first (the run's id sorts before the review's), and the run's receipt reads promotion-refused where it must read promotion-requested. With the queued set widened to include the waiting phase the run keeps its request; once the review's record lands and its request leaves the waiting phase, the review is promoted and the run follows it, with no second request.

A run with no review anywhere is still refused for the missing review, so the widening does not soften the guard it protects. Two negative controls show the guards fire rather than merely pass: the node's new test against the base revision's module refuses the run, and the earlier review-first ordering removed makes the review-order test take the run up first.
