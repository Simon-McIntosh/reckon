A session is told, in the pass that submits its queued work, that the work started

The admit pass now writes one row of its own kind to the request's session's watch stream as it launches, in the same pass that submits the request to a worker, and the session's pane draws that row as one line the moment it arrives. The row names the run, the plan and section, the lane, the model, the advice the worker was launched with and the crew tell command that reaches it, so a coordinator that queued the section hours earlier can steer the worker at the moment it starts instead of waiting for the next tick to draw the start.

On the pane the row is one clause line, in the same shape the limit and lift notices already take: the clock, a submitted stage, the node in the job column, then the run, the plan and section, the lane and the command that reaches the worker. A row of this kind names no state word, so the policy delivers it as it stands rather than reading it as observer context and dropping it, and it records nothing in the per-run memory the round-trip rule reads — a submission says the admit pass submitted a request, not that the run reached a state. Rendered, the line reads:

18:00:00  submitted  n1                            run r-first · plan-a §dispatch · lane local-lane · reckon crew tell --run r-first '<message>'        –   0w  0h  0d  0q

The writer is watch_unit.submission_row with watch_unit.announce_submission beside it, in the module that already announces a seat moving between hosts, and it appends through the same runs._append_watch_lines as every other row on the request's project stream. The row is addressed to the pointer's own session, so a pane scoped to another session reads none of it. It carries facts only — no rendered sentence is stored — and event: "submission" keeps it distinct from the run's state transitions, which belong to the producer's fold. The advice is the text the worker was launched with: its steering.md where the request has one, otherwise the comment the request was queued with. Writing is best-effort by construction: the launch has already happened when the row is written, so a stream that cannot be written costs the announcement and never the launch.
