A composed review waits for a placement-roster seat

A plan review is composed before the lane admits it: the report directory, its brief, the plan snapshot and the sidecar are written first, and the dispatch then asks the placement reservation for a worker. When every seat the allocation was sized for was held, that question ended the composition in a refusal and left no pointer, so the run the review was owed waited until a coordinator composed the review again by hand once a seat freed. The refusal was raised as a bare CrewError, indistinguishable from a standing refusal of the work.

The roster cap is now its own held condition — RosterFull, carrying the occupancy the decision was taken on and the seats that produced it — and the review reflex catches it where it already catches a router hold. The review is written as a queued request through the dispatch's own record builder and the queue's own writer, so the admission pass launches it exactly as it launches any other queued request: from the brief the composed directory already holds, once a resident worker ends and frees a seat. That directory is kept rather than discarded, because a queued pointer names its brief. The recorded dispatch status roster-full joins the held statuses, since a roster hold took no work from the run and so may be re-routed like the other held attempts.
