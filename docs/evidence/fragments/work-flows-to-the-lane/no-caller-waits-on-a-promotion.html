Promotion requests are carried by the fleet service

The default crew complete records a durable request and returns. The review sweep dispatches the reviews it owes before requesting acceptance or review self-promotion. A landing pass records the same kind of request without reporting the delivery as landed. The admission service drains these requests at the configured promotion width, calling the existing synchronous promotion and landing paths with their guards and receipts intact.

crew complete --wait retains the synchronous CLI outcome. Internal callers of the promotion function retain their existing behavior. A sweep can explicitly receive the existing bounded worker pool when its caller consumes that pool's report; its production default persists requests.

The request remains authoritative until its terminal receipt is written as promotion.json in the run directory. Renewable run and slot leases, together with in-process claims, exclude duplicate service work and bound concurrency. A fresh service adopts an unfinished request, and a matching terminal receipt prevents replay during interrupted retirement. Refusals and exceptions remain indexed for session obligations and their published snapshot. The pending-landing sweep leaves a service-owned request to the service.

A completed review promotion survives an interrupted receipt

The service can stop after a review operation has persisted the promoted ledger row and removed its live pointer, but before publishing promotion.json. Both request kinds reproduced the defect: promotion-refused instead of promoted, with CrewError: no live run, even though the matching ledger row was present.

Answering commit 14f5694030b77790bcb1b835a27fc571aa377374 recovers the result and its commit identities from that run's ledger row in the project's registered repository when the pointer is absent. It verifies the row's run identity, publishes the service receipt, and retires the request without repeating either review operation. An absent row or a row naming another run remains a refusal with a session obligation. A neighbor's known-present row is read before testing absence, so the refusal test does not mistake an unreadable instrument for a missing delivery.

The regression tests were committed separately at 4739bf4c0f3b32f63edca8949b3bff05cef8469d. They interrupt receipt publication after the review callback writes a real per-run ledger document and removes the pointer, then require a fresh service to recover the same commits once.
