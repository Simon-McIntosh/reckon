Promotion requests are carried by the fleet service

The CLI records a durable request and returns. The review sweep hands off acceptance and review self-promotion after dispatching the reviews it owes; the measured landing pass records a request without reporting the delivery as landed. The admission service drains these requests at the configured promotion width. The service calls the existing synchronous promotion and landing paths, retaining their guards and their receipts.

The request is authoritative until its terminal receipt is written in the run directory as promotion.json. Renewable run and slot leases, together with in-process claims, exclude duplicate service work and bound concurrency. A fresh service adopts an unfinished request, and a terminal receipt prevents replay when its request file has not yet been retired. Refusals and exceptions remain indexed for the owning session's obligations, including its published snapshot. The pending-landing sweep leaves a run whose promotion is owned by the service alone.
