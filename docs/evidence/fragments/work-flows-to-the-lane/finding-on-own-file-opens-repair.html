A finding on the run's own file opens its repair

A review raised two blocking findings against a run's own work: an evidence fragment written one directory deeper than its declared path, and suite arms recorded as prose in the run's manifest under the crew home. The repair reflex declined the round as decline-only — no finding cites a repository path among the 2 blocking finding(s) — because any absolute path, and any path under docs/evidence/ or docs/figures/ outside the run's declared fence, was read as the fleet's own bookkeeping. Both defects were the worker's to fix, and the run would otherwise have sat refused at landing until a coordinator resumed it by hand.

The reflex now reads two reaches over the run's own files, and they are deliberately different. Whether a round opens is decided on everything the reviewed run itself holds: repair.finding_cites_run_own_file() resolves a cited path against the run's worktree, the manifest the record names, and the run directory under the crew home. What the round may be granted stays narrower — repair.finding_cites_run_worktree() resolves against the worktree alone, because a checkout of the repository is work a claim can cover while the run's record directory is written without one. Both predicates are pure and live in reckon/crew/repair.py, so the composer and the reflex agree about which paths a round can reach; reckon/crew/recovery_repair_dispatch.py threads them through the record-path rule and the scope filter. A round that still declines now names every blocking finding it could not reach, by stable id and by the path as cited, instead of reporting only a count.

The cases the node pins

  • A blocking finding citing docs/evidence/fragments/fixture/deeper/landed.html, which exists only in the reviewed run's worktree, resumes the run with that path in the composed advice; the round records resumed.
  • A blocking finding citing the run's own manifest.md under its run directory opens the round and is carried into the advice.
  • A blocking finding citing a file outside the repository and outside the run's directory declines, and the reason names both that path and the finding's stable id.
  • Resolving the same worktree-only citation against the main checkout alone declines the round, which is what shows the first case passes because the worktree is consulted rather than because every citation is accepted.
