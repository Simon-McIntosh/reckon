A queue edit naming a backend keeps that backend

A queued request edited with --backend beside --model resolved the model to whichever configured backend carried its lane and model key first, so the named backend was silently replaced. Two backends may serve one pair: in the flight configuration a lane's plain backend and an editing variant of it carry the same lane and model key, so --backend codex-anchored --model sol stored codex while reporting changed: ["route"].

The edit now asks the named backend directly. The model is resolved within that backend's own lane, and the backend is kept when its entry serves the pair. When it does not, the edit is refused naming both; nothing is written.

  • reckon/crew/queue_edit.py::_named_route keeps a named backend when one is given beside a model, instead of resolving the model to the first backend that serves it.
  • reckon/crew/queue_edit.py::_pair_a_named_backend_serves resolves the model within the named backend's lane and refuses with the backend and the model both named.
  • reckon/crew/queue_edit.py::_backend_serves_pair decides whether that backend's own entry carries the pair, by the same two paths the catalogue resolver accepts.

tests/test_queue_edit_keeps_the_named_backend.py drives the crew queue verb over a temporary crew home whose configuration declares codex, codex-anchored and claude, the first two both serving lane codex model key sol.

Gate run on all_debug; logs are in the run directory (gate-base.log, gate-head.log, negative-control.log).
