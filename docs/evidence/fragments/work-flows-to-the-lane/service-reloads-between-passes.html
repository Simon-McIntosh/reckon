The admission loop already checks the checkout before each pass; the supervisor's unconditional stop bypasses that boundary.

A supervised admission service holds a pass lock from entry through verdict publication. A supervisor requesting new code writes a reload request, which prevents another pass from entering, and waits for the active lock to become free. Its next cycle stops the copy before starting its replacement. The pass records its own start and bound; a stale copy exceeding the bound is restarted with the bound in the log. Admission's default bound is 1800 seconds. Services without this protocol retain their existing restart behavior. Manual admission commands need no boundary file.

Withdrawal of a code change or refusal of its replacement checkout releases the pending request. A live copy's recorded stamp is retained in supervisor state when its runtime PID record disappears; disappearance alone does not restart it. The implementation reuses the atomic JSON writer, flock, existing checkout-trust decisions, and existing stop/start paths. Worker launches remove RECKON_SERVICE_PASS_PATH after merging their environment overlays. A launched child therefore cannot join its parent service's boundary, and neither the parent environment nor the caller's overlay is mutated.
