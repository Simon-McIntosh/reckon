A plan review's own promotion reads the record its brief named

A plan review is composed under a review id its report directory is named for, and the crew run that actually reads the plan is launched under a different id. The composed brief names the report path under the composed directory, so that is the only place a reviewer can write its record. The review run's own promotion read only a run review's head-keyed path, which no plan review declares, so it refused every delivered plan review with the review run stored no readable record for the run it read while the report sat exactly where the brief had sent it. A review whose record its own promotion cannot read is lost, and the plan keeps owing a review.

review_self_state in reckon/crew/recovery_review_acceptance.py now resolves a plan review through the join the promotion step already uses: the composed directory's dispatch.json names the crew run that ran it, and promotion_checks._delivered_plan_review_for_run turns that into the delivered report. A delivered report makes the review ready and promotion stores it; a review that ended with no delivered report under the plan's report root is refused, naming that root. Run reviews take the same path they took before.
