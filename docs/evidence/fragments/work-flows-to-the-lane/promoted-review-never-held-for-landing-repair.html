A promoted review run is never held for a landing repair

At assigned base b8ea8f9f21006af8668ef0cc226799ae50bf966a, the new regression reproduces the reported defect. A review run promoted while its live pointer moves is refused with run 'r-20261113T140142834510-promoted-review' changed while promotion ran; its promotion is recorded and its pointer is kept, marked pending_landing_repair, so the next landing pass finishes the merge of its reviewed head. The declared-mutation log records 2 failed, 1 passed in 13.68s, EXIT=1, with the marked pointer left in place — the exact hold §50 reported. A review has no head to merge, so that mark is a hold nothing lifts.

reckon/crew/promotion.py now retires a moved pointer when the promotion's record is a review run: its ledger row and any committed review record are already written, so the pointer is removed rather than marked. The removal compares the pointer's attempt identity with the promotion's own, so a pointer a newer attempt has since written is left in place and unmarked. reckon/crew/pending_landing.py adds retire_stuck_review_pointers, called at the head of the landing pass finish_pending_landings. It retires a marked pointer whose run is a review, whose ledger row is present, whose promotion is not still pending and whose lease is not held, removing only the attempt the mark names, and clears that run's pending-landing record in the same step. The ledger row is never rewritten and nothing is re-promoted.

tests/test_promoted_review_never_held_for_landing_repair.py holds three cases on a temporary repository and crew home: a review promoted under a moved pointer reads its pointer retired with its ledger row present; a pointer a newer attempt wrote is left in place and unmarked; and a review pointer planted in the stuck state beside its row and a landing record is retired by one sweep, with the landing record cleared and the row's bytes unchanged.
