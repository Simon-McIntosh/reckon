A re-review's predicted outcome is recorded beside what the review found

What changed. reckon/crew/review_need.py gains a second question for the same judge: the probability that a further code review of work an earlier review already read raises a finding that blocks landing. It is asked under its own subject and its own criteria, because it is a probability about a review's outcome rather than a yes-or-no about whether a review is owed. reckon/crew/recovery_review_dispatch.py asks it for a run that already holds a stored review — a first review is not judged — and records the answer against the review run it has just dispatched, with the inputs it was given: the goal, the done-when, the two revisions, the paths that moved between them, the diff's size, and the earlier review's status, scores, findings and blocking count. When the review is stored, the reflex records its outcome beside the judgement.

Nothing is skipped. Every re-review is dispatched whatever the probability says. An unanswerable judge — the service down, an answer of the wrong shape, a diff past the readable limit — records the row as unavailable with its reason and leaves the dispatch untouched, so a stale predictor cannot hold a review back. The judgement is taken once the review run exists, because a review the lane held was never dispatched and a row for it would put a guess about nothing into the population.

The view. review_need.shadow_view(project) reports, over the recorded rows, how many blocking re-reviews and how many clean ones each threshold would have skipped, and how many judged rows with an outcome still stand between the record and the hundred the lead's decision needs. A row whose outcome has not arrived is counted as pending and never as clean, so an unmeasured row cannot flatter a threshold. It is not reachable as a crew view: the dispatcher's registry is paired with the crew tool's argument model, and declaring the view there needs reckon/_mcp_tools.py, outside this run's write paths. The counts are the deliverable and they are tested; wiring them onto a surface is one line in each of those two files.
