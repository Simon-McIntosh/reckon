The lane is fed while coordinators land: one four-hour window, measured

What changed: a census, not a behaviour. A counting script, scripts/lane_window_census.py, reads the three instruments the plan names — the crew run ledger, the per-run landing records and the admission verdict log — and reports four figures for each window it is given. Its output over the measurement window, the 7 to 11 November baseline and the specified negative control is committed beside this record as wftl-the-lane-is-fed-while-coordinators-land.census.json. The window is 2026-11-14 21:00 to 2026-11-15 01:00 UTC: the last four-hour stretch aligned to the hour that had closed before this node was dispatched at 01:18:29Z, carrying 103 dispatches. The census was read at 2026-11-15T02:54:17Z.

The instrument, and what it read

A working worker is a live worker process. Each run contributes one span, from its worker's own launch stamp to its exit stamp (worker_exit.launched_at and worker_exit.exited_at in the ledger). The mean is the total worker-seconds inside the window divided by the window's seconds; the peak is the highest count reached at any instant. Where a worker exit was never recorded the run falls back to its dispatch and completion stamps, which bound a wider interval. This definition is what makes the negative control read below twelve: the same script counting dispatch to completion read 17.2 against 6.83 on that afternoon, because a run's completion stamp lands well after its worker stopped.

A landing record's first step time is the promotion time. Each run directory holds a landing.json whose first step is the landing commit, stamped when it was made. The cohort is the implement runs whose completion stamp falls inside the window, so the two windows compare the same population. A landing record survives only while its run directory survives, so the baseline reports 14 of its 438 implement runs with a record: that median is computed over the records that survived, not over all 438.

Admission holds are read from the verdict log, and it is short. admission-verdicts.jsonl held passes only from 2026-11-14 19:22 to the census instant, so the baseline window and the negative control report null with a note rather than a zero: nothing there was measured. A hold counts for this gate only where the path its detail quotes lies under the crew home every node shares. The six pointers behind those five passes each named a review record under ~/.config/reckon/crew/runs/…/review-records/.

Identity files are counted at the window's end, not at read time. An identity file is written once, when its process first publishes it, so counting by modification time reports the claims directory as it stood at 01:00Z. The sweep that retires them exists as reckon crew gc --sweep-exec-identities; the hourly retention timer does not pass the flag, so nothing retires these files and the count only grows.

The ledger takes late writes for a window that has closed. A run that completed inside the window can be written to the ledger minutes after, so a repeat read moves the digits. An earlier read at 02:27Z over the same window reported a mean of 20.05, a median of 89.7 minutes over a cohort of 35 and the same three verdicts; the figures above come from the committed output read at 02:54Z, and the baseline reproduces to the digit on every read because no further writes land on it. Three adjacent windows (20:00–00:00, 22:00–02:00 and 17:00–21:00) read means of 16.45, 19.74 and 8.81 and medians of 92.0, 83.4 and 112.4 minutes, so no window in reach meets the twenty-minute bound or clears twelve only by the choice of hours.
