A plan review's standing is judged by its worker and its scope

_standing_plan_review in reckon/crew/recovery_review_dispatch.py answered every live plan review without a stored record as in flight. A plan review's record is written only by its promotion, so a reviewer that had delivered and was waiting to be promoted held the plan's compose gate. When the plan moved to a newer version, every compose request returned the older review's run id, and a section only the new version carried kept its dispatch refused with plan-review-missing.

The reader now checks two facts on a live review whose record is not stored. A review whose worker has ended stands for nothing, read from a terminal pointer phase or a terminal manifest status — never from the store, which by construction has no record yet. A review still working stands only while it reads the plan's current version, read from the plan-version of the sidecar its compose wrote, or while every unit whose digest moved past that sidecar is inside the scope it traces; a whole-plan review, which records no scope, reads every unit. A sidecar, plan file or scope that cannot be read answers that the review still stands, so an unaccountable review is never joined by a second one.
