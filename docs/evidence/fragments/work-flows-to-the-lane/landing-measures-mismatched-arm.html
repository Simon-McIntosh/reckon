§17 — A landing measures a mismatched arm instead of refusing on it

The suite-delta check judged a delivered run by the two arms its manifest recorded, and any arm it could not use — one missing, one recorded at a revision behind the run's head, or one naming a command other than the armed one — was refused as missing evidence. The refusal was about how the pair was written down, not about the code, and every instance cost the worker a resume with the review already clean.

The landing now takes the reading itself. landing_measure.armed_observations runs the armed command at the base revision and at the run's head and returns each arm in the observation shape promotion already reads, carrying measured_by: landing. A declared measurement partition submits each arm as its own job, so a mismatch costs a queue wait rather than a suite run on the landing host.

promotion_records._evaluate_suite_delta calls it only when the recorded pair cannot be used. A pair that matches is still used unmeasured. The measured pair is written to <run>/landing-measure/measured-arms.json and onto the live pointer as suite_measured_arms, and the delta is calculated on it: a measured arm that adds a failure still refuses, naming the id.

Negative control: made to refuse on the mismatched arm as before, the suite reads 4 failed, 2 passed, EXIT=1, the superseded-head case among them.
