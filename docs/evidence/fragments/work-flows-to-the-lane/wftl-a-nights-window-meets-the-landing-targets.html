One of the gate's four figures is met. What the instrument cannot read, stated

  • The mean is a floor, not an estimate, for a window measured while its workers run. A worker's span is built from its launch and its exit, which the run ledger carries once the run is written. A run dispatched before the window ends and still running now is absent from the ledger entirely, so it contributes nothing. The store held 3 unfinished rows out of 12,124 when this was read; counting them adds 27,626 worker-seconds, which moves the mean from 4.31 to 6.23. Neither figure reaches 12, and the peak of 19 with 79 dispatches bounds the window from above: no re-reading of this window meets the target.
  • §9's window cannot be re-read for two of its three figures. The claims directory no longer holds the 27,854 identity files §9 counted — the sweep this plan landed has removed them — so a re-run reports 0, which is the directory now, not the directory then; §9's own record carries the 27,854. The admission verdict log had rotated past that window before this node ran, so its passes read null/unmeasured rather than zero. The negative control therefore demonstrates the script reporting an unmet median, and cannot demonstrate the identity and admission arms at all: the record says that rather than reporting a control that silently passed.
  • The identity count is a window-end reading of names still present. It counts exec-*.identity files whose stamp precedes the window's end and which still exist now, so a file removed after the window reads as absent. For this window the sweep was live throughout and the count is 1 — an undercount of nothing, since the target is an upper bound.
