reckon/crew/dispatch_sessions.py now writes the stopped attempt's exit only after the run's whole process tree has drained. It uses the existing supervisor receipt composer and atomic writer, writes the numbered receipt and canonical exit, and names run-stop. A supervisor receipt already filed at that number remains immutable; the canonical copy additionally records the stop. A surviving worker files no exit, and the stop result still names its pid. The recorded write outcome distinguishes a failed modern receipt write from a legacy stop.

reckon/crew/recovery_liveness.py also recovers legacy stopped records whose placement has no scheduler job identifier: on the recorded launch host, a dead pid and the existing worker probes can settle the end. A living worker, a foreign host, a real scheduler job, or a failed modern receipt write cannot take that compatibility path. The resume and CLI modules need no replacement.

tests/test_a_stopped_run_resumes_with_advice.py contains seven cases using temporary crew homes and a stub process tree. The successful cases execute the real crew stop and crew resume --advice command objects, then read the resumed worker's own receipt to prove it received the advice and continued the prior session as attempt 2. The survivor ignores the actual SIGTERM while escalation is made ineffective; the CLI refusal names that still-living worker. Other cases cover the legacy resume, foreign-host and scheduler-job unknowns, a legacy stop with a surviving worker, and immutable receipt preservation.
