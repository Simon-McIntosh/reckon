A delivered run derives its own scope

The armed suite command, the importer population and the review neighbourhood were read from a run's declared write paths. A run dispatched with none had no prediction to read, so its scoped suite resolved to nothing and no code-review neighbourhood contained it. A delivered diff answers all three, so reckon/crew/delivery_scope.py now derives the effective scope from the changed paths. A run that declared write paths keeps its declared set unchanged; a run that declared none takes the paths its diff changed. The two therefore derive the same armed command, importer population and neighbourhood on the same diff.

The landing measurement records the derived scope beside the suite pair through Measurement.scope, and its own test-file resolution goes through the one derivation. The new test proves the equality between a no-write-paths run and a declared run with the same diff, delivers two no-write-paths runs that meet at a merge, and states the negative control: a derivation over an empty write-path list and no diff arms nothing.
