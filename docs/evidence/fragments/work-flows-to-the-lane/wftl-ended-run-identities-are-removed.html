The maintenance pass removes an ended run's identity file

The sweep that removes exec-<pid>.identity files existed behind gc --sweep-exec-identities, and the hourly retention service never passed that flag: it runs -m reckon.crew.gc --apply --limit N, which reached retention_sweep and no identity judgment at all. That is why §9's window closed at 27,854 files with a target below 100 while every reader that lists the crew home kept paying for them.

One change, in reckon/crew/gc.py: the pass now calls sweep_exec_identities(apply=apply) as its first phase, reports the counts as exec_identities (paths are not copied into the JSON, because a pass over tens of thousands of files would carry them all), writes each removal to the pass's one log, and declares the new identities phase in RETENTION_PHASES, which the bounded-pass timing test reads its expectation from. The judgment itself is unchanged: a file is removed only when the process wearing its pid is not the process that wrote it, so a live execution's file — including one being rewritten atomically as the pass runs — survives.
