A directory claim under a shared root shares as the files beneath it do

What changed. The claim comparison treated only an exact file match as shareable. A holder whose declared scope was the enclosing package directory — reckon/crew/picker beside the two files inside it — therefore fenced a queued request for reckon/crew/picker/lane_context.py, because the shared-file test demanded path == claim and the claim was the directory. Queue admission held that request from 13:54 UTC on 11 November for the whole of the holder's run.

Two helpers in reckon/crew/runs.py state the rule once. _SharedWritePaths.shares_region answers whether a directory shares as the files beneath it do, which is false exactly when the directory is, sits under, or contains a declared exclusive pattern, and membership of the shared set now includes an existing directory under a declared root on the same terms, so two claims on one directory share as two claims on its files do. _claim_paths_share compares two overlapping claims through it, so the narrower path must be shared and the broader one must be a shareable region. Queue admission (_claim_collision), the dispatch conflict report, the launch refusal (_raise_repository_scope_conflict) and the queue-edit comparison (_live_claim_conflict) all now call the same predicate, so admission, the conflict report, the launch and an edit to a queued request give one answer. Each of the four is asserted directly rather than only through a dispatch, which matters here: every dispatch-based test aborts at this workstation's backend launch. An exclusive pattern still fences, and so does a directory claim that is or contains one — for example a claim on docs/figures/ still holds a request for a file inside it.
