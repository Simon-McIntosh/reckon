A directory claim under a shared root shares as the files beneath it do

What changed. The claim comparison treated only an exact file match as shareable. A holder whose declared scope was the enclosing package directory — reckon/crew/picker beside the two files inside it — therefore fenced a queued request for reckon/crew/picker/lane_context.py, because the shared-file test demanded path == claim and the claim was the directory. Queue admission held that request from 13:54 UTC on 11 November for the whole of the holder's run.

Two new helpers in reckon/crew/runs.py state the rule once. _SharedWritePaths.shares_region answers whether a directory shares as the files beneath it do, which is false exactly when the directory is, sits under, or contains a declared exclusive pattern. _claim_paths_share compares two overlapping claims through it, so the narrower path must be a shared file and the broader one must be a shareable region. Queue admission (_claim_collision), the dispatch conflict report, and the launch refusal (_raise_repository_scope_conflict) all now call the same predicate, so the queue and the launch give one answer. An exclusive pattern still fences, and so does a directory claim that is or contains one — for example a claim on docs/figures/ still holds a request for a file inside it.
