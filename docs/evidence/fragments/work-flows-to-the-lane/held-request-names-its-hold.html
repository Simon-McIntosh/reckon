A held request names its hold

Four dispatches of a plan's sections answered awaiting-upstream with one reason — this section's waits have not landed — for sections that declared no waits at all. What held them was an open decision on the plan, so a coordinator reading the answer went looking for an upstream that did not exist. The readiness ref that carries such a hold names no upstream: it is the plan's hold on the section the request would build, and the blockers behind it are what a reader has to settle.

reckon/crew/queue_admission.py now derives the hold in one place, section_hold(), which resolves each ref a request is held on: a declared section, gate or request wait is reported as itself, and a readiness ref is resolved to the roadmap's own blocker rows for that section, naming each blocker as decision:<key> or gate:<id>. The wording about waits survives only where every unmet ref is a declared wait, which is the one case where it is true. The dispatch answer, the request's recorded hold and an admission pass's verdict row all read that one derivation, so the three cannot describe one hold two ways.

The cases the node pins

  • A section held by an open decision and declaring no wait: the dispatch answer carries hold: ["decision:route"] and a reason naming it, the pointer's recorded hold carries the same, and the reason no longer claims an upstream is missing.
  • A section held by a gate whose verdict is empty: the answer and the recorded hold carry gate:ship.
  • A section that does declare a wait: the answer still names that wait's ref and keeps the wording about waits, which is the case it describes, and the hold is recorded under its own verdict, held-on-waits, rather than as held-on-readiness.
  • An admission pass over a decision-held request records a held-on-readiness verdict row carrying the same names, where before the pass recorded nothing for a request that never reached the queue it launches from.
  • A dispatched readiness hold survives the pass that re-reads waits, so the first admission pass no longer releases a decision-held request to launch.
