An execution identity exists only while its claim does

What changed. reckon/crew/dispatch_claims.py published claims/exec-<pid>.identity from a module-level call, so every process that imported the module left a file behind whether or not it ever dispatched anything. The publish now happens only on the path that takes a node dispatch claim (_retain_exec_identity), and the file is removed with the last claim that process gives back (_retire_exec_identity). Claims still inside a refusal or a failed record write retire it too, so a refused dispatch also leaves nothing.

The sweep. reckon/crew/gc.py hosts sweep_exec_identities(apply=...), reachable as python -m reckon.crew.gc --sweep-exec-identities [--apply]. An identity file belongs to a live execution only while its pid is running and the process now wearing that pid began before the file was written; a freed pid, or a pid reused by a later process, leaves a file nothing else removes. Each removal is named on stderr and reported in the returned JSON.

Reclaim decision unchanged. A live holder is still refused and a holder whose identity file no longer matches its claim record is still reclaimed, because both read the same file this node only stopped writing at import.

Every arm is a log whose first line names its revision, tree and command and whose last line reads EXIT=<code>.
