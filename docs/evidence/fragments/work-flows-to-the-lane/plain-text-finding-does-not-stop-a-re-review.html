A review whose findings are plain text does not stop its run being reviewed again

A stored review may record its findings as bare strings such as "non-blocking: reckon/crew/promotion.py:291 ..." rather than as records carrying a severity field; that is the shape a review worker writing its JSON by hand stores, and it is what the record of r-20261114T081014193672 holds. Composing that run's re-review read each finding's severity through the record shape, so declared_severity called .get on a string and raised AttributeError: 'str' object has no attribute 'get'. The reflex's review pass read the failure as a failed composition and dropped the run on every sweep, so it could never be reviewed again without a hand-built brief.

declared_severity now reads a finding that is not a mapping through finding_claim, applying the same leading-word rule (blocking: / non-blocking:) every other finding uses, so a plain-text finding answers with the severity it states and one that states none reports "unstated severity" instead of raising. The same reader serves the promotion audit, the repair reflex and the landing guard, so every consumer of a stored finding gains the same behaviour. The disposition writer already read plain-text findings correctly; the node adds the test that proves it rather than reimplementing it.
