A deferred promotion resolves a relative gate program against the run’s checkout

What was wrong. A worker records the gate command it ran, and the repository’s recipe writes the program as a path relative to the tree: PYTHONPATH=. .venv/bin/python -m pytest -q tests/x.py. The check that refuses a command naming no program resolved such a path with Path(program).is_file(), which reads the promoting process’s working directory. When crew complete promoted in the caller’s shell that directory was the checkout and the check passed; a promotion deferred to the admission service runs from the crew home, where the same reviewed command was refused as naming no executable.

What changed. reckon/crew/promotion_gate.py now resolves a relative program against the run’s recorded checkout and then its repository, and never against the promoting process’s working directory. A command that resolves in neither is still refused, and the refusal names the directories it was resolved against. An absolute program is unchanged, and a bare name is still looked up on PATH.

Evidence. The defect reproduces before the change: with the process working directory moved to an unrelated temporary directory, the relative program present in the run’s checkout was refused with “names no executable”. After the change the same call passes, and the case whose checkout lacks the file is refused with a message naming the checkout path. The declared negative control — resolving the relative program against the promoting process’s working directory again makes the relative-program case refuse — was applied and fails the case, confirming the test measures the change it claims to.

Suite delta. The test files importing promotion_gate.py were run one arm at a time on the all_debug partition with -n 4. Both arms fail tests/test_a_queued_write_path_edit_reaches_the_landing_fence.py::test_a_queued_write_path_edit_is_the_launched_runs_fence, a pre-existing failure carried by the base revision; the head arm adds no failure id to that base.
