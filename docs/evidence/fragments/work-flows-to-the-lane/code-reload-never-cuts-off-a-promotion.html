A code reload never cuts off a promotion in flight

At assigned base 1f81316d74a9ac860e5ee01cc98e6ebfaee9248d the loop re-executed as soon as the code stamp moved. os.execve ends every thread the old image started, and both the promotion threads and the landing thread live there, so a promotion running at a reload was killed partway and its request retried from the start.

reckon/crew/promotion_requests.py gains a drain: begin_drain() refuses every later tick(), and wait_for_in_flight() joins the promotions this service started and returns any still running (the reload path passes no timeout, because cutting a promotion off is the outcome the drain exists to prevent). reckon/crew/admission/service.py calls both, then waits for the landing thread through the landing worker's existing settle(), and only then re-executes; all of it stays inside the service pass, so the supervisor's pass bound still covers the wait.

tests/test_code_reload_never_cuts_off_a_promotion.py drives the real loop with its own seams patched: a promotion executor and a landing action that block on an event, a pause that moves the stamp while that work runs, and a re-execution recorded rather than performed. It reads that no replacement happened while the promotion thread or the landing thread was alive, that no second promotion started although a second request was pending throughout, that the blocking work reached its own end, and that the replacement followed within the pass that noticed the move.
