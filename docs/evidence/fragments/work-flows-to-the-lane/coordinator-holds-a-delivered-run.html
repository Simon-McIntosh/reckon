A coordinator can hold a delivered run from landing

The automatic lander promoted a delivered run the moment its evidence read clean, and a promotion deletes the run's live pointer. A coordinator that had planned to steer that delivery found its resume printing nothing and raising nothing, because the run it named had already been promoted and merged; the repair had to be carried as a new plan section.

A hold now lives on the run record as a single field naming who deferred the landing, why, and when. The landing pass skips a held run rather than refusing it — a refusal is a judgement the pass makes and can retract, while a hold ends only when its coordinator releases it — and the review-acceptance sweep returns an unheld-run refusal naming the hold's reason. Releasing the hold records the reason the deferral ended beside the reason it began, so the run's own record explains the delay it carried.

The single-run resume takes the hold before it launches, so a landing pass running between the two finds the run held instead of free to promote. A resume of a run a promotion already owns is refused with a non-zero exit that names the promotion and the revision it asserted, rather than launching nothing in silence. The guard is installed on the resume command from the CLI's import hub, so the resume door's own composition is untouched.

A promotion claims its host lease before it does any work and removes the run's pointer only at the very end, so the pointer is present through almost the whole promotion window. The lease is therefore read before the pointer: a resume issued anywhere in that window is refused, naming the promotion, and takes no hold. A hold a resume took also names the head the resume was issued against, so it stops covering the run once a later attempt delivers a different head — the repaired delivery reaches the lander instead of waiting for a release nobody remembers to give.

Measurements: the node gate ran in place, one arm at a time; the importer arms ran on all_debug, one arm at a time, four workers. Logs carry the revision, tree, command and imported module, and end with a bare exit-status line.
