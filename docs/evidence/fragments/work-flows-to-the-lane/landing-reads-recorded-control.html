A landing reads the control the run recorded

The negative-control gate judged the field rather than the run. A manifest naming a log with only its exit line, a manifest naming a lint log, and a manifest naming nothing all refused a passing run while the red log of the declared mutation sat in the run's own directory. Each case cost a coordinator waiver or a hand-edited manifest line, and the defect was in the reader rather than the evidence.

Promotion now reads the manifest-named log first and keeps it whenever its run failed and it names at least one failing test id the head arm passes. When that log does not admit the control, the run's own directory is searched for a log of the declared mutation — files named for a control first, then in name order — and the log used is written on the verdict row as control_log_source and resolved_log. When the directory holds no such log, the landing runs the mutation itself: the node's own tests are run over a checkout of the run's base revision, where the repair is absent, submitted to the configured measurement partition as an armed arm is. A mutation that fails nothing is refused, and so is a run with no red log anywhere.

Manifest names no log; run directory holds the red logadmitted on the run's log
Manifest names a log of another mutation; a valid one sits beside itadmitted on the valid log
Manifest names a valid logadmitted on that log; no other is read
No red log anywhere; the mutation fails a test the head arm passesadmitted as landing-measure
No red log anywhere; the mutation fails nothingrefused, naming the measured run

The node's own test file reads 6 passed at the head (EXIT=0); with the suite inventory file the head arm reads 57 passed. The declared mutation — reading only the manifest-named control log — makes the exit-line-only case refuse, and with the repair absent the same test file reads 6 failed, EXIT=1, every id one the head arm passes. The suite arms read 51 passed at the base revision (EXIT=0) and 57 passed at the head (EXIT=0).
