Every budget row a dispatch reaches takes the dispatching session

A session-scoped lift governs which dispatch may spend past pace, so the dispatching session has to ride every row a dispatch composes. The pace row carries it beside the lift id and the multiple in force, the bookend refusal reads it back off the pace row it is already handed, and routing judges a resume or a lane change against the clocks the run was paced by.

Landing

budget.pace_row takes the dispatching session and passes it to budget.group_pace, and the row records it as pace.session beside pace.lift_id and the multiple in force. A row made under a session lift carries the lift id and the lifted multiple; a row made under no lift, or for another session, carries pace.lift_id None and the configured multiple. The multiple a lift raises is written into pace.policy.pace_multiple, so a replay reads the multiple the dispatch was actually judged at.

dispatch_admission._refuse_against_the_bookend_reserve reads the session off the pace row it is already handed, so a session lift releases that session's bookend reserve and holds another session's on the same reading. dispatch_sessions hands the run's session and its own pace-row clocks to routing._budget_verdict, so a resume or a lane change is judged against the clocks the run was paced by and a reading whose seven-day reset has moved ends a reset-anchored lift on that path. budget.preflight names another session's lift on the shared group under session_lift, with its session, without applying it: the lifting session's report carries the lift block as applied. And pace_replay reads session and lift_id as known fields rather than damage, keeping replay reading the multiple each row recorded.

All figures are derived from fixtures at assertion time — 21% of a 168 h window spent after 22.0 h against a 1.1x configured multiple, lifted to 1.8 — and every case asserts the workstation's own budget-lifts.json is untouched afterwards.

Evidence

The negative control — make budget.pace_row pass session None to group_pace — was applied on a scratch copy: the pace-row lift-id assertion then fails (assert None == 'codex-sub-...'), 2 failed, exit 1. At head the node's own test file passes and the gate passed 145 tests with exit 0; the base arm over the pre-existing gate files passed with exit 0, so the node adds no failure by id.
