A pace hold names the instant it releases

The hold is burn > multiple with burn = utilisation / elapsed_fraction, so with no further spend it releases once the elapsed fraction reaches utilisation / (multiple × banked-reset factor): the window start plus that share of the window. That instant is named releases_at and printed in the hold reason instead of the window reset.

For the fixture (a 168 h window read 22.0 h in at 21% used against the 1.1× multiple) the burn is 1.60×, so pace_hold holds an implement dispatch and returns releases_at at the window start plus 0.21 / 1.1 of the window — about ten hours away, not the reset six days out. Rebuilding the reading one minute either side of that instant flips the hold: held one minute before, admitted after, so the instant is pinned to the hold's own arithmetic, banked-reset scaling included. Asserted in tests/test_pace_hold_releases_at.py.
