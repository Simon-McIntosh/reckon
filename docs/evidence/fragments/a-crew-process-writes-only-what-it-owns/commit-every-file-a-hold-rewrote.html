A hold transition commits every run file it rewrote

What changed. reckon/ledger.py keeps the read-modify-write of the ledger in one internal function, _write_state, which returns the version it advanced to together with every file it changed: the aggregate envelope first, then each per-run file _keep_run_files_identical re-encoded. The public write keeps its signature and returns the integer version alone, so no public surface was added. Both committing callers now stage that whole set: write's own roster-retirement branch, and record_hold_checks, which commits under its hold-transition subject. Before this, each passed only the aggregate's path, so a run file whose row still carried the retired follow_on_paths key was re-encoded on disk and left modified in the tree. The inline comment in record_hold_checks that claimed the run rows stay byte-identical now states what the code does.

Reproduction, on the base tree before the repair. The three new cases seed one of the aggregate's own runs rows with its file still carrying the retired key — the only shape record_hold_checks reaches, since it hands the run-file writer the aggregate's rows alone — and then read git status --porcelain over the state directory. On the unfixed tree every one of them failed with exactly:

AssertionError: assert 'M docs/state...ns/r-one.json' == ''
+ M docs/state/reckon/runs/r-one.json

which is the defect this section names: the rewrite happened and the commit did not carry it.
