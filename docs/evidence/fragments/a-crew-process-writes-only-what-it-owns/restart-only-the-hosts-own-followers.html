A running host restarts only its own session's followers

The defect, reproduced first

A host that took a request for another session kept the child and restarted it on the backoff for as long as the host lived, duplicating the owning session’s follower.

The reproduction is the first case run at the dispatch base edc04fd259 before the change: the killed unmarked child for another session came back with a new pid — AssertionError: the foreign child was restarted: [585, 586], 1 failed in 7.41 s, EXIT=1. Log: gate-repro-before-fix.log.

The head arm

The new test file shows all five cases: an unmarked child for another session is dropped and the drop logged with project, session and pid; a marked child for an earlier session of the same owner restarts; a child for the owner’s current session restarts whether or not marked; a running unmarked foreign child is not signalled; and a pair held by a follower whose parent is another owner’s host is followed here, while one held by this host’s own follower or by a hand-armed one with no host parent is left alone.

5 passed in 57.78 s, EXIT=0 at aebf721d7e; the same file copied into a git archive tree of the dispatch base reads 2 failed, 3 passed, EXIT=1, failing exactly the first and fifth cases. Related files importing reckon.crew.session_host or covering plugins/crew-host carry the same eight ambient failure ids at base and at head: zero added.

Negative controls

Each declared mutation was applied to reckon/crew/session_host.py and the named case run:

  • restarting regardless of the mark → first case fails (negative-control-1-ignore-mark.log);
  • dropping on the mark alone, without the current-session arm → third case fails (negative-control-2-mark-only.log);
  • deferring to every live follower regardless of its parent → fifth case fails (negative-control-3-no-parent-check.log);
  • dropping every exited child that is not the current session’s → second case fails (negative-control-4-current-only.log);
  • signalling the running foreign child → fourth case fails (negative-control-5-signal-running.log).
