A running host restarts only its own session's followers

The defect, reproduced first

A host that took a request for another session kept the child and restarted it on the backoff for as long as the host lived, duplicating the owning session’s follower.

The reproduction is the first case run at the dispatch base edc04fd259 before the change: the killed unmarked child for another session came back with a new pid — AssertionError: the foreign child was restarted: [585, 586], 1 failed in 7.41 s, EXIT=1. Log: gate-repro-before-fix.log.

The head arm

Seven cases now: an unmarked child for another session is dropped and the drop logged with project, session and pid; a marked child for an earlier session of the same owner restarts; a child for the owner’s current session restarts whether or not marked; a running unmarked foreign child is not signalled; a pair held by a follower whose parent is another owner’s host is followed here, while one held by this host’s own follower or by a hand-armed one with no host parent is left alone; a marked restart does not defer to another owner’s duplicate; and a host that cannot name its session drops an unmarked child while restarting a marked one.

7 passed, EXIT=0 at 3e510296f5; the same file copied into a git archive tree of the dispatch base reads 4 failed, 3 passed, EXIT=1 (gate-base-arm.log). One run of the file at the same head failed a single case at its hand-armed setup — a follower that had not registered within the bound — and the case passed three times alone and the whole file passed on the next run; recorded in the manifest’s retry_failures rather than left out.

Negative controls

Each declared mutation was applied to reckon/crew/session_host.py at be2df92b79 and the named case run; every one fails its case:

  • restarting regardless of the mark → first case fails (negative-control-1-ignore-mark.log);
  • dropping on the mark alone, without the current-session arm → third case fails (negative-control-2-mark-only.log);
  • deferring to every live follower regardless of its parent → fifth case fails (negative-control-3-no-parent-check.log);
  • dropping every exited child that is not the current session’s → second case fails (negative-control-4-current-only.log);
  • signalling the running foreign child → fourth case fails (negative-control-5-signal-running.log).

The files that import the host

The rule a host that cannot name its session keeps — only marked children, never an unmarked one — turns red the host cases that resolved no session purely as setup and then expected that host’s own unmarked child to restart. That was the old permissive behaviour, not a case the rule protects, so each such request now carries the ownership mark the writing side’s guard sets, and the one census assertion that compares a child entry names the mark it now carries. The suite fixture clears CLAUDE_CODE_SESSION_ID beside CLAUDE_PID, so a suite run from a live Claude session no longer hands a test host the runner’s session.

Against the same twelve related files, with the head’s test files copied into a git archive tree of the dispatch base, both arms carry the same eight failures — the ambient dispatch, hand-off and queued-request ids that fail on the base with no host change at all: 8 failed, 65 passed at edc04fd259 and 8 failed, 65 passed at the head, so the head adds none.
