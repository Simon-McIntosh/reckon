A re-armed host follows its session's live runs at once

The defect, reproduced first

A re-armed plugin entry point waited on its FIFO for a first request before it exec’d reckon crew host, and a follow request only arrives with a dispatch. A session with live runs and no new dispatch therefore showed an empty pane until somebody wrote a request line by hand.

The reproduction is the base arm of the node’s own gate: the new test file copied into a git archive tree of the dispatch base e5179a465f, run with the armed command. Six of its eight cases fail there, each on the absent start-up scan or the entry point’s wait — 6 failed, 9 passed in 103.45 s, EXIT=1. The two that pass are the FIFO-removal cases the section states pass at the base by design. Log: gate-base.log.

What changed

  • plugins/crew-host/bin/crew-host: names the owner, creates and opens the FIFO, and execs reckon crew host with --owner-pid, --owner-start and --fd 3 — no --first-request. The wait loop and its interval variable are gone; removal of the FIFO is the host’s, on a signal and on its owner’s end alike.
  • reckon/crew/session_host.py: parse_request returns the request’s owner_checked mark, which is the only route from a request line into a child entry. adopt_live_work runs at the start of supervise, before the record is written, and follows a run for the owner’s current session and for every earlier session the predecessor’s census names with the mark, through the host’s existing live-work judgement. Its adoptions are marked. A terminal phase and a launch-failed pointer owe no follower, and a pointer naming another session outside the owned set is skipped. SessionHost.record() carries owner_checked on marked children and a waiting_for_dispatch field, true while the start-up scan found nothing and false once a child starts.
  • tests/test_session_host_plugin.py: the four tests that asserted the wait are rewritten. Two assert that the entry point execs at once and passes no first request; two assert that it hands the command its owner pair and the FIFO descriptor it created, still in place. The owner-exit case now asserts the entry point starts nothing for an owner that is already gone.
  • tests/test_a_rearmed_host_follows_live_runs.py: eight cases against the real reckon crew host, a temporary crew home and a stub follower command.

The six failing ids are test_a_live_run_of_its_owner_starts_a_follower, test_live_runs_in_two_projects_start_a_follower_each, test_terminal_and_foreign_pointers_start_no_follower, test_a_host_with_no_live_run_waits_for_dispatch, test_a_marked_request_reaches_the_census_as_a_marked_child and test_an_earlier_marked_session_is_followed_and_an_unmarked_one_is_not. Logs: gate-after.log, gate-base.log.

Negative controls — three, each applied alone to reckon/crew/session_host.py at head and restored afterwards, logged in one file under the run directory (negative-controls.log):

  • the mark dropped from what parse_request returns: the child-entry case fails (1 failed, EXIT=1);
  • unmarked previous children admitted: the earlier-session case starts a follower for the foreign pair and fails (1 failed, EXIT=1);
  • the start-up scan skipped: the first case starts no follower and fails (1 failed, EXIT=1).

Regression over the neighbouring host tests (tests/test_session_host.py, tests/test_a_settled_follower_rearms_while_its_session_owns_work.py, tests/test_no_test_reaches_the_live_session_host.py) at head: 24 passed in 73.60 s, EXIT=0. Log: neighbouring-tests.log.

Lint: ruff check and ruff format --check over the three staged Python paths. Delta against the base revision’s own copies is zero findings: one PLW1510 in tests/test_session_host_plugin.py is present at the base and unchanged here, formatting is clean, and the entry point parses. bash -n over the entry point reports no error. Log: lint.log.

Scope boundary: this node makes a re-armed host follow its own session’s live work and carries the ownership mark a restart decision reads. A running host that already holds a foreign child is the restart section’s to end.
