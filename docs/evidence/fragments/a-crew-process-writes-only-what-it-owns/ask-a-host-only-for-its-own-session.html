A host is asked to follow only its own session

The defect, reproduced first

A follow request line is written to the FIFO owned by the Claude process issuing it (_session_host_fifo), while the line itself names whatever session the caller hands it. A process reading as calling-session asking for another-sessions-run, with its own census holding no child, wrote:

request_lines_written: ['{"project": "proj", "session": "another-sessions-run"}']
ask_answered: True
census_children: []

So the request reached the calling process's host naming another session's pair, and the ask reported success because the pair read as attached somewhere. The real path is a recovery review dispatch: it passes the reviewed run's session to dispatch (reckon/crew/recovery_review_dispatch.py), which need not be the session issuing it, and _arrange_dispatch_follower then asks that host for the pair. Log: repro-foreign-follow-request.log.

What changed

  • reckon/crew/dispatch_watch.py: _request_host_follower writes nothing when the pair it is given is not _calling_session(), and every line it does write carries "owner_checked": true. Both writers of a request go through it, so the guard holds for the ask and for the follower's hand-off alike.
  • _ask_session_host_for_follower answers from _session_host_child_pid — this host's own census — instead of the session-wide attachment, so another host's follower no longer reads as delivery this host serves.
  • tests/test_a_host_follows_only_its_own_session.py: six cases over a temporary crew home, a stub host on the session-host FIFO and the caller's census.

Evidence

Gate — PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_a_host_follows_only_its_own_session.py: 6 passed in 29.09 s, EXIT=0 at head, and 6 failed in 34.08 s, EXIT=1 at the dispatch base e958551af in a git archive scratch tree with the new test copied in. The base arm fails every case, so each case measures the change rather than the harness.

Negative controls, each executed and logged, one declared mutation at a time, each failing only ids the head arm passes:

  • ask predicate always False: cases 2 and 3 fail (2 failed, 4 passed, EXIT=1);
  • owner_checked left off the request line: cases 2 and 5 fail (2 failed, 4 passed, EXIT=1);
  • ownership check dropped: cases 1 and 4 fail (2 failed, 4 passed, EXIT=1).

Regression over the test files importing reckon.crew.dispatch_watch (19 files, one arm at a time, -n 4): head 10 failed, 118 passed, EXIT=1. The same seven node ids re-run serially at the base and at head give base 4 failed, 6 passed and head 6 failed, 4 passed; the failures shared by both arms are subprocess timing tests (/tmp/39486-fleet reload-tree collision, crash-backoff windows) that read as environment contention, not as this change. One added failure is real and is outside this node's write scope: tests/test_a_resume_rearms_its_follower.py::test_a_resume_asks_its_session_host_and_the_host_rearms_the_pair asserts the request line equals exactly {"project", "session"}, and the line now also carries the required owner_checked mark. Its repair is an assertion update in that file.

Scope boundary: this node composes and guards the request line. A host that already holds a child it should not is the host-side restart decision's to end, which reads the owner_checked mark this node now writes.

Lint: ruff check and ruff format --check over the two staged paths add no findings.
