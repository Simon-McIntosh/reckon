A shadow's worktree session names no primary

What changed

shadow_worktree_session in reckon/crew/routing.py used to build the shadow's session token as shadow-<primary>-<candidate>, and the session is the worktree directory the composed prompt names on its Work only in … line. The shadow read its primary's run id out of its own prompt. The token is now shadow-<candidate>-<component>: the candidate backend and the run's recorded unique component, and never the primary. The signature is unchanged, so the caller in dispatch.py is untouched.

_shadow_worktree_records resolves every naming a ledger row could have used, because the row does not record which naming wrote it: the current shadow-<candidate>-<component>, and the pre-change forms shadow-<primary>-<candidate>-<component>, shadow-<primary>-<candidate> and shadow-<primary>. A committed record therefore maps to more than one candidate path, and gc and promotion still find every pre-change shadow worktree.

  • reckon/crew/routing.py — shadow_worktree_session and _shadow_worktree_records.
  • tests/test_a_shadow_worktree_hides_its_primary.py — five cases: the stub-launched shadow's worktree path and prompt name no primary; a dry resolution's session names no primary; and each legacy naming resolves to its original worktree path.
