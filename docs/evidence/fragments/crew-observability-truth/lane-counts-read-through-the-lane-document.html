Execution record · 2026-09-29

The lane counts are read through the lane document

The advisory carry a dispatch rides on resolved its headroom through reckon/crew/lane_document.py and its generating, waiting and rate from the document's raw keys two lines below. Two readers of one shape agree only until a key moves, and these two had already stopped agreeing: the dispatch accepted a second spelling of the generating count that the module's own field reader rejected, so one dispatch could answer the same question twice and give different figures. The counts and the rate are now read by the module, the dispatch holds none of the document's names, and the module's running field resolves through the same key list.

§1 — The second reader, and the drift it had already allowed

At the base revision _lane_reading_carry composed its fresh carry from five reads it owned in reckon/crew/dispatch.py: document.get("mean_context"), "binding_observed", "observed_at", "suggested_shelf_life_seconds", and then the counts and the rate through _lane_count(document, _GENERATING_KEYS), _lane_count(document, _WAITING_KEYS) and _lane_throughput_carry(document, ...) — with _GENERATING_KEYS = ("generating", "running"), _WAITING_KEYS = ("waiting",) and _THROUGHPUT_KEY = "throughput" declared beside them (reckon/crew/dispatch.py:2603 at base). The headroom directly above them already went through the module (_lane_document.read_lane_document(document).get("headroom")), so one function held both patterns.

The drift was not hypothetical. The module's _FIELD_KEYS resolved its running field from ("running",) alone, while the dispatch's own list accepted generating first. A document naming its generating population generating therefore arrived as a measured count in the payload and as unknown from read_lane_document(...)["running"]: the reviewer of the predecessor node recorded exactly that pair, and noted that the phase that routes these counts through the module must also add the alias to the module's list "leaves one owner of the document".

§2 — What moved, and what stayed identical

reckon/crew/lane_document.py gained the document's load and rate: read_lane_counts(document) resolves the two populations each on its own, read_lane_throughput(document, reading_stamp=..., reading_age_seconds=..., now=...) reads the rate with the vintage and the denominator that make a derived figure interpretable, and blank_throughput(detail=...) is the shape carried when no rate could be read. read_lane_document's own running field now resolves through the same _GENERATING_KEYS the counts do, so the alias is one list rather than two. reckon/crew/dispatch.py lost _lane_count, _lane_throughput_carry, _lane_age_seconds and the three key constants; _lane_reading_unknown takes its blank rate from blank_throughput, so the unknown shape has one definition too.

Carried keyResolved byWhen the document is silent
generating lane_document.read_lane_counts — the document's generating, else its running unknown, never 0
waiting lane_document.read_lane_counts — the document's waiting unknown, never 0
throughput lane_document.read_lane_throughput — the block's three figures, its own observed_at when readable and the reading's stamp otherwise a block with state: "unknown" and a detail naming why
headroom, binding_observed, mean_context, observed_at, age_seconds, state, detail unchanged — read_lane_document for the headroom, and the carry's own reads for the rest as before this change

The values carried are identical for every document the tests use, including the unknown-never-zero rule: a count the document omitted still arrives as unknown and a measured 0 still arrives as 0. One behaviour widened deliberately. The rate block's own stamp is now read by lane_document._parse_stamp, the repository's shared timestamp parser, where the dispatch used datetime.fromisoformat directly, so a naive stamp, an offset stamp and an epoch resolve there as they do everywhere else. No document the tests use carries a rate stamp outside ISO-8601, so no carried value moves.

The alias case passes at base, and the reason belongs with the record: at base the dispatch itself held ("generating", "running"), so a document naming the count generating was carried correctly by the old code. The case only becomes load-bearing once the module owns the key list, which is why the negative control is the arm that proves it measures the module's alias rather than the payload's own field name. The reader-agreement case dispatches every document this file publishes — both counts with a dated rate, one count with none, a rate with no stamp of its own, and the alias — and re-reads each from the bytes on disk through read_lane_counts, asserting the payload carries the reader's own answer.

§4 — Boundaries and open items

  • The document's other names still have two readers. _lane_reading_carry still reads observed_at, mean_context, binding_observed and suggested_shelf_life_seconds from the document directly. This node's scope was the counts and the rate, and those four were left alone deliberately: routing them through read_lane_document would change the shape and the detail strings that reckon/flight.py and the MCP views consume. Recorded as a follow-on, not a defect of this change.
  • Four pre-existing failures in the wider lane set. Running every tests/*lane*.py file plus the dispatch and timestamp suites (349 tests) gives 4 failed, 345 passed: three cases in tests/test_lane_advisory_on_dispatch.py and test_crew_lane_agnostic_placement.py::test_adding_a_backend_needs_no_placement_code. All four fail identically against a tree built from 297c5e79, so they are present at base and this change neither causes nor fixes them.
  • The tests touch no real lane state. The harness points RECKON_HOME at a temporary directory and every lane document a case reads is one the case wrote there; grep finds no reference to the real publication in the test file or its harness, and an mtime snapshot of the real ~/.config/reckon/crew/live and crew/runs across a run shows only a concurrent peer run's own files — no path under any node name this file dispatches ( gate/real_state_observation.log). The real lane publication is rewritten every 30 s by the lane itself, so its mtime is not an instrument for reads; the grep is.
  • Files. reckon/crew/lane_document.py (the readers), reckon/crew/dispatch.py (the carry), tests/test_lane_reading_carries_counts.py (the gate), this fragment and its figure. No other path was written.

§5 — Outcome

6aca6f68 carries the move and deecf388 the cases. The document's counts and its rate now have one reader, the dispatch's _lane_reading_carry composes the payload from what that reader returns and holds none of the document's names for them, and a document naming its generating count under either spelling resolves to the same count in the payload and in the module.
