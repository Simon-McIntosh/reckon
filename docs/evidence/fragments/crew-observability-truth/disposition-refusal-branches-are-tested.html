What each case measures, and one reading worth keeping

Mismatched head. The case stores a review keyed to the run’s base revision (carrying a sub-floor durability score), removes the head-keyed record, and premises the reading two ways before invoking the command: the same reader still returns the stored record, and returns None for the run’s head — so the mismatch is a reading the store really holds, not a broken lookup. The command then exits non-zero, names both revisions, does not speak the no-record refusal, writes no disposition, and the sub-floor finding is still undisposed.

The row left standing is asserted through the reader for the described revision, and that is a finding rather than a convenience. The obligations walk selects a review for each live pointer’s tree head, so a store keyed to another revision yields no live row at all for that run. The disposition command refuses in exactly that state. Reading only the live rows would therefore show nothing to protect; the case therefore measures the row the command was aimed at, through _undisposed_rows(run_id, described), before and after.

No record. A second live pointer is written for a run whose store holds no review, beside the fixture run that still has one. The case asserts the sibling’s live sub-floor row is standing, invokes the command against the recordless run, and requires: non-zero exit, the refusal naming the missing run id, the absence of the mismatched-head refusal’s text, the live row untouched, and the store still empty for that run.
