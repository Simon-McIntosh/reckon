One review record is one run's write claim

The review store's write exclusivity is now asserted by a test that declares one review record as the write path of a live review run and dispatches a second review of the same subject under a fresh node id: the second dispatch is refused by the existing scope conflict, naming the first run and the shared record path, and its discriminating negative — a review of a different subject, holding a different record path — is admitted. Negative control declared and executed: with out-of-repository paths excluded from the live-claim comparison, 1 failed, 1 passed — the refusal case fails (test_a_second_review_of_one_record_is_refused, DID NOT RAISE ScopeConflict) and the admission case still passes. ruff check and ruff format --check report no finding on the changed Python path.

The measure this pins

The section requires that two runs never hold one review record, and that the check which says so covers the store. The review store lives under the crew configuration home, outside every repository, and a collision there is worse than a collision on a repository path: the loser of a repository-path collision still leaves a commit or a dirty tree, while the second writer of a review record overwrites the first with no trace at all — and that record is the durable copy of the score. The audit report recorded the remaining gap as no test declaring one review record as two runs' write path and requiring the second dispatch to be refused.

The case

tests/test_review_record_is_one_runs_claim.py builds a temporary crew home and a repository that looks like a reckon mount, then resolves the record paths through the store's own review_path helper — the legacy path keyed by the reviewed run and the head-keyed path beside it, the pair a review dispatch grants. A live pointer for the first review run holds that pair; the second dispatch is a review of the same subject under a fresh node id, the shape a retry takes after a review dies seconds into its turn, where the fresh node id is the right call for manifest hygiene and is what puts two live pointers against one file.

Two assertions, and the second is what makes the first mean something: the same record path is refused as ScopeConflict, naming the first run, its node and the shared path; a different subject's record path is admitted and the second run's pointer records the paths its own subject owns. A check that refused every out-of-repository path wholesale would fail the second assertion, and one that compares only repository paths would fail the first.
