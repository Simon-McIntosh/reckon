A valid wait keeps its state, with an unrelated finding attached beside it

Defect, measured. audit_manifest in reckon/crew/reports.py refused status: waiting outright, reporting status 'waiting' is not complete, blocked or failed. A manifest declaring a well-formed external wait — a job-id wait with an squeue probe — was therefore judged to be in no state at all the moment any other check failed (for example the gate-log first-line check): the audit finding replaced the wait state a coordinator acts on, and with nothing reading waiting the automatic resume had no run to lift. The manifest audit and the fleet's own wait reader disagreed about the same declaration; the classifier and the worker stop hook read such a manifest as waiting.

Change. Commit 3fff1cbc4 reads a waiting manifest's declaration through recovery._manifest_wait — the one reader the classifier and the worker stop hook already share — so the three surfaces cannot disagree. An honoured declaration keeps its state, and the audit's other findings (a gate log naming no revision, an out-of-scope path) are reported beside it as attachments. A declaration the reader refuses is refused with the reader's own error, so a malformed wait block still reads unreadable, both at the audit and at the classifier.

Measure. tests/test_valid_wait_keeps_its_state.py builds a parked run in a temporary configuration home: a valid job-id wait beside a gate log whose first line the audit rules below. At the change, its valid-wait case reads waiting with the gate-log finding attached and no status-replacement finding; its malformed case (echo probe) still reads unreadable. At base 9fe5d8204 the valid-wait case fails — 1 failed, 1 passed on gate-base-supplement.log — and so does the same case inside the base arm gate-base.log (3 failed, 501 passed, its other failure pre-existing). The negative control restores the unconditional status finding and the valid-wait case fails again (EXIT=1, log negative-control.log). Logs and the run manifest live under ~/.config/reckon/crew/runs/r-20261002T225510427652-valid-wait-keeps-its-state/.

Remainder. The head gate arm was cut short once by a full /tmp (disk-full errors, not code); the focused head run passes 2 of 2 and the twelve-file head arm was rerun afterwards. See the run manifest's failure_attribution and tests for the exact figures.
