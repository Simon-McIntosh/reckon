Colliding fragment element ids carry their node ids

Landed. Each element id that repeated across an evidence plan's committed fragments is renamed to begin with its own fragment's node id, so the composed record carries distinct anchor targets again. The rename covers 83 ids across 36 fragments in nine plan fragment directories and changes only id attributes and the same-file href anchors that resolve to them; no prose and no non-colliding id changed. audit_fragment_ids reports 28 duplicate-element-id findings over those directories at base 07ad28145 and none at head 61803a858. No remaining href anywhere in the docs tree targets one of the 19 renamed bare ids. One composed-record collision survives outside this node's scope, pairing an archived record file with a fragment that is not in this node's write scope; it is reported as a follow-on rather than repaired here. This fragment carries no element ids, so it adds none to the composition it is checked by.
