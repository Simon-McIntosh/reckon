A request launched before its release is not drawn as withdrawn

The fleet fold in reckon/crew/recovery_watch.py read admitted_from only from runs that arrived in the current observation. Admission does not keep that order: the launched run's pointer is observed first without the field, gains it a moment later, and the request's own pointer is released last — so by the time a queued request vanishes the run that continues it is already known. The fold held the request one observation and worded it withdrawn, drawn as a drop beside the run that replaced it. The fold now reads admitted_from from every live run, so the request leaves silently while any run names it, whether that run arrived this observation or an earlier one. A request that vanishes with no run naming it is unchanged: held one observation and then worded.

Gate: the 42 test files importing reckon/crew/recovery_watch.py run at base and at head. Base 10 failed, 370 passed; head 3 failed, 377 passed. Every head failure is also a base failure — the three are test_follower_freshness.py and test_follower_reload_is_safe.py subprocess-ordering cases that fail without this change too — so no failure at head is absent at base. Negative control: with continued restricted to arriving runs again, the four-observation case words the request withdrawn on its fourth observation (test_a_launch_naming_its_request_from_an_earlier_observation_leaves_it_silent and test_a_launch_naming_its_request_is_reported_as_the_continuing_run both fail at base and pass at head).
