A snapshot duty whose run has gone is not shown

Landed. A duty naming a run is shown only while that run's live pointer exists and the duty's own condition still holds at the read. The settlement already dropped the pointer-born kinds — a ready, stale or refused-landing row whose run has released its pointer. The review rows were the exception, on the earlier reading that their evidence is the stored record rather than the pointer, and they are now settled the same way: the row goes when the run's pointer is absent, and when that pointer records a dispatched review for the head the row names. Both review kinds take this settlement — review-missing and review-queued, the second being the same duty inside a wait, where the lane refused one attempt as paused or a review run has not been launched. A review dispatched for another head, a dispatch entry that records no head at all, a refused or skipped attempt, and a pointer that cannot be read all leave the row, because none of them is evidence the review stopped being owed. A dispatch entry with no recorded head fails closed: it cannot be shown to have read this duty's revision, so it settles nothing. A duty naming no run, such as index-lags-head, is untouched.

Where it was wrong. A station computes a session's duties once per tick and holds them until the next. The reported answer was written at 21:36:48 and still current at 22:05, listing a review-missing row for a run whose land and release had completed a few minutes after the write; a second duty was listed for a review that was already running. The row carried no action that could clear it, so the monitor kept naming work that was finished.
