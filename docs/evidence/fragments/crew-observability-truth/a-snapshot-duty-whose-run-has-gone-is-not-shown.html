A snapshot duty whose run has gone is not shown

Landed. A duty naming a run is shown only while that run's live pointer exists and the duty's own condition still holds at the read. The settlement already dropped the pointer-born kinds — a ready, stale or refused-landing row whose run has released its pointer. The missing-review row was the exception, on the earlier reading that its evidence is the stored record rather than the pointer, and it is now settled the same way: the row goes when the run's pointer is absent, and when that pointer records a dispatched review for the head the row names. A review dispatched for another head, a refused or skipped attempt, and a pointer that cannot be read all leave the row, because none of them is evidence the review stopped being owed. A duty naming no run, such as index-lags-head, is untouched.

Where it was wrong. A station computes a session's duties once per tick and holds them until the next. The reported answer was written at 21:36:48 and still current at 22:05, listing a review-missing row for a run whose land and release had completed a few minutes after the write; a second duty was listed for a review that was already running. The row carried no action that could clear it, so the monitor kept naming work that was finished.

Both readers, one settlement. The crew view and the prompt hook each take a stored answer, and both pass it through the same read-time settlement, so neither can disagree with the other and neither waits for a station tick. The session's own published snapshot settles identically, which matters because a silent station leaves that snapshot to answer.
