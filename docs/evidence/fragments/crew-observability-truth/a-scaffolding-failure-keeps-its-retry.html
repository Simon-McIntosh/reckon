Scaffolding failures keep the retry available for the work

At base 3fa491432, the worker's stop rule in reckon/crew/prompts.py:663-664 counted two failures of the same command without asking whether either reached the code under test. reckon/crew/dispatch.py:7087 supplied the threshold. This fence was an instruction in the composed brief, not a code-level counter.

Commit 9dab41148814765ebbbc2ce5b5879a06d8c7ebc8 makes the brief require a retry_failures entry for each command failure and a failure_attribution entry of "scaffolding: cause" before excluding one. The exemption applies only to a failure confined to the worker's own probe, measurement script or helper when the code under test was never reached. A failure in that code, or one with missing or unclear attribution, still consumes a retry. The manifest reader in reckon/crew/reports.py applies the same rule when it derives retry_counted_failures; an absent failure record yields an unknown count rather than a clean zero.

In tests/test_scaffolding_failure_keeps_its_retry.py, two marked scaffolding failures count 0 and leave the two-failure fence open; two unmarked failures count 2 and close it; one missing attribution counts 1.
