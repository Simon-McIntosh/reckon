The ticker's tests hold at head under any terminal

The five files pass at head in both terminal arms: 215 passed under TERM=dumb NO_COLOR=1 and 215 passed under TERM=xterm-256color with NO_COLOR unset. At the base revision the dumb arm failed 30 ids and the colour arm 22, each arm naming its own failing ids in its log. Every one of the base failing ids was repaired on the test side; no source file changed. The 18 width, alias and node-name reds carried the same cause: the model-catalogue merge 7e334b9e2 made declared_model_aliases() return ('harness',) inside the suite's isolated config home, so the model cell took the 7-character alias instead of the 10-character no-alias fallback and every column after it moved. The two arms, and what each one measured

A test whose verdict depends on the caller's TERM, NO_COLOR or COLUMNS is a monitor of the terminal, not a test of the ticker, so the gate runs both arms and requires both. The base arm at aff594161 ran the five files before any repair: 30 failed / 185 passed under the dumb arm, 22 failed / 193 passed under the colour arm. The head arm runs the same command at the recorded commit, again in both arms, and both are green. The four logs live under the node's run directory beside this record; the base-arm logs are the negative controls.

The two arms separate the two environment causes cleanly. The 8 colour ids fail only where NO_COLOR=1 is set, and a control run of the dumb arm with NO_COLOR simply unset passed all eight, so NO_COLOR and not TERM is the driver. The 18 layout ids and the 3 follow-stream ids fail identically in both arms, so neither NO_COLOR nor TERM explains them.

What each failing id had wrong

File prefixes below are shorthand: recovery:: is tests/test_crew_recovery.py, ticker:: is tests/test_crew_ticker.py, layout:: is tests/test_crew_ticker_layout.py, node-names:: is tests/test_ticker_node_names_keep_their_ends.py, and recover:: is tests/test_crew_recover.py.

The 18 width, alias and node-name reds — test changed

These failed in both arms. The window is pinned by the plan's own measurement: they pass at a7ff1d4dc and fail at 7e8ba339c, and reckon/crew/ticker.py did not change between those revisions. What changed is the catalogue layer the ticker reads its alias list through. Before it, the ticker's own resolution returned nothing inside the suite — the suite redirects the config home, so no host layer declares an alias — and the model cell fell back to the fixed 10 wide. After it, the flight catalogue fills the backend's alias from the repository, so the isolated suite resolves ('harness',), a 7-wide cell. Every assertion here was written against the fallback and reads a column shifted by those three characters, which is why the symptom is a truncated alias (assert 'dsv4-flash' in '… dsv4-f…') or a node cell read three columns to the left. The ticker is behaving as documented: the model cell is sized from the declared aliases, and the row still fills its width. The tests now declare the geometry they measure — the layout fixture and the inline grids pass model_aliases=(), and the node-cell reader takes its offset from the grid that rendered the row (grid.model_width) rather than from the module constant. The pinned grids are the same shape the sibling ticker test files already used.

The 3 follow-stream reds — test changed

These failed in both arms. crew watch --follow writes why it stopped to stderr, and Click 8.4's Result.output interleaves stdout with stderr, so a test reading one JSON document per line saw the notice as a second line: the compact-line assertion counted two newlines where it expects one, and both JSON readers raised Extra data. The stdout contract itself is unchanged and not in question — the stop notice is intended and has its own tests — so the three assertions now read result.stdout, which is the stream carrying the rows.

The recovery-help red — test changed

recover::test_recovery_command_help_names_the_state_and_the_boundary asserted the phrase never launch, resume, or promote work, which reckon/cli.py no longer says: cb6a06013 replaced it with a scoped opt-in, launch reviews only with --dispatch-reviews and --project, and the default, By default it repairs the record and launches nothing. The behaviour the test guards — that recover is distinguishable from its adjacent recovery verbs and launches nothing unasked — is preserved, so the assertion was updated to the wording that states it. reckon/cli.py is held by another live run and was not touched.

What did not change, and why

No source file changed: reckon/crew/ticker.py sizes its cells from the aliases it is given and fills its width, which is the documented design, and reckon/flight.py's catalogue layer is what makes the alias visible to the suite in the first place — the tests were asserting a geometry the config no longer produces. The two model-catalogue tests in tests/test_crew_ticker_layout.py that read the catalogue through a temporary home are untouched and pass, which is the positive control that the catalogue read still works. Because reckon/flight.py did not change, its own gate was not required; the alias resolution was confirmed directly instead — under an isolated config home, declared_model_aliases('proj') returns ('harness',) and the fallback constant is 10.

One limit is recorded rather than hidden: the pins are geometry, not configuration. A future change that makes the suite resolve a different alias set will move these cells again, and the assertions that pin them will then need re-pinning — the alternative, asserting the row's shape against whatever the config happens to declare, is the monitor defect this node exists to remove.
