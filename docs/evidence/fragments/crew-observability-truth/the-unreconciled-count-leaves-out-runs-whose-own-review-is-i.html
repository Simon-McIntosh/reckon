The unreconciled count counts only runs a coordinator can act on now

Landed. reckon/crew/runs.py gains _in_flight_round_ids and _closure_rows, and both drain and drain_unreconciled_by_session build their rows through the latter. A run whose own review is working, recognised by the reflex's own _review_in_flight rule over the view's snapshot, and a run whose repair round is working, recognised by the minted repair-of- node id read back through round_node_source, no longer count as unreconciled. Rows stay in the payload and carry in_flight: true, so a reader still sees the run and why it is not counted.

One composition. The exclusion is decided in the closure row builder _drain_row itself, over the project's live pointers, so the drain, the published snapshot and a promotion's _unreconciled_live_runs all count through one function. Every reader that counts rows over a snapshot enters row_scope once, so the pointer snapshot and the excuse set are derived once for the whole reading rather than once per row, and the row's classification is handed that same snapshot so recognising an already-dispatched review no longer lists the directory per row — five hundred live pointers stay inside the drain's deadline. The promoted reading enters the same scope, so it reads what the drain reads. A review or repair round is excused only while it has not written a terminal manifest: once it delivers, completing it is the coordinator's action and its own pointer is counted, which is what a plan-review round holding a live pointer shows. A request the lane has only queued is not working yet and keeps the count a parked request always has.

The delivered-round read. Whether a round has delivered is decided by the manifest parser the rest of the crew reads manifests with, reports.parse_manifest — the route admission/readiness._manifest_status takes — so a JSON manifest body answers the same as the tolerant key: value text form instead of being read as undelivered. A round that has delivered neither excuses its subject nor excuses itself: both are counted, because completing the round and filing the subject's verdict are each a coordinator action. A round still working excuses both. The round cases are written for both manifest body forms, and for a review round and a repair round; _write_working_review and _write_working_repair now take a manifest status and write the manifest their pointer names.

One reading, one listing. The promoted reading counts pointer by pointer, so the per-row fallback read the pointer directory, and every round's manifest, once per pointer: over N pointers that is N listings for one fleet reading. The count now enters row_scope, as the drain does, and the case that pins it counts the directory listings over a six-pointer reading and requires at most one; the same case reads 11 with the answering files reverted.
