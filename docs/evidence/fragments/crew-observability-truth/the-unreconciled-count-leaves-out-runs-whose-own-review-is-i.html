The unreconciled count counts only runs a coordinator can act on now

Landed. reckon/crew/runs.py gains _in_flight_round_ids and _closure_rows, and both drain and drain_unreconciled_by_session build their rows through the latter. A run whose own review is working, recognised by the reflex's own _review_in_flight rule over the view's snapshot, and a run whose repair round is working, recognised by the minted repair-of- node id read back through round_node_source, no longer count as unreconciled. Rows stay in the payload and carry in_flight: true, so a reader still sees the run and why it is not counted.

One composition. The exclusion is decided in the closure row builder _drain_row itself, over the project's live pointers, so the drain, the published snapshot and a promotion's _unreconciled_live_runs all count through one function. A drain publishes its pointer snapshot and its excuse set through context variables for the rows it derives, so one reading reads the directory once rather than once per row — five hundred live pointers stay inside the drain's deadline. A review or repair round is excused only while it has not written a terminal manifest: once it delivers, completing it is the coordinator's action and its own pointer is counted, which is what a plan-review round holding a live pointer shows. A request the lane has only queued is not working yet and keeps the count a parked request always has.
