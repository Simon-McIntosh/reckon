A worktree holding only harness scratch reads integrated

The harness plants two untracked directories of its own — codex-home/ and harness/ — in every worktree it provisions. crew gc read them as the run's uncommitted work, so a finished, merged worktree classified dirty and withheld; a coordinator had to force-remove it or leave it holding. The tree state that both gc and the promotion boundary check read now leaves exactly those top-level untracked entries out.

The defect, reproduced at base

A temporary repository with one merged branch and a registered worktree holding only codex-home/ and harness/, passed to reckon.crew.routing.garbage_collect(repo=..., apply=False), answered at revision 27c67a3a: 

{"classification": "dirty", "integrated": false,
 "dirty": ["?? codex-home/", "?? harness/"], "counts": {"integrated": 0, "dirty": 1, "reclaimable": 0}}

_tree_state in reckon/crew/routing.py recorded every entry of git status --porcelain=v1 -z --untracked-files=all, and _inspect_workspace ran its own git status --porcelain, so both the boundary snapshot and the classification saw the scratch as content.

The change

One named constant, _HARNESS_SCRATCH_DIRS = frozenset({"codex-home", "harness"}), and one predicate, _harness_scratch_entry(code, path): an entry is harness scratch only when it is untracked (??) and its first path component matches the constant. Nested paths carrying the same name, tracked files a run modified, and every other untracked path still count as dirt.

_tree_state drops those entries from status_entries and computes status_digest over the kept stream, so a scratch-only change moves neither. _inspect_workspace now takes head and its dirty list from _tree_state, so gc's classification and the boundary snapshot read one exclusion rather than two. At head the same reproduction answers: 

{"classification": "integrated", "integrated": true,
 "dirty": [], "counts": {"integrated": 1, "dirty": 0, "reclaimable": 1}}

Gate

The gate is tests/test_crew_gc.py plus every other test file that calls garbage_collect or _tree_state: tests/test_gc_covers_run_directory_trees.py.
