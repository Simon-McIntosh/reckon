The Stop hook blocks once per unchanged duty list

Landed. _stop in reckon/hooks/coordinator_obligations.py emitted {"decision": "block"} on every stop event over an actionable duty, guarded only by stop_hook_active, so a duty list nobody had added to was refused again on each stop while its age and overdue figure grew. The stop mode now keeps its own record of the duty set it last blocked over (stop_digest_path, beside the prompt path's record) and returns silently when duty_digest over the blocking rows matches it. The two records are deliberately separate: the prompt path injects the very list a following stop reads, so a stop compared against the prompt record would be let through after every injection. The digest covers (kind, run_id) identities only, so a duty arriving or leaving is a different set and blocks again, and the empty-list branch clears the stop record so a duty that drains and returns is refused once more. The pre-existing stop_hook_active guard is unchanged.
