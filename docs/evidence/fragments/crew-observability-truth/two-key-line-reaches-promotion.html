two-key-line-reaches-promotion — a two-field manifest line is refused where the run is promoted

A manifest whose one line carries two keys is now stopped at the promotion boundary, not only at the reader. The reader refuses the line (9a2f95e7f) and promotion carries that refusal forward (b650bbec6); tests/test_two_key_line_reaches_promotion.py proves the chain end to end: a run delivered in the one-line form — commits: <sha>; changed_paths: candidate.txt on one line — is fed through crew.complete in a temporary config home and repository, and the promotion refuses with the line number, the whole line, and the pair of keys; the run's pointer is left in place so the run is not consumed by the refusal. The second case is the promotion-level control the section's done-when asks for: the same run with those fields on separate lines promotes.

Measure. Gate: the new file plus tests/test_manifest_parse_format.py and tests/test_review_gate_coverage.py — three files, run -n 8 --timeout=300 with a per-arm basetemp outside any repository, both arms in the foreground. Base arm (7fbe5fd89, the new test file copied into a git archive extraction): 128 passed, EXIT=0. Head arm (4130bce6): 128 passed, EXIT=0, zero added failure ids. The case passes at the base revision, which is the point: it pins behaviour that has already landed rather than repairing anything, and its arms differ only by the test file. Negative control: the parse-level refusal removed from reckon/crew/reports.py in a scratch copy of the base tree (the refusal's call sites fall 2 to 1) — 3 failed / 125 passed, EXIT=1. The promotion case fails as DID NOT RAISE CrewError: with the refusal gone the one-line manifest promotes, which is the disarm the section measured, and the two parse-level cases in tests/test_manifest_parse_format.py fail beside it.

Follow_ons. _require_commit_for_changed_manifest still swallows a parse refusal as a skip and returns without a verdict, so on an unreadable manifest the changed-paths-without-commit guard is silent and the refusal reaches the operator only through the status carrier it happens to run beside; making that guard speak on a manifest it cannot read is a change under reckon/crew/promotion.py, outside this node's write paths.
