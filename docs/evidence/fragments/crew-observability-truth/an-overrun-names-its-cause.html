The starting point and the reference

At base revision aff594161bf1098fe807fa73b41180db35d32130, the saturated-lane test failed because reckon/crew/recovery.py had no cause helper. The recorded instance in the live plan generated 41,434 tokens at 11.53 tokens/s while seven peers shared the lane. The lane document published no throughput block on 2026-10-03, so it cannot supply the comparison.

The reference comes from the project's committed crew run records: the median positive throughput.tokens_per_second among completions in the preceding seven days with the same backend and model. A live watcher caches each cohort for five minutes. The comparison is absent when the project, backend or model is missing, the ledger cannot be read, or fewer than ten qualifying rates exist. No other backend's rate is substituted. The live record names the source and carries the count beside the rate.

A read through the committed ledger at the code commit found 3,488 total run rows and 1,375 qualifying local-backend/model rates, with a median of 54.79 tokens/s. The 41,434-token specimen would take about 756 seconds at that reference rate, inside the test's 1,800-second allowance; at 11.53 tokens/s it takes about 3,593 seconds. The new test classifies that case lane-saturated, not over-large. A normal-rate run producing 100,000 tokens against the same allowance classifies over-large. Missing run rate and missing reference each classify unknown.

A rate below half the reference takes the lane-saturated branch. At a normal rate, a token allowance exceeded or a generated volume that would exceed the seconds allowance even at the reference rate takes over-large. Other combinations stay unknown. The label describes low per-run throughput; it does not prove engine preemption. An observed prefix-cache failure also depressed rate. The underlying rates remain visible so a reader can check that interpretation.

The soft limit and the separate ceiling

The default budget classifies and reports; it does not signal a worker. The existing _apply_budget_watchdog has a separate opt-in ceiling: only an operator setting fences.enforce_budget_watchdog can enable its signal after the configured grace multiple. The shipped value in reckon/schema/flight-defaults.yaml is false. The call-graph test scans functions under reckon/ reachable from budget and overrun computation. It permits exactly the watchdog's signal, checks that the early-return guard precedes it, reads the shipped default, and exercises the default path to assert that it signals nothing. A scratch copy that adds terminate() inside budget computation makes that test fail.

Delivering an overrun message to a running worker waits on a-live-worker-can-be-reached section 7. No delivery channel is added here, and this fragment claims only the cause and non-signalling default.
