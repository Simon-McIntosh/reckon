One composer for the domain block, and no empty heading

The domain block a worker reads had two spellings: dispatch_admission._brief_domain_block matched the rules through _node_domain_rules and rendered them, while prompts.domain_rules_block matched and rendered the same block for the composed prompt. The admission layer's composer is deleted and its call sites in reckon/crew/dispatch.py and reckon/crew/dispatch_plan.py now import prompts.domain_rules_block; _brief_text in dispatch_admission.py calls it too, so the composed prompt, the run's stored brief and the digest a promotion cites are composed by one owner. The per-check line got the same treatment: prompts.render_review_check is the one spelling of a declared review check's line, and render_domain_rules renders every check through it, so a brief and a review cannot spell one declared check two ways.

The empty heading is fixed at the renderer, not the matcher: DomainRules.__bool__ is true when only model_paths matched, so render_domain_rules now emits nothing unless an invariant or a review check is there to carry, and _domain_rules_carry records no domain_rules block when nothing rendered. A fixture project declaring only model_paths: ["models/**"] with a node writing models/tape.py composes an empty block and a brief byte-identical to its source; the same project with one declared invariant plus one review check composes the frozen four-line block verbatim.
