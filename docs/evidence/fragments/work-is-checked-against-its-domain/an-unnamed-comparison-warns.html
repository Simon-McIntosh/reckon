A model-building node that names no comparison is warned, not refused

Both admission checks a node's own declaration answers are composed in reckon/crew/dispatch_admission.py, but they reached the dispatch through one channel: every finding they produced was appended to the node's verdict, so the unnamed-comparison lint refused the dispatch it existed to admit. Each finding now carries an outcome. node_inputs_finding marks its finding refusal, because a node that names an input the repository does not hold would read a tree lacking what it named; node_measurement_finding marks its finding warning, because the fit the node builds is still worth running with the gap on the record.

One new function, admission_refusals_and_warnings, holds the split into the refusals the verdict is composed from and the warning lines the caller reads. plan_dispatch in reckon/crew/dispatch_plan.py calls it once where the sandbox and admission findings are gathered, extends DispatchPlan.warnings with the warning lines and refuses only on the remainder — so the warning reaches payload["warnings"] naming --compares-with as the field that clears it, and payload["ok"] is true for the model node the base revision refused. The warning is composed from the finding's own detail rather than held in admission state, so a node rebuilt from the node record the dispatch stores reports the same warning.
