A repository declares its domain rules once, in the flight config.

What changed. The per-project flight layer gained a typed domain block carrying the repository's own rules: invariants (each an id, the rule in one sentence, applies_to path globs and an optional check command), review_checks (each an id, the question and applies_to) and model_paths. The block is modelled in reckon/schema/flight.yaml and reaches the tree through the existing generator, so reckon/_flight_schema.py and docs/_shared/flight.schema.json are regenerated and the standing drift test in tests/test_flight.py covers them. reckon/crew/domain_rules.py exposes one public function, rules_for(project, node), which resolves the project's flight config and returns the invariants, review checks and matched model-path globs whose applies_to reaches the node's declared write paths. A node that writes outside every declared glob carries nothing; a project that declares no block returns an empty DomainRules and keeps today's behaviour. The reader parses the block through the generated model (DomainConfig and its entry types), so a field the schema renames fails loudly at the reader rather than silently matching nothing.
