A brief carries its domain rules, and promotion runs their checks

The rules a repository declares once are rendered into the composed prompt under one fixed heading, and each invariant carrying a check command is replayed at promotion through the existing integration replay — the same sh -c execution under one bound, with the output kept in the run directory, that the project's suite command goes through. The heading is composed once and handed to three places, so one document is what the worker reads, what the run's stored copy holds, and what the digest a promotion cites covers: the prompt (prompts.compose_prompt), the stored brief and its digest (dispatch_admission._brief_text, _store_brief, _brief_digest) and the pointer's brief record (_brief_record, which names the matched invariant and review-check ids beside the digest). Surfaces are prompts.domain_rules_block and prompts.render_domain_rules, promotion_gate.replay_domain_invariant_checks, promotion_gate.domain_check_refusal_text and the promotion_checks._require_domain_invariant_checks guard wired into the promotion's guard list, waivable from the command line through --waive-domain-check REASON.
