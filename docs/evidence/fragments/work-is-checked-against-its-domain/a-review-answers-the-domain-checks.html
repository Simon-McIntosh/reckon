A review answers the domain checks its node touches

What changed. A repository's declared review_checks join the review checklist rather than a seventh scored dimension. The composed run-review brief in reckon/crew/recovery_review_subject.py now carries a Declared review checks this node touches block naming every check the reviewed node's write paths match, taken from the one matcher that answers which rules a node touches (rules_for in reckon/crew/domain_rules.py), with the verdict form stated beside the questions — a reviewer in another project's worktree holds no flight config of its own, so the questions and the grammar reach it only through the brief.

On the parser side, parse_review takes the declared check ids as its required set. Each answered check joins item_verdicts under its own id; a check that carried no answered verdict is named in absent_items and leaves the record incomplete; and a check answered fail is stored as a finding carrying blocking. Nothing else moved: REVIEW_DIMENSIONS, the acceptance floor in reckon/crew/recovery_review_acceptance.py and reckon/crew/review_lifecycle.py are untouched, so the existing severity derivation reports such a run open with no new lifecycle code. _VERDICT_RE accepts - and . in an item name, because a declared check is named by the project that declared it rather than by a constant in the parser; the captured item is still matched against a known set, so a line naming nothing declared parses exactly as it did before.
