The domain waiver reaches the guard from the duty surface too

A duty prints the promotion command a coordinator may call, and action_form in reckon/crew/obligations.py renders that command in the crew MCP tool's own action form. The promotion's domain-check waiver was carried by the tool — waive_domain_check is a parameter of the crew tool's complete and land actions and reaches the promotion guard's waiver — but the option --waive-domain-check had no entry in _ACTION_OPTION_PARAM. An option that map does not carry makes the whole command unrenderable rather than lossily rendered, so a duty whose printed command stated that waiver offered a reader no crew-tool call at all. The option now maps onto waive_domain_check, the parameter the verb already takes, beside --waive-live-run and the other waivers.

Measure: the fixture repository declares one invariant whose check fails over the node's own write paths, so the guard is live. Through the crew tool the promotion lands with the reason stated and is refused naming convergence without one, and the guard is observed receiving exactly the stated reason; the CLI arm records the same reason for the same call. The duty command reckon crew complete --run run-waiver --gate passed --waive-domain-check "…" renders as crew(action="complete", run_id="run-waiver", gate="passed", waive_domain_check="…").
