A review of a gated section is queued without its own section's verdict

What changed. _needs_own_section_verdict in reckon/crew/queue_admission.py now answers false for a node whose role is review — the REVIEW_ROLE constant from reckon/crew/recovery_vocabulary.py, no new literal — and _validated_batch_waits now reads a node's own section verdict only when read_own_verdict and that owner both hold. The batch admission path in reckon/crew/dispatch.py passes no read_own_verdict, so it asks the same owner and needed no edit. A gate or an open decision holds new work on a section; a review judges code a run has already written, so it never gains a readiness: ref. Every other wait a review carries is untouched: its explicit --after runs, its section's authored waits from section_wait_refs, and its plan's depends_on.

The preflight keeps its economy. A dispatch preflight read the section verdict eagerly only when the plan authored a gate or a decision that could apply; that answer now sits inside dispatch_waits, which reads the plan's own holds before asking the section's verdict. So a dispatch whose plan authors no hold still scans no roadmap, while the batch admission path, which reads the roadmap for the section, is untouched for every non-review role. Without that split the preflight began scanning the roadmap for a node with no authored hold, and test_section_preflight_does_not_scan_scope_claims refused it.

Not done here. The obligation rows that read “waiting for a lane slot” while a pass says held-by-gate belong to work-is-never-stuck-behind-the-admission-loop, and this change does not touch them. Roles other than the review keep the readiness wait exactly as they had it, and no new helper or parameter was added.
