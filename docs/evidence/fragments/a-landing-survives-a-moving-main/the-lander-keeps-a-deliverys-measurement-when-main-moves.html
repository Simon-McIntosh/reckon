A landing keeps a delivery's measurement

What changed

reckon/crew/queue_landing.py now decides whether a moved primary can change what a delivery was measured against. The measured inputs are the committed reckon/ tree — read through the same content identity the fleet's reload readers use — the catalogue at docs/state/reckon/model-catalogue.yaml, tests/, pyproject.toml and uv.lock. A move that leaves all five unchanged reuses the stored measurement; any other move, or an identity git cannot answer.

Verification follows the same decision. When the primary moved under a measurement that still stands, the pass builds the merge onto the primary as it now stands, refuses a head that no longer merges cleanly, and judges the change markers against that merge rather than against the merge the measurement recorded. The pass result also carries deferred_reasons, a sibling of the unchanged deferred id list, so each deferred run names its reason.
