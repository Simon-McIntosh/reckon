A landed reading follows the primary branch

A promoted run read landed from its ledger row's presence, and a pending-landing record only softened that reading when one existed. A promotion that ended before writing its record — the shape the section's own second cited run hit — left a ledger row and a head no branch carried, and the row still said the work was settled.

_promoted_awaiting_merge in reckon/crew/recovery_classification.py now asks the branch itself: the delivered head comes from the run's ledger row (promoted_revision, else the last promoted commit), the primary revision from the main checkout the run's worktree/repo resolves to, and git merge-base --is-ancestor decides. A head on the primary branch reads promoted, which the pane draws as landed, whether or not a record was left behind; a head off it reads complete — delivered, not landed — with a detail naming the record's own status when one exists and the branch otherwise. An ancestry that cannot be asked leaves the record's evidence standing rather than inventing a merge to wait for.

The ancestry answer is cached by the pair it was taken against, the checkout and the delivered head and the primary revision, and the primary revision itself is reused across the rows of one pass, so a sweep over a project's live runs costs one rev-parse per checkout and one ancestry walk per distinct head rather than one git process per row per tick. A merge moves the primary revision, which changes the key, so a finished landing is read on the next pass.

The walk is plan_review._commit_is_ancestor, the probe the review store already answers reachability with, so the repository holds one answer to that question rather than a copy per caller. The run's ledger row is found through ledger._run_ledger_root, the same ownership resolution promotion writes it under, so a run implementing one project's plan in another repository's checkout is still found. The reading fails closed: an unreadable branch, an unreadable head or a walk that will not answer reads as an unverified landing, never as a landed one, because a coordinator who believes a landed row stops attending to the run.

The test builds three promoted runs on a temporary crew home and repository: one with no pending record and a head off the branch, one with a plain unfinished record, and one whose head is merged. A fourth holds a record left behind after its merge and asserts the branch, not the record, decides.
