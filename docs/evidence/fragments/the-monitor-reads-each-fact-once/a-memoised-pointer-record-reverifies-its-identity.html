A memoised pointer record reverifies its identity

What landed. A listing now hands the parse memo the stat identity its text was read at, instead of letting a second stat inside the store decide which file the record belongs to. reckon.file_memo.memoized takes an optional identity: the value is answered only from what was stored under that identity, and is stored only while the file still reports it — in the read-only region path as well as outside it. runs._pointer_text returns the identity it stat'ed before reading the text, taken through file_memo.signature_from_stat, and runs._pointer_record passes it to the store.

Why it was wrong. Pointer writers replace a file by rename. The listing stat'ed the pointer's text, read it, and then the store took its own stat: a rename landing between the two paired the old text's record with the replacing file's identity, and the region path stored that pairing without the re-verification after compute the unregioned path performs. Every later listing that found the new file unchanged answered with the old record until the pointer moved again.
