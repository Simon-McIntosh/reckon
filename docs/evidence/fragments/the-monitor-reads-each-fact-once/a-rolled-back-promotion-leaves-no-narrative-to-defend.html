A rolled-back promotion leaves no narrative to defend

The defect. A promotion writes the plan's landing comment before it appends the run's promotion row, and _record_landing_comment (reckon/crew/promotion_scope.py near line 1517, base baa6e8307) deferred to an existing comment only when a ledger row already existed. With the row rolled back by a failed store write, the guard fell through to CrewError: landing comment … already contains a different narrative, so the plan defended wording that no promotion had recorded, for a run whose only trace was the comment an earlier attempt committed.

What landed. When the comment exists with a different body and _ledger_holds_row(project, root, run_id, unreadable=False) answers False, the promotion replaces that comment's body, author and time in place under the same run-derived id (c-run-<run_id>) and proceeds with its versioned plan write, so the row that follows records a promotion whose narrative the plan carries. The row-present branch is untouched: it reports the differing narrative beside the receipt as reason: "different_narrative" with kept_narrative and requested_narrative. The receipt for a superseded comment carries superseded_narrative — the plain text it replaced — so the earlier attempt's wording is reported rather than silently dropped.

Two cases on a temporary crew home

tests/test_a_rolled_back_promotion_leaves_no_narrative_to_defend.py builds a committed plan repository and a crew home under a temporary directory. Case (a) writes the landing comment through promotion._record_landing_comment and confirms ledger.runs(…) is empty — the state a rolled-back promotion leaves — then promotes the run with a corrected narrative. The result is one ledger row, the live pointer retired, and exactly one comment on the plan, reading the corrected narrative; the superseded text appears nowhere in it and is returned as superseded_narrative on the receipt. Case (b) promotes the same run twice with the row present: the row count stays at one, the comment keeps the first narrative, and the second call reports kept_narrative and requested_narrative beside the receipt, as the base revision does.

The plan-facing sibling case in tests/test_a_second_complete_finishes_cleanup.py covered the same state and asserted the removed refusal; it now asserts the landed behaviour as test_a_differing_narrative_without_a_row_supersedes_the_comment, because the refusal was the defect, not the contract.
