An unchanged sweep reads no plan and walks no tree

The defect. Each obligations sweep of the watch producer re-parsed every candidate plan to read its section duties, and walked the project's state tree recursively statting every file under it. On a sweep where no plan had changed since the last one, both costs were paid to learn that nothing had moved — eight thousand files against four thousand directories on this project's state tree.

What landed. The change check now records one stat per directory under the trees it watches. Every writer that changes these trees replaces a file rather than editing it in place — plans and review records are written to a temporary and renamed over the original — so a change still moves the containing directory's own stat, and a directory's stat is one call however many files it holds. That reading is handed to a plan-state cache, keyed on the directory identity and the plan file's own signature. While the directory holding a plan is unchanged the cache returns its stored parse with no stat and no parse; when the directory has moved it re-parses exactly the plan whose file changed.

A stat identity reused from the previous sweep can be up to ten seconds old, so it is handed to the plan cache as unknown rather than as proof that no plan moved; the cache then falls back to each plan's own file signature. That is correct and pays the per-file cost only on the sweep that reused a checked identity.

The test. tests/test_an_unchanged_sweep_reads_no_plan_and_walks_no_tree.py drives full sweeps: the in-process sweep memory is cleared and the clock is advanced past both the stat-identity interval and the floor tick, so neither shortcut answers the second sweep on the first one's behalf. The fixture is a project of four plans, each with a live run whose section duty makes the plan a candidate, and one thousand state files across two hundred directories. The cases are:

  • the second of two full sweeps parses no plan, stats no file of the state population, and stats no directory beyond the watched tree but the ledger's own rows directory;
  • a sweep after one plan's file is replaced parses that plan alone;
  • a sweep after a state file changes publishes the change;
  • a sweep after a review record is added publishes the change;
  • in every case the published obligations equal those of a from-scratch sweep over the same state, compared row for row.
