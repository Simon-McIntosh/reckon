A finished pass reports what it recomputed

What changed. The station published what it had observed and never what it had paid to observe it, so a quiet pass and a pass that re-parsed the whole fleet read identically. Every tick and every sweep pass now runs inside one counting scope and publishes the answers it served under memo_counts on its own record: last_tick for the last finished tick, last_sweep for the last finished sweep pass, each keyed by memo kind with cached, extended, recomputed and the bytes_read the recomputed and extended answers read.

The counts cover every file-backed memo kind the passes read: the plan and pointer parses and the mount, flight-layer and resource identifications the station and the sweep pass derive, and stream_observation, the backend stream summary, which grows by the bytes a stream gained rather than by a whole re-read. A path that cannot be stat'ed reads no bytes, so it is counted for nothing, and a derivation another thread runs while the scope is open is not attributed to it, because a tick sharing an interpreter with a sweep pass must report only its own work.

The tick's scope opens outside its operational read, which lists the live pointers and decodes one record per run. That listing was the whole reason the first measured tick read 7,661 bytes of pointer text; a scope opened inside it would have reported a cold tick as having read nothing.

A pass's report hook gained the counts, so every caller states them. SweepBeat hands its report hook the pass's memo counts beside the report. One existing cohort test stubbed that hook with three parameters and appended nothing, so its own assertions read an empty list and two of its tests failed at this head while reporting no error. The stub names the fourth parameter now; the reverted run reproduces the two failures with the same TypeError.

The negative control fails for the right reason. Against a tree extracted at the base revision with the new test copied in, the reading exists and the station ticks, but no record carries a memo_counts key, so the first assertion that a finished tick reported its counts is the one that fails.

Not done here. The reference-rate buckets stay for a later section, and the reading keeps everything else it carried: only the two memo_counts blocks are new.
