A refused wait row names its missing key and its resume command

What landed. The recovery classifier's refused-wait arm now derives, from the parsed declaration, the required keys a wait is missing, and its suggested action carries both that list and the command that moves the run: reckon crew resume --run <id> --advice. A manifest that declares wait_condition, wait_terminal, wait_expected and resume_brief but names no wait_probe or wait_file still classifies unreadable; the duty it raises now says the declaration lacks wait_probe or wait_file and offers the resume command, where before it said only "repair the waiting declaration".

Why it matters. A run parked about 12 h on a wait declaration the reader refused reached its coordinator as an unreadable duty with no remedy, so the session was told something was halted and had to reconstruct both the fault and the fix. The absent probe is the one field a reader can name, and the resume is the one command that carries the run past a declaration it cannot satisfy.

Gate. tests/test_a_wait_no_sweep_can_lift_reaches_its_coordinator.py holds a live pointer in phase working whose recorded pid is a reaped process this host has seen, over a manifest that reads status: waiting with wait_condition, wait_terminal, wait_expected: 1h and resume_brief but no probe. Its first case asserts the owning session's obligation view holds exactly one row for the run, that the row's text names wait_probe, and that its suggested command is reckon crew resume --run <id> --advice. Its second case, with a sacct-shaped probe whose running state is not yet terminal, asserts the run raises no such row. The gate ran 2 passed.

Both ran on the all_debug partition in a job submitted with env -u SLURM_JOB_ID -u SLURM_JOBID sbatch, never on the fleet node; each log opens with its revision, tree, literal command, the absolute module.__file__ it imported and its resolved cwd, and ends in its own EXIT=.
