An owed-review pass reads only what changed

The station's owed-plan-review pass ran three whole-store reads on every tick: the resource walk that lists a project's plans, the listing that decodes every stored plan review, and, per weighed plan, a fresh read of the plan file. None of them asked whether anything had moved since the tick before.

Measure

tests/test_an_owed_review_pass_reads_what_changed.py builds a temporary project of forty plans and four hundred stored plan reviews, then drives four real passes (dry_run=False) with dispatch replaced by a recorder. It counts genuine reads — the uncached decoders and the resource walk, with file_memo cleared before every pass — so a count is a read and not a cache hit. The cold figure is above the store's four hundred because the one weighed plan's own ten records are read again for the coverage and burst checks, which is the plan's own work rather than the store's. The unchanged pass reads nothing. A pass after one review record is rewritten reads that record and no other. A pass after one plan file is edited reads that plan and no stored review.

A parity arm replays the same four passes with the store's change detection flushed before each pass: every pass composes byte-identical reports, same composed reviews and same skip reasons.

What changed

  • The plan listing is remembered against the tree's directory identity. A pass whose tree has gained or lost no document answers from the listing it already holds instead of walking the resources; a plan written in place does not move a directory's identity, so an edit costs no walk.
  • The stored-review listing carries run ids, not record bodies. Each record's (mtime_ns, size) is kept beside its identity and review run id, so a pass knows which runs the store holds without reading any record; a new or rewritten record is read once and its summary kept.
  • Only the records a pass asks about are decoded. The would-not-change notes now resolve the reviews this reflex dispatched — read from the summaries' run ids — instead of walking every stored record to find them, and the burst refusal reads the weighed plan's own records rather than the project's whole store.
  • A plan's status is kept beside its edit. The pass persists the edit each plan carried when it last looked at the tree, so a plan whose file has not moved is weighed from the recorded facts and never opened, and the plan that has moved is weighed first — the one thing the tick knows changed.

The pass still weighs one plan per tick and still rotates through the plans that have not moved, so a plan whose reason never settles cannot starve the ones behind it.

Negative control

At the base revision the unchanged second pass decodes all four hundred stored reviews and rescans the resource directories, because the pass listed the store and walked the tree before looking at any plan. The same test run against the base revision fails on that pass's zero.
