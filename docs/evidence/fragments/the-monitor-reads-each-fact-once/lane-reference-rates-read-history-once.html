Lane reference rates refresh from the rows that changed

The defect. A lane's reference rate is the median measured rate of its runs completed in the last seven days, cached per project and five-minute bucket. Every bucket roll decoded the whole window again: recovery_stream._lane_reference_rates read the ledger with activity_since=start for the full seven days, 14.6% of the station's profile samples, once per project every five minutes.

The change. The function keeps each project's per-run contributions — completion instant and measured rate per lane — beside the bucket that answered. A roll onto the bucket after the one it answered reads only the rows whose newest stamp reaches past the previous bucket's end, folds them in, and drops the rows the new window's start has passed. A run id identifies a row, so a boundary row returned again by the narrow bound replaces its entry rather than counting twice. A project the process holds no previous bucket for, including one whose bucket was skipped, still reads its window once, and a failed narrow read widens to that same window read.

The measure. In a temporary crew home holding 2,000 promoted rows across three lanes, the opening bucket decoded 2,000 rows and the roll over five newly promoted rows decoded 6 (the five promoted rows plus the one boundary row), inside the test's ceiling of 10. The base revision decodes 2,002 in the same arm: the whole window, as recorded in negative-control.log. Every lane's rates and the _budget_overrun_cause of 20 live runs equal the whole-window read's in both buckets; three aged rows leave one lane's cohort between the buckets and the boundary row stays in it.
