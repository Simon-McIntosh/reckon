A vanished review pointer costs one duty, not the tick

The station derives its view over a snapshot of the live pointers and then reads each listed review's own pointer from disk. A review promoted or discarded during a slow tick is listed by the snapshot and gone by the read, and runs.read_pointer raises CrewError for a missing file. _current_review_in_flight expected a falsy value for that case, so the exception escaped the derivation, ended station.tick(), and — through run_station's loop — ended the station process. Every project lost that tick, and the same run failed the same way on the next one.

That read now catches CrewError and answers False, as the sibling reader of a refused delivery already does. run_station prints any other exception a tick raises as a station-tick-failure line with its traceback and goes on to the next tick; a lost lease still ends the process with StationHeldError.

Implementation commit 27a85ee5c1 changes reckon/crew/obligations.py and reckon/crew/station.py. Three cases in tests/test_a_vanished_review_pointer_does_not_stop_the_station.py run on a temporary crew home and repository: the review pointer is published in the view's own snapshot and then deleted before the read, with a control that the same reader finds it in flight while the file exists; a first tick raises CrewError and the second runs and stops the station by its own signal handler; and a tick raising StationLeaseLostError still ends the station with StationHeldError.
