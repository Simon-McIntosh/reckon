A launched run is never read as queued

Dispatch stores a request with phase: queued and the admission pass advances that phase when it launches the request, writing launched_at on the pointer in a separate write. A pointer therefore carries both for as long as the phase write has not followed, and the run it names has launched — and may have finished — while its phase still says queued. That is the stale field: phase: queued surviving launched_at.

Run r-20261112T060747023508 read as run-queued, "position 1 of the queued requests", with launched_at 06:55:24Z on its pointer and its manifest complete. The queued phase was read before the run's own record, so the row hid the duty the run actually owed — its promotion — behind a queue wait that was already over. The pointer now reads phase: complete, which classifies correctly, so the phase is what went stale.

queue_admission.awaits_a_lane_slot names the one rule: a pointer is a request the pass still has to launch only while its phase reads queued and it carries no launched_at (or launch_recorded_at). The queued phase decides nothing on its own. queued_placements orders by it, and obligations classifies such a pointer with its phase left for the classifier to read from the run's manifest and process, so the finished run's promotion is what a coordinator is told to act on.
