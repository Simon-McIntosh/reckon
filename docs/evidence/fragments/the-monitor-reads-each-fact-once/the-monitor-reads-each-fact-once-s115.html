The signature mirror survives a removal

The defect. A read answered from the payload-free mirror falls back to measuring every payload once the mirror and the store disagree. A row removed by a path that does not write the mirror — the direct table delete a refused landing performs — leaves its mirror row marked present, so the disagreement never clears. The mirror also compared only row counts, and one stale mirror row beside one stored row no signature describes leaves both counts equal.

The disagreement was live. Two of the thirteen projects in the live store were in it, and they were the two busiest: reckon (64 stored rows against 21 present mirror rows) and imas-efit (1,550 stored against 1,548 present). A cold signature read of imas-efit cost 62,332,849 bytes and of reckon 16,300,648 bytes, against 1.0 MB and 2.1 MB for projects whose mirror agreed.

The repair. A cold read now compares run ids rather than counts and repairs the difference once. A stored row the mirror does not describe is measured from that row alone; a present signature the store no longer holds is retired to a tombstone; nothing that already agrees is read or rewritten. The read after the repair is answered from the mirror. Archiving a run whose mirror row was missing also gave the new signature the caller's project instead of the row's, leaving it answering under no project; the signature now takes the project from the row.

The measure

Every removal path the store offers — a delete, an archive, a wholesale rebuild, and a direct row discard — leaves the mirror's present ids equal to the store's rows. A store holding a discarded run's mirror row and a stored run with no mirror row is reconciled by one signature read, and the read after it costs under 5 MB on a store whose payloads total more than 200 MB, counted from the process's own read counter. The signature moves when a row is rewritten in place, archived or deleted, and not otherwise.

The same probe that recorded the two disagreements, run over a copy of the live store on a compute node, answers every project from its mirror at this revision: 13 of 13, against 11 of 13 at the base. imas-efit's repair read 19,952,677 bytes and reckon's 1,061,943; the read after each is answered from the mirror.

Negative control. At the base revision the first case fails with the discarded run still marked present in the mirror.
