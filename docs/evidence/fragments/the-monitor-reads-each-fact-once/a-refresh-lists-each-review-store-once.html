One enumeration per store, however many duties a refresh derives

What landed. reckon/crew/station_obligations.refresh now installs review_records.review_store_tick around its whole derivation — the fleet state, every session's payload, and the absent-session rewrites. The store already offered the per-tick enumeration: inside that region _store_paths filters a single os.scandir of each directory, and the store's index is built once per directory per tick. The station's refresh was the one reader that never opened the region, so every review lookup fell back to directory.glob.

What a duty cost. Each review duty reads the store several times over: the store index, the run's own {run}*.at-*.json entries, and the same entries again as the identities its read is keyed on. Unwrapped, each of those is a fresh enumeration of the project's store directory, so the cost of a refresh grows with the number of duties a project holds rather than with the number of files that changed. A refresh over 24 duties enumerated the one directory 194 times.

Gate. tests/test_a_refresh_lists_each_review_store_once.py builds a temporary crew home holding 24 live runs whose reviews are all stored, drives one refresh over them, and counts every enumeration of the store directory through a recording stand-in for both the directory's glob and os.scandir (a glob reaches the filesystem through scandir, so the stand-in counts the listing once rather than once per layer). The case asserts the refresh derived at least 20 duties — so the counter is shown seeing a refresh that does the work — and that the store was listed once. At the base revision the same case counts 194 listings for the same 24 duties.

Where the command sits in a log. The evidence audit reads only the first five lines of each log named in a manifest's test_logs, looking for the revision and the literal command a log reports. A log that introduces its arm, tree or imported module ahead of those two lines puts both past the window the audit reads, so the run reports nothing for a log that is complete. Every arm log therefore opens with # revision: on line 1 and # command: on line 2, and carries its tree, working directory and imported module after them.
