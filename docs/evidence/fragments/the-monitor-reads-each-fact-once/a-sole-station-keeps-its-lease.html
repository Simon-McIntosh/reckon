A worker's process table cannot pronounce the host station dead

The worker shares the host's node-local lease directory but sees a separate PID namespace. In three live samples, the lease kept inode 134544383 and token 8f7a705cbd8743fd91ccf1679fb57688, and its mtime advanced from 1794454376.765274 to 1794454381.8248003. All three os.kill(2323301, 0) probes nevertheless raised ProcessLookupError in the reader's pid:[4026533837]. The advancing mtime is the positive control: the supposedly absent process was renewing that same lease.

dispatch_watch._ensure_node_station treats that namespace-local result as proof of death and calls HostLease.release_holder, which at base clears the fresh lease. The next renewal fails, closes the store guard, and ends the station. An isolated dispatch check during a held-open station tick reproduces the loss at base with the worker evicted the sole station. The production log contains lease-loss and guard-refusal messages but no namespace diagnostics; this proves a live, reproducible cause, without attributing every historic restart to it.

Implementation 84b64e24adf42c265c32b795524fe82d47a6f21b records the holder's PID namespace in the shared lease mechanism. Early dead-holder release requires a known matching namespace and host. In-place reattachment also requires the same namespace, so an unrelated worker with the same numeric PID cannot inherit the token. A legacy record with no namespace waits for normal stale expiry rather than accepting an unverifiable early release. Stale takeover and the token/inode renewal guard retain their existing behavior.
