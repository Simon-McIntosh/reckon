Record names read from the index's own grouping

The review store kept two copies of one per-run grouping: _index_maps builds a reviewed map of run id to its entries, cached per document version by _document_index_maps, and the writer separately maintained a run_names map of run id to record names beside the per-run digests. The station is the process the fleet job has been killing for memory, so the second copy was pure duplication.

review_run_record_names now answers from the cached reviewed map: it reads _document_index_maps for the document and sorts that run's entries' names. The per-document run_names map and its upkeep (_run_name_map, _move_run_name, _drop_run_name and their calls on the indexed write and foreign-write reconcile) are removed; git grep -nw run_names reckon/crew/review_records.py finds nothing. The document's usability check no longer requires the removed key, so a document written before this change stays readable and simply answers from its entries.

The new case builds the index, primes the cached grouping by reading the names a run already holds, writes one record through record_written with no rebuild, and finds the new name by its run. Keying the cache on the document generation alone — leaving the grouping stale across an indexed write, which moves only the version — makes the case fail with the new name missing (EXIT=1).
