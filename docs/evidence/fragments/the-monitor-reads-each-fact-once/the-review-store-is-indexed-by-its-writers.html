One document beside the records, advanced by whoever writes one

What landed. reckon/crew/review_records.py now owns a writer-maintained index document at <store>/.review-index.json, with its lock beside it (.review-index.lock, an fcntl.flock on the shared home). Per record the document holds the SHA-256 of the bytes that landed; per run a digest over that run's (name, hash) pairs; per store a monotonic version, a bounded change log of (version, run id) and the store directory's mtime as of the last indexed write. record_written is the store's one writer path: it writes the record atomically, hashes what landed and advances the entry, the run digest, the version and the log in one locked write. review._write_record — the writer every run review and disposition already shared — and plan_review.store_plan_review both route through it.

Why the old index was not enough. The prior index was keyed on the store directory's stat identity, so a record written for any run moved it. The next reader then listed the store and stat'ed every record it named — 7,563 records and 5.6 s of GPFS on the fleet node, paid once per duty item, per run and per session.

What a reader does now. A run's records, a changed-run query since a version, and the tick's view of the store all answer from the document: no listing of the store and no stat of a record. A record written outside the writer path is found by reconcile_foreign_write, which compares the store directory's mtime with the one the index recorded and then lists names only — a name the index lacks is hashed and entered, a name the listing no longer holds is dropped, and every record already indexed is left alone. A missing, unreadable or foreign-stamped document is rebuilt from one listing and one hash of each record. The document is excluded from every record listing by its leading dot, so it never answers as a record.

Gate. tests/test_the_review_store_is_indexed_by_its_writers.py builds a temporary crew home holding 500 records across 50 runs and shows six things: a record stored through store_review is returned by a run-id lookup with no listing; reading every run's records after that store, inside review_store_tick, makes no stat or listing of the store directory (counted through recording stand-ins for os.stat, os.scandir and Path.glob on that directory); the change log since the prior version names exactly the run written, and that run's digest moves while no other run's does; a record written directly to the directory is found by one listing of names and no stat of an existing record; a deleted document is rebuilt from one listing; and a record stored by a second process is returned to the first process's next lookup.

Negative control. Restoring the base reader — store_index_document refusing the document, so the reader falls through to the whole-store pass — turns the read-pass case red, which is the plan's control.

What is not wired yet. _store_indexes and the non-tick _tick_store still answer through the prior cache. The reason is a measured one: routing them through the document removed the per-record revalidation that sees a record rewritten in place by a writer that bypassed this module (a review worker composing its JSON by hand), and four existing cases covering that went red. Inside a tick the document answers; outside one the revalidation stays until the index carries a per-record freshness signal a non-writer's in-place rewrite moves.
