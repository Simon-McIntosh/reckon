The station's store: one node-local database, one day file per UTC day, and a root it must prove

What landed. reckon/crew/station_store.py owns one SQLite database in WAL mode under the node-local runtime root, with tables pointers, streams, cursors, obligations and station, plus one events database per UTC day under the root's events directory, attached one at a time for reads. Events carry the fields the plan names — id, time, project, audience, run, kind, from, to, detail, duty — with indexes on (audience, id) and (project, id). A missing database is rebuilt from the crew home by rebuild(), which discovers the crew home's live pointers and each pointer's stream and ingests them. The stat identity stored for a pointer and for a stream is reckon.file_memo.file_signature's five-tuple, so the station keys a file exactly as every in-process memo does and re-parses a pointer only when that identity moves.

The root and the two refusals. reckon/crew/dispatch_watch.py gains session_host_runtime_root and session_host_runtime_candidate, public, so the station and the session host that starts it resolve one directory; the private spelling the crew surface re-exports is kept as a thin alias, so no import in reckon/crew/dispatch.py moved. The candidate answer names which of the three candidates produced the root, because only $XDG_RUNTIME_DIR and then /run/user/<uid> are shared by every process on the node: a root reached only through TMPDIR is refused, since TMPDIR differs per session and a store there would be per-session rather than the node's. The root's mount type is read through reckon.host._filesystem_type and every type in host._SHARED_FILESYSTEMS is refused naming its type; a type that cannot be determined is refused too, so the guard fails closed. host._is_node_local is deliberately not called: it accepts the runtime root by path prefix before it consults the mount type (reckon/host.py:190–192), which is exactly the root this store uses. Both refusals raise station_store.StationStoreError, the module's own class, which joins no entry of reckon.crew.refusals.DISPATCH_REFUSAL_REMEDIES.

Retention. A day file is named for the UTC day it holds, and sweep_retention unlinks every file whose day falls outside the window (seven days, a constructor value) so the rows leave with the file. A name that encodes no day is never unlinked, which is what makes the first negative control below red rather than silently green.

Gate. tests/test_the_station_store_is_node_local.py drives all of it: 15 passed, EXIT=0. Its cases are a rebuild from a fixture crew home of three pointers and two streams compared row-for-row against an incremental build of the same home (pointer rows and observation rows equal, both streams at consumed > 0); a day file nine days old unlinked by a sweep at a fixed now, its rows gone from the store's read path, and every surviving file inside the window; a root under a temporary $XDG_RUNTIME_DIR refused once per type in host._SHARED_FILESYSTEMS, naming that type, with host._filesystem_type steered to each of the eight; the same root refused when the type reads None; accepted when it reads tmpfs; a root resolving only through TMPDIR refused; and a pointer whose file_memo.file_signature is unchanged parsed zero further times across a second tick, then parsed exactly once more after its phase changes.

Negative controls. Both declared mutations were applied to the delivered module and reverted immediately. Writing events into one undated file turns the retention case red — 1 failed, EXIT=1 (logs/negative-undated-events.log): the store reports no file to unlink at all, so the row that should have left has not. Checking the root through host._is_node_local rather than the mount type turns all eight shared-type cases red — 8 failed, EXIT=1 (logs/negative-is-node-local-root.log): the root sits under $XDG_RUNTIME_DIR, which that predicate accepts by path prefix whatever the mount type says, so every shared type is accepted and the refusal never fires.

What this section adds and what it does not. The module and the two public root resolvers are added; nothing reads the store yet, so nothing is retired here — the surfaces it replaces are retired where they are named. Ingest that reads only bytes it has not read, the one-station-per-node process and its lock, the subscriber's cursor and generation wake, the obligations snapshot export, the once-per-change review reflex and the measured cutover are the later sections of this plan.
