Obligations recompute only what changed

A steady-state obligations publish now recomputes only the runs whose inputs moved. Three per-run derivations are memoised at the obligations layer: the review tier, keyed on the run's resolved head and tree, cited commits, manifest stat identity and the plan's change token; the held-worktree records, keyed on the ledger file's signature, git's worktree registry and the live pointer directory; and the classification memo, which is not rewritten when the bytes on disk already hold the memo it would write.

tests/test_the_station_reads_only_what_changed.py drives two ticks over a synthetic crew home of six review-owing runs. The second tick makes zero _plan_state_for_run calls, zero ledger.runs reads, zero git subprocesses and zero classification-memo writes; moving one run's head recomputes only that run's tier; and every payload equals the one computed with the memos cleared. At the base revision the same test fails those zero-count assertions, reading plan state six times and recomputing all six tiers on the second tick.

Against the live crew home the second of two payload_for passes over four live sessions took 75.761 s against a target of under 2 s, so the live-cost half of the measure is not met. Both timings, and the profile table that names the chains, are recorded in docs/research/monitor-storage-load-rca.html. The remaining cost is the review-store read each duty makes, which this change did not cover.
