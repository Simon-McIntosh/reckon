A run that failed at launch is told to discard, not to resume

The defect

Between 11:52Z and 15:22Z on 21 November 2026 every launch through the scheduler shim was refused with exit code 97 and no stream record. The obligation raised for each run carried the classifier's command-and-PATH repair verbatim, whose final clause reads "then launch a fresh attempt with reckon crew resume --run <id> --advice continue". A launch that never reached a model has no session to resume, so resume refused and the coordinator was told to run a command that could not work.

Reproduced before repair. Nothing was needed for the existing resume arm: it still passes at head, which is what the second case measures. The defect reproduced at base revision 2a3bf52e35, where the launch case failed with assert 'fix the comm...ed until then' == 'reckon crew ...ld-to-discard' - the obligation named crew resume.

What changed

  1. recovery_classification.py carries the first line of the launch error on the row as launch_error, and marks a launch that recorded its own end with ended_during_launch. A stranded launch reads launch-failed but recorded no end, so it is not treated alike.
  2. obligations.py gives the launch-failed duty the classifier's own detail as its reason, and for a launch that recorded its end replaces the resume-flavoured action with reckon crew discard --run <id> for a launch that recorded its own end.
  3. coordinator_obligations.py prints that cause beside the remedy, so a coordinator taking the discard step sees what failed without opening the run directory.
  4. The new test module drives all three through the obligations view and then runs the command the obligation names against the same temporary crew home.
