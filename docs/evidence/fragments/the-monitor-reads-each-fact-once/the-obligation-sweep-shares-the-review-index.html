The defect. The obligation sweep asks, for every delivered run, which live reviewer stands for its head, through recovery_review_dispatch._review_in_flight. That rule walked every live pointer and, per candidate, resolved the reviewed run's record directory through runs.run_dir — an existence check — and composed the candidate's dispatch to learn the head and project the rule keys on. A build makes 800 such asks over 200 live pointers: 160 from the sweep, one per delivered run, and 320 each from the classifier's and the round-id reader's own calls. On the fixture below that was 20,920 Path.exists and Path.is_dir calls made inside the lookups alone, out of 44,851 for the whole build.

What landed. _ReviewInFlightIndex files each pointer once, in _ReviewCandidateMap: under every record directory its granted paths name, and — for a reviewer — under the run its declarations or its node id spell. Both filings are string reading, so an index costs no filesystem checks to build; a reviewer that spells neither lands in an unresolved list every query also examines, and the query reads that pointer's exact subject before matching it, so no candidate is lost. standing_review then runs the walk's own tests over the short list a run's identity selects, in the read's order, because the first candidate to match is the answer. record_directory answers a run this read holds a live pointer for from runs.runs_dir() / run_id with no check, which is exactly run_dir for such a run: terminal_cleanup.archive_ended_run refuses while a live pointer stands. _review_query_fields reads the head and project the rule keys on instead of composing the whole dispatch command. The sequence-identity cache of _review_index is unchanged: the classifier, the sweep and the round-id reader each hand their own list, and each list keeps its own index.
