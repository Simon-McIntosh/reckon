No steady reader reads a whole stream

What was wrong

Three production readers asked the events cache for the whole stream, so each paid a whole read for every stream the 32 MB byte bound had evicted: _latest_attempt_capacity_refusal (needs the latest terminal event), _admission_refusal (folds three flags across the stream) and observe_log's fallback. The per-stream summary already held a resume cursor and folded observations; it held nothing these three could answer from, so the cursor never reached the census's 42.7 % row.

What changed

Each reader states its question as a fold from a seed over the records in order, and _backends.cached_stream_fold keeps that state in the per-stream summary: the whole stream is read once, and every later tick folds only the bytes gained. The observation fold is keyed by the records — backend settings and receipt — and not by the caller's elapsed time; a new elapsed reading is applied to the folded state, so a tick that passes a tick-later clock misses no fold. What a fold carries for the rate is the inputs a result stated — its spans, model usage and token counters — and not the rate a previous caller's clock computed from them: a stream whose result reports no span is rated against the clock of the read that asks, whether that read folded the result or nothing at all.

The rewrite check keeps the base revision's 8 KiB opening sample and adds a 512 byte boundary sample of the bytes immediately before the offset. The boundary is the guard a growth read pays, because an offset is an index into a sequence and stays valid only while the bytes before it do. A stream rewritten in place to a larger size with its opening byte-for-byte intact is otherwise indistinguishable from an append by stat and by the opening digest alike, and it is exactly the case where the recorded offset no longer names the records it named.

1,524 B = 500 B append + 512 B boundary sample verified before the read + 512 B boundary sample recorded for the offset the read reached. The opening sample is not re-read on a growth read — it is carried from the version it was taken at, which the boundary has just certified. The instrument counts every byte handed back by Path.open over the tracked stream paths; it is asserted to see the first pass's whole reads and, on the second pass, at least the 20,000 appended bytes.

Controls

  • Base revision: the same test reads 85,307,840 B on the second pass and fails.
  • The reviewed head: the parity arm compares each tick's answer to a whole observe_stream read of the same records, and fails there with the wall rate None against the whole read's 0.0 — the fold had baked in a rate computed without a clock.
  • The reviewed head: a stream rewritten in place with its opening untouched fails the same file's rewrite test, because the offset the cursor held named bytes that no longer exist in that place.
  • A growth read that drops the first appended record fails tests/test_watch_stream_parse_is_cached.py, whose resumed-answer check now requires an answer to reach every appended record it is owed rather than merely be a suffix of them.
