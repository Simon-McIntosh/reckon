The review reflex and the settle reading move into the station

What changed. A follower ran the recovery sweep on its own cadence, so one session with three panes paid for the same fleet reads three times, and each pane judged its own settle by listing the live pointer directory under the crew home. The station is the node's one reader, so both move there: the sweep runs once per session in the station, and the reading a pane's settle is judged by is written by the station on every tick. The settle window is dated from the newest resume of either kind, so a run resumed with advice waits the same window an automatic resume does.

The sweep runs in the station, once per session. SweepBeat in reckon/crew/station.py starts one session's whole sweep — the resume pass and the review pass — when the fleet changed or when the station's beat has elapsed (SWEEP_BEAT_SECONDS, the sweep's own default cadence), and never starts a session already walking. It runs on a daemon thread because a sweep walks registered worktrees and can run for hours: a heartbeat stalled behind it is a station an off-node reader calls stopped. The host rule runs.sweep_unfollowed_sessions applies is supplied by _sessions_to_sweep: a session with any live run launched on another host is left to that host's station, because a resume restarts a process where it runs.

The settle reading replaces the directory listing. record_live_work writes, for each project on every tick, the sessions holding work that has not ended, the project-wide answer an unscoped pane is judged by, and whether a live pointer carries no owner — an ownerless pointer keeps every session's reading live, because nothing shows the work is not the reader's own. station_subscriber.live_work_reading answers one population from that reading, and StationSubscriber.live_work exposes it to a pane. A reading older than the stale-heartbeat window answers nothing, so a pane is never settled on a reading nothing is refreshing.

The settle window dates from the newest resume. review_settle_seconds_remaining in reckon/crew/recovery_review_dispatch.py now reads _latest_resume_at rather than the sweep's auto_resume stamp alone, so a run a coordinator resumed with crew resume --advice — which records its instant through resume_superseded_head and writes no auto_resume — waits the window instead of being reviewed at the head it was moved past.

Two smaller corrections in the same tick. The heartbeat moves before anything is published, so the first snapshot a started or restarted station exports carries its current beat and reads not-stale; and StationReloader.poll no longer replaces checkout_trust._committed_tree_cache, because that resolver answers through station_store.runtime_root_source and refuses a non-local root itself — the reload still publishes under the station's runtime root.

Measure. The 32 test files importing the changed modules report 274 passed, EXIT=0 at both base and head — no added failure. ruff check and ruff format --check on the four staged paths add no finding and no format regression against base.

What the test shows, one property per failure it prevents. Three subscribers attached to one session add no sweep of their own: a tick runs one, and the count stays one after three polls; a second tick inside the beat runs none, and one after the beat runs a second. A session launched on another host is not swept here. A quiet resumed run — no pointer moves, no stream grows, nothing else changes — is still swept once the beat elapses, so a settle window that expires in a silent fleet is not missed. The settle reader dates a run from its advice resume, from the newer of an older automatic and a newer advice resume, and reads a long-resumed run as settled. The reading is live for a session with a live run, live for every session when a live pointer carries no owner, dead for a project holding only terminal runs, and dead when it is older than the stale window. The first obligations snapshot of a tick carries that tick's own heartbeat. A reload materialises its image under the station's runtime root and leaves checkout_trust._committed_tree_cache the module's own function.

The trace, with its positive control. A settle-aware subscriber reading the station (StationSubscriber polling and judging three populations, 1794 readings over 596 passes in 60 s) names no path under the crew home; the only paths it opens are 26 under the node's runtime root, the store it reads. The same 60 s trace of today's per-follower settle reader (crew_follow_commands._population_has_live_work, 596 samples) names 1789 crew-home paths — live, live/ and live/r-one.json, the run directory it lists — so a trace naming nothing is shown to be a trace that could have named something. Clipped path extracts are committed here; the full traces (615892 and 1010992 bytes) sit in the run directory under logs/after.trace and logs/before.trace.

Negative control. Three declared mutations applied together — the station requests no sweep, the settle reader takes auto_resume alone, and the sweep is due only on change — turn 4 failed, 3 passed, EXIT=1: test_three_subscribers_share_one_sweep_run_in_the_station, test_a_session_launched_elsewhere_is_not_swept_here, test_a_resumed_run_waits_its_settle_window_from_the_newest_resume and test_a_quiet_resumed_run_is_swept_on_the_beats_clock.

What remains, and why. Two items of this section's done-when reach past this node's write scope. StationSubscriber.wake is still the second poll loop beside the one _follow_watch_lines drives; the surviving loop belongs in reckon/crew_follow_commands.py, and the only other way to make it exist once is to delete wake and its two call sites in tests/test_a_follower_is_a_station_subscriber.py — both outside the granted paths. And the same file is where a running follower stops sweeping on its own cadence and calls StationSubscriber.live_work instead of _population_has_live_work, which is what turns the trace above into a measurement of the delivered follow process rather than of the module that process will read. Until that lands, a follower sweeps and the station sweeps; both passes are idempotent, so the duplicate costs reads rather than correctness.
