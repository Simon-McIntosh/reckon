One listing, one decode per pointer, per fleet-state derivation

What landed. obligations.live_pointer_snapshot is the one entry point that publishes a live-pointer population for the length of a derivation: it lists the directory itself, or takes the population a pass already holds, publishes that listing under obligations._VIEW_LIVE_POINTERS grouped by the project each pointer names, and resets the publication when the block ends. obligations.obligations, station_subscriber.live_work_populations and obligation_snapshot._derive_fleet_state all use it, and none of them keeps its own set/token/reset pair. runs.drain_unreconciled_by_session gained pointers, and _classified_rows passes the published snapshot to recovery.classify_pointer, which was the last per-row listing.

The memo is keyed on the snapshot, so the snapshot owns it. _VIEW_REVIEWS_IN_FLIGHT carries the pass's own snapshot to tell one pass from the next. Publishing a snapshot therefore has to drop an answer computed against the previous one: a derivation that published pointers without scoping the memo left the review answer behind, and the next question outside a station's pass read another pass's fleet. tests/test_a_duty_pass_reads_reviews_in_flight_once.py::test_a_question_outside_a_pass_costs_one_search was already written to catch exactly that, and it failed on the ordering test_a_fleet_reading_builds_each_store_view_once.py then this file. The publication now drops the memo as it drops the pointers, which is why both publishing and clearing live in one entry point rather than in each caller.

Gate. tests/test_fleet_state_reads_the_live_pointers_once.py builds a temporary crew home with 300 live pointers across three sessions — delivered implement runs with stored reviews, reviews of those runs, held requests and unreconciled runs — and derives the fleet state once with runs._list_live_records and runs.json.loads counted. Inside open_run_index.read_scope(), so the scope's own listing is not counted against the derivation, one derivation lists the project once and decodes 300 pointers. The second case derives the same home through a stand-in that reproduces the per-reader read pattern, checks that stand-in makes more than one listing, and asserts the derived pointers, the unreconciled counts and every session's obligations are non-empty and equal.
