An unchanged reconcile writes only its stamp

The review store's directory identity moves whenever any process creates and removes a file in it, while every record the index describes is untouched. The identity a reconcile proved settled lived only in the memory of the process that reconciled, so every other process -- the station, each project's watch producer, every MCP server and CLI call, and every process started after the reconcile -- found the store moved and listed its names again under the index lock. The settled identity is now written to .review-index/stamp.json beside the document, and both identity probes read it from there.

The regression moves the store directory's identity by creating and removing a temporary file, then calls store_index_document once in the test process and asserts the document's inode and bytes are unchanged. A helper asserts the identity actually moved, so a filesystem that coalesced the writes fails as an instrument rather than reporting a silent zero. A second, freshly started interpreter counts every os.scandir and Path.glob over that store before calling store_index_document: it reads 1 at the base revision and 0 at head. The same test then writes a record and shows the document move.

The stamp records the identity taken before the listing its entries came from, never a later stat, so a record written after that listing moves the identity again and the stamp cannot mask it. A document write carries its stamp in the same step, so a reader sees both or sees the stamp lagging and reconciles.

The declared mutation restores the base behaviour -- writing the whole document when a reconcile changes no entry -- and the test fails with an unchanged reconcile rewrote the index document and EXIT=1.
