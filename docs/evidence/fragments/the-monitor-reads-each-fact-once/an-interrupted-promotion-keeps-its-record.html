An interrupted promotion keeps its record until its attempt is retired

The order the unfinished-promotion branch ran in. finish_pending_landings reads a pending-landing record whose run is live, whose ledger has no promoted row, whose promotion holds no lease and whose pointer carries an unanswered attempting land attempt as a promotion that ended between its record and its ledger row. Until this change it called clear_pending first and _retire_interrupted_landing second. The record is the only evidence that the promotion stopped short, and the landing pass refuses a run whose attempt produced no receipt, so a pass that ended between the two left a live pointer with an attempting attempt, no record and no later sweep able to tell the promotion had stopped: an unliftable hold.

Change (commits f12479c498, ce205d6b58, 3509867a32). The branch now retires the attempt and its pointer first and clears the record second, so a pass that dies between the branch's own steps leaves the record for the next sweep. The record is cleared only when the retirement succeeded: when the pointer write fails, the retirement returns false, the run is reported as attempt-not-retired, and the record stays as the next sweep's evidence rather than being removed. A sweep that reads a record whose attempt an earlier partial pass already retired settles it the same way, so the record cannot outlive the attempt it names. Both steps take the run's own pointer and crew home, so no shared state outside the run's records is written.

Reproduction before the repair. The new case was run against the unmodified branch: assert 'attempting' == 'interrupted' failed at the record's removal, with no interrupted status reaching disk. The defect reproduced.

Gate. tests/test_a_finished_pending_landing_retires_its_run.py gains a case that delivers a run on a temporary crew home and repository, marks its pointer's land attempt attempting, writes a pending-landing record older than the promotion's lease window, and makes clear_pending raise. It asserts that the attempt was already retired to interrupted when the pass ended and that the record is still on disk, then restores clear_pending and asserts a second sweep answers retried-unfinished and removes the record, releasing the run for promotion. A second case makes the retirement itself fail and asserts the sweep reports attempt-not-retired with the record and the attempting pointer both intact, then that a sweep with the retirement restored retires the attempt and clears the record. tests/test_staged_write_inventory.py also imports the changed module.
