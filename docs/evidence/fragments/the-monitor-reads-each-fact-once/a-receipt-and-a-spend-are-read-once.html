A receipt and a spend are read once

The defect. A station tick asked every terminal run for its client receipt and its spend, and both answers decoded the same files again: promotion_checks._measured_rollout_receipt opened a codex run's rollout and decoded every line, and recovery_watch._spend_facts read each attempt's stream twice — once in measure_stream_tokens, once in _stream_time_span. A 60 s main-thread profile of the station put 22.8% in the receipt's line loop and a further 17.9% in the spend's passes, though neither file changes once its run is terminal.

What changed. Each reader keeps a per-process fold of one file, keyed by the file's path and validated by its identity, length and stamp. An unchanged file is answered from the fold; a grown one is decoded only past its stored offset; a replaced, truncated or in-place-rewritten one is folded again from the start. The stream's token measure and its time span now come from one decode of that stream rather than two. The directory listings these lookups need are kept while the directory's own identity, size and stamp are unchanged, so resolving an unchanged harness home costs no directory read. Nothing is written to disk: a fresh process holds no fold and reads every byte again.

The measure. Over a temporary crew home holding 20 terminal codex runs, each with a 3,000-line rollout and a 3,000-line stream, and with a recording stand-in counting json.loads calls attributed to reckon.crew.rollout and reckon.crew.metering plus every directory listing under the fixture:

PassDecodesListings
first (cold) 126,000 101
second (same files) 0 0
after 5 lines appended 5 0
after truncation 1,500 — every complete line left 0

The cold pass is the instrument's own check that it sees work before it reports an absence: 126,000 decodes is every line of the fixture's 126,000 lines. The second pass answers byte-identically to a separate process holding no summary at all, and both the grown and the truncated rollout agree with an uncached read of the same file.

Negative control. The declared mutation — restoring whole-file reads — is the base arm: base code at 6fa76c49f48e1d4fe4f104431f85f519ce92aae0 with this node's test copied in. Its second pass made 138,000 decodes and 300 listings, and the test failed on that count (logs/base-node.log, ending EXIT=1); the appended and truncated cases failed there too, at 138,005 and 136,501 decodes. At the head the same file passes (logs/head-node.log, EXIT=0), and the suite template's own test files pass in both arms — 58 at base, 62 with the node's test added.
