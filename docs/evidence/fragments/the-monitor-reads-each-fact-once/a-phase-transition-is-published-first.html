Every project's transitions are committed before any session's duties are derived

The defect. A station's tick walked the projects in one loop and, per project, folded that project's fleet, committed its transitions, and then derived its sessions' review duties before touching the next project. The derivation reads the review store once per run and, on 12-13 November, ran for 44 to 58 minutes inside a single tick. A run's phase transition is what wakes the session that owns it, so a run whose state changed in a later project was committed only after every earlier project's derivation had finished. Sessions were told nothing for 29 to 75 minutes, and the fleet looked quiet, not stuck: the tick was alive and its heartbeat fresh throughout.

What landed. reckon/crew/station.py splits the tick's per-project work into two passes. The first folds and commits every project's transitions through store.record_tick, unchanged; only then does the second pass derive each project's duties with station_obligations.publish and request its sweeps. Both passes run inside the same per-project-refresh stage, so a reader that names the stage still learns where a slow tick spends its time. No thread, no second publisher and no new seam were added: the change moves when the existing derivation runs relative to the existing commit, and each derivation still reads the fleet image this same tick committed, because every commit has already happened by the time the first derivation starts.

Gate. tests/test_a_phase_transition_is_published_before_review_duties.py mounts two projects on one temporary repository and drives one real Station.tick over a temporary crew home. It records both runs as inventory on a first tick, then moves both projects' runs and holds the first project's review-duty derivation open on an event the case controls, through the derivation's own _review_duty_item. While that derivation is held, a second StationStore on the same root reads the committed rows and asserts the later project's transition is already there. The case ends by releasing the derivation and asserting the tick completes with no failure and the transition is still present afterwards.

Negative control. The declared mutation restores the base publish order — the derivation moved back inside the per-project loop, ahead of the next project's fold and commit. The case then reads only the first project's transition while the derivation is held: 1 failed, EXIT=1, the later project's transition waited for the earlier project's derivation: ['r-alpha'] (logs/negative-control.log). That is the defect stated as an assertion. The mutation is reverted in the delivered revision.
