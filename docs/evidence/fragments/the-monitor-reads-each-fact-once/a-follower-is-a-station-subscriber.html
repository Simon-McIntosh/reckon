The pane's place is a row in the station's store, not a file under the crew home

What landed. reckon/crew/station_subscriber.py holds one pane's place in the station's event sequence and paints what it reads with the row path that was already there: ticker.PaneRowPath decides, the subscriber queries and advances. The place is a pair — the station-wide event sequence number and the UTC day it belongs to — because events live in one file per day. poll() attaches every day file from the cursor's day onward, selects the rows addressed to this session, to the sessions it observes and to every pane, feeds them in the station's own order, and writes the place back in the same pass. StationStore gained the cursor API the subscriber needs: read_cursor/write_cursor over a row holding the place, the day, the pane's checkpoint, its rendered history and its registration, plus data_version, event_generation, oldest_day and events_for.

What wakes it. PRAGMA data_version moves only for commits to the main database, and the event rows live in the attached day files, so the station commits a generation counter in the main database after every event commit (station_store.write_event) and the subscriber queries only when that counter moves. An idle poll is therefore two cheap reads and no event query, and the subscriber's own cursor and checkpoint writes — commits to the same database — do not read as news, because the generation has not moved.

Two races the day files forced. A day file is written by the station while several subscribers attach it, and under the default rollback journal that attach needs a lock the writer holds: a 1-millisecond poll loop failed with database is locked on the attach. Day files are now opened in WAL with a bounded busy wait like the main database. A day file also exists from the moment its writer opens it and its schema is written a statement later, so a reader can attach it in that window (no such table); that read is skipped for the pass, and the row written to it afterwards carries a higher id than the cursor the read advanced to, so the next poll reaches it. The attach itself is guarded on the same terms, because retention can unlink a file between the listing and the statement, and the markers carry both spellings SQLite uses when it refuses to open one. Every refusal the read treats as a race is named in _READ_RACES; any other operational error is raised rather than swallowed.

One reader, and a place per project. The attach loop, the race guard, the payload-column probe and the id sort live in one private reader that the station's own read and the subscriber's both call, so a race fixed in one cannot stay broken in the other; each keeps what it returned before — the station's read the whole station or one audience, the subscriber's one project. A cursor row is keyed by (project, audience) rather than by audience alone, because a session-less pane reads as * in every project it watches and two such panes would otherwise share one place, one checkpoint and one history. A primary key cannot be added in place, so a store written in the older shape has the table rebuilt on open with its rows kept under an empty project; the two cases above hold both the migration and the separation.

How the follower takes it. crew follow keeps every argument and its output format. _station_subscriber_for hands it a subscriber only when the node's store exists, was built from this follower's own crew home (CREW_HOME_KEY) and has beaten at least once; otherwise the producer's stream still serves the pane, so a node without a station and a session armed before one exists both keep delivering. On the subscriber path the wait loop polls, flushes the settle holds, prints the stale-heartbeat line once, renews the producer lease and its own delivery lease, and never constructs the reloader. The pane's memory is seeded from the subscriber's checkpoint instead of runs.read_delivered, which was the last crew-home read on that path.

Gate. tests/test_a_follower_is_a_station_subscriber.py drives the delivery path directly through a second connection as the station writes: a row delivered exactly once across a subscriber restart (11 passed, EXIT=0; the whole gate below, all 55 cases, 55 passed, EXIT=0); a re-armed subscriber drawing no new row for a run the pane already shows; a cursor spanning a UTC rollover delivering every event across two day files exactly once; a cursor 16 days older than retention resuming at the oldest held event with one skip line and no repeat; a stale heartbeat printing one line naming reckon crew station; a subscriber woken by an event written to an attached day file and by nothing else with the heartbeat silent; the registration stored as the pane's own cursor row, absent after detach; the delivery lease rewritten at half the lease interval while the pane runs; a day file the read cannot open skipped rather than ending the pane; a store written before the cursor row carried a project key opening with the places it already held; and two session-less subscribers over two projects keeping two places and two checkpoints. The freshness reload case is retargeted at the station, the one process that reloads: 1 passed, 23 rows across a station replacement, in order, once each, with the registration still set. The three named pane suites ran with them — tests/test_a_delivered_row_does_not_round_trip.py, tests/test_a_dispatch_is_one_row.py and tests/test_crew_session_delivery.py — alongside the freshness case and this node's own file, 55 passed, EXIT=0 (logs/gate-pane-suites.log).

The trace. A follower was armed over a synthesised node-local store and crew home and left to finish its attach pass; the plan's 60 seconds of its steady state were then traced with strace -f -e trace=openat,stat,newfstatat, one event published part-way through so the delivery path itself is inside the window. Under the crew home the window names two lease families and one directory stamp. The producer watch lease is read and its lock stat'ed on every pass — crew/watch/leases/proj-*.json, crew/watch/proj-*.lock and the crew/watch lookup its renewal makes — 1820 records in all; the pane's own delivery lease under crew/watch/proj-*.followers/ accounts for 15; and a single stat of crew/live is the retained recovery sweep's file stamp, which runs on a 120-second cadence and so writes no record of its own inside a 60-second window. Nothing else. No pane checkpoint, no pane history, no delivered.json, no registration lock and no reload tree appears — the paths this node moved are absent, and the control arm run over the same harness names crew/runs/proj/checkpoint.json where the measure names nothing.

Negative controls. Two declared mutations were armed against the delivered code, and both turn red on the measure they were aimed at. A subscriber that keeps its checkpoint but never writes its place (the cursor and day columns dropped from every write_cursor) turns the restart case red — 1 failed, EXIT=1 (logs/negative-no-cursor.log): the first delivery leaves the place at 0, so the case fails on the place it asserts. A subscriber that writes its checkpoint under the crew home on every drawn row is armed through the same trace harness with one variable changed (logs/negctl_b/sitecustomize.py): the control trace names crew/runs/proj/checkpoint.json, which the measured run never touches. The control run exists because a trace that names no pane path is equally consistent with a delivery path that never ran; the cursor row it leaves behind says the subscriber path was taken in both arms.

The armed suite, both arms. Both arms ran the project's armed command, PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_a_follower_is_a_station_subscriber.py tests/test_follower_freshness.py, once in a base tree extracted from c30c057d4 and once at this head in an unmodified worktree. The base arm collects nothing and exits 4, because the file this section adds does not exist at base and that is the honest base state; its freshness case alone would have run had the missing file not aborted collection. The head arm is 21 passed, EXIT=0 (logs/baseline-armed.log, logs/after-armed.log). As a wider sample, the 62 test files that import station_store, crew_follow_commands or station_subscriber ran with PYTHONPATH=. .venv/bin/python -m pytest -p no:cacheprovider -q, once in a base tree extracted from c30c057d4 and once in this worktree, each with .venv linked to the shared environment, at the head this section stood on before its two cursor-key cases were added. Base: 1 failed, 488 passed. Worktree: 1 failed, 497 passed — the extra passes are this node's own cases, and the two added since then are covered by the armed arms above. The failure is the same test id in both arms, tests/test_every_module_is_reached.py::test_every_module_is_reached, which reports reckon.crew.station_store as an allowlist row that should have been removed because the module is in fact reached; it reproduces in the base tree, so the added-failure set is empty and it is reported to the coordinator rather than repaired here.

What this section adds and what it does not. The subscriber, the store's cursor API and the follower's path to it are added. The producers are not retired here, so the subscriber still renews the producer lease and writes its delivery lease, and the follower still falls back to the producer's stream where no station has beaten. The obligations export, the once-per-change review reflex and the measured cutover are the later sections of this plan.
