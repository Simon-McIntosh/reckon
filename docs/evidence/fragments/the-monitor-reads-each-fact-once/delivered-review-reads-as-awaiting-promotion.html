A run whose review has delivered waits on a promotion

The defect. A scoring run whose review_dispatch names a review run that has delivered, whose record no promotion has landed, carried no review duty at all. _current_review_in_flight read the recorded dispatch through _reflex_review_in_flight, which asks only whether the named pointer is readable, so a review holding its pointer in phase complete still counted as working on the revision and the duty was dropped by the view's suppression branch. The same run asked through _review_duty_item alone read review-missing. Either reading tells the coordinator to inspect a follower or dispatch a review when the actual wait is a promotion of a review that already exists.

What landed. reckon/crew/obligations.py gains _recorded_review_dispatch (the review dispatch the run's own pointer records, both rubric fields read, a withdrawn attempt ignored), _delivered_review (the same run, with its pointer read once, when the head the dispatch recorded is the head the run carries and the classifier's _review_pointer_delivered reads that pointer as delivered), and the duty kind review-awaiting-promotion. The duty carries the review run's id in review_run_id, names it in its reason, and offers _delivered_review_promotion_command, composed through the classifier's own _promotion_command so the offered promotion cannot drift from the one a promotable run is offered. _current_review_in_flight now answers False for a delivered review, so the duty is built instead of suppressed; _review_duty_item reads it only when no stored record covers the head, none describes an older one, and the review read the head the run carries, because a review of a revision the run has moved past is a record earned for other work and promoting it would land evidence for a revision no longer delivered.
