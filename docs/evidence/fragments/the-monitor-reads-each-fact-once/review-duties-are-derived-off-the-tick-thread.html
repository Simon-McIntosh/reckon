A long derivation no longer holds a later tick's phase transitions

The defect. Phase transitions for every project were committed before any session's duties were derived, but both passes still ran on the tick's own thread. A project's derivation reads the review store once per run and can outlast a tick many times over, so a tick that began deriving duties held every later tick back: a run whose state changed during that derivation was not published until it returned, and its session was told nothing until the following tick.

What landed. reckon/crew/station.py gains DutyBeat, a worker the station owns. The tick still calls station_obligations.publish for each project and still records the per-project-refresh stage around that call, so the stage a reader sees keeps naming the work. publish now takes a submit callable: given one, it hands the derivation to the station's worker and returns at once; without one it derives in the caller's thread exactly as before. The worker opens its own store connection, because a store handle is bound to the thread that opened it, and it discards its in-flight mark only after the derivation returns.

One at a time. A project already being derived is never started a second time; the tick's request is refused and the duties the last finished derivation published stand until it completes. A change the tick saw while a derivation ran is carried into the next one, so a busy project is not left publishing duties read before its own transition. run_station drains the worker on exit, bounded by DUTY_DRAIN_SECONDS.

Gate. tests/test_review_duties_are_derived_off_the_tick_thread.py drives run_station itself on a temporary crew home across two tick intervals. The first tick's derivation is held open inside the worker; the run's phase then changes between ticks; a second tick's transition for that run is read from the store while the derivation is still held. The case also asserts the worker saw exactly one derivation at a time and that the blocked project is the one in flight.

Negative control. The declared mutation restores the base tick so the second tick's transition waits for the blocked derivation: submit is dropped from the tick's publish call, putting the derivation back on the tick thread. The case then never sees the transition and fails by name.
