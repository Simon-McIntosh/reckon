The tick's fold reads the scalars it needs, not the fleet's fields

What landed. StationStore.tick folded each of the fleet's streams and, for every one of them, called _pointer_for_stream, which scanned the store's pointer rows and decoded each row's fields document until it found the one naming that stream. The scan decoded the whole fleet's fields once per stream, on every tick where any stream had grown, which is every tick of a live fleet. The three scalars the fold needs — the stream path, the backend and the dialect to read it in — are now columns on the pointers table, written beside the fields by the pointer's own ingest, which runs only when the pointer moved. ingest_stream takes the pointer's record from the one pass that names the streams, and _pointer_for_stream remains only as the fallback for a caller folding a stream it holds no pointer for. The pointer's stored signature is compared as the text it was written as instead of being decoded back into a list, which removes the last decode a tick over an unchanged fleet paid per pointer. A store written before the columns existed is backfilled once, at connect.

What the census named. The census harness was first made to take the revision and the log path as arguments, so each arm builds its own tree at its own revision and writes its own log, and each of json.loads and json.load is wrapped to record its caller and input size. On one warm tick at base 2780ddad (133 live pointers, decode-census-base.log) the tick decoded 372,393,182 bytes in 716,226 calls. The callers that decoded the most bytes were _backends.parse_events 124,716,976 bytes over 351,881 calls, station_store._pointer_for_stream 96,496,368 bytes over 1,934 calls, recovery_wait._stream_holds_assistant_record 64,536,556 over 200,476, recovery_wait._tool_call_in_line 32,890,089 over 103,923 and metering.measure_stream_tokens 18,908,022 over 53,822. _pointer_for_stream grew with the tick, not with the fleet's change: 96.5 MB, 104.0 MB, 132.4 MB and 104.6 MB in the four traced ticks, at 1,934 to 2,693 decodes of a ~50 KB document each, beside a fleet whose streams had already been folded.

Peaks. Base's traced ticks peaked at 175,532,440, 221,546,802, 213,683,083 and 230,499,074 bytes; head's at 185,646,977 for tick 1. Every observed tick in both arms is under 600 MB.

Gate. tests/test_a_tick_decodes_only_what_changed.py builds a temporary crew home of four pointers, each naming one recorded stream, settles the store with one tick, and then ticks again. Its ledger wraps json.loads and json.load and keeps the text of every document decoded, so an assertion is against the bytes decoded rather than a call count. Over an unchanged fleet the second tick decodes nothing and reads no stream byte. A pointer that moves is decoded exactly once, by its own ingest, and the tick after it decodes nothing. One byte appended to one stream is read once at its offset, with no fold from the start and no pointer document decoded. A fourth case writes a store in the previous schema and shows a store on disk still folds a codex run in its own dialect after the backfill. Gate: 4 passed, EXIT=0 (gate-head.log).
