The station reads only the bytes a stream gained, and refolds a rewrite

What changed. StationStore.ingest_stream now stores the size it last read beside the consumed offset, and returns without reading anything when a stream's size has not moved — so a trailing partial record waits for the bytes that complete it instead of being re-read on every tick. Every byte it reads passes through one named step, _read_range, so the volume per tick is countable. A grown stream is checked against a 64-byte tail anchor kept beside its offset; a stream whose inode changed, whose size fell below its consumed offset, whose size fell below its last-read size, or whose anchor no longer matches is folded from its start with no carried state. The streams table gains size and anchor, with the columns added in place on a store written before them. Each day file's connection is now closed after its event is written (contextlib.closing), because sqlite3.Connection's context manager commits but does not close, and the unused duplicate constructors store_at_runtime_root and default_store are deleted. The node-local rebuild case now compares the incremental store's pointer paths against the fixture's own three rather than against the rebuilt store's output.

  • The replay. Five recorded claude stream-json runs (init, assistant turns carrying prompt usage, rate-limit readings, a result, and one interrupted half record) are replayed as 93 appends across chunk sizes of 1 to 251 bytes, so records are split mid-line and partial records are carried across ticks. On every tick the bytes read from the grown stream are within appended + 64 + the partial record carried from the previous tick, the four other streams read zero, and after the last append each stream's incremental observation equals one full fold of the finished file (as_dict() equal) with its consumed offset at the file size.
  • The four refolds. Each is measured by what the store read: a changed inode, a size below the consumed offset, and a size below the last-read size (the anchor still matching, so only that test can catch it) each read the file once from offset zero, and a moved anchor on a grown stream reads the anchor then the file from zero. A grown stream whose anchor still matches reads exactly the anchor and the appended tail, and never from zero.
  • A stream that did not grow. A file ending in a half record is read once; the next tick with the same size reads zero bytes and leaves the offset where it was; appending the rest of the record completes the fold.
  • Descriptors. The store's open file descriptors are equal before and after writing 50 events.
  • The 64-byte anchor's limit. It misses a rewrite whose bytes at that position are byte-identical, which timestamped records make vanishingly unlikely; a stream that did not grow is not read at all, so an in-place rewrite that keeps its size is outside this check by design.
  • The negative control. Five mutations, each failing its named case: ignoring the stored offset fails the replay's byte bound and the unchanged-size case; dropping the carried fold state fails the replay's equality (the carried peak prompt and event count come from earlier records); dropping the anchor comparison fails the truncate-and-rewrite-past-the-offset case; dropping the last-read-size test fails the rewrite that lands between the consumed offset and the last-read size; leaving day-file connections open fails the descriptor count (18 descriptors before, 68 after).
