Plan resolution reads its directory once per change

The defect. A named plan read takes the plan's canonical path and then asks whether another file in that root claims the same identity. That question is one lookup into a held index of the root, and the index is revalidated against the root's listing — a glob of the directory and one stat of every sibling. The listing itself was rebuilt per resolve, so the whole plan population's metadata was paid once per named read. At the base revision 200 named reads cost 400 directory globs and 80,000 sibling stats across two passes over an unchanged directory.

What landed. reckon/resources.py holds each directory's listing beside the directory's own stat stamp — device, inode, mtime_ns, ctime_ns and size — read before the listing is taken. A resolve whose directory stamp has not moved is answered from the held listing, so it costs one stat of the directory instead of a glob and a stat per sibling. An entry added, removed or renamed moves the stamp, and the next resolve lists the directory again. The stamp is read first, so a change landing during a listing leaves the stored stamp behind the directory and the next changed call lists it again. Only the directory's entry set is held: the resolved document's own head is still read from its file on every resolve, so a document written in place stays current.

Two passes, then one change

tests/test_plan_resolution_reads_the_directory_once_per_change.py writes 200 plans at their canonical paths, resolves all 200 twice, then adds one plan and renames one and resolves all 200 plus the added plan. It stands in for resources._identity_listing, for the plans directory's glob, and for file_memo.file_signature, so the globs are the directory's own and the sibling stats are the stamps one listing takes.

The head arm reads one glob and exactly 200 sibling stamps across the first two passes — the first listing stamps every sibling, which is the check that the instrument sees something before an absence is claimed, and the second pass takes none — and one further glob after the plan is added and one renamed. Each resolve is compared for equality with the classifier's answer for the file it names, including the added and the renamed plan, so the held listing changes no answer.

The negative control

The same test, run against the base revision's reckon/resources.py in a scratch tree, fails on the glob assertion with two passes over 200 plans globbed the directory 400 times and EXIT=1, matching the section's declared string. The head arm passes at EXIT=0.
