A run mid-repair raises no sweep failure, and one failure is raised once

Two duties were raised against runs with nothing wrong. First, a delivered run resumed for a repair round had its review correctly withheld while the resumed attempt was working, and the review-request census read the withheld request as a missing one: after the deadline it raised a sweep-failed duty for a run whose worker was still alive. Second, the stored failure record is keyed by the session whose sweep recorded it, so three sweep authors reporting one run's failure raised the same sweep-failed row three times.

reckon/crew/recovery_review_dispatch.py now withholds the duty when a resumed attempt is still in flight, reported in the census as in_flight rather than as an unmet obligation. A resumed attempt whose exit receipt shows it ended without delivering still raises, because nothing is working on it. reckon/crew/station_obligations.py raises one row per run, however many authors stored the failure. The predicate is scoped to a resumed attempt, so an ordinary delivered run with unknown liveness keeps raising the duty it always did.
