A sweep failure is a published duty

The station stores each session's failed review-sweep runs in its guarded node-local store. Publication adds a duty naming the run, exception type and error message, with an observation command. A changed report triggers refresh even when the fleet has no transition. A whole-pass error retains the earlier failures; a completed pass replaces them, clearing runs that succeed. Sessions with failed runs receive a published answer even without a live follower. Sweep threads use separate store connections, and concurrent session report updates are serialised.
