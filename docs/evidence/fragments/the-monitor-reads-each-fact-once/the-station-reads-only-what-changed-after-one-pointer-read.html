The station reads only what changed after one pointer read

The defect. The terminal-lane scan asked each run's stream for its newest result record by parsing the stream, and it kept the answer only for the stat identity it was reached at. A live worker appends to its stream continuously, so the identity moved on every pass and the whole stream was parsed again, per run, per pass. On a census of one station over 147 live pointers that read was 19.5 % of every byte the process read and grew with each stream.

What landed. recovery_memo._newest_result_event holds a per-stream cursor in an OrderedDict bounded per process and evicted oldest-first: the identity it was reached at, the offset after the last complete record, and the stream opening's fingerprint. A stream whose identity is unchanged is answered without opening. One that grew at the same inode and still opens with the recorded bytes is read from its offset through _backends._stream_lines_from, and the answer is folded with the result the cursor already held. One that was replaced or rewritten is read from its first record, because an offset into a predecessor's bytes means nothing in a file that never held them. The rewrite check is _backends.stream_head_fingerprint and _backends._stream_head_intact — the same 8 KiB sample the parsed-stream cache records — so one sample size governs every rewrite check in the tree rather than a second, smaller one chosen here.

The fixture: one appended record, one read

tests/test_the_station_reads_only_what_changed.py builds its own crew home of five runs whose streams total 11,004,305 bytes, runs a tick, appends 510 bytes to every stream, and counts the bytes the second tick reads through the same wrapper. The two size checks it makes are preconditions of the fixture, not guards on the measurement: that the five streams total at least 10 MB, so a whole-stream read is distinguishable from a cursor read at all, and that every run of the fixture reached the tick, so the comparison covers all of them. Both hold equally on a tree with no cursor.

The comparison is against a classification computed with recovery_memo._NEWEST_RESULTS cleared, so the reference answers from the streams themselves rather than from the cursor the tick under test just advanced; a reference sharing that cursor would agree with it by construction.

The scan is not the producer's parsed traffic

When the scan first took its appended read through _backends._stream_lines_from, it also fed the producer's parsed-byte counter that reader owns. In one poll that reader then parsed the growth twice — once for the producer's own incremental parse, once for this node's scan — and the registration reported twice the bytes appended. tests/test_producer_reads_only_what_changed.py caught it: 36,002,538 bytes recorded against 18,001,269 appended. The counter reports the fleet traffic a poll folded, and a scan answering its own question about a stream is not that fold, so the read now passes count=False; the case passes with the bytes appended and exactly those, and this node's own gate still passes.

Arms and control

gate-base.log at base 73a771c and gate-after.log at head, each with the command resolved over its own tree, and negative-control.log for the base tree carrying this node's test file alone. matched-importers-base.log and matched-importers-head.log run every test file that imports the changed module in both trees; their failure sets are identical id for id, so the added-failure set is empty. Ruff check and format over the staged paths are recorded in ruff-check.log and ruff-format-check.log and add no finding against base.

What this node did not change

The live 20 MB/min and 5 % of one core bound is not met by this change: the station alone over 147 live pointers read 1,131 MB/min at base 73a771c and 1,376 MB/min with the cursor, both far above the bound. The dominant residual is _backends._cached_stream_entry: its parsed-stream cache is bounded at 32 MB while the fleet's streams are several hundred, so a pass that touches every stream evicts what the next pass asks for and the whole population is re-parsed. That eviction, the per-document content_digest, the review store's whole-file read and runs._pointer_text are the remaining readers and none is reachable from this node's write scope. The section's live bound stays open.
