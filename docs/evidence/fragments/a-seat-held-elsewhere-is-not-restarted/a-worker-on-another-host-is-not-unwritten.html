A worker writing its first status on another host is not drawn halted

A run launched on another host carries a pid this reader's process table cannot look up, so local_liveness answers unknown, and _orientation_write_of_a_run_in_motion in reckon/crew/recovery_liveness.py returned early on any answer other than True. A run between its orientation write and its first status therefore read unwritten and was told to resume work in flight. The liveness gate now refuses only a proven-False answer and decides the unknown case from the run's own stream through the new _newest_stream_in_motion: an assistant turn in the newest stream written within the stall window the stall clock already applies (LOG_STALE_AFTER_SECONDS, no second window) is a run in motion and keeps its classification; a quiet stream still reads unwritten, and a proven-live process is decided as before.
