A resume never launches beside an attempt on another node

Two facts about a run's current attempt cross hosts, and neither was readable by the guards a resume had. A pid issued on another machine means nothing in this host's process table, so a door that refused only a proven live process answered nothing for a foreign attempt and started a worker beside a live one; and the pointer's advisory lock, which the doors already used to serialise their launches, is coherent on one node and not across two.

reckon/crew/resumption.py now reserves each attempt number with an exclusive create — os.open(path, O_CREAT | O_EXCL) on attempt-<n>.claim in the run directory — which is a fact of the shared filesystem rather than of one kernel. Of two doors that read the same current attempt, the first creates the claim and launches; the second finds it, raises the run's existing in-flight wording (already has a resume launching), and keeps the coordinator's advice for the run's next resume rather than dropping it. A claim is reclaimed rather than left to wedge the run when the pointer's attempt has already moved past it, or when its launch has exceeded LAUNCH_WINDOW_SECONDS without the launcher recording that attempt. A claim is released only when no worker started; a launch that reached the spawn keeps its claim. No refusal family is added.

When the current attempt's liveness is unknown because its pid belongs to another host, _observed_end_refusal now reads the run's own stream through the recovery module's _newest_stream_in_motion, the same reading the stalled-row surface uses. A stream carrying an assistant record and quiet within the stall window is a life this host can read, and the resume is refused as a live pid is refused; a stream that has gone quiet past the window licenses the resume. A stream holding no assistant record is unchanged — it is not an end, so the unknown-liveness refusal stands.

tests/test_a_resume_never_launches_beside_another_node.py holds five cases with the crew home pointed at a temporary directory and the real home asserted untouched afterwards: two doors that read one current attempt launch exactly once and the loser refuses naming the run with its advice stored; a foreign pid with a stream in motion inside the stall window refuses; the same pid with a stream past the window launches; an abandoned claim is reclaimed after the launch window; and a fresh claim still guards a launcher composing. The declared mutation — removing the exclusive claim, so both doors launch — turns two of the five red, logged to negative-control.log with the mutation verbatim on its first line and a bare EXIT=1 as its last.
