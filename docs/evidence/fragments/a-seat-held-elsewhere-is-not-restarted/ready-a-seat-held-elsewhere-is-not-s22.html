A seat held by a process that produces nothing is reclaimed

reckon crew watch --ensure now resolves who holds the project’s watch lock before it starts anything. It reads the kernel’s lock table (/proc/locks), matching the watch lock file’s device and inode against each FLOCK entry, so a process that merely has the lock file open — a reader that released its flock or never took one — is never named and never signalled. When the seat is held and the producer snapshot is stale past its bound — the producer’s own lease, the interval its poll loop exits on — a holder that is this project’s producer is reported seat-held-by-stuck-producer and stopped (SIGTERM, then SIGKILL once the claim’s contention window passes) before the unit starts, so the producer the arming launches takes the seat. Any other holder is reported with its pid and command line under seat-held-by-non-producer, nothing is started and nothing is stopped. A live producer whose lease is inside its interval is left alone exactly as before.

Measure: tests/test_a_seat_held_by_a_non_producer_is_reclaimed.py, four cases against a temporary crew home and real stub processes holding a real advisory lock — the lock’s holders resolve to the pid the arming started and the stale pid is gone; the non-producer is named and stays alive; the fresh producer is untouched; an opener beside a stale producer is neither named nor stopped. 15 passed at head (11 at the base revision plus the 4 new cases). With the stop of the stale producer removed the first case fails (1 failed), because the producer the arming starts never takes a seat the stale pid still holds.

The stop does not signal from here. The pid it acts on is a scan result — a row of the kernel’s lock table — which is exactly the target whose process group the crew refuses to assume, so delivery goes through reckon.crew.process_signal.signal_worker, the crew’s one home for os.kill, and the holder’s command line is read through fleet_supervisor.process_cmdline rather than a second parse of /proc/<pid>/cmdline. A case in tests/test_watch_seat_across_hosts.py pins the routing: with the source half of that change reversed the case fails (1 failed), because the fake signaller sees no signal at all.

Both the files that import these modules and the staged-write inventory were measured rather than asserted: the five importing test files pass at the base revision and at this head (22 at base, 27 with the new seat case at head), and tests/test_staged_write_inventory.py passes at both revisions (51 passed each, EXIT=0).
