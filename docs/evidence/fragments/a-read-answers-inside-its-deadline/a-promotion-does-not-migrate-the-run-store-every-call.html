A promotion does not migrate the run store on every call

Every promotion opens the run store to append its row. A store created under the earlier narrow-column declaration keeps those columns beside the ones the migration adds, so its shape never equals the current declaration and the backfill stayed owed forever: each open decoded and rewrote every row before the append could run. The migration now records the declaration version it brought the store to, in a store_meta row beside the store's own rows, and an open that finds that record skips the pass. The version hashes the schema declarations themselves, so a changed declaration changes the version and the pass runs again rather than being skipped against a store the new code cannot read.
