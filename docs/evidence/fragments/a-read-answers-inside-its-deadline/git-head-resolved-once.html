Git HEAD is resolved once per commit, not once per lookup

_git_head now memoises the resolved sha on the identity of the repository's HEAD and the ref file it names (mtime, inode and size, read as files rather than by git), so a warm creation or last-modified lookup for an unchanged checkout starts no git process, and a new commit changes that identity so the next lookup resolves the new date. tests/test_git_head_is_resolved_once.py: 1 passed, EXIT=0; negative control (HEAD memo keyed on nothing) 1 failed, EXIT=1.
