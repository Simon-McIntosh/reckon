The attempt memo names the stamp members it compares

The section-attempts memo compared the ledger index stamp by a positional slice, stamp[0][:4], so a member added to or reordered within ledger.index_stamp silently changed the state the memo keyed on. The member set now has one owner, ledger._index_stamp_members: index_stamp renders it as the ordered list its positional callers read, and index_state_stamp returns the same members keyed by name with the index file's own identity omitted by name. mcp_views._attempt_state reads that record by name. A member added to the set reaches the memo without a second list to keep in step, and the index identity stays out of the comparison because a read rewrites it.

Measure. tests/test_the_attempt_memo_names_its_stamp_members.py drives memoised reads. Head, 5 passed with the existing attempts-cache tests (EXIT=0): the memo holds on an unchanged stamp, invalidates when the runs directory's identity moves, holds when only the index file's identity moves, and invalidates when a member added to the stamp changes. Base arm: the inserted leading member pushes the runs directory's identity out of the four-member slice, the memo misses the change, and the runs-directory assertion fails with assert 1 == 2 (EXIT=1). ruff check and format add no findings on the changed files.
