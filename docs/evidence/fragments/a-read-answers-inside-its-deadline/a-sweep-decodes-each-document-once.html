A sweep decodes each crew document once

Per-run ledger documents are now decoded through one process-wide memo, ledger.read_document, held against the file's stat identity. Both readers of a run file — the held-worktree scan in reckon/crew/obligations.py and the ledger's own _read_run — take the memo, so a sweep decodes each per-run document once, and a later sweep in the same process skips every file whose identity is unchanged. Over a fixture of 200 per-run files and 20 live pointers, one obligation_snapshot.sweep decodes each of the 200 run documents once; a second sweep with one run file changed decodes exactly that file; the snapshots both sweeps write equal an unmemoised sweep's.

The memo is bounded twice over, because the producer that runs a sweep lives for days while run files come and go. It is least-recently-used beyond a stated DOCUMENT_CACHE_LIMIT, and the sweep releases it to the documents that sweep opened, so a run file deleted or renamed between sweeps does not keep its parse for the life of the process. The crew.json row memo in the same scan keyed its parse on the same four fields; it now takes that identity from ledger.document_identity, so the repository holds one rule for when a file has moved rather than two copies of it.
