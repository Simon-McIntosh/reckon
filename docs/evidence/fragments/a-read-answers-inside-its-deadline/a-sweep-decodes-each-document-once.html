A sweep decodes each crew document once

Per-run ledger documents are now decoded through the repository's one memo, reckon/file_memo.py, keyed on the file's stat identity by file_memo.file_signature. Both readers of a run file — the held-worktree scan in reckon/crew/obligations.py and the ledger's own _read_run — take the memo, so a sweep decodes each per-run document once, and a later sweep in the same process skips every file whose identity is unchanged. Over a fixture of 200 per-run files and 20 live pointers, one obligation_snapshot.sweep decodes each of the 200 run documents once; a second sweep with one run file changed decodes exactly that file; the snapshots both sweeps write equal an unmemoised sweep's.

The memo is not a new one. file_memo already owns this capability for plan parses, with an LRU bound and a lock, and it deep copies on store and on return so no caller can corrupt another's record. The crew documents travel through that same memo under their own kind, so the repository holds one stat-identity rule and one memo rather than a second of each. The crew.json row memo in the same scan keyed its parse on the same fields inline; it now takes that identity from file_memo.file_signature. The deep copy costs the sweep nothing measurable here: over the 200-file fixture a warm sweep takes 17.9 s against the base tree's 23.2 s.
