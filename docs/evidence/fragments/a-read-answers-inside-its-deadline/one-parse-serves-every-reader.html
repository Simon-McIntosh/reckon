Every plan reader derives from one parse

Read the roadmap authored-section reader (read_authored in reckon/roadmap.py), the serve readiness reader (_read_readiness_uncached in reckon/serve.py) and the metadata index per-plan record (_plan_record in reckon/metadata_index.py) all derive from read_state_and_text_file's path-keyed parse instead of parsing each file again under their own memo kind. A cold roadmap and then a discovery read of ten plans, the metadata index build included, count 10 read_state calls through a counting wrapper. The negative control — read_authored given back read_state_file, its own memo kind — counts 20 and both tests fail.
