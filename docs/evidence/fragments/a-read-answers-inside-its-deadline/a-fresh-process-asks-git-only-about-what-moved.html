A fresh process asks git only about what moved

The two git answers a derivation takes that are functions of immutable object ids — the commit a full revision resolves to, and the count of commits between a worktree head and its base — are now read from and written to a store under the crew home, keyed on those ids. A ref name or abbreviation still asks git, because a ref moves. A corrupt or absent store falls back to git, returns the same answer, and rewrites the entry.

With the store populated and the in-process caches cleared, a derivation over four unmoved worktrees spawned no git rev-parse --verify and no git rev-list --count, and reported the answers git gives. With the store's read disabled, the same derivation spawned both: one test id fails there and none fails at head.

  • reckon/crew/recovery_watch.py — the store, its bound, and _commits_beyond_base's read and write of it.
  • reckon/crew/recovery_review_subject.py — _resolve_commit takes a stored answer for a full revision, in-process and across processes.
  • tests/test_a_fresh_process_asks_git_only_what_moved.py — the six cases above.
