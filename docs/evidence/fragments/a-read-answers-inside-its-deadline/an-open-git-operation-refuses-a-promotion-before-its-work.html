An open git operation refuses a promotion before its work

Promotion now judges the checkout's git state at the top of complete, before the ledger is read or any store is opened. An open merge, rebase, cherry-pick or revert is refused there, naming the operation, instead of being reached inside the landing checks after the promotion had already done its work. In a serial sweep that late refusal delayed every later promotion by a whole promotion's time.

The zero is shown to mean something: on a clean checkout the same wrappers see the ledger read a promotion makes, and the run-store counter is shown to see a construction made directly in the test. With the early refusal removed, all five open-operation cases fail at 2 ledger loads and the two control tests stay green, which is the declared negative control.

On the all_debug partition, one arm at a time: the base arm (the node's write-scope tests as they exist at the base revision) ran 51 passed, and the head arm 58 passed, a delta of the seven added tests and no added failure. Across the 112 test files importing the changed modules, both arms report the same 38 pre-existing failures and 767 passes, with byte-identical failure sets.
