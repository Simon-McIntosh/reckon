A SPA poll waits for its previous answer

The three SPA pollers ran on window.setInterval, which fires whether or not the previous request has returned, so under load a slow /crew answer let polls stack. All three now go through window.startPoll in docs/ui/_shared.jsx, which schedules the next request only once the previous one has settled. The shell owns the single /crew poll and hands the live run list to CrewView as a prop, so a tab showing the crew view polls that route once per interval. The interval and the rendered data are unchanged.
