One discovery pass writes the persisted store once

The persisted index is one flat JSON blob, and metadata_index.record_discovery rewrote the whole blob for every file whose digest moved, so a first read re-serialised it once per discovered document. record_discovery now records into a batch that serve._discover_plans_uncached opens with begin_discovery around its document loop and flushes once with flush_discovery when the loop ends; a caller outside a pass still writes immediately, and the store's content after the pass equals the per-document writes'. tests/test_building_the_store_writes_it_once.py builds a 25-plan tree and counts _store_persisted calls in one first read over an empty store: two at the change (the flush and the covered-shape write from the tree walk) against 26 at the base tree (fb7d74b8), the negative-control log negative-control-base-tree.log ending EXIT=1 with 26 store writes in one read. Three fresh-process first reads per arm over one frozen corpus (the docs tree at fb7d74b8, 1326 HTML files, 186 plans), on one exclusive all_debug node (98dci4-clu-3142) submitted with sbatch and waited for in the foreground, give base median 78.804 s against head median 20.491 s — a 58.313 s saving, ahead of the 30 s required; each log names its revision, corpus, host and literal command, shows reckon.__file__ under its arm's tree, and ends EXIT=0 (measure-first-read.log).
