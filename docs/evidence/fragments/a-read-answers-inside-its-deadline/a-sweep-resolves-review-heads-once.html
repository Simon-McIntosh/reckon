A sweep resolves review heads and the ledger index once

Two regions now bound the repeated work. review_heads_resolve_once in reckon/crew/recovery_review_dispatch.py resolves each live run's reviewed head and tree once and serves the later readers of that run from the result; ledger.index_reuse in reckon/ledger.py builds the run index once for every ledger read inside it. A nested region joins the cache already open, so obligation_snapshot.fleet_state and the per-session slices obligation_snapshot.sweep builds share both: the slices read the heads the derivation resolved. Outside a region every call resolves as it did before.

Over a fixture of six live runs each owing a review of its head, one fleet_state resolved 36 reviewed heads before the change and 6 after — at most one per live run — and one sweep resolved 42 before and 6 after. The ledger index is built once per derivation; a registered worktree no record names drives the whole-ledger fallback so the count is taken over a read the fixture really makes. The snapshot's obligations equal the derivation's over the same state. Running the same test against a copy of the base tree fails both head counts (36 and 42 against a bound of 6), which is the negative control.
