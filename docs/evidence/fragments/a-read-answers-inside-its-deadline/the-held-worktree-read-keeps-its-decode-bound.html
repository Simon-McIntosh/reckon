The screen's fallback no longer re-implements the ledger's merge. _run_file_rows held a copy of the aggregate-plus-per-run union, the (completed_at, run_id) sort and the run-id-against-file check; reckon/ledger.py owns all three in load and _read_run. The merge is now one function, _merge_run_documents, called by load with refuse=True and by the new entry point run_rows_from_documents with refuse=False: the refusing mode loses the read to a document that disagrees with the aggregate or does not hold its own run id, and the non-refusing mode loses only that document, which is what a screen that must never drop a duty needs. The ordering key is one module-level promotion_order_key, used by load, by the index payload and by the merge. obligations.py now holds no union, no sort and no stem check.

The naming-route helper takes the run id rather than a path, so the file-name stem is not consulted outside the ledger either. The rule it applies is unchanged: a run names a tree by its node id or by the path its retention carries, and a run the index does not carry stays a candidate.

Every property the earlier section pinned still holds. The stale-record case — a run file rewritten in place after the index is published so it retains an inspected tree under a node id that names no tree — still answers as the whole-ledger scan. The refused-reader case still costs a read rather than a duty, with the refusal shown real before it is relied on. The read-only path still copies nothing: copy.deepcopy is 0, unchanged.
