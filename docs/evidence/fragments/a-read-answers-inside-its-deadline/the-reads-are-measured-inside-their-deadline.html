Roadmap, audit and discovery measured cold and warm against their deadlines

Both arms read one frozen corpus pinned at the base revision d249200c7. Head code b8a9fc24f2 and base code d249200c7 were extracted beside the corpus, and each arm got its own empty RECKON_HOME so its persisted index is its own. Roadmap and audit ran in one exclusive all_debug job (1315973) on 98dci4-clu-3141. Discovery ran in its own exclusive all_debug job (1315977) on 98dci4-clu-3144, as the brief directed. Each job ran one untargeted build invocation per arm, then three rounds of base then head for every read in it. Every invocation is a fresh process taking one cold sample and then one warm sample. No two reads ran at once.

Cold here means a fresh process with the arm's own persisted index already built by that arm's build invocation; it is not a first-ever read. The build invocations' samples are excluded from the medians for that reason, and the two that differ strongly are recorded here instead: head roadmap cold 50.834 s, warm 0.016 s, and head discovery cold 49.863 s, warm 0.181 s.

The frozen corpus is docs/ extracted from d249200c7 into a one-commit git repository (git revision 300648740565609298ec7966fd3d52342088b4cd). A repository root is required because a read at the base revision resolves git HEAD. The digest over docs/ minus .reckon is identical before and after each job, d54f2921d61b5dee54fda9ad96098a2b on 98dci4-clu-3141 and 3ddbff91a8686be0f6917f82421abd2e on 98dci4-clu-3144, so both arms measured a corpus that did not move. .reckon is excluded because a read at the base revision takes the project's recovery lock there.

The control holds: the base revision's cold roadmap exceeds the 30 s deadline

At d249200c7 the cold roadmap answers in a median 92.584 s against the MCP deadline of 30 s, and at b8a9fc24f2 in 7.481 s, so the comparison the section requires counts. The base arm's warm roadmap is 1.742 s, already inside the 2 s target: the deadline the head revision was asked to meet is the cold one, and the warm figure is reported without a claim that the base arm missed it.

Discovery: 6.568 s cold and 0.182 s warm at head, 73.319 s and 0.521 s at base

Discovery carries no target in the section. Both arms return the same inventory count, 866 items, so neither answered from an empty walk; the head payload is 2,978,494 bytes against the base arm's 2,849,793.

No targeted median is missed on this corpus, so no attribution is owed here

The three medians that carry targets all meet them: warm roadmap 0.015 s against 2 s, warm audit 1.999 s against 3 s, cold roadmap 7.481 s against 30 s. The only miss in the tables is the base arm's cold roadmap, whose excess is what the control is for.

An earlier run of this node, on a corpus pinned at head b4700c0d20, measured the head warm audit at 5.772 s and attributed its 2.772 s excess from kept profile dumps to roadmap._build_roadmap (3.39 s cumulative, 122 percent of the excess, introduced by 47d832767e0), within it roadmap._plan_authored_state (1.93 s, b93352322a6) and roadmap._section_scoped_edges (1.55 s with 2.25 M copy.deepcopy calls, 2f870c2bf6f), plus resources.resolve_resource (1.26 s). Those dumps are kept under measure/profiles/. That corpus carried more plans than the base-pinned one, so the same read costs 1.999 s here; the two figures measure different corpora and the earlier miss is not evidence that the warm audit misses on current documents. If the warm-audit deadline is to be held against a head-pinned corpus, that is a re-measurement, not a repair.

Logs, profiles and the literal commands

Logs are under measure/core/logs/ and measure/discovery/logs/ in the run directory, with the job transcripts at measure/core/sbatch.log and measure/discovery/sbatch.log. Every log is headed by its invocation line naming arm, read, round and code revision, then by # revision=, # corpus=, # host= and # command=[...], and ends in a bare EXIT=0. The profile dumps are measure/core/profiles/ (28 files) and measure/discovery/profiles/ (16 files).

The two jobs were submitted from the fleet node with env -u SLURM_JOB_ID -u SLURM_JOBID sbatch --partition=all_debug --exclusive --cpus-per-task=12 --mem=48G --time=00:50:00 --wrap "CORPUS_SHA=d249200c7 ONLY=core bash measure/run_measure.sh ..." and the discovery job the same form with ONLY=discovery and --time=01:00:00. Each arm's reads import their own code tree: every log carries reckon_under_code_tree=True beside the reckon.__file__ it imported.

No read answered from an error path: every sample carries ok=True and a payload size, and no log contains roadmap_error, discovery_error, audit_error or an exception line.

Suite fence: the node's write scope is this fragment only, so the suite command the fence names resolves to no test files for this node and no suite arm was run. Stating that is the alternative to inventing a test.
