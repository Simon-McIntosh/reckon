What this node did

It adds one guard module over whole crew verbs rather than over single functions. tests/test_a_crew_verb_costs_the_same_at_any_population.py drives a crew complete --gate not-run of a review run, a plan-review compose, and a crew complete --land of an implement run, each against a temporary crew home and ledger holding 20 and then 200 other runs, and counts the stat, scandir, listdir and glob calls each verb makes. Each other run is written to all three places a stage grew over: a ledger aggregate row, a per-run document under the ledger's runs/, and a crew run directory carrying a client harness home. Each measurement runs in its own interpreter, and within an arm the verb runs once before the counter is armed, so one-time costs are outside the count.

The growth is one ledger._run_snapshot walk of every runs/*.json document. A promotion writes its own row, which advances the write generation and the run directory's identity, so the read that follows the append cannot reuse the index's stamps and rebuilds as before. That is one walk per verb, not one per read: a warm read reuses. The walk is therefore the residual §64 deliberately left to a read whose generation differs, and §67's own design requires exactly one such read after the append.

The remedy is one function, outside this node's scope

With that walk answered from the stamps the index already holds, the same measurement is exactly equal at both populations — stat 1536, scandir 15, glob 13 at 20 and at 200 — in the review-promotion case. So the population dependence has one cause, and bounding it in reckon/ledger.py (record the append's own generation beside the index, or on a generation change read the run directory's names and open only the documents it has not indexed) makes this module pass with no change to it.
