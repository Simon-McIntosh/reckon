A tree the index leaves unresolved costs a lookup, not a pass over every row

The rows the naming screen could not read — a row carrying no run id has no namings entry — are the only rows that can name a tree the index leaves unresolved. _held_worktree_records_read now files those rows once into a second WorktreeRecordIndex, built from the same naming keys, and looks each unresolved tree up in it, in place of the nested pass that called _names_worktree for every recorded row against every unresolved tree.
