A plan write parses the plan once

One plan write now parses its document once and hands that parse to every pass. Before, write_state rebuilt the document per pass: the section-record splice built a soup, the body-resident comment census built another, the authored-child census built one per collection section it checked, and the record-carrying question built one more. On a real 517 KB plan one landing's write built five document-sized soups; on the node's fixture it built six.

A private _PlanDocumentParse holds a lazily built soup and structural scan for one text. write_state builds one and passes it to _splice_section_records, _body_resident_comment_counts, _authored_child_count, _reject_emptying_unparsed_section and _impl_is_carried_by_records. The section-record splice now runs before any meta edit, because it indexes the document by the source offsets that parse holds, so it must see the text the parse was built from. The passes it feeds occupy disjoint regions from the meta writers, so the bytes written are unchanged.

Measure

  • Fixture write, document-sized soups: 1 at head against 6 when the per-pass parse is restored (the negative control).
  • Real 517 KB plan write, document-sized soups: 1 at head against 5 at the base revision, counted with the same wrapper.
  • Bytes written: identical to the base revision's writer for the same inputs, on both the fixture and the 517 KB plan (cmp clean).
  • Focused plan-write tests importing the changed modules: 116 passed at base and 116 passed at head, no added failure.
  • Gate arms: base tests/test_staged_write_inventory.py 49 passed with two setup errors from the extraction carrying no git object store (scaffolding, not code under test); after arm 54 passed, exit 0.
  • Ruff check on the staged paths adds no finding against the base revision; both staged files are format-clean.

The node's test is tests/test_a_plan_write_parses_its_plan_once.py. It counts document-sized soups during one landing's write, asserts exactly one, and asserts the written bytes equal the per-pass writer's output for the same inputs.

The landing met a conflict against primary main, which had since added a head meta for descope reasons. Resolving kept both: the section-record splice still runs before the meta writers, because it indexes the document by the offsets the parse holds, and the descope-reasons meta write sits with the other meta writers. A diff of the merged file against the delivered head contains only additions, so neither side was discarded. At the merged head the node gate and the descope tests pass together (15), the focused plan-write arm passes (179), and the file adds no ruff finding against the upstream revision.
