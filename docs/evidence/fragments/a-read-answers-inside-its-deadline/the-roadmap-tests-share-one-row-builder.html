The three hand-built roadmap rows now come from the one shared builder

tests/roadmap_fixtures.py is the single plan-row builder the roadmap readers share. Three test files still rebuilt the same inventory row by hand, each carrying its own copy of the row's field set: tests/test_roadmap_endpoints.py, tests/test_roadmap_names_interrupted_runs.py and tests/test_roadmap_sprint_derivation.py. A renamed field in the inventory row meant one edit to the fixture and three silent drifts.

Each file's private _plan helper is deleted and every call site now calls plan_row. A row is not the same as a field set: the shared builder's defaults are not the deleted builders' values, so each call site passes the values its own builder set — impl, effort, gates, followups and title — rather than letting a shared default settle them. The builder gained an optional title and an optional decisions field for exactly that. The only field a row takes from the shared builder that the deleted ones did not carry is sprint, which every row now names as None; the roadmap readers ignore it.

One shared default silently changed a scenario's meaning rather than only its shape. The sprint derivation's "begun" case is a plan with progress but no active status, chosen so the progress branch alone answers it; plan_row defaults to active, which satisfies the status branch of _derived_sprint_state whatever the figure. That case now sets status="pending" and asserts both the member's status and its figure, so the branch under test is the one the case was written for.

A committed check, test_the_roadmap_tests_build_rows_through_the_shared_fixture, parses the three files and fails if any function in them returns a hand-assembled row or if one stops importing plan_row. It is the only source-reading invariant that lives outside tests/test_structural_invariants.py, so it belongs there: the module declares itself the one place in the suite where reading source is the point, and the check constrains three other files rather than the one it sat in. It reads each module's parsed tree rather than its text, so the import is found by module and name and a parenthesised or multi-name import — which ruff format emits once a second name is imported — still counts instead of reddening the guard on a mechanical reformat. The deduplication is therefore demonstrable by a test rather than only by a one-off mutation.

Measured over the six consumer files plus tests/test_structural_invariants.py. Both arms run the same 81 test ids: 80 passed, 1 failed, EXIT=1 at the base revision and at head, the single failure being test_only_the_shared_parser_calls_fromisoformat, which fails on reckon/project_brief.py:_parse_utc at base as well and is not this change's. The id set is otherwise unchanged: the guard's id moves from the consumer file to tests/test_structural_invariants.py.
