The three hand-built roadmap rows now come from the one shared builder

tests/roadmap_fixtures.py is the single plan-row builder the roadmap readers share. Three test files still rebuilt the same inventory row by hand, each carrying its own copy of the row's field set: tests/test_roadmap_endpoints.py, tests/test_roadmap_names_interrupted_runs.py and tests/test_roadmap_sprint_derivation.py. A renamed field in the inventory row meant one edit to the fixture and three silent drifts — each local copy would have gone on producing the old shape.

Each file's private _plan helper is deleted and every call site now calls plan_row from the shared fixture. The builder gained one optional field, decisions, which the endpoint rows need so a plan can carry an open decision; it follows the fixture's existing optional-field pattern and changes nothing for the other callers. No test assertion changed — only where the row comes from.

Measured over the six files that consume the shared builder. At the base revision the six files pass 74 test ids; at head the same six files pass the same 74 ids, collected identically and compared as sets. The negative control is what gives that number its meaning: renaming one key inside the builder's row dict (slug to slugx) makes all six files fail together, not three of them — the proof that every one of them builds its rows through this one function.
