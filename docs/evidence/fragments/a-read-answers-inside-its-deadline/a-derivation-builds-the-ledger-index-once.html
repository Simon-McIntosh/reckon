A derivation builds the ledger index once and hands it to every reader

Inside one fleet_state two readers reach the same ledger file: the held-worktree screen asks for the refreshed rows through the registered checkout's root, and the utilisation reader that attributes a run's overrun asks through the default root. Both name one ledger file, but the run index's reuse cache keys on the root as it was spelled, so root=<checkout> and root=None missed each other and the index was built twice for one derivation's answer.

reckon/crew/obligations.py now resolves that root once: _ledger_read_root compares the two spellings with ledger.ledger_path(...).resolve() and passes no root when they name one file, so both readers land in one reuse region, and passes the checkout root unchanged when the checkout's state is not the registered one, so a checkout whose ledger is genuinely elsewhere still reads its own. The reader inside the region sees the same rows either way.
