The screen was the defect the bound was hiding. It read the ledger's last-published index, gated only on the aggregate's identity, so a run file edited after publication kept its old row: a run that starts retaining another node's tree kept its node id, named no inspected tree, and was dropped, and the read answered with the earlier record. The screen now reads the rows from the reader that stats every per-run document once and re-decodes one only when it has moved, so no record is older than its file, and the same rows supply the candidates.

The stale-record case is asserted directly. After the index is published, one run's file is rewritten in place to retain an inspected tree under a node id that names no tree; the bounded read must answer exactly as the whole-ledger scan, which puts the tree with the later record. The negative control serves the screen the last-published snapshot instead of fresh rows, and that case then fails.

The screen fails open. The namings it screens on come from the merged ledger's reader, and a reader that refuses or fails would otherwise leave it with no namings and no rows, dropping every run and answering with nothing — which is not a bound but a lost duty. A refused reader now costs a read instead: every run stays a candidate and the aggregate's own rows and the per-run documents are read for themselves, ordered by the merged reader's own key, so a tree two of them name still goes to the later run. Two tests that refuse that reader by monkeypatch and expect the answer from the per-run files fail without this and pass with it.
