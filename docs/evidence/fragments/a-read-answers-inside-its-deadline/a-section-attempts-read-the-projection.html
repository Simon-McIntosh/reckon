A section-attempts read decodes only its projection

Change. mcp_views.section_attempts_by_plan takes its history rows from ledger.picker_runs instead of ledger.load, so a warm read decodes only the projection the index keeps beside each payload. section and failure_classification joined ledger._PICKER_FIELDS, and ledger._RUN_INDEX_VERSION moved from 3 to 4 so each host rebuilds its index once with the wider projection. ledger.load gained a picker_only mode that reads the projection on the index path and projects what the aggregate returns on the cold path, so picker_runs keeps the one read entry point every existing attempts-read test substitutes.

The index is now named by its version. Raising the version alone was a defect of mine, not of the read: many processes on a host run older code — a session server that predates a release, the producer, peer agents — and they shared one index file whose drop-on-mismatch guard makes each version destroy the other's tables on its first read. Two readers alternating then paid a full rebuild on every switch (25–80 s here), until every process had restarted. _run_index_path now returns ledger-{identity}-v{version}.sqlite, so each version keeps its own file and the guard remains the refusal for a same-named file. The retention sweep in reckon/crew/gc.py globs ledger-*.sqlite and still matches the versioned name; the two other readers of the path (mcp_views.section_attempt_count, the index stamp) call the function and move with it.

The four cases hold. tests/test_section_attempts_read_the_projection.py checks that the projection agrees with _group_section_attempts over full rows (a failed row keeps its classification, a non-executable row never becomes an attempt); that a call never reaches _index_payload with picker_only=False; that an index recorded at the previous version inside a version-named file is rebuilt with section restored (the stored projection is blanked as well as the version rolled back, so only a rebuild can bring the field back); and that a reader at the previous version and a reader at the current one alternate twice over one ledger without either rebuilding — counted on _read_run, which a rebuild must call for every run document it re-decodes.
