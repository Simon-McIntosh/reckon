A promotion reads only its own run's rollout home

_harvest_lane_receipt in reckon/crew/promotion_release.py now passes the promoting run's own id to rollout.read_rollout_receipt, taking it from the live pointer record the promotion already holds. That argument confines the lookup in run_home_rollout_paths to one run's harness home instead of iterating every run directory under the crew home to find the session the promoting run already owns.

The measure counts the directories the receipt lookup stats over a temporary crew home whose promoting run and its peers each carry a harness sessions root. With 200 other runs and with 20 the count is the same, and the receipt reports the promoting run's own context window rather than a peer's. The negative control drops the run_id argument, and the same measure then reads 43 stats with 20 peers against 403 with 200, so the counter demonstrably sees the population rather than a constant. The base arm is the set of test files importing reckon.crew.promotion_release or reckon.crew.rollout at the base revision; the head arm adds this node's test. The paid-lanes scan, which names no run, is unchanged.
