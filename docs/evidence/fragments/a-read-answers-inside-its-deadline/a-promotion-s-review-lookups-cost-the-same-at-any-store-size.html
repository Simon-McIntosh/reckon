A promotion's review lookups cost the same at any store size

A one-shot crew complete starts with no in-process review-store index. The index it loads from the node-local cache was re-derived from a listing of the whole store on every cold load, so each of the two review reads a promotion makes — once under the review gate through classify_pointer, once through select_review_for_head — paid a stat per stored record.

The persisted index document now records the store directory's stat identity at the moment its entries were read. A reader that loads it adopts the entries as they stand when that identity is still current, because no record has been added, removed or atomically replaced since — which is every write the store's own writers make. A document whose store has moved is listed and updated as before, and the whole-store revalidation stays for an index this process built or updated itself, which is the case where a record rewritten in place is the change it exists to see.
