The read-only region refuses a mutation

A read-only region handed out the memo's own stored value, so a caller that mutated a document it read would silently corrupt the process-wide memo for every later reader, and no test held the contract. The guard is the region handing out values on which a mutation raises — the first of the two the section allows — rather than a test running the derivation over frozen values: the region is where a future caller meets the document, so the refusal protects every caller and not only the ones a test reaches, and it protects the memo rather than reporting its corruption after the fact. file_memo stays the memo's owner and is extended, not forked.

Inside a region memoized now hands back a read-only view of the parsed value: _ReadOnlyDict, _ReadOnlyList, _ReadOnlyTuple and _ReadOnlySet, each rebuilt once to carry the value's own members — so dict(value), json.dumps, equality and every read are unchanged — while every mutating method (__setitem__, append, pop, sort, add, …) raises TypeError. Containers wrap recursively, in a tuple's members and in a frozenset's alike, so a change anywhere inside a document is refused. The view is built once per document per region through _handout, not once per hand-out, so the read-only path still copies no value and the stored memo is never handed out directly; a caller that must mutate asks for mutable=True and receives a mutable copy.

Copying stays the way to a mutable value. Every view carries __copy__ and __deepcopy__ returning plain, fully mutable containers, so a caller that lets what it reads outlive the region — the held-worktree read does, since it returns its result from inside one — can change it. The refusal reaches only the view, never a copy of it, and the memo and the view copied from are left untouched.
