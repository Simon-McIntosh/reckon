A file's identification is reused across reads

Every discovery read re-identified every file it walked — hashing the bytes and parsing the meta head — although nothing had changed between reads. identify_resource in reckon/resources.py now memoises each file's identification on its own stat signature, path, mtime_ns and size, through the shared file_memo helper, so a warm read stats each file and reuses the result; only the files whose signature moved are hashed and parsed again, an unstattable file is identified uncached so its error path is unchanged, and memo hits keep the helper's defensive copy. In tests/test_identification_is_reused_across_reads.py a wrapped _identify_resource shows two reads of an unchanged tree identify each file once in total, and after one file's bytes change only that file is identified again on the next read. Under the declared mutation — dropping the memo so every read identifies every file — the same test fails (EXIT=1).
