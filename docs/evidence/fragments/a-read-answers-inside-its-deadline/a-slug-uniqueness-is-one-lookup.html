A slug's uniqueness is checked against one held index of its root

_canonical_identity_is_unique answered whether a sibling claims the same identity by listing its root directory and identifying every file there on each named resolve, so a read resolving many slugs re-identified the whole plan population per resolve. It now reads one identity index of that directory — each sibling's type, slug and archived flag — keyed on the directory's listing and each sibling's stamp, held for the read and rebuilt only when an entry moves or a sibling is written. A read of 20 resolves over 24 plans identifies at most 24 siblings (was 480 under the declared mutation, which fails the bounded-count case); a tree where two files claim one slug is still refused naming both; warm roadmap over the docs tree at the pinned revision is 2.575 s at head against 19.889 s at base. Write paths: reckon/resources.py, tests/test_a_slug_uniqueness_is_one_lookup.py.
