§17 — a docs tree outside a repository asks git once

reckon/serve.py _git_head remembers a root that git reports as outside any repository, keyed by the root's path and directory stamp (_GIT_OUTSIDE_MEMO). A root with no .git was resolved by git once, failing with exit 128, and nothing kept the answer, so a lifecycle audit paid one failed git rev-parse HEAD per plan. Now the first such answer is recorded and every later age or HEAD lookup for that root returns no commit without starting git. A root whose .git moves changes the stamp and is resolved afresh; every root inside a repository is resolved and reported exactly as before.

The answer is remembered only when it is git's own: _run_git_head keeps three outcomes apart — a resolved commit, git's exit whose stderr names “not a git repository”, and every other failure — and only the second is durable enough to record. A timeout, a spawn error, or any other exit says nothing about the tree, and recording one would freeze a wrong answer into the long-lived server, because a docs directory below its repository's root has no .git at that level and would then read as untracked for the rest of the process's life. The shared _run_git query keeps its contract for its existing callers, so the one spawn a HEAD lookup makes is made in the new helper.
