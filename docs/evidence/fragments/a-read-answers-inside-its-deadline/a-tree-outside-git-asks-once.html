§17 — a docs tree outside a repository asks git once

reckon/serve.py _git_head remembers a root that git reports as outside any repository, keyed by the root's path and directory stamp (_GIT_OUTSIDE_MEMO). A root with no .git was resolved by git once, failing with exit 128, and nothing kept the answer, so a lifecycle audit paid one failed git rev-parse HEAD per plan. Now the first such answer is recorded and every later age or HEAD lookup for that root returns no commit without starting git. A root whose .git moves changes the stamp and is resolved afresh; every root inside a repository is resolved and reported exactly as before.

The answer is remembered only when it is git's own: the HEAD lookup keeps three outcomes apart — a resolved commit, git's exit whose stderr names “not a git repository”, and every other failure — and only the second is durable enough to record. A timeout, a spawn error, or any other exit says nothing about the tree, and recording one would freeze a wrong answer into the long-lived server, because a docs directory below its repository's root has no .git at that level and would then read as untracked for the rest of the process's life.

Every git process the module starts goes through one query, _run_git, which now takes report_failure — false by default, so every existing caller keeps exactly its current return value and its current warning. A caller that must classify the exit asks for the completed process instead, and the HEAD lookup uses that to separate git's own verdict from every other failure; a timeout and a spawn error still return None for every caller and so cannot be mistaken for it. One spawn path and one ten-second timeout remain, and the duplicated helper this replaced is gone. That query also pins LC_ALL=C on the spawn while leaving the rest of the environment alone: the verdict is read from git's stderr, which git translates when the operator's environment asks for a language, and a translated message would have read as a different failure and left an outside root asked again on every plan. The environment handed to git is asserted as it is passed, so the check does not depend on any catalogue being installed on the host.
