The audit read takes its resources from the shared scan

_audit enumerated its plans with its own tree walk, sorted(docs_dir.rglob("*.html")) and a direct identify_resource per file, beside the scan the rest of the read reaches through iter_resources. The read now runs inside one resource_scan_scope, so it walks the docs tree once and reuses the scan's identification. A strict caller reached inside the scope — doccheck.audit_lifecycle through _iter_doc_files, which must still raise on an invalid file — no longer buys a second walk: iter_resources raises ResourceCollision from the record of files the shared scan dropped, so its exception type and message are unchanged. That record is keyed by (docs_dir, project) as the scan cache is, because one scope can span several docs trees — promotion resolves resources across more than one — and a reader must take only its own tree's drops rather than raise on a foreign path. In tests/test_the_audit_shares_the_scan.py a wrapped resources._scan_resources is called once for one audit read of a temporary corpus (9 at base), and the audit's findings are equal to their base rows for a clean corpus and for one carrying an invalid resource path; a direct walk computed in the test finds exactly the invalid files the audit reports. Under the declared mutations the arms are red: restoring the audit's own rglob walk gives 2 failed, 4 passed, EXIT=1, the walk-count case reporting 9 walks (negative-control-own-walk.log); dropping invalid files without recording them gives 3 failed, 3 passed, EXIT=1, the audit losing its invalid-resource-path finding (negative-control-unrecorded-drop.log); and a record held as one list for the whole scope gives 1 failed, 5 passed, EXIT=1, a strict read of the second docs tree raising the first tree's message (negative-control-single-drop-record.log). The 27 test files reaching the audit give 355 passed / 0 failed at head and at base, apart from the new file; ruff check and ruff format --check add no finding and no format delta on reckon/mcp.py and reckon/resources.py.
