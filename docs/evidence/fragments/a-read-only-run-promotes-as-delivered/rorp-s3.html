A claims review record passes the check on the run's verdicts

What changed. review_record_refusals in reckon/crew/review.py asked every parsed record for the six landed-node text scores, exempting only the figure rubric. A claims review scores none of them: it re-runs the report's top claims and records a verdict per claim. So both claims records stored for this session's census and prototype reviews were refused for missing scores, and each had to be repaired by hand before it could promote.

Two edits, one rule. The exemption is now the declared set ITEM_VERDICT_RUBRICS — the claims, figure, health, plan-review and plan-design rubrics — so a rubric that measures verdicts owes no text scores and a rubric added later is exempt by being listed there, not by a second check beside the first. The delivery contract then holds a claims record to the measurement it does owe: a verdict for each of the ranks 1..CLAIMS_REQUIRED and one for the report's own summary line. CLAIM_VERDICT_FIELDS reads either spelling a record may state its per-claim verdicts under (claims, and the claim_verdicts a hand-written record uses), so a complete record is never refused for the key it chose.

The stored corpus decides whether the new refusal costs an answer. Every claims record in docs/state/reckon/reviews (23 of them) was run through review_record_refusals at the base revision and at this head: none is newly refused, one (the census record) newly passes, and the 17 refused in both were refused before for reasons this change does not touch. The one record that the first attempt did newly refuse — r-20261020T125655924881, a complete review stating its verdicts under claim_verdicts — is why CLAIM_VERDICT_FIELDS exists: a refusal there would have reported a review that answered all three claims as one that answered none.

Not done here. The stored census and prototype records are copied into the test as fixtures rather than re-derived from the run directories, the claims-rank rule assumes the report's ranks start at 1 as the claims prompt asks. A record whose reviewer ranked its claims from zero would be refused naming claim 1; no such record exists in the store.
