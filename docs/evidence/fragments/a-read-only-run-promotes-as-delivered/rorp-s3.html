A claims review record passes the check on the run's verdicts

What changed. review_record_refusals in reckon/crew/review.py asked every parsed record for the six landed-node text scores, exempting only the figure rubric. A claims review scores none of them: it re-runs the report's top claims and records a verdict per claim. So both claims records stored for this session's census and prototype reviews were refused for missing scores, and each had to be repaired by hand before it could promote.

Two edits, one rule. The exemption is now the declared set ITEM_VERDICT_RUBRICS — the claims, figure, health, plan-review and plan-design rubrics — so a rubric that measures verdicts owes no text scores and a rubric added later is exempt by being listed there, not by a second check beside the first. The delivery contract then holds a claims record to the measurement it does owe: a verdict for each of the claims it was asked to re-run and one for the report's own summary line. CLAIM_VERDICT_FIELDS reads either spelling a record may state its per-claim verdicts under (claims, and the claim_verdicts a hand-written record uses), so a complete record is never refused for the key it chose.

Repair: one rule, asked by both readers

A review found that the first cut split the claims measures in two. The delivery check restated the completeness rule beside the promotion reader's copy, and it read the claim_verdicts spelling that neither the store nor the promotion rule reads. A record stating its verdicts under that key therefore passed crew check --review and was then refused as incomplete at promotion; in the other direction a record whose two claims carried the same rank read complete to promotion while the check refused it. A rule must not answer differently depending on which reader asks.

claims_verdict_refusals now calls _claims_missing_measures — the declared single owner, imported at call time because its module reads this one — and does nothing but word each measure it reports from CLAIMS_MISSING_MESSAGES. The second spelling is gone with the second rule, so nothing is admitted here that promotion will refuse.

Repair: the spelling is folded once, at the read boundary

Calling the owner directly closed the split but left it reading only the parser's claims key, so a stored record that states three verdicts under claim_verdicts was refused as incomplete by both readers — a review that answered every claim it was asked about, refused twice. The folding belongs at the boundary the readers share, not in either of them.

with_canonical_claims folds the hand-written spelling onto the parser's key once. The store's read path applies it, so every promotion consumer — the classifier, the gate, the obligations pass — asks the same field, and the delivery check applies the same function before calling the rule. One fold, one rule, one answer.
