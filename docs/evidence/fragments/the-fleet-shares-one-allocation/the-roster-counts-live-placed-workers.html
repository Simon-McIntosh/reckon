The roster counts live placed workers

occupying_the_reservation now takes a seat from the recorded process rather than from the placement alone: a placed pointer holds a seat when its recorded worker or supervisor pid is alive, or while it is still launching — no pid recorded yet, and its current attempt inside the launch window a fresh dispatch gets. A placed run whose worker has exited holds no seat, so a finished-but-unpromoted run, a blocked run awaiting resume, and a run waiting on an external condition with no live process count for nothing. Liveness is read through reckon.crew.runs.process_alive, the reader the live classifier consults, reached through its own module so a substituted probe is honoured; an unreadable probe or launch clock holds the seat rather than freeing it on no evidence. The cap of 25 is unchanged.
