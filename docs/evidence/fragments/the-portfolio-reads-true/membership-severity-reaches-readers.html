Lifecycle severity reaches the audit readers

The MCP lifecycle consumer and the reckon audit table each read a finding's own severity, so a shipped plan an open sprint lists reaches both as info rather than the warn a flag-derived rule assigns. tests/test_lifecycle_severity_reaches_readers.py passes EXIT=0: the MCP read and the CLI table both report info, warn and error for the shipped/mismatched/missing-impl rows, and the audit exit code stays 1. The negative control — the MCP consumer deriving severity from the flag — reports the info row as warn and fails.
