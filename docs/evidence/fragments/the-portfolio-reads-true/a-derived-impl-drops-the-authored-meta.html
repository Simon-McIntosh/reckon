A derived impl drops the authored plan-impl meta

What changed. write_state (reckon/_plan_html.py) gains drop_authored_impl_meta. When the state's impl_source is declarations or computed and the opt-in is set, the authored plan-impl meta is removed from the document. The derived figure is the server's, so it is never written back as an authored one. The default is unchanged, so a round-trip and a write carrying no content change move no bytes.

The four full-state writers pass it. Each holds a full read_state, which the opt-in needs in order to know whether impl is derived: the store's write path (reckon/_store.py, which edit_plan's state ops use), its text-replacement path (_replace_plan_text), the plan POST handler (reckon/serve.py), and the tag backfill (backfill_tags_from_preimage, reckon/tags.py). apply_archive_candidates passes only {"archived": "1"}, so it keeps the meta; that plan loses it at its next full-state write.

The stale figure is what makes it matter. Measured on a plan declaring {s1: done, s2: implementable} with one done record, the declarations derive 0.5 while an authored plan-impl of 0.67 sat in the file. Before the change, doccheck reported impl-meta-stale and a write_state round-trip returned the 0.67 line untouched — every write path rewrites only the names it is given. After the change the first full-state write leaves no plan-impl meta and the audit reports no impl-meta-stale.

The no-change path still moves nothing

A patch through edit_plan that carries no content change leaves the file's bytes identical, because the store's existing comparison of the parsed state (stamps excluded) still finds the two reads equal: a derived figure is unaffected by whether the authored line is present. write_state(text, read_state(text)) without the opt-in also returns the stale-meta text byte for byte, so a reader-only serialise is untouched.
