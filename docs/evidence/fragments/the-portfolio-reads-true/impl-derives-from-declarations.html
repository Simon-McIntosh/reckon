A plan derives its impl from the section declarations when its records fall short

What changed. A plan's served implementation fraction now has three sources, ordered. Records that cover every declaration answer with the effort-weighted figure, sourced computed as before (reckon/_plan_html.py). Records that do not cover the declarations fall back to the declaration count — done over done plus implementable, with deferred excluded — sourced declarations, a value added to the schema's impl_source enumeration (reckon/_schema.py) and to the plan-review reader's documentation (reckon/crew/plan_review.py). A plan carrying no declaration keeps its authored plan-impl meta, sourced authored. A plan with an implementable declaration therefore never reads 1.0 while its records are partial.

The audit agrees the file with the server. reckon audit-doc now reports impl-meta-stale at warn (reckon/doccheck.py) when the plan-impl meta on disk differs from the served figure by more than 0.01, so a reader of the file and a reader of the server agree once the next write lands.

The store's authoring refusal is unchanged

The refusal at reckon/_store.py still fires only once the records cover the declarations, so a coordinator's set impl on a partially recorded plan is accepted — the served figure is governed by the declarations regardless, the disk write is elided by the idempotency guard, and the audit reports the meta stale. Nothing retires: no prior value or code reported a figure derived from declarations.

Superseded expectations, updated in place

Four existing tests asserted the behaviour this section supersedes — that a partially recorded plan keeps its authored figure with source authored. Each now asserts the declaration-count figure instead:

  • tests/test_impl_needs_every_section_recorded.py — its partial plan (three declarations done, one implementable, one record) now reads 0.75/declarations.
  • tests/test_impl_stays_authorable_while_records_are_partial.py — the write is still accepted, but the served figure is 0.5/declarations.
  • tests/test_bookkeeping_earns_no_review.py — a plan with declarations and no records reads 0.0/declarations, and coverage stays whole.
  • tests/test_plan_review_store.py — a derived plan's plan-impl meta is inert: the edit lands in the file but does not move the served figure.
