A worktree with unique commits releases after its commits are pinned

Change (commit 553f23f6a). garbage_collect (reckon/crew/routing.py), the function crew gc calls, gains pin_unique_commits (default false). When requested, a dirty worktree that no live run claims and whose commits beyond the integration head were measured with no patch-equivalent on it is released through the existing residue-preserving path after _pin_archived_commits points refs/reckon/archive/<worktree directory name> at the worktree head, and the ref is recorded as archive_ref in the classification record beside residue.patch. The pin runs before the removal and before the residue is written, so the commits stay reachable however the rest of the residue step ends. An occupied ref that resolves to a different commit is refused rather than overwritten. The reclaimable flag on the row honours the same predicate the removal branch uses, so a dry run with the option reports those rows as reclaimable. Without the option nothing changes: such a tree stays with classification dirty and reclaimable false, exactly as before.

The two review follow-ons also land here. The partial report a sweep stopped mid-pass emits now carries refused_worktrees beside removed_worktrees: a tree whose removal was attempted and did not complete is recorded in its own list at the moment it fails, so a reader no longer recovers it by walking the classifications. And garbage_collect re-raises TypeError, AttributeError and NameError untouched — a defect in the sweep's own code surfaces with its traceback instead of reading as an ordinary refusal with ok: false.

New tests (tests/test_gc_pins_unique_commits_before_release.py, each in a temporary repository with RECKON_HOME under tmp_path):

  • a dirty tree with one commit that exists nowhere else is released with the option: the row names refs/reckon/archive/<name>, the worktree directory is gone, the commit resolves through the ref and still carries its file, and the residue classification records the ref beside the patch;
  • the same tree without the option stays: classification dirty, reclaimable false, no ref, directory and its file intact;
  • an occupied archive ref is refused, the earlier pin still resolves to what it did, and the tree stays — with the row named in the partial report's refused list;
  • a sweep that releases one tree and then fails on a locked one exits carrying removed_worktrees with the released tree and refused_worktrees with the locked one, neither conflated with the other;
  • a TypeError, AttributeError or NameError raised inside the sweep reaches the caller as itself, not as a sweep refusal.
