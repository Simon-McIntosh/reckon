An unmeasured commit list reads as unmeasured

Change (commit 8f47851d). _inspect_workspace (reckon/crew/routing.py) compared a worktree's commits against the integration head only when release_residue, so every other caller — the promotion audit row among them — received non_equivalent_commits: [] and patch_equivalent_commits: [] for a tree whose commits were never compared. A divergent dirty tree therefore read as carrying no commits of its own, an unmeasured absence indistinguishable from a measured zero. Both fields are now null when the commits beyond the integration head were not measured, and the sibling commits_unmeasured_reason names which of four conditions held: this caller did not ask (release_residue false), the head is an ancestor of the integration head, the tree is clean, or the comparison could not run. A measured row keeps both lists, even when they are empty. _commits_beyond_merge_base now returns None rather than an empty list when git cherry cannot run, so an unreadable tree is still kept for its commits rather than released, and the same null contract reaches the unavailable-tree row.

Readers. A grep of reckon/ for both field names finds no reader outside the writer: the two gc call sites consume the classification, which is computed from the internal list and is unchanged by the null contract; the promotion call sites read classification and reclaimable. The fields reach readers only through serialized report rows, where null is now the honest value.
