A resume refuses a session over the lane's window

A resumed turn re-sends the session's whole context, so a session grown past the lane's published input window dies at the endpoint with its attempt file already open: the worker exits having done no work, and the delivered manifest it leaves reads stale to promotion. Every resume now reads the session's own measurement before it is planned. The count is the run's last recorded request input — the charged input of the final request its stream reports, cache read included, because that is the context a resumed turn carries — and the window is the smallest figure the lane publishes: usable_input_window (already net of the launcher's output reservation) and effective_input_window (the lowest input the lane's endpoint is recorded refusing), the same pair the dispatch-time context-fit check gates on. When the count exceeds the window, the resume is refused before the plan is built and before anything is written, naming both figures and the lane and giving a fresh repair node as the remedy; the run keeps its classification, its phase and its manifest, and gains no attempt file.

Both doors read the same guard. A hand-typed crew resume reaches resume_plan directly; the review-repair reflex resumes through the sweep's _resume, which is that plan plus the attempt's files and the turn it records; and the sweep's dry run consults the same gate through _launcher_refusal, so a preview reports the refusal a real resume would raise rather than a resume it would not. The gate fails open on absence in both directions: a lane publishing no window and a run whose stream recorded no usage each refuse nothing, because an unmeasured session is not a session known to be too large.

Six cases pass in tests/test_resume_refuses_a_session_over_the_window.py against a temporary RECKON_HOME, proving the real crew home untouched: a session inside the window resumes through both doors (the reflex writes resume-1.jsonl and records the turn), a session over it is refused with the count and the window named by both doors with no resume-* file and the pointer unchanged, the dry-run prediction matches the real refusal's type and message, and both fail-open directions hold. The last-record reading is exercised in both cases with an earlier request on the other side of the window, so a guard reading the first or the largest figure would fail the case. The two existing resume tests (test_direct_resume_needs_an_observed_death.py, test_resume_sweep_needs_an_observed_death.py) and the dry-run parity test keep passing, 18 cases at base and 24 at head.

The declared mutation — remove the window check — takes the same test file to 3 failed: the over-window sessions resume, and the reflex case fails because its attempt opens and its launcher is called (EXIT=1, control log kept). This gate measures only this node's own change over a bounded arm of the tests that reach the resume doors; a full-suite arm was started and abandoned — the suite is 10,367 cases and the shared node sat at load ~45, so a full arm projects to hours against this node's fence. Verifying the merged result at the suite scale belongs to a separately dispatched test node.
