§5 — Paid-backend headroom is published as one document pre-flight reads

The defect. A metered account's headroom was read only when someone ran a pre-flight or a dispatch, and it was read from three homes that could each be a day old: a run's committed or live lane_receipt, a session rollout, and the rate_limit_event windows a served stream carried. Two readers recomputed the position independently, and because one reading's windows were taken as a whole, a source that had never carried the five-hour clock blanked the week it had measured — every field turned unknown at once, which cannot be told apart from a genuinely empty window.

What landed. reckon/crew/paid_lanes.py composes one document per account from those same three recorded homes, carrying for each of the five-hour and seven-day windows its utilisation, reset time, burn multiple, projected exhaustion, the source the figure came from and when it was observed. Reconciliation is per window by recency: a newer reading speaks only for the windows it actually carried, so a fresh stream reading at 40% holds the five-hour clock while an older receipt still holds the week the stream never reported. The two windows are therefore resolved independently, which is what stops one failed precondition from blanking the other. A window no source resolved is an explicit absence (state: "unknown", every figure null) and never a 0.0, which would read as a measured empty window. A figure whose own observation is older than the staleness horizon keeps its value and is marked stale: true for that window alone.

python -m reckon.crew.paid_lanes --once writes the document atomically through a sibling temporary file and an os.replace, so a reader that opens it mid-refresh sees the previous document or the new one and never a truncated account list whose missing accounts would look like real absences. budget.preflight takes its per-backend and per-group figures from that document when the caller names it and supplies no reading of its own, so both come from one reconciled record rather than two readers; an explicit windows argument still wins where a caller supplies one.

§5 — The production pre-flight reads the published document, falling back per backend

The defect. budget.preflight had a document arm, but it ran only when the caller injected no reading of its own (windows is None and (document or document_path) is not None). Both production callers — reckon crew preflight and the MCP budget view — always build a reading from recorded_windows and passed it as windows, so the arm never executed for either. The published document was reachable only from a caller that named it and injected nothing, which no production path did: the document the whole section exists to publish was inert in the two places that run.

What landed. The two callers now name the document at budget.published_document_path() — the environment override, then the file under the crew home, then the document's own default — and budget.preflight merges the document and the caller's recorded reading per backend. A backend the document carries a fresh reading for is paced from the document; every other backend keeps the reading the caller recorded. A backend therefore falls back for itself alone when the document is absent, unreadable, silent about it, or holds only a stale figure for it.

Age is derived at read time, not baked at composition. The document records each figure's age as of the moment it was published, and a reader that echoed that figure would report a reading an hour old as twenty seconds old. The observation time travels with the figure and does not drift, so the merge re-derives each age from it against the moment of the read, at both the figure and the reading level, and judges freshness on the re-derived value. A document published past the staleness horizon therefore falls back even though the age written inside it is small.

The path resolves through the crew home, so a pre-flight reads its own tree. published_document_path() prefers the shared environment override, then the document under RECKON_HOME, and only then the document's own HOME-based default. The crew home is what a fixture isolates, so a test's pre-flight reads its own temporary tree rather than a document the workstation happens to hold under the operator's real home — which would report on the machine rather than on the fixture.

Per-backend, not per-document. One stale account must not drag a fresh sibling down with it, and one fresh account must not vouch for a stale one. Each backend's newest document observation is judged against the document's staleness horizon on its own, so the fallback is scoped to the backend it applies to.

Only the fields a reading actually produced are named. When the document and the records both miss every backend, the report carries no window_sources block and no group grows a source, so a reader sees an addition only where something was read; this is also what keeps the pre-flight's existing field set unchanged for a report with no reading at all.

§5 — The publisher and the pre-flight resolve the document path through one resolver

The defect. The reader and the publisher had two rules for one path. budget.published_document_path() preferred the environment override, then the document under RECKON_HOME, then the HOME-based default; paid_lanes' own resolution preferred the override and then went straight to the default, with no crew-home step. What landed. reckon.crew.paid_lanes.document_path() is the one resolver, with the reader's four-step order: an explicit argument, then the DOCUMENT_ENV override, then $RECKON_HOME/paid-lanes.json when RECKON_HOME names a tree, then the default. budget.published_document_path() delegates to it and keeps no second rule, so the file the publishing command writes is by construction the file every pre-flight reads. The crew home is what a caller isolates to run against its own tree, so the resolution an isolated run performs is the same one a production run performs, one step shifted.

§5 — The refresh deployment installs a user service and timer

The gap. The document is composed and read, but nothing republished it on a clock: it was only as fresh as the last dispatch or pre-flight that happened to run. §5's own record named the five-minute refresh as the remaining step, and the lead fixed the design — a systemd user timer, installed by reckon the same way the crew watch unit is.

What landed. python -m reckon.crew.paid_lanes --install-timer now writes two units under the user's systemd directory (XDG_CONFIG_HOME/systemd/user, defaulting to ~/.config/systemd/user) and brings the timer up. The service is a Type=oneshot whose ExecStart is the running checkout's interpreter with -m reckon.crew.paid_lanes --once and whose WorkingDirectory is the checkout root, so the unit runs the tree it was installed from even where the package is not installed into the interpreter's environment. The timer activates that service (Unit=reckon-paid-lanes.service) at OnBootSec=1min and OnUnitActiveSec=5min. The command then runs systemctl --user daemon-reload and systemctl --user enable --now reckon-paid-lanes.timer.

Idempotence is the property the definition is compared on. Each unit is written only when its rendered bytes differ from what is on disk, and the manager calls are made only when something changed — so a re-run with an unchanged definition writes nothing and issues no manager command, which is what keeps a live timer from being restarted. A changed definition (in practice, a different interpreter path) rewrites the units and reloads. --help now lists --install-timer, and the flag itself installs then exits without publishing.
