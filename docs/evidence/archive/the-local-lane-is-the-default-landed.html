§5 — Paid-backend headroom is published as one document pre-flight reads

The defect. A metered account's headroom was read only when someone ran a pre-flight or a dispatch, and it was read from three homes that could each be a day old: a run's committed or live lane_receipt, a session rollout, and the rate_limit_event windows a served stream carried. Two readers recomputed the position independently, and because one reading's windows were taken as a whole, a source that had never carried the five-hour clock blanked the week it had measured — every field turned unknown at once, which cannot be told apart from a genuinely empty window.

What landed. reckon/crew/paid_lanes.py composes one document per account from those same three recorded homes, carrying for each of the five-hour and seven-day windows its utilisation, reset time, burn multiple, projected exhaustion, the source the figure came from and when it was observed. Reconciliation is per window by recency: a newer reading speaks only for the windows it actually carried, so a fresh stream reading at 40% holds the five-hour clock while an older receipt still holds the week the stream never reported. The two windows are therefore resolved independently, which is what stops one failed precondition from blanking the other. A window no source resolved is an explicit absence (state: "unknown", every figure null) and never a 0.0, which would read as a measured empty window. A figure whose own observation is older than the staleness horizon keeps its value and is marked stale: true for that window alone.

python -m reckon.crew.paid_lanes --once writes the document atomically through a sibling temporary file and an os.replace, so a reader that opens it mid-refresh sees the previous document or the new one and never a truncated account list whose missing accounts would look like real absences. budget.preflight takes its per-backend and per-group figures from that document when the caller supplies no reading of its own, so both come from one reconciled record rather than two readers; an explicit windows argument still wins where a caller supplies one.

What this record does not claim

  • The document was not deployed on a five-minute clock. The brief places the refresh deployment and the dispatch-side read out of scope; what landed is the composer, the atomic writer and the pre-flight read. Until an observer runs on a timer the document's absence is reported as no reading rather than a fabricated position, which is what read_document returning None means.
  • No state grading. Open, pace and hold from §6 are not derived here; the document publishes the figures a grader would read (utilisation, burn multiple, projected exhaustion) but assigns no state.
  • The claude path was exercised through the stream reader, not against a live subscription. The three sources are the ones the pre-flight already read (receipt, rollout, stream), each named as the source it was; no network call is made by this node's tests.
  • The merged-head result is not this node's. The gate measures this node's change at its own head; a merged-head verification is a separately dispatched node's job.
  • Pre-existing plan-labelled identifiers in reckon/budget.py were left in place. Four occurrences of a bare deliverable identifier sit on lines this commit does not touch, in a file concurrent peers are editing; a rename there would collide and is not this node's focused commit.
