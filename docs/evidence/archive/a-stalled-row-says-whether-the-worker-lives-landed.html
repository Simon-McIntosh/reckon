A Stalled Row Says Whether The Worker Lives

A run whose process is gone is reported on the snapshot that observes the death; the stall window no longer gates the row.

§2 — A worker's death is a row within one poll

Landed (8b759fa0). _watch_snapshot in reckon/crew/recovery.py reads the newest stream's last complete record when the process table has already falsified the manifest's word. A last record of type result is a turn that ran to its own conclusion, whose remedy is to continue it, and §8 owns that row, so the death branch leaves it alone. Every other last record is a death mid-turn: the row moves to blocked and carries the classifier's own interrupted reading and the redispatch verb, so its cause and remedy match every other surface rather than a second vocabulary composed in the reducer.

The reason names the end that was observed. Where the supervisor's exit.json records one, the reason carries it — the classifier already reads a recorded signal as the interruption it is, and a recorded non-signal exit is named as exited with code N. Where nothing recorded the end, the reason says the process is gone with no recorded exit and names the stream record the death interrupted. Measured before the change: the killed run's classification read running, its snapshot read working with an empty reason, and the fold emitted no transition at all.

Node death-row-reads-any-final-record — the last record however large it is

Landed (c5b2e184). The reader that decides between a death and a turn that ended took one fixed 64 KiB window from the end of the run's newest stream. A record larger than the window leaves that window entirely inside it, and a fragment parses as nothing, so the reader answered “no last record” — the run kept reading as working and no death clause appeared, which is the stale row this section exists to remove. The window is now a floor: the read reaches further back in geometric steps while the chunk begins inside a record, and stops as soon as a chunk begins at a record boundary, because such a chunk holds only complete lines and a scan that finds nothing in it is the stream's own answer. The boundary test is on where the chunk begins: the file's final byte can be the terminating newline of the very record that overflows the window, so counting newlines in the chunk is not the same test and answers wrongly for a record of about one window plus a line.

§3 — A stalled row says alive or gone

Landed (8be6a8af, states made three-way in 8236dcc3). The stalled branch of _watch_verdict in reckon/crew/recovery.py composes its reason clause from the process verdict the classifier has already put on the row, so every row entering stalled names its process state in words beside the quiet time it has measured: alive, process gone, or liveness unknown. The three states carry three different remedies — a long quiet step needs nothing, a dead process needs a resume, an unproven reading needs the check a reader would otherwise run by hand — and only a reading taken on the reading host may call the process gone, which the row's own liveness_proven records. A pointer with no recorded pid, or one whose pid belongs to another host's process table, therefore reads as unknown rather than stating a death nobody observed. The minutes are the row's own quiet time, floored, so the figure can never claim more silence than was measured. The pane needed no change: the ticker renders the classifier's detail through the clause helper it already had, and the words reach the row unchanged.
