A Landing Record Never Conflicts — landed record

Composition of a plan's cumulative evidence record at read time: the record file's own bytes followed by its fragments in ledger promotion order.

§3 — The record is composed at read time, and the plan comment goes through the versioned write

compose_landed_record in reckon/evidence.py reads a record's own bytes and appends each fragment under docs/evidence/fragments/<plan>/<node>.html in the order the ledger records the fragments' promotions, resolving both the archived and live record spellings. A fragment is named for the ledger row's node, so a redispatch carries that node's latest fragment once. The function writes no file and does not call synthesize_landed_record, so a record with no fragments composes to its own bytes byte-for-byte.

  • Negative control: ordering fragments by filename instead of by ledger promotion order makes the three-fragment ordering case fail on both spellings.
