A promotion records the revision it asserts, and a sweep tests both halves

What landed and where. promotion.complete records promoted_revision on the ledger row — the tip of the run's own work, resolved by _promoted_revision in reckon/crew/promotion.py while the run's tree is still present. A shadow run and a run that cited no commit record none, so an absent key never reads as a promotion whose work was verified as landed. The revision is the worker's cited tip rather than the worktree's HEAD, because a shared checkout can advance under other runs between the commit and the promotion, and the cited tip is the revision whose diff promotion already measured.

Why the promotion's own commit cannot be the recorded revision. A promotion commits its ledger row and plan comment into the branch it is promoted into, so that commit is an ancestor of the branch head by construction and an ancestry question asked of it can never fail. Asked of the run's own head it can: measured in a synthesised repository, the promote commit is an ancestor of HEAD while the run's head is not, until a merge carries it.

The sweep, and the two questions. promotion.sweep_promoted_revisions(project, target_head=…, markers=…) reads the ledger and the branch and writes neither. Per promoted row it asks whether the recorded revision is an ancestor of the target head, and whether a caller-declared marker survives there — expect="present" for a change that added content, expect="absent" for one whose purpose was a removal. Findings carry the reason (not-an-ancestor, marker-absent, removed-marker-still-present, unresolvable-revision). A git failure in either probe raises rather than answering absent or not-an-ancestor, because an unreadable tree and a genuinely absent marker otherwise return the same empty result.

The reflexive sweep: the review a scoring run already composed

Measure. The reflex only earns its name when it fires on the path a healthy run takes. A run that reaches scoring has already had its review dispatch composed and returned as a string; leaving it composed is what left runs waiting on a coordinator to notice and retype the command. The site chosen is resumption.sweep, because that is the periodic pass a session watching its own fleet already runs, and it is the one place the reflex reaches all three of its callers at once. The claim is stated as an issued command, not as an observed effect: tests/test_review_reflex_sweep.py drives the sweep against a stub launcher that records every call. The number of recorded calls is the evidence; a review that ran and wrote nothing is not visible in any output.

The strongest half is the quiet one. Every property is argued with its negative half, because both failure modes here look like an idle fleet rather than an error. A sweep that dispatches nothing is indistinguishable from a fleet with nothing to dispatch, and a sweep that re-dispatches what it already dispatched manufactures reviews — so two sweeps over the same fleet are run and asserted to produce exactly one recorded call. A refusal on one run must leave the rest dispatched, because a sweep that stops at the first refusal reports nothing about the run it never reached.
