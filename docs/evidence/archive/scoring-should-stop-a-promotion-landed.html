A review bound in what it reads and enumerated in what it reports

Defect, reproduced at the base before the repair. A review emitting all five SCORE lines and no per-item line parsed as a complete record: parse_review returned status=parsed, total=50, and keys ['absent', 'findings', 'justifications', 'raw_text', 'scores', 'status', 'total'] — no item field of any kind. In the same reading, reckon/crew/prompts/review.md contained 0 occurrences of each of the three exclusions and 0 occurrences of the word VERDICT. So a reviewer that read four of the five targets and summarised them produced a record indistinguishable from a thorough one, and nothing in the prompt bounded how far a review should range.

What changed. The prompt states the reading bound — do not re-derive the implementation, do not re-run the full suite, do not review code the node did not touch — and requires one VERDICT <item>: <sentence> line per checklist item, with the reviewer's own done-when being that each of the five carries one. The parser records item_verdicts, absent_items and item_aggregate.

Review emitteditem_verdictsabsent_itemsitem_aggregatetotal
five VERDICT lines, five SCOREs5 entries[]585
five SCOREs, VERDICT diff: omitted4 entries['diff']None85
VERDICT diff: emitted with no text4 entries['diff']None85
five VERDICT lines and no SCOREs5 entries[]5None

The withheld half is the point. An omitted item does not shorten a count to four; it names the item absent and withholds the aggregate, exactly as a missing dimension withholds total. Rows two and three differ only in whether text followed the colon, and an empty verdict is read as no verdict — a line that says nothing is not a report. Row four shows the two axes stay independent: verdicts alone do not make a record parsed, and neither does a record's status change because its items are complete.

The limit, asserted by calling the predicate. reckon.crew.recovery._review_is_complete returns True for a record carrying all five dimension scores and absent_items equal to all five items — so 147 stored reviews across four projects, and any scoring run in flight in another session, keep promoting as they did. ledger_block is unchanged in shape for the same reason: the ledger row is what a promotion and a lane comparison read, and both are defined on the five dimensions. The item verdicts are recorded in the durable store, not in the row.

A completed review-role run is exempt from the scoring classification

What landed. classify_pointer in reckon/crew/recovery.py reads the role the run carried and returns promotable for a completed review run, with a next_action that composes no dispatch naming it. Every other completed run is unchanged: promotable when a parsed review is attached, scoring when one is missing or incomplete, and scoring is the classification the review reflex acts on. Without the exemption the reflex dispatches a review of a review run, that review completes, classifies as scoring in turn, and dispatches another of the same shape — a chain in which every link is a real dispatch against a real member.

The defect reproduced at the base revision before the repair. With aa3c5ac6's reckon/crew/recovery.py restored in place, the module run against the base tree reports 6 failed, 1 passed, and the composed action for a completed review-role run reads, verbatim:

reckon crew dispatch ... --role review --spec-level exact \
  --node review-of-r-prior-review \
  --goal 'attach an independent review to run r-prior-review' \
  --done-when 'the review for r-prior-review stores a parsed record ...' \
  --write-path .../crew/reviews/sample/r-prior-review.json ... --local

That is a review of a review, composed by the same function that composes the review a genuine scoring run needs. After the repair the same fleet mints exactly one review node, review-of-r-work, and none for the review run.

The reflexive sweep: the review a scoring run already composed

Measure. The reflex only earns its name when it fires on the path a healthy run takes. A run that reaches scoring has already had its review dispatch composed and returned as a string; leaving it composed is what left runs waiting on a coordinator to notice and retype the command. The site chosen is resumption.sweep, because that is the periodic pass a session watching its own fleet already runs, and it is the one place the reflex reaches all three of its callers at once. The claim is stated as an issued command, not as an observed effect: tests/test_review_reflex_sweep.py drives the sweep against a stub launcher that records every call. The number of recorded calls is the evidence; a review that ran and wrote nothing is not visible in any output.

The strongest half is the quiet one. Every property is argued with its negative half, because both failure modes here look like an idle fleet rather than an error. A sweep that dispatches nothing is indistinguishable from a fleet with nothing to dispatch, and a sweep that re-dispatches what it already dispatched manufactures reviews — so two sweeps over the same fleet are run and asserted to produce exactly one recorded call. A refusal on one run must leave the rest dispatched, because a sweep that stops at the first refusal reports nothing about the run it never reached. And a pointer whose node id was minted as some run's review is asserted to classify as scoring yet dispatch nothing and gain no review_dispatch: inert by its minted name, not by a role it may not carry.

The waiver, and the fence it opens. A run awaiting review is an unreconciled run, so past the grace window the fence refused the very dispatch that clears the backlog, measured as exit 6 naming the same three runs. The suite arms that fence rather than assuming its absence: the fixture manifests are backdated past a short grace, the dispatch is driven with the waiver withheld and required to be refused with the run id and the grace in its reason, and the same run is then driven with the waiver and required to be dispatched carrying waived_runs. A test that cannot see the fence fire cannot show the waiver is doing anything.

The refusal accumulator stored a generator. A refusal recorded as a generator expression is not a report: it is a value that raises on json.dumps in the CLI emit path, so one refusal aborted the sweep's entire emit. The repair stores the report itself, asserted by checking the stored entry's type and its content round-tripped through JSON. The repair is load-bearing independently of the reflex, which is why it was carried here rather than deferred, and the negative control reaches it.

Negative control. Withholding the waiver at the dispatch (unreconciled_override=False) turns the waiver test red, along with the two tests whose fixtures depend on a dispatch succeeding; the log's first line repeats the mutation verbatim. The source was reverted and reckon/crew/recovery.py is byte-identical to its pre-mutation revision — sha256 7454bdc2ba943749b8c79358a8d388f2ca60183fe24b354c251e528ff52ae133 both before the mutation and after the revert — and the suite re-run after the revert reports 9 passed, 0 failed.

Cohort. The 15-file promotion cohort that invokes promotion.complete is run at this revision and measures 18 failures against its recorded before value of 18, with 0 newly failing: the sweep's review pass reaches no promotion.complete call site, which is the independence this number is here to show.

Limits, recorded rather than implied. Three things are explicitly outside this measure. The review resolves against a competing local lane and _review_dispatch_argv still ends in a hardcoded --local, so lane routing for the reflex is separate work. A wave of two reviews inside one coordinator session is still refused — the first review takes the session's private member seat and the watch admission, both inside the dispatch path rather than at this caller — so the wave test asserts the honest continuation (dispatching resumes on the next run) rather than the two-review outcome the template implies, and the seat collisions are recorded as follow-ons. And this gate measures this node's own change only; verifying the merged result belongs to a separately dispatched test node.
