§1 — a revision without the ledger reads as one with no runs

_read_ledger in reckon/velocity.py is now the one reader of the committed ledger at a revision. When the tree has no docs/state/<project>/crew.json, which _blob_sha reports, it returns no records and a None digest. Otherwise it reads the bytes through read_blobs, so a failed read of a ledger that is present still raises. recover_ledger_clocks no longer parses the ledger itself. It takes the runs present at the base from _read_ledger, and keeps the path its git log search uses. Commits: a966f5b7e (fix) and d78210764 (fragment).

§2 — A long window's ledger search stays inside its git bound

recover_ledger_clocks now places a run first by the commit that added its own record file. It finds those with a path-limited git log --first-parent --diff-filter=A --name-only, which generates no patch, and records them under the source first_primary_record_file_addition_upper_bound. Only the ids left after that reach the crew.json -G search, which runs over consecutive slices of _LEDGER_SEARCH_SLICE_COMMITS = 128 ledger-touching commits. The cache is stored after each slice, so an interrupted read resumes where it stopped and a completed window runs no search. Commits caf08d8e8 and 0bb5da164, which only wraps the new lines to the project width.
