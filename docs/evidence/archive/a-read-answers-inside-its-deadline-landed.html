§4 — Git HEAD is resolved once per commit

_git_head (reckon/serve.py) is memoised on the identity of the repository's HEAD file and the ref file it names, resolved through the common git directory in a linked worktree, so a read with no new commit starts no git process and a commit invalidates it. The profile's attribution was corrected on the way: none of the nine warm-audit git processes came from _git_head; seven were git rev-parse HEAD from recovery_review_subject._reviewed_run_head and two rev-parse --verify from _resolve_commit, both uncached per lookup, which is where the audit's remaining git cost lies. _git_head is the roadmap's cost. Commits 4685373af and the repair 323a2a62f (a worktree's ref was read from its private git directory, so its memo never saw a new commit), merged at 5c09a1ef9; 19 tests pass, negative controls for the memo and for the worktree case fail as declared.
