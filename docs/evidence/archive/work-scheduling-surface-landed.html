Caveats a reader should carry

  • The crew view name is not wired. portfolio_view exists and is asserted, but the literal view name a caller passes to crew(view=...) lives in a view list and a literal type that reckon/mcp.py holds, and a concurrent node held that file for the whole of this node's run. Until one line is added there, the portfolio is reachable through the flight project key and not by its own view name.
  • The CLI prints the report as JSON. reckon flight --project '*' emits the portfolio inside the CLI's existing JSON envelope, so the ranked rows are all present and the columns that sort them are readable, but a rendered table would need an edit to reckon/cli.py, which another node held.
  • The read is heavy. A real-mount pass over all thirteen registered projects took 155 s, because each project's docs tree is discovered and each live pointer is classified against the process table. This belongs on a compute partition, not the login node.
  • A live pointer launched on another host reports its stored liveness as unproven. That is the crew contract rather than a defect here, and it is why the row carries the classifier's own answer instead of re-deriving one.
  • One unreadable project reports its refusal on its own row and in the report's errors list, and sorts last rather than posing as a project with nothing left to cover.
