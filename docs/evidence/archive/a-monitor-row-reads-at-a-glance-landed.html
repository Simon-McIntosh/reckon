Finding recorded rather than acted on: an id ends in its node name

The spec appends the last four characters of a run id, and the fleet mints an id as r-<stamp>-<sanitised node> — so an id's last four characters are the node name's own last four. Two names that a middle cut renders as one text agree at both ends by construction, so their ids end alike and the suffix separates nothing for them; it separates ids whose ends differ, which the pair test in the new file mints deliberately. Implemented as specified and recorded here: the id format, not this renderer, is what would have to change for the suffix to separate two rows of one node name.

Corrective landing: the collision suffix draws from the run's minted stamp

Commit 6925df20 in the colliding-node-cells-carry-a-distinguishing-suffix worktree, base 398a1f31. The independent review of the node-name landing — review run r-20260925T011629068862-long-node-names-keep-their-ends, stored at /home/ITER/mcintos/.config/reckon/crew/reviews/reckon/r-20260925T011629068862-long-node-names-keep-their-ends.json, total 85/100 — recorded two findings, and this node repairs both. It supersedes the finding above that "the id format, not this renderer, is what would have to change": the id does carry the distinguishing part, the minted stamp, and the suffix was simply drawn from the wrong end of the id.

  • The suffix was run_id[-4:], and a fleet-minted id ends in its node name, so two names a middle cut renders alike (which agree on their last eighteen characters) also ended alike and carried the same four characters.
  • The collision was detected by comparing node names in self._node_claims, so two runs of one node — a repair redispatched under a new run id, the commonest way a pane shows two rows of one worker name — were never marked at all.

The claim is now keyed by the run that claimed a rendered cell text, and the suffix is the tail of that run's minted stamp: minted_stamp reads r-<stamp>-<node token> by shape, never by field position, so a dashed id that is not minted cannot pass its middle field off as a stamp, and an id carrying no minted stamp falls back to its own tail. NODE_ID_TAIL is renamed RUN_STAMP_TAIL, because the width it holds is no longer the id's tail.
