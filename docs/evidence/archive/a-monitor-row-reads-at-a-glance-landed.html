  • Baseline marker. A baseline row carries the word now in the marker cell immediately ahead of its own state. The marker cell is held on every row, blank on a transition, so the state cell lands on one screen column whichever kind of record the row is.

§3 corrective — every column follows the grid's own width

Commit a45e4387 on the ticker-tests-read-the-grid-width worktree, base revision 961b288e, on main. Repairs the two defects the review of the first landing named (scored 81): the tests derived their expected columns from the fixed MODEL constant rather than the width the rendered grid uses, and the ticker resolved the model aliases without the row's project.

Gate measure, as executed

Both fenced ticker test files derive every expected column from the grid under test (grid.model_width or the value the renderer reports) rather than the module constant, including the _spend_columns prefix. Run with the worktree's venv interpreter under a temporary flight config declaring no alias, and again under one declaring dsv4.1-flash. Both runs are logged.

What changed

The model cell's width is now a property of the grid being rendered: the resolver reads the row's project's alias layer, so the project layer is read alongside the shipped, host and override layers, and a config declaring a wider alias widens the grid so every column downstream moves with it. The tests read the grid's own width rather than the constant, so they assert against the row they render. launch-failed gains a light-theme hue beside failed, which closes the one pre-existing failure (test_the_action_set_is_one_set_with_three_readers) that the first landing left open.
