August comparison and evidence limits

The published August 12–16 baseline reported 259 completed runs in four projects, 108,587 added lines in three reporting projects, 228 commits, median 9.8 minutes/run, 66.2 stall-corrected worker-hours, and median authored throughput of 16–24 changed lines/worker-minute. September adds a fifth project, includes review and record work explicitly, measures primary landings and retains uncorrected duration sources. August reported no seven-day survival, record/product split or durable worker-hour rate; these figures do not establish a causal efficiency change.

  • 83 reachable promotions were missing from the captured final ledgers: 82 imas-efit and one Nova. SQLite supplied those records with explicit fallback provenance. Repairing the primary ledgers is outside this node's scope.
  • 104 rows lacked an explicit promote commit. The first primary commit adding their run id supplies a separately labelled upper-bound clock; every recovered clock has a commit citation.
  • 28 run records carry unresolved or unreachable commit citations. 18,118 product additions remain unattributed; 3,319 have mixed-lane attribution.
  • 24,997 mature attributed additions lack a fully matched positive-duration producing cohort. Eleven rows report zero worker seconds, one with commit citations and a 3,401.36-second dispatch-to-completion interval. They remain visible and receive no zero-cost productivity credit.
  • Attempts use declared lineage, the same plan/node identity and explicit repair-name links. The application can infer predecessor_run from a base SHA; it is therefore excluded as standalone retry evidence. Unrecorded discarded attempts remain missing.
