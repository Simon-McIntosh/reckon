Wiring is asserted at creation — landed evidence

The roadmap can only follow wires that were drawn. This landing makes drawing them a condition of creating a plan: one predicate, reached from the write boundary, the audit and the sprint view, refuses an implementable plan that waits on nothing, feeds nothing and gates nothing — unless the plan says in its own document why it genuinely stands alone.

§7 — Wiring is asserted at creation

Commit 5ded914 (implementation and tests), e87e5e3 (skills).

The rule, and where it is reached

One predicate, unwired_plan_finding(), decides. A document is held to the rule only when it declares reckon-type=plan; a plan whose plan-status is terminal is exempt; a plan that declares any of plan-depends-on, plan-blocks, plan-informs, a gate, or a non-empty plan-standalone reason is silent. Everything else yields the finding, whose severity is taken from plan-modified: a warning for a plan that predates the rule, an error for a plan authored after it.

The three readers call the same function. The audit (reckon/doccheck.py) emits it as unwired-plan; edit_plan(create=True) (reckon/mcp.py) refuses with the same message and deletes the file it had begun to write, so a refused create leaves no trace; the sprint view (reckon/roadmap.py) folds it into wiring_findings at the same severity. A plan that declares standalone round-trips it through a read.

The positive control was exercised, not asserted

The refusal, shown. A create with no wire and no declaration returns {"ok": false, "error": "unwired_plan"} and the message names the three questions; the target file does not exist afterwards. The test asserts both, because a refusal that leaves half a plan behind is not a refusal.

The measure. The gate pytest tests/test_doccheck_unwired_plan.py tests/test_roadmap_unwired_plan.py tests/test_doccheck*.py tests/test_roadmap*.py tests/test_mcp_roadmap.py tests/test_review_roadmap.py — 133 passed in 14.50 s, exit 0, zero added failures against the base revision. The four audit paths are covered as the fence required: wired plan silent, unwired new plan error, unwired old plan warning, standalone declaration silent. The roadmap test asserts its message is equal to the predicate's, so the two readers cannot drift into two spellings of one rule.

Why the two numbers differ, and why the instrument is not the suspect. The prediction is stale rather than the reader being blind, and the evidence for that is a positive control: the reader does fire on the one plan that qualifies, at the prescribed severity, while staying silent on 26 that declare wires. The population also moved — nova carries 27 live plans today against the 16 the plan text counted when the estimate was written. The plausible reading is that the wiring the prediction complained about has largely been drawn since, not that nine wired plans are being passed over; but the honest statement of this measurement is the table above, not that conclusion. A reader who wants the conclusion verified should re-run the probe and inspect the wires on the 26 silent plans.

A caveat that cost a reading. The first run of the probe reported zero, and the cause was not the code: /tmp/reckon/ is a ten-day-old copy of the package (mtime 2026-09-09), and a probe run as a script puts its own directory first on sys.path — so import reckon.doccheck resolved to that stale copy and the finding was absent from it. The same probe run through a stdin heredoc (working directory first) resolved to the worktree and reported one. Any measurement taken by running a script out of /tmp in this repository is measuring that copy. The scratch tree is not this node's to remove and was left in place.

The checklist moved into the author's path

A refusal that arrives after the plan is written is a tax on the author; the decision belongs where the plan is authored. skills/reckon-create/SKILL.md Step 1.5 and skills/reckon-edit/SKILL.md now carry the three questions as a table the author fills from the sprint's plan list — one row per candidate, does my first section wait on it, does it consume my evidence, does one section of mine wait on one section of it — and each answer maps to exactly one relation to write: depends_on, blocks, or a gate on the section. A no to all three is recorded in the document as a plan-standalone declaration carrying its reason, because a declaration a later reader can check against is the whole point of the escape hatch.

Follow-ons this landing creates
