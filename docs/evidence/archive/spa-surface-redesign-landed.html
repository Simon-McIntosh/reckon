Redrawing the degraded surfaces — landed evidence

Three waves of surface work had passed every gate and the served page was still wrong, three times, each time found by a human looking at a screenshot. This record is what happened when the looking was automated: a browser-backed check that reads composed geometry rather than authored declarations, and the lead's seven follow-up complaints landed against its evidence.

The instrument, and why it exists

Every gate on this plan asserted a declaration, and a declaration cannot fail the way this page kept failing. A correct width under a wrong container renders wrongly while the assertion that the width is correct stays true. That happened three times in one day: a structural redraw that had not happened under passing structural tests, geometry lost to a prose paraphrase of a canvas, and a CSS grid still governing every component redrawn beneath it. In all three the evidence chain contained nothing false.

The trade the plan had reserved for the lead turned out not to exist. The open question was whether a rendering check was worth its dependency, on the premise that it needs a JavaScript toolchain in a repository whose manifest cannot express one. But /usr/bin/google-chrome is installed system-wide on this host and node 22 is on the path, so a check that shells out to a present browser and skips when it is absent costs nothing to declare. The measured proof: after landing the check, git diff pyproject.toml is empty.

What generalises

A test that pins a value existing in order to change is a fuse on the next person to touch that file. This plan recorded the lesson twice already and met it a third time from a new direction: three landed tests actively enforced what the lead had just rejected — one requiring the chip render no label, one pinning 64 px, one requiring the model string by name. All three were inverted deliberately and recorded as edits. A regression and a superseded requirement look identical in a red suite; only the plan can tell them apart.

Two rulers for one bound is worse than a loose bound. The summary gate measures the decoded string; the audit measures the HTML-encoded attribute. An apostrophe costs five characters the author never typed, so a 158-character summary passed the write and was flagged at 164 by the audit — the author told it is fine, a later reader told it is not. Found by the first plan through the gate, which was this one.

A red suite has three kinds of row, and only one of them is a defect

Two sessions measured the same repository at the same moment and got one failure and six. Neither was wrong about what it observed. Sorting the six, jointly with the peer session that reported them, produced a taxonomy sharper than either of us started with:

KindCountWhat it actually wasWhat to do
Real1 An exact-field-set assertion superseded by two fields a merge added to the served projection Repair it. This is the only row that was a defect.
Sandbox tier4 An offline wheel build and an executable-path assumption that a restricted worker sandbox cannot satisfy. All four pass unsandboxed in under nine seconds; two of them appear as skips rather than failures in an unrestricted run Attribute to the tier, not the code. Re-measure in the main checkout.
Stale base1 A row a later commit had already fixed, reported from a worktree cut before that commit. Never a regression and never a live failure Re-measure at head. A delta at the node's own base would have called it pre-existing — true of that revision, false of the repository.

So “judge a run by its delta against a base” is necessary and not sufficient: the measurement has to name which base. For attributing anything to another session's merges, the only useful base is head in the main checkout. A delta taken inside a restricted worktree at an older base is internally consistent, cheap, and wrong — and it is wrong in the most durable way, because it lands in an evidence record looking like a measurement. The peer session had a baseline node dispatched to answer exactly this question and killed it mid-run rather than let it write four sandbox artifacts down as pre-existing failures. Two dispatches spent, nothing promoted, and that was the correct outcome.

The class is wider than test suites, and a third instance the same day proved it. The peer session re-ran a shadow pair that had recorded one model producing markedly thinner work than another, this time holding every condition of the primary equal and substituting only the model:

So a whole recorded model comparison had been resting on an uncontrolled variable — the same defect as four sandbox rows read as code failures and one already-fixed row read as pre-existing.

Three instances in one day gives the general form, and it is not about tests at all: a measurement can be internally consistent and be measuring something other than what it names. None of the three was sloppy, none contained a false number, and each would have survived review, because reviewing a measurement checks its arithmetic rather than its attribution. What separates them from sound measurements is only whether the thing being varied is the thing in the label. That is why all three were caught by re-measuring under changed conditions rather than by anyone re-reading the record.

A related finding, surfaced by workers rather than by tests. Several nodes reported that they could not lint, because ruff is absent from the project environment as both an executable and a module. The repository configures it — there is a [tool.ruff] block in pyproject.toml — and never declares it, so the pre-stage format-and-lint protocol is unfollowable for any worker whose PATH does not happen to carry a user-level install. A tool that is configured but not declared is worse than one that is absent: the configuration implies a guarantee the environment does not provide.

Resolved, and the resolution produced the number that shows what it cost. ruff is now declared, with a check that enumerates every configured namespace, resolves each through an explicit distribution alias table, and fails closed on one it cannot place — proven failing before the declaration and passing after. The first successful run of the documented command reports 322 pre-existing findings, none of which was reachable through it before. That count is the measure of how long a rule can decay while its prose stays correct. The thesis and the remaining half — whether an assertion stating a snapshot rather than a contract can be checked at all — moved to binding-rules-need-bound-checks, because a repository-wide rules-without-checks concern is not this plan's subject and a followup on this page would have hidden it.

A reach path a user cannot see is not a reach path. An earlier landing asserted that hiding a project excluded it “from aggregates and from the shortcut list but never from reach”, and its test passed, because the palette and the route genuinely worked. The lead still could not switch to the project. Reachability that requires knowing the palette exists is a claim about the implementation, not about the interface.
