§6 — Patch-equivalent commits release (merged at 4ceb579f5)

crew gc now asks git cherry whether each commit a dirty worktree carries beyond the integration head already has a patch-equivalent there. A worktree whose every such commit is equivalent, because it landed through a squash or a merge of a different sha, is released through the §3 residue-preserving path. A worktree carrying any non-equivalent commit is kept, and its row names that commit's sha and subject. A comparison that cannot run counts as not equivalent, so an unreadable tree is kept.
