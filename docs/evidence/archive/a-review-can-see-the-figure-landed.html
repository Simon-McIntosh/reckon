A lane declares its input modalities

Execution record for a-review-can-see-the-figure §1. A backend now states which input modalities its model actually receives, and a profile that needs one a lane does not declare is refused by name rather than falling through to default_backend.

The slot, and the refusal it makes possible

BackendConfig gained input_modalities, ranging over a closed InputModality enum of text here, image for a lane whose model receives an attached figure. The LinkML source is authoritative and both derived artifacts were regenerated from it; the committed round-trip tests report 2 passed, exit 0, not skipped, so the Pydantic model and the served JSON schema regenerate byte-identically from the source.

Resolution runs through select_profile_backend. The candidate is the lane the caller named, or the resolved default_backend when none is named. A candidate that does not declare a modality the profile requires is refused by name — the message carries the backend, the missing modality and the modalities that were declared. No second backend is tried, and default_backend is never substituted for a named candidate: the substitution is not a cheaper or slower lane, it is a lane that never receives the image and still answers.

A lane that declares nothing is read as having no declared modality, never every modality. That asymmetry is the measure: the text profile demands no declaration, so a layer predating the slot still serves the text review, while the figure profile can only be served by a lane that says it receives the image.

The falsifier, and its negative control

The falsifier is applied literally: point the figure profile at a lane declaring no image input and require a refusal. In the fixture the default lane does declare image input, so a resolver that ignored the slot would return it and the assertion would pass on the defect. Asserting against that arrangement is what makes the check discriminate.

The declared negative control - make the figure-profile resolver ignore the input-modalities slot and fall through to default_backend - was applied, and exactly the two refusal tests failed with DID NOT RAISE FlightConfigError, the other 84 tests in the declared gate unaffected. The resolver was restored and the gate re-run green.

The figure reaches the command line, or the launch refuses

Execution record for a-review-can-see-the-figure §2. A node's figures are now attached where the plan is composed - reckon._backends.launch_plan(..., images=...), the argument vector the launcher actually runs - rather than threaded through a helper only a test calls. The codex dialect emits one -i <path> per file; every dialect with no way to hand an image to its harness raises by lane rather than dropping the figure and answering without it.

What the argv carries

The attachment is judged on the object the launcher runs, never on a helper's return value: a direct call proves the function, not the wiring. A codex backend handed two figures resolves to exactly two -i flags, each immediately followed by its own path, and both before the trailing - that carries the prompt on stdin.

['codex', 'exec', '--json', '-C', '/wt',
 '--dangerously-bypass-approvals-and-sandbox',
 '-i', 'a.png', '-i', 'b.png', '-']

Handed no figures the same backend emits no -i at all. The flags precede the resume subcommand for the same reason every other exec option does: resume takes only a session id and a prompt, so an option placed after it is rejected outright rather than carried into the resumed turn.

Falsifier, and the lane named by the refusal

A lane with no image flag is refused, not silently degraded, and the refusal carries the name of the lane the operator configured - the local harness that shares the claude flag grammar reports the lane, not the dialect family behind it:

BackendError: the 'clive' dialect cannot carry attached images, so 1 figure(s)
would be dropped from the command line; route a figure review to a dialect that
emits an image flag

An in-harness lane has no command line to carry the figure at all and is refused the same way, naming itself: backend 'native-harness' has launch: 'in-harness'; only a 'cli' backend can be spawned. A figureless node on a text-only lane composes its argv exactly as before, because the refusal responds to the figure and not to the lane.

Negative control

The declared mutation is that the codex dialect's argv ignores its images argument, so no -i flag is emitted. Applied, it reddened exactly the two attachment tests - assert 0 == 2 on the flag count, and ValueError: list.index(x): x not in list for a one-figure launch - while the six others stayed green, the empty-tuple test among them. The discrimination therefore sits on the emitted flag, not on the lane count. The mutation was reverted and the gate re-run green.
