Prior-art reconnaissance — the meter surface and the refusal stamp

The headline finding is that nothing in this section requires a newly authored derivation. Every figure the surface needs is already computed in Python, and both refusal detections already exist; what is missing is persistence and a display.

Already computed, and not to be re-derived in the surface

reckon/budget.py's BudgetState already carries utilisation, burn multiple, projected exhaustion, the window period, the reset and the observation time. The window-selection machinery already distinguishes a lane's own window from a shared account figure, returning own, shared or own-unmeasured — the same distinction the borrowed-figure measure needs, one layer down. Building a second computation in JSX would be the defect the repository's render-never-derive invariant exists to prevent.

The meter primitive exists and is the right one to extend

The Crew surface already carries a track-plus-fill meter with a percentage label, styled in docs/ui/crew.css. It currently shows time budget rather than quota, so a quota meter is a second use of the same primitive, not a new one. Three other progress bars in the SPA are explicitly not the right primitive — different semantics and thinner. No new CSS token is needed; the accent, warning and background tokens already exist in the shared foundation.

Two refusal detections exist; neither persists where it must

One reads the live run's stream for the newest rejected rate-limit event; the other classifies a rejected threshold status into a blocked reason. Both are pure readers. What is written today goes to the committed ledger — which is precisely the store the survivorship trap excludes, because a refusal kills the run, a killed run never promotes, and so no ledger row is ever written for the one event that proves a limit exists.

The lowest-cost durable slot was already declared and empty. The run store — an embedded database on the shared config home, outside both the run directory and the committed ledger — carries a holds table in its schema that nothing writes. Both halves of the survivorship requirement hold there by construction.

The Crew surface renders a quota meter carrying the position, the reset at its right edge labelled with the window's own duration, and the projected exhaustion plotted on the same axis. When the projection falls left of the reset the lane will run out before it refills, and the bar says so.

Why one mark rather than two tiles. The refusal that kills the run outlives the run

Landed 2026-09-15, commit ea9c9a3a. The survivorship trap is that the one event proving a lane has a limit is the one event guaranteed not to reach the ledger: a rate-limit refusal kills the run, a killed run never promotes, so no row is written. When the budget's live-read observes a genuine rate-limit event, the refusal is now stamped with both its own observation time and the return time the refusal itself states, and the stamp is written to the shadow run store — outside the run directory, which is reclaimable, and outside the ledger row, which will not exist.

Only the reading that owns the refusal's time stamps. The budget distinguishes the age-source of each recorded refusal. A rate-limit-event is the one reading carrying the refusal's own observation time and its stated return time, and it is the only one minted: an earlier-bound refusal with no own time, and a served-turn refutation that the lane later satisfied, must not fabricate a record for anyone reading the store.

Survivorship is asserted, not argued. A stamp is written, its run directory is removed, and the stamp is read back from the store. The quiet half is asserted too: a served request writes no stamp, so the store holds refusals only and its emptiness means no refusal was seen rather than no lane was used.

Isolated writes, verified as isolated. Every test path points the store at a temp location through the environment; the real store is asserted untouched afterwards. A failed shadow write is recorded on the reading and surfaced in its detail — the failure is visible, never silent — and it never raises, because a dispatch consults this read outside a try/except.

Measure: five tests over the live-read path a dispatch consults. 70 passed / 0 failed at head against 65 / 0 at base 4f221447, zero added failures. The called-out follow-on — the denial seat a non-cli launch experiences sits outside this node's write scope — is recorded in a section comment on the owning plan.
