Prior-art reconnaissance — the meter surface and the refusal stamp

The headline finding is that nothing in this section requires a newly authored derivation. Every figure the surface needs is already computed in Python, and both refusal detections already exist; what is missing is persistence and a display.

Already computed, and not to be re-derived in the surface

reckon/budget.py's BudgetState already carries utilisation, burn multiple, projected exhaustion, the window period, the reset and the observation time. The window-selection machinery already distinguishes a lane's own window from a shared account figure, returning own, shared or own-unmeasured — the same distinction the borrowed-figure measure needs, one layer down. Building a second computation in JSX would be the defect the repository's render-never-derive invariant exists to prevent.

The meter primitive exists and is the right one to extend

The Crew surface already carries a track-plus-fill meter with a percentage label, styled in docs/ui/crew.css. It currently shows time budget rather than quota, so a quota meter is a second use of the same primitive, not a new one. Three other progress bars in the SPA are explicitly not the right primitive — different semantics and thinner. No new CSS token is needed; the accent, warning and background tokens already exist in the shared foundation.

Two refusal detections exist; neither persists where it must

One reads the live run's stream for the newest rejected rate-limit event; the other classifies a rejected threshold status into a blocked reason. Both are pure readers. What is written today goes to the committed ledger — which is precisely the store the survivorship trap excludes, because a refusal kills the run, a killed run never promotes, and so no ledger row is ever written for the one event that proves a limit exists.

The lowest-cost durable slot was already declared and empty. The run store — an embedded database on the shared config home, outside both the run directory and the committed ledger — carries a holds table in its schema that nothing writes. Both halves of the survivorship requirement hold there by construction.

The binding window is inferred, and says when it cannot be

Landed 2026-09-14, commit f26287e. Two refusals of one lane about five hours apart report the weekly window as binding, because the short window reset in between and the lane refused anyway. Two far apart report the short window. A single refusal reports undetermined rather than guessing.

Why this works for a lane whose probe says nothing. The inference reads the durable refusal stamps rather than any live reading, so the evidence is constructed from refusals the lane could not avoid emitting rather than from a position it never publishes. That is the whole argument for stamping refusals in the first place, arriving as a usable answer.

Measure: 9 passed, 5 tests added. One mark, not two tiles

Landed 2026-09-14, commit a5254ef. The Crew surface renders a quota meter carrying the position, the reset at its right edge labelled with the window's own duration, and the projected exhaustion plotted on the same axis. When the projection falls left of the reset the lane will run out before it refills, and the bar says so.

Why one mark rather than two tiles. Position and rate are orthogonal, and the state that costs a session is low position with high burn — which two adjacent tiles render as reassuring, because the eye reads the small number and stops. That is what happened on 2026-09-03: the lane read thirteen percent used while burning at seven and a half times sustainable, and the position figure only became alarming once it was too late to act on.

Measure: 8 passed, 298 lines of new tests, every case driven by a fixture payload rather than a live account — so the tests measure the surface rather than the lane, which matters more than usual given the lane's figures moved by a factor of eight within thirty seconds today.

Two assertions are negatives, and both exist because a surface is most tempted to fake exactly these. A backend whose payload reports no window renders no meter at all, asserted by the absence of the element rather than by its text, because a surface that assumes a period is inventing state. And no cache-hit figure appears anywhere in the rendered region — placed beside a burn figure it implies a lever that does not exist, since the meter charges cached re-reads anyway.

The run was classified abandoned on an incomplete manifest while its commit had already landed cleanly, one ahead of base with a clean tree. Redispatching on the classification would have discarded two hours of work and 563 insertions.

Derived rate figures now carry that marking and the meter position does not, so the distinction lives between them rather than as decoration on both. 3 further tests, 10 passing.

The cause was the coordinator's, not the worker's. The node contract was assembled from this section's node table and never cross-checked against the plan's own decisions, so a requirement locked elsewhere in the same plan was silently absent from the measure. A borrowed figure is never shown as the lane's own

Landed 2026-09-15, commit 6c18dd4. All four codex lanes declare the same command, so one account-level probe is rendered against each backend name. Identical readings prove they were probed identically, never that they share a budget — and an identical reset time is not a discriminator either. A lane whose figure came from a probe shared across diverging declared pools is now marked borrowed rather than carrying another account's number as its own.

Grouping is declared, not inferred. Backends declaring the same pool carry the shared probe legitimately; identical reset schedules never group without one, asserted directly. The worker drew a sharper distinction than the brief asked for: sharing a probe command is not the same fact as sharing a budget, and only a declared pool settles which.

Grouping is declared, not inferred

Landed 2026-09-15. The flight schema now declares the quota-group slot a backend carries, so an account pool is named by the operator who owns it rather than inferred from identical readings. Four tests assert the slot: it resolves from the shipped layer and reports the layer that supplied it; two backends declaring the same group resolve as one pool; two backends sharing an identical reset time with no declared group stay ungrouped, asserted directly so a shared reset time can never group; and an invented reset-time key is refused by the schema, because a reset time is not a legal configuration key for grouping to quietly rest on.

The month figure is not the gate a dispatch consults

Landed 2026-09-15, commit a8692b4. The account's month-scale figure cannot reach the decision a reader makes about a lane. The window a request actually runs into is unifiedWindows.five_hour; the top-level overage line records the account's calendar position, reads above 1 for the rest of the month, and resets on the month boundary. Neither the month figure nor its reset may appear in the emitted state or its reason.

Behaviour was verified, not reimplemented. The windowed read already keeps 1.21 and the month-boundary reset out of the verdict at the dispatch's own entry point — one preflight with the measured shape (top-level 1.21 and overage aside a five-hour window at 5% with a near reset, no severity, no exhausted status) reports the lane open, and neither figure reaches the state or reason.
