§3 — Coordinator cost per landed node

Commits e2fc9f03, 280d7fa9, 118b06ba and 474d8119 extend reckon/velocity.py with a coordinator_cost section. Each landed node names its coordinator's runtime session, so nodes are grouped by the session that directed them; the section then divides that session's assistant responses, logical input, separately reported cache-read share and output tokens by the nodes it landed in the window. Runs whose node carries no runtime session id enter an explicit unattributed bucket. The transcript accounting is ported from the review's census and the module imports nothing from docs/.

§5 — Work in progress is visible

Commit fe33dbf6 extends reckon/velocity.py with a plan census read from each project's own git history. A plan is opened by the commit that added its file: the earliest commit at which the path exists, counted only when that commit added the file, so a path whose first appearance is a rename has no opening here. It is closed by the earliest commit at which its plan-status reaches shipped, done, superseded or abandoned, or its plan-archived flag is set — counted once however many later commits repeat the state. Pending is every plan not closed at the named commit. The census buckets opened and closed by ISO week and measure rolls them up per project beside each project's pending backlog. A second reading, plan_cohort, answers the review's question: of the plans opened in a window, how many are closed as of a named commit. The module imports nothing from docs/.

§4 — Session continuity share per lane and day

Commit 106e4bbb adds session_continuity() to reckon/velocity.py and reports, per lane and promotion day, the share of all dispatches that continued another task's session. A dispatch continues another task's session when its recorded session_id equals that of an earlier-dispatched run whose (project, plan, node) differs. Each lane-and-day cell carries the share beside the same-task, fresh and unmeasured counts; a dispatch with no recorded session_id is unmeasured and is never counted fresh and never counted as a continuation. Classification runs over the whole population before any cell is formed, so a continuation is counted in the day it lands even when the run it inherits is in another cell, and the join uses the recorded session_id rather than a second rollout parse.

They disagree on magnitude before the switch, 37.98% against 7.08%, for two stated reasons.
