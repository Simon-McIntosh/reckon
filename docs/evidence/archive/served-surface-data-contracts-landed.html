§2 — Figure rows, and an edited stamp on every row

Discovery emits one row per PNG and SVG under docs/figures, with the slug taken from the path relative to that directory and the dimensions read from the file headers rather than from an imaging library: _png_dims unpacks the big-endian integers after the signature and IHDR, and _svg_dims reads the viewBox or the width and height attributes. Rows are appended after the typed resources, and reckon/resources.py continues to treat figures as infrastructure, so no figure becomes a typed resource.

Every inventory row of every type carries an edited stamp derived by _row_times from the last commit time, replaced by the working-tree mtime when the path is modified or untracked, and never earlier than created.

Measure: tests/test_serve_figure_rows.py, tests/test_spa_state_boundary.py and tests/test_discovery_cache.py pass.

§3 — The fleet index is computed, not read

reckon/fleet_index.py derives each mounted project's row from its own repository: status buckets by the same effective-status rule the project surface applies, the live count from that project's run pointers, the latest edited stamp across its artifacts, the active sprint from the distributed sprint resources or null, and a thirty-entry activity series counting commits per calendar day from one git log per project. A project with no commits in the window reports an empty list rather than thirty zeros, because a flat line and a silent project are different facts and a reader cannot tell them apart from a drawn line. The reference instant is a parameter of the function rather than the wall clock, which is what keeps the test from becoming a fuse.

Measure: tests/test_fleet_index.py passes and tests/test_project_state.py stays green.
