The finding that outlived the plan

Five times a capability landed in the module owning the mechanism while the call site sat outside the node's fence, so a green suite covered a dead feature. The role reached the snapshot and not the transition builder. The reason reached the parser and not the deriver. The alias reached the ticker and not the label composer. The width resolver reached the ticker and not the grid constructor. The shadow dimming reached the renderer while the producer carried no lineage at all — that one had never fired once, and the renderer's own docstring stated it read a fact the producer never wrote.

The counter-evidence sits in the same day and settles the cause: every node whose done-when named the entry point a reader reaches — asserted through the dispatch path rather than the helper, constructed from a real pointer rather than a synthetic event, routed through the follow command's own grid construction — worked first time. The defect was in the measures, not the work.

A contract test was introduced to catch the class and caught neither of the last two, for two separate reasons worth keeping. It asserted the snapshot carries a value for every field the ticker's column set reads, and presence is not correctness — it passed while the value was present and wrong. And it was keyed to the column set, while shadow dimming is a whole-row attribute rather than a column. It now covers every event field the renderer reads by any means.

Two records of no capability

Kept because in each case the absence is the result.

  • The pane's own width is not measurable from inside the process. Process ancestry reaches the hosting terminal and reports 208 columns, tracking a resize. The pane drawn inside it is not a pty, so no ioctl reaches it, and the harness bundle that draws it carries the pane's label as a bare string literal far from any layout arithmetic. Any frame inset is therefore inference. The remedy was positional rather than numeric: move the counters ahead of the reason and the line stops depending on the width being exact. That reversed an earlier directive for flush-right counters, because flush right means last and last means sacrificial.
  • Two sessions read inventory rows as live failures for most of a day. The watch log tagged every row baseline or transition and recorded a null from-state on all 167 baseline rows against 367 transitions, while the renderer routed both through one formatter and contained no reference to the event kind. So each follower restart emitted one alarming row per live run, and a terminal one carried a full failure reason that read exactly like news. The cost was diagnostic rather than cosmetic: an implausible-looking abandonment note prompted a classifier investigation which found a real defect, while the row that prompted it was inventory from a restart seconds earlier.
