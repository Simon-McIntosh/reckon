§2 — A plan with section declarations derives its impl from them

When section records do not cover every declaration, impl is derived from the declarations by count and the parsed state names impl_source: declarations, a third value added to the schema's enumeration; the covered case keeps computed, and a plan with no declarations keeps authored. reckon audit-doc reports impl-meta-stale when the file's meta differs from the derived figure. The four tests that pinned the superseded authored figure (test_impl_needs_every_section_recorded.py, test_impl_stays_authorable_while_records_are_partial.py, test_bookkeeping_earns_no_review.py, test_plan_review_store.py) were rewritten in a repair round, the store's acceptance of an authored impl write still asserted. §3 — a plan's age counts from its last commit

derived_plan_age in reckon/doccheck.py now reads a plan's last commit first, through the existing whole-tree _git_last_committed map, and falls back to the authored date, creation time and mtime only when no commit resolves. The audit loop, the roadmap's _authorisation_age and the archive candidate scan all route through it and report the age's source on the row. An active plan below impl 1.0 whose last commit is 14 to 30 days old is now reported AGING (info); STALE past 30 days is unchanged. Commit c597bb999, merged at c9320e15b.
