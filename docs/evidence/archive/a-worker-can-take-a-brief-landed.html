§2 — Dispatch accepts a brief

Commit dcb66ac8 on the base revision 3f251453 makes reckon crew dispatch take --brief <file> as the node's authority in place of --plan/--section. The two are mutually exclusive at the CLI (reckon/cli.py), and --plan is no longer a required option. TaskNode in reckon/crew/node.py carries brief, brief_sha256 and brief_path beside plan and section, and validate_node's fully-specified property is satisfied by either a plan or a brief. In plan_dispatch (reckon/crew/dispatch.py) the brief branch takes the digest and skips the committed-section and plan-review gates around their call sites — not inside routing.py — while scope claims, the write-path authority check and the fences still run. In dispatch the brief is copied under the run directory and its digest and stored path are written to the live pointer and the pre-launch claim; the text is passed to compose_prompt(..., brief=...) so the worker's task-authority slot carries it verbatim.

Correction — the record's directory is not committed

Independent review found the first brief landing contract untrue. It sent the record to this run's own directory and then said both go into the final commit, but that directory is crew_home()/runs/<run_id>, which lies outside the worktree, so git refuses a path under it with outside repository (exit 128). The instruction named an act the worker cannot perform. Commit e4d70125 rewrites the contract to state where the record goes, that the directory is never committed, that the node commits only the repository files it changes, and that the manifest carries the record's absolute path. Two tests hold the correction: one asserts the brief prompt carries no instruction to commit the run-directory record, one asserts the contract names the run directory as the record's home and says it is not committed. The figure convention and the meta-line ban are unchanged, the plan contract is untouched and the plan prompt stays byte-identical, and the declared mutation — restoring the commit instruction to the brief contract — fails both new tests at exit 1.
