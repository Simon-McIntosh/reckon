A finished run dispatches its own review — landed evidence

The §2 done-when passes on the recovery sweep: a scoring run with no review and a serving local lane has a review run in flight with no coordinator issuing a command, the contained half is asserted before the loud one, an unavailable lane is recorded with the lane’s own state as the reason and dispatches when the lane returns, and the follower admission that refuses a hand-typed dispatch refuses the automatic one by the same code and the same message. Four tests, four passes; the failing count over the cohort is unchanged from the base revision.

The change

_review_dispatch_fields in reckon/crew/recovery.py owns the composition once — project, plan, section, node id, goal, done-when, write path, time budget, session — and _review_dispatch_argv, _review_dispatch_action and the new dispatch_review_for_run all read it, so the command a record carries and the dispatch it performs cannot drift apart. dispatch_review_for_run takes one scoring run and returns a report rather than raising: dispatched says a review run is now in flight, awaiting_lane says the lane was unavailable and the reason is recorded against the run, refused carries whatever admission said no. recover runs the reflex for every scoring run it classifies and reports the outcome per run alongside its existing counts.

The node is dispatched as role=review with a write path outside the repository, because the review role is repository-write-restricted and the review store lives under the delivery root. The dispatch passes watch_required=True, which is the same admission a coordinator’s crew dispatch passes. The refusal is caught rather than propagated, and that is deliberate: the caller is a sweep over the fleet, and one run’s refusal must not stop the rest. The refusal itself still comes from dispatch.

The path, and where each assertion sits on it

The same dispatch call decides all four. Nothing in the reflex re-implements an admission check; assertion 4 is the claim that this is so, and the follower gate on the automatic path is the one asserted to still fire.

What the suite was suppressing, and why it matters to the test

The suite’s autouse configuration fixture sets RECKON_WATCH_ARMING=off for every module it does not mark, and dispatch converts a suppressed arming into a recorded waiver rather than a refusal. So the first version of the refusal assertion read dispatched: True — not because the gate was broken but because the environment had waived the requirement it asserts. The module now carries pytestmark = pytest.mark.arms_watch_producer and arms a real producer, which is the only form in which assertion 4 means anything.

This is recorded because it is the shape of a test that passes for the wrong reason: an environment that disables the guard makes the assertion succeed on the path where it should fail. The waiver is correct behaviour for the fleet and a trap for a test that borrows the fleet’s environment.

The boundary of what landed

The reflex is reached through recover, the sweep. It is not yet wired into the dispatch ticker, so a run that reaches scoring and a coordinator who never sweeps still see the old behaviour: the state’s action remains the command string. ticker.py and cli.py are outside this node’s write scope and were not touched, so this is a follow-on rather than an omission: the composition, the lane handling and the admission path are shared and already exercised, and the ticker call is one line at the point where it currently prints the action.

The lane-unavailable branch is exercised through the config resolution (flight.select_local_backend raises when local_backend is unconfigured) and through BudgetHold, and the reported reason is asserted to be the recorded reason — the run says why it is still awaiting review rather than only that it is.
