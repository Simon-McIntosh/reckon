The project selector scopes the page — landed evidence

Seven commits landed the shell work and all seven were proven ancestors of the head. The two things worth reading here are the gaps that a review found afterwards, because both were the kind that a passing suite reports as fine.

Record scope

Four of the seven measured shell defects were fixable against the data the server already served: a visibility toggle that did nothing, a topbar ordered differently from the canvas, a Crew list that neither scrolled nor scoped to the selected project, and a ground and type ramp that were not the canvas's. All landed, with six captures at two widths.

The selector was narrower than the canvas specifies

The plan states a 168px minimum for the project selector. The stylesheet set 150px. Both numbers were true statements about different things, and nothing compared them, so the disagreement survived the plan reaching full implementation.

The repair is recorded not for its size — one declaration — but for how the disagreement was settled. Neither the plan's prose nor the shipped CSS was treated as the authority. The handoff canvas itself sets min-width:168px on the selector, so the plan's figure is grounded in the design and the implementation was the defect. The check fails at the base revision on assert 168 == 150 and passes at the head: 17 passed, one pre-existing unrelated skip.

The available shortcut was to edit the plan to read 150. That makes the two agree, passes every check, and destroys the only record that the surface had drifted from the canvas. A plan corrected to match its implementation cannot report drift, because it no longer disagrees with anything.

The capture gate read a directory this plan does not write

§6's capture evidence rested on tests/test_spa_owed_captures.py, which hardcoded a single docs/figures/rendered-evidence root. Three plans cite that file as their capture measure and none of them writes that directory. All three had real captures on disk carrying real metrics, and a gate that never looked at them.

It now reads each gated plan's own index — capture indexes read rise from 1 to 3 — and asserts the captures exist, carry their recorded viewport width, and show the population their section requires. What makes it a gate rather than a formality is that it was shown to refuse: pointed at a synthesised plan with an empty index it fails with capture index holds no captures. A gate never demonstrated to refuse is indistinguishable from one that cannot.

Eighteen deliverables stated without a measure

A prose-deliverable audit over this plan found eighteen deliverables written as prose with no measure of their own. Exactly one was not done — the selector width above. The other seventeen hold at the head and are asserted by nothing, so each would break silently.

That is recorded here as a known property of this plan rather than as outstanding work, because writing seventeen assertions after the fact is a different job from the one this plan describes. The number is the useful part: a plan can be entirely correct and almost entirely unguarded, and its implementation percentage says nothing about which.
