§6 — The dry run consults the launcher it predicts

Outcome. sweep() judges an eligible run, then — in dry-run mode — returns before a launcher is ever consulted. Its report said would_resume: True, which reads as the launcher would resume this run and means only the sweep would call the launcher. A prediction is now made by consulting the launcher's own guards, so the two claims are one claim.

Both repairs the plan offers were available. The guard consultation was chosen over the rename, because a rename fixes the wording and not the harm: the incident's damage was an operator acting on a list of runs that a real sweep would refuse, and only consulting the guards can empty that list. The rename would have left the dry run unable to answer the question it is asked, under a more honest name.

The defect, reproduced before it was repaired

The pre-change branch, at reckon/crew/resumption.py:

if dry_run:
    resumed.append({**entry, "would_resume": True, ...})
    continue
try:
    launched = _resume(...)

Disabling the new consultation restores that behaviour exactly. Under it, a run whose lane's budget verdict holds it — which resume_plan() refuses — is reported by the dry run as a resume: with the guards unconsulted, report["skipped"] for that run is empty and the run appears under resumed. The parity test fails on it (the prediction missed the 'budget' guard), and the end-to-end assertion fails with IndexError: list index out of range on skipped[0] — the over-report the plan describes, shown rather than asserted.

The one added failure, and why it is not re-swallowed

Its fixture (_waiting_pointer) builds a pointer with no launch field, no argv and no repo — a record resume_plan() refuses with not a spawned run, so a real sweep never resumes it either. The test asserted would_resume is True for it, which is true only of the sweep's intention and never of the launcher's action: the fixture was resting on precisely the fail-open this node closes. The repair is one launch: "cli" (plus argv) in that fixture — a file outside this node's write scope, reported rather than edited. Weakening the guard to keep the test green would restore the defect and report safety it does not provide.

What the guard consultation does not do

It does not write. resume_plan() records a budget check into the ledger and stamps the pointer with an unchecked context-fit marker; a prediction that did either would leave the durable traces of an attempt that never happened, so the budget guard is evaluated from the same recorded evidence without the ledger write. It also carries no live provider probe of its own beyond what the recorded evidence holds — the guard reads what the launcher reads, and a probe the launcher would make is made here too, because a prediction that cannot see the launcher's evidence cannot predict the launcher.
