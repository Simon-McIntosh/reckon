§2 — Session-scoped provisioning

Commit 632712f. A dispatch naming no member now derives one from the dispatching coordinator's session — a stable session-<digest-prefix> identity — so two coordinators cannot select the same row. Concurrent roster registration retries optimistic write conflicts, and the session-owned row is written after pointer preparation so a failed setup still unwinds cleanly. Named members keep their existing validation and reuse path untouched.

The measure is the collision itself, reproduced and shown absent: two concurrent unnamed dispatches produced two distinct derived members and zero refusals, and a follow-up dispatch from the same session reused captured session 019ff509-8a60-7723-94fd-65942a6d8faa — so anonymity and warm-session continuity hold at once, which was the tension the plan had to resolve rather than trade. 136 passed, 0 failed across the crew, ephemeral-member, gc and routes suites.

The defect was measured three times in the session that fixed it

This plan was written from a live collision and then produced two more instances of its sibling defect while being executed. All three are the same shape — a node fenced out of a file it structurally requires — and none was caught by the seven-property check, because every property it tests is about the node in isolation.

Two things worth reading off that table rather than leaving implicit. The workers behaved correctly every time — each refused rather than writing outside its scope, so the fence did its job even when the fence was wrong. And the third instance was caught only because a stale --peer declaration happened to be reviewed by hand: dispatch accepted it, because a peer list is supplied by the same coordinator that got the scope wrong and is therefore no independent check at all.

That last point is a finding this plan did not start with. Auto-provisioning removes the contention between coordinators; it does nothing about a single coordinator fencing its own concurrent nodes off each other's files. The scope a node needs is derivable from the files it is asked to change far more reliably than from a hand-written peer list.
