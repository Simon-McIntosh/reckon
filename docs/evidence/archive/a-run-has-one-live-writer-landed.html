§2 — a worker never outlives its supervisor

Reproduction. A worker launched through an intermediary is reparented to init when the intermediary exits. The run directory's worker record then names a pid the process table no longer holds. local_liveness falls through, and a manifest left at complete is classified complete and then scoring while the worker still runs. A direct worker's children survived too, because the signal reached only a process group the worker did not lead.

Repair. signal_worker gains reach_run. It ends every process the run owns, found two ways: by descent from the recorded supervisor and worker pids, each checked against its recorded start time, and by RECKON_RUN_ID in a process's environment, through a new private /proc scan, _processes_owning_run, with a launch-time floor. A process whose environment cannot be read is not signalled. A process that only holds the worktree as its cwd is listed, never signalled. _signal_process_group gives the reach to every run-ending caller that passes a run directory, so promotion release, the stall watch, review delivery and the rest inherit it. The suite runner and fleet service stops stay single-pid. crew stop records ended_pids, alive_after and held_by. The supervisor's exit record names the pids ended. A run whose recorded pids are gone but whose environment mark lives reads alive.

§3 — a resume never launches beside a live attempt

Cause. Launching a resumption was not atomic with the check that licensed it. resume_plan read the pointer and the caller spawned the process, but only later did record_resumption fold the new pid onto the pointer. A second door reading the pointer inside that window started a worker beside one that was already starting. Separately, _prepare_attempt_records in dispatch_launch.py published the new attempt marker and archived and unlinked the canonical worker.json before the backend was asked to start. A second launch that then died on the backend's active-writer refusal left a working run reading halted, and erased its only worker record.

Live reproduction on nova, measured by a peer and read only: r-20261014T044136316062-forward-solve-options.

  • One wait-lift started two supervisors at 08:16:40Z.
  • Their launches came 25 s later.
  • The loser died on the active-writer error and was recorded as attempt 8.
  • The pointer then named the dead supervisor, so the run read halted while its winner worked.

Repair.

  • An in-flight mark, carrying the launching pid and its kernel start tick, sits on the pointer while a launch is between its check and its recorded attempt. Every door judges the mark through process_liveness.record_process_alive, so a reused pid cannot hold a run off.
  • The sweep's own launch path, _resume, holds that window too.
  • A refused resume keeps its advice for the next resume.
  • A launch that meets a live attempt is refused before it writes its attempt marker or retires either canonical record. The live holder is found through live_worker_pid, which reaches a reparented worker by its RECKON_RUN_ID mark, not through a private copy.
