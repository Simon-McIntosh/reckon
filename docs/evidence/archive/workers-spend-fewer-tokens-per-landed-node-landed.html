§3 — the line-anchored edit tool

Run r-20261110T192355232896-anchored-edit-tool (local lane), landed at reviewed head 27ed13983a3d; independent review 110/120 with three non-blocking findings; armed arms at base cb5dcf17a3 (51 passed) and head (74 passed), zero failures added. The worker found and fixed a defect beyond the plan: an insert_after addressed to a line the same call replaces or deletes was lost; commit 7e3dea8112 keeps it, with a test.

Landing

reckon/anchored_edit.py now serves two MCP tools over stdio, read_anchored (lines as N:HHH|text, a default limit of 400 lines with the remainder named) and edit_anchored (replace, insert_before, insert_after and delete, addressed by N:HHH or by a bare HHH when exactly one line carries that hash). All anchors are verified and all overlaps detected before a byte is written, so a refusal leaves the file byte-identical and returns the current anchors for the region; the file is published through the shared atomic writer, keeping its mode, its line-ending convention and whether it ends in a newline. The console script reckon-anchored-edit is declared in pyproject.toml, taking repeated --root arguments and refusing every path when it is given none. Confinement resolves each path through its links and applies the fence's _within_any to the result, so a symlink inside a root that points outside it is refused with the target untouched.

Measure

tests/test_anchored_edit.py: 23 passed, covering every behaviour the section lists and including the console-script round trip that starts the server over stdio and completes a read and an edit through the MCP protocol. Ruff reports no findings on either staged path, and ruff format --check finds them formatted.

Defect found on review

The first version of the build loop left each original line with continue once it had emitted a replacement or dropped a deleted line, so the insert_after handler for that anchor never ran: a call that replaced line 2 and inserted after line 2 wrote only the replacement and reported success. The edit was lost without a refusal, which is the failure this tool exists to prevent. The three cases now branch on their own so the after-insert always applies, and a parametrised test covers the insert sharing an anchor with a replace and with a delete; both cases fail against the previous loop.

Negative controls

With the root containment check removed (_outside returning False), three confinement tests fail, the symlink-escape one among them. With the line-hash verification removed (_hash_matches returning True), the stale-anchor test fails alone: the two-edit call is applied and the stale anchor is accepted. A third run reverts the build loop to its continue form and fails both insert-after cases. Each run restored the module to its committed checksum.
