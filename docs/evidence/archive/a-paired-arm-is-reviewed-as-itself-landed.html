§1 — the review of a paired arm names the arm by its run id

Run r-20261018T084035535944-a-paired-arm-review-names-its-run, commits 0f4de52af and a5985da3f. _review_dispatch_fields in reckon/crew/recovery_review_subject.py now mints the review node id from the run id when _paired_partner_run_id (imported inside the function, since the two modules import each other) finds a partner. source_node stays the node id. _resolved_reviewed_run_id in reckon/crew/recovery_review_delivery.py takes a keyword-only refuse_ambiguous flag: with it set, more than one live pointer carrying the source node id returns the bare source. Only _reviewed_run_id_for_node in reckon/crew/dispatch_admission.py sets it, so only the dispatch grant changes. Because _paired_partner_run_id reads any shadow lineage, a standalone crew shadow run also has its review minted from its run id. §3 — A promoted run's review resolves its run

A review node id whose run no longer has a live pointer now resolves over the durable run records. _resolved_reviewed_run_id in reckon/crew/recovery_review_delivery.py falls back to _durable_reviewed_run_id when no live pointer carries the source node id. That function reads run_store.runs_for_node, a read-only reader added to reckon/run_store.py, scoped to the caller's project whenever one is given. The review node id's head suffix picks the one row whose reviewed head starts with it. No match, or more than one, returns the bare source as before, and a store that cannot be read returns it too.
