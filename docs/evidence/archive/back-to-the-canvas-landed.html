Read it against the canvas — landed evidence

Seven work sections, all landed. Three of them landed only after a review looked for deliverables the plan's own structure could not surface — which is the same failure, one level up, as the drift the plan was written to correct.

Record scope

Six surfaces had drifted from the handoff canvas because every implementing node read the plan's prose and nothing read the canvas itself. The plan corrected them and, in §8, made the canvas into a measure so the drift cannot recur unnoticed.

§2 to §4 and §7 — corrected before this session

Every routable view and reader kind scrolls inside the viewport; prev, next and the readout read one published list for every artifact kind; the reader chrome returned to the canvas's inline control and ground; and the sprint diagram prints the hours and completion its layout already computed.

§5 — The measure stopped moving

The section requires full screen to fill the screen and the measure to stop moving. The measure moved: the base reader capped its column at 760px while full screen allowed 820px, so the text reflowed at the moment it was being read.

The repair sets the base to the larger value, honouring the locked constant-reader-measure decision — constant at the larger of the two — which was read directly rather than taken from the commit's citation of it. A rendered probe now reads the content column in the base view, in full screen, and again after Escape, at two widths, and requires all three to agree. At the base revision the same probe read 760, 820, 760, and that failure was recorded before the fix.

The section's named gate could never have caught this: 24 assertions, exactly one of which touched a rendered measure.

§6 — The figure caption reached the index row

The server emitted each figure's caption and the reader printed it; only the figures index row discarded it. Caption assertions in the covering test rise from 0 to 11, counted at both revisions, and the row now emits no caption element at all where no description exists rather than falling back to a prettified filename.

How this was found is the part worth keeping. The deliverable had been deferred by instruction because its file was concurrently held — correct practice — and the record of that deferral went into a landed summary. A reader stops at a summary, and the dependency scan reads plans rather than section text, so the work was invisible to every surface that decides what runs next. A section-level census could not see it either; it took an audit aimed specifically at deliverables stated in prose with no measure of their own.

§8 — The canvas became a measure

The section meant to stop the drift recurring had no implementation at all: both files its own done-when named were absent from the tree. It now exists — 13 tests over two new files — and the property that decides whether it will work is that every named value is extracted from the canvas import by pattern, never retyped as a literal. A retyped literal drifts from the canvas silently, which is exactly how six surfaces drifted.

It raises CanvasValueError rather than skipping when a named value cannot be found, so a renamed canvas key is reported instead of quietly shrinking the comparison to nothing, and it reports compared, matched and mismatched as counts rather than a bare verdict. Its own tests run it against mutated copies, so it is demonstrated to catch drift rather than only to pass on a clean tree.

The plan's gate is prose, and that is a finding

This plan carries no gate element. Its aggregate gate in §7 exists only as prose, so it can neither block the plan nor be reported unmet nor be satisfied. An authored gate element with no passing verdict blocks a plan and drops it out of the ready set, which is loud; a gate written only as prose is silent. While this plan read ready at position one of the sprint's critical path, its own text described an acceptance condition nothing could check.

Measured across the sprint at the same time: no plan in it carries a gate element, so the project's strict gate enforcement is configured and firing on nothing. The repository's convention is to write the measure as prose when a plan is authored and add the element with its verdict when it lands — so a gate that never lands is a gate that never existed. The prose carries the intent; only the element has teeth.

That is the same defect as the deferred deliverable in §6, one level up. A deliverable written as prose never becomes work anyone can see; a gate written as prose never becomes a condition anything can check.
