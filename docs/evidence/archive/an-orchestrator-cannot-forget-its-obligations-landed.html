A worker's stop binds to its manifest

Commit ce87d4caa1539ebeb3b18d41d9e2073ba89a727e adds reckon/hooks/worker_stop.py and tests/test_worker_stop_hook.py. The Stop hook reads the harness payload on stdin and resolves the run manifest from RECKON_MANIFEST, else from the live pointer whose worktree resolves to the payload's cwd. With no run resolved the hook writes nothing and exits 0, so a coordinator or interactive session is untouched. With one, it refuses the turn end while the manifest is absent or its status: line is not complete, blocked or failed; the reason names the manifest path and the gap, and the refusal stops after three blocks for one run.

The installer prints by default and merges only on request

Commit fbf1bca147dc2c3bfc924cbcfb98d9f8df8d1997 adds reckon/hooks/install.py and tests/test_hook_installer.py. The module builds the settings fragment that binds reckon/hooks/coordinator_obligations.py under UserPromptSubmit and SessionStart in prompt mode and under Stop in stop mode. Its default call prints the fragment as JSON and returns it without opening the settings file; only an explicit write merges it, into the path the caller names and into the user-scope settings file when the caller names none.

The merge keeps every other key and every existing hook group, and refuses when a command it would add is already present anywhere in the target's hooks, naming the event and the command it found. The refusal is raised before the document is written, so it leaves the file byte-identical. The write itself is atomic: the document is composed inside the target's directory and moved into place, and a settings file that changed between the read and the write is not overwritten.
