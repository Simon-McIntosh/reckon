server-listens-before-it-watches — the port answers before the watch is armed

The defect, reproduced from the code. main called start_fleet_change_watch(load_mounts()) before ThreadingHTTPServer(...).serve_forever(), and _FleetChangeWatch.__init__ constructed one _ProjectChangeWatch per mounted tree, each walking its tree with os.walk. The server socket was therefore not bound until the last tree had been walked, so every connection was refused during that walk. The py-spy dump in the plan's §1 put the main thread in _watch_tree at islink with 10 of 13 trees done; this node's test reproduces the refusal by patching watch construction to take 5 s per tree over three mounted trees.

The change. main constructs the ThreadingHTTPServer first, which binds and listens, and then starts the fleet watch, which now arms each tree on its background reader thread, one tree at a time. _FleetChangeWatch.start sets running before launching the thread so the arming loop's running check cannot run ahead of it, and a lock guards the watch registry so a concurrent close cannot leave an fd registered after teardown. A tree is covered by the discovery reuse window (RECKON_DISCOVERY_REUSE_S, 60 s in the served process) until its watch is armed. armed_roots reports which roots are covered.

§15 — The cached index absorbs each change: code landed

Code landed at ced5b6e31 (worker head 43e6f9eb6; run r-20261024T030624268974-the-cached-index-absorbs-each-change, three attempts). The live head arm is still to run once the served process carries this code.

A source's change becomes a TreeChange (the covered files and the directories it named). mark_tree_paths records it on the cached build, and _absorb_marked patches every cached variant at the next read by re-scanning only the marked directories and re-reading only the marked files. An empty change keeps the build, and an unattributable one still drops it. The sources:

  • Kernel watch: it returns its burst's names.
  • Fast pass: it marks moved directories.
  • Git: a staged change marks nothing, and a commit marks the covered paths between the two heads.
  • Slow pass: it compares its walk against the persisted entries.
  • Change-stream handler: it marks its own burst's names, and a wake through the fleet watch's pipe marks nothing.

The first attempt found a regression of its own making. Once each absorbing read re-persisted the index, the fast pass's wholesale stamp reload hid a second write. A reloaded stamp is now adopted only where the directory still matches the detector's held stamp. One suffix set backs both covered_name and the walker's cheap rejection, so an uncovered entry never resolves a path. Resolving costs 21.07 µs per entry against 0.091 µs for the suffix check, over 10,779 uncovered files.
