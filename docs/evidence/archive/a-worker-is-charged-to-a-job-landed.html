A backend's placement declares a scheduler executable, its options, and optionally a job_id_probe. Dispatch resolves the scheduler head against the same PATH the launch searches and prefixes the already-resolved argv, so the absolute executable, the environment and the stream file descriptors are the ones the launch was built with — the wrap carries the launch through rather than replacing it. A backend that declares no placement is returned untouched, which is the sense in which the field is optional and the reason no undeclared backend changes behaviour.

The job is read, not guessed. A placed launch records job_id beside pid, read through the placement's declared probe so reckon learns no scheduler's own vocabulary; a probe that answers nothing records its reason rather than a fabricated id. Promotion carries the field onto the committed ledger row, which is the durable record a later attribution reads — the live pointer it was first written on is removed by that same promotion.
