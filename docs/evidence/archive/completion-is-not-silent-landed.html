One project watch, armed from dispatch

Commit 8b9a638 (2026-08-24, worker codex-m, 928 worker-seconds against a 40 m budget, 402 insertions / 31 deletions over 7 files, merged no-ff as 8cf8f0a).

  • One watcher, whole project. reckon crew watch --project P blocks on every live pointer at once. A per-run watch would scale with the fleet, which is exactly the shape that produced the incident below.
  • Exclusivity is kernel-backed, not advisory prose. A second watch for the same project reports the live watcher and exits; metadata whose process no longer holds the lock is reclaimed rather than blocking forever behind a dead owner.
  • Three exits, all of them events. A terminal manifest exits with the shared classification and next_action; a stream quiet past 15 m or --stall-window exits naming the stalled run; an empty fleet exits at once instead of waiting for work that does not exist.
  • Liveness is stream quiet, never the recorded pid. Reading the pid misled the session that found this, and an in-harness run has no pid at all.
  • Arming is reported, not remembered. Every successful dispatch returns watch.arming_line and watch.watcher_live. The pointer is published before the probe, so the empty-fleet answer cannot race a run that already exists.

Delivery is session-local, and now verified

Commits c47b3f7, ff0e950 and 7718c5d (2026-09-01, coordinator inline — dispatching workers to repair the dispatch guard they run behind was declined on the obvious circularity, and one live pointer in this project was already owned by a concurrent session). Root-cause analysis: Why a Finished Worker Reaches Nobody.

What the earlier sections could not reach. The three sections above made the producer guaranteed and its signal load-bearing. None of them could establish that the dispatching session read what the producer wrote, so the guard's predicate stayed “a producer exists for this project” — satisfied by a peer session's seat, and by the detached producer dispatch arms on the caller's behalf. Measured across four mounted projects on 2026-09-01: terminal runs unpromoted for 11 min, 16 min, 41 min and 4.25 days, the last behind a watcher process still alive after four days with nothing reading its stream. The arming form recommended in One project watch, armed from dispatch is the form this section refuses.

  • A follower per session, registered. reckon crew follow --project P --session S --attention filters the ticker to one session's runs and registers that session as attached. Several coordinator sessions share a project — two were live in imas-codex during the measurement — and each now hears only its own fleet.
  • Delivery is measured, not declared. A backgrounded shell's stdout is a regular file; a per-line monitor's is a socket. A pipe is traced to the process that ends the chain, up to four links, so follow | grep > file is judged by where the lines stop. The verdict is re-read live from the follower's descriptor, so a registration cannot outlive its consumer and one written under a weaker check is re-judged.
  • The guard asks the proposition that matters. A CLI dispatch whose session has no delivering follower is refused with watcher-required before a worktree exists, naming the command to arm. --no-watch stays the waiver and records the unattached session on the run.
  • One arming covers the session. The seat is released when a wave drains, so a follower that ended there covered one wave; it now waits for the next producer and re-derives state on re-attach, emitting only what changed. It also waits rather than refusing when no producer exists yet, so arming ears before dispatching works.
  • The stream stores transition objects. A rendered line cannot say which session owns a run. Lines from a producer that has not restarted still read, with ownership unknown, so scoping degrades rather than breaking while producers turn over.
  • Negative finding, and the most actionable state. stalled was in neither the attention nor the progress set, so no filter ever woke anyone for a worker gone quiet inside its budget. The check meant to catch an unrouted state asserted against the recovery classes, which do not contain the states the ticker derives, so it stayed green over the gap. It now reads the states out of the function that emits them.
  • Second-order defect found while fixing the first. Read-only liveness took the seat's exclusive lock, so an observer could deny a producer's arming for the moment it held it. Observation is now lock-free and a claim distinguishes a passing probe from an occupied seat.

Skill repair — the second root cause. The correct arming rule already existed in the Claude Code harness reference, with its incident. The section a coordinator reads at arming time neither pointed there nor repeated it, and ended with “background the bare command and read its output file”. That section is rewritten around the two-part model, names session_attached, and sends the reader to the harness reference at the moment of arming; both contract tests moved from wording checks to intent checks.
