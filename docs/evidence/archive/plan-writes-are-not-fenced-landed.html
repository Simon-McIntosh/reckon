§5 — A comment append meeting a landing write is not refused and not lost

Commit 36330a4, 181 insertions and 41 deletions across reckon/_store.py, reckon/_plan_html.py and tests/test_landing_append_is_commutative.py.

Reproduced first, at the base revision. Two writers, a comment append and the landing write a promotion performs, were rendezvoused at the render step so each had proven its own version check before either replaced the file. Both passed. The failure the reproduction reported verbatim:

AssertionError: a comment was discarded on the meeting: ['c-edit'] at version 1; outcomes {'edit': FileNotFoundError(2, 'No such file or directory'), 'landing': 1}

The reading that matters is not the count but the shape. The landing writer returned version 1, so a write landed and the returned counter agreed with it. The file on disk held the other writer's comment, because both writers had rendered to one shared .html.tmp path and the landing writer's own replace call moved the other writer's bytes into place. The other writer's replace then found no temporary file left and raised. Two writers, one comment surviving, one version — a silent lost update with the counter advancing, which is the §1 shape and not a near one.

The mechanism, and what it replaces. Neither candidate repair alone was sufficient and the two are separable:

ChangeWhat it closes
Per-file lock over the version check and the replacementthe shared-temporary-file race and the two-winners outcome: the writer that arrives second is decided by the file rather than by scheduling, and the loser is refused rather than clobbering
Comment collections unioned by section and id before a write that lost its basethe refusal itself: an append is commutative, so the writer that did not lose content should not be turned away, and both writers' comments survive the meeting
A write that disagrees about anything other than the commentsstill a real conflict — merging it would silently revert the other writer's change, so it still raises
One parse helper for both the reader and the re-reading writera comparison that could never agree: the two sides must be shaped identically to be comparable

A comment is append-only, which is why the residue becomes an append-ordering question rather than a lost update. Position is kept from the file, so the result does not depend on which writer arrived last.

Positive control, asserted in the same test. A sequential append after the meeting still lands and still advances the version, and the full identifier set is asserted afterwards. A fence that refuses everything passes the falsifier alone; this one cannot.
