§4 — the pane ends when no work is live

Run r-20261012T225737550130-the-pane-settles-when-no-work-is-live, commits 6c2f9626a and cb61d58ff, merged at 68df03dfa.

A session's follower child prints one idle line and exits once its own session, and every session it observes with --observe-session, has no live run. That is judged by calling _population_has_live_work once per session. The session host removes the settled child from its census and stays alive, and the next dispatch's request starts one new child, which replays nothing already printed.

The child settles only when its host advertises that it can. An old host therefore never sees a new child settle, and a new host keeps an old-style child alive. This follows the rule that running hosts keep their old code while their children reload.

§15 — a held request stays queued

The queue runner (admit_once in reckon/crew/queue_admission.py) now asks the lane's gate document alongside the session allowance before it releases a queued pointer. A request the lane would still hold keeps its run id and queued phase, and appends no withdrawal, dispatch or re-queue row. A request whose last attempt failed for any other reason, such as a missing brief, is held under a doubling back-off (30 s, capped at 600 s). The back-off is keyed to a fingerprint of the request's brief, its plan and the flight layers that resolve its backend. It is deliberately not keyed to the router lane document, which is republished every few seconds. The first such failure is reported once, through failure_reported_at and one row on the watch stream; later passes report nothing.

§17 — a standing lift is not announced again on every restart

RowPolicy in reckon/crew/ticker.py now remembers, per pane, the lift groups it has drawn as in force (_lift_groups, decided in _feed_lift). A lift row carries no run id and holds its group in node, so it is keyed on the group. A grant records the group and prints. An end forgets it and prints, so the next grant draws again. A baseline in-force row for a group already drawn draws nothing, so the baseline a reloaded lift watcher emits for a standing lift adds no row, and a pane attaching for the first time still shows the lift once.

The three lift states are spelled in ticker.py rather than imported from lift_watch.py, which would close an import cycle. lift_watch.py is unchanged.

§19 — a producer that crashes is restarted

The fallback producer's inline supervisor (_WATCH_PRODUCER_SUPERVISOR in reckon/crew/dispatch_watch.py) now restarts a producer that crashes, instead of waiting on it once. A crash is an exit status from 1 to 127 (an exception escaping the watch loop exits 1), or a death by a signal the producer does not trap, which shows as a negative status (for example SIGKILL). A deliberate stop is left alone: zero, the producer's own 128 + signum exit for SIGTERM or SIGHUP, or a signal the supervisor itself receives, which it forwards. Restarts follow the fleet supervisor's curve: the first delay, doubling to the cap, with the delay and the crash count both reset after a steady run. After five consecutive short-lived crashes it stops and writes reckon crew watch stopped: producer crashed repeatedly; restart limit reached to the producer log. _watch_producer_argv passes FIRST_BACKOFF_SECONDS, BACKOFF_CAP_SECONDS and STEADY_RUN_SECONDS from reckon/crew/fleet_supervisor.py through the argv, so the values have one owner. The supervisor imports nothing from reckon, so a broken tree cannot take it down with the producer.

The first delivery restarted five times within about 1.5 s and never reset. A crash from a half-edited checkout, the case behind this section, would have exhausted that bound in the first second and left the seat empty again. The coordinator returned it, and the repair adopted the fleet curve.

Gate: tests/test_a_crashed_producer_is_restarted.py and the importers of dispatch_watch.py, 92 passed at head, exit 0. It was replayed green at the integrated head 3f33027df. The base arm failed 8, all of them the new file's own tests, and passed 84; nothing outside the new file regressed. Negative control: without the steady-run reset, the reset case fails, because no producer appears after a steady run and later crashes. Review: 102, then 104 after the repair, with 0 added. Its follow-on, that the curve's logic is restated beside next_backoff, is the deliberate price of an import-free supervisor.

§18 — a reload waits for a clean, importable tree

A follower or producer now defers its reload in two cases, and in both it keeps its running image and prints one dim deferred line. The first is when any tracked file under reckon/ differs from HEAD. _tracked_reckon_tree_is_dirty checks this with git status --porcelain -uno -- reckon. The second is when any module in the package fails to import, checked by a probe that now imports every module, not just three entry points. The tree is re-read each cadence, so committing the edit releases the reload even though the code stamp is unchanged. An in-place edit of the main checkout therefore no longer crashes the fleet's producers onto a half-edited tree.
