§4 — the pane ends when no work is live

§15 — a held request stays queued

The queue runner (admit_once in reckon/crew/queue_admission.py) now asks the lane's gate document alongside the session allowance before it releases a queued pointer. A request the lane would still hold keeps its run id and queued phase, and appends no withdrawal, dispatch or re-queue row. A request whose last attempt failed for any other reason, such as a missing brief, is held under a doubling back-off (30 s, capped at 600 s). §19 — a producer that crashes is restarted

The fallback producer's inline supervisor (_WATCH_PRODUCER_SUPERVISOR in reckon/crew/dispatch_watch.py) now restarts a producer that crashes, instead of waiting on it once. A crash is an exit status from 1 to 127 (an exception escaping the watch loop exits 1), or a death by a signal the producer does not trap, which shows as a negative status (for example SIGKILL). A deliberate stop is left alone: zero, the producer's own 128 + signum exit for SIGTERM or SIGHUP, or a signal the supervisor itself receives, which it forwards. Restarts follow the fleet supervisor's curve: the first delay, doubling to the cap, with the delay and the crash count both reset after a steady run. After five consecutive short-lived crashes it stops and writes reckon crew watch stopped: producer crashed repeatedly; restart limit reached to the producer log. _watch_producer_argv passes FIRST_BACKOFF_SECONDS, BACKOFF_CAP_SECONDS and STEADY_RUN_SECONDS from reckon/crew/fleet_supervisor.py through the argv, so the values have one owner. The supervisor imports nothing from reckon, so a broken tree cannot take it down with the producer.

The first delivery restarted five times within about 1.5 s and never reset. A crash from a half-edited checkout, the case behind this section, would have exhausted that bound in the first second and left the seat empty again. The coordinator returned it, and the repair adopted the fleet curve.

Gate: tests/test_a_crashed_producer_is_restarted.py and the importers of dispatch_watch.py, 92 passed at head, exit 0. It was replayed green at the integrated head 3f33027df. §16 — the pane draws no round trip

RowPolicy in reckon/crew/ticker.py keeps _shown, the word the pane actually drew for each run, and _departures, held round-trip rows. When a row takes a run away from its shown word into a settled stop or the dropped word, _hold_departure holds it for SETTLE_WINDOW, provided the row is not actionable and is not a coordinator duty. If the run returns to its shown word inside the window, the departure and the return are both dropped, so the pane draws neither. A departure with no return is delivered when the window passes. The hold is applied only where the policy has already decided a row would print, after the observer-context hold, so it can remove a row and never add one.
