§2 — Root cause: the served entry point went stale

Landed 2026-09-02, commit edd4488, node spa-project-render-fault, gate passed (reckon audit-doc … --check-links, exit 0, 0 ERROR). Full research record: spa-project-render-fault.

The measurement

The managed service entered its active state at 2026-09-01 22:10:59. Commit 737340f, which replaced the hard-coded entry-point renderer with one derived from the authored index, landed at 22:31:27 — twenty minutes into the life of the process that was still serving. The running server therefore emitted the entry point as it existed before that commit, and kept doing so for the following day.

The eight absent modules were shell-route, shell-topbar, shell-plans, shell-titlebar, shell-ready, shell-palette, shell-overview and shell-prompt. With shell-ready absent, window.ReckonShell?.ready?.ReadyGate evaluated to undefined, and the composition root took its fallback branch: <main data-shell-modules="unavailable"> with a child count of zero.

No exception was thrown. That is the property that made the failure expensive: an empty document, a clean server log, every request answering 200, and no error anywhere to point at the cause.

What the measurement excluded

Two hypotheses were raised from the reported symptom and both were falsified rather than merely set aside:

  • Project-specificity. The report named one project, and the first framing accepted that. Measured afterwards, all five checked mounts served the identical broken entry point. The home page continued to render because it does not depend on the missing modules, so its health never evidenced a mounted shell.
  • Payload scale and the distributed state format. This project is genuinely the only mount carrying a manifests/ tree and genuinely the largest payload (1.81 MB against 0.74 MB for reckon). Neither is causal: mounts on the single live aggregate, at a fifth of the payload, were blank in the same way at the same time.

Immediate repair

reckon service restart. Verified afterwards: every mount serves 22 script tags, and the served /_ui module list diffs identically against docs/index.html. All eight shell-* modules resolve 200.

This repairs the instance and not the class. Two defects the incident exposed remain open on the plan: the fallback renders a blank document silently rather than a legible failure, and no check in roughly thirty test_spa_* suites asserts that a project surface renders anything at all.
