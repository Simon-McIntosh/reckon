Why it was a third done already, and why nobody knew

The migrating node refused its own acceptance contract before starting. The contract demanded 149 moves in one commit; only 115 sources existed, because an August canonicalization commit had already moved 34. That commit's message says it flattened the research documents, updated every legacy reference, and added a guard driven by Reckon's authoritative typed-root map.

That guard is the layout check whose import raises. Reckon was not a declared dependency of the target repository, the import failed, and because its pytest configuration collects that directory by default the error interrupted collection for the entire tree. So one commit performed a third of this migration, added the test that would have verified it, and shipped that test unable to execute — dead on arrival rather than decayed. The canonicalization was left half-finished and its own check was blind, which is why neither half was noticed for a week. It is also the best available explanation for the 46 already-missing link targets: they have the shape of a partially applied move whose guard never ran.

Two disclosures the worker made rather than smoothed: it measured 50 pre-existing suite failures where a peer had reported 49 and kept its own figure; and it created 34 temporary compatibility symlinks so the real backfill could write through to the already-moved destinations, removed them before the migration, and kept them out of the commit.

What the collection column supports, and what it does not

Both receipts record whether the typed-layout check collects, and that column is doing narrower work than it first appears. It shows the suite was not silently broken between the two measurements, which is what it was built for and why the newly-broken figure can be trusted. It does not show the layout invariant was verified either side.

The distinction is the conditional import. The check now opens with pytest.importorskip("reckon.resources"), and reckon is neither declared in the target repository's dependencies nor installed in its environment — so in that repository the module is skipped whole and the file reports exit 5, zero tests collected. A measurement of two passing tests was taken where reckon was importable, which is real and is not representative of the repository the check lives in. Corrected here on a peer's measurement rather than left standing; the migration's own gate does not depend on it, so no conclusion moves.

The shape is worth more than the correction. Before the conditional import, a missing dependency aborted the whole tree at exit 2 — catastrophic, and impossible to miss. After it, the suite collects, which is a genuine improvement and was the point. But the check itself still never executes there and nothing says so, which is the zero-signal state this project's own guidance names for a disabled test: not run, invisible, nobody knows it exists. A loud failure became a silent no-op. The remedy is a decision rather than a repair — declare the dependency so the check runs, or remove a check that cannot — and it belongs to the repository that owns it.

Coordination

The write was authorised by the lead and scheduled by asking. Both live sessions in the target repository were consulted directly; one handed the tree over after finishing its own plan, the other confirmed its live run wrote no docs/ path and then deferred its own promotion until the window closed, because promoting would have written a plan comment into a file whose links were being rewritten. That ordering cost a peer a tidy landing beat and bought a falsifiable before and after.

The read path alone would have shipped a false headline. §5 — The shell and the cascade

shell.jsx goes from 1,837 lines to 350 plus eight separately loaded modules, with the SPA set held to an absolute zero rather than a delta because the tree was green when the split started: 120 passed, 24 skipped, 0 failed, and collection 144 either side so nothing was traded away. The module-scope regression that enforces the ownership property the split depends on stayed byte-untouched — editing the test that guards the property you are changing removes the only thing checking you.

The cascade gained a stated owner per file and a test that holds it: selector overlap 4 → 0, custom-property definitions outside the token layer 9 → 0, with two mutation controls proving the guard bites on each. The equality that matters is that nothing moved on screen — before and after renders byte-identical at 152 nodes and 22 authored scripts.

The duplication repair came first and paid for itself within hours. The stylesheet reckon-sync ships had silently drifted 448 lines and 72 selector groups behind canonical, so every synced repository was receiving a stale surface; the direction was established before either file was touched. Its parity guard then caught the very first divergence anyone introduced — an ownership comment — which is exactly what it exists to notice, harmless included.

§6 — Publication, and the decision that reversed

The deploy job gates on an exact repository-identity declaration in the repository's own tree, so a fork that copies the workflow does not inherit consent and no visibility or fork metadata can imply it. That is the locked rule rather than the plausible predicate it replaces: measured, publish-unless-private would have published a personal fork while reporting itself correct. Asset parity is asserted at 0 files differing, so the surface being designed is the surface shipped.

The lead then reversed the disclosure choice before anything published, on the ground that reckon is infrastructure others adopt and the plans belong to the codes themselves. So reckon withdrew its own declaration while the machinery stayed importable and tested for adopters, and a reckon badge command replaced the central example with a per-repository link. The badge refuses at both ends — no declaration, and no badge asset — so it can neither link to an unpublished site nor render as a broken image. Nothing was retracted because nothing was ever published: GitHub Pages was never enabled, verified by an authenticated read returning 404 while confirming admin.
