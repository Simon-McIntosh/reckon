The census, and why it over-reports. A pattern sweep over the surface — equality tests against a kind variable, title-casing mechanisms, kind-keyed lookups with fallbacks, raw tokens in visible elements — returned nine further candidates. None is live: five consult the route declaration before their fallback, so an animation resolves through it and the fallback is reachable only for an undeclared kind, and the remainder render a type badge where a type token is what is meant. So the pattern enumerates the sites, because a missed site never mentions the new kind, and then each hit needs a judgement about whether its fallback happens to be right for the new case. Handing a sweep to a worker without that instruction is a licence to break working sites while repairing broken ones.

§4 — Claims withdrawn

Recorded because each was stated confidently and each was wrong in a way worth keeping.

  • “The server restart broke the project selector.” Attributed a slow selector to a cold cache after a restart. Three consecutive calls measured 28, 32 and 30 seconds: it never warms, so the previous process was equally slow and the restart was not the cause. The real defect is thirteen mounts recomputed serially with no caching, one repository costing 24 seconds by parsing 937 HTML files.
  • “Both features are live.” Verified the served JavaScript and the served payload, then composed them into a conclusion about the rendered page. Both halves were true; the index module sat between them and was never read. Two valid facts about adjacent layers do not compose into a fact about the layer between them.
  • “The output reservation is a policy constant.” Inferred a quarter from two exact figures on one lane. The sibling lane reserves 3.1 percent, so the reserve is per-model and the roundness was a coincidence. A fraction derived from a correct resolution inherits none of its authority.
  • “My context measurement went stale.” Distrusting the five-day-old figure was right; concluding it had drifted was wrong. It named the usable input where the config named the served context, and the gap was exactly the output reservation. The first question is which quantity a figure names, not whether it has moved — assuming drift locates the error in the world rather than in the reading.

§5 — How it was verified, and the instrument that was missing

Every gate ran in a worker's own worktree; the merged-head checks are the coordinator's, because a worker asserting only its own commit cannot see what a pair does. The save control's greyed half was measured against live rows and its enabled half against a fixture, because its base predated the server field — the worker reported which half used which rather than claiming both, and the enabled-against-live-data check was the coordinator's.

The gap worth recording: no automated instrument here reads the rendered page against the live server. The browser harness's HTTP navigation path faults on this host, so rendered checks run against fixture state. That is why the index fix was verified against 58 figure rows and 1 animation row rather than the live 495 and 51, and why three of the five sites were found by the lead opening the page. A payload read and a source read cannot substitute; they are both producer-side.

One misclassification is worth its own line. A rendered failure was labelled navigation-never-completed from the harness's stage marker while the browser's own stderr showed navigation completing and the evaluation throwing fixture has no gif reader item. Accepting the label — a known, pre-existing host fault — would have merged a broken fixture under cover of an infrastructure excuse. Read the underlying stderr before accepting any classifier's verdict.
