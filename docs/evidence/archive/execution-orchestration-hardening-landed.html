§4 — The gate runs again at the integrated revision

Commit d3a27bc adds rerun_gate_at_integrated_revision to reckon/crew/promotion.py. It executes a node's gate command — the same gate_check command the run recorded — only when the repository actually sits on the integrated revision: the tree the coordinator is about to push. A run against any other tree verifies the wrong tree and is refused with the reason stated, never executed. The base verdict is taken as given (the gate the run already recorded), and a finding is produced exactly when a gate that passed at the worker's base is not passed by the integrated tree. An unmeasured re-run is reported not-run with its reason, never as passed.

The first case reproduces the failure class in the record: a gate green at the worker's base turns red at the merged head because a contract landed after that base. The very same gate command is red on the integrated revision, and the re-run reports the divergence. The second case proves the re-run stays silent when base and merged head agree. The third demonstrates the guard: the re-run refuses to execute against a tree that is not the integrated revision.
