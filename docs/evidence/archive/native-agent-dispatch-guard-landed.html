§2 — The refusal now reaches its reader, and the scope is the whole repository

Delivery (commit 5311e033a). The guard wrote its deny JSON to stderr and exited 2. The harness parses hook JSON only from stdout, so it took the whole of stderr as the blocking text and printed the raw object, script path included, as PreToolUse:Agent hook error: [<path>]: {"hookSpecificOutput": …}. The structured decision was never read, and the systemMessage reached nobody. The worker-message and worker-git guards shared the same main() and the same defect. All three now exit 0 and write the documented decision on stdout: hookEventName: PreToolUse, permissionDecision: deny, and the refusal prose as permissionDecisionReason. A note on an allowed call, such as the in-harness waiver's attach command, now travels as additionalContext, so the session that must run it sees it, and still as systemMessage for the operator. Against the previous hooks the five rewritten contract assertions fail (exit 2, JSON on stderr).

Scope and teaching (commit 70a164a6a). The scope test looked for docs/state/ only in the exact working directory, so a session in reckon/, docs/ or tests/ spawned agents unrefused. It now walks up to the nearest directory carrying crew or flight state. The walk stops at the first .git boundary, which is a file in a linked worktree, so a nested repository is judged by its own state. The in-harness waiver matches against that root. The refusal now tells a coordinator that a lookup needs no agent, and keeps the dispatch shape for fan-out. A session carrying RECKON_RUN_ID is told to do the reading inline within its run, with no dispatch line.
