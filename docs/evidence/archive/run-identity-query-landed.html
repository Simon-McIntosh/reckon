§3 — A session has a provenance, and an absence is stated

Commit 148d1cc. Gate uv run --no-sync pytest tests/test_crew_run_identity.py tests/test_crew_recover.py -q — 23 passed, 7 new and the recover suite's 16 held.

resolve_session is the sole authority and the view calls it, so a query and a resume cannot disagree about the same run. A pointer carrying an id short-circuits stream access; a promoted row with no pointer resolves from its committed row — the source that gets forgotten, and a false negative on exactly the runs a later audit asks about; a run with none anywhere yields a stated absence naming all three consulted sources, never a bare null, because not yet observed and genuinely absent are different facts and a coordinator once read one as a verdict on five runs.

resumable is the join across three roots, and its negative form is the useful half: false naming the released worktree when the directory is gone, false naming the live process when one is alive, true when a session resolves against an existing tree with a dead process. The reason string is what was actually needed at 19:41Z on the day of the incident and had to be derived by hand from a release result reporting only worktree_released: true.

This node reported an out-of-scope consequence instead of reaching for it — the section-2 test file expected a stored resumable flag to be authoritative, where the computed contract now correctly returns false naming the live process. Repaired separately in 702fb76, so the fixture asserts the derived verdict rather than a stored one. That is one failure at a merged head that no per-node gate could have seen.

§4 — Workstation scope, because the roots have different spans

Commit 2c8ad64. Gate uv run --no-sync pytest tests/test_crew_runs_scope.py -q — 1 passed carrying 13 assertions over all five required behaviours, plus 17 passed across the two sibling files and zero added ruff findings.

The config home is workstation-global while a ledger is per-repository, so "what is running on this machine" and "what has this repository recorded" are different questions against different roots. scope: "workstation" enumerates live pointers across every project in the config home and labels each row with the project and repository that owns it, including projects whose repository is not the working directory. A pointer whose repository no longer exists is returned with the repository reported absent rather than omitted or raising. A row from another project is data, never something to act on: the view is read-only, and the label is precisely what lets a coordinator tell a peer's run from its own without reading the peer's files — a boundary crossed four times across three sessions before this landed.

Isolation is asserted rather than assumed: with the environment pointed at a temporary config home, the real directory's mtime is checked unchanged. An isolated read does not prove an isolated write.

One note on the shape of the evidence. A single test carrying five behaviours was checked before acceptance, because one passing test against a five-part done-when is the pattern that hides an under-delivery; it genuinely carries all five. The cost is that a failure in it will not say which behaviour broke, which is the price of one shared fixture.
