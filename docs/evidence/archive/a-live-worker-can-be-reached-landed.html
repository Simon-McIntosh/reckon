§3 — A send addressed to a live crew worker is refused, naming the run and the command

The delivered surface is one self-contained, stdlib-only hook, reckon/hooks/worker_message_guard.py, modelled on the existing native-agent guard and wired the same way: reckon sync installs it as a PreToolUse group matching the harness send tool in a crew-managed repository's harness settings, beside the native-agent group, and removes both as one unit with exact byte restoration of the original settings file.

Decision logic

A send is refused only when every one of these holds:

  • the tool is the harness send tool, with a non-empty to recipient;
  • the send originates in a repository carrying crew or flight state (docs/state/<project>/{crew.json,flight.yaml});
  • the recipient string equals one of the identity fields of a live run pointer recorded under this host's crew live directory — run id, node id, member, session, or session id; and
  • that pointer recorded this host as its launcher.

There is no name-pattern fallback at any step. Two consequences follow from the identity-based, host-local match: a coordinator session that happens to share a node's name is not caught (the section's stated requirement), and a pointer launched on another host is never matched, so foreign pointers cannot make a session refuse sends here. These two are the falsifier's precise target — a guard that refused peer messaging generally would pass a test that only checked the loud half, and this one cannot, because its quiet half is asserted first.

The refusal

On a match the refusal names the resolved run id and the recovery-order command that reaches that run, with the message the send would have carried slot into the advice:

reckon crew resume --run <run-id> --advice "<your message>"

resume continues the same session with its prior context intact, which is the recovery-order answer for a worker whose turn has ended; a run still mid-turn resumes once its turn ends. The refusal states exactly that, so the caller is never told the send succeeded and is given the channel that actually delivers instead. One deliberate, visible escape remains for a case the guard did not anticipate: the session-scoped RECKON_ALLOW_PEER_MESSAGE override, named inside the refusal.
