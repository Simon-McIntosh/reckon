The leak that preceded it, and its reap

Separately and earlier, every browser gate on this host failed for a different and now-fixed reason. fs.inotify.max_user_instances is 128 per user; a browser needs at least one; leaked browsers hold theirs permanently because no parent survives to reap them.

One method note worth keeping, because the obvious discriminator is wrong. Selecting orphans by ppid == 1 matches 123 processes, 82 of which carry a real ~/.config/google-chrome profile path in their command line and look exactly like an interactive browser. Chrome helper processes are reparented to init and inherit that path, so the rule both over-matches and appears to threaten a user's own session. The safe discriminator is the pytest temp-profile path combined with an age exceeding every probe deadline.

§6 — Client load

Landed f9080fd and 7642080; gate passed, 9/9, browser-free. The served and static shells now carry zero text/babel scripts, zero standalone-compiler URLs, zero unpkg references and zero remote font origins. React and ReactDOM are served locally as production builds; the eleven JSX modules are compiled server-side and cached, so an edited component is still visible on reload with no build command — the constraint the locked no-build-step-constraint decision imposed.

A real defect was caught statically, not in a browser. The first implementation compiled each module but left its top-level const declarations intact, and plain <script> loading merges every module into one global lexical scope: Identifier useState has already been declared between two modules, which would have prevented the SPA from rendering at all. A syntax check over the concatenated output found it. The repair wraps each compiled artifact in its own scope; the gate now asserts an IIFE boundary on all 11 artifacts, parses all 10 SPA modules in declared load order with zero duplicate top-level lexical declarations, and confirms 39 window exports survive. That assertion is permanent, not a one-off command.

An integration defect the worktree could not have shown. After merge the live service returned HTTP 500 for every compiled module: No such file or directory: 'node'. The compiler shells out to a bare node, and the systemd unit pins a PATH that excludes the directory where node is installed, while a worker's shell has it. Restored by adding that directory to the unit's PATH, after which every referenced asset returns 200. That restoration is a hand-edit to a generated unit and the next reckon service install will overwrite it, so the durable fix is a separate node.

Locally served bytes went up, and that is the honest headline. React and ReactDOM now travel over the same link as everything else instead of arriving from a CDN, so a viewer reaching this server through a forwarded port trades roughly 3.4 MB of internet fetches for 179 KB more tunnelled traffic. That is a clear win on a constrained or offline network and a smaller one otherwise. The end-to-end reload time this section exists to reduce has not been measured, because measuring it needs a browser.

A corrected attribution

The reload cost was first attributed, in this plan and by two sessions independently, to the in-browser transform of roughly 240 KB of JSX. Measured, that transform costs about 470 ms including the compiler's own parse and initialisation — not the seconds the framing implied. Server-side timings are equally small: the document is 13 ms and warm discovery is 0.02 s. The CDN is fast from this host as well, fetching the 3.1 MB compiler in 0.17 s with no proxy in the path.

What remains is transfer: 888 KB across 25 requests before this change, of which discovery alone is 455 KB and is refetched on every reload. So the client-side framing survived and the named mechanism did not, which moves §5's revalidation seam from a refinement to the larger of the two remedies.

§5 — Live refresh

Landed 85d10ce; gate passed, 3/3, browser-free. window.revalidateProjectState is exposed as the one assembly used for both the initial load and an on-demand refresh, so there is no second code path that could drift from the first. The existing Refresh control awaits it and bumps the inventory revision instead of calling window.location.reload(), which is what previously made a full document navigation the only way to see a new plan.

The boundary gate proves two successive discovery reads publish inventories of one and then two plans, so a plan created while the page is open becomes visible without navigating. No polling was added, so the designed steady-state cost is zero added requests.

Owed: the rendered proof that document identity is unchanged and that zero navigation entries are recorded, and the measured steady-state figure. Both need a browser.

§3 — Scroll owner

Landed 034dc5d; gate not-run. .r-sprint-view .r-reader-with-attachments > .r-body is now the sole intentional vertical scroll selector for the Sprints view, and .r-sprint-surface carries zero overflow: auto declarations — it previously combined that with flex: 1, making the scroll container a flex child sized by its parent rather than its content, so material below the available height was unreachable rather than merely below the fold.

docs/_shared/foundation.css was verified byte-identical by SHA-256. That file is copied into every consuming repository, so a height rule changed there would have altered scrolling on every plan page in every project while fixing one screen.

Why the gate reads not-run rather than passed. No clean browser-free log exists for this node. Its captured run mixes the two rendered cases, which met the host fault above, with three pre-existing failures in node-evaluated helper tests that predate this node and are caused by untranspiled JSX. Recording it as passed would have required treating a mixed log as clean evidence. The constrained-viewport reachability capture at 900×420 remains owed.

A pre-existing failure this section surfaced

Three tests evaluate helper functions from docs/ui/sprint.jsx by passing the module text to node -e. That worked while the file held only plain JavaScript helpers; it fails now that the same file also contains JSX, because node cannot parse JSX. The failure predates this section and is not caused by it, but it bears directly on the remaining work: the sections that rebuild the horizon strip, the state table and the ready set all modify that file heavily, and they cannot be verified while its helper tests cannot run.

§2 — All-sprints state table

Landed 5af7c7b; gate passed, 6/6, browser-free. Every sprint in the project renders as a table row carrying status, an implementation figure, its derived order position and blocked/delayed/active flags, ordered by the server's sprint_order with a natural-id fallback. This is the section that answers the original complaint that there was no way to see all sprints at once.

Four properties are asserted rather than assumed, and each exists because a consumer project measured the failure it prevents. The composed metrics and review fields are consumed with no second fetch and no client-side recomputation. A project whose stored active pointer disagrees with its active set renders a conflict badge instead of choosing one — one project reports four simultaneously-active sprints by design while its pointer derives to a sprint that is merely first-with-unfinished-work, so any element naming one active sprint states a falsehood there. A sprint carrying no start or end date is still present, which matters because in that project undated sprints were three of four active lanes. And closed sprints fold by default, since 11 of its 17 sprints are closed.

§4a — Readiness served as a projection

Landed 3d38ac1; gate passed, 38 related tests. Readiness reaches HTTP for the first time. Before this, build_roadmap was the sole authority for ready work, reasons, blocked sets and critical path, and it was reachable only through the MCP tool and the CLI — so a browser client could not render ready work honestly at all, only recompute it.

One assertion is the whole guarantee. The test requires the served ready_set to equal ready_set_view(roadmap) for the same project. Equality rather than consistency is what makes a competing derivation impossible instead of merely discouraged, and the distinction is not theoretical here: two independently written copies of one review derivation, authored the same afternoon from the same reuse map by workers unaware of each other, had already drifted into disagreeing about sprint order. An equality assertion fails on the first commit that introduces the second copy.

Rows carry their reason and section granularity, so a plan ready at plan level with one blocked section reports both ready_sections and blocked_sections rather than a single verdict. A project with no review resource degrades to review: null without leaving a hole. Verified live after merge: discovery serves 13 ready rows with order, sprint, progress and what each unlocks.

§8 — Browser-gate failure legibility

Landed 6979f98; gate passed, 7/7. A failed probe now reports which of three start failures occurred instead of a bare timeout: ceiling-exhausted, sandbox-denied, or navigation-never-completed, carrying the browser's own stderr and the inotify count against the limit. A preflight refuses to start a probe at all when an AF_INET socket cannot be created, naming the worker role as the likely cause.

The third failure mode was discovered after the section was written, by the investigation recorded above: a read-only sandbox denies socket creation outright, so the browser aborts every scheme in 0.135–0.142 s on a crashpad setsockopt rather than timing out. That is instantly separable from both other causes, and it is why an investigate-role worker cannot reproduce the navigation fault at all.

The gate deliberately does not exhaust the real ceiling. Each classification is asserted from an injected condition, because proving the message by filling the shared per-user limit would inflict the host-wide outage this section exists to prevent — four nodes across two sessions each independently blamed their own change for it.

A cost this plan created, and owes

§6 added two browser tests that cannot pass on this host. Measured across the full suite by another session: four test_build.py cases each spend 75 seconds producing no assertion — roughly five minutes per run, landing as four indistinguishable timeouts behind which a genuine regression would be invisible. Two of the four trace to f9080fd here; the others predate this plan. Failing closed is correct where a browser works, but on this host it converts a known-unavailable dependency into opaque red. The remedy uses the classifier above to skip with a stated reason, and it carries one clause that keeps it honest: the tests must still fail, not skip, when a browser is available and the assertion is wrong. Without that clause a skip becomes a permanent blindfold.
