§1 — a review run is delivered only by a record of the head it was dispatched to read

Run r-20261018T215115257728-a-review-delivers-only-its-own-head, merged at c3e988abd (head 4d49a7084, 41 passed).

_delivered_review_record (reckon/crew/recovery_review_delivery.py) accepts a record as a run review's delivery only when all four of these hold:

  • it sits at the head-keyed path the review's dispatch declared;
  • it describes that head, compared through review_described_head and same_revision;
  • it names this review run when it names one;
  • it was written after the review's dispatch, read with run_id_dispatch_time.

The legacy path and the any-head .at-* glob no longer count as a delivery. A run review declaring no head-keyed path is refused by promote_review_run_itself with a reason naming the missing head. Every reader inherits the predicate: the watcher's self-promotion, promotion's review checks, and the round a promoting review files under its own id.

What the fail-closed guard exposed. Six tests in five files stored a delivered round only at the legacy path. Each now stores it at the head-keyed path of the head it dispatches, with its case kept. A sweep of all 67 test files touching stored review records, run at base and head, finds no test that passes at base and fails at head.
