The prescription judgement — the local lane's admission test

Node prescription-check-for-a-lane (§2). The lead ruling of 2026-09-21 06:35Z reopens the locally served lane for prescribed implementation nodes only. This node states that rule once, as a pure function, so dispatch reads a definition rather than the ruling's prose restated in a second place.

reckon/crew/prescription.py declares one public function, judge_prescribed(node: TaskNode), returning {prescribed: bool, failures: [property, …], detail: {property: reason}}. It reports every failed property rather than stopping at the first, so a caller reshaping a node sees the whole list in one pass. The judgement is pure — it reads no file, no config and no environment — which is what lets a dispatcher refuse an unprescribed node before any worktree exists.

Interpretation recorded for review

The ruling says "one artifact"; the cue in this node's brief glossed it as "at most one non-test path". Read literally over all write paths, that would refuse every node dispatched on a plan — including this one, whose record carries the two shared landing paths — which contradicts the same brief's requirement that this node's record pass. The judgement therefore excludes test paths and the two landing records, which is the repository's own existing notion of what a node's scope contains (reckon.crew.dispatch._shared_landing_paths: the plan file and the cumulative evidence record "are shared by all of them rather than owned by any one"). A node that produces two source artifacts still fails one-artifact.

Session ownership — a stored conversation does not outlive the session that opened it

Node worker-session-is-session-scoped (§2d, stage one: stop the lookup). An earlier record established that 252 of 259 roster session entries are owned by another coordinator session, and that the median roster session is around 525,000 tokens against the local lane's 480,000-token usable window — so the reuse path was already broken at the median, not merely wasteful. This node makes ownership load-bearing: a stored session is returned only when the coordinator session recorded as owning it is the session dispatching now.

Gate measure, as executed

  • Focused gate. pytest -p no:cacheprovider -q tests/test_worker_session_is_session_scoped.py → 13 passed, 0 failed (13 test functions; the ruling requires at least 8). Both branches are asserted separately: the configuration-keyed entry and the legacy entry reached through the bare session_id plus session_model fields. An entry recording no owner is asserted foreign in both. A same-session entry is asserted returned in both. The capture path is asserted to write the owner by reading the roster back after a synthesised capture. A dispatch to a member holding only foreign entries is asserted against the launched argv — "resume" not in dispatched["argv"] — and its run is asserted to carry session_withheld naming the session, its owner and a reason. reckon.crew.resumption.resolve_session is asserted to resolve the session from a synthesised run pointer, so the recovery path is independent of the roster.
  • The reverse direction. test_a_dispatch_to_a_member_owning_its_session_still_resumes dispatches to a member whose entry is owned by the dispatching session and asserts the session id is returned and that its token follows resume in the argv — the rule narrows the lookup rather than disabling reuse.
  • No collateral change. The 15-file promotion cohort recorded at ~/.config/reckon/crew/reports/unreviewed-promotion-exposure.md fails exactly 18, its measured before value, with this change in the tree (18 failed, 166 passed), and the failing id set is identical to the one measured before the change.

Negative findings on the way

  • Three tests encode the replaced behaviour. tests/test_crew_session_keying.py dispatches its nodes from a different coordinator session each call (session=f"coordinator-{'{sequence}'}"), so three cases assert that a session captured by one coordinator session is resumed by another — the defect this node closes. They are outside this node's write scope and are reported rather than edited: test_two_dispatches_at_the_same_configuration_resume_one_session, test_changed_effort_starts_fresh_and_both_sessions_remain_reusable, test_legacy_model_key_reuses_when_capture_configuration_matches. Each needs its dispatch session held constant (or its expectation inverted) before the suite is green.
  • The bare member add --session path stops resuming by design: a session set that way records no owner, so no dispatch can prove it. This is the same statement as the no-owner case above, recorded here because tests/test_crew_members.py exercises that path and already fails three cases at this base revision for an unrelated reason (a node contract requiring a declared specification level), so the behaviour change there is not currently observable.
  • Ownership is not preserved by roster re-registration. reckon.ledger.register_member rebuilds an entry from a fixed field list and does not carry session_owners, so a later member add makes an owned entry foreign. The failure direction is safe (a fresh conversation, never a resumed foreign one), and the write is outside this node's scope.
