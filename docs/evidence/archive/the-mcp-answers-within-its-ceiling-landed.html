§4 — A crew read returns the fields it was asked for

Commit 39dee90a (implementation and test) in the crew-live-honours-fields worktree, base revision a130260c.

The defect, reproduced

crew(view="live", fields=[…]) accepted the list and ignored it: the live arm called classify_pointer per pointer and returned every field of the classification, so the compact projection the runs view applies was never reached on this path. crew(view="runs") honoured fields but refused the three fields a coordinator checks first, because they were absent from the accepted set.

The change

  • reckon/crew/query.py — commits_beyond_base, log_age_seconds and manifest_reported_status joined OPTIONAL_RUN_FIELDS, so the existing refusal widened to accept them and the compact row carries them from the same classification the live path computes. A new session-aware project_live_rows classifies and, when fields is given, projects each row to the requested fields plus run_id.
  • reckon/mcp.py — the live arm routes through project_live_rows, so the requested fields are honoured; the mine marker is computed from the full classification and survives projection.

The gate measures, as executed

tests/test_crew_live_honours_fields.py on a synthetic config home with two live runs, head 39dee90a against base a130260c:

  • Live projection. crew(view="live", fields=["classification", "node"]) returns two rows whose key set is exactly {run_id, classification, node}.
  • Refusal names the accepted set. fields=["not_a_field"] returns ok: False with a detail naming log_age_seconds, commits_beyond_base and manifest_reported_status among the accepted fields.
  • The three fields are populated from the classification. A runs read with source="live" returns the three values equal to classify_pointer(row) for the same pointer, with manifest_reported_status == "in-progress", commits_beyond_base == 1 (a real git worktree one commit past its base), and log_age_seconds an int from the run's own log file.

Negative control, as declared and executed

Declared: remove the fields projection from the live arm. Applied to reckon/mcp.py (the fields= argument dropped from the project_live_rows call) and run over tests/test_crew_live_honours_fields.py::test_live_view_returns_exactly_the_requested_fields; the test fails, the row key set growing from {run_id, classification, node} to the whole classification. The control was then reverted and the tree returned to the committed revision.
