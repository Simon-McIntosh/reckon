§6 — A worker's harness caches leave with the worker

When an attempt's process exits, _supervisor_exit_record in reckon/crew/dispatch_launch.py removes the caches its harness built for that process: codex-home/cache/ and codex-home/plugins/, the codex plugin catalog each codex run downloads afresh, and the cache/ tree a worker's tools fill. It keeps codex-home/sessions/, which a resume needs, and records each removed path and its size, measured by the module's existing tree_size_bytes, on the exit record. Nothing removes the caches at any other time, so a running attempt is never touched.

§3 — Only a run something can still need keeps its directory

The retention pass in reckon/crew/gc.py now retires a finished run's directory once nothing can still need it, instead of after thirty days of directory age. A directory is kept while the run has a live pointer or a queued entry, has no terminal ledger row, has a review owed, or lacks its stream-derived figures on its ledger row. After that it is kept for a grace window, gc.directory_grace in flight config, 24 hours by default, read through the flight config of the checkout being swept and parsed with the existing parse_duration. Whether a review is owed is read through the committed-review walk promotion_checks already owns. Each removal is printed with its path and size before it happens.
