A window paces the lane — landed evidence

One section, one derivation, one declaration it could not reach. The allowance is no longer a configured cap: it falls out of the week's remaining budget and the windows left before the drain deadline, so it throttles a group that is ahead and opens up for one that is behind, with no gain term and no memory of how the week has gone.

§2 — The pace function, on two clocks

Commit 6fa4a99c. Gate tests/test_pace.py — 19 passed, exit 0, run through the repository's root environment with the module asserted to resolve to the worktree copy of reckon.crew.pace rather than to a sibling checkout, because a run that imports another tree's module measures the wrong revision. The two files are reckon/crew/pace.py and tests/test_pace.py; both are new, so the gate's baseline is an empty file set and every one of the nineteen is this change's own.

The allowance for a declared budget group is

remaining_budget  = 1 - utilisation
remaining_windows = (D - elapsed) / 5h
allowance_5h      = pace_multiple * remaining_budget / remaining_windows

with D the weekly period less a configured lead time, and the provider's own five-hour ceiling applied last as a separate number. The last window before the deadline is asked for whatever remains rather than for a share, so the deadline itself cannot construct a hidden None through a denominator of zero. A ceiling that could not be read is not a ceiling: the effective limit falls back to the derived share, because absence of a signal is not evidence of absent headroom.

The measure

Four states are named in the test before they are asserted, and the shape that separates them is the derivation's own rather than four literals: ahead of pace returns less than the multiple times nominal, behind returns more, exhausted returns nothing. The on-pace case is constructed — utilisation is set to elapsed / D — and then asserted to equal pace_multiple × (5 / D) with both sides computed in the test, so the equality is the self-consistency proof rather than a number that would keep passing after the formula moved.

The two tunables are each asserted to move the allowance, and separately. A doubled multiple scales the derived share exactly and leaves drain_hours alone; a longer lead closes the deadline and raises the share while leaving the recorded multiple alone. A third case asserts the pair is load-bearing in every returned allowance by retuning the multiple to 7.0 and reading it back off the returned record, which is what §9 needs of a row that is meant to tune the setting later. The ceiling comparison is asserted in both directions — one reading where the derived share is the tighter of the two, one where the provider ceiling is — and a third reading asserts that an unread ceiling leaves the derived share in force rather than holding at zero.

The negative control

Declared mutation, quoting the node: “drop the pace multiple so the allowance returns the bare nominal share on pace; tests/test_pace.py must fail”. It is a single token in derived = remaining_budget * multiple / windows, applied to a scratch copy of the committed package and run from a neutral working directory, because python -c and pytest both put the working directory first on the import path and a mutant run started inside the worktree re-imports the unmutated module — observed on the first attempt, where the resolved path was the worktree's own. The parametrized assertion that every returned allowance carries the multiple still passes under the mutation, and the distinction is worth keeping in view: the field survives, the factor does not.

What could not be landed in scope

The declaration, not the derivation. Both tunables are read from the budget block of resolved flight config, which is what makes them data rather than constants. For an operator to set either, the flight schema must carry the slots: BudgetConfig in reckon/schema/flight.yaml enumerates a fixed slot list, reckon/_flight_schema.py and docs/_shared/flight.schema.json are generated from it by scripts/regen_flight_schema.py, and the model is extra="forbid" — so a budget.pace_multiple written into any layer today is rejected as an unknown key rather than silently ignored or honoured. Those three files plus the shipped defaults are outside this node's write paths, so the half that remains is four declarations and a regeneration; until they land, the documented pair in pace.py is what applies and neither key is settable.

This is recorded rather than worked around deliberately: reading an undeclared key from the mapping would look identical in the tests and fail open in production, because the layer that would carry it is validated before any of this code sees it.

Follow-ons

  • Declare the two pace keys. Add drain_lead_hours or equivalent and pace_multiple to BudgetConfig in reckon/schema/flight.yaml, set the shipped pair in reckon/schema/flight-defaults.yaml, and regenerate reckon/_flight_schema.py and docs/_shared/flight.schema.json. Then the two key-change assertions can be made against resolved flight config instead of a plain mapping.
  • The reading is not this node's. pace.py takes a utilisation, an elapsed time and an emitted ceiling; who reads the two clocks off a served stream, and the age that reading carries, is the reader's own section. The effective-ceiling input is likewise supplied rather than derived here.
