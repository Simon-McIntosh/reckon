Group position is its freshest member reading

The defect. Read through crew(view="lanes") on 2026-09-21, four sol-family lanes shared one subscription to the second while each carried budget_group: null and its own reading, and codex-spark carried a separate pair of windows with a 6.7-day-old figure presented as a position. The lanes view already restated a declared budget_group into a budget_groups map, so what was missing was not the declaration but any computation that reads once per wallet: a position, a bar or a reserve computed per lane divides one allowance four ways and reports each quarter as the whole.

What landed. reckon/crew/budget_group.py resolves backends into their declared groups from resolved flight config and returns a group's position as its freshest member reading, carrying that member's own observation age. The module's only position callable takes a declared group identifier: group_position("codex", …) raises, so there is no route by which one lane's share of a shared wallet can be reported as the wallet's figure. Where no member reading can be aged the position is unobserved with no member and no age, never a zero that would read as a figure taken this instant.

§5 — Reading the windows without inventing them

Gate PYTHONPATH=$PWD .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_window_reading.py — 9 passed. ruff check and ruff format --check are clean on both paths; the files are new, so their finding baseline is zero and every finding reported was fixed rather than absorbed.

Each clause of the section's measure is carried by a named assertion:

  • The newest carrying event is the one read. A fixture whose newest event is a report carrying the top-level figure and no window still returns the two window figures from the earlier event, asserted for five_hour and seven_day together with an assertion that the top-level figure was not substituted.
  • No window anywhere is unknown. The reading is unknown, its figure set is empty, and the accessor returns None — asserted, for both periods, to be neither 0.0 nor 1.0, so it cannot read as exhaustion and cannot read as headroom.
  • The top-level figure is never a window. An overage record is asserted to contribute nothing to the returned figures even when it is the only figure present.
  • Every figure carries its age in seconds. The observation time is anchored off the closest surrounding stamped record, which is the mechanism the refusal hold already uses for the same reason; ties prefer the following record, since ageing a reading too far causes a needless re-query while ageing it too little is the safe direction. A window whose observation time cannot be established at all is unknown rather than a figure.

Two controls a green suite would not otherwise show. The first is a positive control for the never-zero rule: a fixture in which the provider genuinely reports 0.0 asserts that 0.0 is returned, so the rule is about the unknown reading rather than about a figure, and is not the vacuous shape "never returns a number that also means one thing". The second is a stamp-form control: the other fixtures build their timestamps with isoformat's +00:00 offset, while the fleet actually writes a trailing Z, so one fixture uses the real form — without it, a parser handling only offsets would age every real reading as unknown and no conveniently written fixture would say so.

§5 — The instrument against real streams, and one discrimination it makes

Read against five real fleet streams known to contain the string unifiedWindows: four returned figures with ages of 1.6 to 2.3 million seconds (their runs are weeks old), one returned unknown. The unknown one is the useful reading. Its single occurrence of the string sits inside an item.completed event — a worker's prose about the windows, not a rate-limit report — so a string-presence grep counts it and the reader correctly declines to. This is the same shape the section warns about: the reader keys on the event, so prose mentioning a window can never become one.

The same sample also shows a genuine 1.0 figure returned for a lane whose five-hour window the provider reported as full, which is the other half of the never-zero/one claim: the reader returns a real 1.0, and returns None, not 1.0, when it should.

§4 — The bookend reserve holds from the start of the window

A review dispatch verifying a local repair is small and bounded, and it is the first thing an audit wave starves: the wave ahead of it spends the window, and the bookend that would have closed the repair waits for a reset. The fix makes the window two pools rather than one. A fraction of every window is reserved for the review and verify roles and is not available to implementation work at any bar.

The reserve holds from the start of the window, and that is a property of the arithmetic rather than a branch on window state: a non-bookend role's ceiling is the window ceiling less the reserve outright. Nothing is withheld until the window fills, so the fraction is already gone when the window is empty. A rule that withdrew the fraction only near the ceiling is a function of utilisation; this one reads the role and the configured fraction alone.

§5b.i — The re-query, and what it returns when it cannot answer

The plan's premise for this section is a view that hands back a 2.4-hour-old receipt and a 6.7-day-old one as though they were positions. A five-hour window rolls over several times inside 2.4 hours, so an old figure is a statement about a window that has already closed. The landed mechanism decides, per reading, whether the figure and the age it carries are enough to report it, or whether the lane's own probe must be asked again.

Commit 0fc81fc, 161 insertions across the module and its tests. Gate pytest -q tests/test_staleness.py — 8 passed.

Reading inside its shelf life. The reading is returned as a position with its own serving state and requeried=false, and the probe is never called. The test supplies a probe whose body raises, so a call that should not happen fails loudly rather than passing silently — the assertion is that the re-query is not unconditional, which a test written without that guard could not show.

Reading past its shelf life. The probe is asked once; its figure and provenance are what the caller reports, with requeried=true.

A re-query that fails. Two failure shapes are driven — a probe that raises, and a probe that returns no figure — and both must not be read as a measurement. The old figure survives with its age and a serving state of unknown: neither a fresh-looking number nor nothing. That the returned used_percent is the old value and not the probe's is what makes "not a fresh-looking number" an assertion rather than a hope.

An undated reading is not trusted. A reading with no observation time cannot be shown to be inside any shelf life, so it is re-queried like a stale one; if that also fails, its age is reported as unknown rather than invented. This is the plan's carry the age with the figure rule applied at the one point it must be.

The shelf life is a flight key, and its change moves behaviour. The resolver reads budget.evidence_shelf_life_minutes through the same budget.policy the fence uses, and the test drives two resolved configs differing only in that key: a 90-minute-old reading re-queries at a 60-minute shelf life and is trusted at 180. The test asserts the resolved key values before asserting the behaviour, so a config plumbing error cannot masquerade as a passing boundary.

Negative control. The declared mutation replaces the inside-shelf-life guard with if False:, so every reading re-queries unconditionally. Applied to a scratch copy of the package and the test file, the named test test_reading_inside_its_shelf_life_does_not_requery fails (assert True is False at the requeried check); the unmutated twin of the same scratch tree passes. The log's first line repeats the mutation verbatim.

§2 — The pace function, on two clocks

Commit 6fa4a99c. Gate tests/test_pace.py — 19 passed, exit 0, run through the repository's root environment with the module asserted to resolve to the worktree copy of reckon.crew.pace rather than to a sibling checkout, because a run that imports another tree's module measures the wrong revision. The two files are reckon/crew/pace.py and tests/test_pace.py; both are new, so the gate's baseline is an empty file set and every one of the nineteen is this change's own.

The allowance for a declared budget group is

remaining_budget  = 1 - utilisation
remaining_windows = (D - elapsed) / 5h
allowance_5h      = pace_multiple * remaining_budget / remaining_windows

with D the weekly period less a configured lead time, and the provider's own five-hour ceiling applied last as a separate number. The last window before the deadline is asked for whatever remains rather than for a share, so the deadline itself cannot construct a hidden None through a denominator of zero. A ceiling that could not be read is not a ceiling: the effective limit falls back to the derived share, because absence of a signal is not evidence of absent headroom.

Figure note: the graphic is inline SVG rather than a PNG under docs/figures/, which is the usual placement, because this node's write paths cover only the two source files and this record.

The measure

Four states are named in the test before they are asserted, and the shape that separates them is the derivation's own rather than four literals: ahead of pace returns less than the multiple times nominal, behind returns more, exhausted returns nothing. The on-pace case is constructed — utilisation is set to elapsed / D — and then asserted to equal pace_multiple × (5 / D) with both sides computed in the test, so the equality is the self-consistency proof rather than a number that would keep passing after the formula moved.

The two tunables are each asserted to move the allowance, and separately. A doubled multiple scales the derived share exactly and leaves drain_hours alone; a longer lead closes the deadline and raises the share while leaving the recorded multiple alone. A third case asserts the pair is load-bearing in every returned allowance by retuning the multiple to 7.0 and reading it back off the returned record, which is what §9 needs of a row that is meant to tune the setting later. The ceiling comparison is asserted in both directions — one reading where the derived share is the tighter of the two, one where the provider ceiling is — and a third reading asserts that an unread ceiling leaves the derived share in force rather than holding at zero.

The parametrized assertion that every returned allowance carries the multiple still passes under the mutation, and the distinction is worth keeping in view: the field survives, the factor does not.

What could not be landed in scope

The declaration, not the derivation. Both tunables are read from the budget block of resolved flight config, which is what makes them data rather than constants. For an operator to set either, the flight schema must carry the slots: BudgetConfig in reckon/schema/flight.yaml enumerates a fixed slot list, reckon/_flight_schema.py and docs/_shared/flight.schema.json are generated from it by scripts/regen_flight_schema.py, and the model is extra="forbid" — so a budget.pace_multiple written into any layer today is rejected as an unknown key rather than silently ignored or honoured. Those three files plus the shipped defaults are outside this node's write paths, so the half that remains is four declarations and a regeneration; until they land, the documented pair in pace.py is what applies and neither key is settable.

This is recorded rather than worked around deliberately: reading an undeclared key from the mapping would look identical in the tests and fail open in production, because the layer that would carry it is validated before any of this code sees it.
