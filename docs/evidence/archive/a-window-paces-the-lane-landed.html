A window paces the lane — landed evidence

§5 has landed. The reader returns the newest event on a served run's stream that actually carries a window, with the observation age of that reading in seconds, and an explicit unknown where no window can be read — never a zero, never a one, and never the account's top-level calendar figure standing in for a rate-limit window.

Record scope

This record currently covers §5 only, the window reader. The plan's other sections are separate nodes and their outcomes are not claimed here. The reader landed in reckon/crew/window_reading.py under commit e302ad39, with its tests in tests/test_window_reading.py; the commit is insert-only, 475 insertions across the two files, and it changes no existing call path.

§5 — Reading the windows without inventing them

Gate PYTHONPATH=$PWD .venv/bin/python -m pytest -p no:cacheprovider -q tests/test_window_reading.py — 9 passed. ruff check and ruff format --check are clean on both paths; the files are new, so their finding baseline is zero and every finding reported was fixed rather than absorbed.

Each clause of the section's measure is carried by a named assertion:

  • The newest carrying event is the one read. A fixture whose newest event is a report carrying the top-level figure and no window still returns the two window figures from the earlier event, asserted for five_hour and seven_day together with an assertion that the top-level figure was not substituted.
  • No window anywhere is unknown. The reading is unknown, its figure set is empty, and the accessor returns None — asserted, for both periods, to be neither 0.0 nor 1.0, so it cannot read as exhaustion and cannot read as headroom.
  • The top-level figure is never a window. An overage record is asserted to contribute nothing to the returned figures even when it is the only figure present.
  • Every figure carries its age in seconds. The observation time is anchored off the closest surrounding stamped record, which is the mechanism the refusal hold already uses for the same reason; ties prefer the following record, since ageing a reading too far causes a needless re-query while ageing it too little is the safe direction. A window whose observation time cannot be established at all is unknown rather than a figure.

Two controls a green suite would not otherwise show. The first is a positive control for the never-zero rule: a fixture in which the provider genuinely reports 0.0 asserts that 0.0 is returned, so the rule is about the unknown reading rather than about a figure, and is not the vacuous shape "never returns a number that also means one thing". The second is a stamp-form control: the other fixtures build their timestamps with isoformat's +00:00 offset, while the fleet actually writes a trailing Z, so one fixture uses the real form — without it, a parser handling only offsets would age every real reading as unknown and no conveniently written fixture would say so.

§5 — The instrument against real streams, and one discrimination it makes

Read against five real fleet streams known to contain the string unifiedWindows: four returned figures with ages of 1.6 to 2.3 million seconds (their runs are weeks old), one returned unknown. The unknown one is the useful reading. Its single occurrence of the string sits inside an item.completed event — a worker's prose about the windows, not a rate-limit report — so a string-presence grep counts it and the reader correctly declines to. This is the same shape the section warns about: the reader keys on the event, so prose mentioning a window can never become one.

The same sample also shows a genuine 1.0 figure returned for a lane whose five-hour window the provider reported as full, which is the other half of the never-zero/one claim: the reader returns a real 1.0, and returns None, not 1.0, when it should.

§5 — The negative control

The declared mutation replaces the newest-event-that-carries-a-window rule with the newest event, so a newer windowless report erases the window reading:

index = len(ordered) - 1 if ordered else None

Applied to a scratch copy of the fixed tree, the named test (test_newest_carrying_event_wins_over_a_newest_that_carries_none) fails, as do four others; the driver asserts the imported module resolves inside the scratch copy before running, so a red produced against the unmutated tree cannot be mistaken for this one. The log is at ~/.config/reckon/crew/runs/r-20260921T101754262859-window-reading-carries-its-age/negative-control.log, first line the mutation verbatim.

What this record does not claim

It claims a reader, not a fence. Nothing here paces a wave, opens a lane or refuses a dispatch: §5 supplies the position and its age, and the sections that consume them — the two-clock pace function, the per-group target and bar, the reserve, and the four-lane pacing view — are separate nodes whose outcomes are not asserted in this record.

The reader is also not wired to any caller yet. §5's measure is the reader's own behaviour, and its tests enter at read_windows; whether the surface a coordinator actually reaches consumes it belongs to the sections that build that surface, and is the failure mode this repository has recorded most often.
