§4 — The bookend reserve holds from the start of the window

A review dispatch verifying a local repair is small and bounded, and it is the first thing an audit wave starves: the wave ahead of it spends the window, and the bookend that would have closed the repair waits for a reset. The fix makes the window two pools rather than one. A fraction of every window is reserved for the review and verify roles and is not available to implementation work at any bar.

The reserve holds from the start of the window, and that is a property of the arithmetic rather than a branch on window state: a non-bookend role's ceiling is the window ceiling less the reserve outright. Nothing is withheld until the window fills, so the fraction is already gone when the window is empty. A rule that withdrew the fraction only near the ceiling is a function of utilisation; this one reads the role and the configured fraction alone.

§3 — The bar names the lane, and never holds a prescribed node

Commit ea8d38f5. Four verdicts replace the single send that covered both lanes. send-metered is a node that clears the bar with room left in the window; send-local is a node the free lane executes as written; split is a close call in the band below the bar; and hold is a node too open-ended for the free lane, or one the full window has no room left for. The order of the tests in the one decision function is the policy: prescription is judged before the bar, because at a full window the bar sits at its ceiling above every prescribed score and a node judged by the bar alone falls through it into hold.

The bar is a smoothstep in the fill and is asserted monotone at 201 points, not at transitions a continuous bar does not have. It is fill²(3 − 2·fill): zero at an empty window, one at its ceiling, flat at both ends and steepest in the middle. One fixed score therefore travels from an admitted metered send at an empty window through the near-bar band to a hold at a full one, which is the only assertion that proves the bar reads window state at all.

The two assertions the rejected implementation inverted are pinned separately. A maximally prescribed node (score 0.0) is send-local at every fill sampled across the whole domain including a completely full window, asserted as a set of one over 201 fills and then again at the ceiling alone. A maximally open-ended node (score 1.0) at that same full window is hold and explicitly not either send, which is the other half of the same inversion. And hold is asserted to be decided by the score with the fill held constant at 0.85: varying only the score produces both outcomes, and every held score is above the prescribed ceiling.

No routing is checked against the type's own field names rather than a blocklist of lane spellings. §6 — The probe reader was called because the command became a probe carrier

Where the call is decided

The composer reaches the reader at one site, reckon/mcp_views.py in crew_lanes_view: for each configured backend it asks _declared_probe_command(settings) for a command, and only a non-None command is keyed into probe_by_command by calling _cached_probe_reading(…, reader=read_probe, …) — the call that enters the reader seam. So the question is exactly which backends _declared_probe_command hands back a command for.

It hands one back for a dialect that owns its account surface, and that is the decision. The function resolves _backends.dialect_for(settings) from the command's stem, then asks _owns_account_surface_reading(dialect) — true when the dialect class overrides read_account_surface, which the base returns None from. For such a dialect the probe exchange is never consulted; the function returns the command with the reason "account-surface probe declared".

Which reading the measurement supports

The fixture's referent moved: this is a test asserting yesterday's contract, not a production defect. The case was written with {"command": "claude"} standing for a probe-less dialect. Commit fab092da (2026-09-14) “claude dialect owns the account-surface budget read…” gave the claude dialect its own read_account_surface, and from that commit claude became a command the composer declares a reading for. The fixture kept asserting the absence of a probe against a command that now has one.

The rejected reading, and the evidence against it. The other candidate is that the composer should not reach for a reader here and the behaviour is a bug. It is refuted by the read path underneath the seam: the default reader is _run_budget_probe → _backends.probe_budget, which resolves the dialect and calls dialect.read_account_surface(backend=…) first, and only falls back to the probe exchange when that answers None. For claude and clive the account surface is the live reading — the whole purpose of the lanes view is that a live reading replaces an ancient receipt. Suppressing the call for a dialect that owns its surface would leave every claude and clive lane carrying a stale receipt as though it were a position, which is the failure §5b exists to prevent, and it would do so while every focused lane case stayed green.

The repair

The fixture's command became a deliberately synthetic token (synthetic-no-dialect-harness) that names no harness at all, which is what “not a known probe carrier” means in the composer's own vocabulary: the function returns (None, 'dialect declares no quota probe…'), no command is keyed, and the reader seam is never entered. The name is synthetic because a real one re-fuses the case. The composer resolves a dialect from the command, so every real harness name is a candidate to become a dialect and re-fuse the fixture the way claude did — a first attempt at this repair used a real local-model runner and was rejected on review for exactly that reason. A token no dialect can claim cannot acquire one. The case keeps its name and its three assertions (invocations == 0, probe_status == "not_declared", quota_source == "receipt"), and its docstring records both why claude can no longer serve as the stand-in and why the replacement is deliberately not a real name.
