§2 — The review resource

A singleton distributed resource at docs/state/<project>/review.html, written through edit_plan(create=True, doc_type="review") on the existing distributed-state path. The active-sprint-mismatch fixture round-trips with both evidence lines at version 1; resolving it advances only the review resource to 2 while a sibling sprint stays at 1, returns derived status="resolved", and stores no status field. Strict writes name the offending field: findings[0].category, findings[0].evidence, priority[0].rank, priority[1].ref and findings[0].subject.id. A dotted priority.0.rank set is refused, so only a complete ranking may be written.

Negative finding recorded during integration: a refusal reports its field in the detail key, not message. A coordinator briefly mistook the empty message for a contract violation and nearly filed a false defect.

§3 — Composition is a join, not a cache

Sprint cards gained metrics.item_count, metrics.by_effective_status, metrics.mean_impl and metrics.current_work; findings gained subject_found/subject_status/current; priority rows gained live status, effective_status, impl, sprint and landed.

Liveness was proved directly rather than asserted: a one-member sprint moved from mean_impl 0.5 and current_work 1 to 1.0 and 0 on re-read while the stored review version did not change.

This node first refused rather than claim a full-suite run it could not finish, and the refusal was correct. Its base predated an unrelated commit that turned two tests red on main; at its own commit those same two files passed 80/80, establishing a delta of zero new failures without waiting for anyone else's repair.

§4 — A review advises the graph and never gates it

build_roadmap carries the review block and appends two warn-level wiring findings, priority-order-inversion and review-stale. The property that matters was demonstrated, not assumed: on a constructed prerequisite-behind-successor ranking, ready_now retained only the prerequisite — the advisory signals left readiness untouched. A project with no review resource returns review=None rather than an error. Corpus audit gained three report-only codes.

§8 — One derivation, and a signal that knows a closed loop

Two duplicate pairs were collapsed into mcp_views.compose_review and mcp_views.load_composed_review, now serving discovery, typed reads and the roadmap. roadmap._review_projection and roadmap._load_review were deleted — verified as zero remaining definitions — rather than left beside their replacements. 200 insertions against 137 deletions.

The discriminator was accepted against a corpus this project did not author: a consuming project's 35 findings with 34 resolved yield exactly one stale subject, and it is rf-035, the single genuinely open row. The prior implementation would have reported 34 healthy closed loops as stale — the false-positive flood that makes a surface stop being read.

The consolidation paid for itself the same hour. A defect found immediately after — the derived sprint order returning S12, S13, S6, S8, S9 from a string sort where _natural_identifier_key already existed and was already used elsewhere — was then a one-line fix in one place instead of two divergent sites. Live order corrected to S6, S8, S9, S12, S13, with a fixture pairing a single-digit and a double-digit identifier because with single digits alone a string sort passes forever.

§7 — A closed vocabulary found short by use

safety was added as a seventh category, and all five review vocabularies are now pinned by exact-set assertions so a future addition or removal fails a test. The unknown-category refusal asserts both the field path and the complete sorted accepted set.

Two limitations recorded rather than worked around. A finding's category cannot be edited in place — set covers scalars, append adds rows, resolve closes one — so re-filing the isolation finding required resolve-plus-replacement, and the original row remains resolved as the audit trail with an outcome stating that the underlying defect is not repaired. And the worker declined to fold the file's pre-existing lint backlog into a feature commit, stating the counts unchanged either side.

§5 — Behaviour shipped, capture not produced

The sprint view renders derived order with a natural-id fallback, a focus-conflict badge where the derived active pointer disagrees with the sprints actually carrying active, per-sprint metric strips, finding badges linking to evidence anchors, and a priority panel with reason chips whose landed rows fall to a muted tail — all from the composed payload the shell already loads, with no extra fetch and no client-side plan parsing.

The rendered gate was never produced and nothing here claims it. Both capture attempts stalled with zero browser events while a foreign process fleet held the host at load 60 to 130 and a peer ran a full suite in the shared checkout. The run then died without rewriting its manifest, so the two commits were audited directly. Promoted as gate: not-run, deliberately. The capture obligation transfers with the files to sprint-horizon-surface, which now owns them and whose own gates run in a browser.
