Plan lifecycle hygiene — landed evidence

This cumulative record preserves the measured lifecycle failures, the enforcement rules derived from them, and the boundaries that remain subject to design review.

Closed-sprint findings become actionable errors

Measured miss: one session was told twice that two new plans were absent from their declared sprint, acted on neither finding, and left both plans attached to a closed sprint. The finding therefore produced 0 corrective actions from 2 warnings. Its shared warning severity and generic message hid the consequential case among ordinary hygiene findings.

Landed rule: absence from an open sprint remains plan-sprint-missing-item at warn severity because the state is untidy but recoverable. Declaring a sprint whose status is done, shipped, closed, or archived now produces plan-sprint-closed at error severity because the plan is invisible to the advancing scheduling horizon. Both the roadmap scan and MCP audit use the shared CLOSED_SPRINT_STATUSES vocabulary and name the status and scheduling consequence.

Actionability standard: the result follows the example set by sprint-order-inversion: a lifecycle finding must identify the affected plan, the specific failed relationship or state, and the consequence that requires action. The general severity boundary is now explicit: untidy is a warning; unschedulable is an error.

Verification and provenance: tests/test_mcp_audit.py pins the two-case split—closed sprint to an error naming its status and invisibility, open sprint to a warning. The implementation landed in commit ec3b9fb.

Scope boundary: this adds the enforcement half of the audit-cadence mechanism. Write-time lifecycle invariants, the plan-creation diet, and the sprint-close gate remain pending the lead’s strictness decision; this finding does not pre-empt those choices.
