§12 — A verifier reports an attribution, and cannot edit what it grades

Landed 2026-09-04, commit 1a103b6. Gate uv run --no-sync pytest tests/test_crew_test_role.py -q — 12 passed against a base of 10, zero added failures.

Three of this section's four measures were already in place: the test role's own sandbox, budget and scope defaults, its prompt stating the division of labour, and the refusal of a verifier whose commit touches source. The missing one was the deliverable itself, and it is now there: a test node's prompt requires baseline_suite, after_suite and a complete failure_attribution while declaring the repository read-only, and its manifest separates new failure ids from pre-existing ones against a stated base, naming for each new one the merged commit that introduced it.

Two properties are worth naming because they close the ways the check would otherwise be talked past. An armed test-role promotion refuses an added failure carrying no candidate commit even when suite-delta waiver text is supplied — a waiver being exactly the instrument that would otherwise wave the attribution through. And every repository-changing commit a test-role run cites is refused before the ledger append, regardless of a widened declared source scope, so a verifier cannot edit what it grades even when scope has been granted to it.

The integration case is end-to-end rather than unit: it promotes report-only evidence, deletes its manifest, reloads the committed ledger through ledger.runs, and recovers the pre-existing failure set, the one added failure, and its exact broken candidate commit among several clean merges.
