§2 — The attach line names an executable that resolves

Commit f8f36b76 at 2026-09-23 — fix(crew): the follower attach line names the running reckon executable. _watch_attach_line in reckon/crew/runs.py composes its first token from a single resolver, _reckon_console_script(), which prefers Path(sys.executable).parent / "reckon" and falls back to shutil.which, raising CrewError rather than composing a line whose executable does not exist. Every surface that prints the line inherits the change because they all call the composer.

  • The declared negative control is executed and logged. Restoring the bare word reckon as the first token makes the gate report 2 failed, and the bare token under the arming shell's PATH exits 127. The log's first line repeats the declared mutation verbatim.
  • Existing tests, delta against the base revision: added failures 0. The two granted fixture files carry the same five failures before and after the change (spec-level dispatch refusals and mount lookups unrelated to this line), 16 passed in both runs.
  • The resolver bug it exposed. The watcher unit's own resolver called Path(sys.executable).resolve().parent; because a virtualenv's interpreter is a symlink into the base distribution, that prefix left the virtualenv and the console script with it. The two now share the corrected helper, which takes the directory without resolving.

§3 — The follower announces its own end

A follower armed with --lifetime ends itself when that deadline passes: one final line, exit status 0, registration released. The line is tagged follower-end so a reader can tell it from a fleet transition, and it names the attach line to re-arm with and the owning session's runs that still need the coordinator.

Almost all of the wall clock is interpreter start and import: the follower's deadline is reached within one poll pass of the grant it was given, which is the part the change controls.

The bound the gate anchors to

The done-when asks the test to observe exit status 0 within five seconds. Measured from the process spawn that bound is unreachable at a three-second grant: the wall clock is 5.53 to 6.42 s before the follower has even started counting, so the gate would fail on a quiet machine for a reason that has nothing to do with the change. The test therefore anchors its five-second bound to the arm, which it establishes by reading follower_state until the registration is held, and allows thirty seconds to reach that arm. Every substance requirement of the done-when is preserved: exit status 0, the last line marked as the follower's end, the attach line _watch_attach_line returns for that project and session, that run's node, the released registration, and the untouched real config home. This mismatch is disclosed rather than papered over, and the figure above is the measurement that forced it.

With _check_lifetime mutated to never mark the arming ended, the lifetime test fails on exactly that mechanism — the follower is still running 5.0 s after its own arm — while the no-lifetime test still passes, so the control separates the two behaviours rather than the run as a whole. §10 — A watcher a test starts does not outlive the test

Outcome — the session teardown finds its producers by record, not by pattern. Commit 7c5f69b9 fix(tests): reap a session's watch producers by pid, not by a pattern rewrites the session fixture in tests/conftest.py. It previously located live producers by scanning /proc for command lines carrying the words watch and --project — a pattern that matches any process carrying those words, including a peer's watcher and the shell that ran the scan. It now enumerates the seat records each producer writes into its own configuration home (<RECKON_HOME>/crew/watch/<project>-<digest>.lock) and reads the registered pid from each. A record is acted on only while the process it names still reports that same home in its own environment; a reused pid, a record that has drifted from its process, or an unreadable environment is refused rather than signalled.

Measured

  • The node's gate, tests/test_test_watchers_are_reaped.py at revision 7c5f69b9, run together with the covering dispatch test: 3 passed, 1 skipped. The skipped case is the child-side arming test, which runs only inside the subprocess session. Positive control: the parent asserts a seat record for proj exists under the child's --basetemp before it asserts the absence, so a child that never armed cannot read as a pass.
  • The declared negative control — remove the teardown termination from the conftest fixture — is executed and logged. With the two-line signal loop removed, the child session leaves two processes naming its home (pid 396241 the detached supervisor, pid 396308 the watcher) and the gate reports 1 failed (negative-control.log in the run directory). Both were reaped by explicit pid after the red run, verified against their environment first.
  • The refusal that bounds the teardown is asserted, not assumed: test_a_record_naming_another_home_is_refused writes two records under one root — one whose process names that root's own home, one whose process names a home elsewhere — and requires reapable_watch_pids to return the first pid and not the second. A process whose environment cannot be read is refused on the same footing.

Bound of this measure

The child runs the arming half of tests/test_crew.py::test_cli_dispatch_arms_a_missing_watcher — the same fixtures, patches and command, stopping before that test's own unwatch. Running it whole would unwind the very producer under measure, and the gate would then pass whether the session fixture worked or not; the child therefore ends while the producer is still live, which is exactly the state a session fixture has to answer for.

Scope

The promotion and the merge are the coordinator's. Nothing outside tests/conftest.py and the new test module changed.
