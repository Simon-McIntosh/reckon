§3 — The follower announces its own end

A follower armed with --lifetime ends itself when that deadline passes: one final line, exit status 0, registration released. The line is tagged follower-end so a reader can tell it from a fleet transition, and it names the attach line to re-arm with and the owning session's runs that still need the coordinator.

Almost all of the wall clock is interpreter start and import: the follower's deadline is reached within one poll pass of the grant it was given, which is the part the change controls.

The bound the gate anchors to

The done-when asks the test to observe exit status 0 within five seconds. Measured from the process spawn that bound is unreachable at a three-second grant: the wall clock is 5.53 to 6.42 s before the follower has even started counting, so the gate would fail on a quiet machine for a reason that has nothing to do with the change. The test therefore anchors its five-second bound to the arm, which it establishes by reading follower_state until the registration is held, and allows thirty seconds to reach that arm. Every substance requirement of the done-when is preserved: exit status 0, the last line marked as the follower's end, the attach line _watch_attach_line returns for that project and session, that run's node, the released registration, and the untouched real config home. This mismatch is disclosed rather than papered over, and the figure above is the measurement that forced it.

Negative control

Declared as: make the lifetime deadline check in the follower's wait pass never fire. With _check_lifetime mutated to never mark the arming ended, the lifetime test fails on exactly that mechanism — the follower is still running 5.0 s after its own arm — while the no-lifetime test still passes, so the control separates the two behaviours rather than the run as a whole. The mutation was reverted and git diff was empty afterwards. The red log is cited under the node's manifest.
