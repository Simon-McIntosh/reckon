§3 — The follower announces its own end

A follower armed with --lifetime ends itself when that deadline passes: one final line, exit status 0, registration released. The line is tagged follower-end so a reader can tell it from a fleet transition, and it names the attach line to re-arm with and the owning session's runs that still need the coordinator.

The bound the gate anchors to

The done-when asks the test to observe exit status 0 within five seconds. Measured from the process spawn that bound is unreachable at a three-second grant: the wall clock is 5.53 to 6.42 s before the follower has even started counting, so the gate would fail on a quiet machine for a reason that has nothing to do with the change. The test therefore anchors its five-second bound to the arm, which it establishes by reading follower_state until the registration is held, and allows thirty seconds to reach that arm. Every substance requirement of the done-when is preserved: exit status 0, the last line marked as the follower's end, the attach line _watch_attach_line returns for that project and session, that run's node, the released registration, and the untouched real config home. This mismatch is disclosed rather than papered over, and the figure above is the measurement that forced it.

§7 — A follower whose consumer is gone releases its registration

Commit 5194657a at 2026-09-23 — feat(crew): release a follower whose consumer has gone. The follower checks its recorded consumer on each wait pass in _follow_watch_lines (reckon/cli.py). The consumer is the parent recorded at registration, so a re-parent to init or to a subreaper reads as os.getppid() no longer naming that pid, and the recorded start time is the pid-reuse guard. When the consumer is gone the arming ends: the registration is released by leaving, and nothing is printed, because nobody is left to read a numeric line.

What was measured

  • The gate, at 5194657a: 1 passed in 3.37 s. tests/test_orphaned_follower_releases.py points RECKON_HOME at a temporary directory, starts an intermediate parent that in turn starts the follower through sys.executable -c "from reckon.cli import main; main()" crew follow … (never the bare word reckon), waits for the registration to be held, then SIGKILLs the parent. Within ten seconds of the kill it observes all three: the follower process has left; its stdout, captured to a file, carries nothing; and after a non-blocking acquire proves the registration free, a second follower becomes the holder named by follower_state.
  • Why -m reckon is not used. The package carries no __main__, so python -m reckon cannot run; the done-when allows the absolute path of the running console script or -m reckon, and this node uses the interpreter with the explicit module entry instead, which resolves the worktree's own reckon and never the bare word.
  • Added failures in the adjacent follower/watcher set: 0. The set of nine follower- and watcher-facing files reports 5 failed, 64 passed. All five are outside this node's diff.
