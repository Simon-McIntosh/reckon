Count the population the reader asked for — landed evidence

The §2 done-when passes: a session-scoped follower’s trailing figures count only that session’s live pointers, asserted over one fixture holding runs from two sessions whose populations differ and including a foreign run that is blocked. The part of this record worth reading is the pair of digits that fail separately: the scoped render reads 1w· 0b· 0u while the fleet render of the same event reads 2w· 1b· 0u, and a substitution of the fleet population for the scoped one fails the assertion. An unscoped follower over the same fixture is unchanged, because the unscoped path is what every peer coordinator reads.

The change, and why it is render-time

The watcher seat is project-global and the stream it writes carries the whole fleet’s totals on the wire, so a follower cannot ask the producer for per-session figures. When a session is given, the figures are therefore re-derived at render time from the same live pointers the few seconds the line takes to draw, narrowed to the ownership already persisted on each pointer.

_fleet_counts in reckon/crew/recovery.py gains a session argument and narrows its rows through the ownership splitter that already exists for the dispatch fence; format_watch_transition gains a session argument and re-scopes the event’s figures before the ticker paints them. A pointer with no recorded owner stays in the counted set, because absence cannot prove that a live pointer belongs to a peer.

The pair of digits, in the same fixture

The fixture holds a working run owned by the reader’s session (r-mine, session mine), a foreign working run and a foreign run written blocked (r-peer-work and r-peer-blocked, both session old-a). Over that fixture the totals are:

session="mine" → working 1, blocked 0, unpromoted 0.

session="old-a" → working 1, blocked 1, unpromoted 0.

no session → working 2, blocked 1, unpromoted 0.

The scoped totals are both stated as digits and the scoped reading differs from the fleet reading, which is the defect this record exists to pin: the foreign blocked run joins the fleet total but never the reader’s.

The guard that fails if the population falls back to the fleet

The assertion that carries the measure is on the rendered line, not on a summary dict. A transition event is built exactly as the follower would deliver it — a blocking foreign run’s snapshot, previous state working, current state blocked — and rendered both ways. With the session present the line reads 1w· 0b· 0u; without it the same event reads 2w· 1b· 0u. The two renders are asserted unequal, and the scoped render is asserted to carry the scoped digits. A regression that handed the whole fleet to the session-scoped reader changes those digits and fails the render assertion.

An unscoped follower’s figures are asserted unchanged over the same fixture rather than assumed: three tests cover _fleet_counts with no session over the shared fixture and the sector’s existing watch-render files, test_follow_observes_other_sessions.py and test_fleet_counter_coverage.py, stay green (15 passed), because a regression on the unscoped path is worse than the defect being fixed.

Demonstrating that the guard fires

The done-when requires the assertion to fail if the counts are taken over the fleet. That half was demonstrated by rendering with the scoped re-derivation replaced by a pass-through of the event’s own (fleet) figures: the scoped assertion then fails, because the line shows 2w· 1b· 0u where the session’s population is 1w· 0b· 0u. A guard that only asserts equality against a constant could pass on a population that never changed; this one is tied to the digits of the fixture, so a wrong population changes the numbers.

Scope and follow-ons

The renderer and the grid are untouched: ticker.py and its test files are held by another node that needs no change for this, and the grid’s count cells are painted from the event’s own fields, which is exactly the seam the re-derivation feeds. One line outside this node’s write fence completes the production effect: crew_follow in reckon/cli.py passes session=session to format_watch_transition. The kernel, the render seam and the tests are landed here; the wiring is recorded as a follow-on rather than taken, because editing cli.py would step on a concurrently running session’s scope. The pre-existing promotion suite failure is likewise recorded, not repaired, as it sits outside this section’s declared scope.

The wiring, and the measure that names the surface

The kernel above was landed while its one consumer stayed unwired. crew_follow in reckon/cli.py called format_watch_transition with with_session and ticker and stopped, so the new session parameter fell to its default and every scoped follower on this workstation kept reading the fleet’s figures. The fix is the one keyword argument the earlier record named as its follow-on: session=session.

The prior record’s tests all passed while the surface stayed wrong, because they assert on _fleet_counts and format_watch_transition and nothing asked whether the command passes a session to them. So this node’s measure drives the command, not the helper: it feeds crew follow one project-wide transition over a fixture holding two sessions whose populations differ and reads the line the command prints.

The pair of digits at the command, and the guard that fires

The fixture holds one working run of the reader’s session (mine), one working and one blocked run of a second session (peers). Over it reckon crew follow --project proj --session mine reads 1w· 0b· 0u, the same command with no session reads 2w· 1b· 0u, and the two are asserted unequal so a renderer that ignored --session could not pass by agreement. The blocked run is the foreign session’s precisely because the observed defect was a blocked figure the reader could do nothing about.

The declared mutation — remove session=session from the format_watch_transition call in crew follow — makes the scoped assertion fail (2w· 1b· 0u where 1w· 0b· 0u is required) and collapses the scoped and unscoped readings together; the red log is on disk. With the fix in place tests/test_follow_counts_its_session.py is 4 passed, and the real live pointer directory under the user config home is asserted untouched afterwards.

Three failures in adjacent files (test_crew_ticker_layout.py, test_crew_session_delivery.py, test_removed_flag_migration.py) were reproduced identically with the fix removed, so the delta against base is zero added failures; they concern unrelated surfaces and are recorded under follow-ons.
