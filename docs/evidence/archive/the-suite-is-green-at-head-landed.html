§2's diagnosis, confirmed and extended

The research record's §2 already names the mount guard row (0f9c0e6f) as a stale expectation, and this node confirms it for the seven ids it covers.

It also lists the figure-topic scope conflicts as "the likeliest real defect in the set". They are not a defect. The seven claim-refusal ids fail only because the fixture's stub launcher named a pid that had already exited. A write claim binds only while the run that holds it is disposed as running, so a dead pid means no claim, and the guard correctly declines to refuse a conflict that does not exist. The measurement that settles it: the failing and the passing runs are at the same product revision, so the refusal firing once a live pid is stubbed is behaviour the product already had. This is a stale fixture, not a shipped defect, and the plan's "likeliest real defect" is closed without a product change.

Two further classes §2 did not name for this cluster are recorded above: the host-dependent node-local case (test isolation) and the spawn failure (a product defect, carried).
