Correction — two repairs were measuring the runner

A coordinator verification at 601d0239 reported three failures in tests/test_crew.py where this node's own run had reported one. Two were this node's fault: both repairs below encoded the machine rather than the behaviour.

  • The in-harness directive's scope. test_an_in_harness_dispatch_returns_a_directive_to_bind asserted the plan's shared landing paths join the declared scope. They do, but only when the worker can write the worktree it is handed, and that judgement is resolved from the sandbox write roots, which include the process temp directory. A throwaway repository under /tmp therefore reads as writable and one outside it does not, so the assertion's outcome followed where pytest's tmp root lived — and this node's own base and head runs named a --basetemp under it. Measured directly: with the --basetemp under /tmp the directive carried four scope entries; with the same --basetemp under ~/.cache it carried one and the test failed, exactly as the coordinator's run found. The judgement is now pinned and both branches are asserted, so the test measures the directive contract rather than the filesystem layout.
  • The redispatch delivery clock. test_redispatch_does_not_inherit_a_terminal_delivery holds that the previous attempt's terminal delivery is not credited to the next attempt. Manifest freshness compares the file's mtime against a second-resolution attempt start, so a delivery whose mtime lands inside the following attempt's own second is judged to have been written after that attempt began. Demonstrated against the classifier with a delivery stamped one nanosecond into the following attempt's second: freshness returns True, where a delivery in an earlier second returns False. Each delivery in the test is now back-dated to the attempt that wrote it, which keeps the two attempts ordered however quickly the run proceeds.
