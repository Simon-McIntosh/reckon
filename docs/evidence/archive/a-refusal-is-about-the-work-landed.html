A Refusal Is About The Work

§2 — the goal lint now refuses an unresolved placeholder or a goal that genuinely is two deliverables, and no longer refuses the punctuation that joins one deliverable. A goal joins two deliverables only when a separator opens a clause that carries its own action verb.

§2 — The contract lint refuses placeholders and two deliverables, not punctuation

Commit 601e51e5 fix(crew): refuse placeholders and two-deliverable goals, not punctuation narrows validate_node in reckon/crew/node.py. A separator — a semicolon, "then", "and", "&" or "plus" — now opens a second deliverable only when the clause that follows it begins with its own action verb, so a semicolon or "then" between the parts of one deliverable, and one verb over several objects, stay one node. An angle-bracket placeholder is refused outside a quoted string and outside a code span; the vague placeholder words (TBD, TODO, FIXME, "figure out", "somehow", "as appropriate") are refused in the goal only, so a done-when naming a marker to count is a measure rather than a gap. validate_node gained an optional execution_capable input, defaulting to None so dispatch behaviour is unchanged, which reuses capability.assess_execution_fit — the same role-versus-measure comparison dispatch already applies — so a node is judged whole before any run is created.

§3 — A session whose follower was released keeps dispatching, warned to re-arm

Commit ee6fb313 feat(crew): let a released follower keep dispatching with a re-arm warning narrows the watcher-required refusal. A follower registration is an advisory lock on a per-session file, and the release drops the lock while deliberately leaving the file as a record, so a session that armed a follower and then lost it is distinguishable from one that never armed one at all. _follower_liveness in reckon/crew/runs.py now reports that same distinction as released — the key is true only where the file remains and its lock is free, false where no file was ever written — and watch_state surfaces it as session_follower_released.

reckon/crew/dispatch.py gains _watcher_delivery_admission, one judgement invoked by both the launching path (dispatch) and the validating path (plan_dispatch). An attached session needs nothing; a session whose registration was released proceeds while the watcher process is live and is handed _released_follower_warning, whose text carries the exact attach command from attach_line; a session that never registered a follower is still refused with WatcherRequired. The validating path evaluates the same two verdicts without starting a producer.

§5 — A hyphenated noun is not a second action

Commit 956f91dd fix(crew): read a hyphenated compound as one token in the goal lint narrows _deliverable_conjunction in reckon/crew/node.py. The clause after a separator was matched as its leading letters alone (([a-z]+)), so a hyphenated compound whose first word is an action verb was read as that verb. The leading token is now matched whole ([a-z][a-z0-9-]*) and tested against _DELIVERABLE_ACTIONS as a unit, so verify-gate is the noun the author wrote while a clause that genuinely begins with a bare verify still splits.
