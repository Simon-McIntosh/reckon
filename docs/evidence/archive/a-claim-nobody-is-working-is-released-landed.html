A Claim Nobody Is Working Is Released — landed record

Section §6. Two censuses of every live pointer on the workstation, one taken before the §2–§5 release passes drained the fleet and one taken at least six hours after the last of them landed. Each row names the run, its kind, the host the pointer records as its launcher, whether a turn is in progress, and the age of the claim.

Method

A pointer is a *.json file in ~/.config/reckon/crew/live/. The census reads every one the directory holds and refuses to report if any fails to parse: a census that read fewer pointers than the directory holds would be unread, so the count is read back in the record. The row's kind comes from the same modules the release passes use — promotion._measurement_reason for a measurement-only run, the pointer's landing_group for a group member, pending_landing._is_a_promoted_pointer for a promoted run, and resumption.resume_without_a_started_turn for a resume whose worker began no turn. The turn reading is process_liveness.turn_in_progress; the host reading is process_liveness.launched_on_another_fleet_node. The instrument mutates nothing.

Pointer age is the age of the claim: now minus the pointer's launched_at, falling back to created_at and then claim_registered_at. A run is a claim without a worker when its kind is promoted, measurement-only or landed-group member, its claim is older than one hour, and its stream shows no turn in progress. The second reading the section asks for is a run whose phase is working and which has begun no turn at all: its phase reads as work while its own attempt stream holds no assistant record since the attempt began.

The fleet's own release machinery is read in the same pass, because a pass that has landed but is not loaded drains nothing. Each service's reported running_code tree is listed with the census it was read at.
