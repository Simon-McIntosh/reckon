§5 — The suite carries its own bounds

What was declared. pyproject.toml adds pytest-timeout and pytest-xdist to the dev dependency group and a [tool.pytest.ini_options] section whose sole key is timeout = 300. The three named tests below were observed in that order (pip-free, through the declared plugin set), then the declaration was removed to falsify its effect. uv.lock was regenerated with uv lock (117 packages resolved; execnet 2.1.2, pytest-timeout 2.4.0, pytest-xdist 3.8.0 added).

Three observations, one mechanism

Why the middle row is the load-bearing one. The first row shows the plugin can be told to fire, which a -o flag would do whether or not the file declares anything. The middle row is the only observation that reads the declaration itself: its header prints configfile: pyproject.toml and timeout: 300.0s, so the 300 is the file's and not the command's. The third row removes that line and the header's timeout: entry disappears with it, so the middle row's value is shown to be produced by the declaration rather than by the plugin's mere presence.

What the throwaway test is for. It lives outside tests/ under /tmp and does one thing — time.sleep(10) — so the red is unambiguously the bound rather than a real defect. The third row's green is the control: it shows the same file passes when unbounded, so the red was the bound speaking.

§3 — A nested launch is refused where it would fan out

What landed. reckon/nested_launch.py holds the decision, and reckon/host_shims/srun, reckon/host_shims/sbatch and reckon/host_shims/salloc are thin executables that call it. main() reads reckon.host.host_facts().in_allocation. Inside the allocation it refuses with exit status 97 unless the caller sets RECKON_ALLOW_NESTED_LAUNCH or the argv is an srun carrying --overlap together with an explicit --jobid or a single task. Every other path os.execvs the real binary with the argv unchanged, found on PATH with the shim's own directory removed by resolved path, so the shim never execs itself. The refusal names the job, the node and the override, says the command should run directly, and states outright that the command line is not rewritten.

The shims derive the tool name from their own basename, so the three files are byte-identical. Each shim resolves a Python 3.12+ interpreter itself — the repo's .venv first, then an explicit 3.12, then python3 — because the host's bare python3 is 3.11.5 and cannot parse the package (type X = … in reckon/crew/quota_weight.py).

Evidence — the gate. The node's gate is tests/test_nested_launch.py, run in the worktree against the shared root environment:

command: PYTHONPATH=<worktree> <main-checkout>/.venv/bin/python -m pytest -p no:cacheprovider -q tests/test_nested_launch.py
..........                                                               [100%]

Every case drives the real shim executables, with the fixture host facts injected through a temporary sitecustomize the test writes into tmp_path and puts first on the fixture PYTHONPATH. That seam replaces reckon.nested_launch.host_facts with a fixture HostFacts, so no test reads the real /proc — which matters here, because this suite runs inside the allocation (the real in_allocation is true), so a case asserting outside the allocation against the real answer would fail. A fake real binary records its resolved path and its argv one per line into a record file, which is how the exec paths are told from the refusal path and how a case proves the shim directory was dropped from the lookup rather than re-exec'd.

Evidence — the negative control. The declared mutation is remove the in-allocation check so plain srun always execs. It is applied by docs/figures/a-worker-knows-it-is-on-compute/nested_launch_mutation_check.py, which loads the mutant beside the run; nothing here edits the reviewed module or test.
