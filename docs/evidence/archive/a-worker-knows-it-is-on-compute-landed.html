§3 — A nested launch is refused where it would fan out

What landed. reckon/nested_launch.py holds the decision, and reckon/host_shims/srun, reckon/host_shims/sbatch and reckon/host_shims/salloc are thin executables that call it. main() reads reckon.host.host_facts().in_allocation. Inside the allocation it refuses with exit status 97 unless the caller sets RECKON_ALLOW_NESTED_LAUNCH or the argv is an srun carrying --overlap together with an explicit --jobid or a single task. Every other path os.execvs the real binary with the argv unchanged, found on PATH with the shim's own directory removed by resolved path, so the shim never execs itself. The refusal names the job, the node and the override, says the command should run directly, and states outright that the command line is not rewritten.

The shims derive the tool name from their own basename, so the three files are byte-identical. Each shim resolves a Python 3.12+ interpreter itself — the repo's .venv first, then an explicit 3.12, then python3 — because the host's bare python3 is 3.11.5 and cannot parse the package (type X = … in reckon/crew/quota_weight.py).

Every case drives the real shim executables, with the fixture host facts injected through a temporary sitecustomize the test writes into tmp_path and puts first on the fixture PYTHONPATH. That seam replaces reckon.nested_launch.host_facts with a fixture HostFacts, so no test reads the real /proc — which matters here, because this suite runs inside the allocation (the real in_allocation is true), so a case asserting outside the allocation against the real answer would fail. A fake real binary records its resolved path and its argv one per line into a record file, which is how the exec paths are told from the refusal path and how a case proves the shim directory was dropped from the lookup rather than re-exec'd.

One case places the shim directory first and the fake second, with the fixture facts reporting the process outside the allocation. That is the order the lookup's own filter exists for: every other case puts the fake ahead of the shim directory, where a lookup that never filters is indistinguishable from one that does. The observable is the record the fake writes, so the case fails on the fake never being reached rather than on whatever a self-exec then produced. The two refusal cases assert exit status 97 as the literal the contract names, not the module's own REFUSAL_STATUS constant, so they pin the status instead of restating the implementation.
