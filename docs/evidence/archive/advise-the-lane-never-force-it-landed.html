Advise The Lane, Never Force It

A dispatch onto a lane that will exhaust inside the node's own horizon carries the trajectory it never asked for, names the lane measured rework says serves the role more cheaply, and changes nothing about where the work goes.

§2 — The advisory arrives where the choice is made

Commit abfee217 adds a lane_advisory carry to the dispatch payload. The carry rides the lane reading the dispatch already takes — it opens no second probe — and reports the utilisation, the burn multiple, the projected exhaustion and the reset, with the node's own horizon placed beside them.

It is emitted without a caller asking, and without a second probe

The observing read is counted. A dispatch that emits the advisory reads the lane trajectory exactly once — the same call the dispatch made before the advisory existed — so no caller asks for the advisory and no extra request is spent on it.

Nothing about it moves the work

Three dispatches onto one lane are taken: one whose projection lands inside the horizon, one whose projection lands beyond it, and one whose lane publishes no projection at all. The payloads differ only in the carry. The resolved backend and the agent's backend are the same string in all three, so the advisory is data and never a routing decision.

The shortfall clause carries its threshold: a lane with one usable run reports 1 usable run(s) against 10 needed rather than naming a lane from a single sample. An absent or unreadable ledger states the same shortfall and refuses nothing.
