One derivation, every surface — landed evidence

Moving four derivations to Python is worth little on its own, because nothing would stop the next surface node from inventing a fifth. This plan's last section builds the bound check: for one fixture project, render each surface, call each read, and require the rendered value to equal the returned value. The check compares the two surfaces, never a literal on either side — the only form that fails when one copy drifts.

Record scope

The deliverable is two test files. tests/spa_parity_harness.py builds one fixture project — a single inventory that carries both the dependency graph behind the endpoint closures and the schedule chain behind the lane packing — and renders both sides of every comparison. The rendered side is a node evaluation of the authored JSX helpers (the sprint rows, the two graph endpoint adapters, the crew-flow lane pack, the fleet-home summary), with no React runtime and no re-implementation. The returned side is the Python read the rest of the codebase uses. tests/test_surface_parity.py asserts the equality and carries the companion case.

The pair count itself is asserted against the fixture's endpoint count, so it cannot silently shrink.

The red is part of the check, not a one-off demonstration

A parity test that has never failed cannot tell agreement from comparing a value with itself. The companion case patches exactly one value on one side — a sprint's rendered state, a drift's stored half, an endpoint's closure total, a rollup count, a schedule's lane count — rebuilds the pairs, and requires the comparison to report a mismatch. Six parameterised mutations cover a both-sides sample of the four dimensions, and each failure message names the mutate that should have been caught. The red is asserted on every run, so the check cannot silently become a mirror while the source fixtures stay green.

Why the check is stable on any host

The schedule is anchored to one reference instant carried by the fixture: every recorded plan carries an edited ISO stamp and the live run a dispatched_at, all derived from the same constant, so bars, lane count and chain far end are the same numbers on any host and any day. Rollup uses a synthesized one-project repository committed inside the activity window, so the series is populated without touching anything outside the test. Both surfaces run through node evaluation of the authored JSX — no browser, no network, no runtime clock.
