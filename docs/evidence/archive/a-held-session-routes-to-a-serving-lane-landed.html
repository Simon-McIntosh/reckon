§4 — a queued request moves to another lane with its waivers

The worker found that recorded dispatch options exist only on a queued request: _queued_request_record in reckon/crew/dispatch.py is their only writer. So the 2026-10-13 waiver loss, which was on a queued run, is repaired by moving a queued request rather than by changing how a launched run is redispatched. A run that launched directly has no recorded options to carry.

The change adds move_queued_run in reckon/crew/queue_admission.py. It rebuilds the launch through _launch_queued with a new backend_override, so the pointer's recorded dispatch_options still supply the plan-review waiver, accept_directory_claim and the comment, and a waiver the original dispatch never carried is never added. The launched run records carried_options, a lane_move record (source, destination and reason) and admitted_from. The queued pointer is replaced, not discarded, and a move that cannot launch puts the request back where it was. change_lane in reckon/crew/dispatch_sessions.py routes a queued record to this path instead of refusing it with "needs a fresh session but its original prompt is unavailable". crew_redispatch resolves the flight from the request's recorded overrides.
