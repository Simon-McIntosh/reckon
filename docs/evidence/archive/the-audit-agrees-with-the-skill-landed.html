§1 — A landed section's header is not a spliced document

The defect. The collapse-on-landing template puts a <header> as the direct child of a <section class="section-landed">, so a document that has collapsed three sections legitimately carries four headers. reckon audit-doc counted every <header> and warned header-duplicate ("document carries 2 <header> elements … content from another document spliced into this one") on any plan with two landed sections, while the authoring skill prescribed exactly that shape. It was seen on imas-ambix agent-sessions-live-on-the-fleet-node.html and description-reader-migration.html.

What landed. reckon/doccheck.py's _StructureScanner now keeps a stack of open elements alongside its section stack. On a <header> start tag it counts the header only when the innermost open element is not a <section> carrying the section-landed class, so the collapse-on-landing summary header is not counted while every other header is. The check is positional, not a blanket skip: a header nested one element deeper (for example inside a <div> within a landed section) still counts, and a header under an unlanded section still counts. The duplicate warning's own message keeps naming the counted total, so a document with three landed sections and one shell header reports nothing while a document carrying a real second shell header reports two.

Verification. tests/test_doccheck_landed_header.py covers four cases: three landed sections in the §6b template produce no header-duplicate finding; a second top-level header beside three landed sections still produces it, with the message naming two counted headers; a header whose parent is a <div> inside a landed section still counts; and a header under an unlanded section still counts. tests/test_doccheck.py passes unchanged (25 passed). The doccheck-focused set (test_doccheck.py, test_doccheck_structure.py, test_doccheck_landed_header.py, test_doccheck_code_spans.py, test_doccheck_unwired_plan.py) is 69 passed. ruff check --output-format=concise reckon/doccheck.py reports 12 findings, equal to the base revision's 12, so the change adds none.

Negative control. The declared mutation removes the exemption by having handle_starttag count every <header> again. With it applied, the three-landed-sections case fails with exactly one header-duplicate finding reading "document carries 4 <header> elements" — 1 failed. The log is at the run's negative-control.log. The exemption was restored afterwards and the full focused set re-run green.

§2 — A slug two resource types share is refused at audit

The defect. A research note at docs/research/fleet-view-rendering.html carried the plan-slug of a live plan, agent-sessions-live-on-the-fleet-node. resolve_resource then resolved that slug to two resources and raised "resource slug … is ambiguous across types: plan, research", so every slug-only edit_plan on the plan failed. The worker's gate was reckon audit-doc, and a per-file audit of either document passed — the collision lived in the project, which no single-file check looked at.

What landed. reckon/doccheck.py gains slug_collision_findings(path, docs_dir=, project=). It reads the audited document's plan-slug and declared reckon-type, then consults reckon.resources.resource_map for the project and reports an error-severity slug-collision finding when another resource carries the same slug under a different type. The resource map already indexes the project by type and slug, so the check reuses that one index rather than adding a second tree scan. The finding names both documents, and either side reports it when audited, so no direction depends on which document the caller names. Project-scoped run() resolves the docs root from the registered mounts and merges the finding into the per-path results, so a reckon audit-doc --project <p> <doc> that hits a collision now exits non-zero. A run with no --project is unchanged, because there is no docs root to read a map from.

Verification. tests/test_doccheck_slug_collision.py builds a synthetic project under tmp_path (never a real mount) with a plan and a research document sharing a slug. It asserts the error for each side, that the message names both paths, that the command surface (doccheck.main with a synthetic mounts file, so argument parsing, the mounts lookup and the exit code are all exercised) exits non-zero on the collision, and that a project whose slugs are unique produces no slug-collision finding and exits zero. The doccheck-focused set (test_doccheck.py, test_doccheck_landed_header.py, test_doccheck_slug_collision.py) is 33 passed. ruff check --output-format=concise reckon/doccheck.py reports 12 findings, equal to the base revision's 12, and the new test file reports none, so the change adds no findings.

Negative control. The declared mutation removes the cross-type comparison in slug_collision_findings, so only a same-type slug share is compared and a cross-type collision is never detected. With it applied, the three collision assertions fail (test_shared_slug_reported_for_each_document, test_shared_slug_run_exits_nonzero, test_shared_slug_cli_exits_nonzero) while the unique-slug case still passes — 3 failed, 1 passed. The log is at the run's negative-control.log, its first line the declared mutation verbatim. The comparison was restored afterwards and the focused set re-run green.
