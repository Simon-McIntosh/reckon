§1 — A landed section's header is not a spliced document

The defect. The collapse-on-landing template puts a <header> as the direct child of a <section class="section-landed">, so a document that has collapsed three sections legitimately carries four headers. reckon audit-doc counted every <header> and warned header-duplicate ("document carries 2 <header> elements … content from another document spliced into this one") on any plan with two landed sections, while the authoring skill prescribed exactly that shape. It was seen on imas-ambix agent-sessions-live-on-the-fleet-node.html and description-reader-migration.html.

What landed. reckon/doccheck.py's _StructureScanner now keeps a stack of open elements alongside its section stack. On a <header> start tag it counts the header only when the innermost open element is not a <section> carrying the section-landed class, so the collapse-on-landing summary header is not counted while every other header is. The check is positional, not a blanket skip: a header nested one element deeper (for example inside a <div> within a landed section) still counts, and a header under an unlanded section still counts. The duplicate warning's own message keeps naming the counted total, so a document with three landed sections and one shell header reports nothing while a document carrying a real second shell header reports two.

Verification. tests/test_doccheck_landed_header.py covers four cases: three landed sections in the §6b template produce no header-duplicate finding; a second top-level header beside three landed sections still produces it, with the message naming two counted headers; a header whose parent is a <div> inside a landed section still counts; and a header under an unlanded section still counts. tests/test_doccheck.py passes unchanged (25 passed). The doccheck-focused set (test_doccheck.py, test_doccheck_structure.py, test_doccheck_landed_header.py, test_doccheck_code_spans.py, test_doccheck_unwired_plan.py) is 69 passed. ruff check --output-format=concise reckon/doccheck.py reports 12 findings, equal to the base revision's 12, so the change adds none.

Negative control. The declared mutation removes the exemption by having handle_starttag count every <header> again. With it applied, the three-landed-sections case fails with exactly one header-duplicate finding reading "document carries 4 <header> elements" — 1 failed. The log is at the run's negative-control.log. The exemption was restored afterwards and the full focused set re-run green.
