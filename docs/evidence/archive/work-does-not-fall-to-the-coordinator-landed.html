A write claim can be narrowed or released without a promotion

A run's declared write paths are created at dispatch and were, until this change, destroyed only at promotion. --write-path appears in the help of one of the 31 crew subcommands, dispatch, and the scan finds it there as its own positive control; no crew claim subcommand exists. A coordinator whose worker blocked at its fence therefore had two moves, both wrong: hand-edit the live pointer under the shared crew config home, or redispatch and discard every turn of context the worker held.

reckon/crew/claims.py (commit c754cfe2a37fd5e4e25ab3523078804de99f0020) adds release_claim and narrow_claim, which rewrite the pointer's node.write_paths and report the amendment as a ClaimAmendment — previous and current declarations, the paths removed, and any unintegrated work the stopped run still holds. Nothing is wired to a command: reckon/cli.py is owned by a second node, so the module is the deliverable and the intended entry point is crew claim narrow|release, rendering ClaimAmendment.as_dict().

Refusal is the mechanism

An amendment is admitted only for a worker shown to have stopped, and "shown" is narrow by design: a live process refuses; a pointer whose launcher_host is not this host refuses, because a pid answers only on the machine that issued it and the crew config home is shared across login nodes; and a pointer that records no process yet refuses, because the pointer is written before its worker is spawned. Ones that cannot be answered refuse rather than being read as dead.
