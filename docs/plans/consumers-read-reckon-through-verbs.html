Consumers Read Reckon Through Verbs

§1 — What consumers depend on, measured

Reckon is the shared infrastructure for every other repository on this workstation, so the question is inverted: where must a consumer know reckon's internals? On 2026-09-24 the audit consumers-reach-into-reckon-internals searched imas-ambix, imas-codex, imas-efit, nova and dotfiles. Its report is at ~/.config/reckon/crew/reports/reckon/ship-s20-20260923/consumers-reach-into-reckon-internals.md, with every file and line in its appendix. Three couplings dominate:

  • Config-home paths, 1,537 lines. Consumers hardcode /home/ITER/mcintos/.config/reckon/... with the username in it. Some is code: nova writes sbatch --output into crew/runs/<run>/, and imas-ambix writes into crew/reports/. Most is docs quoting run directories. The resolver exists, _config_home() in reckon/_store.py honouring RECKON_HOME, but it is private and no verb prints it.
  • reckon crew output, 151 lines. These are all docs, and the CLI is already the interface consumers use. But nothing declares its JSON output shapes, so callers grep prose.
  • lane.json fields, 91 lines, 56 of them code. The fields are read by hand, including in ~/.agents/AGENTS.md's capacity gate. MCP has crew(view="lanes"), but the CLI has no verb.

Two coordinator surveys corroborate it. reckon-e5's s19-internals-consumers-survey (report under crew/reports/reckon/ship-s19-20260922/) found that skills/reckon-ship/scripts/worktree_fleet.py re-implements pointer classification and worktree layout; that the reckon-sync fallback writes mounts.json and the state symlink from the shell; and that the recovery recipe in AGENTS.md opens a live pointer's JSON for its worktree. reckon-e4 found that the SPA knows the server's fallback chain (index.json, then projection.json, then /_discover) and that the mount list is a config-home file served by filename. It also found that crew observe writes session captures into the committed roster docs/state/reckon/crew.json. That dirties the shared checkout, and every other session's member add is refused until someone commits it: 5 times in one day. imas-codex has its own inventory in docs/evidence/imas-codex-replan/shared-infrastructure-coupling.md.

§2 — One verb prints where reckon keeps things

reckon crew path --kind config-home|reports|runs|live|reviews [--project P] [--run R] prints the resolved absolute path. It reuses _config_home()'s precedence (RECKON_HOME, then ~/.config/reckon) rather than inventing one, and with --run it prints that run's directory. Done when tests/test_crew_path_prints_the_resolved_home.py shows, under a temporary RECKON_HOME, each kind printing a path under it, and with it unset, a path under ~/.config/reckon. The negative control is executed and logged: a verb that hardcodes the default ignores RECKON_HOME and fails. The write paths are reckon/cli.py and that test.

§3 — Lane, run and claim facts come from verbs, not files

Three read-only verbs, each printing JSON whose field names are declared once:

  • reckon crew lanes prints the fields lane_document.py already parses, the same payload as the MCP view="lanes".
  • reckon crew list --run R --field worktree|pid|phase|base_sha prints one pointer fact, so no recipe opens pointer JSON.
  • reckon crew claims [--path P] prints which live run holds a write path, read from each pointer's node.write_paths.

Done when tests cover each verb against temporary fixtures, and skills/reckon-ship/scripts/worktree_fleet.py uses crew list and crew claims in place of its own pointer classification. Its diff removes the duplicated classifier. The write paths are reckon/cli.py, reckon/crew/lane_document.py, that script and the tests.

§4 — Hand recipes become verbs

Two coordinator recipes repeat daily and are error-prone. reckon crew repair-manifest --run R --set field=value keeps manifest.md.asdelivered, writes the field in its canonical shape, and runs check-manifest afterwards. It replaces hand edits whose appends ran onto the previous line on 2026-09-24. The reckon-sync fallback's writes of mounts.json and the state symlink move behind reckon sync --write, which prints what it wrote. Done when each verb has a test whose negative control reproduces the hand-recipe defect, and ~/.agents/AGENTS.md and the skills cite the verbs in place of the recipes. The write paths are reckon/cli.py, the sync module the node names, the skill files the node names, and the tests.

§5 — Session captures leave the committed roster

crew observe and dispatch write session captures into docs/state/<project>/crew.json, a committed file. So every observation dirties the shared checkout, and peers' roster writes refuse until someone commits it. Captures move to <config-home>/crew/sessions/<project>/<member>.json. The committed roster keeps only member identity and role. new-work-gets-a-new-worker §3 moves the session onto the run record, and this section and that one must agree. Whichever lands second reads the first. Done when a test observes a run in a temporary repository and home, and asserts that the committed roster file's bytes are unchanged and the capture is under the config home. The write paths are the observe and dispatch capture sites, which the node names, and that test.

§6 — The CLI's JSON outputs are a declared contract

The JSON that crew dispatch, crew complete, crew list and the verbs above print is declared in one schema, versioned beside the flight config's LinkML. A consumer can then validate what it parses, and a change to a field is a schema change reviewers can see. The refusal classes consumers need are part of it. Preflight refusals launch nothing, while post-launch refusals always carry the run id they created; imas-codex measured a caller retrying against its own phantom run. Done when a test validates each command's output against the schema over its existing fixtures, and a refusal after launch carries run_id and launched: true. The negative control is executed and logged: removing run_id from a post-launch refusal fails validation. The write paths are the schema file, the commands' result builders, which the node names, and the tests.
