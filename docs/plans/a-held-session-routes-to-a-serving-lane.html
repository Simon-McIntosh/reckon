§2 — Jev reads the session's own admission before it routes

Deliverable. The state rendered for Jev carries, for each lane with a router, the worker slots the router would grant this coordinator session, taken from the lane document's admission.sessions[session].worker_slots or, when the session is not listed, admission.new_session_worker_slots, in the order the global routing rules already define. The route question's guidance says that a lane granting the session no slot is not available to it now. When a route nonetheless lands on such a lane for an implement or test node at the exact or guided specification level, Jev is asked once more with that lane excluded. The second answer stands, and the record names both asks, so the decision is visible. Routine or open work keeps today's behaviour and is queued under §13 of the queue plan.

Done when a test renders a state in which the local lane is open lane-wide but grants the session no slot, with codex serving, and finds that a guided implement node is not left queued on the local lane; the same state with the session granted one slot routes as before; an open-specification node in the zero-slot state is still allowed to hold. The picker's and dispatch's test files show no added failure against base. Negative control: without the session figure in the rendered state, the zero-slot case must reproduce the 2026-10-13 queueing.

§3 — A pick probe uses the inputs a dispatch would

Deliverable. reckon crew pick accepts the node fields that dispatch hands to the picker (write paths, negative control, estimated hours and section), and its answer lists any of them the probe left out, so a coordinator can see that a hold may come from what the probe lacked. With every field supplied, a pick and a dry-run dispatch render the same node state for Jev.

Done when a test renders the node state from a pick and from a dry-run dispatch with the same fields and finds them equal; a pick that omits write paths names them in its answer. Negative control: a pick given fewer fields than the dry-run must render a different state and the equality test must fail.

§4 — A lane change keeps the run's recorded waivers

Deliverable. reckon crew redispatch carries the waivers recorded in the original run's dispatch_options (allow_unreviewed_plan, accept_directory_claim and the reason in comment) into the new launch and records them as carried, so moving a run to another lane is not refused by a gate the original dispatch had already answered. A waiver is never added by a redispatch, only carried. A queued run is moved by redispatch without being discarded, so the move does not race the admission pass, and a queued run that never launched is moved by re-composing its launch from the recorded node rather than refused for having no prompt. The review reflex's retry asks the same question §2 asks before it re-queues on the lane that refused it.

Done when a test dispatches a node with --allow-unreviewed-plan against an uncovered plan, redispatches it to another backend, and finds it launched with the waiver recorded as carried; a node dispatched without the waiver is still refused on redispatch. Negative control: with the carry removed, the first case must be refused as on 2026-10-13.
