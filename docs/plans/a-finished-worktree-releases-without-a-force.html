On 2026-10-02 the lead authorised a force removal of one finished worktree and asked for the cause to be fixed, so that the authorisation stops recurring. A census of the project's managed worktrees found the same condition 35 times. Each such worktree is retained because it holds uncommitted changes. crew gc never forces, so every one of them waits for a human, and its worktree-held obligation blocks the coordinator's turn end with a remedy that cannot clear it.

§1 — Root cause: where the dirt comes from

reckon crew gc --repo ~/Code/reckon --project reckon on 2026-10-02 at about 20:00Z classified 87 managed worktrees: 35 dirty, 32 extraction, 16 unintegrated and 4 integrated. A read-only git status --porcelain of each dirty worktree found two causes.

  • A hand patch applied uncommitted across the fleet (30 of 35). Thirty worktrees modify tests/test_crew_orphan.py, most of them also tests/conftest.py, with the same _signal_one helper. It replaces an os.killpg(os.getpgid(pid), SIGTERM) that could signal every process the user owns. The worktrees come from the s9, s13, s15, s16, s18 and s20 waves, from 2026-08-25 to 2026-09-23. Main fixed the hazard differently at 586a1ac6e (2026-09-20, a worker signal reaches the worker, never the whole account), and _signal_one appears nowhere on main. So the patch was an emergency mitigation, written into live worktrees and never committed or cleaned up. Its content is superseded, but gc cannot tell superseded dirt from unique work.
  • A worker ends its turn with uncommitted edits (5 of 35, and the run that prompted this plan). Docs and plan edits, untracked figures and logs, one untracked test, and in s13-ship/execution-fit-refusal uncommitted source changes to reckon/capability.py and reckon/crew.py, which may be unique. The run that prompted this plan, passed-verdict-needs-exit-zero, was resumed by the review-repair reflex after its commits were merged. It rewrote a comment, exited without committing, and could not be resumed again: its session needed 232,500 input tokens against the lane's new 230,144 cap. On the same day, the impl-stays run left an uncommitted evidence correction behind its review.

Two properties of the system turn both causes into a standing authorisation request. The worker stop hook checks the manifest's status, not the worktree's cleanliness, so a turn can end dirty. And release treats any dirt as unique work. That is the right default, but it has no way to preserve dirt and then release. The worktree-held obligation then names crew gc --apply as its remedy, which never removes a dirty worktree, and a promoted run has no live pointer to acknowledge. The obligation can be cleared only by a human.

§2 — A worker cannot end its turn with uncommitted changes

Done when reckon/hooks/worker_stop.py refuses a worker's turn end while its worktree holds an uncommitted change to a tracked file, or an untracked file that is not ignored, outside the run directory. The refusal names each path and says to commit it or discard it. The .venv and .env provisioning links are exempt. A worker whose status is blocked or failed may still end dirty, but only after its manifest names every uncommitted path. A test covers a clean end, a dirty end refused, a blocked end that names its paths and is allowed, and the provisioning exemption, each in a temporary repository. The negative control removes the cleanliness check, and the dirty end then stops.

§3 — A finished worktree preserves its residue and releases

Done when release of a worktree whose commits are integrated into the integration head saves any residue first: tracked-file changes as a patch, and untracked files as a tar. They go into the run's directory, or for a worktree with no run into ~/.config/reckon/crew/worktree-residue/, named for the worktree. Release then removes the worktree. Before removing, it verifies that the saved patch applies cleanly to the worktree's head, which shows nothing was lost, and it prints the residue paths. Each dirty path is classified as one of:

  • subsumed: its working content equals that path at the integration head, or its change is identical to one in another preserved residue;
  • superseded: the path is also changed on the integration head since the worktree's base;
  • unique: neither of the above.

The classification is written beside the patch. A worktree whose residue includes unique source changes is preserved and released the same way, and is listed in a residue report for a human to read. Nothing is discarded unsaved, so no force authorisation is needed. The worktree-held obligation names this release as its remedy and clears once it runs. A test drives each class in a temporary repository, asserts the patch round-trips and the worktree is gone, and asserts that a worktree still claimed by a live run is untouched. The negative control skips the save, and the round-trip assertion then fails.

§4 — The standing dirty worktrees are released through §3

Done when §3's release has run over every dirty worktree that no live run claims, and the residue report lists each with its classes. The report is committed under docs/evidence/, and the dirty count gc reports is zero apart from worktrees a live run claims. The 30 _signal_one worktrees classify as superseded. Any unique source residue, such as s13-ship/execution-fit-refusal's changes to reckon/capability.py and reckon/crew.py, is named in the report for the lead.

§5 — The repair reflex does not resume a session the lane cannot hold

The review-repair reflex resumed passed-verdict-needs-exit-zero after its commits were merged. It got one useful turn, then two resumes that died at launch on the lane's context cap, which opened attempts that made the delivered manifest read as stale to promotion. Done when the reflex, and a manual crew resume, read the session's last recorded input-token count. A session whose count plus the completion reserve exceeds the lane's published window is refused before an attempt opens, naming the count and the window, with a fresh repair node as the remedy. A test covers a session within the window that resumes, and one over it that is refused without a new attempt. The negative control removes the check, and the over-window case then opens an attempt.

§6 — A worktree whose commits landed elsewhere releases too

§4's release at about 21:35Z kept 12 dirty worktrees, because each carries one to six commits that are not on main. They are listed in the landed record, docs/evidence/archive/a-finished-worktree-releases-without-a-force-landed.html#s4. Their dirt is mostly the superseded _signal_one patch, but a commit that is not on main may hold work that exists nowhere else.

Done when each of the 12 is checked commit by commit for patch equivalence with main, using git cherry or git patch-id against the integration head. A worktree whose every commit has a patch-equivalent on main is released through §3's residue-preserving path. A worktree with any commit that has no equivalent is kept and named with that commit's subject, in a report committed beside the landed record for the lead. The check also runs in crew gc, so a future squash-landed worktree releases the same way, with a test in a temporary repository covering an equivalent commit that releases and a non-equivalent one that is kept. The negative control drops the equivalence check, and the equivalent case is then kept.

§7 — An unmeasured commit list reads as unmeasured

From the §6 review (89, zero added failures). _inspect_workspace in reckon/crew/routing.py measures a worktree's commits beyond the integration head only when release_residue is true. Every other caller still gets a row with non_equivalent_commits: [] and patch_equivalent_commits: []. The promotion audit row is one of them (promotion.py, default release_residue=False). For a divergent dirty tree it reports an empty list of non-equivalent commits, so an unmeasured absence reads as a measured zero.

Done when. A row whose commits were not measured carries null in both fields, with a field naming why. A measured row keeps the lists. A test inspects one divergent dirty worktree both ways and asserts null in one case and a list in the other. Existing gc and residue tests keep passing.
