§2 — Reckon adopts its four north-star directions

north-star-orientation §5 proposed four directions:

  • State that tells the truth: every status, number and gate verdict is derived from evidence a reader can re-check, and nothing computable is stored as an assertion.
  • Unattended execution: an orchestrator carries a sprint from ready node to committed evidence without a human in the loop, and holds recoverably rather than failing when it must stop.
  • Legible to human and agent alike: a person and an agent read the same plan state through surfaces suited to each, with neither a second store nor a second truth.
  • Portable across harnesses: reckon's contracts hold whichever agent harness runs the work, so adding a backend never adds a second execution path.

§3 — A dispatched run reads working within 3 s, and /crew answers in under one

From §1's live measurement on 2026-10-03. Two causes keep the in-flight measure from passing, and they are separable.

The phase waits for the stream. reckon/serve.py derives a run's working phase from its stream file, which the worker writes only after its harness starts, so a launched run reads idle for 15 to 45 s. The pointer and the attempt record already exist at launch. A run with a live supervisor and no stream yet is launching, not idle, and should read so.

The read is slow. GET /crew took 6.5 to 7.7 s per request on the live server. That alone exceeds the gate, and it makes every watcher poll a seven-second wait.

Done when a test dispatches a fixture run and reads its row as launching or working from the first /crew response after the pointer appears, before any stream file exists. GET /crew answers in under one second on a fixture of 40 live pointers, timed in the test. The negative control is a scratch copy that derives the phase only from the stream file again, where the first assertion fails.
