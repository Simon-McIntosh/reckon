Rendered truth · the class an assertion about fields cannot reach

Nothing Leaves the Window

A surface can be correct in every field it exposes and still be unreadable, because the assertions available to it — document order, rendered row sets, computed properties — describe elements and say nothing about where those elements ended up. One defect of this kind was found today by a screenshot after five green gates. This plan builds the guard that makes the class measurable, applies it to every rendered surface, and records what it finds.

§1 — Why this exists

Measured 2026-09-04. The project picker's dropdown is anchored to its selector's left edge and extends rightwards past the viewport, so its right border and every row's plan count are clipped off-screen at 1374 and again at 1920. Five gates were green while that was true, and none of them was wrong:

GateWhat it assertsWhy it could not see this
test_spa_topbar_snapshotthe bar's children in document orderorder is correct; position is not asserted
test_spa_project_visibilitythe picker renders exactly the visible rowsthe right rows are present, and unreadable
test_spa_shell_geometrycomputed properties of named elementsa computed property is a value on one element, not a relation between an element and the window
test_css_layeringwhich stylesheet owns which custom propertyownership is correct; the resulting box is not measured
test_shared_token_contrastcontrast ratios against the groundthe colours pass; the element is off-screen

This is not a missing assertion, and that is the point. Adding more assertions in any of those five styles would not have caught it, because none of those styles can express the proposition “this box is inside the window”. It is a whole dimension the measure does not reach, which is harder to notice than a wrong assertion: the suite is not failing to check carefully, it is checking something else. It was the third time in one session that a rendered reading beat a green suite, and the only one of the three where no existing test could have been strengthened into the catch.

The remedy that fits the shape is a bound check on the class rather than a test for the instance — the same move that made an import-order-dependent module name and a three-source session id unreachable rather than merely fixed. Applied here: for every surface, at both widths, no element's bounding rectangle may leave the viewport.

§2 — One containment check over every surface

A single test walks each rendered surface at 1374 and 1920 and asserts, for every element in the document, that its bounding rectangle lies within the viewport horizontally: left >= 0 and right <= innerWidth. Horizontal only, and deliberately: vertical overflow is what scrolling is for, and the existing container tests already hold that the document itself does not grow. The surfaces are the ones the shell can route to, each in a populated state, plus the three states a reader can open on top of one — the project picker, the visibility sheet and the command palette — because the defect that motivated this plan lives in an overlay and an unopened overlay has no box to measure.

Two exemptions are legitimate and are declared as data rather than discovered as failures. An element inside a container that scrolls horizontally on purpose is measured against that container, not the window; the wide tables and the flow lanes are the cases. And an element deliberately positioned off-screen — a visually-hidden label, a transition's start state — is exempt by an explicit marker, so an exemption is a choice someone made and can be read, never an accident the check happens to tolerate.

Gate for this plan, recorded when the measure runs: against this repository the containment check runs over every routable surface at both widths and its verdict list is recorded in full — the number of surfaces walked, the number of elements measured, and every violation with its selector and overflow in pixels. Its evidence is that recorded list plus the check failing on a deliberately shifted element, because a check that has never failed has not been shown to work.

§3 — Whatever it finds

The check is written before anyone knows what it will report, which is the only honest order: a guard authored after the surfaces were adjusted to pass it would measure the adjustment rather than the surfaces. The picker overflow is already being fixed under its own plan's section, so this node covers the remainder — every other violation the §2 verdict lists, fixed at its own surface with the containment check as the measure. If the verdict lists nothing beyond the picker, this node closes as a recorded negative result rather than being quietly dropped, because “the guard found one defect in the whole surface” is a finding worth writing down.

§4 — Out of scope

Vertical overflow, which is what scrolling is for and what the existing container tests already cover. Contrast, which test_shared_token_contrast owns. Element overlap, because no instance of it has been measured here and a guard built for a hypothesis measures the hypothesis. Responsive behaviour below 1374, which no capture width exercises and which the handoff does not specify. And the per-plan capture sections stay exactly as they are: a capture shows a human what a surface looks like, while this check answers one narrow question automatically, and neither replaces the other — it was a capture that found this defect, and a capture that will find the next one of a kind nobody has thought to guard.

§ Decisions

Does the fix target the picker or the class?

The picker is already fixed under its own plan's section. An assertion there would leave every other surface unmeasured against a dimension no existing gate can express, and the next overflow would again be found by a screenshot or by a reader.

Which axis does the check measure?

Vertical overflow is scrolling, which the surfaces are built to do and the container tests already hold; asserting it would fail on every correct page. Horizontal overflow has no legitimate whole-page form here.

How is a deliberately off-screen element handled?

A heuristic exemption grows until it covers the defect it was meant to permit around, and nobody can tell which elements it swallowed. A declared marker appearing in the verdict makes every exemption a readable choice.

Is the check written before or after the surfaces are adjusted?

A guard authored to pass measures the adjustment rather than the surfaces, and its first verdict is the only unbiased inventory anyone will get. Recording it whatever it says is also what makes a low count a finding instead of an assumption.
