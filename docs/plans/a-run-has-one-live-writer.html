§2 — A worker never outlives its supervisor

What already exists. Most of the machinery this section needs is already in the code:

  • The supervisor already escalates its direct worker to SIGKILL after STOP_GRACE (reckon/crew/dispatch_launch.py), and tests/test_a_stopped_run_ends_its_supervisor.py locks that in.
  • signal_worker in reckon/crew/routing.py is the crew's signalling owner for runs; the session host signals only its own follower children, through its own _signal. Four production modules import signal_worker, besides routing.py itself.
  • Descendants are enumerated by _process_children and _live_descendant in reckon/crew/recovery_liveness.py. Processes holding a path as their working directory are found by _processes_holding in routing.py.
  • local_liveness in reckon/crew/recovery_liveness.py already asks the run directory's worker record when the supervisor's pointer pid is gone. recovery_classification.py calls it, and tests/test_live_process_outranks_classification.py asserts that a live process outranks a manifest-derived classification.

Deliverable. First reproduce the polygon-moment-owner shape: a supervisor that receives SIGTERM while its worker is working, and a worker that has started children of its own. Against the machinery above, establish two things, and record both in the manifest:

  • whether the direct worker or only its children survived;
  • why that run classified complete and then scoring while its worker lived, although local_liveness already reads the worker record. For example: the worker record was absent, it named a pid that the reparenting changed, or the classifier read a path that bypasses local_liveness. Check also why terminate's process-group signal missed the worker: a worker launched through srun --overlap runs under slurmstepd, not as a child in the supervisor's process group.

Then repair by extending those owners rather than adding a kill path beside them:

  • signal_worker gains the reach to end a run's own processes, and returns the pids it ended. Every one of its callers inherits this, not terminate alone. A process qualifies through either of two sources. The first is the descendant walk (_process_children) from the run's recorded supervisor and worker, each checked against its recorded start time. The second is a scan of this user's processes for an environment whose RECKON_RUN_ID names this run, with a start time no earlier than the run's launch. No existing enumerator can do the second: the descendant walk cannot reach a worker reparented to init, and _processes_holding reads only working directories and open files. So the scan is one new private helper beside _processes_holding in reckon/crew/routing.py, reusing its /proc walk, and _processes_holding stays report-only. A process whose environment cannot be read is not signalled. A process that merely holds the worktree as its working directory is listed and never signalled. That covers a coordinator or a peer that changed into it, so the extension cannot widen into the kill-everything hazard signal_worker exists to prevent.
  • The supervisor's exit path and crew stop (terminate in reckon/crew/dispatch_sessions.py) end the run's tree through it, and record the pids ended. crew stop reports any process still alive afterwards, rather than returning ok.
  • The gap the reproduction named is closed where it lives (in local_liveness, in the worker record's writer, or in the classifier's call), so a run whose worker lives is never classified complete or scoring.

No new public definition or refusal family is added; signal_worker's reach is the only interface that grows.

Done when tests/test_a_worker_never_outlives_its_supervisor.py passes, using real child processes in a temporary tree:

  • SIGTERM to the supervisor leaves no worker and no worker child alive, and the exit record names the pids ended.
  • crew stop on a run whose worker was reparented to init ends that worker and its children, identified by their RECKON_RUN_ID, and names them.
  • A process holding the run's worktree as its working directory, with no ownership mark, is listed by crew stop and left alive.
  • A run in the state the reproduction named, whose supervisor has exited while its worker pid lives, is not classified complete or scoring.

The negative control, which signals the supervisor pid alone, fails the first case. It is logged under the run directory. The reproduction's finding (why the worker survived) is recorded in the manifest. The test files that import dispatch_launch or exercise terminate pass. Every process the tests start is ended by the tests themselves, and is checked by pid afterwards.

Write paths: reckon/crew/routing.py (signal_worker), reckon/crew/dispatch_launch.py, reckon/crew/dispatch_sessions.py (terminate), reckon/crew/recovery_classification.py, reckon/crew/recovery_liveness.py (local_liveness), tests/test_a_worker_never_outlives_its_supervisor.py. routing.py is also written by the in-flight run a-worktree-release-is-whole (crew-runtime-positive-controls §47). §3 — A resume never launches beside a live attempt

What already exists. The guards this section needs are already in the code. resume_plan in reckon/crew/dispatch_sessions.py refuses a resume while the run "still has a live process", and _launcher_refusal in reckon/crew/resumption.py holds the same guard for the dry run. _observed_end_refusal in resumption.py refuses a sweep lift that has not observed the attempt end. Three test files, landed between 2026-09-29 and 2026-10-03, lock these in: tests/test_resume_refuses_a_live_worker.py, tests/test_resume_sweep_needs_an_observed_death.py and tests/test_direct_resume_needs_an_observed_death.py. Yet on 2026-10-12, attempt 7 launched beside attempt 6.

Deliverable. First reproduce that sequence: the sweep's auto-resume launches an attempt, and a coordinator's crew resume follows a minute later. Establish why resume_plan's check did not fire, and record it in the manifest. Candidates include:

  • a pointer read before the new attempt's pids were recorded;
  • a check made outside the run's pointer lock;
  • a liveness read keyed on the previous attempt's pids.

Then repair it inside resume_plan's own check, moving the check under the pointer lock if the window is the cause, so that no second refusal is written:

  • The refused resume keeps its advice text in the run directory beside the existing resume records. The existing refusal names that file, and the live attempt's next resume delivers it, so the text is never lost.
  • A launch that ends before it holds the session (as with the "active writer" refusal) records its own attempt's failure. It never overwrites the live attempt's pointer fields or its classification.

No refusal family is added. The stored advice file is the one new piece of state, and the manifest says why the existing resume record cannot carry it.

Done when the existing tests/test_resume_refuses_a_live_worker.py and tests/test_resume_sweep_needs_an_observed_death.py are extended with these cases, and pass:

  • The reproduced sequence: after an auto-resume launches an attempt, a crew resume launches nothing, exits non-zero naming the live attempt and its pids, and leaves its advice stored.
  • The next resume of that run carries the stored advice.
  • A sweep pass over a run whose attempt is alive resumes nothing.
  • A launch failing on an active-writer refusal leaves the live attempt's pointer phase and pids unchanged.

The negative control, which restores the cause the reproduction named, fails the reproduced case. It is logged under the run directory. The test files that import resumption or dispatch_sessions show no added failure against base.

Write paths: reckon/crew/resumption.py, reckon/crew/dispatch_sessions.py, tests/test_resume_refuses_a_live_worker.py, tests/test_resume_sweep_needs_an_observed_death.py. It runs after §2, which also writes dispatch_sessions.py.

§4 — A resumed worker is not ended as a delivery it has not made

Why. The launch supervisor ends a worker once its delivery is on disk. _reap_worker_on_its_terminal_manifest in reckon/crew/dispatch_launch.py sends SIGTERM, and SIGKILL after a grace, once the manifest reads a status in _WORKER_DONE_MANIFEST_STATUSES (complete or failed), is whole, was written after the attempt's baseline (_supervisor_manifest_baseline_ns), and has rested past the quiet period. The baseline discounts a manifest written before the attempt began. It does not discount a done status the previous attempt left on disk. A resumed worker inherits that word, so its first edit to any other field of the manifest makes the stale complete fresh, and the supervisor ends it as delivered.

Measured on 2026-10-14. Run r-20261014T022831463134-overlapping-queued-requests-launch-in-turn delivered with status: complete and was resumed with repair advice. At 03:03:38Z the worker corrected its landing: line and left the status word alone. Slurm then recorded step 1281970.2854 as CANCELLED with exit code 0:9 at 03:08:42Z, while the worker waited on its importer population with the repair uncommitted. The run's exit record read exit 0, no signal, last record tool_progress. Nothing in reckon/crew/resumption.py resets the status word, and the exposure is wide. Every path that resumes a run whose manifest reads complete or failed is exposed: the coordinator's crew resume, the repair reflex resuming a delivered worker on a blocking review finding (recovery_repair_dispatch.py, through resumption._resume), the sweep's auto-resume (resumption.py, through _resume), the MCP resume action in reckon/mcp.py, and a lane change (change_lane in reckon/crew/dispatch_sessions.py). reckon-cd's resume of a-held-dispatch-waits-its-fair-turn §15 at 01:43Z the same day survived only because its worker left the manifest alone until it had finished. The coordinators' current workaround is crew repair-status --status blocked before every resume, because blocked is not in the reaper's done set.

Deliverable. Before a resumed or relaunched worker is spawned, a manifest whose status is in the reaper's done set has its status word set to in-progress. That is a recognised non-terminal status (NON_TERMINAL_MANIFEST_STATUSES in reckon/crew/reports.py), so the reaper ignores the worker's interim edits and the classifier reads the run as working, not unreadable. The replaced manifest is kept beside it under a name carrying the attempt it came from, so an earlier copy, such as repair-status's manifest.md.asdelivered, is never overwritten. Only a done status the new attempt writes counts as its delivery. The reset is one function in reckon/crew/resumption.py. Two launch functions call it: _resume, which serves the sweep and the repair reflex, and change_lane. The CLI crew resume in reckon/crew_run_commands.py and the MCP resume action in reckon/mcp.py today copy _resume's launch steps (prompt write, baseline read, gate check, spawn, record_resumption). They call _resume instead, with their exit codes and payloads unchanged, so the reset has two callers rather than four. A manifest whose status is not in the done set, such as blocked, waiting or in-progress, is left as it is.

Done when tests/test_a_resumed_worker_is_not_ended_as_delivered.py passes, logged under the run directory with the literal command, its revision and an EXIT=0 line, with these cases:

  • A run whose manifest reads complete is resumed through the crew resume command, with a stub worker that edits a non-status manifest field and keeps running. The test shortens the quiet period and grace through their environment variables. The supervisor does not signal the stub within the shortened quiet period plus grace. The manifest reads in-progress, and the attempt-named copy holds the delivered manifest.
  • The same holds for a resume through _resume, as the sweep and the repair reflex call it, and through change_lane.
  • A resumed stub that writes complete is still ended as delivered once the quiet period passes.
  • A run whose manifest reads blocked keeps that word through the resume.
  • While the stub works, the live view classifies the run as running.

The negative control is executed and logged under the run directory with the runner's own FAILED line and a non-zero EXIT: with the reset removed, the first case fails, and the stub is signalled. The test files importing reckon/crew/resumption.py, reckon/crew/dispatch_sessions.py or reckon/crew_run_commands.py show no added failure against base. Write paths: reckon/crew/resumption.py, reckon/crew/dispatch_sessions.py, reckon/crew_run_commands.py, reckon/mcp.py, tests/test_a_resumed_worker_is_not_ended_as_delivered.py. This section runs after §2 and §3, which also write resumption.py and dispatch_sessions.py.
