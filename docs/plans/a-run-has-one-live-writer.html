§1 — Why: a run's tree had two writers twice in one morning

The nova session s21-nova reported both incidents on 2026-10-12.

A worker outlived its supervisor. Run r-20261012T041906125895-polygon-moment-owner (clive, attempt 2) recorded an exit of signal 15 at 05:45:02Z for supervisor pid 2222592, ending while it was working. Its claude worker, pid 2225621, kept running for about ten more minutes, now with parent pid 1. In that time it:

  • spawned pytest;
  • committed 4523dc2f3;
  • rewrote manifest.md.

Meanwhile reckon classified the run as complete, then scoring, and the review reflex dispatched a review against 775370a7c while the tree was still moving. reckon crew stop --run returned ok, but the orphan and its children were alive five seconds later, because it targets only the recorded pid. The worker is launched in the supervisor's process group (start_new_session=False in reckon/crew/dispatch_launch.py), so a stop aimed at the group should end it. Why it survived here is the first thing §2 establishes.

A resume launched beside a live attempt. Run r-20261012T042612803730-proto-read-route (codex) was auto-resumed by the wait sweep at about 10:07:30Z (attempt 6: supervisor 3206965, codex 3207785, still alive). At 10:08:49Z a coordinator's crew resume --advice launched attempt 7. Codex refused it with "thread … already has an active writer", and it exited in 4 s. The pointer then recorded attempt 7's exit and classified the run exited-unfinished, and its next action suggested repair-status --status complete while attempt 6 was still working. The coordinator's advice text was lost without any notice. The previous minute's resume-3.stderr.log shows the same conflict.

§2 — A worker never outlives its supervisor

Deliverable. First reproduce the polygon-moment-owner shape: a supervisor that receives SIGTERM while its worker is working, and a worker that has started children of its own. Establish from that reproduction why the worker survived, whether because it changed its process group, or the signal reached the supervisor alone, or the handler did not forward it. Then repair three things:

  • The supervisor's exit path ends the worker's whole process tree before it records the exit, and records which pids it ended.
  • crew stop (terminate) ends every live descendant of the run's recorded supervisor and worker pids, plus any process whose working directory lies in the run's worktree. It lists each pid it signals, and reports any process still alive afterwards rather than returning ok.
  • A run whose recorded worker pid is still alive is never classified complete or scoring, so the review reflex cannot dispatch against a tree that is still moving.

Done when tests/test_a_worker_never_outlives_its_supervisor.py passes, using real child processes in a temporary tree:

  • SIGTERM to the supervisor leaves no worker and no worker child alive, and the exit record names the pids ended.
  • crew stop on a run whose worker was reparented to init ends that worker and its children, and names them.
  • A run whose supervisor has exited while its worker pid lives is not classified complete or scoring.

The negative control, which signals the supervisor pid alone, fails the first case. It is logged under the run directory. The reproduction's finding (why the worker survived) is recorded in the manifest. The test files that import dispatch_launch or exercise terminate pass. Every process the tests start is ended by the tests themselves, and is checked by pid afterwards.

Write paths: reckon/crew/dispatch_launch.py, reckon/crew/dispatch_sessions.py (terminate), reckon/crew/recovery_classification.py, tests/test_a_worker_never_outlives_its_supervisor.py.

§3 — A resume never launches beside a live attempt

Deliverable. crew resume and the wait sweep's auto-resume both check, under the run's pointer lock, whether a supervisor or worker for the run is alive.

  • If one is, a coordinator's crew resume does not launch. It refuses, naming the live attempt and its pids. Its advice is kept in the run directory as pending advice, and the live attempt's next resume delivers it, so the text is never lost.
  • The sweep never resumes a run whose attempt is alive.
  • A launch that ends before it holds the session (as with the "active writer" refusal) records its own attempt's failure, and never overwrites the live attempt's pointer fields or its classification.

Done when tests/test_a_resume_never_launches_beside_a_live_attempt.py passes:

  • A crew resume while the run's supervisor pid is alive launches nothing, exits non-zero naming the live attempt, and leaves its advice stored.
  • The next resume of that run carries the stored advice.
  • A sweep pass over a run whose attempt is alive resumes nothing.
  • A launch failing on an active-writer refusal leaves the live attempt's pointer phase and pids unchanged.

The negative control, which drops the liveness check from crew resume, fails the first case. It is logged under the run directory. The test files that import resumption or dispatch_sessions pass.

Write paths: reckon/crew/resumption.py, reckon/crew/dispatch_sessions.py, tests/test_a_resume_never_launches_beside_a_live_attempt.py. It runs after §2, which also writes dispatch_sessions.py.
