The nova session s21-nova reported both incidents on 2026-10-12.

A worker outlived its supervisor. Run r-20261012T041906125895-polygon-moment-owner (clive, attempt 2) recorded an exit of signal 15 at 05:45:02Z for supervisor pid 2222592, ending while it was working. Its claude worker, pid 2225621, kept running for about ten more minutes, now with parent pid 1. In that time it:

  • spawned pytest;
  • committed 4523dc2f3;
  • rewrote manifest.md.

Meanwhile reckon classified the run as complete, then scoring, and the review reflex dispatched a review against 775370a7c while the tree was still moving. reckon crew stop --run returned ok, but the orphan and its children were alive five seconds later. terminate signals the recorded pid's whole process group, through _signal_process_group in reckon/crew/routing.py, so the signal did not reach the group the worker was in. The worker is launched in the supervisor's process group (start_new_session=False in reckon/crew/dispatch_launch.py), so a stop aimed at the group should end it. Why it survived here is the first thing §2 establishes.

A resume launched beside a live attempt. Run r-20261012T042612803730-proto-read-route (codex) was auto-resumed by the wait sweep at about 10:07:30Z (attempt 6: supervisor 3206965, codex 3207785, still alive). §2 — A worker never outlives its supervisor

What already exists. Most of the machinery this section needs is already in the code:

  • The supervisor already escalates its direct worker to SIGKILL after STOP_GRACE (reckon/crew/dispatch_launch.py), and tests/test_a_stopped_run_ends_its_supervisor.py locks that in.
  • signal_worker in reckon/crew/routing.py is the crew's signalling owner for runs; the session host signals only its own follower children, through its own _signal. Four production modules import signal_worker, besides routing.py itself.
  • Descendants are enumerated by _process_children and _live_descendant in reckon/crew/recovery_liveness.py. Processes holding a path as their working directory are found by _processes_holding in routing.py.
  • local_liveness in reckon/crew/recovery_liveness.py already asks the run directory's worker record when the supervisor's pointer pid is gone. recovery_classification.py calls it, and tests/test_live_process_outranks_classification.py asserts that a live process outranks a manifest-derived classification.

Deliverable. First reproduce the polygon-moment-owner shape: a supervisor that receives SIGTERM while its worker is working, and a worker that has started children of its own. Against the machinery above, establish two things, and record both in the manifest:

  • whether the direct worker or only its children survived;
  • why that run classified complete and then scoring while its worker lived, although local_liveness already reads the worker record. For example: the worker record was absent, it named a pid that the reparenting changed, or the classifier read a path that bypasses local_liveness. Check also why terminate's process-group signal missed the worker: a worker launched through srun --overlap runs under slurmstepd, not as a child in the supervisor's process group.

Then repair by extending those owners rather than adding a kill path beside them:

  • signal_worker gains the reach to end a run's own processes through the existing enumerators, and returns the pids it ended. Every one of its callers inherits this, not terminate alone. A process qualifies only if it descends from the run's recorded supervisor or worker, identity-checked by its start time, or if its environment carries RECKON_RUN_ID naming this run. A process that merely holds the worktree as its working directory is listed and never signalled. That covers a coordinator or a peer that changed into it, so the extension cannot widen into the kill-everything hazard signal_worker exists to prevent.
  • The supervisor's exit path and crew stop (terminate in reckon/crew/dispatch_sessions.py) end the run's tree through it, and record the pids ended. crew stop reports any process still alive afterwards, rather than returning ok.
  • The gap the reproduction named is closed where it lives (in local_liveness, in the worker record's writer, or in the classifier's call), so a run whose worker lives is never classified complete or scoring.

No new public definition or refusal family is added; signal_worker's reach is the only interface that grows.

Done when tests/test_a_worker_never_outlives_its_supervisor.py passes, using real child processes in a temporary tree:

  • SIGTERM to the supervisor leaves no worker and no worker child alive, and the exit record names the pids ended.
  • crew stop on a run whose worker was reparented to init ends that worker and its children, identified by their RECKON_RUN_ID, and names them.
  • A process holding the run's worktree as its working directory, with no ownership mark, is listed by crew stop and left alive.
  • A run in the state the reproduction named, whose supervisor has exited while its worker pid lives, is not classified complete or scoring.

The negative control, which signals the supervisor pid alone, fails the first case. It is logged under the run directory. The reproduction's finding (why the worker survived) is recorded in the manifest. The test files that import dispatch_launch or exercise terminate pass. Every process the tests start is ended by the tests themselves, and is checked by pid afterwards.

Write paths: reckon/crew/routing.py (signal_worker), reckon/crew/dispatch_launch.py, reckon/crew/dispatch_sessions.py (terminate), reckon/crew/recovery_classification.py, reckon/crew/recovery_liveness.py (local_liveness), tests/test_a_worker_never_outlives_its_supervisor.py. routing.py is also written by the in-flight run a-worktree-release-is-whole (crew-runtime-positive-controls §47). This section waits for that run to merge, through a section gate declared on it.

§3 — A resume never launches beside a live attempt

What already exists. The guards this section needs are already in the code. resume_plan in reckon/crew/dispatch_sessions.py refuses a resume while the run "still has a live process", and _launcher_refusal in reckon/crew/resumption.py holds the same guard for the dry run. _observed_end_refusal in resumption.py refuses a sweep lift that has not observed the attempt end. Three test files, landed between 2026-09-29 and 2026-10-03, lock these in: tests/test_resume_refuses_a_live_worker.py, tests/test_resume_sweep_needs_an_observed_death.py and tests/test_direct_resume_needs_an_observed_death.py. Yet on 2026-10-12, attempt 7 launched beside attempt 6.

Deliverable. First reproduce that sequence: the sweep's auto-resume launches an attempt, and a coordinator's crew resume follows a minute later. Establish why resume_plan's check did not fire, and record it in the manifest. Candidates include:

  • a pointer read before the new attempt's pids were recorded;
  • a check made outside the run's pointer lock;
  • a liveness read keyed on the previous attempt's pids.

Then repair it inside resume_plan's own check, moving the check under the pointer lock if the window is the cause, so that no second refusal is written:

  • The refused resume keeps its advice text in the run directory beside the existing resume records. The existing refusal names that file, and the live attempt's next resume delivers it, so the text is never lost.
  • A launch that ends before it holds the session (as with the "active writer" refusal) records its own attempt's failure. It never overwrites the live attempt's pointer fields or its classification.

No refusal family is added. The stored advice file is the one new piece of state, and the manifest says why the existing resume record cannot carry it.

Done when the existing tests/test_resume_refuses_a_live_worker.py and tests/test_resume_sweep_needs_an_observed_death.py are extended with these cases, and pass:

  • The reproduced sequence: after an auto-resume launches an attempt, a crew resume launches nothing, exits non-zero naming the live attempt and its pids, and leaves its advice stored.
  • The next resume of that run carries the stored advice.
  • A sweep pass over a run whose attempt is alive resumes nothing.
  • A launch failing on an active-writer refusal leaves the live attempt's pointer phase and pids unchanged.

The negative control, which restores the cause the reproduction named, fails the reproduced case. It is logged under the run directory. The test files that import resumption or dispatch_sessions show no added failure against base.

Write paths: reckon/crew/resumption.py, reckon/crew/dispatch_sessions.py, tests/test_resume_refuses_a_live_worker.py, tests/test_resume_sweep_needs_an_observed_death.py. It runs after §2, which also writes dispatch_sessions.py.
