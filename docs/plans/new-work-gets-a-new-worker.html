New Work Gets A New Worker

A dispatch to a roster member resumed that member's last session, whatever that session had been doing. A member's session was keyed by agent configuration (lane, effort and sandbox), not by task. So a new node sent to a member inherited the previous node's whole conversation and paid for it on every turn. The decision was made at reckon/crew/dispatch.py:3622-3634 and carried into argv by launch_plan(resume_session=…). It fired whenever a backend set session_reuse: true, and every backend did.

Measured 2026-09-23, 5,440 runs. 312 of 2,089 local runs resumed another task's session and inherited a median 81,957 tokens on their first turn (max 494,189). A fresh local run carries about 60,000 tokens of setup, so a resumed one started at roughly 2.4 times that. 1,315 of 3,105 codex runs (42%) resumed one. The codex stream does not expose the first-turn figure, and codex bills all input, cached or not, so every turn of those runs paid for another task's transcript. The review reflex dispatches every review under one session-derived member, so each review inherited the last. One then resumed a session whose previous run had died looping in compaction, and opened in compaction again. The benefit the pattern was meant to buy, a worker that remembers the node, was never measured.

The rule. A session continues the task it began and nothing else. Three reuses are valid and are kept deliberately:

  • crew resume of the same run, to answer a NEEDS-HELP brief, ride out an outage or recover a turn that ended early;
  • crew redispatch of the same run, which keeps the run and changes the lane;
  • a new run on the same task: a repair of the same node, or a re-review of the same reviewed run.

Every other dispatch starts a fresh session. Stopgap in force: session_reuse: false on every backend, in the project layer (daabeca2) and the host layer, which also blocks the third valid case until §2 lands. §7 restores it.

§1 — Every site that carries a session between runs is named

Measure. A reuse map lists every code and guidance site that does any of the following, each with its file and line:

  • composes a resume into a worker's argv (--resume or the codex equivalent);
  • writes session fields onto a roster member (session_id, session_model, sessions, session_owners);
  • selects or serialises dispatch by member;
  • tells a coordinator to route work to a member because its session remembers.

Each row is classed as same-run, same-task or cross-task. Each row also names the test files that assert on it, so later nodes fence those tests with the source.

Falsifier. The map must contain dispatch.py:3622-3634, the redispatch continued branch, crew resume, the reflex's dispatch_review_for_run and the reckon-ship Continuity rule. A map missing any of the five has not searched.

§2 — A dispatch resumes a session only on the same task

Measure. The dispatch-time session decision compares task identity, not member identity. For implement, test and investigate runs, task identity is (project, plan, node id). For a review, it is the reviewed run id. A prior session is resumed only when its run carried the same task identity. It is never resumed when that run ended with the session too large to continue: Prompt is too long / blocking_limit, or compaction that never completed. The decision does not depend on the session_reuse key, which becomes a statement of whether the harness can resume at all.

Falsifier. Tests assert on the argv the launcher would run, never on a helper's return value. With session_reuse: true:

  1. A new node sent to a member whose recorded session belongs to a different node composes no resume.
  2. A second dispatch of the same node composes the prior session.
  3. A re-review of the same reviewed run composes the prior review session.
  4. A session whose run ended blocking_limit is not composed.
  5. crew resume still composes its own run's session.

The negative control restores member-keyed selection, and case 1 must turn red.

§3 — A session belongs to its run, not to the roster

Measure. Dispatch and observe stop writing session_id, session_model, sessions and session_owners onto roster members. The captured session lives on the run record and its ledger row, and §2's lookup reads it from there by task identity.

Falsifier. A test snapshots docs/state/<project>/crew.json members, runs a dispatch and an observe, and requires member fields byte-identical afterwards while the run record carries the session. That uncommitted roster write is what dirtied crew.json under a peer session tonight.

§4 — No shared member serialises unrelated work

Measure. A dispatch that names no member no longer binds to one session-derived member. That includes every reflex review. Each such dispatch gets its own member identity, or none, so one run in flight never refuses an unrelated task with member-in-flight.

Falsifier. Two reflex reviews for two different runs dispatch back to back and both launch, with distinct members and no resume. A dispatch naming an explicit member still serialises on it, because that remains a deliberate choice.

§5 — The guidance teaches the same rule

Measure. The reckon-ship skill's Continuity rule and references/sprint-orchestration.md §Continuity stop routing same-plan follow-up work to the roster member whose long-lived session remembers the node. They state the same-task rule from §2 and its three valid cases, with the measured cost as the reason.

Falsifier. A grep over skills/ for long-lived session and remembers the node returns nothing, and each rewritten passage names all three valid reuses. A rule without its reason is routed around the first time the alternative looks slower.

§6 — The burn is stated in tokens, before and after

Measure. Codex's own session files (rollout files) give cumulative input per run where its stream does not. For the codex runs that resumed another task's session, the census states the input attributable to the inherited transcript. After §2 lands, a census over at least the next 50 dispatches reports zero cross-task resumes and states how many same-task resumes remain.

Falsifier. A positive control: a run known from its argv to have resumed a session must show a non-zero inherited figure through the same parser. Otherwise the zero is the instrument, not the fleet.

Outcome — the inherited figure is stated for codex, before §2 lands. The census of every codex run under ~/.config/reckon/crew/runs reads 3,274 codex runs across 1,916 sessions. A fresh run opens a session rollout; a run that inherits an earlier task's transcript appends a task to one that already exists. By that boundary, 1,916 runs are fresh (median opening-request input 40,997 tokens) and 1,358 runs (41%) resumed a different task's session (median 166,421, four times the fresh figure). The input attributable to the inherited transcript, priced as each resumed run's opening request above the fresh median, totals 172,082,502 tokens. Codex bills every input token, cached or not, so this is charged again on every request a resumed run makes. same_run is zero: every codex resume observed is a cross-task resume, which is the defect this plan targets. A false-positive control, kept, because the obvious substitute instrument lies. The dialect appends resume <session id> to a codex exec argv, so the recorded argv looks like the natural way to find resumes — but no codex run's recorded argv carries the token, and a dispatch pointer's session_resumed flag is not a substitute: r-20260923T034949217912-pcrf-production-route-ladder carries session_resumed: true with no resume token in argv and a rollout that opened fresh. Recorded as a gap, not repaired here. The falsifier was written for a run "known from its argv to have resumed a session". For codex that literal is unsatisfiable at this revision: argv is durably recorded only on the ephemeral live pointers, the resume token is appended only when session_reuse is on, and the stopgap has it off, so no historical codex argv carries it. The substance of the falsifier — a known-resumed run showing a non-zero inherited figure through the same parser — is met by the positive control above, and the archaeology that established the argv finding is in the data's argv_note. A follow-up may wish to make the resumed session id a durable field on the run record so the argv clause becomes checkable.

§7 — The stopgap is lifted once the rule holds

Measure. After §2 and §3 land and their tests pass at the merged head, session_reuse returns to true in the host and project layers on the backends whose harness can resume. The first re-review of an already-reviewed run composes its prior review session, and the first new node composes none. Both are read from the launched argv and recorded here.

Falsifier. If any dispatch after the flip composes a session from a different task, the flag goes back to false the same hour and §2 reopens.
