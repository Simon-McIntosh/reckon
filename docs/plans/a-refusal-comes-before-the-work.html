§1 — Why: three refusals that arrived after the work they judged

power-convertor-df reported these on 6 November from the power_convertor filter-recommendation sprint (session c76cf9d1, 5–6 November). Each is a check that exists but runs later than the first call that could have made it.

  • A batch skips the node contract. crew dispatch --batch queued malformed entries that a single dispatch or --dry-run refuses. The single path runs validate_node (reckon/crew/dispatch_plan.py near line 843). The batch path, queue_batch (reckon/crew/dispatch_batch.py near line 478) into queue_requests (reckon/crew/dispatch.py near line 293), runs only admission_domain_findings, so the contract refusals surface later at admission. The single path's contract is four refusals, not one: validate_node, then negative_control_finding (near line 851), gate_population_finding (near line 863) and the execution-fit refusal (near line 869).
  • A brief run's plan link is asked for only at landing. An implement-role run dispatched with --brief and no --plan must land with --plan-link or --unplanned-reason (reckon/crew/promotion_checks.py near line 1770), at both crew complete and crew merge. Dispatch neither asks for it nor records it, so the coordinator first meets it after the work is done.
  • An edit refusal reveals one missing field at a time. append_evidence raises on a missing plan, then anchor, then title, then body (reckon/_store.py near lines 1289–1305); close raises on status, then by (near lines 4141–4149); append on target (near line 3668). Each retry costs a round trip to learn the next field.

The same report found a fourth: a write path under ~/.cache/power_convertor-briefs/ was accepted by --dry-run and refused by the real call as outside the authorised work repository (_require_write_paths_in_authority, reckon/crew/dispatch_admission.py near line 1983, called from plan_dispatch in reckon/crew/dispatch_plan.py near line 911). a-dry-run-must-resolve-what-the-real-call-resolves §5, which made the dry run resolve what the real call resolves, is done, so this is a gap it left; §5 here owns it.

§2 — A batch entry is refused on the node contract when it is queued

Deliverable. The three node-local contract refusals plan_dispatch makes (validate_node, negative_control_finding and gate_population_finding) move into one function in reckon/crew/dispatch_plan.py that both paths call, and each batch entry's node is judged by it, with the same locked decisions and budget ceiling, before it is stored. An entry the contract refuses is reported in the batch result with the same refusal detail the single path gives and is not stored. The rest of the batch is stored as today. The fourth refusal, execution fit (dispatch_plan.py near line 869), is judged against the backend plan_dispatch resolves for the node. A queued request has no such backend until the picker routes it, so that refusal stays where the lane is known, at launch, and is not shared. The call is shared rather than copied: the batch reaches it through the function the single path uses, so the two cannot drift.

Done when a new tests/test_a_batch_entry_meets_the_node_contract.py shows three things with a temporary crew home: an entry whose goal joins two action clauses, read the config; run the lane, whose second clause opens with an action verb from _DELIVERABLE_ACTIONS (reckon/crew/node.py near line 79), is refused in the batch result with the single path's detail and leaves no queued pointer; a well-formed entry in the same batch is stored; and the refusal detail is equal to what a single --dry-run of that entry reports. A fifth case: an entry whose gate names a test file the repository does not hold is refused in the batch result. Four negative controls: removing the batch's contract call stores the malformed entry; calling validate_node alone stores the fourth case's entry; omitting gate_population_finding from the shared function stores the fifth case's entry; and a batch-local copy of the check whose message differs fails the third case. The test files importing reckon.crew.dispatch_batch or reckon.crew.dispatch add no failure against the base revision, run one arm at a time with at most -n 4. §3 — A brief run's plan link is recorded at dispatch

Deliverable. crew dispatch accepts --plan-link and --unplanned-reason and records the one given on the node. An implement-role dispatch with --brief and no --plan that gives neither is refused at dispatch with the same two-flag remedy the landing refusal names. At crew complete and crew merge, the brief discharge in reckon/crew/promotion_checks.py reads the recorded value when the flag is not passed. A flag passed at landing still overrides it. Runs dispatched before this change carry no recorded value and are judged at landing as today.

Done when a new tests/test_a_brief_run_names_its_plan_at_dispatch.py shows four things with a temporary crew home: an implement-role brief dispatch with neither flag is refused naming both flags; one with --plan-link is stored with the link on its node; its landing discharge passes with no landing flag; and a pointer with no recorded link and no landing flag is refused at landing as today. Three negative controls: dropping the dispatch refusal stores the first dispatch; not reading the recorded link makes the third case refuse; and treating a missing recorded link as a discharge makes the fourth case pass. The test files importing reckon.crew.promotion_checks or reckon.crew.dispatch add no failure against the base revision, run one arm at a time with at most -n 4.
