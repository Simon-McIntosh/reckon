§4 — Critical work can take a slot ahead of waiting reviews

On 22 November 2026, once the lane allowance became binding, reviews of delivered runs waited for the same slots as new implement work. 39 delivered runs sat waiting for review while new sections took the slots that freed. A delivered run cannot land without its review, and the sections that wait on it cannot launch, so a review held behind new work stops the plan's forward work. The lead's direction: reviews of delivered runs go to the front of the queue by default, with room left for critical work.

A delivered run's review already takes a freed slot ahead of implement work: the admission order keeps delivered reviews at the head of the lane, above every priority override. What the lead's direction still lacks is the room it leaves for critical work, because no override can reach ahead of a waiting review.

Deliverable. A request whose priority override is at or above the project's critical level is offered a freed slot ahead of waiting reviews of delivered runs. The critical level is the flight setting queue.critical_priority, default 100. Every other request keeps today's order, with delivered reviews first.

Done when. tests/test_a_critical_request_takes_a_slot_before_reviews.py passes, covering: with one slot free, one queued review of a delivered run and one implement request at override 100, the implement request launches first; at override 99 the review launches first; with no override set the review launches first; and a project flight setting queue.critical_priority to 50 lets an override of 50 launch first.
