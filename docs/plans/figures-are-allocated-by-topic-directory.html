§1 — Untested rather than safe

Figures are tracked binaries. Seventy-five of them are in the repository, written by workers in detached worktrees and merged by coordinators, and the guidance that exists covers only where to put them and how to reference them: under docs/figures/<topic>/, embedded with a project-absolute src because a relative one 404s in the SPA.

Nothing states the allocation unit. A node may declare docs/figures/<topic> — a directory, not a file, and one that may not exist yet — as an exclusive write path, and dispatch accepts it and registers the claim. Whether that claim means the tree, whether two nodes may write sibling files inside one topic, and what exclusivity means for a path with no contents are all unanswered.

Nothing states a merge policy either. There is no .gitattributes, so a PNG written by two workers under one filename would conflict with no resolution a coordinator could perform — the halves cannot be combined and neither is obviously right.

Zero figure merge conflicts have occurred in seven days. That is the evidence this is untested, not the evidence it is safe: no two nodes have yet been fenced to the same topic, and nothing would have stopped them.

§2 — The topic directory is the unit

State the rule that dispatch already half-implements: a figure topic directory is claimed by exactly one node, the claim covers the tree, and a second node declaring the same topic or a path inside it is a scope conflict rather than a shared workspace.

The corollary is the merge policy, and it is not a merge: a figure is added or replaced wholesale, never combined. Two nodes producing one filename is a scope defect caught at dispatch, not a conflict resolved at integration, because there is no correct resolution at integration.

Done when a second node declaring a topic directory already claimed by a live run is refused, naming the owning run, and a node declaring a path inside another node's claimed topic is refused the same way — both demonstrated as refusals rather than asserted, since a containment rule never shown to refuse cannot be told from one that admits everything. The refusal for a directory that does not yet exist is exercised explicitly, because that is the ordinary case for a capture node and the one most likely to be mishandled. The count of claims the check walks is stated as a digit.

Dispatch already contained the containment walk; the node verified it rather than reimplementing a working guard, and added a mechanism comment at the refusal site stating the allocation unit. Six figure-topic cases in tests/test_crew_dispatch_guard.py demonstrate the three refusals the done-when names — a second node on a claimed topic, a path inside a claimed topic (both directions), both for a topic directory with no contents on disk — each as an actual refusal carrying the owning run id and node id; the never-combined corollary is pinned by refusing a second producer of one filename, while disjoint topics still dispatch. The walk reads 3 live claims at refusal, asserted by instrumenting the walk. A mutation control replacing the containment predicate flips exactly the six refusal tests to DID NOT RAISE while the eight non-refusal cases pass, proving the guard fires. Landed under commit 4437fbf3, 14 consecutive dispatch-guard cases passing (eight pre-existing unchanged). The sibling-writers decision is left open to the plan. Full record: §2 landed.

§3 — Write it where a worker reads it

The rule is worth nothing in a plan alone. It belongs where an author or a coordinator will encounter it: the figure guidance in reckon-create, which is the only place figures are currently described, and the worktree and scope section of the ship references.

Done when both surfaces state the allocation unit and the never-merged rule, and a reader of either can determine what to declare for a capture node without inspecting dispatch's source. State as a digit how many figure-writing plans in this repository would have been refused under the new rule when they ran — the expected answer is zero, and a non-zero answer is a finding rather than an error.

§4 — Out of scope

This does not change where figures live, how they are referenced, or the style rules governing them. It does not introduce a figure registry or a naming scheme; the topic directory is already the grouping and this only makes it the allocation unit too.

It does not address what a capture's gate reads, which is a separate contract with its own plan.
