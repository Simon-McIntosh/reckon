§1 — The surface's only lever under pressure is a worse brief

The context-fit estimate counts every resolvable repository path named anywhere in a node's brief at full file load, not only its declared write paths. When the estimate exceeds the lane's window the node is refused with competence-refusal, and the refusal reports the total without naming which input was marginal. The declared write paths cannot be removed — the node must edit them. So the one field a coordinator can shrink is the prose, and the prose is where the evidence, the constraints and the fences live.

Three coordinators hit this on 2026-09-21, in three shapes, and the third is the one that makes it a safety defect rather than friction. All three figures are from refusal payloads, not estimates.

The third row inverts the incentive the fence exists to create. A coordinator under budget pressure learns to stop writing the prohibition, and what the prohibition prevents is exactly the stray write that the repository treats as its hazard. The workaround is not free either: imas_codex.standard_names.graph_ops is less checkable than a path — a naming check that greps for repository paths will not catch it, and a reader cannot stat it. So the affordance the surface leaves is say it in a form that is harder to verify.

Why it is invisible. The retry reads as an ordinary success. Nothing on the run, the manifest or the ledger row records that the accepted node is not the node that was designed, so a later reader sees a clean dispatch and no trace that its evidence was cut to fit. One of the three coordinators reproduced this on themselves ten minutes after writing it up as a finding, which is what makes it a gradient rather than a lapse.

§2 — The refusal names its dominant term

The cheapest repair, and most of the value. The refusal already computes the per-file breakdown — the dry-run payload carries repository_files.named_files and write_paths with an estimated_tokens against each. It reports only the total, so the coordinator is left guessing which input to cut and rationally cuts the only one they control.

Done when a context-fit refusal names the single largest contributing input with its token figure and whether it arrived as a declared write path or as a mention, asserted against a fixture whose dominant term is a write path and again where it is a mention, since the remedy differs between the two; the refusal is asserted to name a term even when every contribution is small, because no dominant term is itself the answer that tells a coordinator the brief is not the problem; and the existing total and window figures are asserted unchanged, so this adds a line rather than replacing the evidence a reader already relies on.

§3 — A mention is charged at a reference cost, and a prohibition always is

A path a node must edit and a path a node is told never to open are not the same load, and today they cost the same. The estimator should charge a declared write path at full and a mention at a reference cost.

A path in a negative clause is the unambiguous case and should be charged as a reference outright, because the worker provably will not open it — that is what the sentence says. This is the one place the estimator can be certain, and it is currently the place it is most wrong.

Done when a path appearing only in prose is charged at a reference cost rather than at file load, asserted by estimating one brief twice, identical but for the mention, and requiring the difference to be the reference cost and not the file size; a path inside a negative clause is asserted to be charged as a reference even when the same path is also a declared write path elsewhere in the brief, since the two clauses are about different files in the general case and the write path must still be charged at full; the three measured briefs above are asserted to fit their lanes after the change, using their recorded figures rather than re-derived ones; and a brief naming no repository path is asserted unchanged, so the change cannot be mistaken for a blanket discount.

§4 — A named anchor that is not preloaded

Even at a reference cost, a coordinator sometimes wants to name a large file without buying any of it. An explicit opt-out makes that a stated choice rather than a trick, and removes the incentive to reach for the dotted module name purely to dodge the estimate.

Done when a dispatch can name a path as an anchor without its content entering the estimate, asserted by the same brief estimating lower with the opt-out than without it; the opt-out is asserted to be recorded on the run, so a later reader can see that the worker was briefed about a file it was not given; and a path that is both opted out and declared as a write path is refused rather than silently resolved either way, asserted, because a node cannot both need to edit a file and not need to see it.

§5 — A reduced brief leaves a trace

The three repairs above reduce the pressure; none of them removes it. A window will still be exceeded, a coordinator will still cut, and today that cut is invisible. What makes it safe to cut is that the cut is recorded.

Done when a dispatch accepted after a refusal for the same node id records that it was retried and what changed about its brief, asserted by refusing one dispatch and accepting a shortened one, then requiring the accepted run to carry the fact of the reduction; the record is asserted to survive promotion onto the ledger row, because the reader who needs it most is the one auditing the landed work rather than the one watching the dispatch; and a node accepted on its first attempt is asserted to carry no such marker, so its presence means something.

§6 — What this plan does not do

It does not change the window, the lane, or what a node is allowed to edit. It does not relax the context-fit refusal: a node that genuinely cannot fit its lane must still be refused before a worktree exists, which is the behaviour that replaced nodes dying mid-run. It does not attempt to estimate more accurately in general — the token estimator's ceil(utf8-bytes/3.5) is unchanged, and improving it is a different subject with a different measure.

It also does not address the related refusal a coordinator meets one tier down, where a file is too large to be a declared write path at all on a bounded-window lane. That is the first row of the table above and it has no lever at all; naming it here so the next reader knows it was seen and deliberately left out rather than missed.

§7 — A fence that refuses what the mandate requires

The same shape as the sections above, arriving through the write fence rather than the context estimate, and raised by the lead directly. _grant_landing_write_paths gives every dispatched node two shared repository paths — the cumulative evidence record and the plan file — on the correct reasoning that every node appends a landing record and an evidence anchor, so those belong to all of them rather than to any one.

docs/figures/<plan>/ is not in that set, and the standing graphics mandate requires a landing record to be illustrated where a figure aids understanding. So a node that illustrates its record writes outside its fence, and a node that respects its fence under-communicates. There is no third option and the node cannot create one, because write scope is granted at dispatch and the worker only discovers the conflict once it has something to draw.

Measured 2026-09-21: two of two doc-producing nodes in one wave wrote a figure outside their declared paths, and both independent reviews recorded it as a scope violation. One of them put it exactly: the graphics instruction did not transfer write scope. The coordinator first recorded this as its own scoping error and the lead corrected that reading — a rule every node must break is a defect in the rule.

The objection to answer, because a sibling rule pulls the other way. reckon-create states that a figure topic directory is claimed by exactly one node and that a second node declaring it is a scope conflict, since two nodes producing one filename cannot be merged. That is true of a filename and not of a directory — and it is equally true of the cumulative evidence record, which is already shared by every node on a plan. The narrow hazard is a filename collision; refusing the whole directory to prevent it is the same trade this plan objects to elsewhere.

Done when a node dispatched against any plan receives docs/figures/<plan>/ in its granted write paths without asking for it, asserted from a dispatch payload rather than from the prompt text; the grant is asserted to be the directory and not a file inside it, so a node writing two figures needs no second claim; two concurrent nodes on one plan are asserted NOT to conflict on that directory, matching how the evidence record already behaves, while two nodes declaring the same figure FILENAME are asserted to conflict, since that is the case with no correct resolution at integration; and a node on a plan whose figures directory does not yet exist is asserted to receive the grant anyway, because the first illustrated node is exactly the one that would otherwise be refused.

§ Followups

Name the dominant term first — it is most of the value for one line of payload

Section 2 comes first and is nearly free: the per-file breakdown is already computed and already present in the dry-run payload, and only the total is reported. It converts a guessing game into a decision without changing what the estimator charges. Section 3 is the behaviour change and needs its decision settled on what a mention costs. Section 4 follows section 3, since an opt-out is only meaningful once a mention is cheap enough that the opt-out is about certainty rather than about cost. Section 5 is independent of all three and could run in the same wave as section 2. Note that the estimator lives in reckon/crew/routing.py, which was unclaimed when this plan was written, while reckon/crew/dispatch.py was held — check both before scoping.
