§1 — Why: two writers acted on state that was not theirs

A hold transition left every run record rewritten and uncommitted. nova-39 reported on 7 November that nova's checkout held 356 modified run records, all written at 02:11:02 local. Each had the same change: the retired follow_on_paths key renamed to outside_scope_paths. They were written 1 min 44 s before nova commit a03fe0706, “chore(holds): close hold-codex-20261107011059”. record_hold_checks (reckon/ledger.py near line 3440) calls write (near line 2007). That brings every per-run file into line with its aggregate row, through normalize_outside_scope_paths (reckon/run_record.py near line 33), but _commit_state_write (near line 2438) is then given only the aggregate's path. The function's own comment says the run rows stay byte-identical across a hold transition; they do not when a row still carries the retired key. Reckon's own checkout had carried 1,319 such rewrites since hold close 916bd85724 on 24 October. Both were committed by hand as their own change, nova's at 274e2b00c and reckon's at ca3029c385, after each file was checked to differ from its committed JSON by that rename alone. Any commit made without a pathspec would otherwise have swept them in.

A session host followed a session it did not own. nova-39 reported the same day that its session host (record session-hosts/457425-270383021.json, owner 457774) held three follower children. One was for nova-8a's session 35a66cc6-f4f1-4358-8dbb-99c9333c7249 (pid 1042564, started 08:10:21Z), 5 s after nova-8a's own follower (pid 4035663) exited “settled”. nova-8a's host (2339302-329925366.json) held none. Two consequences followed:

  • nova-39's UserPromptSubmit and Stop hooks showed and blocked on 35a66cc6's obligations, including promoting nova-8a's run, which a coordinator acting on them would have landed for another session.
  • nova-8a's re-arm through _ask_session_host_for_follower (reckon/crew/dispatch_watch.py near line 770) returned True with nothing spawned. Its test is watch_state(...)["session_attached"], which any follower satisfies. Meanwhile the misplaced follower held the session's single-follower lock.

The pair then stayed with the wrong host. When nova-39 stopped 1042564, its host started a replacement, pid 1076196, within a minute, because supervise (reckon/crew/session_host.py near line 625) restarts any child that exits other than settled. nova-8a's own host, pid 2339833, alive and reading the same FIFO inode its record names, still listed no child after _rearm_session_follower, which returned False. The live follower held the session's lock throughout.

The host a request reaches is chosen from the caller's CLAUDE_PID (_session_host_owner, near line 583), while the request names a session. So a crew call made under one session's Claude process that names another's session asks the wrong host. _rearm_session_follower (near line 786) already refuses that case; the ask does not.

§2 — A hold transition commits every run file it rewrote

Deliverable. write in reckon/ledger.py reports the per-run files it changed beside its new version. record_hold_checks passes those paths, with the aggregate's, to _commit_state_write, so a hold transition leaves no run record rewritten and uncommitted. Every other caller of write is unchanged except where it already commits; those callers stage the same reported paths. The docstring claim that run rows stay byte-identical is corrected to what the code does.

Done when a new tests/test_a_hold_commits_what_it_rewrote.py shows two things in a temporary git repository holding a ledger and one per-run record that still carries follow_on_paths:

  • Opening a hold through record_hold_checks leaves git status --porcelain over the state directory empty, and the hold commit contains the rewritten run record.
  • A hold check that changes no hold writes and commits nothing.

One negative control: passing only the aggregate's path to _commit_state_write leaves the run record modified in the first case. The test files importing reckon.ledger add no failure against the base revision, run one arm at a time with at most -n 4. Ruff adds no findings on the staged paths. Every log is under the run directory, starts with its revision and the literal command, and ends in EXIT=. Write paths: reckon/ledger.py and the new test.

§3 — A host is asked to follow only its own session

Deliverable. The worker first reproduces, in a temporary crew home, how a follow request for one session reaches another session's host. It records the path it finds in the run directory: a review the reflex dispatches for another session's run, a resume, or another. Then _ask_session_host (reckon/crew/dispatch_watch.py), which _ask_session_host_for_follower and _rearm_session_follower both use, asks no host when the session it names is not _calling_session(). It returns False with the same reason _rearm_session_follower gives today, so no caller can route another session's follower to its own host. _ask_session_host_for_follower tests _session_host_child_pid (near line 695), the calling host's own census, instead of the session-wide attachment, so a re-arm reports True only when its own host runs the child. A host also stops restarting a child for a pair whose session another live host's census already serves; it settles that child instead. The owner's host can then take the pair once the misplaced child ends.

Done when a new tests/test_a_host_follows_only_its_own_session.py shows four things, with a stubbed host FIFO and census:

  • An ask naming a session other than the calling one writes no request and returns False with the ownership reason.
  • An ask naming the calling session writes one request.
  • An ask for the calling session while another host's follower is attached, and the calling host's census has no child, returns False.
  • A host whose child for a pair exits while another host's census serves that pair's session settles the child and does not restart it.

Four negative controls: dropping the ownership check writes the first case's request; restarting every non-settled child restarts the fourth case's; testing the session-wide attachment returns True in the third case; and the reproduction's path, restored with the check removed, routes the request to the other host. The test files importing reckon.crew.dispatch_watch add no failure against the base revision, run one arm at a time with at most -n 4. Ruff adds no findings on the staged paths. Every log is under the run directory, starts with its revision and the literal command, and ends in EXIT=. Write paths: reckon/crew/dispatch_watch.py, reckon/crew/session_host.py and the new test.

§4 — The obligations hooks report only their own session

Deliverable. reckon/hooks/coordinator_obligations.py resolves the session it reports from the hook payload's own harness session (session_id, read near line 867), through _session_from_followers (near line 865). It never takes a follower child the host holds for another session as its own. When the host holds children for several sessions, the hook reports only the obligations of the session matching its harness session, and names any other session's child it saw as not its own.

Done when a new tests/test_the_obligations_hook_reads_its_own_session.py shows two things with a temporary crew home whose host record lists children for sessions A and B:

  • The hook run with harness session A reports A's obligations and none of B's.
  • The Stop hook in A does not block on an obligation that only B owes.

One negative control: resolving the session from the host's first follower child makes the first case report B's obligations.
