§1 — The pane, and what it was actually showing

One line per transition, about eight lines visible, read down a column rather than across: which worker, what state, how many still running. That contract is already implemented and tested. What reached the reader was not it. A fleet session followed on 2026-09-03 rendered every line monochrome, truncated the model to claude-sonnet-5/m…, left the counters floating short of the right edge, and printed a worker's request for help as a single character: 

09:47:11  test-role-declares-its-write-scope    dispatched → blocked     claude-sonnet-5/m…  |                     5 working ·  1 blocked ·  0 unpromoted

Three separate defects, measured this session, none of them in the grid the tests cover:

  1. The palette never leaves the process. click.echo strips every SGR escape when its stream is not a terminal, and both ticker emit sites call it without color=True. The hues chosen by contrast measurement are computed, formatted into the line, and deleted on the way out. Nothing errors, so nothing reports it — the pane simply looks like a renderer that was never written.
  2. The reason renders a YAML artefact instead of the question. The stored event carries "reason": "|" verbatim. A blocked run's reason is derived from the manifest's blockers: line, and the manifest parser takes a line value, so a worker writing a block scalar hands the grid the scalar indicator. An earlier event in the same stream shows the other half of the same fault: "\"scope authority for tests/test_backends.py is required — a leaked opening quote. Meanwhile the worker's actual NEEDS-HELP: headline was already parsed, and unused.
  3. The width was guessed because the conventional probe fails. COLUMNS is unset, stdout.isatty() is false and shutil.get_terminal_size() returns its 80-column fallback, so the renderer defaults to a stated 180 in a pane that is neither 80 nor 180 wide.

The first and second are the expensive kind: both report success while failing. A line that says | where a question should be is worse than a blank, because it looks like the display working.

§2 — Colour survives the emit path

The grid decides whether to paint; the emit path must not second-guess it. Passing color=True at both call sites is safe precisely because it does not force colour on — it only stops click deleting what is already there. When --no-color or NO_COLOR is in force the ticker emits no escapes, so there is nothing to keep.

Done when a line rendered by a painting grid still carries its \x1b[38;5; sequences after passing through the follow emit path into a non-terminal stream, asserted by a test that fails against the current code; and the same holds for the watch command's emit site. This section is two lines of production change and is sequenced first because a peer session needs the same file for its next wave.

§3 — The reason says what the worker asked

A blocked transition explains itself from the best source available, in order: the parsed NEEDS-HELP: headline when the report is complete, then the manifest's blockers, then the classifier's own detail. The headline is the sentence a coordinator can answer in one turn, which is the whole purpose of the escape hatch, and it is already parsed.

The manifest parser is fixed alongside it: a key whose value is a block scalar indicator or an opening quote has no value on that line, and the indented body below it is the value. Returning the indicator is how a parse failure became a display that lied.

Two markers distinguish what the reader must do, painted in the blocked hue: ? for a request a reckon crew resume --advice can answer, ! for a blocker that has to be read at the manifest. The distinction is already computed — a needs-help report is complete only when all four fields and a headline are present — and today it is discarded.

Done when a manifest carrying a block-scalar blockers: and a complete NEEDS-HELP: report produces a transition whose reason is the headline's first clause and whose marker is ?; a manifest with blockers and no needs-help report produces ! and the blocker text; and no reason anywhere can be a bare punctuation character. This section touches the same module a concurrent session is rewriting, so it lands after that wave merges, not beside it.

§4 — The line carries the worker's role

A reader judging whether a stall is the model or the work needs to know what kind of work it was, and had to leave the pane to find out. The role is already on the run pointer. It goes in a fixed column to the left of the node, in the dispatch vocabulary verbatim — implement, cleanup, review, investigate, test — so that no glossary exists to fall out of date. documentation alone is displayed as docs, because at thirteen characters it would set the column width for all six and nobody misreads it; that is the substitution the display map already makes for completed_unpromoted.

The role is rendered dim rather than hued. Colour here answers exactly two questions — which worker is this and does this need me — and a third colour axis would make the first two harder to read.

Done when every role in the configured vocabulary renders whole in its column, an unknown role renders a marker rather than a truncated word, and the column budget test still finds every field on the same screen column on every row.

§5 — Aliases live in configuration, not in code

claude-sonnet-5/medium spends eighteen columns to say what sonnet5·me says in ten, and today it is elided to claude-sonnet-5/m…, which hides the effort — the half a reader actually compares. But the shortening cannot be a table in the renderer. The flight schema states the rule it would break: no concrete model identifier, provider name or relative hierarchy is baked into reckon or its generated artifacts, and effort is deliberately an open string with no enumeration. A regex table matching vendor prefixes inside the ticker would hardcode three vendors into a repo-agnostic tool and would render nothing at all for a model nobody has configured yet.

So the spelling belongs beside the model id it shortens, in the operator's own flight configuration, and is stamped into the run pointer at dispatch — because the agent label is read from what was persisted when the run started, so that a later configuration edit cannot silently restate what ran. Code keeps only a mechanical fallback for an unaliased backend.

The effort suffix is derived rather than tabulated: the first two characters, lowercased. That is collision-free across the whole real ladder — lo, me, hi, xh, ma, mi, ex — so medium, max and minimal stay distinct, and an effort word invented next month still renders.

§6 — Width is measured, not stated

The conventional probes fail in this pane, and the note this project was carrying drew the wrong conclusion from that: therefore width must be a flag. It does not follow. The follower's own stdout is a pipe, but the follower has ancestry, and the harness process at the top of it owns a terminal. Walking /proc/<pid>/stat to the first ancestor with a controlling tty and reading that tty's window size answered it on the first attempt. Measured across all eight live followers on this machine: each resolves to its own session's pseudo-terminal, and each reports 45 × 208.

Two cautions bound the mechanism. The value read is the terminal, not the inner text width of the harness box drawn inside it, so a calibrated inset is subtracted and the bias is conservative: under-filling by a column leaves a harmless gap, over-filling loses the counters off the right edge. And a stale read would produce a wrong width rather than no width, which is the failure class this whole plan is about — so the claim that it follows a resize is verified against a resized pane before it is relied on, not assumed from the fact that the kernel maintains the field. Where no ancestor terminal exists — a detached or nohup'd follower — the stated --width is the fallback, and it remains the override everywhere.

Width earned this way is spent in priority order, so that one grid serves every pane size without a field ever changing screen column between rows: the node column to 24, then a clause to 12, then the node to 44, then the clause to its bounded maximum. Whatever remains is padding in front of the counters, which stay flush right. Below the floor the width is raised rather than wrapped, because a wrapped row costs a quarter of the visible history.

§7 — What this plan inherits, and what it leaves alone

This plan is about the pane's format. Its truth obligations are not restated here: they are owned by crew-observability-truth §4, whose standing rules — a wrong answer is worse than no answer, activity is generation rather than bytes — govern every section above. The colour and reason defects are truth defects and would fit on that plan; they live here because splitting one renderer's work across two plans to honour the boundary costs more than it buys, and because that plan is being shipped concurrently from another session and took twenty versions in a day.

The dependency runs the other way for §3 in particular: that plan's spend-limit work makes a provider refusal classify as blocked, and a refusal whose reason renders as | is still untriageable. This plan's §3 is what makes that classification readable.

Two things are deliberately out of scope. A live-redrawn dashboard — a sortable table of the fleet with per-worker rows — cannot render in this pane at all, which is append-only captured output where a repainting region would garble; it is a separate surface for a real terminal and gets its own plan. And the fleet counters' own definition, which states which run states are working, blocked or unpromoted, belongs to the concurrent session's live wave; this plan prints those numbers and does not redefine them.

§ Decisions

Where does the role sit, and how is it spelled?

A four-character tag was tried first and failed on its own reading: invs did not communicate investigate .

Spend the columns on words a reader does not have to decode. The badge goes left because the eye should land on the node as the primary identifier and because it keeps the node adjacent to the transition arrow it belongs to.

How is the effort rendered beside the model alias?

A single letter collapses medium , max and minimal into one glyph. A lookup table would enumerate a ladder the schema deliberately leaves open.

Derivation is collision-free across the real ladder and needs no table, so a configured effort nobody has used yet still renders.

How is the render width resolved?

The measurement exists and follows a resize; a stated width does not. The override stays because a detached follower has no ancestor terminal to read, and because a stale read must have a manual remedy.

Should the ticker be rebuilt on a rendering library?

Rich was the candidate. Its width detection returns 80 in a pipe and its colour detection switches off in a pipe, so it needs the same forced width and forced colour this plan establishes — it consumes the solution rather than providing one — and it is not currently a dependency.

The streaming pane keeps its measured palette and its zero-dependency renderer. The library earns its place on a surface that can repaint, which this pane cannot, so that becomes its own plan rather than a rewrite of this one.
