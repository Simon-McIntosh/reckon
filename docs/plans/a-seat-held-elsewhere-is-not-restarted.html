Each restart starts a Python process that imports reckon on the login node, about nine a minute, and the log grows without bound. This is the kind of background process the user-wide rules hold to be a defect. The-review-loop-runs-without-hand-steps §5, "A producer seated on another node reads as live", is marked done, but the hook on this host still reports no producer. Either the hook takes a branch §5 did not cover, or the snapshot it reads is missing for these sessions, which matches the directory above.

§2 — A producer finding a foreign seat waits instead of exiting

Deliverable. When reckon crew watch finds the project's seat held by a live producer on another host, it stays up and re-reads the seat at a bounded interval, taking the seat when that producer's stream goes stale, instead of exiting into the unit's restart. The foreign-seat judgement reuses _seat_names_a_foreign_host and _seat_stream_fresh in reckon/crew/watch_unit.py. --ensure reports a unit whose restart count rises between two readings as cycling, not healthy, with both readings. The unit's restart policy stays as it is, because a crash should still restart it.

Done when a test gives the watch a seat naming another host with a fresh stream and finds the process still running after three re-read intervals, having written no restart; with the stream made stale it takes the seat. An --ensure test with a unit whose restart count rose between readings reports it cycling. The watch and unit test files show no added failure against base. Negative control: with the wait removed, the first test must see the process exit 0.
