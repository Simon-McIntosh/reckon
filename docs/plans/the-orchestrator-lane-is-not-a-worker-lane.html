The Orchestrator Lane Is Not A Worker Lane

One subscription runs every orchestrator on this workstation. Background work dispatched to the same lane spends the capacity the orchestrators need, and when it saturates nothing stops partially — every session stops, including the ones that would have noticed. That is the difference between this fence and an ordinary routing preference: the failure is not a slow node, it is the loss of the layer that dispatches, merges, promotes and records. Work already in flight is then unreachable by the only processes that could reconcile it.

It is already happening and for a defensible reason. The locally served lane died mid-turn nine times in one day at high effort, so sessions moved their reviews to the orchestrator lane to keep the review reflex working. That was a reasonable field decision under a broken alternative, and it is exactly why an instruction is the wrong instrument. A rule an agent must remember is not a rule when the alternative is failing in front of it. The remedy is a refusal at the dispatch boundary, paired with repairing the lane that drove them there — neither half works alone.

§1 — The dispatch refuses, and names what to do instead

Measure. A crew dispatch whose resolved backend is an orchestrator lane is refused before anything is written, and the refusal names the lane, states that it carries this workstation's orchestrators, and names a discharge — the lane to use instead, or the explicit override and what it costs. A refusal with no way through is a stop, and this plan's sibling already counts 42 refusal sites against 5 discharges; this one arrives with its discharge.

Which lanes, declared rather than pattern-matched. The orchestrator role is a property of the deployment, not of a backend's name — matching on the string claude would break the moment an orchestrator runs elsewhere, and would miss an alias. A backend declares that it serves orchestrators, the fence reads the declaration, and a lane that declares nothing is dispatchable as now.

Falsifier. Dispatch a background node to a lane declaring the orchestrator role and require the refusal; dispatch the same node to a lane that does not and require it to launch. Then remove the declaration and require the refusal to stop firing — a fence that refuses regardless of the declaration is not reading it.

§2 — The override is explicit, recorded, and rare

Measure. A deliberate dispatch to an orchestrator lane requires a flag whose reason is recorded on the run and reaches the ledger row, so the cost is attributable afterwards rather than inferred from a spend curve. The default is refusal; the override is not a preference and does not persist across runs.

Why an override exists at all. A fence with no exception invites the exception to be taken by editing config, which is invisible. One recorded override is cheaper to audit than a silent configuration change, and it keeps the fence honest about being a policy rather than a physical impossibility.

§3 — The rule reaches the surfaces an agent actually reads

Measure. The prohibition is stated where dispatch decisions are made rather than only in a plan: the crew dispatch help and its refusal text, the ship and sprint skills where a coordinator chooses a lane, and the tool descriptions an agent reads before calling. Each states the same fact in the same terms — this lane runs the orchestrators, background work here costs orchestrator capacity, and a saturated orchestrator lane stops every session rather than one node.

Falsifier. Read each surface and require the rule and its reason to be present. A surface carrying the prohibition without the reason fails: an agent that knows only the rule will route around it the next time the alternative is failing, which is precisely what happened.

§4 — The lane they were escaping is fixed, or the fence is a cage

This section is a dependency, not a courtesy. Closing the escape hatch while the locally served lane still dies nine times a day converts a degraded review loop into no review loop. The fence and the repair land together or the fence waits.

Measure. The local-lane death rate at the effort the review reflex uses is measured before and after the repair carried by the review-reliability work, and the fence is enabled by default only once the after-rate is stated. Until then it warns and records rather than refusing, which still removes the silent case without stopping the reviews.
