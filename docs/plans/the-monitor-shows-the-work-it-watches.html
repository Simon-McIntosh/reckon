§1 — Why: the pane is empty while work runs, and it never ends

The imas-codex coordinator session 6fe78f81 relayed this on 2026-10-12, at the lead's request. At 04:47Z on 98dci4-clu-2002 that session dispatched one review run, r-20261012T044739534705-review-portfolio-4dde24777e04. The host wiring was correct: crew host pid 2116694 started follower pid 2162620, and both write to the pane. The watch stream held the run's baseline row (04:47:43Z) and its dispatched → running row (04:47:56Z). After more than 12 minutes the lead's Monitor pane still read "Status: running · No output available".

The cause is the row policy shipped by a-follower-row-is-worth-a-wake (commits 089cd7741, 79d3a5458, contract 778219ba2). It delivers only a row that asks the coordinator for action, or news nobody caused, and never a start. So a session with work in flight shows nothing. The host also never exits on its own, because Claude Code would not restart it (reckon/crew/session_host.py, module docstring). So the pane stays "running" after the work has ended.

The lead's requirements, in their words: "it should not be overly verbose, but also not empty"; "I should be able to see all work active"; "the monitor should auto stop when there is no live work"; and "the monitor is for me too, I want to see what is going on". The pane has two readers, the coordinator and the lead. The policy that is right for waking the coordinator is not enough for the person watching.

§2 — A run's start is one row on its own session's pane

Deliverable. The row policy in reckon/crew/ticker.py delivers one row when a run that the pane's own session dispatched starts working. The row names the run id, node, lane and model, and time budget. It revises the start-row rule of a-follower-row-is-worth-a-wake for the session's own runs only. A peer session's start, a bare re-announcement, an echo and a replay are still held, so nothing is added to a pane for work that is not its own.

Done when a new test file, tests/test_a_pane_shows_its_own_starts.py, passes:

  • A follower for session S receives exactly one start row for S's run as it moves from dispatched to working, carrying the four fields.
  • A peer session's start delivers nothing.
  • A re-announcement or replay of the same start delivers nothing.

The existing tests that encode the never-a-start rule are updated to the new rule, never deleted, each named in the manifest. The test files that import ticker pass. The negative control, which holds own starts back again, fails the first case. It is logged under the run directory.

Write paths: reckon/crew/ticker.py, tests/test_a_pane_shows_its_own_starts.py, plus the existing test files whose start-row assertion changes, each named at dispatch.

§3 — Every delivered row carries the session's live roll-up

Deliverable. Each row the pane delivers ends with a compact roll-up of the session's live runs: a count, and the node of each, in the ticker's existing abbreviated form. So "all work active" is visible on the latest line without the full stream. The roll-up reads the same live classification that crew(view="live") uses, and computes nothing of its own. It adds no row: a pane with no deliverable change stays quiet.

Done when tests/test_a_pane_row_carries_the_live_rollup.py passes:

  • With three live runs in session S and one in a peer session, S's delivered row reports three, names their nodes, and omits the peer's run.
  • When the last live run settles, its row reports none live.
  • The roll-up matches crew(view="live", session=S) for the same fixture.

The test files that import ticker pass. The negative control, which counts every session's runs, fails the first case. It is logged under the run directory.

Write paths: reckon/crew/ticker.py, tests/test_a_pane_row_carries_the_live_rollup.py. This section runs after §2, since both write ticker.py.

§4 — The pane ends when no work is live

Deliverable. When the session has no live run, the pane says so in one closing line and stops. The design is deferred to the lead's decision below. The session host exists so that a session does not spend a turn re-arming a follower, and Claude Code does not restart a plugin monitor that exits.

Done when the decision is locked and a test drives the chosen design:

  • The last live run settles and the closing line is delivered once.
  • The pane process ends, or its child does, as decided.
  • A later dispatch in the same session brings the pane back, by the decided route, with no row lost between.

Decision: how the pane ends.

  • Host exits. The host writes a closing "no live work" line and exits, so Claude Code shows the monitor as stopped. The next dispatch re-arms the monitor, which costs the session one turn per idle-to-busy transition.
  • Child settles. The follower child ends on a settled summary line, and the host stays and starts a new child when the session next dispatches. No turn is spent, but Claude Code still shows the monitor as running.

Write paths: fixed when the decision is locked; expected reckon/crew/session_host.py and its tests.
