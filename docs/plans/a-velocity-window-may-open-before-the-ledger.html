§1 — A revision without the ledger reads as one with no runs

At main 3e4736687, reckon crew velocity --project reckon --since 2026-08-01 exits 1. The error is CalledProcessError from git show 69fb3c1e5…:docs/state/reckon/crew.json, raised inside recover_ledger_clocks at reckon/velocity.py:1191. The window's base commit is 69fb3c1e5, from 2026-07-30. docs/state/reckon/crew.json was first committed in af650745d on 2026-08-12, so the base has no such file. recover_ledger_clocks reads the ledger at the base only to learn which runs already existed. When the path is absent, the whole view aborts, although the true answer is that no runs existed.

The read at the head has the same defect. _read_ledger at reckon/velocity.py:708 looks up the blob with _blob_sha, which returns None for an absent path. It then calls git show unconditionally at line 719. So a window whose head predates 2026-08-12 fails in the same way. Every window will fail once the-ledger-is-one-file-per-run §4 deletes crew.json, because no head will have it from then on. That is why this plan blocks that section. _read_run_rows already copes with an absent runs/ directory, because git ls-tree prints nothing for one.

Remedy. Change both read sites so that a revision whose tree has no crew.json reads as a ledger with no runs:

  • recover_ledger_clocks treats every candidate run as absent at the base.
  • _read_ledger returns no records. _read_run_rows still supplies the per-run files.
  • For an absent ledger, the digest the snapshot reports is null, not the digest of an empty document. A reader can then tell a revision with no ledger from one whose ledger is empty.

Decide absence from the tree, using the existing _blob_sha helper. Do not catch the failed git show. When a path does exist and its read fails, that failure must still raise. No new public name is added.

Write paths: reckon/velocity.py and tests/test_velocity_reads_a_revision_without_the_ledger.py, which is new.

Done when all four of these hold:

  1. The new test builds a temporary git repository. Its first commits have no docs/state/<project>/crew.json, and later commits add one with run rows. The test asserts three cases:
    • a window whose base predates the ledger reports the window's runs and does not raise;
    • a window whose head predates the ledger reports zero runs with a null ledger digest and does not raise;
    • a monkeypatched git that fails the show of a ledger that is present still raises.
    The test writes nothing outside its temporary directory. It points RECKON_VELOCITY_CACHE and RECKON_CLONE_CACHE into that directory.
  2. Pytest over the new file, tests/test_velocity_cache.py, tests/test_velocity.py, tests/test_crew_velocity_view.py and tests/test_every_module_fits_a_worker_window.py adds no failure against the base.
  3. ruff check and ruff format --check add no finding on the staged paths.
  4. After the merge, the coordinator runs reckon crew velocity --project reckon --since 2026-08-01 at the merged head and it exits 0. This check is not part of the worker's gate. It reads the live repository's history, so it is an integration observation and not a test.

Negative control: restore the unconditional git show at either read site. The matching case in the new test must then fail with CalledProcessError. Removing the presence check in favour of a blanket except must instead fail the third case.
