§1 — A review run is delivered only by a record of the head it was dispatched to read

Why. On 2026-10-18 nova's coordinator measured a review run promoted with a verdict it never gave. Review run r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02 was dispatched to review r-20261018T134957600545-tcv-liuqe-known-answer at head 0a451acfdb02d4b05a5d8f77c7a711943f0d4cce. Its worker wrote a complete manifest claiming both records stored, then exited before running the step that writes them. The reviewed run's review-records/ directory holds no .at-0a451acf… record. Its unsuffixed r-20261018T134957600545-tcv-liuqe-known-answer.json is a copy of the round at fbc3788e, written at 20:30:37 local by an earlier review. At 21:45 the watcher promoted the run anyway, in nova commit e99d2b385 with promoted_by: review-self. The ledger row docs/state/nova/runs/r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02.json records review.reviewed_head_sha fbc3788e… and review.total 91, another round's head and score. The review's own verdict was 96 at 0a451acf and is unwritten.

The cause, as read from the code on 2026-10-18. _delivered_review_record (reckon/crew/recovery_review_delivery.py:236) returns the first path among the review's write paths whose record parses complete (_read_complete_review, line 222). It never asks which head the record read, which review run wrote it, or whether it was written after this review was dispatched. The legacy unsuffixed path is one of those write paths, and any earlier round leaves a complete record there. When no write path parses, the fallback reads the store by the reviewed run (lines 251 to 261): the legacy path first, then every .at-* record of any head. That one predicate decides delivery for every reader: the watcher's self-promotion (promote_review_run_itself, reckon/crew/recovery_review_acceptance.py:314), promotion's review checks (reckon/crew/promotion_checks.py:1152), the round a promoting review commits (promotion_checks.py:2327, which files it under the promoting run's id), and review_delivered (recovery_review_delivery.py:265).

The dispatched head is on the review run. The bad row's node_definition.write_paths declares the head-keyed path …/review-records/r-20261018T134957600545-tcv-liuqe-known-answer.at-0a451acfdb02d4b05a5d8f77c7a711943f0d4cce.json beside the legacy one, and _review_subject (reckon/crew/recovery_review_dispatch.py:153) already reads a head from such a path. The predicate never compares a record against it.

Deliverable.

  • The dispatched head is the declared head-keyed path. The head a review was dispatched to read is the head of the .at- write path it declares, as _review_subject reads it. A run review that declares no head-keyed path is reported, not promoted, by the watcher, and its refusal names the missing head.
  • Delivery names that head. _delivered_review_record accepts a record as this run's delivery only when all four hold: it sits at the head-keyed path for the dispatched head; its reviewed_head_sha equals that head; its review_run_id, when present, names this review run; and its modification time is after this review's dispatch. The legacy path and the any-head .at-* glob no longer count as a delivery. The change is made in that one function, so every reader above inherits it, and no reader gains a check of its own.

Plan reviews are unchanged: their record is a report keyed by the plan's blob, not a run's head. Earlier rounds keep being committed as the subject's rounds, as _delivered_review_payloads_for_commit does today. Only the round filed under the promoting run's id must be the round that run delivered.

The guard fails closed, so measure first what currently passes only because it fails open. Run the gate tests below with the change and list in the manifest every test that relied on the legacy path counting as a delivery. Change such a test only where it encoded this defect, and give the reason for each.

Write paths. reckon/crew/recovery_review_delivery.py, reckon/crew/recovery_review_dispatch.py, reckon/crew/recovery_review_acceptance.py, and tests/test_a_review_promotes_only_its_own_verdict.py, which is new.

Negative control. At the base revision, the new test's predecessor-round case, its three mismatch cases and its no-head case fail, because the base accepts the predecessor's record as delivered.

Done when all five of these hold:

  • A test builds a reviewed run's review-records/ directory under a temporary directory. The legacy path holds a complete round at head H0, and a review run is recorded as dispatched to read head H1. _delivered_review_record returns None, and promote_review_run_itself returns promoted false with a reason naming the missing H1 record. Once a complete H1 record is written at the H1 path after the dispatch time, the same calls report it delivered, and the promotion's ledger row carries H1 and that record's total.
  • Three mismatches are each refused: a record at the H1 path whose reviewed_head_sha is H0; one whose review_run_id names another review run; and one whose modification time precedes the review's dispatch.
  • A review run that declares only the legacy write path, beside a complete record there, is refused by promote_review_run_itself with a reason naming the missing head.
  • The negative control is shown: the new test file, run at the base revision with the same command, reports the predecessor-round case, the three mismatch cases and the no-head case as FAILED by id, in a log under the run directory.
  • PYTHONPATH=$PWD .venv/bin/python -m pytest -p no:cacheprovider -q -rA over the new test file, tests/test_a_review_run_promotes_itself.py, tests/test_a_delivered_review_ends_its_turn.py and tests/test_a_run_review_cannot_remove_a_siblings_record.py adds no failure against the base, beyond the tests the manifest names as encoding the defect. ruff check and ruff format --check report no new finding on the changed files.

§2 — Count the promoted review rows that carry another round's verdict

Why. The predicate §1 fixes has decided delivery for every review run, so e99d2b385 may not be the only row whose review fields describe another round. A row like that feeds a wrong score to every reader of review totals, including the picker's per-dimension medians. Before deciding how such rows are corrected, count them.

Deliverable. A read-only census that writes docs/research/review-rows-with-another-rounds-verdict.html and the script that computes it, scripts/review_rows_with_another_rounds_verdict.py. It reads the committed ledgers of every mounted project. For each promoted run review, it takes the dispatched head from the strongest source the row carries: a declared .at- write path, then the hex suffix of the node id. It compares that head with the row's review.reviewed_head_sha. A row whose recorded head does not begin with the dispatched head is listed by run id, with both heads, the recorded total, its promoted_by, and the project's commit that landed it. A row with no dispatched head from any source is counted as unclassifiable and listed separately.

It changes no product code.

Write paths. docs/research/review-rows-with-another-rounds-verdict.html and scripts/review_rows_with_another_rounds_verdict.py, both new.

Done when all three of these hold:

  • The document gives, per project, the count of promoted run reviews, of mismatched rows and of unclassifiable rows. It lists every mismatched and unclassifiable row by id, with every figure read from the ledgers at a stated revision and time.
  • The census is shown to see a known positive: it lists nova's r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02 as mismatched, with dispatched head 0a451acfdb02 and recorded head fbc3788e….
  • The document names the script and the command that produced every figure, and no file outside the write paths changes.

§3 — A misattributed review row is corrected by an appended correction every reader honours

Why. A committed ledger row records what a promotion believed when it landed. A row whose review fields describe another round should not be rewritten in place, because the record of what was believed is itself evidence. It should carry an appended correction stating the fields' true status, and every reader of review totals should read the correction rather than the stale fields. Until this section lands, e99d2b385's row stays as it is: nova does not hand-edit it, and reckon applies the correction here once the mechanism exists.

It is deferred until §2 has counted the rows, because a handful of rows and hundreds call for different mechanisms. The done-when, write paths and negative control are written once §2 lands, and the section is then reviewed before it is built.
