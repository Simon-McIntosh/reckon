§1 — A review run is delivered only by a record of the head it was dispatched to read

Why. On 2026-10-18 nova's coordinator measured a review run promoted with a verdict it never gave. Review run r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02 was dispatched to review r-20261018T134957600545-tcv-liuqe-known-answer at head 0a451acfdb02d4b05a5d8f77c7a711943f0d4cce. Its worker wrote a complete manifest claiming both records stored, then exited before running the step that writes them. The reviewed run's review-records/ directory holds no .at-0a451acf… record. Its unsuffixed r-20261018T134957600545-tcv-liuqe-known-answer.json is a copy of the round at fbc3788e, written at 20:30:37 local by an earlier review. At 21:45 the watcher promoted the run anyway, in nova commit e99d2b385 with promoted_by: review-self. The ledger row docs/state/nova/runs/r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02.json records review.reviewed_head_sha fbc3788e… and review.total 91, another round's head and score. The review's own verdict was 96 at 0a451acf and is unwritten.

The cause, as read from the code on 2026-10-18. _delivered_review_record (reckon/crew/recovery_review_delivery.py:236) returns the first path among the review's write paths whose record parses complete (_read_complete_review, line 222). It never asks which head the record read, which review run wrote it, or whether it was written after this review was dispatched. The legacy unsuffixed path is one of those write paths, and any earlier round leaves a complete record there. When no write path parses, the fallback reads the store by the reviewed run (lines 251 to 261): the legacy path first, then every .at-* record of any head. That one predicate decides delivery for every reader: the watcher's self-promotion (promote_review_run_itself, reckon/crew/recovery_review_acceptance.py:314), promotion's review checks (reckon/crew/promotion_checks.py:1152), the round a promoting review commits (promotion_checks.py:2327, which files it under the promoting run's id), and review_delivered (recovery_review_delivery.py:265).

The dispatched head is on the review run. The bad row's node_definition.write_paths declares the head-keyed path …/review-records/r-20261018T134957600545-tcv-liuqe-known-answer.at-0a451acfdb02d4b05a5d8f77c7a711943f0d4cce.json beside the legacy one, and _review_subject (reckon/crew/recovery_review_dispatch.py:153) already reads a head from such a path. The predicate never compares a record against it.

Deliverable.

  • The dispatched head is the declared head-keyed path. The head a review was dispatched to read is the head of the .at- write path it declares, as _review_subject reads it. A run review that declares no head-keyed path is reported, not promoted, by the watcher, and its refusal names the missing head.
  • Delivery names that head. _delivered_review_record accepts a record as this run's delivery only when all four hold: it sits at the head-keyed path for the dispatched head; the head it describes is that head, compared with the owners the promotion gate and the classifier already share, review_described_head and same_revision (reckon/crew/recovery_review_subject.py:80 and :102, as select_review_for_head at line 111 uses them); its review_run_id, when present, names this review run; and its modification time is after this review's dispatch, read with run_id_dispatch_time (reckon/crew/review.py:2584) or run_record_times (line 2541) rather than a new definition of when a review was dispatched. The legacy path and the any-head .at-* glob no longer count as a delivery. The change is made in that one function, so every reader above inherits it, and no reader gains a check of its own.

Plan reviews are unchanged: their record is a report keyed by the plan's blob, not a run's head. Earlier rounds keep being committed as the subject's rounds, as _delivered_review_payloads_for_commit does today. Only the round filed under the promoting run's id must be the round that run delivered.

The guard fails closed, so measure first what currently passes only because it fails open. Run the gate tests below with the change and list in the manifest every test that relied on the legacy path counting as a delivery. Change such a test only where it encoded this defect, and give the reason for each.

Write paths. reckon/crew/recovery_review_delivery.py, reckon/crew/recovery_review_dispatch.py, reckon/crew/recovery_review_acceptance.py, tests/test_a_review_run_promotes_itself.py, tests/test_a_delivered_review_ends_its_turn.py, and tests/test_a_review_promotes_only_its_own_verdict.py, which is new. The two existing tests are in scope because each stores its record only at the legacy path and declares only that path (lines 147 and 139), which is the defect this section removes.

Negative control. At the base revision, the new test's predecessor-round case, its three mismatch cases and its no-head case fail, because the base accepts the predecessor's record as delivered.

Done when all five of these hold:

  • A test builds a reviewed run's review-records/ directory under a temporary directory. The legacy path holds a complete round at head H0, and a review run is recorded as dispatched to read head H1. _delivered_review_record returns None, and promote_review_run_itself returns promoted false with a reason naming the missing H1 record. Once a complete H1 record is written at the H1 path after the dispatch time, the same calls report it delivered, and the promotion's ledger row carries H1 and that record's total.
  • Three mismatches are each refused: a record at the H1 path whose reviewed_head_sha is H0; one whose review_run_id names another review run; and one whose modification time precedes the review's dispatch.
  • A review run that declares only the legacy write path, beside a complete record there, is refused by promote_review_run_itself with a reason naming the missing head.
  • The negative control is shown: the new test file, run at the base revision with the same command, reports the predecessor-round case, the three mismatch cases and the no-head case as FAILED by id, in a log under the run directory.
  • PYTHONPATH=$PWD .venv/bin/python -m pytest -p no:cacheprovider -q -rA over the new test file, tests/test_a_review_run_promotes_itself.py, tests/test_a_delivered_review_ends_its_turn.py and tests/test_a_run_review_cannot_remove_a_siblings_record.py adds no failure against the base. The two existing tests that stored their record only at the legacy path now store it at the head-keyed path of the head they dispatch, and the manifest names each change with its reason. ruff check and ruff format --check report no new finding on the changed files.

§2 — Count the promoted review rows that carry another round's verdict

Why. The predicate §1 fixes has decided delivery for every review run, so e99d2b385 may not be the only row whose review fields describe another round. A row like that feeds a wrong score to every reader of review totals, including the picker's per-dimension medians. Before deciding how such rows are corrected, count them.

Deliverable. A read-only census that writes docs/research/review-rows-with-another-rounds-verdict.html and the script that computes it, scripts/review_rows_with_another_rounds_verdict.py. It reads the committed ledgers of every mounted project. For each promoted run review, it takes the dispatched head from the strongest source the row carries: a declared .at- write path, then the hex suffix of the node id. It reads a head from a declared path by importing _review_record_subject (reckon/crew/recovery_review_dispatch.py:133), not by parsing the name again. The script lives under scripts/, outside the package, and defines only private helpers and its entry point, so it adds no public definition and has none to retire. It compares that head with the row's review.reviewed_head_sha. A row whose recorded head does not begin with the dispatched head is listed by run id, with both heads, the recorded total, its promoted_by, and the project's commit that landed it. A row with no dispatched head from any source is counted as unclassifiable and listed separately.

It changes no product code.

Write paths. docs/research/review-rows-with-another-rounds-verdict.html and scripts/review_rows_with_another_rounds_verdict.py, both new.

Done when all three of these hold:

  • The document gives, per project, the count of promoted run reviews, of mismatched rows and of unclassifiable rows. It lists every mismatched and unclassifiable row by id, with every figure read from the ledgers at a stated revision and time.
  • The census is shown to see a known positive: it lists nova's r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02 as mismatched, with dispatched head 0a451acfdb02 and recorded head fbc3788e…. It is also shown to pass a known negative: nova's r-20261018T172216624608-review-of-vertical-pin-45213bf1cd62, whose recorded head 45213bf1cd6216df… begins with its dispatched head, is counted as a promoted run review and not listed as mismatched.
  • The document names the script and the command that produced every figure, and no file outside the write paths changes.

§3 — A misattributed review row is corrected by an appended correction every reader honours

Why. A committed ledger row records what a promotion believed when it landed. A row whose review fields describe another round should not be rewritten in place, because the record of what was believed is itself evidence. It should carry an appended correction stating the fields' true status, and every reader of review totals should read the correction rather than the stale fields. Until this section lands, e99d2b385's row stays as it is: nova does not hand-edit it, and reckon applies the correction here once the mechanism exists.

What §2 found. At least 19 promoted run reviews across six projects carry another round's head. The figure is a lower bound, because the census read only review.reviewed_head_sha. That is a bounded set, so one append-only correction applied by a verb is proportionate, and no bulk migration is needed. This section builds the mechanism. §4 re-counts and applies it.

Deliverable.

  • One reader of a row's review. An accessor in reckon/ledger.py returns a row's review block, or nothing when the row carries a review_correction that supersedes it. Every reader of a ledger row's review block reads through it. The known readers are reckon/capabilities.py:968, reckon/ledger.py:3702, reckon/crew/picker/snapshot.py:377 and reckon/crew/picker/outcomes.py:477. The node finds any other by grep and lists each in the manifest. A corrected row then reads as a run with no review: it drops out of review totals and per-dimension medians, and it is not counted as reviewed.
  • A verb that appends the correction. reckon crew supersede-review --project <project> --run <id> --reason <text> appends a correction that supersedes a row's review. The name repair-review is already taken: that verb (reckon/crew_run_commands.py:760) repairs a review run's status or subject identity, reckon/crew/obligations.py emits it as a next command, and it stays as it is. The new verb takes the dispatched head as §2 does. It reads the row's declared .at- write path through _review_record_subject (reckon/crew/recovery_review_dispatch.py:133), and otherwise the hex head suffix of the node id. round_node_source (reckon/crew/repair.py:310) returns the source a round id carries and discards that suffix. So a reader of the suffix is added beside it in reckon/crew/repair.py, deriving it as the census's _node_head_suffix (scripts/review_rows_with_another_rounds_verdict.py:59) does: what follows the review prefix, the source and one separator, when it is the writer's digit count. The verb does not import from scripts/. It reads the recorded head through carried_revision_pair (reckon/crew/review.py) applied to the row's review block, carried_revision_pair(row["review"]), because the row keeps its head there and not at its top level. It appends review_correction with the time, the reason, both heads and the superseded field to the row's committed per-run file, and never rewrites the recorded fields. It lands that write as one commit through _commit_landing_writes. It refuses three kinds of row. The first is a row whose recorded head is the same revision as the dispatched head, compared through same_revision (reckon/crew/recovery_review_subject.py:102), which matches an abbreviated head against a full one. This is the complement of §2's rule that a row is mismatched when its recorded head does not begin with its dispatched head. The second is a row with no dispatched head. The third is a row already corrected.

Write paths. reckon/ledger.py, reckon/crew/repair.py, reckon/capabilities.py, reckon/crew/picker/snapshot.py, reckon/crew/picker/outcomes.py, reckon/cli.py, reckon/crew_run_commands.py, tests/test_crew_help_names_its_state.py, and tests/test_a_corrected_review_row_reads_as_unreviewed.py, which is new. A registration the CLI contract tests need in a file outside these paths is added with crew widen, naming the file.

Negative control. At the base revision there is no verb and no accessor. A row carrying a review_correction is still read with its stale review, so the new test's reader cases fail by id.

Done when all five of these hold:

  • A test builds a ledger under a temporary directory with a misattributed review row: a declared head H1 and a recorded head H0. supersede-review on it appends one review_correction naming H1 and H0, leaves every recorded field byte-identical, and lands one commit. After that, each reader named above reads the row as unreviewed: the picker's review counts and medians, the outcome reader's review total, and capabilities.
  • The verb refuses, writing nothing, three kinds of row: a row whose recorded head is the same revision as its dispatched head, a row with no dispatched head, and a row already corrected. The first case includes a row whose dispatched head is a 12-character prefix of its recorded head, like nova's r-20261018T172216624608-review-of-vertical-pin-45213bf1cd62, which §2 certified as correctly attributed.
  • The new verb satisfies the CLI-wide contract tests: tests/test_crew_help_names_its_state.py, and tests/test_skill_contracts.py's every-registered-verb check.
  • The negative control is shown: the new test file, run at the base revision with the same command, reports the reader cases as FAILED by id in a log under the run directory.
  • PYTHONPATH=$PWD .venv/bin/python -m pytest -p no:cacheprovider -q -rA over the new test file, the two contract test files, tests/test_ledger.py and tests/test_a_pick_sees_each_review_dimension.py adds no failure against the base. ruff check and ruff format --check report no new finding on the changed files.

§4 — Re-count across every head spelling, then correct the misattributed rows

Why. §2's 19 rows are a lower bound, and a correction is a write to every project's committed ledger. The full set is counted first, and the writes are made project by project, by the session that owns each checkout.

Deliverable, once §3 lands. The census reads the recorded head through carried_revision_pair, so a row recorded under reviewed_commit or commits_read is counted. It is re-run across every mounted project, and the document gains the full list. supersede-review is then applied to reckon's own rows. For every other project, the document lists the exact supersede-review command per row, and that project's coordinator is told to run it in its own checkout. No session writes another project's shared checkout.

The done-when, write paths and negative control are written when §3 lands, and the section is then reviewed before it is built.
