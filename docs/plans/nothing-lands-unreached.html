§2 — The reach graph is a reckon instrument, and a ratchet test keeps it honest

Deliverable. The module index in reckon/served_code.py already resolves module names and files, parses imports and follows attribute references to a closure over definitions (_ModuleIndex, line 180; _module_name, 194; _module_file, 201; _import_targets, 213; _used_definitions, 405). This section extends that owner rather than building a second import graph beside it: a reachability reader in served_code.py that, for a revision's reckon/ tree, resolves the production entry points (the console scripts in pyproject.toml and the Click verbs they mount, the MCP tool functions, the serve.py handlers, and every module launched by -m from reckon's own source) and returns the set of modules and module-level definitions reachable from them through imports and attribute references, plus a neighbourhood(paths) function returning the production modules one import away from the named paths in either direction. It reads sources with ast and never imports the package, reusing the source walk in reckon/velocity.py (read_sources), the definition enumeration of reckon/interface_counts.py (definitions, line 74) and its cache pattern. It adds two public functions, the reached set and neighbourhood; nothing retires in this section, and §3 and §4 then remove four modules and twelve helpers, so the plan's net public surface falls. The health review's script (health-reachability/reach_graph.py) is the starting point; its first version under-reported reachability and was corrected against a positive control, so the module carries that control as a test. A ratchet test, tests/test_every_module_is_reached.py, asserts every module under reckon/ is reached or appears in an allowlist that names, for each entry, the plan that owns wiring it; the allowlist may shrink and the test fails when it grows.

Done when the ratchet test passes at the integrated head with an allowlist of exactly the modules unreached at this section's base, each naming its owner (§3 and §4, which run after this section, remove their modules from it), and tests/test_reach_graph.py passes: a temporary tree with a console script importing a, a importing b, and an unimported c reports a and b reached and c not; neighbourhood(["b"]) returns a; and a module reached only through python -m in a reckon source string is reported reached (the positive control). The negative control is executed and logged: an extra unreached module added to the temporary repository's reckon/ fails the ratchet test by name. Write paths: reckon/served_code.py, tests/test_reach_graph.py, tests/test_every_module_is_reached.py.

§ Decisions

What happens to a module that produced committed evidence once and that nothing runs?

Wiring adds a verb nobody asked for; deleting loses the reproduction of committed evidence. A script keeps the reproduction and takes the module out of the package's surface.
