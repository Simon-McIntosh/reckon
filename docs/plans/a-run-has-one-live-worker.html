§13 — A launch is refused while another launch of the run is in flight

Why. §12 landed (9587a26dd7) and its review found a window it opens. When retired receipts answer, _retired_attempt_ended in reckon/crew/dispatch_launch.py decides the launch without consulting the in-flight attempt. Between the moment a launch writes attempt.json for its own attempt and the moment its supervisor writes worker.json, a second launch of the same placed run reads the older, ended attempt and is admitted. Two workers then run in one worktree, the defect this plan exists to prevent. The window is bounded by supervisor startup and placement, because on_spawn writes the worker record straight after each spawn. Before §11 every placed reading of unknown liveness refused, so the window is new. The resume path already reserves its attempt through claim_next_attempt in reckon/crew/resumption.py, an exclusive create that one of two racing doors wins. The dispatch path that relaunches an existing run id (reckon/crew/dispatch.py, the _prepare_attempt_records call near line 3369) takes no reservation, so two dispatch doors, or a dispatch beside a resume, can prepare the same attempt. Two content reviews of this section found that the existing claim cannot simply be reused. claim_next_attempt numbers its claim from the attempt already taken (near line 398), while the dispatch pointer already carries the attempt being launched (dispatch.py near lines 3013 and 3316). And _claim_may_be_reclaimed answers not-reclaimable as soon as the pointer has reached the claimed number (near lines 366–382), before it reads the claim's age, so a dispatch killed after writing its pointer would hold its claim forever.

Deliverable. A launch of a run id is refused while another launch of that run is in flight, and a launcher killed in flight never strands the run. In flight means an attempt newer than every receipt, with no worker record, whose reservation is still held. Every door that relaunches an existing run id, dispatch and resume alike, takes a reservation for the attempt it launches, and of two doors racing for one attempt exactly one holds it. A reservation with no worker record is freed once it is older than LAUNCH_WINDOW_SECONDS, whatever the pointer's attempt says. The spawn guard of the supervisor launched for an attempt is not refused by that attempt, because its launch holds the reservation. The node chooses how to reserve. It may extend the attempt claim to the dispatch path, numbering the claim from the attempt being launched and freeing it by age, or add an equivalent record, but it must meet both constraints named above. A first launch of a new run id is unchanged. The receipt reads stay in dispatch_launch.py. Write paths: reckon/crew/dispatch.py, reckon/crew/dispatch_launch.py, reckon/crew/resumption.py and the new test tests/test_a_concurrent_launch_is_refused.py.

Done when.
