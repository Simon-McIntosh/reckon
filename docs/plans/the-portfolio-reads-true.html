§1 — Why: the instruments that should say a plan is finished or forgotten do not

The portfolio health review of 2026-10-10 read every plan and sprint resource in reckon (~/.config/reckon/crew/reports/reckon/health-review-1010/health-plan-portfolio/, with one row per non-shipped plan in portfolio.csv). Of 164 plans, 63 are not shipped. The roadmap ranks 38 of them ready. Sprint S22, titled Open work carried from S16 to S20, has 55 members, 12 of them shipped, and no dates: it is a backlog. 24 shipped plans keep a live sprint membership. The review proposed closing 6 plans, merging 4 into their live owners, retiring 3 and re-sprinting the rest of S22.

The audit did not raise any of this, because its instruments read the wrong thing:

§2 — A plan with section declarations derives its impl from them

Deliverable. When section records cover every declaration, impl stays the effort-weighted figure it is today, with impl_source: computed as now (reckon/_plan_html.py:1128). When they do not, impl is derived from the declarations by count (done over done plus implementable, deferred excluded) and the parsed state says so with a third value, impl_source: declarations, added to the schema's enumeration (reckon/_schema.py:112) and to the values the plan-review reader documents (reckon/crew/plan_review.py:122); the authored meta stands only for a plan with no declarations, with impl_source: authored. A plan with an implementable declaration therefore never reads 1.0. reckon audit-doc reports impl-meta-stale (warn) when the meta on disk differs from the derived figure by more than 0.01, so a reader of the file and a reader of the server agree once the next write lands. Every caller of derive_impl_from_sections is moved with it: both impl_source assignments in reckon/_plan_html.py (lines 1125 and 2234), the reader at line 1939, and the authoring refusal at reckon/_store.py:2606, which keeps refusing an authored impl only in the covered case, so a coordinator's impl write on a partially recorded plan is still accepted and the audit flags it stale. The section adds one schema value and one audit code; nothing retires, because no existing value or code reports a figure derived from declarations.

Done when tests/test_impl_derives_from_declarations.py parses three temporary plans: one whose records cover its declarations (impl effort-weighted, source computed); one with authored meta 1.0, declarations {s1: done, s2: implementable} and a record for s1 only (impl 0.5, source declarations); and one with no declarations (authored figure, source authored). reckon audit-doc on the second file reports impl-meta-stale. The negative control is executed and logged: with the coverage fallback returning the authored figure, the second plan reads 1.0 and the test fails. The tests importing reckon._plan_html pass, their list built at dispatch from the head tree, and the schema validates a state carrying each of the three values; an impl write on the second plan through the store is accepted. Write paths: reckon/_plan_html.py, reckon/_store.py, reckon/_schema.py, reckon/crew/plan_review.py, reckon/doccheck.py, tests/test_impl_derives_from_declarations.py, and tests/test_impl_stays_authorable_while_records_are_partial.py, which pins the behaviour this section supersedes: it asserts the authored figure stands for a partially recorded plan (lines 114 to 126), the case in which a-lane-can-say-where-it-stands reads 1.0 over an open section. Its authoring half stays true and stays asserted; its served-figure half is rewritten to the declarations figure.

§3 — Staleness counts from a plan's last commit

Deliverable. A plan's age has an owner, derived_plan_age (reckon/doccheck.py:230), which resolves plan-modified then the file's mtime and is read by reckon/archive.py:87 and reckon/roadmap.py:945; the audit loop (doccheck.py:531) bypasses it and reads the mtime itself. This section puts the last commit first in derived_plan_age, read through the existing last-commit lookup _git_last_committed (reckon/serve.py:1432) rather than a new git reader, and routes the audit loop through it; the roadmap's first call (reckon/roadmap.py:945), which passes no path today, passes the plan's path so the commit is read first there too. The audit, the roadmap and the archive then report one age, with its source named on the row. The two other git-date readers (reckon/metadata_index.py:681, reckon/fleet_index.py:33) are left as they are and listed in the manifest. A non-shipped plan between 14 and 30 days old is reported AGING (info), and past 30 days STALE as today. The section adds one audit code, AGING; nothing retires, because no row reports the 14 to 30 day band.

Done when tests/test_staleness_counts_from_the_last_commit.py builds a temporary git repository with a plan committed 20 days ago (by GIT_COMMITTER_DATE) and then touched on disk today, runs the audit, and asserts an AGING row with age 20 and source commit; a second plan committed 40 days ago reports STALE. The dates are derived from the fixture's own commit dates at assertion time, never written as literals. The negative control is executed and logged: with the age read from the mtime, the first plan reports age 0 and no row, and the test fails. Write paths: reckon/doccheck.py, reckon/roadmap.py, tests/test_staleness_counts_from_the_last_commit.py. This section runs after §2, which also writes doccheck.py.

§5 — A section-level relation counts as wiring

Deliverable. unwired_plan_finding (reckon/doccheck.py:874) treats a plan as wired when it declares plan-section-depends-on or plan-after, or when another plan holds a gate whose required evidence names it, beside the links, gates and standalone reason it accepts today. The audit message and the reckon-create skill's wiring table name the section-level forms, so the right wire is also the one that silences the finding. Its three callers pass the new inputs: reckon/doccheck.py:858, reckon/roadmap.py:1287 and reckon/mcp_discovery.py:221, the last of which drives the new-plan refusal.

Done when tests/test_section_relations_count_as_wiring.py audits a temporary project in which plan x declares only plan-section-depends-on on y#s2, plan y is named only as the required evidence of a gate on x, and plan z declares nothing: z is reported unwired, x and y are not. The negative control is executed and logged: with the gate-evidence clause removed, y is reported unwired and the test fails. Write paths: reckon/doccheck.py, reckon/roadmap.py, reckon/mcp_discovery.py, skills/reckon-create/SKILL.md, tests/test_section_relations_count_as_wiring.py. This section runs after §4.
