A Worker Owns Its Own Record

A worker is the only agent that knows what its change did, what its figure shows, and which of its measurements survived. It is therefore the right author of its plan section, its evidence record and its figures — and today it routinely writes none of them, not because it declines but because its brief handed it a scope that made the record someone else's file.

§1 — The scope was always available; only the brief withheld it

The obvious explanation for a missing evidence record is that the worker could not write it. That explanation is wrong here, and the code says so in its own comment. reckon/crew/dispatch.py exempts the plan file and the cumulative evidence record from exclusive-claim machinery, and the comment ends with the sentence this plan turns on:

The plan file and cumulative evidence record are write claims every node on the plan holds, so they cannot be exclusive to one of them … They are exempted from the exclusive-claim machinery, never from the declared write scope.

So the paths were never contended and never forbidden. They were simply absent from briefs, and a path a node has not declared is a path its worker will not write. Measured on the nova project: six nodes in one session were dispatched with the plan and evidence record deliberately excluded, because the coordinator believed a sibling node's claim covered them. It did not, and could not — that is exactly what the exemption exists to prevent.

The exemption is per plan. A node declaring another plan's record is still refused against a live node on that plan, verified on nova by a cut-cell node refused against a live millisecond node. So the default scope this plan grants is the node's own plan's records; cross-plan record writes stay with the coordinator, where the merge that reconciles them can be sequenced.

A worker given the scope does the work. The positive control landed here today: docs/figures/registration-commit/roster_write_order.png, from a node whose brief declared docs/figures/registration-commit explicitly. It shipped the figure and its generator, roster_write_order.py, in the same commit. Nothing about that worker was different; its brief named the directory.

§2 — Every node is scoped to its own record by default

The rule. crew dispatch adds three paths to every implement, test and investigate node without the coordinator declaring them: the node's own plan file, its cumulative evidence record, and a figures directory for the node. The coordinator opts out explicitly or not at all.

And it refuses a brief that scopes them out. This is the half that makes it stick. A brief carrying text to the effect that the plan or evidence record is not this node's to edit is refused at dispatch, naming the path and the sentence, because that sentence is the measured cause: it was written by coordinators who believed they were preventing a conflict that the exemption had already prevented.

Falsifier, to be written before the change. A node dispatched with no write paths declared beyond its source files comes back with its plan and evidence record in scope; a node whose brief excludes them is refused with both named. Assert the negative half too: a node on plan A does not silently acquire plan B's record, and an investigate node in a read-only sandbox is scoped without being granted a write capability it cannot exercise.

§3 — A landing that records nothing is refused

Scope alone is permission, not practice. The gate belongs where the run becomes evidence: crew complete on a passing implement or test run refuses when the run's commits touch neither the plan nor the evidence record. The escape is --no-record REASON, which lands on the ledger row, so a deliberately recordless promotion stays distinguishable from one that recorded nothing by accident — the same shape as the existing --no-commit.

A second, weaker check rides with it: when a node's write paths include a figures directory and the evidence anchor it added carries no figure, the promotion warns. A warning rather than a refusal, because a node can legitimately declare a figures directory and conclude that a table communicates the result better — which the authoring rules explicitly prefer.

§4 — A figure is a named deliverable, not a courtesy

The contract text in reckon/crew/prompts.py and skills/reckon-ship names the figure as a deliverable with a topic directory, a statement of what it shows, and the plotting rules — rather than leaving illustration as a standing encouragement that competes with a time budget.

How a worker verifies a figure it cannot see. The lanes that produce most figures are text-only, and a worker that cannot open a PNG can still verify the thing that matters: the SVG's structure and the data receipt behind it. So figures are saved as twins — a PNG for the document and an SVG whose element tree the worker asserts against — or, better and already practised here, the figure ships beside the script that generated it, which makes it reproducible rather than merely checkable. A text-only lane never opens the PNG and must not claim to have looked at it.

Vision review is exempt on the local lane. The local lane does not review images, by the lead's instruction. Where a figure genuinely needs an eye, it routes to a vision-capable lane — see the open decision below, which is the lead's to make.

One trap worth stating so it is not learned by refusal: the placeholder validator refuses angle-bracket text in a done-when, so a brief naming a literal such as a bracketed sha is rejected as an unsubstituted placeholder. Describe the deliverable instead of templating it.

§5 — An artifact written where nothing owns it is lost

The stranded-figure census on nova is 139 figures across 47 worktrees: 31 untracked because *.png is gitignored there and workers never force-add, and 108 committed in worktrees that were never merged.

That cause does not transfer to reckon, and checking rather than inheriting it changes the remedy. reckon's .gitignore carries no image rule at all — *.py[cod], *.egg-info/, *.log, and nothing else — so the force-add half is nova-specific. reckon's own exposure, measured as figures added over each worktree's base rather than total files present:

The same defect has a second instance nobody was looking for. *.log is gitignored in reckon, so gate logs cannot be committed and land on bare /tmp names instead. A run dispatched on 17 September cites /tmp/gate_final.log; that file was rewritten at 10:09 the following morning by a different run. The promotion read it, the contents happened to still agree, and nothing would have said so had they not. A gate log is evidence with the same standing as a figure, and it is being written where nothing owns it.

What this section builds. The follower and drain views list figures committed in unmerged worktrees and untracked figures under docs/figures, so a coordinator sees stranded artifacts before removing a worktree rather than after. Gate logs move under the run directory, which is already where the well-behaved runs put them.

§6 — What this plan does not own

Whether a review record can state its own incompleteness, and whether a finished run dispatches its own review, belong to an-orchestrator-is-bound-by-its-inbox. The distinction is that that plan governs what happens to a run after it reports; this one governs what the run is scoped and required to produce while it works. They meet at crew complete, where both add a gate, and the two gates must be written as one pass over that function rather than two.

§ Decisions

When a figure needs a human-equivalent look, which lane reviews it? The local lane is exempt by instruction, and the codex lane is held until 21 September.

§ Followups

Grant the scope before gating on it, because the gate is unfair otherwise

§2 goes first and §3 cannot precede it. Refusing a landing that records nothing, while briefs still exclude the record from scope, punishes workers for a scope their coordinator withheld. Grant the default scope, let a wave run under it, and only then gate the promotion.

§5 can run in parallel and is independent of both. It reports on artifacts that already exist and blocks nothing; its cheapest half is the stranded-figure listing, which is a read over worktrees.

§4 is contract text and follows §2, because naming a figure as a deliverable in a brief whose scope excludes the figures directory is the current failure restated.

Measure this plan by produced records, not by intentions. The number that matters is the proportion of passing implement runs whose commits touch their own plan or evidence record, measured before and after §2. A count of figures is a weaker signal, because the authoring rules correctly prefer a table to an imagified one and a node may rightly produce none.

/reckon-build a-worker-owns-its-own-record §2

Correcting this section's own headline within the hour of writing it, because opening the stranded worktree changed the finding. §5 says 21 figures are stranded in a worktree unmerged since 25 August. That count is right and the conclusion drawn from it is wrong.

What is actually in there. The commit adds 21 files: 10 PNGs, 10 per-view DOM receipts and a capture index. Comparing each against main: all 10 PNGs are byte-identical to files already on main. The capture index differs, and the 10 DOM receipts exist only in the worktree, at roughly 494 KB each.

And the reason is not that the worktree was forgotten. Its capture index is stamped 2026-08-25T12:57:06Z; main's is stamped 2026-09-01T18:39:05Z. A later run of the same capture harness landed on main a week afterwards. So nothing of current value is stranded here — the worktree holds a superseded capture, and the images from it reached main by a route that made this commit redundant.

The real finding is the one the count concealed, and it is worse. Main carries 19 PNGs and exactly one JSON under the after/ captures — the index. Neither capture landed its per-view DOM receipts. Not the 25 August run, whose receipts are stranded, and not the 1 September run that superseded it, which appears never to have committed them at all. So the systematic behaviour is not that figures are lost; it is that the picture lands and the machine-readable receipt behind it does not, every time.

That binds §4 directly rather than §5. §4 asks a worker on a text-only lane to verify its own figure through the figure's structure and its data receipt. This measurement says the receipt is the half that systematically fails to reach the repository, so the verification §4 specifies would today have nothing on main to verify against. A figure whose receipt is missing is a claim without its evidence, which is the same defect as a gate verdict without its log.

A second, structural finding falls out of trying to dispose of the worktree. Cleanup policy removes a worktree only when it is clean and its commit is reachable from the primary branch. This one is clean and will never be reachable, because its content was superseded rather than merged. So a worktree holding superseded work satisfies the safety half forever and the reachability half never, and accumulates by construction — which is why one has sat here for three weeks with no live pointer and nothing reporting it. The recovery view §5 builds must therefore distinguish unmerged and unique from unmerged and superseded; only the first is work at risk, and only the second is safe to retire. Reporting a single count of unmerged figures would have told this coordinator to rescue 4.9 MB of obsolete DOM dumps.

A cost of this section, measured before the section shipped, and it is the strongest argument against it that exists so far. Two promotions were refused this afternoon for reasons that both trace to record paths, and the second one is what §2 would make common rather than rare.

The refusal. crew complete refused a run with uncommitted changes at its declared paths outside its own worktree, naming the plan file and the cumulative evidence record, both held by a different live run in that run's own worktree. Nothing was wrong: the peer was mid-flight and doing exactly what it should, and the promoting run's own deliverable was committed, merged and green at the merged head.

Two rules pulling against each other, and only on these paths. The plan file and evidence record are exempt from exclusive claims so that several nodes on one plan can hold them and reconcile their appends at merge — that exemption is the argument §1 opens with. Promotion separately refuses when a peer holds a declared path uncommitted, which is a sound protection against recording a run as complete while its declared surface is still moving. Both are right. They collide precisely and only on the shared landing paths, because those are the only paths two live runs are expected to hold at once.

Why this section makes it routine. Today the collision is rare because most briefs omit those paths — the omission this plan calls the defect. Grant them to every implement, test and investigate node by default and the arithmetic inverts: any two concurrent nodes on one plan hold the same two paths for their whole lifetime, so each blocks the other's promotion for as long as either has an uncommitted record. On a plan running three or four nodes at once, that is most of the time.

So §2 owes a resolution rather than a note. Three candidates, none free. Exempt the shared landing paths from the peer-uncommitted check as well as from exclusivity, which is coherent — the same reasoning covers both — but removes a protection on the paths most likely to be edited concurrently. Require a node to commit its record before it can block a peer, which is really a timing rule and hard to enforce. Or treat the refusal as the intended cost and give it a first-class waiver, which is what exists today: --waive-boundary-refusal with a reason on the ledger row. The third is what was used here, and a waiver every coordinator learns to type reflexively is a check that has stopped checking.

The companion refusal, for completeness. The other promotion was refused on docs/figures/<topic>/….svg being outside the declared scope — a figure a worker drew of the states it had just made distinguishable, refused because the brief declared no figures directory. That one is unambiguously the defect this plan removes. It is recorded here beside the other so the pair is not read as one problem: granting the figures directory is a straightforward win, and granting the shared records carries the cost above.

Half of §2 is already built. 86aafc6a, 15 September, fix(crew): grant the landing paths the dispatch contract instructs — 336 insertions across reckon/crew/dispatch.py and two test files. It returns the plan file and cumulative evidence record for every node, on exactly the reasoning §1 spends its length arguing. The grant is advisory, so an unresolvable plan contributes no path. The sentence §2 adds three paths to every node without the coordinator declaring them therefore describes existing work for two of the three.

What remains is the half nobody built. Nothing in reckon/crew/ refuses a brief whose text scopes those paths out — the enforcement half, and the one the measured failure actually needed, because the six nodes cited in §1 were dispatched with briefs excluding paths the grant would have supplied. The figures directory is not granted at all.

The figures wording contradicts a live plan and the readings are incompatible. §2 says a figures directory for the node. As a node-named directory, siblings each get one and the topic-exclusivity guard never fires. As the topic directory, figures-are-allocated-by-topic-directory §2 already makes it an exclusive single-node claim, so two concurrent nodes on one plan would both be granted one topic and the second refused at dispatch. One reading silently disables a shipped guard, so this is a decision to lock rather than prose to tidy.

Eight further sentences admit two readings, the three that change what an executing node would build being §1's the paths were never contended and never forbidden, which asserts the reading this plan's own argument contradicts; §1's cross-plan record writes stay with the coordinator, which does not say whether the coordinator writes them or only sequences them and so leaves a cross-plan record with no author; and §2's the coordinator opts out explicitly or not at all, which cannot be implemented without a name for the opt-out it may or may not describe. All nine are quoted with both readings in the read-back report at the run record.

What the reflex cost and caught. One read-only node on the local lane, reporting parts=4 sections=6 claims=3 plans=21: all three of the plan's factual claims resolved as still-holding with file and line, twenty-one live plans checked for overlap. Without it, a node dispatched against §2 would have rebuilt a grant that shipped on 15 September and guessed between two incompatible figures semantics. The plan was written carefully the same afternoon by someone with the code open, which is what makes this the useful case rather than an embarrassing one.
