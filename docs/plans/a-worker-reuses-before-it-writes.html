§1 — Why: isolation made the codebase repeat itself

The structural census found 44 functions in reckon that parse an ISO timestamp themselves (27 in the crew package), 14 that write JSON atomically with differing temporary naming, cleanup and fsync behaviour, three that enumerate a run's streams, and four byte-identical numeric decoders under four names. The crew package's clone share rose from 5.5% to 7.1% while its code doubled, and its public definitions grew 226% in three weeks (crew pattern review §7). Every copy is private and sits in the one module its node could write. A worker holds exclusive write paths; when the helper it needs lives outside them, or does not exist, a private copy is the cheapest compliant move, and neither the gate nor a per-diff review compares the copy with the others. The lead's standard — deep modules behind small interfaces, no reimplementation — needs a mechanism, not another paragraph.

§2 — One timestamp parser

Deliverable. reckon/_timestamps.py with parse_utc, whose behaviour on a Z suffix, an offset, a naive value, a numeric epoch in seconds or milliseconds, and malformed input is specified by tests first; then the 44 call sites migrate, in batches whose write paths do not overlap, keeping each caller's elapsed-time and display policy where it is.

Done when the census's timestamp group, re-run on the new head, reports at most three direct fromisoformat users, each with a stated reason, and the full suite shows no added failure against the base revision.

§3 — One atomic JSON writer, one stream enumeration, one numeric decoder

Deliverable. write_json_atomically beside the existing envelope writer in reckon/_store.py, with a unique sibling temporary, cleanup on failure and an explicit fsync policy, adopted by the 14 writers while each keeps its own locking; metering.run_streams used by promotion and the ledger in place of their copies; and one bool-rejecting numeric decoder for the four identical bodies.

Done when the census's groups for all three concepts report one implementation each, and an interrupted-write test runs against the shared writer.

§4 — A copy is visible at promotion

Deliverable. Promotion runs the census's normalised six-line clone detector over the run's added functions against the rest of the package and puts any match — the new function, the existing one, both file:line — in the review packet and on the ledger row. It warns; it does not refuse.

Done when a synthesised run that adds a private copy of parse_utc is reported with the existing function's location, and a run adding no copy reports none.

§5 — The interface has a budget

Deliverable. The velocity view reports public definitions, CLI options, MCP views and refusal families per week for reckon; a plan section that adds any of them names what it retires or merges, or records why the surface must grow. The plan-review rubric already favours deep modules (a-plan-is-reviewed-before-it-is-built); this gives it a number to read.

Done when the weekly surface counts are in the view and the plan-review rubric cites them.
