§1 — Why: isolation made the codebase repeat itself

The structural census found 44 functions in reckon that call fromisoformat themselves (27 of them in the crew package), 14 that write JSON atomically with differing temporary naming, cleanup and fsync behaviour, three that enumerate a run's streams, and four byte-identical numeric decoders under four names. From 5 to 26 September the crew package's source lines tripled (13,268 to 40,343), its clone share rose from 5.5% to 7.1%, and its public definitions grew 226% (crew pattern review §7). Almost every copy is a helper inside the one module its node could write, and most are private. A worker holds exclusive write paths; when the helper it needs lives outside them, or does not exist, a local copy is the cheapest compliant move, and neither the gate nor a per-diff review compares the copy with the others. The lead's standard — deep modules behind small interfaces, no reimplementation — needs a mechanism, not another paragraph.

§2 — One timestamp parser

Deliverable. reckon/_timestamps.py with parse_utc. Its behaviour on a Z suffix, an offset, a naive value, a numeric epoch in seconds or milliseconds, and malformed input is fixed by tests that land before any caller migrates. The 44 functions then migrate in batches whose write paths are disjoint from each other and from any live run's claims, each keeping its own elapsed-time and display policy.

Done when a pin at the new head is appended to the code-depth census's snapshots.json and census.py re-run there reports at most three functions still calling fromisoformat directly, each carrying a code comment that states why; and the full suite shows no added failure against the head this section started from.

§3 — One atomic JSON writer, one stream enumeration, one numeric decoder

Deliverable. write_json_atomically beside the existing envelope writer in reckon/_store.py: a unique sibling temporary, removal on failure, and an fsync parameter that defaults on and that each of the 14 callers sets to match what it does today, keeping its own locking. metering.run_streams replaces the copies in promotion and the ledger. One numeric decoder, reckon/_observations.py:optional_number, rejects bool and any value that is not an int or float, and otherwise returns float(value), replacing the four identical bodies.

Done when the census re-run as in §2 reports one implementation per concept, with any retained exception listed with its reason, and a test in the suite interrupts a write through the shared writer and asserts the target file is either the old or the new content.

§4 — A copy is visible at promotion

Deliverable. The census's normalised six-line clone detector, ported into a package module (reckon/clones.py); the study's script stays as the review's artifact and nothing in the package imports from docs/. Promotion runs it over the functions the run added or modified, against reckon/ and tests/ at the promoted revision, and records each match — the run's function, the existing one, both file:line — on the ledger row and, when the run was reviewed, in its stored review record. It warns; it does not refuse. The velocity view counts matches per week.

Done when two tests in the suite pass: a synthesised run that adds a private copy of parse_utc is reported with reckon/_timestamps.py:parse_utc's location, and a run that adds a function matching nothing reports no match.
