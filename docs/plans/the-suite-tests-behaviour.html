§8 — A real-home guard fails only on what its own test wrote

Why. A test that runs under a temporary RECKON_HOME should also prove it wrote nothing into the real one, and many tests here do. Several prove it by snapshotting a whole shared directory before the test and requiring the same snapshot after it. Peer sessions write into those directories continuously: dispatch adds and removes live pointers and run directories, a follower adds its registration under crew/watch, promotion rewrites docs/state/<project>/crew.json in the shared checkout, and a peer's lanes read rewrites the lane-probe cache. So these guards fail whenever a peer acts during the test, at base as well as at head. On 2026-10-14 reckon-28 measured tests/test_no_member_dispatch_runs_alone.py::test_two_unnamed_reviews_launch_with_disposable_members failing at base this way. Its _live_view compares the full real crew/live listing and the bytes of every docs/state/*/crew.json in the checkout. The real crew/ directory's mtime moved at 02:30Z that day while no test ran. A guard that fails on someone else's write cannot say whether this test wrote, and a reader learns to ignore it.

The same unfiltered shape sits in at least these modules, read at 64f44fdbe:

  • tests/test_watch_arming_isolation.py: every name in the real crew/watch.
  • tests/test_member_registration_commits.py: the checkout roster's bytes, git status --porcelain -- docs/state of the checkout, and every top-level name in the real home.
  • tests/test_impl_is_computed.py: every top-level name and mtime in the real home, crew/ included.
  • tests/test_rollup_isolates_a_project.py: the same, with crew/ excluded, while logs/, state/ and budget-lifts.json still move.
  • tests/test_append_decision_keeps_its_question.py: the path and size of every file under the real state/.
  • tests/test_lanes_view_is_live.py: the whole real lane-probe cache tree, which any session's lanes read rewrites.

Other guards already have the robust shape. They report only an entry whose name or content carries a needle the test minted: a run id, node id, project or session. These are _own_traces in tests/test_follow_lifetime.py, and the fixture_pointers helper copied into tests/test_concurrent_dispatch_of_one_node.py, tests/test_dispatch_launch_is_not_its_own_conflict.py, tests/test_dispatch_result_matches_launch.py and tests/test_refused_dispatch_leaves_no_pointer.py.

Deliverable. The needle-filtered check gets one home, tests/real_home_traces.py, taken from _own_traces. It takes a root, the subtrees to search and the test's needles, and returns each file under them whose name or content carries a needle. Every unfiltered guard listed above moves onto it with needles its own test minted. The write-side assertion stays: each test still fails if it leaves a trace of its own in the real home or the shared checkout. It no longer fails on a peer's entry. A guard whose test mints no needle of its own, such as a top-level mtime comparison, is rewritten to search for an identifier the test does mint. It is deleted only if the test genuinely writes nothing it could name, and the census records the reason. _own_traces and the four fixture_pointers copies move onto the same helper, so one definition remains. The census is part of the deliverable. It covers every test module that resolves the real config home, by Path.home() or any other spelling, or the shared checkout's docs/state, and compares a snapshot of it before and after. Each module is classified as needle-filtered or unfiltered and named with the line it reads, so an unfiltered guard this list missed is found and moved too.

Done when tests/test_real_home_traces.py passes, logged under the run directory with the literal command, its revision and an EXIT=0 line. Against a temporary root, it shows that a foreign entry added between the two readings is not reported, and that an entry carrying one of the test's needles, by name or by content, is. The census is logged under the run directory, every module it classifies as unfiltered is on the helper, and no module keeps a private copy of the trace search. The test files this section edits show no added failure against base. Their base arm is run once while a peer dispatches into the real crew/live during the run, and the head arm passes that same condition. Two negative controls are executed and logged under the run directory, each with the runner's own FAILED line and a non-zero EXIT. With the helper reverted to comparing the whole root before and after, the foreign-entry case fails. With the migrated guard in tests/test_no_member_dispatch_runs_alone.py pointed at the test's own temporary home, the test's own pointers land where the guard looks, and that guard fails naming a pointer the test wrote. This control writes nothing into the real home. For every migrated guard, the census also records the needles it searches for and the line of its test that writes each one. A guard watching for a value its test never writes is therefore visible in the evidence. Write paths: tests/real_home_traces.py, tests/test_real_home_traces.py, the six modules listed above, tests/test_no_member_dispatch_runs_alone.py, tests/test_follow_lifetime.py, and the four modules carrying fixture_pointers.
