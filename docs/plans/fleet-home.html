Fleet home · the one cross-project surface

A Fleet Home That Hides at Zero

The landed home is a separate page listing every registered project, most of them at zero plans and zero updates, with sparklines that draw a flat line whether the series is empty or genuinely flat. The canvas replaces it with a read-only oversight dashboard inside the shell: a stat band, one row per project that is actually moving, a thirty-day edit streakline that says "no recorded activity" when there is none, and the fleet's in-flight and just-landed work side by side. It obeys the one visible set everywhere, and it carries no action queue.

§1 — Why this exists

From the handoff triage (design/reckon-spa-handoff.md, item B4 and part E) and the canvas (design/reckon-spa-handoff.dc.html), checked against main on 2026-09-03:

  • docs/home.html mounts its own React root and docs/ui/home.jsx reads /_projects/index.json, whose rows come from each project's superseded index file; the four real projects sit below nine dead rows.
  • docs/ui/_shared.jsx's sparkline draws activity30, which nothing serves, so every line is flat.
  • The project shell's default route is the cockpit, a per-project overview of active sprints and unresolved blockers with a next action, owned by docs/ui/shell-overview.jsx. The canvas has no Overview tab and no per-project overview: its tab groups are the four artifact tabs and Sprints, Graph, Crew, and the brand mark is the home button. Its home carries held counts and open decisions as figures on rows and in the sprint header, and states that a "waiting on you" list implies resolution happens on a planning surface, which it does not.

Two prerequisites are declared. served-surface-data-contracts computes the fleet index live, including the activity series and each project's active sprint. spa-shell-scope-and-visibility makes the visible set real and points the brand at the home route. Retiring the cockpit is a visible deletion of a surface the lead has used, so it is its own node here, reversible in one revert, rather than folded into the home view.

§2 — The home view

A shell view at #home, the default when the hash is empty and the target of the brand mark, rendered by docs/ui/home.jsx (rewritten in place; the module is loaded by the shell entry point) with its own view stylesheet. In order: an eyebrow, Fleet · <date>, then N of M shown and a configure link that opens the visibility sheet; a stat band of six figures at 26px mono, projects moving, plans, active, in flight, held, shipped, computed over the visible set only; the project table, one row per visible project with at least one plan, ordered by last edit, each with a live dot and edited <ago>, the thirty-day streakline as a filled polyline with N edits · M last 3d or, for an empty series, the text no recorded activity and no polyline, a status composition bar (shipped, active, held, pending) with tooltips, the plan count and N held when non-zero, and the active sprint id with its theme or no active sprint; a dormant strip under the table, N visible projects with no recorded work — show, expanding to a row of chips and absent entirely at zero; In flight (every live run across the visible set with title, section, repository, current line, budget bar and phase, headed N runs · polling every 3s) beside Just landed (the visible set's evidence and shipped plans from the last 72 hours, newest first, at most seven). Clicking a project row opens its Plans index; clicking a landed row opens the document. There is no headline sentence and no action queue.

§3 — Retire the standalone home and the cockpit

Once §2 renders, the shell has two homes and two overviews, which the canvas's rule against redundant ink forbids. GET / answers a redirect to /<project>/#home for the first mounted project whose docs directory exists, so the fleet home has one URL; docs/home.html is deleted and the server stops looking for it. The cockpit module, its stylesheet and its tests are deleted; the #cockpit hash maps to #home so old links land. The fleet prompt module rendered above the sprint surface is deleted with it, because the sprint surface now carries its own copy control. The build test's assertion that exactly one module defines the cockpit body becomes the assertion that none does and exactly one defines the home body.

§5 — Out of scope

Settings beyond visibility are undesigned in the handoff; the theme and density controls stay behind the gear. Cross-repository sprint scope stays as focus plus a repository badge, which is what the canvas draws on run cards and closure members, and the open question of forcing multi-project sprints is not decided here. The fleet index itself is computed by served-surface-data-contracts.

§ Decisions

Where does the fleet home live, and what happens to the per-project cockpit?

The canvas has no Overview tab and its brand mark is the home button; keeping the cockpit would keep a second overview and an action queue the canvas explicitly rejects. The retirement is its own node so a revert is one commit.

How are visible projects with no recorded work shown?

Nine dead rows above four real ones is the measured defect; a control whose count is zero is hidden rather than rendered dead.

How is an empty activity series drawn?

A flat line reads as broken and is indistinguishable from a genuinely flat series; the payload distinguishes them and so must the surface.

What does the server's root URL serve once the standalone home is gone?

The shell's state is loaded per project and the canvas itself keeps a project in scope while showing the fleet; a project-less shell is a second loader for one route.
