§1 — Why: fourteen sessions reported the monitor misleading them in one day

On 15 November the lead asked for a fleet-wide call for monitor defects. Fifteen sessions answered within an hour: reckon-f3, reckon-1e, reckon-af, nova-8e, nova-3c, nova-84, nova-09, nova-2e, nova-a8, nova-a1, power-convertor-85, power-convertor-12, imas-efit-05, imas-codex-5a and code-a6. Together they reported about seventy defects. Grouped by root cause they fall into eleven clusters. The register with each report's evidence is kept at ~/.cache/reckon-monitor-defects/register.md.

The costs were concrete. One coordinator was blind for 90 minutes. A sprint stalled for 14 hours on a review that raised no event. A review stored no findings because it was filed from a template, and three real design findings never reached the gate. Coordinators told the lead nodes had started or landed when they had not. Stop hooks blocked turns on obligations that had already been discharged, and some offered remedies that would have landed an unreviewed head.

§5 — An obligation never offers a command that asserts what nobody measured

Why. Several obligations offered remedies that would have done harm if followed:

  • promotion-failed offered crew complete --gate passed for a run whose gate was never measured, for a discarded run, and for a run whose resumed worker was alive (nova-2e, nova-a8, nova-3c, imas-efit).
  • The hook printed crew dispose --rubric node, which the CLI rejects (nova-3c).
  • crew complete --gate pass, an invalid word, exited 0 as promotion-requested and was refused later (code-a6).

Done when. New tests, each failing at the base revision:

  • No obligation's command asserts --gate passed unless the run records a passing gate for its current head. A discarded run raises no promotion obligation. A run with a live attempt raises none until that attempt delivers.
  • Every command an obligation prints parses under the CLI it names; one test runs each composed command through the click parser.
  • crew complete refuses an unknown gate word synchronously, with exit 1. This replaces the later refusal of the queued promotion request, which is no longer reached for that cause.
  • One predicate decides which command an obligation may offer, and every obligation kind reads it. While a repair attempt is live, it offers neither crew complete nor crew repair --status complete for that run.

The tests importing reckon.crew.obligations or reckon.hooks.coordinator_obligations add no failure against the base on all_debug. Write paths: reckon/crew/obligations.py, reckon/hooks/coordinator_obligations.py, reckon/crew/recovery_classification.py, reckon/crew_run_commands.py, reckon/crew/promotion_checks.py and reckon/crew/queue_landing.py (both compose the --gate passed string today) and a new test.

§7 — A declared wait is judged against itself

Why. Three sessions found the same misreading from different angles:

  • nova-a8: a multi-hour compute wait read overdue and went to "investigate" because the expected horizon defaulted to 900 s, while its job was RUNNING (r-20261114T211231918544).
  • nova-a1: a declared probe that was a script, not a squeue or sacct argv, counted as "no scheduler job", and the parked worker read producer-gone (r-20261115T075315275505, r-20261115T081846316772).
  • nova-09: a probe naming a job cancelled before it started read as terminal, and the sweep resumed the worker early (r-20261114T210059239602).

Done when. New tests, each failing at the base revision:

  • A wait whose probe reports a live state is never overdue before its own declared or scheduler-known time limit.
  • Any declared probe that answers counts as the wait's evidence, whatever its argv names, so a parked worker with such a probe is never read as abandoned.
  • A probe naming a job that never started, with a cancelled state and zero elapsed time, is reported as a suspect probe on the run's row rather than as a terminal wait.

The tests importing reckon.crew.recovery_liveness or reckon.crew.recovery_classification add no failure against the base on all_debug. Write paths: reckon/crew/recovery_liveness.py, reckon/crew/recovery_classification.py, reckon/crew/recovery_watch.py, reckon/crew/recovery_wait.py (which owns the probe and expected-horizon readings) and a new test.
