§1 — Why: fourteen sessions reported the monitor misleading them in one day

On 15 November the lead asked for a fleet-wide call for monitor defects. Fifteen sessions answered within an hour: reckon-f3, reckon-1e, reckon-af, nova-8e, nova-3c, nova-84, nova-09, nova-2e, nova-a8, nova-a1, power-convertor-85, power-convertor-12, imas-efit-05, imas-codex-5a and code-a6. Together they reported about seventy defects. Grouped by root cause they fall into eleven clusters. The register with each report's evidence is kept at ~/.cache/reckon-monitor-defects/register.md.

The costs were concrete. One coordinator was blind for 90 minutes. A sprint stalled for 14 hours on a review that raised no event. A review stored no findings because it was filed from a template, and three real design findings never reached the gate. Coordinators told the lead nodes had started or landed when they had not. Stop hooks blocked turns on obligations that had already been discharged, and some offered remedies that would have landed an unreviewed head.

§2 — The queue ranking asks git nothing about landings

Why. Eight py-spy samples of the live station (pid 1137861, 12:14–12:16Z) found its main thread inside the tick's queue ranking every time. That ranking builds the project roadmap to read section priority keys. Five samples were in a git merge-base subprocess under the roadmap's landing audit, and three in the whole-ledger decode the same audit triggers. A ranking reads no finding.

Done when. A roadmap built for queue ranking runs no landing audit, while a roadmap read outside ranking still reports an unlanded run. One test asserts both, failing at base; a second asserts that the queue ranking opens its build with the audit off. Each test fails under its own mutation. The tests importing reckon.roadmap or reckon.crew.queue_order add no failure against the base on all_debug. After the station reloads past the landing, three py-spy samples of its main thread show no frame under the landing audit. Write paths: reckon/roadmap.py, reckon/crew/queue_order.py, tests/test_a_section_a_run_has_delivered_is_not_ready.py.

§3 — A held request is drawn by whose move the hold is

Why. The pane's word set puts held under "needs you", while the counter in reckon/crew/ticker.py counts a held run as waiting. A request parked by the queue itself (held on a claim, on an allowance, on a retry back-off, or with queue_hold.automatic true) was drawn "needs you" in five sessions with nothing to do. A request the coordinator held with crew hold, or one whose hold asks for a coordinator act such as composing an owed plan review, is the coordinator's move.

Done when. New tests, each failing at the base revision. A request held on a claim, on an allowance or on a back-off is drawn in the waiting pane and counted there. A request held by crew hold, or by a hold whose lifting condition is a coordinator act, is drawn "needs you" and names that act. The row word and the counter bucket agree for every hold kind the code defines. The tests importing reckon.crew.ticker or reckon.crew.recovery_watch add no failure against the base on all_debug. Write paths: reckon/crew/ticker.py, reckon/crew/recovery_watch.py and a new test.

§4 — A launch that never reached a worker is reaped and drawn unlaunched

Why. Four sessions found runs at phase starting with no process and only prompt.txt and claim.json on disk. Some had a dispatch or review killed by its caller's timeout (code-a6, twice). Others had a launch whose holder was alive but stuck at claim-published for 15 minutes or more (three cases, two of them under station 506666). Discarding these runs removed their directories, so the reproduction is the condition itself, built in a test: a pointer at starting whose claim.json names step claim-published, with no worker record, and a launcher pid that is either gone or past the launch bound. The pane drew each as working and then as needs-you; the obligations view showed nothing.

Done when. New tests, each failing at the base revision. A run at starting or claim-published whose launcher pid is gone, or whose claim step is older than the launch bound with no worker record, is released within one pass. A launch from a queued request goes back to the queue, and a composed review is recomposed. Until then it is drawn as unlaunched, not as working. A launch still within its bound is untouched. The tests importing reckon.crew.dispatch_claims or reckon.crew.recovery_classification add no failure against the base on all_debug. Write paths: reckon/crew/dispatch_claims.py, reckon/crew/recovery_classification.py, reckon/crew/admission/launching.py and a new test.

§5 — An obligation never offers a command that asserts what nobody measured

Why. Several obligations offered remedies that would have done harm if followed:

  • promotion-failed offered crew complete --gate passed for a run whose gate was never measured, for a discarded run, and for a run whose resumed worker was alive (nova-2e, nova-a8, nova-3c, imas-efit).
  • The hook printed crew dispose --rubric node, which the CLI rejects (nova-3c).
  • crew complete --gate pass, an invalid word, exited 0 as promotion-requested and was refused later (code-a6).
  • A coordinator could not mark an obligation as held on purpose, so a correct refusal blocked every stop for hours (nova-3c).

Done when. New tests, each failing at the base revision:

  • No obligation's command asserts --gate passed unless the run records a passing gate for its current head. A discarded run raises no promotion obligation. A run with a live attempt raises none until that attempt delivers.
  • Every command an obligation prints parses under the CLI it names; one test runs each composed command through the click parser.
  • crew complete refuses an unknown gate word synchronously, with exit 1.

The tests importing reckon.crew.obligations or reckon.hooks.coordinator_obligations add no failure against the base on all_debug. Write paths: reckon/crew/obligations.py, reckon/hooks/coordinator_obligations.py, reckon/crew/recovery_classification.py, reckon/crew_run_commands.py and a new test.

§6 — A review record is stored only from a finished report, in either shape

Why. power-convertor-85 found a design review stored with findings: [] while its report.md still held RUBRIC-PLACEHOLDER and FINDING-PLACEHOLDER lines. The record was taken before the reviewer finished writing, so three real findings never reached the gate. The run's directory is gone, so the reproduction is the condition itself, built in a test: a report whose rubric and finding lines still read RUBRIC-PLACEHOLDER-n and FINDING-PLACEHOLDER. Two sessions also had figure-review records with per-figure verdicts refused as "not a complete review" (r-20261114T223637959073, r-20261114T155313333323).

Done when. New tests, each failing at the base revision. A report still carrying a template placeholder is not stored while its reviewer is running, and a later read of the finished report stores its findings. A report still carrying one once its reviewer has ended is refused as a delivery defect naming the placeholders, which opens a repair round rather than holding the review open. A figure-review record with complete per-figure verdicts promotes, while one missing a figure's verdict is refused naming the figure. The tests importing reckon.crew.plan_review or reckon.crew.recovery_review_delivery add no failure against the base on all_debug. Write paths: reckon/crew/plan_review.py, reckon/crew/recovery_review_delivery.py, reckon/crew/review.py and a new test.

§7 — A declared wait is judged against itself

Why. Three sessions found the same misreading from different angles:

  • nova-a8: a multi-hour compute wait read overdue and went to "investigate" because the expected horizon defaulted to 900 s, while its job was RUNNING (r-20261114T211231918544).
  • nova-a1: a declared probe that was a script, not a squeue or sacct argv, counted as "no scheduler job", and the parked worker read producer-gone (r-20261115T075315275505, r-20261115T081846316772).
  • nova-09: a probe naming a job cancelled before it started read as terminal, and the sweep resumed the worker early (r-20261114T210059239602).

Done when. New tests, each failing at the base revision:

  • A wait whose probe reports a live state is never overdue before its own declared or scheduler-known time limit.
  • Any declared probe that answers counts as the wait's evidence, whatever its argv names, so a parked worker with such a probe is never read as abandoned.
  • A probe naming a job that never started, with a cancelled state and zero elapsed time, is reported as a suspect probe on the run's row rather than as a terminal wait.

The tests importing reckon.crew.recovery_liveness or reckon.crew.recovery_classification add no failure against the base on all_debug. Write paths: reckon/crew/recovery_liveness.py, reckon/crew/recovery_classification.py, reckon/crew/recovery_watch.py and a new test.

§8 — The pane emits only real transitions, in order, with a live age

Why. Several sessions reported noise rows:

  • X → X rows ("waiting → waiting", "in review → in review", "delivered → delivered") woke coordinators for nothing (imas-codex, nova-2e).
  • Rows arrived late and out of order; a needs-you stamped before a resume arrived after it (reckon-af).
  • Stale obligation rows carried an age frozen at 720 s, which made them look freshly observed (nova-2e).
  • "run-stalled 1" and "queued-awaiting-session" named no run (reckon-f3, imas-codex).

Done when. New tests, each failing at the base revision:

  • No row is emitted whose from-word and to-word are equal.
  • Rows for one run are emitted in the order of their observation times, and a row older than a later row already emitted for that run is dropped.
  • An obligation's age is measured from its own observation time at each read.
  • Every counted obligation names at least one run id.

The tests importing reckon.crew.ticker, reckon.crew.recovery_watch or reckon.crew.obligations add no failure against the base on all_debug. Write paths: reckon/crew/ticker.py, reckon/crew/recovery_watch.py, reckon/crew/obligations.py and a new test.

§9 — The hook's summary counts only what is owed

Why. nova-09's hook read "unreconciled runs: 3; work the list to empty before ending the turn" while its obligation list was empty. The three runs were two in-flight workers and one request awaiting upstream. nova-8e's hook has read "not current: no producer" on every prompt since 13 November for a session that has dispatched nothing.

Done when. New tests, each failing at the base revision. A session whose runs are all in flight or awaiting upstream prints no instruction to work a list. A session with no runs and no producer prints no staleness warning. The hook's count equals the number of obligations it lists. The tests importing reckon.hooks.coordinator_obligations add no failure against the base on all_debug. Write paths: reckon/hooks/coordinator_obligations.py and a new test.

§11 — A run-scoped gc touches only that run

Why. reckon crew gc --run <one review run> --apply printed "removed worktree trash" for two other sessions' runs (imas-codex-5a, 01:31Z). Nothing was lost because the trees were already in the trash, but a destructive command scoped to one run acted outside its scope.

An obligation held on purpose says so until its condition is met

Why. Moved out of §5 at its review. nova-3c spent about 20 turns restating why two obligations were correctly left open: a promotion that must wait for a re-review, and a worktree holding the only copy of an unmerged commit. Each one blocked every stop, because a coordinator has no way to say "held on purpose until X". crew ack silences an obligation outright, which is the opposite of what is wanted: the hold should stay visible and end on its own condition.

Done when. New tests, each failing at the base revision. A coordinator can hold a named obligation with a reason and an end condition or time. While held, the hook shows it as held with that reason and does not count it toward blocking a stop. It returns to the open list when the condition is met or the time passes. An obligation whose run changes state is released from its hold at once. The tests importing reckon.crew.obligations or reckon.hooks.coordinator_obligations add no failure against the base on all_debug. Write paths: reckon/crew/obligations.py, reckon/hooks/coordinator_obligations.py, reckon/crew_run_commands.py and a new test.

A due station reload fires within its bound however slow the ticks are

Why. On 15 November a station ran 100 minutes past several landings without reloading, the fix that would have made it fast among them, and reckon-f3 restarted it by hand twice. StationReloader in reckon/crew/station.py holds a due reload for at most RELOAD_HOLD_SECONDS while derivations land. But it polls only after a tick, so a tick several minutes long stretches the bound, and a deferred image restarts the hold whenever main moves. Each hold, defer and re-exec is now written to the station's log (e8871a04ee). This section makes the bound hold.

Done when. New tests, each failing at the base revision. A reload due while ticks take longer than the hold bound fires no later than one tick after the bound expires. A deferred image whose import later succeeds is re-tried on the next poll rather than waiting for main to move again. A reload due while no derivation is in flight fires at the first poll. tests/test_a_reload_lets_derivations_land.py keeps its cases. The tests importing reckon.crew.station add no failure against the base on all_debug. Write paths: reckon/crew/station.py and a new test.

A stopping station exits within a bound and hands its claims back

Why. Two of reckon-f3's three station restarts on 15 November needed SIGKILL after SIGTERM was ignored for 120 s. A killed station orphans every claim it holds: seven at 13:00Z, six of them other sessions'. One orphaned review then needed a hand discard and redispatch. The shutdown path waits on dispatch_claims.wait_for_dispatches_in_flight and the duties drain (DUTY_DRAIN_SECONDS) behind work stuck on storage.

Done when. New tests, each failing at the base revision. A station sent SIGTERM while a derivation and a dispatch are blocked exits within a stated bound. Every launch claim it holds that has not reached a worker is released so the queue can relaunch it, and every claim whose worker is running is left in place. The tests importing reckon.crew.station or reckon.crew.dispatch_claims add no failure against the base on all_debug. Write paths: reckon/crew/station.py, reckon/crew/dispatch_claims.py and a new test.

A resumed repair is never killed as a terminal run

Why. reckon-1e found a repair round started by folding review findings force-killed four minutes in (forced exit, reason terminal-run). The run's pointer still read phase complete from its earlier delivery, so the terminal-run guard in reckon/crew/dispatch_launch.py treated the live repair as finished. It left a half-written edit in the worktree, and the obligations view offered two remedies that were both wrong for a run mid-repair.

Done when. New tests, each failing at the base revision. A run resumed for a repair round, from a fold, a hand resume or the reflex, reads as working from its resume until its next delivery, and the terminal-run guard does not signal it. A run genuinely finished with no live attempt is still stopped as before. While a repair attempt is live, no obligation offers crew complete or crew repair --status complete for that run. The tests importing reckon.crew.dispatch_launch or reckon.crew.resumption add no failure against the base on all_debug. Write paths: reckon/crew/dispatch_launch.py, reckon/crew/resumption.py, reckon/crew/obligations.py and a new test.

A promotion refused because its inputs moved is judged again

Why. Three reckon runs on 15 November, history §21, §22 and §25, reached promotion-refused with "the run or its acceptance inputs changed while it was judged" (reckon/crew/recovery_review_acceptance.py). Nothing judged them again, and each needed a coordinator to land it by hand. reckon-af's alro-s2 was the same, after a dispose raced the reflex. The refusal is correct for the moment it describes, and the defect is that it ends the run's promotion rather than deferring it.

Done when. New tests, each failing at the base revision. A promotion refused because its inputs changed during the judgement is judged again on the next sweep against the new inputs, and lands if they pass. A run whose inputs keep changing is reported after a stated number of attempts, naming what moved. A run whose new inputs fail is refused on those inputs. While a repair attempt is live, the sweep does not attempt the promotion at all. The tests importing reckon.crew.recovery_review_acceptance add no failure against the base on all_debug. Write paths: reckon/crew/recovery_review_acceptance.py and a new test.

A resume started inside the station records its own worker, never the station

Why. nova-a1 found an attempt reservation, written by a recovery-sweep resume launched inside the station, naming the station's own pid (2178731) as the attempt's process. When that worker never spawned, the reservation held a live pid for as long as the station lived, so nothing could declare the attempt ended. Any coordinator command that signals a run's recorded pids, such as stop or discard, would have signalled the station, which holds every session's claims.

Done when. New tests, each failing at the base revision. A launch made inside a long-lived process records the supervisor or worker it started, never the launching process itself. No stop or discard signals a pid that belongs to the station, whatever a record names. A reservation naming a pid that is the reading host's station is read as not this run's process. The tests importing reckon.crew.dispatch_launch add no failure against the base on all_debug. Write paths: reckon/crew/dispatch_launch.py, reckon/crew/runs.py and a new test.
