§1 — Why

The ledger exists to calibrate effort and route work, but three of its measurement systems record the wrong quantity (fleet review §4/§8): worker_seconds is orchestrator wall-clock inferred from stream file mtime (nine stalled runs contribute 64 of 130 recorded hours), the per-run token counters are session-cumulative (summing over-reports 4.2×), and 86% of runs — including 21 of 25 non-passing ones — carry no outcome text. Everything downstream (effort calibration, the competence horizon, sprint capacity planning) consumes these numbers, so their repair gates the gate-signal work.

§2 — Deliverables

Worker time from the stream, not the clock. Derive duration from first-to-last stream event timestamps; record wall duration separately; flag a run stalled when wall exceeds a small multiple of its budget so aggregations can exclude it rather than average it in. Done when the 26.7-hour lockfile run's record distinguishes 45 minutes of work from a day of idle stream.

Per-run token deltas. On promotion, difference the session-cumulative counters against the previous run on the same session (keep the cumulative figures too, labelled). Done when summing per-run deltas over a multi-run session equals the session total.

One completion-source vocabulary. ledger.effort_report, capabilities.derive_capabilities and calibration._observation accept the same set, including provided (an explicit stamp is a good stamp); exclusion reasons are reported identically everywhere. Done when a run promoted with --completed-at appears in all three consumers.

Outcome discipline. crew complete refuses an empty --outcome when the gate is not passed. Done when the refusal has a test and the message says what to write.

Durable delivery by default. Auto-filled manifest paths already land in the durable run directory; make the dispatch surface warn when a caller-named manifest points into a tmpfs mount (248 of 259 recorded manifests do), and document the durable default as the recommended shape. Done when a tmpfs manifest path draws a warning naming the durable alternative.

Diff stats everywhere. changed_lines is recorded for every run with commits (the newest project records none), computed from recorded SHAs — never from a log path or a placeholder string; unresolvable inputs record a typed absence, not a git error string. Done when the twelve corrupted historical shapes are impossible to re-create.

Identifier normalization. Section identifiers normalize at write time (one canonical form); a redispatched node id gains a recorded lineage marker so retries are trackable. Done when cross-project section rollups see one vocabulary.
