A Lane Can Say Where It Stands

The subscription account publishes its own quota position, for free, on demand. Reckon does not read it. Instead it infers a position from worker streams, which stop arriving the moment nobody dispatches to that lane — so the reading decays exactly when a coordinator most wants to know whether it may start again. On the morning this plan was written the recorded claude reading was 186 hours old, the fence reported the lane clear, and the account was at 89 percent of its weekly window with a scoped window at 93 percent marked critical.

§1 — The fence is open, and it is open by construction

Every figure below was read on 2026-09-14 rather than recalled. The preflight surface already carries the complete shape a heartbeat needs — utilisation, burn multiple, projected exhaustion, seconds until reset, headroom and a threshold status, per horizon. Nothing is missing from the data model. What is missing is an input.

The chain that produces this is mechanical and each link was confirmed. No claude worker has been dispatched for days, because current work routes to other lanes. No claude worker means no claude stream. The quota position is emitted only inside a stream, as a rate-limit record, so no stream means no new reading. The stored reading ages past the policy's declared five-minute shelf life, is marked expired, and its headroom is correctly reduced to unknown. The fence then declines to hold, because absence of a signal is never read as exhaustion — which is the right rule. The result is a wave admitted at full width against a window the fence cannot see.

The policy declares evidence_shelf_life_minutes of five. The claude reading is past that by a factor of roughly two thousand, and the surface reports the lane clear. This is the failure that is silent rather than loud: a stale hold announces itself every time someone is refused, while a stale clearance says nothing at all until a wave is already spending.

§2 — The account answers for free, and the answer disagrees with the cache

The client publishes an account usage endpoint. Read with the credential already on this machine it answered in 0.27 seconds with 2018 bytes and consumed no model tokens at all — it is an account metadata read, not an inference request, and it is directly analogous to the surface the codex lanes already use. There is no cost to declare, no cadence to ration, and no reason a poll should be rare.

What it returns is richer than what the codex lanes offer. Several named windows, each with its own utilisation and reset time; a server-computed severity rather than a locally derived ceiling; an explicit flag naming which window is currently binding; and a scoped per-model window. That last field matters beyond this plan: the four codex lanes share one account reading and therefore cannot be fenced apart, while a scoped window makes per-lane fencing possible here.

There is also a copy of this block cached on disk by the client, and it is not a substitute. It carries its own fetch stamp, which is the one thing that makes it usable at all, and at the time of writing that stamp was 92 hours old and reported 53 and 60 percent against the live 38 and 89. The cache is a last-known position, not a heartbeat. It has a place in this design only as a fallback that is always rendered beside its age, never as a bare figure.

§3 — The probe belongs to the dialect, not to a shared data structure

The existing probe type models a request-response exchange written to a held-open standard input. Its own docstring explains why: that is what the one harness offering such a surface needs, because it serves over a line protocol and exits the moment its input closes. That assumption is now false. A second harness offers a surface over HTTP, and forcing an HTTP read into a structure whose fields are an argument vector and a list of protocol requests would distort both.

The change is to invert the relationship. Today a caller asks a dialect for a probe description and then executes it. Instead the dialect should be asked for the reading and should own its own transport — the line protocol for one, an HTTPS read for the other. The existing structure survives as an implementation detail of the dialect that needs it. The one thing that must not move is the failure contract: every way a reading can fail already funnels into a single place that returns an explicit unknown naming the reason, because a pre-flight must never be stopped by its own instrument. That funnel stays exactly where it is.

§4 — Parse strictly, because the silent failure runs toward headroom

This is an internal endpoint of the client rather than a published contract, so its shape can change without notice. The obvious failures are safe: a not-found, an unauthorised answer, an expired credential, a timeout. Each is loud, each is caught by the existing funnel, and each correctly produces an unknown that the fence declines to read as exhaustion.

The dangerous failure is the quiet one. A shape change that still parses, but yields a low utilisation, reads as headroom and opens the fence wider than reality. So the reader must require the named window and a numeric utilisation, and must return unknown rather than a default when either is absent. A missing field must never resolve to zero. This is the same asymmetry the fence already encodes at the policy level, applied one layer down at the parser, where it currently is not.

The credential itself needs the same treatment. It expires on the order of hours and carries a refresh token beside it. An expiry must produce an unknown reading, never a clear one, and never an exhausted one either — the honest answer when the instrument cannot read is that the position is not known.

§5 — The coordinator spends the window it is fencing

The account position already includes every consumer: dispatched workers, interactive sessions, and the coordinator running the wave. That is a property of the figure rather than a defect, and it corrects a natural assumption — the reading is not under-counting the coordinator, it is counting it and reckon simply cannot see the total. On the morning this plan was written the weekly window stood at 89 percent while no claude worker had run for days, so substantially all of that consumption was coordinator traffic.

The consequence for batch dispatch is specific and it runs in the dangerous direction. A wave sized to fill the remaining headroom leaves nothing for the coordinator that must survive the wave to audit manifests, merge commits, and record outcomes. If the coordinator is refused mid-wave, every worker's output is stranded in a worktree with nobody to land it — the workers succeed and the wave is lost. A reserve already exists for resume, which is a different quantity reserved for a different purpose. A coordinator reserve is not modelled at all.

The first version of that reserve should be declared rather than computed, with its reasoning recorded beside it. There is no measurement of coordinator burn rate on this machine, the client's own transcripts do not persist the quota position, and inventing a figure and presenting it as measured would be the precise error this plan exists to correct. Reading the account surface on a cadence is what makes the figure measurable later; the reserve is calibrated from that evidence once it exists, not before.

§5b — A utilisation figure inherits its denominator unless the reading pins one

Handed over by a peer coordinator on 2026-09-14 and verified here in source and against the committed ledger, because it constrains what the reader this plan adds is allowed to return. §4 argues that the dangerous parse failure is the quiet one, where a shape change still parses and yields a low utilisation. This is its mirror and it is already live: a figure that parses perfectly, is arithmetically self-consistent, and is measured against a window nothing enforces.

The local lane presents four different window figures as of this afternoon, and only the first governs a dispatch.

The mechanism is inheritance, not a hardcoded constant, which is why it survives review. The dialect reads contextWindow from the stream's own per-model usage entries and passes it through as the budget the run is measured against. The local lane speaks that dialect, so it reports the client's declared window rather than the serve's. Four consecutive committed rows read 71.0, 61.1, 63.7 and 63.7 percent against peak inputs of 142,037, 122,144, 127,415 and 127,335 — each one exactly that peak over 200,000.

This is the same defect as the inherited price, one field over. The dependent plan already records that this lane totals the highest dollar figure of any backend because it speaks a dialect whose per-token rates it has no claim to. The denominator is that fault repeated on the window, and it is quieter: a cost figure that ranks free hardware top of a spend table looks absurd on sight, while 63.7 percent of a context window looks exactly like a measurement.

The consequence for this plan is narrow and binding. Any utilisation this plan's reader returns must name the window it divided by and take it from the authority that enforces it, never from whatever the client happened to announce. A percentage whose denominator is unstated is not a reading, and the falsifier should include a case where the client announces one window while the configured lane declares another: the reading must follow the configured figure or return unknown, never split the difference and never silently prefer the announced one.

§6 — What this plan does not cover

The four codex lanes share one account reading and therefore report identical figures, while the configuration for one of them states that it has its own smaller meter which a single wave can exhaust. That is a real per-lane attribution defect and it is not repaired here; this plan establishes that a scoped per-model window exists and can be read, which is the evidence that work would build on.

Rendering the position in the fleet pane is also out of scope. A heartbeat shipped before the reading is fresh would display an unknown for every claude lane and one shared figure for four codex lanes, which is worse than no display: it looks live and says nothing. The display work is owned by the plans that already hold the pane and the meter, and it should follow this rather than accompany it.

Whether a lane whose only signal is the ledger can ever be a heartbeat is settled in the negative and needs no further work: such a reading is a by-product of dispatch and decays when dispatch stops. What those lanes need is not a fresher figure but an honest age beside the figure they have.

§ Decisions

Does the fence read the account's own severity, or reckon's configured ceiling?

The endpoint computes a severity per window and flags which window is binding. Reckon computes its own verdict from a utilisation ceiling and a reserve. Taking the account's severity means one authority and no drift, at the cost of a threshold this project does not control and cannot test against. Keeping the configured ceiling means the fence stays testable over the whole input domain, at the cost of two opinions about the same window.

Each input alone has a measured failure mode, and the composition is the only form that survives either one being wrong. The account reports on whichever horizon it chooses: on 2026-09-14 claude-opus read utilisation 1.21 percent, which is the calendar-month overage resetting on 2026-10-01 and not the window that gates a request, while a sibling record on the same family carried a five-hour figure that had already expired. Fencing on the account figure alone therefore admits work against a number describing a different period. Reckon's configured ceiling is knowable and stable but blind to a severity the account raises before its own number looks bad. Holding at the ceiling, never looser than the account's severity, takes the protection from whichever input is currently telling the truth.

Do the three claude lanes map onto scoped per-model windows now, or share the account-wide figure first?

A scoped window is the only way a lane can be fenced separately from its siblings, and the account-wide figure will hold a lane that has headroom of its own. Mapping now needs a rule from lane to model identity that the endpoint names only by display label, which is a weaker join than a model id and may not resolve for every lane. Sharing the account-wide figure first is always correct and never precise.

Ship the figure that is observed rather than the structure that would be tidy. There is no evidence that per-model claude windows exist: on 2026-09-14 both claude and claude-haiku reported headroom unknown from unattributed ledger records, so a scoped mapping would be inventing a shape nobody has seen. The opposite shape is measured on the same host - codex, codex-luna, codex-spark and codex-terra all reported identical utilisation of 7 percent and an identical reset time, which is one account window serving four declared lanes. Scoping now would also reintroduce the error this plan is named against, reporting a position inferred from configuration rather than read from the account. Scope later if a per-model window is ever actually observed.

§ Followups

Read the account surface, and make a stale reading say its own age

Settle both decisions first; each changes what the reader returns and what the fence does with it. Then give the claude dialect its own reading over the account surface, move transport ownership to the dialect while leaving the failure funnel where it is, parse strictly so that an unrecognised shape returns unknown rather than a low utilisation, fall back to the on-disk cache only with its fetch age attached, and add a declared coordinator reserve with its reasoning recorded beside it. The falsifier must range over the input domain rather than over the lanes currently configured: a reading older than the shelf life must fail to clear at any utilisation on any lane, including one absent from today's configuration. Write the quiet half before dispatch — a fresh reading below the ceiling clears, and does not re-read inside the cadence.
