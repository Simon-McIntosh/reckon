§1 — A paired shadow resolves against the backend it names

reckon crew dispatch --pair-backend <backend> refuses every pair backend except the one the node's role already resolves to. The nova session reproduced it three times on 2026-10-17 as dry runs with --pair-backend codex, while the host flight's default_backend is clive: 

candidate backend 'codex' resolved to 'clive'; route the node explicitly to the candidate
Resolve with `reckon crew shadow --backend <candidate>` after correcting the flight override.

The cause is in reckon/crew/dispatch.py at main 7f1f83c6e. dispatch_pair (line 686) passes the dispatch's own config, unmodified, to _shadow_dispatch_config (line 465). That function calls resolve_role(config, node.role, node.spec_level) at line 474. With nothing routing the role to the candidate, that call returns the role's configured backend or the flight's default_backend. It then refuses with D21 whenever that name differs from the candidate. crew shadow never trips the check, because reckon/crew_dispatch_commands.py:2070 first adds roles.<role>.backend=<candidate> and roles.<role>.by_spec_level.<level>.backend=<candidate> to the flight overrides. dispatch_pair has no such step.

The tests did not catch it. tests/test_a_paired_dispatch_hides_each_arm.py builds its config with _candidate_config (line 85), which routes the implement role itself to the pair backend at line 94. So in every paired test, both arms resolve to candidate and the comparison always matches.

The refusal's remedy also misleads. D21's remedy in reckon/crew/refusals.py (line 81) says to run reckon crew shadow --backend <candidate> "after correcting the flight override". That is wrong for a paired dispatch. The nova flight has no override layer at all (crew(view="flight") reports override: present false), so the coordinator searched for a layer that does not exist. The lead read the refusal as a limit on codex. Until this lands, nova dispatches deep nodes unpaired.

Remedy. Resolve the shadow arm against the backend it names, in the one function both callers share:

  • In _shadow_dispatch_config, replace the resolve_role call and the equality check with resolve_role_override(config, node.role, node.spec_level, candidate_backend) (reckon/crew/routing.py:195). That function already exists to resolve a role's overlays against a named backend. The role and spec-level overlays still apply, so the effort and sandbox inheritance that follows is unchanged. The host flight's role overlays name only sandbox and effort, so no clive-specific setting carries onto another backend.
  • Keep D21 for the one case that remains: a candidate that no layer defines. _effective_backend (reckon/crew/routing.py:126) already raises CrewError naming the backend and listing the defined ones. Raise D21 with that text as its detail. Catch it in _shadow_dispatch_config, not in the shared resolver. resolve_role_override has five other callers (reckon/crew/dispatch_plan.py:425, reckon/crew/dispatch_admission.py:409 and :1515, reckon/crew/picker/snapshot.py:1030, reckon/crew/routing.py:373), resolve_role shares _effective_backend as well, and none of those is a shadow. D21 names the shadow's candidate, so raising it in the resolver would give the budget-fallback, admission and picker paths a refusal that does not describe them.
  • Rewrite D21's remedy in reckon/crew/refusals.py so it names the real fix for both verbs: pass a backend declared under backends in the flight, to --pair-backend or crew shadow --backend. It must not mention a flight override.
  • Change nothing else. In particular, leave the primary arm's routing, the overrides crew shadow adds, and the fence and mask composition as they are. The overrides crew shadow adds become redundant but stay harmless.

Write paths: reckon/crew/dispatch.py, reckon/crew/refusals.py, and tests/test_a_paired_shadow_runs_on_its_named_backend.py, which is new.
