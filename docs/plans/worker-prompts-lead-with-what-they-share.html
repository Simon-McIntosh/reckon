§1 — The measurement

Eight worker prompts, captured from four projects dispatched within one hour on 2026-09-15, are between 7,847 and 13,363 bytes each. Any two of them are 88% identical. They share a 152-byte prefix.

The cause is placement, not content. The prompt opens with 152 bytes of fixed preamble, then emits NODE <id> and GOAL <text> — both variable length — and only then the contract, the fences, the manifest template and the write scope, all of which are near-identical across every worker. §2 — Why this costs the served lane

Prefix caching matches blocks from position 0 while bytes are identical. The serve owner demonstrated the engine's behaviour directly: sending one novel prompt and then the identical prompt again returned 27.4% then 90.8% hit rate. The mechanism works perfectly the moment a prefix repeats.

The fleet average sits at 28.2% instead, measured at 369,774,336 hits against 1,310,811,845 queries. That is not an engine defect and no pool size changes it — the engine cannot hit on a prefix nobody has sent before. Reckon supplies 88% repeated content arranged so that almost none of it repeats as a prefix, and the lane spends 18,863 of 22,557 tok/s of prefill recomputing prefixes it has already built.

What was excluded. A larger KV pool was proposed and dropped: occupancy runs 0.29–0.50 with preemptions 0 and waiting 0, and the memory fraction that would enlarge it re-arms a lazily-allocated fused-MoE workspace that killed the serve at 256 concurrent. Shedding workers was also excluded — draining the fleet from 36 to 20 concurrent requests moved aggregate throughput 198 to 190 tok/s, and three long-running nodes measured 13.9 tool calls per ten-minute bucket at ~35 live workers against 16.5 at ~19–23, a 19% rise where a concurrency explanation predicts roughly double.

§3 — Reorder the prompt, and gate it on byte identity

Emit the invariant contract first, byte-identical across every worker, and the node-specific fields after it. Nothing is rewritten; the same text is composed in a different order.

The failure mode that would make this silently worthless is a single varying byte inside the block that is supposed to be invariant. A timestamp, an absolute path, a set iteration order or a dict ordering anywhere inside it destroys the prefix it exists to create — and the result still reviews as correct, because the prompt reads exactly as intended. The gate is therefore not "the tests pass" but a direct comparison of rendered output.

Done when two prompts rendered for different nodes in different projects are byte-identical up to the declared boundary offset, asserted by a test that fails when any variable value is moved ahead of it; and the measured shared prefix across a fresh set of captured prompts is materially larger than 152 bytes, with the new figure stated as a number.

Landed: reckon/crew/prompts.py now emits the unconditional contracts before variable node data. Three fresh prompts share 1,311 bytes through the declared boundary, up from 152; the focused prompt contract suite passed 36 tests. Full record: § contract-prefix evidence (commit 59526eb).

§4 — The measurement contract

The before-half is already secured and does not expire: the shared-prefix bytes above were computed from the captured prompt files themselves, which is deterministic, immune to cache state and ambient load, and repeats byte-identically after the change.

An endpoint replay was considered and rejected on arithmetic rather than preference: a 12 KB prompt is roughly 88 block queries against 1,164,295 ambient queries in a 45-second window, so the signal is 0.0076% of the noise, and the engine returns prompt_tokens_details: null so no per-request attribution is available on this build. A de-biased measurement of a quantity below the noise floor is still noise.

Refutation. After the reordering, the same byte computation on freshly captured prompts must show a materially larger shared prefix. No movement refutes the placement hypothesis and the plan closes as a negative result.

What this measurement does not claim. The 152-byte figure bounds the cross-worker shared prefix on a first turn. Each turn's context grows as a conversation extends, so the initial prompt is a shrinking fraction of the prefix as a run progresses, and a fleet whose live runs are mostly hours old — measured at thirteen of fifteen over two hours, median 2.8 h — will show a smaller fleet-wide gain than the prefix ratio alone suggests. A real but much smaller improvement is consistent with the hypothesis, not against it.

§ Decisions

Where does the invariant boundary sit — after the full contract, or after the contract plus the fences?

Everything ahead of the boundary must be byte-identical across every worker in every project. A longer invariant block caches more, and each additional section is another place a varying value can hide and silently destroy the prefix.
