§1 — Why: the record is the conflict

Three of the five surveyed coordinators rank merge conflicts in the append-only plan and evidence HTML among their largest wall-clock costs — "nearly every merge, always a mechanical union" (s21), "the single worst conflict generator" (s23) — and the imas-ambix coordinator reports the same (crew pattern review §3). The cause is the default write scope: dispatch widens every node to its plan's HTML file, the plan's cumulative evidence record and one figure directory named after the plan. The review's own six study nodes, dispatched against one plan with six disjoint data directories, were each granted all three of those shared paths (§9), so six parallel nodes produce six conflicting appends by construction.

The worker authoring its own record is right and stays (worker-authors-its-own-record); the append_evidence op already landed (a-landing-beat-needs-no-hand-edit §2). What is wrong is that the record the worker authors is a region of a file every other worker also edits.

§2 — Each node's default scope is its own fragment

Deliverable. Dispatch grants a node, by default, docs/evidence/fragments/<plan>/<node>.html for its evidence anchor and docs/figures/<plan>/<node>/ for figures, and no longer grants the shared plan HTML, the shared cumulative record or the plan-wide figure directory. The worker prompt names the fragment path where it named the record. The node's plan comment moves to one landing: line in its manifest.

Done when a dry-run of six nodes against one plan reports six disjoint default scopes, and a test fails if any default scope contains a path another concurrent node's default scope contains.

§3 — The record is assembled, never merged

Deliverable. Reading a plan's cumulative evidence record composes the authored record with its fragments in promotion order, so the SPA, read_plan and audit-doc see one document; and promotion writes each node's manifest landing: line to the plan as a comment through the versioned edit_plan path rather than through a git merge.

Done when this review's six study branches, replayed onto a scratch copy of the base with fragment scopes, merge with zero conflicts in docs/plans and docs/evidence (measured with git merge-tree), and the composed record renders every anchor.

§4 — Existing records keep working

Deliverable. A cumulative record with authored anchors and no fragments renders exactly as today; a record with both renders the authored anchors first. No existing record is rewritten.

Done when the rendered bytes of every existing docs/evidence/archive/*-landed.html in reckon are unchanged by the composition, checked by a test over the current tree.
