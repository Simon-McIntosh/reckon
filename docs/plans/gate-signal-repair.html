§1 — Why

Dispatch has two admission gates and neither currently tells the truth (fleet review §4/§5). The budget gate has never held a wave in 259 runs because codex — the backend doing nearly all the work — publishes no headroom on its stream, and its working off-stream probe is disabled by an unset flag. The competence gate divides estimated hours by a speed factor measured in the wrong units, judges every node by its whole plan's estimate, reads a cache frozen since the fleet's second day, and reports its refusals as configuration errors with the structured verdict discarded. Depends on run-measurement-truth: the calibration inputs must be true before the gate derived from them can be.

§2 — Competence gate

Units. One definition of speed (document its direction), applied so the compared quantities share units; node-level estimates come from the node (a dispatch-surface hours input), falling back to plan hours only with an explicit provenance label. Done when the gate's refusal threshold equals the horizon it names, under test with both calibration directions.

Cache lifecycle. Staleness check against recorded ledger versions, a CLI to rebuild and inspect (reckon capabilities or a crew subcommand), and rebuilds off the dispatch path. Done when a ledger append invalidates, and first dispatch never triggers a synchronous all-repo scan.

Verdict surfacing. A competence refusal exits with its own documented code and the structured verdict (including target size) in the payload, mirroring the budget hold; --dry-run runs the same check so wave validation and real dispatch agree. Done when the CLI help enumerates it and dry-run parity has a test.

§3 — Budget gate

Honest readings. A headroom block claims known only with a numeric utilisation (an empty rate-limit mapping is a silence, not a measurement); the window identity (rate-limit type/period) is retained so a monthly reading cannot silently pin a five-hour decision; the stream-evidence attribution fallback is updated in the same change since it keys on the current lax signature. Done when an empty-known block no longer displaces a real reading, under test.

Codex headroom. Enable the account-limits probe path for codex (budget_check), with a probe-once-per-wave shape: _budget_verdict accepts a caller-supplied state so preflight probes once and the wave's dispatches reuse it instead of paying a ≤20 s probe each. Done when a codex preflight reports numeric utilisation on this workstation and a wave of three dispatches runs one probe.

Policy reaches every path. CLI resume resolves flight config like observe does (ceiling, reserve and exhausted-statuses apply); a ledger bookkeeping failure while recording a budget check degrades to a warning in the payload instead of aborting the dispatch whose budget was fine. Done when both have tests.

§ Decisions

Should the codex account-limits probe be on by default once the once-per-wave shape exists?

On: the pre-flight finally guards the backend doing all the work, at one ≤20 s probe per wave. Off: zero dispatch latency, but the budget gate stays structurally blind for codex and the flag must be set per host.

Lead decision 2026-08-17: this workstation runs codex on a 20x weekly subscription and does not approach limits, so the shipped default stays zero-latency; the probe path ships working with the once-per-wave shape and is enabled per host via budget_check, documented loudly.
