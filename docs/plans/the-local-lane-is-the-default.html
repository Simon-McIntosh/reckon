§2 — Route by backend and model, not by per-model lane

The lead's routing model. A backend is a provider: clive (Claude Code against the locally served model), codex, and claude. A dispatch names a backend, a model, both, or neither:

  • Neither: the default backend (clive) is used, and crew picks the model and effort from the task.
  • A backend: crew picks the member model within it from the task, as crew-effort-routing already does for effort.
  • A model: it implies its backend. A model named without a version resolves to the latest version implemented in the flight config.
  • Both: they must agree, or the dispatch refuses.

Today the flight config has per-model entries (codex = gpt-5.6-sol, codex-luna, codex-terra, codex-astra, codex-spark, claude = sonnet-5, claude-opus, claude-haiku), and crew dispatch has --backend but no --model. The change collapses them into three backends, each listing its models, and adds --model. The selection logic lives in crew and never in a skill, so a skill carries no lane or model table. An orchestrator names a backend, or a model only when the lead has explicitly asked for one.

Landed as an interim: default_backend: clive in the host flight layer (dotfiles fe1d648).

Done when the flight schema declares backends with member models, and crew dispatch accepts --model, including an unversioned model resolving to the latest implemented version. §3 — Escalation is named, paced, and claude needs permission

The local lane is the default. An orchestrator may escalate a genuinely hard node by naming a paid backend, and states why in the dispatch. It paces escalations by the paid backends' published headroom (§5): it escalates when the backend reads open, holds back when it reads pace, and does not escalate when it reads hold. The claude backend requires the lead's explicit permission, because it is the account the orchestrators themselves run on. Dispatch to it refuses unless the call carries the permission as a quoted reason (for example --permission "<the lead's words>"), which is recorded on the run.

Done when a claude dispatch without a permission reason refuses, and one with it records the reason. A paid-backend dispatch records the escalation reason. The build skill's lane section is reduced to these rules and points at crew for everything else.

§4 — No silent fallback

A review whose local attempt failed falls back to the next backend in an explicit, ordered review_fallback list, which is clive then codex on this host. It never walks the configured backends alphabetically, and it never reaches claude. With every candidate spent, the review waits for its lane. The same rule applies to producers and resumptions.

§5 — Paid-backend headroom is observed continuously and published

Headroom for a paid backend is read only when someone runs preflight or dispatch, from sources that can disagree and can be a day old. The fix mirrors what the local lane already has in lane.json. A small observer publishes one document per account, for example ~/public/reckon/paid-lanes.json. It carries each window (five-hour and seven-day): utilisation, reset time, burn multiple, projected exhaustion, the source, and an observed_at. It reconciles its sources by recency and reports which one it used. Preflight and dispatch read that document. A value too old is reported as stale for that field alone, and one missing precondition no longer turns every field to unknown. The claude backend is read from the rate_limit_event records its own streams already carry.

§7 — One follower for the whole session

The host kills every Monitor at 30 minutes, so a follower armed that way is dropped and re-armed all session. It is the host's limit, not reckon's, but reckon can stop depending on it. crew follow --until-actionable exits on the first transition that needs the orchestrator, printing it. The harness's background-task primitive carries no time limit and wakes the session when the command exits. So one follower then waits across the whole session, wakes it only for work, and is re-armed only after a real event. The owner check that landed today (74c1c5fe) means a follower whose session has gone exits instead of orphaning.

Done when a session keeps one follower for more than two hours with no re-arm except after an actionable event. The harness reference for Claude Code documents the form, and a feedback item asks the host for a Monitor with no time limit.
