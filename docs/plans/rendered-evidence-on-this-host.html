§1 — Why this exists as its own plan

Every rendered gate in this repository is currently unprovable, and the cause is a host condition rather than any repository's code. The sprint-surface rebuild finished with seven sections landed on browser-free evidence and a list of captures it could not take. Those captures are real obligations, but hanging them on a completed plan would hide them: roadmap excludes a completed plan from pending work, so the followup would render on the page and appear nowhere anyone looks to decide what to do next.

They are also not that plan's work. The fault affects every rendered gate in the project, so it needs an owner of its own rather than a corner of a surface plan.

§6 — A bounded rendered capability exists, and four of the six captures do not need the host fixed

§4 was authored on the premise that the captures are worthless before a browser works. The trace above narrows that premise rather than confirming it. What is broken is exactly one thing — the Network Service never creates an Internet socket — and file: and data: URLs load in about 0.4 s on the same binary. That split has already been used productively here: inlining every served script into one self-contained HTML file and loading it over file: reproduced the SPA blank page and surfaced Uncaught ReferenceError: useState is not defined in seconds, after that same defect had survived a compiled-AST ownership check, a duplicate-declaration check, an export inventory and three node evaluation harnesses.

The shared harness cannot use it as it stands, because it serves the SPA over http://127.0.0.1 on an ephemeral port — the one thing the browser cannot reach. The bounded capability is therefore a second delivery path in the harness rather than a second harness: inline the composed project state and every script into one document and open it over file:. State that arrives inlined is state the page never fetches, which is what makes a populated render possible without a network.

What this reaches, and what it honestly does not. A capture needing only composed state and layout is takeable now; a capture whose subject is a live fetch is not, and remains owed against the host change.

§5 — What is already in place, so it is not rebuilt

Two mechanisms landed while this fault was being diagnosed, and they are why the fault is now visible rather than silent. A failed probe classifies as ceiling-exhausted, sandbox-denied or navigation-never-completed and reports the browser's stderr with the inotify count against the limit. And every browser-dependent case across seven test modules skips with that stated reason rather than accumulating as an opaque timeout — 28 cases, down from 11 opaque failures to zero, with a boundary regression proving an AssertionError is still never converted into a skip.

So this plan starts from a suite that is honest about what it cannot run. Do not remove those skips to "restore coverage": they are what makes the debt visible, and the boundary regression is what stops them becoming a blindfold.

§ Decisions

The surface plan landed seven sections on browser-free evidence and cannot take its own captures. A followup on a completed plan is excluded from roadmap 's pending work, so it would render on the page and be invisible everywhere a reader decides what to do next.

Locked at authoring. A followup on a completed plan is the documented way to lose work while leaving a paper trail that looks like tracking. Keeping the surface plan active would be honest but wrong in a different way: its seven sections are done, and holding it open on a host condition it does not own would misreport both its state and the reason. The fault is shared, so the owner should be too.

Reframing this plan's subject, from a cross-session review of the cleared baseline. The host fault presented in THREE forms across the 24 measured failures, and only one of them was legible as itself: 28 cases skipped honestly with a stated reason, 13 failed opaquely as TimeoutExpired outside the classifier's wrap, and 2 more were filed as stale assertions predating the window when in truth their claim had never been decided either way — their harness could not reach the surface, so nothing was ever exercised. The durable statement, and it is wider than this plan: A TEST WHOSE SUBJECT WAS NEVER ACTUALLY EXERCISED IS INDISTINGUISHABLE FROM A TEST WHOSE SUBJECT REGRESSED, UNTIL THE RENDER PATH WORKS. Calling that second class stale flatters it. This changes what the plan's value is. Clearing 24 red tests is the visible outcome; making the class decidable is the one that matters, because an undecidable test is worse than a failing one — it accrues silently and every reader who meets it has to re-derive whether it means anything. That is the same defect as an unread log or a guard that never runs, and it is why §6's file-URL path counts for more than the captures it unblocks.
