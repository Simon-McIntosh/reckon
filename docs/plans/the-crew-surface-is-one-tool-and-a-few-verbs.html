§1 — Why: a refusal per guard, and verbs that outlive their skills

At d8ff471c9 the reckon CLI has 80 leaf commands carrying 398 options. crew dispatch takes 44 options and crew complete 25. In the four days before 2026-10-19, coordinators called complete 3,754 times and dispatch 2,972 times, read their help about 150 times, and still reached for retired verbs: crew review-plan 263 times after its alias was retired in 18739912f. Thirty-one leaves were never invoked by a coordinator (census).

The fifteen coordinator reports describe what that costs (themes):

  • complete refuses one guard per call and has no dry run. Five promotion refusals cost about twelve turns.
  • complete asks again for the gate command, exit status and log path the worker's manifest already carries.
  • Landing one run takes five to seven commands: complete, merge, check, push, release.
  • Reopening a delivered run takes three verbs: repair-status, widen, resume.
  • Identity flags differ by verb. dispatch needs --project and complete rejects it; merge has no --run.

On 2026-10-19 the lead set the direction:

  • The coordinator's surface is the crew MCP tool, which every-plan-write-goes-through-edit-plan §3 keeps on current code.
  • The CLI remains the transport for workers, hooks and services, with its families folded behind flags.
  • A retired or folded name becomes a tombstone that names its successor.

The fold this plan delivers is below. Each change has its own section. A row moves only when its section's measure holds, and none moves when the old name still has a consumer it would break (§6).

§2 — A retired or folded verb names its successor

Deliverable. Add a tombstone registry, reckon/crew/tombstones.py. Each row maps a retired name to its successor invocation, and each row is registered on the crew group as a hidden command that accepts any arguments. Invoking one writes nothing. It prints one JSON document naming the retired verb, its successor and the successor invocation, with the caller's --run, --project, --plan and similar arguments carried across where they map. It then exits with one distinct exit code, which the crew group's help documents beside codes 0 to 8. Seed the registry with three rows:

  • review-plan → crew review --plan
  • obligations → the MCP crew(view="obligations"), with no CLI twin, by the lead's decision
  • promote → crew complete

Sections §4, §6 and §7 add their own rows.

Done when tests/test_a_retired_verb_names_its_successor.py checks four things. Each row exits with the documented code and prints its successor. No row appears in reckon crew --help. reckon crew review-plan --plan p --answer f --acted prints reckon crew review --plan p --answer f --acted. Every row's successor resolves: a CLI successor in the live command tree, and an MCP successor among the views and actions the crew tool accepts. The negative control adds a row whose successor names a verb the CLI does not have, and the test then fails naming it. tests/test_cited_commands_exist.py also refuses a skill or reference citation that resolves to a tombstone, naming the citation and its successor, so every later fold must repoint the citations of the names it retires. The help-contract tests that read the crew group's help pass unchanged. Write paths: reckon/crew/tombstones.py, reckon/crew_dispatch_commands.py, tests/test_a_retired_verb_names_its_successor.py, tests/test_cited_commands_exist.py.

§3 — crew complete reads the manifest's gate receipt, and its dry run lists every refusal

Why. Seven reports describe the same loop: complete refuses one guard per call and there is no way to ask for all of them at once. Flags that take a reason (--no-commit, --no-impl-change, the --waive-* family) swallow the next flag when the reason is left out. The manifest fill already exists. promotion_records.py fills a passing promotion's gate flags from the worker's manifest (tests, test_logs, commits), while an explicit flag wins. reports.py parses the manifest and reads only an end-of-log EXIT= line. promotion_scope.py refuses a commit that does not resolve. Yet three coordinators still supplied the gate command, status and log by hand on every promotion, one because the worker's tests: field was prose.

Deliverable. Three changes, each extending the owners above rather than adding a module:

  • Measure, over the manifests of the runs promoted in the last seven days, how often the existing fill applied and why it did not, and repair the cause the measurement names. The repair goes in the fill, or in how the dispatch contract tells workers to write the receipt fields.
  • A reason-taking flag refuses a value that begins with --.
  • --dry-run evaluates every guard without writing. It returns all of their failures together, and the one invocation that would pass for the run's state: review attached or not, impl moved or not, gate passing or failing.

Done when tests/test_complete_reports_every_refusal.py passes three cases on a temporary project. --dry-run on a run that fails three guards lists all three in one answer, with an invocation that then promotes. --no-commit --gate passed is refused as a missing reason. A run whose manifest carries the receipt in the contracted form promotes with no gate flags. The evidence gives the fill rate on the measured manifests before and after the repair. The negative control makes the dry run return only its first failure, and the three-guard case then fails. tests/test_every_module_fits_a_worker_window.py passes. Write paths: reckon/crew_run_commands.py, reckon/crew/promotion.py, reckon/crew/promotion_records.py, reckon/crew/promotion_gate.py, reckon/crew/reports.py, reckon/crew/prompts.py, tests/test_complete_reports_every_refusal.py.

§4 — One call lands a run

Why. Four reports keep a scratch script that lands a run. One ran it about forty times a session. The script completes the run and merges its reviewed head without touching the shared index. It checks that the change survived the merge, pushes over the port a compute node allows, and releases the worktree.

Deliverable. crew complete --land adds no module. It calls a land function beside land_merge in reckon/crew/merge.py, which already builds the merge without the shared index and pushes with the port-443 fallback. It then calls the existing release after promotion, _release_after_promotion in reckon/crew/promotion_release.py, which removes the worktree through gc. The one new step is the content-survival check between merge and push: the primary branch's copy must carry a marker the change introduced and lack any marker it removed. Each step reports, and a failed step stops the call and names the command that resumes from it.

Before removing anything, the node reads the ledger for crew merge landings of heads that no run produced. The evidence records how many landed in the last thirty days. §7 tombstones crew merge, naming crew complete --land, when that count is zero, and otherwise leaves it as the form for a head with no run. This node registers no tombstone.

Done when tests/test_one_call_lands_a_run.py builds a temporary repository with a bare remote and a finished run, and calls complete --land on it. The primary branch then carries the change's marker, the remote ref equals the local one, and the worktree is gone. The negative control resolves the merge so that the change is dropped; the marker check refuses, and nothing is pushed. Write paths: reckon/crew_run_commands.py, reckon/crew/merge.py, reckon/crew/promotion_release.py, tests/test_one_call_lands_a_run.py.

§5 — The crew MCP tool carries the coordinator's write verbs

Why. The crew tool is already one tool over read views and four recovery actions. The verbs a coordinator calls most still go through Bash, with argument quoting, help lookups and a timeout that can kill a call after it has written. Once the server serves current code (every-plan-write-goes-through-edit-plan §3), the tool can carry them.

Deliverable. crew(action=…) accepts eight more actions: complete, land, dispose, ack, answer (a plan-review finding), widen, stop and discard. Each one calls the function its CLI verb calls, with the same arguments, and returns the same JSON. A refused complete or land carries every failing guard, from §3's evaluation. The tool's description names each action's parameters. The commands the obligations view prints use the action form.

Done when tests/test_crew_tool_carries_the_write_verbs.py runs each action through the MCP tool and through the CLI on copies of one temporary project, and asserts the two answers are equal. Parity is held by comparing the surfaces. The negative control maps one action's argument differently from its CLI counterpart, and that parity case then fails. tests/test_every_module_fits_a_worker_window.py passes. Write paths: reckon/mcp.py, reckon/_mcp_tools.py, reckon/mcp_crew_actions.py, reckon/crew/obligations.py, tests/test_crew_tool_carries_the_write_verbs.py.

§6 — The read verbs become one crew view

Deliverable. crew view <name> serves every view the MCP crew tool serves, through one function both call. No such function exists yet: _crew in reckon/mcp.py dispatches its views inline, and crew list builds its own rows. So the view dispatch moves into reckon/mcp_views.py, and crew list's row builder is retired in its favour. It is the transport for hooks and scripts. list, ledger, directory, drain and velocity each become a tombstone naming its view.

Other repositories call these verbs, and consumers-read-reckon-through-verbs made their JSON a contract. So the node first lists every invocation of the five verbs in the tracked files of every mounted project.

  • Reckon's own callers are migrated in the same node.
  • A foreign caller is named in the evidence with its file and line, and gets a followup on its owning project.
  • A verb with a foreign caller stays visible until that caller migrates, its help naming crew view as successor. It is tombstoned only then.

Done when tests/test_crew_view_serves_every_view.py checks that, for each view, crew view prints what the MCP tool returns for the same arguments, and that each tombstoned verb exits with §2's code. The census of callers is in the evidence. Every citation of the five verbs in reckon's skills and agent files is repointed to crew view, and tests/test_cited_commands_exist.py passes, which it cannot while a citation names a tombstone. The negative control registers a view on the MCP tool only, and the parity case then fails naming it. Write paths: reckon/crew_run_commands.py, reckon/mcp.py, reckon/mcp_views.py, reckon/crew/tombstones.py, reckon/hooks, skills/reckon-build/SKILL.md, skills/reckon-build/references/coordinator-reference.md, skills/reckon-build/references/sprint-orchestration.md, skills/reckon-review/SKILL.md, reckon/crew/AGENTS.md, tests/test_crew_view_serves_every_view.py.

§7 — The verb families fold behind flags

Deliverable. Apply the §7 rows of §1's table:

  • crew repair --status|--review.
  • crew budget --lift|--list|--reset|--check.
  • crew check --manifest|--review; --review accepts --run.
  • crew resume --ready, crew resume --backend B --model M, and crew resume --reopen --write-path P. --model is what redispatch lacked; --reopen replaces repair-status, widen and resume.

§8 — Every run verb takes one identity grammar

Deliverable.

  • Every verb that takes --run also accepts --project, and refuses one that disagrees with the run's.
  • dispose stops requiring --project.
  • crew review returns one run id to complete, and names the other only as provenance.
  • crew review --answer accepts --review-run. Without it, a finding id carried by two covering reviews is refused, naming both, instead of landing on one of them.

Done when tests/test_run_verbs_share_one_identity_grammar.py invokes every --run verb with a matching --project and a disagreeing one, and asserts the first is accepted and the second refused. It also drives the repeated-finding answer both ways. The negative control drops --project from one verb's options, and the sweep then fails naming it. Write paths: reckon/crew_run_commands.py, reckon/crew_dispatch_commands.py, reckon/crew/plan_review.py, tests/test_run_verbs_share_one_identity_grammar.py.

§ Decisions

Where does the coordinator's consolidated surface live?

Locked by the lead on 2026-10-19 after the coordinator reports: centralise in MCP once the server serves current code, rather than maintain a second surface for every coordinator verb.

What happens to a CLI name that is retired or folded into another verb's flag?

Locked by the lead on 2026-10-19. Long-lived sessions carry skill text loaded before a retirement; a tombstone corrects them in one turn without keeping the old surface alive.
