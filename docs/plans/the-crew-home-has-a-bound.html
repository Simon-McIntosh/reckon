§2 — A ledger index whose checkout is gone is swept

Deliverable. Each ledger index records, in a metadata table written when it is built, the ledger path it indexes. reckon crew gc reports, and with --apply removes, every ledger-*.sqlite in the pick-input cache root whose recorded ledger path no longer exists, and every one that records no path and was not opened in seven days. Removal prints each path and its size; nothing is removed silently, and an index locked by a live process is never removed. The index stays keyed per checkout, because each checkout has its own ledger files and its freshness stamp is the ledger file's identity (reckon/ledger.py:850-916), so one index shared by several checkouts would be invalidated on every switch between them. The cache location is unchanged, because the same pick-input kind also holds the picker's picker-*.json files (reckon/capabilities.py:1190), which the sweep does not match.

Done when tests/test_gc_sweeps_ledger_indexes.py seeds a temporary cache root with two indexes recording ledger paths that have been deleted, one recording a live ledger path, one recording no path with an mtime eight days old, and one picker-x.json, and asserts gc reports exactly the two orphans and the old unrecorded index, and gc --apply removes exactly those three, leaving the live index and the picker file. An index built through the ledger reader records its path. The cache root is a temporary path and the test asserts the real ~/.cache/reckon is untouched. The negative control is executed and logged: with the existence check removed, the live index is reported and the test fails. The pick and ledger tests pass, their list built at dispatch from the head tree. Write paths: reckon/ledger.py, reckon/crew/routing.py, tests/test_gc_sweeps_ledger_indexes.py.

§3 — gc reaches reports, locks and run directories with no ledger row

Deliverable. garbage_collect (reckon/crew/routing.py:1520) gains three row sets, each reported by default and acted on only with --apply, each re-checking for a live pointer immediately before acting, as the pointer reap already does: report trees under reports/<project>/ whose newest file is older than the run retention and whose run is not live; lock files whose run is in the ledger, not live and past retention; and run directories with neither a ledger row nor a live pointer, past retention. Every removal prints its path and size. The existing plan-review sweep is folded into the report row set rather than kept beside it.

Done when tests/test_gc_reaches_every_crew_store.py builds a temporary crew home holding, for each row set, one entry past retention and one inside it, plus one past-retention entry whose run has a live pointer, and asserts gc reports exactly the three past-retention entries without a live pointer and gc --apply removes exactly those, printing each. The negative control is executed and logged: with the live-pointer re-check removed, the live run's entry is reported and the test fails. The existing gc tests pass. Write paths: reckon/crew/routing.py, tests/test_gc_reaches_every_crew_store.py. This section runs after §2, which also writes routing.py.

§4 — A run's captured file has a size limit

Deliverable. After a run is promoted, gc reports any file in its run directory over a configured size (flight key gc.run_file_max_mb, default 256) and, with --apply, replaces it with its first and last megabyte around a one-line marker naming the original size and sha256, so a log cited as evidence keeps its head, its tail and a verifiable identity. A file a ledger row names as a gate log is truncated the same way, never deleted. Binary artefacts over the limit (*.pt, *.h5, *.npz) are reported, not touched. The cut reuses what the repository already owns: the head-and-tail truncation behind the service-log bound in reckon/crew/fleet_supervisor.py (SERVICE_LOG_LIMIT_BYTES and SERVICE_LOG_KEEP_BYTES, line 223; the cut at lines 540 to 574) is lifted into one helper both call, cutting on line_boundary (reckon/crew/runs.py:1923) so no line is split; gate-log paths are read with _declared_arm_paths (reckon/crew/promotion_release.py:127). The rotating watch log (WATCH_LOG_MAX_BYTES, runs.py:3985) keeps its newest bytes because nothing cites its head; a run's log keeps both ends because a gate's command and its verdict sit at opposite ends.

Done when tests/test_gc_bounds_a_run_file.py builds a promoted temporary run directory with a 3 MB log and a 3 MB .pt file under a 1 MB limit, and asserts gc --apply leaves the log at about 2 MB with the marker, its first and last line intact and the original sha256 in the marker, and the .pt file unchanged and reported. A run that is not promoted is untouched. The negative control is executed and logged: with the promoted check removed, the unpromoted run's log is truncated and the test fails. Write paths: reckon/crew/routing.py, reckon/crew/fleet_supervisor.py, reckon/schema/, tests/test_gc_bounds_a_run_file.py; the fleet supervisor's own log tests pass. This section runs after §3, which writes the same module.

§5 — The existing backlog is reclaimed

Deliverable. An operational node, run after §2 to §4 are promoted and installed: run reckon crew gc for the reckon repository and capture its report, then reckon crew gc --apply, capturing every printed removal to a log under the run directory; remove the six redirection-named directories in the crew home and the seven stray files at the checkout root after listing each with its contents' first line; and remove the 18 clean worktrees whose heads main already contains through gc --apply. Nothing is removed that the listing did not name.

Done when the log records the before and after sizes of ~/.cache/reckon, ~/.config/reckon/crew/runs, reports and locks (measured with du -s under a timeout), the cache holds no ledger index whose recorded checkout is gone, the crew home holds no redirection-named directory, git status --porcelain at the checkout root lists none of the seven files, and the combined size of the four stores is at least 100 GB lower than the §1 figures. The removal listing is in the log before the first removal line. Write paths: the run's own log directory.
