§2 — One ledger index per project, and the old ones are swept

Deliverable. _run_index_path keys the index on the project and the repository's common git directory, so a worktree and its main checkout share one index file, which rebuilds when its stamp moves exactly as now. The pick-input kind gets its own leaf under the cache root instead of the root itself (reckon/_store.py:162), and reckon crew gc reports, and with --apply removes, every ledger-*.sqlite in the old location and every index in the new one not opened in seven days. Removal prints each path and its size; nothing is removed silently. A sweep never removes an index open by a live process (checked with fcntl lock probing the index already takes).

Done when tests/test_ledger_index_is_shared_by_worktrees.py builds a temporary repository with a main checkout and two linked worktrees, resolves the index path from each, and asserts one path; and a temporary cache root seeded with three old-location files and one recent new-location index reports exactly three removals under gc and removes them under gc --apply, leaving the recent one. The cache root is a temporary path and the test asserts the real ~/.cache/reckon is untouched. The negative control is executed and logged: with the key reverted to the resolved ledger path, the worktrees resolve two paths and the test fails. The pick and ledger tests pass, their list built at dispatch from the head tree. Write paths: reckon/ledger.py, reckon/_store.py, reckon/crew/routing.py, tests/test_ledger_index_is_shared_by_worktrees.py.

§3 — gc reaches reports, locks and run directories with no ledger row

Deliverable. garbage_collect (reckon/crew/routing.py:1520) gains three row sets, each reported by default and acted on only with --apply, each re-checking for a live pointer immediately before acting, as the pointer reap already does: report trees under reports/<project>/ whose newest file is older than the run retention and whose run is not live; lock files whose run is in the ledger, not live and past retention; and run directories with neither a ledger row nor a live pointer, past retention. Every removal prints its path and size. The existing plan-review sweep is folded into the report row set rather than kept beside it.

Done when tests/test_gc_reaches_every_crew_store.py builds a temporary crew home holding, for each row set, one entry past retention and one inside it, plus one past-retention entry whose run has a live pointer, and asserts gc reports exactly the three past-retention entries without a live pointer and gc --apply removes exactly those, printing each. The negative control is executed and logged: with the live-pointer re-check removed, the live run's entry is reported and the test fails. The existing gc tests pass. Write paths: reckon/crew/routing.py, tests/test_gc_reaches_every_crew_store.py.

§4 — A run's captured file has a size limit

Deliverable. After a run is promoted, gc reports any file in its run directory over a configured size (flight key gc.run_file_max_mb, default 256) and, with --apply, replaces it with its first and last megabyte around a one-line marker naming the original size and sha256, so a log cited as evidence keeps its head, its tail and a verifiable identity. A file a ledger row names as a gate log is truncated the same way, never deleted. Binary artefacts over the limit (*.pt, *.h5, *.npz) are reported, not touched.

Done when tests/test_gc_bounds_a_run_file.py builds a promoted temporary run directory with a 3 MB log and a 3 MB .pt file under a 1 MB limit, and asserts gc --apply leaves the log at about 2 MB with the marker, its first and last line intact and the original sha256 in the marker, and the .pt file unchanged and reported. A run that is not promoted is untouched. The negative control is executed and logged: with the promoted check removed, the unpromoted run's log is truncated and the test fails. Write paths: reckon/crew/routing.py, reckon/schema/, tests/test_gc_bounds_a_run_file.py. This section runs after §3, which writes the same module.

§5 — The existing backlog is reclaimed

Deliverable. An operational node, run after §2 to §4 are promoted and installed: run reckon crew gc for the reckon repository and capture its report, then reckon crew gc --apply, capturing every printed removal to a log under the run directory; remove the six redirection-named directories in the crew home and the seven stray files at the checkout root after listing each with its contents' first line; and remove the 18 clean worktrees whose heads main already contains through gc --apply. Nothing is removed that the listing did not name.

Done when the log records the before and after sizes of ~/.cache/reckon, ~/.config/reckon/crew/runs, reports and locks (measured with du -s under a timeout), the cache holds no file in the old index location, the crew home holds no redirection-named directory, git status --porcelain at the checkout root lists none of the seven files, and the combined size of the four stores is at least 100 GB lower than the §1 figures. The removal listing is in the log before the first removal line. Write paths: the run's own log directory.
