§2 — A ledger index whose checkout is gone is swept

Deliverable. Each ledger index records, in a metadata table written when it is built, the ledger path it indexes. reckon crew gc reports, and with --apply removes, every ledger-*.sqlite in the pick-input cache root whose recorded ledger path no longer exists, and every one that records no path and was not opened in seven days. Removal prints each path and its size; nothing is removed silently, and an index locked by a live process is never removed. The index stays keyed per checkout, because each checkout has its own ledger files and its freshness stamp is the ledger file's identity (reckon/ledger.py:850-916), so one index shared by several checkouts would be invalidated on every switch between them. The cache location is unchanged, because the same pick-input kind also holds the picker's picker-*.json files (reckon/capabilities.py:1190), which the sweep does not match.

Done when tests/test_gc_sweeps_ledger_indexes.py seeds a temporary cache root with two indexes recording ledger paths that have been deleted, one recording a live ledger path, one recording no path with an mtime eight days old, and one picker-x.json, and asserts gc reports exactly the two orphans and the old unrecorded index, and gc --apply removes exactly those three, leaving the live index and the picker file. An index built through the ledger reader records its path. The cache root is a temporary path and the test asserts the real ~/.cache/reckon is untouched. The negative control is executed and logged: with the existence check removed, the live index is reported and the test fails. The pick and ledger tests pass, their list built at dispatch from the head tree. Write paths: reckon/ledger.py, reckon/crew/routing.py, tests/test_gc_sweeps_ledger_indexes.py.

§4 — A run's captured file has a size limit

Deliverable. After a run is promoted, gc reports any file in its run directory over a configured size (flight key gc.run_file_max_mb, default 256, added as a gc namespace in reckon/schema/flight.yaml with reckon/_flight_schema.py and docs/_shared/flight.schema.json regenerated by scripts/regen_flight_schema.py, because the generated model forbids an undeclared namespace and tests/test_flight.py asserts the regeneration is byte-identical) and, with --apply, replaces it with its first and last half of the limit around a one-line marker naming the original size and sha256, so the result never exceeds the limit plus the marker, so a log cited as evidence keeps its head, its tail and a verifiable identity. A file a ledger row names as a gate log is truncated the same way, never deleted. Binary artefacts over the limit (*.pt, *.h5, *.npz) are reported, not touched. The cut reuses what the repository already owns: the service-log trim in reckon/crew/fleet_supervisor.py (trim_service_log, lines 548 to 574, bounded by SERVICE_LOG_LIMIT_BYTES and SERVICE_LOG_KEEP_BYTES at line 223) keeps only the newest bytes; it is lifted into one helper taking a head size and a tail size, the service log calling it with a head of zero so its behaviour and its tests are unchanged, and the run-file bound with half the limit each side, and no line is split: the tail cut advances forward to the next newline as trim_service_log does (fleet_supervisor.py:566-570), and the head cut backs off to the last newline before its end, a forward-reading snap of its own, because line_boundary (in reckon/crew/runs.py) reads backward from the end of a whole file and takes no offset; gate-log paths are read with _declared_arm_paths (reckon/crew/promotion_release.py:127). The rotating watch log (WATCH_LOG_MAX_BYTES, defined in reckon/crew/watch_unit.py since runs.py was split, and re-exported from it) keeps its newest bytes because nothing cites its head; a run's log keeps both ends because a gate's command and its verdict sit at opposite ends.

Done when tests/test_gc_bounds_a_run_file.py builds a promoted temporary run directory with a 3 MB log and a 3 MB .pt file under a 1 MB limit, and asserts gc --apply leaves the log at no more than 1 MB plus the marker, its first and last line intact and the original sha256 in the marker, and the .pt file unchanged and reported. A run that is not promoted is untouched. The negative control is executed and logged: with the promoted check removed, the unpromoted run's log is truncated and the test fails. Write paths: reckon/crew/routing.py, reckon/crew/fleet_supervisor.py, reckon/schema/, reckon/_flight_schema.py, docs/_shared/flight.schema.json, tests/test_gc_bounds_a_run_file.py; tests/test_flight.py passes; the fleet supervisor's own log tests pass. This section runs after §3, which writes the same module.
