§1 — A page waits for the whole derived fleet, and a restart forgets it

The discovery repair removed the quadratic parse, and warm /_discover fell below 1.5 s at load average 8 to 12. The operator restarted reckon.service at 20:18 CEST on 2026-09-23 to pick up that plan's §7. The site was then unreachable for about 5.5 minutes, and afterwards /_discover/imas-efit did not answer within 120 s and /crew took 27 s. The login node stood at load average 169. The operator's requirement, in their words: lazy load the plans and thumbnails with only metadata loaded quickly on startup or refresh, make refresh lightning quick and also unnecessary, and keep the site in sync automatically.

Five causes, each measured or read from the code on 2026-09-23:

  • The server listens only after it has watched every tree. main calls start_fleet_change_watch before serve_forever, and each _ProjectChangeWatch walks its tree with os.walk. py-spy dump at 20:20 put the main thread in _watch_tree, at islink, with 10 of 13 trees done, and the port refused every connection until the walk finished.
  • Every cache lives in process memory. The per-file parse memo, the discovery cache and the git-history memo start empty after a restart, so the first request for each project re-reads every plan, evidence and figure file from the shared filesystem.
  • One response carries everything, and nothing paints before it. /_discover/<project> returns every row together with the roadmap, the ready set, readiness state, live crew runs, git creation times and review state. That is 5.5 MB for nova, and the SPA renders nothing until the whole response arrives.
  • A change means a full reload. /_changes/<project> emits only a content digest, and the SPA answers each event by fetching the whole /_discover payload again.
  • Thumbnails are full-size figures. The figure list draws each row's image at 50 by 34 pixels from the original file. Loading lazily defers the download but does not shrink it.

§3 — A metadata index survives a restart and answers in milliseconds

The server keeps one metadata index per mounted project on disk, under the configuration home's cache directory. Each row carries the fields a list needs: slug, href, type, title, status, sprint, archived, created and edited stamps, and figure dimensions. It also carries the stat identity of the file the row came from. At startup the index is read, and each file is re-parsed only when its stat identity differs from the recorded one, so a restart costs stat calls rather than reads. The change watch updates the rows of the files it reports. A new endpoint /_index/<project> serves the rows and nothing derived: no roadmap, no readiness, no live runs.

Done when tests/test_metadata_index_survives_restart.py builds a temporary project of 200 plan and evidence files and a temporary configuration home. It builds the index once, clears every in-process memo to stand in for a restart, and asserts that the rebuild parses 0 files, counted through _plan_html._parse_meta_uncached. It rewrites one file, and asserts that the next build parses exactly that one and returns its new title. It also asserts that the /_index response carries no key outside the declared row fields. The negative control is executed and logged: with the persisted index ignored, the post-restart build parses all 200 files and the first assertion fails. The write paths are a new module reckon/metadata_index.py, reckon/serve.py and that test. This section runs after §2, which shares reckon/serve.py.

§4 — A page paints from the index, and derived state arrives when ready

docs/ui/state-loader.js fetches /_index/<project> first, renders the rows, and resolves the page's first paint. It then fetches /_discover/<project> in the background and merges the derived fields into the rows already on screen, without re-sorting a list the reader is looking at. A plan's body is fetched only when that plan is opened. The derived values are computed in Python, as the served-surface rule requires; the loader only merges them.

Done when tests/test_page_paints_from_the_index.py runs the real loader under node with a recording fetch in which /_discover never resolves. It asserts that window.STATE_READY resolves with every index row present, and that the only requests made before readiness are for /_index. A second case resolves /_discover later and asserts the derived fields, effective_status and the ready set, are merged into the same rows with their order unchanged. The negative control is executed and logged: with readiness gated on /_discover again, the first case never resolves and fails on its timeout. The write paths are docs/ui/state-loader.js and that test. This section runs after §3, whose endpoint it reads.

§5 — A change pushes its rows, and the page patches them in place

On a change, /_changes/<project> emits the index rows that changed, were added, or were removed, taken from the §3 index diff, rather than a bare digest. The loader patches those rows into window.STATE and marks new ones as arrivals. It refetches derived state at most once per settle window, in the background. A refresh then has nothing to add.

Done when tests/test_changes_push_rows.py opens a change stream against a temporary project, rewrites one plan's title, and asserts the next event carries exactly that row with its new title within 2 s. A loader case under node feeds that event to the real loader, and asserts the row is patched in window.STATE with no request to /_discover or /_index made to apply it. The negative control is executed and logged: with the stream emitting the bare digest, the row assertion fails. The write paths are reckon/serve.py, docs/ui/state-loader.js and that test. This section runs after §3 and §4, whose files it shares.

§6 — A thumbnail is a thumbnail

The server serves a downscaled copy of a figure at /_thumb/<project>/<path>, at most 200 pixels on the long edge. It is generated once, cached on disk under the configuration home keyed by the source file's stat identity, and revalidated by ETag. SVG sources are passed through, because they scale without cost. The figure list draws rows from the thumbnail URL, lazily. Pillow is declared in pyproject.toml rather than reached through another package's dependency.

Done when tests/test_figure_thumbnails.py serves a 2000-by-1500 PNG from a temporary project, and asserts the thumbnail answers 200 with an image whose long edge is 200 pixels and whose byte size is under a tenth of the source. It asserts a second request with the ETag answers 304 without regenerating, counted through a counter the test installs, and that an SVG is returned unchanged. The negative control is executed and logged: with the thumbnail route serving the source file, the size assertion fails. The write paths are reckon/serve.py, docs/ui/shell-plans.jsx, pyproject.toml, uv.lock and that test. This section runs after §5, which shares reckon/serve.py.

§8 — Agent readers answer from the same index

The MCP server and the CLI call discover_plans in their own processes (reckon/mcp.py line 1250, reckon/mcp_views.py line 1985). They run with the library's reuse window of 0 and no change watch, so every call walks every tree it touches, including those of external dependencies, and each starts cold whenever the MCP process restarts. On 2026-09-23, at load average 150, a read_plan of one sprint sent nothing for 1,800 s and was aborted by its client, while the served process was answering. A human and an agent reading the same project pay different costs, and the agent pays the larger. The thin interface is the §3 index: agent readers take list-level facts from reckon.metadata_index, the same module and the same persisted file the served process uses, and derive heavier state only for the resource they were asked about.
