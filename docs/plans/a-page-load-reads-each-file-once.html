§1 — Every page load rediscovered the fleet

Reported on 2026-09-23 as the SPA being unusable: slow to load on nova, reckon, imas-codex and imas-efit, and after switching to imas-efit the project picker listed no other project, so there was no path back. py-spy dump of the server put every request thread in discover_plans. A cProfile of one cold discovery of reckon took 119.6 s and made 7,776 calls to parse_meta for 410 inventory rows. Opening a file on the loaded shared filesystem cost 2.3 ms on average. Six causes compound:

  • The wiring scan is quadratic. build_roadmap calls _unwired_plan_findings, which calls _standalone_reason for each unwired plan, and each call goes through resolve_resource to iter_resources. That walks the whole docs tree and parses every file's meta, so the tree is walked and parsed once per plan. read_plan_record and _authorisation_age resolve slugs the same way.
  • A cache hit still walked the tree. The discovery cache is validated by a signature that ran four recursive globs over the docs tree, plus the same for every project the plans depend on. That took 8 to 11 s for nova, and a warm rediscovery of reckon took 19.8 s.
  • The rollup ran a full-history git log per project. fleet_index._activity30 took 6 to 10 s per repository, serially over 13 mounts, under a 10 s timeout. Its TimeoutExpired was not caught, so one slow repository aborted the whole /_projects/index.json response. That is the empty reply above and the empty project picker: the shell set its project list only after that response and all thirteen /_discover calls had finished.
  • Every page load fetched every project's inventory. The shell fetched /_discover/<p> for all thirteen mounts, although only the fleet home and the command palette read other projects' inventories.
  • The served loader still reads the superseded aggregate. state-loader.js requests state/<project>/index.json with required: true before /_discover. The server intercepts that URL and runs a full discovery to overlay the inventory on the frozen envelope, so each project page transfers its inventory twice. It also puts the persisted projects[] block of a file that the fleet migration superseded into window.STATE. All five projects measured carry the distributed marker.
  • Every response was sent no-store. Figures, stylesheets and compiled scripts were downloaded again on every refresh.

§2 — Discovery reads each file once, and a refresh reads none

The server-side repair is on main at 56e13e11 and has had only a compile check. reckon/file_memo.py memoises parse_meta, the head-meta reader, the readiness-state reader and the standalone declaration against each file's stat identity: device, inode, size, mtime and ctime. resource_scan_scope in reckon/resources.py shares one tree scan for every lookup inside a read-only pass; discover_plans and build_roadmap open it. The cache signature is one os.scandir walk. The served process reuses a walk for RECKON_DISCOVERY_REUSE_S seconds (default 5), dropped on every POST and every change event. The library default is 0, so a direct caller always walks. One discovery per project runs at a time. A change stream settles a burst of events for 0.25 s into one rediscovery, and drops only a cache entry computed before the event. The fleet rollup computes projects concurrently. The activity history is memoised against HEAD, and a git timeout yields an empty series instead of aborting the rollup. Static files revalidate by ETag with Cache-Control: no-cache, and JSON over 64 KiB is gzipped when the client accepts it.

Done when tests/test_discovery_reads_each_file_once.py builds a temporary docs tree of 40 unwired plans in the discovery_cache test fixture's style, with a temporary mounts file and no real mount read. It counts calls to reckon._plan_html._parse_meta_uncached through a counter the test installs, and asserts:

  • a cold discover_plans parses each HTML file at most once;
  • a second call with nothing changed parses none;
  • after one file is rewritten, the next call parses only that file;
  • with serve._SIGNATURE_TTL_S set to 60, a rewritten file is not seen until serve._invalidate_discovery_signatures() runs, and is seen immediately after;
  • a second fleet_index._activity30 call at an unchanged HEAD runs no git log, counted through a patched subprocess.run;
  • a git log that raises subprocess.TimeoutExpired yields [] rather than an exception.

The negative control is executed and logged: with reckon.file_memo.memoized patched to call compute() directly and resource_scan_scope made a no-op, the cold-parse assertion fails with more than 5 parses per file. The regression gate is tests/test_discovery_cache.py, tests/test_fleet_index.py, tests/test_mcp_roadmap.py, tests/test_cross_project_refs.py, tests/test_crew_routes.py and tests/test_project_state.py. It is run at the base 00106ce2 and at the head, one log each, on the all_debug partition, and it passes with zero added failures. The write paths are that test file and, only for repairs the gate shows are needed, reckon/file_memo.py, reckon/serve.py, reckon/resources.py, reckon/roadmap.py, reckon/fleet_index.py and reckon/_plan_html.py.

Landed 2026-09-23 at 98d99673, base 00106ce2. tests/test_discovery_reads_each_file_once.py passes all six assertions against a temporary 40-plan tree: one parse per file cold, none warm, only the rewritten file after an edit, the signature TTL deferring a rewrite until invalidation, one git log per unchanged HEAD, and an empty series rather than an exception on a git timeout. §3 — The served loader reads discovery, not the superseded aggregate

docs/ui/state-loader.js assembles window.STATE from /_discover/<project> alone whenever that endpoint answers. Discovery already carries the inventory, sprints, milestones, blockers, timeline, active sprint, north stars, source format and resource versions for both the distributed and the legacy formats. state/<project>/projection.json is read only when discovery is unreachable, which is the static-build case, and state/<project>/index.json only when both are unavailable. The single project row in window.STATE.projects is synthesised from live counts. It is never taken from a persisted projects[] block while discovery answered.

Done when tests/test_served_loader_reads_discovery_only.py runs the real loader under node with a recording fetch, in the style of tests/test_spa_state_boundary.py. It asserts three cases.

  1. With discovery answering, no URL ending in index.json or projection.json is requested. window.STATE.sprints, active_sprint_id and timeline equal discovery's, and window.STATE.projects[0] carries no field present only in a persisted projects[] block the mock would have served.
  2. With discovery refused at the network level, projection.json is requested and its sprints are used.
  3. With discovery refused and no projection, index.json is requested.

The negative control is executed and logged: restoring the aggregate-first order at the base 56e13e11 makes the first assertion fail. tests/test_spa_state_boundary.py, tests/test_spa_live_arrival.py and tests/test_served_schedule_payload.py pass with zero added failures against the same base. The write paths are docs/ui/state-loader.js and that test.

Outcome — the served loader reads discovery alone. Commit f6529a51 perf(ui): the served loader assembles state from discovery alone asks /_discover/<project> first and, when it answers, reaches no aggregate fetch at all: its inventory, sprints, milestones and north stars are adopted for both layouts, and the single projects[0] row is synthesised from the live counts, so no field of a persisted projects[] block reaches window.STATE. projection.json is read only on a network-level refusal or an explicit 404, and index.json only when projection is also missing. A discovery HTTP failure other than 404 is still raised even when a projection exists, so a live server refusing its own inventory is not disguised by a stale aggregate.

Measured

  • Four cases pass in tests/test_served_loader_reads_discovery_only.py, running the real loader under node with a recording fetch: discovery answers — no aggregate requested and projects[0] carries no persisted-only field; discovery refused — projection requested, index not; discovery refused and no projection — index requested; and a 500 discovery is not hidden by a projection.
  • Zero added failures against base 56e13e11, one log per file: tests/test_spa_state_boundary.py 5 → 5, tests/test_spa_live_arrival.py 4 → 4, tests/test_served_schedule_payload.py 3 → 3.
  • The declared negative control is executed and logged: restoring the aggregate-first order at 56e13e11 makes case 1 fail with index.json in the recorded request list.

Evidence: the landed record.

§5 — The served process runs the repair, and the load is measured

The operator restarts reckon.service once §2 to §4 are merged. The table in §1 is then measured again against the restarted process.

Done when a timing report records wall time, status and bytes for the six requests of §1 in two passes against the restarted process. The cold pass is the first request to each URL after the restart, issued one at a time. The warm pass repeats the six at least 10 s after the cold pass ends, so it outlives the 5 s walk-reuse window and measures a cache hit that still validates against the tree. The report records the host, its load average at the start of each pass, and the UTC window of each pass, because the §1 baseline was taken at load average 49. It also records a figure fetched with its ETag answering 304, and the gzipped size of /_discover/nova.

The gate is hard: every warm request answers 200 in under 2 s. A slower warm request fails §5, and the report names it with a py-spy dump frame taken while it runs. Naming a slow request records the failure; it does not pass the gate. The write path is the report under the session's reports directory.

§6 — The palette asks for each project's inventory exactly once

The independent review of §4 (score 97) found that tests/test_shell_project_list_is_immediate.py collapses the recorded /_discover/<project> requests into a set before comparing them with the mounted projects. It therefore measures coverage, not the one request per project that §4 states, and a shell that asked for an inventory twice would still pass.

Done when that test asserts, over the requests recorded after the palette opens, that each mounted project's /_discover URL appears exactly once, and that no other /_discover URL appears. The negative control is executed and logged: with docs/ui/shell.jsx's requested-set guard removed, so an inventory is requested again whenever the effect re-runs, the count assertion fails where the set assertion passed. The run is recorded on the login node, because no compute partition carries a browser binary. The write path is that test only.
