§1 — A pair whose arms resolve to one backend and model is refused before either launches

On 2026-10-18 nova dispatched census-certified-convergence with --pair-backend codex. Jev routed the primary arm to codex as well, at confidence 0.46. So primary r-20261018T062147901424-census-certified-convergence and shadow r-20261018T062147901543-census-certified-convergence both ran codex with gpt-6-sol, as both run directories record. The pair compared nothing and spent codex twice. nova stopped and discarded the shadow, which had made no commits.

Nothing checks for this. dispatch_pair (reckon/crew/dispatch.py:690) plans the primary first through plan_dispatch, so the primary's agent is known before either arm launches. That includes the backend and model the picker chose (primary_agent). _shadow_dispatch_config (line 465) then builds the shadow's agent for the named backend and compares it with the primary's, field by field, in the comparison it returns. The backend always lands in comparison["substituted"] with both arms' values. The model lands there only when the two arms' models differ, and otherwise in comparison["inherited"]. dispatch_pair stores that comparison in the shadow's lineage, but nothing refuses on it. The paired tests could not see it. _candidate_config in tests/test_a_paired_dispatch_hides_each_arm.py (line 85) routes the implement role itself to the pair backend, so every pair those tests build has both arms on candidate.

Remedy. In dispatch_pair, read the comparison that _shadow_dispatch_config already returns, and do not compare the two agents a second time. Refuse when its substituted backend entry carries equal primary and shadow values and model is not among its substituted entries. The check runs before the dry-run return and before any run directory or worktree is created. Refuse with D21, and name in the detail the backend and model both arms resolved to. The detail also says that the pair backend must differ from the lane the primary runs on. That sentence goes in the detail rather than in D21's registered remedy, because crew shadow shares that remedy and does not enforce the rule. A pair whose arms share a backend but run different models still compares something, the two models, and is not refused.

Why refuse rather than re-pick. Two automatic answers exist, and each overrides a choice someone made. Moving the shadow to another lane overrides the lane the coordinator named, and a named lane is authoritative. Taking the named lane out of the primary's pick overrides Jev, which nova's lead has said should route by itself. A refusal overrides neither and spends nothing. The coordinator can re-dispatch with another pair backend, or name the primary's lane with --backend. A dry run shows the refusal, because the check runs before the dry-run return. Jev can still pick differently between a dry run and the real dispatch, but then the refusal comes at dispatch, still before anything launches.

Out of scope. crew shadow on a finished run has the same gap: shadow (line 558) resolves the named backend without comparing it to the primary's. A shadow of a finished run on its own lane can be a deliberate repeat, so it is not changed here.
