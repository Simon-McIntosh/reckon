§3 — Warm reads answer under five seconds

The §2 profile names the cost: unchanged plan files parsed again and again, with parse_plan run 268 times and read_state 625 times in one warm read, plus a separate link, lifecycle, question and followup pass in the audit. This section lands the part of that fix that lives in reckon/_plan_html.py and reckon/doccheck.py. The read_state half lives in reckon/_store.py and follows as its own node.

  • parse_plan is memoized through reckon.file_memo.memoized, keyed on the file's path, size, mtime and inode, so an unchanged file is parsed once per process and a changed one is re-parsed. It returns an isolated copy, so a caller that mutates the result cannot poison the memo.
  • The audit's per-file passes (links, lifecycle, questions, followups) read the memoized parse instead of re-reading the file.

Done when:

  • Tests assert: a second parse_plan of an unchanged file does not re-read it; a rewrite that changes the size, the mtime or the inode is re-parsed; mutating a returned result does not change the next result.
  • The warm audit(project="reckon"), roadmap(project="reckon", view="summary") and discovery reads are each timed three times, before and after, on this host, and recorded. The audit falls from its §1 warm time of 28.9 s. What remains is attributed to the read_state half or to live-pointer classification.
  • The declared mutation, keying the memo on the path alone, is observed to fail. The log is recorded.
  • Existing tests for plan parsing, the audit and doccheck pass unchanged.

A plan read takes its state and its text from one read of the file

Found by the review of read-state-and-live-runs-reuse (86). In reckon/_store.py read_plan, the state comes from _plan_html.read_state_file(html_file) and the text from _plan_html._read_plan_text(html_file). These are two independent memoized lookups, each keyed on its own stat of the file. A write landing between them pairs a state parsed from the old bytes with text from the new, and _unparsed_section_warnings then reports authored children of a section that the stale state shows empty. Before the memo, one read produced both.

The fix: one call that stats and reads the file once and returns the parsed state and the text that state was parsed from, memoized as a pair on one file signature. read_plan uses that pair. Keep the memo's speed: a warm read must not parse twice.

Test: replace the file between the two halves of a read (monkeypatch the text read to rewrite the file first). Assert that the state and text a read returns come from the same bytes. The test must fail at the current head.
