§1 — A landing's commits write leaves the design review standing

reckon/crew/plan_review.py digests each plan unit for the design-review gate and drops the scalars in PLAN_METADATA_SCALARS (version, modified, impl, status, roi, effort_hours, owner, sprint, tags, archived), so bookkeeping writes do not re-stale a review. commits is not in that list, and the reckon-build landing beat sets it on every landing. So every landing makes the next crew dispatch refuse with plan-review-missing and the uncovered unit _document. Measured on imas-ambix jt60sa-machine-map on 2026-10-06 and 07: several of that night's design-review cycles were caused by landing beats alone, each costing a local-lane review of about five minutes before the next node could go out.

commits records which commits landed the plan. It is provenance, not authored design, so it joins PLAN_METADATA_SCALARS. Any key the parser derives from it is excluded the same way, as the derived-field exclusions below that list already do for the other scalars.

Done-when: a test sets commits on a plan with a stored review and asserts that its _document digest and every section digest are unchanged and that review_coverage still reports the review as covering. The same test with an authored prose edit reports the unit uncovered, so the exclusion is shown not to swallow real edits.

§2 — A plan's first landing marks it in progress

A plan's status is set by hand, and nothing moves it when work starts. Measured on imas-ambix on 2026-10-07: jt60sa-machine-map read draft through 50 landed nodes over two days, while the SPA's in-flight list showed its live runs. Promotion already does a versioned read-modify-write of the plan in reckon/crew/promotion.py _record_landing_comment to append the landing comment.

In that same write, a plan whose status is draft or pending becomes in-progress. Every other status is left alone, so active, blocked, shipped and the other terminal states never move. status is in PLAN_METADATA_SCALARS, so the flip never re-stales a design review. The flip happens at the first landing rather than at dispatch because promotion already owns a committed plan write and dispatch does not; until the first landing, the SPA's in-flight list already shows the running nodes.

Done-when: a test promotes a run against a draft plan and reads back in-progress together with the landing comment in the same plan version. A test against an active plan and one against a shipped plan read back the status unchanged. The existing promotion tests that exercise _record_landing_comment pass unchanged.
