§4 — A re-synthesis keeps every anchor an append wrote, and names every loss

Why. power-convertor-df reported this on 6 November after re-running reckon evidence synthesize on the record §1 quotes. The rebuild read 14 runs, 64 comments and 47 commits. But the two sections append_evidence had written, anchored frch-presentation-figures and frch-assemble-pages, were folded into the s4 and s6 sections. Links to those anchors no longer resolve.

Deliverable. One function in reckon/evidence.py derives two sets for a plan. The rendered set is the ids this synthesis writes: the plan's comment keys and the current ledger runs' section keys, the available set _render_document renders (near line 349). A declared plan section with no comments or runs is not in it. The reserved set is the rendered set plus every plan section id and outcome, since any of them may be rendered later. Each is normalised through _section_key (near line 50). Comment keys are normalised before rendering (near lines 340–343), so the plan-level key _top renders as top; the _top branches near line 372 are unreachable. When the plan has a plan-level comment, both sets carry top, and outcome stays reserved for the closing section. The landed-record path accessor _evidence_record_path moves from reckon/_store.py (near line 1172) to reckon/evidence.py as that path's one owner. synthesize_landed_record (near line 674), the append writer (_store.py near line 1249) and the refusal below all call it.

  • The mark. _evidence_section_html writes data-evidence-origin="append" on each section it creates.
  • Carry-forward. synthesize_landed_record carries the existing record's marked sections into the rewritten record under the same ids, except an id in the rendered set. An unmarked section on a record written before the mark is carried when its id is outside the reserved set.
  • The refusal. _apply_evidence_appends (_store.py near line 1230), the half of the op that has the docs directory, refuses an anchor whose _section_key form is in the reserved set. It reads that set through the same function. Today it reads the plan only for a missing record's title and never reads the ledger.
  • Every loss named. EvidenceSynthesisResult (evidence.py near line 24) gains one list, lost_anchors. Each entry is tagged dropped (a marked append whose id a ledger run later came to render), replaced (an unmarked section a rendered one took the place of), retired (an unmarked section on a reserved id this synthesis does not render, such as a plan section left with no comments or runs) or carried (an unmarked section on an id no longer producible, kept because it cannot be told from an append). synthesize_evidence (reckon/project_maintenance_commands.py near line 1473) prints the list with its tags.

The accepted limit is the carried case. On a record written before the mark, a generated section whose plan section was deleted, or whose ledger run no longer maps, looks like an append. It is listed so an operator can remove it. A record written after the mark cannot reach it.
