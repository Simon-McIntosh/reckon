§4 — A re-synthesis keeps every anchor an append wrote

Why. power-convertor-df reported this on 6 November after re-running reckon evidence synthesize on the record §1 quotes. The rebuild read 14 runs, 64 comments and 47 commits. But the two sections append_evidence had written, anchored frch-presentation-figures and frch-assemble-pages, were folded into the s4 and s6 sections. Links to those anchors no longer resolve.

Deliverable. synthesize_landed_record (reckon/evidence.py) carries the existing record's appended sections into the rewritten record under the same ids, with their content, so an anchor once published keeps resolving. A section counts as appended by a mark, not by whether this run happens to render its id. _evidence_section_html (reckon/_store.py) writes data-evidence-origin="append" on each section it creates, and the synthesis carries forward only marked sections. That keeps it from republishing a stale section an earlier synthesis generated but this one no longer produces. A record written before the mark existed has unmarked appended sections. For those, an unmarked section counts as appended when its id is none of the ids a synthesis can produce. Those are the plan's section ids, outcome, and every id this synthesis renders, which _render_document takes from the plan's comment keys and the ledger runs' section keys (reckon/evidence.py near lines 340–354). Whatever the mark, an id this run renders is never also carried forward. And append_evidence gains a refusal of an anchor equal to an id a synthesis can render now: the plan's section ids, outcome, and every id _section_key makes of the plan's comment keys and of the current ledger runs' section keys. A ledger run recorded later under a new section key can still render an id an earlier append took. That residual is accepted, but it is never silent: when the rendered-id exclusion drops an appended section, the synthesis names it in its result. The refusal lives in _apply_evidence_appends (reckon/_store.py near line 1230), the half of the op that has the docs directory and reads the ledger, not in the pure validator _apply_append_evidence beside the anchor-shape guard (near lines 1292–1299). The synthesis result, EvidenceSynthesisResult (reckon/evidence.py near line 24), gains a field listing dropped anchors. The command that runs it, synthesize_evidence (reckon/project_maintenance_commands.py near line 1473), prints that field.
