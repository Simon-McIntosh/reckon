§1 — The review of a paired arm names the arm by its run id

On 2026-10-18 nova ran a paired dispatch of efit-field-swap: primary r-20261018T063236394668-efit-field-swap on clive, and shadow r-20261018T063236394831-efit-field-swap on codex. Both live pointers carry the node id efit-field-swap. The obligation for the codex arm printed a review command with --node review-of-efit-field-swap-eba500937412 and write paths under the codex arm's review-records/. Dispatch refused it as not-dispatchable on the scoped property. nova re-dispatched it by hand as review-of-r-20261018T063236394831-efit-field-swap-eba500937412, which ran.

The cause is that the review node id names the node, and a pair has two runs with one node id. _review_dispatch_fields (reckon/crew/recovery_review_subject.py:460) takes source_node from the reviewed record's node id, falling back to its run id only when there is none (line 608). It mints the node id from that through round_node_id. Dispatch recovers the reviewed run through _reviewed_run_id_for_node (reckon/crew/dispatch_admission.py:1866), which calls _resolved_reviewed_run_id (reckon/crew/recovery_review_delivery.py:156). That resolver returns a run id source as it is. Any other source it matches against the live fleet's node ids, returning the first pointer that matches (lines 172 to 174). For this pair the first match was the clive primary. So the record-directory grant named the primary's directory, and the codex arm's declared record path fell outside it. The same ambiguity hits the primary's own review, whichever pointer the listing returns first.

Remedy, two parts:

  • In _review_dispatch_fields, mint the returned node_id from the run id, not the node id, when the reviewed record is one arm of a pair. Leave the returned source_node as the node id. compose_repair_for_run also reads source_node (reckon/crew/recovery_repair_dispatch.py:665) to mint a repair's node id, and this section does not change repair node ids. Read whether the record is a paired arm from _paired_partner_run_id (reckon/crew/promotion_checks.py:606), which already resolves a partner from either side: the primary's paired_shadow_run_id, or a shadow lineage's primary_run_id. Do not write a second pairing test. An unpaired run keeps its node id as the source, so its review node ids and every reader of them are unchanged.
  • Give _resolved_reviewed_run_id a keyword-only refuse_ambiguous flag, defaulting to false. With it set, when more than one live pointer carries the source node id, the resolver returns the bare source rather than the first match. A bare source names no run directory, so the grant is refused rather than given to the wrong run. One matching pointer resolves as today. Only _reviewed_run_id_for_node (reckon/crew/dispatch_admission.py:1866) sets the flag, so only the dispatch grant changes. The resolver's other readers keep the first match: reckon/crew/recovery_review_delivery.py lines 118 and 233, reckon/crew/recovery_review_dispatch.py:180 and reckon/crew/promotion_checks.py:2343. So does _reviewed_run_id in reckon/crew/dispatch_sessions.py. Once a paired arm's review node is minted from its run id, every one of them resolves that arm directly.

Out of scope. _reviewed_run_id in reckon/crew/dispatch_sessions.py (line 457) resolves the same source over ledger and live records to pick a review's session, taking the newest match. Once a paired arm's review is minted from its run id, that reader resolves it directly, so it is not changed here. Repair node ids keep the node id, because source_node is unchanged. Whether a repair of a paired arm's review resolves to the right arm is not measured here.

Write paths: reckon/crew/recovery_review_subject.py, reckon/crew/recovery_review_delivery.py, reckon/crew/dispatch_admission.py, where _reviewed_run_id_for_node sets the flag, and tests/test_a_paired_arm_is_reviewed_as_itself.py, which is new.

Done when all three of these hold:

  • The new test points the crew home at a temporary directory and writes three live pointers there: a primary carrying node id pair-node and a paired_shadow_run_id naming the second; a shadow carrying node id pair-node and a lineage of kind shadow naming the first as primary_run_id; and an unpaired run carrying node id solo-node. It asserts four cases:
    • For each arm, the node id in _review_dispatch_fields's result starts with review-of- followed by that arm's own run id, and its source_node is still pair-node. _reviewed_run_id_for_node on that node id returns that arm's run id.
    • For the unpaired run, the node id starts with review-of-solo-node, as it does today, and _reviewed_run_id_for_node on it returns the unpaired run's id.
    • _reviewed_run_id_for_node for node id review-of-pair-node returns pair-node, the bare source, and neither arm's run id. _resolved_reviewed_run_id called on the same node id without the flag still returns one arm's run id, as today.
    • _review_record_directory_grant refuses a record path under either arm's review-records/ when given that bare source as the reviewed run.
    The test asserts the real crew home is untouched afterwards.
  • Pytest over the new file, tests/test_a_resumed_head_is_reviewed.py, tests/test_a_run_review_with_run_directory_records_dispatches.py, tests/test_a_paired_arm_waits_for_its_partner.py, tests/test_a_re_review_is_scoped_to_what_changed.py, tests/test_review_reflex_sweep.py, tests/test_rereview_keeps_its_lane.py, tests/test_a_run_review_cannot_remove_a_siblings_record.py, tests/test_review_of_a_brief_run_names_its_brief.py and tests/test_every_module_fits_a_worker_window.py adds no failure against the base. §2 — A shadow arm is reviewed on its retained patch

On 2026-10-18 nova's codex shadow arm r-20261018T065749620519-seed-census-departure was reviewed by r-20261018T080020843192-review-of-r-20261018T065749620519-seed-census-departure-efbeb794e60b. The review scored goal_fidelity 0, fit 0 and durability 0, for a total of 48. Its first blocking finding reads: "commits is empty and source HEAD equals the reviewed base; seven changed tracked files remain uncommitted, so neither the repair nor its assertions can land at this revision." The shadow did what its contract asks. Its prompt says to produce the named evidence without committing, and that the durable deliverable is the worktree patch retained at completion. The clive primary on the same node scored 77. nova reports that the shadow alone measured the census on titan and found a departure only on the GPU.

The cause is that the run-review brief describes every reviewed run as committed work. The rubric, reckon/crew/prompts/review.md, tells the reviewer to read "the diff of its commits against its base" (line 21). _review_brief_text (reckon/crew/recovery_review_subject.py:370) appends only the run's id, its head and its brief to that rubric. A shadow's head is its base, so the diff the reviewer reads is empty, and the patch that is its real deliverable is never named. Promotion already treats that patch as the deliverable. _write_shadow_patch (reckon/crew/promotion_scope.py:905) preserves git diff <base_sha> of the shadow's working tree, plus its untracked files, and _refuse_commits_for_a_shadow (reckon/crew/promotion_checks.py:1730) refuses a shadow presenting commits. The scores matter beyond the run. A shadow's review total, and since §32 of lane-and-model-routing its dimension medians, feed the at-requirement block of the lane that ran the shadow, so every shadow review biases Jev's evidence against that lane.

Remedy. In _review_brief_text, when _is_shadow (reckon/crew/promotion_scope.py:899) reads the record as a shadow, append a block after the run's identity lines. Do not write a second shadow test. The block says four things:

  • This run is a shadow, and its deliverable is its worktree patch, never commits.
  • The diff to review is git -C <worktree> diff <base_sha> plus the files git -C <worktree> ls-files --others --exclude-standard lists, with the worktree and base taken from the record. That is the diff promotion preserves.
  • An empty commits list and a head equal to the base are the shadow's contract, not findings.
  • Every dimension is scored on that patch as the reviewed change.

A run that is not a shadow gets the same brief text as today. Change nothing in the rubric file itself, which every other run review reads.

Out of scope. Reviews of shadows already stored keep their scores, and nothing here re-scores them.

Write paths: reckon/crew/recovery_review_subject.py and tests/test_a_shadow_is_reviewed_on_its_patch.py, which is new. §1 writes the same module, so §2 is dispatched only after §1 is merged.

§3 — A promoted run's review resolves its run

Why. On 2026-10-19 power_convertor discarded the first review of r-20261019T214532819779-cs1-ripple-window, then promoted that run with --waive-unreviewed-promotion. Re-attaching the review with the obligation's own command was refused as not-dispatchable on the scoped property. The command used node id review-of-cs1-ripple-window-a317532bd536, and the refusal said that review "reviews run cs1-ripple-window and may write only that run's record directory". The run's review-records/ directory exists. The same review dispatched as review-of-r-20261019T214532819779-cs1-ripple-window-a317532bd536 launched (r-20261019T233949612668-…).

The cause is that an unpaired run's review node id is minted from the run's node id, which §1 left unchanged. _resolved_reviewed_run_id (reckon/crew/recovery_review_delivery.py:220) returns a run-id source as it is, and matches any other source against live pointers only (lines 248 to 254). When none matches, it returns the bare source. A promoted run has no live pointer. So _reviewed_run_id_for_node (reckon/crew/dispatch_admission.py) hands _review_record_directory_grant a bare node id, which names no run directory, and nothing is granted. The resolver's other readers, the delivery reader among them, resolve the same way. A queued review that the admit service launches after its run has been promoted meets the same refusal.

Remedy. When no live pointer carries the source node id, _resolved_reviewed_run_id resolves it over the durable run records whose node id is that source.

  • The review node id's head suffix chooses among them. Read the suffix with round_node_head_suffix (reckon/crew/repair.py:331). A record matches when the head _run_head_for_review (reckon/crew/recovery_review_dispatch.py:577) gives for it starts with that suffix. A node id that carries no suffix matches every record carrying its node id.
  • Exactly one match resolves to that record's run id. No match, or more than one, returns the bare source, as today, whether or not refuse_ambiguous is set.
  • Read the durable records through RunStore in reckon/run_store.py. Add one reader there that selects rows by the node column, scoped to the resolver's project whenever one is given. The live path scopes by project through list_live(project=...), and the fallback must never be wider. A caller that passes a project, such as the delivery reader, so never resolves to another project's run. Only when project is None, as for the dispatch grant, does the reader select across projects. Open the database nowhere else.
  • A durable read that raises returns the bare source and never propagates.

Live pointers are still read first, so every case that resolves today resolves the same way. The grant and the review node ids are unchanged.

Write paths: reckon/crew/recovery_review_delivery.py, reckon/run_store.py, the new tests/test_a_promoted_runs_review_resolves_its_run.py, and the node's evidence fragment.
