§1 — The review of a paired arm names the arm by its run id

On 2026-10-18 nova ran a paired dispatch of efit-field-swap: primary r-20261018T063236394668-efit-field-swap on clive, and shadow r-20261018T063236394831-efit-field-swap on codex. Both live pointers carry the node id efit-field-swap. The obligation for the codex arm printed a review command with --node review-of-efit-field-swap-eba500937412 and write paths under the codex arm's review-records/. Dispatch refused it as not-dispatchable on the scoped property. nova re-dispatched it by hand as review-of-r-20261018T063236394831-efit-field-swap-eba500937412, which ran.

The cause is that the review node id names the node, and a pair has two runs with one node id. _review_dispatch_fields (reckon/crew/recovery_review_subject.py:460) takes source_node from the reviewed record's node id, falling back to its run id only when there is none (line 608). It mints the node id from that through round_node_id. Dispatch recovers the reviewed run through _reviewed_run_id_for_node (reckon/crew/dispatch_admission.py:1866), which calls _resolved_reviewed_run_id (reckon/crew/recovery_review_delivery.py:156). That resolver returns a run id source as it is. Any other source it matches against the live fleet's node ids, returning the first pointer that matches (lines 172 to 174). For this pair the first match was the clive primary. So the record-directory grant named the primary's directory, and the codex arm's declared record path fell outside it. The same ambiguity hits the primary's own review, whichever pointer the listing returns first.

Remedy, two parts:

  • In _review_dispatch_fields, take the run id as source_node when the reviewed record is one arm of a pair. Read that from _paired_partner_run_id (reckon/crew/promotion_checks.py:606), which already resolves a partner from either side: the primary's paired_shadow_run_id, or a shadow lineage's primary_run_id. Do not write a second pairing test. An unpaired run keeps its node id as the source, so its review node ids and every reader of them are unchanged.
  • In _resolved_reviewed_run_id, when more than one live pointer carries the source node id, return the bare source rather than the first match. A bare source names no run directory, so the grant is refused rather than given to the wrong run. One matching pointer resolves as today.

Out of scope. _reviewed_run_id in reckon/crew/dispatch_sessions.py (line 457) resolves the same source over ledger and live records to pick a review's session, taking the newest match. Once a paired arm's review is minted from its run id, that reader resolves it directly, so it is not changed here.

Write paths: reckon/crew/recovery_review_subject.py, reckon/crew/recovery_review_delivery.py and tests/test_a_paired_arm_is_reviewed_as_itself.py, which is new.

Done when all three of these hold:

  • The new test points the crew home at a temporary directory and writes three live pointers there: a primary carrying node id pair-node and a paired_shadow_run_id naming the second; a shadow carrying node id pair-node and a lineage of kind shadow naming the first as primary_run_id; and an unpaired run carrying node id solo-node. It asserts four cases:
    • For each arm, the node id in _review_dispatch_fields's result starts with review-of- followed by that arm's own run id. _reviewed_run_id_for_node on that node id returns that arm's run id.
    • For the unpaired run, the node id starts with review-of-solo-node, as it does today, and _reviewed_run_id_for_node on it returns the unpaired run's id.
    • _resolved_reviewed_run_id for node id review-of-pair-node returns pair-node, the bare source, and neither arm's run id.
    • _review_record_directory_grant refuses a record path under either arm's review-records/ when given that bare source as the reviewed run.
    The test asserts the real crew home is untouched afterwards.
  • Pytest over the new file, tests/test_a_resumed_head_is_reviewed.py, tests/test_a_run_review_with_run_directory_records_dispatches.py, tests/test_a_paired_arm_waits_for_its_partner.py, tests/test_a_re_review_is_scoped_to_what_changed.py, tests/test_review_reflex_sweep.py, tests/test_rereview_keeps_its_lane.py, tests/test_a_run_review_cannot_remove_a_siblings_record.py, tests/test_review_of_a_brief_run_names_its_brief.py and tests/test_every_module_fits_a_worker_window.py adds no failure against the base. Run it in the foreground.
  • ruff check and ruff format --check add no finding on the staged paths, judged by delta against the base blobs.

Negative control, two mutations, each applied alone. With the pairing test removed from _review_dispatch_fields, the first case must fail. With _resolved_reviewed_run_id returning the first match again, the third case must fail.
