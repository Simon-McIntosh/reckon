§1 — The name and the directory both assert something untrue

Measured during the sprint that produced this plan, not inferred. pypi-release-landed.html was created when its plan stood at impl 0.75; resource-tagging-system-landed.html was created at impl 0.33 and rewritten twice inside twenty minutes. Both live under docs/evidence/archive/.

So two claims are made by structure rather than by content, and both are false for most of the file's life. The suffix -landed asserts the work landed. The directory archive/ asserts the document is frozen. A reader browsing the archive sees completed records for work that is a third done, and the only way to learn otherwise is to open the plan it points at.

The third problem is duplication, and it is the one that will cause a wrong answer. The execution skill already requires a section-anchored plan comment on every node landing carrying the commit, the gate verdict and its quantitative measure, and the artifacts. The evidence file then receives a fuller version of the same facts. Both were written on every landing during this sprint, in near-identical words. Two records of one fact with no mechanism keeping them equal is a drift surface, and the drift will be discovered by someone quoting the stale one.

§2 — Both replacements already exist

This is not a proposal to build a store. The per-step record has two homes already, and the work is to stop writing a third.

It is committed, version-paired, and already carries per-run measurements no prose record reconstructs — worker seconds against declared effort, changed-line counts, whether scope moved mid-flight. A landed document written from it can state what a plan cost as well as what it did.

§3 — The synthesis is a better document than the accretion

Writing the landed record once, at closure, is not merely more honest — it produces a different and better artifact. An accreted record is written beat by beat by an author who cannot yet see which findings mattered, so it preserves everything at equal weight and in arrival order. A synthesis is written with the whole arc visible: it can say which node changed the plan's shape, which measurement turned out to be the load-bearing one, and which detour was a dead end worth recording as a negative result.

The evidence written during this sprint demonstrates the difference in both directions. The genuinely valuable entries — a scout finding that an acceptance could never have passed, a rehearsal that failed usefully and proved a credential path, a worker that blocked rather than writing outside a wrong fence — were only recognisable as the important ones afterwards. They were recorded beside routine per-node counts that a synthesis would compress to a line.

Done when the execution skill's rules state one per-node write and one closure write rather than two per-node writes, and a test asserts that no plan-evidence-for record exists for a plan whose status is not terminal.

§4 — The failure this trades into, and the gate that prevents it

Deferring the synthesis makes it skippable, and a plan that reaches shipped with no landed record at all is a worse outcome than a misnamed file. An accreted record has one virtue: it exists by the time the plan closes, because it was written incrementally and nobody had to remember a final step.

So closure must require the synthesis, the same way the write boundary already refuses a landing that names no continuation. That refusal is the model: a plan-terminal write is rejected unless the continuation chain is closed in words. The same boundary rejects a plan-terminal write with no evidence record carrying plan-evidence-for.

Done when setting a plan to a terminal status without a matching evidence record is refused at the write boundary with a message naming the missing record, and a test asserts the refusal fires rather than the plan closing silently.

§5 — What happens to the records already written this way

Several evidence records already exist in the accreted shape, including the two this plan cites as measurements. They are not wrong in content — the counts, commits and verdicts in them are accurate — so nothing is rewritten for its own sake.

The migration is therefore a rename question, not a content one, and it splits by plan state. A record whose plan is terminal is already what it claims to be and stays as it is. A record whose plan is still active is a live document in an archive directory, and the honest resolution is to move it out of archive/ until its plan closes.

Done when every plan-evidence-for record under an archive path belongs to a plan with a terminal status, verified by a test over the live corpus rather than by inspection, and the audit reports any future violation as a finding.

§ Followups

Stop writing the third record, then make closure require the synthesis

The order matters because the second step is what makes the first safe. Collapse the per-node write to one — the section-anchored plan comment — and leave the run ledger to carry the measurements it already carries. Then make the write boundary refuse a plan-terminal status with no plan-evidence-for record, so deferring the synthesis cannot turn into omitting it; the existing continuation refusal is the working precedent. Then reconcile the records already written in the accreted shape, which is a placement question rather than a content one: a record whose plan is terminal is already what it claims to be, and one whose plan is still active does not belong under an archive path.

Full 40-hex tokens are resolved by git object existence rather than commit reachability, because a landing record may legitimately cite a tree identity — a reachability check would reject it as unresolvable. Two choices in the test worth keeping. The record count is asserted > 0 rather than pinned to a literal, so it cannot rot into a fuse the way a snapshot of a moving number does. And the exemption fix is verified by a marker the change introduced together with the absence of the one it removed, rather than by the suite merely staying green.

This section is the plan's own thesis turned on the plan's own machinery. The document asks what it means for a landed record to mean landed; the answer here is that for 116 records it meant nothing, because the check that would have spoken for them never ran.
