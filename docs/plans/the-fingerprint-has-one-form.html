§1 — Why: the fingerprint carries a form only collapsed plans needed

A stored plan review stays valid while the plan's fingerprint still matches it. _fingerprint_forms in reckon/crew/plan_review.py accepts three digests of one snapshot:

  • the section-set form;
  • a pre-collapse form, which keeps section declarations and landed cards;
  • the whole-document form.

The pre-collapse form exists because the landing beat used to collapse a section's body into a landed card. Since a-plan-is-done-when-every-section-is-ticked §7, the landing beat ticks a section instead. No skill now calls the collapse_section op (_apply_collapse_section in reckon/_store.py).

This work was that plan's §8. The lead dropped it from that plan on 2026-10-12 (decision fingerprint-retirement-timing), so that the plan could close, and it moved here.

The risk is the one that kept it deferred. A change to the fingerprint's shape makes every plan whose stored review matched only through the retired form owe a new review at its next build. So the retirement starts with a count of those reviews.

§2 — Count the stored reviews that match only through the pre-collapse form

Deliverable. A read-only census, across every mounted project, of every stored plan review and every delivered plan-review sidecar. For each, record which of the three forms its fingerprint matches against the plan's current snapshot.

Matching only through the pre-collapse form does not by itself mean retirement uncovers a review. When the whole-plan match fails, review_coverage in reckon/crew/plan_review.py falls through to per-unit coverage, which compares each section's digest with the review's own snapshot and can still cover it. So the count that decides §3 comes from review_coverage itself: run it for every plan once as is and once with the pre-collapse form withheld from _fingerprint_forms, and count the plans whose covered units shrink.

The census reads through the modules that already own each population, so its count is the one production sees:

  • stored reviews from list_plan_reviews(project=None) in reckon/crew/plan_review.py, which reads the committed tree beside staging and excludes code reviews;
  • delivered sidecars from delivered_reports over _delivered_report_sidecars, in the same module;
  • the three digests from _fingerprint_forms, tested for membership the way the stored-review reader does.

The census also names two things. First, every caller of collapse_section and of landed_section_ids outside tests. Second, any live run whose write paths claim reckon/crew/plan_review.py or reckon/_store.py, enumerated with list_live() in reckon/crew/runs.py and read per run with declared_claim_paths in reckon/crew/claims.py.

Done when the report under the run directory lists, per project, the count of reviews matching each form, the slugs that match only through the pre-collapse form, and the plans whose covered units shrink when that form is withheld, with the script that produced it. Two fixtures are the controls. A review of a collapsed plan, whose sections are not covered per unit, must be counted as pre-collapse-only and must lose coverage. A review stored under the current section-set form must be counted as neither. Collapse history does not decide the form a review matches: the pre-collapse form is the older definition that kept section declarations in the digest, so a review stored under that definition matches only it, whether or not its plan was ever collapsed. Write paths: the run's own report directory.

§3 — Retire the pre-collapse form and the collapse op

Deliverable. _fingerprint_forms returns the section-set and whole-document forms only. The collapse_section op is removed from _store.py's op table and from the op vocabulary the MCP server publishes. Plans already collapsed keep their cards, and the display path in reckon/mcp_views.py that reads landed cards is unchanged.

This section runs only when §2's census shows that retiring the form uncovers no stored review, or uncovers a number the lead accepts in writing on this section.

Done when a test shows a plan whose collapsed card is unchanged keeps its stored review, and another shows collapse_section is refused as an unknown op. The test files importing plan_review show no added failure against base. The negative control restores the pre-collapse form, and the census's pre-collapse-only fixture must then read as covered again. The op's entry in skills/reckon-edit/SKILL.md is removed with it. Write paths: reckon/crew/plan_review.py, reckon/_store.py, reckon/mcp.py, skills/reckon-edit/SKILL.md and tests/test_the_fingerprint_has_one_form.py.
