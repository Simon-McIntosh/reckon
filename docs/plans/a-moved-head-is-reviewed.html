A resumed run reads complete again while its stored review is keyed to a superseded head, so the head that merges goes unreviewed unless the coordinator notices. §3 — The reflex launches a review for every settled head

Deliverable. The cause §2 names is repaired in the function it names, by extending the existing path through dispatch_review_for_run, review_head_move and carry_review_forward in reckon/crew/recovery_review_dispatch.py. No second launch path is added. After the repair, a re-review round of a resumed run whose head moved launches, rather than colliding with the round before it. This covers two of §2's nine misses. Six others were the review tier's skip of test-only moves, which the-review-loop-runs-without-hand-steps §3 retired (merge 7c923144a). The last was a coordinator's hand-dispatch race, which the reflex answered correctly. The reflex still carries a review forward when §5 of a-review-is-sized-to-its-risk says the move needs none.

The cause to repair. §2 named it: a re-review reuses the first round's node id, so its worktree path collides with the first round's and the launch fails. In dispatch_review_for_run, each review round of a run gets a node id and a worktree path that differ from every earlier round's. Every round's id carries the head it reviews, so the composition site needs no round history. Rounds at different heads therefore never share an id. A round at an unchanged head is never launched, because a review keyed to that head is carried forward rather than relaunched. The id follows the rule repair_node_id in reckon/crew/repair.py already applies to repair rounds, <prefix><source>-<head[:12]>, with the head _review_dispatch_fields already resolves. That rule is extended once so both prefixes share it, rather than written a second time. The run-review node id is composed in reckon/crew/recovery_review_subject.py (f"{REVIEW_NODE_PREFIX}{source_node}"), so the shared rule is applied there. Two readers recover the reviewed run by stripping the review-of- prefix from a node id: _task_identity in reckon/crew/dispatch_sessions.py and _resolved_reviewed_run_id in reckon/crew/recovery_review_delivery.py. Today neither strips a trailing head suffix. This section changes both to strip it, so that a later round still resolves to the run it reviewed. The plan-review and code-review id sites in reckon/crew/recovery_review_subject.py and reckon/crew/plan_review.py are outside this section. This section adds no CLI option, view, public definition or refusal family. Review tiers are not changed here; the lead's 2026-10-12 ruling on test-only runs is built by the-review-loop-runs-without-hand-steps §3.

Done when tests/test_a_resumed_head_is_reviewed.py drives the watch path with a temporary run through four cases:

  • A run completes and is reviewed at head A, then is resumed and completes again at head B, where the move from A to B changes runtime source. The reflex launches exactly one review keyed to B, and its node id and worktree path differ from the first round's.
  • A resume from A to B that changes only data (plans, evidence or state) carries the stored review forward and launches none, under §5 of a-review-is-sized-to-its-risk.
  • A run whose stored review is keyed to its head gets no launch.
  • A third round of the same run gets an id and path distinct from both earlier rounds, and _task_identity and _resolved_reviewed_run_id resolve every round's id to the reviewed run.

Each case that reproduces a cause from §2's report is named for it. The tests importing reckon/crew/recovery_review_dispatch.py or reckon/crew/recovery_watch.py show no added failure against base, their list built from the head tree. The negative control is executed and logged under the run directory: with the reused round id restored, the runtime-source resume case fails. Write paths: reckon/crew/recovery_review_dispatch.py, reckon/crew/repair.py (where repair_node_id's rule gains its prefix), reckon/crew/recovery_review_subject.py (where the run-review id is composed), reckon/crew/dispatch_sessions.py and reckon/crew/recovery_review_delivery.py (the two id readers), and tests/test_a_resumed_head_is_reviewed.py.
