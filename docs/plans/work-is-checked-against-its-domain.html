§1 — Why: work that passed every check reckon runs, and was wrong

On 2026-10-21 the four power_convertor coordinators were asked which of their recent work was low value in hindsight, and what signal would have warned them. Three answers account for most of the waste, and the lead asked for them to be treated at their root in reckon.

What happenedWhy reckon let it happen
The session host dispatched two reviews at heads whose previous review still had unanswered blocking findings. Both were certain to repeat those findings, and the coordinator stopped them by hand.The review reflex in crew/recovery_watch.py dispatches a review for every run classified scoring whose coordinator's follower is live. Neither it nor dispatch_review_for_run reads the node's previous review record.
The first CS co-wound tape model was built at 40 sections when the repository's converged count is 168, which overstated the result 15-fold.The convergence rule lives in the repository's code. No brief carries a repository's numerical invariants, and no gate checks a node against them.
A landed record claims that CS1's insertion step trips quench detection at 1.87 V. The claim rests on a static capacitive divider, which is wrong at low frequency. It passed two reviews and was found by the coordinator in a negative-control log.The review dimensions are goal_fidelity, evidence, scope_discipline, durability, fit and reuse. All six grade the work against its brief, and none asks whether the result is right in the domain.

The same coordinators named four more instances of the second and third causes:

  • A solver convergence test measured how far a 1e-5 perturbation spread and accepted it. The lead rejected that as normalising an instability, since in a lossy system a small perturbation must not grow.
  • The fast-discharge resistor's inductance was modelled three ways before anyone read the measured prototype report.
  • A converter model was fitted before anyone checked that its identification constants were available. They are withheld.
  • An acceptance compared a physical zero with a filtered measurement, so the node failed for a reason its method created rather than its physics.

Every one of these is knowledge the repository's people already hold. Reckon offers no place to declare it once, so each brief and each review has to rediscover it, and most do not. This plan gives that knowledge a declared home and makes dispatch, promotion and review read it. reckon stays repository-agnostic: the rules are the repository's, and reckon only carries them.

§2 — No review round while a blocking finding is unanswered

Before a review is dispatched for a node, by the reflex or by hand, the node's newest stored review is read. If it carries blocking findings that are not yet disposed, the dispatch is refused with repair-owed. A run review's finding is retired by crew dispose --project P --run <id> --finding <index>, with --kind folded --node <n> when a repair node took it or --kind exempted --reason <r> when it is declined. That is the writer the obligations already pair with their duty row; crew review --answer addresses plan reviews only and cannot retire it. The refusal names each finding and the crew dispose command for it, and the coordinator's obligations show a repair-owed entry in place of review-missing. Disposing the findings lifts the refusal, and the next round then reviews the repair rather than repeating the last one.

Done when: a fixture run whose previous review has one unanswered blocking finding is refused by the reflex with repair-owed, and no review run is created. The same fixture with the finding disposed through crew dispose dispatches. On the base commit the first fixture dispatches a review, and the test fails there. The obligations test reads repair-owed for the first fixture.

§3 — A repository declares its domain rules once

The project resource (docs/state/<project>/project.json) gains an optional domain block. No schema for the project resource exists today: _read_project_json in reckon/project_state.py checks the envelope's identity and validates nothing else. This section therefore adds a typed model for the block in reckon/_schema.py, validates the block on read, and publishes it beside plan.schema.json under docs/_shared/. The block has three lists.

invariants are rules a result must satisfy. Each entry has an id, the rule in one sentence, applies_to (path globs or tags) and an optional check, a command whose zero exit means the rule holds.

review_checks are questions a reviewer must answer about any node they apply to. Each has an id, the question and applies_to. Examples from the coordinators above are the limit behaviour at DC and at high frequency, whether both sides of a comparison pass through the same measurement operator, whether a perturbation grows, and whether a measurement of the modelled quantity already exists.

model_paths is a list of path globs naming where the repository's models live. A node whose write paths match one is a model-building node for the purposes of §6. The plan format has no section-level tags, so the write paths are the carrier that exists.

reckon project domain --project and the project read in the MCP return the block. An absent block changes nothing, so every repository keeps today's behaviour until it opts in.

Done when: a fixture project with two invariants and two checks loads, and a malformed entry (a missing rule, or applies_to that is not a list) is refused naming the field. A project without the block reads an empty domain. PLAN-FORMAT.md and the reckon-sync skill document the block.

§4 — A brief carries the rules its node touches, and promotion runs their checks

When a node is dispatched, the invariants and review checks whose applies_to matches its write paths or its plan's tags are composed into the brief under a fixed heading. The worker therefore reads the converged section count before it chooses one. When the node is completed, every matching invariant that carries a check runs against the node's head, and a failing check is a promotion guard. It is reported beside the others by crew complete --dry-run and waivable only with a stated reason, like every other guard.

Done when: a fixture node writing a path an invariant applies to has that rule in its composed brief, and a node writing elsewhere does not. A fixture whose invariant check exits non-zero is refused at crew complete with the invariant's id, and passes once the check exits zero. Without the declaration the same fixture promotes; that is the negative control.

§5 — A review answers the domain checks, and a failed one blocks

When a project declares review_checks, a review of a node they apply to gains a seventh dimension, domain, and one verdict line per matching check, read like the existing REVIEW_ITEMS checklist. A record that omits a declared check's verdict parses as incomplete rather than as a pass, because a reviewer who skips an item must not produce a record that looks thorough. A blocking domain finding stops promotion exactly as any other blocking finding does. The six existing dimensions and the projects that declare nothing are unchanged.

Done when: the composed review prompt for a fixture node lists exactly the checks that match it. A fixture review record with every verdict parses complete and carries a domain score, and one missing a verdict parses incomplete and names the check. The falsifier that holds prompts/review.md to REVIEW_DIMENSIONS covers the new dimension. A project without declarations still scores six dimensions.

§6 — A node names its measurement and its inputs before it starts

A brief can declare inputs: the data files, records or document identifiers the node needs. Dispatch refuses a node whose repository-path inputs do not exist and names them, so a fit is not started on constants nobody holds. A brief for a node that builds or calibrates a model also states compares_with: the measurement or reference the result will be checked against, or none-exists with the search that established it. Dispatch lints a model-building node, one whose write paths match the project's domain.model_paths from §3, that states neither. This is the "is there a measurement of this?" question the coordinators said would have saved two node rounds.

Done when: a fixture brief naming a missing input path is refused at dispatch with the path, and the same brief with the file present dispatches. A brief whose write paths match a declared model_paths glob and which states neither compares_with nor none-exists receives a lint warning, and one that states either receives none. A project that declares no model_paths is never linted, which is the negative control.

§7 — The checks find the faults that got through, on the work they missed

The power_convertor coordinators author that repository's domain block in their own repository; reckon does not write it for them. With the block in place, the cases in §1 are replayed through the new checks:

  • a domain review of the landed CS tape record, the one two reviews passed;
  • the 40-section tape node's head, checked against the convergence invariant;
  • a review dispatch at a head with an unanswered blocking finding.

Done when: the domain review raises a blocking finding about the record's low-frequency behaviour; the invariant check refuses the 40-section head; and the dispatch is refused with repair-owed. A domain review of a record the coordinators name as sound raises no blocking domain finding; that is the negative control. Each result goes to the landed record with its run id. A miss, where a check does not find the fault it was built for, is recorded with the reason and becomes a section here.
