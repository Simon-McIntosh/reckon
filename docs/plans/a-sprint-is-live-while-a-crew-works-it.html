A sprint is live while a crew works it

On 2026-09-25, read_plan(project="reckon") reported active_sprint_id: "S12". That value was written by hand weeks ago. Meanwhile S21, S22 and S23 each had a coordinator and live workers. The lead's directive that day: a live sprint is a sprint with a live crew implementing it, and the hard cap of one active sprint is removed. A stored marker says what someone once decided; a live crew says what is happening now, and that is the signal an agent needs.

§1 — What the surfaces say today

The cap comes from four places:

  • The push op makes one sprint active and demotes the rest to open.
  • The audit reports multiple-active-sprints as an error.
  • active_sprint_id is derived from the one sprint whose stored status is active.
  • The work-scheduling-surface plan (S22) records the invariant.

None of this consults the crew. Discovery returns a state block with counts by_sprint, but no sprint list. roadmap(view="summary") lists open_sprints ids and nothing about sprints closed recently.

The live crew is already readable. Every live pointer names its project and plan, and every plan names its sprint.

§2 — Liveness is derived from live crews

A sprint is live when at least one live pointer in its project serves a plan whose plan-sprint is that sprint, and that pointer is classified as working, starting or dispatched. A blocked or unpromoted pointer counts as held, not live. Liveness is computed at read time from the same classification crew(view="live") uses, and is never written to any resource.

Each sprint row carries four fields:

  • live
  • live_runs
  • live_sessions: the coordinator session ids
  • last_activity_at: the newest stream write among its runs

Done when:

  • A test with a synthetic config home, holding live pointers for plans in two sprints and a terminal pointer for a third, asserts that exactly those two sprints read live: true with the right run and session counts.
  • The third sprint reads live: false.
  • No resource file changes as a result of the read.
  • The declared mutation, reading the stored active status instead of pointers, is applied, and the test is observed to fail. The log is recorded.

§3 — Every summary lists open and recently closed sprints

Discovery's read_plan(project) and roadmap(view="summary") both gain a compact sprints list:

  • every sprint not done or shipped
  • every sprint closed within sprint_recent_days, which defaults to 14 and is configurable in flight config

Each row gives the sprint id, theme, stored status, the §2 liveness fields, member and pending counts, completion percentage, and closed_at for a closed sprint. Rows are ordered live first, then open, then recently closed.

Done when:

  • A test on a synthetic project with one live, one open idle, one closed 3 days ago and one closed 40 days ago asserts that the first three appear, in that order, and the fourth does not.
  • The recorded length of the reckon project's discovery summary at the worktree head stays under the response budget.

§4 — The one-active cap is removed

The changes:

  • push no longer demotes other sprints. It sets active on its target as a scheduling hint and leaves every other sprint's status alone.
  • The multiple-active-sprints audit finding is retired.
  • active_sprint_id stays as a compatibility field. It now names the live sprint with the most recent activity, or the stored active sprint when no sprint is live. It sits beside a new live_sprint_ids list.

The reckon-sprint skill text and the roadmap's active_sprint_id description are updated to match. The S22 coordinator is told, because work-scheduling-surface records the old invariant.

Done when:

  • A test pushes two sprints and asserts both keep active.
  • The audit on that project reports no multiple-active-sprints finding.
  • active_sprint_id follows the live sprint when crews exist, and falls back to the stored status when none do.
  • Every existing sprint test that asserted demotion is updated to the new contract in the same commit. Each such change is named in the landing record.
