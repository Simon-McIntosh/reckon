§1 — Why: a refused wait left a session idle for eight hours

nova-8a reported this on 6 November. Run r-20261106T084812488886-polygon-near-band-quadrature (nova session 35a66cc6-f4f1-4358-8dbb-99c9333c7249) parked waiting on Slurm job 1306915 with this probe:

wait_probe: ["python3","-c","import subprocess; p=subprocess.run(['squeue','-h','-j','1306915'],...); print('PENDING' if p.stdout.strip() else 'TERMINAL')"]

The reader refused it as a probe that cannot fail: “it names nothing outside the worker — no job id, pid, port or path” (reckon/crew/recovery_liveness.py near lines 1003–1008). That is false: the job id is in the argument. _wait_probe_reference_kind (reckon/crew/recovery_wait.py near line 683) splits an argument into words only when the command is one of _WAIT_PROBE_SHELL_COMMANDS (near line 668, bash sh zsh dash ksh), so a python3 -c string is one opaque token. Even split by _wait_probe_shell_words (near line 744), the Python list spelling '-j', keeps its trailing comma and the flag rule would not match.

The run was classified unreadable, whose recovery verb is repair (reckon/crew/recovery_vocabulary.py near line 88), with next action “repair the waiting declaration”. But crew view obligations for the session returned count 0 with unreconciled_runs 1: RECOVERY_CLASSIFICATION_DUTY_KINDS (reckon/crew/obligations.py near line 64) lists only needs-help. The follower delivered nothing, the session sat idle from 11:52Z until the lead asked at about 19:40Z, and the awaited Sirius job ended in TIMEOUT and OOM at 15:17Z unseen. nova-8a resumed the run with a sacct argument-vector probe.

nova-8a also asked that crew check --manifest refuse the probe when the manifest is written. It already does: audit_manifest (reckon/crew/reports.py near line 2576) runs _wait_declaration_refusal on a waiting manifest. A worker that ran it would have met the same misleading reason, which §2 corrects, so no separate section is needed.

§2 — A job id inside an interpreter's code string is read, or named as unread

Deliverable. _wait_probe_reference_kind reads the code string an interpreter is given with -c (python, python3 and versioned python3.N, perl, ruby, node with -e) as words, the way it reads a shell's string, and strips a word's list and call punctuation (, [ ] and quotes) so '-j', '1306915' reads as the flag and the job id it is. A probe it still finds no reference in keeps its refusal, but the refusal then says that the probe runs an interpreter whose code string named no job id, pid, port or path the reader recognises, and names the argument-vector shape (["squeue","-h","-j","<id>"] or a sacct vector) instead of saying the probe names nothing.

Done when a new tests/test_an_interpreter_probe_names_its_job.py shows three things: the §1 probe, verbatim, is accepted as naming job 1306915; ["python3","-c","print('pending')"] is still refused; and that refusal's text names the interpreter and the argument-vector shape. Three negative controls: reading interpreter strings as one token makes the first case refuse; keeping the trailing comma on '-j', makes the first case refuse; and restoring the old refusal text fails the third case. The test files importing reckon.crew.recovery_wait or reckon.crew.recovery_liveness add no failure against the base revision, run one arm at a time with at most -n 4. Ruff adds no findings on the staged paths. Every log is under the run directory, starts with its revision and the literal command, and ends in EXIT=. Write paths: reckon/crew/recovery_wait.py, reckon/crew/recovery_liveness.py and the new test.

§3 — A run whose recovery is repair is a duty of its session

Deliverable. RECOVERY_CLASSIFICATION_DUTY_KINDS in reckon/crew/obligations.py gains an entry for the repair recovery verb, so a run classified unreadable with a refused wait declaration is listed among its session's obligations with its next_action and the refusal text, and the follower emits a row for it. A run already owed under another duty kind is not listed twice. This edits the same map as a-reexec-never-orphans-a-dispatch §4, which adds launch-failed, so it waits for that section to land.

Done when a new tests/test_a_refused_wait_is_an_obligation.py shows three things with a temporary crew home: a waiting run whose manifest carries the §1 shape of refused probe appears in obligations for its session with the refusal text; a waiting run with a valid probe does not; and a run already listed as turn-ended-early is listed once. Three negative controls: dropping the duty-kind entry leaves the first case absent; listing every unreadable run regardless of verb makes a run with another verb appear; and skipping the de-duplication lists the third run twice. The test files importing reckon.crew.obligations add no failure against the base revision, run one arm at a time with at most -n 4. Ruff adds no findings on the staged paths.
