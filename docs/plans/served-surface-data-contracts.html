Server data contracts · prerequisite for the artifact tabs and the fleet home

What the Server Must Serve Before the Canvas Can Land

The handoff canvas binds three things the server does not yet emit: figures as first-class artifact rows, an edited timestamp on every artifact, and a fleet index whose counts and activity are computed from the repositories rather than read from a superseded index file. This plan lands those three contracts and nothing visible, so the two surface plans that consume them can be built against real payloads.

§1 — Why this exists

The design canvas imported at design/reckon-spa-handoff.dc.html was checked against the served state on 2026-09-03 and its triage (design/reckon-spa-handoff.md, part E) lists six data contracts it could not verify. Reading the code settles them:

§2 — Figures become inventory rows, and every row carries an edited stamp

Figure rows. A new module, named for what it does (reckon/figures.py), enumerates docs/figures/**/*.png and docs/figures/**/*.svg and returns one row per file with type: "figure", slug equal to the path relative to docs/figures/ (so rendered-evidence/ready-lanes.png, matching the canvas fixture), title from the filename with separators turned into spaces unless a sibling capture-index.json or <name>.geometry.json names the capture, dims as "W × H", and for_plan equal to the first path segment when a plan of that slug exists in the same project. Dimensions come from the file, not from a library: a PNG's width and height are the two big-endian 32-bit integers following the 8-byte signature and the IHDR chunk header; an SVG's come from its viewBox or width/height attributes. Reckon has no imaging dependency and gains none. The discovery loop in reckon/serve.py appends these rows after the typed resources; reckon/resources.py keeps treating figures as infrastructure so nothing else changes type semantics.

Edited stamps. Every inventory row of every type gains edited, an ISO-8601 timestamp: the file's last git commit time, replaced by its working-tree mtime when the path is modified or untracked. The existing batch helper that finds first-commit times is the model; a sibling batch for last-commit times keeps discovery to two git invocations per project rather than one per file. created is unchanged and edited is never earlier than it.

§3 — The fleet index is computed live

GET /_projects/index.json is the one cross-project payload, and the fleet home reads everything from it. Today each project row is whatever its superseded index file said. A new module (reckon/fleet_index.py) computes each mounted project's row from the repository: plans_count, active, blocked, pending and shipped from discovery over actionable plans, with the same effective-status rule the project SPA already applies; live as the count of that project's live run pointers; last_edited as the latest edited stamp across its artifacts; active_sprint as {id, theme} from the distributed sprint resources or null; and activity30, thirty integers, one per calendar day ending today, counting commits that touched docs/plans, docs/research or docs/evidence in that repository on that day, read from one git log per project. A project with no commits in the window reports an empty list, not thirty zeros, so the surface can distinguish silence from a flat line, which the canvas requires. collect_projects delegates to the module and keeps its response envelope, so docs/ui/home.jsx and docs/ui/_shared.jsx keep reading the fields they already name.

The reference instant is a parameter of the function, defaulted to now, so the test can fix it. A test that computes a day bucket from the wall clock and then asserts a literal count is the fuse the repository's test rules describe; the fixture commits are dated relative to the injected instant.

Gate for this plan, recorded when the measure runs: against this repository, discovery returns at least one figure row per PNG under docs/figures, every row of every type carries an edited stamp, and the fleet index reports a non-empty activity series for this project. Its evidence is the two named test files passing plus one recorded run of discovery and of the fleet index against the real checkout with the figure-row count, an example edited stamp and the activity series length written into the execution record.

§4 — Out of scope

No surface changes: this plan alters payloads only, and both consuming surfaces are specified on their own plans. No new plan-schema field and no MCP tool: figures are served rows, not typed resources with a lifecycle, and the fleet index stays a read-only rollup. The live change stream (/_changes/<project>) already exists and is consumed by artifact-feeds-and-reader; it is not extended here.

§ Decisions

Where do figure dimensions come from?

The canvas shows dimensions on every figure row. Twelve of the forty figures have a geometry sidecar, so sidecars alone would leave most rows blank, and an imaging dependency for two integers per file is a cost every install pays. The PNG IHDR chunk and the SVG viewBox are eleven lines of standard library.

What is an artifact's edited time?

The canvas sorts feeds by edited at minute resolution and the meta is a date. mtime alone resets on every clone and worktree, which would make a fresh checkout report every document as edited today. Git time is stable and mtime covers the served working tree's uncommitted edits, which the server deliberately serves.

How is a project with no plan edits in the window represented?

The canvas prints "no recorded activity" for a silent project and never draws a zero-height polyline; the surface can only make that distinction if the payload does.
