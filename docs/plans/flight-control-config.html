§1 — Why this exists

Worker routing must be tunable from one place without editing a skill. The user-space agent policy forbids skills, plans, schemas and source from prescribing concrete models, model families or relative hierarchies — those are runtime choices for the current task. It permits application configuration. This plan builds that configuration: the single surface where the default backend, its model and effort, concurrency, gate strictness and worker fences are set for every project, and from which the current prompt can always deviate.

The architecture, layer precedence and rejected alternatives are recorded in Agent Fleet Orchestration §4. Read it before implementing; do not restate it here.

§2 — Deliverables

The LinkML source and its committed artifacts. Author reckon/schema/flight.yaml as the LinkML model covering default_backend, per-backend launch/command/ model/effort/sandbox/session_reuse/ concurrency/time_budget, the roles map, and the gates, fences, worktree and summary blocks. Generate and commit both reckon/_flight_schema.py (Pydantic) and docs/_shared/flight.schema.json (JSON Schema export). The generated files are committed so reading a config at runtime requires none of the toolchain, and runtime gains exactly one dependency, pyyaml.

Place the generator in the dev dependency group, not an optional extra. The reason is mechanical: uv run auto-installs dev groups with no flag, so regenerating the schema is a bare command with nothing to remember, while an extra requires an incantation a dispatched worker can miss. That matters because the failure mode of a missed extra is not an error — it is a worker hand-editing the generated file and silently desynchronising it from its source. Runtime weight decides the rest: the full generator adds 62 packages to a 30-package closure, tripling the install of a service that runs continuously for a generator that runs a few times a year.

Four-layer resolution. Implement resolution in precedence order — shipped model defaults, then ~/.config/reckon/flight.yaml, then <repo>/docs/state/<project>/flight.yaml, then explicit overrides supplied by the caller. Merging is per-key deep merge, not whole-block replacement, so a project overriding one backend's model does not have to restate the rest of that backend. A malformed layer is a hard error naming the file, the key path and the violated constraint — never a silent fallback to defaults.

Backend availability probing. For each configured backend of launch: cli, report whether its command resolves on PATH and whether it appears authenticated. Availability is reported, never acted on silently; the caller decides whether to degrade to native.

The reckon flight command. An agent-callable primitive: JSON on stdout by default, --pretty for humans, --project X to include the project layer, deterministic key ordering, and a non-zero exit only on a config error. Output carries the resolved config, the per-key provenance of which layer supplied each value, and the availability report. Provenance is what makes the surface debuggable — a resolved value with no visible origin is untunable.

A committed host config. Write the initial ~/.config/reckon/flight.yaml with the values agreed in the design — default_backend: codex, codex at gpt-5.6-sol and effort high, claude at effort medium, native as the in-harness backend, read-only sandbox for review and investigate roles, gates.enforce: strict. It is not committed to the repository — record its content in this plan's evidence instead.

§3 — Evidence gates

These are measures to demonstrate, not thresholds to tune around. The sprint does not advance through a gate that has not produced its evidence.

MeasureRequired evidence
Schema round-trip The committed Pydantic model and JSON Schema are both regenerable from reckon/schema/flight.yaml with no diff, proving the committed artifacts are not hand-edited drift.
Layer precedence A test asserting all four layers, in which a project layer overriding one backend key leaves that backend's other keys at their host or shipped values — deep merge, not replacement.
Provenance reckon flight --project reckon reports, for every resolved key, which layer supplied it. Spot-checked against a deliberately three-layer setup.
Malformed config fails loudly A test proving an invalid enum and an unknown key each raise an error naming file, key path and constraint. No test may show a silent fallback to defaults.
Availability Recorded output showing codex and claude detected on PATH, and the report a missing binary produces.
Machine contract Default stdout parses as JSON with a stable key order; exit code is 0 on a valid config and non-zero on an invalid one.
Suite green The full reckon test suite passes, with the new-test count recorded.

§4 — Constraints

No concrete model identifier, provider name or relative model hierarchy may appear in reckon source, the LinkML schema, the generated artifacts, any skill, or this plan's prose. They live only in a config file's values, which is user data. The host config referenced above is illustrative content of a user file, not a default embedded in the package.

pyproject.toml is not a config location. It is absent from the wheel, so a [tool.reckon] section would resolve only from a source checkout.

§ Decisions

How is the flight config schema authored and validated?

Reckon already has a Pydantic + published-JSON-Schema stack for plan state. Adding a second schema system needs justification.

LinkML is the established house pattern — nova, helix and imas-codex all declare it. The dev group is chosen over nova's optional extra because uv auto-installs dev groups with no flag, so regeneration needs no incantation a dispatched worker could miss; the failure mode of a missed extra is a silently hand-edited generated file. A full runtime dependency was rejected on measured weight: it adds 62 packages to a 30-package closure, tripling the install of a continuously-running service for a generator invoked a few times a year.

Where does host-level flight config live?

pyproject.toml is not shipped in the wheel, so it resolves only from a source checkout and would break reckon build and wheel installs. It also conflates build metadata with runtime routing. Host config belongs with host config.
