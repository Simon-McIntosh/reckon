§1 — What a coordinator had to do by hand, and why none of it needed a coordinator

The imas-efit S13 coordinator ran 27 landings on the local lane between 2026-09-16 20:30Z and 2026-09-17 morning, and kept a record of everything it did by hand that the crew surface could have done. Evidence and timestamps are under ~/.config/reckon/crew/reports/ship-s13/.

The list is not a wish for features. Every item is work the surface already holds the facts for and declines to perform, so a human-facing coordinator performs it instead — and each hand-performance is an opportunity to do it slightly differently from the last coordinator.

Two of the ten reported items are repaired or in flight elsewhere and are not restated here. Two more belong to plan-writes-are-not-fenced, which owns the concurrent-writer problem. This plan owns the remaining five.

The remedy is a better-designed toolset, not a better-instructed coordinator. That distinction is the plan's whole shape and it is easy to get backwards. Nothing here restricts what a coordinator may do: reading the code, editing it, and refactoring it with the overview only a coordinator has are legitimate and valuable, and a rule telling coordinators to do less of any of that would make the system worse. What this plan targets is the busy work — carrying a value from one surface to another, copying a file so it survives, registering twenty-seven members one at a time — which a coordinator performs only because the work fell through a gap and someone had to catch it.

The test for every item is therefore the same: would a well-designed surface have left this for a human at all? Where the answer is no, the repair belongs in the tool. Adding a rule instructing coordinators not to compensate would remove the compensation and leave the gap, which is strictly worse than the state this plan starts from — the work would still fall through, and nobody would be catching it.

§2 — A roster write that rides someone else's commit

crew member add rewrites docs/state/<project>/crew.json and does not commit it. Verified: there is no commit anywhere in the add path. The roster diff therefore rides whatever commit comes next — for the reporting coordinator that was a plan write (39bc64bc); for this session it would have been a promotion.

The consequence is a commit whose message describes one change and whose content carries two, which is the condition that makes a later reader unable to tell what a commit did. The coordinator registered 27 members by hand (clive-46 through clive-72) because dispatch refuses an unknown member, so the dirty write happened 27 times.

Two repairs, and they are not equivalent: member add commits its own write, or dispatch registers a missing member itself and commits that. The first is smaller. The second removes the reason a coordinator was registering members one at a time, and is the one that matches this plan's thesis.

Landed 2026-09-17. member add commits its own roster write — an opt-in flag on the ledger registration, default off so every internal caller is unchanged, requested only by the public command — and that commit carries only the registration it names, refusing when another uncommitted registration is already in the file rather than absorbing it. The landing comment a promotion writes now names its writer instead of the run's member, and no longer reports success while silently discarding a corrected outcome. Confirmed in imas-efit under real load within the hour: two member adds and six dispatches left a clean tree and an empty roster diff, where the previous session had been sweeping those diffs into plan commits by hand. Four nodes, reviews 85, 100, 100 and 100. Full record: the cumulative evidence.

§4 — An evidence record that has to be authored before a plan can ship

Shipping a plan requires a cumulative evidence record. When a plan's landings are investigate nodes the deliverable is a report rather than a diff, no evidence record exists, and the coordinator authors one by hand — as the reporting session did for docs/evidence/archive/boundary-method-critical-path-closure-landed.html.

The run already carries what such a record needs: its report path, its commits, its gate, its measured outcome. A complete or edit_plan path that composes the record from the run's own report would remove the hand-authoring step entirely, and would remove the more serious hazard behind it — that a coordinator writing an evidence record by hand is writing the evidence for work it is also judging.

Constraint from the reuse map — the composer exists, the source does not. The composition engine already exists: reckon/evidence.py:synthesize_landed_record (:244) composes this artifact and _render_document (:134) renders it. The missing half is the source. reckon/evidence.py:_run_rows (:84) draws from the ledger row, which is exactly why a plan whose landings are investigate nodes has nothing to compose from — their deliverable is a report on disk, and no code reads it. The repair gives the existing composer a report-backed source; it does not add a second composer, because two implementations of one record is the drift this plan's own §9 argues against.

Landed 2026-09-21. The composer now has the second source this section asks for. Commit 1f12f4bf gives reckon/evidence.py a report-backed pass: for a run with no commits the composer reads the manifest the row already names, takes the durable path the run declared, and cites it by path with its content reproduced inside the section; when no declared path resolves to a readable file the section states that no record could be composed and why, rather than rendering an anchored section with no content. A run that has commits is composed exactly as before, and the module still defines one document renderer — _render_document — so no second composer was introduced, which is the constraint this section set.

The declared mutation, remove the report-backed source so the composer falls back to ledger rows only, reddened the two report-backed assertions and left the ledger-row and single-renderer assertions green, so the red log is the declared mutation rather than a failure for another reason; it carries the mutation verbatim on its first line. The focused gate (tests/test_evidence_from_report.py with the pre-existing tests/test_evidence_synthesis.py) reports 1f12f4bf's change as 9 passed, against zero coverage for the behaviour at base. The residue is recorded rather than smoothed: manifests deleted with the /run/user tree they lived in, run directories gone, and artifacts values written as prose rather than as a path — each now reaches the reader as a stated absence, none as a cited report.

Not claimed by this node. The gate measures this node's own change, not the merged result; verifying the merged head belongs to a separately dispatched test node. One limit the section's own wording exposes: the report-backed pass is reached for every commit-less row, which includes review rows as well as investigate rows, so a plan's landed record will carry a cited report for every commit-less node rather than only for the report-delivering ones. That is the behaviour the four assertions pin, and narrowing it by role is a change to the contract this section states rather than a defect in the pass.

§5 — Per-node wall time and width-at-start, already in the ledger

The ledger row carries dispatched_at and completed_at. Per-node wall time is their difference, and width-at-start is derivable from the live pointers at the dispatch stamp. Neither is emitted, so the reporting coordinator recorded both by hand in post_repair_record.md, and another session asking for the same figures had to ask a human for them.

This is the smallest item and the clearest instance of the plan's shape: the values are present, the derivation is arithmetic, and the surface emits neither. It is a read, not a mechanism.

Constraint from the reuse map, and it decides what the figure is derived from. Both halves of the arithmetic already exist: reckon/ledger.py:_worker_seconds derives seconds from a row's dispatched_at and completed_at, and reckon/crew/summary.py:concurrency_bounds already derives width from occupancy. Only the emission is missing. (Both are named by symbol rather than by line deliberately: the line numbers this paragraph first carried were exact when written and one of them was stale within the hour, moved by this very section's own landing. A citation into a file the plan is about to change should name what does not move.) Do not emit the stored wall_seconds field. Measured at dc39dad5, it equals completed_at minus dispatched_at on 564 of 1156 rows, so on nearly half the ledger it is a different quantity from the one a reader asking for per-node wall time wants — and two coordinators have already derived a false overrun rate from it. §8 — The measure that separates a fix from a workaround

Each section above is satisfied only when the hand step disappears, not when it becomes easier. A helper script that copies gate logs, a documented convention for roster commits, or a template for hand-authored evidence records would all reduce the effort and leave the coordinator performing the step — which is the condition this plan exists to remove.

So every node's measure names the hand step and asserts a run completing without it: a promotion whose cited gate log resolves inside the run directory after the source is deleted; a member add leaving a clean tree; a plan shipping on investigate-node landings with no hand-authored evidence file; a ledger read returning wall time and width without arithmetic by the reader.

A function with no caller has not removed any hand step, and this codebase produces them habitually. Measured twice in one session on this plan, by two unrelated reconnaissance nodes: reckon/crew/reports.py:audit_manifest existed, was correct, was covered by four test modules, and nothing in production called it; then reckon/crew/summary.py:run_rows landed green and falsified, and a word-boundary search returned its definition and its own test and nothing else. In both cases the mechanism was already there and the gap was the wiring, which is not what either section's prose predicted.

That has a consequence for how a node on this plan is written. A measure that names a function is satisfiable without the hand step disappearing; a measure that names the surface a reader reaches is not. So a node's done-when asserts the behaviour at the entry point a caller actually uses — the command, the read, the promotion path — and, where the node's purpose is to create a first caller, asserts the call-site census directly. Fencing a node to the module that holds the mechanism, without the files that would call it, makes its own measure unsatisfiable: the worker can only land the half inside the fence, and the hand step survives.

§9 — A manifest contract checked at the last possible moment

The promotion contract validates a worker's manifest when the coordinator promotes it — hours after the worker's process has ended. Measured twice on 2026-09-21 in imas-efit: two workers finished sound work with sound negative controls, and both promotions were refused because the contract reads negative_control_log as a scalar path and neither manifest was shaped that way. One held a mapping of declared, log and result sub-keys; the other a markdown heading with the path beneath.

Three properties make this the same animal as sections 2 to 6. The check fires when the one party who could satisfy it is gone. The only remedy available to a coordinator is editing an artifact it did not author, which is the condition under which two coordinators produce two different repairs — and they did, one moving the value to a scalar and preserving the mapping alongside, the other preserving the worker's section under a heading and adding the scalar above it. And the check is satisfiable by editing its own input, so the compensation is corrosive rather than merely undesirable: a coordinator under time pressure can make the refusal go away without adding any evidence, and nothing afterwards distinguishes that from the honest repair.

The repair this plan owns is the write-time check. The manifest is written while the worker still has turns, so validating at the moment of writing refuses it then, to the party who can fix it, at a cost of one turn. Widening the reader to accept the shapes workers actually produce is the other candidate — it removes the refusal but leaves the lateness, and it belongs to the plan that owns the field, crew-runtime-positive-controls. The two are not exclusive, and only the first matches this plan's thesis.

The measure is §8's, applied here: a worker whose manifest is malformed learns of it while it still has a turn in which to act, and a promotion of a manifest that passed the write-time check performs no validation a coordinator could satisfy by editing the manifest.

One correction to the record. The reporting coordinator checked whether it had been hand-editing crew.json and had not: every write to it in that session came from crew complete or crew member. The ledger is not the surface that leaks this work — the manifest contract is. Worth stating because the two are easy to conflate from the outside, and a repair aimed at the ledger would miss.

The write-time check landed enforcing a different contract from the one promotion enforces, which is this section's own thesis turned against it. Found by the node that hardened the check's test, measured on that node's own changed paths, and verified since at the merged head. reckon/crew/reports.py:audit_manifest tests exact membership — a changed path is stray unless it appears in node.write_paths verbatim. reckon/crew/promotion.py:_outside_declared_scope tests root containment, and says so in its own docstring: it returns paths "not contained by a declared write root". Where dispatch grants a directory, the two disagree: the write-time check calls a file under that directory stray and the promotion check accepts it.

So the early refusal this section installed currently sends a worker to repair a manifest that promotion would have accepted. That is the same class of harm as the late refusal it replaced — a refusal the recipient cannot act on correctly — simply aimed at a different party one node earlier, and it is worse than the original in one respect: a worker who obeys it edits a manifest that was already right. A check moved earlier must carry the same contract, not a stricter one, or it trades a late false negative for an early false positive and calls that progress.

The remaining node makes the two agree. Doing it in reckon/crew/reports.py by making the membership test containment-aware keeps one implementation reachable from both surfaces; having dispatch enumerate files instead of granting a directory would also close it, but it moves the fix away from the contract and into the caller, which is the drift this section already warns about.

§10 — A fence that can only be drawn once

A worker that blocks because its write scope is too narrow can be answered but not re-scoped. Verified in the source rather than recalled: --write-path occurs exactly once in reckon/cli.py, under the dispatch command, and crew resume accepts --advice, --backend, --reason and --print-only and nothing that touches scope. So the fence is decided at dispatch and is immutable for the life of the run.

The coordinator is then left with two moves, and both are the kind this plan exists to remove. Redispatch throws away a worker that has already done the reading — its session, its accumulated context, and whatever it had committed — to change one string. Editing the live pointer's write_paths by hand keeps the work but is an undeclared mutation of run state, performed slightly differently by each coordinator that reaches for it; it is already the recorded workaround, which is the signal that the surface is missing rather than that coordinators are careless.

It compounds with the promotion contract. A granted extension is not honoured by crew complete unless the pointer itself carries the wider paths — --scope-changed records that the scope moved without waiving the validator — so a coordinator who grants scope in conversation and not in the pointer meets a refusal at promotion, hours later, with the worker long gone. That is the same late-refusal shape as §9, reached by a different route.

The measure, in §8's terms: a run blocked on a too-narrow fence is widened by a command, keeps its session and its commits, and promotes without the coordinator having edited any file under the crew state directory by hand. Widening writes the pointer's own write_paths, which is what promotion already reads, so one change closes both halves.

§11 — A contract that asks for a string it never supplies

The manifest template tells a worker that the red log's "first line repeats the declared mutation verbatim, so a log that failed for any other reason is refused". The declaration is never given to the worker. Verified rather than inferred: compose_prompt in reckon/crew/prompts.py mentions negative_control at three lines and every one is template text about the field — the value on the node is interpolated nowhere. Grepping a dispatched worker's own prompt.txt for its exact declaration returns zero.

So the worker is required to reproduce, word for word, a string it has never seen. It writes an honest restatement instead — usually a better one, naming the file, the symbol and the line the mutation touches — and _require_declared_negative_control then refuses the promotion on a substring test that could never have passed. The refusal arrives after the worker's process has ended, so the only party who can respond is the coordinator, whose options are to waive it or to edit the log. That is §9's shape exactly, reached by a different route.

Measured in one session: five occurrences, five different remedies. Two waivers recording the executed mutation as equivalent, one waiver arguing the executed control was stronger than the declared one, and two resumes asking a worker to rewrite a log's first line. Each was defensible alone; together they are five spellings of one repair, which is the signature this plan uses to identify work that fell through a gap. An independent review found the cause, not the coordinator who had paid the cost five times.

The repair is to supply what the contract demands: interpolate the node's negative_control into the prompt beside the requirement, so the worker can copy the declaration rather than invent one. The measure is that a node dispatched with a declaration produces a red log whose first line matches it without the coordinator waiving, resuming, or editing anything — and a node dispatched without one is still told plainly that none was declared.

A second, smaller question sits behind it and should be decided rather than drifted into: whether the match should stay a substring test at all. A worker that names the file and symbol it mutated has written something more useful than the coordinator's sentence, and a contract that refuses the better artifact is worth revisiting once the declaration is actually supplied.
