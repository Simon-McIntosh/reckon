§1 — The symptom, and what it rules out

Reported 2026-09-02: the reckon home page loads, and selecting the nova project shows a blank page. Nothing renders — not an error banner, not an empty state, not a partial shell.

Every request the surface makes succeeds. Measured against the running server at 127.0.0.1:8765 on the day of the report:

The server log records the whole sequence completing: the shell's modules are fetched, the projection.json probe 404s, the loader falls back to index.json and gets it, and discovery returns. Then nothing appears. So the fault is downstream of transport and downstream of parsing, in the client-side render — and the 404 is a documented fallback path, not by itself the failure.

The surface was not project-specific, and the report's framing misled the first pass. Measured after the fact: every mount served the same broken entry point, so nova, reckon, imas-codex, imas-ambix and imas-efit were all blank together. The home page kept rendering because it does not depend on the shell modules that were missing, so "the home page renders" never implied the shell mounted. Only one project got clicked.

Two hypotheses were raised from the initial evidence and both are now excluded, recorded here so they are not re-run: payload scale, and the distributed state format. They are recorded below with the measurement that killed them.

Excluded: the distributed state format and payload scale

Across the thirteen mounted projects, nova is indeed the only one whose state directory carries a manifests/ tree, and it is the largest payload of the mounts — 1.81 MB of project state against 1.30 MB for imas-codex and 0.74 MB for reckon. Both facts are true and neither is the cause: the projects on the single live aggregate, at a fifth of the payload, were blank in exactly the same way at exactly the same time. A property unique to the one project that got reported cannot explain a failure shared by all of them.

The table below stands as a record of the layout, which remains accurate and is worth keeping for the reader who wonders about the 404 in the log above: this project's projection.json genuinely is absent, and the loader genuinely does fall back. That fallback succeeds, and it is not what produced the blank page.

Three properties of that migration were measured. All three are real, none of them caused the blank page, and the third is a genuine trap for anyone reproducing state-loading behaviour later:

  • The aggregate this project serves is frozen. Its index.json carries a superseded block dated 2026-08-24 declaring itself no longer authoritative. Its data retains sprints (15, as they stood at migration), timeline and blockers — and has no milestones, no inventory and no north_stars key at all.
  • The loader's preferred source does not exist here. docs/ui/state-loader.js requests state/<project>/projection.json first and falls back to index.json when it 404s. reckon writes projection.json only for a distributed project, and no such file exists for this one — so the single project that should have it is the one without it, and it takes the fallback meant for the projects it no longer resembles.
  • What the server returns is not what is on disk. GET /state/nova/index.json answers with 1 801 471 bytes against a 92 999-byte file: the served aggregate is composed at read time from the distributed resources. Any reproduction must therefore exercise the served payload, not the file.

§2 — Root cause ✓ landed 2026-09-02

The managed service started 2026-09-01 22:10:59, twenty minutes before commit 737340f replaced the hard-coded entry-point renderer — so it served 12 of 20 /_ui modules, all 8 shell-* among the missing. ReadyGate was undefined, the composition root rendered data-shell-modules="unavailable" with zero children, and no exception was thrown. Every mount was affected identically. Repaired by restart: 22 scripts served, module list identical to the authored index. Full record: §2 landed (commit edd4488).

There was no throw to find — the deliverable turned out to be the silent fallback itself, which is why §3 and §4 below are the substantive remainder rather than tidy-up.

The repository already carries machinery for evaluating the surface without a live browser: tests/spa_module_eval.py, tests/spa_render_capture.mjs, and tests/spa_browser_harness.py, alongside roughly thirty test_spa_*.py suites. Use them rather than building a parallel harness.

The investigation must state, with evidence: which module throws, on which field of which payload, and why nova reaches it while at least one other mounted project does not. A root cause that does not explain the project-specificity is incomplete.
