What a node may write. A node writes only the test files it owns, plus a snapshot or generated artifact that one of its failing tests compares against, when that artifact is regenerated with the repository's own generator and not edited by hand. A node that finds a product defect in reckon/, a skill file, or an SPA source does not repair it in place, because several nodes reach the same modules. It names the defect in follow_ons with the failing node id, the file and line, and the evidence that the behaviour and not the assertion is wrong. The coordinator then cuts a separate node for it.

Where tests run. Run tests per file on compute as in §1, each file with its own --basetemp, never the whole suite in one process. A test that fails only under load is recorded as such, never retried until it passes.

No node disables, skips, xfails or deletes a failing test. Each repair either corrects a stale assertion to the shipped behaviour, with the cause named, or fixes the product defect the test found.
