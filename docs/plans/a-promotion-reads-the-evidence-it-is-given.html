§2 — A red base matches a bare test name to its qualified id

Deliverable. The red-base admission compares failure ids on the node name the two sides share:

  • A bare test name matches a qualified id whose final :: part, with any parameter bracket removed, equals it. So test_charge matches both tests/x.py::test_charge[1] and tests/x.py::test_charge[2].
  • A bare name that itself carries a bracket matches only that parametrisation.
  • A qualified id matches only the same qualified id.
  • A bare name that matches more than one head id covers all of them.

The matching rule lives with the owner of node-id identity. canonical_node_id in reckon/crew/review.py (near line 1938) deliberately keeps :: segments and parameter brackets, because they tell apart two tests sharing a file, and it is not changed. A new predicate beside it, failure_ids_covered(base_ids, head_ids), applies the rule above and returns the head ids the base does not cover. Every comparison of a red base against a head goes through it. In promotion_evidence.py, _red_base_uncovered_ids is the one function that reads the arms and calls the predicate. It returns the uncovered ids, or None when no comparison could be made: a missing arm, an arm without completed: true, a green baseline, or an unreadable head log. _zero_added_against_a_red_base keeps its boolean return, which tests/test_a_ctest_id_names_its_test.py and tests/test_a_ctest_gate_is_read_at_promotion.py assert, and returns uncovered == set() from that function, so the rule is written once: only a comparison that was made and left nothing uncovered admits, and None, an unmeasured delta, stays refused as today. _require_verdict_matches_exit_status (reckon/crew/promotion_evidence.py, near lines 1281–1294) calls the new function when the admission fails. When it returns ids, the refusal lists them, at most twenty plus a count of the rest. When it returns None, the refusal keeps today's explanation, including the clause naming an arm without completed: true.

Done when a new tests/test_a_red_base_matches_bare_names.py calls the admission functions and the refusal path directly. It shows six things:

  • A base of bare names and a head of qualified ids naming the same tests is admitted.
  • A head with one id the base lacks is refused, and the refusal names that id.

  • A bare base name matching two parametrisations of one test covers both, so a head failing only those two is admitted.
