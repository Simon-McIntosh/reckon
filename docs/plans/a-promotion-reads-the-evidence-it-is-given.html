§2 — A red base matches a bare test name to its qualified id

Deliverable. The red-base admission compares failure ids on the node name the two sides share:

  • A bare test name matches a qualified id whose final :: part, parameters included, equals it.
  • A qualified id matches only the same qualified id.
  • A bare name that matches more than one head id covers all of them.

When the admission still fails, the refusal lists the head failure ids the base does not cover, at most twenty, plus a count of the rest. It replaces the "two contradictory readings" sentence for this case.

Done when a new tests/test_a_red_base_matches_bare_names.py calls promotion_evidence._zero_added_against_a_red_base and the refusal path directly. It shows four things:

  • A base of bare names and a head of qualified ids naming the same tests is admitted.
  • A head with one id the base lacks is refused, and the refusal names that id.
  • A qualified base id from a different file does not cover a head id with the same test name.
  • A bare base name matching two parametrised head ids covers both, so a head failing only those two is admitted.

The negative control compares ids exactly, as now, and the first case fails. The test files importing reckon.crew.promotion_evidence and reckon.crew.review add no failure against the base revision. ruff check and ruff format --check add no findings on the staged paths. Write paths: reckon/crew/promotion_evidence.py, reckon/crew/review.py and the new test.

§3 — A review run's gate check is its stored review record

Deliverable. A passing gate's check is filled by _default_gate_evidence_from_manifest (reckon/crew/promotion_records.py, near line 244), which promotion.py calls near line 357. For a run whose role is review, promoted with a passing gate and no check given, that function builds the check from the run's stored review record:

  • the record's path as the log;
  • its content digest as the digest;
  • exit status 0 when the record parses as a stored review, and a refusal naming the record when it does not.

An implement run keeps the present requirement, which promotion_checks._require_gate_check_precondition still enforces unchanged.

Done when a new tests/test_a_review_run_gate_is_its_record.py shows three things:

  • A review run with a stored, parseable review record promotes with --gate passed --no-commit and no check, and its ledger row carries the record's path and digest.
  • A review run whose record is missing or unparseable is refused, naming the record.
  • An implement run with no check is still refused with today's message.

The negative control removes the review-role branch, and the first case fails. The test files importing reckon.crew.promotion_records, reckon.crew.promotion_checks and reckon.ledger add no failure against the base revision. Ruff adds no findings on the staged paths. Write paths: reckon/crew/promotion_records.py and the new test.

§4 — A presented head covers the commits beneath it

Deliverable. The subset test that produced the 16-of-17 shortfall is _require_gate_evidence in reckon/crew/promotion_evidence.py (near line 908, resolving_presented < resolving_declared). It takes the commits between the run's base and the presented head as covered, so a manifest commit is short only when it is not in base..head. promotion.py only carries the shortfall record it returns. The presented-citation and commitless-beyond-base refusals in _require_commits_beyond_base, in the same file, read the same covered set. The shortfall record and every refusal then name only commits outside that range.

Done when a new tests/test_a_presented_head_covers_its_ancestors.py shows three things:

  • A manifest listing five commits, promoted with --commit naming the fifth, reports no shortfall when the other four are its ancestors above the base.
  • A manifest commit outside base..head is named in the shortfall.
  • A commit at or below the base is named too, because it is not the run's work.

The negative control requires each commit by sha, as now, and the first case fails. The test files importing reckon.crew.promotion_evidence and reckon.crew.promotion add no failure against the base revision. Ruff adds no findings on the staged paths. Write paths: reckon/crew/promotion_evidence.py and the new test.
