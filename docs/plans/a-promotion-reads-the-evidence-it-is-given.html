§2 — A red base matches a bare test name to its qualified id

Deliverable. The red-base admission compares failure ids on the node name the two sides share:

  • A bare test name matches a qualified id whose final :: part, with any parameter bracket removed, equals it. So test_charge matches both tests/x.py::test_charge[1] and tests/x.py::test_charge[2].
  • A bare name that itself carries a bracket matches only that parametrisation.
  • A qualified id matches only the same qualified id.
  • A bare name that matches more than one head id covers all of them.

The matching rule lives with the owner of node-id identity. canonical_node_id in reckon/crew/review.py (near line 1938) deliberately keeps :: segments and parameter brackets, because they tell apart two tests sharing a file, and it is not changed. A new predicate beside it, failure_ids_covered(base_ids, head_ids), applies the rule above and returns the head ids the base does not cover. Every comparison of a red base against a head goes through it. In promotion_evidence.py, _red_base_uncovered_ids is the one function that reads the arms and calls the predicate. It returns the uncovered ids, or None when no comparison could be made: a missing arm, an arm without completed: true, a green baseline, or an unreadable head log. _zero_added_against_a_red_base keeps its boolean return, which tests/test_a_ctest_id_names_its_test.py and tests/test_a_ctest_gate_is_read_at_promotion.py assert, and returns not uncovered from that function, so the rule is written once. _require_verdict_matches_exit_status (reckon/crew/promotion_evidence.py, near lines 1281–1294) calls the new function when the admission fails. When it returns ids, the refusal lists them, at most twenty plus a count of the rest. When it returns None, the refusal keeps today's explanation, including the clause naming an arm without completed: true.

Done when a new tests/test_a_red_base_matches_bare_names.py calls the admission functions and the refusal path directly. It shows six things:

  • A base of bare names and a head of qualified ids naming the same tests is admitted.
  • A head with one id the base lacks is refused, and the refusal names that id.
  • A qualified base id from a different file does not cover a head id with the same test name.
  • A bare base name matching two parametrisations of one test covers both, so a head failing only those two is admitted.
  • A bare base name test_charge[1] does not cover the head id tests/x.py::test_charge[2], so that head is refused and the refusal names it. The same base name does cover tests/x.py::test_charge[1], so a head failing only that id is admitted.
  • A run whose head arm lacks completed: true is refused with today's arm-completion clause and no id list.

The negative control compares ids exactly, as now, and the first case fails. A second control strips brackets from both sides, and the fifth case fails. The test files importing reckon.crew.promotion_evidence and reckon.crew.review add no failure against the base revision, including the two ctest files above. ruff check and ruff format --check add no findings on the staged paths. Write paths: reckon/crew/promotion_evidence.py, reckon/crew/review.py and the new test.

§3 — A review run's gate check is its stored review record

Deliverable. A passing gate's check is filled by _default_gate_evidence_from_manifest (reckon/crew/promotion_records.py, near line 244), which promotion.py calls near line 357. For a run whose role is review, promoted with a passing gate and no check given, that function builds the check from the run's stored review record:

  • the record's path as the log;
  • its content digest as the digest;
  • exit status 0 when the record parses as a stored review, and a refusal naming the record when it does not.

An implement run keeps the present requirement, which promotion_checks._require_gate_check_precondition still enforces unchanged.

Done when a new tests/test_a_review_run_gate_is_its_record.py shows three things:

  • A review run with a stored, parseable review record promotes with --gate passed --no-commit and no check, and its ledger row carries the record's path and digest.
  • A review run whose record is missing or unparseable is refused, naming the record.
  • An implement run with no check is still refused with today's message.

The negative control removes the review-role branch, and the first case fails. The test files importing reckon.crew.promotion_records, reckon.crew.promotion_checks and reckon.ledger add no failure against the base revision. Ruff adds no findings on the staged paths. Write paths: reckon/crew/promotion_records.py and the new test.

§4 — A presented head covers the commits beneath it

Deliverable. The subset test that produced the 16-of-17 shortfall is _require_gate_evidence in reckon/crew/promotion_evidence.py (near line 908, resolving_presented < resolving_declared). The covered set becomes the presented commits plus, for each presented commit, every commit in base.. that commit. With --commit a b c, each of the three contributes its own ancestors above the base, so no single presented head has to be chosen. A manifest commit is short only when it is outside that set. promotion.py only carries the shortfall record it returns. _require_commits_beyond_base already refuses a presented commit that is not above the base (_revision_is_ancestor, near line 294), and it is left unchanged.

The existing contract file tests/test_a_short_commit_list_is_reported.py builds its fixture commits and then sets base_sha to the resulting HEAD (_record_with_manifest, near line 89), so its ranges are empty. Its two silence cases, test_presenting_all_declared_commits_is_silent and test_presenting_a_superset_is_silent, stay green because the presented commits are themselves in the covered set. The node runs that file at base and head and records both.

Done when a new tests/test_a_presented_head_covers_its_ancestors.py shows three things:

  • A manifest listing five commits, promoted with --commit naming the fifth, reports no shortfall when the other four are its ancestors above the base.
  • A manifest commit outside base..head is named in the shortfall.
  • A commit at or below the base is named too, because it is not the run's work.
  • With --commit naming two commits on separate branches above the base, each covers its own ancestors.

The negative control requires each commit by sha, as now, and the first case fails. The test files importing reckon.crew.promotion_evidence and reckon.crew.promotion add no failure against the base revision. Ruff adds no findings on the staged paths. The test files importing reckon.crew.promotion_evidence, including tests/test_a_short_commit_list_is_reported.py, add no failure against the base revision. §6 — A landed head releases its worktree

Why. On 5 November crew complete --land returned exit 1 with “the reviewed head landed and was pushed, but the worktree was withheld: its HEAD is not reachable from the integration revision” at least six times, for runs whose reviewed head it had just merged and pushed. power_convertor reported r-20261027T105434581532-csrr-report-assembly: steps.land shows head c1aea20c07b2 merged as 7042540a3 and pushed, while release.worktree_audit classified the worktree, whose HEAD was c1aea20c07b2, as unintegrated against integrated_into: "HEAD". git merge-base --is-ancestor c1aea20c0 origin/main succeeded minutes later. The coordinator's own landings of the locked-ledger, research-slug, measure, recurrence-fold and §34 runs reported the same, and each worktree was gone shortly after. The audit (_commits_beyond_merge_base, reckon/crew/routing.py near lines 755–790) resolves the string HEAD rather than the merge commit the landing just wrote. The landing builds that commit from objects and moves the ref without touching the main checkout's working tree (crew merge), so the audit can read a revision that does not yet contain the head. The failure path is reckon/crew_run_commands.py near lines 3231–3240.

Deliverable. The release audit judges the worktree against the merge commit the landing recorded (steps.land.merge or remote_head), not against HEAD. A landing whose reviewed head is an ancestor of that commit releases its worktree and returns ok with exit 0.

Done when a new tests/test_a_landed_head_releases_its_worktree.py shows two things with a temporary repository whose landing moves the branch ref without touching the checkout's working tree:

  • A worktree whose HEAD is the landed head is classified integrated and released, and the landing exits 0.
  • A worktree holding one commit beyond the landed head is withheld, as now.

The negative control audits against HEAD again, and the first case is withheld. The test files importing reckon.crew.routing or reckon.crew.promotion_release add no failure against the base revision. Ruff adds no findings on the staged paths. Every log is under the run directory, starts with its revision and the literal command, and ends in EXIT=. Write paths: reckon/crew/routing.py, reckon/crew/promotion_release.py and the new test.
