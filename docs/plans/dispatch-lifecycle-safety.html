§1 — Why

A run's lifecycle — dispatch, spawn, observe, stop, resume, recover — has verified defects at each transition (fleet review §4). The costliest is silent: dispatching a second node to a roster member whose session is still held by a live run kills the newcomer with no stream, no manifest and a phase that reads orphaned. Since the roster is the fleet's de-facto concurrency ceiling, this defect is exactly what a wider fleet trips first.

§2 — Deliverables

Member-collision guard. dispatch() consults list_live() and refuses (typed error naming the in-flight run) when the requested member has a pointer in a non-terminal phase. Done when the double-dispatch scenario refuses instead of silently orphaning, under test.

Complete dispatch rollback. Move the run-directory mkdir inside the rollback scope, and on any post-spawn failure signal the spawned process group before removing its worktree. Done when a forced pointer-write failure leaves no worktree, no directory and no running process.

Phase truth. observe preserves an intentional stopped phase; in-harness manifests are classified by their recorded status rather than mere existence, so observe/list agree with recover. Done when stop → observe → recover round-trips as stopped.

Signal safety. Before killpg, verify pid identity (process start-time or cmdline) and treat PermissionError in process_alive as not-ours rather than alive. Done when a recycled-pid fixture is refused.

Resume correctness. Resume must not overwrite log_path; completion measurement reads stream.jsonl plus resume streams in numeric order (matching ledger._run_streams), and resume refuses while the previous process is alive. Done when a resumed run's completion measures the full stream set and the tenth resume orders correctly.

Timestamp guards. _epoch_to_iso tolerates millisecond epochs and out-of-range values (returning a null reading, never raising through observe, complete, recover or the budget probe); complete --completed-at accepts naive timestamps by assuming UTC, matching the guard already in ledger._worker_seconds. Done when the two demonstrated crashes are regression tests.

Honest live view. classify_pointer (and therefore the MCP crew(view="live") surface the skill tells orchestrators to poll) re-checks process liveness when a pid is present instead of trusting the stored flag. Done when a killed worker shows as non-running on the live view without an intervening observe.

§ Followups

Implement the lifecycle guards

All seven deliverables in §2. The member-collision guard lands first — it is one consult of existing data and removes the silent-node-loss failure mode.
