A worker can take a brief

Every background worker must name a plan and a section, and that section must already be committed at the dispatch base. Otherwise dispatch refuses with plan-unavailable, exit 4. That is right for work that changes a plan's product. It is friction for a read-only probe, a measurement, a review or an investigation. For those, a coordinator has to write, audit, commit and push a plan edit first, only to give a worker a place to read its brief from. On 2026-09-25 the lead asked for a brief in place of a plan, holding the same requirements and dropping only the committed file.

§1 — Assessment and design

The direction is right. The committed-plan rule does two jobs:

  • The worker reads its authority from its own tree, so no second, stale store of instructions exists.
  • Every run's evidence traces back to durable text a later reader can open.

A brief can do both, provided it is itself durable and checked. The rule's cost, a plan edit before every probe, is paid most by the runs that change nothing.

The design:

  • Same contract. reckon crew dispatch --brief <file> replaces --plan and --section. --goal, --done-when, --write-path, --spec-level and --time-budget are still required, and the same eight-property validator runs.
  • The brief is durable. It is copied into the run directory at dispatch, and its sha256 and path are recorded on the live pointer and on the promoted ledger row. The composed prompt embeds it where a plan section would sit. A promoted row therefore still points at the exact text the worker read.
  • Any role may take a brief. Investigate, review, documentation and test roles need nothing more. An implement-role brief run is tagged unplanned. Its promotion must pass --plan-link <slug>, naming the plan whose product it changed, or --unplanned-reason <text>. Either lands on the ledger row, so a product change never lands without a stated owner.
  • Nothing else loosens. Scope claims, fences, the review reflex, the review-before-promotion guard, the budget fence and the watcher requirement all apply unchanged. The impl-move guard is skipped for a brief run, because there is no plan impl to move.

§2 — Dispatch accepts a brief

reckon/cli.py and reckon/crew/dispatch.py accept --brief as mutually exclusive with --plan/--section. The committed-section check is skipped for a brief. The brief is copied into the run directory, and its digest is recorded on the pointer.

Done when:

  • A test dispatches (with --dry-run and with a stub launcher) using a brief file and no plan. It asserts a pointer carrying brief.sha256 and brief.path, and the copied brief under the run directory.
  • A brief dispatch missing --done-when is refused with not-dispatchable, exactly as a plan dispatch is.
  • Passing both --brief and --plan is refused.
  • The declared mutation, restoring the committed-plan check for a brief, is applied, and the brief test is observed to fail with plan-unavailable. The log is recorded.

§3 — The prompt carries the brief where the plan section was

reckon/crew/prompts.py composes the worker prompt from the brief text in place of the plan-section read instruction. The prompt keeps every other part of the contract: fences, manifest shape and the landing rule. For a brief run, the landing record goes to the run directory, not to a plan.

Done when:

  • A test composes the prompts for a plan dispatch and for a brief dispatch of the same node. It asserts that the brief prompt contains the brief text and the manifest contract, and contains no plan-section read instruction or plan-landing instruction.
  • The plan prompt is byte-identical to its output before the change.

Landed — node brief-prompt-composition

compose_prompt in reckon/crew/prompts.py now takes an optional brief. When it is non-empty the prompt carries the brief text verbatim in the task-authority slot where the plan-section read instruction sits, and the landing contract sends the record to the run's own directory rather than to a plan section. Every other slot is composed for both carriers: the four fences, the durable-write and falsifiable-evidence contracts, the manifest key list, the closure authority, the negative-control declaration, and the landing contract's figure convention and meta-line ban. §4 — Promotion records a brief run's owner

reckon/crew/promotion.py promotes a brief run with plan: null and the brief digest on its ledger row, and skips the impl-move guard. An implement-role brief run is refused unless --plan-link or --unplanned-reason is given. The refusal names both discharges.

Done when:

  • Promotion tests assert that an investigate brief run promotes with no extra flag.
  • An implement brief run without either flag is refused, naming both.
  • With --plan-link, the row carries plan_link; with --unplanned-reason, it carries unplanned_reason.
  • The declared mutation, dropping the implement-role check, is observed to fail. The log is recorded.

§5 — The skill says when a brief is the right carrier

reckon-build SKILL.md §3b currently says "there is deliberately no flag for passing prose to a worker". It is rewritten: a probe, measurement, review or investigation may carry a brief, and work that changes a plan's product carries its plan. The brief meets the same eight properties, and the done-when is still the specification. crew(view="runs") shows brief runs with plan null and their brief digest.

Done when:

  • The skill text no longer states the retired rule.
  • Every test that greps skills/ passes.
  • A runs-view test shows a promoted brief run's row carrying its brief digest.

§ Decisions

May an implement-role worker take a brief instead of a plan?

The lead asked for the committed-plan requirement to be lifted for background work generally. Requiring a stated owner at promotion keeps every product change traceable without forcing a plan edit before the work starts.
