§1 — Why one picker

Flight config today names a separate backend for every model a provider serves: claude, claude-opus and claude-haiku on one subscription, and codex, codex-astra, codex-luna, codex-terra and codex-spark on the codex accounts. Every coordinator picks one by name, and nothing checks that the name still serves. On 2026-10-01 and 2026-10-02 that cost the fleet three kinds of failure, all measured.

The bookend reserve refuses every non-review codex dispatch because there is no five-hour window to read. One 27-minute run took the 30-day window from 7% to 100%. crew preflight then opened holds on all five codex backends from a 100% reading taken 0.21% into a fresh window.
Duplicate lanes drift apartclaude-opus reaches the claude dialect only through a recorded key that no test pins. The claude credential fix (a-worker-cannot-write-your-home §5) had to reason about each variant separately.

The lead's direction (2026-10-02): one lane per provider (claude, clive, codex). The model inside a lane is chosen by a single system picker that weighs capability, availability, account burn rate and local-lane room, and a coordinator may still name a model explicitly. The picker is typesafe, so a lane, a model and a selection reason are values the code checks, not strings it trusts. This is a significant redesign, and the typesafe skills will guide its development; the design section waits on them.

It overlaps the-local-lane-is-the-default (route by backend and model, local by default), a-window-paces-the-lane and advise-the-lane-never-force-it. This plan is sequenced after the first and is meant to absorb the routing parts of all three, which the design section reconciles explicitly.

§2 — Why the codex account refuses its configured models

Establish, from the provider's own responses and the account's recorded rate-limit events, why gpt-5.6-sol and gpt-6-astra are refused while gpt-5.6-terra serves. The leading explanation is that the account's plan changed to free. Confirm or refute it from evidence, never from the credential file's contents. Report which codex models this account can serve today, the window and credit structure it reports, and what the bookend reserve and preflight should do on an account with no five-hour window.

Done when: a report names every configured codex model, each with a served or refused verdict taken from a live response or a recorded stream, plus the account's plan type and window structure with their source records, and one recommended reserve behaviour for an account with no five-hour window.

§3 — Which model is current for each provider

For each provider, list the newest release of every model family it serves to this workstation's accounts, and every configured or pinned id that an older release still shadows. Measured so far from the installed Claude CLI (2.1.287): claude-fable-5-1, claude-opus-5-5, claude-sonnet-5-5 and claude-haiku-4-5 are current, and no lane offers Fable 5.1. Stale pins found: claude-sonnet-5 in dotfiles/copilot/settings.json, and gpt-5.5 and gpt-5.6-sol in ~/.codex/config.toml. The clive wrapper's behavesAs: claude-sonnet-5 is a capability-catalog mapping for the local model, not a routing pin. The codex catalog has not been read.

Done when: a table lists, per provider and family, the current id, its source (CLI catalog, provider model list, or live probe), and every location on this workstation that pins an older id.

§4 — Selecting models through OpenRouter

Investigate using the lead's OpenRouter account to choose a model per task automatically, from availability, capability, account burn rate and local-lane availability. The lead named a component, "jev", that this plan cannot yet resolve; the open question below asks what it refers to. Until it is answered, this section covers what OpenRouter itself publishes: model availability, capability metadata, pricing and the account's usage. It also covers how each of those would feed a picker beside the subscription lanes and the local lane.

Done when: a report names each signal the picker would consume, with its OpenRouter endpoint or field, its refresh rate and its failure mode, and states whether OpenRouter should be a lane, a signal source, or both.

§5 — The typesafe picker

Design and build one picker that turns a node's declared needs (role, specification level, capability class, context size) and the live state of every lane into one typed selection: lane, model, effort and a recorded reason. It replaces per-model backends with one backend per provider. A coordinator's explicit choice is honoured and recorded as an override. Old backend names resolve, with a warning, for one transition period so that no peer's dispatch breaks mid-flight. This section waits on the typesafe skills the lead will install. Its node shape and done-when are written once those skills define the conventions.
