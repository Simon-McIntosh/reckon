Shell defects and chrome · the self-contained half of the handoff

The Project Selector Scopes the Page

Four of the seven defects the designer found in the landed SPA live in the shell: hidden projects that stay in the picker, a visibility toggle that silently does nothing, a Crew list that neither scrolls nor respects the selected project, and a cream ground the canvas never asked for. This plan fixes them against the data the server already serves, then lands the topbar the canvas draws: search beside the brand, the project selector beside the gear, two tab groups, and a compass mark with no wordmark.

§1 — Why this exists

The handoff canvas at design/reckon-spa-handoff.dc.html and its triage at design/reckon-spa-handoff.md name root causes in source, each confirmed against main on 2026-09-03:

  • Hidden projects appear in the picker. docs/ui/shell-topbar.jsx renders manageableProjects, which is every project, while visibility is computed over mountedProjectRows(). Hidden rows are rendered with a suffix instead of removed.
  • Visibility cannot be toggled. mountedProjectRows() keeps only rows with plans_count > 0, and the served count is stale for most projects, so the survivor set the last-one guard computes is nearly empty and the guard fires on almost every click, silently.
  • Crew floods and cannot scroll. .r-crew-view is flex:1; overflow:auto but no ancestor between the app root and it carries min-height:0, so it grows past the viewport. At 1374 the list is clipped.
  • Crew is not repo-scoped. docs/ui/shell.jsx passes every visible project to the Crew view, so an imas-ambix run renders under a nova selection.
  • The ground is cream. docs/index.html carries an inline style block that overrides the token layer with #fbfaf7; the canvas declares a white ground and the Geist type ramp.

The canvas also changes the topbar itself: search on the left beside the brand, the two tab groups (artifact tabs, then work tabs) in the middle, a live receipt, the project selector on the right beside the gear, and the brand reduced to a compass mark that is the home button. Nothing here needs a payload the server does not emit, which is why this plan carries no dependency and is the first to run; the two plans that hang off it need its topbar tab groups and its visibility predicate.

Two rules from the handoff apply to every node: no explanatory prose blocks on a surface (the design carries the meaning; colour keys and column legends stay because they decode an encoding), and no redundant ink (a control whose count is permanently zero is hidden, not rendered dead).

§2 — Visibility that can be toggled, and a sheet that says what it does

Mount means registered. mountedProjectRows() returns every registered project row; plans_count is a label, never a predicate. The picker shows the visible set. The dropdown renders visibleProjectRows() and nothing else; the full list belongs only in the configurator. The last visible project is locked, visibly. The guard stays, but its refusal is a state the row shows (locked, switch disabled, cursor not-allowed) rather than an ignored click, and the change helper reports {changed:false, locked:true} so callers can tell the two apart. The configurator is a sheet. A fixed overlay at the canvas geometry (560px wide, 74vh tall, opened from the picker footer and from the gear), one row per registered project with a real switch, its plan and live counts, and a state word in visible, hidden or locked; esc and a click outside close it. It replaces the visibility section of the settings menu. Its one line of copy states the consequence: hidden projects leave the picker, the crew feed and the fleet roll-up; registration is unaffected. Persistence stays where the earlier plan locked it: browser storage, default all visible.

§4 — Crew scrolls, and shows the selected project

Every surface in the canvas is flex:1; min-height:0; overflow-y:auto by construction. The layout layer gives every flex ancestor between the app root and a canvas view min-height:0, so the Crew list scrolls inside the viewport at every width and the page never grows. Crew is scoped to the selected project by default, with the label <project> · N runs in its header and an explicit All visible toggle that widens it to the visible set; the rule is this plan's title, and only the fleet home is cross-project. The derived-flow lanes the canvas places above the crew cards belong to graph-derived-schedule, which writes these same files after this node lands.

An exact change. §7 — Out of scope

The artifact tabs and their routes (artifact-feeds-and-reader), the fleet home and the retirement of the cockpit (fleet-home), and the derived-flow lanes on Crew (graph-derived-schedule). Settings beyond visibility (theme, density, snapshot receipt) are undesigned in the handoff and keep their current place behind the gear. § Decisions

What makes a project row mounted for visibility purposes?

The count is a label the fleet index gets wrong today, and using it as a predicate is the root cause of the toggle that does nothing. Registration is the fact visibility governs.

How does the guard against hiding the last visible project surface?

The canvas draws the locked row; a silent no-op is the defect being fixed; an empty visible set makes every surface blank.

Where do search and the project selector sit?

Search is a global verb and belongs with the identity; the selector is a scope control and belongs with the other scope and appearance controls it governs.

What is the brand mark?

The canvas draws the mark and states the wordmark is redundant ink; the mark is the home button.

How is the Geist type ramp delivered?

A repository test holds that served and static pages request only their own origin. The stack renders Geist where it is installed and falls back to the system face elsewhere, which is what the canvas's own stack does after the link.
