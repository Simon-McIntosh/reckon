§1 — What the auditor balances, and what it does not

reckon audit-doc is the gate the ship skill requires before any plan or evidence record is committed, and its own instruction is that all errors are cleared before the turn ends. It can emit forty-seven distinct check codes. Exactly one of them comes from a structural balance scan, and that scan counts <section> opens against closes: an unclosed section raises section-unclosed and an orphaned close raises section-stray-close. Every other code is about metadata, links, images, markdown leakage, or review state. Nothing looks at table structure, so a table whose rows are never closed is not merely tolerated — it is invisible.

The consequence is not cosmetic. An unclosed row does not degrade into a slightly untidy table; the browser reflows everything after it into the cell that was left open, so the rest of the document is swallowed by a table cell. That is the same class of failure as the unclosed section the scanner already catches, and it is caught for one tag and not the other for no reason anyone chose — the scanner was written for sections because sections were the problem that day.

The measurement

All 205 files under docs/plans and docs/evidence were scanned on 2026-09-22 by counting opening against closing tags. Three carry a structural imbalance. The auditor was then run against each of those three. Optional-close tags such as <td> and <li> are excluded from the count, because HTML permits them to be left open and an imbalance there is not evidence of anything.

The third row is the whole plan. That file is the cumulative evidence record of a plan sitting at impl 0.99, which is to say the record a later reader consults to find out what was actually proved, and the check that exists to keep such records readable reports it clean. The first two rows are the positive control: they establish that the auditor is not silent in general, only silent about this. Without them the third row would be equally consistent with the auditor never running at all.

How it was found is worth recording, because it was not found by the auditor and could not have been. A worker repairing an unrelated test fixture parsed the evidence file with its own section cut out, in order to prove that the damage it could see was not damage it had caused, and reported the four unclosed rows as an out-of-fence follow-on. The auditor had passed that file on every commit it had ever received.

§2 — Generalise the scan, then repair what it finds

The balance scanner already exists and already has the right shape; what it lacks is a second tag. The work is to widen it to the tags whose imbalance reflows a document, emit a finding in the same form as section-unclosed, and then repair the three files the widened check names. The order matters: the check lands first and is observed to fail on the real file, because a repair made before the check exists proves only that someone edited the file.

Two properties keep this from becoming a general HTML validator, which is not what is wanted here. The scan stays a tag-balance count rather than a parse, so it cannot object to anything a browser accepts. And the tag list is explicit and short rather than open-ended, so a tag whose imbalance is legitimate is never reported.

Done when

A fixture built from the real evidence record — its four unclosed rows preserved — produces a finding naming the tag and the counts, and that finding is observed before any file is repaired; the two files already caught by section-unclosed still produce exactly the finding they produce today, asserted so the widening is shown not to have changed the existing check; all three measured files pass the widened auditor after repair, with the before and after counts recorded from the same pass; the other 202 files produce no new finding, which is the measure that catches a tag added to the list too eagerly; and the declared negative control — revert the widened scan to sections alone — is applied to a scratch copy, the fixture case is observed to fail there, and the red log's first line repeats the declared mutation verbatim.

§3 — The stronger case: a document the reader cannot parse at all

The tag finding above is the small end of this. The large end was measured the same evening, by walking into it. A sprint document landed carrying its metadata and its rendered item list but no reckon-resource-state script, and that script is not decoration — it is the authority the reader parses, with the visible list being its rendering. Resolving any plan enumerates every sprint document, so one file without an island made every plan read in the project fail, for every session sharing the checkout, from the moment it landed. The reader's message named the file; nothing named the cause.

The auditor reported that file OK. Not a warning, not an informational note — clean, at every severity, on the document that had just taken the plan surface down. That is the same shape as the unclosed rows and it is worth stating as one sentence rather than two findings: the auditor validates a document against the authoring rules and never against the contract its readers require. A file can satisfy every check it has and still be unreadable by the only code that reads it.

The asymmetry is what makes this worth building. Authoring mistakes are caught by a person noticing something looks wrong on the page. A missing state island looks like nothing at all — the page renders, the metadata is right, the list is there — and the failure surfaces somewhere else entirely, as every plan in the project becoming unreadable at once.

Done when

A document of each resource type that carries no state island is reported as an error by the auditor, shown against the real file that caused this, preserved as a fixture with its island removed; an island whose JSON does not parse, and one whose declared type or id disagrees with the document's own metadata, are reported as distinct errors rather than one; every sprint, plan and evidence document currently in the repository passes the new checks, which is the measure that catches a rule written more strictly than the corpus; and the declared negative control — remove the island check — is applied to a scratch copy, the fixture case is observed to pass there, and the log's first line repeats the declared mutation verbatim.
