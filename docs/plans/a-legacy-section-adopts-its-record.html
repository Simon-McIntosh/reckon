§1 — The missing-record finding names the write that adopts its section

Why. A plan section written before typed section records existed is an <h2> and its prose, with no <section data-reckon="section"> element after the heading. Once it is declared implementable, reckon audit-doc fails it with section-without-contract. The finding's message comes from _section_contract_refusal in reckon/_store.py, a builder shared with the store's own new-section refusals, and its worked example is an append to sections that carries a body. On a section that already has its heading, that write is refused: the body routes it through insert_section, which answers section id '<id>' already exists. The write that does work is the documented body-less append ("attaches a record to an <h2 id> already in the file", reckon/mcp.py), which places the record directly after the heading through _splice_section_records. Measured 2026-10-22: following the finding's example on the-page-paints-from-an-index §7 was refused, the body-less append gave §7 its record at e88cec99d, and §7's prose hashed identically before and after. An author who follows the audit's own remedy is refused, and nothing in the message points at the write that succeeds.

Deliverable. The section-without-contract finding in reckon/doccheck.py carries its own remedy. Its worked example is a body-less append to sections that names the reported section's id and uses its heading's text as the title, with effort_hours, capability and links filled in. Submitted unchanged to the plan it was reported on, that example succeeds. _section_contract_refusal and its other callers are unchanged: for a new section, a body is the right remedy.

Done when a new tests/test_a_legacy_section_adopts_its_record.py writes a temporary plan whose implementable section is a heading and prose with no record, and proves three things, each with its own control. (1) reckon audit-doc reports section-without-contract for that section, and the example in the finding's message parses as JSON, names that section's id and its heading's text, and carries no body. Control: return the finding to the shared builder, and the example names s2 and carries a body, so the case fails. (2) Submitting that parsed example, unchanged, through edit_plan to the temporary plan succeeds. Afterwards the audit reports no section-without-contract finding, a read returns a section record with that id, and the section's prose is byte-identical. Control: the shared builder's example is refused with already exists, and the finding remains. (3) A new-section refusal that _section_contract_refusal builds, such as an append with an unsupported field, still carries the shared example with its body. Control: make the shared builder body-less, and this case fails. tests/test_audit_doc_section_contract.py, tests/test_section_contract_is_refused.py and tests/test_section_record_round_trips.py pass, and so does tests/test_every_module_fits_a_worker_window.py. Tests importing reckon/doccheck.py show no added failure against base; the coordinator runs that population at merge. Every log sits under the run directory with a revision header and ends in EXIT=, and suites run on the fleet allocation, not the login node. Write paths: reckon/doccheck.py and tests/test_a_legacy_section_adopts_its_record.py.
