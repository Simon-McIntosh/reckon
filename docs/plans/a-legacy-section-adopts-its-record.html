§1 — The missing-record finding names the write that adopts its section

Why. A plan section written before typed section records existed is an <h2> and its prose, with no <section data-reckon="section"> element after the heading. Once it is declared implementable, reckon audit-doc fails it with section-without-contract (_section_contract_findings, reckon/doccheck.py). The finding's message comes from _section_contract_refusal in reckon/_store.py, which owns the envelope Use edit_plan mode=state. Example: <json> and always renders one fixed example: an append to sections for s2 that carries a body. _carries_authored_prose (reckon/_store.py) routes any item with a body to authoring a new heading, so on a section whose heading already exists that example is refused with section id '<id>' already exists. The body-less append attaches a record to the existing heading instead, documented in reckon/mcp.py and proved by tests/test_record_attaches_to_existing_section.py. Measured 2026-10-22: following the finding's example on the-page-paints-from-an-index §7 was refused, the body-less append gave §7 its record at e88cec99d, and §7's prose hashed identically before and after. The remedy the audit prints is the one write that fails on every section it reports.

Deliverable. _section_contract_refusal takes an optional item and renders it in its envelope in place of the fixed example, so one owner keeps the envelope and every caller that passes nothing prints exactly what it prints today. The section-without-contract finding passes a body-less item for the reported section: its id, its heading's text as the title, and effort_hours, capability and links filled in. Submitted unchanged to the plan it was reported on, that example succeeds. A new-section refusal keeps the body-carrying example, because _carries_authored_prose makes a body the right remedy there.

Done when new cases in tests/test_record_attaches_to_existing_section.py, reusing its plan fixture with a section written as heading and prose, prove three things, each with its own control. (1) The section-without-contract finding's example parses as JSON, names the reported section's id and its heading's text, and carries no body. Control: pass no item from the finding, and the example names s2 and carries a body. (2) That parsed example, submitted unchanged through edit_plan, succeeds, and the audit then reports no section-without-contract finding. That file's existing cases already prove that the record attaches and the prose stays byte-identical, and they keep passing. Control: add a body to the parsed item, as the default example carries one, and submit it for the same reported id; it is refused with already exists, and the finding remains. (3) A refusal built with no item, such as an append carrying an unsupported field, still prints the body-carrying example byte-for-byte as today. Control: make the default example body-less, and the case fails. In tests/test_audit_doc_section_contract.py, test_the_finding_carries_the_write_boundary_example pins the finding's example to the fixed one. This change supersedes that by design, so the assertion is rewritten to pin the item-built example for the reported section, and that file's other tests pass unchanged. tests/test_section_contract_is_refused.py, tests/test_section_record_round_trips.py and tests/test_every_module_fits_a_worker_window.py pass. Tests importing reckon/_store.py or reckon/doccheck.py show no added failure against base; the coordinator runs that population at merge. Every log sits under the run directory with a revision header and ends in EXIT=, and suites run on the fleet allocation, not the login node. Write paths: reckon/_store.py, reckon/doccheck.py, tests/test_record_attaches_to_existing_section.py and tests/test_audit_doc_section_contract.py.
