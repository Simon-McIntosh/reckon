§1 — A section written as prose adopts its typed record

Why. A plan section written before typed section records existed is an <h2> and its prose, with no <section data-reckon="section"> element after the heading. reckon audit-doc reports such a section, once it is declared implementable, as the error section-without-contract, and its message (built by _section_contract_refusal, reckon/_store.py near line 1693) tells the author to append a typed record. Both write paths refuse that section. Measured 2026-10-22 on the-page-paints-from-an-index §7, against current code in a scratch worktree: append to sections answers section id 's7' already exists, because the heading exists. set sections.s7.effort_hours answers plan has no section 's7', because apply_section_field_set in reckon/_store_section_ops.py looks only in the typed record list. A legacy section therefore can never be given a record, and its audit error can never be cleared without hand-editing the plan's markup.

Deliverable. A set sections.<id>.<field> naming a section that has an authored <h2> and a declaration but no typed record adopts that section. The write creates the record from the heading, with the heading's text as its title, and places the record element where insert_section places one: directly after the heading. It then applies the field. The section's prose is left byte-identical. An id with no authored heading is still refused with today's message. The audit's section-without-contract message names a write that succeeds on the section it reports: a set of each of effort_hours and capability on that id.

Done when a new tests/test_a_legacy_section_adopts_its_record.py writes a temporary plan whose implementable section is a heading and prose with no record, and proves four things, each with its own control. (1) A set sections.<id>.effort_hours and a set sections.<id>.capability succeed, and a read of the plan returns a section record with that id, those values and the heading's title. Control: route the set to today's lookup only, and the first set is refused with plan has no section. (2) The plan's text outside the inserted record element is byte-identical before and after the writes, and the record element sits directly after the section's heading. Control: write the record element at the end of main instead, and the position assertion fails. (3) reckon audit-doc on the written plan reports no section-without-contract finding, after applying exactly the writes the finding's own message names on the unwritten plan. Control: restore today's message, which names an append; applying it is refused, so the finding remains. (4) A set on an id that has no heading is refused with today's message, and the plan is unchanged. Control: adopt any id, and a heading-less record appears. The tests that already cover section records, tests/test_section_record_round_trips.py, tests/test_section_contract_is_refused.py, tests/test_audit_doc_section_contract.py and tests/test_section_record_moves_between_declarations.py, pass. tests/test_every_module_fits_a_worker_window.py passes. After the merge, the coordinator gives the-page-paints-from-an-index §7 its record through the new write and reports reckon audit-doc on that plan before and after: the section-without-contract error must be present before and absent after, with §7's prose unchanged.
