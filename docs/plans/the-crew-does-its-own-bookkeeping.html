Change. A live claim protects a file from a second concurrent editor. So when crew complete accepts a path, a claim held by a stopped run with a terminal manifest no longer refuses the acceptance. The acceptance records that claim by run id and path, as _accepted_scope_exceptions in reckon/crew/promotion_scope.py already records a claim on a change behind the integration head. A claim held by a run that is still working refuses as before. The node first reproduces the refusal: in a temporary crew home, two completed runs each changing a path the other claims, and crew complete --accept-path ... --land on one of them. It records the message and the call that raised it in the manifest. The rule is therefore applied where the acceptance calls in, passing the stopped peers to set aside, and never inside the shared function, so dispatch keeps refusing as today; _accepted_scope_exceptions applies the same rule, so both checks agree. Whether a peer is stopped is read at the moment of the acceptance, from the peer's process and its manifest, never from a field kept on the pointer.
