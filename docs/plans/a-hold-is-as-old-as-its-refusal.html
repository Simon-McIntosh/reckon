§1 — The fix that landed can be undone by reading it

A spend hold used to be immortal. A refusal that named no reset time was stored with no expiry, so it held its lane for as long as the process lived — measured on 2026-09-03 at five hours and forty-nine minutes past its own observation, against a direct probe of the same account that returned a served turn with real token accounting. An ageing rule landed the same afternoon: a judgement carrying no reset time stops being read as current once its observation is older than a declared shelf life, and the lane returns to unknown headroom rather than exhausted.

That rule has a defect, found by a peer session within the hour and verified here. The age is measured from the pointer's observed_at, and observe rewrites that stamp whenever it re-reads a run's stream. The stream still carries the original rejection, so re-observing a refused run re-stamps an old refusal as a fresh one. A coordinator investigating why its lane is held extends the hold by looking. Their sentence for it is better than mine: a stale hold can be renewed by probing the wrong instrument.

Two further properties were measured alongside it and both belong here. The hold is per backend, and so is its cure: one lane went from held at 100.0% exhausted to clear at 1.21% the moment a single resume was served and observed on it, while its sibling stayed pinned at the stale figure because nothing had been served there. And the fence has no lever at all: budget.policy() honours evidence_shelf_life_minutes, the schema does not declare it, so the key is refused as an unknown input — while the ceiling is capped at 100 and utilisation reads exactly 100.0, so no ceiling override lifts it either. The only exit is waiting out a hardcoded hour.

§2 — The age is taken from the refusal, not from the last read

A refusal happened once, at a knowable moment, and that moment does not change however many times the record is read. The ageing rule must therefore measure from the event rather than from the pointer's last-written stamp, so that reading a record cannot alter the verdict derived from it. This is the same principle the display work settled from the other direction: a rendered row without a transition is a rumour about time, because it invites a reader to infer recency from position rather than from evidence. Here the system itself is making that inference.

The refusal's own time is available. A per-request rejection arrives as a rate_limit_event in the run's stream, at a fixed position with the surrounding records' timestamps, and the run's created_at bounds it from below. Any of those is immutable under re-reading, which is the only property that matters.

Done when the age used by the ageing rule is derived from the refusal event rather than from the pointer's observed_at; when calling observe on a refused run one hundred times leaves the derived age and the hold verdict unchanged; when a hold whose refusal is older than the shelf life reads as expired immediately after such an observe rather than being renewed by it; and when a genuinely fresh refusal still holds. Asserted through the same decide call preflight makes, over a state built by the ledger reader from a stream carrying a real rejection, with the observe-then-decide sequence asserted as one case rather than two.

§3 — The shelf life is declared, so the fence has a lever

Every other fence in this system carries a waiver. Dispatch takes an explicit flag to proceed past an unreconciled-run backlog, past an execution-capability mismatch, and past a missing watcher, and each waiver is recorded on the run so a deliberate override is auditable afterwards. The budget hold carries none, and the absence is not a design choice — it is an undeclared configuration key.

budget.policy() reads evidence_shelf_life_minutes and falls back to a module default. BudgetConfig does not declare the field, and the configuration model rejects unknown inputs, so --set budget.evidence_shelf_life_minutes=1 fails as an extra input. The mechanism is reachable from code and unreachable from the command line, which is the worst of both: the value looks configurable to a reader of the source and is not configurable by the operator holding the incident.

Declaring it is most of the fix and it must be declared with its meaning, not merely its type: the field bounds how long a refusal that named no reset time keeps describing the present, zero or less disables ageing and restores the indefinite hold, and it has no effect on a refusal that did name a reset, because a stated reset is stronger evidence than an age. Done when the key is declared in the flight schema with that description, when an override through --set is accepted and changes the verdict, when zero restores the un-aged behaviour, and when the shipped default is unchanged so no existing host's behaviour moves.

§4 — The refusal names the instrument that would inform it

A held dispatch currently states the utilisation, the ceiling and the purpose. It does not state what would change the answer, so a coordinator supplies its own theory, and the natural theory is wrong in a way that makes things worse: observing the refused run seems like gathering evidence and is in fact renewing the hold. §2 removes the harm from that mistake; this section removes the mistake.

Three facts turn the refusal into something actionable, and all three are already known at the moment it is emitted. The hold is per backend, so it names which lane it governs and does not imply anything about a sibling backend on a different account. The cure is a served turn on that same backend, so it names that rather than leaving a reader to infer that any probe will do. And where the ageing rule is what holds it, it states the refusal's age against the bound and the wall-clock time at which the bound will pass, so the operator can wait deliberately instead of retrying blindly.

Done when a budget refusal names the backend it governs, states the age of its evidence against the bound in force, gives the time at which ageing will lift it when that is what applies, and names a served turn on that backend as the observation that would refresh it; when a refusal held by a stated reset time names that time instead of an age; and when no refusal message suggests re-reading the refused run. Asserted on the message the dispatch path emits, not on a formatting helper, for one aged hold and one reset-bearing hold.
