The lead reported not using the reckon skills and suspected they "could be improved." A holistic review of all five skills (create / edit / ship / status / sync) against the server source found four mechanical causes — none is "the skills are conceptually wrong" — plus a behavioral gap (dependency-order blindness).

§1 — Rename reckon-ship → reckon-implement (keep the prefix)

The full-family rename (drop reckon-, add -plan suffix) was considered and rejected: it creates collisions (edit-plan vs the edit_plan MCP tool), noun-ish awkwardness (status-plan, sync-plan), and carries all the migration risk while fixing none of the usability causes above. The reckon- prefix is namescoping that aids discovery and dodges every collision. Only ship is a bad noun ("implement" describes the skill's execute-and-record job better). Because reckon-implement keeps the prefix, even the reckon-* directory glob in reckon-sync still matches — blast radius stays tiny.

Rename inventory (full sweep):

  • Skill dir skills/reckon-ship/ → skills/reckon-implement/; name:, title, trigger verbs, self-references inside it.
  • Cross-references in the other four skills (create/edit/status all point at reckon-ship).
  • reckon/cli.py:432 SKILLS list entry (doctor/install-skills).
  • Re-point symlinks in ~/.claude/skills/ and ~/.agents/skills/.
  • Reckon repo AGENTS.md routing table + all /reckon-ship mentions.
  • Migrate recommends_skill="/reckon-ship …" in reckon docs + the ~10 imas-codex plan HTML files (so queued followups stay live).
  • User-global ~/.agents/AGENTS.md + imas-codex AGENTS.md Plan System tables.

§2 — Systemic fixes (all five skills)

  • impl truth. Correct the "server-computes-impl" falsehood in PLAN-FORMAT.md, AGENTS.md, and the skills; reckon-implement sets impl = shipped_sections / total on every landing (monotonic, meaningful). Leave version/modified as genuinely server-owned.
  • allowed-tools. Add mcp__reckon___read_plan / edit_plan (and audit for status) to create/edit/status/implement.
  • Fast-path. A 4–6 line "to do X, do Y" recipe atop each skill; demote checkout_path / edit_plan(create=True) deep-dives below the everyday steps.
  • §05 dedup. One canonical §05 template; the others reference it. Fix reckon-edit:149's example that violates its own "don't re-list decisions" rule.
  • Dependency gate. reckon-implement Step 1 reads depends_on; STOP+surface if a prerequisite isn't shipped/done; name the blocks successors on completion.

§3 — Structural redesigns

  • reckon-status leads with the DAG. A "dependency order / ready-set / what-to-ship-next" section computed from depends_on (ready = active plans whose prereqs are all shipped); never recommend a plan ahead of its prerequisites. Call the audit MCP tool instead of the hand-coded checklist that drifts; add dangling/cyclic depends_on checks.
  • reckon-sync → thin wrapper. Delegate CSS/index/mounts/state to reckon sync + install-skills; keep only the genuinely-unique ~/.agents/skills/ leg + legacy migration; finish with reckon doctor. Kills the two-copies-of-index.html drift hazard.
  • Sprint management. ~78 lines of sprint orchestration in reckon-edit has a distinct trigger surface from plan-text editing — see decision.

§ Decisions

Rename scheme for the skill family?

LOCKED. The prefix is namescoping (groups the family in autocomplete, dodges edit_plan/generic collisions). The full rename carries all the migration risk and fixes none of the usability causes. Only "ship" is a poor noun; "implement" fits the execute-and-record job and still autocompletes under /reckon-.

Extract sprint management out of reckon-edit?

A new skill expands the family (cli.py list, symlinks, AGENTS.md) — the same blast radius we just avoided. Lean delimited-section unless the lead wants the cleaner separation.

Where does dependency-order / ready-set logic live?

Skill-only is faster/lower-risk and sufficient now. Server-side is the robust single-source-of-truth (the logic already exists in graph.jsx) but is a code change. Default skill-only; queue server-side as a follow-up if the in-skill computation proves fiddly.

Then §3 structural redesigns, honouring the sprint-extraction + dep-order-home decisions. Commit reckon repo and imas-codex separately; verify with reckon doctor.
