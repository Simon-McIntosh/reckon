SPA project render fault

Nova's empty project surface is a mixed-generation frontend: the unrestarted server process emits its obsolete 12-script entry point, then serves the current decomposed shell.js, which detects the eight absent shell modules and deliberately renders an empty main.

Root cause

The failing server module is reckon/serve.py. The live process started at 2026-09-01 22:10:59 +0200 with the former hard-coded _render_spa_html(), whose emitted value contains 12 application scripts. Commit 737340f subsequently changed that function to read the canonical authored index, but server and parse code are not hot-reloaded. The current authored and installed indexes each contain 20 application scripts; the still-running process continues to return the earlier 12-script value for every mounted project.

The visible failure is in /_ui/shell.js. The expression window.ReckonShell?.ready?.ReadyGate evaluates to the offending value undefined, because the live entry point omits shell-ready.js along with seven sibling shell modules. The ternary at the shell composition boundary therefore chooses React.createElement("main", { "data-shell-modules": "unavailable" }); the captured value is a main with zero children.

There is no observed throwing expression. If App were forced to execute, its first missing dependency would be window.ReckonShell.route.useHashRoute() with window.ReckonShell.route === undefined. The readiness fallback prevents that call. Treating an exception as the fault would discard the actual evidence: the blank render is an intentional, silent fallback selected by an incomplete module manifest.

Regression-guard shape

The smallest durable guard should install the wheel into an isolated test environment, obtain the entry point from that installed service boundary, and compare its ordered application-script list with the packaged module manifest. It should then render that exact list through the existing file-URL browser harness and assert all three properties: the root has a child, no data-shell-modules="unavailable" marker exists, and the state of both Nova and a smaller mounted project reaches a visible view. A source-only parse cannot detect a stale long-lived process, so the operational gate must also verify a service restart after server or render code changes.

Qualifications retained

  • The live HTTP browser probe did not complete navigation on this host; deterministic module evaluation and file-URL Chrome capture provide the render evidence instead.
  • All four tested mounted project routes share the fault. The comparison does not support a claim that Nova alone is blank.
  • The current source and installed asset are already internally complete. The observed skew belongs to the unrestarted process, not to the current index on disk.
  • No exception is thrown in the observed path. The silent unavailable-module branch is the failure mechanism.
