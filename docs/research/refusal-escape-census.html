§1 — Verdict

The target was zero and the census does not read zero. In the first week after the two narrowings became due, coordinators passed --no-impl-change on 18.8 of every hundred corrective runs and --outcome on 51.0 of every hundred review runs. The coordinator-overhead census, read over its own earlier window with the same instrument and the same denominators, gives 18.5 and 52.5.

The two readings are the same reading. A week after the guard stopped refusing a corrective run for a plan that did not move, and stopped demanding a hand-typed summary from a review run, the operators reached for the same flags at the same rate. The refusal was retired; the habit was not.

The absolute counts rose — 183 corrective uses against 99, 745 review uses against 414 — and that rise is the cohort, not the behaviour: the covered coordinators completed 972 corrective and 1,471 review runs in the new week against 534 and 788 in the census window. Per run, the line is flat.

The sharpest reading is the one the ledger can confirm independently. Of the 327 corrective promotions the narrowing exempted from the impl-move check in the new week, 113 (34.6 per cent) still carried --no-impl-change. On those runs the flag could not have changed the outcome: the exemption is unconditional and is evaluated before the waiver. It was typed, and it did nothing.

The unit is one promotion invocation. A use is a crew complete or crew merge command — CLI or the mcp__reckon__crew action — that carries the flag with a non-empty value. An invocation counts once per command segment, and the same flag value re-issued for the same run is reported a second time as a retry: the table gives both the invocation count and the distinct (run, flag, value) count.

What is deliberately not a use. Text mentions of either flag (2,604 in the new arm, 2,657 in the comparator) are counted separately and never reported as uses: the flag appears in plan prose, in worker manifests pasted into a tool result, in --help output and in refusal messages. A flag with an empty value is not a use. The picker's --outcomes option is not --outcome. Heredoc and script bodies are stripped before a command is read, so a script that mentions the flag is not an operator use. Sidechain records are excluded, so a subagent's own tool calls are not the coordinator's.

The population is coordinators, not sessions. A session enters the arm when a run it dispatched records it as node_definition.coordinator.runtime_session_id in the run store. The new arm reads the live store; the comparator arm reads the census's own inputs/runs.json.gz and its 39 frozen transcript snapshots, so the comparator number cannot drift with a rewrite of history.

The flags and what retired them. Both belong to crew complete. --no-impl-change REASON waived the impl-move check; reckon/crew/promotion_checks.py now exempts a resume or redispatch attempt and a run whose dispatch declares --repairs RUN_ID before it reads that waiver. A review run's --outcome is now composed from its stored review's total score and finding count. Neither narrowing removes the flag; both make it unnecessary on the runs named here.

§4 — What the counts mean

The narrowing removed a refusal and left a habit in place. A corrective run no longer needs --no-impl-change, and a review run no longer needs --outcome. Operators passed both at the same rate in the week after as in the fortnight before. Nothing broke — an unnecessary waiver still records a reason on the row, and an unnecessary outcome is still written — which is why the behaviour is invisible without a count.

Three readings are available and the numbers distinguish them:

  • The narrowing did not reach the operators. The rate is flat across two different months and two different coordinator populations, so it is not one team's habit. A change that lands in the code but not in the habits of the people typing the command measures the code, not the surface.
  • The flags are cheap. Nothing refuses an unnecessary --no-impl-change or an unnecessary --outcome; both are accepted and recorded. A retired escape whose use is never surfaced costs nothing to repeat, so it is repeated.
  • The flags are re-derived each time from a template. The same run and the same flag value recur across a session: distinct uses run between a seventh and a quarter below the invocation count on both flags, which is what a retried or copied command looks like rather than a fresh decision each time.

What would move the number. The measure cannot say which; the census can only show that a week of ordinary work did not move it. A refusal of an unnecessary flag, a default already supplied by the tool that the operator sees, and a dispatch brief that stops modelling the flag are three different mechanisms, and none of them is in this node's scope.

§5 — Coverage, controls and caveats

Coverage is partial on sessions and strong on runs. The harness prunes session transcripts, so only 23 of the 152 coordinator sessions the run store knows about had records inside the new window. Those 23 completed 2,201 of the 2,916 runs completed in the week — 75 per cent — so the rate is measured over most of the fleet's work even though it is read from a minority of sessions. The absolute counts are a floor: an uncovered session's uses are missing, a covered one's are not.

Two residual classes are counted as uses but are not the retired escape. An --outcome on a review run that has delivered no stored review is still required, and the census cannot tell that case from the rest; and 231 outcome uses and 38 no-impl uses name a run through a variable assigned in an earlier turn, so the command does not state its target. Both are reported in their own rows rather than folded into a rate.

The controls. The instrument finds a known use: of the 164 comparator promotions the ledger records as waived — the flag changed the outcome — the scanner recovers the command for 143 (87 per cent), and in the new arm for 117 of 166 (70 per cent). The remainder are promotions whose command fell outside the covered coordinator sessions or named its run through an unresolved variable, which is the coverage gap reported above rather than a scanner miss. It does not count the flag where it is not typed: 2,604 text mentions in the new arm and 2,657 in the comparator are excluded from every figure above. It distinguishes the regime: the corrective-run:* exemption reason is absent before the narrowing and present 327 times after. And the negative control for the instrument is that a transcript containing either flag is counted — a run of the scanner over a corpus with a known flag in it cannot report zero, which is the failure this census had to rule out before reporting any figure.

What the comparator is not. It is the coordinator-overhead census's own frozen corpus, re-read with this instrument, not a fresh capture of the census's window. The census itself did not report these two counts, so the comparator column is this node's measurement of that corpus; a later reader can rerun it against the same immutable snapshots.

§6 — Reproducing it

The measure is one script over the run store and the transcript corpus: refusal_escape_census.py, with its output census.json and the exemption breakdown from classify_uses.py, under ~/.config/reckon/crew/runs/r-20261103T082606754290-count-uses-of-the-retired-refusal-escapes/. Coordinator identities and run kinds come from ~/.config/reckon/crew/run_store.db; transcripts from ~/.claude/projects/*/*.jsonl, filtered by record timestamp; the comparator transcripts and run cohort from the coordinator-overhead census's frozen inputs. Rerunning it against the same week reproduces the same figures; rerunning it later reads a longer corpus and will not.
