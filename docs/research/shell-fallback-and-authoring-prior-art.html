Reuse map

This document maps the machinery the blank-surface repair (§3 of blank-project-surface) and the plan-authoring exemplar must reuse instead of rebuild. It names 17 concrete existing candidates across three surfaces — the SPA composition root, the browser-free module-eval harness, and the plan-authoring template surface — each with a verdict of reuse, extend, or unsuitable-because. It extends, rather than duplicates, the harness inventory already recorded in spa-project-render-fault: that document catalogued browser-capability fitness; this one catalogues what the two reform efforts would otherwise re-author from scratch.

The two consumers differ in what they must not rebuild. The shell-fallback repair must not invent a second legible failure panel when one exists, and must not hand-roll a module-list source when the authored index is the canonical one. The plan-authoring exemplar must not design a new section spelling when the parser recognises exactly one, and must not skip the schema parity guard that already decides whether an authored plan is well-formed.

Candidate count

17 candidates total across the three surfaces: 6 in the composition root, 7 in the browser-free module-eval harness, 4 in the plan-authoring template surface. One candidate (write_file_spa_document/file_spa/run_probe) is judged unsuitable-because for the primary gate (host browser boundary), two are extend at the fault site and the guard's dependency map, and the remaining fourteen are direct reuse.

Where new code is genuinely owed

The reuse map does not imply no new code. What is owed is narrow, and each piece extends a listed candidate rather than replacing it:

  • The legible fallback branch when ReadyGate is undefined — extend docs/ui/shell.jsx:457-462 to render through the ProjectStateLoadPanel vocabulary with the missing module list.
  • The composition-root child-count probe at the full-bundle scale — the guard the §4 half "fires when it should" needs, built on test_spa_module_scope's assembly so reverting the §3 repair turns it red.
  • The installed-service parity assertion if the wheel boundary is added — an extension of test_build.py:327 to the installed wheel's served entry point.

Qualifications retained

  • This is a reuse map, not an implementation. Every candidate was verified to exist with the cited symbol in the current tree; none was run here.
  • Line numbers are current as of e81672a; they are anchors, not contracts — the source paths and symbols are the binding identities.
  • The unsuitable-because verdict on the browser path restates the plan's own host constraint from rendered-evidence-on-this-host; it is a host fact, not a defect in the harness file.
  • The prior render-fault research doc remains authoritative for the browser-capability classification; this map fills the "what to reuse" gap it deliberately left open.
