§1 — What this census records

A review run is delivered when its record names the head it was dispatched to read, and a promotion files that record under the review run's id. When the delivery predicate accepts a predecessor round's record instead, the promoted ledger row carries another round's reviewed_head_sha and score, and every reader of review totals — including the picker's per-dimension medians — inherits the wrong number. This document counts how many rows are like that.

The census reads every mounted project's committed ledger (<repo>/docs/state/<project>/runs/<run id>.json). A promoted run review here is a ledger row whose role is review and which carries a recorded verdict — a non-empty review.reviewed_head_sha. A review row with no recorded head carries no verdict to misattribute, so it cannot carry another round's, and is outside this population.

For each such row the dispatched head is taken from the strongest source the row carries: first a declared .at-<head> write path (read through _review_record_subject, the predicate the delivery code itself uses, so the name is parsed once and not again), and failing that the head suffix the review's node id mints — a trailing twelve hexadecimal digits, the spelling round_node_id writes, read back through its own inverse round_node_source so one grammar is parsed by the pair that enforces it. A row whose recorded head does not begin with the dispatched head is mismatched. A row carrying no dispatched head from any source is unclassifiable.

§5 — Controls

The census was shown to see a known positive and to pass a known negative, so a run that found nothing reads as the ledger's state and not as a broken instrument.

  • Known positive — listed as mismatched. nova's r-20261018T192200408612-review-of-tcv-liuqe-known-answer-0a451acfdb02 appears in §3: dispatched head 0a451acfdb02d4b05a5d8f77c7a711943f0d4cce (read from its declared .at-0a451acfdb02… path), recorded head fbc3788e228330e9547deaeb10ea3c12d03cea25, total 91, promoted_by: review-self. The recorded head is a predecessor round's, so the row carries another round's verdict — the defect this census exists to count.
  • Known negative — counted, not listed. nova's r-20261018T172216624608-review-of-vertical-pin-45213bf1cd62 has recorded head 45213bf1cd6216df72a450af58038e088407d39e, which begins with its dispatched head 45213bf1cd62…. It is counted among nova's 177 promoted run reviews and does not appear in §3.
  • Unclassifiable path — shown to fire. A synthetic promoted run-review row is written under a temporary runs directory (never a real ledger) with a recorded verdict but no dispatched head from either source: a write-path list holding only a legacy path with no .at- segment, and a node id (review-of-synthetic-row) carrying no head suffix. Pushed through the same classification function the census calls, it lands in the unclassifiable list: reviews=1 mismatched=0 unclassifiable=1, the single unclassifiable row being the synthetic one. Command: … review_rows_with_another_rounds_verdict.py --control, exit 0. Log: unclassifiable-control.log in the run directory. The portfolio's zero unclassifiable rows is therefore a reading about the ledger, not an artefact of a branch that never runs.

§6 — Reproduce

Both figures above and the first two controls come from one read-only run of scripts/review_rows_with_another_rounds_verdict.py. Run it with: 

PYTHONPATH=$PWD .venv/bin/python scripts/review_rows_with_another_rounds_verdict.py --json

The third control is its own run, which writes a synthetic ledger row under a temporary directory and removes it afterwards: 

PYTHONPATH=$PWD .venv/bin/python scripts/review_rows_with_another_rounds_verdict.py --control

The script resolves the mounted projects through reckon.flight.mounted_project_docs, walks each project's docs/state/<project>/runs/ directory, and writes nothing. It reads the node-id head suffix through reckon.crew.repair.round_node_source and the record-path head through reckon.crew.recovery_review_dispatch._review_record_subject, the same two owners the product uses, so it adds no second spelling of either grammar. It defines only private helpers and its entry point, so it adds no public definition to the package.
