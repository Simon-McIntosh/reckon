§1 — What happened

On 2026-08-26, two concurrently running coordinator sessions each launched a fleet of harness-native background agents (the host harness's Agent tool, read-only Explore type) in repositories whose crew configuration routes worker execution to codex CLI backends. A reckon session mapping the codebase for a new plan spawned three; a nova review session validating sprint state spawned seven (six per-sprint validators plus a followup-staleness sweep). Both fleets ran until the lead's stop directive; both sessions then killed their agents and re-routed to reckon crew dispatch. No files were written by the native agents and no work was lost, but ten agent runs consumed harness-model budget outside the run ledger, invisible to crew watch, the manifests, calibration, and the budget signal — and directly against the lead's routing instruction.

§3 — Root causes, ranked

1 — Rule locality. The only binding text against harness-native background agents ("never a harness-native background agent — that bypasses the run ledger, manifest contract, and calibration") lives inside the ship skill's scout section. Sessions doing review, status, roadmap, or plan-design work legitimately never load that skill, so the rule was in front of neither session when the spawn decision was made. The rule is scoped to where it was first learned, not to where the temptation occurs.

2 — A binding rule with no bound check. Nothing refuses the spawn at the moment it happens. This repository's own doctrine states the failure mode precisely: a rule that is prose is followed most of the time and skipped exactly when it matters, and the remedy is a check bound to a moment that always happens. The moment that always happens here is the Agent tool call itself.

3 — The affordance gradient points the wrong way. Native fan-out is one tool call with zero setup; crew dispatch requires a committed plan section, a seven-property node contract, pre-flight, a watcher seat, and a member. Every step of that friction exists for a reason (authority, isolation, delivery, calibration, budget), but a session under time pressure feels only the gradient. Both sessions slid down it.

4 — Classification latitude. "Read-only scoping" reads as coordinator-permitted work; "investigation" reads as a worker node. Both sessions took the lighter reading of the same activity. The ship skill closes this ("investigation … is a worker node"), but that text was not loaded (cause 1), and no loaded skill owned the classification for non-ship work.

§4 — Why the bypass costs more than the tokens

  • Model routing: the lead directed codex workers; native agents spend the harness session's model family instead, unmetered by crew budget state.
  • Observability: no run pointer, no manifest, no crew watch event, no drain accounting — a native fleet is invisible to every recovery path the crew system builds.
  • Calibration: completed work leaves no ledger record, so effort calibration and gate history silently under-count.
  • Isolation: read-only Explore types are safe, but the same gradient reaches write-capable native types that hold no worktree, scope fence, or commit discipline.

§5 — Prevention: recommendation and options

Recommendation: a hard block at the tool boundary, plus the routing rule in every skill that can face the temptation. Guidance alone is measured insufficient — the rule existed in memory in one session and in an unloaded skill in both, and was rationalized past twice on the same morning. A warn-level check invites the same rationalization. The block is cheap to obey: at spawn time both sessions held well-formed work lists that translated one-to-one into crew dispatches.

Two design notes from the reviewing session, adopted: the block must apply only to spawning new background agents — messaging or stopping existing ones must stay allowed, or cleanup after an incident is itself blocked; and inline reads by the session's own tools stay free, so a single-file lookup never needs a waiver — the block bites only where the ledger bypass begins.

The executable design, enforcement-mode decision, and tests are owned by the native-agent-dispatch-guard plan, which this record informs.
