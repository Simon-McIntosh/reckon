§1 — What was observed

Coordinators repeatedly failed to notice that their workers had finished. The reported symptom was intermittent — “sometimes the orchestrator is not notified” — but a single measurement across every mounted project on this workstation, taken at 10:20 on 2026-09-01, found it in every project at once. Each of these runs had written a terminal manifest and was waiting for a coordinator that was not going to look:

Two details make this more than a backlog. The imas-ambix row had a watcher process still alive after four days, holding its project's seat and writing transitions that nothing had read since the session that dispatched it ended. And imas-codex carried four live runs belonging to two concurrent coordinator sessions, sharing one watcher and one event stream between them.

A second observation arrived while the repair was being written, and confirmed the mechanism from the other direction: three sessions had independently fallen back to hand-rolled polling loops of the form until ok=1; for n in …; do R=$(ls -td …). Agents do not invent manifest polling when a wake-up works.

§3 — Four causes, each measured

The attach line was shaped for the wrong primitive. Reckon handed the caller a shell pipeline — { reckon crew follow --project P | grep --line-buffered -E … || true; }. A shell string's natural home is the shell tool, whose one notification arrives when the command exits; the follower returns only when its watch dies. Measured on this host: a backgrounded shell's stdout is a regular file (REG), a per-line monitor's is a socket (SOCK). The observed instance had run 14m23s with four terminal transitions buffered in a file nobody would open until it ended. The trailing || true compounded it, turning the follower's own refusal into an exit-zero with no output — indistinguishable from a quiet fleet.

The correct rule lived where nobody reads it. The harness reference already said the right thing, with the incident that motivated it. But the section a coordinator reads at arming time never pointed there, and instead ended with “background the bare command and read its output file” — a polling loop, three paragraphs after the same document condemned polling. A cross-reference at the end of a 1300-line skill is not a trigger at the moment of action. This is the same rule-locality failure recorded for native-agent dispatch: a correct rule, filed somewhere the acting agent has no reason to open.

One stream served every session. The follower had no session filter, the durable stream stored rendered lines so filtering downstream was impossible, and a line carried only a node name. So a coordinator woken by a peer's run could not tell it was a peer's — and acting on another session's run is worse than not seeing it.

A stalled worker woke nobody at all. The ticker emits stalled for a run whose stream has gone quiet past its window, and stalled appeared in neither the attention set nor the progress set, so no filter ever matched it. The check that was supposed to catch an unrouted state asserted against the recovery classes, which do not include the states the ticker derives, so it stayed green over the gap. The single most actionable state was unroutable.

§4 — Why the previous ten fixes did not close it

This area was not neglected. One hundred and fifty-two commits mention the watch surface; the plan that owns the subject shipped eight days earlier at full implementation, with two decisions locked on measured evidence. Every pass hardened the producer: seat exclusivity, orphan detection, a refusal when no seat exists, the ticker's state vocabulary, stream memory across re-arms, reclaiming a stale registration. One pass was even titled for this exact distinction.

All of them were correct, and none of them could close the gap, because the guard's predicate was the wrong proposition. “A producer exists for this project” is satisfied by a peer session's seat, and by a detached producer armed on the caller's behalf — the four-day-old watcher in §1 satisfied it perfectly. Reckon could observe production and could only advise about delivery, so delivery stayed the one link with no check on it. Ten advisory restatements of an unobservable rule is the signature of a wrong predicate rather than ten failed fixes.

§5 — What changed

Delivery becomes a first-class, registered, verified thing, with the producer arrangement unchanged — one seat per project, armed by dispatch, exactly as locked.

The skill and the harness reference were repaired for the second cause. The arming section now states the two-part model where the arming happens, names session_attached as the only field that answers “will I be told”, and sends the reader to the harness reference at that moment. The polling instruction is gone. The harness reference leads with the discriminator as a table and names the wrong primitive in order to exclude it. Both contract tests moved from wording checks to intent checks: the skill must not recommend reading an output file, and the harness section must state the contrast rather than only the right answer.

§6 — Residual, and what to expect

Every session on this workstation is currently unattached. Verified after the change: no project has a delivering follower, so the next CLI dispatch in each will be refused with the exact command to arm. That is the mechanism working, and it is the intended cost of the strictness choice — a refusal that names its own remedy, rather than another silence.

Producers hold their code until they restart. A running reckon crew watch keeps writing rendered lines rather than transition objects. Those lines still reach followers, with their ownership unknown, so session scoping is degraded for a project until its producer turns over — which happens on its own when a wave drains and the next dispatch arms a fresh one. Nothing needs to be killed by hand.

What this does not address. The unreconciled-run refusal, the drain count, and the scope-conflict registry remain project-wide by design, so one session can still be refused a dispatch because a peer left a terminal manifest unpromoted, and a session's closure fence still counts pointers it does not own. That coupling is defensible for scope conflicts, which are genuinely cross-session, and questionable for the other two. It is a separate subject and needs its own decision rather than being changed in passing here.

The generalisation worth keeping. Three findings in this investigation had the same shape, and only one of them was about watchers: a command whose failure was swallowed by || true; a lint baseline that measured zero because its interpreter did not exist and its stderr was discarded; and a state the ticker emits that no filter selected. Each produced a confident, wrong, quiet answer. A signal nobody can read is not a signal, and the only durable defence is to measure the end of the chain rather than the first link that looks healthy.
