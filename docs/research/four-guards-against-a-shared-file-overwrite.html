Four guards against a shared-file overwrite

Safe log creation and a shell-held allocation are feasible now. A write fence can cover uv and be re-entered by jobs, but a PATH shim cannot enforce that on every job. Foreign-host recovery already works for an empty node; allocation identity is the remaining gap.

Reference, method and ownership

The incident mechanism is a four-argument wrapper called without its revision argument. Its third slot receives the Python path, and > "$LOG" follows worktree → checkout → uv links and truncates the shared interpreter. This investigation read the whole incident record before experiments. Reckon owns the fence, gate execution, allocation launcher and recovery classification; dotfiles owns the client-side cx diagnostics, and the cluster administrator owns scheduler enforcement. This is research input for a future plan, with no sprint or plan lifecycle changes.

A gate creates its own log

Owning code and missed incident. reckon/crew/standing_suite.py:273 opens a log with "w"; reckon/crew/promotion_gate.py:145 uses write_text for replay output. Both can overwrite an existing file at their API boundary. The CLI suite owner, reckon/crew_run_commands.py:2133, generates a time-based log name and runs the declared whole-project suite; reckon/crew_run_commands.py:4512 replays a stored gate at an integrated revision. Neither was used by the incident's hand-written wrapper. Safety inside one verb would therefore leave the demonstrated wrapper path exposed.

Prototype and control. log-prototype.patch invokes the real standing-suite executor with /bin/echo gate-output-marker rather than a suite. A temporary patch changes only its log open from w to exclusive x in memory. Job 1320774 (logs.out) and the per-case receipts (log-results.json) show the following.

The refusal is [Errno 17] File exists. Exclusive open supplies the atomic existing-file check; checking exists() before an ordinary open would leave a race. The gate must retain and write the descriptor it created, rather than reserve a name and reopen it. Parent directories also need to be owned or protected against substitution.

Which endpoint matters. The prescribed ls -t | head -200 sample names 200 run directories by modification order. Twelve moved into the archive during inspection; resolving those exact names in the archive recovered all 200 without walking crew home. 43/200 hold a gate wrapper script, and 0 observed shell command inputs invoke crew verify-gate or crew suite run. There are readable shell inputs in 151/200; the remaining 49 do not establish verb use or non-use. These are non-exclusive artifact/use counts, not a division into 43 versus 157 gate users. The parser sees a deliberately present verb in all three observed formats (message/tool-use, completed command item and tool-execution-start), ignores output-only mentions, and detects the incident's known arm.sh. The cohort receipt (population-final.out), per-run bindings and parser controls (population-results.json) and the scanner (population.py) preserve the denominator and uncertainty. The initial scan mistakenly searched command output; it was rejected and corrected before drawing this conclusion.

Feasibility, exposure and effort. Atomic safe creation is straightforward. The larger endpoint should be workers have no reason to write a gate wrapper: a managed executor must support the dispatched scoped command, revision-labelled base/head arms, separate-partition execution and durable headers/receipts, reusing the current gate owners. Budget 2.00 h including that integration and tests; an isolated open-mode change is only about 0.25 h and does not remove the incident's path. Arbitrary worker shell redirections remain possible, so this complements the filesystem guard. Repeat gate runs need new generated paths, not permission to truncate an earlier log.

Proposed done-when. Grant tests/test_a_gate_creates_its_log.py and the existing standing-suite, replay and worker-gate composition owners. A worker follows its composed managed command to run one scoped gate and both revision-labelled arms in all_debug without authoring a wrapper; each returns a named durable log and a terminal exit receipt. Passing a regular sentinel, a symlink or a dangling symlink as a caller-supplied log returns non-zero before the gate executes, preserving target bytes and mtime or target absence; a fresh path records the command marker and receipt. Restoring ordinary truncate-mode open must fail those preservation assertions, and disabling managed scoped-command composition must fail the wrapper-free workflow assertion. Do not change the unresolved gate-time-accounting decision to satisfy this section.

Sessions outlive the supervisor's interpreter

Owning code. reckon/crew/fleet_node.py:268 execs the fleet supervisor as the batch process. bin/fleet-supervisor:19 then execs the checkout interpreter running reckon.crew.fleet_supervisor. reckon/crew/fleet_supervisor.py:2453 starts the zellij server in that batch lineage, and reckon/crew/fleet_supervisor.py:2532 starts per-run supervisors. The similarly named reckon/crew/supervisor_main.py:23 is a worker supervisor entry point; making it resilient would not preserve the fleet batch process. The read-only dotfiles/bin/cx caller uses fleet-node hold --submit, and attaches a viewer by SSH or an explicit srun step. The zellij server is a batch descendant, not that viewer step.

Control first. supervisor-prototype.patch and supervisor_rehearsal.py start two owned sleep 65 stand-ins: a detached batch descendant matching server ownership, and an explicit Slurm step answering the requested step measure. With today's exec shape, rehearsal 1320763 killed its own Python supervisor with SIGKILL. The allocation failed with 0:9 after 2 s and step 1320763.0 was cancelled with 0:15 after 4 s. The control log (rehearsal-control-bound.out) and scheduler accounting (supervisor-accounting.out) show the end.

Prototype. The batch shell instead runs Python as its child, absorbs its wait status 137, and keeps holding the allocation. In rehearsal 1320782, after a real 30-second sleep, kill -0 succeeded on the stand-in, ps showed Ss /bin/sleep 65, squeue showed 1320782|RUNNING, and scontrol showed 1320782.0 State=RUNNING. The step later completed normally after 65 s and the allocation after 70 s. The surviving-job receipt (rehearsal-survivor-state.out) records the result at the requested instant. No fleet process was signalled; the only SIGKILL targeted the Python process the rehearsal itself started.

Feasibility and cost. A native shell can own allocation lifetime independently of Python on this cluster. Budget 1.50 h for a shell holder around the existing supervisor, bounded restart/backoff, explicit intentional-stop/reload semantics and rehearsal tests. The prototype proves survival, not supervisor restart or a working UI after the interpreter is lost. Python services will still be unavailable until their interpreter is repaired; node loss, allocation cancellation and memory exhaustion of a session remain outside this guarantee. Starting another Python supervisor before its interpreter is healthy must not produce a rapid restart loop.

Proposed done-when. Grant tests/test_sessions_outlive_the_supervisor.py, the hold-script generator and its existing launcher. In an all_debug rehearsal of at most ten minutes, start both a batch-child session stand-in and an explicit step, then SIGKILL only the owned Python supervisor. At least 30 s later both stand-ins must be non-zombie processes, the step must read RUNNING, and squeue must report the allocation RUNNING; restoring exec-Python as the batch lifetime owner must end the allocation and session step. Separately assert bounded supervisor restart, preserved session identity across restart, and intentional retirement that exits rather than restarts. Preserve the ids, the 30-second receipt and final accounting.
