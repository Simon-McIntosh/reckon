Implementation boundary

The repair should extend the existing stat-identity contract, not add a second invalidation system. parse_plan(path), lifecycle state, and link/anchor summaries are pure functions of one file and belong in reckon.file_memo.memoized. Cross-plan scans should consume those records. The discovery corpus/tree result remains owned by the memo introduced by a-page-load-reads-each-file-once. Live-run classification should memoise only file-derived results against each pointer, manifest, receipt, and stream stat identity; it must recompute when any of those files changes.

The projected values above are the expected warm latencies that set the next implementation measure: audit about 4.0 s, roadmap about 1.2 s, and discovery about 1.5 s on this host. They are deliberately below the declared five-second ceiling but are not acceptance evidence. The repair must measure each public read unprofiled three times at its landed revision and preserve invalidation tests for one changed plan and one changed live-run file.
