A census of coordinator attempts to message a crew worker

This is the attempt side of the delivery measurement. Where Messages to workers never arrive counted the deliveries, this census counts the attempts and what each attempting coordinator did in its next turn. The two read together: the channel is attempted over two thousand times, delivers into worker streams exactly zero times, and the attempting coordinator believes it worked in the large majority of cases.

Attempts — the sender-side marker

A send attempt is an executed SendMessage tool use: an assistant record whose content carries a block with type: "tool_use" and name: "SendMessage". Counting tool descriptions is the known false-positive trap (the system prompt lists the tool), so the parse requires the block, not the string. 

python3 - <<'EOF'
import json, glob
n = 0
for f in glob.glob('/home/ITER/mcintos/.claude/projects/*/*.jsonl'):
    for l in open(f, errors='replace'):
        try: r = json.loads(l)
        except Exception: continue
        if r.get('type') != 'assistant': continue
        c = r.get('message', {}).get('content')
        if isinstance(c, list):
            n += sum(1 for b in c if isinstance(b, dict)
                     and b.get('type') == 'tool_use'
                     and b.get('name') == 'SendMessage')
print(n)   # 2,232 on 2026-09-15T08:52Z
EOF

The extraction also captured each attempt's recipient, tool result, and the full next assistant turn into census_attempts.jsonl; the classification below reads that artifact.

Delivery — the receiver-side marker

A delivered message is a harness-injected user record whose content opens with the delivery preamble and carries a <cross-session-message from="…"> element. The preamble distinguishes a real delivery from model output that merely quotes the phrase, which is exactly the artefact that otherwise pollutes a substring count. 

python3 - <<'EOF'
import json, glob
n = 0
DONE = 'Another Claude session sent a message:'
for f in glob.glob('/home/ITER/mcintos/.config/reckon/crew/runs/*/stream.jsonl'):
    for l in open(f, errors='replace'):
        try: r = json.loads(l)
        except Exception: continue
        if r.get('type') != 'user': continue
        c = r.get('message', {}).get('content')
        if isinstance(c, str) and c.startswith(DONE) and '<cross-session-message ' in c:
            n += 1
        elif isinstance(c, list):
            n += sum(1 for b in c if isinstance(b, dict)
                     and b.get('type') == 'text'
                     and (b.get('text', '') or '').startswith(DONE)
                     and '<cross-session-message ' in (b.get('text', '') or ''))
print(n)   # 0 on 2026-09-15T08:52Z
EOF

The positive control applies the identical receiver-side marker to the interactive transcripts: 1,204 times in 91 files. The same instrument that finds nothing in worker streams finds deliveries where they exist, so the zero in worker streams is a real absence, not a mis-aimed grep. At occurrence level (the looser marker the product has been cited with) it finds 12,561 occurrences in 259 interactive files against the referenced study's 11,939 in 244 — the fleet grew, the marker still fires.

What each attempting coordinator did next

Of the 2,232 attempts, 1,563 have a subsequent assistant turn captured in the same transcript; 669 are the last tool use of the transcript and are excluded from the classification. Each next turn is placed in one of three classes by mechanism, not by prose: a further SendMessage is a retry; text naming an alternate delivery mechanism (crew resume, a run-directory write, the file peer channel) is a channel switch; everything else is a stand-down — the coordinator believed the send succeeded and moved on.

The stand-down is the failure the parent plan names. The large majority of coordinators who attempted the channel treated the send's success result as the end of the matter and made their next decision on that basis.

Stood down

“Sent to reckon-fd — they own the monitor and had just fixed the ruler regression, so it’s the right desk.”
“Messaged all three owners with their specifics rather than generic procedure — I inventoried each dead run first, and the facts changed the advice per run.”

The third line is the exact failure: an instruction to a run owner that the owner never saw, recorded as done. The coordinator’s own next message to another interactive peer (controls, delivered) is where the content that could have reached the worker went instead.

Retried

“Request from imas-ambix-8c: if you are the nova S19 sprint coordinator, please s…” — sent to nova-50 and again to nova-88 within the same turn.
“H200 scheduling on 98dci4-gpu-0003 — nova-ec redirected me to you as the owner o…” — to reckon-d8, immediately re-sent.

Retreats to a second SendMessage in the same turn are how a coordinator re-aims when it doubts the first recipient, never a different transport. Both recipients above are session names, so the second send carries the same delivery odds as the first.

Switched channel

“Resumed, and the catch exposed something worse than the stranded run itself. crew resume reattached with no preparation — session 17d1dc38, recovered from the stream, worktree intact, nothing to redo.”
“Note delivered on both channels.”

The first is the only channel the system genuinely provides to a stopped worker, and it produced the desired contact. The second line’s transcript confirms the coordinator reached the worker through a second, non-message surface in the same turn. These are the exceptions: only a handful of the 12 text-flagged switches are actions rather than prose that happens to mention the mechanism, and they are the counter-example for the stand-down class — coordinators do not, on available evidence, routinely fall back to a working channel.

Method and limitations

Populations scanned in full, once, at a single stamp; the extraction script and its raw 2,232-row output are preserved alongside this census. Re-running the three compact commands against the now-grown fleet yields 2,257 attempts, 0 deliveries in 3,984 streams, and 1,216 control records — the load-bearing zero reproduces; the attempt and control counts drift with live-fleet growth in the minutes between.

Limitations worth stating. The census counts attempts whose transcripts are still on this host; an archived or moved transcript is invisible, and a run whose stream was truncated at promotion could have received a delivery no longer present to count — the control bounds how wrong that could be but does not eliminate it. The classification reads only the immediately following turn, so a coordinator that switched channels a turn later is counted as stood down; the true switch count is therefore a lower bound. Recipients are session addresses, and whether a given recipient was headless at send time is not reconstructable from the transcript; the delivered-zero across every worker stream is the ground truth that makes the per-recipient question moot for headless runs.
