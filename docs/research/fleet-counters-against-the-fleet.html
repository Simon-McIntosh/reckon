Limits and implementation input

This is a fifty-observation slice of one project watcher, not an estimate of a long-run failure rate. It was selected because it contains the lead's reported rapid launch wave and retains the worker receipts needed to distinguish pending launches from dead workers. The zero stale and scope fractions apply to this slice only. They do not show those failure modes are impossible.

The implementation gate should target the classifier boundary, not the arithmetic: keep a newly written pointer in dispatched while its supervised launch is still pending, and do not turn disappearance into promoted without a ledger receipt. The counter already partitions the states it is given and already recomputes on bucket-moving transitions.
