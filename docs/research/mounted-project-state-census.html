§1 — What this census records

The sweep-complete gate on derived-gate-state requires a re-scan of the mounted portfolio, so the sweep is sized from a census taken at the time rather than from the figures frozen on 2026-08-12. This document is that census: for every mounted project it records three numbers — the count of documents persisting a blocked plan status, the count of persisted sprint-item statuses, and the count of error-level wiring findings — each read from a single scan run, stamped with the scan time and the project's own git HEAD at scan time. It replaces the 2026-08-12 inventory rather than reusing it.

Scan performed 2026-09-15T08:15:35Z (unix 1789460135) across the 13 mounted projects in ~/.config/reckon/mounts.json, through reckon's own machinery: project discovery for the blocked-status and persisted-item counts, the roadmap builder (view="raw") for wiring findings, and the persisted docs-tree index for sprint-item statuses. Nothing in any project tree was written.

§4 — Instrument notes

Counts are the persisted state a sweep must clear, not the composed state a reader derives. Persisted sprint-item statuses are read from each project's persisted index file, not from read_plan, which returns composed state with derived statuses. Reading the persisted index reproduces the two moved figures already recorded for this sweep (imas-ambix 41, nova 4) exactly, which confirms the instrument reads persisted rather than composed state. The roadmap wiring-finding instrument counts each finding once per build; the all-severity total is read from a single build in the same scan run.
