§1 — What this is, and where it lives otherwise

This is a repository copy of a retrospective review that existed only at ~/.config/reckon/crew/reports/s15-day-review.md — outside every checkout, reachable from no fresh clone, no CI run, no peer worktree and no reader on another machine. That source file is 24451 bytes, 379 lines, dated 2026-09-03, and it is not deleted or edited by this page: it remains the provenance, and every figure below is reproduced from it verbatim rather than re-derived. Its own opening line states its method: "A retrospective reading of recorded history. Every judgement below is against the brief the node was given (the goal and done_when on its promoted ledger row in docs/state/reckon/crew.json), not against its exit status. No file was edited and no check was invoked to produce it."

§7 below carries one addition the source could not: three of the four still-open items it named have since been repaired, and a reader of the source alone would not know that.

§2 — Headline

Verbatim from the source: "11 of 40 code-bearing commits merged to main today are MET-IN-LETTER-ONLY — 27.5 per cent. One is EXCEEDED, and 28 are MET." Every one of those 40 commits came from a node whose gate reads passed; the gate is not wrong, it is narrow — it measures the assertion the worker was told to make, and eleven times the assertion was satisfiable without the goal being reached.

On the widely quoted 92 per cent figure, the source is explicit that it could not be reproduced: "Today's 67 dispatch rows give gate=passed 48, failed 18, not-run 1 — 71.6 per cent by row. Collapsing retries to distinct node ids (59 of them) and counting a node as passed if any attempt passed gives 81.4 per cent by node. A running cumulative rate over the day never touches 92 per cent at any point, and no denominator I tried (non-malformed rows, rows with a completion timestamp, rows with commits) produces it either." All 18 failures carry a harness classification — 10 infrastructure-failure, 8 malformed-node — so a rate computed over worker-attributable failures alone is 48/48, i.e. 0 of 48 passed rows carry a worker-attributable failure.

The source named two defects still live at HEAD when it was written, and two signals it found measured in flight and then discarded at promotion. Re-checked against this worktree's HEAD, three of the four have since landed a repair; the fourth has not, and a reader of the source alone would not know which is which.

No commit after 2322564 touches hooks, sync, or a settings file. The guard script itself is real and executable; nothing installs it.

§8 — Limits the source carries, unchanged

Verbatim: "A limit of this reading, stated rather than hidden: this determination is static. This node edits no file and invokes no check, so I did not check out any base revision and run its tests. Each judgement above is from reading whether the asserted behaviour existed in the source at that commit's parent. For the two test-only commits the conclusion is structural and certain; for the rest it is a reading, and a test that passes at base for a reason invisible in the diff would not have been caught by it." This page does not lift that limit — it reports figures from the source and, in §7, later commit history; it does not itself check out any base revision or invoke a test suite either.
